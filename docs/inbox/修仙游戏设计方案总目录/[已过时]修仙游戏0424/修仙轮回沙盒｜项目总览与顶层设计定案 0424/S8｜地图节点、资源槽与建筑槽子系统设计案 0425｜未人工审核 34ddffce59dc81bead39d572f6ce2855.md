- 文档类型：子系统设计案。
- 当前状态：**未人工审核**。本页由 AI 根据现有 Notion 约束按最小可行原则补齐，待人工审阅后才能视为定稿。

- 上位约束：项目总览与顶层设计定案、S3 行动经济、S7 宗门行动。
- 本页范围：有向带权节点图、节点类型、资源槽、建筑槽、控制权、影响力、隐藏层、前世后手层。
- 本页不展开：完整地图内容表、所有节点事件表、精确产出公式、复杂地形模拟。

## 1. 子系统定位

S8 定义世界地图如何被系统理解和结算。

一句话定位：

> S8 决定世界由哪些地理节点组成、节点之间如何通行、节点上挂载什么资源 / 建筑 / 事件 / 后手，以及宗门如何争夺这些节点。
> 

## 2. 地图基础结构

地图采用有向带权节点图。

```
MapGraph {
  nodes
  directed_edges
  route_states
  hidden_routes
  global_region_tags
}
```

边可以支持：

- 双向但成本不同。
- 单向门。
- 权限门。
- 状态门。
- 风险门。
- 隐藏路线。
- 临时通道。

S3 读取通行成本、路线状态和可达性；S8 不直接决定玩家本季度行动计划。

## 3. 节点最小结构

```
WorldNode {
  node_id
  display_name_key
  node_type
  region_id
  visible_state
  danger_level
  owner_control
  faction_influence_map
  resource_slots
  building_slots
  event_slots
  hidden_layers
  legacy_layers
  route_connections
}
```

节点是地图主单位。资源和建筑不是独立漂浮物，而是挂载在地理节点上的槽位层。

## 4. MVP 节点类型

MVP 建议支持：

1. 宗门山门节点。
2. 城镇 / 坊市节点。
3. 村庄 / 凡人聚落节点。
4. 资源型地理节点。
5. 荒野探索节点。
6. 秘境入口节点。
7. 前世后手节点 / 隐藏层。
8. 禁地 / 高危节点。
9. 道路 / 山道 / 渡口 / 交通设施节点。

第一阶段新手流程中的青禾村、镇集、镇集武馆、云麓山道、云麓宗山门均可映射为这些节点类型。

## 5. 资源槽

资源槽代表节点自然或半自然产出。

```
ResourceSlot {
  slot_id
  resource_type
  abundance_state
  extraction_difficulty
  regeneration_rule
  controlling_faction_bonus
  depletion_risk
  discovery_state
}
```

资源槽由 S7 开采、探索、驻守等行动触发；库存结果写入 S6。

## 6. 建筑槽

建筑槽代表人工建设、宗门设施或特殊功能。

```
BuildingSlot {
  building_id
  building_type
  owner_faction
  construction_state
  level_or_quality
  function_tags
  damage_state
  access_permissions
}
```

建筑可以被建设、修复、破坏、占领或废弃。S7 建设行动负责创建或改变建筑状态；S5 决定玩家是否有权限使用。

## 7. 控制权与影响力

节点归属采用控制权 + 影响力混合模型。

控制权决定：

- 主资源收益权。
- 建设权。
- 驻守权。
- 通行管理权。
- 节点事件优先响应权。

影响力决定：

- 行动成本。
- 情报发现率。
- 任务成功率。
- 探索与交易便利。
- 控制权争夺基础。
- 对控制者收益的轻微竞争。

## 8. 控制权变更

控制权变更采用阈值 + 事件模型。

玩家不需要逐个节点点击“接管”。控制权由以下行为逐步推动：

- 探索。
- 驻守。
- 建设。
- 开采。
- 处理节点事件。
- 削弱对手影响力。
- 宗门远征。

当影响力、驻守、事件结果和资源投入达到条件时，S10 可触发控制权变更事件。

## 9. 隐藏层与发现状态

节点可包含隐藏层：

- 未发现资源。
- 秘境入口。
- 特殊路线。
- 前世遗产线索。
- 宗门密藏。
- 高危事件源。

发现状态建议：

```
unknown
rumored
located
partially_revealed
revealed
resolved
```

角色日志只展示角色可知信息；完整节点状态仍在世界状态中保存。

## 10. 前世后手层

前世后手层由 S11 负责详细规则，S8 只提供挂载点。

```
LegacyLayer {
  legacy_id
  owner_spirit_ref
  concealment_level
  discovery_state
  access_conditions
  risk_state
}
```

正式后手失效、暴露或被破坏时，必须有日志和追查路径。

## 11. 节点可见性

节点可见性至少分三层：

1. 地图上不可见。
2. 已知方向 / 名称但不可查看详情。
3. 可查看部分详情。
4. 已亲身抵达或已获得可靠情报，可查看完整已知详情。

第一阶段中“云麓山道 / 云麓宗山门已显露但不可查看详情”的状态属于第 2 层。

## 12. 与其他系统的接口

- S3：提供当前位置、路线、通行成本、途经节点、目标节点与结束位置。
- S5：提供宗门节点权限、建筑使用权限。
- S6：提供节点产出进入宗门库存。
- S7：作为宗门行动目标与结果回写对象。
- S10：挂载节点事件、危机、秘境窗口和控制权变更。
- S11：挂载后手、遗产、隐藏层。
- S13：提供多人间接竞争的节点控制和资源名额基础。
- S14：持久化节点、边、槽位和可见性状态。

## 13. MVP 验收标准

1. 半固定种子地图能生成核心宗门、主路线和关键节点。
2. 节点间有向带权通行可被 S3 读取。
3. 至少一种资源槽可被宗门开采并写入库存。
4. 至少一种建筑槽可被建设或使用。
5. 至少一次节点控制权或影响力变化可被事件驱动。
6. 至少一个隐藏层可通过探索或后手感应揭示。
