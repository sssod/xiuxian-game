- 文档类型：子系统设计案草稿
- 当前状态：第一版草稿；用于讨论，不视为最终定案
- 所属项目：修仙轮回沙盒
- 上位页面：项目总览与顶层设计定案
- 前置依赖：S3 个人行动经济与通行子系统收尾版

### 0.1 属性、资源、物品一致性约束

S4 会涉及修为、心境、肉身、功法、突破资源、护法、地点、宗门支持、因果、前世经验等概念。当前这些内容只有顶层设计中的部分描述，因此本页遵循以下约束：

1. S4 只把这些概念作为“突破输入维度”和“跨系统接口占位”，不在本页定义完整角色属性系统。
2. S4 不新增独立物品系统，不定义丹药、法器、材料、功法玉简等物品的品质、稀有度、堆叠、耐久、交易或库存规则。
3. S4 不重写宗门资源系统。宗门资源仍遵循顶层已定的灵石、修炼资源、材料 / 矿材、人力 / 弟子规模、声望 / 影响力方向。
4. S4 不把贡献设计成货币，也不假设贡献可以直接兑换突破资源。
5. S4 可以提出“需要某类突破资源 / 护法力量 / 地点条件 / 宗门培养支持”，但具体由后续 S2、S5、S6、S8、S9、S11 或平衡文档定义。
6. 如果后续角色属性、资源或物品系统与本页草案冲突，以专门子系统定案为准，S4 只保留突破事件链接口。

## 1. 子系统定位

S4 负责将“突破”从简单概率按钮改造为高价值插入事件链。

一句话定位：

> S4 决定玩家何时可以尝试突破、突破前需要准备什么、突破过程中发生什么、失败为什么发生、结果如何影响本世与后世。
> 

S4 的核心价值不是制造单次随机成败，而是让玩家在多个季度中围绕突破进行准备、取舍、冒险和复盘，并在失败后得到可解释、可修正、可跨世利用的反馈。

## 2. S4 负责 / 不负责

### 2.1 S4 负责

- 定义突破事件链的标准结构。
- 定义突破前准备维度的系统分类。
- 定义 MVP 两段关键突破链的骨架：M1 → M2、M2 → M3。
- 定义突破触发条件的类型，不定义具体阈值。
- 定义突破过程中的阶段、分支入口和玩家选择类型。
- 定义突破结果类型：完美突破、正常突破、残缺突破、失败但存活、身死转世、严重失败附带真灵 / 因果 / 遗产后果。
- 定义失败原因标签，并输出给轮回账本。
- 定义与 S3 时间轴的中断、消耗、返回接口。
- 定义突破与宗门、地图节点、后手、资源、护法、日志系统的接口边界。

### 2.2 S4 不负责

- 完整修炼数值系统。
- 完整角色属性系统。
- 完整物品、库存、交易、炼丹、炼器系统。
- 宗门资源产出、库存、财政和贡献规则。
- 护法 NPC / 宗门人力的完整模拟。
- 战斗 / 斗法的复杂过程。
- 地图节点生成、灵气产出、控制权争夺公式。
- 具体突破概率、阈值、成长曲线和奖励数值。
- UI 面板字段与数据库 schema。

这些内容分别进入 S2、S5、S6、S8、S9、S10、S11、S14 或平衡文档。

## 3. 顶层突破设计原则

### 3.1 突破不是概率按钮

突破必须由“准备度门槛 + 多阶段事件链”构成。

玩家点击突破前，应已经理解：

- 哪些准备较充分。
- 哪些准备存在短板。
- 哪些风险来自角色自身。
- 哪些风险来自地点、资源、宗门、因果或外部事件。
- 本次突破可能失败在哪里。

### 3.2 失败必须可解释

突破失败不能只输出“失败”。每次失败都必须生成一个或多个原因标签。

示例标签方向：

- 修为积累不足。
- 修为纯度不足。
- 肉身承载不足。
- 心境不稳。
- 功法不合。
- 突破资源不足或不匹配。
- 护法不足。
- 地点灵气不足或不稳定。
- 宗门支持不足。
- 因果负担过重。
- 前世失败阴影未化解。
- 外部干扰过强。

这些标签进入轮回账本，成为下一世优化路线的依据。

### 3.3 失败不是纯惩罚

标准失败体验允许痛感，但必须给出修正方向。

突破失败可以造成：

- 资源损耗。
- 短期修炼受阻。
- 道伤或状态缺陷。
- 境界残缺。
- 寿元压力增加。
- 身死转世。
- 真灵受损。
- 因果加重。
- 遗产暴露或后手污染。
- 宗门职位或声望下降。
- 错过秘境 / 节点窗口。

但应避免：

- 无理由毁档。
- 核心传承永久消失且无追查路径。
- 正式布置后手无日志失效。
- 离线托管自动执行高风险突破。
- 失败后没有任何可执行的修正方向。

### 3.4 突破要反向支撑行动经济

S4 要让 S3 的 6 个朔望行动格产生真实压力。

玩家为了突破，可能需要在多个季度中选择：

- 修炼或巩固。
- 寻找突破资源。
- 改善突破地点。
- 争取宗门培养支持。
- 邀请护法或维持关系。
- 处理心境 / 因果问题。
- 回收前世后手。
- 等待秘境、灵脉、宗门窗口。

因此，突破准备应消耗时间、位置、行动格和机会成本，而不是只消耗一个抽象资源。

## 4. MVP 突破链范围

MVP 只需要完整验证两段关键突破链，不做完整高境界体系。

### 4.1 第一段：M1 → M2

默认包装可以是“第一次大境界突破 / 道基成型 / 筑基”，但规则层不绑定具体世界观词。

设计目标：

- 教会玩家突破不是概率按钮。
- 验证准备维度、突破地点、突破资源、失败标签、轮回账本。
- 让玩家第一次感受到寿元、风险、资源和地点选择压力。
- 允许失败但存活，也允许严重失败进入转世。

事件强度：中高。作为 MVP 中第一次关键突破，应该有清晰风险，但不应过早制造过重的不可逆挫败。

### 4.2 第二段：M2 → M3

默认包装可以是“凝核 / 金丹初成 / 第三大境界起点”，但规则层仍使用 M2 → M3。

设计目标：

- 验证更高层的突破准备链。
- 引入宗门高层影响、节点资源竞争、护法、突破地点和外部干扰。
- 让 M3 成为进入长老序列或等价高层决策体验的合理门槛。
- 验证突破失败对后手、宗门地位、节点局势、遗产暴露或真灵负担的长期影响。

事件强度：高。M2 → M3 应成为 MVP 中最重要的纵向目标之一，但不应作为强制终局。

## 5. 突破事件链标准结构

每次重大突破建议采用以下通用结构。具体事件文本和分支可以按境界、功法、地点、宗门、后手状态变化。

### 5.1 阶段 0：突破可尝试提示

系统根据角色状态、修炼进度和环境条件提示“可以尝试突破”或“突破准备不足”。

此阶段不等于自动突破，也不应由离线托管主动执行。

### 5.2 阶段 1：突破准备审查

系统汇总当前准备状态，向玩家展示方向性判断：

- 修为相关准备。
- 身体 / 承载相关准备。
- 心境 / 因果相关准备。
- 功法匹配。
- 突破资源。
- 护法力量。
- 突破地点。
- 宗门支持。
- 前世经验或后手辅助。

此处只展示定性风险与短板，不需要在第一版中展示具体数值。

### 5.3 阶段 2：突破方案锁定

玩家选择是否正式开始突破，并确认突破地点、资源投入、护法安排、是否动用后手、是否请求宗门支持。

锁定后生成突破事件链，并通过 S3 中断或接管当前季度行动时间轴。

### 5.4 阶段 3：入定 / 引动 / 凝练

突破正式开始。系统消耗或占用相应资源、行动格、地点状态、护法承诺和事件窗口。

此阶段主要检验角色自身准备与资源匹配。

### 5.5 阶段 4：内劫 / 心魔 / 因果扰动

突破进入不稳定阶段。根据心境、因果、前世失败经验、功法缺陷、外部压力等因素触发事件选择。

事件选择不应变成纯文字分支，而应与准备维度、失败标签和后续结果绑定。

### 5.6 阶段 5：外扰 / 护法 / 地点事件

如果地点、宗门、节点事件或敌对势力存在外部压力，可在此阶段插入干扰。

MVP 中不需要复杂战斗系统。外扰可以作为高风险事件链结算：护法是否足够、宗门是否支持、地点是否安全、玩家是否提前布置。

### 5.7 阶段 6：成败定型

系统根据准备维度、阶段选择、事件干扰和风险承受，生成突破结果。

结果至少分为：

- 完美突破。
- 正常突破。
- 残缺突破。
- 失败但存活。
- 身死转世。
- 严重失败并附带真灵受损、因果加重或遗产暴露。

### 5.8 阶段 7：后处理与记录

系统写入：

- 角色新状态。
- 境界变化。
- 资源消耗。
- 伤势 / 道伤 / 残缺状态。
- 位置与季度结束状态。
- 宗门声望 / 职位影响。
- 节点状态变化。
- 轮回账本失败原因或突破经验。
- 世界日志与玩家可见传闻。

## 6. 准备度维度草案

本节只定义准备维度，不定义公式。

### 6.1 角色自身维度

- 修为积累：是否达到尝试突破的基本量级。
- 修为纯度：修炼质量、杂质、速成副作用等方向。
- 肉身承载：身体是否能承受突破冲击。
- 心境稳定：是否存在心魔、执念、恐惧、前世阴影。
- 功法匹配：当前功法是否支持目标阶段突破。
- 寿元压力：是否因寿元逼近而被迫冒险突破。

### 6.2 外部支持维度

- 突破资源：丹药、灵材、阵材、功法辅助、一次性消耗物等的抽象输入，不在本页定义物品系统。
- 护法力量：宗门、NPC、弟子、道侣、护道人或阵法守护提供的安全支撑，不在本页定义 NPC 模拟。
- 突破地点：洞府、灵脉、宗门静室、秘境节点、前世布置地点等。
- 节点灵气：节点环境对突破的支持或干扰。
- 宗门培养支持：宗门资源调度、名额、护法、场地、阵法、声望背书。

### 6.3 跨世与隐藏维度

- 前世失败经验：可减轻同类失败原因，或提供警示提示。
- 真灵强度：作为跨世主体的长期底层支撑，具体规则进入 S2。
- 因果负担：可能放大心魔、外扰或突破不稳。
- 正式后手辅助：前世洞府、接引阵、突破资源、护道人安排等，具体追踪进入 S11。

### 6.4 维度使用原则

每个准备维度应可以产生三类作用：

1. 提高成功质量。
2. 降低某类失败风险。
3. 在失败后生成可解释标签。

S4 不要求每次突破都检查所有维度，但重大突破至少要覆盖角色自身、外部支持和跨世反馈三个层面。

## 7. MVP 突破阶段草案

### 7.1 M1 → M2：第一次大境界突破

建议阶段：

1. 瓶颈感知：玩家发现普通修炼收益下降或进入瓶颈。
2. 准备审查：系统提示关键短板。
3. 地点选择：宗门静室、普通洞府、灵气节点、秘境环境等。
4. 资源确认：消耗或占用突破资源。
5. 入定凝练：检验修为积累与纯度。
6. 心境扰动：检验心境、前世经验和因果负担。
7. 承载定型：检验肉身、功法匹配和地点支持。
8. 结果写入：突破、残缺、失败、身死或其他后果。

主要失败标签：修为虚浮、纯度不足、肉身不足、心境不稳、功法不合、资源不足、地点不足、因果干扰。

### 7.2 M2 → M3：第三大境界起点突破

建议阶段：

1. 大瓶颈形成：普通成长进入平台，需要更系统的突破准备。
2. 破境方案准备：玩家围绕资源、护法、地点、宗门支持、后手辅助进行多季度规划。
3. 突破名额 / 宗门支持确认：如果角色依赖宗门平台，需要宗门权限、资源或护法。
4. 地点与窗口确认：选择宗门核心节点、灵脉、秘境窗口或前世布置点。
5. 凝核前置：检验修为、纯度、功法和资源匹配。
6. 内劫 / 心魔 / 因果：检验心境、前世失败经验、因果负担。
7. 外扰 / 护法：检验护法力量、宗门支持、地点安全和节点局势。
8. 成色定型：输出完美、正常、残缺、失败或严重失败。
9. 后果扩散：影响宗门职位、节点传闻、资源消耗、轮回账本、后手安全。

M2 → M3 应比 M1 → M2 更强调外部世界：宗门资源、节点控制、突破地点、护法、后手、竞争宗门和世界传闻。

## 8. 失败类型与结果分层

### 8.1 轻失败

突破未成，但角色保留大部分行动能力。

可能结果：资源损耗、短期修炼受阻、心境波动、需要休整。

### 8.2 中失败

突破未成，并产生明确代价。

可能结果：道伤、瓶颈加深、寿元压力上升、宗门评价下降、错过窗口、需要特殊资源修复。

### 8.3 残缺突破

突破成功进入新阶段，但留下结构性缺陷。

可能结果：战力或成长上限受限、后续修复需求、特殊缺陷标签、宗门评价复杂化。

残缺突破不是简单失败，而是一种可继续游玩的分支。它应该提供后续修复、补全或转世优化空间。

### 8.4 身死转世

突破失败导致本世结束，进入轮回流程。

必须写入：死亡原因、突破失败标签、保留的内在继承、可能暴露或遗留的外在资产、下一世可感应或追查的信息。

### 8.5 严重失败

严重失败可以与身死转世叠加，也可以在角色存活时发生。

可能结果：真灵受损、因果加重、核心后手暴露、遗产被污染、宗门关系破裂、节点灾变、世界传闻扩散。

严重失败必须有原因链，不允许无日志地摧毁正式后手或核心传承。

## 9. 轮回账本与前世经验接口

### 9.1 写入内容

每次重大突破都应写入轮回账本摘要。

成功写入：

- 突破阶段。
- 关键准备来源。
- 突破地点。
- 资源与护法方向。
- 是否动用后手。
- 成功质量。
- 对后续路线的提示。

失败写入：

- 失败阶段。
- 失败原因标签。
- 已消耗资源方向。
- 是否因外部干扰失败。
- 是否与前世因果相关。
- 是否产生遗产、后手、宗门或节点后果。
- 下一世可利用的经验提示。

### 9.2 前世经验作用

前世经验不应直接保证成功。它可以：

- 提前暴露风险提示。
- 降低重复踩同类坑的概率或严重度。
- 解锁特殊准备方向。
- 提供对关键地点、资源或事件的感应。
- 在事件链中提供额外选择。

具体作用强度进入 S2 / S11 / 平衡文档。

## 10. 与 S3 行动时间轴的接口

### 10.1 触发入口

S4 可以通过以下方式进入：

1. 玩家在角色行动阶段选择突破相关持续行动。
2. 玩家在季度结算中达到突破触发条件并确认尝试。
3. 特定地点、秘境、后手或宗门支持使突破事件链可用。
4. 剧情或节点事件诱导玩家提前或被迫面对突破选择。

离线 / 超时托管不得主动发起高风险突破。

### 10.2 S3 提供给 S4

S3 至少提供：

- 角色所在节点。
- 当前 tick。
- 剩余行动格。
- 当前持续行动状态。
- 是否处于移动、停靠、目标节点或特殊地点。
- 季度计划是否已被其他事件中断。
- 托管状态。
- 暴露上下文。
- 季度结束位置候选。

### 10.3 S4 返回给 S3

S4 至少返回：

- 是否继续原计划。
- 是否消耗剩余行动格。
- 是否强制终止本季度计划。
- 是否改变角色位置。
- 是否改变连续状态。
- 是否进入休整、重伤、闭关、转世或特殊状态。
- 最终季度结束位置。
- 需要记录到可回放时间轴的事件摘要。

### 10.4 时间语义

突破事件链可以暂停、接管或终止普通季度计划。

MVP 中建议：重大突破一旦正式开始，通常会接管本季度剩余行动，并在事件链结束后返回一个明确的季度结果。是否跨季度延续作为后续扩展，不在第一版中定数值。

## 11. 与其他子系统的接口

### 11.1 与 S2 玩家角色、真灵与轮回

S2 定义真灵、角色状态、内在继承、前世经验、因果债务等。S4 只读取这些状态并写入突破经验或失败后果。

### 11.2 与 S5 宗门组织、职位与权限

S5 决定玩家是否有资格申请宗门突破场地、护法、名额、资源或长辈支持。S4 不定义职位体系。

### 11.3 与 S6 宗门财政、资源与库存

S6 决定宗门资源是否真实存在、是否可调拨、是否消耗。S4 只请求“突破资源是否满足 / 是否被消耗 / 是否被占用”。

### 11.4 与 S7 宗门行动与执行完成度

如果宗门行动为玩家突破提供护法、驻守、建设、资源调度或地点控制，S7 负责组织层行动的执行完成度。S4 只读取其结果。

### 11.5 与 S8 地图节点、资源槽与建筑槽

S8 决定突破地点、灵气节点、洞府、静室、秘境入口、阵法建筑等地点条件。S4 读取地点上下文，不定义地图规则。

### 11.6 与 S9 物品、装备与资源使用

S9 决定丹药、灵材、法器、功法玉简等物品的身份、品质、使用规则和库存。S4 只表达突破资源需求与消耗结果。

### 11.7 与 S10 节点事件与世界事件

S10 决定突破期间是否触发节点危机、秘境关闭、灵气波动、妖兽袭扰、宗门冲突或世界传闻。S4 可以请求外部干扰判定，但不拥有完整事件表。

### 11.8 与 S11 前世后手与隐藏层

S11 决定前世洞府、接引阵、护道人、遗书、突破资源封存、秘境线索等后手是否可用、是否暴露、是否被污染。S4 读取后手辅助结果，并写入可能的暴露或污染原因。

### 11.9 与 S14 存档、数据结构与技术架构

S14 负责存档、回放、日志和结算追踪。S4 必须输出可复盘的突破摘要与失败标签。

## 12. 服务端权威结算与日志要求

突破事件链必须由服务端权威结算。

### 12.1 服务端必须记录

- 突破触发时间。
- 突破地点。
- 角色状态摘要。
- 准备维度摘要。
- 资源与护法输入摘要。
- 阶段选择。
- 外部干扰来源。
- 成败结果。
- 失败原因标签。
- 轮回账本写入内容。
- 世界日志与玩家可见传闻。

### 12.2 日志分层

- 结算日志：服务端调试与回放使用，包含完整关键判定摘要。
- 轮回账本：玩家长期复盘使用，记录突破经验与失败原因。
- 玩家当世日志：本世角色可见的事件结果。
- 世界传闻：其他玩家或宗门可能听到的可见子集。

S4 不决定所有可见性规则，只提供日志内容与敏感标签，由 S13 / S14 处理展示与多人可见性。

## 13. MVP 验收用例

### 13.1 M1 → M2 正常突破

玩家经过数个季度准备，在合适地点使用突破资源并成功突破。系统写入突破经验，角色进入 M2。

验证点：准备审查、事件链阶段、资源消耗、角色状态更新、日志写入。

### 13.2 M1 → M2 失败但存活

玩家准备不足或选择冒险突破，失败但存活。系统输出明确失败标签，并给出下一步修正方向。

验证点：失败可解释、轮回账本记录、角色可继续游玩。

### 13.3 M2 → M3 残缺突破

玩家在外部支持不足或心境存在缺陷时突破成功但残缺。角色进入 M3 起点，但带有后续修复需求。

验证点：残缺突破作为可游玩分支，不是简单失败。

### 13.4 M2 → M3 严重失败并转世

玩家在高风险条件下突破失败，本世结束并进入转世。失败原因、遗产状态、正式后手追查路径进入轮回账本。

验证点：死亡不等于毁档；失败原因可追踪；后手不无理由消失。

### 13.5 突破被外部事件干扰

玩家选择的突破地点出现节点事件、宗门冲突或秘境窗口变化。S4 接收 S10 / S8 / S7 的外部上下文，生成事件链分支。

验证点：突破链能与世界演化产生交互。

### 13.6 离线托管不主动突破

玩家离线时达到突破可尝试状态，托管不自动发起高风险突破，而是维持安全行动或准备状态。

验证点：托管安全边界成立。

## 15. Handoff 摘要

S4 的第一版目标是确认突破作为高价值插入事件链的系统骨架。

当前草稿建议定案方向：

1. MVP 只完整验证 M1 → M2 与 M2 → M3 两段关键突破链。
2. 突破采用准备度门槛 + 多阶段事件链。
3. 重大突破可以中断、接管或终止 S3 季度行动时间轴。
4. 突破准备维度只作为接口占位，不在 S4 中定义完整角色属性、资源或物品系统。
5. 失败必须输出原因标签，并写入轮回账本。
6. 残缺突破、失败但存活、身死转世和严重失败都应是可复盘、可继续推进长期体验的结果。
7. S4 需要 S2、S5、S6、S8、S9、S10、S11、S14 后续补齐属性、宗门、资源、节点、物品、事件、后手和日志实现。

下一步建议：先讨论 S4 的“突破链阶段结构”和“MVP 两段突破链强度”，暂不进入数值和平衡。
