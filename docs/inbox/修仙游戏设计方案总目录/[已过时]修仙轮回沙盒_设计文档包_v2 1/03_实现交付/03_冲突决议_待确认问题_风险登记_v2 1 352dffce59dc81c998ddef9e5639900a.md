# 冲突决议、待确认问题与风险登记（v2.1）

## 0. 文档定位

本文记录新版整理中发现并处理的设定冲突、变量命名冲突、范围冲突和仍需人工确认的问题。

开发阶段建议把本文作为“v2.1 临时定版口径”。

---

## 1. 已消解的关键冲突

### 1.1 玩家最小回合冲突

旧口径：

```
季度是玩家最小行动回合。
每季度 6 个朔望行动格。
```

新版决议：

```
玩家最小推进单位统一称为回合。
回合时长可配置，当前默认 5 个游戏天。
UI 显示天级时间预算条。
服务端以小时作为内部结算单位。
```

### 1.2 5 天是否世界观包装

决议：

- 5 天只是配置值，不使用“一候”等世界观包装。
- 不以 5 天重新标定世界观时间体系。
- 未来可配置为 3 / 7 / 10 天。

### 1.3 行动格术语冲突

旧字段：

```
action_slot / remaining_action_slots / 6 个朔望行动格
```

新版决议：

- 废弃行动格作为规则单位。
- 使用 `planned_duration_hours`、`planned_duration_days`、`remaining_hours`。
- UI 使用 `TurnTimeBudgetBar`。

### 1.4 tick 语义冲突

旧口径中 tick 有时表示行动格，有时表示内部结算单位。

新版决议：

- 内部结算单位明确为小时。
- 推荐字段 `world_hour` / `hour_tick`。
- 事件结果使用 `consumed_hours`。

### 1.5 宗门行动数量冲突

旧口径：

```
每个宗门每季度始终只有 1 个宗门主行动。
玩家可提交宗门建议 / 提议 / 决策意图。
```

新版决议：

```
每个宗门同一时间最多 1 个宗门持续行动。
宗门持续行动可跨多个回合推进。
宗门持续行动由宗门 AI 自行选择、推进、中止或完成。
移除玩家宗门即时指令和宗门主行动输入流程。
```

### 1.6 宗门高地位价值冲突

旧风险：高地位玩家若不能输入宗门行动，会显得权力不足。

新版决议：

高地位价值改为：

- 更多宗门情报。
- 更高资源申请权限。
- 更容易触发议事 / 委派 / 宗门支持事件。
- 对宗门 AI 倾向有更高被动影响权重。
- 更容易通过个人行动影响宗门节点和持续行动。

### 1.7 短耗时行动限制冲突

曾考虑加入短行动次数槽或轻事务额度。

新版决议：

- 不额外限制短耗时持续行动次数。
- 所有行动只按实际耗时占用回合时间预算。
- 通过内容设计避免单节点出现大量可执行短行动。

### 1.8 玩家排程粒度冲突

决议：

- 玩家不排小时表。
- 一般指令以天级预算条表达。
- 小时只用于服务端统计碎片化耗时、事件延误和后续指令触发时点。

### 1.9 宏观世界刷新冲突

风险：把所有世界刷新都绑定到默认 5 天回合，会导致世界过快变化。

决议：

- 玩家同步单位是回合。
- 世界宏观刷新使用 `macro_period_id` 或专用窗口。
- 资源再生、N4 宏观行动、宗门战略变化不必每回合全量执行。

## 2. 继续沿用的旧决议

以下旧决议仍保留：

- MVP 边界为本地单人测试 + 私人服务器 + 3 人共玩 + M0→M3。
- M0–M3 是体验里程碑，不等于境界编码。
- 规则层境界使用 A/B/C，不用中文包装名做规则判断。
- 精力 `base_vigor` 与元气 `bar_qi` 分离。
- 悟性统一为 `aptitude_comprehension`，不使用 `base_comprehension`。
- 灵石不分等级，高密度灵气由聚灵石表达。
- 不设计半可堆叠物品。
- MVP 不引入背包容量、装备栏、重量负重。
- 商店库存不属于掌柜个人。
- MVP 不引入宗门内部派系。
- 山门核心节点常态不被 AI 普通行动夺取。
- 正式后手不做无原因随机磨损。
- MVP 多人是分宗并行 + 间接竞争 + PvE 沙盒演化。

## 3. 仍需人工确认的问题

### 3.1 存档格式

待定：

- SQLite。
- Godot Resource / JSON。
- 混合方案。

建议尽快决策，因为这会影响服务器保存、调试查询、版本迁移和数据驱动工作流。

### 3.2 行动模板耗时表

待定：

- 常见移动、采购、探索、修炼、研习、采集的默认小时数。
- 固定执行时间行动的跨回合规则。
- 炼丹 / 炼器中断后的材料损耗和暂停规则。

### 3.3 宗门 AI 权重表

待定：

- 宗门 AI 选择持续行动的权重因素。
- 高身份玩家对 AI 的影响权重。
- 关键 NPC 意图和宗门战略倾向如何合并。

### 3.4 功法等级结构

待定：

- 固定等级。
- 阶段式熟练度。
- 篇章 / 层数解锁。
- 混合结构。

### 3.5 寿元 MVP 最小实现

待定：

- 只实现突破延寿。
- 同时实现延寿丹 / 延寿灵物。
- 寿元压力显式状态是否使用 safe / pressured / urgent / exhausted。

## 4. 风险登记

### R1：2 分钟决策仍可能被信息阅读拖垮

缓解：

- 回合开始报告分优先级。
- 默认延续上一回合安全指令。
- 只强提示影响本回合决策的信息。

### R2：宗门 AI 变得不可理解

缓解：

- 宗门面板显示当前持续行动、进度、风险、可亲自介入机会。
- 不展示完整 AI 推理，但展示可理解摘要。
- 宗门日志记录关键状态变化。

### R3：短耗时行动自由安排导致节点内容过载

缓解：

- 内容设计层控制单节点行动入口数量。
- 细碎行为合并为高层行动入口。
- UI 只显示与当前位置、目标、可达性相关的行动。

### R4：小时级结算增加实现复杂度

缓解：

- 玩家 UI 不显示小时排程。
- 只在服务端时间线和报告中使用小时。
- MVP 先实现移动延误、事件耗时、可选投入结算三类核心用途。

### R5：字段迁移遗漏

缓解：

- 先按字段迁移表统一命名。
- Debug 面板同时显示旧字段迁移警告。
- 旧文档引用时优先查术语表。
