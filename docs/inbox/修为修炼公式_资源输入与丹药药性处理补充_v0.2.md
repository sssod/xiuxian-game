# 修为修炼公式补充：行动资源输入与丹药药性处理 v0.2

> 文档定位：本文是功法与修炼系统的补充稿，专门收敛“丹药、灵材、符箓、临时增益资源如何进入行动结算”这一部分。本文承接当前 v2.1 的回合时间预算、小时级服务端结算、个人行动指令、事件结果包、资产容器与资源使用日志口径。

---

## 0. 版本结论

本版最终收敛为：

```text
丹药、灵材、符箓、临时增益资源，不优先设计为独立持续行动。
它们统一作为“行动资源输入项”挂载到对应行动或事件选项上。
```

典型对应关系：

```text
修为丹药 → 主动吐纳的额外资源输入
临时悟性丹 → 研习功法的额外资源输入
解毒丹 / 避瘴丹 → 毒瘴区域移动、探索、采集、战斗语境的额外资源输入
疗伤丹 → 休整 / 治疗 / 医疗事件选项的额外资源输入
定心丹 → 巩固根基 / 突破准备 / 突破事件链选项 / 研习功法的额外资源输入
战斗丹药 → 战斗事件链指令或战斗准备输入
```

明确不做：

```text
MVP 不设计独立持续行动：丹药炼化。
MVP 不允许即时服用修为丹药后直接增加修为。
MVP 不允许丹药绕过时间预算产生收益。
```

原因：

```text
如果“丹药炼化”和“主动吐纳时使用修为丹药”的转化率一致，
则绝大多数情况下主动吐纳都优于丹药炼化。
独立“丹药炼化”会成为低价值、低使用率、增加 UI 和规则复杂度的冗余入口。
```

因此，资源系统的统一问题不是“是否要单独炼化丹药”，而是：

```text
某个资源能否作为当前行动的输入？
它在当前行动实际执行了多少小时？
剩余效果是否保留、散逸、转为压力，或被止损收束？
```

## 1. 行动资源输入项

### 1.1 定义

行动资源输入项是指：

```text
玩家在规划某个行动时，选择额外投入一类资源。
该资源在行动实际执行期间，按兼容小时生效，进入该行动专属结算管线。
```

示例：

```text
行动：主动吐纳 2 天
额外输入：清灵丹 × 1

行动：研习《青木养真诀》1 天
额外输入：启悟丹 × 1

行动：探索毒瘴谷，投入剩余时间
额外输入：避瘴丹 × 1
```

行动资源输入项不改变行动本身的类型：

```text
主动吐纳仍然是可选投入持续行动。
研习功法仍然是可选投入持续行动。
探索仍然是可选投入持续行动。
战斗仍然是事件链。
```

资源只是挂载在这些行动 / 事件上的输入，不单独成为默认行动入口。

---

### 1.2 总效果公式

资源输入的基础模型为：

```text
资源效果总量 = 单位增量 × 最大有效时长
```

实际结算为：

```text
本次应用效果 = 单位增量 × 实际兼容小时 × 品质修正 × 状态修正
```

字段解释：

```text
unit_effect_rate：每小时释放多少灵气、提供多少悟性修正、抵消多少毒瘴压力等。
max_effective_hours：该资源最多能在兼容语境中生效多少小时。
applied_effective_hours：本次行动中实际消耗的有效小时。
```

示例：

```text
清灵丹
unit_aura_rate = 20 / hour
max_effective_hours = 12
总灵气量 = 20 × 12 = 240
```

```text
启悟丹
temporary_comprehension_bonus = +15
max_effective_hours = 8
效果 = 在最多 8 小时研习中提供 +15 悟性修正
```

```text
避瘴丹
miasma_resist_rate = 1.0 / hour
max_effective_hours = 24
效果 = 在最多 24 小时毒瘴暴露语境中提供防护
```

## 2. “持续时间”的解释

### 2.1 默认不是无条件世界小时

`max_effective_hours` 默认不表示“服下后经过多少世界小时就必定消耗完”。

它表示：

```text
该资源在兼容行动或兼容语境中最多能生效多少小时。
```

因此：

```text
修为丹药只在主动吐纳实际执行时释放修为灵气包。
悟性丹只在研习功法实际执行时提供悟性修正。
避瘴丹只在毒瘴暴露语境中消耗有效时长。
```

这样可以避免玩家因为事件延误、移动插入、行动未开始而无意义损失资源。

---

### 2.2 三种计时模式

建议资源模板使用：

```text
effect_tick_mode:
- compatible_action_hours
- hazard_exposure_hours
- world_elapsed_hours
```

#### compatible_action_hours

用于：

```text
修为丹药
悟性丹
疗伤丹
定心丹
```

规则：

```text
只有行动标签匹配时，才消耗有效时长。
```

#### hazard_exposure_hours

用于：

```text
避瘴丹
解毒丹
防寒 / 防火 / 防腐蚀资源
```

规则：

```text
只有角色实际暴露在对应危险语境中，才消耗有效时长。
```

#### world_elapsed_hours

用于：

```text
强制释放型丹药
危险剧情丹药
高阶破关资源
```

规则：

```text
服用后按世界小时持续释放。
即使没有兼容行动，也会消耗效果，并可能转为浪费、压力或反噬。
```

MVP 不使用 `world_elapsed_hours` 作为常规资源模型，只预留字段。

## 3. 修为丹药处理规则

### 3.1 修为丹药只挂载主动吐纳

定版规则：

```text
修为类丹药只能作为主动吐纳的额外输入项。
不提供独立“丹药炼化”行动。
不允许在主动吐纳之外手动服用修为丹药来获得修为。
```

合法：

```text
主动吐纳 24 小时，附加清灵丹 × 1。
```

非法：

```text
即时服用清灵丹，立即获得修为。
单独执行丹药炼化 12 小时。
移动途中服用清灵丹，持续获得修为。
```

---

### 3.2 修为丹药跳过道功吸收环节

主动吐纳中存在两条输入流：

```text
环境灵气流：
节点灵气 / 聚灵阵 / 灵液池
→ 受道功吸收速度限制
→ 进入转化与承载

修为丹药资源流：
丹药自身提供定额灵气包
→ 跳过道功吸收速度
→ 直接进入转化与承载
```

因此修为丹药不是：

```text
提高节点灵气浓度。
提高聚灵阵效果。
简单提高最终转化倍率。
```

它是：

```text
主动吐纳行动期间额外释放的定额灵气输入。
```

---

### 3.3 主动吐纳公式关系

环境灵气输入：

```text
environment_aura_input =
actual_hours
× min(
    node_aura_density + facility_aura_density_bonus + temporary_aura_bonus,
    dao_base_absorption_rate × mastery_absorption_factor × state_factor
  )
```

修为资源输入：

```text
cultivation_resource_aura_input =
Σ(unit_aura_rate_i × applied_effective_hours_i × resource_quality_factor_i)
```

合流：

```text
raw_aura_input =
environment_aura_input + cultivation_resource_aura_input
```

之后统一进入：

```text
根骨安全承载
根骨转化效率
灵根与道功相性
道功基础转化率
状态修正
修为进度
修炼压力
```

---

### 3.4 主动吐纳时间短于丹药有效时长

如果主动吐纳实际执行时长少于丹药 `max_effective_hours`，只结算实际执行部分。

示例：

```text
行动：主动吐纳 6 小时
资源：清灵丹 × 1
清灵丹：unit_aura_rate = 20 / hour，max_effective_hours = 12

本次释放灵气：20 × 6 = 120
剩余有效时长：6 小时
剩余可释放灵气：120
```

剩余药性进入：

```text
ActiveResourceEffect
```

后续只能在兼容行动中继续使用。对于修为丹药，兼容行动默认是：

```text
主动吐纳
```

巩固根基可以选择性“收束”剩余修为药性，但收束不产生修为进度。详见第 6 节。

## 4. 其他资源类型的统一处理

### 4.1 临时悟性丹

对应行动：

```text
研习功法
```

作用方式：

```text
在兼容行动实际执行期间，临时提高 aptitude_comprehension 的计算值，
或直接提高 method_exp_gain 的悟性修正项。
```

推荐模板：

```text
启悟丹
compatible_action_tags = [study_method]
temporary_comprehension_bonus = +15
max_effective_hours = 8
residual_policy = stable_suspend / slow_decay
```

如果研习功法实际执行 3 小时：

```text
启悟丹只生效 3 小时。
剩余 5 小时效果进入 ActiveResourceEffect。
```

如果之后玩家去移动或探索：

```text
启悟丹不继续产生功法经验。
根据 residual_policy 暂存或衰减。
```

---

### 4.2 解毒丹 / 避瘴丹

对应行动或语境：

```text
毒瘴区域探索
毒瘴区域移动
毒瘴区域战斗事件链
毒瘴节点采集
```

这类资源不只看行动类型，还要看上下文：

```text
context_tags 包含 miasma / poison / toxic_area
```

推荐模板：

```text
避瘴丹
compatible_action_tags = [explore, movement, gather, combat_event]
compatible_context_tags = [miasma, toxic_area]
effect_tick_mode = hazard_exposure_hours
max_effective_hours = 24
```

含义：

```text
只有角色实际处于毒瘴暴露语境时，避瘴丹才消耗有效时长。
```

---

### 4.3 定心丹

对应行动或语境：

```text
研习功法
巩固根基
突破准备
大境界突破事件链中的资源选项
```

作用方式：

```text
降低 mind_unstable 风险。
降低心神扰动。
提高神念稳定相关检定。
```

MVP 中建议先把定心丹作为：

```text
巩固根基 / 突破准备 / 研习功法 / 突破事件链选项 的额外输入项。
```

不作为普通主动吐纳的修为收益资源。

---

### 4.4 疗伤丹

对应行动或语境：

```text
休整
治疗
医疗事件选项
战斗后救治选项
```

作用方式：

```text
提高生机恢复。
降低伤势持续时间。
降低行动期间伤势恶化风险。
```

疗伤丹不提高修为。

---

## 5. 残余效果 ActiveResourceEffect

### 5.1 生成条件

当资源已经消耗，但其效果没有在本次行动中完全用完时，生成：

```text
ActiveResourceEffect
```

它不是独立行动，而是角色身上的临时资源效果状态。

生成场景：

```text
行动实际时长少于资源最大有效时长。
行动开始后被事件打断。
行动中部分小时不满足资源兼容语境。
```

不生成场景：

```text
带资源输入的行动没有实际开始。
服务端校验未通过，资源没有消耗。
```

---

### 5.2 数据结构建议

```text
ActiveResourceEffect {
  effect_id: String,
  character_id: String,
  source_item_ref: String,
  source_item_template_id: String,

  effect_type: cultivation_aura / comprehension_boost / detox_protection / mind_stabilize / healing_support,

  unit_effect_rate: float,
  remaining_effective_hours: float,
  remaining_effect_amount: float,

  compatible_action_tags: Array,
  compatible_context_tags: Array,
  effect_tick_mode: compatible_action_hours / hazard_exposure_hours / world_elapsed_hours,

  residual_policy: stable_suspend / slow_decay / stimulating_decay / forced_release,
  residual_stability_hours: float,
  idle_world_hours: float,

  can_be_settled_by_consolidation: bool,
  settlement_policy: none / suppress_side_effect / release_without_progress,

  affinity_tags: Array,
  stimulation_level: String,
  stability_level: String,

  consumed_turn_id: int,
  consumed_world_day: int,
  consumed_world_hour: int,
  last_applied_world_hour: int,

  state: active / suspended / decaying / exhausted
}
```

`remaining_effect_amount` 通常可由以下公式推导：

```text
remaining_effect_amount = unit_effect_rate × remaining_effective_hours
```

也可以在高阶资源中单独存储，用于支持非线性衰减。

---

### 5.3 四种残余策略

#### stable_suspend：稳定暂存

适合：

```text
普通清灵丹
普通启悟丹
低刺激养元类资源
```

规则：

```text
非兼容行动期间不生效。
在 residual_stability_hours 内不明显损失。
超过后缓慢散逸。
```

#### slow_decay：缓慢散逸

适合：

```text
品质较差丹药
保存状态一般的灵材
普通但不完全稳定的临时增益资源
```

规则：

```text
非兼容行动期间不生效。
remaining_effect_amount 会缓慢减少。
通常只产生轻微疲劳或药力浪费。
```

#### stimulating_decay：刺激性衰减

适合：

```text
速成修为丹
烈性火系丹药
高刺激破关资源
```

规则：

```text
非兼容行动期间不生效。
剩余药性会较快衰减。
衰减部分可能转为经脉压力、疲劳、神念扰动。
```

用途：

```text
要求玩家安排连续主动吐纳。
强化速成资源的风险感。
```

#### forced_release：强制释放

适合：

```text
高阶危险丹药
剧情丹药
强行破关资源
```

规则：

```text
服用后按世界小时持续释放。
即使不进行兼容行动，也会消耗药性。
未被行动结算吸收的部分转为浪费、压力或反噬。
```

MVP 不作为常规内容使用。

## 6. 残余效果跨回合规则

### 6.1 允许跨回合

定版规则：

```text
ActiveResourceEffect 允许跨行动、跨回合保存。
```

但它受以下字段限制：

```text
residual_policy
residual_stability_hours
idle_world_hours
remaining_effective_hours
remaining_effect_amount
```

理由：

```text
如果主动吐纳被事件打断，或者本回合剩余时间不足，
玩家不应该因为服务端小时级结算误差而直接损失整枚丹药。
```

---

### 6.2 决策阶段不推进药性衰减

回合结算结束后，进入下一回合报告与行动规划阶段时，游戏内时间暂停。

因此：

```text
玩家阅读报告、查看地图、规划行动、等待其他玩家锁定期间，
不会推进 idle_world_hours。
```

`idle_world_hours` 只在服务器结算阶段、世界小时实际推进时增加。

这与回合制时间预算一致：玩家最小同步单位是回合，服务端内部以小时结算，但决策阶段不推进世界时间。

---

### 6.3 下一回合如何继续承接

如果角色体内仍有修为丹药残余：

```text
下一回合规划主动吐纳
→ 可继续承接剩余药性。
```

示例：

```text
第 5 回合末：清灵丹剩余 6 小时药性。
第 6 回合开始：时间暂停，药性不衰减。
玩家规划：主动吐纳 6 小时。
第 6 回合结算：承接剩余药性，清灵丹耗尽。
```

如果下一回合先执行移动、探索、采购等非兼容行动：

```text
移动 / 探索 / 采购消耗的世界小时会计入 idle_world_hours。
超过稳定窗口后，药性按 residual_policy 衰减。
```

---

### 6.4 跨回合保存与存档

`ActiveResourceEffect` 必须进入角色状态并随存档保存。

最小保存字段：

```text
source_item_template_id
remaining_effective_hours
residual_policy
residual_stability_hours
idle_world_hours
state
consumed_turn_id
consumed_world_hour
last_applied_world_hour
```

调试回放中需要记录：

```text
资源何时消耗。
哪些小时实际生效。
哪些小时处于非兼容状态。
残余效果如何衰减或保留。
```

## 7. 巩固根基对残余修为药性的处理

### 7.1 可以收束，但不转化为修为

定版规则：

```text
巩固根基可以选择性收束残余修为药性。
收束不产生修为进度。
收束不替代主动吐纳。
收束主要用于止损、减压、稳定根基。
```

也就是说：

```text
主动吐纳：把修为药性转化为修为输入。
巩固根基：把残余药性收束为低损耗 / 低压力结局，但不涨修为。
```

---

### 7.2 默认不自动消耗稳定药性

为了避免玩家误操作，巩固根基默认不自动消耗稳定残余药性。

规则：

```text
如果残余药性是 stable_suspend，
且玩家没有勾选“收束残余药性”，
巩固根基不消耗该药性。
```

UI 应给出选择：

```text
你体内仍有清灵丹残余药性，约 6 小时。
可选择：
1. 保留药性，后续主动吐纳时继续承接。
2. 收束药性，本次巩固根基将消耗残余药性，但不产生修为进度，可降低散逸或经脉压力风险。
```

---

### 7.3 刺激型药性建议提示收束

如果残余药性是：

```text
stimulating_decay
forced_release
```

则巩固根基界面应强提示：

```text
体内烈性药性未尽，若继续移动或探索，可能快速散逸并造成经脉压力。
本次巩固根基可选择收束药性，减少副作用，但不会获得修为进度。
```

---

### 7.4 收束结算

收束残余修为药性时：

```text
settled_hours = min(action_actual_hours, effect.remaining_effective_hours)
settled_amount = effect.unit_effect_rate × settled_hours
```

但 `settled_amount` 不进入：

```text
resource_aura_input
cultivation_progress_gain
```

而进入：

```text
pressure_prevention
side_effect_reduction
residual_effect_clearance
```

建议输出：

```text
cultivation_progress_gain = 0 from residual_settlement
cultivation_pressure_delta <= 0
side_effect_risk_delta <= 0
remaining_effective_hours -= settled_hours
```

如果巩固根基本身有纯度收益，该收益来自巩固行动本身，不来自修为丹药残余。

---

## 8. 强制释放型丹药

### 8.1 不进入常规 MVP

定版规则：

```text
forced_release 不作为 MVP 常规修为资源。
MVP 只预留字段和处理分支。
```

原因：

```text
强制释放型丹药会要求更复杂的时间线、副作用、反噬、事件打断处理。
它适合高阶、危险、剧情型内容，不适合作为基础丹药模型。
```

---

### 8.2 未来适用场景

可以用于：

```text
强行破关丹
濒死续命丹
剧情传功丹
高阶邪道速成丹
秘境限时增益资源
```

这些资源的体验应是：

```text
一旦使用，就必须尽快处理。
不处理会浪费、冲脉、反噬或产生严重状态。
```

---

### 8.3 MVP 字段预留

保留：

```text
effect_tick_mode = world_elapsed_hours
residual_policy = forced_release
```

但内容表中默认不投放常规 `forced_release` 修为丹药。

如果特殊事件必须使用：

```text
只能作为事件链专用资源或剧情资源。
必须在事件文本和 UI 中明确风险。
不得作为普通背包消耗品无提示使用。
```

---

## 9. 事件选项临时追加资源输入

### 9.1 允许，但必须由事件模板声明

定版规则：

```text
事件选项允许临时追加资源输入。
但只有事件模板明确声明 resource_input_slot 时才允许。
```

示例：

```text
毒瘴战斗事件中临时服用避瘴丹。
突破交锋中临时服用定心丹。
战斗中临时服用回气丹。
医疗事件中临时使用疗伤丹。
```

---

### 9.2 不允许追溯生效

临时追加资源只能从事件选项确认后的时间点开始生效。

禁止：

```text
事件发生后，回溯让避瘴丹覆盖之前已经暴露的 5 小时。
战斗结束后，回溯使用回气丹改变已结算的交锋。
突破失败后，回溯服用定心丹重算风险。
```

---

### 9.3 资源校验与日志

事件临时追加资源必须走统一资源使用接口。

校验：

```text
角色是否持有资源。
资源是否在可调用资产容器中。
资源是否允许用于该事件选项。
是否满足位置、状态、行动、事件标签。
是否违反同类资源叠加限制。
```

成功后写入：

```text
ResourceUseRequest
ResourceUseResult
事件结果包
资产日志
角色日志 / Debug 日志
```

事件资源消耗不得绕过 S1 结果包回写。

---

### 9.4 临时追加后是否产生残余效果

由资源模板决定：

```text
allow_residual_after_event = true / false
```

建议规则：

```text
避瘴丹、定心丹、疗伤丹：可允许残余效果延续。
战斗中一次性回气丹：默认不产生残余。
突破事件链关键资源：按突破事件链定义，不进入普通 ActiveResourceEffect。
```

如果事件发生在某个父行动内，且资源仍兼容父行动：

```text
毒瘴探索 → 触发毒瘴战斗 → 临时服用避瘴丹
战斗结束后继续毒瘴探索
避瘴丹残余效果可以继续在父行动中生效
```

如果不兼容：

```text
主动吐纳被普通社交事件打断
事件中服用疗伤丹
疗伤丹不应转为主动吐纳的修为输入
```

## 10. UI 承载规则

### 10.1 采用行动内折叠项

定版规则：

```text
资源输入 UI 采用“行动内折叠项”。
玩家选择具体行动后，只显示与该行动兼容的资源输入。
```

不采用默认全局资源栏作为主入口。

原因：

```text
资源种类会快速膨胀。
全局资源栏容易变成背包搜索和倍率堆叠界面。
行动内折叠项更符合“资源服务于行动”的设计。
```

---

### 10.2 行动规划界面显示内容

主动吐纳界面示例：

```text
行动：主动吐纳
计划投入：12 小时
可用资源输入：
- 清灵丹：20 灵气 / 小时，最多 12 小时
- 木髓液：适配木系道功，释放稳定

当前选择：清灵丹 × 1
预计本次释放：12 / 12 小时
```

如果行动时间不足：

```text
行动：主动吐纳
计划投入：6 小时
当前选择：清灵丹 × 1
完整药性：12 小时
预计本次释放：6 / 12 小时
剩余：约 6 小时药性，将暂留体内
```

---

### 10.3 已有残余效果使用全局状态提示

虽然资源输入主入口在行动内，但角色已有残余效果必须在角色面板或行动规划器中常驻提示。

示例：

```text
体内仍有未尽药性：清灵丹，约 6 小时。
执行主动吐纳可继续承接。
若长时间不处理，药性可能散逸。
```

刺激型提示：

```text
体内仍有烈性药性：赤焰速元丹，约 4 小时。
非修炼行动期间可能快速散逸并造成经脉压力。
建议：继续主动吐纳或巩固根基收束。
```

---

### 10.4 事件界面显示资源选项

事件资源输入不使用行动折叠项，而是作为事件选项的附加条件或子选项显示。

示例：

```text

消耗：定心丹 × 1
效果：降低本阶段 mind_unstable 风险
风险：仍可能产生神念疲惫
```

事件选项必须明确显示：

```text
消耗什么资源。
是否立即消耗。
是否产生残余效果。
是否会中断或改变当前行动计划。
```

## 11. 行动开始、执行、中断与残余结算

### 11.1 行动开始前校验

服务端在行动实际开始前检查：

```text
1. 角色是否持有资源。
2. 资源是否在合法资产容器中。
3. 资源是否允许用于该行动。
4. 当前行动标签是否匹配 compatible_action_tags。
5. 当前地点或事件上下文是否匹配 compatible_context_tags。
6. 是否违反同类资源叠加限制。
7. 是否存在未处理的同类 ActiveResourceEffect。
```

如果校验通过：

```text
消耗资源道具。
写入资源使用日志。
创建本行动的 ActiveResourceEffect 或直接进入行动结算段。
```

如果行动没有开始：

```text
不消耗资源。
```

---

### 11.2 行动执行中按小时结算

每个行动片段结算：

```text
compatible_hours = 本片段中资源可生效的小时数
applied_hours = min(compatible_hours, effect.remaining_effective_hours)
applied_amount = effect.unit_effect_rate × applied_hours
```

根据资源类型进入不同管线：

```text
修为丹药：applied_amount → resource_aura_input
悟性丹药：applied_amount / bonus → method_exp_gain 修正
解毒丹药：applied_amount → toxic_risk_delta / poison_pressure_delta
疗伤丹药：applied_amount → vitality_recovery / injury_delta
定心丹药：applied_amount → mind_stability_delta / risk_tag_delta
```

结算后：

```text
remaining_effective_hours -= applied_hours
remaining_effect_amount -= applied_amount
```

---

### 11.3 行动中断

如果行动被事件中断：

```text
已生效部分正常结算。
未生效部分转入 ActiveResourceEffect 残留。
```

事件本身是否消耗残余效果，取决于：

```text
事件是否具有兼容 action_tag 或 context_tag。
```

示例：

```text
毒瘴探索被毒瘴妖兽战斗打断。
战斗仍发生在毒瘴环境中。
避瘴丹继续按 hazard_exposure_hours 消耗。
```

示例：

```text
主动吐纳被同门来访事件打断。
来访事件不属于主动吐纳。
清灵丹不继续释放修为灵气，剩余药性暂存或衰减。
```

---

### 11.4 非兼容行动中的残余处理

```text
if effect.residual_policy == stable_suspend:
    effect.idle_world_hours += segment_hours
    if effect.idle_world_hours > effect.residual_stability_hours:
        apply_slow_decay(effect)

if effect.residual_policy == slow_decay:
    apply_slow_decay(effect)

if effect.residual_policy == stimulating_decay:
    apply_decay(effect)
    add_cultivation_pressure_or_condition(effect)

if effect.residual_policy == forced_release:
    force_release_to_waste_or_pressure(effect, segment_hours)
```

## 12. 同类资源叠加规则

### 12.1 MVP 限制

MVP 建议：

```text
同一行动中，同一效果通道最多使用 1 个主资源输入。
```

例如：

```text
主动吐纳：最多 1 种主修为丹药。
研习功法：最多 1 种主悟性增益资源。
毒瘴探索：最多 1 种主避瘴 / 解毒资源。
休整治疗：最多 1 种主疗伤资源。
```

原因：

```text
避免早期处理多丹叠加、多持续时间、多残余药性、多压力曲线。
```

未来可扩展：

```text
主药 + 辅药
丹方组合
药引
多资源叠加但受根骨 / 神念 / 状态承载限制
```

---

### 12.2 已有残余与新资源冲突

如果角色已有同一 `stacking_group` 的 ActiveResourceEffect：

```text
默认不允许再使用同组新资源。
```

UI 提示：

```text
你体内已有清灵丹残余药性，约 6 小时。
请先主动吐纳承接、等待散逸，或通过巩固根基收束后，再使用新的同类资源。
```

这样可以避免玩家叠加多份残余效果导致结算复杂。

---

## 13. 托管规则

### 13.1 托管不主动消耗新高价值资源

托管不得主动：

```text
服用新的稀有修为丹药。
服用新的高刺激速成丹药。
消耗不可逆高价值资源。
```

### 13.2 托管可以处理已有残余效果

如果角色已经存在 ActiveResourceEffect，托管可以选择低风险兼容行动来减少损失。

例如：

```text
角色体内有清灵丹剩余药性。
当前位置安全。
托管可选择主动吐纳一段时间，承接剩余药性。
```

如果残余药性是刺激型且当前位置安全：

```text
托管可选择巩固根基并收束药性。
```

但托管仍需遵守：

```text
保命 / 避险优先。
不主动发起重大不可逆选择。
不主动进入高危区域。
不消耗新高价值资源。
```

## 15. 结算伪代码

### 15.1 行动开始

```text
for input in instruction.resource_inputs:
    if action_has_not_started:
        do_not_consume_resource()

    if action_is_starting:
        validate_resource_ownership()
        validate_action_compatibility()
        validate_context_compatibility()
        validate_stacking_group()
        consume_resource()
        create_or_attach_ActiveResourceEffect()
        write_resource_use_log()
```

---

### 15.2 行动片段结算

```text
for effect in active_resource_effects:
    if is_effect_compatible_with_current_segment(effect, action, context):
        compatible_hours = segment_hours
        applied_hours = min(compatible_hours, effect.remaining_effective_hours)
        applied_amount = effect.unit_effect_rate * applied_hours

        route_effect_to_pipeline(effect.effect_type, applied_amount)

        effect.remaining_effective_hours -= applied_hours
        effect.remaining_effect_amount -= applied_amount
        effect.last_applied_world_hour = current_world_hour

        if effect.remaining_effective_hours <= 0:
            effect.state = exhausted
    else:
        process_residual_policy(effect, segment_hours)
```

---

### 15.3 巩固根基收束

```text
if action.action_template_id == "root_consolidation":
    for effect in active_resource_effects:
        if effect.effect_type == "cultivation_aura" and effect.can_be_settled_by_consolidation:
            if player_selected_settle_residual or effect.residual_policy in ["stimulating_decay", "forced_release"]:
                settled_hours = min(action_actual_hours, effect.remaining_effective_hours)
                settled_amount = effect.unit_effect_rate * settled_hours

                prevent_or_reduce_pressure(effect, settled_amount)
                effect.remaining_effective_hours -= settled_hours
                effect.remaining_effect_amount -= settled_amount

                # 不进入修为输入
                cultivation_resource_aura_input += 0
```

---

### 15.4 事件临时追加资源

```text

    validate_resource_ownership()
    validate_event_option_compatibility()
    validate_context_compatibility()
    validate_stacking_group()

    write_resource_use_log()
    apply_resource_effect_from_event_option()

    if resource_effect_has_residual and allow_residual_after_event:
        create_or_update_ActiveResourceEffect()
```

## 17. 已收敛决议

### R-21｜取消独立“丹药炼化”持续行动

```text
MVP 不设计独立持续行动：丹药炼化。
丹药、灵材、临时增益资源统一作为行动资源输入项。
```

---

### R-22｜修为丹药只作为主动吐纳输入

```text
修为类丹药不允许即时服用涨修为。
不允许通过独立丹药炼化行动涨修为。
只能挂载到主动吐纳行动。
```

---

### R-23｜资源效果总量 = 单位增量 × 有效作用时长

```text
丹药等资源的总效果按 unit_effect_rate × max_effective_hours 计算。
实际结算按行动实际兼容小时消耗。
```

---

### R-24｜行动未开始则资源不消耗

```text
若带资源输入的行动因前置延误或条件失败没有实际开始，资源不消耗。
```

---

### R-25｜行动已开始但未完全消耗资源时生成残余效果

```text
行动实际时长短于资源有效时长时，剩余效果进入 ActiveResourceEffect。
```

---

### R-26｜非兼容行动不转化资源效果

```text
修为丹药在非主动吐纳行动中不转化修为。
悟性丹在非研习功法行动中不产生功法经验收益。
解毒丹只在对应危险语境中生效。
```

---

### R-27｜MVP 同类主资源输入最多一个

```text
同一行动中，同一效果通道最多使用 1 个主资源输入。
```

---

### R-28｜托管不主动消耗新高价值资源

```text
托管不得主动服用新的高价值丹药或高刺激修为资源。
但可以在安全条件下通过兼容行动承接已有残余效果。
```

---

### R-29｜残余效果允许跨回合

```text
ActiveResourceEffect 允许跨行动、跨回合保存。
决策阶段时间暂停，不推进药性衰减。
药性只在世界小时实际推进时，根据 residual_policy 处理。
```

---

### R-30｜巩固根基可收束修为药性，但不转化修为

```text
巩固根基可以选择性收束残余修为药性。
收束不产生修为进度。
收束只用于止损、减压、稳定根基。
稳定药性默认不自动收束，需玩家选择。
```

---

### R-31｜强制释放型丹药不进入常规 MVP

```text
forced_release 只预留字段和处理分支。
MVP 不投放常规强制释放修为丹药。
如特殊事件使用，必须在事件链中明确风险。
```

---

### R-32｜事件选项允许临时追加资源输入

```text
事件模板可声明 resource_input_slot。
玩家可在事件选项中临时消耗兼容资源。
资源不得回溯生效，必须走服务端校验、资源日志和结果包。
```

---

### R-33｜资源输入 UI 采用行动内折叠项

```text
资源输入主入口放在具体行动界面内。
角色已有残余效果使用角色面板 / 行动规划器常驻提示。
事件资源输入作为事件选项附加条件显示。
```

## 18. MVP 范围

MVP 应实现：

```text
1. 行动资源输入项。
2. 修为丹药挂载主动吐纳。
3. 悟性丹挂载研习功法。
4. 避瘴 / 解毒类资源挂载危险语境行动。
5. 资源效果总量 = 单位增量 × 有效作用时长。
6. 行动未开始不消耗资源。
7. 行动开始后按实际兼容小时消耗资源。
8. 残余效果 ActiveResourceEffect。
9. 残余效果跨回合保存。
10. stable_suspend / slow_decay / stimulating_decay 三类残余策略。
11. forced_release 字段预留，但不常规投放。
12. 巩固根基可选择性收束残余修为药性。
13. 事件选项可临时追加资源输入。
14. 同效果通道最多 1 个主资源输入。
15. 资源使用日志与回合报告。
16. 行动内折叠式资源输入 UI。
```

MVP 不实现：

```text
1. 独立持续行动：丹药炼化。
2. 即时服丹涨修为。
3. 多枚修为丹药复杂叠加。
4. 主药 + 辅药 + 药引组合。
5. 常规强制释放型丹药。
6. 复杂丹毒长期累计值。
7. 丹药作为装备栏式被动挂件。
8. 玩家在结算阶段主动暂停来重新安排药性。
```

## 20. 当前定版口径摘要

```text
丹药不是独立行动，丹药是行动输入。
修为丹药不是即时经验药，必须依附主动吐纳。
资源总效果按单位增量 × 有效小时计算。
行动未开始不消耗资源。
行动已开始但未完全消耗，则生成残余效果。
残余效果可跨回合，但受稳定窗口和残余策略约束。
非兼容行动不转化资源效果。
巩固根基可以收束残余修为药性，但不转化修为。
强制释放型丹药不进常规 MVP。
事件选项可以临时追加资源，但必须模板声明、服务端校验、写日志。
资源输入 UI 放在具体行动内，残余效果在角色状态中常驻提示。
```

这套规则的目标是：

```text
统一丹药、灵材、符箓、临时增益资源的使用模型；
避免“丹药炼化”成为低价值冗余行动；
保持时间预算是核心约束；
允许事件打断后有合理残余处理；
为不同路线的资源获取和资源投入保留差异化空间。
```
