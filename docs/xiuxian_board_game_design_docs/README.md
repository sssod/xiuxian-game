# 修仙模拟棋盘｜独立设计文档包

适用范围：快节奏、多人共玩、回合驱动的修仙题材棋盘模拟游戏方案。

## 1. 当前定位

本目录是“修仙题材多人棋盘模拟游戏”的独立、自包含设计包。方案以个人修仙竞速为核心，通过多人同时规划、同步移动、统一行动结算、地图事件、玩家竞争和轻量经营形成单局循环。

当前处于“已确认规则完成首轮拆分，转入 MVP 大模块补全”阶段。设计开发仍冻结：本包只承接设计裁决、主题配置和未来开发准备条件，不授权修改游戏运行时、客户端、工具、测试或平衡实现。

本包不修改、不覆盖 `docs/xiuxian_design_docs`。

## 2. 阅读顺序

1. 从《[总索引](00_INDEX/INDEX_总索引.md)》确认文档状态与主题归属。
2. 以《[游戏框架与核心裁决](00_INDEX/01_游戏框架与核心裁决.md)》作为当前权威入口。
3. 以《[MVP 框架缺口与阶段门](00_INDEX/02_MVP框架缺口与阶段门.md)》确定下一阶段裁决顺序。
4. 进入主题、系统、数值或交互专题文档查阅详细规则；同一规则只保留一个详细维护位置。
5. 继续工作前读取《[MVP 框架下一阶段 handoff](../handoff/2026-07-12_修仙模拟棋盘_MVP框架下一阶段handoff.md)》，避免重新从公式细节开始裁决。

## 3. 来源边界

新方案材料按以下方式处理：

1. 用户对新方案的明确裁决优先。
2. 本包已经回写的裁决是新方案当前口径。
3. `docs/inbox/修仙模拟棋盘核心玩法_阶段稿_v0.1.md` 与 `docs/inbox/修仙模拟棋盘_行动修炼与自动战斗方案_v0.2.md` 只用于恢复思路和识别冲突。
4. `docs/xiuxian_design_docs` 只用于逐项评估是否复用旧概念；未在本包重新表述的旧规则不属于新方案。
5. 当前 UI artifact / Figma 只在未来承接稳定界面决策，不决定玩法规则。

本包正文不得依赖包外材料才能解释当前规则。

## 4. 目录职责

```text
00_INDEX/   权威入口、总索引、MVP 缺口与阶段门
01_主题设计/ 通用主题契约与具体主题内容
02_系统设计/ 回合、移动、行动、战斗、成长、构筑与经营规则
03_数值设计/ 节奏、移动竞争与自动战斗的配置规则
04_交互设计/ 稳定的信息职责与操作边界
```

节点级布局、视觉样式和动效不在本包中提前固化。

## 5. 维护规则

1. 核心裁决文档只维护局级摘要、模块权威映射和待裁决总表。
2. 专题细则只在所属文档维护，其他文档使用摘要和包内链接。
3. 未经用户确认的提议必须标为未决、缺口或制作期建议，不能写成规则。
4. 每轮提问不超过 `5` 个，且只围绕一个相近主题；提问前先检索本包和旧包。
5. 用户回答后，同步更新专题正文、核心待裁决总表和维护记录。
6. 每次变更后验证 `git diff -- docs/xiuxian_design_docs` 为空。
