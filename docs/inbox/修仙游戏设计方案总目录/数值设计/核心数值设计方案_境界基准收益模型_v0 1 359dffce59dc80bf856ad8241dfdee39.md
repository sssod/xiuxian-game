# 核心数值设计方案：境界—基准收益数学模型

版本：v0.1

日期：2026-05-07

适用范围：修仙题材文字/策略游戏的个人成长、境界推进、功法修炼、资源输入、地图节点、宗门支持、突破挑战与轮回效率判断

---

## 0. 文档目的

本文档用于收敛当前项目的核心数值设计方案，重点解决以下问题：

1. 如何从“境界段预期达成时间”反推出角色在当前境界的基准收益。
2. 如何让小时 tick 作为结算粒度，而不是跨境界统一收益基准。
3. 如何将功法、道具、设施、地图节点灵气、宗门支持统一接入境界收益模型。
4. 如何用标准化进度替代失控的原始修为点作为调参核心。
5. 如何让突破挑战承接境界段准备结果，而不是退化为概率按钮。
6. 如何让轮回成为低效率世代的效率修正机制，而不是由寿元或事件门槛半强迫触发。

---

## 1. 核心结论

当前项目的核心数值设计应定为：

```
以 RealmSegmentBalance 为根表；
以目标达成时间反推 compatible_hour_benchmark_rate；
以标准化境界段进度作为内部调参单位；
以 ActionCultivationProfile 提供行动相对效率；
以 RealmInputFitMatrix 统一功法、资源、设施、节点灵气和宗门支持的境界适配；
以 ResourceEffectBalance 将资源价值折算为 benchmark_hours_saved；
以 StatePressureModel 让高效率产生经脉压力和突破风险；
以 BreakthroughScoreBalance 把阶段准备转化为 B1 突破初始条件；
以 ReincarnationEfficiencyPolicy 判断轮回价值，而不是用寿元或事件门槛硬逼轮回。
```

一句话概括：

> 境界段目标时间是数值设计的源头；小时 tick 只是把境界段基准收益拆成可结算的兼容小时收益；轮回则是围绕“当前世代效率是否低于基准”建立的长期效率修正机制。
>

## 2. 当前系统约束

本方案必须兼容当前系统设计中的以下约束。

### 2.1 时间结算约束

当前系统采用共享世界时间：

```
1 游戏日 = 24 游戏小时
服务器最小结算单位 = 1 游戏小时
world_day / world_hour 是权威时间字段
```

F1 / N1 / B1 / P0 是不同的公开推进状态，而不是不同的数值单位：

```
F1：高速推进，用于长期低交互行动
N1：常规推进
B1：局部时停/交锋/突破挑战推进，1 轮 = 1 游戏小时
P0：等待玩家关键输入
```

因此：

```
world_hour 是结算粒度；
RealmSegmentBenchmark 才是收益基准。
```

### 2.2 行动系统约束

当前个人行动队列支持：

```
cultivate
meditate
rest
heal
craft
travel
visit
apply_resource
breakthrough_open
minor_breakthrough
managed
```

自动兜底行动应为低收益或极低收益，不应参与 F1，不应成为长期最优路径。显式托管是玩家主动选择的低关注行动，可以在满足条件时参与 F1，但效率应低于主动规划路径。

### 2.3 修炼状态约束

角色修炼状态中已经存在或应承接以下字段：

```
realm
minor_stage
cultivation_points
bottleneck_state
foundation_quality
meridian_pressure
resource_aura_input
last_settled_world_day
last_settled_world_hour
```

本方案建议新增内部调参字段：

```
normalized_segment_progress
```

该字段用于表示当前境界段进度，建议范围为：

```
0.0 ~ 1.0+
```

其中：

```
0.0 = 当前境界段刚开始
1.0 = 达到该境界段推进目标，具备进入下一阶段或开启突破资格
>1.0 = 超额准备，可转化为突破初始优势、品质修正或稳定性修正
```

### 2.4 功法系统约束

功法状态至少影响：

```
修炼效率
突破模板
事件选项
战斗策略
资源输入兼容
心魔与走火风险
宗门评价
NPC 关系
```

因此功法不能只是一个静态倍率，而必须接入“境界段适配度”。

### 2.5 地图节点约束

地图节点包含：

```
risk_level
aura_profile
resource_slots
facility_refs
active_events
active_windows
visibility_state
```

节点资源槽、事件窗口、风险暴露、多人争夺均按 world_hour 推进。因此地图节点不是简单“收益加成点”，而是角色在不同境界段的修炼支持环境。

### 2.6 宗门系统约束

宗门是组织资源平台，不是玩家直接操控的城市建设面板。宗门支持可通过以下方式影响角色数值：

```
资源供给
设施权限
护法支持
功法获取
节点情报
宗门库存调用
职位与贡献影响
NPC 支持
宗门 AI 持续行动结果
```

宗门支持不应设计成免费全局倍率，而应改变可达效率上限、风险控制能力、资源可得性和突破质量。

### 2.7 突破系统约束

大境界突破不是概率按钮，而应包括：

```
准备期
开启突破短指令
B1 突破挑战
轮内资源消耗
结果报告
后续影响
轮回账本记录
```

B1 突破挑战中：

```
1 交锋轮 = 1 游戏小时
真实资源消耗发生在交锋轮中
系统按轮结算并同步推进世界时间
```

境界基准模型只负责判断“是否达到突破资格”和“进入突破时的初始状态”，不直接决定突破结果。

### 2.8 轮回系统约束

真灵是跨世主体，当世角色是一次生命载体。死亡与转世应写入：

```
LifeLedger
ReincarnationRecord
后手与遗产记录
资产去向
真灵暴露变化
下一世初始条件
```

轮回应是：

```
低效率世代的长期效率修正机制；
高效率世代的主动追求、路线重构或竞争策略选择。
```

轮回不应被寿元、事件难度或资源门槛半强迫触发。

## 3. 核心对象：RealmSegment

### 3.1 定义

```
RealmSegment = 从一个稳定修炼状态推进到下一个关键里程碑的最小数值成长段。
```

它可以对应：

```
炼气一层 → 炼气二层
炼气九层 → 炼气圆满
炼气圆满 → 筑基开启资格
筑基准备期 → 筑基成功并完成初步巩固
```

### 3.2 设计原则

每个 `RealmSegment` 都有自己的：

```
目标达成时间
有效修炼小时占比
标准化进度需求
原始修为表现值
功法掌握要求
根基要求
经脉压力上限
伤势上限
心魔风险上限
突破模板
轮回效率阈值
```

不要用一条全局经验曲线覆盖全部境界。

## 5. 基准收益反推模型

设：

```
s = 当前 RealmSegment
T_s = target_elapsed_hours_standard
U_s = expected_cultivation_hour_ratio
P_s = required_normalized_progress，默认 1.0
```

### 5.1 日历基准推进率

```
calendar_benchmark_rate_s = P_s / T_s
```

含义：

```
标准玩家每 1 个世界小时，平均应该完成多少境界段进度。
```

该值用于长期节奏、CEI、轮回判断和模拟验收。

### 5.2 有效修炼小时基准收益

```
compatible_hour_benchmark_rate_s = P_s / (T_s × U_s)
```

含义：

```
当角色处于“有效修炼兼容小时”时，每小时应获得多少标准化进度。
```

该值用于修炼、闭关、吐纳、资源效果、设施加成和节点灵气结算。

### 5.3 示例

假设某境界段：

```
目标 30 游戏日完成
T_s = 720 小时
预期其中 60% 是有效修炼时间
U_s = 0.60
required_normalized_progress = 1.0
```

则：

```
calendar_benchmark_rate_s = 1 / 720
compatible_hour_benchmark_rate_s = 1 / (720 × 0.60)
                                 = 1 / 432
```

解释：

```
标准玩家在 720 个日历小时内完成该段；
其中约 432 个小时是真正有效修炼小时；
每个有效修炼小时获得 1/432 的标准化进度。
```

## 6. 标准化进度与原始修为

### 6.1 内部调参字段

```yaml
normalized_segment_progress: number
```

建议范围：

```
0.0 ~ 1.0+
```

### 6.2 表现层字段

```yaml
cultivation_points: number
```

用于：

```
世界观表达
日志展示
玩家反馈
境界膨胀感
排行榜或传闻包装
```

### 6.3 换算公式

```
cultivation_points_gain = normalized_gain × raw_cultivation_required_s
```

这样可以做到：

```
炼气段 raw requirement = 1,000
筑基段 raw requirement = 20,000
金丹段 raw requirement = 500,000
```

但调参始终看：

```
normalized_segment_progress: 0.0 ~ 1.0
```

## 7. 每小时修炼结算公式

每个兼容小时的核心公式为：

```
normalized_gain_per_compatible_hour =
B_s
× A_action
× Q_aptitude
× M_method
× K_mastery
× N_node_aura
× F_facility
× R_resource
× S_sect_support
× P_state_penalty
× C_competition_or_window
```

其中：

```
B_s = compatible_hour_benchmark_rate_s
```

展开为：

```
B_s = required_normalized_progress_s /
      (target_elapsed_hours_standard_s × expected_cultivation_hour_ratio_s)
```

### 7.1 修正项说明

| 项 | 含义 |
| --- | --- |
| `A_action` | 当前行动类型效率，例如闭关、吐纳、显式托管、自动兜底 |
| `Q_aptitude` | 资质修正 |
| `M_method` | 主修功法对当前境界段的适配度 |
| `K_mastery` | 功法掌握度修正 |
| `N_node_aura` | 地图节点灵气对当前境界段的适配度 |
| `F_facility` | 洞府、静室、阵法等设施支持 |
| `R_resource` | 丹药、灵材、符箓、ActiveResourceEffect 等资源效果 |
| `S_sect_support` | 宗门资源、护法、权限、库存支持 |
| `P_state_penalty` | 伤势、心魔、经脉压力、寿元压力等惩罚 |
| `C_competition_or_window` | 秘境窗口、节点争夺、资源枯竭等动态影响 |

## 8. 有界效率模型

为避免倍率爆炸，所有修正项先计算原始效率倍率：

```
efficiency_ratio_raw =
A_action
× Q_aptitude
× M_method
× K_mastery
× N_node_aura
× F_facility
× R_resource
× S_sect_support
× P_state_penalty
× C_competition_or_window
```

然后按当前境界段限制：

```
efficiency_ratio = clamp(
  efficiency_ratio_raw,
  min_efficiency_ratio_s,
  max_efficiency_ratio_s
)
```

最终收益：

```
normalized_gain = B_s × efficiency_ratio × compatible_hours
```

### 8.1 推荐初始效率区间

| 路径 / 行动 | 相对基准效率方向 |
| --- | --- |
| 标准主动路径 | 约 1.00 |
| 安全低风险路径 | 0.65 ~ 0.90 |
| 资源投入路径 | 1.20 ~ 1.70 |
| 高风险节点路径 | 1.30 ~ 2.20 |
| 宗门支持路径 | 1.10 ~ 1.60 |
| 显式托管 | 0.20 ~ 0.50 |
| 自动兜底 | 0.05 ~ 0.20 |

说明：以上区间不是最终数值，而是首版调参方向。具体上限应由每个 `RealmSegment` 自己决定。

## 9. 行动相对效率：ActionCultivationProfile

行动类型不直接提供绝对收益，只提供相对于当前境界段基准的效率倍率。

```yaml
ActionCultivationProfile:
action_type: string
source: explicit_player | timeout_managed | system_fallback

valid_segment_tags: array
compatible_hour_policy: full | partial | none

base_efficiency_ratio: number
f1_eligible: bool
event_interrupt_policy: string

pressure_gain_ratio: number
risk_exposure_ratio: number
resource_slot_count: int

min_duration_hours: number
max_duration_hours: number | null
```

### 9.1 行动设计方向

### 闭关修炼

```
兼容小时：full
效率：接近或略高于标准基准
可接资源输入
可设置闭关预案
可参与 F1
会产生一定经脉压力或事件中断风险
```

### 普通吐纳

```
兼容小时：full
效率：低于标准主动路径
风险低
资源槽少
适合作为稳定补充，不应成为主流最优路线
```

### 显式托管

```
兼容小时：full
效率：低到中低
安全、低交互
可参与 F1
适合玩家暂时降低关注度
```

### 自动兜底

```
兼容小时：full 或 partial
效率：极低
不消耗关键资源
force_speed = N1
f1_eligible = false
不能成为长期成长策略
```

### 休整

```
兼容小时：none 或 partial
主要恢复伤势、心魔、经脉压力、暴露度
不作为成长主路径
```

## 10. 境界适配矩阵：RealmInputFitMatrix

功法、资源、设施、节点灵气、宗门支持共用一套境界适配矩阵。

```yaml
RealmInputFitMatrix:
input_type: method | resource | facility | node_aura | sect_support
input_grade: int
segment_realm_grade: int
tag_match_policy: string

efficiency_multiplier: number
contribution_cap_ratio: number
waste_ratio: number
pressure_modifier: number
side_effect_risk: number
breakthrough_relevance: number
```

### 10.1 设计目的

该矩阵用于解决：

```
低阶丹药为什么后期无效？
高阶丹药为什么低境界可能浪费或反噬？
普通宗门静室为什么支撑不了高境界？
低阶灵脉为什么对高境界玩家失去核心价值？
同品阶功法为什么仍需看相性和掌握度？
```

### 10.2 初始矩阵方向

| 输入品阶 vs 境界段 | 效率 | 贡献上限 | 浪费 | 压力 / 反噬 |
| --- | --- | --- | --- | --- |
| 低 2 阶 | 极低 | 极低 | 高 | 低 |
| 低 1 阶 | 低 | 低 | 中 | 低 |
| 同阶 | 标准 | 高 | 低 | 低 |
| 高 1 阶 | 高 | 高 | 中 | 中 |
| 高 2 阶以上 | 较高但不稳定 | 中 | 高 | 高 |

注意：

```
高阶资源不应简单碾压。
它可以提高效率，但应通过浪费、经脉压力、相性风险、突破副作用来限制。
```

## 11. 资源效果：ResourceEffectBalance

资源不应写成固定 raw 修为加成，而应折算为：

```
在适配境界段内，节省多少基准兼容小时；
最多贡献当前境界段进度的多少比例；
增加或降低多少经脉压力；
是否影响突破 success_score 或 quality_score。
```

```yaml
ResourceEffectBalance:
resource_template_id: string
resource_grade: int
valid_segment_tags: array

effect_mode: progress_bonus | rate_multiplier | breakthrough_modifier | pressure_control | injury_recovery | aura_stabilizer

benchmark_hours_saved: number | null
normalized_progress_bonus: number | null
rate_multiplier: number | null
compatible_hours: int

contribution_cap_ratio: number
meridian_pressure_delta: number
mental_risk_delta: number
foundation_delta: number

breakthrough_success_delta: number
breakthrough_quality_delta: number

residual_policy: string
stack_policy: string
```

### 11.1 资源价值换算

若资源定义为：

```
benchmark_hours_saved = H
```

则：

```
normalized_progress_bonus = H × compatible_hour_benchmark_rate_s
```

例如某同阶丹药在当前境界段内：

```
节省 18 个基准兼容小时
B_s = 1 / 432
```

则：

```
normalized_progress_bonus = 18 / 432 = 0.0417
```

这意味着该丹药贡献当前境界段约 4.17% 的标准化进度。

## 12. 状态压力模型：StatePressureModel

经脉压力应是“高效率的代价”，不是单纯负面状态。

```yaml
StatePressureModel:
segment_id: string

pressure_from_overbenchmark_rate: number
pressure_from_resource_grade_gap: number
pressure_from_risky_node: number
pressure_decay_rest_per_hour: number
pressure_decay_facility_per_hour: number

pressure_penalty_curve_id: string
breakthrough_risk_curve_id: string
```

### 12.1 压力生成

```
over_rate = max(0, efficiency_ratio - 1.0)
```

```
meridian_pressure_gain =
over_rate × pressure_from_overbenchmark_rate
+ resource_pressure
+ node_pressure
+ method_mismatch_pressure
```

### 12.2 状态惩罚

```
P_state_penalty =
1 / (1 + λ1 × meridian_pressure + λ2 × injury + λ3 × mental_risk)
```

### 12.3 策略效果

该模型形成以下取舍：

```
低效安全修炼：压力低，但时间慢。
高效资源冲刺：时间快，但压力高。
高风险灵地：效率高，但事件和伤势风险高。
宗门设施：不一定大幅加速，但能降低压力或提高上限。
```

## 17. 当前世代效率指数：CEI

### 17.1 定义

```
CEI_s = actual_effective_milestone_progress_rate_s /
        calendar_benchmark_rate_s
```

其中：

```
calendar_benchmark_rate_s = 1 / target_elapsed_hours_standard_s
```

### 17.2 有效进度

`actual_effective_milestone_progress_rate_s` 不只看修为，建议用综合有效进度：

```
effective_progress =
w_cultivation × normalized_segment_progress
+ w_method × method_mastery_norm
+ w_foundation × foundation_readiness_norm
+ w_resource × resource_bank_value_norm
+ w_sect × sect_support_value_norm
+ w_node × node_position_value_norm
- w_injury × injury_cost_norm
- w_pressure × meridian_pressure_cost_norm
- w_mental × mental_risk_cost_norm
```

### 17.3 CEI 解释

| CEI 区间 | 含义 | 轮回价值 |
| --- | --- | --- |
| `CEI < low_threshold` | 当前世代效率低于基准 | 轮回应具有明显效率修正价值 |
| `low_threshold <= CEI <= high_threshold` | 接近标准路径 | 继续或轮回都可行，取决于目标 |
| `CEI > high_threshold` | 当前世代效率高于基准 | 不应被寿元或事件门槛半强迫轮回 |

### 17.4 轮回策略原则

```
低效率世代：轮回提高下一世效率。
高效率世代：继续修行必须仍然是合理路径。
主动轮回：用于追求更高上限、路线重构、竞争抢位或真灵目标。
```

## 18. 寿元与继续可行性

寿元不应是强制重开按钮，而应进入继续可行性判断。

### 18.1 预计到达下一里程碑时间

```
expected_hours_to_next_milestone =
remaining_progress / projected_calendar_rate
+ expected_breakthrough_rounds
+ expected_recovery_or_consolidation_hours
```

其中：

```
projected_calendar_rate = calendar_benchmark_rate_s × projected_CEI_s
```

### 18.2 寿元预算比

```
life_budget_ratio =
remaining_lifespan_hours / expected_hours_to_next_milestone
```

### 18.3 判断

| `life_budget_ratio` | 含义 |
| --- | --- |
| `>= 1.0` | 继续推进在时间上可行 |
| `0.5 ~ 1.0` | 继续可行但有压力，需要资源、宗门、冒险或降低品质追求 |
| `< 0.5` | 继续修行期望收益偏低，轮回价值上升 |

即使 `life_budget_ratio < 1.0`，也不应直接强制轮回。玩家仍可选择：

```
消耗延寿资源
请求宗门支持
冒险抢高阶节点
降低突破品质目标
布置后手后轮回
继续硬冲
```

---

## 19. 事件难度原则

事件难度不能按世界时间硬抬，避免“玩家明明高效率，却被系统逼轮回”。

建议事件难度由以下因素决定：

```
节点等级
机会窗口等级
宗门态势
玩家主动进入的区域
多人竞争状态
玩家可见情报
后手触发状态
```

而不是：

```
世界时间越久，所有事件强度越高。
```

由此形成：

```
低效率玩家可以留在低阶区域慢慢修，但会错过高价值窗口。
高效率玩家可以进入高阶节点争夺机会。
宗门经营型玩家可以用组织资源降低风险。
轮回玩家可以用前世信息提前抢节点或避坑。
```

## 20. 每小时结算伪代码

```
settle_character_cultivation(character, command, world_hour):

    s = get_current_realm_segment(character.realm, character.minor_stage)

    if not is_cultivation_compatible(command, character, s):
        settle_non_cultivation_effects(character, command)
        return

    B = s.required_normalized_progress /
        (s.target_elapsed_hours_standard * s.expected_cultivation_hour_ratio)

    compatible_hours = get_compatible_hours(command, character, active_resource_effects)

    action_ratio = get_action_efficiency_ratio(command, s)
    aptitude_ratio = get_aptitude_ratio(character, s)
    method_ratio = get_method_fit_ratio(character.main_method, s)
    mastery_ratio = get_mastery_ratio(character.method_state, s)
    node_ratio = get_node_aura_fit(character.location_node, s)
    facility_ratio = get_facility_fit(character.location_node, s)
    resource_ratio = get_active_resource_ratio(character.active_resource_effects, s)
    sect_ratio = get_sect_support_ratio(character.sect_membership, s)
    state_penalty = get_state_penalty(character.injury_state,
                                      character.mental_state,
                                      character.cultivation_state.meridian_pressure)

    raw_efficiency =
        action_ratio
      * aptitude_ratio
      * method_ratio
      * mastery_ratio
      * node_ratio
      * facility_ratio
      * resource_ratio
      * sect_ratio
      * state_penalty

    efficiency =
        clamp(raw_efficiency,
              s.min_efficiency_ratio,
              s.max_efficiency_ratio)

    normalized_gain =
        B * efficiency * compatible_hours

    character.cultivation_state.normalized_segment_progress += normalized_gain
    character.cultivation_state.cultivation_points +=
        normalized_gain * s.raw_cultivation_required

    update_method_mastery(character, command, s, compatible_hours)
    update_meridian_pressure(character, efficiency, resource_inputs, node)
    update_active_resource_effects(character, compatible_hours)
    update_bottleneck_state(character, s)

    emit_result_package()
```

## 24. 核心验收指标

该模型的验收不应看“每小时收益是否好看”，而应看以下指标。

```
1. 每个 RealmSegment 的实际完成时间是否接近 target_elapsed_hours_standard。
2. 安全、资源、高风险、宗门路径是否落在各自目标时间区间。
3. 自动兜底是否明显低效，不能成为长期最优路线。
4. 显式托管是否安全低收益，能服务低关注，但不是最高效率。
5. 同一资源在不同境界段的价值是否自然衰减或产生浪费。
6. 高阶资源给低境界是否有收益，同时伴随浪费或压力。
7. 普通灵地是否会随境界提升失去核心价值。
8. 宗门支持是否改变上限、风险和资源可得性，而不是免费全局加成。
9. 突破是否由准备质量 + B1 决策共同决定，而不是概率按钮。
10. CEI 低于基准时，轮回是否明显提高下一世效率。
11. CEI 高于基准时，寿元和事件门槛是否不会半强迫玩家轮回。
12. 多人竞争是否通过节点、资源、窗口、宗门库存和后手改变实际效率。
```

## 26. 设计警戒线

以下情况应视为数值方案出现偏差：

```
1. 所有境界共用一个小时收益基准。
2. 行动表直接写死 raw 修为收益。
3. 丹药、功法、设施、节点灵气没有境界适配度。
4. 自动兜底成为长期最优成长方式。
5. 高阶资源对低境界角色无脑最优。
6. 宗门支持退化成免费全局倍率。
7. 经脉压力只作为惩罚，没有承载高效率代价。
8. 突破退化成成功率按钮。
9. 寿元变成强制重开倒计时。
10. 事件难度随世界时间硬抬，半强迫玩家轮回。
11. 轮回奖励只给收藏，不提高下一世效率。
12. 轮回奖励过强，导致玩家反复低质量刷轮回。
```

## 27. 最终摘要

当前项目的数值设计应从“境界段目标达成时间”开始，而不是从“1 小时给多少收益”开始。

核心路径为：

```
RealmSegmentBalance
→ RealmBenchmarkRate
→ ActionCultivationProfile
→ RealmInputFitMatrix
→ ResourceEffectBalance / NodeRealmSupport / SectSupportBalance
→ StatePressureModel
→ BreakthroughScoreBalance
→ ReincarnationEfficiencyPolicy
→ 模拟验证
```

最终目标是让玩家的每一次修炼、资源投入、地图选择、宗门请求、突破决策和轮回判断，都能回到同一个核心问题：

> 当前世代在当前境界段的实际效率，是否高于、等于或低于设计基准？
> 

当效率低于基准时，轮回应变得有价值；当效率高于基准时，继续修行必须仍然合理。玩家是否轮回，应取决于自身追求、竞争压力和路线规划，而不是被寿元或事件门槛半强迫。
