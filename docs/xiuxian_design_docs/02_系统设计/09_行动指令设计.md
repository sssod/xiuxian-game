# 系统设计｜行动指令

## 1. 设计定位

行动指令负责把玩家意图转成服务端可校验、可排队、可结算、可回放的世界行动。它不允许客户端直接改写角色、地图、库存、宗门或事件状态，而是在共享世界日历中按 `world_day / world_hour` 接收指令、校验合法性、推进小时 tick，并把消耗、收益、位置、事件、速度变化、日志和结果包写回权威状态。

本文只维护普通行动短队列、行动校验、自动兜底、显式托管、资源输入、局部时停 / C1 承接，以及普通行动与 B1 正式交锋的边界。战斗轮内指令、突破阶段选择、事件选项生成和页面布局由对应系统或交互文档维护。

## 2. 当前结论

1. 行动指令是服务端结算的意图记录，不是客户端状态修改；所有行动必须进入权威校验、小时 tick、日志和回放链路。
2. 普通行动采用“当前执行指令 + 最多 3 条预输入指令”的短队列，只允许提前排入当前已经合法的普通指令。
3. 队列不锁定未来资源，不做条件脚本、未来产出推导、跨指令依赖图或通用事件预案。
4. 队列为空、下一条指令执行前校验失败或玩家未补充行动时，系统进入低收益自动兜底，并强制世界回到 N1；自动兜底不能作为进入 F1 的依据。
5. 普通行动队列只承接 B1 交锋、突破挑战和重大事件结束后的后续行动，不替代正式交锋轮内选择、突破阶段选择或个人即时处理事件处理权。
6. 长期低交互行动只有在具备结束条件、资源绑定、中断策略和安全默认时，才可作为 F1 批量结算候选。

## 4. 核心循环或触发入口

玩家通过指令管理入口提交普通行动。服务端收到指令后，按当前世界时间、角色状态、位置、资源、事件状态、功法 / 境界 / 关系条件和目标要求做入队校验；通过后进入短队列。

行动运行时由共享世界日历推进：

```text
玩家提交普通行动
→ 服务端做入队校验
→ 加入当前执行指令或预输入队列
→ 每个世界小时推进当前行动
→ 当前行动完成或被中断
→ 取下一条预输入指令做执行前校验
→ 合法则继续执行
→ 不存在或不合法则进入自动兜底并降至 N1
```

底层时间口径：

```text
1 游戏日 = 24 游戏小时
服务器最小结算单位 = 1 游戏小时
公开速度档位 = F1 / N1 / B1 / P0
C1 = 局部时停结束后的追赶补结算机制
```

行动完成后若下一条指令合法，且全员仍处于长期低交互行动，没有事件、交锋、全局节点或自动兜底，F1 可以继续。行动完成本身不强制降速。

## 5. 规则与状态

### 5.1 速度档位与行动关系

| 档位 | 行动含义 |
| --- | --- |
| F1 | 仅在全员明确处于长期低交互行动，且无自动兜底、局部时停、C1、正式交锋、同步处理事件 / P0 同步保护或临近截止节点时进入 |
| N1 | 普通多人运行、普通队列编辑、局部时停期间外部世界运行、自动兜底等待玩家接管 |
| B1 | 正式战斗、突破挑战、秘境关键交锋、玩家直接交锋等正式交锋 |
| P0 | 同步处理事件、全员决策、P0 同步保护和房间规则允许的主机暂停 |

### 5.2 普通指令队列

玩家角色保留一个短队列：

```text
当前执行指令 + 最多 3 条预输入指令
```

指令预输入不是自动化脚本系统，而是允许玩家把“当前已经合法的普通指令”提前放入短队列。队列为空或校验失败时，系统使用低收益兜底行动维持角色存在，并降至 N1 等待玩家补充新指令。

核心边界：

```text
预输入 = 提前排队已经合法的普通指令
不是 = 条件脚本、自动推导、未来资源规划、通用事件预案、追求全程高速推进
```

玩家主动编辑普通队列时：

1. 角色当前行动继续结算。
2. 其他玩家、宗门与世界继续推进。
3. 若当前为 F1，打开普通队列编辑界面时世界降至 N1。
4. B1 或 P0 中可编辑普通队列，但普通队列不替代交锋轮选择或 P0 公共提交 / 全员决策。
5. 外部 UI 只显示中性速度状态，不暴露私人事件或具体玩家归因。

### 5.3 可入队指令类型

可作为普通指令入队：

```text
闭关修炼
吐纳
休整
养伤
炼丹
炼器
长期赶路
拜访指定 NPC
申请指定宗门资源
进入指定地图节点
开启当前已满足条件的大境界突破
执行当前已满足条件的小境界突破
显式托管行动
```

不进入普通队列，改由事件、交锋或即时处理系统处理：

```text
未知事件的选项选择
需要新情报判断的宗门站队
多人直接冲突选择
正式交锋中的轮内策略选择
突破挑战中的轮内选择
临时触发的机缘事件
临时触发的心魔或风险抉择
```

长期低交互行动由行动模板标签决定，典型包括洞天 / 时间阵法闭关、普通长期闭关、长期修炼、安全长距离移动、显式托管、低风险宗门职责、休整 / 疗伤、资源采集 / 加工等低交互长行动。自动兜底固定 `f1_eligible=false`，不能作为进入 F1 的依据。

每个 F1 候选行动必须声明：

```text
结束条件；
资源绑定；
中断策略；
安全默认；
最大批次或可接受断点；
是否允许 F1 处理等级为 `summary / auto` 的事件摘要或自动处理。
```

### 5.4 校验规则

每条指令在入队时和执行前都必须校验。

入队时必须满足：

```text
当前状态允许
当前地点允许
当前资源足够
当前风险没有阻止
当前事件状态不冲突
当前境界 / 功法 / 关系条件满足
主修功法对应模板可用
资源输入项可从合法资产容器取得
```

队列不做：

```text
资源锁定
未来产出承诺
队列内资源占用推导
条件 if-else 链
跨指令依赖图
甘特图计划
通用事件预案策略表
```

执行前校验通过时，角色开始该指令。执行前校验失败时，系统跳过该指令，记录个人日志，进入自动兜底并强制世界进入 N1。

### 5.5 行动完成点

行动完成后，系统按以下顺序处理：

```text
1. 取出下一条预输入指令。
2. 对下一条指令做执行前校验。
3. 若下一条指令合法，直接开始执行。
4. 若下一条指令不存在或校验失败，进入自动兜底。
5. 自动兜底时世界进入 N1，等待玩家补充主动指令。
```

### 5.6 自动兜底、显式托管与超时默认

自动兜底触发条件：

```text
当前指令完成后队列为空
下一条指令执行前校验失败
下一条指令地点不合法
下一条指令资源不足
下一条指令被当前风险状态阻止
玩家未输入任何后续指令
```

风险兜底：

| 当前节点风险 | 自动兜底 |
| --- | --- |
| 低风险 / 宗门 / 城镇 / 安全洞府 / 已控制灵地 | 吐纳 |
| 中风险 / 高风险 / 秘境 / 敌对边境 / 未控制节点 / 战斗后区域 | 休整 |
| 风险等级不明 | 休整 |

显式托管是玩家主动声明短期低关注，不等于自动兜底。它可以在满足安全条件时参与 F1，但不得主动消耗新高价值资源、发起重大不可逆选择、进入高危区域或开启高风险突破。

托管可保守处理低价值事件，例如普通邀约、普通传闻、低价值机会、轻微状态波动和普通资源波动。死亡风险、正式交锋、重大心魔、重大机缘、不可逆选择、大境界突破挑战、主动转世、叛宗、强 PvP、稀有不可逆资源消耗、多人直接冲突和宗门重大事件仍进入通知、局部时停、B1 或 P0。

### 5.7 行动资源输入

丹药、灵材、符箓、临时增益资源统一作为行动或事件选项的资源输入项，不设计独立持续行动“丹药炼化”。

资源输入规则：

1. 入队时只校验当前是否拥有和可使用资源。
2. 队列不锁定未来资源。
3. 行动真正开始前再次校验资源。
4. 行动开始后才消耗资源输入。
5. 未用完资源效果生成 `ActiveResourceEffect`。
6. 局部时停期间，该玩家资源变化暂停。
7. C1 追赶只补结算确定性资源效果。

### 5.8 事件、局部时停与 C1

个人即时处理事件保留玩家处理权：

```text
事件玩家本人局部时停
其他玩家、宗门与世界继续 N1
gap 最大 1 游戏日
事件结束后 C1 追赶补结算
其他玩家不看到事件归因
```

事件选项可有游戏内时间成本，该时间从事件触发 `world_hour` 开始回填。C1 只补结算确定性行动进度、修炼收益、资源消耗、药性衰减、伤势恢复、队列切换、已知状态变化和事件选择明确后果，不触发随机个人即时处理事件、普通机缘、普通战斗、软机会事件、普通心魔或普通资源反馈。该“不触发”复用事件池压制逻辑，符合硬条件的候选继续累积未触发压力，但不在追赶结束时回溯生成事件。

### 5.9 突破与正式交锋边界

大境界突破可以预输入开启指令，但必须在入队当下已经满足条件。预输入保存“开启突破”本身，以及少量突破专用道具、主修功法突破模板确认和必要的突破挑战默认策略。

若开启突破在执行前仍合法，则进入突破挑战，世界切换至 B1。若执行前不合法，则跳过开启指令，不消耗突破道具，记录个人日志，进入自动兜底并降至 N1。

正式交锋和突破挑战不由普通队列替代：

```text
世界进入 B1
每个决策窗口现实时间 = 60 秒
B1 世界推进 = 每 60 秒现实时间对应非参战玩家和世界推进 1 游戏小时
未提交者执行当前默认策略
战斗交锋自身：每轮 5 个交锋格，叙事耗时 10 分钟，常规 3 轮共 30 分钟，不足 1 游戏小时按 1 游戏小时结算
突破交锋自身：每阶段 1 个交锋格，阶段耗时由突破模板声明，总耗时暂定 1～6 游戏小时
战斗 / 突破交锋均沿用 gap 最大 1 游戏日，不额外设置实现层时间预算限制
```

正式交锋结果包应区分 `b1_world_elapsed_hours`、`nonparticipant_progress_hours`、`encounter_scene_elapsed_minutes`、`encounter_accounting_hours` 和 `participant_gap_hours`。普通行动队列只承接交锋结束后的后续行动，不记录战斗 5 格序列或突破阶段选择。

## 7. 数据字段建议

### 7.1 普通行动指令

| 字段 | 含义 |
| --- | --- |
| `command_id` | 行动指令唯一标识 |
| `command_type` | 行动类型：`cultivate`、`meditate`、`rest`、`heal`、`craft`、`travel`、`visit`、`apply_resource`、`breakthrough_open`、`minor_breakthrough`、`managed` |
| `actor_ref` | 执行主体引用 |
| `character_id` | 玩家角色或 NPC 角色标识 |
| `target_node_id` | 目标地图节点，可为空 |
| `target_ref` | NPC、宗门资源、物品、设施或其他目标引用 |
| `duration_hours` | 本指令声明或模板推导的持续小时，可为空 |
| `selected_items` | 玩家选择携带或使用的物品列表 |
| `resource_inputs` | 绑定到行动的资源输入项列表 |
| `location_requirement` | 指令要求的地点条件，可为空 |
| `seclusion_policy` | 闭关或长期低交互策略：`safe`、`standard`、`risky` 或空 |
| `managed_mode` | 托管模式：`explicit`、`timeout_policy` 或空 |
| `f1_eligible` | 是否允许该指令作为 F1 候选 |
| `completion_condition` | 结束条件，例如时长、资源耗尽、阈值达到、窗口关闭或玩家中止 |
| `interruption_policy` | 中断策略，例如摘要、自动处理、软中断、硬中断 |
| `safe_default_policy_ref` | 低风险事件或超时时可用的安全默认策略引用 |
| `bound_resource_years_ref` | 洞天、闭关或长期修炼绑定的资源年包引用，可为空 |
| `batch_settlement_summary_ref` | F1 批量结算摘要引用，可为空 |
| `created_world_day` | 创建时世界日 |
| `created_world_hour` | 创建时世界小时 |
| `created_speed_context` | 创建时速度上下文：`F1`、`N1`、`B1`、`P0` |
| `submitted_by_player_id` | 提交玩家标识 |
| `source` | 指令来源：`explicit_player`、`timeout_managed`、`system_fallback` |
| `status` | 队列状态：`queued`、`running`、`completed`、`skipped`、`failed` |

| 字段 | 含义 |

| `validation.failed_reason_tags` | 失败原因标签 |
| `validation.checked_world_day` | 校验发生的世界日 |

| `validation.location_check` | 当前地点、目标地点和路线条件检查结果 |
| `validation.state_check` | 角色状态、境界、功法和风险阻止检查结果 |
| `validation.event_conflict_check` | 当前事件、局部时停、B1 或 P0 冲突检查结果 |

### 7.3 自动兜底状态

| 字段 | 含义 |
| --- | --- |
| `fallback_id` | 兜底记录唯一标识 |
| `character_id` | 进入兜底的角色 |

## 8. UI 展示边界

普通 UI 应展示玩家本人当前执行指令、最多 3 条预输入、可编辑状态、入队失败原因、执行前失败原因、资源输入消耗时点、自动兜底状态、显式托管状态、公开速度档位、行动完成摘要和个人日志。

长期行动若可进入 F1，UI 还应展示其 F1 条件是否满足、资源绑定是否完整、结束条件、中断策略、无安全默认时为何不能进入 F1，以及批量摘要中按 F1 / 批量结算处理等级区分的 `auto / summary / soft_interrupt / hard_interrupt` 和断点原因。

普通 UI 不展示其他玩家私人事件归因、隐秘局部时停原因、其他玩家具体队列、未公开突破选择、隐藏资源输入、内部校验明细、原始倍率、Debug 字段或 C1 内部逐 tick 明细。外部玩家只能看到中性的速度状态、公开事件摘要和世界层结果。

B1、P0、局部时停和 C1 期间，UI 应明确提示当前行动是否仍在结算、是否可编辑普通队列、是否等待本人处理事件、是否已进入自动兜底，以及普通队列不会替代交锋轮选择或 P0 公共提交 / 全员决策。

## 9. MVP 范围

MVP 应实现：

1. 当前执行指令 + 最多 3 条预输入指令。
2. 入队时当前合法性校验。
3. 执行前再次校验。
4. 队列为空或校验失败后自动兜底。
5. 低风险吐纳，中高风险休整。
6. 自动兜底强制降至 N1。
7. 自动兜底不参与 F1。
8. 闭关三档预案。
9. 显式托管行动。
10. 大境界突破在当前满足条件时可预输入开启指令。
11. 个人即时处理事件保留玩家处理权。
12. 资源输入绑定行动或事件选项，并按世界小时结算残余效果。
13. B1 交锋区分世界推进、现实提交窗口和交锋自身结算耗时。
14. 长期低交互行动的 F1 候选字段、资源绑定、结束条件和中断策略。

MVP 不实现：

1. if-else 条件脚本。
2. “未来满足条件后自动执行”。
3. 前置产出和后置消耗的未来推导。
4. 通用事件默认策略表。
5. 用预输入替代正式战斗、突破挑战和重大事件选择。
6. 让自动兜底伪装成长期高速计划。

## 10. 验收约束

1. 客户端提交的行动必须只表达意图，不能绕过服务端校验直接修改角色、资源、位置、事件或宗门状态。
2. 每条普通指令必须至少经过入队校验和执行前校验；执行前失败必须跳过该指令、记录日志并进入自动兜底。
3. 普通队列最多保留当前执行指令和 3 条预输入，不得扩展成条件脚本、未来规划器或资源锁定系统。
4. 自动兜底必须低收益、强制 N1、`f1_eligible=false`，不得作为高速推进依据。
5. 显式托管不得主动消耗新高价值资源、发起高风险突破、进入高危区域或处理重大不可逆选择。
6. 长期行动缺少结束条件、资源绑定、中断策略或安全默认时，不得进入 F1。
7. C1 追赶只能补确定性行动进度、收益、消耗、衰减、恢复、队列切换和已知结果，不得触发新的随机个人即时处理事件或普通机缘；符合硬条件的候选可继续累积未触发压力。
8. 普通队列不得替代 B1 正式交锋、突破挑战、P0 公共提交 / 全员决策或重大事件的玩家决策。
9. UI 和日志不得泄露其他玩家私人事件归因、隐秘局部时停原因、隐藏资源输入或 Debug 字段。
