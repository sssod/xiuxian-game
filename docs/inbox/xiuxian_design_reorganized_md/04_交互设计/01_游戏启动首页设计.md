# 交互设计｜游戏启动首页设计

## 1. 当前状态

本页面仍处于交互约束草案阶段，当前只固定启动首页必须承接的入口、状态和不可误导的边界，不维护具体视觉稿、像素布局、Figma 节点或旧来源清单。

启动首页服务于玩家从打开游戏到进入房间大厅、读取存档或加入私人房间的第一步决策。它不负责真灵选择、当前世角色初始化、进入世界后的新手教学或普通行动队列编辑；这些内容应在后续页面或对应系统中承接。

## 3. 用户目标与入口

玩家进入启动首页时，需要完成以下目标之一：

1. 创建本地单人房，用于单人测试或正式单人游玩。
2. 创建私人多人房，并在开局前配置可加入的玩家槽位。
3. 加入未开局的私人多人房。
4. 读取已有房间存档，按存档原模式继续。
5. 查看当前是否存在可恢复、不可读取或版本不兼容的存档。

启动首页的入口来自游戏根入口或退出到标题页后的返回入口。玩家完成创建、读取或加入后进入房间大厅；取消创建、加入失败、读取失败或断开连接后回到启动首页并保留可理解的失败原因。

## 4. 必须表达

1. 本地单人房和私人多人房是不同模式，创建后存档类型不能互转。
2. 读取存档必须显示该存档的原模式，不能把单人存档伪装成多人房，也不能把多人存档降级为单人继续。
3. 私人多人房在 MVP 中至少支持 3 人共玩，并应在开局前表达玩家槽位、准备状态和加入窗口。
4. 多人房开局后不接受新玩家中途加入；断线玩家只能回到原玩家槽位。
5. 创建房间时需要明确房间名称、模式、玩家槽位上限和世界种子策略。
6. 加入私人房间时需要表达连接目标、房间状态、是否已开局、槽位是否可用和失败原因。
7. 读取存档时需要表达最近保存时间、房间模式、当前世界时间或恢复摘要，以及是否存在未完成关键状态需要恢复。
8. Debug / 测试入口若存在，必须与普通游玩入口区分，不作为玩家默认路径。

## 5. 页面区块与信息优先级

启动首页的首要信息应是可执行入口，而不是世界观说明或营销式展示。

推荐信息优先级：

1. 主入口区：创建本地单人房、创建私人多人房、加入私人房间、读取存档。
2. 存档恢复区：展示最近存档、模式、保存时间、可继续状态和不可读取原因。
3. 多人配置区：展示房间名、玩家槽位、加入方式、世界种子策略和开局前锁定提示。
4. 连接状态区：展示连接中、连接失败、房间已开局、槽位已满、版本不匹配等状态。
5. 辅助入口区：设置、Debug / 测试模式、版本信息或退出入口。

页面只记录稳定区块和信息层级，不固定具体按钮位置、组件坐标、背景图或 Figma 节点。

## 6. 操作流程与状态

创建本地单人房：

```text
选择本地单人
→ 确认房间名称和世界种子策略
→ 创建 RoomState
→ 进入房间大厅
→ 后续进入真灵初始化流程
```

创建私人多人房：

```text
选择创建私人多人房
→ 设置房间名称、玩家槽位上限和世界种子策略
→ 创建房间并展示加入信息
→ 开局前玩家加入并占用槽位
→ 全部必要条件满足后进入真灵初始化流程
```

加入私人房间：

```text
输入或选择私人房间连接信息
→ 校验连接、版本、房间状态和槽位
→ 成功则进入房间大厅
→ 失败则回到启动首页并展示失败原因
```

读取存档：

```text
选择存档
→ 校验存档版本、模式和恢复状态
→ 恢复 RoomState
→ 进入房间大厅或恢复摘要
```

启动首页需要覆盖的状态：

1. 首次启动：无存档时仍可创建本地单人房和私人多人房。
2. 有可用存档：优先展示最近可继续房间，但不遮蔽新建入口。
3. 存档不可用：展示不可读取原因，不删除或覆盖存档。
4. 多人连接中：避免重复提交加入请求。
5. 多人连接失败：说明失败类别，例如房间不存在、已开局、槽位已满、版本不匹配或连接超时。
6. 创建参数缺失：禁止提交，并指出缺失项。
7. Debug / 测试模式：仅在明确入口中出现，不混入普通创建流程。

## 7. 不表达或 Debug 边界

普通启动首页不展示：

1. 内部 `room_id`、`player_id`、`slot_id`、随机命名空间或完整存档结构。
2. 他人真灵偏好、真灵分配随机顺序、私人剧情线细节或隐藏后手归因。
3. 共享世界日历的完整速度规则、结果包内部字段、行动队列校验细节或 Debug 回放。
4. 具体数值公式、事件权重、资源刷新细节或未揭示剧情内容。
5. 包外旧稿、历史方案对照或废弃入口说明。

Debug / 测试模式可以显示房间种子、构建版本、连接目标、存档校验摘要和恢复诊断，但必须明确标记为 Debug / QA 信息。
