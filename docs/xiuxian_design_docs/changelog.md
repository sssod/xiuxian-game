## 2. 总体变化

本次变更不是目录重排，而是把 v1.5 时间、F1、局部时间域、事件流和跨系统数值裁定吸收到正式设计包，并把相关系统、数值、交互文档同步到同一口径。

核心结论：

1. 新增时间速度与局部时间域主文档，正式承接 F1、外界日历、洞天资源年、局部时间域和轮回总时长口径。
2. 新增 v1.5 数值合并待裁决清单，用于集中保留仍需用户裁决、补表或重新验算的项目。
3. F1 从“长期等待加速”收束为按外界日提交边界、F1 校验断点和 F1 中断断点推进的批量结算状态。
4. 事件系统从来源型顶层分类进一步收敛为 `EventNode`、事件层级、候选池二段抽样、双层伪随机保底和简化触发提案裁决。
5. 洞天和时间阵法不再被视为自动提供完整修炼收益的时间压缩器，必须同时受资源年、寿元、功法适配、风险和外界日历约束。
6. 新增修炼系统数值投放收敛裁决，用于盘点修炼消耗资源与时间后已经承诺获得的数值项。
7. 根据用户裁决，主动吐纳、闭关修炼和自动运转不再增加当前主修道功掌握度；功法掌握增长归入研习功法等功法系统行动。
8. 修为丹药从“主动吐纳资源输入”调整为“直接服用生成体内药性”；体内药性由兼容修为增长流逐步消化，正常修行不默认增加经脉压力。

## 4. 主要设计变更

### 4.1 时间、F1 与世界日历

- F1 默认速度调整为 `1.5 秒 = 1 外界日`，并保留 `1 / 1.5 / 2 秒` 调参档。
- 接受当前约 `47.55 外界年` 的理论直线基线；默认现实目标为 `32 小时`，Debug 可按最高 `50 小时` 与 `100 外界年` 复算。
- 玩家可见速度状态收敛为 `N1 / F1 / B1 / P0`，不新增独立宏观流年速度。
- 在线 F1 固定以 `1 外界日 / 批` 作为提交上限，不按阶段、人数或事件密度动态拉长批次。
- 普通数值变化只作为日内结算分段；需要提交并重检继续 F1 的情形是 F1 校验断点；必须退出到 N1 / B1 / P0 的情形是 F1 中断断点。

### 4.2 境界节奏与修炼数值

- `03_数值设计/01_修为境界与期望游玩时间建模.md` 重排分阶段现实目标，默认合计保持 `32.00h`，其中 N1 `21.12h`、F1 `7.04h`、B1 `3.84h`。
- MVP 优先目标炼气到化神默认约 `13.8h`，其中 N1 约 `9.76h`、F1 约 `2.55h`、B1 约 `1.49h`。
- 炼气到筑基以外部世界修炼和 N1 学习决策为主；筑基到金丹开始引入独立时间域；金丹以后通过集中开放的高速时间域提高多人 F1 占比。
- 修炼公式新增分域时间、资源支撑年、资源不足年、寿元扣除时间域和结果包字段。
- 资源不足年份仍消耗寿元，但修为收益默认只保留 `0%-20%` 基础吐纳收益，并提高心魔、经脉、枯坐和状态恶化风险。

### 4.3 局部时间域、洞天与资源年

- 新增 `LocalTimeDomainProfile`、`TimeDomainActivityAllocationProfile`、`CultivationResourceYearBundle` 和 `ReincarnationRunTimePolicy` 等配置口径。
- 洞天 / 时间阵法分为 T0-T5，但具体倍率、成本、风险和开放窗口仍待补表。
- 局部时间域默认分配为 `70%` 修行成长、`30%` 支持行为；修行成长中默认 `20%` 功法研习、`80%` 道功修炼。
- 洞天外 F1 外界流年只有 `10%-20%` 建议作为普通修炼 / 低阶修炼，其余主要用于资源等待、长耗时生产、长期游历和宗门职责。
- 阶段预算、市场、宗门库存、节点资源和 NPC 宏观成长读取外界日历，不读取洞天内主观时间。
- 轮回重修不再承诺总通关时间一定短于单世通关；其主要收益改为提高稳定性、成功率、资源利用率、路线确定性和结局质量。

### 4.4 事件流与随机事件分类

- 顶层事件类型改为五类：后台结算事件、信息回读事件、个人即时处理事件、世界窗口事件、同步处理事件。
- 移动、节点、宗门、世界演化、控制权、传闻和专用链入口降为来源标签或触发入口，不再作为顶层事件类型。
- 选择、检定、投入、交锋、探索揭示、窗口、余波和协同 / 仲裁改为事件内部玩法模块。
- 事件主配置收敛为 `EventNode`：事件编号、事件层级、基础权重、候选池入口、玩法类型、玩法配置引用和事件链路由构成主字段。
- 旧 `top_level_type`、来源标签、事件时间模式、F1 处理等级、结果强度和可见性策略从事件主配置移出，改为派生字段、玩法配置、日志配置或 settlement 结果。
- `event_tier` 表示与修为境界阶段、地图 `node_level` 对齐的事件层级；它不是 F1 处理等级、风险等级或结果强度。
- `base_weight` 表示事件基础发生率、稀有度和事件层级设计基准；地形、行动类型、路线状态和标签默认作为候选池进入 / 移出条件，不再重复作为权重倍率。
- 随机事件候选池采用二段抽样：第一段用候选池 / 语义桶级无事件权重决定本池是否出事件，第二段用事件节点级附加权重参与同池事件抽选。
- 候选池级保底使用 `pool_occurrence_mass`、`no_event_current_weight` 和 `pool_pity_decay_rate`；事件级保底使用 `event_select_weight = effective_weight + event_pity_bonus_weight`。
- 首版不设置事件级附加权重累积上限；`event_pity_accrual_rate` 是事件节点级配置，用于控制高基础权重、常见或填充事件是否享受事件级触发累积。
- N1、F1、后台追赶和局部时间域复用同一事件候选池与伪随机状态；C1 或其它时间追赶期间不触发新随机个人即时处理事件，但继续累积伪随机状态。
- 触发来源只作为回放、审计和调试字段；同桶竞态先按事件层级裁决，同层级按当前 `event_select_weight` 加权再随机。
- 通用限量首版只保留个人单事件限量和全世界 P0 限量。
- F1 处理等级收敛为 `silent / summary / auto / soft_interrupt / hard_interrupt`，并明确不同于事件层级。

### 4.5 系统文档联动

- 单人 / 多人流程同步 F1 基准、外界日提交边界、校验断点、中断断点和批量结果包口径。
- 行动指令补充长期低交互行动进入 F1 所需的结束条件、资源绑定、中断策略、安全默认和批量摘要字段。
- 修炼玩法补充局部时间域闭关所需主观年、资源支撑年、资源不足低效、寿元时间域、闭关事件摘要和硬中断要求。
- 突破玩法明确大境界突破和高风险突破契机不得由普通预设自动处理；F1 中触发时按提醒、摘要或中断处理，突破挑战仍进入 B1。
- NPC、宗门、洞天、移动和地图节点文档同步外界日历、来源标签和事件顶层分类口径。
- 宗门库存、时间阵、洞天席位、职责和审批读取外界日历；低风险宗门职责可参与 F1，重大宗门来源事件和资源冲突中断 F1。

### 4.6 交互文档联动

- 主界面待处理区按玩家可见性和可互动性区分信息回读、个人即时处理、世界窗口与同步处理事件；后台结算事件不进入普通待处理入口。
- 修为页面补充现实耗时、外界经过、洞天内修炼年数、寿元、资源支撑年、资源不足年、F1 中断策略和轮回不必然更快的页面表达。
- 指令管理页面只管理普通行动队列，不保存个人即时处理事件选项、同步处理事件提交或世界窗口进入后的专项选择。
- 指令管理页面补充长期行动 F1 条件、洞天闭关资源绑定、结束条件、中断策略、安全默认和 F1 批量摘要展示。

### 4.7 验算与验收

- `03_数值设计/08_数值验算.md` 新增 Case K-T，覆盖 F1 速度、批量提交边界、事件流、洞天资源年、局部时间域拆分、非相关对象惰性结算和轮回总时长。
- 验算要求覆盖 F1 `1 / 1.5 / 2 秒` 调参档，且任一档位下内部都不得执行 24 个全量 `hour_tick`。
- F1 批量结算结果必须可复盘，包括采样随机种子、事件流、日内结算分段、F1 校验断点、F1 中断断点、外界日提交边界和聚合收益。

### 4.8 修炼系统数值投放收敛

- 新增 `00_INDEX/修炼系统数值投放收敛裁决.md`，把修炼行动直接结算、研习功法结算、小境界 / 大境界承接、丹药资源输入和非直接投放项目拆开记录。
- 明确修炼系统的主投放仍是修为绝对值、境界段标准化进度，以及经脉压力、根基质量、修为纯度、残余资源效果、突破准备变化等质量或压力结果。
- 主动吐纳、闭关修炼和自动运转只读取当前主修道功掌握度、相性、吸收和转化口径，不写入 `MethodState.mastery_exp`、掌握等级或掌握度变化。
- 修为丹药可直接服用生成体内药性，但不得即时发放完整修为；主动吐纳、闭关修行片段、自动 / 被动运转和明确允许的修为事件按配置消化药性。
- 经脉压力不再是正常修行的默认副产物，主要来自丹药、灵材、符箓、阵法灌注、强行吸收外源灵气、不适配资源和其他高风险外源条件。
- `CultivationTickResult`、阶段资源包循环示例和功法数值结果中移除 `method_mastery_delta` 的正向产出口径。
- 功法掌握经验、掌握等级、标准化掌握度、当前可修上限变化和解锁项归属功法系统，由研习功法等功法系统行动承接。
- “主修道功经验转移”表述收敛为“已学道功掌握经验转移”，避免暗示修炼过程会产出主修道功经验。
