# 系统设计｜单人游戏与多人共玩流程

## 1. 设计定位

本文固定从创建房间到进入共享世界推进的完整流程，负责说明房间边界、玩家槽位、真灵分配、共享日历、房间速度、单人与多人的差异、存档隔离和最小验收链路。

本文只维护房间级流程和系统状态边界。真灵与角色初始化细节由《真灵初始化与角色初始化流程》（`02_真灵初始化与角色初始化流程.md`）承接；普通行动、战斗、突破、随机事件和页面表达由对应包内文档维护。

## 2. 当前结论

1. 基础流程是“共享世界 + 可保存房间 + 权威结算 + 可暂停 + 可加速低交互阶段 + 单人与多人底层同构”，不是传统实时 MMO，也不是纯单机暂停制 RPG。
2. 房间是所有运行时状态、存档、玩家槽位、世界种子、日志和回放的边界；单人房也是一等公民，只是权威进程可在本地运行。
3. 单人与多人共享底层规则和数据结构，但存档永久隔离：单人存档不能升级为多人存档，多人存档不能降级为单人存档。
4. MVP 多人以分宗并行、间接竞争、PvE 沙盒演化、信息不完全和低频关键同步为核心，不以强 PvP 或高频直接互动为核心。
5. MVP 多人房开局后锁定玩家槽位，不允许新玩家中途加入；断线玩家只能以原玩家身份重连。
6. 预设真灵在多人房中采用偏好提交后的服务器随机分配，不采用先点先得，避免网络延迟和 UI 操作决定稀缺身份归属。

## 4. 核心循环或触发入口

房间入口包括：

```text
新建本地单人房
新建私人多人房
加入未开局的私人多人房
读取已有房间存档
```

创建或读取房间主流程：

```text
选择入口
→ 创建或读取 RoomState
→ 校验 RoomConfig 与存档版本
→ 初始化或恢复世界种子、地图节点、宗门、资源窗口、NPC 与日志索引
→ 进入房间大厅
→ 开局前玩家占用玩家槽位
→ 真灵选择与竞争模拟
→ 创建或恢复玩家真灵
→ 创建或恢复当前世角色
→ 写入初始日志 / 恢复摘要
→ 进入共享世界日历
```

房间主循环：

```text
房间加载 / 恢复
→ 世界日历运行
→ 玩家在允许状态下编辑普通短队列
→ 服务器按当前速度推进 hour_tick
→ 行动完成点 / 小时 tick 执行校验、结算、事件判定
→ 宗门持续行动、地图节点、资源窗口、NPC 与传闻更新
→ 个人事件进入局部时停 + 外部 N1
→ 正式交锋 / 突破挑战进入 B1
→ 全局公共事件进入 P0
→ 事件结束后 C1 追赶或恢复速度判定
→ 合并结果包
→ 回写角色、真灵、宗门、节点、资产、日志、传闻和 TimelineReplay
→ 玩家阅读报告并规划下一阶段
```

读取存档时，未完成的局部时停、C1 追赶、B1 交锋、P0 全局暂停和待合并结果包必须先恢复为明确状态，再允许玩家继续输入普通行动。

初次进入世界流程：

```text
真灵分配完成
→ 创建 TrueSpiritState
→ 绑定真灵名、剧情线、轮回账本和暴露初态
→ 创建当前世 CharacterState
→ 写入角色姓名、性别、年龄、出生区域、出生位置、外观、属性、初始物资
→ 写入真灵背景日志与当前角色自知日志
→ 初始化 CommandQueue
→ 初始化 FallbackState 为空
→ 初始化 ManagedActionState 为空
→ 进入 world_running
```

初次角色不生成世俗背景身份。出生位置、外观、属性和初始物资可以影响可玩开局，但不得反向生成家族、门第、官籍、职业履历或主线身份锚点。

## 5. 规则与状态

### 5.1 房间模式与存档边界

| 模式 | 用途 | 玩家数量 | 权威位置 | 存档边界 |
| --- | --- | --- | --- | --- |
| `single_local` | 本地单人测试与正式单人游玩 | 1 | 本地房间进程 | 单人存档，不可转多人 |
| `private_hosted` | 私人服务器 / 主机房间 | 开局前锁定槽位 | 私人服务器 / 主机 | 多人存档，不可转单人；MVP 开局后不可加人 |
| `loaded_room` | 读取存档继续 | 取决于存档原模式 | 取决于存档原模式 | 按原模式读取，不转换 |

房间创建时固定 `world_seed` 和 `save_lineage`。世界种子用于地图初始生成、真灵候选池排序、非玩家宗门初态、资源窗口初态和可复盘随机命名空间；玩家不能通过刷新 UI 改变已经提交的房间级随机结果。

`single_only` 与 `multiplayer_only` 不允许互相转换，也不允许通过读取存档改写。多人存档即使只剩一名玩家继续游玩，也继续按多人房间规则保存、暂停、恢复和结算。

单人与多人只在规则和数据结构上同构，不在存档层面互通。同构范围包括 `RoomState`、`world_day / world_hour`、`CommandQueue`、`ResultPackage`、`TimelineReplay`、真灵与角色分层；运行时历史、玩家槽位、私人日志和隐藏归因不能跨存档类型迁移。

房主可以创建、保存、暂停和恢复房间。房主权限不能绕过结算规则，不能直接修改玩家角色、真灵、资产、后手和世界结果。无人在线时默认世界保持静止；只有房间规则明确启用离线托管推进时，才允许在所有玩家都有合法显式托管或房间托管策略的情况下继续推进。

### 5.2 玩家槽位与加入规则

多人房间使用玩家槽位管理，不使用即时匹配。MVP 加入窗口只存在于房间进入 `world_running` 之前：

```text
房间大厅开放
→ 玩家加入并占用空槽位
→ 玩家完成真灵选择和角色初始化
→ 全部必要槽位 ready 或房主按规则开局
→ 房间进入 world_running
→ 锁定玩家槽位
→ 不再接受新玩家中途加入
```

`reserved` 槽位只能用于开局前邀请或掉线重连，不表示开局后可以补进新玩家。开局后断线玩家回到同一 `player_id / slot_id / true_spirit_id`，不是新玩家加入。

正式版若支持中途加入，必须由房间创建时显式开启 `special_midgame_join`，且加入点处于非 B1、非 P0、非局部时停、非 C1 追赶、无待合并结果包的稳定小时快照。新玩家只能获得加入时允许的新真灵入口，不得改写已发生历史；公开历史、私人日志、隐藏后手归因和 Debug 记录仍按可见性过滤。该能力不进入 MVP，正式版默认也不开启。

### 5.3 真灵选择与竞争模拟

真灵选择发生在房间大厅到进入世界之间，目标是让玩家获得跨世身份锚点，同时保留预设真灵的稀缺感，并避免多人房靠抢 UI 操作获得优势。

| 类型 | 说明 | 剧情线 | 是否参与竞争模拟 |
| --- | --- | --- | --- |
| 预设真灵名 | 房间候选池中已有的真灵名，绑定专属剧情线和初始角色模板 | 专属剧情线 | 是 |
| 自定义真灵名 | 玩家自定义名称，不占用预设名额 | 通用弱剧情线 | 否 |

多人房默认使用“玩家提交偏好，服务器随机分配”：

```text
房间根据 world_seed 生成预设真灵候选池
→ 所有玩家看到同一候选池和可选自定义入口
→ 玩家提交 0-N 个偏好真灵名，或选择自定义真灵名
→ 到达准备截止条件后锁定所有提交
→ 服务器使用 room_rng.true_spirit_assignment 随机排序玩家槽位
→ 按随机顺序尝试满足玩家偏好
→ 偏好冲突时由随机顺序决定归属
→ 未获得偏好的玩家进入剩余候选随机分配或自定义真灵确认
→ 写入 TrueSpiritAssignmentLog
```

偏好只表达倾向，不保证获得。随机顺序必须由房间种子、玩家槽位、提交摘要和专用随机命名空间生成，保证可复盘、不可通过 UI 刷新重掷。

单人房中，玩家选择预设真灵名时直接获得；玩家选择随机真灵时从候选池随机分配。未被选择的预设真灵名可作为世界线索、NPC 传闻、宿敌、后续真灵故事或不可见背景保留，但不得阻断玩家当前选择。

多人竞争模拟必须满足：

```text
不能先点先得
不能因网络延迟决定归属
不能在提交后通过刷新重掷
不能公开其他玩家的完整偏好
不能把真灵分配结果直接暴露为私人剧情归因
必须记录随机命名空间、提交摘要、分配顺序和最终归属
```

真灵分配可见性：

| 信息 | 本人可见 | 其他玩家可见 | Debug 可见 |
| --- | --- | --- | --- |
| 本人偏好列表 | 是 | 否 | 是 |
| 他人偏好列表 | 否 | 否 | 是 |
| 最终真灵名 | 按房间公开策略 | 按房间公开策略 | 是 |
| 专属剧情线细节 | 是 | 否 | 是 |
| 分配随机顺序 | 否 | 否 | 是 |

### 5.4 共享世界日历与速度状态

房间主时间字段为 `world_day` 和 `world_hour`。1 游戏日 = 24 游戏小时；运行时结算粒度是 `hour_tick`，不是回合、季度或行动格。

| 状态 | 用途 | 现实时间 : 游戏时间 | 规则含义 |
| --- | --- | --- | --- |
| `N1` | 常规推进 | 15 秒 = 1 游戏小时 | 默认多人速度；可编辑普通行动队列 |
| `F1` | 高速推进 | 2 秒 = 1 游戏日 | 全员处于长期低交互行动时启用 |
| `B1` | 交锋慢速 | 60 秒现实时间 = 1 游戏小时世界推进 | 正式战斗、突破挑战、秘境关键交锋、玩家直接交锋；参战交锋自身耗时另由战斗 / 突破模板结算 |
| `P0` | 全局暂停 | 游戏时间不流动 | 公共阶段事件、同步保护、主机暂停、全局决策 |

速度优先级固定为：

```text
P0 > B1 > N1 > F1
```

速度选择规则：

```text
如果存在 active_global_pause → P0
否则如果存在 active_formal_encounter → B1
否则如果任一玩家处于 local_time_stop → N1
否则如果全员满足 F1 条件 → F1
否则 → N1
```

F1 条件：

```text
所有玩家都有当前行动
所有玩家处于长期低交互行动
所有当前行动均允许 f1_eligible=true
没有玩家处于自动兜底
没有待响应局部事件
没有 B1 / P0 / C1
没有即将到期的关键公开窗口
```

F1 不是跳转未来，不允许“推进至下一事件”“跳到下一节点”“跳到预设未来时间”。F1 只是按固定 tick 连续压缩推进，所有行动、资源衰减、节点变化、宗门持续行动和日志仍按权威结算写入。

普通行动队列使用“当前指令 + 最多 3 条预输入”的短队列。队列编辑不冻结世界；玩家在 F1 中打开普通队列编辑界面时，房间应降为 N1，避免高速状态下误操作。阶段摘要只负责阅读、报告和规划承接，不作为底层结算单位。

### 5.5 局部时停、C1、B1 与 P0

个人事件可以让事件玩家进入局部时停，事件玩家角色时间冻结在触发 `world_hour`，其他玩家、宗门和世界继续 N1。`gap = 世界当前时间 - 玩家冻结时间`，最大 1 游戏日。

`gap` 达到上限时，有安全默认选项则自动执行安全默认；无安全默认选项则进入 P0 同步保护。

局部时停结束后执行 C1 追赶补结算。追赶只补确定性行动进度、修炼收益、资源消耗、药性衰减、伤势恢复和队列切换；追赶期间不触发随机个人事件、普通机缘、普通战斗、软机会事件、普通心魔或普通资源反馈。

B1 用于正式战斗、突破挑战、秘境关键交锋和玩家直接交锋。B1 决策窗口暂定为 60 秒现实时间；未提交者执行预设策略或超时安全默认。P0 全局暂停必须有公开原因、参与要求、默认处理策略和状态记录。

B1 世界推进按“每 60 秒现实时间让非参战玩家和世界推进 1 游戏小时”处理。战斗交锋自身按 5 个交锋格 = 10 分钟叙事耗时，常规 3 轮共 30 分钟，不足 1 游戏小时按 1 游戏小时结算；突破交锋每阶段只输入 1 个交锋格，阶段耗时由突破模板声明，总耗时暂定 1-6 游戏小时。交锋结果包记录 B1 世界推进、非参战推进、交锋叙事耗时、交锋结算耗时和参战 gap。

### 5.6 离线、超时与托管

离线和超时玩家采用稳健托管，但必须区分三种来源：

| 类型 | 来源 | 是否可参与 F1 | 用途 |
| --- | --- | --- | --- |
| 自动兜底 | 队列空或执行前校验失败 | 否 | 防止角色冻结，等待玩家补指令 |
| 显式托管 | 玩家主动输入或房间托管设置 | 满足条件时可 | 低关注、低收益、安全运行 |
| 超时安全默认 | 局部事件 / B1 / P0 超时 | 否 | 防止多人时间卡死 |

托管优先级：

```text
保命 / 避险
> 不暴露核心后手线索
> 延续安全连续状态
> 巩固修炼或基础修炼
> 维持低风险宗门职责
> 休整 / 警戒 / 停留
```

托管不得主动执行高风险突破、主动转世、叛宗、宗门战争、暴露核心后手线索、高危秘境、强 PvP、消耗稀有不可逆资源、重大路线选择、高风险宗门外洞府 / 普通藏宝开启或破阵。

### 5.7 多人竞争边界

MVP 多人保留轻量间接竞争：宗门节点控制、世界资源名额、秘境 / 机会窗口、宗门库存申请与预留、路线发现或封锁、NPC 关系偏移、传闻判断、宗门遗产清点、宗门外洞府 / 普通藏宝发现与争夺、突破公开影响。

MVP 不以玩家直接交易、直接赠予、互相护法、玩家共同秘境、直接斗法、离线袭击、破坏他人突破、直接抢夺他人洞府或核心后手、强 PvP 围杀、复杂同宗议事投票为核心验证对象。

若出现直接玩家冲突，必须进入 B1 `FormalEncounterState`，并受正式战斗、事件和可见性规则约束。

同宗多人不走强制投票，不恢复宗门主行动建议，也不引入宗门主行动冲突。玩家通过资源申请、事件处理、宗门贡献、职位、NPC 关系、传闻、个人行动和后手间接影响彼此。

后手、遗产与无主遗留设施在多人中遵循同一资产规则：玩家转世前留下的宗门个人洞府库存按有主遗产清点回收；宗门外个人洞府和普通藏宝是无主遗留设施，可能因线索泄露、条件满足或破阵被其他角色提前打开；真灵藏宝作为正式后手由同一真灵跨世感应和开启，受设置数量与单个容量限制，MVP 阶段不作为他人直接抢夺目标。

### 5.8 单人与多人的差异

| 维度 | 单人房 | 多人房 |
| --- | --- | --- |
| 权威结算 | 本地房间进程权威 | 私人服务器 / 主机权威 |
| 时间推进 | 可由玩家更自由暂停和继续，但仍表达为房间状态 | 受全员行动、局部时停、B1、P0 和超时策略约束 |
| F1 条件 | 只检查单个玩家、AI 宗门和世界状态 | 必须全员满足长期低交互条件 |
| 超时 | 通常不需要强制超时 | 必须有安全默认，防止卡死 |
| 可见性 | 可简化为本人 / 世界 / Debug | 必须过滤私人归因、他人偏好、隐秘后手和 Debug 信息 |
| 竞争压力 | AI 宗门、资源窗口、世界事件提供压力 | AI 宗门 + 真实玩家间接竞争 |
| 真灵选择 | 可直接获得预设真灵 | 预设真灵通过随机分配竞争模拟 |
| 直接互动 | 不适用 | MVP 不以直接互动为核心 |

单人不是“删掉多人规则”。单人只是参与者少，因此等待、超时、可见性过滤和真灵分配竞争更简单。

## 6. 资源、角色、地图、事件或 NPC 接口

房间流程读取或写入以下系统口径：

| 接口 | 读取 | 写入 |
| --- | --- | --- |
| 真灵与角色 | 真灵候选池、玩家偏好、当前世角色初始化规则 | `TrueSpiritState`、`CharacterState`、真灵分配日志、角色初始日志 |
| 行动指令 | 当前指令、最多 3 条预输入、托管策略、自动兜底状态 | `CommandQueue`、`ManagedActionState`、`FallbackState` |
| 地图节点与路线 | 世界种子、地图初态、节点状态、路线可见性 | 节点变化、路线变化、资源窗口变化 |
| 宗门与 NPC | 非玩家宗门初态、宗门持续行动、NPC 关系和传闻规则 | 宗门状态变化、NPC 关系偏移、传闻更新 |
| 随机事件 | 个人事件触发条件、安全默认、局部时停规则 | 事件结果、C1 追赶结果、私人日志与公开摘要 |
| 战斗与突破 | B1 触发条件、交锋模板、阶段耗时和默认策略 | B1 结果包、参战 gap、非参战推进、交锋日志 |
| 后手与遗产 | 宗门个人洞府库存、宗门外个人洞府、普通藏宝、真灵藏宝边界 | 后手、遗产、无主遗留设施和可见性变化 |

所有系统变化必须通过结果包合并，不允许子系统绕过房间权威结算直接改写世界。

结果包至少覆盖角色变化、真灵变化、修炼收益、行动队列变化、托管 / 兜底记录、资源消耗与残余效果、宗门状态变化、节点与路线变化、资产与物品变化、事件结果、B1 交锋结果、P0 开始与结束、后手 / 遗产 / 无主遗留设施 / 传闻 / 可见性变化和多人间接竞争结果。

`TimelineReplay` 至少记录速度变化、队列编辑、指令校验、自动兜底、显式托管、局部时停、C1 追赶、B1 交锋状态片段、P0 全局暂停、真灵分配、房间保存 / 恢复、结果包合并、公开摘要与私人日志分发。

## 8. UI 展示边界

普通 UI 应展示房间模式、房间名称、玩家槽位、准备状态、是否允许中途加入、存档类型、当前世界日 / 小时、公开速度状态、暂停原因、队列可编辑状态、托管状态、公共结果摘要和玩家本人可见日志。

多人房的普通 UI 不展示他人真灵偏好、真灵分配随机顺序、私人剧情线细节、隐藏后手归因、Debug 随机种子、完整结果包内部字段和其他玩家私人日志。

玩家在 F1 中打开普通队列编辑界面时，房间应降为 N1，避免高速状态下误操作。P0 必须向所有受影响玩家展示公开原因、参与要求和默认处理策略。

## 9. MVP 范围

MVP 应实现：

1. 本地单人房创建、保存、读取和恢复。
2. 私人多人房创建，至少支持 3 个玩家槽位共玩。
3. 房间级世界种子、`single_only` / `multiplayer_only` 存档隔离和权威结算。
4. 开局前真灵选择、多人预设真灵偏好随机分配和当前世角色初始化入口。
5. `world_day / world_hour`、`hour_tick`、N1、F1、B1、P0 和局部时停 / C1 恢复。
6. 普通行动短队列、自动兜底、显式托管、超时安全默认的房间级状态承接。
7. 结果包合并、可见性过滤和 `TimelineReplay` 记录。
8. 保存后读取房间，并恢复未完成的关键状态。

MVP 不实现：

1. 开局后新玩家中途加入。
2. 单人存档与多人存档互相转换。
3. 强 PvP、高频直接社交、复杂同宗投票和直接抢夺他人核心后手。
4. 玩家直接交易、直接赠予、互相护法、玩家共同秘境。
5. 宗门主行动建议或宗门主行动冲突。

## 10. 验收约束

1. 单人和多人必须共享房间权威结算、时间字段、结果包和回放结构，但存档类型不能互转。
2. 多人房进入 `world_running` 后，MVP 不接受新玩家槽位；断线只能重连原槽位。
3. 预设真灵分配不能先点先得，不能由网络延迟决定归属，不能在提交后通过刷新重掷。
4. F1 必须连续按 tick 结算，不能跳到未来事件点或跳过日志、资源衰减、节点变化和宗门持续行动。
5. 局部时停不能让事件玩家无限冻结；达到 gap 上限后必须执行安全默认或进入 P0 同步保护。
6. 自动兜底固定 `f1_eligible=false`，并强制房间速度不高于 N1。
7. 直接玩家冲突必须进入 B1 `FormalEncounterState`，不能绕过正式交锋和可见性规则。
8. 玩家可见回放必须按可见性过滤，公开速度变化不得泄露私人事件归因。
