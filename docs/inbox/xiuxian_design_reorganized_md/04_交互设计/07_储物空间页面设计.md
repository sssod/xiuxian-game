# 交互设计｜储物空间页面设计

## 1. 当前状态

本页只记录储物空间页面的稳定交互约束，不定义视觉布局稿、节点级组件坐标或最终美术样式。

储物空间页面应保持统一与简化。玩家在不同入口打开的仍是同一类页面，只是来源容器、目标容器、可执行操作和风险提示不同。

本页只记录稳定交互约束。行囊与库存底层规则见《02_系统设计/06_储物空间系统设计/01_基础行囊.md》和《02_系统设计/06_储物空间系统设计/03_库存系统.md》；商店买卖、NPC 交易和玩家交易规则见《02_系统设计/03_经济系统设计/04_交易系统.md》。

## 2. 核心概念

页面必须区分两个概念：

```text
行囊：角色随身资产容器。
库存：非随身储存空间，绑定在店铺、宗门、节点、洞府、藏宝、真灵藏宝、市场或事件容器上。
```

页面不应把“行囊”和“库存”混称为同一个背包。界面文案可以使用玩家容易理解的名称，但底层交互必须让玩家知道当前物品是随身携带，还是放在某个非随身空间中。

## 3. 页面入口

### 3.1 商店入口

商店入口打开储物空间页面时，应同时打开：

```text
行囊
+ 商店库存
```

规则：

1. 商店入口 NPC 只是服务入口，不是商店库存绑定点。
2. 购买时，来源容器是商店库存，目标容器通常是行囊。
3. 出售时，来源容器通常是行囊，目标容器是商店库存或商店交易缓存。
4. 商店库存缺货、补货、锁定、价格和可见性变化，应从商店或市场容器读取，不从入口 NPC 个人行囊读取。
5. 若入口 NPC 死亡、失踪或替换，页面不应默认搬空商店库存。
6. 玩家与非商店 NPC 的个人交易也可以复用本页，但必须明确显示当前交易对象是 NPC 个人资产，而不是店铺库存。

### 3.2 储物入口

储物入口打开页面时，必须先打开行囊。

如果当前角色拥有合法、可访问的个人非随身储物空间，页面可以同时打开并允许切换：

```text
行囊
+ 个人洞府库存
+ 普通藏宝设置目标
+ 真灵藏宝设置目标
+ 其他合法个人库存
```

规则：

1. 没有合法储物空间时，只显示行囊和不可存取原因，不虚构一个默认仓库。
2. 有多个合法储物空间时，使用清晰的空间切换入口。
3. 切换空间只改变当前目标容器，不自动移动物品。
4. 每个目标容器必须展示自身的访问状态，例如可存取、只可查看、只可取出、已锁定、一次性取出、权限不足。

### 3.3 洞府入口

个人洞府入口打开页面时，应展示：

```text
行囊
+ 当前洞府库存
```

规则：

1. 个人洞府库存可以反复存取。
2. 存入和取出都需要校验地点、权限、洞府状态、角色状态和物品转移规则。
3. 山门宗门分配洞府应在必要时提示宗门管辖、清查、转世前遗产清点或异常接管风险；其中普通库存可按有主资产清点规则回收宗门。
4. 山门外自辟洞府是无主遗留设施风险语境，不进入遗产分配、继承或回收，应在必要时提示隐蔽、防御、维护、开启条件、破阵和被其他角色提前打开的风险。

### 3.4 藏宝入口

藏宝类入口分为设置、查看和取出三种模式。

设置藏宝时：

```text
行囊或合法来源库存
+ 新建藏宝库存
```

规则：

1. 藏宝类储物空间只能在设置藏宝时存入。
2. 设置藏宝时的存入界面复用储物入口的储物空间页面。
3. 设置完成后，该藏宝库存关闭存入能力。
4. 存入前必须明确藏宝地点、隐蔽、防御、解锁条件、阵法或维持消耗等已配置项。
5. 普通藏宝是无主遗留设施风险语境，不进入遗产分配、继承或回收；页面应提示该藏宝未来需要满足开启条件，或可能被破阵、争夺、提前打开。

查看藏宝时：

```text
藏宝内容查看
```

规则：

1. 查看藏宝中的内容不影响藏宝有效性。
2. 查看不等于取出，不产生一次性失效。
3. 查看权限不足时，只展示符合可见性的信息，不泄露完整清单。

取出藏宝时：

```text
行囊或合法目标库存
+ 藏宝库存
```

规则：

1. 藏宝正式取出是一次性的。
2. 页面必须在确认前提示：取出后该藏宝不再作为可继续存取的库存使用。
3. 确认取出后，将可取资产一次性转移到目标容器，并更新藏宝状态。
4. 取出失败时，必须展示失败原因，不得无提示销毁或搬空。

### 3.5 真灵藏宝入口

真灵藏宝是 MVP 阶段正式后手的藏物形态。

规则：

1. 真灵藏宝入口只对同一真灵可感应的后世角色可见。
2. 真灵藏宝可以跨世直接感应和开启；查看不影响有效性。
3. 真灵藏宝取出按藏宝的一次性取出规则处理。
4. MVP 阶段不展示真灵藏宝被他人发现、损坏、移动或搬空的交互。
5. 页面必须表达真灵藏宝的设置数量上限和单个容量上限，不得把它表现成无限跨世背包。
6. 页面可提示真灵解锁条件是否满足，但不得把条件做成可被其他玩家查看的公开清单。

## 4. 页面模式

储物空间页面至少支持以下模式：

| 模式 | 主要用途 | 可执行操作 |
| --- | --- | --- |
| `carry_only` | 只查看行囊 | 查看、筛选、使用合法物品 |
| `shop_trade` | 商店买卖、NPC 个人交易或玩家交易入口 | 买入、出售、报价、确认、查看价格与库存状态 |
| `storage_transfer` | 洞府或其他个人库存存取 | 存入、取出、批量转移 |
| `treasure_setup` | 设置藏宝或真灵藏宝 | 从行囊或合法库存选择存入物，确认后封存 |
| `treasure_view` | 查看已发现或已感应藏宝 | 查看可见内容，不改变有效性 |
| `treasure_withdraw` | 取出藏宝或真灵藏宝 | 一次性取出并关闭该藏宝库存 |
| `event_locked` | 事件奖励、战利品或锁定资产 | 按事件条件领取、查看或等待解锁 |

## 5. 必须表达

页面必须表达以下信息：

1. 当前打开的是行囊、哪一个库存或哪一组可切换库存。
2. 每个物品的位置：随身、个人洞府、宗门、节点、商店、市场挂牌、交易暂存、事件锁定、普通藏宝或真灵藏宝。
3. 物品是否可堆叠，还是独立实例物品。
4. 物品是否 `combat_ready`。
5. 物品是否绑定、封存、挂牌、预留、事件锁定或后手相关。
6. 物品是否可用于当前行动、事件、战斗、突破、交易或存取。
7. 目标库存是否允许当前角色查看、存入、取出或一次性取出。
8. 残余效果不只在储物页面显示，还需在角色状态中提示。
9. 高价值物品、后手物、功法载体、法宝和突破资源的转移应有可追溯提示。

## 6. 操作规则

行囊与库存之间的所有移动都应表现为明确操作：

```text
选择物品
→ 选择数量或实例
→ 选择目标容器
→ 校验权限、位置、状态和物品限制
→ 确认转移
→ 写入资产流水
→ 更新页面状态
```

交互要求：

1. 页面切换、筛选、查看详情不应自动移动物品。
2. 批量转移必须在确认前展示来源容器、目标容器、数量和风险。
3. 操作失败时，保留原资产位置，并展示失败原因。
4. 权限不足时，不应展示调试级完整库存。
5. 被事件锁定、后手封存、市场挂牌、交易暂存或资源预留的物品，应显示为什么不能移动。
6. 程序层数量上限若触发，只按技术限制或异常提示处理，不设计为背包容量玩法。

## 7. 不应表达为

页面不应表达为：

1. 背包格子。
2. 重量、体积或通用负重条。
3. 通过装备栏决定法宝和道具可用性。
4. 商店入口 NPC 的个人背包。
5. 所有库存都可像行囊一样随时随地调用。
6. 藏宝可反复存入、反复取出。
7. 查看藏宝内容会导致藏宝失效。
8. 把 MVP 阶段真灵藏宝设计成他人可发现、损坏、移动或搬空的普通藏宝。

## 8. 空状态与提示

推荐稳定空状态：

| 场景 | 提示口径 |
| --- | --- |
| 无合法个人库存 | 当前没有可访问的个人储物空间 |
| 洞府库存被锁定 | 当前洞府无法存取，原因见状态提示 |
| 藏宝仅可查看 | 查看不会影响藏宝有效性 |
| 藏宝待取出 | 取出为一次性操作，确认后该藏宝关闭 |
| 宗门个人洞府遗产清点 | 该宗门洞府库存将按有主遗产规则清点 |
| 宗门外洞府或藏宝未满足开启条件 | 需要钥匙、功法、线索、位置、事件条件或破阵结果 |
| 真灵藏宝容量不足 | 已达到真灵藏宝数量或单个容量上限 |
| 商店无货 | 商店库存当前没有可见物品 |
| 物品不可移动 | 该物品当前被绑定、预留、封存、挂牌、交易暂存或事件锁定 |
| 权限不足 | 当前角色没有查看或转移该库存的权限 |

## 9. 本次裁决记录

2026-05-11：储物空间页面统一为行囊与库存的资产容器界面。商店入口同时打开行囊和商店库存，但入口 NPC 不是商店库存绑定点。储物入口先打开行囊，若有合法个人储物空间则同时打开并允许切换。个人洞府库存可反复存取。藏宝和真灵藏宝只能在设置时存入，查看内容不影响有效性，正式取出为一次性。MVP 阶段真灵藏宝只对同一真灵可感应角色可见，不展示损坏或移动交互。交易与库存底层改引用库存系统和商店与交易系统。

2026-05-11：同步遗产与后手交互口径。遗产只指有主且需要分配、继承、清点或回收的资产；宗门个人洞府库存在转世前遗留时可按有主遗产规则回收宗门。宗门外个人洞府和普通藏宝是无主遗留设施，必须通过钥匙、功法、线索、位置、事件条件或破阵结果才能进入 / 取出，并可能被其他角色提前打开。真灵藏宝可跨世直接感应和开启，但必须显示设置数量与单个容量限制。
