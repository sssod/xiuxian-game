# 交互设计｜角色页面设计

## 1. 当前状态

本页面仍处于交互约束草案阶段，当前只固定角色页面需要展示的角色身份、属性、派生状态、寿元、主修、修为纯度、持续状态和真灵可见性边界，不维护视觉布局稿、Figma 节点或旧来源清单。

角色页面服务于玩家理解当前世角色“是谁、处在什么状态、哪些信息已经可见”。它不负责修炼行动规划、突破准备、功法研习、储物转移或宗门资源申请；这些操作应由对应专项页面承接。

## 3. 用户目标与入口

玩家进入角色页面时，需要完成以下目标：

1. 查看当前世身份、外观、人设摘要、年龄、寿元和宗门身份。
2. 查看体魄、精力、根骨、悟性、灵根等已知属性和资质。
3. 查看生机、元气、神念当前状态、上限、保留值或受限摘要。
4. 查看当前主修道功、修为阶段、当前大境界纯度、当前道功纯度上限、瓶颈或突破状态摘要。
5. 查看伤势、体内药性、经脉承载、残余药性、符箓持续效果、法宝触发态和事件持续状态。
6. 理解真名可见状态和真灵相关信息是否已经暴露。

入口来自主界面角色摘要、修为页、功法页、事件结果、日志回放和角色创建 / 转世后的确认页。

## 4. 必须表达

1. 当前世身份、姓名、年龄、寿元、宗门身份和必要的人设摘要。
2. 基础属性：体魄、精力。
3. 修炼资质：根骨、悟性、灵根。
4. 派生状态：生机、元气、神念。
5. 当前主修道功、修为阶段、当前大境界纯度具体值、当前道功纯度上限、瓶颈 / 突破状态。
6. 持续状态摘要：伤势、体内药性、经脉承载、残余药性、符箓持续效果、法宝触发态和事件状态。
7. 真名可见状态：`hidden`、`declared` 或 `exposed`。
8. 隐藏、未知、条件显示和 Debug 信息必须有清晰区分。

## 5. 页面区块与信息优先级

推荐信息优先级：

1. 角色身份区：姓名、外观、人设摘要、宗门身份、当前所在地摘要。
2. 寿元与年龄区：当前年龄、寿元上限、剩余寿元和必要年龄影响摘要。
3. 属性与资质区：体魄、精力、根骨、悟性、灵根和已知状态。
4. 派生状态区：生机、元气、神念当前值、上限、保留值和受限原因。
5. 修为与主修区：当前阶段、主修道功、当前大境界纯度具体值、当前道功纯度上限、瓶颈、突破状态和跳转入口。
6. 持续状态区：伤势、体内药性、经脉承载、残余药性、符箓、法宝、事件持续状态和剩余时间。
7. 真灵信息区：真名可见状态、真灵相关摘要和轮回信息入口。

页面只记录信息层级，不固定具体卡片、标签、图标或节点位置。

## 6. 操作流程与状态

常规查看：

```text
打开角色页面
→ 查看身份、属性、派生状态和持续状态
→ 需要专项操作时跳转修为、功法、储物或宗门页面
```

状态展开：

```text
选择持续状态摘要
→ 展开来源、剩余时间、可见效果和风险提示
→ Debug 字段只在调试模式显示
```

属性揭示：

```text
属性或资质尚未公开
→ 显示未知或待检测状态
→ 条件满足后更新为可见结果
```

寿元或上限变化：

```text
寿元上限、年龄或延寿状态变化
→ 页面刷新剩余寿元与年龄影响摘要
→ 不在普通 UI 展开完整寿元公式
```

## 7. 不表达或 Debug 边界

角色页面不应表达为：

1. 真灵强度直接加修炼效率。
2. 执念容量像传统属性点。
3. 单一资质总分直接参与核心判定。
4. 神念、灵根或悟性读取寿元年龄影响。
5. 体内药性或残余药性可以在战斗或突破交锋中即时转化为修为。

普通 UI 不展示完整公式、原始倍率、缓存字段、Debug ID、隐藏真灵线索、未公开资质来源或其他玩家不可见信息。

主界面角色摘要不需要常态显示纯度；角色页面本体需要常态显示当前大境界纯度具体值，以及当前主修道功在本大境界的纯度上限。页面不使用模糊包装词替代数值。
