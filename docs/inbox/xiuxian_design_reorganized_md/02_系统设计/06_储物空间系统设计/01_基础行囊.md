# 系统设计｜基础行囊

## 1. 设计定位

基础行囊负责定义当前角色随身资产的默认容器。它回答“角色当前带在身上的物品、道具、法宝、材料和可调用资产在哪里、如何进入流转、何时可以被使用”的系统问题。

行囊只负责随身资产位置和调用边界。非随身资产容器、权限策略、预留锁定、交易暂存和库存流水由《库存系统》（`03_库存系统.md`）维护；储物空间法宝的未来扩展由《储物空间法宝》（`02_储物空间法宝.md`）维护。

## 2. 当前结论

1. 行囊绑定当前角色实例，随角色行动移动，是当前角色随身资产的默认容器。
2. 行囊和库存是两个概念：行囊随角色移动，库存绑定设施、地点、组织、事件、市场、洞府、藏宝或后手封存点。
3. MVP 不引入背包重量、体积、格子、通用负重或玩法层容量上限；物品栏数量只保留程序层上限，用于性能、存档和异常防护。
4. 物品是否可用不由“装备栏”决定，而由资产位置、权限、标签、事件条件、角色状态和上下文共同决定。
5. 行囊不跨世复制。转世前遗留资产进入洞府、藏宝、真灵藏宝或宗门清点等对应流程，不作为当前角色行囊直接继承。

## 4. 核心循环或触发入口

行囊的核心循环：

1. 资产通过事件奖励、采集、购买、交易结算、库存取出、战利品分配或系统授予进入行囊。
2. 系统记录资产来源、目标容器、数量、实例状态、获得时间、获得原因和可见日志。
3. 玩家在行动、战斗、突破、交易、移动、事件或整理界面中尝试调用行囊资产。
4. 系统校验角色状态、资产状态、上下文、权限、绑定、预留、锁定、位置和可见性。
5. 调用成功后资产被使用、消耗、转移、封存或继续留在行囊；调用失败时保留原位置并返回失败原因。

中断点包括权限不足、角色状态不允许、资产被预留或锁定、上下文不兼容、物品绑定限制、目标库存拒收、藏宝或后手开启条件未满足。

## 5. 规则与状态

### 5.1 行囊定义

基础行囊对应随身资产位置：

```yaml
AssetLocation:
  carried_by_character
```

基础行囊规则：

1. 行囊绑定当前角色实例，随角色行动移动。
2. 行囊中的资产默认视为随身，但随身不等于任何场景都可用。
3. 行囊不使用玩法容量、重量、体积或格子限制。
4. 行囊中高价值、唯一、绑定、后手相关或带独立状态的物品仍应作为独立实例追踪。
5. 行囊中的可堆叠物品仍需按模板、品阶、品质、关键状态、绑定状态和所有者限制拆分堆叠。
6. 行囊变更必须写入资产流水，至少记录来源、目标、物品、数量、时间、原因和可见日志。

### 5.2 行囊与库存的最小区别

| 概念 | 绑定点 | 是否随角色移动 | 典型使用 |
| --- | --- | --- | --- |
| 行囊 | 当前角色实例 | 是 | 随身物品、可调用道具、当前携带资产 |
| 库存 | 设施、地点、组织、事件、市场、洞府、藏宝或后手封存点 | 否 | 商店库存、宗门库存、节点库存、洞府库存、藏宝库存、事件锁定资产 |

当前重整包中的库存类型、容器字段、权限策略、预留锁定、交易暂存和资产位置枚举，以《库存系统》（`03_库存系统.md`）为准。

商店特别规则在本文只保留边界：掌柜、摊主、接引 NPC 或商店入口 NPC 不等于商店库存持有人。商店交易和出售物回收规则见《交易系统》（`../03_经济系统设计/04_交易系统.md`）。

### 5.3 可用性限制

物品是否可用由以下条件共同决定：

1. 资产是否在行囊中，或当前行动是否允许从指定库存调用。
2. 物品是否 `combat_ready`，以及是否满足行动、战斗、突破、交易或事件上下文。
3. 角色当前状态是否允许调用该物品。
4. 权限、绑定、宗门身份、贡献、位置和可见性是否满足。
5. 资源是否被预留、事件锁定、后手封存、市场挂牌或交易暂存。
6. 目标库存是否允许当前角色存入、取出、查看或转移。

随身不等于可用。非随身也不等于永远不可用。部分行动可以在合法条件下从宗门库存、个人洞府库存或事件锁定容器调用资源，但必须经过权限校验和资产流水记录。

### 5.4 行囊流转

行囊与库存之间的转移使用库存系统的 `AssetTransferRequest`。

通用规则：

1. 从库存取出到行囊时，校验库存访问权、当前位置、角色状态和物品状态。
2. 从行囊存入库存时，校验目标库存是否接受该物品类型、当前模式是否允许存入、是否需要权限或消耗。
3. 商店买卖、洞府存取、藏宝设置、后手封存、事件奖励领取都使用同一类流转记录。
4. 藏宝类库存只能在设置藏宝时存入；正式取出后按一次性取出规则处理。
5. 任何高价值物品、后手物、法宝、功法载体、突破资源或绑定物的流转必须写入可复盘日志。
6. 从宗门外洞府或普通藏宝取入行囊前，必须先满足钥匙、功法、线索、位置、事件条件或破阵结果；从真灵藏宝取入行囊前，必须校验同一真灵、数量容量限制和一次性取出状态。

### 5.5 转世、遗产与后手边界

行囊不作为跨世复制容器。

1. 玩家角色转世前留下的宗门个人洞府库存按有主遗产清点回收。
2. 宗门外个人洞府和普通藏宝是无主遗留设施，需要开启条件或破阵结果。
3. 真灵藏宝可由同一真灵跨世感应和开启，但受设置数量和单个容量限制。
4. 当前世角色的随身行囊资产若未进入合法封存、遗产、洞府、藏宝或真灵藏宝流程，不应在转世后静默出现在新角色行囊中。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 本文读取 | 本文写入或要求 |
| --- | --- | --- |
| 角色系统 | 当前角色实例、状态、位置、身份、宗门权限、战斗或事件上下文 | 行囊资产归属、可用性校验结果、调用失败原因 |
| 物品系统 | 物品模板、品阶、品质、绑定、识别、损伤、封印、`combat_ready` 和特殊标签 | 实例追踪、堆叠拆分、消耗或状态变更日志 |
| 库存系统 | 容器类型、访问权限、预留锁定、事件锁定、交易暂存和资产位置 | 行囊与库存之间的 `AssetTransferRequest` 和资产流水 |
| 地图与洞府系统 | 角色当前位置、洞府位置、藏宝点开启条件、破阵结果 | 可取出或不可取出的权限结果 |
| 事件与交易系统 | 奖励、战利品、押注、市场挂牌、买卖结算和交易失败状态 | 入囊、离囊、锁定、释放、回滚或异常日志 |
| NPC 系统 | NPC 随身资产、可见性、死亡或交易上下文 | NPC 随身资产不静默归入商店库存的边界 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `character_id` | 行囊绑定的当前角色实例，不等同于真灵或玩家账号 |
| `asset_location` | 随身资产位置；基础行囊使用 `carried_by_character` |
| `item_instance_refs` | 行囊内独立实例物品和堆叠物品引用 |
| `stack_key` | 可堆叠物品的拆分键，至少覆盖模板、品阶、品质、关键状态、绑定和所有者限制 |
| `combat_ready` | 物品是否已进入可战斗调用状态，不代表所有上下文都可用 |
| `usable_context_tags` | 可使用场景标签，例如行动、战斗、突破、交易、事件或移动 |
| `reservation_refs` | 与该资产相关的预留、事件锁定、市场挂牌、交易暂存或后手封存引用 |
| `source_container_ref` | 资产进入行囊前的来源容器或系统来源 |
| `target_container_ref` | 资产离开行囊时的目标容器 |
| `transfer_log_refs` | 入囊、离囊、消耗、封存、回滚和异常处理流水 |
| `visibility_state` | 普通 UI、传闻、宗门日志、隐藏世界日志或 Debug 的可见状态 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示：

1. 当前角色可查看的行囊资产、数量、品阶、品质、关键状态和可用性摘要。
2. 物品不可用、被预留、事件锁定、市场挂牌、交易暂存或后手封存时的原因提示。
3. 高价值、唯一、绑定、后手相关或带独立状态物品的详情入口。
4. 行囊与库存之间转移前的目标容器、权限、消耗和失败风险。
5. 转移、消耗、封存或领取后的可见日志摘要。

普通 UI 不展示：

1. 完整 `container_id`、内部实例 ID、原始 Debug 权限策略或隐藏世界日志。
2. 玩家当前无法知晓的 NPC 完整随身资产、隐藏藏宝、未揭示后手或事件锁定奖励。
3. 程序层数量上限、性能保护阈值或异常防护字段，除非触发异常提示。

## 9. MVP 范围

MVP 应实现：

1. 行囊作为角色随身资产容器。
2. 行囊与库存的概念区分。
3. 行囊与库存之间的转移、预留、消耗和日志规则。
4. 高价值物品的实例追踪。
5. 可堆叠物品与独立实例物品的区别。

MVP 不实现：

1. 背包格子、重量、体积、通用负重和容量成长玩法。
2. 通过装备栏决定法宝或道具可用性。
3. 储物空间法宝的独立取放、扩容、偷取、掉落和内部空间结算玩法。
4. 把入口 NPC 当成商店库存绑定点。

## 10. 验收约束

1. 行囊必须绑定当前角色实例，不能与设施、店铺、宗门、节点、洞府、藏宝或交易暂存库存混写。
2. 任何行囊变更都必须留下可复盘资产流水，尤其是高价值物品、后手物、法宝、功法载体、突破资源和绑定物。
3. MVP 不得把程序层数量上限表达为玩法层背包容量、重量、格子或负重限制。
4. 物品可用性必须同时校验资产位置、上下文、角色状态、物品状态、权限、绑定、预留和锁定状态。
5. 商店、宗门、节点和事件库存不得绑定到入口 NPC 个人行囊上。
6. 转世后新角色行囊不得静默继承前世随身资产；跨世资产只能通过洞府、藏宝、真灵藏宝、遗产清点或其他明确流程出现。
