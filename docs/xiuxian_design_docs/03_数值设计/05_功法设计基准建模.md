# 数值设计｜功法设计基准建模

## 1. 设计定位

本文负责功法数值的基准建模，定义道功、法门、掌握度、功法适配、学习收益、修炼公式接口和结果日志。它回答功法模板需要哪些数值字段、掌握度如何影响上限与效果、主修道功如何接入每小时修炼公式，以及法门如何接入行动、战斗、事件和生产效率。

本文只维护数值层单位、字段、公式结构、配置表、输出和调参边界；道功 / 法门的系统定义、载体物品规则、主修功法流程、页面展示和具体投放内容由关联文档维护。本文不定义所有功法内容表、不定义最终数据库 schema，也不替代战斗、行动、事件、物品和投放文档。

## 2. 当前结论

1. 功法是上位泛称，规则层拆为 `DaoMethod` 道功与 `TechniqueMethod` 法门；只有道功能设为主修并推动修为进度，法门不能设为主修，也不直接推动修为。
2. 完整功法载体是常规学习来源；残页和篇章只参与合成、线索、权限或投放，不创建 `MethodState`。角色学会功法后，运行时掌握状态由 `MethodState` 保存，与背包中的载体分离。
3. 主修道功通过环境灵气吸收上限、`cp_conversion_rate`、`mana_amplifier`、纯度区间、`M_method`、`K_mastery`、相性、压力和突破模板接入修炼与突破；法门通过行动标签、战斗指令、事件选项、生产配方、效率修正、消耗修正和风险修正接入其他系统。
4. 道功掌握度影响当前可修上限、单位时间收益、资源输入兼容、风险提示和可追回知识型收益；它不提高理论最高上限，不改变大境界突破模板类型，也不事后改写纯度、最终法力、小境界奖励质量或阶段性不可追回收益。
5. 主动吐纳、闭关修炼和自动运转只读取当前主修道功掌握度，不增加主修道功掌握经验或掌握等级。
6. 法门掌握度影响解锁强度、稳定性、消耗、成功率、效果质量和风险，但不直接改变修为进度。
7. 功法阶级、品级、路线标签和灵根 / 资源 / 地点相性必须进入适配矩阵，不提供无来源全局倍率；MVP 不做废功重修、正式改修折算、功法推演、功法创造、功法融合、残页直接学习或功法上限后的免费续接换主修。

## 4. 基准、单位与输入参数

功法数值链路分为内容资产、模板、角色状态和结算接口四层：

```text
MethodCarrierTemplate / MethodCarrierInstance
→ DaoMethodTemplate / TechniqueMethodTemplate
→ MethodState
→ MainMethodState / Action / Event / Combat / Production
→ CultivationTickResult / MethodPracticeTickResult / ResultPackage
```

| 层级 | 作用 |
| --- | --- |
| 功法载体 | 物品层资产，控制残页、篇章、完整功法、交易、合成、封存和学习来源 |
| 功法模板 | 规则层内容，定义道功或法门的阶级、品级、标签、效果曲线和适配规则 |
| 掌握状态 | 角色本世对该功法的学习进度、掌握等级、经验、上限和解锁 |
| 结算接口 | 将道功接入修炼与突破，将法门接入行动、战斗、事件、生产和资源获取 |

功法模板不能保存角色进度；功法载体不能替代 `MethodState`；`MethodState` 不能保存残页或篇章收集进度。

数值输入按以下口径拆分：

| 输入 | 单位或类型 | 用途 |
| --- | --- | --- |
| `method_type` | `dao_method` / `technique_method` | 决定是否可主修、是否接入修为公式 |
| `tier_code / tier_order` | 大境界或内容层级 | 控制学习门槛、适配、压力、投放价值和跨阶惩罚 |
| `quality_code / quality_order` | 功法完整度、传承质量、保存质量或稳定性 | 控制研习难度、效果曲线上限、波动和副作用 |
| `method_tags` | 内容标签列表 | 连接路线、战斗、事件、生产和投放语义 |
| `route_affinity_tags` | 路线标签列表 | 参与 `M_method`、突破路线和相性矩阵 |
| `root_affinity_tags` | 灵根或资质标签列表 | 参与功法与角色适配 |
| `resource_affinity_tags` | 资源标签列表 | 判断丹药、灵材、符箓、残余效果等输入适配 |
| `node_affinity_tags` | 地点标签列表 | 判断节点灵气、设施、区域机会和环境压力 |
| `mastery_level` | 等级 | 用于解锁、当前上限、效率和风险修正 |
| `mastery_norm` | 0 到 1 标准化掌握度 | 用于公式缩放、突破门槛和跨系统效果 |
| `compatible_hours` | 小时 | 修炼、自动运转或研习实际有效时间 |

研习功法读取实际投入小时、悟性、功法阶级、功法品级、导师 / 讲经 / 藏经阁 / 静室 / 演武场 / 工坊等支持、当前神念 / 伤势 / 心魔 / 经脉压力、前置知识 / 基础法门 / 装备 / 资源条件，以及悟性丹、定心丹等研习资源输入。

## 5. 公式或模型

### 5.1 道功当前上限

道功有两个上限概念：

```text
effective_current_cap_stage = min(
  theoretical_max_cap_stage,
  mastery_current_cap_stage
)
```

若当前主修道功不支持下一小阶段，该道功不能把角色推进到下一小境界 0%。大境界突破读取当前大境界锁定的主修道功记录和突破路线标签。

### 5.2 道功接入修炼公式

每小时修炼公式中的道功字段分工如下：

```text
aura_absorption_cap_per_hour = 环境灵气吸收上限
cp_conversion_rate = 已承接灵气转化为 CP 的速度
mana_amplifier = 单位 CP 对应法力强度
purity_floor / purity_ceiling = 当前大境界默认纯度和可巩固上限
M_method = 主修道功对当前境界段、地点、资源和路线的适配度
K_mastery = 角色对该道功的掌握度修正
```

行动效率仍可使用适配与掌握度修正：

```text
action_efficiency_factor =
  clamp(
    A_action
    * Q_aptitude
    * M_method
    * K_mastery
    * F_facility
    * S_sect_support
    * P_state_penalty
    * C_competition_or_window,
    min_efficiency_ratio_s,
    max_efficiency_ratio_s
  )
```

环境灵气流读取道功吸收上限：

```text
environment_aura_input =
  min(
    node_aura_available,
    aura_absorption_cap_per_hour * compatible_hours
  )
```

体内药性流不受道功环境灵气吸收上限限制，但主要受药性容量、体魄承载、经脉负载、服用规则和释放时长限制：

```text
medicine_aura_intake =
  Σ(unit_aura_rate_i * consumed_medicine_effect_hours_i * resource_quality_factor_i)

raw_aura_input =
  environment_aura_input
  + medicine_aura_intake

cp_gain =
  raw_aura_input
  * cp_conversion_rate
  * action_efficiency_factor
```

法力派生：

```text
major_realm_mana =
  major_realm_cp
  * current_purity
  * mana_amplifier
```

巩固修为使用同一外部输入和转化率，但写入当前大境界巩固 CP 条：

```text
consolidation_gain =
  raw_aura_input
  * cp_conversion_rate
  * consolidation_action_efficiency
```

防重复计入口径：

1. 道功吸收上限只作用于环境灵气流，不重复限制已服用体内药性的定额灵气释放。
2. 道功转化率作用于合流后的 `raw_aura_input`。
3. 若某模板已把功法适配计入 `M_method`，不得再以另一个同来源最终倍率重复计入 `K_mastery`、`R_resource` 或 `N_node_aura`。
4. `debug_formula_trace` 必须能复盘功法适配、掌握度修正、吸收上限、CP 转化率、法力放大系数、纯度区间和压力来源。

### 5.3 道功掌握度效果

默认示例以 5 级掌握度作为低阶种子，不代表所有功法必须 5 级：

| 等级 | 上限方向 | 效率方向 | 解锁方向 |
| --- | --- | --- | --- |
| level 1 | 入门，可支持低阶起点 | 基础效率 | 基础运转、可设主修 |
| level 2 | 当前可修上限推进 | 轻微提升 | 初步提示或被动 |
| level 3 | 上限不一定提升 | 单位时间收益提升 | 稳定性、资源提示 |
| level 4 | 当前可修上限推进到理论上限附近 | 明显提升 | 突破承载条件可能达标 |
| level 5 | 通常不突破理论上限 | 进一步提升或降低风险 | 高掌握提示、稳定性或可追回知识 |

掌握度能影响：

1. `mastery_current_cap_stage`。
2. 主动吐纳单位时间收益。
3. 自动运转单位时间收益。
4. 资源输入兼容性、体魄承载稳定性或风险提示。
5. 突破开启条件中的掌握度达标。
6. 可追回的知识型、提示型、路线型或法门型收益。

掌握度不能影响：

1. `theoretical_max_cap_stage`。
2. 大境界突破模板类型。
3. 大境界突破模板核心风险结构。
4. CP 到法力的纯度系数。
5. 道功法力放大系数。
6. 已获得 CP 的法力密度。
7. 小境界升级奖励质量的既往结果。
8. 阶段性不可追回收益。

### 5.4 研习功法收益

研习功法属于可投入时间的个人持续行动，可以用于未入门功法入门，也可以用于提高已学道功或法门掌握度。研习功法使用独立学习基准，不复用修为 `RealmSegmentBalance`：

```text
method_mastery_exp_gain =
  L_method
  * compatible_learning_hours
  * Q_comprehension
  * D_method_difficulty
  * F_learning_support
  * R_method_insight_resource
  * P_mental_state
  * C_prerequisite_fit
```

| 项 | 含义 |
| --- | --- |
| `L_method` | 当前功法掌握曲线的基准学习率 |
| `compatible_learning_hours` | 研习功法实际执行小时 |
| `Q_comprehension` | 悟性和理解能力修正 |
| `D_method_difficulty` | 功法阶级、品级、复杂度和是否跨阶学习 |
| `F_learning_support` | 导师、设施、讲经、藏经阁或事件支持 |
| `R_method_insight_resource` | 悟性丹、定心丹、辅助材料等研习资源输入 |
| `P_mental_state` | 神念、伤势、心魔、疲劳和压力惩罚 |
| `C_prerequisite_fit` | 前置功法、法门、装备、灵根或路线理解适配 |

研习功法可以产出：

1. `MethodState.mastery_exp` 增加。
2. `MethodState.mastery_level` 提升。
3. 未入门完整功法进入 learned level 1。
4. 道功当前可修上限提高。
5. 道功单位时间收益或自动运转收益提高。
6. 法门指令、行动标签、事件选项、配方或效率修正解锁。
7. 可追回的知识型、提示型、路线型或法门型收益。

研习功法不能产出：

1. 直接修为进度。
2. 残页、篇章或缺失内容自动补齐。
3. 功法理论最高上限提高。
4. 大境界突破模板类型变化。
5. 小境界升级奖励质量变化。
6. 纯度、法力或既往修炼结果变化。

主动吐纳、闭关修炼和自动运转只读取当前主修道功掌握度作为 `K_mastery`、当前可修上限、资源兼容和风险提示输入，不产出 `method_mastery_delta`，也不替代研习功法行动。

### 5.5 法门效果缩放

法门不直接推动修为，不决定当前可修上限，也不能成为主修。它的数值价值来自“能做什么”和“做得多稳、多省、多快”。

法门效果边界：

1. `unlock` 可以打开战斗指令、行动标签、事件选项或配方。
2. `rate_modifier` 可以提高移动、采集、生产、探索或研习效率，但不得直接写成修为进度。
3. `cost_modifier` 可以降低元气、神念、资源或时间消耗。
4. `risk_modifier` 可以降低暴露、受伤、失败、损坏或事件恶化风险。
5. `quality_modifier` 可以提高采集品质、炼制品质、事件结果质量或战斗策略表现。
6. `information_reveal` 可以提高识别、预警、线索可见度或结果预览精度。

建议法门效果缩放使用：

```text
technique_effect_value =
  base_effect
  * mastery_scaling
  * affinity_fit
  * realm_fit
  * equipment_fit
  * state_factor
```

法门效果同样需要贡献上限和领域边界。例如采集法门可以提高隐藏灵植发现率或采集品质，但不能无来源生成超出节点资源池和世界预算的高阶资产。

若一个设计同时包含修为路线和能力展开，应拆分：

```text
推动修为、上限和突破路线的部分 → DaoMethod
战斗、探索、采集、生产、移动、事件选项和效率部分 → TechniqueMethod
```

### 5.6 阶级、品级与适配

功法阶级默认与大境界层级对齐：

| `tier_order` | `tier_code` | 表现层级 | 默认用途 |
| ---: | --- | --- | --- |
| 0 | `mundane` | 凡俗 / 入门 | 教学、凡俗技艺、低阶 NPC |
| 1 | `qi_refining` | 炼气 | 入门道功、基础法门 |
| 2 | `foundation` | 筑基 | 正式宗门道功、第一次大境界法门 |
| 3 | `golden_core` | 金丹 | 宗门骨干、高价值法门、区域路线 |
| 4 | `nascent_soul` | 元婴 | 宗门核心、高阶路线和区域强者能力 |
| 5 | `spirit_transformation` | 化神 | 第一阶段大后期道统和世界层机会 |
| 6+ | 扩展 | 炼虚及以后 | 后期阶段预留 |

功法品级影响研习难度和经验需求、初始稳定性、保存质量或传承完整度、效果曲线的上限 / 波动 / 副作用、交易 / 贡献 / 宗门权限 / 投放价值，以及功法载体是否需要实例化、封存、借阅或特殊日志。

功法阶级对当前境界段的默认处理：

| 功法阶级 vs 当前境界段 | 默认处理 |
| --- | --- |
| 低两阶或更多 | 安全但贡献极低，主要用于补充、教学或低阶 NPC |
| 低一阶 | 贡献降低，适合过渡或低风险稳定路线 |
| 同阶 | 主要设计目标，完整读取模板 |
| 高一阶 | 潜在收益更强，但学习难度、压力、浪费和失败风险上升 |
| 高两阶或更多 | 默认阻止常规稳定使用，除非事件、后手、强敌真实资产或专用模板允许 |

高阶功法不应简单碾压。它可以带来更高上限、更强效果或更好突破路线，但要通过学习门槛、相性要求、经脉压力、心魔风险、宗门权限、载体稀缺和阶段预算限制。

### 5.7 突破承接

道功影响大境界突破，但方式必须稳定：

```text
突破模板来自道功模板本身的路线特质；
突破模板负责定义难度 profile、成功收益 profile、阶段序列和失败标签池；
掌握度只影响模板声明的事件内修正、执行表现或风险可见性；
掌握度不能把一门道功的突破模板改造成另一门道功；
掌握度不能成为默认突破入口门槛。
```

突破入口的角色数值门槛只读取当前大境界 CP。法力、生机、元气、神念、体魄、精力、根骨和悟性只在突破事件内部验证；伤势、经脉过载等状态通过持续状态修正这些明确数值后间接参与。

大境界突破最终永久收益由境界基础收益与道功突破模板收益共同决定，不再另设突破品质公式。阶段损伤只进入当前状态、恢复成本和失败标签，不降低成功后的永久模板收益。

金丹到元婴及之后的道功突破模板可启用雷劫阶段。雷劫阶段仍只能读取法力、生机、元气、神念、体魄、精力、根骨、悟性这 8 类明确数值，不引入外扰或护法抵挡逻辑。

## 6. 配置表或根表

### 6.1 通用功法数值字段

```yaml
MethodNumericProfile:
  method_id: string
  method_type: dao_method | technique_method
  display_name: string
  lineage_id: string | null
  tier_code: string
  tier_order: number
  quality_code: string
  quality_order: number
  method_tags: list
  route_affinity_tags: list
  root_affinity_tags: list
  resource_affinity_tags: list
  node_affinity_tags: list
  required_realm_tags: list
  prerequisite_method_ids: list
  learning_difficulty_profile_id: string
  mastery_curve_id: string
  effect_scaling_profile_id: string
  compatibility_profile_id: string
  pressure_profile_id: string | null
  source_rules_ref: string
  mvp_enabled: bool
```

字段口径：

1. `tier_code / tier_order` 表示适配的大境界或内容层级，不是单纯价格等级。
2. `quality_code / quality_order` 表示功法完整度、传承质量、保存质量、稳定性或理解难度，不直接赠送掌握度。
3. `method_tags` 是内容标签；`route_affinity_tags`、`root_affinity_tags`、`resource_affinity_tags`、`node_affinity_tags` 用于适配矩阵。
4. `learning_difficulty_profile_id` 控制研习门槛和经验曲线。
5. `effect_scaling_profile_id` 控制掌握等级、标准化掌握度与效果强度之间的关系。
6. 功法相性与资源、设施、节点和宗门支持一样，需要进入适配矩阵，不应写成固定全局倍率。

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `stage_support_range` | 该道功覆盖的抽象阶段或包装境界段 | 用于推进限制 |
| `theoretical_max_cap_stage` | 道功理论最高上限 | 掌握度不能提高该值 |
| `mastery_cap_profile_id` | 掌握等级到当前可修上限的映射 | 影响 `effective_current_cap_stage` |
| `method_fit_profile_id` | 道功对当前 `RealmSegment` 的适配 | 进入 `M_method` |
| `aura_absorption_cap_per_hour` | 环境灵气流吸收上限 | 不限制体内药性定额灵气释放 |
| `cp_conversion_rate` | 已承接灵气转化为 CP 的速度 | 转化率高低代表修炼速度，不直接代表道功强弱 |
| `mana_amplifier` | 单位 CP 对应法力强度 | 低转化率凝实道功可拥有更高放大系数 |
| `purity_floor / purity_ceiling` | 当前大境界默认纯度和最高纯度 | 纯度范围必须在 `(0, 1]` 内 |
| `consolidation_cost_factor` | 巩固 CP 条需求系数 | MVP 可先默认为 1 |
| `consolidation_action_efficiency` | 巩固修为行动效率 | 用于计算 `consolidation_gain` |
| `cultivation_speed_tag / mana_density_tag` | UI 和调参标签 | 速成、均衡、凝实等体验摘要 |
| `auto_circulation_profile_id` | 自动运转的低额收益、触发条件和停止条件 | 由系统设计决定入口 |
| `resource_compatibility_profile_id` | 丹药、灵材、符箓、残余效果等资源输入的相性 | 接入资源输入 |
| `breakthrough_template_ref` / `breakthrough_route_tags` | 大境界突破模板入口、路线标签、难度 profile、成功收益 profile 和失败标签池入口 | 接入突破系统 |
| `pressure_profile_id` | 不适配、跨阶、强行冲修或高倍率修炼带来的压力口径 | 接入状态压力 |

## 7. 结算输出

研习功法、法门使用、功法解锁，以及修炼公式对主修道功掌握度的读取，都需要可复盘结果。

研习功法建议输出：

```yaml
MethodPracticeTickResult:
  world_day: number
  world_hour: number
  command_id: string
  character_id: string
  method_id: string
  method_type: dao_method | technique_method
  compatible_learning_hours: number
  mastery_exp_gain: number
  mastery_level_before: number
  mastery_level_after: number
  mastery_norm_before: number
  mastery_norm_after: number
  cap_stage_before: string | null
  cap_stage_after: string | null
  unlocked_effect_refs: list
  resource_effects_consumed: list
  active_resource_effect_delta: list
  state_pressure_delta: object
  visible_summary: string
  debug_formula_trace: object
```

主动吐纳、闭关修炼和自动运转不得写入 `MethodPracticeTickResult`、`MethodMasteryDelta` 或 `CultivationTickResult.method_mastery_delta`。修炼结果只可记录本次读取的主修道功、掌握度、适配度、吸收上限、CP 转化率、法力放大系数、纯度区间和公式追踪，用于复盘收益与风险来源。

法门在战斗、事件、移动、采集、生产中的效果应写入对应系统结果包，至少记录：

1. 触发的法门。
2. 读取的掌握度。
3. 生效的解锁、倍率、消耗、风险或品质修正。
4. 相性、装备、资源和状态修正。
5. 是否产生失败、反噬、暴露、损坏或额外资源消耗。

普通可见摘要应说明掌握提升、解锁、上限变化、消耗和风险变化；Debug / QA 输出可包含公式追踪、倍率来源和适配矩阵细节。

## 8. 调参验收口径

功法数值验收至少检查：

1. 任一功法模板都能明确归类为道功或法门。
2. 只有道功能成为主修；法门不能被设为主修。
3. 完整功法载体学习后才创建 `MethodState`；残页和篇章不会创建运行时学习进度。
4. 道功理论最高上限和掌握度当前上限分离。
5. `effective_current_cap_stage` 能阻止不支持的自动小境界推进。
6. 主修道功能进入修炼公式，并能在结果明细中复盘 `M_method`、`K_mastery`、吸收上限、CP 转化率、法力放大系数、纯度区间和压力。
7. 体内药性流跳过道功环境灵气吸收上限，但仍受药性容量、体魄承载、经脉负载、服用规则、标签匹配、压力和贡献上限约束。
8. 研习功法不直接增加修为。
9. 悟性丹在非研习行动中不产生功法经验收益。
10. 主动吐纳、闭关修炼和自动运转不产生主修道功掌握经验、掌握等级或掌握度变化。
11. 法门效果不会直接写成修为进度。
12. 法门解锁、效率、消耗、风险和品质修正都有作用域和贡献上限。
13. 掌握度升级不会改写既往纯度、法力或不可追回收益。
14. 大境界突破模板、难度 profile 和成功收益 profile 来自道功路线，不由掌握等级临时生成，也不再叠加独立突破品质公式。
15. 高阶功法受阶级适配、学习门槛、压力风险、权限和投放约束。
16. 功法收益、解锁、资源消耗、残余效果和状态变化都能写入结果包、角色日志和回放。

## 9. MVP 范围

MVP 应实现：

1. `DaoMethodNumericProfile` 和 `TechniqueMethodNumericProfile` 的最小模板字段。
2. 完整功法载体学习后创建 `MethodState`。
3. 道功 / 法门共用的 `MethodMasteryCurve`。
4. 道功 `theoretical_max_cap_stage`、`mastery_current_cap_stage` 和 `effective_current_cap_stage`。
5. 主修道功接入 `M_method`、`K_mastery`、环境灵气吸收上限、CP 转化率、法力放大系数、纯度区间、巩固修为配置和突破模板。
6. 道功自然上限优先落在下一大境界第一小阶段，方便新大境界改修。
7. 研习功法行动，支持悟性丹、定心丹等研习资源输入。
8. 主动吐纳、闭关修炼和自动运转读取主修道功掌握度，但不增加掌握度。
9. 法门解锁行动标签、战斗指令、事件选项、生产配方或效率 / 风险修正。
10. 功法适配矩阵和基本相性提示。
11. `MethodPracticeTickResult` 或等价日志。
12. 功法页面和修为页面能显示道功 / 法门分类、主修道功、掌握度、当前可修上限和理论最高上限。

MVP 不实现：

1. 残页或篇章直接学习。
2. 缺页 / 缺篇导致运行时修为卡点。
3. 功法修复、校订、推演、创造或融合。
4. 废功重修、改修折算和主修经验转移。
5. 功法上限后的免费续接换主修。
6. 掌握度改变大境界突破模板类型。
7. 掌握度事后补发纯度、法力、小境界奖励质量或阶段性不可追回收益。
8. 多法门复杂连携、技能树式深层组合和全部生产技艺曲线。
9. 高阶功法跨阶稳定碾压低阶内容。
