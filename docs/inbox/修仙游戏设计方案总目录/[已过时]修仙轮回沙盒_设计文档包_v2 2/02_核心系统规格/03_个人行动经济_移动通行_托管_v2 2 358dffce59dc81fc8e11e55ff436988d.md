# 03_个人行动经济_移动通行_托管_v2.2

# 个人行动经济、移动通行与稳健托管（v2.2）

## 0. 文档定位

本文整理角色每回合如何规划行动、移动、持续操作、事件中断与离线托管。

S3 是角色层时间、位置和行动时间线底座。突破、事件、战斗、后手、宗门亲自介入都应从 S3 获取触发位置、世界小时、剩余时间预算和上下文。

---

## 1. 核心口径

S3 新版采用：

> **大地图驱动的回合个人行动规划。**
> 

玩家不是先从抽象行动列表选择，而是在大世界地图上面对当前位置、已探索节点、可达范围、路线耗时、节点风险和目标关联，通过少量线性行动指令形成本回合计划。

当前默认：

```
1 回合 = 5 个游戏天
UI 显示单位 = 天
服务端内部 tick = 小时
```

但 5 天只是配置值，不进入世界观命名。

## 2. 回合时间预算

### 2.1 天级预算条

底部 UI 显示：

```
第 1 天｜第 2 天｜第 3 天｜第 4 天｜第 5 天
```

如果配置为 7 天，则显示：

```
第 1 天｜第 2 天｜第 3 天｜第 4 天｜第 5 天｜第 6 天｜第 7 天
```

不显示小时级网格。

### 2.2 小时级内部结算

服务器内部使用：

```
turn_total_hours = turn_duration_days * 24
```

小时用于：

1. 统计多个短耗时行动的总占用。
2. 处理移动延误、战斗耗时、等待、提前抵达。
3. 修正下一条指令的实际触发时间。
4. 支撑“原计划 vs 实际结果”报告。

## 3. 三类角色行动

```
个人即时行动
移动行动
个人持续行动
```

个人持续行动再拆为：

```
固定执行时间
可选投入执行时间
```

## 4. 个人即时行动

个人即时行动发生在回合决策阶段、时间暂停时。

特点：

- 不推进游戏内时间。
- 不占用回合时间预算。
- 点击后由服务器立即校验并生效。
- 进入个人行动指令规划后冻结。

适合：

- 查看报告。
- 查看回信。
- 领取当前可领取的俸禄 / 配给 / 委托成品。
- 整理随身物品显示。
- 调整目标模板。
- 查看功法详情。
- 查看角色日志、轮回账本。
- 当前节点允许的极短事务。

不适合：

- 移动。
- 探索。
- 采集 / 开采。
- 修炼 / 吐纳。
- 研习功法。
- 炼丹 / 炼器。
- 大境界突破。
- 后手布置 / 回收。
- 宗门运营指令。

资源转移类即时行动必须受位置、权限、库存、资产容器、交易对象和日志约束。

## 5. 移动行动

移动行动是时间消耗型指令。

玩家输入粒度：

```
目标节点 + 移动方式 + 可选显式停靠点
```

MVP 不做完整逐边手动排路，也不做复杂复合交通路线编辑。

服务端读取：

- 节点连接。
- 有向边权。
- 交通设施。
- 隐藏路线。
- 权限门。
- 状态门。
- 风险门。
- 路线封锁。
- 角色移动能力。
- 事件延误。

移动耗时可为：

```
数小时 / 半天 / 1 天 / 多天 / 跨回合
```

移动中可触发：

- 遭遇战。
- 路线阻断。
- 延误。
- 信息发现。
- 行踪暴露。
- 消耗补给。
- 临时停靠。
- 安全抵达。

### 5.1 移动上下文

```
MovementContext {
  character_id: String,
  turn_id: int,
  world_day: int,
  world_hour: int,
  from_node: String,
  to_node: String,
  route_segment: String,
  travel_mode: String,
  stopover_nodes: Array,
  planned_travel_hours: int,
  exposure_tags: Array,
  risk_tags: Array
}
```

### 5.2 移动跨回合

如果移动跨越回合，角色进入：

```
行程中 / 路途中 / 临时停靠
```

下一回合默认提供：

```
继续原路线
```

玩家可选择修改计划，但必须受当前位置、路线状态和事件后果约束。

## 6. 固定执行时间持续行动

固定执行时间行动是：

> 必须投入完整持续时间，才产生完整结算结果的持续行动。
> 

典型例子：

- 炼丹。
- 炼器。
- 大境界突破。
- 重要仪式。
- 特定治疗。
- 高价值后手布置。
- 固定工期制造。

规则：

```
行动模板规定固定耗时。
玩家选择开始后，系统显示预计完成日。
未完成前不产出完整结果。
可根据模板允许跨回合延续。
被事件打断时，按该行动的中断规则处理。
```

示例：

```
炼制清心丹：固定 3 天。
第 1 天开始。
第 3 天末完成。
中途被打断：可能暂停、损耗材料或炼制失败。
```

大境界突破特殊处理：

```
固定时间投入
+ 关键突破物开始时消耗
+ 专用事件链
+ 不可回头补准备
+ 中断后果由突破事件链决定
```

## 7. 可选投入执行时间持续行动

可选投入执行时间行动是：

> 玩家可以决定投入多少时间，投入越多，收益、进度、熟练度或发现概率越高。
> 

典型例子：

- 采药。
- 挖矿。
- 探索。
- 修炼 / 吐纳。
- 研习功法。
- 驻守。
- 休整。
- 调查。
- 参悟。

规则：

```
若行动模板最大可投入时间超过 1 天，玩家选择正整数投入天数。
系统按实际投入时间结算收益。
被事件延误后，按实际剩余投入结算。
不需要完整完成才能有结果。
```

UI 输入规则：

- 只有 `duration_mode = variable_investment` 且模板最大可投入时间超过 1 天的个人持续行动，才提供动态投入时间控件。
- 控件显示为 `< 1 > 天` 左右按钮式输入，中间数字可直接键入。
- 输入范围为 `[1, X]`，`X = min(模板最大可投入天数, 本回合剩余可用天数)`。
- 只接受正整数天数，不接受半天、小时数、小数天或“投入剩余时间”作为玩家输入。
- 短于或等于 1 天的持续行动均按行动模板固定耗时处理。

示例：

```
计划探索黑石岭 3 天。
途中斗法延误 8 小时。
实际探索约 2 天 16 小时。
按实际投入结算探索进度、发现概率、风险暴露和资源结果。
```

## 8. 不额外限制短耗时行动次数

本版不设计：

- 每天短行动槽。
- 每节点短事务上限。
- 每回合轻事务次数。
- 碎片行动额度。

统一原则：

```
所有行动只按实际耗时占用回合时间预算。
```

如果多个短行动合计占满一天，UI 就表现为这一天被这些事务占用。玩家可以自由安排。

复杂度控制不靠机械次数限制，而靠内容设计：

```
单个节点不要堆大量可执行短行动。
多个细碎操作应合并成更高层的行动入口。
```

推荐合并入口：

- 坊市采购。
- 出售 / 置换物资。
- 打听消息。
- 拜访指定 NPC。
- 处理当前节点事务。

## 9. 行动指令队列

玩家输入的是线性行动指令。

示例：

```
行动 1：前往镇集。
行动 2：坊市采购避瘴符，预算 30 灵石。
行动 3：前往黑石岭。
行动 4：探索黑石岭，投入 3 天。
```

系统自动映射到时间预算条。

### 9.1 指令结构

```
PersonalActionInstruction {
  instruction_id: String,
  actor_ref: String,
  action_type: String,
  action_template_id: String,
  target_node_id: String,
  target_ref: String,

  duration_mode: String,
  planned_duration_days: int,
  planned_duration_hours: int,

  fixed_required_hours: int,
  min_effective_hours: int,

  route_params: Dictionary,
  resource_budget: Dictionary,
  resource_inputs: Array,
  start_condition: Dictionary,
  stop_condition: Dictionary,

  failure_policy: String,
  interrupt_policy: String,
  overflow_policy: String,
  auto_continue: bool,

  created_turn_id: int,
  submitted_by_player_id: String
}
```

`resource_inputs` 绑定本行动的额外资源输入项，不是新的行动类型。结构建议使用：

```
ActionResourceInputBinding {
  binding_id: String,
  instruction_id: String,
  resource_ref: String,
  source_container_ref: AssetContainerRef,
  resource_effect_template_id: String,
  effect_channel: String,
  timing_mode: String,
  max_effective_hours: int,
  residual_policy: String,
  stack_group: String
}
```

典型映射：

- 主动吐纳可绑定修为丹药、灵材等 `cultivation_aura` 输入。
- 研习功法可绑定悟性 / 定心类输入。
- 毒瘴移动、探索、采集或战斗语境可绑定避瘴 / 解毒输入。
- 休整、治疗或医疗事件可绑定疗伤输入。

资源输入必须通过资产容器、权限、位置、行动标签和同类叠加限制校验。

### 9.2 策略字段

`failure_policy`：行动前置条件失败时如何处理。

`interrupt_policy`：行动过程中被事件打断时如何处理。

`overflow_policy`：行动无法在本回合内完成时如何处理。

`auto_continue`：下一回合是否默认延续。

推荐默认：

| 行动类型 | failure_policy | interrupt_policy | overflow_policy |
| --- | --- | --- | --- |
| 移动 | fallback_to_stay_or_rest | delay / route_event | carry_to_next_turn |
| 炼丹 / 炼器 | wait_for_player_next_turn | pause / partial_salvage | carry_to_next_turn |
| 大境界突破 | block_if_invalid | convert_to_event_chain | event_chain_defined |
| 探索 / 采集 | skip_and_continue | partial_settle | settle_partial_at_turn_end |
| 修炼 / 研习 | skip_and_continue | partial_settle | carry_to_next_turn / settle_partial |
| 休整 / 警戒 / 停留 | fallback_to_stay | partial_settle | settle_partial_at_turn_end |

## 10. 行动资源输入与残余效果

行动资源输入项是具体行动内部的可选折叠配置，不进入全局行动列表，也不成为默认行动入口。

规则：

- 资源输入不改变行动本身的 `action_type` 或 `duration_mode`。
- 带资源输入的行动未实际开始时，不消耗资源。
- 行动开始前，服务端再次校验资源是否存在于可调用资产容器、是否允许用于当前行动、是否满足位置 / 状态 / 标签条件、是否违反同类资源叠加限制。
- 行动开始后才消耗资源并写入资源使用日志。
- 行动执行中按小时统计兼容语境，资源效果只在兼容小时内进入对应结算管线。
- 行动被延误、中断、提前结束或部分小时不兼容时，未用完效果按模板生成 `ActiveResourceEffect`。
- 决策阶段不推进残余药性衰减；只在世界小时实际推进时处理。

MVP 同一行动中同一效果通道最多使用 1 个主资源输入，避免早期处理多丹叠加、多持续时间、多残余药性和多压力曲线。

已有同组 `ActiveResourceEffect` 时，默认不允许再使用同组新资源。玩家应先通过兼容行动承接、等待散逸，或在巩固根基中选择性收束残余药性。

## 11. 连续状态与自动延续

连续状态的存在与本回合是否重新输入指令分离。

规则：

- 下回合开始时，玩家可一键延续兼容行动。
- 选择不兼容行动视为中断或退出。
- 离线托管只在安全、低风险、无重大分支的情况下自动延续。

```
ContinuousActionState {
  state_id: String,
  character_id: String,
  action_type: String,
  action_template_id: String,
  node_id: String,
  route_state: Dictionary,
  started_turn_id: int,
  started_world_hour: int,
  accumulated_hours: int,
  required_hours: int,
  progress: float,
  compatible_followup_actions: Array,
  interruption_rules: Dictionary,
  overflow_policy: String,
  risk_tags: Array
}
```

## 12. 插入事件中断权

插入事件链可以中断 S3 时间轴。

S3 提供：

- 触发 turn_id。
- 触发 world_day / world_hour。
- 触发位置。
- 剩余小时数。
- 当前指令状态。
- 路线段。
- 当前连续行动。
- 托管状态。
- 暴露上下文。

事件链返回：

- 继续原计划。
- 消耗小时数。
- 强制中断本回合计划。
- 改变位置。
- 改变状态。
- 改变连续行动。
- 进入死亡、转世或特殊结算。

---

## 13. 休整、警戒、停留

三者是节奏、风险和位置管理工具，不是主要成长收益来源。

| 行动 | 作用 | 时间模式 |
| --- | --- | --- |
| 休整 | 恢复状态、降低疲劳、处理轻伤 | 可选投入 |
| 警戒 | 降低突发风险、提高事件反应 | 可选投入 |
| 停留 | 保持位置、等待窗口、降低额外风险 | 可选投入 |

## 14. 托管系统

### 14.1 托管触发

触发条件：

1. 玩家在决策阶段超时未提交。
2. 玩家明确设置本回合托管。
3. 房间恢复后存在缺失决策。
4. 插入事件链需要离线玩家做低风险响应。

### 14.2 托管生成

托管应优先：

```
保命 / 避险
> 不暴露核心后手
> 延续安全连续状态
> 巩固修炼或基础修炼
> 休整 / 警戒 / 停留
```

托管不得主动：

- 发起大境界突破。
- 进入高危秘境。
- 回收高风险正式后手。
- 消耗稀有不可逆资源。
- 主动消耗新的高价值丹药、高刺激速成资源或不可逆资源输入。
- 做死亡 / 转世 / 真名暴露等重大选择。

托管可以在安全、低风险且目标明确时处理已有残余效果：

- 角色体内有稳定残余修为药性时，可选择继续主动吐纳承接剩余药性。
- 刺激型残余药性存在且当前位置安全时，可选择巩固根基并收束药性。
- 不得为了处理残余效果而进入高危地点或触发重大不可逆选择。

### 14.3 托管输出

```
AutopilotPlan {
  player_id: String,
  character_id: String,
  turn_id: int,
  generated_reason: String,
  instruction_queue: Array,
  safety_notes: Array,
  forbidden_actions_checked: Array
}
```
