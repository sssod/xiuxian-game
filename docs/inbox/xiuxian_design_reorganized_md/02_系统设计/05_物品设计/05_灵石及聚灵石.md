# 物品设计｜灵石及聚灵石

## 1. 当前定位

本页是本目录包内关于灵石、低阶货币与聚灵石的统一引用目标。经济系统、交易系统、资源流转、设施维护、突破资源和资源输入规则只引用本页口径，不再各自维护币制或“高阶灵石”定义。

当前结论：

1. 灵石是修行世界主经济循环通货。
2. 灵石不分等级；不设计“中品灵石 / 上品灵石”作为货币面额。
3. 低阶货币只服务凡人阶段、村镇消费、伪装、剧情任务和新手教学，不进入主修行经济循环。
4. 聚灵石是高密度灵气物品，不是灵石的高阶面额，也不进入货币余额。
5. 普通灵石不能无损满足所有高阶灵气需求；高阶需求应通过聚灵石、阵法、设施、特殊资源或专用配方形成供给阀门。
6. 贡献、门内声望和职位不是货币，只能影响权限、价格修正、申请资格或可见范围，不能绕过真实库存兑换物品。

## 2. 灵石

灵石默认表达为资产容器中的货币余额，用于交易、基础修行消耗、交通通行、常规设施维护、服务费用、罚没、赔偿和事件支付。

```yaml
SpiritStoneBalance:
  currency_key: spirit_stone
  amount: number
  owner_container_ref: string
  bind_state: string | null
  reservation_refs: list
  ledger_refs: list
```

当灵石被封存、事件锁定、后手储藏、任务打包或需要独立追踪来源时，可以表现为可堆叠物品栈，但它仍然不是分级货币。

```yaml
SpiritStoneStack:
  item_template_id: spirit_stone_stack
  amount: number
  owner_container_ref: string
  bind_state: string | null
  stack_key_tags: list
  source_ref: string | null
  ledger_refs: list
```

规则：

1. 普通买卖、商店支付和玩家交易优先读写 `AssetContainer.currency_balances.spirit_stone`。
2. 灵石可作为基础修行、低阶设施、交通设施、服务入口和常规事件的支付成本。
3. 灵石支付不等于灵气资源输入。若某行动需要“灵气包”“高密度灵气”或“突破资源”，必须走资源输入、物品消耗或设施供能接口。
4. 绑定灵石、事件锁定灵石、市场挂牌所得、交易暂存灵石和后手封存灵石必须保留容器、预留和流水记录。
5. 出售、拆解、销毁、上交、回收或消耗灵石相关资产，不返还世界生成预算。

## 3. 低阶货币

低阶货币用于凡人世界与新手阶段的局部交易，不承担修行世界通用价值锚。

```yaml
MundaneCurrencyBalance:
  currency_key: coin_copper | silver | custom
  amount: number
  owner_container_ref: string
  context_tags: list
  ledger_refs: list
```

规则：

1. 低阶货币可用于村镇购买、干粮、住宿、凡人工具、伪装、低风险任务和早期教学。
2. 灵石可以兑换低阶货币，用于凡人区域消费、身份伪装或剧情任务。
3. 低阶货币兑换或折算灵石只能作为受限场景入口，不能成为稳定套利、刷修行资源或绕过主经济循环的入口。
4. 角色进入修行世界主循环后，普通 UI 应弱化低阶货币，只在相关节点、任务或身份伪装语境中展示。

## 4. 聚灵石

聚灵石是高密度灵气物品。它用来表达“普通通货经过加工、设施转化或特殊配方后，变成可供高阶系统调用的灵气资源”。

MVP 只打通一条加工路径：

```text
灵石 + 加工设施 + 时间 / 人力 / 技艺修正
→ 聚灵石
```

聚灵石默认可作为可堆叠物品处理；当它被用于正式后手、高价值突破、命名资源、事件锁定奖励或带有独立状态时，可以提升为 `ItemInstance`。

```yaml
CondensedSpiritStone:
  item_template_id: condensed_spirit_stone
  tier_code: string
  quality_code: string
  amount: number
  owner_container_ref: string
  stack_key_tags: list
  bind_state: string | null
  source_ref: string
  resource_effect_profile_ref: string | null
  compatible_hours: number | null
  ledger_refs: list
```

堆叠键至少包含：

```text
item_template_id + tier_code + quality_code + bind_state + key_state_tags
```

若来源、污染、宗门标记、后手共鸣、封印、相性或不稳定状态会影响突破、战斗、交易、后手、设施供能或消耗结果，则必须进入堆叠键，或改为独立实例。

## 5. 加工与生产接口

灵石加工属于轻量配方制生产，不展开完整工业链。

```yaml
CondenseSpiritStoneRecipe:
  recipe_id: string
  input_currency:
    spirit_stone: number
  required_facility_ref: string
  required_skill_tags: list
  action_cost_hours: number
  manpower_cost: number | null
  loss_rate_rule: string
  output_tier_rule: string
  output_quality_rule: string
  byproduct_profile_ref: string | null
  failure_profile_ref: string | null
```

规则：

1. 加工必须消耗真实容器中的灵石，并写资产流水。
2. 加工设施可以来自宗门设施、市场服务、个人洞府设施、节点资源槽附属设施或事件临时设施。
3. 加工产物进入指定行囊、宗门库存、节点库存、商店库存或事件锁定容器。
4. 加工效率、损耗率、产物阶级、产物品级和失败结果受设施等级、节点灵气、资源槽规模、人力、技艺、权限和事件状态影响。
5. MVP 阶段只要求能验证“通货 → 高密度灵气物品”的供给阀门，不要求开放多级加工链、金融套利或复杂市场工业。

## 6. 消耗与资源输入接口

聚灵石参与消耗时按物品或资源输入处理，不按货币支付处理。

典型用途：

1. 高阶阵法启动、维持、修复或过载。
2. 突破准备、突破事件链阶段消耗或护法阵供能。
3. 洞府维护、闭关设施供能、灵气环境临时强化。
4. 法宝充能、修复或特殊主动效果。
5. 特殊配方、炼器、阵盘、符箓或资源转换。
6. 事件选项中的高密度灵气投入。

资源输入可使用以下接口：

```yaml
ResourceUseRequest:
  request_id: string
  character_id: string
  source_container_id: string
  item_instance_id: string
  target_command_id: string | null
  target_event_option_id: string | null
  submitted_world_day: int
  submitted_world_hour: int
  status: pending | approved | rejected | consumed | refunded
  validation_result_ref: string
```

规则：

1. 消耗前必须检查容器权限、物品存在、数量、绑定、预留、事件锁定、市场挂牌、位置、行动标签兼容和角色状态。
2. 若聚灵石按兼容小时释放灵气，必须记录 `compatible_hours`、已消耗小时、残余策略和日志。
3. 若聚灵石作为一次性设施燃料或突破阶段资源，必须记录消耗阶段、失败损耗、释放或退款规则。
4. MVP 暂不在消耗环节强制复杂的阶级和品级限制；但所有消耗必须保留 Tier / Quality，供数值、日志、UI 和正式版适配矩阵读取。
5. 普通灵石不能自动替代聚灵石消耗。若系统允许临时折算，必须通过明确配方、设施服务或事件选项完成，并写明损耗和失败风险。

## 7. 价值与预算口径

灵石、低阶货币和聚灵石至少区分以下价值：

| 价值 | 灵石 | 低阶货币 | 聚灵石 |
| --- | --- | --- | --- |
| `TradeValue` | 主交易锚，可作为普通价格单位 | 只在凡人或特殊语境折算 | 按物品估价，受 Tier / Quality / 供给影响 |
| `BudgetValue` | 由生成预算或奖励模板决定，不等于交易价格 | 通常很低或不进入修行预算 | 按高密度资源预算扣除，可能高于加工灵石面值 |
| `SalvageValue` | 通常直接保留为余额或回收价 | 场景内折价处理 | 受损耗、污染、设施、技艺和品级影响 |
| `ContributionValue` | 可作为上交宗门的贡献折算来源 | 通常不作为宗门核心贡献来源 | 可按宗门需求、阶级和品级高权重折算 |

规则：

1. `BudgetValue` 不必等于 `TradeValue`。
2. 加工聚灵石的灵石投入不自动决定聚灵石最终交易价；设施成本、时间、人力、损耗、技术门槛和供给风险都应进入价格修正。
3. 贡献不是货币。上交灵石或聚灵石可以产生贡献、声望、职位评价或权限修正，但宗门发放资源仍必须检查真实库存。
4. 市场交易中的聚灵石是物品挂牌；成交后移动物品与灵石余额，不把聚灵石折算进货币余额。

## 8. 与经济系统的接口

经济系统引用本页时按以下边界处理：

| 场景 | 灵石口径 | 聚灵石口径 |
| --- | --- | --- |
| 商店买卖 | 主支付通货，读写货币余额 | 商品物品，进入 `shop_stock`、行囊或市场挂牌 |
| 玩家交易 | 可作为交易支付项 | 可作为交易物品项，需校验绑定、锁定和预留 |
| 市场寄售 | 成交款默认以灵石结算 | 挂牌资产本身是物品，不是货币余额 |
| 宗门库存 | 可作为五类宗门库存之一 | 作为修炼资源、材料或具体物品栈入库 |
| 资源申请 | 可申请或预留灵石支付 | 可申请或预留为突破、设施或资源输入 |
| 节点产出 | 通常来自事件、交易、税收或库存流转 | 可来自加工设施、特殊节点、事件或配方 |
| 世界生成预算 | 由奖励模板或预算规则决定 | 作为高密度灵气物品扣预算或由加工转化产生 |
| 后手封存 | 可封存为灵石栈 | 可封存为物品栈或实例，占用后手容量 |

## 9. 待补充配置

1. 低阶货币与灵石的受限兑换规则、节点适用范围和防套利约束。
2. `CondenseSpiritStoneRecipe` 的设施模板、损耗率、时间、人力和技艺修正公式。
3. 聚灵石 Tier / Quality 对 `TradeValue`、`BudgetValue`、`ResourceEffectBalance` 和 `RealmInputFitMatrix` 的具体映射。
4. 聚灵石在突破、洞府维护、阵法、法宝充能和特殊配方中的消耗表。
5. 聚灵石作为资源输入时的兼容小时、残余策略、压力风险和退款规则。
6. 灵石、聚灵石与宗门贡献折算的需求权重表。
