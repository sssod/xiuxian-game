## 1. 视觉基调

当前主界面视觉基调：

- 暖色宣纸底。
- 低饱和青绿作为主操作色。
- 金棕色用于强调、警示和边界。
- 灰褐色用于次级信息、不可用和保留锁定。

组件应服务于信息密度和可读性，不做装饰性大卡片堆叠。

## 2. 通用尺寸与圆角

规则：

- 主面板可使用 `10-12` 圆角。
- 按钮使用 `8` 圆角。
- 小标签 / 状态胶囊使用 `12` 圆角。
- 图标按钮保持 `38 x 38`。
- 角色头像保持 `52 x 52`。
- 状态数值条保持固定宽度，避免数值变化导致布局抖动。

## 3. 按钮状态

按钮类型：

| 类型 | 用途 |
|---|---|
| primary | 进入规划、设为目标等主操作 |
| secondary | 查看详情、一键延续等次操作 |
| ghost | 列表内轻量查看、即时行动项 |

按钮交互状态至少包含：

- default。
- hover。
- pressed。
- disabled。

禁用态必须明确降低对比度，不可只移除点击事件。

## 4. 标签与状态胶囊

标签用途：

- 信息分类。
- 风险等级。
- 选中状态。
- 阶段状态。

当前标签示例：

```text
P1
目标相关
节点变化
宗门
持续行动
可介入
已探索
资源紧张
边境争夺
风险中
即时行动仍可用
进入规划后，即时行动冻结
```

规则：

- 标签不承载长句。
- 同一卡片内标签数量过多时，优先保留风险和目标相关标签。
- 状态标签的颜色必须与语义一致，避免同一颜色同时表达成功与危险。

## 5. 阶段芯片

阶段芯片必须表达三种状态：

| 状态 | 视觉 | 示例 |
|---|---|---|
| 已完成 | 浅绿底、绿字 | `✓ 回合开始` |
| 当前 | 深绿底、白字 | `● 信息处理 / 即时行动` |
| 未开始 | 米色底、灰字 | `⌕ 个人行动` |

阶段条必须始终居中，不因左右信息卡变化而偏移。

## 6. 状态数值条

状态数值条用于：

```text
生机
元气
神念
```

### 6.1 保留值规则

保留值代表右侧最大上限锁定段。

错误表现：

- 把保留值画在当前填充条内部。
- 把保留值当作当前损失值。
- 把保留值用和空槽几乎相同的颜色表达。

正确表现：

- 保留段紧贴右侧。
- 保留段宽度按 `保留值 / 最大值` 计算。
- 当前填充最多到 `最大值 - 保留值`。
- 保留段与空槽有明显材质差异。

### 6.2 数值显示

默认不显示具体数字。

显示触发：

- hover。
- click。

显示位置：

- 浮层压在对应数值条上。
- 内容格式：`当前 / 保留 / 最大`。

命中区域必须覆盖整条数值条，而不只是彩色填充部分。

## 7. 信息卡

信息卡结构：

- 标题行。
- 正文摘要。
- 标签行。
- 可选按钮。

正文只保留本回合判断需要的信息。完整详情进入日志、账本、节点详情或宗门面板。

信息卡按钮不得直接触发回合结算。

## 8. 地图浮窗

地图浮窗类型：

- 顶部位置浮窗。
- 路线预估浮窗。
- 图例。
- 图层切换。
- 缩放控件。

规则：

- 地图顶部位置浮窗优先级高于图层切换面板。
- 图层切换面板可让位，不可遮挡当前位置 / 查看目标 / 计划目标。
- 路线预估应靠近地图底部，不压住底部预算条。

## 9. 文案规则

必须使用：

- `回合`。
- `第 N 天`。
- `当前位置`。
- `正在查看`。
- `计划目标`。
- `即时行动`。
- `个人行动规划`。
- `宗门当前持续行动`。

不得作为当前 UI 概念使用：

- `季度`。
- `六个朔望行动格`。
- `action_slot`。
- `宗门主行动输入`。
- `宗门决策阶段`。
- `时间暂停`。

## 10. 信息露出原则

默认首屏必须露出：

- 角色头像和两行身份。
- 三条状态数值条。
- 顶部阶段条。
- 房间回合摘要与倒计时。
- 地图顶部位置浮窗。
- 左侧待处理变动标题和至少前三张卡片的开头。
- 右侧目标模板和选中节点摘要。
- 底部 5 天预算条。
