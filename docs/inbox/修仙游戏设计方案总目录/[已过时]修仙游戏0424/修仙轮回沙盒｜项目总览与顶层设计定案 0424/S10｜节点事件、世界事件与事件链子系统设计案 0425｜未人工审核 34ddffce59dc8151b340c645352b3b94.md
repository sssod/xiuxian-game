## 1. 子系统定位

S10 是世界演化的事件层。

一句话定位：

> S10 决定玩家、宗门和世界在某个时间、地点、状态下会触发什么事件，以及事件结果如何改变角色、节点、宗门和日志。
> 

S10 是事件框架，不替代 S4 突破、战斗、后手等专用事件链。

## 2. 事件分类

MVP 事件分为：

1. 移动事件。
2. 节点事件。
3. 宗门事件。
4. 世界刷新事件。
5. 秘境 / 窗口事件。
6. 控制权变化事件。
7. 传闻生成事件。
8. 专用事件链入口。

专用事件链包括突破、战斗、死亡 / 转世、前世后手回收等。

## 3. 事件触发上下文

```
EventContext {
  quarter
  tick
  trigger_type
  node_id
  route_segment
  actor_refs
  faction_refs
  action_context
  visibility_context
  danger_level
  hidden_layer_refs
  rng_namespace
}
```

S3 提供离开 / 进入 / 途经 / 停靠 / 路途中 tick 的判定上下文。

## 4. 移动事件

移动事件覆盖：

- 离开节点。
- 进入节点。
- 途经节点。
- 目标节点。
- 每个行动格结束时所在路线段。

移动事件可以产生：

- 遭遇战。
- 路线阻断。
- 资源消耗。
- 信息发现。
- 行踪暴露。
- 延误。
- 安全抵达。

第一阶段山门路途中的“迎战或用轻身功法逃遁”属于移动事件。

## 5. 节点事件

节点事件挂载在 S8 节点、资源槽、建筑槽、隐藏层或控制权状态上。

节点事件可包含：

- 资源异变。
- 妖兽袭扰。
- 荒野探索发现。
- 秘境入口波动。
- 建筑损坏。
- 宗门冲突。
- 控制权争夺。
- 前世线索显露。

## 6. 世界刷新事件

季度开始时，S1 调用 S10 生成或更新世界事件池。

刷新内容：

- 秘境窗口。
- 节点危机。
- 宗门动向。
- 市场波动。
- 传闻候选。
- 资源槽状态变化。
- 隐藏层可发现性变化。

无人在线时世界不自动推进，因此刷新只在季度推进中发生。

## 7. 事件链结构

```
EventChain {
  chain_id
  event_type
  parent_context
  stages
  choices
  checks
  result_packages
  visibility_rules
  log_rules
}
```

MVP 事件链不需要复杂脚本语言；可先使用模板 + 条件 + 结果包。

## 8. 事件选择

事件选择应提供明确后果方向，而不是纯文字装饰。

选择影响：

- 资源消耗。
- 风险承担。
- 战斗 / 逃遁 / 交涉 / 调查入口。
- 节点状态。
- 角色状态。
- 宗门声望。
- 后续线索。
- 行动计划是否中断。

## 9. 事件结果包

```
EventOutcome {
  event_id
  outcome_level
  character_delta
  inventory_delta
  node_delta
  sect_delta
  route_delta
  triggered_child_events
  interrupt_s3_plan
  consumed_ticks
  ledger_entries
  visible_log_entries
  hidden_world_log_entries
}
```

所有结果交给 S1 统一回写，避免事件直接绕过结算总线。

## 10. 传闻与世界日志

需要区分：

- 世界日志：系统完整记录，用于测试、调试、回放，默认玩家不可见。
- 玩家传闻：世界日志的可见子集，根据角色位置、宗门关系、情报能力、事件公开性生成。
- 角色日志：角色自身经历、听闻和确认的信息。

玩家不应直接看到完整世界日志。

## 11. 事件优先级与去重

同一 tick 可能有多个候选事件。

MVP 规则：

1. 强制事件优先于普通事件。
2. 专用事件链优先于普通传闻。
3. 同一语义事件本 tick 只触发一次。
4. 事件链进行中时，普通 S3 时间轴暂停。
5. 事件链返回后，由 S1 决定是否继续原计划。

## 12. 与战斗系统的关系

S10 可以触发战斗，但不负责战斗内部结算。

流程：

```
S10 判定遭遇
→ 创建战斗事件请求
→ 战斗系统结算 5 格预输入与结果
→ 返回 EventOutcome
→ S10 / S1 写入节点、角色、日志变化
```

## 13. 与其他系统的接口

- S1：调度事件链并回写结果。
- S3：提供 tick、位置、路线、行动状态和剩余行动格。
- S4：突破中外扰、心魔、地点事件可请求 S10。
- S7：宗门行动可触发节点事件和控制权事件。
- S8：提供节点挂载点、隐藏层、危险等级。
- S11：前世后手线索与回收事件。
- S13：多人可见性、传闻传播、资源名额竞争。
- S14：事件模板、日志和调试回放。

## 14. MVP 验收标准

1. 移动中至少能触发一种路途事件。
2. 节点上至少能触发一种资源 / 危机事件。
3. 季度开始能刷新至少一种世界窗口。
4. 事件可以中断 S3 时间轴并返回结果。
5. 事件结果能写入角色日志、世界日志或传闻。
6. 至少一个事件能触发战斗或突破外扰子链。
