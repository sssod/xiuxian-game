# 流程设计｜单人游戏与多人共玩流程

## 1. 文档定位

本文固定“从创建房间到进入共享世界推进”的完整流程，并把房间设定、时间轴、单人与多人的差异、规则同构与存档隔离、真灵选择竞争模拟纳入同一条流程推导。

本文应能独立阅读。读者不需要依赖外部来源列表才能理解以下结论。

## 2. 当前结论

本项目的基础流程不是传统实时 MMO，也不是纯单机暂停制 RPG，而是：

```text
共享世界
+ 可保存房间
+ 服务端 / 房间主机权威结算
+ 可暂停
+ 可加速低交互阶段
+ 单人与多人底层同构
```

MVP 边界：

```text
本地可单人测试
可部署私人服务器
至少支持 3 人共玩
房间可保存、暂停、恢复、续开
单人与多人存档不可互相转换
MVP 多人房开始后不允许中途加入新玩家
```

单人房是一等公民。多人不是重做一套规则，而是在同一套 PvE 宗门沙盒、共享日历和权威结算规则上加入真实玩家变量、可见性过滤、超时托管和间接竞争。

核心乐趣不依赖高频玩家直接互动。多人压力主要来自共享世界中的节点、资源、宗门、传闻、机会窗口、后手与时间选择。

## 3. 房间类型与创建入口

房间是所有运行时状态的边界。无论单人还是多人，玩家都先进入一个可保存房间，再进入世界。

房间入口：

```text
新建本地单人房
新建私人多人房
加入未开局的私人多人房
读取已有房间存档
```

房间模式：

| 模式 | 用途 | 玩家数量 | 权威位置 | 存档边界 |
| --- | --- | --- | --- | --- |
| `single_local` | 本地单人测试与正式单人游玩 | 1 | 本地房间进程 | 单人存档，不可转多人 |
| `private_hosted` | 私人服务器 / 主机房间 | 开局前锁定槽位 | 私人服务器 / 主机 | 多人存档，不可转单人；MVP 开局后不可加人 |
| `loaded_room` | 读取存档继续 | 取决于存档原模式 | 取决于存档原模式 | 按原模式读取，不转换 |

单人房不是“无服务器规则”。单人本地也走同一套房间权威结算，只是权威进程可以在本地运行，超时、可见性和等待规则简化。

## 4. 房间基础设定

每个房间至少需要保存以下设定：

```yaml
RoomConfig:
  room_id: string
  room_name: string
  mode: single_local | private_hosted
  world_seed: string
  created_at: datetime
  max_players: int
  min_multiplayer_supported_players: 3
  host_player_id: string | null
  save_policy: manual | autosave | manual_and_autosave
  save_lineage: single_only | multiplayer_only
  join_policy: pre_start_only | special_midgame_join
  midgame_join_enabled: bool
  offline_time_policy: freeze_when_empty | allow_managed_progress
  debug_mode: off | local_only | host_only
  visibility_policy: normal | debug_visible
  time_config_ref: string
  timeout_policy_ref: string
  true_spirit_pool_ref: string
```

房间创建时固定 `world_seed`。世界种子用于地图初始生成、真灵候选池排序、非玩家宗门初态、资源窗口初态和可复盘随机命名空间。玩家不能通过刷新 UI 改变已经提交的房间级随机结果。

`save_lineage` 在房间创建时固定。`single_only` 与 `multiplayer_only` 不允许互相转换，也不允许通过读取存档改写。单人存档即使底层使用同一套结算模型，也不能升级为多人存档；多人存档即使只剩一名玩家继续游玩，也不能降级为单人存档。

MVP 中 `join_policy` 固定为 `pre_start_only`，`midgame_join_enabled=false`。正式版即使支持中途加入，也必须通过特殊房间设置显式开启，默认仍为关闭。

## 5. 创建 / 读取房间主流程

```text
选择入口
→ 创建或读取 RoomState
→ 校验 RoomConfig 与存档版本
→ 初始化或恢复世界种子、地图节点、宗门、资源窗口、NPC 与日志索引
→ 进入房间大厅
→ 开局前玩家占用玩家槽位
→ 真灵选择与竞争模拟
→ 创建或恢复玩家真灵
→ 创建或恢复当前世角色
→ 写入初始日志 / 恢复摘要
→ 进入共享世界日历
```

读取存档时，未完成的局部时停、C1 追赶、B1 交锋、P0 全局暂停和待合并结果包必须先恢复为明确状态，再允许玩家继续输入普通行动。

## 6. 玩家槽位与加入流程

多人房间使用玩家槽位管理，不用即时匹配。

```yaml
PlayerSlot:
  slot_id: string
  player_id: string | null
  join_state: empty | reserved | joined | ready | disconnected
  true_spirit_id: string | null
  character_id: string | null
  visibility_scope: private_player
  ready_for_world_start: bool
```

MVP 加入窗口只存在于房间进入 `world_running` 之前：

```text
房间大厅开放
→ 玩家加入并占用空槽位
→ 玩家完成真灵选择和角色初始化
→ 全部必要槽位 ready 或房主按规则开局
→ 房间进入 world_running
→ 锁定玩家槽位
→ 不再接受新玩家中途加入
```

`reserved` 槽位只能用于开局前邀请或掉线重连，不表示开局后可以补进新玩家。开局后断线玩家回到同一 `player_id / slot_id / true_spirit_id`，不是新玩家加入。

正式版若要支持中途加入，必须满足：

```text
房间创建时显式开启 special_midgame_join
midgame_join_enabled=true
UI 对房主和玩家明确提示该房间允许中途加入
加入点必须处于非 B1、非 P0、非局部时停、非 C1 追赶、无待合并结果包的稳定小时快照
新玩家只能获得加入时允许的新真灵入口，不得改写已发生历史
公开历史、私人日志、隐藏后手归因和 Debug 记录仍按可见性过滤
```

该能力不进入 MVP，且正式版默认不开启。

房主可以创建、保存、暂停和恢复房间。房主权限不能绕过结算规则，不能直接修改玩家角色、真灵、资产、后手和世界结果。房主暂停也必须进入明确的 P0 状态，并记录公开原因。

无人在线时，默认世界保持静止。只有房间规则明确启用离线托管推进时，才允许在所有玩家都有合法显式托管或房间托管策略的情况下继续推进。

## 7. 真灵选择与竞争模拟

真灵选择发生在房间大厅到进入世界之间。目标是同时满足三件事：

```text
玩家获得跨世身份锚点
预设真灵保持稀缺感和世界唯一性
多人房间避免玩家靠抢 UI 操作获得优势
```

真灵选择分两类：

| 类型 | 说明 | 剧情线 | 是否参与竞争模拟 |
| --- | --- | --- | --- |
| 预设真灵名 | 房间候选池中已有的真灵名，绑定专属剧情线和初始角色模板 | 专属剧情线 | 是 |
| 自定义真灵名 | 玩家自定义名称，不占用预设名额 | 通用弱剧情线 | 否 |

### 7.1 随机分配为主

多人房间中，预设真灵名不采用先点先得。默认流程是“玩家提交偏好，服务器随机分配”。

```text
房间根据 world_seed 生成预设真灵候选池
→ 所有玩家看到同一候选池和可选自定义入口
→ 玩家提交 0-N 个偏好真灵名，或选择自定义真灵名
→ 到达准备截止条件后锁定所有提交
→ 服务器使用 room_rng.true_spirit_assignment 随机排序玩家槽位
→ 按随机顺序尝试满足玩家偏好
→ 偏好冲突时由随机顺序决定归属
→ 未获得偏好的玩家进入剩余候选随机分配或自定义真灵确认
→ 写入 TrueSpiritAssignmentLog
```

偏好只表达倾向，不保证获得。随机顺序必须由房间种子、玩家槽位、提交摘要和专用随机命名空间生成，保证可复盘、不可通过 UI 刷新重掷。

### 7.2 单人房中的竞争模拟

单人房没有真实玩家争抢，但仍可保留“真灵稀缺感”。默认处理：

```text
玩家选择预设真灵名 → 直接获得
玩家选择随机真灵 → 从候选池随机分配
未被选择的预设真灵名可作为世界线索、NPC 传闻、宿敌、后续真灵故事或不可见背景保留
```

单人房不需要模拟其他玩家抢走当前玩家选择的预设真灵。若设计需要表现“命数竞争”，只能作为剧情展示或后续世界线索，不得阻断玩家当前选择。

### 7.3 多人竞争模拟的公平约束

```text
不能先点先得
不能因网络延迟决定归属
不能在提交后通过刷新重掷
不能公开其他玩家的完整偏好
不能把真灵分配结果直接暴露为私人剧情归因
必须记录随机命名空间、提交摘要、分配顺序和最终归属
```

可见性：

| 信息 | 本人可见 | 其他玩家可见 | Debug 可见 |
| --- | --- | --- | --- |
| 本人偏好列表 | 是 | 否 | 是 |
| 他人偏好列表 | 否 | 否 | 是 |
| 最终真灵名 | 按房间公开策略 | 按房间公开策略 | 是 |
| 专属剧情线细节 | 是 | 否 | 是 |
| 分配随机顺序 | 否 | 否 | 是 |

### 7.4 真灵分配结果

真灵分配完成后生成：

```yaml
TrueSpiritAssignmentLog:
  room_id: string
  assignment_id: string
  rng_namespace: room_rng.true_spirit_assignment
  locked_world_day: int
  locked_world_hour: int
  submitted_slot_refs: list
  result:
    - slot_id: string
      true_spirit_id: string
      true_name_mode: preset | custom
      story_line_type: dedicated | generic_weak
      assignment_method: preference_random | remaining_pool_random | direct_single | custom
```

该日志用于复盘和 Debug，不等同于玩家可见公共日志。

## 8. 初次进入世界流程

```text
真灵分配完成
→ 创建 TrueSpiritState
→ 绑定真灵名、剧情线、轮回账本和暴露初态
→ 创建当前世 CharacterState
→ 写入角色姓名、性别、年龄、出生区域、出生位置、外观、属性、初始物资
→ 写入真灵背景日志与当前角色自知日志
→ 初始化 CommandQueue
→ 初始化 FallbackState 为空
→ 初始化 ManagedActionState 为空
→ 进入 world_running
```

初次角色不生成世俗背景身份。出生位置、外观、属性和初始物资可以影响可玩开局，但不得反向生成家族、门第、官籍、职业履历或主线身份锚点。

## 9. 共享世界日历与时间轴

房间主时间字段：

```text
world_day
world_hour
```

1 游戏日 = 24 游戏小时。运行时结算粒度是 `hour_tick`，不是回合、季度或行动格。

公开速度状态：

| 状态 | 用途 | 现实时间 : 游戏时间 | 规则含义 |
| --- | --- | --- | --- |
| `N1` | 常规推进 | 15 秒 = 1 游戏小时 | 默认多人速度；可编辑普通行动队列 |
| `F1` | 高速推进 | 2 秒 = 1 游戏日 | 全员处于长期低交互行动时启用 |
| `B1` | 交锋慢速 | 60 秒 = 1 游戏小时 | 正式战斗、突破挑战、秘境关键交锋、玩家直接交锋 |
| `P0` | 全局暂停 | 游戏时间不流动 | 公共阶段事件、同步保护、主机暂停、全局决策 |

速度优先级：

```text
P0 > B1 > N1 > F1
```

速度选择：

```text
如果存在 active_global_pause → P0
否则如果存在 active_formal_encounter → B1
否则如果任一玩家处于 local_time_stop → N1
否则如果全员满足 F1 条件 → F1
否则 → N1
```

F1 条件：

```text
所有玩家都有当前行动
所有玩家处于长期低交互行动
所有当前行动均允许 f1_eligible=true
没有玩家处于自动兜底
没有待响应局部事件
没有 B1 / P0 / C1
没有即将到期的关键公开窗口
```

F1 不是跳转未来，不允许“推进至下一事件”“跳到下一节点”“跳到预设未来时间”。F1 只是按固定 tick 连续压缩推进，所有行动、资源衰减、节点变化、宗门持续行动和日志仍按权威结算写入。

## 10. 房间主循环

```text
房间加载 / 恢复
→ 世界日历运行
→ 玩家在允许状态下编辑普通短队列
→ 服务器按当前速度推进 hour_tick
→ 行动完成点 / 小时 tick 执行校验、结算、事件判定
→ 宗门持续行动、地图节点、资源窗口、NPC 与传闻更新
→ 个人事件进入局部时停 + 外部 N1
→ 正式交锋 / 突破挑战进入 B1
→ 全局公共事件进入 P0
→ 事件结束后 C1 追赶或恢复速度判定
→ 合并结果包
→ 回写角色、真灵、宗门、节点、资产、日志、传闻和 TimelineReplay
→ 玩家阅读报告并规划下一阶段
```

普通行动队列使用“当前指令 + 最多 3 条预输入”的短队列。队列编辑不冻结世界。玩家在 F1 中打开普通队列编辑界面时，房间应降为 N1，避免高速状态下误操作。

阶段摘要只负责阅读、报告和规划承接，不作为底层结算单位。

## 11. 局部时停、C1、B1 与 P0

个人事件可以让事件玩家进入局部时停：

```text
事件玩家角色时间冻结在触发 world_hour
事件玩家当前行动、资源变化和风险变化暂停
其他玩家、宗门和世界继续 N1
gap = 世界当前时间 - 玩家冻结时间
gap 最大 1 游戏日
```

gap 达到上限时：

```text
有安全默认选项 → 自动执行安全默认
无安全默认选项 → 进入 P0 同步保护
```

局部时停结束后执行 C1 追赶补结算：

```text
从冻结 world_hour 回填事件选择后果
补结算确定性行动进度、修炼收益、资源消耗、药性衰减、伤势恢复、队列切换
追赶期间不触发随机个人事件、普通机缘、普通战斗、软机会事件、普通心魔或普通资源反馈
补结算完成后重新检查速度条件
```

B1 正式交锋：

```text
世界进入 B1
1 交锋轮 = 1 游戏小时
未提交者执行预设策略或超时安全默认
每轮结算后世界时间推进 1 游戏小时
非参战玩家也按 B1 世界时间推进
```

P0 全局暂停必须有公开原因、参与要求、默认处理策略和状态记录。P0 不是普通玩家随意暂停，而是房间级同步保护或房间规则允许的主机暂停。

## 12. 离线、超时与托管

离线和超时玩家采用稳健托管，但必须区分三种来源：

| 类型 | 来源 | 是否可参与 F1 | 用途 |
| --- | --- | --- | --- |
| 自动兜底 | 队列空或执行前校验失败 | 否 | 防止角色冻结，等待玩家补指令 |
| 显式托管 | 玩家主动输入或房间托管设置 | 满足条件时可 | 低关注、低收益、安全运行 |
| 超时安全默认 | 局部事件 / B1 / P0 超时 | 否 | 防止多人时间卡死 |

托管优先级：

```text
保命 / 避险
> 不暴露核心后手线索
> 延续安全连续状态
> 巩固修炼或基础修炼
> 维持低风险宗门职责
> 休整 / 警戒 / 停留
```

托管不得主动执行：

```text
高风险突破
主动转世
叛宗
宗门战争
暴露核心后手线索
高危秘境
强 PvP
消耗稀有不可逆资源
重大路线选择
高风险宗门外洞府 / 普通藏宝开启或破阵
```

自动兜底固定 `f1_eligible=false`，并强制房间速度不高于 N1。

## 13. 多人流程边界

MVP 多人默认采用：

```text
分宗并行
+ 间接竞争
+ PvE 沙盒演化
+ 信息不完全
+ 低频关键同步
```

保留的轻量间接竞争：

```text
宗门节点控制竞争
世界资源名额竞争
秘境 / 机会窗口占用
宗门库存申请与预留
路线发现、封锁或泄露
NPC 关系偏移
传闻改变判断
宗门遗产清点、宗门外洞府 / 普通藏宝等无主遗留设施发现、触发或争夺
突破公开影响改变宗门和世界态势
```

不作为 MVP 核心验证：

```text
玩家直接交易
玩家直接赠予
互相护法
玩家共同秘境
直接斗法
离线袭击
破坏他人突破
直接抢夺他人洞府或核心后手
强 PvP 围杀
复杂同宗议事投票
```

若出现直接玩家冲突，必须进入 B1 `FormalEncounterState`，并受正式战斗、事件和可见性规则约束。直接 PvP 不是默认多人压力来源。

同宗多人不走强制投票，不恢复宗门主行动建议，也不引入宗门主行动冲突。玩家通过资源申请、事件处理、宗门贡献、职位、NPC 关系、传闻、个人行动和后手间接影响彼此。

后手、遗产与无主遗留设施在多人中遵循同一资产规则：玩家转世前留下的宗门个人洞府库存按有主遗产清点回收；宗门外个人洞府和普通藏宝是无主遗留设施，可能因线索泄露、条件满足或破阵被其他角色提前打开；真灵藏宝作为正式后手由同一真灵跨世感应和开启，受设置数量与单个容量限制，MVP 阶段不作为他人直接抢夺目标。

## 14. 单人与多人的差异

| 维度 | 单人房 | 多人房 |
| --- | --- | --- |
| 权威结算 | 本地房间进程权威 | 私人服务器 / 主机权威 |
| 时间推进 | 可由玩家更自由暂停和继续，但仍表达为房间状态 | 受全员行动、局部时停、B1、P0 和超时策略约束 |
| F1 条件 | 只检查单个玩家、AI 宗门和世界状态 | 必须全员满足长期低交互条件 |
| 超时 | 通常不需要强制超时 | 必须有安全默认，防止卡死 |
| 可见性 | 可简化为本人 / 世界 / Debug | 必须过滤私人归因、他人偏好、隐秘后手和 Debug 信息 |
| 竞争压力 | AI 宗门、资源窗口、世界事件提供压力 | AI 宗门 + 真实玩家间接竞争 |
| 真灵选择 | 可直接获得预设真灵 | 预设真灵通过随机分配竞争模拟 |
| 直接互动 | 不适用 | MVP 不以直接互动为核心 |

单人不是“删掉多人规则”。单人只是参与者少，因此等待、超时、可见性过滤和真灵分配竞争更简单。

## 15. 规则同构与存档隔离

单人与多人只在规则和数据结构上同构，不在存档层面互通。

```text
同一套 RoomState
同一套 world_day / world_hour
同一套 CommandQueue
同一套 ResultPackage
同一套 TimelineReplay
同一套真灵与角色分层
```

存档隔离规则：

1. 单人存档创建后永久保持 `single_only`，不可转换为多人存档。
2. 多人存档创建后永久保持 `multiplayer_only`，不可转换为单人存档。
3. 多人房进入 `world_running` 后，MVP 不允许新玩家中途加入。
4. 多人玩家断线后只能以原玩家身份重连，不创建新玩家槽位。
5. 多人存档即使只剩一名玩家在线，也继续按多人房间规则保存、暂停、恢复和结算。
6. 单人和多人可以共享规则、字段、结果包和回放结构，但不能共享或迁移运行时历史。

正式版中途加入规则：

1. 默认关闭。
2. 只能在创建多人房时通过特殊房间设置开启。
3. 开启后必须在房间 UI、存档元数据和服务器配置中清楚标记。
4. 中途加入不能用于单人转多人，也不能用于多人转单人。
5. 中途加入不能改写历史归属、真灵分配、已发生竞争结果、私人日志或隐藏后手归因。

因此，“规则同构”只服务开发、测试、复盘和实现一致性；“存档隔离”是玩家流程和房间边界的硬规则。

## 16. 结果包、日志与时间轴回放

所有系统变化必须通过结果包合并，不允许子系统绕过房间权威结算直接改世界。

结果包至少应覆盖：

```text
角色变化
真灵变化
修炼收益
行动队列变化
托管 / 兜底记录
资源消耗与残余效果
宗门状态变化
节点与路线变化
资产与物品变化
事件结果
B1 轮结果
P0 开始与结束
后手 / 遗产 / 无主遗留设施 / 传闻 / 可见性变化
多人间接竞争结果
```

`TimelineReplay` 记录：

```text
速度变化
队列编辑
指令校验
自动兜底
显式托管
局部时停
C1 追赶
B1 交锋轮
P0 全局暂停
真灵分配
房间保存 / 恢复
结果包合并
公开摘要与私人日志分发
```

玩家可见回放必须按可见性过滤。公开速度变化不得泄露私人事件归因。

## 17. MVP 验收流程

最小验收链路：

```text
创建本地单人房
→ 生成世界种子与房间配置
→ 选择或随机获得真灵
→ 创建当前世角色
→ 进入 world_running
→ 提交普通行动队列
→ 按 N1 推进 hour_tick
→ 满足条件后进入 F1
→ 触发个人事件并进入局部时停
→ 完成选择并执行 C1 追赶
→ 触发突破或正式交锋并进入 B1
→ 保存房间
→ 读取房间并恢复同一状态
```

多人验收链路：

```text
创建私人多人房
→ 至少 3 个玩家槽位加入
→ 所有玩家提交真灵偏好
→ 服务器随机分配冲突预设真灵
→ 所有玩家创建当前世角色
→ 进入共享世界日历
→ 玩家分别提交普通行动队列
→ 全员长期低交互时进入 F1
→ 一名玩家触发局部时停时外部世界保持 N1
→ 另一名玩家触发 B1 时全房间进入 B1
→ 玩家超时执行安全默认
→ 节点、资源或宗门库存产生一次间接竞争结果
→ 日志按本人、公开、Debug 三类可见性过滤
→ 保存并恢复房间
```

## 18. 裁决与待定参数

已固定裁决：

| 采用方案 | 废弃方案 | 原因 |
| --- | --- | --- |
| 连续日历 + `world_day / world_hour` + `hour_tick` | 回合、季度、行动格作为底层结算单位 | 多人、局部时停和回放需要绝对小时对齐 |
| F1 / N1 / B1 / P0 | 跳到未来事件点 | 高速也必须连续结算 |
| 单人多人底层规则同构，但存档隔离 | 单人与多人两套流程，或单人多人存档互转 | 降低开发分叉，同时避免历史、可见性和玩家槽位被转换破坏 |
| 预设真灵随机分配 | 预设真灵先点先得 | 避免网络延迟和 UI 操作决定稀缺身份归属 |
| MVP 多人开局后锁定玩家槽位 | 开局后默认补进新玩家 | 避免真灵分配、世界历史、私人归因和资源竞争被中途加入破坏 |
| 多人间接竞争为核心 | 强 PvP 和高频直接社交 | MVP 验证共享世界压力，不改变核心体验 |
| 显式托管、自动兜底、超时安全默认分离 | 离线 / 超时 / 自动行为混用 | 三者来源、收益、F1 资格和风险边界不同 |

仍需后续填表的参数：

```text
预设真灵名列表与候选池规模
真灵偏好提交数量上限
多人准备截止条件
局部事件、B1、P0 的具体超时时长
房主暂停的权限边界和冷却
正式版 special_midgame_join 的技术与叙事准入条件
```

这些是配置表和内容表参数，不改变本文固定的主流程。
