# 系统设计｜角色持续状态系统

## 1. 设计定位

角色持续状态系统负责承接挂在角色身上的非一次性状态、条件和持续效果。伤势、道伤、心魔、体内药性、药性残余、符箓术式、法宝触发态、环境侵蚀、事件结果状态和战斗 / 突破后的阶段性影响，都应进入本文统一管理。

本文不维护角色属性字段本身，也不直接改写体魄、精力、根骨、悟性、灵根、派生状态上限或寿元事实字段。持续状态若需要影响角色属性有效值，必须通过《角色属性》（`02_角色属性.md`）中的后天修正接口生效；若需要造成生机、元气、神念当前值变化，则通过状态结算输出写入派生状态变化日志。

本系统服务：

1. 统一记录角色身上的持续状态来源、时长、显隐、叠加、互斥和失效条件。
2. 承接符箓、丹药、法宝、阵法、战斗、突破、移动、环境和事件结果施加的持续状态。
3. 向角色属性系统导出临时后天修正或状态结算结果。
4. 为修炼、战斗、移动、突破、事件、AI 和 UI 提供可解释的状态读取入口。
5. 为日志、回放、C1 追赶和异常排查提供统一状态流水。

## 2. 当前结论

1. 伤势状态不再作为角色属性分层，也不进入 `CharacterAttributeProfile`；它属于角色持续状态系统。
2. 所有持续状态必须有来源、目标角色、生命周期、结算时钟、显隐策略、叠加 / 互斥规则和日志引用。
3. 丹药、符箓、法宝或事件结果只负责声明“可以创建什么状态”；状态创建后由本文规则统一管理。
4. 持续状态对角色属性有效值的影响，统一导出为 `acquired_modifiers` 的临时后天修正，不直接写入先天值或后天永久值。
5. 持续状态到期、治愈、驱散、转化或结算后，其临时修正必须同步失效；若产生永久后果，必须由结算结果另行写入角色属性的后天永久修正、寿元来源或角色履历。
6. 同一状态可以同时包含可见描述、数值修正、事件标签、行动限制和结算输出，但这些子效果必须能追溯到同一个状态实例。
7. 经脉压力在当前修炼口径中只表达身体承载、体内药性、外源灌注或刺激型资源输入风险；它不再承接当前大境界纯度、法力密度、根基质量、心神稳定、战斗出力或复杂突破链条。

## 4. 核心循环或触发入口

持续状态围绕“创建、激活、结算、导出、失效、归档”循环维护。

1. 创建：丹药直接服用、符箓使用、丹药吸收、法宝触发、战斗结果、突破结果、事件选项、环境暴露、行动中断或治疗结果创建状态实例。
2. 激活：状态进入 `active` 后开始向系统导出标签、限制、后天修正或结算输出。
3. 结算：按世界小时、兼容行动小时、危险暴露小时、战斗轮、事件阶段或条件触发进行 tick。
4. 导出：状态影响角色属性时，生成或更新 `acquired_modifiers` 临时修正；影响生机、元气、神念当前值时，写入派生状态变化结果。
5. 失效：状态因时长耗尽、条件解除、治疗、驱散、覆盖、转化、角色死亡或事件结算结束而失效。
6. 归档：失效状态保留来源、已生效时长、最终结果、日志引用和回放所需字段。

持续状态不负责决定某件物品能否被使用，也不负责决定战斗、突破或事件的完整结果。物品、行动、战斗、突破和事件系统确认结果后，将需要挂到角色身上的持续影响交给本文承接。

## 5. 规则与状态

### 5.1 状态分类

| 分类 | 示例 | 主要来源 |
| --- | --- | --- |
| 伤病类 | 外伤、内伤、道伤、经脉损伤、毒伤、濒死后遗症 | 战斗、突破、事件、环境、治疗失败 |
| 心神类 | 心魔、心神动摇、神念紊乱、定心保护 | 修炼、突破、事件、丹药、符箓、法宝 |
| 资源残余类 | 体内药性、残余药性、灵材余效、恢复效果、避瘴效果、药性负载 | 丹药、灵材、临时增益资源 |
| 术式类 | 护盾、防护、隐匿、破禁窗口、标记、符箓余效 | 符箓、阵法、法门、事件 |
| 法宝触发类 | 护体触发、镇压、预警、短时强化、暂时失灵影响 | 法宝主动使用或被动触发 |
| 环境与事件类 | 毒瘴侵蚀、寒热压制、诅咒、誓约、封禁、剧情标记 | 地图节点、事件结果、NPC 行为 |
| 行动限制类 | 疲惫、负重感、禁用移动、闭关锁定、战后虚弱 | 行动结算、移动、战斗、事件 |

分类用于状态管理和 UI 汇总，不替代具体效果模板。具体数值、时长和风险由来源系统或数值文档维护。

### 5.2 生命周期

推荐状态生命周期：

```text
pending -> active -> suspended -> decaying -> settling -> resolved
```

| 状态 | 含义 |
| --- | --- |
| `pending` | 已创建但尚未满足激活条件，例如事件阶段未到或自动触发条件未确认 |
| `active` | 当前生效，允许导出修正、标签、限制或 tick 结果 |
| `suspended` | 暂停生效，例如非兼容行动期间稳定体内药性或残余药性不释放 |
| `decaying` | 正在衰减，可能减少剩余时长、剩余额度或转化为副作用 |
| `settling` | 正在做最终结算，例如治愈、驱散、转化、到期清算 |
| `resolved` | 已结束并归档，不再导出任何当前效果 |

规则：

1. 只有 `active`、`suspended` 和 `decaying` 状态可以保留未完成的持续影响。
2. 只有当前生效的状态可以导出后天临时修正。
3. `resolved` 状态不得继续影响角色属性、行动可用性或 UI 当前状态。
4. 从状态转为永久后果时，必须产生新的结果记录，不能让一个“永久持续状态”绕过后天永久修正或寿元来源记录。

### 5.3 结算时钟

持续状态的时钟由创建来源声明，状态系统统一执行。

| 时钟 | 用途 |
| --- | --- |
| `world_elapsed_hours` | 启用后随世界小时推进，不因行动不兼容暂停 |
| `compatible_action_hours` | 只在兼容行动或兼容事件阶段内推进 |
| `hazard_exposure_hours` | 只在危险暴露时间内推进 |
| `combat_rounds` | 只在战斗轮内推进 |
| `event_phase` | 只在事件链指定阶段内推进 |
| `condition_until` | 不按固定时长，直到治疗、驱散、离开地点、完成任务或条件解除 |
| `permanent_until_cured` | 作为长期伤病或道伤存在，但仍可被治疗、转化或结算为永久后果 |

默认不把所有状态都设为 `world_elapsed_hours`。体内药性、药性残余、符箓术式、法宝防护和事件状态应按模板选择与玩家决策相匹配的时钟。

体内修为药性默认读取 `compatible_action_hours` 或等价兼容修为增长流时钟。主动吐纳和闭关修行片段可高效消化；自动 / 被动运转可低效消化；移动、交易、普通社交和战斗交锋默认不消化，除非来源模板或事件模板明确覆盖。

### 5.4 后天修正接口

持续状态对角色属性的影响通过 `acquired_modifiers` 导出。

推荐导出结构：

```text
StateModifierExport {
  export_id: String
  state_id: String
  target_attribute: base_physique | base_vigor | aptitude_bone | aptitude_comprehension | bar_vitality_max | bar_qi_max | bar_mind_max | bar_vitality_reserve | bar_qi_reserve | bar_mind_reserve
  modifier_kind: temporary_flat | temporary_percent | reserve_delta | max_flat_bonus | max_percent_bonus
  value: number
  stacking_group: String
  conflict_group: String | null
  priority: int
  valid_while_state: active | active_or_decaying
  source_ref: String
}
```

规则：

1. 状态导出的修正都是临时后天修正，除非状态最终结算另行写入后天永久改变。
2. 状态不得直接改写 `innate_value`、`acquired_permanent_delta`、灵根基础评级或灵根相性结构。
3. 状态影响体魄、精力、根骨或悟性时，角色属性系统只读取导出的临时修正合计。
4. 状态影响生机、元气、神念上限或保留值时，仍通过后天修正接口或派生状态调整入口表达，不直接改写数值缓存。
5. 状态造成生机、元气、神念当前值变化时，应输出 `state_tick_result`，由派生状态结算日志承接。
6. 状态失效后，所有由该状态导出的修正必须停止参与属性有效值计算。

### 5.5 叠加、互斥与覆盖

持续状态必须声明 `stacking_group` 和必要的 `conflict_group`。

| 规则 | 说明 |
| --- | --- |
| 同组数量上限 | 同一 `stacking_group` 可同时存在的状态数量由模板声明 |
| 覆盖 | 新状态可以覆盖旧状态，但必须写入旧状态结束原因 |
| 刷新 | 新状态可以刷新剩余时长或剩余额度，但必须保留来源日志 |
| 并存 | 不同来源状态可以并存，但导出修正仍需按同一乘区和叠加规则合并 |
| 互斥 | 处于同一 `conflict_group` 的状态不得同时生效，除非事件模板明确允许 |
| 转化 | 一个状态可以转化为另一个状态，例如药性衰减转为疲惫或经脉压力 |

叠加规则必须先解决状态是否并存，再解决数值如何合并。不得让来源系统各自私下叠加，绕过状态系统。

### 5.6 显隐、日志与回放

状态可见性建议：

```text
visibility = hidden | hinted | revealed | debug_only
```

规则：

1. 玩家可见状态应显示来源、方向、剩余时长或触发条件、主要影响和可处理方式。
2. 未揭示状态可以只显示症状、风险提示或异常感知，不显示内部 ID 和精确公式。
3. Debug 信息可以显示状态 ID、来源引用、剩余 tick、导出修正和叠加组。
4. C1 追赶和回放必须只使用已经固化的随机结果，不重新随机状态强度。
5. 状态创建、tick、暂停、衰减、覆盖、失效、转化和结算都应写入日志或结果包引用。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 角色属性 | 读取状态导出的临时后天修正；不保存伤势状态列表 |
| 派生状态 | 承接状态 tick 对生机、元气、神念当前值、上限或保留值的变化结果 |
| 丹药与资源 | 创建体内药性、药性残余、恢复、避险、属性临时修正或炼化状态 |
| 符箓 | 创建术式、防护、移动、探索、破禁或战斗轮持续状态 |
| 法宝 | 创建主动使用、被动触发、镇压、防护、预警或暂时失灵相关状态 |
| 战斗系统 | 创建伤势、虚弱、护盾、控制、标记和战后状态；读取状态限制与修正 |
| 突破系统 | 创建道伤、经脉压力、心魔、稳定状态、突破保护或失败后遗症 |
| 修炼系统 | 读取药性、伤势、疲惫、经脉压力和后天修正导出；经脉压力只影响承载与外源输入风险，不直接改写 CP、法力或纯度 |
| 移动与地图 | 创建危险暴露、环境侵蚀、避险保护和路线限制状态 |
| 事件系统 | 创建剧情状态、诅咒、誓约、封禁、祝福、治疗结果和隐藏标记 |
| NPC / AI | 读取可见或系统可用状态，用于判断治疗、袭击、交易、救援和托管策略 |

## 7. 数据字段建议

```text
CharacterOngoingState {
  state_id: String
  character_id: String
  state_type: injury | dao_wound | mental | resource_residue | talisman_effect | artifact_effect | environment | event_condition | action_limit | custom
  display_name: String
  source_type: pill | talisman | artifact | event_result | combat_result | breakthrough_result | environment | method | npc | system
  source_ref: String
  polarity: beneficial | harmful | mixed | neutral
  lifecycle_state: pending | active | suspended | decaying | settling | resolved
  visibility: hidden | hinted | revealed | debug_only
  clock_type: world_elapsed_hours | compatible_action_hours | hazard_exposure_hours | combat_rounds | event_phase | condition_until | permanent_until_cured
  remaining_duration: number | null
  remaining_amount: number | null
  tick_policy: String
  stacking_group: String
  max_same_group_active: int
  meridian_load: number | null
  meridian_capacity_cost: number | null
  load_type: String | null
  medicine_capacity_used: number | null
  conflict_group: String | null
  modifier_exports: Array
  tick_outputs: Array
  tags: Array
  created_world_day: int
  created_world_hour: int
  last_settled_world_hour: int | null
  resolved_reason: String | null
  log_refs: Array
}
```

字段说明：

1. `state_id` 是持续状态实例身份，不等同于物品、法宝或事件 ID。
2. `source_ref` 必须能追溯到创建它的物品使用、事件结果、战斗结果、突破结果或环境暴露。
3. `modifier_exports` 只描述当前状态导出的后天临时修正，不保存角色属性事实值。
4. `meridian_load`、`meridian_capacity_cost` 与 `load_type` 用于体内药性、外源灌注或刺激型资源状态占用经脉承载；非相关状态可为空。
5. `medicine_capacity_used` 表达体内药性占用的药性容量，供丹药消化、体魄承载和风险提示读取；它不是当前大境界纯度或法力来源。
6. `tick_outputs` 描述本状态对生机、元气、神念当前值、行动限制、日志或事件标签的结算输出。
7. `resolved_reason` 记录到期、治愈、驱散、覆盖、转化、死亡、事件结束等终止原因。

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示：

1. 对玩家决策有影响的当前持续状态摘要。
2. 伤势、体内药性、残余药性、护盾、封禁、心魔、环境侵蚀和重要祝福 / 诅咒。
3. 主要来源、剩余时间或解除条件。
4. 对修炼、战斗、移动、突破或资源使用的可理解影响。
5. 可处理方式，例如休整、治疗、驱散、继续吐纳 / 闭关承接药性、巩固修为或离开危险环境。

普通 UI 不应展示：

1. 内部状态 ID。
2. 原始叠加组、冲突组、优先级和公式缓存。
3. 未揭示隐藏状态的完整真相。
4. C1 追赶内部 tick 明细。
5. Debug 专用导出字段和调参系数。

## 9. MVP 范围

MVP 应实现：

1. 统一 `CharacterOngoingState` 状态实例。
2. 伤势、体内药性、残余药性、符箓持续效果、法宝临时效果和事件结果状态的统一承接。
3. 状态来源、生命周期、剩余时长 / 剩余额度、显隐、叠加组、互斥组和日志引用。
4. 状态通过 `acquired_modifiers` 导出临时后天修正。
5. 状态对生机、元气、神念当前值的 tick 输出。
6. 状态到期、治疗、驱散、覆盖和转化。
7. 角色页面可见状态摘要和 Debug 边界。
8. C1 追赶只补结算确定性状态时钟，不重新随机效果。

MVP 不实现：

1. 完整疾病生态、复杂毒理、长期丹毒或杂质累计系统。
2. 所有状态之间的复杂化学反应式组合。
3. 无限层级状态嵌套。
4. 通过持续状态改写灵根先天结构。
5. 由角色属性文档保存独立伤势状态字段。
6. 用永久持续状态替代后天永久修正或寿元来源记录。

## 10. 验收约束

1. 伤势、道伤、心魔、药性、符箓持续效果、法宝触发态和事件持续结果不得作为角色属性分层维护。
2. 任一挂在角色身上的持续状态都必须能追溯来源、生命周期和日志。
3. 持续状态影响属性有效值时，必须通过后天修正接口导出，不得直接改写属性事实字段。
4. 状态失效后，其导出的临时修正和行动限制必须同步停止。
5. 永久属性改变、寿元改变和死亡 / 转世结果必须由对应系统结果写入，不得由一个未结束状态静默承担。
6. 丹药、符箓、法宝和事件不能各自维护互不兼容的角色持续状态私有结构。
7. 普通 UI 必须能说明重要持续状态的来源、影响方向和可处理方式。
