# 系统设计｜世界凭空产出

## 1. 设计定位

世界凭空产出负责回答事件、宝藏、NPC 掉落、秘境奖励、隐藏资源和阶段投放如何从“尚未显性入库的世界内容”实例化为可追踪资产。

“凭空产出”不等于无约束刷物品。本文只维护生成入口、预算扣除、来源语境、入库边界和资产追踪要求；不维护完整投放数值、奖励模板、物品对象定义、交易价格、库存底层字段或页面布局。

灵石、低阶货币与聚灵石的对象定义、价值口径、加工和资源输入边界统一见《灵石及聚灵石》（`../05_物品设计/05_灵石及聚灵石.md`）。本文只处理它们作为奖励、预算扣除、事件锁定资产或库存流转对象时的生成约束。

## 2. 当前结论

1. 事件、宝藏、NPC 掉落、秘境奖励等隐性或实例化内容，必须受分阶生成预算和来源语境约束。
2. 生成预算用于控制世界投放，不是玩家可见资源，也不是资产回收池。
3. 一旦物品由事件、宝藏或隐性状态实例化，就按物品完整预算价值扣除生成预算；后续出售、拆解、损坏、销毁、上交或封存不返还预算。
4. 暂不可领取的生成结果应先进入事件锁定库存，不应直接伪装成行囊物品。
5. 后手、遗产和无主遗留设施优先按已有资产流转处理，不应被误写成新资产生成。

## 4. 核心循环或触发入口

世界凭空产出的常规循环：

```text
系统触发奖励或隐性资产实例化
→ 确认 source_system、generation_context 和可见性
→ 读取 tier_budget_ref 与 reward_profile_ref
→ 生成资产或失败原因
→ 扣除 budget_value_spent
→ 写入目标库存或 event_locked
→ 写入资产流水
```

主要触发入口：

1. 随机事件、奇遇、任务、秘境、宝藏、遗迹、洞府探索或节点隐藏层开启。
2. NPC 死亡、战利品结算、搜刮、清点、宗门回收或势力接管。
3. 世界阶段预算激活后，将资源机会投放到事件、NPC 资产、市场、节点或宗门库存。
4. 宝藏、普通藏宝、真灵藏宝、遗产和无主遗留设施被发现、开启或取出。
5. 奖励暂不可领取时，先进入事件锁定库存，待条件满足后再转移。

## 5. 规则与状态

### 5.1 生成预算规则

经济系统需要同时维护两类资产变化：

1. 库存流转：已经显性存在的资源和物品在容器之间移动，底层见《库存系统》（`../06_储物空间系统设计/03_库存系统.md`）。
2. 生成预算：事件、宝藏、NPC 掉落、秘境奖励等“凭空生成”内容受分阶预算帽约束。

规则：

1. 一旦物品由事件、宝藏或隐性状态实例化，就按物品完整预算价值扣除生成预算。
2. 后续出售、拆解、损坏、销毁、上交、封存或回收，不返还生成预算。
3. 生成预算用于控制世界投放，不是玩家可见资源，也不是资产回收池。
4. 若生成结果暂不可领取，应先进入事件锁定库存，不应直接伪装成行囊物品。
5. 生成预算扣除必须能追溯到来源系统、奖励模板、阶段预算和资产流水。

### 5.2 资产生成请求

资产生成应由显式请求表达：

```yaml
AssetGenerationRequest:
  source_system: string
  generation_context: object
  tier_budget_ref: string
  reward_profile_ref: string
  target_container_ref: string | null
  event_locked_first: bool
  visibility: string

AssetGenerationResult:
  success: bool
  generated_assets: list
  budget_value_spent: number
  target_container_ref: string
  ledger_entry: string
  failure_reason: string | null
```

请求规则：

1. `source_system` 必须说明生成入口，例如事件、秘境、NPC 掉落、宝藏或阶段投放。
2. `generation_context` 记录地点、角色、节点、事件状态、权限和风险语境。
3. `tier_budget_ref` 和 `reward_profile_ref` 指向数值层，不在本文维护具体点数和奖励表。
4. `target_container_ref` 为空或 `event_locked_first` 为 true 时，结果应先写入事件锁定库存。
5. 失败时不得生成半成品资产，除非 RewardProfile 明确允许部分成功并记录剩余失败原因。

### 5.3 后手、遗产与无主遗留设施

正式后手不是凭空生成，而是显性物品储存、封存、跨世追踪。MVP 阶段正式后手以真灵藏宝表达，由同一真灵跨世感应和开启，且受设置数量和单个容量限制。

遗产也不是生成预算返还。遗产是仍有原持有人、需要分配、继承、清点或回收的资产；典型对象是 NPC 死亡后的随身物品、NPC 洞府库存、玩家角色转世前留在宗门管辖个人洞府中的普通库存，以及宗门托管 / 职务资产。玩家角色转世前留下的宗门个人洞府库存，按宗门相关遗产规则清点并回收宗门。

宗门外个人洞府和普通藏宝是无主遗留设施，不进入遗产分配、继承或回收，也不会因为转世自动进入宗门库存或新世行囊。它们需要满足钥匙、功法、线索、位置、事件条件或破阵结果后才能进入 / 取出，可能被其他角色提前打开。这类开启只移动已有资产，不凭空生成物品。真灵藏宝作为正式后手处理，也不进入遗产分配、继承或回收。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 投放数值 | 读取阶段预算、RewardProfile、预算价值和投放渠道 |
| 库存系统 | 写入 `event_locked`、目标库存、资产流水、物品堆叠或独立实例 |
| 物品系统 | 按奖励模板实例化物品、资源、灵石、聚灵石或高价值资产 |
| 随机事件 | 提供事件状态、领取条件、可见性、失败原因和后续分支 |
| 地图节点 | 提供节点、隐藏层、宝藏、秘境、遗迹或资源机会的地点语境 |
| NPC / AI | 提供掉落、随身资产、洞府库存、遗产清点和持久化资产边界 |
| 宗门系统 | 承接宗门回收、战利品分配、宗门库存、职务资产和权限判断 |
| 交易系统 | 承接生成后资产的出售、挂牌、估价和市场流转，不返还生成预算 |
| 后手系统 | 承接真灵藏宝、普通藏宝、个人洞府库存和无主遗留设施的已有资产移动 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `asset_generation_id` | 单次资产生成请求或结果身份 |
| `source_system` | 生成来源系统，例如事件、秘境、NPC 掉落、宝藏或阶段投放 |
| `generation_context` | 地点、角色、节点、事件、权限、风险和可见性语境 |
| `tier_budget_ref` | 分阶预算引用，指向数值层预算池 |
| `reward_profile_ref` | 奖励模板引用，指向数值层或配置层 |
| `budget_value_spent` | 本次实例化扣除的预算价值 |
| `generated_assets` | 已生成资产、物品堆叠、物品实例或资源引用 |
| `target_container_ref` | 生成结果写入的库存容器；暂不可领取时指向事件锁定库存 |
| `event_locked_first` | 是否先进入事件锁定资产 |
| `visibility` | 玩家、队友、宗门、NPC 或 Debug 可见性 |
| `ledger_entry` | 对应资产流水、预算扣除和后续审计记录 |
| `failure_reason` | 生成失败、预算不足、条件不足或部分成功原因 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示：

1. 奖励、宝藏、战利品或事件锁定资产是否可领取。
2. 资产当前位于行囊、节点库存、宗门库存、事件锁定库存、藏宝或其他合法容器。
3. 玩家可理解的不可领取原因，例如事件未完成、权限不足、容器不可达、开启条件不足或遗留设施被占用。
4. 真灵藏宝、普通藏宝、遗产和无主遗留设施的业务差异，避免玩家误以为所有前世资产都会自动继承。

普通 UI 不展示：

1. 原始预算池点数、RewardProfile 权重、随机种子和完整掉落表。
2. Debug 用预算 ID、生成批次 ID、内部物品查询条件和完整概率追踪。
3. 尚未揭示的隐藏宝藏、秘境奖励、NPC 持有资产或后续事件分支。

## 9. MVP 范围

MVP 应实现：

1. 事件、宝藏、NPC 掉落和秘境奖励统一通过资产生成请求实例化。
2. 生成结果扣除预算价值，并写入目标库存或事件锁定库存。
3. 出售、拆解、损坏、销毁、上交、封存或回收不返还生成预算。
4. 真灵藏宝、普通藏宝、遗产和无主遗留设施按已有资产流转处理，不作为新资产生成。
5. 生成、领取、失败和转移都写入资产流水。

MVP 不实现：

1. 各阶预算点数完整表。
2. RewardProfile、宝藏、秘境和 NPC 掉落的完整模板库。
3. 复杂多人可见性、争夺结算和长期世界资产再平衡。
4. 预算回溯图谱、完整概率审计和高级 Debug 面板。

## 10. 验收约束

1. 任何凭空实例化资产都必须有来源系统、来源语境、预算引用、奖励模板和资产流水。
2. 预算扣除不得因为资产后续出售、拆解、损坏、销毁、上交、封存或回收而返还。
3. 暂不可领取的奖励不得直接进入角色行囊，必须进入事件锁定库存或等价容器。
4. 后手、遗产和无主遗留设施中的已有资产不得重复按新奖励生成。
5. 灵石、低阶货币与聚灵石不得在本文重定义对象、价值或加工口径。
6. 普通 UI 不得暴露未揭示奖励、完整掉落概率或内部预算池。
