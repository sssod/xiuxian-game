# 角色、真灵、轮回与修炼养成（v2.2）

## 0. 文档定位

本文整理玩家主体、当世角色、真灵、执念、修为、功法、寿元、突破前置、死亡与转世的开发口径。

新版重点修订：

- 修炼、研习、突破等行动不再消耗“行动格”，而是占用回合时间预算。
- 主动吐纳、研习功法等属于可选投入执行时间持续行动。
- 大境界突破属于固定执行时间持续行动 + 专用事件链。
- 自动运转按小时级内部结算，但不能代替主动修炼行动。
- 功法系统收敛为完整载体学习 + 掌握度成长；残页 / 篇章用于合成与获取线索，不作为可学习进度。
- 丹药、灵材、符箓和临时增益资源统一作为行动资源输入项，不再把“丹药炼化”作为 MVP 独立持续行动。

---

## 1. 三层角色模型

玩家主体分为三层：

```text
真灵：跨世延续的玩家主体。
执念：转世初始化时可携带的少量遗留包。
身躯与灵魂：当前世实际行动、成长、承受后果的角色实例。
```

判断标准：

- 必须永久跨世存在 → 真灵。
- 只用于下一世初始化选择 → 执念。
- 只在当前生命中存在并承担行动后果 → 身躯与灵魂。

---

## 2. 真灵

### 2.1 定位

真灵提供长期身份感、执念容量、正式后手容量和轮回履历。真灵不是数值外挂，不应直接稳定提高每世修炼效率。

### 2.2 最小数据

```text
TrueSpirit {
  spirit_id: String,
  true_name: String,
  spirit_strength: int,
  true_name_visibility: String,  # hidden / declared / exposed
  incarnation_count: int,
  highest_stage_reached: String,
  dao_rhyme_tags: Array,
  obsession_capacity: int,
  formal_contingency_slots: int,
  reincarnation_ledger_refs: Array
}
```

### 2.3 真名可见性

```text
hidden：默认隐藏，只有玩家自己可见。
declared：玩家主动归本溯源，宣告真名。
exposed：因重大事件、突破、旧怨、后手争夺等被动暴露。
```

真名暴露会带来优势与风险：

- 优势：可调用真名层面的深层力量或高阶事件入口。
- 风险：更容易被高阶存在、旧怨、其他玩家、后手争夺链识别。

---

## 3. 执念

执念是下一世初始化遗留包，不等于完整前世记忆或完整人格继承。

执念可携带：

- 天赋标签。
- 出生背景倾向。
- 少量开局资源或线索。
- 特殊开局条件。
- 某些前世失败标签的修正方向。

容量采用权重制：

```text
ObsessionLoadout {
  spirit_id: String,
  capacity_limit: int,
  selected_entries: Array,
  used_weight: int
}
```

玩家选择的遗留总权重不得超过容量上限。

## 5. 属性与状态条

### 5.1 基础属性

| 显示名 | 内部字段 | 作用 |
|---|---|---|
| 体魄 | `base_physique` | 生机上限、负伤承受、肉身类突破准备 |
| 精力 | `base_vigor` | 元气底子、持续行动承受、疲劳恢复 |

基础属性只保留当世身躯 / 状态底子的基础字段，不包含可评级资质子项。

### 5.2 资质子项

“资质”不是独立总等级，不设置总资质等级参与核心判定。

可评级子项：

- 根骨：`aptitude_bone`，身体承载、修炼基础、部分突破准备。
- 悟性：`aptitude_comprehension`，功法理解、配方学习、技艺成长。
- 灵根：`aptitude_root`，灵气亲和、路线适配、功法门槛。
- 灵根相性：`root_affinity_tags` / `root_affinity_profile`，表达木、火、水、风、雷、阴阳等路线或资源相性，不替代 `aptitude_root` 的基础评级。

`base_comprehension` 弃用，开发实现不得将“悟性”放入 `BaseAttributes` 或使用 `base_` 前缀表达。

### 5.3 派生状态条

| 显示名 | 内部字段 | 含义 |
|---|---|---|
| 生机 | `bar_vitality` | 健康、伤病、肉身完整度 |
| 元气 | `bar_qi` | 法力 / 气力 / 可支配能量 |
| 神念 | `bar_mind` | 神识、心神、灵魂稳定 |

生机、元气、神念是持久状态，不是战斗内临时资源。战斗结束后不自动回满。

## 6. 修为状态

```text
CultivationState {
  current_stage_code: String,       # A-1 / A-2 / B-1
  cultivation_progress: float,
  cultivation_purity: float,
  purity_visibility_state: String,  # hidden / visible_at_major_bottleneck
  bottleneck_state: String,         # none / soft_cap / breakthrough_required
  main_dao_method_ref: String,
  major_method_record_refs: Dictionary,
  progress_cap_context: Dictionary
}
```

### 6.1 修为纯度

- 数据层保留。
- 平时默认隐藏。
- 到达大阶段瓶颈、进入突破准备语境后显示。
- 显示时必须提示提纯 / 巩固路径。

## 7. 道功与法门

### 7.1 道功

道功是可推动修为增长的功法，可设为主修。

```text
DaoMethod {
  method_id: String,
  tier_code: String,
  quality_code: String,
  method_tags: Array,
  theoretical_max_cap_stage: String,
  mastery_cap_profile: Dictionary,
  absorption_profile: Dictionary,
  conversion_profile: Dictionary,
  resource_affinity_profile: Dictionary,
  purity_profile: Dictionary,
  passive_effect_refs: Array,
  breakthrough_transition_support: Dictionary,
  compatibility_requirements: Dictionary
}
```

字段口径：

| 字段 | 含义 |
|---|---|
| `theoretical_max_cap_stage` | 道功完整传承在规则层可支持的理论最高阶段，不随掌握度提高 |
| `mastery_cap_profile` | 掌握度对当前有效可修上限、单位时间收益和能力解锁的影响 |
| `resource_affinity_profile` | 与灵根、节点灵气、丹药 / 灵材输入的相性 |
| `purity_profile` | 道功路线自身的修为纯度倾向，不由掌握度直接改变 |
| `breakthrough_transition_support` | 大境界突破模板、风险标签与承载要求的读取入口 |

道功掌握度可以提高当前有效上限和单位时间收益，但不提高理论最高上限，不改变突破模板类型，不直接提高修为纯度收益或小境界升级奖励质量。

### 7.2 法门

法门不直接推动修为进度。它提供：

- 战斗指令。
- 非战斗能力。
- 采集、炼丹、炼器、阵法、医术、卜算等技艺。
- 事件选项。
- 资源获取效率修正。

### 7.3 主修道功

规则：

- 同一时间只能有一个主修道功。
- 只有道功能被设为主修。
- 主修道功决定被动吸收、主动吐纳、行动资源输入适配、修为上限和突破模板匹配。
- 主修道功只允许在大境界第一小阶段内无时间预算成本替换，例如 A-1 / B-1 / C-1。
- 离开第一小阶段后，本大境界主修路线锁定。
- 每个大境界记录最终主修道功，用于突破模板、奖励结构和失败标签池。
- 不因为道功自然上限、获得同传承后续道功或玩家后悔选择而开放免费续接换功。
- MVP 不做废功重修、改修折算、中途换主修惩罚和免费续接换功。

UI 需要在主修详情和更换界面常驻提示：

```text
当前处于 B-1，仍可无时间成本更换本大境界主修道功。
当修为推进至 B-2 后，本大境界主修道功将锁定，直至进入 C-1。
```

## 8. 修炼收益来源

### 8.1 自动运转

自动运转用于表现修士日常吐纳，但不能替代主动修炼行动。

规则：

- 按小时级内部结算。
- 主动吐纳期间自动运转不额外叠加。
- 突破、昏迷、重伤、封印等状态下不生效。
- 合法状态下可提供少量被动修为收益。
- 可触发小境界升级。
- 不可跨越大境界瓶颈。
- 不自动消耗高价值丹药或突破资源。

### 8.2 主动吐纳

主动吐纳是核心修为增长持续行动，属于：

```text
duration_mode = variable_investment
```

读取：

- 实际投入小时数。
- 当前节点灵气。
- 主修道功吸收速度。
- 主修道功转化效率。
- 可选行动资源输入项。
- 角色资质。
- 当前状态和伤势。
- 修为阶段与瓶颈。

主动吐纳可以使用：

```text
投入 N 天
或
投入本回合剩余时间
```

事件延误后，按实际投入时间结算。

修为丹药只允许作为主动吐纳的额外资源输入。丹药自身提供定额灵气包，进入主动吐纳结算中的 `resource_aura_input`，不再读取主修道功的背景吸收速度，但仍受行动实际兼容小时、丹药品质、状态修正、经脉压力和资源相性影响。

### 8.3 行动资源输入项

丹药、灵材、符箓和临时增益资源不优先设计为独立持续行动，而是挂载到对应行动或事件选项上。

典型映射：

| 资源 | 默认挂载语境 |
|---|---|
| 修为丹药 | 主动吐纳 |
| 临时悟性丹 | 研习功法 |
| 解毒丹 / 避瘴丹 | 毒瘴区域移动、探索、采集、战斗语境 |
| 疗伤丹 | 休整 / 治疗 / 医疗事件选项 |
| 定心丹 | 巩固根基、突破准备、突破事件链选项、研习功法 |

资源效果总量按以下基础模型结算：

```text
资源效果总量 = 单位增量 × 最大有效时长
本次应用效果 = 单位增量 × 实际兼容小时 × 品质修正 × 状态修正
```

MVP 规则：

- 不设计独立持续行动：丹药炼化。
- 不允许即时服用修为丹药后直接增加修为。
- 不允许丹药绕过回合时间预算产生收益。
- 行动未实际开始时，不消耗已绑定资源。
- 行动已开始但资源效果未完全用完时，剩余效果进入 `ActiveResourceEffect`。
- 同一行动中，同一效果通道最多使用 1 个主资源输入。
- 巩固根基可以选择性收束残余修为药性，但收束不产生修为进度。
- 常规 MVP 不投放 `forced_release` 强制释放型修为丹药，只预留字段和事件链分支。

### 8.4 研习功法

研习功法属于：

```text
duration_mode = variable_investment
```

读取：

- 实际投入小时数。
- 悟性 `aptitude_comprehension`。
- 功法阶级与品级。
- 是否有导师、宗门设施、相关法门基础。
- 当前状态与神念稳定度。
- 可选悟性 / 定心类资源输入项。

学习与研习口径：

- 只有完整功法载体可学习并生成 `MethodState`。
- 残页和篇章用于合成、线索、权限、任务或内容投放，不生成可学习进度字段。
- 研习功法提高掌握度、功法经验、当前有效上限、单位时间收益或法门能力解锁。
- 道功掌握度收益应可追回，不制造阶段性永久错过收益。

## 9. 小境界与大境界突破

### 9.1 小境界升级

小境界升级是阶段内成长节点，不进入高风险突破链。

不做：

- 不消耗关键突破物。
- 不进入突破事件链。
- 不触发死亡 / 转世。
- 不生成复杂外部干扰。
- 不需要挑战交锋格。

可以做：

- 弹出轻量提示。
- 更新阶段编码。
- 增加少量派生属性或解锁功法效果。
- 写入角色日志。
- 读取主修道功当前有效上限判断是否允许推进。
- 不在升级关口插入“是否继续以当前主修修炼”的确认事件；主修锁定风险由常驻 UI 提前提示。

### 9.2 大境界突破

大境界突破必须满足：

1. 玩家主动发起。
2. 至少消耗一个关键突破物。
3. 属于固定执行时间持续行动。
4. 进入事件链后不可回头补准备。
5. 结果可能改变本世路线、宗门地位、轮回账本和下一世规划。

大境界突破模板建议：

```text
BreakthroughActionTemplate {
  template_id: String,
  required_stage_code: String,
  target_stage_code: String,
  fixed_required_hours: int,
  key_item_requirements: Array,
  location_requirements: Dictionary,
  support_requirements: Dictionary,
  event_chain_template_ref: String,
  interruption_policy: String
}
```

## 10. 连续行动状态

长期修炼、闭关、炼丹、研习、赶路、探索等可以跨回合延续。

```text
ContinuousActionState {
  state_id: String,
  character_id: String,
  action_type: String,
  action_template_id: String,
  node_id: String,
  route_state: Dictionary,
  started_turn_id: int,
  started_world_hour: int,
  accumulated_hours: int,
  required_hours: int,
  progress: float,
  compatible_followup_actions: Array,
  interruption_rules: Dictionary,
  overflow_policy: String,
  risk_tags: Array
}
```

规则：

- 下回合开始时，系统应提示“延续上一回合行动”。
- 安全、低风险、无重大分支的连续行动可由托管自动延续。
- 高风险突破、后手回收、高危秘境等不得由托管主动延续到不可逆选择。

## 11. 寿元与死亡

MVP 至少保留：

- 年龄与寿元上限。
- 突破延寿。
- 寿元压力提示。
- 死亡 / 转世事件链入口。

寿元压力建议状态：

```text
safe / pressured / urgent / exhausted
```

死亡后：

- 当世角色终结。
- 普通遗产留在世界中，可能被转移或破坏。
- 正式后手按规则保留，并写入轮回账本。
- 真灵进入转世初始化流程。
