# MVP 框架缺口与阶段门

适用范围：判断飞升胜利主题在设计配置与未来开发计划前，各大模块的规则裁决、正式配表、内容生产和多人韧性状态。这里的“关闭”只表示设计门满足，不解除开发冻结。

## 1. 当前判断

本包已经能够解释从大厅开局、炼气起步、跑图占地、获取资源、自动修炼 / 研习、五次突破、渡劫、转世、掉线退出到大乘飞升或全体一致共同中止的主要状态流。

`P0-A` 多人韧性与主动结束、`P0-B` 境界进度 / 修为强度 / 改修、`P0-C` 统一总护盾和 `EXIT-01` 基础退出归属已经关闭。仍不能直接进入开发：专属追赶、外交、动态关隘障碍及内容依赖的局部合同尚未关闭或明确延期；首张地图、正式价格和属性、功法 / 物品 / 敌人 / 事件内容表及全局验算尚未完成。

## 3. 本轮已经关闭的 P0 规则门

### P0-A 多人韧性与主动结束｜关闭

- 目标席位 `2—4`；满员、宗门唯一、全员准备后 `10` 秒自动开局；
- `60 / 90 / 45 / 30` 秒基础时限，每人 `180` 秒整局思考储备；
- 锁定前可撤回、全员完成后 `3` 秒收束、未响应采用无消费安全默认；
- 单次 / 整局断线保护 `60 / 180` 秒，保护耗尽后进入 MVP 无策略托管；
- 连续掉线 `10` 分钟永久失去重连资格，稳定连接 `30` 秒才清零累计；
- 主动退出与强制退出都只在最近一次合法回合开始即时阶段第一步实际退隐；
- 全员离线时世界冻结，最后一个席位失去重连资格后直接共同中止；
- 主动结束要求全部未退隐玩家亲自一致同意，并以全局暂停、`30` 秒表决和 `3` 秒撤回缓冲执行。

平台会话保存时长属于未来产品配置；策略 AI 属于未来单人模式方向，不重新打开 MVP 基础规则。

### P0-B 境界进度、修为强度与改修｜关闭

```text
标准 CP：境界进度唯一来源
实际灵气吸收效率 = α_template × M_dao × 其它明确吸收修正
修为强度 = (S0 + S_total) × β_template × M_dao + 合法修正
```

普通改修不扣标准 CP，也不改变小境界、大境界或历史记录；当前主修重算本世完整累计量。节点、丹药等效灵气和直接标准 CP 奖励分流；每单位先修炼、处理阈值 / 瓶颈，再研习；统一按 `0.01` 标准 CP 精度写入。道功与法门共用掌握，同一知识来源在单条效果链只读取一次。

`S0 / 1A / 境界 CP / α_template / β_template / C_template / 战斗常数` 未填属于正式配置门，不表示基础规则开放。

### P0-C 统一总护盾｜关闭

- 所有普通与护劫护盾写入一个总值，整场持续；
- 总上限为开战最大生命 `100%`，普通每次生成上限为 `50%`；
- 护劫先于其它开战护盾生成，可超过普通单次上限但仍计入总上限；
- 来源只写日志，溢出作废，不保存余额、时间、刷新或消耗顺序；
- 通用增减伤后先扣总护盾，剩余伤害进入体魄减伤；
- 战中最大生命变化不追溯修改上限，战后与连续战斗下一场重置。

招式护盾量、冷却、成本、Buff、五档最终比例和四场敌人属于正式战斗配置。

### EXIT-01 基础退出与地产归属｜关闭

退隐使角色和个人数值停止维护，随身资产系统回收，退隐本身不产生死亡掉落；地产保留为退隐宗门地产，稳定供养作废，费用由系统回收。只有以后由正式游戏规则合法易主后才按新归属结算。具体易主事件仍属于 `CATCHUP-01` / 内容门。

## 4. 真正仍会改变规则的 P0 门

### 4.1 `CATCHUP-01`｜专属追赶与节点易主事件

需决定 MVP 是否在全图灵气增长、历史突破自动跨越和转世灵石下限之外，再制作只对落后者开放的追赶；若制作，还需定义落后判定、效果类型、持续、叠加及是否允许取得退隐宗门地产。若延期，必须验证现有自然追赶足以完成对局。

### 4.2 `DIPLOMACY-01`｜普通关系、仇敌与盟友范围

需决定主动宣战 / 解除是否进入 MVP，补全时点、成本、持续、公开和对相遇 / PVP / 收费 / 关隘 / 飞升阻拦的效果；或明确延期半套外交入口。首轮盟友目前只有“无免租 / 折扣”的边界，仍需决定是否完全延期。

### 4.3 `GATE-01`｜动态关隘障碍范围

需决定 MVP 只保留固定收费关隘，还是允许玩家设置临时路线障碍。若允许，必须补全入口、成本、持续、叠加、上限、绕行 / 解除 / 强行突破和与仇敌 / 飞升阻拦的关系；若延期，应从首图内容表移除动态障碍字段。

### 4.4 内容依赖的局部合同

| 项目 | 当前边界 | 关闭方式 |
| --- | --- | --- |
| 通用竞价合同 | 无主地产暗标已完整；其它事件可以调用战斗或竞价 | 每个实际调用事件填写支付、最低出价、败方支付与平价；若不调用则明确延期 |
| 同层世界结算顺序 | 内容不得利用隐式先后获利 | 内容表完成后列真实依赖；无依赖时验收声明无需额外顺序表 |
| 强制事件安全默认 | 每个必须选择的模板都需要无消费、低风险默认 | 逐模板填写，缺默认不得进入 MVP |
| 普通事件禁逃 | 通用默认允许，事件可显式禁止；渡劫允许 | 首批事件逐项标注，不建立隐式黑名单 |
| 退隐地产合法易主 | 退出本身不重置地产 | 若制作此类事件，与 `CATCHUP-01` 同时裁决；否则只保留接口 |

## 5. 正式配置与内容门

这些项目多数不再需要重开框架裁决，但缺表时仍不能形成可配置 MVP。

### 5.1 地图与地产内容

- 固定地图坐标、连接和 `2 / 3 / 4` 人座位组合；
- 三类经营节点、不可购地点、固定关隘、洞府和飞升地点；
- 节点标价、灵气、建筑类型、等级上限、逐级成本、收益、收费、目录与容量；
- 四出生区域的首枚筑基丹路径、双路线和基础经济等价验算；
- 退隐宗门地产在地图与费用日志中的表现。

### 5.2 五宗门、经济与物品内容

- 五宗门名称、题材、临时英文、初始功法、特色资源和等价预算；
- 资源、商品、配方、丹药、法宝和功法载体清单；
- 停留 / 功能 / 过路费、生产投入、价格与回收期；
- 逐物品成熟开关、默认 `1.5` 例外、完整 `Q1—Q5` 权重和三次取高模板；
- 宗门贡献白名单、固定贡献值、兑换目录与最终成本。

### 5.3 成长、功法与移动内容

- `S0 / 1A`、五境总 CP、属性、状态、恢复、寿元与 `G-23`；
- 各品级道功 `α_template / β_template / C_template` 预算与具体模板；
- 六境移动骰池、法门分布、法宝加成及元气 / 灵石 / 耐久成本；
- 五宗门初始功法、三套高阶路线、研习标签和 `72` 项阈值内容；
- 通用高阶功法第 `9—10` 回合投放、低掌握改修和同源字段检查。

### 5.4 战斗、敌人与奖励内容

- `C1`、`C2`、`C3(g)`、各档 `K1_ref`；
- 招式冷却、成本、`K1/K2/D/K3`、护盾和 Buff；
- 普通、重点、洞府入口和飞升前置敌人；
- 四场固定渡劫的标准构筑与 `Q3` 单次 `70%—80%` 样本胜率；
- 统一总护盾在周期生成、总上限、穿盾伤害和连续战斗重置下的验算。

## 6. P1 表达与验证门

P0 规则范围与正式内容表完成后，再集中处理：

1. 从开局到第 `20 / 24 / 28` 回合飞升的逐回合资源、状态与行动验算；
2. 吸灵 / 凝练 / 高品级道功、瓶颈、小洞天、渡劫失败、死亡与转世路径；
3. 地产扩张、生产、贡献和物品成熟的全链经济回归；
4. `2 / 3 / 4` 人地图、竞争、同轮飞升和退出后的续局；
5. 未提交、掉线、重连、托管、连续掉线退隐、全员离线和结束表决；
6. 主棋盘、角色资产、功法研习、战斗和结果页的信息架构；
7. 错误、费用变化、安全默认、溢出与系统回收提示；
8. 简体中文 / 英文术语、玩家文本占位和本地化长度检查；
9. `G-23` 等取整规则和完整数值回归。

节点级布局、视觉样式和动效仍由未来当前 UI artifact / Figma 承接，不写入稳定玩法规则。

## 8. 未来进入开发计划的最小验收

只有同时满足下列条件，且用户明确解除开发冻结，才可制定 MVP 开发计划：

1. 所有会改变规则的 P0 门关闭，或用户明确写出首轮延期范围；
2. 首张地图、初始状态、主要行动、经济、敌人和内容清单可以直接配置；
3. 一局从开局到飞升的状态、资源、地产和异常路径可逐回合解释；
4. 死亡、重伤、逃遁、平局、渡劫失败、未提交、掉线、退出与主动结束都有闭环；
5. 所有必填常数与内容字段有唯一归属，不存在实现层默认；
6. 本包不依赖旧正式包、草案、handoff 或对话才能解释规则；
7. 交互文档可以说明稳定信息与操作流，节点布局留给 Figma；
8. 包内链接、旧术语、阶段门状态和维护记录通过审计。
