# 个人洞府库存、藏宝与后手系统设计

## 1. 当前结论

个人洞府库存、藏宝库存和后手库存都属于非随身库存，不是行囊。

个人洞府需要明确为一种设施类型，设施类别可记为 `personal_cave` 或宗门批量形态 `personal_cave_complex`。它可以提供居住、闭关、储物、防护、隐蔽、空间关联和阵法承载能力。个人洞府库存是绑定在洞府设施上的资产容器。

库存底层字段、资产容器、权限策略、预留锁定和资产流水统一见《06_储物空间系统设计/03_库存系统》。本页只定义个人洞府、藏宝和真灵藏宝的业务差异。

藏宝可以视为特化的个人洞府，也可以记为 `treasure_cache` 类设施化记录。它具备与洞府一致的隐蔽、防御、维持消耗、储物空间、关联空间、解锁条件和附加阵法槽位，但核心功能是储物。藏宝中的物品取出是一次性的。

正式后手在 MVP 阶段按“真灵藏宝”处理。真灵藏宝不是资源槽设施，不读取资源槽灵气，不承担资源槽占用带来的普通暴露风险，也不能把洞天福地或任何 `blessed_land` 资源槽当作封存点。它只能附着在节点隐藏层，具有独立隐蔽属性和真灵解锁条件，可由同一真灵的后世角色跨世直接感应和开启，但受设置数量和单个容量限制。

玩家角色转世前留下的个人洞府进入前世资产处理流程。其中，宗门管辖内的个人洞府库存按遗产清点，和 NPC 死亡后的宗门相关遗产使用同一套规则回收宗门；宗门外个人洞府和普通藏宝作为无主遗留设施，必须满足开启条件、持有钥匙、掌握特定功法或强行解除阵法后才能进入或取出；真灵藏宝作为正式后手处理。

本页使用的“遗产”有明确边界：遗产是仍能追溯到原持有人、并且需要在死亡、转世、失踪、资格丧失或组织接管后进行分配、继承、清点或回收的有主资产。典型对象是 NPC 死亡后的随身物品、NPC 个人洞府库存、玩家转世前留在宗门管辖个人洞府中的普通库存，以及宗门托管 / 职务资产的归还或接管。宗门外个人洞府、普通藏宝、失落库存、旧洞府线索等无主或失主遗留地点，不是遗产；它们按 `RemnantSiteRecord` 或等价遗留设施记录处理。

## 2. 基础概念

### 2.1 个人洞府

个人洞府是可归属角色的设施，不是角色行囊，也不是纯 UI 分类。

个人洞府至少应能表达：

```yaml
PersonalCaveFacility:
  cave_id: string
  cave_type: sect_assigned | self_built_outside_sect
  owner_character_id: string
  location_node_id: string
  attachment_mode: natural_resource_slot | hidden_layer
  location_resource_slot_id: string | null
  location_hidden_layer_id: string | null
  controlling_faction_ref: string | null
  concealment_rating: number
  concealment_modifier_from_attachment: number
  defense_rating: number
  resource_aura_benefit_policy: inherit_slot_aura | none
  upkeep_rule: object
  storage_container_id: string
  linked_space_refs: list
  unlock_condition: object
  formation_slot_refs: list
  blocks_resource_slot_facility_construction: bool
  status: active | locked | abandoned | exposed | damaged | depleted
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `cave_type` | 洞府类型，区分宗门分配和山门外自辟 |
| `owner_character_id` | 当前洞府主人 |
| `location_node_id` | 洞府所在地图节点 |
| `attachment_mode` | 洞府附着方式；只能是自然资源槽或节点隐藏层 |
| `location_resource_slot_id` | 当洞府附着在自然资源槽时记录资源槽；未附着资源槽时为空 |
| `location_hidden_layer_id` | 当洞府附着在隐藏层时记录隐藏层；未附着隐藏层时为空 |
| `controlling_faction_ref` | 宗门或其他势力的管辖关系；无管辖时为空 |
| `concealment_rating` | 隐蔽程度，影响被发现、清查或感应难度 |
| `concealment_modifier_from_attachment` | 附着方式造成的隐蔽修正；自然资源槽落点通常降低隐蔽，隐藏层落点通常不受该惩罚 |
| `defense_rating` | 防御强度，影响突破、争夺或损毁风险 |
| `resource_aura_benefit_policy` | 是否读取附着资源槽的灵气浓度、相性、稳定度和污染作为洞府收益或风险 |
| `upkeep_rule` | 维持消耗、失修条件、维护来源和异常处理 |
| `storage_container_id` | 洞府库存容器 |
| `linked_space_refs` | 关联空间、密室、隐藏层、阵眼、路线或洞天入口 |
| `unlock_condition` | 开启、进入、取物或使用洞府的条件 |
| `formation_slot_refs` | 附加阵法、禁制、伪装、传送、守护或封印槽位 |
| `blocks_resource_slot_facility_construction` | 洞府附着自然资源槽时为 true，表示该资源槽不能继续建设其他设施，直到洞府被清理、迁移、拆除或事件处理 |

### 2.2 藏宝

藏宝是以储物为核心的特化洞府。它可以很小，也可以附着在自然资源槽或节点隐藏层上，或由已有洞府中的密室、阵法、隐藏层入口等关联空间承载；普通藏宝不能直接以“节点”作为无约束落点。

藏宝至少应能表达：

```yaml
TreasureCache:
  cache_id: string
  owner_character_id: string
  location_node_id: string
  attachment_mode: natural_resource_slot | hidden_layer
  location_resource_slot_id: string | null
  location_hidden_layer_id: string | null
  storage_container_id: string
  concealment_rating: number
  concealment_modifier_from_attachment: number
  defense_rating: number
  resource_aura_benefit_policy: inherit_slot_aura | none
  upkeep_rule: object
  linked_space_refs: list
  unlock_condition: object
  formation_slot_refs: list
  blocks_resource_slot_facility_construction: bool
  deposit_policy: setup_only
  withdrawal_policy: one_time
  status: hidden | known | opened | depleted | lost | contested
```

藏宝规则：

1. 藏宝库存只能在设置藏宝时存入。
2. 设置完成后，藏宝不支持像洞府库存一样反复存入。
3. 查看藏宝中的内容不影响藏宝有效性。
4. 正式取出时，将可取资产一次性转移到目标容器，并使该藏宝进入已取出或耗尽状态。
5. 藏宝可有隐蔽、防御、维持消耗、关联空间、解锁条件和阵法槽位。
6. 藏宝不是无来源奖励。存入物品必须来自已有行囊、库存、事件结果或其他合法资产容器。
7. 普通藏宝附着自然资源槽时，和个人洞府一样占用该资源槽的设施承载位，并降低隐蔽；附着隐藏层时不读取资源槽收益。

### 2.3 真灵藏宝

真灵藏宝是正式后手在 MVP 阶段的藏物形态。

```yaml
TrueSpiritCache:
  cache_id: string
  true_spirit_id: string
  creator_character_id: string
  location_node_id: string
  location_hidden_layer_id: string
  storage_container_id: string
  independent_concealment_rating: number
  true_spirit_unlock_condition: object
  slot_limit_ref: string
  capacity_limit_ref: string
  attachment_policy: hidden_layer_only
  deposit_policy: setup_only
  withdrawal_policy: one_time
  discovery_policy: same_true_spirit_direct_sense
  damage_policy: immune_in_mvp
  movement_policy: fixed_in_mvp
  status: dormant | sensed_by_same_true_spirit | opened | depleted
```

真灵藏宝规则：

1. 真灵藏宝绑定真灵，不等同于当前世角色行囊。
2. `creator_character_id` 记录设置该后手的当世角色。
3. `true_spirit_unlock_condition` 是解锁条件，表示后世同一真灵如何确认、感应或开启。
4. 真灵藏宝具有独立隐蔽属性，不直接继承所在洞府或节点的普通隐蔽值。
5. 同一真灵的后世角色可以跨世直接感应并开启真灵藏宝；这不是当前世角色背包复制。
6. MVP 阶段真灵藏宝不会被其他角色、宗门、NPC、事件或世界演化损坏。
7. MVP 阶段真灵藏宝不会被移动；所在位置作为固定目标供同一真灵的后世角色感应、寻找和开启。
8. 真灵藏宝正式取出后按一次性取出处理，不变成可反复存取的洞府库存。
9. 真灵藏宝必须受可配置的设置数量和单个容量上限限制，不能用无限真灵藏宝绕过行囊、洞府、遗产和经济流转规则。
10. 真灵藏宝只能附着在节点隐藏层，不能设置在自然资源槽、人工扩展资源槽、洞天福地 / `blessed_land`、洞天内部子资源槽、个人洞府、普通藏宝或其他设施上。
11. 真灵藏宝没有灵气浓度需求，不从资源槽获得修炼、相性或空间收益，也不因占用资源槽而降低隐蔽。

### 2.4 承载与设施占用

个人洞府和普通藏宝有两种合法落点：

| 落点 | 收益 | 隐蔽 | 设施占用 |
| --- | --- | --- | --- |
| 自然资源槽 | 可读取资源槽灵气浓度、相性、稳定度、污染和空间条件 | 因附着在可调查、可争夺、可经营的资源槽上，隐蔽程度降低 | 占用该资源槽设施承载位，阻止其他设施建设 |
| 节点隐藏层 | 不读取资源槽灵气收益 | 由隐藏层、阵法、线索和事件决定，通常更隐蔽 | 不占用资源槽设施承载位 |

承载规则：

1. 个人洞府和普通藏宝只能设置在模板允许的自然资源槽或节点隐藏层上。
2. 自然资源槽指 `slot_origin = natural` 的资源槽；人工常规扩展槽默认不作为个人洞府或藏宝的优先落点，除非后续模板明确允许。
3. 若自然资源槽已有 `attached_facility_ref`、`attached_facility_class` 或未清理的 `blocking_site_refs`，不能设置个人洞府或普通藏宝。
4. 个人洞府或普通藏宝附着自然资源槽后，应写入资源槽的 `attached_facility_class`、`attached_facility_ref` 或 `blocking_site_refs`，使该槽后续建造、扩建或改造其他设施失败。
5. 要继续改造被占用的自然资源槽，必须先清理、迁移、拆除、收回或通过事件处理对应个人洞府 / 普通藏宝，并写入资产流水、位置记录和可见性记录。
6. 真灵藏宝只使用隐藏层落点，不参与资源槽设施占用、清理、拆除或改造流程。

## 3. 个人洞府类型

个人洞府分两类：宗门分配的山门洞府，以及山门外自己开辟的个人洞府。

| 类型 | 位置与管辖 | 库存归属 | 角色重大异常后的处理 |
| --- | --- | --- | --- |
| 山门上的宗门分配洞府 | 位于宗门控制地理节点中的宗门山门设施群、附属山峰、内门区域、自然资源槽或隐藏层 | 洞府归个人使用，但处于宗门管辖与清查范围 | 角色叛宗、被逐、濒死、死亡、转世、长期失踪或资格丧失后，宗门可以直接锁定、清点并获取洞府普通库存中的道具 |
| 山门外自辟洞府 | 位于山门外地图节点、自然资源槽、隐藏层、荒野、秘境边缘或个人控制区域 | 洞府归个人建设和维护，不自动纳入宗门库房 | 角色叛宗、濒死、死亡、转世或失踪后，宗门不能直接获取其中道具；洞府转为有开启条件的无主遗留设施、藏宝线索、争夺对象或失落库存 |

两类洞府最大的区别是：

```text
角色状态出现重大异常后，宗门是否直接获得洞府库存中的普通道具。
```

山门洞府规则：

1. 宗门分配洞府是个人使用设施，但不是完全脱离宗门管辖的私有世界。
2. 角色叛宗、被逐、死亡、濒死托管、长期失踪、职位或资格丧失时，宗门可锁定洞府入口。
3. 宗门可将洞府普通库存中的道具转入宗门库存或临时清点容器。
4. 该转移必须写入资产流水，记录触发原因、时间、清点主体、来源容器、目标容器和可见日志。
5. 真灵藏宝不应混入山门洞府普通库存。若玩家要设置正式后手，应使用真灵藏宝容器和对应解锁条件表达。

宗门个人洞府实现规则：

1. 宗门本身不应作为节点类型；宗门山门是地理节点中的宗门设施群，通常位于 `mountain_region`、`valley_region`、`plain_region` 或其他宗门控制节点内。
2. 宗门可在合法自然资源槽上建设 `personal_cave_complex`，也可在节点隐藏层或宗门设施群内部建立洞府区记录。
3. 若 `personal_cave_complex` 附着自然资源槽，该槽必须没有既有设施或未清理的洞府 / 藏宝占用；建设后该槽被洞府区占用，不能同时建设灵田、市场、传送阵、修炼房或其他设施类别。
4. `personal_cave_complex` 是一类设施类别，可以包含多个分配洞府单元；单个弟子的 `PersonalCaveFacility` 记录是洞府区下的分配单元，而不是新的地图节点。
5. 每个分配洞府单元应记录 `owner_character_id`、`storage_container_id`、权限、清点规则和状态；宗门记录洞府区设施、洞府单元列表、分配资格、清点权限和维护来源。
6. 宗门若要把洞府区所在资源槽改造成其他设施，必须先迁移、清点、收回或废弃该洞府区，并处理其中每个个人洞府库存。
7. 宗门分配洞府可以读取所附自然资源槽的灵气收益；若洞府区建立在隐藏层或纯宗门设施群中，则不自动读取自然资源槽灵气收益。

山门外自辟洞府规则：

1. 自辟洞府由角色发现、建设、维护或占据，不自动纳入宗门库房。
2. 角色重大异常后，宗门不能凭身份直接获得自辟洞府库存。
3. 自辟洞府可因线索、传闻、地图探索、阵法破损、维护中断或他人发现而暴露。
4. 自辟洞府库存作为无主遗留设施资产，不自动回收宗门，也不随转世自动交给后世角色。
5. 后世角色或其他角色进入自辟洞府，需要满足预设开启条件，例如携带洞府钥匙、掌握指定功法、持有线索、处在正确地点或完成相关事件。
6. 自辟洞府也可以被强行解除阵法、破禁或攻破防御后开启；若其他角色先满足条件或破阵成功，可能提前进入、取走或争夺其中资产。
7. 自辟洞府是否继续维持，取决于隐蔽、防御、维持消耗、所在节点状态和后续事件。
8. 自辟洞府若附着自然资源槽，会获得资源槽灵气、相性或空间条件收益，但因落在可调查资源槽上而降低隐蔽；若附着隐藏层，则不读取资源槽收益。
9. 自辟洞府附着自然资源槽后会阻止该槽建设其他设施，直到洞府被清理、迁移、拆除、争夺解决或事件处理。

## 4. 洞府库存

洞府库存是绑定在洞府设施上的资产容器，底层容器类型按库存系统的 `personal_storage` / `personal_cave_storage` 口径处理。

洞府库存支持反复存取，前提是当前角色满足：

1. 拥有或被授权访问该洞府。
2. 当前所在位置、路线或事件状态允许进入洞府。
3. 洞府未被锁定、封禁、毁坏、争夺或事件锁定。
4. 物品本身允许转移。
5. 若洞府处于宗门管辖范围，存取行为符合宗门权限或不触发清查限制。

洞府库存不应表达为：

1. 行囊容量扩展。
2. 可随角色移动的背包。
3. 无日志转移空间。
4. 入口 NPC 或宗门人物的个人背包。
5. 无位置、无权限、无维护成本的抽象列表。

## 5. 藏宝设置与取出

藏宝设置流程：

```text
选择合法自然资源槽、节点隐藏层或已有洞府 / 密室
→ 校验角色状态、位置、权限和可用资源
→ 校验自然资源槽是否已有设施或洞府 / 藏宝占用
→ 打开储物空间页面
→ 从行囊或合法库存中选择要存入的物品
→ 设置隐蔽、防御、解锁条件、阵法或维持消耗
→ 确认后生成藏宝设施和藏宝库存
→ 写入资产流水、位置记录、资源槽占用或隐藏层记录和可见性记录
```

藏宝查看流程：

```text
找到或感应藏宝
→ 校验查看权限或解锁线索
→ 展示藏宝内容摘要或完整内容
→ 不改变藏宝有效性
```

藏宝取出流程：

```text
找到或感应藏宝
→ 校验开启条件
→ 打开储物空间页面
→ 展示一次性取出确认
→ 将可取资产转移到行囊或合法目标库存
→ 藏宝进入 opened / depleted 状态
→ 写入资产流水、日志和状态变化
```

一次性取出含义：

1. 取出确认前，查看内容不消耗藏宝。
2. 一旦确认取出，不支持同一藏宝的多次反复取放。
3. 取出后，该藏宝不再作为可继续存取的库存使用。
4. 若取出过程因权限、状态或事件中断，应明确记录失败原因，不得无提示搬空或销毁。

## 6. 正式后手、遗产与无主遗留设施

正式后手、遗产和无主遗留设施必须区分。

| 类型 | 当前整理口径 |
| --- | --- |
| 正式后手 | MVP 阶段以真灵藏宝为主，绑定真灵、设置时存入、同一真灵跨世直接感应和开启、一次性取出、不被损坏或移动，且受设置数量和单个容量限制 |
| 遗产 | 原持有人死亡、转世、失踪、资格丧失或组织接管后，需要分配、继承、清点或回收的有主资产；典型对象是 NPC 随身物品、NPC 洞府库存、宗门管辖个人洞府普通库存、宗门托管 / 职务资产 |
| 无主遗留设施 | 宗门外个人洞府、普通藏宝、失落库存、旧洞府线索和其他未归入真灵藏宝的藏物点；没有当前资产主人，不进入遗产分配、继承或回收，按钥匙、功法、线索、位置、事件或破阵条件开启 |

正式后手不是死亡后自动继承的全部资产。只有经过后手设置流程，进入真灵藏宝容器，并满足真灵解锁条件的资产，才按正式后手处理。

遗产不是正式后手。宗门管辖内的个人洞府库存，在玩家角色转世、死亡、长期失踪或资格丧失后，按宗门相关遗产规则清点并回收宗门。宗门托管资产、职务资产和宗门发放但未私有化的资产优先归宗门。

宗门外个人洞府、普通藏宝和真灵藏宝不视为遗产，不进入遗产分配、继承或宗门回收。普通藏宝和宗门外洞府作为无主遗留设施，需要满足预设开启条件才能进入或取出，也可以被强行破阵开启，因此可能被其他角色提前打开。真灵藏宝作为正式后手通常允许同一真灵跨世开启，但必须受数量与容量限制。

## 7. 重大异常与资产去向

角色重大异常包括但不限于：

```text
叛宗；
被逐；
濒死；
死亡；
转世；
长期失踪；
身份被剥夺；
洞府权限被撤销；
所在节点被攻占或封禁。
```

资产去向规则：

| 资产位置 | 重大异常后的默认处理 |
| --- | --- |
| 行囊 | 按死亡、战利品、遗产、事件或后手规则另行结算 |
| 山门宗门分配洞府库存 | 宗门可直接锁定、清点并获取普通库存道具；玩家转世前留下的宗门个人洞府库存按 NPC 死亡后的宗门相关遗产规则回收宗门 |
| 山门外自辟洞府库存 | 宗门不能直接获取；保留为无主遗留设施、藏宝线索或争夺事件 |
| 普通藏宝库存 | 保持无主遗留设施状态，直到满足开启条件、被合法开启、被强行破阵、被争夺或事件处理 |
| 真灵藏宝库存 | 作为正式后手处理；MVP 阶段保持固定且不可损坏、不可移动；同一真灵可跨世直接感应和开启，但受数量与容量限制 |
| 宗门库存 | 归宗门，不随个人状态异常流失 |
| 商店库存 | 归店铺或市场容器，不随入口 NPC 状态异常流失 |

## 8. UI 与实现约束

1. 储物空间页面应区分“行囊”和“库存”。
2. 洞府库存可以反复存取。
3. 藏宝库存只能在设置藏宝时存入。
4. 藏宝内容可以查看，查看不影响有效性。
5. 藏宝取出必须有一次性取出确认。
6. 真灵藏宝在 MVP 阶段只展示给同一真灵的可感应角色，且不得显示为可被他人搬空、损坏或移动；界面必须表达数量和单个容量限制。
7. 所有存入、取出、封存、清点、回收和异常转移都必须写资产流水，并遵守库存系统的预留、锁定、权限和可见性规则。
8. 设置个人洞府或普通藏宝时，UI 必须区分“自然资源槽落点”和“隐藏层落点”：前者显示灵气收益与隐蔽降低，后者显示无资源槽收益但隐蔽更强。
9. 已有设施、个人洞府或普通藏宝占用的自然资源槽，不能继续显示为可建设设施的合法目标，除非先完成清理、迁移、拆除或事件处理。
10. 真灵藏宝设置界面只能选择节点隐藏层或由后手流程生成的隐藏层目标，不允许选择自然资源槽、洞天福地 / `blessed_land`、洞天内部子资源槽或已有设施。

## 9. 待细化问题

1. 隐蔽、防御、维持消耗和阵法槽位的数值模型。
2. 山门洞府被宗门清点时，哪些物品会生成本人可见日志、宗门日志或隐藏日志。
3. NPC 死亡后的随身物品、NPC 洞府库存、玩家转世前宗门个人洞府库存和宗门托管 / 职务资产之间的清点优先级。
4. 自辟洞府、普通藏宝的开启条件模板、破阵难度和被其他角色提前打开的事件模板。
5. 真灵藏宝的设置数量上限、单个容量上限和不同境界或真灵状态下的扩展规则。
6. 真灵藏宝未来是否开放非同一真灵发现、争夺、损坏、移动或污染，MVP 阶段不开放。
7. 自然资源槽附着洞府 / 藏宝时，灵气收益、污染风险和隐蔽惩罚的具体数值公式。
8. 宗门 `personal_cave_complex` 的规模、洞府单元数量、维护成本和迁移清点流程。
