# NPC持久化、库存与经济定位框架草稿 0426｜人工参与编辑

## 0. 文档状态

- 文档类型：经济系统前置框架草稿 / NPC 模拟边界草稿。
- 当前状态：**未人工审核**。本页从 Canvas 草稿写入 Notion，待人工审阅后才能视为定稿。
- 目标：在正式展开经济系统之前，先确定 NPC 在经济系统中的定位，尤其是 NPC 库存、物品实例化、行动模拟与性能边界。
- 本案暂不展开：NPC 生成、人际关系、完整 AI 决策树、好感系统、日常作息、婚恋师徒关系、完整市场价格公式。

## 1. 背景与问题

此前的隐含语义是：

```
NPC 平时不持有完整库存
→ 当玩家与 NPC 进入战斗或交互时
→ 临时初始化 NPC 库存与物品实例
→ 根据战斗 / 交易 / 事件结果转移给玩家或销毁
```

该方案实现简单，但会带来一组系统性问题：

1. **经济来源不可信**：NPC 战斗开始时突然生成库存，本质上是凭空生成物品，难以接入物品预算帽、来源日志和世界资源流转。
2. **战斗与交易不一致**：同一个 NPC 可能在交易界面、剧情描述、战斗掉落中呈现不同资产状态。
3. **可重复利用风险**：如果初始化逻辑依赖交互触发，玩家可能通过重复触发、打断、重新进入事件链来刷出物品。
4. **宗门库存可信度下降**：宗门发放、NPC 持有、节点储藏、坊市流通如果没有统一资产容器，会削弱“资源真实存在”的体验。
5. **后手与追踪系统冲突**：正式后手要求重要资产可追踪、有日志；临时生成库存会破坏“物品曾经真实存在并经历流转”的叙事基础。
6. **性能边界不清**：如果为了解决上述问题改成所有 NPC 全量持久化，又会进入深度 NPC 生态模拟，超出 MVP 非目标。

因此，本案需要回答：

> 哪些 NPC 需要持久化？哪些 NPC 需要库存持久化？哪些 NPC 需要行动模拟？NPC 的经济行为如何既能支撑沙盒演化，又不拖垮实现复杂度与结算性能？
> 

## 2. 已继承的上位约束

### 2.1 项目与技术边界

- 游戏是修仙题材、文字 / 策略、选择导向、个人成长 + 宗门经营 + 沙盒演化。
- MVP 边界是本地单人可测试、可部署私人服务器、支持 3 人共玩。
- 技术路线已确定为 Godot，采用客户端 + 权威服务器，规则和内容尽量数据驱动。
- 世界不是实时持续推进，而是季度回合 + 关键事件插入链。
- 服务器负责房间状态、季度推进、行动结算、宗门 AI、地图节点、事件触发和存档写入。
- MVP 明确不追求深度 NPC 生态。

### 2.2 行动与结算约束

- 标准季度流程包含世界刷新、宗门行动阶段、角色行动阶段、玩家锁定 / 超时、服务器统一结算、事件链插入、结果回写与日志生成。
- 玩家角色每季度有 6 个朔望行动格。
- 角色行动阶段的预估不是最终结果，最终以服务器权威结算为准。
- 宗门行动与角色行动是双层季度结构。
- 每个宗门每季度始终只有 1 个宗门主行动。
- 已控制资源节点的稳定产出走常态结算，不占用宗门主行动。

### 2.3 物品与库存约束

- 物品、资源、法宝、功法载体、后手等都需要进入明确资产位置与日志。
- 个人库存与宗门库存必须区分。
- 宗门发放给玩家或 NPC 的资源必须来自真实库存。
- 贡献不是货币，不能直接兑换资源。
- MVP 不引入背包重量、体积、格子或通用负重上限，随身资产用标签与事件条件限制。
- 灵石是核心通货；灵石不分等级，高密度灵气需求通过聚灵石等独立加工物品表达。
- 物品生成必须服从来源、预算、堆叠规则与实例化边界。

## 3. 设计目标

本框架要达成四个目标：

1. **经济可信**：重要物品、资源和库存都应属于明确资产容器，能解释来源、归属、转移和消耗。
2. **沙盒有效**：关键 NPC 能通过修炼、探索、宗门决策、资源调度等行为影响世界演化。
3. **复杂度可控**：不是所有 NPC 都是完整角色，不模拟所有人的每日作息与逐物品库存。
4. **性能可控**：季度结算只模拟需要模拟的 NPC，其余 NPC 使用身份持久化、机构资产、聚合流或惰性唤醒。

## 4. 核心结论草案

### 4.1 采用“分层持久化”，不是“全 NPC 全量模拟”

NPC 需要持久化，但持久化分为多种粒度：

```
身份持久化
角色状态持久化
库存持久化
行动意图持久化
世界影响持久化
```

低层 NPC 只需要身份持久化；高层 NPC 才需要完整角色状态、库存和行动模拟。

### 4.2 NPC 库存不再在战斗开始时初始化

新规则：

> 战斗开始时不得临时初始化“完整 NPC 库存”。
> 

战斗可获得的资产只来自三类来源：

1. 该 NPC 已持久化的随身 / 可调用资产。
2. 事件链在结算前已经明确锁定的奖励包或掉落包。
3. 由事件预算生成的非个人库存奖励，且必须写入来源日志。

这意味着：

- 轻量 NPC 被击败，不会突然掉出一整套经济上重要的个人库存。
- 商人被劫，不等于商人身上带着整个商店库存。
- 宗主 / 长老 / 关键敌人被击败，可以根据其真实随身法宝、消耗道具、护身资源、储物资产和事件条件产生战利品。

### 4.3 商店库存优先属于“机构 / 节点 / 市场”，不是属于掌柜个人

掌柜、摊主、执事、村长等 NPC 可以是交互入口，但库存容器不必归属 NPC 本人。

建议资产归属：

```
坊市售卖物 → MarketListing / ShopStock / NodeStorage
宗门库房物 → SectStorage
资源节点产出 → NodeStorage / ResourcePool
掌柜个人资产 → 只有掌柜达到高层 NPC 时才追踪
```

这样可以避免：

- 杀死掌柜就获得整个坊市库存。
- 更换掌柜后商店库存无故消失。
- 每个服务型 NPC 都需要维护个人钱包和完整背包。

### 4.4 关键 NPC 可以像角色一样参与经济流转

达到特定层级的 NPC 可以拥有：

- 修为阶段。
- 属性与状态。
- 功法 / 术法 / 神通。
- 法宝与消耗道具。
- 个人库存和储藏位置。
- 宗门身份与权限。
- 每季度宏观行动。
- 与宗门、节点、市场之间的资源流转记录。

但这只适用于关键 NPC，不适用于所有村民、杂役、路人、普通掌柜。

### 4.5 NPC 行动使用“宏观行动 + 事件插入”，不使用全量 6 tick 排程

玩家角色使用 6 个朔望行动格进行显性规划。NPC 不应默认也全部使用同样粒度逐 tick 规划。

建议：

- 低层 NPC 无独立行动结算。
- 中层服务 NPC 使用季度刷新、库存补货、职责状态更新。
- 高层关键 NPC 使用季度宏观行动。
- 当 NPC 与玩家行动、宗门行动或节点事件发生交叉时，再进入局部事件链。

即：

```
平时：宏观结算
相交：事件链精算
重要结果：写入日志与资产容器
```

## 5. NPC 分层设计

### 5.1 分层总览

| 层级 | 名称 | 典型对象 | 身份持久化 | 库存持久化 | 行动模拟 | 世界影响 |
| --- | --- | --- | --- | --- | --- | --- |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| N0 | 抽象人群 / 劳力池 | 凡人村民群体、杂役群体、矿工规模 | 否 | 否 | 聚合 | 低 |
| N1 | 轻量身份 NPC | 村长、普通掌柜、低价值任务入口、路人修士 | 是 | 否 | 无 / 被动 | 低 |
| N2 | 功能服务 NPC | 坊市商人、宗门执事、炼丹师服务入口、任务发布人 | 是 | 通常否；库存归机构 | 职责刷新 | 中低 |
| N3 | 关键角色 NPC | 长老、真传、护道人、命名竞争者、重要敌人 | 是 | 是 | 季度宏观行动 | 中高 |
| N4 | 世界轴心 NPC / 势力代理 | 宗主、大势力领袖、主线关键人物、秘境核心守护者 | 是 | 是 | 高优先级宏观行动 + 事件链 | 高 |

说明：

- 层级不是身份尊卑，而是数据复杂度与玩法复杂度。
- 同一个“村长”一般是 N1，但如果某条主线把他提升为关键修士、后手守护者或宗门暗线，他可以晋升为 N3。
- 同一个“商人”一般是 N2，但如果他是跨区域商会首脑、持有关键法宝并会主动布局，可以晋升为 N3 / N4。

### 5.2 N0：抽象人群 / 劳力池

用途：表达世界人口、劳动力、人力资源、基础消费与宗门弟子规模。

不创建单个 NPC 记录，只维护聚合字段：

```
PopulationPool {
  pool_id
  node_ref / sect_ref
  population_type
  scale
  productivity
  stability
  consumption_profile
  risk_state
}
```

经济作用：

- 参与宗门人力 / 弟子规模。
- 参与节点常态产出。
- 参与基础消费、灾害损失、征召、流民、矿工伤亡等事件。
- 不持有物品实例。
- 不作为战斗对象单独掉落。

### 5.3 N1：轻量身份 NPC

典型对象：凡人村庄村长、普通掌柜、低价值剧情入口、可反复见到但不影响核心经济的 NPC。

持久化字段建议：

```
NpcIdentityState {
  npc_id
  tier = N1
  name
  sex
  age
  lifespan
  portrait_key
  role_ref
  node_ref
  faction_ref
  alive_state
  replacement_rule_ref
}
```

设计目的：

- 玩家再次见到村长时，姓名、年龄、头像不变化。
- 村长会随时间衰老、死亡或更换继任者。
- 世界看起来连续，而不是每次进入节点重新随机。

不追踪：

- 个人铜钱。
- 个人背包。
- 个人修炼进度。
- 每季度具体作息。
- 低价值性格、欲望和日常关系网。

经济规则：

- N1 NPC 不作为重要经济主体。
- 与 N1 的交易、征税、任务奖励应来自节点 / 组织 / 事件预算，而不是 NPC 个人库存。
- N1 被击败或死亡时，只产生事件结果，不展开完整个人遗产。

### 5.4 N2：功能服务 NPC

典型对象：坊市商人、宗门执事、炼丹服务入口、炼器服务入口、任务发布人、渡口管事、飞舟售票人。

N2 比 N1 多持久化服务状态：

```
NpcServiceState {
  npc_id
  service_type
  permission_rule_ref
  price_policy_ref
  restock_rule_ref
  service_cooldown
  reputation_modifier
  linked_asset_container_ref
}
```

关键规则：

> N2 的“可售卖库存”一般不属于 NPC 个人库存，而属于 ShopStock、MarketListing、SectStorage 或 NodeStorage。
> 

N2 可以显示商品列表，但商品列表有两种实现：

1. **真实挂牌**：高价值、唯一性或有随机词条的物品已经存在为 item_instance，并挂在市场 / 商店容器下。
2. **模板供给**：低价值常见物品只记录库存数量、模板、价格和刷新规则，购买时实例化或加入堆叠。

N2 一般不进行独立修炼与行动模拟。其经济变化来自：

- 季度补货。
- 节点市场状态。
- 宗门控制权。
- 玩家购买 / 出售。
- 事件造成的商路中断、价格波动、库存短缺。

N2 被攻击或抢劫时：

- 如果目标是 NPC 本人，只处理其随身防身道具、身份令牌、事件掉落。
- 如果目标是商店 / 仓库，需要进入节点事件链，目标资产容器是 ShopStock / NodeStorage，不是掌柜个人背包。

### 5.5 N3：关键角色 NPC

典型对象：宗门长老、真传弟子、玩家竞争者、护道人、重要敌人、命名散修、前世后手守护者。

N3 开始具备角色化数据：

```
NpcCharacterState {
  npc_id
  tier = N3
  cultivation_stage
  core_attributes
  derived_bars
  method_refs
  technique_refs
  artifact_refs
  inventory_ref
  location_ref
  sect_identity_ref
  status_tags
  macro_action_state
}
```

N3 可以：

- 修炼或闭关。
- 外出探索。
- 参与宗门行动。
- 作为护法、敌人、竞争者或交易对象进入事件链。
- 消耗真实资源。
- 获得真实物品。
- 因战斗、事件或突破改变状态。

库存规则：

- N3 有个人库存，但仍区分随身携带、洞府储藏、宗门托管、市场挂牌、事件锁定。
- 战斗中只默认暴露随身携带和可即时调用的资产。
- 洞府资产、宗门托管资产、隐藏后手不因普通战斗自动掉落，除非事件链明确追踪和攻破。

### 5.6 N4：世界轴心 NPC / 势力代理

典型对象：宗主、竞争宗门领袖、主线大人物、秘境核心守护者、可能长期改变世界格局的人物。

N4 与 N3 的区别不是字段更多，而是模拟优先级更高、世界影响更大。

N4 可以：

- 影响宗门战略倾向。
- 触发或改写重大节点事件。
- 推动宗门扩张、保守、培养、财政恢复、秘境争夺等倾向。
- 使用个人法宝或修为改变关键事件结果。
- 死亡、闭关、突破失败、远征失踪时改变宗门局势。

关键边界：

> N4 的个人行动不应无条件增加宗门主行动数量。
> 

宗主闭关、宗主外出、宗主亲征等行为可以通过以下方式表达：

1. 作为宗门主行动的叙事执行者或修正来源。
2. 作为宗门 AI 倾向变化的原因。
3. 作为独立世界事件链，但必须占用世界事件预算或高优先级 NPC 行动预算。

不能因为宗门有宗主、多个长老、多个真传，就让宗门在每季度获得大量额外组织行动。

## 6. 库存与资产容器设计

### 6.1 基本原则

经济系统不应问“这个 NPC 身上有什么”，而应先问：

> 这个资产属于哪个容器？这个容器的持有者、位置、权限和可见性是什么？
> 

建议所有资产进入统一容器模型：

```
AssetContainer {
  container_id
  container_type
  owner_ref
  location_ref
  persistence_mode
  item_stacks
  item_instances
  budget_pool
  access_rules
  ledger_refs
}
```

### 6.2 容器类型

| 容器类型 | 含义 | 示例 |
| --- | --- | --- |
| CharacterInventory | 角色 / 高层 NPC 个人库存 | 玩家背包、长老随身资源 |
| CharacterStorage | 角色个人储藏 | 洞府、临时藏物点 |
| SectStorage | 宗门库存 | 宗门库房、培养资源、材料仓 |
| NodeStorage | 节点储藏 | 矿场库存、村庄仓储、秘境封存区 |
| ShopStock | 店铺库存 | 丹药铺、法宝铺、坊市摊位 |
| MarketListing | 市场挂牌 | 玩家或 NPC 挂售物品 |
| EventLocked | 事件锁定资产 | 押运货物、秘境奖励、战斗赌注 |
| SealedLegacy | 正式后手封存 | 前世洞府、封印阵、遗产盒 |
| ResourcePool | 聚合资源池 | 灵脉产能、矿脉储量、药田收成 |

### 6.3 个人库存与机构库存分离

必须避免以下错误：

```
掌柜 = 商店库存持有人
宗主 = 全宗门库房持有人
村长 = 全村所有铜钱持有人
```

正确设计：

```
掌柜只是 ShopStock 的操作入口
宗主只是 SectStorage 的权限影响者
村长只是 NodeStorage / PopulationPool 的角色代表
```

这能支持：

- NPC 死亡后机构仍存在。
- 职位更替后库存不丢失。
- 抢劫、查抄、交易、发放、征收都能定位到正确资产容器。
- NPC 个人失败不自动等于组织资产全量失守。

### 6.4 真实实例与模板库存

物品不必全部提前实例化。

建议区分：

1. **真实实例物品**
    - 法宝。
    - 功法载体。
    - 有独立词条 / 状态 / 耐久 / 来源的物品。
    - 正式后手物。
    - 高价值突破资源。
    - 玩家或 N3+ NPC 真实持有物。
2. **堆叠物品**
    - 灵石。
    - 普通材料。
    - 普通丹药。
    - 普通符箓。
    - 补给。
3. **模板库存**
    - 高频、低价值、可稳定供给的商品。
    - 只记录模板、数量、价格、刷新规则。
    - 在购买、发放、消耗或事件要求时实例化或加入堆叠。

注意：模板库存不是 NPC 个人库存，也不是战斗掉落池。它属于店铺 / 节点 / 市场容器。

## 7. NPC 行动模拟框架

### 7.1 模拟模式

NPC 的模拟模式应与层级绑定：

| 模式 | 适用层级 | 说明 |
| --- | --- | --- |
| none | N0 | 不创建个体，只做聚合变化 |
| passive | N1 | 年龄、寿元、职位更替、死亡等被动变化 |
| service_refresh | N2 | 服务状态、库存刷新、价格修正、冷却恢复 |
| macro_action | N3 | 进入活跃集时选择 0–1 个宏观行动，未激活时使用惰性追赶 |
| high_priority_macro | N4 | 每季度必定生成个人宏观行动，可按完整结算或汇总结算落地，并可能触发事件链 |
| event_precise | N3 / N4 | 与玩家、宗门行动或关键节点相交时进入事件链精算 |

### 7.2 活跃集机制

不应每季度模拟所有 N3。N4 作为世界轴心 NPC / 势力代理，必须每季度生成个人宏观行动，否则会导致补偿滞后、状态失真，并削弱 N4 主导世界演化的能力。

建议每季度先建立 NPC 活跃集，用于决定哪些 N3 需要完整宏观行动结算，以及哪些 N4 需要进入事件链精算：

```
NpcActiveSetSelection {
  near_player_characters
  involved_in_player_sect
  involved_in_current_events
  controls_target_node
  competes_for_resource_window
  high_world_influence
  unresolved_previous_action
  scheduled_major_event
}
```

进入活跃集的 N3 才进行宏观行动结算；未进入活跃集的 N3 使用低成本追赶公式或状态冻结。N4 不受该限制：每季度必须生成个人宏观行动，但若未与玩家、宗门主行动或关键节点发生交叉，可使用汇总结算写入紧凑日志。

### 7.3 惰性追赶

当一个 N3 NPC 多个季度没有进入活跃集时，不需要逐季度保存详细行动。

重新激活时，可按以下方式追赶：

```
inactive_quarters
+ npc_growth_profile
+ stipend_claim_profile
+ risk_profile
+ rng_namespace
→ summarized_state_delta
→ compact_log
```

例如：

```
某长老闭关 8 个季度，未发生玩家相关事件。
重新进入活跃集时，根据其修炼倾向、已领取俸禄 / 基础供给、闭关季度数和风险表，汇总生成修为进度、资源消耗、伤势或突破尝试结果。
```

MVP 阶段，N3 的惰性追赶暂不支持“宗门支持”作为独立输入。宗门对 N3 成长的支出与 NPC 修为增加之间的关联，先通过俸禄领取、基础供给或职责待遇表达。

这既保留世界演化，又避免无意义的逐季度模拟。

### 7.4 NPC 宏观行动类型

N3 / N4 的宏观行动只定义高层语义，不在本案展开 AI 细则：

```
Cultivate        // 修炼 / 闭关
Explore          // 外出探索 / 寻宝
SectDuty         // 执行宗门职责
Guard            // 驻守 / 护法 / 镇守
Travel           // 移动到关键节点
TradeOrAcquire   // 采购 / 交换 / 争夺资源
Recover          // 疗伤 / 休整 / 稳定状态
Breakthrough     // 尝试突破，仅限关键 NPC 且需事件预算
EventRole        // 作为某事件链角色参与
```

行动结果可以改变：

- NPC 修为、状态、伤势。
- NPC 个人库存。
- 宗门库存。
- 节点状态。
- 市场挂牌。
- 宗门战略倾向。
- 玩家可见传闻。
- 隐藏世界日志。

### 7.5 NPC 行动与宗门主行动的关系

需要防止 NPC 行动绕开“每宗门每季度 1 个主行动”的约束。

规则建议：

1. **宗门级结果必须归入宗门主行动或常态结算**。
    - 例如宗主带队抢矿，属于宗门主行动“开采 / 资源介入”或“远征”。
2. **个人级结果可以是 NPC 宏观行动**。
    - 例如长老个人闭关、真传外出寻宝、散修购买法宝。
3. **影响宗门但不直接消耗组织资源的行为，可以作为宗门倾向修正**。
    - 例如宗主闭关导致本季度宗门更保守，或某长老力主培养路线。
4. **重大 NPC 个人行为如果会改变节点控制、资源名额或宗门库存，必须进入事件预算或宗门行动预算**。

## 8. 经济系统中的 NPC 定位

### 8.1 经济主体分类

本游戏经济系统中的主体不只有玩家和 NPC，而是多类资产持有者：

```
World / Node / ResourcePool
Sect / Organization
Market / Shop / Listing
PlayerCharacter
HighTierNpcCharacter
EventLockedAsset
SealedLegacy
```

NPC 的经济定位取决于其层级：

| 层级 | 经济定位 |
| --- | --- |
| N0 | 聚合生产 / 消费 / 人力参数 |
| N1 | 交互代表，不是重要资产持有者 |
| N2 | 服务入口，连接市场 / 店铺 / 宗门库存 |
| N3 | 真实经济角色，可消耗、获取、携带、储藏资源 |
| N4 | 经济与世界格局的高影响行动者 |

### 8.2 资源流转总路径

建议经济系统使用以下总路径：

```
自然资源槽 / 事件窗口
→ ResourcePool / NodeStorage
→ SectStorage / ShopStock / MarketListing
→ PlayerCharacter / HighTierNpcCharacter
→ 修炼 / 突破 / 战斗 / 建设 / 封存 / 损坏 / 消耗
→ Ledger / VisibleLog / HiddenWorldLog
```

这样可以把 NPC 纳入世界、宗门、角色之间的流转，而不是在战斗开始时临时生成孤立资产。

### 8.3 NPC 购买、出售与交易

N1 / N2：

- 通常不进行真实个人交易。
- 代表节点、店铺、宗门或市场完成交易。
- 价格、库存和可售项来自对应资产容器与市场规则。

N3 / N4：

- 可以作为真实交易对象。
- 买入物品进入个人库存、洞府储藏或宗门托管。
- 出售物品从个人库存或授权容器中移出。
- 重要交易需要日志，尤其是高阶物品、法宝、突破资源、后手相关物。

### 8.4 NPC 修炼资源消耗

N3 / N4 NPC 自己修炼时，资源来源应明确：

- 个人库存。
- 已领取俸禄 / 基础供给；MVP 中 N3 不使用独立“宗门支持”输入。
- 洞府 / 节点资源。
- 师承 / 势力支持。
- 事件奖励。

不建议出现：

```
NPC 修炼进度提升，但没有任何资源来源、时间成本或宗门支持说明。
```

MVP 可以先使用汇总消耗：

```
本季度某长老领取俸禄并闭关：从宗门库存或俸禄预算中扣除基础供给 X，个人修为进度 +Y，生成隐藏日志。
```

不需要展开逐日丹药、逐件材料、逐格背包消耗。

## 9. 战斗、抢劫与掉落边界

### 9.1 战斗可用资产

战斗开始时，应读取：

```
combat_ready_items
active_artifacts
passive_artifacts
consumables_allowed_by_event
method_refs
technique_refs
temporary_event_buffs
```

这些来自角色真实状态或事件结果包，而不是临时生成完整库存。

### 9.2 掉落来源

战斗或抢劫后的可获得资产来源：

1. 目标随身携带且未被消耗 / 损坏 / 逃遁带走的资产。
2. 事件链锁定的押运、赌注、战场遗物、秘境奖励。
3. 战斗造成的破碎法宝、残片、材料回收。
4. 低层 NPC 的模板化事件奖励，但必须有预算和来源标签。

### 9.3 不自动掉落的资产

以下资产默认不因一场普通战斗自动掉落：

- NPC 洞府储藏。
- 宗门库房。
- 店铺全部库存。
- 节点仓库。
- 市场挂牌中但不在现场的物品。
- 正式后手封存物。
- 未被发现的隐藏资产。

如果玩家要夺取这些资产，需要进入对应事件链，例如查抄、搜魂、追踪储物袋、攻破洞府、洗劫仓库、破解阵法。

### 9.4 低层 NPC 被击败

N1 / N2 被击败时，不生成完整个人库存。

可能结果：

- 小额事件奖励。
- 身份物品。
- 情报。
- 节点关系变化。
- 宗门 / 村庄 / 坊市声望损失。
- 触发守卫、通缉、赔偿、报复或商路中断。

重点不是“掉装备”，而是行为对世界关系和资产容器的影响。

### 9.5 NPC 死亡后的遗产分配规则

N3 / N4 死亡后，不应直接把所有资产合并为战斗掉落。统一规则为：

```
死亡事件链结算
→ 读取死亡时资产容器状态
→ 分类剩余资产
→ 按遗产规则分配
→ 写入资产流水、可见日志与隐藏世界日志
```

分配顺序：

1. **先结算死亡事件链**：死亡事件链可消耗、损坏、封印、转移或锁定部分资产，例如随身法宝破碎、储物物品被毁、逃遁失败遗失、护身资源耗尽。
2. **随身资产**：按死亡事件链结果和现场控制权分配，可被玩家缴获、宗门回收、敌对方夺取、损坏残留或进入事件锁定状态。
3. **个人储藏**：不因死亡自动掉落。根据继承规则、洞府防护、是否暴露、宗门关系和后续追踪事件，进入继承、宗门回收、隐藏保留、被外人发现或被事件破坏等状态。
4. **宗门托管 / 职务资产**：原则上归还宗门或保持在 SectStorage，不作为个人遗产分配。
5. **市场挂牌资产**：按挂牌规则处理，可保留挂牌、取消挂牌并退回继承容器，或进入争议 / 冻结状态。
6. **正式后手资产**：按 SealedLegacy 与后手规则处理，不因普通死亡自动暴露或转移。
7. **日志要求**：所有高价值物品、法宝、功法载体、突破资源和后手相关资产的转移必须写入 ledger；玩家可见范围由事件可见性决定。

MVP 阶段不展开复杂继承人关系网。遗产分配先使用规则模板和事件结果包表达，避免引入完整家族、师徒、道侣和宗门继承系统。

## 11. 接入季度结算的方式

### 11.1 S1 接入点

NPC 模拟层建议接入 S1 的三个位置：

1. **世界刷新阶段**
    - 更新 N1 生命周期与职位更替。
    - 刷新 N2 服务状态与商店 / 市场可见信息。
    - 生成本季度可能活跃的 N3 候选，并生成所有 N4 的本季度个人宏观意图候选。
    - 生成 NPC 相关传闻候选。
2. **服务器统一结算阶段**
    - 根据玩家与宗门决策确定最终活跃 NPC。
    - 结算 N3 / N4 宏观行动。
    - 处理 NPC 与玩家行动、宗门行动、节点事件的交叉。
    - 写入资产流水和世界日志。
3. **事件链插入阶段**
    - 当玩家行动与 NPC 行动相交时，进入局部精算。
    - 事件链返回 NPC 状态变化、库存变化、位置变化、日志变化。

### 11.2 推荐结算顺序

MVP 可以采用以下顺序：

```
读取房间状态
→ 世界刷新与 NPC 被动更新
→ N2 服务 / 市场 / 店铺刷新
→ 生成 N3 活跃集与全部 N4 宏观意图
→ 读取并校验宗门行动意图
→ 读取并校验玩家角色行动计划
→ 服务器统一结算宗门行动、角色行动和 NPC 交叉事件
→ 非交叉 NPC 宏观结果汇总落地
→ 回写角色、NPC、宗门、节点、库存、日志
→ 写入存档
```

关键原则：

- NPC 宏观意图可以提前生成，但最终结果要服从服务器统一结算。
- 与玩家或宗门行动发生冲突的 NPC 行为，必须进入同一结算上下文，不能事后单独改写。
- 非交叉 NPC 行为可以在季度末汇总落地。

## 12. 性能分析与控制策略

### 12.1 避免的高成本模型

不建议采用：

```
所有 NPC 每季度都生成完整行动计划
× 每个 NPC 都有完整库存实例
× 每个 NPC 都参与市场买卖
× 每个 NPC 都逐 tick 移动、修炼、交易、战斗
```

该模型会导致：

- 存档体积膨胀。
- 季度结算时间不可控。
- 规则调试困难。
- 日志噪声过多。
- 玩家难以理解世界变化原因。

### 12.2 推荐性能模型

采用：

```
身份广覆盖
+ 库存分层持久化
+ 聚合经济流
+ N3 活跃集宏观模拟
+ N4 必定宏观行动汇总结算
+ 事件相交时局部精算
+ 惰性追赶
```

结算复杂度从：

```
O(全部 NPC × 全部行动 × 全部库存)
```

降低为：

```
O(活跃关键 NPC + 聚合资源池 + 本季度事件链 + 玩家相关资产容器)
```

### 12.3 MVP 建议预算

暂定建议，不作为最终数值：

- N4：每个主要宗门 1–3 名。
- N3：每个主要宗门 5–15 名候选，但每季度只激活其中一部分。
- 全世界活跃 N3：每季度控制在几十级别，而不是几百级别。
- N4：数量必须严格控制；所有 N4 每季度都生成个人宏观行动，但未交叉时使用汇总结算。
- N2：可以较多，但只做服务刷新，不做个人行动模拟。
- N1：可以更多，但只做身份与生命周期持久化。
- N0：使用聚合池，不生成个人。

### 12.4 存档优化

- N1 只保存身份、年龄、角色和位置。
- N2 保存服务状态和关联资产容器，不保存完整个人库存。
- N3 / N4 使用稀疏写入，只有状态变化时更新。
- 高频普通商品用模板库存或堆叠，不创建大量独立实例。
- 高价值物品、法宝、后手、功法载体使用真实实例。
- 随机结果使用命名空间，支持复盘，不要求保存所有中间随机细节。

## 13. MVP 落地建议

### 13.1 MVP 应立即采用的规则

1. NPC 按 N0–N4 分层。
2. N1 以上 NPC 至少持久化身份。
3. N3 以上 NPC 才默认持久化个人库存。
4. N2 的商品库存归 ShopStock / MarketListing / SectStorage / NodeStorage，不归 NPC 个人。
5. 战斗开始时不初始化完整 NPC 库存。
6. NPC 掉落必须来自随身资产、事件锁定资产或预算奖励包。
7. N3 进入活跃集时使用季度宏观行动；N4 每季度必定生成个人宏观行动；二者都不使用全量 6 tick 排程。
8. 宗主 / 长老行动不得绕开“每宗门每季度 1 个主行动”的限制。
9. NPC 与玩家行动发生交叉时，通过事件链局部精算。
10. 所有重要资产变化写入 ledger 和日志。
11. N3 / N4 死亡后，先结算死亡事件链，再按统一遗产分配规则处理剩余资产。
12. MVP 保留店铺 / 仓库抢劫的规则接口，但不要求实现完整玩法。

### 13.2 MVP 暂不做

- 全 NPC 日程模拟。
- 全 NPC 个人金钱与背包。
- NPC 之间完整交易网络。
- 凡人社会完整经济循环。
- 所有宗门成员逐个修炼成长。
- 每个 NPC 都可被玩家劫掠完整财产。
- NPC 每季度都与玩家一样规划 6 个朔望行动格。

### 13.3 MVP 可验证闭环

最小验证用例：

1. 玩家反复进入同一村庄，村长姓名、头像、年龄保持一致，并会按寿元规则更替。
2. 玩家在坊市购买普通丹药，商品来自 ShopStock / 模板库存，购买后扣除灵石并写入日志。
3. 玩家攻击普通掌柜，不会获得整个商店库存；店铺 / 仓库抢劫在 MVP 只保留规则接口，后续实现时必须触发节点事件链。
4. 玩家挑战一名 N3 长老，战斗读取其真实法宝、术法和随身消耗道具。
5. 长老战败后，掉落只来自随身资产和事件锁定资产；其洞府或宗门库房不自动掉落。
6. 宗主等 N4 每季度都有个人宏观行动；闭关、外出或亲自介入会影响宗门倾向或特定事件，但不额外增加宗门主行动数量。
7. 一个季度结算能同时处理玩家行动、宗门行动、N2 店铺刷新、N3 活跃 NPC 宏观行动、N4 必定宏观行动与资产日志。
8. 一个 N3 / N4 死亡事件链结束后，系统能按遗产分配规则处理随身资产、个人储藏、职务资产、宗门托管资产和正式后手。

## 14. 已确定决策记录

### 14.1 个人库存持久化阈值

**已确定：接受推荐，不设置 N2.5。**

规则口径：

- N3 以上 NPC 默认持久化个人库存。
- N2 不进入半角色化状态，不设置“N2.5 富商 / 大掌柜”中间层。
- N2 如需持有少量防身物、身份物或剧情物，使用特殊字段或事件锁定资产表达，不因此升级为完整经济角色。
- 商店、坊市、服务入口的主要资产仍归属于 ShopStock、MarketListing、SectStorage 或 NodeStorage。

### 14.2 宗主 / N4 个人行动与宗门行动的绑定程度

**已确定：接受推荐，但补充 N4 每季度必定有个人宏观行动。**

规则口径：

- N4 每季度必须生成个人宏观行动。
- N4 行动可以是闭关、外出、亲自介入宗门主行动、推动重大事件、处理内部危机、争夺资源窗口、稳定宗门局势等。
- 若 N4 行动与玩家、宗门主行动或关键节点发生交叉，进入事件链精算。
- 若未发生交叉，使用汇总结算写入状态变化、宗门倾向修正、传闻候选或隐藏世界日志。
- N4 个人行动不得无条件增加宗门主行动数量；宗门级结果仍必须归入宗门主行动、常态结算或事件预算。

设计理由：

- 如果 N4 只在活跃集命中时行动，会导致补偿滞后和状态失真。
- N4 是世界轴心 NPC / 势力代理，必须具备稳定推动世界演化的能力。

### 14.3 店铺可抢劫性

**已确定：接受推荐，MVP 只保留规则接口。**

规则口径：

- 店铺 / 仓库可以作为正式版可抢劫、查抄或洗劫对象。
- 抢劫目标是 ShopStock / NodeStorage / EventLocked 等资产容器，不是掌柜个人背包。
- 抢劫必须进入节点事件链，处理守卫、风险、声望、通缉、宗门关系、市场秩序和资产转移。
- MVP 不要求实现完整店铺抢劫玩法，只保留数据结构、事件接口和资产容器边界。

### 14.4 NPC 修炼追赶公式

**已确定：接受推荐，但 MVP 阶段 N3 不支持独立“宗门支持”输入。**

N3 惰性追赶公式暂定为：

```
inactive_quarters
+ npc_growth_profile
+ stipend_claim_profile
+ risk_profile
+ rng_namespace
→ summarized_state_delta
→ compact_log
```

规则口径：

- N3 未进入活跃集时，不逐季度模拟完整修炼行动。
- 重新进入活跃集时，用成长画像、已领取俸禄 / 基础供给、闭关季度数、风险画像和随机命名空间汇总修为变化。
- MVP 中，N3 修炼不读取独立的宗门支持 profile。
- 宗门对 N3 成长的支出与 NPC 修为增加之间的关联，先通过俸禄领取、基础供给或职责待遇表达。
- 关键 NPC 的精确修炼进度默认不作为常驻公开信息展示，只在交互、传闻、事件链或结算摘要中揭示结果。

### 14.5 NPC 死亡后的资产继承

**已确定：接受推荐，并制定统一遗产分配规则。**

规则口径：

- N3 / N4 死亡后，先结算死亡事件链。
- 死亡事件链负责处理战斗损坏、逃遁失败、法宝破碎、随身资产遗失、临终封存、遗言、现场控制权等即时结果。
- 死亡事件链结束后，再读取剩余资产容器并按遗产分配规则处理。
- 个人随身资产按事件结果处理。
- 个人储藏按继承、宗门回收、洞府隐藏、玩家追踪等规则处理。
- 宗门托管 / 职务资产归宗门，不随个人死亡流失。
- 正式后手资产按 SealedLegacy 规则处理，不因普通死亡自动暴露。
- 所有高价值遗产转移必须写入资产流水与日志。

## 15. 推荐定案方向

推荐采用：

> NPC 分层持久化 + 资产容器归属 + 关键 NPC 宏观行动模拟。
> 

理由：

1. 能解决“战斗开始才生成 NPC 库存”的经济可信度问题。
2. 能让关键 NPC 真正参与世界、宗门、角色之间的资源流转。
3. 能支持宗主、长老、竞争者等人物影响沙盒演化。
4. 不会把 MVP 推向全 NPC 生态模拟。
5. 与季度结算、宗门主行动、物品系统、后手系统和权威服务器架构兼容。

不推荐：

- **全 NPC 不持久化**：实现简单，但世界连续性、经济可信度和后手系统都会受损。
- **全 NPC 全量持久化**：理论真实，但性能、设计、调试和内容成本都过高，且与 MVP 不做深度 NPC 生态的边界冲突。

最终设计应把 NPC 视为三种东西的组合：

```
身份对象：保证世界连续性
经济接口：连接资产容器与交易 / 奖励 / 消耗
沙盒行动者：只有关键 NPC 才承担
```

这三者不必同时存在于每个 NPC 身上。
