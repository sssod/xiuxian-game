## 1. 子系统定位

S3 负责定义玩家角色在一个季度内如何投入时间、如何移动、如何抵达目标节点、如何执行节点操作、如何承担路途风险，以及行动结束后角色停留在哪里。

一句话定位：

> S3 决定玩家每季度“人在哪里、能去哪里、做什么、花多少行动格、冒多少风险、最后停在哪里”。
> 

### 1.1 S3 负责

- 角色季度行动规划。
- 6 个朔望行动格的时间预算。
- 角色当前位置、目标节点、路线与季度结束位置。
- 即时行动、移动行动、持续行动的基本分类。
- 移动方式、交通设施、中转与停靠规则。
- 路途中的事件判定、信息判定和行踪暴露上下文。
- 持续行动的 tick 推进、连续状态、打断和配置化原则。
- 客户端预览与服务端权威校验的边界。
- 离线 / 超时托管如何接入同一套行动格与 tick 结算。
- 向突破、后手、宗门行动、节点事件、存档与日志系统输出可用上下文。

### 1.2 S3 不负责

- 宗门行动收益、采纳判定与执行完成度公式。
- 突破事件链、前世后手事件链、节点事件链的具体分支。
- 修炼、探索、驻守、闭关等行动的最终数值收益。
- 战斗 / 斗法事件链内部结算。
- 多人强 PvP 规则。

这些内容分别下沉到 S4、S7、S10、S11、S13 或平衡文档。

## 2. 核心定案摘要

### 2.1 节点驱动的季度行动规划

S3 当前采用：

> 节点驱动的季度行动规划。
> 

玩家不是先从抽象行动列表选择主目标，而是先面对当前所在节点、当前节点可执行操作、当前移动方式下的可达范围，再通过节点选择自然形成本季度行动计划。

设计目标：降低行动规划的抽象感；强化当前位置与地图节点的存在感；避免让玩家直接填写 6 个行动格导致排班化；保留节点地图、交通方式、通行成本和季度结束位置的策略意义。

### 2.2 双层季度结构

每季度先处理宗门行动决策，再处理角色行动决策。

```
宗门行动决策阶段
→ 玩家提出宗门建议 / 决策提议
→ 系统即时反馈采纳、预计消耗、路线、风险和执行倾向
→ 进入角色行动决策阶段
→ 玩家规划本角色 6 个朔望行动格
→ 锁定提交
→ 服务端统一结算
```

宗门行动一般不受玩家角色当前位置限制，但角色亲自介入宗门行动时，必须进入 S3 的行动格、路线、节点和 tick 结算。

### 2.3 6 个朔望行动格

一个季度显性拆分为 6 个行动格，也可理解为 6 个半月 tick：

```
一月·朔
一月·望
二月·朔
二月·望
三月·朔
三月·望
```

行动格不是 6 次完整独立行动，而是本季度的时间预算。移动、执行、介入、撤出、休整、留驻等都从这 6 格中分配。

### 2.4 三类角色行动

S3 将玩家角色行动分为三大类：

1. 即时行动。
2. 移动行动。
3. 持续行动。

这三类行动共同构成角色季度计划。

### 2.5 Tick 是统一时间单位，不是统一收益公式

> tick 只是统一的时间结算单位，不是统一收益公式。
> 

不同持续行动可以有不同 tick 效果：修炼 / 闭关可有阶梯与平台，探索可提高线索发现率，驻守可提供稳定防护，建造可推进进度。

### 2.6 配置化原则

所有行动格消耗、标准周期、tick 收益参数、触发率、阈值、倍率均应配置化。规则代码只读取配置，不直接写死具体数值。

### 2.7 本轮边界定案（2026-04-25）

本轮追加定案用于收敛 S3 的行动语义与跨系统边界。后续规则文档、UI 文案和系统接口统一使用以下术语：宗门行动阶段、角色行动阶段、6 个朔望行动格、即时行动、移动行动、持续行动。

1. 即时行动边界：即时行动可以改变信息、界面状态、轻量库存状态或轻量行政状态，但不能推进时间型进度、风险型事件链、地图控制、突破、后手回收、秘境探索。资源转移类即时行动必须受位置、权限、库存、交易对象和日志约束。
2. 一般持续操作限制：MVP 中，所有玩家主动发起的一般持续行动都受“初始节点 + 第一个目标节点”的持续操作限制。例外仅包括移动行动与交通设施、休整 / 警戒 / 停留、已触发插入事件链后的事件内部选择、服务端强制触发的危机 / 中断 / 撤离流程。
3. 不移动时的限制：如果玩家本季度不移动，同一节点也只能选择一个主要持续行动。该行动可以消耗多个行动格或形成连续状态，但不能在同一节点组合多个收益、调查、社交、采集等一般持续行动。
4. 跨季度连续状态：连续状态的存在与本季度是否继续投入行动格分离。下季度开始时，玩家需要继续投入兼容行动格才延续该状态的收益或进度；选择不兼容行动则视为中断或退出。离线托管只在安全、低风险、无重大分支的情况下自动延续。
5. 插入事件链中断权：插入事件链可以中断 S3 时间轴。S3 负责提供触发 tick、触发位置、剩余行动格、当前行动状态；事件链系统负责返回继续原计划、消耗剩余行动格、强制中断本季度计划、改变位置 / 状态 / 连续行动，或进入死亡、转世、特殊结算。
6. 路线规划粒度：MVP 默认采用“目标节点 + 移动方式 + 可选显式停靠点”。不做完整逐边手动排路；可以预留路线意图，但 MVP 不展开复杂路线策略。
7. 移动判定可见性：S3 只输出移动上下文与暴露标签。S10 / S13 / S14 决定事件、传闻、多人可见性和日志展示。
8. 托管行动优先级：保命 / 避险 > 不暴露核心后手 > 延续安全连续状态 > 巩固修炼或基础修炼 > 维持低风险宗门职责 > 休整 / 警戒 / 停留。
9. 协同行动边界：S3 只判断协同资格，包括角色是否在正确节点、是否处于正确 tick 或事件窗口、是否选择介入、路线和位置是否合法。S7 决定协同带来的执行完成度、贡献、声望、收益和风险。
10. 季度结束位置：季度结束位置必须是 S3 的一级输出，并由服务端权威写入。客户端只显示预计结束位置；事件中断、危险撤离、秘境关闭、交通失败等可以改变实际结束位置。
11. 交通路线模板：MVP 不做自动复合交通路线。正式版可考虑保存常用路线模板，但仍需显式消耗资源、权限并承担风险。
12. 休整 / 警戒 / 停留定位：三者是节奏、风险和位置管理工具，不是主要成长收益来源。
13. 日志与回放契约：S3 每季度必须输出可回放的行动时间轴摘要，作为 S14 技术、调试、日志和结算追踪需求输入。

### 2.8 S3 收尾状态与 Handoff

本页到此进入收尾状态。S3 的职责不是定义所有行动的收益、概率、事件分支或 UI 细节，而是作为以下系统的时间、位置、路径、行动格、连续状态和事件触发底座。

后续子系统应从 S3 获取的输入包括：角色起始位置、目标节点、路线与停靠点、移动方式、行动格占用、当前 tick、剩余行动格、季度结束位置、连续状态、托管状态、暴露上下文、协同行动资格、插入事件触发时点。

S3 向后续系统输出的边界如下：

- S4 突破事件链：获取突破触发时点、角色所在节点、剩余行动格、当前连续状态、突破地点上下文、事件链中断与返回接口。
- S7 宗门行动与执行完成度：获取角色是否亲自抵达宗门行动目标、是否在正确 tick 介入、是否满足协同行动资格。
- S10 节点事件与世界事件：获取离开 / 进入 / 途经 / 停靠 / 路途中 tick 的事件判定上下文，以及暴露标签。
- S11 前世后手与隐藏层：获取后手搜寻、回收、破解等持续行动的节点、tick、进度延续和中断上下文。
- S13 多人互动与冲突边界：获取玩家位置、行动公开性、行踪暴露上下文和多人间接竞争所需的行动日志入口。
- S14 存档、数据结构与技术架构：获取可回放行动时间轴、服务端权威结算摘要、季度结束位置和可追踪日志。

后续不应继续在 S3 中展开以下内容：各行动具体收益、修炼 / 闭关成长曲线、探索发现率、路途事件概率、交通方式速度与消耗、托管收益公式、突破检定、后手隐藏等级、宗门协同收益、节点事件表、UI 具体字段、数据库 schema。上述内容应进入对应子系统或数值平衡文档。

下一步建议进入 S4：突破事件链子系统。S4 第一轮只应确定突破链定位、MVP 两段突破链骨架、准备维度、S3 触发 / 中断接口、失败结果类型和轮回账本接口，不直接展开公式与数值。

## 3. 角色行动标准交互流程

角色进入决策阶段后，标准流程为：

```
进入角色决策阶段
→ 自动弹出当前角色所在节点面板
→ 展示当前节点可执行操作
→ 展开当前移动方式下的可达区域范围
→ 玩家可在初始节点执行 0–1 次一般持续操作
→ 玩家可执行当前节点允许的即时行动
→ 玩家可点击“离开”关闭当前节点操作面板
→ 玩家可切换移动方式，改变可达区域范围
→ 玩家点击新目标节点，选定目的地
→ 系统按当前移动方式预扣行动格
→ 自动弹出目标节点可执行操作
→ 玩家可切换移动方式比较行动格开销
→ 玩家可在目标节点执行 0–1 次一般持续操作
→ 若行动格归零，进入待锁定预案
→ 若仍有剩余行动格，可继续移动，但后续节点只能休整、警戒或停留
→ 玩家确认锁定后提交本季度行动
```

### 3.1 待锁定预案

行动格归零后不立即提交，而是进入“待锁定预案状态”。在该状态下，玩家仍可退回上一步、修改移动方式、修改目标节点、修改节点操作、清空本季度计划、查看预期结算。只有玩家点击“锁定本季度行动”后，计划才正式提交服务器。

### 3.2 规划阶段与结算阶段分离

玩家在规划阶段选择节点、路线、移动方式和行动。服务端在结算阶段根据锁定计划生成权威 tick 时间轴，并在每个 tick 上执行行动合法性校验、移动与停靠推进、行动进度推进、路途与节点事件判定、世界状态变化、日志与传闻输出。

## 4. 行动类型规则

### 4.1 即时行动

即时行动是轻量、短时间、低风险的 UI 行为。

特征：

- 不消耗行动格。
- 不计入每季度持续操作次数。
- 通常少于游戏内 1 小时。
- 通过 UI 面板直接完成。
- 可受节点、权限、职位、库存、宗门身份、资源或界面入口限制。
- 不额外设置每季度次数限制，但必须严格审查哪些操作可归入即时行动。

可归入即时行动的例子：查看个人信息、调整装备、领取俸禄、贡献资源、整理随身空间、整理洞府库存、坊市一口价交易、接取宗门任务、查看轮回账本、查看宗门状态、查看节点情报。

边界原则：

> 即时行动不能替代持续行动，不能推进高价值事件链，不能完成实质探索、突破、秘境推进、前世后手回收、斗法、节点危机处理等需要时间投入的行为。
> 

### 4.2 移动行动

移动行动用于节点间移动、交通设施使用和路线转移。

特征：

- 消耗行动格。
- 每回合没有次数限制。
- 每个移动段至少消耗 1 个行动格。
- 一个移动段可以包含多条地图边。
- 移动可改变当前规划位置和季度结束位置。
- 移动可触发路途风险、路线权限检查、信息判定、行踪判定或节点状态检查。

飞舟、传送阵、传送门、渡口、驿站等交通设施统一归入移动行动。它们不占用节点一般持续操作次数，但会消耗行动格，并可消耗灵石、票据、权限、阵法状态、宗门资格或其他资源。

### 4.3 持续行动

持续行动是需要较长时间投入的节点操作。

特征：

- 消耗行动格。
- 占用节点持续操作机会。
- 通常用于修炼、调查、探索、拜访、秘境推进、后手回收、宗门介入、节点危机处理等。
- 可以按 tick 产生进度、收益、风险或事件入口。
- 可以形成跨季度连续状态。

## 5. 节点持续操作限制

### 5.1 一般持续操作限制

每回合玩家最多只能在两个特定节点执行一般持续操作：

1. 初始节点：本季度开始时角色所在节点。
2. 第一个目标节点：玩家本季度主动选择并移动抵达的第一个目标节点。

玩家可在初始节点执行 0–1 次一般持续操作，也可在第一个目标节点执行 0–1 次一般持续操作。

### 5.2 防组合爆炸限制

如果玩家在初始节点不执行持续操作，而是直接移动到第一个目标节点并执行持续操作，之后即使还有剩余行动格，也不能再移动到第二个目标节点后执行一般持续操作。

不允许出现：

```
初始节点不操作
→ 移动到目标节点 A 并执行一般持续操作
→ 再移动到目标节点 B 并执行一般持续操作
```

### 5.3 目标节点行动后的剩余行动格

第一个目标节点的持续操作结束后，若仍有剩余行动格，玩家可以继续移动到第二个目标节点。

但抵达后只能选择：

- 休整：持续行动，消耗 1 行动格。
- 警戒：持续行动，消耗 1 行动格。
- 停留：不消耗行动格。

不能在第二个目标节点执行普通收益操作、调查操作、秘境操作、后手操作、宗门介入操作或其他一般持续操作。

## 6. 移动、交通设施与路线规则

### 6.1 交通设施归类

飞舟、传送阵等节点设施归入移动行动，不归入持续行动。它们的主要功能是改变位置，不应占用节点持续操作次数，应通过行动格、资源、权限和设施状态约束。

### 6.2 消耗合并规则

飞舟、传送阵等交通设施的执行消耗与相邻移动消耗合并计算。

默认规则：

1. 默认向前合并：当玩家从当前节点移动到交通设施节点，并继续使用交通设施前往下一节点时，交通设施使用消耗优先与之前的移动段合并计算。
2. 起点例外，向后合并：如果本季度开始时角色就在传送门、飞舟站或类似交通设施所在节点，则交通设施使用消耗向后与离开该节点后的移动段合并计算。
3. 最低消耗原则：每个移动段至少消耗 1 个行动格；一个移动段可以包含多条地图边。
4. 边界兜底：其他复杂边界情况按照至少消耗 1 行动格处理。

### 6.3 移动方式切换规则

玩家可以在规划阶段切换移动方式，以比较不同交通方式下的可达范围、行动格消耗、资源消耗、路线风险、权限要求和暴露风险。

如果切换移动方式后，当前已选目标节点在新移动方式下不可达：不强制退回原节点；保留目标节点预览；标记为“当前移动方式不可达”；禁用确认按钮；允许玩家恢复原移动方式、重新选择目标节点，或取消目标选择并返回当前规划位置面板。

### 6.4 中间节点与停靠规则

自动路径经过的中间节点默认只是途经节点。系统不弹出该节点的持续操作、即时行动、交通设施、商店或宗门事务入口。

只有玩家主动将某个节点设为停靠节点、中转节点或当前目标节点时，才可查看该节点可执行操作。

如果玩家要使用飞舟、传送阵、渡口、驿站等交通设施，必须显性把对应节点设为停靠 / 中转节点。

系统不自动执行以下复合路线：

```
前往坊市
→ 自动购票
→ 自动乘飞舟
→ 自动下船
→ 自动继续前往目标节点
```

除非后续另行设计“预设路线模板”，否则 MVP 不采用自动中转。

### 6.5 移动中的事件与信息判定

移动不开放中间节点操作，但会参与事件判定、信息判定和行踪判定。

判定范围包括离开节点、进入节点、途经节点、目标节点，以及每个行动格结束时所在的路线段。

例如：

```
A → B → C → D
```

若本次移动共消耗 3 个行动格，则结算中应覆盖：离开 A、进入 B、离开 B、进入 C、离开 C、进入 D，以及每个行动格结束时的“路途中”事件判定。

行动格结束时如果刚好抵达节点 C，则可能同时存在两类语义：抵达 C；赶路途中抵达了 C。由于内置冷却或去重规则通常只会触发 1 项，顺序不应影响最终结果。若需要显式顺序，同一 tick 内暂定为：

```
节点离开判定
→ tick 结束的路途判定
→ 节点进入判定
```

## 7. 持续行动体系

持续行动分为两大类：通用持续行动与特殊持续行动。特殊持续行动再分为两类：通用持续行动的进阶形态，以及节点特有持续行动。

### 7.1 通用持续行动

通用持续行动是玩家在多数节点上都能理解和尝试的基础行为。

当前通用持续行动包括：

```
休整 / 警戒 / 探索 / 修炼
```

### 7.2 通用持续行动的进阶形态

结构为：

```
基础通用行动 + 节点 / 建筑 / 权限 / 关系 / 状态条件 = 进阶持续行动
```

示例：警戒 → 驻守；修炼 → 闭关；休整 → 疗伤 / 整备；探索 → 深入探索 / 秘境探查 / 后手搜寻。

关键规则：

> 进阶行动替代基础行动，而不是与基础行动叠加。
> 

例如选择“闭关”不是先修炼一次再额外闭关一次；闭关本身就是本次持续行动。

### 7.3 节点特有持续行动

节点特有持续行动来自具体节点、资源槽、建筑槽、事件槽或隐藏层。

来源包括节点类型、基础资源槽、人工建筑槽、节点事件、隐藏层、宗门权限、任务状态、NPC 或组织关系。

示例：开采矿石、采集灵药、建造建筑、修复建筑、调查资源异变、处理妖兽潮、搜寻前世洞府、破解前世阵法、拜访关键 NPC。

### 7.4 已定边界

1. 通用探索只负责低到中价值的信息揭示和节点认知提升；高价值秘境、核心后手、禁地、重大节点危机等应转化为特殊持续行动或事件链入口。
2. 通用修炼提供基础收益，高收益修炼应依赖洞府、灵气节点、宗门设施、修炼资源、闭关条件或秘境环境。
3. 个人驻守与宗门驻守必须区分；二者同节点同季度发生时，可形成协同效果，但具体公式进入 S7。
4. 个人采集 / 建造不能替代宗门级开采 / 建设；个人行为偏小规模收益、关键材料、临时设施、个人洞府或亲自监督。
5. “通用 / 进阶 / 节点特有”主要是设计与数据分类，UI 应展示玩家可理解的行动名称、消耗、收益方向、风险和限制，而不是强迫玩家理解内部术语。

## 8. Tick 结算与连续状态

本节只定义行动存在性、行动周期、tick 推进方式、连续状态规则和参数维护原则。具体收益数值、成长曲线、发现率、风险概率等核心循环数值后续再展开。

### 8.1 标准周期参数暂定，但必须可配置

当前参考周期：

```
休整：1 格
警戒：1 格
探索：3 格
修炼：4 格
闭关：6 格
```

这些数值在系统层暂定为 MVP 初始参数，但不写死为规则常量。

实现要求：所有行动格消耗、标准周期、tick 收益参数、触发率、阈值、倍率均应配置化；常量与变量分开维护；规则代码只读取配置，不直接写死具体数值；后续平衡阶段可以调整参数而不改动核心行动系统。

### 8.2 不采用统一 tick 收益公式

持续行动不设计一套全局统一的 tick 收益公式。每类持续行动根据自身设计定义 tick 效果。

示例：修炼 / 闭关可以随连续 tick 增加而逐步进入状态，收益阶梯上升，直到进入稳定平台；探索可以每 tick 根据已经持续的探索 tick 数，提高线索发现、节点认知或事件触发概率；驻守可以按 tick 提供稳定防护、警戒、影响力维持或事件响应加成，不一定随连续时间增强；建造可以每 tick 增加施工进度；后手搜寻可以每 tick 增加线索进度或破解进度。

### 8.3 世界按 tick 推进

一个季度包含 6 个朔望行动格，也即 6 个半月 tick。

世界状态、角色行动、节点事件、秘境窗口、修炼收益、探索判定等均可在 tick 级别推进。

同一 tick 内的原则暂定为：

> 先结算角色行动在本 tick 的效果，再处理本 tick 到期的世界状态变化。
> 

示例：某秘境将在本 tick 结束时关闭。本 tick 内仍在秘境中的角色先完成本 tick 的秘境内探索判定；正在修炼者先完成本 tick 的修炼收益结算；然后进入秘境关闭流程。

### 8.4 所有持续操作统一采用连续状态规则

当前定案：

> 所有持续操作都采用类似的连续状态规则。只要一个持续操作的实际消耗、持续进度或状态没有在本季度内自然结束，它就可以在 tick 层面延续到下个季度。不存在一个单独的“支持跨季度持续行动”分类。
> 

连续状态不是某些行动的特殊能力，而是 tick 结算的自然结果。只要新回合的操作不打断上一回合的操作，状态就可以从旧回合续接到新回合。

连续状态不必然意味着收益增强。不同持续行动可以有不同设计。

### 8.5 状态打断原则

持续行动在以下情况下通常会被打断或退出：玩家新回合选择了不兼容的持续行动；玩家移动离开当前行动所需节点；当前节点状态变化导致行动条件不再满足；事件链强制中断，例如秘境关闭、妖兽袭击、阵法失控；玩家主动选择停留、休整、警戒等替代行动；托管策略选择保命、撤离或稳健行动。

具体打断后果不在 S3 中定数值，只定义后续系统需要返回：是否保留部分进度；是否产生失败结果；是否触发风险事件；是否进入撤离、受伤、暴露或中断状态。

## 9. 客户端预览与服务端权威结算

### 9.1 基本原则

客户端负责清晰展示可选项、预估消耗、可达范围、风险提示和预计结束位置。

服务端负责最终合法性校验、权威 tick 时间轴生成、事件触发、状态写入和日志输出。

> 客户端可以预览，不能裁决；服务端必须裁决，并能重放或追踪关键结算步骤。
> 

### 9.2 服务端从计划生成 tick 时间轴

锁定后的 `QuarterActionPlan` 应被服务端展开为权威时间轴。

```
QuarterActionPlan
→ 校验起点、路线、移动方式、行动格、资源、权限
→ 拆分为 6 个 tick 的行动片段
→ 为每个 tick 标记：位置 / 路线段 / 行动 / 事件判定点 / 状态变化
→ 逐 tick 结算
→ 输出角色状态、位置、行动结果、事件入口、日志与传闻
```

### 9.3 权威 tick 时间轴需要表达

每个 tick 至少应能表达：tick 序号；起始位置或路线段；结束位置或路线段；当前执行的行动片段；是否正在移动；是否处于途经节点、停靠节点、目标节点或路线段；是否触发离开判定、路途判定、进入判定；是否消耗资源或权限；是否更新持续行动进度；是否触发插入事件链；是否产生世界日志或玩家可见传闻。

### 9.4 客户端预览应展示但不保证

客户端可以展示当前移动方式下的可达范围、预计行动格消耗、预计资源消耗、预计路线风险、预计目标节点可执行操作、预计季度结束位置、预计连续状态是否延续。

但最终结果可能因服务端结算时的世界状态变化、节点事件、权限变化、资源变化、秘境关闭、他人行动或随机判定而改变。

## 11. 与其他子系统的接口边界

S3 是多个高价值系统的入口层。突破、后手、宗门介入、节点事件和托管行为都不应绕过 S3 直接发生。

### 11.1 对 S1 时间、房间与回合推进子系统

S3 输出：已锁定的角色季度行动计划；行动格消耗与 tick 时间轴；离线 / 超时托管计划；是否进入插入事件链；结算完成后的角色位置和状态。

S1 负责决定季度何时开始、何时锁定、何时统一结算，以及插入事件链如何暂停或恢复普通季度流程。

### 11.2 对 S4 突破事件链子系统

S3 负责回答：玩家是否在本季度抵达突破地点；玩家是否投入足够行动格进行突破准备或突破触发；玩家是否处于闭关、护法、秘境修炼、宗门培养等可作为突破输入的行动状态；玩家季度结束时是否仍处于可继续突破准备的连续状态；玩家本季度是否因移动、事件、托管或节点变化打断突破准备。

S4 负责突破事件链内部阶段、检定、结果、失败原因和跨世经验。

### 11.3 对 S7 宗门行动与执行完成度子系统

S3 输出：玩家是否亲自抵达宗门行动目标节点；玩家是否投入行动格介入宗门行动；玩家介入的 tick 范围和现场状态；玩家是否与宗门行动形成协同行动；玩家路途风险、迟到、撤离或中断情况。

S7 负责宗门行动采纳、执行完成度、贡献、声望、收益和节点影响力修正。

### 11.4 对 S8 / S9 节点地图、控制与影响力子系统

S3 读取：节点连接关系、通行成本、权限门、状态门、风险门、节点控制者、影响力与封锁状态、交通设施状态。

S3 输出：实际经过路线、目标节点、停靠 / 中转节点、角色季度结束位置、行踪暴露上下文、可用于影响力 / 控制权事件 / 节点封锁事件的行动记录。

### 11.5 对 S10 节点事件与世界事件子系统

S3 输出：玩家所在节点、途经节点、路线段和目标节点；每个 tick 的事件判定点；行动类型、持续时间、风险上下文、暴露上下文；是否正在探索、警戒、驻守、后手搜寻、秘境推进等。

S10 负责具体事件刷新、响应窗口、事件链分支、奖励、损失和节点变化。

### 11.6 对 S11 前世后手、遗产与隐藏层子系统

S3 负责：玩家是否抵达后手所在节点或线索节点；玩家是否选择搜寻、破解、回收、封存或维护等持续行动；后手相关行动持续了多少 tick；行动是否被移动、事件、节点状态或托管打断；是否触发后手回收事件链入口。

S11 负责正式后手状态、隐藏层揭示、防护、暴露、损失、回收结果和轮回账本更新。

### 11.7 对 S13 多人互动与冲突边界子系统

S3 可提供：多名玩家是否处于同一节点、同一路线段或同一事件窗口；玩家是否同时介入同一宗门行动或节点事件；玩家行动是否产生间接竞争的时间与空间上下文。

MVP 不要求 S3 支撑强 PvP、玩家追杀、离线袭击或直接破坏他人突破。

### 11.8 对 S14 存档、数据结构与技术架构子系统

S3 需要被存档与回放的内容包括：锁定行动计划、服务端展开后的 tick 时间轴、行动合法性校验结果、连续状态、角色位置变化、事件入口与结果引用、随机判定关键结果、世界日志与玩家可见传闻引用。

## 12. 离线 / 超时托管接入

离线和超时玩家使用同一套行动格、节点、tick 和连续状态规则，不另开一套隐藏结算系统。

### 12.1 托管目标

托管策略应满足：不阻塞回合；不让玩家严重掉队；不替玩家做重大冒险选择；不主动突破；不主动发动战争；不主动叛宗；不主动暴露核心后手；不做高风险不可逆选择。

### 12.2 托管可生成的行动计划

托管可以优先生成原地修炼、巩固境界、休整、低风险宗门日常、洞府或后手维护、自动防御、必要时保命撤离。

托管不应默认生成高风险秘境探索、主动突破、主动斗法、高风险远行、破坏他人资产、暴露或搬迁核心后手。

### 12.3 托管与连续状态

如果玩家上回合处于可安全延续的连续状态，例如闭关、修炼、疗伤或低风险维护，托管可优先延续该状态。

如果连续状态变得不安全，例如节点封锁、秘境关闭、妖兽袭击、阵法失控，托管应优先选择保命、撤离或稳健中断，而不是强行追求收益。

## 13. UI、日志与可读性要求

### 13.1 UI 必须持续展示的状态

角色行动规划 UI 需要持续展示：当前季度起点、当前规划位置、当前查看节点、当前移动方式、可达范围、剩余行动格、已执行的一般持续操作数量、初始节点是否已执行持续操作、第一个目标节点是否已执行持续操作、当前节点还能否执行一般持续操作、当前节点可用即时行动、当前节点可用交通设施、当前路线是否包含显性停靠 / 中转节点、预计季度结束位置、是否已进入待锁定预案、当前计划是否可锁定、计划锁定后的主要风险提示。

### 13.2 日志与传闻边界

世界日志默认不是玩家可见信息。

玩家端应表现为“世界传闻”“宗门情报”“节点消息”或“个人感知”，这些内容是世界日志的子集。

原则：世界日志偏系统记录，用于测试、回放、调试和语义追踪；玩家传闻偏表现层，只展示角色可合理知道、推断或听闻的信息；S3 输出行踪、路线、节点、tick 和触发上下文，S10 / S14 决定如何写入日志与传闻。

## 14. MVP 验收用例

S3 的 MVP 验收不看收益数值是否最终平衡，而看它能否稳定支撑 M0→M3 的核心闭环。

### 14.1 基础规划用例

玩家在当前节点完成：

```
查看节点 → 执行即时行动 → 选择修炼 / 探索 / 休整 → 锁定计划 → 服务端结算
```

要求：行动格扣除正确；计划可预览；服务端能生成 tick 时间轴；季度结束位置正确。

### 14.2 移动 + 目标节点行动用例

玩家从初始节点移动到目标节点，并在目标节点执行持续行动。

要求：路线可达性正确；移动格消耗正确；目标节点持续行动限制正确；途经、离开、进入和路途中判定点正确。

### 14.3 交通设施用例

玩家显性停靠交通节点，使用飞舟、传送阵、渡口或驿站。

要求：交通设施归入移动行动；不占用一般持续操作机会；资源、权限、设施状态校验正确；不自动执行复杂复合路线。

### 14.4 持续行动跨季度用例

玩家上季度开始闭关、探索、建造、后手搜寻或疗伤，并在下季度继续。

要求：连续状态可保存；新季度选择同一兼容行动时可续接；新季度移动或选择不兼容行动时正确打断；打断结果可交由对应子系统处理。

### 14.5 突破准备入口用例

玩家移动至合适突破地点，进行闭关、修炼或突破准备。

要求：S3 能向 S4 输出地点、行动格投入、连续状态、打断状态和 tick 进度；S3 不直接决定突破成败。

### 14.6 后手搜寻入口用例

玩家根据轮回账本线索前往某节点，选择后手搜寻、破解或回收行动。

要求：S3 能向 S11 输出节点、行动格投入、持续 tick、路线风险、是否被打断；S3 不直接决定后手内容、污染、损失或回收结果。

### 14.7 宗门协同行动用例

宗门本季度探索 / 驻守 / 远征某节点，玩家本人也前往该节点介入。

要求：S3 能判断玩家是否抵达目标节点；S3 能输出玩家介入 tick、迟到、提前撤离或现场参与情况；S7 根据这些输入决定协同效果、贡献、声望和执行完成度修正。

### 14.8 离线 / 超时托管用例

玩家未提交行动。

要求：系统能生成稳健托管计划；托管计划使用同一套行动格和 tick 结算；不主动突破，不主动高风险远行，不做高风险不可逆选择。

## 16. Handoff 摘要

后续只读本节时，应掌握以下上下文：

- S3 负责玩家角色每季度的时间、空间、行动合法性、移动、持续状态和事件入口。
- 当前采用节点驱动的季度行动规划，而不是抽象行动列表优先。
- 每季度先进行宗门行动决策，再进行角色行动决策。
- 角色行动使用 6 个朔望行动格，它们是季度时间预算，不是 6 次完整独立行动。
- 行动分为即时行动、移动行动、持续行动。
- 即时行动不消耗行动格，但不能推进高价值事件链。
- 移动行动消耗行动格，改变位置，并参与路途风险、信息和行踪判定。
- 持续行动消耗行动格，承载修炼、探索、后手搜寻、节点事件介入等需要时间投入的行为。
- 每回合一般持续操作最多发生在初始节点和第一个目标节点；之后只能休整、警戒或停留。
- 飞舟、传送阵、渡口、驿站等交通设施属于移动行动，不占用一般持续操作机会。
- 中间节点默认只是途经节点；玩家要使用交通设施或节点操作，必须显性设为停靠 / 中转 / 目标节点。
- 移动会对离开节点、进入节点、途经节点、目标节点和每个 tick 结束路线段进行事件、信息与行踪判定。
- 同一 tick 内若需排序，暂定为节点离开判定 → tick 结束路途判定 → 节点进入判定。
- 持续行动分为通用持续行动、通用持续行动的进阶形态、节点特有持续行动。
- tick 是统一时间结算单位，不是统一收益公式。
- 所有持续操作都可以按连续状态规则跨季度延续；不存在单独的“支持跨季度持续行动”分类。
- 连续状态是否增强收益由具体行动决定，不由 S3 统一规定。
- 客户端负责预览，服务端负责权威校验、tick 时间轴、事件触发、状态写入和日志输出。
- 离线 / 超时托管必须接入同一套行动格与 tick 规则，不另开隐藏结算系统。
- 世界日志默认玩家不可见；玩家端看到的是传闻 / 情报 / 消息等世界日志子集。
- S3 不直接决定收益，但必须稳定决定时间投入、空间位置、行动合法性、连续状态、风险暴露上下文和事件链入口。
