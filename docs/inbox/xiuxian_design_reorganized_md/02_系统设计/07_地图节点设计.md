# 地图节点设计

更新日期：2026-05-11

## 1. 当前结论

地图采用有向带权节点图。地图主单位是大尺度地理节点或空间区块，路线是节点之间的有向边；资源槽、资源槽附属设施、事件窗口、隐藏层、后手、宗门清点和遗留设施只挂载在节点或路线之上，不替代节点本身。

节点类型只描述地理或空间尺度，不描述建筑、组织、市场、传送点或功能入口。宗门山门、宗门驻地、坊市、村镇、传送阵、关隘、渡口、秘境入口和洞府入口等都不是节点类型；它们应作为节点中的资源槽附属设施、机会窗口、隐藏层、路线条件或状态标签表达。

地图不是静态菜单，而是共享世界中的空间状态机。玩家移动、修炼、探索、资源采集、宗门行动、NPC 行动、事件、秘境窗口、传闻、正式后手、宗门清点和宗门外遗留设施都可以改变节点状态。

地图变化按连续世界时间推进：

```text
world_day / world_hour 是地图主时间；
hour_tick 是服务器推进地图状态的最小结算步；
macro_period_id 只用于季节、旬月、资源批次、灾变期等宏观内容标签，不作为玩家回合；
所有节点、路线、资源、可见性和事件窗口变化都必须能写入结果包和回放。
```

## 2. 地图总状态

`WorldMapState` 是地图运行时主状态。

```yaml
WorldMapState:
  map_id: string
  current_world_day: int
  current_world_hour: int
  current_macro_period_id: string
  node_states: dict[node_id, NodeState]
  route_states: dict[route_id, RouteState]
  active_region_effects: list[RegionEffect]
  resource_budget_refs: list[string]
  rumor_pool_refs: list[string]
  visibility_overrides: dict
```

规则：

1. `current_world_day` 与 `current_world_hour` 必须和房间权威时间同步。
2. 地图系统只输出变化结果，不绕过权威结算直接改写角色、宗门、库存或经济状态。
3. 地图可生成的结果包括 `node_delta`、`route_delta`、`resource_slot_delta`、`visibility_delta`、`event_window_delta`、`risk_level_delta`、`rumor_entries`、`ledger_entries` 和日志条目。

本文件中的“结果包”指权威结算可合并的状态变化集合；“回放”指按世界时间记录的可审计事件序列。地图只负责生成这些变化和记录，不负责直接提交最终状态。

## 3. 节点运行字段

`NodeState` 记录节点当前运行状态。旧版 `WorldNode` 可作为内容模板名保留，但运行时主字段使用 `NodeState`。

```yaml
NodeState:
  node_id: string
  node_type: mountain_region | valley_region | forest_region | river_lake_region | plain_region | underground_region | ruin_region | secret_realm_region | special_region
  node_scale: area | large_region | pocket_realm
  node_level: int
  display_name: string
  region_id: string
  owner_faction_id: string | null
  controlling_influence: dict[faction_id, number]
  risk_level: low | medium | high | unknown
  aura_profile: object
  resource_slots: list[NodeResourceSlot]
  facility_refs: list[string]
  active_events: list[string]
  active_windows: list[OpportunityWindow]
  visibility_state: object
  hidden_layer_refs: list[string]
  contingency_refs: list[string]
  sect_clearance_refs: list[string]
  remnant_site_refs: list[string]
  route_edge_refs: list[string]
  node_state_tags: list[string]
  cooldown_tags: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `node_type` | 大尺度地理或空间类型，不表达宗门、坊市、传送阵、秘境入口等设施或功能身份 |
| `node_scale` | 节点空间尺度；MVP 默认是可容纳大量资源槽和多类设施的大区域，少数秘境内部节点可使用 `pocket_realm` |
| `node_level` | 节点等级，影响自然生成资源槽基线数量、资源品级范围、灵气浓度、风险强度和可建设规模上限 |
| `owner_faction_id` | 当前主控制势力；无人稳定控制时为空 |
| `controlling_influence` | 各势力在节点上的影响力分布，是控制权变化的基础 |
| `risk_level` | 节点风险等级，驱动移动提示、自动兜底和托管默认 |
| `aura_profile` | 节点整体灵气密度、品阶、相性、污染、稳定度和修炼修正；受节点等级、资源槽和附属设施共同影响 |
| `resource_slots` | 节点自然、半自然、空间、灵气、生态或组织控制的广义资源承载位 |
| `facility_refs` | 节点上已存在或可使用的设施索引；设施必须可追溯到某个广义资源槽 |
| `active_windows` | 秘境入口、资源名额、节点危机、短期交易、突破护法机会等限时窗口 |
| `hidden_layer_refs` | 未完全公开的隐藏空间、路线、资源、线索、旧洞府、伏笔事件引用 |
| `contingency_refs` | 正式后手记录引用；MVP 主要对应真灵藏宝 |
| `sect_clearance_refs` | 宗门管辖洞府、宗门托管资产或职务资产的清点、锁定和回收记录引用 |
| `remnant_site_refs` | 宗门外个人洞府、普通藏宝、旧洞府线索、失落库存或可开启遗留设施引用 |

`danger_level` 不再作为地图节点字段使用。若旧事件模板中仍出现 `danger_level`，应迁移为节点 `risk_level` 或事件自身的风险描述标签，不能同时作为地图节点的第二套风险字段。

## 4. MVP 地理节点类型

MVP 节点类型只保留地理区块大类。大多数节点在空间尺度上应足够大，可以容纳大量自然资源槽、人工扩展资源槽、设施、隐藏层和事件窗口。节点功能由 `facility_refs`、`resource_slots`、`active_windows`、`node_state_tags`、控制权和可见性共同表达，不通过 `node_type` 表达。

MVP 至少支持以下节点类型：

| 地理类型 | `node_type` | 作用 |
| --- | --- | --- |
| 山脉 / 山域 | `mountain_region` | 宗门山门、洞府、矿脉、灵脉、山道、关隘、传送阵、禁地和隐藏层的常见承载区 |
| 谷地 / 盆地 | `valley_region` | 药谷、灵田、聚落、宗门外据点、妖兽巢穴和资源争夺的承载区 |
| 林野 / 荒原 | `forest_region` | 探索、妖兽生态、灵植群落、野外事件、隐藏路线和普通资源的承载区 |
| 河湖 / 水域 | `river_lake_region` | 渡口、水路、灵泉、湖泽秘境、水产资源和路线封锁的承载区 |
| 平原 / 聚落周边 | `plain_region` | 村镇、坊市、农田、驿道、低到中风险事件和人流交易的承载区 |
| 地下 / 洞窟区 | `underground_region` | 洞府、地窟、矿洞、地下遗迹、藏宝和隐蔽空间的承载区 |
| 遗迹 / 古战场区 | `ruin_region` | 古遗迹、旧战场、破败宗门、历史事件、遗留设施和高风险资源的承载区 |
| 秘境 / 独立空间 | `secret_realm_region` | 少数长期存在、可反复观察、探索和争夺的秘境内部空间；入口本身仍是机会窗口、设施或路线条件 |
| 特殊地理区块 | `special_region` | 剧情异象、世界裂隙、不可归入上列的定制空间 |

宗门山门、宗门大殿、坊市、村镇、传送阵、渡口、关隘、洞府入口等应作为设施或资源槽附属内容挂在上述地理节点中。例如“青云宗山门”应是某个 `mountain_region` 节点中的宗门设施群，而不是 `sect` 节点；“青木坊市”应是 `plain_region`、`valley_region` 或 `mountain_region` 中的市场设施，而不是 `market` 节点。

普通道路、山路、水路和隐藏通道默认是 `RouteState`，不是独立节点。渡口、关隘、传送阵、山道要冲等有状态交通对象也优先作为节点内设施、路线条件或路线状态建模；只有当其本身扩展成大尺度地理区块时，才按对应地理节点类型建模。

## 5. 路线与移动

路线使用有向带权边。双向通行应建成两条路线，因为两侧成本、风险和通行条件可能不同。

```yaml
RouteState:
  route_id: string
  from_node_id: string
  to_node_id: string
  base_cost_hours: int
  current_cost_hours: int
  route_type: road | mountain_path | river | teleport | hidden | rumor
  passability: open | blocked | conditional | unknown
  requirements: list[object]
  risk_tags: list[string]
  discovered_by: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

移动校验读取：

```text
当前位置；
目标节点；
路线是否可见；
passability；
requirements；
risk_tags；
current_cost_hours；
角色状态；
宗门、NPC 或事件授予的通行许可；
是否存在路线封锁、节点事件或公开危险。
```

移动是普通个人行动，按 `world_hour` 消耗时间。队列中的移动在入队时校验一次，执行前必须再次校验，避免路线被封锁、节点风险改变或权限失效后仍强行通过。

## 6. 风险、节点等级、灵气与设施

`risk_level` 枚举：

```text
low
medium
high
unknown
```

基础兜底口径：

| `risk_level` | 自动兜底 | 显式托管默认 |
| --- | --- | --- |
| `low` | 吐纳 | 托管吐纳 |
| `medium` | 休整 | 托管休整 |
| `high` | 休整 | 托管休整 |
| `unknown` | 休整 | 托管休整 |

风险等级变化必须写入结果包、个人可见日志或公开地图日志。地图 UI 可以显示中性风险提示，但不得泄露其他玩家私人事件来源。

`node_level` 或等价节点等级由节点模板、区域、控制权、历史演化和特殊事件决定。MVP 阶段节点等级至少影响：

1. 自然生成的资源槽基线数量。
2. 资源槽内资源的基础品级、可波动范围和稀有变体概率。
3. 节点整体 `aura_profile` 的灵气浓度、品质、稳定度、污染和相性权重。
4. 可见风险、机会窗口、资源争夺强度和可建设规模上限的默认区间。

节点等级只决定自然生成资源槽的基线和单槽规模、品级、风险的默认区间。MVP 阶段暂时不设置“节点资源槽总数量上限”；人工扩展后的资源槽数量不因节点等级触发总量硬封顶，但每个资源槽自身的规模、设施类别、维护成本和结算产能仍必须被记录。

`aura_profile` 最少表达：

```yaml
aura_profile:
  aura_density: number
  aura_quality: string
  element_affinity_tags: list[string]
  pollution_tags: list[string]
  stability_tags: list[string]
  cultivation_modifiers: dict
```

灵气只提供修炼环境、资源输入相性、经脉压力、心魔风险、突破准备和事件选择的修正，不直接发放无来源修为。

设施通过 `facility_refs` 建索引，但设施和建筑不是与资源并列的第二套槽位。MVP 阶段，能建造、升级、运行或维护的生产、修炼、加工、防护、交通、市场、宗门行政等设施，必须附属于一个合法资源槽。设施可以提供修炼环境、功法研习、炼丹炼器、治疗护法、传送、储物、阵法、防护、市场、宗门行政和资源加工等能力。设施效果必须通过行动、权限、资源消耗、资产流水和结果包进入结算，不能作为无来源全局倍率。

设施附属规则：

1. 同一个资源槽同时只能承载一类设施。设施的规模、等级、维护状态和产能可以变化，但设施类别不能在同一槽内并存。
2. 资源槽模板声明可建设施类别、初始规模上限、最终规模上限和升级条件；节点等级可提高或压低这些上限。
3. 更换设施类别必须走拆除、迁移、废弃、污染修复或事件改造流程，不能直接把已建灵田瞬间改成矿场、传送阵或市场。
4. 不易改造资源槽可以禁止常规建设，只允许封禁、维护、参悟、争夺、探索或机会窗口类操作。
5. 交通设施、坊市入口、宗门行政建筑等不依赖自然产出的公共设施，也必须绑定到 `aura_node`、`space_site` 或 `special` 等广义资源槽，不能绕过资源槽规模限制。

## 7. 资源槽

`NodeResourceSlot` 代表节点上的广义资源承载位。资源不只指可采集物，也包括灵气节点、可建设地脉、矿脉、药谷、灵泉、妖兽巢穴、稳定空间、洞天福地、秘境入口条件和其他可被争夺、利用或建设依附的世界条件。

资源槽类型在 MVP 阶段只保留少量大类；具体用途由 `slot_usage_tags`、`buildable_facility_classes` 和附属设施类别表达，不再为灵田、市场、传送阵、行政地块等各建一套资源槽类型。

```yaml
NodeResourceSlot:
  slot_id: string
  node_id: string
  resource_type: aura_node | material_deposit | ecology_site | space_site | blessed_land | opportunity_site | special
  resource_template_id: string
  slot_origin: natural | artificial_regular | event_created | hidden_layer | legacy
  slot_scale: int
  generated_by_node_level: int
  resource_grade: string
  resource_grade_range: string
  aura_density: number
  aura_density_policy: above_node_average | near_node_average | below_node_average | none
  slot_usage_tags: list[string]
  current_amount: number
  max_amount: number
  regen_per_world_hour: number
  buildable_facility_classes: list[string]
  attached_facility_class: string | null
  attached_facility_ref: string | null
  blocking_site_refs: list[string]
  facility_scale: int
  facility_level: int
  facility_scale_cap: int
  transformability: free_build | limited_build | preserve_only | no_build
  special_property_tags: list[string]
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  depletion_event_refs: list[string]
  contest_state: object
```

规则：

1. 资源采集、争夺、消耗、枯竭和刷新都按 `world_hour` 记录。
2. 自然资源点先产出资源池或资源量，再通过采集、加工、炼制、修复等行动转为物品、材料或宗门资源。
3. 已控制资源节点的基础产出属于常态结算，不占用宗门唯一持续行动槽。
4. 稀有资源、秘境资源、藏宝资源和后手封存资产必须有来源、预算或资产容器记录，不能作为无约束随机奖励。
5. 枯竭、再生、污染、异变按节点模板配置，不使用统一生态公式。
6. 资源槽的自然生成基线数量、资源品级和 `resource_grade_range` 受节点等级影响；同类节点也可以因区域、污染、秘境窗口或历史事件产生差异。
7. 设施必须读取资源槽的 `buildable_facility_classes`。同一资源槽只能选择一个 `attached_facility_class`，后续只允许在该类别内调整规模、等级、维护和产能。
8. `slot_scale` 表示资源槽自身规模；`facility_scale_cap` 表示该槽可承载设施的规模硬上限。节点等级、资源品级、地形、控制权和特殊事件可以修正单槽规模与设施上限，但 MVP 不设置节点级资源槽总数量上限。
9. 洞天福地在 MVP 阶段按 `blessed_land` 或等价不易改造资源槽处理，通常是 `limited_build`、`preserve_only` 或 `no_build`，不是可随意改造的一般建筑地块，也不是常规人工扩展可制造的资源槽。
10. 灵气节点按 `aura_node` 资源槽处理。`aura_node` 是通用可建设灵气承载位，不只服务修炼房，也可以按模板支持灵田 / 药园、传送阵、渡口、坊市 / 店铺 / 摊位、宗门行政、阵法、防护和普通加工等设施类别。
11. 个人洞府和普通藏宝允许附着在自然资源槽上，也允许附着在节点隐藏层上；真灵藏宝只能附着在节点隐藏层上，不能附着在资源槽上，包括洞天福地 / `blessed_land` 及其子资源槽。
12. 个人洞府或普通藏宝附着在自然资源槽时，会读取该槽的灵气浓度、相性、稳定度、污染和空间条件作为收益或风险来源；同时因为占用明确世界条件，隐蔽程度应低于同等投入的隐藏层藏宝或隐藏层洞府。
13. 个人洞府或普通藏宝不能设置在已有附属设施的自然资源槽上。设置后该资源槽视为被 `personal_cave` 或 `treasure_cache` 类设施化占用，后续建造、扩建或改造其他设施必须失败，直到清理、迁移、拆除或事件处理该个人洞府 / 藏宝。
14. 真灵藏宝没有资源槽灵气需求，也不承担因资源槽占用带来的普通暴露风险；其可见性、感应和开启只由正式后手、真灵解锁条件和隐藏层记录决定。

MVP 简化资源槽类型：

| `resource_type` | 覆盖内容 | 常见设施或操作 |
| --- | --- | --- |
| `aura_node` | 灵气节点、灵脉支点、可常规开发地脉、人工扩展的常规资源槽 | 修炼房、静室、聚灵阵、灵田、药园、传送阵、渡口、坊市、店铺、行政建筑、阵法、防护、普通加工 |
| `material_deposit` | 矿脉、药谷、灵泉、灵液池、可采集灵材点等明确物质产出 | 采矿场、灵泉维护、灵液收集、采集前置、炼矿前置 |
| `ecology_site` | 妖兽巢穴、灵植群落、特殊生态位 | 狩猎营地、驯养栏、看守点、生态保全、风险事件入口 |
| `space_site` | 洞府空间、稳定空间、仓储空间、隐藏空间入口、可建空间 | 洞府、仓储、防护、隐蔽、休整、入口维护 |
| `blessed_land` | 洞天福地、特殊高价值空间或特殊灵气场 | 保全、封禁、参悟、突破场地、受限入口维护 |
| `opportunity_site` | 秘境窗口、资源名额、短期入口、临时争夺条件 | 入口维护、探索准备、临时封锁、争夺事件 |
| `special` | 无法归入上列的定制资源槽 | 按模板声明用途、建设限制和结算来源 |

人工扩展资源槽规则：

1. MVP 只支持常规人工扩展，新增资源槽的 `resource_type` 固定为 `aura_node`，`slot_origin` 记为 `artificial_regular`。
2. 常规人工扩展不能凭空制造矿脉、灵泉、妖兽生态、洞天福地、秘境窗口、隐藏层特殊入口或带剧情来源的特殊资源。
3. 常规人工扩展后的资源槽没有特殊属性，`special_property_tags` 必须为空；如后续事件赋予特殊属性，必须改记为事件来源并写入结果包。
4. 常规人工扩展后的 `aura_density_policy` 必须为 `below_node_average`，其灵气浓度低于当前地图节点平均灵气浓度，不能用人工扩展绕过节点灵气稀缺性。
5. 人工扩展时可以设定 `slot_scale`；规模由建设行动、资源投入、地形、权限和模板约束决定。规模影响可承载设施规模和产能，但不附带特殊相性、特殊产出或稀有变体。
6. 常规人工扩展后的 `aura_node` 可以按模板承载灵田、修炼设施、传送阵、市场、行政等常规设施类别；仍遵守同槽只承载一类设施。

资源再生可按 `world_hour` 连续累计，也可按 `macro_period_id` 批量刷新；无论哪种方式，都必须保留可追溯的世界时间、来源和可见性记录。

## 8. 控制权与影响力

节点归属采用“控制权 + 影响力”混合模型。

控制权影响：

```text
主资源收益权；
建设权；
驻守权；
通行管理权；
节点事件优先响应权；
宗门 AI 行动目标选择。
```

影响力影响：

```text
行动耗时与便利；
情报发现率；
任务成功率；
探索与交易便利；
控制权争夺基础；
对控制者收益的轻微竞争；
传闻可信度与可见性。
```

控制权变更采用阈值 + 事件模型。玩家不需要逐个节点手动点击接管。可推动节点易主的因素包括：

```text
玩家探索、驻守、建设、开采；
玩家处理节点事件；
玩家亲自参与宗门相关个人行动；
宗门持续行动；
外部宗门或 NPC 压力；
后手触发；
资源枯竭、路线封锁、灾变或重大事件链。
```

达到条件后，控制权变化应生成控制权事件或受控 `node_delta`，再由权威结算合并。

## 9. 机会窗口、秘境与临时节点

秘境、资源名额、节点危机、短期交易、突破护法机会等限时内容使用 `OpportunityWindow`。

```yaml
OpportunityWindow:
  window_id: string
  node_id: string
  starts_world_day: int
  starts_world_hour: int
  ends_world_day: int
  ends_world_hour: int
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  entry_requirements: list[object]
  event_template_refs: list[string]
  contest_policy: string
```

规则：

1. 普通秘境入口作为节点上的机会窗口或入口设施表达。
2. 少数长期存在、可以被反复观察和争夺的著名秘境，其内部空间可作为 `secret_realm_region` 节点；秘境入口本身仍是机会窗口、入口设施、隐藏层或路线条件。
3. 窗口开启、关闭、进入、错过、被争夺或被后手影响，都必须写入结果包和回放。
4. 玩家进入机会窗口必须通过个人行动、事件选择或正式交锋入口完成，地图不能直接修改角色状态。

秘境内部或短期空间可使用临时节点：

```yaml
TemporaryNode:
  temp_node_id: string
  parent_node_id: string
  created_world_day: int
  created_world_hour: int
  expiry_rule: object
  access_rules: object
  event_chain_refs: list[string]
  cleanup_rules: object
```

## 10. 隐藏层、后手、清点与遗留设施

隐藏层是地图上的信息与空间承载层，不是后手、宗门清点、遗留设施或库存本身。

隐藏层状态：

```text
unknown → rumored → located → partially_revealed → revealed → resolved
```

隐藏层可承载：

```text
隐藏资源；
旧洞府；
普通藏宝；
真灵藏宝位置；
线索；
秘境入口；
伏笔事件；
前世痕迹；
隐藏路线。
```

隐藏层承载规则：

1. 个人洞府和普通藏宝可以挂在节点隐藏层，不占用资源槽，也不读取资源槽灵气收益；其隐蔽、防御、维持和开启条件由隐藏层、阵法、线索和事件记录决定。
2. 真灵藏宝只能挂在节点隐藏层，不能挂在自然资源槽、人工扩展资源槽、洞天福地 / `blessed_land`、洞天内部子资源槽、洞府设施或普通藏宝设施上。
3. 真灵藏宝所在隐藏层可以与普通洞府线索、旧洞府线索或其他隐藏内容同处一个节点，但必须有独立 `ContingencyRecord` 或真灵藏宝记录，避免被宗门清点、普通藏宝取出或资源槽改造流程误处理。

当前不再保留旧版把无主遗留物并入遗产的 active 设定。死亡、转世、失踪、洞府失守、组织接管或事件后的资产去向，拆成三类处理：

| 类型 | 地图承载方式 | 资产规则 |
| --- | --- | --- |
| 宗门个人洞府清点层 | 节点设施、宗门管辖状态、宗门清点事件或宗门清点记录 | 玩家转世前留在宗门管辖个人洞府中的普通库存，可由宗门锁定、清点并回收；它不是正式后手，也不是新世角色自动继承物资 |
| 宗门外个人洞府 / 普通藏宝层 | 自然资源槽、节点隐藏层、洞府设施、普通藏宝记录、开启条件和争夺事件 | 不进入宗门清点回收，不随转世自动进入宗门库存或新世行囊；附着自然资源槽时获得资源槽收益但降低隐蔽并阻止该槽建设其他设施；必须满足钥匙、功法、线索、位置、事件条件或破阵结果后才能进入或取出，且可能被其他角色提前打开 |
| 真灵藏宝层 | 正式后手记录、真灵藏宝记录、目标节点和隐藏层位置 | MVP 阶段的正式后手藏物形态；绑定同一真灵，可跨世感应和开启；受设置数量和单个容量限制；取出一次性；MVP 阶段不展示被他人搬空、损坏或移动 |

宗门个人洞府清点流程在地图层的最小要求：

```text
角色死亡、转世、长期失踪、被逐、叛宗、资格丧失或洞府权限被撤销
→ 宗门管辖状态校验
→ 洞府入口锁定或权限撤销
→ 普通库存转入宗门库存或临时清点容器
→ 写入资产流水、节点日志、宗门可见摘要和必要的隐藏日志
→ 节点设施状态更新为 locked、cleared、abandoned 或 contested
```

正式后手最少记录：

```yaml
ContingencyRecord:
  contingency_id: string
  true_spirit_id: string
  creator_character_id: string
  created_world_day: int
  created_world_hour: int
  contingency_type: resource_cache | message | formation | relationship_debt | hidden_route | sect_influence | reincarnation_clue
  target_node_id: string | null
  target_hidden_layer_id: string | null
  target_ref: string | null
  activation_condition: object
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  risk_tags: list[string]
  status: dormant | active | triggered | failed | discovered | contested
  result_package_refs: list[string]
```

宗门清点记录最少表达：

```yaml
SectClearanceRecord:
  clearance_id: string
  source_character_id: string
  trigger_world_day: int
  trigger_world_hour: int
  source_facility_ref: string
  source_container_id: string
  target_container_id: string
  controlling_faction_ref: string
  clearance_reason: death | reincarnation | missing | expelled | betrayed | qualification_lost | facility_locked | node_captured
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  status: pending | locked | cleared | contested | failed
  result_package_refs: list[string]
```

宗门外遗留设施记录最少表达：

```yaml
RemnantSiteRecord:
  remnant_site_id: string
  location_node_id: string
  attachment_mode: natural_resource_slot | hidden_layer | facility
  location_resource_slot_id: string | null
  location_hidden_layer_id: string | null
  remnant_type: outside_cave | treasure_cache | sealed_room | clue_site | lost_storage
  origin_hint_ref: string | null
  storage_container_id: string | null
  access_condition: object
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  discovered_by: list[string]
  blocks_resource_slot_facility_construction: bool
  status: hidden | known | opened | depleted | lost | contested
```

后手、清点和遗留设施的地图规则：

1. 后手必须有位置或明确目标引用，不能只有抽象描述。
2. 后手创建、触发、失败、争夺和发现必须写入日志、轮回账本、结果包和回放。
3. 正式后手失效必须有原因链，例如节点被占、资源被采尽、宗门清查、NPC 死亡、竞争者发现、世界事件破坏、触发条件被改变、目标资产被转移、隐藏路线被封锁或机会窗口关闭。
4. 宗门清点只处理宗门管辖洞府、宗门托管资产、职务资产或宗门发放但未私有化的资产，不处理宗门外个人洞府、普通藏宝或真灵藏宝。
5. `RemnantSiteRecord` 是无主遗留设施记录。它可以保留来源线索或传闻，但没有当前资产主人，因此不进入遗产分配、继承或回收流程。
6. 宗门外遗留设施只通过钥匙、功法、线索、位置、事件条件、破阵或争夺事件处理，不生成遗产实体。
7. 宗门外个人洞府或普通藏宝若附着自然资源槽，`RemnantSiteRecord` 必须记录 `location_resource_slot_id`，并在资源槽上保留设施占用或阻塞引用；该槽不能继续建设其他设施，直到遗留设施被清理、迁移、拆除或事件处理。
8. 真灵藏宝对应的正式后手记录必须记录目标节点和隐藏层目标，不能记录为资源槽占用，不能把洞天福地 / `blessed_land` 或洞天内部子资源槽当作封存点，也不能被资源槽改造流程清理。
9. 不做每回合、每季度、年久失修或无世界变化的随机磨损。
10. 高风险后手回收必须由玩家明确行动或事件选择推动，自动兜底和显式托管不得主动回收、暴露、移动或销毁核心后手。

## 11. 可见性与传闻

地图可见性使用统一层级：

```text
private_player：单个玩家、真灵或当前角色可见；
known_to_party：当前事件、队伍、临时协作对象或授权对象可见；
sect_visible：宗门权限范围内可见；
rumor_visible：作为传闻、模糊信息、延迟信息或不完整情报可见；
public_world：公共世界信息，可进入公开地图或世界摘要；
hidden_world：世界真实状态记录，玩家不可直接看到；
debug_only：调试、审计和开发工具可见。
```

玩家 UI 只显示其可见层级内的节点、路线、风险、资源槽摘要、机会窗口、宗门影响与传闻。

不得显示：

```text
其他玩家私人事件归因；
隐秘局部时停来源；
未公开突破选择；
隐藏后手真实归属；
debug_only 信息。
```

公开地图变化应使用中性描述，例如：

```text
黑石岭驻守加强。
云麓山道近日妖兽踪迹增多。
青木谷灵气波动，疑有秘境窗口。
坊市筑基资源短缺。
```

传闻可以模糊、延迟、不完整，不等同于全知世界日志，也不能泄露隐藏真相引用。

## 12. 世界小时演化

每个 `hour_tick`，地图系统根据当前世界状态输出变化结果。

```text
advance_nodes(world):
  for node in node_states:
    regenerate_resource_slots(node)
    update_resource_slot_facilities(node)
    update_risk_level(node)
    update_influence(node)
    check_event_windows(node)
    check_hidden_layers(node)
    write_node_result_packages(node)
```

演化来源：

```text
玩家行动；
宗门行动；
NPC 行动；
资源采集和枯竭；
事件结果；
后手触发；
宏观周期；
世界随机状态。
```

追赶补结算期间只补确定性节点影响，不触发新的随机个人事件、普通机缘或软机会事件。若地图变化属于强制公开节点事件、正式交锋或全局公共决策，应交给房间速度状态处理。

## 13. UI 与验收约束

主界面地图应稳定展示：

```text
当前位置；
可见节点；
可见路线；
节点风险；
资源槽摘要；
宗门影响；
秘境 / 机会窗口；
公开传闻；
队列目标路线；
当前节点可用行动入口。
```

验收检查：

1. 地图状态使用 `current_world_day / current_world_hour`。
2. `node_type` 只使用大尺度地理或空间类型，不使用宗门、坊市、村镇、传送阵、关隘或秘境入口作为节点类型。
3. 移动读取 `RouteState.current_cost_hours` 并按 `world_hour` 结算。
4. `risk_level` 正确影响自动兜底和显式托管默认。
5. 节点 `aura_profile` 能被修炼和突破准备读取。
6. 节点资源槽能按节点等级生成自然槽基线、品级范围、灵气影响、刷新、消耗、枯竭、争夺和传闻。
7. 人工常规扩展能新增 `aura_node` 资源槽，记录规模、低于节点平均的灵气浓度和空特殊属性，且 MVP 不校验节点资源槽总数量上限。
8. 资源槽附属设施遵守一槽一设施类别、单槽规模上限、等级调整和维护状态。
9. 个人洞府和普通藏宝附着自然资源槽时能阻止该槽建设其他设施；附着隐藏层时不读取资源槽灵气收益。
10. 真灵藏宝只能落在节点隐藏层，不能记录为资源槽占用；洞天福地 / `blessed_land` 是资源槽，不能作为正式后手封存点。
11. 宗门行动能改变节点影响、风险、资源槽、附属设施、路线或机会窗口。
12. 机会窗口有开始、结束、可见性、准入条件和争夺策略。
13. 后手只在有明确世界变化或触发条件时检定，不做无原因随机失效。
14. 地图 UI 不显示其他玩家私人事件归因。
15. 地图变化进入结果包和回放。

## 14. 冲突裁决与废弃口径

| 旧口径或冲突点 | 当前采用口径 | 裁决原因 |
| --- | --- | --- |
| `WorldNode` 作为唯一节点运行结构 | 运行态使用 `NodeState`，`WorldNode` 仅可作为旧模板名 | 节点需要记录时间、可见性、事件窗口、路线、后手和资源状态 |
| 宗门山门、城镇、村庄、坊市、传送阵、关隘、秘境入口作为节点类型 | 节点类型只保留山脉、谷地、林野、水域、平原、地下、遗迹、秘境空间等地理或空间区块；功能对象改由设施、资源槽、机会窗口、隐藏层、路线条件或状态标签表达 | 节点应是可容纳大量资源槽和设施的大尺度空间，建筑、组织、市场和入口不应与地理节点混为一层 |
| `building_slots` | 不采用独立建筑槽；使用广义 `resource_slots` + 附属 `facility_refs` | 资源槽决定可利用世界条件和规模上限，设施是资源槽上的建设或运营形态 |
| 资源槽只代表可采集产出点 | 资源槽泛化为灵气、空间、生态、矿脉、灵泉、洞天福地等世界条件 | 设施建设、修炼环境和资源产出需要同一套来源与规模约束 |
| 为灵田、市场、传送阵、行政地块分别设置资源槽类型 | 简化为 `aura_node` 等少量资源槽大类，具体用途由用途标签和可建设施类别表达 | 避免类型爆炸；灵气节点作为通用可建设承载位，可支持灵田、传送阵、市场和行政设施 |
| 地图节点存在资源槽总数量硬上限 | MVP 不设置节点级资源槽总数量上限；只限制单槽规模、设施类别、维护成本和结算产能 | 当前阶段先跑通常规扩展和设施挂载，不把总量上限作为阻断条件 |
| 人工扩展可制造特殊资源槽 | MVP 人工扩展只生成常规 `aura_node`，无特殊属性，灵气浓度低于节点平均浓度，规模可设定 | 防止人工扩展绕过自然资源、洞天福地、秘境窗口和特殊事件来源 |
| 同一资源槽堆叠多类建筑 | 同一资源槽只能建造一类设施，规模和等级可变 | 避免一个灵气节点同时无限承载修炼房、炼丹房、矿场和市场，破坏地图资源稀缺性 |
| 个人洞府、普通藏宝、真灵藏宝都可以任意附着资源槽 | 个人洞府和普通藏宝可附着模板允许的自然资源槽或节点隐藏层；真灵藏宝只能附着节点隐藏层，不能把洞天福地 / `blessed_land` 或洞天内部子资源槽作为封存点 | 普通洞府 / 藏宝需要从资源槽获得灵气等收益并承担暴露代价；真灵藏宝没有灵气需求和普通暴露风险 |
| 个人洞府或普通藏宝不影响资源槽建设 | 附着自然资源槽后视为 `personal_cave` / `treasure_cache` 类设施化占用，其他设施建设必须失败，直到清理、迁移、拆除或事件处理 | 洞府 / 藏宝占用了可建设世界条件，不能与灵田、市场、传送阵、修炼房等设施无成本叠加 |
| `danger_level` | 使用 `risk_level` | 风险字段需要直接驱动兜底、托管、移动提示和 UI 摘要 |
| 普通道路或普通交通设施作为节点 | 普通道路作为 `RouteState`；渡口、关隘、传送阵、山道要冲等优先作为设施、路线条件或路线状态，只有扩展成大尺度地理区块时才建节点 | 避免路线边、交通设施和地理节点重复建模 |
| “前世后手节点”作为独立节点类型 | 使用隐藏层、正式后手记录、宗门清点记录、遗留设施记录或洞府 / 藏宝设施承载 | 后手、清点、藏宝和洞府是挂载内容，不应混成节点类型 |
| 旧版无主遗留物作为遗产 active schema | 不采用；拆成宗门清点记录、宗门外遗留设施记录、正式后手记录 | 当前重整口径不再保留无主遗留物作为遗产实体，避免把宗门清点、宗门外洞府和真灵藏宝混成一种跨世继承规则 |
| 宗门个人洞府、宗门外洞府、普通藏宝、真灵藏宝混作同一种遗产 | 按宗门清点、可开启遗留设施、正式后手三类分开 | 解决资产去向、跨世继承、宗门回收和多人竞争规则冲突 |
| 正式后手被随机磨损、年久失修或无日志失效 | 正式后手失效必须有原因链；MVP 真灵藏宝不展示被他人搬空、损坏或移动 | 轮回体验需要可信、可复盘，且不能把正式后手降级为普通随机宝箱 |
| 推荐阶段作为硬锁 | 推荐阶段只做内容筛选、提示和风险预期 | 玩家可以冒险，但系统必须展示风险和后果 |
| 地图公开所有节点真相和私人归因 | 地图按可见性层级展示，中性化公开后果 | 多人间接竞争依赖信息边界，私人事件不能被地图泄露 |
