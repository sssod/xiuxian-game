# 系统设计｜资源与材料

## 1. 设计定位

本文维护资源与材料在物品、资源池、宗门库存、配方生产、世界投放和后手封存中的系统边界。它负责回答“哪些内容需要成为物品实例、哪些内容可以抽象为库存或资源池、资源如何转化为材料或正式物品、价值和预算如何区分”。

本文不维护完整材料分类表、具体数值倍率、公式定稿、资源槽详细地形规则或具体 UI 布局。公式、倍率、预算和验算由数值设计文档承接；节点、资源槽和设施只引用本文的资源对象与转化边界。

## 2. 当前结论

1. MVP 不要求所有资源都成为具体物品实例；宗门大宗资源可先抽象为库存数值，节点自然产能可先作为 `ResourcePool` / `ResourceSlot`。
2. 普通材料、丹药、符箓可作为可堆叠物品；法宝、功法载体、正式后手物、高价值突破资源和带独立状态的物品应作为实例物品。
3. 自然资源点优先维护资源状态，只有经过采集、加工、炼制、宗门行动、事件结算或资源槽附属设施产出后，才转化为库存资产、抽象资源、可堆叠材料或独立实例。
4. 配方是“明确投入 -> 明确产出”的生产规则，不是随机掉落表；随机只影响品级、数量、副产、状态、成色、副词条、失败副作用和返还比例。
5. 资源与材料必须区分交易价值、世界预算价值、回收价值和宗门贡献价值，不能用单一价格覆盖所有系统语境。
6. 正式后手物来自既有显性物品记录，可跨世感应和开启，但必须受真灵藏宝数量与单个容量限制。

## 4. 核心循环或触发入口

资源与材料围绕“资源状态 -> 采集 / 加工 / 生产 -> 入库 / 消耗 / 封存 -> 流水与回放”循环维护。

```text
节点资源池 / 宗门抽象资源 / 世界生成池 / 既有物品
-> 采集、开采、维护、加工、炼制、配方生产、事件结算或宗门常态经营
-> 抽象宗门资源、材料 ItemStack、具体物品 ItemStack 或 ItemInstance
-> 行囊、宗门库存、商店库存、节点库存、事件锁定容器、藏宝或后手容器
-> 交易、上交、拆解、消耗、突破、修炼、设施供能、任务提交或后手封存
-> 写入资产流水、资源池变化、配方结果、事件结果、行动回放或后手记录
```

常见触发入口：

1. 地图节点、资源槽、灵脉、矿脉、药田、兽群、生态位、空间裂隙或特殊资源点。
2. 宗门控制资源点后的常态采矿、药田收成、灵脉基础抽取、初级材料加工和已建成设施稳定产出。
3. 玩家持续采集、深层开采、资源异变处理、抢占 / 恢复资源点、修复损坏设施或高阶加工设施建设。
4. 丹药、符箓、阵盘、法宝修复、灵材精炼、功法拓印、建筑构件和特殊事件制造的配方生产。
5. 探索、事件、秘境、战斗、NPC 工坊、坊市服务、任务奖励、宗门配给、普通藏宝和正式后手回收。

## 5. 规则与状态

### 5.1 资源层级与对象身份

MVP 推荐使用以下资源层级：

| 层级 | 当前口径 |
| --- | --- |
| 宗门大宗资源 | 可先抽象为宗门库存数值 |
| 节点自然产能 | 可先作为 `ResourcePool` / `ResourceSlot` 维护状态 |
| 普通材料、丹药、符箓 | 可作为可堆叠物品 |
| 法宝、功法载体、高价值突破资源、正式后手物 | 应作为独立实例或在特定条件下提升为实例 |

MVP 宗门追踪五类资源：

1. 灵石。
2. 修炼资源。
3. 材料 / 矿材。
4. 人力 / 弟子规模。
5. 声望 / 影响力。

声望 / 影响力不是货币，不直接兑换物品，而是行动修正、外部响应、控制权竞争和事件承担参数。人力不是物品，可被占用、损耗、恢复或转化为执行完成度修正。

### 5.2 自然资源池

自然资源点首先管理资源状态，不直接等价于背包物品或可领取库存。节点自然产能可用 `ResourcePool` 或 `ResourceSlot` 表达。

资源池最小字段：

```yaml
NaturalResourcePool:
  resource_pool_id: string
  node_ref: string
  resource_slot_ref: string | null
  resource_type: aura | ore | herb | beast | ecology | space | special
  tier_code: string
  abundance_state: rich | normal | poor | depleted
  current_amount: number
  max_amount: number
  regeneration_rate: number
  extraction_difficulty: number
  depletion_risk: number
  pollution_state: none | minor | serious | corrupted
  discovery_state: hidden | rumored | discovered | controlled
  controlling_faction_ref: string | null
  controlling_faction_bonus: number
  attached_facility_ref: string | null
  ledger_refs: list
```

约束：

1. 自然资源不消耗世界物品预算帽，受 `max_amount`、`regeneration_rate`、`depletion_risk`、污染状态、资源槽规模、控制权和事件状态约束。
2. 资源池可由事件、宗门建设、秘境变化、灾害、污染、迁移、清理或世界演化创建、削弱、枯竭或销毁。
3. 宗门经营和玩家持续采集必须读取同一资源池状态，避免同一资源被重复结算。
4. 宗门已控制资源点后的基础采矿、药田收成、灵脉基础抽取、初级材料加工和已建成设施稳定产出，可作为常态结算或持续项目，不必都占用宗门主行动。
5. 新资源点开采、深层开采、过度开采、资源异变处理、抢占 / 恢复资源点、修复损坏设施、建设高级加工设施、尝试产出特殊物品或高阶材料，仍可占用宗门持续行动或触发事件链。
6. 资源点产出进入库存前分两类转化：简单加工规则用于普通材料，配方生产规则用于特定物品、特殊材料或更高品级结果。

### 5.3 配方生产

配方是“明确投入 -> 明确产出”的生产规则，不是随机掉落表。它服务于丹药、符箓、阵盘、法宝修复、材料加工、功法拓印、灵材精炼、建筑构件、宗门常态加工、NPC 工坊、坊市服务和特殊事件制造。

```yaml
Recipe:
  recipe_id: string
  display_key: string
  recipe_category: alchemy | forging | talisman | array | refining | repair | copy | processing
  tier_code: string
  quality_floor: string
  quality_ceiling: string
  required_method_tags: list
  required_recipe_level: number
  required_facility_tags: list
  input_requirements: list
  optional_inputs: list
  output_prototype_refs: list
  output_stack_policy: stackable | unique_instance
  base_batch_size: number
  time_cost: object
  resource_cost: object
  failure_modes: list
  allowed_random_fields: list
  variance_profile: object
  byproduct_rules: object
  recycle_rules: object
  upgrade_rules: object
  modification_slots: list
```

配方来源可以是非战斗类功法 / 技艺、NPC 传授、玉简 / 手札 / 残方 / 传承印记、宗门职位与藏经阁权限、任务奖励、秘境发现或正式后手回收。功法 / 技艺提供理解、效率、品质上限、失败控制和改造能力；配方提供具体产出规则。配方不等于功法本身。

配方生产请求：

```yaml
RecipeProductionRequest:
  request_id: string
  actor_type: character | sect | npc_workshop
  actor_ref: string
  recipe_ref: string
  source_container_ref: string
  input_resources: list
  optional_inputs: list
  facility_ref: string
  operator_method_tags: list
  operator_skill_level: number
  recipe_level: number
  batch_count: number
  time_budget: object
  quality_intent: stable | efficient | high_quality | risky
  risk_acceptance: object
  rng_namespace: string
  log_policy: object
```

生产结果：

```yaml
RecipeProductionResult:
  success: bool
  produced_stacks: list
  produced_instances: list
  byproducts: list
  consumed_inputs: list
  returned_inputs: list
  recipe_exp_delta: number
  item_quality_result: object
  failure_reason: string | null
  item_logs: list
  stock_logs: list
```

随机边界：

1. 核心产物类型由配方决定，不由随机决定。
2. 投入资源满足最低条件时，至少产生可用结果或明确失败返还。
3. 随机主要影响品级、数量副产、状态桶、成色桶、副词条、失败副作用和返还比例。
4. 高阶配方可以有更大波动，但必须提前展示风险。
5. 批量生产优先生成 `ItemStack`，不为每个单体创建独立实例。
6. 产出价值不得长期稳定高于投入价值，除非由稀有配方、稀有设施、高阶技艺、长时间成本、高失败风险、关键材料稀缺、宗门权限或地域限制解释。

配方养成可作为接口保留：

```yaml
RecipeProgression:
  recipe_id: string
  known_by_actor: bool
  recipe_level: number
  mastery_exp: number
  quality_floor_bonus: number
  variance_reduction: number
  input_efficiency_bonus: number
  batch_size_bonus: number
  byproduct_chance_bonus: number
  failure_recovery_bonus: number
  modification_unlocks: list
```

配方改造是高级玩法，MVP 不要求完整展开，但字段应允许替换核心材料、改变副词条倾向、降低副作用、提高批量产出、增加突破 / 战斗 / 修复 / 封存等用途标签，或将稳定配方改造成高风险高收益配方。

### 5.4 价值、预算与回收口径

资源与材料至少区分四类价值：

| 价值 | 用途 |
| --- | --- |
| `TradeValue` | 买卖、估价、商店价格、市场挂牌 |
| `BudgetValue` | 事件、秘境、掉落、宝藏等生成预算扣除 |
| `SalvageValue` | 拆解、修复折价、残片产出和商店回收 |
| `ContributionValue` | 上交宗门后的贡献、声望、职位评价或权限修正 |

规则：

1. `BudgetValue` 不必等于 `TradeValue`。
2. `SalvageValue` 通常低于交易价值，受物品状态、设施、角色技艺、污染和物品类型影响。
3. `ContributionValue` 可读取 `TradeValue` 并乘以宗门需求程度，但贡献不是货币。
4. 出售、拆解、销毁、上交、回收或消耗不返还世界生成预算。
5. 正式后手封存物的身份来自既有显性物品记录，不重新生成；状态变化按日志修正。

物品标准价值可用下式作为建模起点，具体参数由数值文档维护：

```text
V_std = B_category * T_tier * Q_quality * E_effect * S_scarcity * C_condition * U_utility
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `B_category` | 物品类型基础价值 |
| `T_tier` | 阶级倍率 |
| `Q_quality` | 品级倍率 |
| `E_effect` | 效果预算倍率 |
| `S_scarcity` | 稀缺度倍率 |
| `C_condition` | 状态、耐久、完整度、充能、污染等倍率 |
| `U_utility` | 用途覆盖倍率 |

MVP 调参起点：

```text
T_tier = R_tier ^ (tier_order - 1)
R_tier = 8 ~ 20

Q1 下品 = 0.70
Q2 中品 = 0.90
Q3 上品 = 1.15
Q4 极品 = 1.45
Q5 绝品 = 1.90
```

这组数值只是平衡起点，不是定稿。品级差异应明显，但不应超过跨阶差异。

状态倍率示例：

```text
耐久完整 = 1.00
轻微受损 = 0.80
严重受损 = 0.45
破碎但可修复 = 0.20
污染且未净化 = 0.30 ~ 0.70
```

用途越多，价值越高：

```text
U_utility = 1 + utility_bonus - restriction_penalty
```

用途包括战斗、突破、修炼、宗门上交、制造 / 修复、拆解、封存和任务提交。限制包括绑定角色、宗门权限、使用阶段、地点、一次性消耗、副作用或因果风险。

世界预算价值不使用通货价格：

```text
V_final = V_std * D_random * D_optional_origin * D_information
V_world_budget = V_final
```

约束：

1. `V_world_budget` 不乘通胀系数。
2. `V_world_budget` 不受市场买卖价影响。
3. 跨阶使用时，生成预算仍按物品自身阶级扣除。
4. 交易价格可另行读取通胀、供需、关系、节点状态、权限、声望和事件压力修正。

交易价格可保留接口：

```text
BuyPrice = V_final * InflationCoeff * market_buy_spread * relation_modifier * scarcity_modifier
SellPrice = V_final * InflationCoeff * market_sell_spread * relation_modifier * liquidity_modifier
```

突破资源不只按直接数值估价，还要读取降低失败风险或提高突破质量的能力：

```text
V_breakthrough = V_std * (1 + risk_reduction_value + success_quality_value + stage_specificity_value)
```

配方产出不消耗世界预算帽，但必须受投入约束：

```text
OutputValueExpected <= InputValue * recipe_efficiency * skill_modifier * facility_modifier * risk_modifier
```

### 5.5 正式后手、洞府与遗留资产

正式后手物指已封存进真灵藏宝的实例物品。它们可由同一真灵跨世感应和开启，但必须受真灵藏宝设置数量和单个容量限制。

规则：

1. 正式后手物必须来自既有显性物品记录，不重新生成。
2. 封存时应写入后手记录、资产流水、容量占用、来源、状态和开启条件。
3. 转世后同一真灵可感应和开启正式后手；取出时原物品重新进入合法容器。
4. 宗门个人洞府中的材料或资源可按宗门遗产清点回收。
5. 宗门外洞府和普通藏宝中的材料属于无主遗留设施资产，需满足开启条件或破阵结果后才能取出。

## 6. 资源、角色、地图、事件或 NPC 接口

1. 资源接口：读取自然资源池、资源槽、宗门抽象资源、材料物品栈、实例物品、配方输入、资源效果和世界预算。
2. 角色接口：角色通过合法容器、权限、位置、绑定状态、行动耗时、技艺标签和风险接受度调用资源与材料。
3. 地图接口：节点、资源槽、资源槽附属设施、秘境和隐藏层可以创建、削弱、枯竭、污染、控制或输出资源池。
4. 事件接口：事件可生成资源候选、锁定奖励、改变资源池状态、触发配方生产或要求材料提交；结果包必须记录资源变化和资产流水。
5. 宗门接口：宗门可持有五类抽象资源、控制资源点、执行常态采集、发起持续项目、申请资源、上交材料和记录贡献影响。
6. NPC 接口：NPC、工坊、商店、坊市服务和隐性库存可参与配方生产、售卖、回收、奖励或战后转显性资产。
7. 后手接口：正式后手、个人洞府、普通藏宝和遗留设施读取既有物品记录、开启条件、容量限制和取出日志。

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `resource_pool_id` | 自然资源池唯一标识 |
| `node_ref` | 资源池所在地图节点 |
| `resource_slot_ref` | 所属资源槽；没有资源槽时可为空 |
| `resource_type` | 资源类型，如灵气、矿、药草、妖兽、生态、空间或特殊资源 |
| `tier_code` | 资源、材料或产物阶级 |
| `abundance_state` | 富集、普通、贫瘠或枯竭状态 |
| `current_amount` / `max_amount` | 当前资源量和上限 |
| `regeneration_rate` | 再生速度 |
| `extraction_difficulty` | 采集、开采或抽取难度 |
| `depletion_risk` | 过度采集后的枯竭风险 |
| `pollution_state` | 污染、腐化或净化状态 |
| `discovery_state` | 隐藏、传闻、已发现或已控制状态 |
| `controlling_faction_ref` | 当前控制势力 |
| `attached_facility_ref` | 附属设施或加工设施引用 |
| `recipe_id` | 配方标识 |
| `recipe_category` | 配方类别，如炼丹、炼器、制符、阵法、精炼、修复、拓印或加工 |
| `input_requirements` / `optional_inputs` | 必需投入与可选投入 |
| `output_prototype_refs` | 明确产出模板引用 |
| `output_stack_policy` | 输出为可堆叠物品还是独立实例 |
| `failure_modes` | 失败、返还、副作用或污染结果 |
| `allowed_random_fields` | 允许随机化的品级、数量、状态、副词条或副产字段 |
| `TradeValue` | 买卖、估价和市场挂牌用价值 |
| `BudgetValue` | 世界生成、事件、秘境、掉落或宝藏预算扣除价值 |
| `SalvageValue` | 拆解、修复折价、残片产出或商店回收价值 |
| `ContributionValue` | 上交宗门后的贡献、声望、职位评价或权限修正价值 |
| `legacy_recovery_state` | 正式后手或遗留资产的回收状态 |
| `ledger_refs` | 资源池变化、资产流水、配方结果、事件结果或后手记录 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示：

1. 资源或材料的归属容器、数量、阶级、品级、状态、绑定 / 锁定和可用语境。
2. 自然资源点的可发现状态、控制权、资源富集程度、采集风险、污染状态和预计产出摘要。
3. 配方生产的明确投入、可选投入、设施需求、耗时、预计产物、风险、失败返还和批量策略。
4. 宗门抽象资源、材料库存、资源申请、上交贡献影响和常态产出摘要。
5. 正式后手、普通藏宝或遗留设施中的开启条件、容量占用、取出风险和资产变化摘要。

普通 UI 不展示：

1. 内部资源池 ID、完整随机种子、完整预算公式、原始倍率、隐性 NPC 库存或未发现资源真相。
2. 未被角色识别的污染、封印、来源、隐藏副词条、未来事件触发信息或藏宝真实内容。
3. QA 调试用的世界预算累积值、消耗值、降级替换规则和完整资源池流水。

MVP 调试界面可显示当前各阶预算累积值、本宏观周期增长值、本宏观周期消耗值，以及因预算不足而降级或替换的生成结果。

## 9. MVP 范围

MVP 应实现或保留：

1. 宗门五类抽象资源：灵石、修炼资源、材料 / 矿材、人力 / 弟子规模、声望 / 影响力。
2. 自然资源池最小状态：当前资源量、资源上限、再生速度、采集难度、枯竭 / 污染状态和控制宗门修正。
3. 资源点到宗门库存闭环：宗门控制资源节点 -> 资源池按再生规则增加 -> 宗门常态经营采集 / 加工 -> 生成抽象宗门资源或材料 `ItemStack` -> 写入宗门库存日志。
4. 玩家持续采集闭环：玩家在节点持续采集 / 加工 -> 读取资源池当前状态 -> 消耗行动时间与补给 -> 按技艺、工具、风险和事件结果转为材料 `ItemStack` -> 写入角色日志与节点资源变化。
5. 配方生产闭环：玩家、宗门或 NPC 工坊掌握配方 -> 投入明确资源、材料、设施和时间 -> 产出明确目标物品 -> 品级、数量或状态只在配方范围内随机 -> 写入配方经验、资产流水和结果包。
6. 探索 / 事件生成闭环：玩家探索节点、隐藏层或秘境 -> 事件按难度、地点和资源倾向生成候选物 -> 检查对应阶级生成预算 -> 玩家获得后扣预算并进入显性库存或事件锁定库存。
7. 战斗隐性实例化闭环：战斗中按 NPC 或事件模板实例化法宝、符箓、丹药或材料；战后若被获得，进入显性库存并按来源扣预算；若未获得，回收为隐性、损坏或销毁。
8. 突破资源闭环：玩家申请宗门资源、自行收集或配方生产突破资源 -> 突破系统读取资源支持维度 -> 突破消耗、损坏或释放资源 -> 成功 / 失败写日志和结果包。
9. 正式后手闭环：玩家将已有显性物品封存为真灵藏宝 -> 写入后手记录和资产流水 -> 转世后同一真灵感应和开启 -> 取出时原物品重新进入合法容器。
10. 通货与高密度资源闭环：普通灵石可通过加工转化为聚灵石；高阶消耗不直接无限消耗普通灵石；加工设施效率形成普通灵石通胀与高阶需求之间的阀门。

## 10. 验收约束

1. 自然资源池不得直接等同于背包物品或可领取库存；必须经过采集、加工、生产、事件或宗门结算才转为资产。
2. 宗门经营和玩家采集必须读取同一资源池状态，避免重复结算同一资源。
3. 自然资源不消耗世界物品预算帽，但其转化为具体奖励、材料或物品时应按对应规则入库、记账或扣预算。
4. 配方必须定义明确投入与明确核心产出，不得把随机掉落表伪装成配方。
5. 投入资源满足最低条件时，必须产生可用结果或明确失败返还。
6. 配方随机不得改变核心产物类型，只能影响数量、品级、状态、副词条、副产、失败副作用或返还比例。
7. 批量生产普通材料、丹药和符箓时优先生成 `ItemStack`，不得无意义地为每个单体创建独立实例。
8. 高价值突破资源、正式后手物、命名秘宝、带独立状态或需要来源追踪的材料必须实例化或保留可追溯状态。
9. 产出价值不得长期稳定高于投入价值，除非由稀有配方、稀有设施、高阶技艺、长时间成本、高失败风险、关键材料稀缺、宗门权限或地域限制解释。
10. 贡献不是货币；上交材料可以产生贡献、声望、职位评价或权限修正，但不得绕过真实库存兑换物品。
11. 出售、拆解、销毁、上交、回收或消耗资源与材料，不返还世界生成预算。
12. 正式后手物必须来自既有显性物品记录，封存、开启和取出都要保留后手记录与资产流水。
