# 系统设计｜NPC 设计

## 1. 设计定位

NPC 系统负责在共享修仙世界中表达非玩家角色的身份、分层持久化、资产归属、机构服务入口、事件参与、战斗与死亡后果、宏观成长和与宗门 / 交易 / 库存 / 后手系统的边界。

NPC 不应全量模拟成每人都有完整钱包、背包、消费偏好和逐小时生活的社会经济系统。MVP 采用“身份广覆盖 + 库存分层持久化 + 聚合经济流 + 活跃集宏观模拟 + 汇总结算 + 事件相交局部精算 + 惰性追赶”的口径。

本文只维护 NPC 的系统规则与边界，不负责商店库存、宗门库存、节点库存、交易价格、战斗公式、事件权重或完整社会经济模拟。NPC 作为入口、参与者、权限影响者或资产持有人时，必须把真实资产、组织资产和事件锁定资产区分清楚。

## 2. 当前结论

1. NPC 按 N0-N4 分层持久化；只有 N3 / N4 默认可持有真实个人随身资产、个人储藏、关键状态和宏观行动，N2 功能服务 NPC 通常只是服务入口。
2. 商店库存、宗门库存和节点库存不绑定入口 NPC；掌柜、摊主、宗门管事、村长或接引 NPC 的失败、死亡或替换，不等于机构资产全量失守。
3. 玩家与非商店 NPC 交易必须使用持久化资产、合法个人库存、事件锁定资产或有预算来源的轻量交易包，不能在交易开始时临时生成完整 NPC 库存。
4. NPC 战斗、死亡和遗产结算必须先处理事件链与当场损失，再区分个人遗产、宗门托管 / 职务资产、宗门管辖洞府库存、普通藏宝、市场挂牌资产和正式后手。
5. NPC 同时只能有一个明确所属组织；MVP 阶段通常为宗门或空。家族、帮派、商会、王朝官署等非宗门组织不进入 MVP。
6. N3 未进入活跃集时不逐小时完整模拟，重新进入活跃集时用成长画像、供给、闭关周期、风险画像和稳定随机命名空间汇总追赶。
7. N4 可拥有个人宏观行动和世界影响，但不得无条件增加宗门持续行动数量；与玩家、宗门持续行动或关键节点交叉时进入事件链精算。
8. F1 中非相关 NPC 不逐小时全量刷新；NPC 宏观成长、宗门职务变化、市场和世界资源事件读取外界日历，不读取玩家洞天主观年。

## 4. 核心循环或触发入口

NPC 系统围绕“分层存在、相交精算、结果落账”运行：

```text
世界推进 / 玩家行动 / 宗门行动 / 节点事件 / 战斗 / 交易 / 死亡
→ 判断 NPC 层级、活跃状态、位置、组织归属和事件相交
→ N0-N2 使用抽象身份、服务入口或聚合经济流
→ N3-N4 读取个人状态、资产、关系、宏观行动或事件锁定资产
→ 需要玩家选择、正式交锋、死亡清点或关键世界影响时进入事件链精算
→ 输出结果包、资产流水、NPC 状态变化、宗门日志、传闻或隐藏世界日志
```

主要触发入口：

1. 事件参与：NPC 作为对话对象、冲突对象、护法、同门、敌对者、证人、任务来源或结果承接者参与随机事件。
2. 交易互动：非商店 NPC 使用个人持久化资产、事件锁定资产或轻量交易包；功能服务 NPC 进入商店、宗门或节点库存规则。
3. 战斗与死亡：NPC 被击败、死亡、失踪、封禁、俘虏或事件移除时，进入战斗结果、死亡事件链和资产清点。
4. 宗门协作：宗门 NPC 提供职位、审批、资源预留、护法、导师、运营指令、宗门持续行动或清点支持。
5. 宏观成长：N3 / N4 在非活跃状态下用汇总结算追赶修为、职位、关系、资源消耗和风险标签。
6. 世界轴心行动：N4 或势力代理可以触发高优先级宏观行动、事件链、传闻、节点压力或宗门倾向变化。

## 5. 规则与状态

### 5.1 NPC 分层持久化

| 层级 | 定位 | 个人资产口径 |
| --- | --- | --- |
| N0 | 抽象人群 / 劳力池 | 无独立身份或库存 |
| N1 | 轻量身份 NPC | 身份可持久化，通常无个人库存 |
| N2 | 功能服务 NPC | 服务入口，库存通常归机构、店铺、宗门或节点 |
| N3 | 关键角色 NPC | 状态、关系、关键资产、个人随身资产和宏观行动持久化 |
| N4 | 世界轴心 NPC / 势力代理 | 高优先级宏观行动、事件链、持久化资产和世界影响 |

N3 / N4 可持有真实个人随身资产、个人储藏或事件锁定资产。N2 若只是掌柜、摊主、管事、接引或服务 NPC，则不自动拥有其所代表的全部商店库存、宗门库存或节点库存。

分层规则：

1. N0 只作为劳力、人群、背景人口、宗门人力或节点流量存在，不生成独立资产容器。
2. N1 可以有姓名、身份、关系标签或事件记录，但默认不维护完整资产、行动队列和成长曲线。
3. N2 提供交易、宗门、节点、任务、传送、接引或教学入口；其个人状态不应替代机构容器。
4. N3 是可长期追踪的关键角色，需要记录关系、修为、核心资产、随身物、个人储藏、宏观行动和死亡后果。
5. N4 是对世界局势有轴心影响的角色或势力代理，可产生传闻、事件链、宗门倾向、节点压力或高优先级宏观行动。

### 5.2 组织归属

NPC 同时只能有一个明确所属组织。MVP 阶段该所属组织一般为宗门，记录为宗门身份、职位、权限和关系；无明确组织时为空。

家族不是宗门下级，也不是宗门之后的备用归属，而是与宗门同级的组织形态。MVP 不开发家族、帮派、商会、王朝官署等非宗门组织。文档中可保留 `faction_ref`、`owner_faction_id` 等泛组织扩展字段，但 MVP 运行规则不得据此生成第二所属组织。

组织归属影响：

1. 宗门身份、职位、权限、资源申请和门内声望。
2. 死亡后普通个人遗产的组织顺位。
3. 宗门托管 / 职务资产的回收。
4. 宗门管辖个人洞府库存的锁定与清点。
5. 宗门事件、宗门 NPC 支持和宗门日志可见性。

### 5.3 NPC 与机构库存

NPC 个人失败不等于组织资产全量失守。

错误口径：

```text
掌柜 = 商店库存持有人；
宗主 = 宗门库房持有人；
村长 = 节点仓库持有人。
```

正确口径：

```text
商店库存属于 shop_stock；
宗门库存属于 sect_storage；
节点库存属于 node_storage；
入口 NPC 只是服务入口、权限影响者或事件参与者。
```

规则：

1. 商店、宗门、节点、市场、事件锁定容器和交易暂存容器应有独立资产记录。
2. 入口 NPC 死亡、替换、离开、被俘或被击败，不自动搬空对应机构库存。
3. 抢劫、查抄、洗劫机构资产必须进入正式事件链、权限校验、守卫反应、资产转移和日志，不走“击败入口 NPC 即获得全部库存”。
4. 宗门托管资产、职务资产、宗门发放但未私有化资产，归宗门或职位规则，不作为 NPC 私人遗产。

### 5.4 NPC 交易

玩家与非商店 NPC 交易必须使用持久化资产或事件明确锁定资产。

可交易来源：

1. NPC 已持久化的随身 / 可调用资产。
2. NPC 合法个人储藏或洞府库存中当前可调用的资产。
3. 事件链在结算前明确锁定的交易包、赔偿、赎买、赠予或奖励包。
4. 有预算来源并写入日志的轻量交易包。

禁止口径：

1. 交易开始时临时生成完整 NPC 库存。
2. 把商店货架写成掌柜个人背包。
3. 把宗门库房写成宗主或长老个人资产。
4. 用 NPC 个人交易绕过绑定、事件锁定、资源预留、后手封存或市场挂牌限制。

轻量交易包只用于事件或低复杂度 NPC 互动，不代表 NPC 拥有完整个人经济模拟。其预算来源、可见性、有效期、交易日志和失败回滚必须可追踪。

### 5.5 战斗、死亡与资产

战斗可获得资产只来自：

1. NPC 已持久化的随身 / 可调用资产。
2. 事件链在结算前明确锁定的奖励包或掉落包。
3. 由事件预算生成的非个人库存奖励，且必须写入来源日志。

N3 / N4 死亡后，应先结算死亡事件链，再读取剩余资产容器。NPC 随身物品和 NPC 个人洞府库存属于遗产，需进入分配、继承、清点或回收流程；宗门托管 / 职务资产归宗门，不随个人死亡流失；普通藏宝按无主遗留设施处理；正式后手按真灵藏宝处理。

死亡遗产结算顺序：

```text
死亡事件链
→ 处理死亡原因、战斗损坏、遗失、封存、遗言和现场控制权
→ 结算父事件链明确指定的战利品、赔偿、赌注、任务结算和当场损失
→ 锁定剩余可继承资产
→ 分类处理宗门托管 / 职务资产、宗门管辖洞府库存、普通个人遗产、市场挂牌资产和正式后手
→ 按继承主体顺序选择一个最终接收主体
→ 写入资产流水、可见日志、隐藏世界日志、传闻或轮回账本
```

MVP 不展开复杂继承人关系网。除当场损失、宗门清点、职务回收、市场冻结和正式后手等例外外，普通个人遗产的剩余归属权整体移交给一个主体，不做多主体比例分配。

普通个人遗产继承顺位：

```text
道侣
→ 子嗣
→ 弟子
→ 所属组织（MVP 为宗门）
→ 世界
```

若前一顺位不存在、不可用、无继承资格或被事件链禁止继承，则顺延到下一顺位。所属组织只读取 NPC 当前唯一明确组织；MVP 阶段通常就是宗门。若未来开发家族或其他组织，它们也只占用同一个所属组织顺位，不作为宗门之后的额外继承层级。

“世界”不是凭空生成预算，而是表示资产脱离可追踪个人 / 组织继承关系，可由事件模板转入无主遗留设施、传闻、隐藏层、市场回收、节点储藏或其他世界流转状态。

### 5.6 当场损失与高价值资产

当场损失包括已由死亡事件链明确转移给胜利者、劫掠者、救援者或任务对象的资产，也包括战斗中损坏、破碎、消耗、遗失、污染、封禁、失效或转入事件锁定状态的资产。

高价值物品、法宝、功法载体、突破资源和后手相关资产的转移必须写入可追踪记录。战斗或死亡文本不得直接决定高价值资产归属，必须通过结果包、资产流水、清点流程或事件锁定容器表达。

### 5.7 宗门相关遗产、无主遗留设施与后手

NPC 死亡后的宗门相关遗产规则，同时用于玩家角色转世前留下的宗门个人洞府库存：宗门可锁定、清点并把普通库存回收到 `sect_storage` 或临时清点容器。该规则不适用于宗门外个人洞府、普通藏宝和真灵藏宝。

宗门外个人洞府和普通藏宝是无主遗留设施，后续只能通过钥匙、功法、线索、位置、事件条件或强行破阵开启，并可能被其他角色提前打开。

正式后手资产按真灵藏宝处理，由同一真灵跨世感应和开启，不因普通死亡自动暴露，也不变成 NPC 掉落。

### 5.8 NPC 修炼追赶

N3 未进入活跃集时，不按固定宏观阶段逐项模拟完整修炼行动。重新进入活跃集时，用成长画像、俸禄 / 基础供给、闭关周期、风险画像和随机命名空间汇总修为变化。

F1 批量结算中，非相关 N3 / N4 不逐小时全量刷新。只有与当前 F1 批次相关的 NPC、护法、敌对者、宗门事件、洞天争夺或玩家当前行动交叉对象进入活跃相关对象集合；其他 NPC 使用外界日历惰性追赶或宏观周期汇总结算。

追赶输入可包括：

1. NPC 当前境界、资质、年龄段、功法状态和风险画像。
2. 宗门身份、俸禄、基础供给、导师或护法资源。
3. 所在节点、宗门状态、世界时间、事件窗口和宏观周期。
4. 已记录的关系、伤势、封禁、心境、失败标签或隐藏世界日志。
5. 稳定随机命名空间，保证同一上下文下追赶结果可复现。

追赶输出应写入：

1. 修为、境界、瓶颈、伤势、资源消耗或闭关结果摘要。
2. 宗门倾向、职位变化、传闻候选或隐藏世界日志。
3. 需要玩家处理、宗门处理或事件链精算的异常。

### 5.9 N4 宏观行动

N4 每个宏观周期应有个人宏观行动，但不得无条件增加宗门持续行动数量。若 N4 行动与玩家、宗门持续行动或关键节点交叉，进入事件链精算；若未交叉，用汇总结算写入状态、宗门倾向、传闻候选或隐藏世界日志。

N4 宏观行动读取外界世界日历。玩家在洞天或时间阵法内经历的主观年不直接推动 N4 多次行动、宗门职位变化、市场刷新或世界资源成熟。

N4 宏观行动可以影响：

1. 宗门战略倾向或资源压力。
2. 关键节点风险、控制权、窗口或传闻。
3. 事件候选权重、关系网络、敌对追踪或护法支持。
4. NPC 自身修为、伤势、身份、声望和资产状态。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 角色系统 | 读取角色属性、修为、状态、关系和可复用角色模型；写入 NPC 状态、成长和死亡后果 |
| 库存系统 | 读取个人资产、机构资产、锁定、预留、交易暂存和资产流水；写入 NPC 交易、遗产、战利品和清点结果 |
| 交易系统 | 读取非商店 NPC 交易、商店入口和交易校验边界；写入 NPC 个人交易结果 |
| 战斗系统 | 读取 NPC 战斗模板、随身资产、事件锁定奖励和战斗后果；写入死亡、损坏、掉落和父事件链结果 |
| 事件系统 | 生成 NPC 参与、死亡、遗产、余波、传闻、追踪和交锋事件；承接 NPC 结果包 |
| 宗门系统 | 读取宗门身份、职位、权限、库存、资源预留和宗门 NPC 支持；写入宗门清点、职务资产回收和宗门日志 |
| 洞府 / 后手系统 | 区分 NPC 个人洞府、宗门管辖洞府、宗门外无主遗留设施、普通藏宝和真灵藏宝 |
| 地图节点 | 提供 NPC 所在节点、路线、隐藏层、节点控制权、节点风险和可见性背景 |
| 数值设计 | 提供 NPC 属性模板、成长画像、事件预算、轻量交易包、战斗模板和掉落 / 遗产验算边界 |
| 交互设计 | 展示 NPC 事件、宗门 NPC、交易、战斗结果、死亡清点、传闻和日志，不暴露 Debug 内部字段 |

## 8. UI 展示边界

普通 UI 应展示：

1. 玩家当前可见的 NPC 姓名、称号、身份、宗门关系、事件状态和可交互入口。
2. 与当前选择相关的关系、风险、权限、可交易来源、战斗风险、宗门支持或失败原因。
3. NPC 作为服务入口时，展示对应商店、宗门、节点或任务入口，而不是伪装成 NPC 个人背包。
4. NPC 死亡、失踪、清点、继承或传闻结果的可见摘要。
5. 宗门页面中的关键 NPC、职位、权限、资源申请支持、清点结果和审计摘要。

普通 UI 不展示：

1. N0-N2 抽象人群的完整内部状态。
2. NPC 完整私人物品清单，除非当前交易、战斗、清点或事件已经合法公开。
3. `npc_id`、容器 ID、随机命名空间、候选权重、完整追赶公式、隐藏世界日志和 Debug 字段。
4. 其他玩家私人事件归因、隐藏后手真实归属、未公开宗门审计细节或未公开继承链。
5. 入口 NPC 所代表机构的完整后台库存，除非当前角色有对应权限且界面处于机构库存或商店模式。

## 9. MVP 范围

MVP 应实现：

1. N0-N4 NPC 分层与最小持久化规则。
2. N2 功能服务 NPC 与机构库存分离。
3. N3 / N4 的个人资产、关系摘要、宏观成长和死亡后果接口。
4. 玩家与非商店 NPC 交易的资产来源校验：持久化资产、合法个人库存、事件锁定资产或轻量交易包。
5. NPC 战斗后的可获得资产来源校验和结果包落账。
6. N3 / N4 死亡事件链、当场损失、普通个人遗产继承顺位和宗门相关清点。
7. NPC 当前唯一所属组织口径；MVP 仅支持宗门或空。
8. N3 非活跃追赶和 N4 宏观行动的汇总结算接口。
9. NPC 事件、宗门日志、传闻和隐藏世界日志的可见性分层。

MVP 不实现：

1. 每个 NPC 的完整钱包、背包、消费偏好和逐小时生活模拟。
2. 家族、帮派、商会、王朝官署等非宗门组织系统。
3. 复杂继承人关系网和多主体比例分配遗产。
4. 完整 NPC 议价、赠予、贿赂、债务、赎买和关系变化公式。
5. 完整社会经济模拟、商路生产链或所有 NPC 的真实库存流转。
6. N4 行动自动扩展为额外宗门持续行动槽。
7. 通过击败入口 NPC 自动获得商店、宗门或节点全部库存。

## 10. 验收约束

1. 任何 NPC 交易、战斗获得、死亡遗产、宗门清点和事件奖励都必须能追踪资产来源、目标容器、权限和日志。
2. N2 功能服务 NPC 不得被实现为机构库存持有人；入口 NPC 死亡或离开不得自动搬空 `shop_stock`、`sect_storage` 或 `node_storage`。
3. 玩家与非商店 NPC 交易不得在交易开始时临时生成完整 NPC 个人库存。
4. 战斗掉落不得绕过事件链、资产容器、结果包和高价值资产记录。
5. NPC 死亡后必须先结算死亡事件链和当场损失，再处理普通遗产、职务资产、宗门清点、市场冻结、无主遗留设施和正式后手。
6. NPC 当前明确所属组织只能有一个；MVP 不得把家族或其他组织作为宗门之后的额外归属顺位。
7. 宗门外个人洞府、普通藏宝和真灵藏宝不得被普通遗产继承、宗门回收或 NPC 掉落规则吞掉。
8. N3 非活跃追赶必须可复现、可解释并写入摘要，不得通过 UI 刷新改变成长或事件结果。
9. N4 宏观行动不得绕过宗门持续行动上限；与玩家、宗门持续行动或关键节点交叉时必须进入事件链或明确结果包。
10. Debug 字段、隐藏世界日志、未公开资产、未公开后手和其他玩家私人事件归因不得进入普通玩家 UI。
11. F1 中非相关 NPC 和远端节点不得逐小时全量刷新；追赶应读取外界日历并可复盘。
12. 玩家洞天内主观时间不得驱动 NPC 宏观成长、宗门职务变化、市场或世界资源事件。
