**版本**：v2.2

## 1. 本交付包用途

本交付包用于替代旧版以“季度 / 6 个朔望行动格 / 宗门主行动输入”为核心的文档口径。新版统一为：

```
可配置时长的回合制
+ 个人线性行动指令
+ 天级 UI 时间预算条
+ 小时级服务端内部结算
+ 宗门 AI 自行演化
+ 每宗门同一时间最多 1 个宗门持续行动
+ 完整功法载体学习与掌握度成长
+ 丹药 / 灵材 / 符箓作为行动资源输入
```

核心变化：

1. **玩家最小推进单位统一称为“回合”**，当前默认每回合 5 个游戏天，但该值仅是配置。
2. **取消 6 个朔望行动格**，改为按“天”显示回合时间预算条。
3. **玩家不做小时级排程**，只输入少量线性行动指令；小时只用于服务端结算。
4. **持续行动拆为固定执行时间与可选投入执行时间**。
5. **移除玩家宗门即时指令、宗门建议、宗门提议、宗门主行动决策流程**。
6. **宗门由 AI 自行维护唯一宗门持续行动**，玩家通过个人行动、身份、贡献、资源申请和事件结果间接影响宗门。
7. **字段统一**：将旧 `quarter / action_slot / tick` 等语义拆为 `turn_id / world_day / world_hour / hour_tick / macro_period_id` 等字段。
8. **功法系统收敛**：完整功法载体学习后生成 `MethodState`；残页 / 篇章只作为合成、线索、权限或投放资产。
9. **修炼资源输入统一**：取消独立“丹药炼化”行动，资源通过 `ActionResourceInputBinding` 绑定具体行动或事件选项。
10. **残余药性状态化**：行动已开始但资源效果未完全用完时生成 `ActiveResourceEffect`，可跨回合保存并进入日志 / 存档。

本版合并依据：

1. `../功法系统_收敛设定汇总_v0.4.md`
2. `../修为修炼公式_资源输入与丹药药性处理补充_v0.2.md`
3. `../新功法与修炼资源设定_旧文档冲突同步清单_v0.1.md`

## 4. 本版优先级

开发引用规则时，建议优先级如下：

```
当前 Figma 主界面 artifact（仅限节点级布局 / 组件位置 / 最新视觉状态）
→
v2.2 UI/UX 需求方案
→
v2.2 术语表 / 字段统一
→ v2.2 房间回合推进 / 行动经济 / 宗门 AI
→ v2.2 运行时状态 / 字段迁移表
→ v2.2 其他核心系统文档
→ v2.0 回合行动经济与宗门 AI 持续行动方案
→ 旧版 sources 文档
```

旧版中出现以下口径时，以本包为准：

- “季度作为玩家最小行动回合”。
- “6 个朔望行动格”。
- “tick 默认对应 15 天或行动格”。
- “玩家宗门即时指令 / 宗门主行动建议 / 宗门提议 / 宗门决策阶段”。
- “每季度一个宗门主行动”。
- “丹药炼化”作为独立默认持续行动。
- `MethodState.learned_sections / missing_sections` 作为功法学习进度。
- `stage_support_range / level_cap_profile / breakthrough_support_profile` 作为道功主字段。
- `quarter / action_slot / tick` 混用的字段。

1. SQLite / Godot Resource / JSON / 混合存档方案最终选择。
2. 各行动模板的实际耗时、收益、风险曲线。
3. 宗门 AI 选择持续行动的具体权重表。
4. 事件模板脚本格式与内容管线。
5. UI 视觉稿、交互原型与 Godot 组件拆分。
6. 修为数值曲线、根骨承载公式和资源输入模板样例的最终数值。
