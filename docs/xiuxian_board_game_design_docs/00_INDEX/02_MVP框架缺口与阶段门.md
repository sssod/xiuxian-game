# MVP 框架缺口与阶段门

适用范围：基于当前已经完成的核心裁决，判断“飞升胜利主题”进入 MVP 设计配置与后续开发准备前仍缺少哪些大模块，并安排下一阶段裁决顺序。

## 1. 当前判断

当前方案已经具备可辨识、可拆分的游戏骨架：

- `2—4` 人、`45—60` 分钟、竞争为主的飞升竞速目标；
- 同时规划、同步移动、统一行动结算的回合循环；
- 六边格、多路线、速度与距离分离的移动框架；
- 自动修炼、大境界突破、小洞天、死亡与转世的成长框架；
- 道功、法门、招式、法宝和炼化程度构成的战前构筑；
- 冷却驱动的自动战斗、竞价、逃遁、平局与死亡资产结算；
- 宗门作为地区影响力经营的辅助定位；
- 飞升事件和同轮共同胜利规则。

这些规则足以支持文档拆分，但还不足以直接形成可配置的 MVP。当前主要问题已经不再是某个公式如何取整，而是缺少局级节奏、内容生产、经济闭环、多人容错和主题配置等大模块。

## 2. MVP 大模块覆盖情况

| 模块 | 当前状态 | 已有基础 | 进入 MVP 配置前仍缺 |
| --- | --- | --- | --- |
| 产品与胜利目标 | 基本稳定 | 人数、局长、飞升目标、共同胜利 | 目标回合数、终局节奏预算 |
| 单局流程 | 规则稳定 | 即时、规划、同步移动、行动、回合末 | 规划时限、未提交兜底、断线恢复 |
| 地图与移动 | 结构稳定 | 六边格、路径、骰池、速度、相遇 | 首张地图、骰池表、速度表、元气成本、地形权限 |
| 行动与事件 | 框架部分稳定 | 一次移动、一个主要行动、两段承诺、途中事件 | 完整主要行动表、事件模板、内容池、竞价细则 |
| 成长与突破 | 规则较稳定 | 自动修炼、境界、突破、渡劫、小洞天 | 境界阈值、回合预算、恢复数值、转世追赶 |
| 功法与构筑 | 规则较稳定 | 道功、法门、掌握度、招式、法宝炼化 | 首批内容表、研习行动闭环、获取与炼制入口 |
| 自动战斗 | 规则稳定、数值待配置 | 冷却、列表顺序、伤害、护盾、Buff、逃遁 | 首批敌人、冷却 / 成本表、`C1/C2/K1_ref` 正式值 |
| 死亡与转世 | 后果稳定 | 掉落、回收、知识保留、资产清空 | 出生地点、最低物资、追赶机制 |
| 宗门地区经营 | 仅定位稳定 | 影响力、资源 / 封锁方向 | 地区单位、占领升级、收益、竞争、转世归属 |
| 经济与资产循环 | 大模块缺失 | 独立商店库存、交易即时行动、死亡流转 | 货币用途、价格锚点、采集、炼制、购买、消耗闭环 |
| 主题内容 | 大模块缺失 | 通用 / 主题职责分离、飞升终点 | 地图拓扑、地点、事件、敌人、奖励、飞升地点配置 |
| NPC 与敌人 | 大模块缺失 | 自动战斗可承接 NPC | 敌人模板、构筑、行为、奖励、难度分层 |
| 多人房间韧性 | 大模块缺失 | 同时规划、隐藏计划 | 房间准备、计时、掉线、重连、托管、退出处理 |
| UI 信息架构 | 高层边界已有 | 三段输入、隐藏信息、战斗列表 | 页面流、信息优先级、错误与兜底提示；节点布局以后交给 Figma |
| 数值验证 | 配置门已识别 | 伤害与 TTK 制作公式 | 属性表、境界表、冷却表、资源表、对局预算与验算用例 |

## 3. 下一阶段必须优先关闭的 P0 阶段门

### P0-1 单局节奏与初始状态

需要关闭：

1. 目标总回合数及可接受波动范围；
2. 各大境界预期到达回合；
3. 初始境界、初始修为、初始掌握度和基础物资；
4. 普通回合、小洞天和死亡重修分别占用多少局级预算；
5. 属性、境界、冷却和资源表的数量级锚点。

对应现有待裁决：`S-01`，以及正式数值配置阶段的 `B-08` 必填项。

### P0-2 主要行动、经济与内容获取闭环（`S-02`、`F-01`）

需要先决定 MVP 中实际存在的主要行动，再决定资源为什么有价值：

```text
移动到地点
→ 执行探索 / 采集 / 研习 / 炼制 / 经营 / 战斗等行动
→ 获得功法、法宝、丹药、货币或地区收益
→ 改善成长、移动或战斗构筑
→ 前往更高价值地点
```

当前必须明确：

- 探索、采集、炼丹、炼器、主动战斗是否进入 MVP；
- 哪些是主要行动，哪些只由事件触发；
- 货币、材料、丹药和法宝的最小来源与消耗点；
- 商店、交易、竞价使用何种支付资源；
- 行动失败与资源预留的边界。

对应现有待裁决：`S-02`、`S-06`；新增框架阶段门 `F-01`“经济与资产循环”。

### P0-3 首张主题地图与事件内容包（`F-02`）

通用移动规则已经存在，但没有可游玩的地图内容。下一阶段必须至少定义：

- 出生区域、普通地点、研习地点、经营地点、危险地点和飞升地点；
- 地点之间的六边格拓扑与特殊连接；
- 途中事件、地点事件、固定事件和随机事件的模板；
- 小洞天入口、关闭时间和奖励投放；
- 首批敌人、资源点和飞升阻拦机会。

上述内容统一记为新增框架阶段门 `F-02`。

### P0-4 NPC、敌人与奖励分层（`F-03`）

自动战斗已经能够执行玩家与 NPC 战斗，但当前没有可配置的敌人内容。下一阶段至少需要定义：

- 敌人模板的境界、属性、道功 / 法门 / 法宝构筑与招式排序；
- 普通、精英、事件首领和飞升前置敌人的难度职责；
- 战斗胜利、重伤、逃遁和平局对应的奖励与事件结果；
- 敌人投放地点、出现条件和重复遭遇边界；
- 用 `60` 秒战斗上限和目标 TTK 验证首批构筑。

上述内容统一记为新增框架阶段门 `F-03`。

### P0-5 死亡后继续参与与追赶

死亡惩罚已经很重，但还没有回答玩家如何重新进入竞争。必须明确：

- 转世出生位置；
- 最低境界 / 修为 / 道功 / 物资包；
- 是否按领先者进度提供追赶；
- 死亡后多久恢复完整行动权；
- 地区资产和宗门关系如何处理。

对应现有待裁决：`S-04`。

### P0-6 宗门是否进入首轮 MVP

宗门的定位已经明确，但闭环仍为空。下一阶段应先作范围选择：

1. 做出一个最小地区影响力闭环；或
2. 保留接口和主题叙事，但从首轮 MVP 可玩内容中暂缓。

若保留，必须补占领、升级、收益、封锁、竞争和转世归属。对应现有待裁决：`S-05`。

### P0-7 多人房间与未提交兜底（`F-04`）

同步回合不能只定义理想路径。进入 MVP 前至少需要：

- 房间创建、加入、准备和开局；
- 即时阶段与规划阶段的时限；
- 未提交玩家的安全默认；
- 掉线、重连、托管和永久退出；
- 同步结算期间的不可逆确认提示；
- 对局中止与房主离开处理。

上述内容统一记为新增框架阶段门 `F-04`。

## 4. P1 配置与表达阶段门

P0 关闭后，再集中处理：

1. `C1`、`C2`、各档 `K1_ref`、`C3(g)` 和属性表；
2. 骰池、速度、元气成本、逃遁和事件概率表；
3. 首批道功、法门、招式、法宝、丹药和敌人配置；
4. 战斗、移动、成长、经济和终局的验算用例；
5. 主棋盘、角色、资产与战斗构筑的信息架构；
6. 简体中文与英语的术语表及玩家可见文本占位。

G-23 百分比继承取整等细节应在相关属性表进入配置时一并关闭，不再抢占 P0 大模块裁决顺序。

## 5. 推荐裁决顺序

下一阶段按以下顺序推进，每轮仍只处理一个相近主题且问题不超过 `5` 个：

1. `S-01`：目标回合数、境界节奏和初始状态；
2. `S-02` + `F-01`：主要行动完整表与 MVP 经济闭环；
3. `F-02`：首张主题地图、地点类型和事件内容包；
4. `F-03`：NPC / 敌人、奖励和难度分层；
5. `S-04`：转世重返对局与追赶；
6. `S-05`：宗门最小闭环或延期；
7. `F-04`：多人房间时限、未提交、掉线和退出；
8. `S-06`：研习行动数值与竞争边界；
9. P1 数值配置与交互信息架构；
10. G-23 等细节收尾。

## 6. 进入后续开发准备的最小验收

在用户明确解除开发冻结前，不进行实现。未来只有同时满足以下条件，才可把设计包视为“可制定 MVP 开发计划”：

1. P0 七个阶段门全部关闭，或明确写出延期范围；
2. 首张地图、初始状态、主要行动、敌人和内容清单可配置；
3. 一局从开局到飞升 / 共同胜利的资源和状态流能够逐回合解释；
4. 死亡、重伤、逃遁、平局、掉线和未提交均有闭环；
5. 数值配置中的所有必填常数有明确归属，不存在静默默认；
6. 主题内容不会依赖旧正式包或阶段稿才能解释；
7. 当前 UI 文档能说明信息与操作流，节点级布局仍由后续 Figma 承接。
