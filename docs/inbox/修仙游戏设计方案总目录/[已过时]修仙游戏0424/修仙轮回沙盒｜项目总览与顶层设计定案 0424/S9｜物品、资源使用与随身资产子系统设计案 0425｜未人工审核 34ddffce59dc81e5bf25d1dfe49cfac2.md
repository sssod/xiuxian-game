## 1. 子系统定位

S9 定义玩家和宗门在事件、战斗、突破、行动中消耗与持有的具体资产。

一句话定位：

> S9 决定角色随身携带什么、能使用什么、消耗什么、损坏什么，以及这些资产如何进入日志和资源循环。
> 

## 2. 核心边界：无装备栏

本项目不采用传统“装备栏 / 换装备 / 换法宝”作为核心限制。

规则口径：

- 随身携带的法宝、道具、已掌握术法 / 神通都可以成为可用来源。
- 被动法宝可以在满足条件时自动生效。
- 主动型法宝需要通过战斗交锋格、事件选择或行动入口主动投入。
- 限制来自行动格、交锋格、元气 / 神念 / 生机、耐久、充能、消耗品数量、事件条件与携带能力，而不是固定装备栏位。

## 4. 资产位置

资产不一定都在角色身上。

```
AssetLocation {
  carried_by_character
  home_storage
  sect_storage
  node_storage
  sealed_legacy
  market_listing
  event_locked
}
```

只有随身携带或事件允许调用的资产，才能在战斗、移动、事件链中直接使用。

### 5.1 已确定决策：MVP 不引入携带容量数值

**人工决策：MVP 不引入携带容量数值，先使用标签和事件限制。**

规则口径：

- 不设计重量、体积、背包格子、负重上限等通用容量数值。
- 随身资产通过标签表达使用条件、携带状态和事件限制。
- 常用标签包括 bulky、fragile、sealed、combat_ready、food、currency、quest_item、legacy_related 等。
- 真正需要限制携带时，由具体事件、远行、战斗、后手封存、宗门调拨或特殊节点规则检查标签与上下文。
- 不让背包系统在 MVP 阶段变成独立的重量管理玩法。
- 后续若需要容量系统，应作为正式版扩展或特殊场景规则，不反向影响 MVP 基础背包结构。

示例：

- 普通干粮可以通过 food 标签参与远行补给。
- 大型阵盘可以带 bulky 标签，在普通移动中允许携带，但在逃遁、潜入或狭窄秘境中受到限制。
- 封存遗产可以带 sealed 与 legacy_related 标签，只能通过后手或特定事件打开。
- 战斗可即时使用的物品必须具备 combat_ready 或由事件明确允许调用。

## 6. 货币与资源

MVP 角色侧可存在：

- 铜钱：凡人阶段交易。
- 银两：凡人较高额交易，可后置。
- 灵石：修行世界标准资源。
- 抽象修炼资源：用于宗门发放、突破准备或培养。
- 材料 / 矿材：用于建设、法宝修复、炼制或宗门库存。

货币与资源需要区分“个人持有”和“宗门库存”。贡献不能直接当作货币使用。

## 7. 法宝状态

法宝不是装备栏插槽，而是可投入、可损耗、可传承的资源。

```
ArtifactState {
  artifact_id
  owner_ref
  carried_state
  active_command_refs
  passive_effect_refs
  durability
  charge
  spirituality
  damage_state
  repair_requirements
  legacy_bind_state
}
```

法宝状态变化：

- 主动使用后受损。
- 被动触发后受损。
- 被针对性破坏后受损。
- 破碎。
- 失去充能。
- 灵性衰减。
- 暂时失灵。
- 战后修复。
- 拆解回收材料。
- 作为后手、遗产或宗门资源重新进入资源循环。

## 8. 消耗道具

消耗道具包括符箓、丹药、阵盘、一次性护符等。

使用场景：

- 战斗指令。
- 突破准备。
- 移动风险应对。
- 节点事件选择。
- 后手开启或破解。
- 疗伤与恢复。

使用必须写入库存变化日志，并由 S1 / 父事件链记录结果。

## 9. 功法、术法与神通载体

需要区分两层：

- 载体：玉简、书册、碑刻、传承印记等物品。
- 已掌握内容：角色学习后写入角色能力与技能标签。

载体可以被交易、遗失、封存或作为后手；已掌握内容属于当世角色，不默认跨世继承。跨世影响通过轮回账本、前世经验、道韵或正式后手重新建立。

## 10. 补给

MVP 不做完整饥饿度系统，只保留远行补给与事件消耗。

补给用途：

- 支持长距离移动。
- 抵消部分疲劳或负面状态。
- 作为新手阶段理解背包和资源消耗的低成本入口。

具体每行动格是否消耗、如何消耗，由移动 / 补给配置决定，不在 S9 写死。

## 11. 资源使用接口

所有资源使用应采用统一请求：

```
ResourceUseRequest {
  actor
  source_inventory
  item_or_resource_type
  amount
  use_context
  target_event
  allow_partial
}
```

结果：

```
ResourceUseResult {
  success
  consumed_amount
  remaining_amount
  item_state_changes
  failure_reason
  log_entry
}
```

- S2：角色背包、随身资产、已掌握功法 / 术法。

- S4：突破资源、法宝辅助、功法匹配。
- 战斗系统：可用指令来源、消耗道具、法宝状态回写。
- S6：宗门库存与个人资产区分。
- S8：节点存储、资源槽产出、建筑消耗。
- S11：后手封存物、遗产回收与正式后手资产。
- S14：持久化资产位置、状态和日志。

## 13. MVP 验收标准

1. 角色有随身背包和至少两类物品。
2. 铜钱、干粮、基础功法载体能支持第一阶段流程。
3. 至少一种突破资源可被消耗并写入 S4。
4. 至少一种法宝可提供战斗指令或被动效果并回写损坏状态。
5. 个人库存与宗门库存可区分。
6. 资源使用失败能输出明确原因。
7. 随身资产可通过标签参与远行、战斗、事件、后手封存等规则检查。
8. MVP 不需要重量、体积、背包格子或负重上限即可跑通基础资产闭环。
