**版本**：v0.1  
**日期**：2026-05-01  
**适用对象**：PC 端 16:9 主界面 / 回合开始 / 信息处理阶段  
**对应 Figma 文件**：`XiuxianUI`  
**对应节点**：`UI_TurnStart_InfoProcessing_v0.1 / MainFrame_1920x1080_TurnStart_InfoProcessing`  
**Figma 链接**：https://www.figma.com/design/5NFYx1eLoNKzLxRMqbSh0l/XiuxianUI?node-id=1-2&p=f&t=etIBGyPkrs86GFdv-0

## 1. 修改目标

本方案用于优化当前 1920×1080 PC 端主界面的按钮与信息布局，使其更符合项目既定的核心界面定位：

> 大世界地图驱动的回合行动工作台。

玩家在主界面的首要心智应是：

```text
先看世界地图变化
→ 判断当前角色、宗门、节点、资源、传闻、风险的关系
→ 决定本回合个人行动
→ 映射到回合时间预算条
→ 锁定提交
```

本次修改不改变玩法规则，不新增系统，只针对以下内容进行 UI/UX 优化：

1. 16:9 PC 主界面的视觉热区与操作热区规范。
2. 当前 Figma 主界面信息层级优化。
3. 左侧待处理变动中心的职责收敛。
4. 右侧目标模板、节点摘要、即时行动模块的整合。
5. 底部回合时间预算条与阶段级按钮的权重强化。
6. 地图画布的主视觉地位强化。
7. 按钮层级与阶段状态的一致性修正。

## 3. 16:9 PC 端视觉热区规范

### 3.1 视觉热区总原则

PC 端 16:9 横屏界面应采用：

```text
中央主视觉区
+ 顶部状态扫描区
+ 右侧上下文决策区
+ 左侧风险 / 变动区
+ 底部时间规划区
```

其中，中央地图必须始终是主视觉中心。左右面板与底部栏只承担辅助解释与操作承托，不应让主界面退化成三栏仪表盘。

### 3.2 视觉热区表

| 热区 | 建议坐标范围，基于 1920×1080 | 视觉权重 | 适合承载内容 | 不建议承载内容 |
|---|---:|---|---|---|
| 核心视觉热区 | x=520–1400, y=180–760 | 最高 | 地图、当前位置、目标节点、路线、风险、战争迷雾、宗门势力边界 | 大量文字列表、全局设置、复杂表格 |
| 顶部扫描区 | x=0–1920, y=0–96 | 高 | 阶段、倒计时、角色摘要、房间状态、全局入口 | 复杂决策按钮、长文本说明 |
| 右侧决策区 | x=1480–1920, y=96–920 | 高 | 选中节点、目标模板、可达性、抵达后事项、对象级操作 | 全量日志、长列表消息 |
| 左侧告警区 | x=0–380, y=96–920 | 中高 | P0/P1 风险、目标相关变化、重要传闻、宗门摘要 | 阶段推进主按钮、复杂经营操作 |
| 底部规划区 | x=0–1920, y=920–1080 | 高 | 回合时间预算条、行动规划入口、锁定提交、阶段提示 | 地图图层、全局日志列表 |
| 四角弱视觉区 | 四角 80–140px | 低到中 | 设置、日志、缩放、角标、辅助入口 | 核心风险、主 CTA、关键资源判断 |

## 4. 16:9 PC 端操作热区规范

PC 端操作热区不受拇指范围限制，关键是减少高频操作跨屏移动，并让同类操作固定在稳定区域。

### 4.1 操作热区表

| 操作类型 | 建议位置 | 操作示例 | 设计原则 |
|---|---|---|---|
| 地图探索操作 | 中央地图区 | 拖拽、缩放、点击节点、悬停摘要、查看路线 | 保持最大画布面积，地图反馈优先 |
| 上下文操作 | 右侧面板 | 加入计划、设为目标、查看详情、抵达后处理事项 | 只处理当前选中对象，不承担阶段推进 |
| 风险处理操作 | 左侧面板 | 定位节点、查看传闻、标记关注、归档风险 | 只处理信息，不直接抢主 CTA |
| 阶段推进操作 | 底部右侧 | 进入个人行动规划、锁定前检查、确认锁定、返回修改 | 所有阶段级按钮统一收束到底部 |
| 全局工具操作 | 顶部右侧 / 地图浮层 | 账本、库存、宗门、日志、设置、图层切换 | 工具入口保持稳定，不干扰回合主流程 |

### 4.2 按钮层级规范

| 层级 | 放置位置 | 示例 | 规则 |
|---|---|---|---|
| 阶段级主 CTA | 底部右侧 | 进入个人行动规划、锁定前检查、确认锁定 | 只能改变当前回合阶段或提交状态 |
| 对象级 CTA | 右侧上下文面板 | 加入计划、设为目标、查看详情 | 只作用于当前节点、目标或计划草稿 |
| 卡片级 CTA | 左侧信息卡片内 | 定位节点、查看传闻、标记稍后 | 只作用于单条信息或单个风险 |
| 工具级 CTA | 顶部右侧 / 地图浮层 | 日志、设置、图层、缩放 | 不进入主决策链 |

## 5. 当前布局的主要问题

### 5.1 左右面板共同压缩地图

当前地图宽度为 1164px，占屏幕宽度约 60.6%。对“地图驱动”的策略游戏而言，默认信息处理阶段可以接受，但进入地图浏览或行动规划后会显得偏窄。

**影响**：

- 玩家视线容易被左右信息面板分散。
- 地图节点、路线、图层、战争迷雾的优先级被削弱。
- 行动规划阶段地图与底部预算条的联动不够突出。

**优化方向**：

- 左侧待处理面板支持折叠为 rail。
- 进入个人行动规划时默认收起左侧。
- 右侧保留上下文面板，但内部信息重新整合。

---

### 5.2 右侧面板职责过多

当前右侧面板包含三个常驻模块：

```text
目标模板
选中节点摘要
当前位置即时行动
```

这会造成右侧既像目标管理区，又像节点详情区，又像即时事务区。

**影响**：

- 玩家难以区分“当前位置”“正在查看”“计划目标”。
- 非当前位置节点与当前位置即时行动同时出现时，容易产生误解。
- 目标模板占用较大高度，压缩节点上下文信息。

**优化方向**：

- 将右侧改为统一 `ContextPanel`。
- 顶部明确三态：当前位置 / 正在查看 / 计划目标。
- 根据状态显示不同操作，而不是三个模块常驻。

---

### 5.3 即时行动列表存在超框风险

当前 `InstantAction_List_ScrollViewport` 高度为 112px，但内部按钮从 y=0 排到 y=136，已经超过视口高度。

**影响**：

- 若未开启 clip content，按钮可能覆盖底部提示。
- 若滚动反馈不明显，玩家可能误以为只有部分即时行动。
- 高价值即时事务和普通即时事务权重混在一起。

**优化方向**：

- 启用真实滚动容器。
- 默认只显示 3 个高优先级即时行动。
- 其余操作折叠到“更多即时事务”。
- 提示文案改为 sticky footer 或移动到 header subtitle。

---

### 5.4 左侧待处理列表信息密度偏高

当前左侧待处理中心包含筛选、卡片列表、底部按钮、冻结提示。对于 356px 宽度而言，承担职责偏多。

**影响**：

- 左侧容易变成全量消息流。
- P0/P1 与传闻、宗门变化、即时行动提示混杂。
- 阶段级按钮出现在左侧，会与底部 CTA 竞争。

**优化方向**：

- 左侧只显示“影响本回合决策的信息”。
- 移除左侧阶段级按钮。
- 将左侧底部按钮降级为文本操作或归档操作。
- 保留定位、查看、关注，不承载进入规划或锁定。

---

### 5.5 底部 CTA 与右侧 CTA 竞争

当前右侧节点区有对象级按钮，底部也有阶段级按钮。若视觉层级不清晰，玩家可能混淆“加入计划”和“进入个人行动规划”。

**优化方向**：

- 底部只放阶段级按钮。
- 右侧只放对象级按钮。
- 左侧只放信息级按钮。
- 不同层级按钮使用不同视觉权重。

---

## 6. 推荐改版布局

### 6.1 信息处理阶段默认布局

```text
- 统一 ContextPanel

- 左：预算说明
```


## 7. 分模块修改方案

## 7.1 顶部阶段栏 `01_TopPhaseBar`

### 保留内容

- 当前角色摘要。
- 生机、元气、神念状态条。
- 回合阶段条。
- 房间状态。
- 决策倒计时。
- 全局入口：轮回账本、库存、宗门、日志、设置。

### 修改建议

1. 阶段条继续居中，当前阶段 chip 需要更醒目。
2. 全局入口图标点击热区统一为 40×40 或 44×44。
3. 顶部不放阶段推进按钮。
4. 房间状态与倒计时靠右，但不要压缩全局入口。
5. 角色状态条可保留 hover/click target，但默认不要显示过多数值，避免顶栏信息噪声。

### 验收标准

- 玩家在 1 秒内能识别当前阶段。
- 玩家在 1 秒内能看到是否未锁定 / 倒计时剩余。
- 顶部不出现“进入规划 / 锁定提交”等阶段级主按钮。

## 7.2 左侧待处理变动中心 `02_Left_PendingChangesCenter`

### 新定位

左侧不是全量消息中心，而是：

> 本回合决策影响队列。

### 信息优先级

| 优先级 | 内容 | 显示策略 |
|---|---|---|
| P0 | 死亡、重伤、突破、转世、关键后手异常 | 强提示，默认置顶，不可被普通归档淹没 |
| P1 | 路线风险、目标节点变化、宗门关键行动变化 | 次强提示，可定位，可标记关注 |
| 目标相关 | 当前目标、计划目标、后手线索相关变化 | 与目标模板联动 |
| 宗门 | 宗门当前持续行动进展、资源预留、可介入机会 | 摘要显示，详情进宗门面板 |
| 传闻 | 延迟传播、不完整情报、地图线索 | 弱提示，可定位 / 关注 |

### 结构调整

```text
PendingChangesCenter
- Header：待处理变动中心
- Filter：必看 / 目标相关 / 传闻 / 宗门
- Cards：按 P0 → P1 → 目标相关 → 宗门 → 传闻排序
- Footer：只保留“全部归档 / 只看必看”等轻操作
```

### 需要移除或降级

- 移除左侧底部阶段级主按钮。
- 不在左侧提供“进入个人行动规划”。
- 不在左侧提供“锁定提交”。
- 卡片内按钮只保留：查看、定位、关注、稍后。

### 折叠态 rail

左侧应支持折叠为 72–96px rail。

折叠态只显示：

```text
P0 数量
P1 数量
目标相关数量
传闻数量
宗门变化数量
```

点击 rail 可重新展开左侧面板。

### Figma 修改建议

| 项 | 当前 | 建议 |
|---|---:|---:|
| 左侧宽度 | 356px | 默认 320px；折叠 72–96px |
| 卡片列表 | 常驻长列表 | 只显示 4–5 条关键卡片，其余进入更多 |
| 底部按钮 | 两个阶段级按钮 | 改为轻量文本操作 |
| 进入规划按钮 | 左侧 + 底部重复 | 只保留底部 |

## 7.3 中央地图画布 `03_Map_WorldCanvas`

### 新定位

地图是主界面第一视觉中心，负责承载：

- 当前角色位置。
- 当前查看节点。
- 计划目标节点。
- 路线预估。
- 战争迷雾。
- 宗门势力边界。
- 传闻 / 风险 / 秘境窗口。
- 后手感应点。

### 修改建议

1. 左侧折叠时地图自动扩展。
2. 地图图层面板保持在地图左上，但应支持收起。
3. 地图图例默认可折叠，避免占据左下空间。
4. 路线预估浮层应靠近底部预算条，但不能遮挡重要节点。
5. 当前节点、选中节点、目标节点应有稳定视觉编码。

### 节点状态视觉建议

| 节点状态 | 表现 |
|---|---|
| 当前所在地 | 最强光环 + 清晰节点名 |
| 计划目标 | 次强光环 + 路线连接 |
| 已探索 | 普通清晰节点 |
| 传闻节点 | 模糊节点 / 问号 / 虚线边 |
| 高风险节点 | 风险色边框或风险角标 |
| 宗门控制节点 | 势力色轮廓或底纹 |
| 战争迷雾 | 降低饱和度 + 遮罩 |

### 地图与底部预算条联动

当玩家 hover 或点击路线时：

```text
地图显示路线
→ 浮层显示预计耗时 / 风险 / 权限门
→ 底部预算条预览占用天数
```

当玩家点击“加入计划”时：

```text
路线预估变为计划草稿
→ 底部预算条生成行动块
→ 右侧切换为计划目标模式
```

## 7.4 右侧上下文面板 `04_Right_ContextAndGoalPanel`

### 核心修改

将当前三个常驻模块：

```text
ModuleA_GoalTemplates
ModuleB_SelectedNodeSummary
ModuleC_CurrentLocationInstantActions
```

整合为统一：

```text
RightContextPanel
```

### 推荐结构

```text
RightContextPanel 400×842

1. ContextHeader，约 72px
   - 当前位置：云麓宗山门
   - 正在查看：黑石岭矿脉
   - 计划目标：黑石岭矿脉 / 无

2. GoalTemplateCompact，约 48–64px
   - 延续上一回合计划
   - 推进修炼
   - 处理风险
   - 更多模板

3. SelectedObjectSummary，约 360–430px
   - 节点名称
   - 节点状态标签
   - 控制权 / 影响力
   - 危险 / 灵气 / 资源 / 事件
   - 最近变化

4. RouteAndReachability，约 96px
   - 预计耗时
   - 风险标签
   - 权限门
   - 状态门

5. ContextActions，约 120–160px
   - 根据当前模式显示不同按钮

6. FooterHint，约 24–32px
   - 冻结提示 / 预估非最终提示
```

### 三种上下文模式

#### 模式 A：当前位置模式

触发条件：当前查看节点 = 当前角色所在地。

显示：

```text
当前位置：云麓宗山门
正在查看：云麓宗山门
计划目标：无 / 当前草稿目标
```

可显示按钮：

- 领取俸禄 / 配给。
- 查看门内回信。
- 接收委托成品。
- 调整目标模板。
- 当前位置持续行动入口。

注意：即时行动应明确显示“不占用回合时间预算”。

#### 模式 B：选中节点模式

触发条件：玩家点击非当前位置节点，但尚未加入计划。

显示：

```text
当前位置：云麓宗山门
正在查看：黑石岭矿脉
计划目标：无
```

可显示按钮：

- 设为关注目标。
- 查看详情。
- 预估路线。
- 加入行动计划。

不可显示：

- 领取。
- 交付。
- 立即探索。
- 立即采集。
- 任何当前位置即时行动。

应显示文案：

```text
抵达后可能处理事项：探索矿脉、调查异动、协助驻守。
```

#### 模式 C：计划目标模式

触发条件：选中节点已经进入本回合行动草稿。

显示：

```text
当前位置：云麓宗山门

计划目标：黑石岭矿脉
```

可显示按钮：

- 修改目标。

同时提示：

```text
进入个人行动规划后，个人即时行动将冻结。
```

### 目标模板调整

当前目标模板区高度 168px 偏大，建议降级为紧凑组件：

```text

```

默认只展示 3 个推荐 chip，更多模板进入下拉或抽屉。

## 7.5 即时行动区域

### 新定位

即时行动只应出现在：

1. 当前位置模式的右侧上下文面板。
2. 顶部右侧全局事务抽屉。

即时行动不应作为地图目标节点的直接操作，也不应与持续行动混排。

### 列表规范

```text
默认显示：3 个高优先级即时行动
超过 3 个：显示“更多即时事务”
列表高度：至少容纳 3 个按钮 + 2 个间距
按钮高度：28–32px
按钮间距：4–6px
滚动容器：clip content = true
底部提示：sticky footer 或 header subtitle
```

### 优先级排序

| 优先级 | 类型 | 示例 |
|---|---|---|
| 高 | 高价值已完成事务 | 接收委托成品、领取宗门配给、重要回信 |
| 中 | 当前节点短事务 | 拜访执事、查看公告、整理随身物品 |
| 低 | 信息类事务 | 查看功法详情、普通日志、目标模板调整 |

### 冻结状态

进入个人行动规划后，即时行动区不再显示可点击按钮，改为显示：

```text
即时行动已冻结。
如需处理即时事务，请返回信息处理阶段并清除行动草稿。
```

## 10. 交互流程建议

### 10.1 点击地图节点

```text
点击地图节点

→ 显示节点摘要、可达性、风险、抵达后事项
→ 地图高亮该节点
```

### 10.2 加入计划

```text
点击“加入计划”
→ 如果尚未进入个人行动规划：提示将进入规划并冻结即时行动
→ 生成移动指令草稿
→ 底部预算条显示预计占用
```

```text

→ 服务端立即校验并生效

```

## 11. 内容与文案规则

### 11.1 左侧卡片文案

左侧卡片应短句化，避免长段叙述。

推荐格式：

```text
标题：黑石岭矿脉局势升温
正文：宗门驻守推进至 40%，外宗活动增加。若本回合前往，路线风险上升。
标签：P1 / 目标相关 / 节点变化
按钮：定位节点 / 查看详情
```

### 11.2 右侧节点摘要文案

右侧节点摘要应突出可决策字段：

```text
控制权：云麓宗
影响力：云麓宗高，外宗低
危险：中，边境冲突升温
灵气：较低，矿脉灵气不稳
资源：矿材紧张，疑似异动
路线：约 1.5 天，有妖兽与外宗活动风险
抵达后可能事项：探索矿脉 / 协助驻守 / 调查异动
```

### 11.3 冻结提示

推荐文案：

```text
进入个人行动规划后，个人即时行动将冻结。
如需处理即时事务，请返回信息处理阶段并清除行动草稿。
```

不要使用模糊文案，例如：

```text
部分操作不可用。
```

## 14. 验收标准

### 14.1 视觉验收

- 地图在默认状态下仍是第一视觉中心。
- 左右面板不应让界面呈现强仪表盘感。
- 当前所在地、正在查看节点、计划目标三者能被清晰区分。
- P0/P1 风险在左侧能被立即识别。
- 底部阶段级按钮权重高于右侧对象级按钮。

### 14.2 交互验收

- 点击非当前位置节点时，不出现可直接执行的即时行动。
- 进入个人行动规划后，即时行动全部冻结。
- 阶段推进按钮只出现在底部右侧。
- 左侧卡片按钮只执行查看、定位、关注、归档等信息操作。
- 右侧对象级按钮不会直接锁定提交。
- 底部预算条能展示空闲、预览、已规划、冻结、锁定等状态。

### 14.3 信息架构验收

- 玩家能在 10 秒内回答：我在哪里、我正在看哪里、我本回合是否已有计划。
- 玩家能在 10 秒内回答：是否有 P0/P1 风险影响本回合。
- 玩家能在 10 秒内找到“进入个人行动规划”。
- 玩家能明确理解“即时行动”和“占用时间预算的行动”的区别。

### 14.4 Figma 文件验收

- 右侧不再存在三个互相竞争的常驻模块。
- 即时行动列表不存在内容超出容器后覆盖提示的问题。
- 左侧没有阶段级主按钮。
- 底部 `PhaseCTA_Group` 中包含当前阶段唯一主 CTA。
- 折叠态左侧 rail 有独立组件或变体。

## 16. 本轮修改后的预期效果

修改后，玩家的主界面阅读路径应从当前的：

```text
左侧消息 → 右侧目标 → 地图 → 底部按钮
```

调整为：

```text
地图变化
→ 左侧确认风险
→ 右侧查看对象上下文
→ 底部规划本回合
→ 底部锁定提交
```

这能更好服务项目的核心体验：玩家不是管理一个宗门后台，而是在共享沙盒地图中，用有限的回合时间预算规划本世行动，影响宗门、节点、资源与后续轮回。
