# 07_后手遗产_可见性_多人间接竞争_v2.2

# 后手、遗产、可见性与多人间接竞争（v2.2）

## 0. 文档定位

本文整理前世遗产、正式后手、隐藏层、后手风险、回收流程、可见性、传闻和 MVP 多人边界。

核心原则：

> 后手可信，多人间接，信息不全知。
> 

新版重点：后手创建与回收使用回合时间预算，不再消耗行动格；所有时间字段统一为 `turn_id / world_day / world_hour`。

---

## 1. 普通前世遗产与正式后手

必须区分两类跨世外在资产。

| 类型 | 规则含义 | 保护强度 |
| --- | --- | --- |
| 普通前世遗产 | 前世死亡或放置后自然留在世界中的资产 | 可被发现、搬空、污染、破坏或转移 |
| 正式后手 | 经过正式行为封存、布置、记录并占用后手容量的安排 | 必须可追踪、有日志、失效有原因链 |

正式后手不是无限保险箱。它可以暴露、受损或被争夺，但不能无日志、无原因地消失。

---

## 2. 后手容量

正式后手容量由真灵强度提供。

```
FormalContingencySlot {
  spirit_id: String,
  max_slots: int,
  used_slots: int,
  unlocked_by_spirit_strength: int
}
```

MVP 只需要支持少量正式后手，不追求复杂组合。

---

## 3. 后手类型

MVP 推荐：

1. 藏物后手：封存物品、灵石、丹药、法宝、功法载体。
2. 地点后手：洞府、隐蔽山洞、阵法点、接引点。
3. 信息后手：遗书、地图、暗号、任务链、线索。

接口预留：

1. 权限后手：宗门密库权限、令牌、身份凭证。
2. 护持后手：护道人、弟子安排、阵法守护。

---

## 4. 后手创建流程

```
玩家选择正式布置后手
→ 检查真灵后手容量
→ 检查当前位置、物品、资源、权限与时间投入
→ 选择后手类型与封存目标
→ 生成后手记录
→ 写入节点隐藏层 / 后手层
→ 写入轮回账本
→ 消耗回合时间预算、资源或物品
```

后手创建应是固定执行时间或可选投入执行时间的个人持续行动，或事件链结果，不应作为纯即时行动完成。

## 6. 后手感应

后手感应不是常规强度加成，而是轮回账本交互规则。

最小规则：

- 玩家越接近正式后手所在区域，账本描述越清晰。
- 相关地点、传闻、路线或事件可提高感应清晰度。
- 感应只提供线索，不自动传送或直接领取。
- 感应强度可受真灵强度、道韵、失败经历、地点状态影响。

---

## 7. 后手回收流程

```
玩家获得后手线索
→ 通过地图、传闻、账本感应定位区域
→ 规划个人行动前往节点
→ 触发隐藏层 / 后手层事件
→ 检查访问条件、封存状态、风险状态
→ 处理守卫、污染、被发现、被搬空等结果
→ 生成回收或失败结果包
→ S1 回写资产、账本、节点状态和日志
```

回收高风险后手不得由托管主动执行。

回收通常属于：

```
个人持续行动 + 专用事件链
```

可根据模板使用固定执行时间或可选投入执行时间。

---

## 8. 后手风险状态

建议状态：

```
stable：稳定。
exposed：已暴露。
contested：被争夺。
damaged：受损。
polluted：污染。
moved：被转移。
looted：被搬空。
lost_with_reason：失效但有原因链。
```

正式后手风险只在相关节点发生明确变化时检定，例如：

- 节点控制权变化。
- 节点被洗劫。
- 隐藏层被发现。
- 重大灾害。
- 宗门 AI 持续行动波及。
- 玩家高风险回收失败。
- 后手相关敌对事件触发。

不做每回合随机磨损，不做年久失修型低频随机风险。

---

## 9. 普通前世遗产

普通遗产不是正式后手。

规则：

- 可自然留在死亡现场、住所、洞府、宗门库房或节点储藏中。
- 可被 NPC、宗门、事件、玩家、世界状态转移或破坏。
- 重要变化应有世界日志。
- 玩家下一世未必能感应或定位。
- 若普通遗产被正式封存，则转为正式后手并占用容量。

---

## 10. 失效原因链

正式后手失效必须有原因链。

```
ContingencyFailureReason {
  contingency_id: String,
  failure_turn_id: int,
  failure_world_day: int,
  cause_type: String,
  cause_ref: String,
  involved_factions: Array,
  visible_to_player: String,
  recoverable_clue_refs: Array,
  world_log_ref: String
}
```

失效后应尽量提供：

- 可追查线索。
- 传闻或账本模糊记录。
- 可能的补救事件。
- 资产去向或损毁解释。

---

## 11. 可见性系统

玩家行动不是全图公开。

可见性来源：

- 是否同节点。
- 是否同宗门或有权限查看。
- 行动是否公开。
- 行踪是否暴露。
- 是否进入传闻。
- 是否由宗门日志或世界事件公开。
- 情报能力。

统一层级：

```
private
local_visible
sect_visible
rumor_visible
world_visible
debug_only
```

功法资产封存口径：

- 可封存残页 / 篇章等 `MethodComponentItem`，作为下一世线索、合成材料或宗门任务凭证。
- 可封存完整功法载体 `MethodCarrierItem`，下一世满足访问条件后可学习并生成新的 `MethodState`。
- 不封存当世角色的 `MethodState` 作为跨世能力；掌握度默认随当世角色终结。
- 若需表达前世理解，应通过轮回账本、执念、道韵或线索提高下一世重新研习效率，而不是直接继承功法等级。

---

## 12. 世界日志与传闻

世界日志默认玩家不可见。玩家看到的是：

- 角色日志。
- 宗门摘要。
- 轮回账本。
- 传闻。

传闻由事件或世界日志生成，经可见性系统决定是否传播。

传闻受以下因素影响：

- 事件公开性。
- 地点人流。
- 宗门关系。
- 玩家声望。
- 行踪暴露标签。
- 事件严重度。
- 情报能力。

传闻可以模糊、延迟、不完整，不能等同于全知日志。

---

## 13. 多人原则

MVP 多人默认：

```
分宗并行 + 间接竞争 + PvE 沙盒演化
```

不以玩家直接合作、直接对抗或高频社交互动作为核心验证目标。

---

## 14. 允许的 MVP 竞争

保留两类轻量间接竞争：

1. 宗门节点控制、资源窗口、秘境机会的间接竞争。
2. 正式后手、遗产、传闻与地图信息的不完全竞争。

禁止：

- 玩家直接交易。
- 玩家直接赠予。
- 玩家共同秘境。
- 玩家互相护法。
- 玩家破坏他人突破。
- 离线袭击玩家主体。
- 强 PvP 围杀。

---

## 15. 同宗多人边界

同宗玩家不做强制投票，不做宗门行动输入冲突解析。

由于本版移除玩家宗门指令，同宗多人之间不再通过宗门主行动建议产生直接输入冲突。

同宗多人可能通过以下方式间接互相影响：

- 申请宗门资源，影响库存和预留。
- 解决同一节点危机，改变宗门 AI 后续判断。
- 上交资源，提升宗门库存。
- 提高自身身份，改变可见情报和资源权限。
- 触发传闻或事件，改变他人的已知世界状态。
