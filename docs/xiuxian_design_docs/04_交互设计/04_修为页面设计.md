# 交互设计｜修为页面设计

## 1. 当前状态

本页面仍处于交互约束草案阶段，当前只固定修为页面对境界进度、主修、资源输入、突破准备和 B1 突破挑战的展示边界，不维护完整视觉稿、Figma 节点或旧来源清单。

修为页面服务于玩家理解“当前修到哪里、还能不能继续修、下一步需要准备什么”。它不直接替代行动指令页面，不在交锋中提供即时服丹入口，也不保存突破阶段选择。

## 3. 用户目标与入口

玩家进入修为页面时，需要完成以下目标：

1. 查看当前阶段编码、包装名和当前境界段进度。
2. 判断主修道功、掌握度和当前可修上限是否限制继续修炼。
3. 区分小境界升级和大境界突破。
4. 查看突破准备维度、关键资源、地点、护法和宗门支持。
5. 查看修炼资源输入和已有残余效果对后续行动的影响。
6. 从修为页面跳转到行动规划、功法、储物或突破准备相关入口。

入口来自主界面修为摘要、角色页、功法页、突破提示、修炼结果包和瓶颈提示。

## 4. 必须表达

1. 当前阶段编码与包装名。
2. 当前境界段进度，可用 CP 或标准化进度包装展示。
3. 主修道功、掌握度、当前可修上限和理论最高上限摘要。
4. 小境界升级与大境界突破的区别。
5. 突破准备维度、关键资源、地点、护法、宗门支持。
6. 高风险突破不得由托管自动发起。
7. 修为丹药等资源输入应出现在具体行动内折叠项，而不是默认全局资源栏。
8. 已有残余效果应在角色状态或行动规划器中常驻提示。
9. MVP 丹药没有即时生效类型，不能在突破或战斗交锋中提供“即时服丹”入口。
10. 洞天 / 时间阵法闭关必须展示现实预计耗时、外界预计经过时间、洞天内预计修炼年数、预计寿元消耗、资源可支撑年数、资源不足年份、预计有效修炼年数和本次 F1 中断策略。
11. 轮回提示不得承诺“轮回后一定更快”，应表达为提高路线确定性、先天适配和成功率，但可能需要等待世界资源成熟或大型机缘窗口。

## 5. 页面区块与信息优先级

推荐信息优先级：

1. 修为总览区：阶段编码、包装名、境界段进度、瓶颈状态。
2. 主修与上限区：当前主修道功、掌握度、当前可修上限和上限原因。
3. 修炼行动入口区：吐纳、闭关、巩固、疗伤等可跳转行动入口。
4. 资源输入区：当前行动可选资源、已炼化残余效果和剩余有效小时。
5. 时间与资源年区：现实耗时、外界经过、洞天内主观年、资源支撑年、资源不足年、寿元和风险。
6. 突破准备区：资源、地点、护法、宗门支持、风险和默认策略。
7. 突破结果区：突破阶段、耗时、资源消耗、成功 / 失败摘要和日志入口。

页面不固定进度条样式、面板布局或具体视觉组件。

## 6. 操作流程与状态

查看进度：

```text
打开修为页面
→ 查看当前阶段、进度、主修和瓶颈
→ 根据提示进入修炼行动或突破准备
```

配置修炼资源输入：

```text
选择修炼行动入口
→ 展开具体行动的资源输入项
→ 校验资源、状态和地点
→ 提交到指令管理页或行动规划器
```

准备突破：

```text
达到突破前置
→ 查看准备维度和风险
→ 选择资源、地点、护法或宗门支持
→ 生成开启突破短指令
→ 进入 B1 突破挑战
```

突破挑战进入 B1 后，界面应表达：

```text
每个突破阶段只输入 1 个交锋格；
每阶段现实决策窗口为 60 秒；
阶段耗时由突破模板声明；
总耗时暂定 1-6 游戏小时；
阶段耗时会参与持续效果、资源和时间结算；
未提交时执行当前突破预设。
```

界面不得把突破阶段显示成固定 1 游戏小时，也不得使用普通行动队列保存阶段选择。

## 7. 不表达或 Debug 边界

普通修为页面不展示完整 CP 根表、公式逐项倍率、调参字段、Debug 缓存、隐藏突破权重或未揭示事件条件。

修为页面不应表达为：

1. 全局丹药栏。
2. 交锋中即时服丹入口。
3. 普通行动队列保存突破阶段选择。
4. 托管自动发起高风险突破。
5. 主修掌握度和当前可修上限已经无关紧要。
