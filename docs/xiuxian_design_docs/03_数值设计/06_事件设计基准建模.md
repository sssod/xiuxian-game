# 数值设计｜事件设计基准建模

## 1. 设计定位

本文负责随机事件、节点事件、窗口事件、传闻事件和专用事件链入口的数值建模基准。它维护事件候选生成、候选池评分排序、去重节流、事件强度、选项成本 / 风险 / 收益、隐藏后患、奖励预算、结果包输出和验算指标。

系统玩法由《随机事件玩法设计》（`../02_系统设计/15_随机事件玩法设计.md`）维护；本文只维护数值建模、调参接口和验算约束。本文不负责完整事件文本库、最终概率表、战斗伤害公式、突破轮内成功率公式、NPC AI 权重、UI 视觉布局、数据库 schema 或网络协议。

## 2. 当前结论

1. 事件数值运行在 `world_day / world_hour` 与 `hour_tick` 上，不再使用 `quarter / tick / 行动格` 作为事件主时间字段。
2. 事件候选必须由世界状态、角色状态、节点状态、行动上下文、窗口、资源预算、可见性和冷却共同生成，不做纯 UI 刷新随机。
3. 事件概率、权重、窗口出现频率和同一 `hour_tick` 最大普通触发数量尚未定；本文只定义可验算的配置结构和首版边界。
4. 候选生成可以有随机扰动，但必须使用事件实例稳定种子或稳定排序，不能靠刷新界面改变候选。
5. 普通个人选择事件和轻遭遇使用局部时停；C1 追赶期间不触发新的随机个人事件、普通机缘、普通战斗、软机会事件、普通心魔或普通资源反馈。
6. 正式交锋和突破挑战进入 B1；B1 的现实提交窗口、非参战世界推进和参战交锋自身结算耗时必须分开记录。
7. 事件奖励不得绕过世界产出预算、资产容器、库存来源、资源预留和结果包审计。
8. 低价值事件可以被显式托管保守处理；重大事件、正式交锋、突破挑战、不可逆选择和死亡风险不得被普通队列或自动兜底吞掉。
9. F1 中事件仍会触发；预定事件、阈值事件、危险率事件和条件事件可通过事件流采样进入批量结算断点或摘要。

## 4. 基准、单位与输入参数

事件数值链路分为触发、候选、实例、选项、结果和验算六层：

```text
EventTriggerProfile
→ EventCandidatePool
→ EventCandidateScore
→ EventInstance / EventChain
→ EventOptionNumericProfile / EventCheckProfile
→ EventOutcome / ResultPackage
→ EventBalanceSimulation
```

| 模块 | 作用 |
| --- | --- |
| `EventTriggerProfile` | 定义某类事件在什么触发源、节点、状态和时间条件下进入候选池 |
| `EventCandidatePool` | 聚合同一 `hour_tick`、同一角色、同一节点或同一窗口的候选事件 |
| `EventCandidateScore` | 对候选按上下文匹配、风险、压力、预算、冷却和随机扰动排序 |
| `EventInstance / EventChain` | 固化事件实例、候选选项、稳定随机种子、阶段和状态 |
| `EventOptionNumericProfile` | 定义选项成本、风险、收益强度、时间成本、资源输入和隐藏标签 |
| `EventCheckProfile` | 定义低交互检定、暴露、发现、抵消、追查和失败标签判定 |
| `EventOutcome / ResultPackage` | 输出权威结算所需的时间、状态变化、日志、传闻、预算和子事件请求 |
| `EventBalanceSimulation` | 验算事件密度、打断率、奖励预算消耗、B1 / P0 频率和负反馈强度 |

时间、随机和上下文基准：

1. 候选生成使用 `trigger_world_day / trigger_world_hour` 和 `hour_tick`。
2. 事件模式使用 `event_time_mode` 区分信息、局部时停、轻遭遇、正式交锋、突破挑战和全局暂停。
3. 随机扰动必须归属 `rng_namespace`，并在事件实例或候选排序中稳定复盘。
4. 所有状态变化、预算扣减、窗口变化和日志输出必须能追溯到事件上下文。

`EventContext` 推荐字段：

```yaml
EventContext:
  context_id: string
  trigger_world_day: int
  trigger_world_hour: int
  trigger_type: travel_leave | travel_enter | route_hour_tick | action_hour_tick | action_complete | node_update | sect_update | window_update | contingency_trigger | death_or_reincarnation | rumor_update | manual_debug
  event_time_mode: info | local_time_stop | light_encounter | formal_encounter_b1 | breakthrough_b1 | global_pause_p0
  actor_refs: list[string]
  faction_refs: list[string]
  node_id: string | null
  route_id: string | null
  route_segment_ref: string | null
  current_command_ref: string | null
  action_context: object
  visibility_context: object
  risk_level: low | medium | high | unknown | null
  resource_slot_refs: list[string]
  facility_refs: list[string]
  hidden_layer_refs: list[string]
  contingency_refs: list[string]
  remnant_site_refs: list[string]
  opportunity_window_refs: list[string]
  rumor_refs: list[string]
  current_macro_period_id: string | null
  time_domain_scope: outer_world | local_time_domain | threshold | scheduled | conditional
  local_time_domain_ref: string | null
  rng_namespace: string
```

旧口径迁移：

| 旧字段 / 旧说法 | 当前口径 |
| --- | --- |
| `quarter` | 不作为事件主时间字段；宏观批次使用 `current_macro_period_id` |
| `tick` | 具体结算使用 `hour_tick`、`trigger_world_day`、`trigger_world_hour` |
| `danger_level` | 地图风险统一为 `risk_level`；事件自身可另有风险描述标签 |
| `route_segment` | 迁移为 `route_segment_ref` |
| 行动格消耗 | 迁移为 `consumed_hours`、行动进度变化、B1 世界推进或交锋自身结算耗时 |
| 世界刷新只在季度开始发生 | 迁移为世界小时演化 + 宏观周期批次；窗口、资源和传闻仍可按宏观周期批量显现 |

## 5. 公式或模型

### 5.1 候选池评分

候选评分不是最终概率公式，而是可用于首版实现和验算的统一接口。

```yaml
EventCandidateScore:
  candidate_id: string
  template_id: string
  context_id: string
  base_weight: number
  context_fit_multiplier: number
  realm_fit_multiplier: number
  node_risk_multiplier: number
  pressure_multiplier: number
  resource_budget_multiplier: number
  visibility_multiplier: number
  cooldown_multiplier: number
  repeat_penalty_multiplier: number
  priority_override: force | high | normal | low | suppress | null
  stable_rng_jitter: number
  final_score: number
  score_reason_tags: list[string]
```

推荐起步公式：

```text
final_score =
  base_weight
  * context_fit_multiplier
  * realm_fit_multiplier
  * node_risk_multiplier
  * pressure_multiplier
  * resource_budget_multiplier
  * visibility_multiplier
  * cooldown_multiplier
  * repeat_penalty_multiplier
  * stable_rng_jitter
```

规则：

1. 缺少匹配信息时默认倍率为 `1.0`，不得因为字段缺失自动放大事件概率。
2. `priority_override = force` 的强制事件优先结算，但仍必须写明触发原因。
3. `priority_override = suppress` 用于冷却、C1、不可见、预算不足或状态已失效的候选。
4. `stable_rng_jitter` 只能在事件实例稳定种子下生成，不能随 UI 刷新变化。
5. 调试器应能展示 `score_reason_tags`、命中的条件、被压制原因和排序结果。

### 5.2 候选池节流与去重

同一 `hour_tick` 和同一上下文中可能存在多个候选事件。MVP 采用以下节流规则：

1. 强制事件优先于普通事件。
2. 专用事件链入口优先于普通传闻。
3. 已经进入 B1 或 P0 的事件优先锁定对应速度状态。
4. 同一语义事件在同一 `hour_tick` 和同一上下文中只触发一次。
5. 同一角色同一时刻最多只能有一个需要本人处理的局部时停事件。
6. C1 追赶期间所有新随机个人候选都必须被 `suppress`。
7. 事件链进行中时，普通角色时间线按 `event_time_mode` 决定冻结、继续或进入交锋。
8. 事件返回后，由权威结算决定继续原计划、进入 C1、跳过指令、自动兜底或开启子事件。

首版世界级重大事件容量建议：

```text
同一区域同时最多 1 个 active major 世界事件；
世界全局同时不超过 2 个 active major 世界事件；
每个 active major 世界事件必须至少有一个玩家可理解的介入窗口；
忽略重大事件可以改变世界态势，但不应无预警造成毁档式损失。
```

以上容量只约束重大世界状态机，不等于普通事件候选池的最终触发上限。

### 5.3 事件强度分层

事件实例和结果包应区分事件模板强度与实际结果强度。首版可以统一使用 `outcome_level` 做结果强度：

```text
none
minor
standard
major
critical
```

| `outcome_level` | 含义 | 常见结果 |
| --- | --- | --- |
| `none` | 信息、提示或日志更新，无实质状态变化 | 传闻记录、价格提示、节点趋势 |
| `minor` | 轻量变化，不应造成长期大改动 | 小延误、少量资源消耗、低风险发现、轻微关系波动 |
| `standard` | 常规事件结果，可以改变一次行动、节点、库存、关系或传闻 | 普通移动遭遇、资源异变、节点风险、常规探索发现 |
| `major` | 高价值或高风险结果，会影响窗口、战斗、突破、宗门评价、重要资产或节点态势 | 秘境入口、正式交锋入口、高价值后手线索、控制权变化 |
| `critical` | 不可逆或接近不可逆结果，需要明确模板、安全默认或 P0 同步保护 | 死亡边缘、重大夺舍、不可逆功法路线、严重资源损毁、公共世界级事件 |

强度规则：

1. 低风险普通候选不得直接随机生成 `critical` 结果；必须经过明确模板、玩家选择、B1 / P0 或高风险上下文。
2. `major / critical` 结果必须写入日志、回放、可见性规则和 Debug 审计。
3. 事件奖励强度不得高于其成本、风险、窗口稀缺性和预算来源能解释的范围。
4. 失败结果也要有强度分层，不能只输出“未成功”。

### 5.4 时间成本模型

事件时间成本统一通过 `EventTimeCostProfile` 表达。

```yaml
EventTimeCostProfile:
  event_id: string
  event_time_mode: info | local_time_stop | light_encounter | formal_encounter_b1 | breakthrough_b1 | global_pause_p0
  trigger_world_day: int
  trigger_world_hour: int
  frozen_character_world_day: int | null
  frozen_character_world_hour: int | null
  option_declared_hours: int
  consumed_hours: int
  b1_world_elapsed_hours: int | null
  nonparticipant_progress_hours: int | null
  encounter_scene_elapsed_minutes: int | null
  encounter_accounting_hours: int | null
  participant_gap_hours: int | null
  catchup_required: bool
  default_resolution_used: bool
```

| 场景 | 时间处理 |
| --- | --- |
| 信息事件 | 通常 `consumed_hours = 0`，不打断 |
| 普通个人选择事件 | `option_declared_hours` 从触发 `world_hour` 开始回填；结束后按需 C1 |
| 轻遭遇 | 按普通个人选择事件处理，除非升级为正式交锋 |
| 正式交锋 | B1 负责现实提交窗口与非参战世界推进；交锋自身耗时由战斗结果包返回 |
| 突破挑战 | B1 负责现实提交窗口与非参战世界推进；突破自身耗时由突破阶段模板累计 |
| 全局公共事件 | P0 中游戏时间不流动，解除后由权威结算恢复速度 |

`consumed_hours` 在事件层表示本事件对角色、行动或追赶结算的最终可记账小时。B1 事件必须额外保留 `b1_world_elapsed_hours / encounter_accounting_hours` 等细分字段，避免把现实提交窗口、世界慢速推进和交锋叙事耗时混成一个数。

### 5.5 检定模型

检定事件用于低交互判定、暴露、发现、抵消、追查、被动法宝受损、NPC 察觉等场景。

```yaml
EventCheckProfile:
  check_id: string
  check_domain: exposure | discovery | resistance | persuasion | escape | deception | protection | trace | resource_stability | custom
  primary_actor_stat_refs: list[string]
  method_or_technique_tag_refs: list[string]
  item_or_resource_refs: list[string]
  node_context_refs: list[string]
  relationship_context_refs: list[string]
  base_difficulty: number
  difficulty_stage_fit: number
  pressure_modifier: number
  resource_modifier: number
  visibility_modifier: number
  stable_rng_namespace: string
  success_band_profile_ref: string
  fail_tag_refs: list[string]
```

推荐起步公式：

```text
check_score =
  actor_fit
  + method_fit
  + item_or_resource_support
  + relationship_support
  + node_context_support
  - base_difficulty
  - pressure_modifier
  - visibility_modifier
  + stable_rng_roll
```

结果分段建议：

```text
clear_fail
partial_fail
partial_success
clear_success
exceptional_success
```

检定事件不承担重大路线决策。高风险、高损失、高稀缺机会事件应转成选择事件、正式交锋、窗口事件或 P0 公共事件。

### 5.6 F1 事件流与危险率采样

F1 批量结算中不逐小时全量掷骰，但事件不能被闭关承诺吞掉。事件触发方式包括：

1. 预定事件：宗门会议、洞天开放、市场刷新、行动完成，直接进入日历队列。
2. 阈值事件：资源耗尽、寿元低于阈值、心魔超过阈值、阵法燃料不足，计算 crossing time。
3. 危险率事件：闭关心魔、洞天异动、路途遭遇、宗门突发，以危险率采样下一触发时间。
4. 条件事件：进入某节点、携带某物、达到某境界、触发某关系后，在满足条件的区间内采样或排程。

事件等级：

| 事件等级 | 是否退出 F1 | 处理方式 |
| --- | --- | --- |
| `silent` | 否 | 后台记录或仅影响数值，不打扰玩家 |
| `summary` | 否 | 写入 F1 摘要 |
| `auto` | 否 | 按玩家预设、托管策略或安全默认处理，并写入摘要 |
| `soft_interrupt` | 视情况 | 有预设则自动处理；无预设则退出 F1 到 N1 |
| `hard_interrupt` | 是 | 立即退出 F1，进入 N1 / B1 / P0 |

F1 事件流必须保留采样随机种子、事件流引用、断点和结果摘要，保证可复盘。

## 6. 配置表或根表

### 6.1 事件触发配置

`EventTriggerProfile` 是事件候选进入系统的根配置。

```yaml
EventTriggerProfile:
  trigger_profile_id: string
  trigger_scope: travel | node | action | sect | world | window | contingency | rumor | debug
  trigger_type: travel_leave | travel_enter | route_hour_tick | action_hour_tick | action_complete | node_update | sect_update | window_update | contingency_trigger | death_or_reincarnation | rumor_update | manual_debug
  event_template_refs: list[string]
  eligible_time_modes: list[string]
  required_context_tags: list[string]
  excluded_context_tags: list[string]
  recommended_stage_range: string | null
  required_node_tags: list[string]
  required_risk_levels: list[string]
  required_window_types: list[string]
  resource_budget_refs: list[string]
  base_trigger_weight: number | null
  min_world_gap_hours: int | null
  min_actor_gap_hours: int | null
  cooldown_tags: list[string]
  repeat_penalty_profile_id: string | null
  max_candidates_per_context: int | null
  max_resolved_per_hour_tick: int | null
  mvp_enabled: bool
```

字段口径：

1. `base_trigger_weight` 是排序和验算参数，不代表最终概率已经定稿。
2. `min_world_gap_hours / min_actor_gap_hours` 用于防止同类事件短期重复打断。
3. `max_candidates_per_context / max_resolved_per_hour_tick` 必须可配置；首版可以保守设置，但具体数值仍需实测。
4. `resource_budget_refs` 只表示该事件可能读取或消耗哪些预算，不表示候选生成时立即扣预算。
5. `trigger_scope = debug` 只能用于调试器或 QA，不进入正常玩家流程。

F1 事件流可使用 `EventStream` 或等价配置：

```yaml
EventStream:
  stream_id: string
  scope: character | sect | node | market | world | local_time_domain
  applicable_states: list[string]
  hazard_rate_model: constant | table | formula | scheduled | threshold
  base_rate_per_outer_day: number | null
  base_rate_per_inner_year: number | null
  interrupt_level: silent | summary | auto | soft_interrupt | hard_interrupt
  default_resolution_policy: string | null
  max_triggers_per_batch: number
  cooldown_policy: string
  visibility_policy: string
```

### 6.2 事件选项数值配置

`EventOptionNumericProfile` 定义事件选项的成本、风险、收益和隐藏后患。

```yaml
EventOptionNumericProfile:
  option_id: string
  dimension: direct | unconventional | avoid | deconstruct | deceive | none
  availability_conditions: list[object]
  reveal_conditions: list[object]
  preferred_option_area: primary | overflow | auto
  time_cost_hours: int
  resource_input_refs: list[string]
  inventory_cost_refs: list[string]
  relationship_cost_profile_ref: string | null
  visibility_risk_profile_ref: string | null
  check_profile_refs: list[string]
  child_event_request_refs: list[string]
  outcome_level_floor: none | minor | standard | major | critical
  outcome_level_ceiling: none | minor | standard | major | critical
  reward_budget_profile_ref: string | null
  hidden_debt_tags: list[string]
  fail_tag_refs: list[string]
  preview_direction_tags: list[string]
```

五类维度的数值倾向：

| 维度 | 数值倾向 | 风险边界 |
| --- | --- | --- |
| `direct` 正面应对 | 作为事件基本解法，成本和收益最容易解释 | 条件不足时可退化为承受后果或直面失败 |
| `unconventional` 出奇制胜 | 可降低损耗、提高收益或改变事件类型 | 必须消耗稀缺条件、暴露能力或占用后手 |
| `avoid` 逃避推诿 | 降低即时风险和交互成本 | 常伴随奖励损失、声望下降、窗口错过或长期后果 |
| `deconstruct` 解构问题 | 改变问题成立前提，常降低事件严重度 | 失败时可能带来关系代价、越权风险或追责 |
| `deceive` 欺诈蒙骗 | 短期收益高、即时成本低 | 必须写入隐藏后患、暴露风险、追查标签或因果负担 |

常规选择事件中，每个维度最多生成 1 个候选选项。主选项区显示 1-3 个选项，超过 3 个时通过“...”进入溢出选项区；常规事件默认隐藏不可用选项。

### 6.3 奖励与预算

事件奖励、掉落、交易包、赔偿、宗门资源、秘境收益和后手相关资产必须接入世界产出预算、资源池或既有资产来源。

```yaml
EventRewardBudgetProfile:
  reward_profile_id: string
  reward_type: asset | resource | relationship | clue | window_access | sect_contribution | character_state | mixed
  allowed_tier_codes: list[string]
  allowed_quality_codes: list[string]
  budget_pool_refs: list[string]
  budget_value_cap: number | null
  locked_reward_policy: none | reserve_on_event_start | reserve_on_option_select | reserve_on_success
  fallback_when_budget_insufficient: downgrade | replace_with_clue | delay_refresh | create_locked_unavailable_state | trigger_contest_event | suppress_reward
  provenance_required: none | light | full
  log_level: normal | important | critical
```

预算规则：

1. 隐性候选生成不扣世界产出预算。
2. 资产进入玩家、宗门、NPC、市场、节点显性库存或事件锁定奖励时才扣预算。
3. 出售、拆解、销毁、上交、损坏或消耗不返还世界生成预算。
4. 预算不足时，不得凭空发放高价值奖励；应降品级、替换为线索、延迟刷新、生成“发现但暂不可取”的事件状态，或触发守护 / 争夺事件。
5. 高于当前阶段预算的资源只能来自先锋泄漏、剧情、强敌真实资产、正式后手、专属资源池、事件锁定奖励或明确高风险机会。
6. NPC 战利品、交易包和赠予不得在事件开始时临时生成完整库存，只能来自持久化资产、事件锁定奖励包或有预算来源的轻量资产包。

## 8. 调参验收口径

事件调参与实现验收至少检查：

1. 候选生成使用 `world_day / world_hour` 和 `hour_tick`，不读取 `quarter / tick` 旧字段。
2. 事件候选池可在 Debug 中展示候选、命中条件、排序、压制原因和稳定随机种子。
3. 同一语义事件在同一上下文中不会因 UI 刷新重复触发。
4. C1 追赶期间不触发新的随机个人事件。
5. 普通个人事件最多产生 1 个当前角色局部时停阻塞。
6. 事件选项 1-3 个主选项加“...”溢出结构的分配结果可复盘。
7. `major / critical` 事件结果必须进入结果包、日志、回放和可见性审计。
8. 事件奖励必须能追溯预算、既有资产或事件锁定奖励来源。
9. 窗口事件开启、关闭、错过、进入和争夺都能写入结果包。
10. 普通玩家 UI 不显示完整候选权重、隐藏追查标签、Debug 日志或其他玩家私人事件归因。
11. F1 中资源耗尽、心魔、洞天异动、路途遭遇和宗门突发能通过事件流进入摘要或断点，不被闭关承诺吞掉。
12. F1 事件流结果可复盘采样随机种子、事件流引用、断点、自动处理事件和中断原因。

必测场景：

## 9. MVP 范围

MVP 应实现：

1. `EventTriggerProfile`、`EventContext`、`EventCandidateScore` 和候选池基础节流。
2. `world_day / world_hour / hour_tick` 时间口径和事件实例稳定随机种子。
3. C1 追赶期间压制新随机个人候选。
4. 普通个人事件的局部时停、默认处理和 C1 返回。
5. 正式交锋与突破挑战进入 B1，并拆分现实提交窗口、非参战世界推进和自身结算耗时。
6. 事件选项的 1-3 个主选项加“...”溢出结构。
7. `outcome_level`、`EventOutcome`、`ResultPackage` 和可见 / 隐藏 / Debug 日志分层。
8. 事件奖励接入预算、既有资产或事件锁定奖励来源。
9. 秘境窗口、节点危机、突破资源 / 名额窗口三类窗口事件。
10. 事件调试器展示候选、条件、排序、压制原因、稳定随机种子和结果包摘要。
11. F1 事件流基础配置、`silent / summary / auto / soft_interrupt / hard_interrupt` 五级和批量摘要输出。

MVP 不实现：

1. 完整事件文本库。
2. 最终事件概率表和所有候选基础权重。
3. 全部窗口事件类型和长期频率表。
4. 完整 `outcome_level` 到资源、伤势、关系、节点和传闻强度的量化表。
5. 隐藏后患追查、衰减、暴露和传闻生成的完整细表。
6. active major 世界事件的完整阶段推进策略。
7. 候选池回放文件导出。
