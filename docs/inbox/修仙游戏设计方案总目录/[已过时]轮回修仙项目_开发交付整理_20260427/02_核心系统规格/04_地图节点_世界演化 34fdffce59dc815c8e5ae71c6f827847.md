# 04_地图节点_世界演化

# 地图节点与沙盒世界演化

## 0. 文档定位

本文整理地图节点、资源槽、建筑槽、控制权、区域、秘境入口、世界初始生成和季度演化规则。

实现重点：地图不是静态菜单，而是用于承载宗门行动、资源流转、事件压力、秘境窗口、隐藏层和多人间接竞争的状态机。

## 1. 核心定位

> 沙盒世界演化不是完整生态模拟，而是一个由地图节点模板、资源池、灵气环境、宗门行动、事件压力、秘境窗口和后手隐藏层共同驱动的季度状态机。
> 

玩家应感受到：

1. 地图节点会因宗门、资源、事件、灵气和玩家行动改变。
2. 宗门通过节点控制、资源争夺和事件响应改变世界格局。
3. 资源来自节点产能、秘境窗口、事件预算、后手封存或库存转移。
4. 灵气、危险、秘境、妖兽、突破、资源、宗门争夺之间存在可解释关联。
5. 正式后手嵌入世界演化，但不会无日志、无原因地失效。

## 2. 地图基础结构

地图采用有向带权节点图。

```
MapGraph {
  nodes: Dictionary,
  directed_edges: Array,
  route_states: Dictionary,
  hidden_routes: Array,
  global_region_tags: Array
}
```

边可以支持：

- 双向但成本不同。
- 单向门。
- 权限门。
- 状态门。
- 风险门。
- 隐藏路线。
- 临时通道。

S3 读取可达性、通行成本和路线状态；S8 不直接决定玩家行动计划。

## 4. 节点结构

推荐扩展结构：

```
WorldNode {
  node_id: String,
  display_name_key: String,
  node_type: String,
  region_id: String,
  zone_tier: String,
  recommended_stage_range: Array,

  visible_state: Dictionary,
  danger_profile: Dictionary,
  aura_profile: Dictionary,

  control_owner_faction_id: String,
  node_influence_by_faction: Dictionary,
  garrison_state: Dictionary,

  resource_slots: Array,
  building_slots: Array,
  event_slots: Array,
  entrance_slots: Array,
  hidden_layers: Array,
  legacy_layers: Array,

  route_connections: Array,
  node_state_tags: Array,
  cooldown_tags: Array,
  world_log_refs: Array
}
```

### 4.1 关键字段说明

| 字段 | 含义 |
| --- | --- |
| `zone_tier` | 节点所在区域内容阶层，使用 A / B / C 等抽象编码 |
| `recommended_stage_range` | 推荐接触阶段，只用于内容筛选和提示，不作为硬锁 |
| `danger_profile` | 危险结构，例如妖兽、匪修、宗门冲突、灾害、秘境波动 |
| `aura_profile` | 背景灵气与灵气质量 |
| `entrance_slots` | 临时秘境入口、洞府入口、异常空间入口 |
| `node_state_tags` | 当前态势，如 contested、resource_stressed、aura_surge |
| `cooldown_tags` | 防止同类事件短期重复爆发 |

## 5. MVP 节点类型

MVP 建议支持：

1. 宗门山门节点。
2. 城镇 / 坊市节点。
3. 村庄 / 凡人聚落节点。
4. 资源型地理节点。
5. 荒野探索节点。
6. 秘境入口节点。
7. 前世后手节点 / 隐藏层。
8. 禁地 / 高危节点。
9. 道路 / 山道 / 渡口 / 交通设施节点。

第一阶段中的青禾村、镇集、镇集武馆、云麓山道、云麓宗山门均可映射为这些类型。

## 6. 区域层结构

区域不是行政区，而是地图生成与事件演化的中层容器。

```
RegionState {
  region_id: String,
  display_name_key: String,
  region_type: String,
  zone_tier: String,
  base_aura_band: String,
  base_danger_band: String,
  climate_or_terrain_tags: Array,
  dominant_factions: Array,
  region_pressure_tags: Array,
  major_event_slots: Array,
  resource_budget_refs: Array
}
```

MVP 区域至少包含：

1. 新手 / 凡俗边缘区。
2. 宗门腹地区。
3. 边界 / 荒野 / 禁地区。

## 7. 资源槽

资源槽代表节点自然或半自然产出。

```
ResourceSlot {
  slot_id: String,
  resource_type: String,
  abundance_state: String,
  extraction_difficulty: String,
  regeneration_rule: Dictionary,
  controlling_faction_bonus: Dictionary,
  depletion_risk: Dictionary,
  discovery_state: String
}
```

规则：

- 自然资源点原则上先产出资源池 / 资源量，不直接产出具体物品。
- 通过采集、开采、加工、炼制、修复等行动转化为宗门资源或材料物品。
- 枯竭、再生、污染、异变按节点模板配置，不做统一生态公式。
- 已控制资源节点的基础产出走常态结算，不占宗门主行动。

## 8. 建筑槽

建筑槽代表人工建设、宗门设施或特殊功能。

```
BuildingSlot {
  building_id: String,
  building_type: String,
  owner_faction: String,
  construction_state: String,
  level_or_quality: String,
  function_tags: Array,
  damage_state: String,
  access_permissions: Array
}
```

建筑可被：

- 建设。
- 修复。
- 占领。
- 损坏。
- 废弃。
- 用作聚灵阵、防御阵、炼丹炉、炼器炉等设施。

MVP 启用建筑 / 设施维护成本：设施每季度如果工作，需要消耗维护成本。MVP 不引入折旧曲线和自然磨损压力。

## 9. 控制权与影响力

节点归属采用：

```
控制权 + 影响力
```

控制权决定：

- 主资源收益权。
- 建设权。
- 驻守权。
- 通行管理权。
- 节点事件优先响应权。

影响力决定：

- 行动成本。
- 情报发现率。
- 任务成功率。
- 探索与交易便利。
- 控制权争夺基础。
- 对控制者收益的轻微竞争。

控制权变更采用阈值 + 事件模型。玩家不需要逐个节点点击接管。

推动因素：

- 探索。
- 驻守。
- 建设。
- 开采。
- 处理节点事件。
- 削弱对手影响力。
- 宗门远征。

达到条件后，S10 触发控制权变更事件。

## 10. 隐藏层与后手层

### 10.1 隐藏层

隐藏层用于承载：

- 隐藏资源。
- 旧洞府。
- 线索。
- 秘境入口。
- 伏笔事件。
- 前世痕迹。

### 10.2 后手层

正式后手挂入节点后手层。

规则：

- 后手必须有位置。
- 后手必须写入世界日志和轮回账本。
- 后手风险只在相关节点发生明确变化时检定。
- 不做每季度随机磨损。
- 不引入年久失修型低频随机风险。

## 11. 秘境入口与临时节点

普通临时秘境入口通过 `EntranceSlot` 表达；少数著名秘境可作为常驻高危节点。

规则口径：

- 普通秘境：常驻节点上的入口槽，开启后生成临时节点或子图。
- 著名秘境：可作为长期显示的世界地标。
- 内部空间、进入窗口、探索阶段和关闭状态仍由 EntranceSlot、TemporaryNode 和事件链管理。

```
TemporaryNode {
  temp_node_id: String,
  parent_node_id: String,
  created_quarter: int,
  expiry_rule: Dictionary,
  access_rules: Dictionary,
  event_chain_refs: Array,
  cleanup_rules: Dictionary
}
```

## 12. 世界初始生成

MVP 不建议完全自由程序生成。推荐：

```
固定核心骨架 + 随机槽位填充 + 稳定种子扰动
```

固定内容：

- 主要宗门数量与核心位置。
- 新手村 / 镇集 / 初始宗门入门路线。
- 主交通路线。
- 基础资源节点数量下限。
- 第一批秘境 / 后手 / 控制权争夺节点。

随机内容：

- 资源槽类型、丰度、隐藏状态。
- 荒野节点危险类型。
- 秘境窗口出现节点。
- 传闻起始线索。
- 部分隐藏路线。
- 少量前世后手适配点。

## 13. MVP 地图规模

已定口径：

```
常驻节点：35±10 个
临时节点同时存在：0–6 个
主要宗门：3 个
```

原因：

- 足以承载 3 个主要宗门。
- 支持基础资源链、边界争夺、秘境窗口和后手锚点。
- 避免首张地图在事件、UI、调试和内容生产上失控。

## 14. 宗门空间结构

每个主要宗门使用四层空间结构：

```
宗门核心
→ 宗门腹地
→ 边界争夺带
→ 外围荒野 / 禁地
```

### 14.1 宗门核心

包含山门、主殿、内门区域、主要修炼设施。

MVP 常态不允许山门核心节点被 AI 宗门普通行动夺取，只允许重大事件链造成临时影响。

### 14.2 宗门腹地

包含坊市、药田、矿场、灵脉支脉、低危试炼地。

用于验证稳定产出和常态结算。

### 14.3 边界争夺带

包含争议矿脉、秘境入口、灵脉交汇点、荒废洞府、边境坊市。

多人间接竞争优先发生在这里。

### 14.4 外围荒野 / 禁地

包含妖兽巢穴、旧战场、秘境群、断裂灵脉、高危山脉。

适合远征事件链、临时节点、后手隐藏层和重大事件。

## 15. 三个宗门原型

MVP 固定 3 个主要宗门原型：

1. 稳健型宗门：腹地资源稳定，扩张欲较低，培养 / 防守倾向高。
2. 扩张型宗门：边界行动频繁，远征 / 争夺倾向高，资源波动大。
3. 秘境 / 技艺型宗门：探索、阵法、炼丹、秘境窗口倾向高，控制节点少但高价值事件多。

小家族、小帮派、散修势力、坊市联盟可先作为节点影响力或事件标签，不必都成为完整宗门行动主体。

## 16. 灵气显示

玩家常规只看到标签与趋势：

```
灵气稀薄
灵气尚可
灵气浓郁
灵气紊乱
```

高阶身份、阵法能力或探查道具可以揭示：

- 纯净。
- 混杂。
- 污染。
- 紊乱。
- 趋势变化。

精确数值仅用于服务端规则、调试模式和开发工具。

## 17. 世界季度演化

每季度由 S1 调用世界刷新和 S10 事件系统。演化来源：

- 节点状态变化。
- 宗门行动。
- 资源槽压力。
- 建筑工作和维护。
- 秘境窗口。
- 事件压力累积。
- 传闻传播。
- 正式后手风险触发。
- N4 / 关键 NPC 宏观行动。

高价值变化必须写入世界日志。

## 18. MVP 验收清单

- 地图以有向带权节点图存在。
- 玩家可查看已知节点、半知节点、不可查看详情节点。
- S3 可读取路线成本和风险。
- 节点可挂载资源槽、建筑槽、事件槽、隐藏层、后手层。
- 至少存在 3 个主要宗门。
- 首张地图常驻节点约 35±10。
- 已控制资源节点可常态产出。
- 至少一个边界节点可发生控制权 / 影响力变化。
- 至少一个秘境入口通过 EntranceSlot 开启。
- 正式后手可挂入节点并通过状态变化触发风险检查。
