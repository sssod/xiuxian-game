# 系统设计｜战斗指令

## 1. 设计定位

战斗指令负责正式战斗、斗法、逃亡、护送、防守和突破前后独立外扰等高风险事件链中的轮内主动行为。它回答“本轮能选择什么、如何排布、如何被克制、如何消耗资源并回写后果”，不负责普通行动队列、完整伤害公式、战斗页面具体布局或父事件链的最终解释。

战斗指令不进入普通行动队列，也不替代行动指令系统中的“当前执行指令 + 最多 3 条预输入指令”。正式交锋进入 B1 后，由 `FormalEncounterState` 管理轮内选择；普通行动队列只影响交锋结束后的后续行动。

本文采用已裁决的 B1 三层时间口径：

```text
B1 提交窗口 = 每轮给玩家思考和提交的现实时间，默认 60 秒；
B1 世界推进 = 每 60 秒现实时间对应其他玩家和世界行动推进 1 游戏小时；
交锋结算耗时 = 参战交锋自身在游戏内消耗的时间，由战斗 / 突破规则决定。
```

因此，战斗指令不再默认绑定“交锋自身每轮消耗 1 游戏小时”。普通斗法是短耗时、高强度事件；长耗时应属于追击、围困、秘境拉锯、战后搜索、疗伤、突破准备或突破巩固，而不是普通交锋本身。

## 2. 当前结论

1. 战斗指令只在正式交锋、突破挑战和高风险事件链内生效，不写入普通行动队列。
2. 正式战斗采用 5 格战术预输入；一个 B1 提交窗口内填入 5 个交锋格，锁定后连续结算并逐格检查结束条件。
3. 突破挑战复用 B1 提交窗口和结果包，但每个突破阶段只需要 1 个交锋格，阶段耗时由突破模板声明。
4. 战斗基础克制为“攻击克制 Buff、防御克制攻击、Buff 克制防御”，恢复、控制、逃遁和特殊指令按模板归入对应规则。
5. 指令来源包括基础指令、已学术法 / 神通 / 法门、法宝主动效果、法宝被动效果、消耗道具和事件特殊指令。
6. 生机、元气、神念是角色持久状态；战斗读取当前值，战后回写变化，不自动回满。
7. MVP 丹药没有即时生效类型，不允许在战斗交锋或突破交锋中作为即时指令使用。

## 4. 核心循环或触发入口

正式交锋由战斗、突破、移动遭遇、秘境、宗门任务、资源争夺或父事件链触发。进入 B1 后，战斗指令的基础循环是：

```text
父事件链触发正式交锋
→ 生成 FormalEncounterState 和本场 battle_rule / scene_time_profile
→ 读取角色状态、随身资产、功法、法宝、道具和事件特殊规则
→ 生成本场可用战斗指令列表
→ 玩家 / AI 在 B1 提交窗口内填入交锋格
→ 倒计时结束或全员提前提交后锁定
→ 逐格结算、检查结束条件、记录日志
→ 若未结束，进入下一 B1 提交窗口或模板结局
→ 输出结果包并交还父事件链解释后果
```

正式战斗的 5 格循环：

```text
展示当前态势、结束条件和敌方信息层级
玩家 / AI 填入 5 个交锋格
允许倒计时结束前修改
锁定本战斗回合指令序列
第 1 格结算并检查结束条件
第 2 格结算并检查结束条件
...
第 5 格结算并检查结束条件
若未结束，进入下一 B1 提交窗口或模板结局
```

每个交锋格都必须有指令。玩家未选择时，系统按战斗规则填入默认基础指令。

| 场景 | 默认指令 |
| --- | --- |
| 普通战斗 | 守势 |
| 逃亡战 | 闪避 / 脱离 |
| 教学战 | 观察 |
| 突破前后独立外扰 | 护送 / 防守 |
| 资源不足 | 低效守势 / 喘息 / 空过 |

## 5. 规则与状态

### 5.1 与普通指令队列的边界

普通行动队列只保存已经合法的长期或短期行动，例如闭关、赶路、炼丹、申请资源、开启已满足条件的大境界突破。正式交锋开始后，轮内选择由 `FormalEncounterState` 管理。

不能写入普通行动队列的内容：

```text
正式交锋中的轮内策略选择
突破挑战中的轮内策略选择
战斗 5 格战术指令序列
敌方行为预案
个人即时处理事件选项
需要新情报判断的追击、撤退、护法或消耗道具选择
```

B1 或 P0 期间，玩家可以编辑普通队列，但普通队列只影响交锋结束后的后续行动，不影响本轮战斗结算。

### 5.2 战斗指令来源

战斗开始时，系统根据角色当前状态、随身资产、已掌握能力和事件规则生成本场可用指令列表。

| 来源 | 说明 | 示例 |
| --- | --- | --- |
| 基础指令 | 所有角色可用，强度低但稳定 | 普通攻击、防御、闪避、观察、调息、逃遁 |
| 已学术法 / 神通 / 法门 | 来自主修功法、法门和已掌握术法 | 剑诀、护体法、轻身术、神魂术 |
| 法宝主动效果 | 随身携带且当前可驱动的法宝提供主动指令 | 飞剑斩击、宝镜照魂、护体钟罩 |
| 法宝被动效果 | 不占交锋格，满足条件时触发修正或承受后果 | 护心玉抵消神念伤害、避毒珠降低毒雾影响 |
| 消耗道具 | 符箓、阵盘、一次性护符等；MVP 丹药不允许在交锋中即时使用 | 攻击符、护身符、阵盘压制 |
| 事件特殊指令 | 当前事件临时授予，只在本场有效 | 护送撤离、封锁洞口、抢夺信物、斩断追踪 |

资源不足的指令可以显示，但必须标明不可用原因。这样玩家能理解自己为什么无法使用某个术法、法宝或道具。

### 5.3 三条状态条

| 显示名 | 数据含义 | 主要承载 |
| --- | --- | --- |
| 生机 | `vitality` | 生命、肉身完整度、伤势、濒死 |
| 元气 | `energy` | 法力、气力、术法消耗、法宝驱动、疲惫 |
| 神念 | `mind` | 神魂、心神、神识稳定、幻术和心魔对抗 |

战斗读取当前值，战后不自动回满。消耗、伤害和状态封锁都必须回写角色、物品、事件结果包和回放。

### 5.4 指令类型

MVP 先把大多数行为映射到攻击、防御、Buff 三角关系，再用恢复、控制、逃遁和特殊类型补充事件目标。

| 类型 | 默认定位 | 常见目标 | 说明 |
| --- | --- | --- | --- |
| 攻击 | 克制 Buff | 生机 / 元气 / 神念 | 造成伤害、打断、压制或破气 |
| 防御 | 克制攻击 | 自身 / 队友 / 目标 | 抵消、偏转、护持、屏障、格挡 |
| Buff | 克制防御 | 自身 / 队友 / 场地 | 蓄势、调息、强化、观察、恢复或改变后续格 |
| 恢复 | 默认归入 Buff | 生机 / 元气 / 神念 | 被攻击克制，适合在对方防御或空档时使用 |
| 控制 | 视模板归入攻击或特殊 | 元气 / 神念 / 行动能力 | 封脉、定身、幻术、打断、缴械 |
| 逃遁 | 视模板归入防御或特殊 | 脱离进度 | 逃亡、追击、撤退战使用 |
| 特殊 | 由事件定义 | 事件目标 | 护法、稳定突破、抢夺物品、破阵、封锁 |

### 5.5 核心克制

基础三角关系：

```text
攻击克制 Buff
防御克制攻击
Buff 克制防御
```

攻击 vs 攻击：

```text
双方攻击有效威力相减
威力较高方造成差值伤害
威力较低方攻击被压制
```

防御 vs 攻击：

```text
防御消耗通常低于攻击
同等层级下防御有效值通常高于攻击
攻击超过防御时只造成溢出伤害
```

攻击 vs Buff：

```text
Buff 通常不提供即时防护
Buff 方承受接近完整攻击风险
普通 Buff 不默认必定失败
伤害、冲击或控制超过阈值时，Buff 被打断或效果降低
```

Buff vs 防御：

```text
防御未遭遇攻击时主要价值下降
Buff 方获得蓄势、恢复、观察、强化或后续优势
```

防御 vs 防御通常产生低收益僵持；Buff vs Buff 则制造后续高风险爆发窗口。

### 5.6 5 格战术预输入

战斗内部采用 5 格战术指令结构。一个 B1 提交窗口内，玩家为本轮战斗回合填入 5 个交锋格；倒计时结束或所有参战者提前提交后，系统连续结算这些交锋格。

战斗交锋计时：

```text
1 个战斗回合 = 5 个交锋格 = 10 分钟游戏内叙事耗时；
常规战斗 = 3 个战斗回合 = 30 分钟游戏内叙事耗时；
每个战斗回合的现实决策窗口 = 60 秒；
常规战斗最多 3 分钟现实决策时间；
B1 世界推进仍按 60 秒现实时间 = 1 游戏小时计算；
所以常规战斗期间，非参战玩家最多完成 3 游戏小时行动推进；
战斗交锋结算后，不足 1 游戏小时按 1 游戏小时计入参战交锋消耗。
```

战斗回合的 10 分钟耗时主要用于叙事、日志和表现，不作为逐格计算依据。符箓、法宝等持续效果在战斗结束后按本场已结算的游戏时间扣减剩余持续时间；常规 30 分钟战斗按不足 1 小时取 1 小时处理。

术语：

| 术语 | 含义 |
| --- | --- |
| 战斗 | 一次完整斗法事件链 |
| 战斗回合 | 一次 5 格指令预输入与连续结算 |
| 交锋格 | 战斗回合内的 1 个指令格 |
| 交锋 | 双方同一交锋格的指令对抗 |

### 5.7 填入预览与失败兜底

玩家填入 5 格时，UI 可以显示己方生机、元气、神念的预计变化。该预计只计算己方主动消耗、己方恢复、己方 Buff 和己方自损，不计算敌方未来指令、克制、打断、资源削减、状态封锁或提前结束。

如果某个交锋格结算时资源不足或状态不允许，原指令失败并替换为低效兜底：

```text
资源不足或状态被封锁
→ 指令失手
→ 执行低效守势 / 喘息 / 空过
→ 记录失败原因
```

失败原因可能来自己方前序格消耗过高，也可能来自敌方前序格造成的元气削减、神念震荡、打断、封脉或额外消耗。

### 5.8 信息层级

5 格预输入成立的前提是玩家有足够信息做判断。敌方未来指令不必默认完全公开，但必须给出可用情报。

| 层级 | 说明 | 使用场景 |
| --- | --- | --- |
| 完全未知 | 只知道敌方存在和大致威胁 | 高风险、陌生敌人、伏击 |
| 倾向提示 | 显示偏攻、偏守、偏蓄势、偏逃等 | 普通战斗默认 |
| 局部预兆 | 显示某些强力指令前摇或后续爆发风险 | 精英敌人、可观察法术 |
| 完全预告 | 显示敌方部分或全部格子 | 教学战、低难度事件、侦查优势 |

玩家至少应看到：

```text
己方三条状态
可用指令、消耗、类型、目标条
己方指令序列的主动消耗预览
指令克制关系
本场结束条件
敌方已知战斗风格
敌方大致状态
上一战斗回合交锋记录
当前环境或事件特殊规则
```

### 5.9 AI 指令

AI 与玩家使用同一套 5 格战术预输入规则。AI 不应在知道玩家已锁定指令后作弊式逐格改指令。

AI 生成指令序列时可读取：

```text
NPC 模板
战斗目标
当前资源状态
上一战斗回合玩家行为
性格 / 战斗风格
事件脚本倾向
难度配置
敌方指令预兆配置
```

示例 AI 风格：

| 风格 | 行为倾向 |
| --- | --- |
| 鲁莽 | 高频攻击，低防御，元气消耗快 |
| 稳健 | 攻防均衡，低血量转防御 |
| 狡诈 | 先 Buff / 控制，再爆发 |
| 怯懦 | 受伤后逃遁，偏防御 |
| 护法型 | 优先防御、保护目标、维持阵线 |
| 法修型 | 消耗元气释放高威力术法 |
| 神魂型 | 优先攻击神念，制造心神状态 |

MVP 难度不靠复杂搜索，而靠指令池强度、资源量、克制倾向准确率、识别玩家重复模式的能力和敌方预兆透明度控制。

### 5.10 法宝与道具边界

战斗系统不采用“装备栏 / 换装备 / 换法宝”作为核心限制。随身携带且满足条件的法宝、符箓、阵盘、护符和已掌握术法，都可以参与生成可用指令或被动效果。

MVP 丹药规则：

```text
MVP 丹药没有即时生效类型；
丹药必须依赖炼化与时间流逝生效；
丹药不允许在战斗交锋或突破交锋中作为即时指令使用；
正式版若引入即时生效丹药，可再将其加入交锋可用指令。
```

主动型法宝的限制来自：

```text
5 格指令数量
元气 / 神念 / 生机消耗
法宝耐久、充能或使用次数
道具消耗
指令克制和时机风险
战斗规则对来源的限制
```

被动型法宝不是免费常驻护盾。只要它在战斗中承担防护、抵消、转移、镇压、预警、抗性或替角色承受后果，就可以进入状态变化判定。

符箓、法宝、阵盘或护符若带有持续增益 / 减益效果，可以在指令用出后立即生效。战斗或突破结束时，持续效果按已消耗游戏时间扣减剩余持续时间。

可回写状态包括：

```text
受损
破碎
失去充能
灵性衰减
暂时失灵
战后修复
拆解回收材料
进入后手、遗产或宗门资源循环
```

### 5.11 B1 时间模板

为了修正“普通斗法动辄数小时”的问题，B1 的现实提交窗口、B1 世界推进和交锋结算耗时分离。战斗模板必须声明 `scene_time_profile`。

建议模板：

| 模板 | 单次提交窗口 | 交锋输入结构 | 交锋结算耗时 | 适用场景 |
| --- | ---: | --- | ---: | --- |
| `combat_standard` | 60 秒 | 5 个交锋格 | 10 分钟 / 战斗回合；常规 3 回合共 30 分钟，不足 1 小时按 1 小时结算 | 普通斗法、切磋、路途正式战 |
| `combat_extended` | 60 秒 | 5 个交锋格 | 10 分钟 / 战斗回合；额外追击、阵法、转场另由事件模板处理 | 强敌斗法、秘境关键战斗、资源争夺 |
| `breakthrough_stage` | 60 秒 | 1 个交锋格 | 由突破模板声明，总耗时暂定 1～6 小时 | 突破挑战阶段 |
| `long_confrontation` | 60 秒或事件链处理 | 不按普通战斗处理 | 多小时到多日 | 围困、守阵、长期对峙、宗门节点拉锯 |

普通战斗默认使用 `combat_standard`。只有模板明确包含追击、阵法、场地拉锯、多人协同、秘境转场或突破阶段时，才允许显著跨小时。实现层面不额外设置战斗 / 突破时间预算限制，只沿用 gap 最大不超过 1 游戏日；实际设计层面一般战斗交锋不超过 1 游戏小时，突破交锋不超过 6 游戏小时。

突破交锋特殊规则：

```text
突破模板声明每个突破阶段与挑战耗时；
一般同境界各突破阶段耗时相同；
不同模板的主要差异在突破指令应对，而不是默认拉长耗时；
每个突破阶段只需要 1 个交锋格选择与输入；
每次阶段决策窗口为 60 秒现实时间；
突破阶段累计耗时通常 2～3 阶段就超过 1 游戏小时；
因此突破阶段耗时不仅用于叙事，也参与效果、资源和时间结算。
```

例如，提前服用并已经形成体内药性的丹药或持续资源效果，可能因为突破阶段累计超过 1 游戏小时而生效、暂停或扣减 1 次。注意这不表示丹药可以在突破交锋中即时使用；MVP 修为丹药仍只能通过提前直接服用形成药性，再由兼容修为增长流、模板声明或时间流逝生效。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 | 写入或影响 |
| --- | --- | --- |
| 行动指令与房间流程 | B1、P0、普通队列、默认策略、gap 上限和非参战世界推进 | B1 结果时间字段、普通队列承接提示、交锋结束后的行动恢复 |
| 战斗玩法 | 战斗分级、`battle_rule`、结束条件、父事件链、战斗结果包和后果边界 | 指令对抗结果、回合使用数、交锋格日志、资源变化和胜负原因 |
| 突破玩法 | 突破阶段、阶段耗时、突破目标、雷劫边界和失败标签 | 战斗指令不进入突破阶段；只承接突破前后独立外扰战斗的结果 |
| 角色状态 | 生机、元气、神念、伤势、心魔、状态封锁、功法掌握和当前资源 | 消耗、伤害、状态封锁、打断、经验、战后恢复需求和日志 |
| 功法与术法 | 主修功法、法门、术法、神通、技能标签和掌握度 | 可用指令、指令强度修正、术法使用经验和异常失败记录 |

| 地图与环境 | 战斗地点、环境规则、节点风险、阵法、路线和特殊地形 | 场地特殊指令、追击 / 撤退边界、节点来源事件后果 |
| NPC 与 AI | NPC 模板、性格、战斗目标、战斗风格、敌方预兆配置和难度 | AI 指令序列、敌方行为摘要、可见情报和回放记录 |
| 日志与回放 | 指令来源、克制关系、结算字段、可见性规则 | 逐格交锋摘要、失败原因、公开 / 私密日志和结果包引用 |

本文只维护接口职责边界，不重复伤害公式、倍率表、完整 UI 布局或父事件链后果配置。

## 7. 数据字段建议

### 7.1 战斗指令

| 字段 | 含义 |
| --- | --- |
| `command_id` | 战斗指令唯一标识 |
| `display_name` | 显示名 |
| `source_type` | 来源：`learned_skill`、`method_unlock`、`artifact_active`、`artifact_passive`、`consumable`、`basic`、`event_special` |
| `command_type` | 类型：`attack`、`defense`、`buff`、`recovery`、`control`、`escape`、`special` |
| `tags` | 指令标签，用于克制、环境、AI 和事件判断 |
| `target_bar` | 主要目标条：`vitality`、`energy`、`mind`、`mixed` 或 `none` |
| `resource_cost` | 生机、元气、神念、物品、法宝耐久或充能等成本 |
| `base_power_profile` | 基础威力、强度、恢复、蓄势或事件进度配置引用 |
| `counter_profile` | 克制、抵消、打断或被克制配置引用 |
| `duration_slots` | 持续影响的交锋格数量 |
| `max_uses_per_encounter` | 本场最大使用次数，可为空 |
| `slot_restriction` | 交锋格位置限制，可为空 |
| `event_flags` | 本场事件特殊标记 |
| `ai_usage_hint` | AI 选择该指令的倾向提示 |

### 7.2 交锋格与指令序列

| 字段 | 含义 |
| --- | --- |
| `encounter_id` | 正式交锋实例 |
| `round_index` | 战斗回合或突破阶段序号 |
| `slot_index` | 战斗回合内交锋格序号；突破阶段可固定为 1 |
| `actor_ref` | 选择指令的角色、NPC 或抽象敌方小队 |
| `selected_command_id` | 玩家或 AI 原始选择的指令 |
| `resolved_command_id` | 实际执行的指令；资源不足时可替换为兜底指令 |
| `default_strategy_used` | 是否使用默认策略 |
| `failure_reason_tags` | 指令失败、资源不足、状态封锁或打断原因 |
| `known_enemy_intent_level` | 敌方情报层级 |
| `preview_delta` | 锁定前可展示的己方主动消耗或恢复预览 |
| `resolution_summary_ref` | 逐格结算摘要引用 |

### 7.3 B1 时间记账

| 字段 | 含义 |
| --- | --- |
| `submit_window_seconds` | 现实决策窗口，默认 60 秒 |
| `scene_time_profile` | `combat_standard`、`combat_extended`、`breakthrough_stage` 或 `long_confrontation` |
| `encounter_kind` | `combat` 或 `breakthrough` |
| `combat_rounds_used` | 已结算战斗回合数 |
| `breakthrough_stages_resolved` | 已结算突破阶段数 |
| `slots_resolved` | 已结算交锋格数量 |
| `b1_world_elapsed_hours` | B1 期间世界推进小时 |
| `nonparticipant_progress_hours` | 非参战玩家在 B1 期间完成的行动推进量 |
| `encounter_scene_elapsed_minutes` | 交锋自身叙事耗时 |
| `encounter_accounting_hours` | 参战交锋最终按游戏规则计入的消耗时间 |
| `participant_gap_hours` | B1 世界推进与参战交锋计入耗时之间的差值 |
| `result_package_refs` | 战斗、突破或父事件链结果包引用 |

常规战斗示例：

```text
3 个战斗回合；
现实决策时间最多 3 分钟；
B1 世界推进 3 游戏小时；
非参战玩家完成 3 游戏小时行动推进；
交锋自身叙事耗时 30 分钟；
参战交锋结算耗时按不足 1 小时取 1 小时；
participant_gap_hours = 2 小时。
```

非参战玩家在 B1 期间按同一世界慢速推进；随机个人即时处理事件和普通机缘应等 B1 结束并到达合法检查点后再检查。

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通玩家 UI 应展示可决策信息：

1. 己方生机、元气、神念。
2. 可用指令、来源、消耗、类型、目标条和不可用原因。
3. 5 格战术指令序列与可修改状态。
4. 己方指令序列的主动消耗或恢复预览。
5. 指令克制关系和当前事件特殊规则。
6. 本场目标、结束条件和失败后果摘要。
7. 敌方已知战斗风格、信息层级和上一回合交锋记录。
8. B1 本轮剩余提交时间，以及普通队列只承接战后行动的提示。

普通 UI 不应展示：

1. 敌方未公开的完整未来指令。
2. 完整伤害公式、原始倍率、AI 权重和随机种子。
3. 隐秘交锋的真实触发来源、非公开参战者或其他玩家私人事件归因。
4. 内部指令 ID、完整 Debug 字段、后台状态枚举和逐 tick 细节。
5. 会让玩家误以为“预计变化等于最终结果”的确定性结论。

战斗专用页面或覆盖界面后续应由交互设计文档补齐。本文只沉淀稳定信息边界，不记录节点级布局、组件坐标或具体像素。

## 9. MVP 范围

MVP 应实现：

1. 正式战斗 5 格战术预输入。
2. 突破阶段单格选择。
3. B1 提交窗口、B1 世界推进和交锋结算耗时分离。
4. 生机、元气、神念读取与回写。
5. 攻击、防御、Buff 三角克制。
6. 基础指令、早期功法 / 术法指令、道具指令、法宝主动 / 被动指令。
7. 资源不足、状态封锁和未提交时的低效兜底。
8. 敌方倾向提示、局部预兆和教学场景完全预告。
9. 简单 AI 风格模板。
10. 逐格战斗日志、失败原因和结果包引用。
11. 符箓、法宝等持续效果按已消耗游戏时间扣减剩余持续时间。

第一版指令集：

```text
通用基础指令：普通攻击、防御、闪避、调息、观察、逃遁
早期功法 / 术法指令：轻身功法、基础战斗功法、护身法门、神念术法
道具指令：符箓攻击、护身符、阵盘压制
法宝指令：法宝攻击、法宝护体、照魂 / 破幻、被动抵挡一次关键伤害
```

MVP 不实现：

1. 战斗中换装备、换法宝或复杂装备栏系统。
2. 即时生效丹药。
3. 复杂多人同场协同搜索。
4. 高级 combo、连锁反制和多段打断。
5. 完整 AI 博弈搜索或作弊式逐格改指令。
6. 完整技能树、全部法宝品质数值和高阶术法池。

## 10. 验收约束

1. 战斗轮内指令不得写入普通行动队列，也不得由普通队列自动替代。
2. 一个正式战斗回合必须能在 60 秒 B1 提交窗口内提交并锁定 5 个交锋格。
3. 玩家未提交、资源不足或状态封锁时，系统必须使用明确的低效兜底并记录失败原因。
4. 预计变化只能展示己方主动消耗、恢复、Buff 或自损，不得伪装成最终结算结果。
5. AI 使用同一套指令序列规则，不得在玩家锁定后作弊式逐格改指令。
6. 生机、元气、神念必须读取角色当前值并回写战后变化，不能战后自动回满。
7. B1 结果必须同时记录现实提交窗口、B1 世界推进、非参战推进、交锋叙事耗时和参战记账耗时。
8. MVP 丹药不能在战斗交锋或突破交锋中即时使用。
9. 法宝、符箓、阵盘或护符在战斗中承担后果时，必须能回写消耗、充能、破损、持续时间或失灵状态。
10. 普通 UI 不得泄露未公开敌方指令、隐秘交锋来源、其他玩家私人事件归因或 Debug 字段。
