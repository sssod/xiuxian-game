# UI/UX 稳定需求

状态：第三批正式定稿
更新日期：2026-05-08
来源主版本：v2.3 calendar_preinput

## 1. 文档定位

本文定义 MVP 与开发交付阶段必须稳定遵守的 UI/UX 需求，覆盖主界面信息架构、速度展示、行动队列、局部时停、C1 追赶、B1 交锋、P0 全局暂停、显式托管、资源输入和日志入口。

主界面定位为：

```text
大世界地图驱动的共享日历行动工作台
```

本文不定义节点级精确布局、组件坐标、视觉稿切图或最终美术风格。节点级版面与组件摆放以后续当前 UI artifact / Figma 为准；稳定交互规则、信息结构、速度展示和隐私边界以本文为准。

UI 不承担权威结算职责。客户端提交 intent，服务端完成校验、结算、状态变更、日志、结果包和 `TimelineReplay` 记录；UI 只展示玩家可见状态、个人摘要、公开摘要和 Debug 明确允许的数据。

## 2. 主界面信息架构

玩家在主界面需要持续理解：

```text
当前世界时间
当前公开速度
当前行动
后续 1～3 条预输入
当前位置 / 节点风险
当前兜底规则
显式托管入口
个人局部事件 / 交锋 / P0 的待处理状态
日志、传闻、宗门、功法、物品入口
```

主界面稳定区域：

| 区域 | 稳定职责 |
| --- | --- |
| 顶部时间区 | 世界日历、公开速度、角色摘要、待处理状态入口 |
| 地图主体 | 当前节点、可见路线、节点风险、资源、宗门影响、机会窗口与传闻 |
| 行动队列面板 | 当前 `Command`、后续 1～3 条预输入、兜底规则、显式托管入口 |
| 状态 / 日志入口 | 队列变更、事件、速度切换、资源消耗、突破报告、轮回账本等摘要 |
| 专用处理界面 | 局部时停、C1 追赶、B1 交锋、P0 公共确认 |
| Debug 入口 | 开发模式专用，不作为普通玩家 UI 数据源 |

移动端或窄屏优先保留：

```text
顶部时间 / 速度
地图
当前行动
队列抽屉
日志提醒
```

## 3. 顶部时间与速度显示

顶部时间区显示：

```text
世界日历块
当前速度图标
当前速度名称
当前角色摘要
当前待处理状态入口
```

底层时间读取 `world_day / world_hour`。玩家界面可以用修仙包装显示年月、日、时辰、季节或节气，但不得把包装层重新变成固定推进单位或排程格语义。

公开速度显示：

| 速度 | UI 文案 | 归因展示 |
| --- | --- | --- |
| `F1` | 高速推进 | 不显示具体玩家原因 |
| `N1` | 常态推进 | 不显示私人事件或编辑归因 |
| `B1` | 交锋慢速 | 公开交锋可显示事件名；隐秘交锋仅显示交锋慢速 |
| `P0` | 全局暂停 | 可显示公共事件名或同步保护 |

`C1` 是内部追赶补结算，不是公开速度档位。C1 只在相关玩家的追赶摘要中显示，不进入顶部公共速度名称。

F1 降到 N1 时使用中性提示：

```text
进入常态推进
```

普通玩家 UI 只读取 `SpeedState.current_speed` 与 `SpeedState.public_reason_key`。`private_reason_refs`、阻塞项、其他玩家事件来源和 Debug 字段只能进入服务端日志或 Debug 面板。

## 4. 地图主体

地图是第一视野主体，应展示：

```text
当前节点
可见路线
已知通行状态
节点风险
资源槽摘要
宗门影响
秘境 / 机会窗口
公开传闻
队列目标路线
玩家可见事件标记
```

地图只展示玩家可见层级内的信息。不得显示其他玩家私人事件来源、隐秘交锋归因、隐藏后手的完整记录、Debug 世界日志或未公开结算原因。

隐秘交锋、局部时停和私人突破只通过中性速度、公开后果、传闻、地图变化或个人可见日志体现。点击地图上的风险、传闻、宗门影响、资源、目标或后手感应标记时，可以打开对应上下文面板，但不得绕过 `Command`、事件选项或 B1/P0 专用流程直接改写角色状态。

## 5. 行动队列面板

底部行动队列面板显示：

```text
当前指令
后续 1
后续 2
后续 3
当前兜底规则
显式托管入口
```

示例：

```text
当前：闭关修炼《青木引气诀》10 日
后续 1：调息 2 日
后续 2：开启筑基突破
后续 3：空
兜底：低风险自动吐纳；中高风险自动休整
```

队列面板原则：

```text
看起来像简单队列
不显示 if-else
不显示预计未来满足条件
不提供甘特图式长计划
不把普通队列用于 B1 轮内选择
不把自动兜底包装成长期高速计划
```

稳定入口：

| 功能 | UI 入口 |
| --- | --- |
| 编辑队列 | 队列面板主按钮 |
| 删除后续指令 | 队列项内删除 |
| 调整后续顺序 | 队列项拖拽或上移 / 下移 |
| 显式托管 | 队列面板右侧入口 |
| P0 公共确认 | P0 专用面板 |
| B1 本轮提交 | B1 专用面板 |

## 6. 队列编辑与入队校验

玩家打开普通指令输入界面时：

```text
F1 → 世界进入 N1
N1 → 保持 N1
B1 / P0 → 可编辑普通队列，但交锋轮选择 / 全局选择仍使用专用界面
角色当前行动继续结算
其他玩家界面只显示中性速度
```

入队校验只提示当前是否合法，不展示未来推演、条件链或替代脚本。

示例：

```text
可入队：当前已满足筑基突破条件。
不可入队：当前未拥有筑基丹。
不可入队：当前地点不允许突破。
不可入队：当前灵力储备不足。
```

执行前再次校验失败时，仅给玩家本人提示：

```text
预输入指令未执行：开启筑基突破。
原因：缺少筑基丹。
已自动转入：吐纳。
世界进入常态推进，等待你输入新指令。
```

队列为空时：

```text
队列已空。
当前处于低风险节点，已自动转入吐纳。
世界进入常态推进，等待你输入新指令。
```

队列不得因为前序行动未来可能产出资源而允许后序指令入队。资源消耗、位置、权限、目标状态和行动合法性均以入队时当前事实与执行前再次校验为准。

## 7. 个人局部时停界面

事件玩家本人显示：

```text
你的时间已停滞
当前脱节：X 游戏小时
最大脱节：1 游戏日
```

gap 提示：

| gap | UI |
| --- | --- |
| 0～12 小时 | 常规显示 |
| 12～18 小时 | 轻提示：世界正在继续推进 |
| 18～24 小时 | 强提示：即将执行默认处理或同步保护 |
| 24 小时 | 自动默认 / P0 同步保护 |

非事件玩家只显示：

```text
当前速度：常态推进
```

局部时停界面只处理该玩家的个人选择。重大公共事件、无安全默认且达到 gap 上限的同步保护、多人直接冲突或正式交锋进入 P0 或 B1 专用界面。

## 8. C1 追赶界面

事件结束后显示短摘要：

```text
正在追赶至当前世界时间……
补结算：6 游戏小时
```

追赶完成后显示：

```text
已同步至当前世界时间。
补结算内容：修炼进度、资源消耗、伤势恢复。
追赶期间未触发新随机事件。
```

C1 追赶只展示确定性补结算内容。UI 不得把 C1 表现为玩家可选速度，也不得暗示追赶期间触发新的随机个人事件、普通机缘或软机会事件。

## 9. B1 交锋、突破挑战与 P0

B1 交锋顶部显示：

```text
当前速度：交锋慢速
第 N 轮 / 预计上限
本轮剩余：60 秒
本轮游戏时间：1 小时
```

每轮允许：

```text
提前提交
倒计时结束前修改
未提交则执行默认策略
```

突破挑战使用同一个 B1 框架，但文案为：

```text
突破挑战
本轮道基态势
本轮可用突破资源
当前突破预设
```

B1 轮内选择不得写入普通 `CommandQueue`。突破开启可以是普通短指令；进入挑战后，轮内策略、资源消耗和结果由 `FormalEncounterState` 与结果包处理。

P0 全局暂停只用于公共决策、同步保护、主机暂停或必须全员停表的事件。P0 专用面板应显示公共原因、参与要求、默认处理策略和当前待确认状态，不得替代普通个人事件的局部时停。

## 10. 显式托管预览

托管入口建议位于队列面板右侧。点击后显示摘要，不立即提交：

```text
显式托管：7 日
当前位置风险：低
默认行动：托管吐纳
收益：低
会自动处理：普通邀约、普通传闻、低价值机会、轻微状态波动
不会自动处理：死亡风险、正式交锋、重大心魔、重大机缘、不可逆选择、大境界突破挑战、多人直接冲突、宗门重大事件
满足条件时可参与高速推进
```

显式托管是玩家主动输入的低关注策略；自动兜底是队列空或校验失败后的安全行为；超时安全默认是事件、B1 或 P0 的房间规则处理。三者来源、收益、F1 资格和日志记录必须分离展示。

## 11. 资源输入与残余效果

行动资源输入显示在具体行动编辑卡内。

显示内容：

```text
可投入资源
资源来源容器
兼容小时
可能残余效果
经脉压力
相性提示
入队校验状态
执行前再次校验提示
```

局部时停提示：

```text
局部时停期间，你的药性衰减暂停；外部世界继续推进。
C1 追赶时将补结算确定性药性衰减与兼容小时。
```

丹药、灵材、符箓和临时 boost 作为 `ActionResourceInputBinding` 绑定具体行动或事件选项。未消耗完的兼容小时或药性效果通过 `ActiveResourceEffect` 展示为残余效果，不作为默认独立行动。

修炼行动预览默认展示玩家可理解的估算项，不默认暴露完整 CP 和公式：

```text
当前境界与小阶段；
当前瓶颈状态；
预计还需游戏时间；
预计还需现实时间；
本次行动预计有效修炼年收益；
资源包贡献；
经脉压力 / 心魔 / 伤势风险；
是否具备 F1 条件。
```

高级详情或 Debug 面板可展示 `cultivation_points`、`normalized_segment_progress`、倍率明细、世界产出预算来源、阶段调度来源、资源包消耗记录、CP 转化结果和 CEI。

## 12. 日志与提醒入口

日志分类：

```text
队列变更
入队校验
执行前校验失败
自动兜底
显式托管
速度切换
局部时停
gap 默认处理
C1 追赶
B1 交锋轮
P0 全局事件
宗门传闻
节点变化
资源消耗
突破报告
轮回账本
```

私人日志仅自己可见；公开日志按可见性与传闻规则生成。普通玩家界面不显示其他玩家私人队列、私人事件来源、隐藏后手完整记录、Debug 世界日志或完整随机轨迹。

UI 摘要应来自服务端结果包、玩家可见日志、公开日志和 `TimelineReplay` 公开片段，而不是客户端自行推演权威结算。

## 13. Debug 与数据边界

普通玩家 UI 读取原则：

```text
读取可见状态和公开摘要
读取本人个人摘要
读取 SpeedState.current_speed / public_reason_key
从 ResultPackage 生成个人摘要和公开摘要
不自行推演权威结算
不把本地编辑态写入存档主状态
不显示其他玩家私人事件归因
```

Debug 面板可读取隐藏世界状态、完整阻塞项、`private_reason_refs`、调试日志、结果包 diff、`TimelineReplay` 当前片段和 QA 检查字段，但 Debug 不得成为普通玩家 UI 的数据来源。

临时 UI 状态、悬停、筛选、面板展开状态不进入 `SaveGame` 权威主状态。

## 15. Deprecated aliases 与迁移说明

| 旧 UI 口径 | 当前处理 | 说明 |
| --- | --- | --- |
| 回合行动工作台 / 季度行动工作台 | 废弃 | 主界面为共享日历行动工作台 |
| 顶部回合阶段条 / 季度阶段条 | 废弃 | 顶部显示世界日历与公开速度 |
| 回合时间预算条 / 季度时间条 | 废弃 | 普通行动使用 `CommandQueue`，不做回合预算条 |
| 6 个朔望行动格 / 行动格规划器 | 废弃 | 当前指令 + 最多 3 条预输入 |
| 行动格成本 | 废弃 | 移动和行动耗时按 `world_hour` / 小时成本表达 |
| 宗门主行动输入 / 宗门主行动反馈卡 | 移除 | 宗门 AI 维护 `SectContinuousActionState`，玩家只通过身份、申请、贡献、事件和亲自参与间接影响 |
| `PersonalActionInstruction` | 迁移为 `Command` | 玩家输入为短线性普通指令 |
| 回合结果报告 / 季度结果摘要 | 迁移 | 使用日志、结果包摘要、突破报告和 `TimelineReplay` 公开片段 |
| `P0/P1/P2` 作为风险提示等级 | 废弃该命名 | `P0` 是全局暂停速度；风险提示等级不得复用速度枚举 |
| Figma v0.9 六状态帧作为规则来源 | 不作为当前规则权威 | v2.3 明确本版只定义稳定 UI 需求，不绑定现有 Figma 主界面稿 |

裁决：

| 采用方案 | 废弃方案 | 原因与影响 |
| --- | --- | --- |
| 主界面是共享日历行动工作台 | 回合 / 季度行动工作台 | v2.3 已将连续世界日历定为玩家时间表面 |
| 顶部显示世界日历与 `F1/N1/B1/P0` 中性速度 | 回合阶段条、提交截止阶段条 | UI 需要服务 `SpeedState`，且不得泄露私人速度归因 |
| `CommandQueue` 当前 + 3 后续 | 6 个朔望行动格、回合时间预算条、甘特式长计划 | 玩家只提交短线性普通指令，不做逐小时或格子排程 |
| 普通队列编辑中 F1 降 N1，当前行动继续结算 | 进入规划阶段并冻结回合 | 连续日历下编辑不应冻结世界或角色当前行动 |
| 个人事件走局部时停 + C1 | 普通个人事件全局 P0 | 保留个人选择权，同时减少多人阻塞 |
| 正式交锋与突破挑战走 B1 专用界面 | 普通队列内处理交锋轮，或突破多次 P0 | B1 每轮等于 1 游戏小时，资源消耗和默认策略可复盘 |
| 显式托管、自动兜底、超时安全默认分离 | 托管 / 离线 / 兜底混用 | 三者来源、收益、F1 资格、事件处理权和日志不同 |
| 修炼 UI 默认展示时间、有效收益和风险估算 | 默认暴露完整 CP 公式和所有倍率 | 玩家需要判断行动价值，完整公式属于高级详情或 Debug |
| 普通玩家 UI 与 Debug 数据源分层 | Debug 世界日志玩家可见 | 多人隐私、可见性和调试审计必须分离 |
| v2.3 稳定交互规则优先，Figma 只作后续布局参考 | 旧 Figma 状态帧作为当前规则权威 | v2.3 明确不绑定现有 Figma 主界面稿 |
