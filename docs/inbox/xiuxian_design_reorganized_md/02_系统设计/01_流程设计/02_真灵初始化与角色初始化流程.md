# 流程设计｜真灵初始化与角色初始化流程

## 1. 当前结论

玩家主体采用三层模型：

```text
真灵：跨世延续主体
执念：转世初始化遗留包
身躯与灵魂：当前世角色实例
```

真灵负责“我仍然是我”；执念负责“我能把哪些内生遗留带到下一世”；身躯与灵魂负责“这一世具体能做什么、付出什么代价”。

## 2. 初次入世最小流程

```text
创建真灵
→ 生成第一世身躯与灵魂
→ 生成出生地点、年龄、家庭背景、初始社会身份
→ 生成天赋标签与资质
→ 写入角色自知信息与初始日志
→ 进入 S1 房间季度流程
```

约束：

- 资质在出生 / 身躯生成时已经生成，入门事件只负责检测、揭示和评级。
- 初次入世应保持低认知、低资源、低控制力。
- 出生背景可影响初始资源、身份、家族关系、宗门关系和区域声望，但不应直接替代后续修炼成长。

## 3. 转世初始化流程

```text
本世结束 / 主动计划转世
→ 结算本世身躯与灵魂
→ 提取真灵成长
→ 记录履历、失败原因、后手状态
→ 检查遗产与后手线索
→ 计算执念容量
→ 选择可携带天赋标签与出生背景
→ 选择无成本转世起点参数
→ 生成新身躯与灵魂
→ 写入新世初始日志
```

转世触发来源暂定支持三类：

1. 寿元耗尽转世。
2. 突破失败转世。
3. 主动计划转世。

## 4. 执念权重制

后期已确认：执念容量采用权重制。

```text
TrueSpirit.obsession_capacity = 本次转世可承载的执念容量上限
ObsessionOption.obsession_weight = 某遗留配置的占用权重
```

规则：

- 玩家选择的遗留总权重不得超过当前执念容量。
- 权重不是属性点，不允许拆成根骨 +1 / 悟性 +1 等细碎购买。
- 遗留仍是离散选项，例如天赋标签、出生背景、已解锁初始化遗留。
- MVP 优先支持两类执念遗留：天赋标签、出生背景。

## 5. 无成本转世选项

转世年龄、转世地域、附近宗门不消耗执念容量，而是本次转世的基础起点选项。地域与宗门需要来自玩家已知信息范围，但不要求角色亲身抵达过。

## 6. 设计历史

早期“真灵 / 执念 / 身躯灵魂”用于厘清玩家主体。后续 S2 将其转化为字段和接口。当前整理以 S2 与三层模型草稿共同为准。

## 7. 缺口

- 具体出生背景表、天赋标签表、权重表未定。
- 真名暴露、道韵标签、前世经验加成的具体数值未定。
- 新角色外观、人设模板未检索到细表。
