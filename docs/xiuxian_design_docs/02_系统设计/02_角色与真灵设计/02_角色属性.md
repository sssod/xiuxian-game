# 系统设计｜角色属性

## 1. 设计定位

角色属性是当前世“身躯与灵魂”层的系统主文档。它描述这一世角色的身体底子、修炼维度效率差异、派生状态和寿元情况，不默认跨世继承。

本文是包内所有文档引用角色属性系统层规则的来源。本文负责字段语义、来源 / 持续性口径、属性边界、玩家可决策内容、MVP 范围和验收约束；不维护公式、系数表、倍率、年龄影响折线、缓存字段或调参边界。角色属性数值层设计统一由《角色属性与派生状态数值设计》（`../../03_数值设计/09_角色属性与派生状态数值设计.md`）维护。
伤势、道伤、心魔、药性残余、BUFF / DEBUFF、HOT / DOT、符箓持续效果、法宝触发态和事件结果状态不作为角色属性范围维护，统一由《角色持续状态系统》（`07_角色持续状态系统.md`）承接。

角色属性需要服务：

1. 角色初始化与身躯生成。
2. 角色当前属性与派生状态描述。
3. 修炼、战斗、事件、资源、AI 与 UI 的字段读取。
4. 修炼效果、承载风险、战斗结果和状态反馈。
5. 后天永久修正、临时修正接口、寿元、死亡与转世入口。


## 2. 当前结论

角色属性系统只维护当前世“身躯与灵魂”层的系统语义，核心结论如下：

1. 角色属性以基础属性、修炼资质、派生状态、寿元状态和后天修正为主要分层。
2. 基础属性描述当前世身躯与行动底子，修炼资质描述当前世修炼效率差异。
3. 生机、元气、神念是当前世持久派生状态条，不按战斗、事件结束或页面刷新默认回满。
4. 寿元状态属于角色属性维度，只维护当前年龄、寿元上限、延寿 / 折寿来源及数值；寿元派生、年龄影响和调参规则由数值文档维护。
5. 属性变化必须保留来源、持续性和可解释记录；后天永久改变与临时修正分开，临时效果不得写入先天或永久属性。
6. 本文只定义系统层字段语义、范围边界和验收约束；公式、倍率、缓存字段、调参表和 UI 展示细节由对应数值与交互文档维护。

## 4. 核心循环或触发入口

角色属性围绕“生成、揭示、改变、结算、展示”循环维护。

1. 生成：角色出生、身躯生成、真灵预设或特殊开局写入基础属性、修炼资质、寿元状态和初始派生状态。
2. 揭示：入门事件、宗门检测、机缘、场景鉴定或自我认知更新 `aptitude_rating_visibility`，不在检测现场临时生成资质。
3. 改变：突破、宗门培养、资源使用、燃寿、事件、功法、阵法和明确结算结果可以写入后天永久修正、寿元来源或派生状态调整；符箓、丹药、法宝、伤势、道伤和事件持续结果先进入角色持续状态系统，再通过后天修正接口或状态结算输出影响属性与派生状态。
4. 结算：修炼、战斗、事件、资源输入、死亡与转世等系统按自身规则读取角色属性，不由本文规定固定结算顺序。
5. 展示：角色页面展示玩家可理解的当前世状态、资质揭示程度、重要后天修正、派生状态、寿元和不可用原因。

中断点包括死亡 / 转世、寿元耗尽、持续状态失效、伤势结算、资源炼化完成、突破成功或失败、检测结果更新和角色资料刷新。

## 5. 规则与状态

### 5.1 属性分层

| 层级 | 数据结构 | 作用 |
| --- | --- | --- |
| 基础属性 | `BaseAttributes` | 当前世身躯与状态底子，主要支撑派生状态上限和行动承受 |
| 修炼资质 | `AptitudeProfile` | 当前世修炼维度的效率差异：根骨影响灵气吸收和丹药炼化后的转化效率，悟性影响功法研习效率，灵根提供功法匹配增幅入口 |
| 派生状态 | `DerivedBars` | 当前可用生机、元气、神念及其保留容量 |
| 寿元状态 | `LifespanState` | 当前年龄、寿元上限、延寿来源及数值 |
| 后天修正 | `acquired_modifiers` | 后天永久改变、持续状态导出的临时修正、补偿和来历说明 |

### 5.2 来源与持续性口径

基础属性和非灵根修炼资质使用同一套来源 / 持续性口径。

| 口径 | 含义 | 是否永久 | 记录要求 |
| --- | --- | --- | --- |
| 先天 | 出生、身躯生成、特殊开局或角色初始生成时确定的属性底子 | 是 | 写入对应属性的先天值或先天结构 |
| 后天永久 | 修炼、突破、宗门培养、资源、事件、伤损修复等形成的永久改变 | 是 | 写入对应属性的后天永久修正，并保留来源 |
| 临时 | 持续状态、丹药药性、符箓术式、法宝触发、阵法、伤势、事件阶段效果等形成的非永久修正 | 否 | 通过后天修正接口记录，必须有持续状态或来源引用、持续时间、触发条件或失效条件 |

规则：

1. “先天”和“后天永久”都表示永久事实；非永久效果不得标记为先天或后天永久属性。
2. “临时”是持续性口径，不应回写到先天值或后天永久值；由持续状态产生的临时修正应在状态失效时同步停止生效。
3. 灵根等级和灵根标签在 MVP 仅支持先天口径；不得写入后天永久灵根或临时灵根。
4. 派生状态不使用先天 / 后天口径，只区分永久调整和临时修正。
5. 寿元状态不使用先天 / 后天 / 临时属性口径；寿元变化按来源事件记录。

### 5.3 基础属性

基础属性只保留当前世身躯 / 状态底子的基础字段，不包含可评级资质子项。

| 显示名 | 内部字段 | 主要作用 |
| --- | --- | --- |
| 体魄 | `base_physique` | 生机上限、负伤承受、肉身完整度、体力型行动承受、丹药系统中的经脉承载 |
| 精力 | `base_vigor` | 元气底子、持续行动承受、疲劳恢复、主动运转功法稳定性 |

规则：

1. 体魄与精力可以有先天值、后天永久修正和临时修正。
2. 寿元年龄影响可以影响体魄 / 精力的当前有效值，但它不是先天值、后天永久修正或临时增益。
3. 普通修为进度不直接增加体魄或精力。
4. 突破、宗门培养、资源使用、特殊事件或长期修炼路径可以少量改善体魄或精力，但必须写入来历记录。
5. 丹药系统需要判断经脉承载时读取体魄，不读取根骨。
6. `base_comprehension` 废弃；悟性只进入 `AptitudeProfile`。

### 5.4 修炼资质

修炼资质不汇总为一个总等级或资质总分。MVP 中根骨、悟性、灵根分别评分；灵根评分只看灵根等级，不把灵根标签折算进分值。

| 显示名 | 内部字段 | 主要作用 |
| --- | --- | --- |
| 根骨 | `aptitude_bone` | 灵气吸收效率、丹药炼化后的转化效率 |
| 悟性 | `aptitude_comprehension` | 功法研习效率 |
| 灵根等级 | `aptitude_root` | 灵根评分来源、灵根增幅倍率系数来源 |
| 灵根标签 | `root_affinity_tags` | 判断哪些功法可以获得灵根匹配增幅的标签入口 |

推荐可见性字段：

```text
aptitude_rating_visibility = unknown | revealed
```

可见性含义：

1. `unknown`：角色尚未检测，不向玩家显示完整资质；用于后续检测、鉴定或信息遮蔽扩展。
2. `revealed`：显示当前已确认字段和评级。

MVP 阶段不做分段揭示或疑似评价，`aptitude_rating_visibility` 固定使用 `revealed`。

寿元年龄影响不得影响 `aptitude_bone`、`aptitude_comprehension`、`aptitude_root` 或 `root_affinity_tags`。年龄、延寿、折寿、伤势或燃寿不能改写资质有效值、灵根等级和灵根标签。

### 5.5 灵根专项规则

灵根由“灵根等级”和“灵根标签”共同表达。MVP 只考虑相性匹配增幅，不设计相斥标签、冲突标签或标签惩罚。

| 字段 | 说明 |
| --- | --- |
| `aptitude_root` | 灵根等级，表示灵根评分，并作为灵根增幅倍率系数的来源 |
| `root_affinity_tags` | 灵根标签，例如木、火、水、风、雷、阴、阳等功法匹配标签 |

规则：

1. `root_affinity_tags` 不能单独代表全部灵根；`aptitude_root` 也不能替代灵根标签。
2. UI 或世界观文本可以把灵根包装成单灵根、双灵根、异灵根、杂灵根等说法，但底层仍映射到 `aptitude_root` 和 `root_affinity_tags`。
3. MVP 优先使用标签匹配，不做复杂五行循环、相生相克链、多层灵根谱系、相斥标签或冲突标签。
4. `root_affinity_tags` 中的相性只表示匹配关系，不包含相斥、权重、主次或冲突结构。
5. 灵根标签用于判断功法是否能受到灵根增幅；未匹配时不触发灵根增幅，也不自动施加相斥惩罚。
6. 灵根等级决定灵根增幅的倍率系数；最终增幅由功法上的基础增幅率与灵根等级倍率系数共同决定，具体系数表由数值文档维护。
7. 灵根增幅类型由功法自身配置决定，常见目标包括灵气吸收效率、功法研习效率和功法衍生指令效果。
8. 灵根不直接替代道功掌握度，也不提供功法自身未配置的额外效果维度。
9. 影响灵根相关结算的外部效果可以存在，但不得回写为“临时灵根”或“后天灵根”。

### 5.6 派生状态

派生状态是当前世角色状态条，不是战斗内一次性资源。战斗结束后不默认回满。

| 状态 | 当前值字段 | 上限字段 | 保留值字段 | 用途 |
| --- | --- | --- | --- | --- |
| 生机 | `bar_vitality_current` | `bar_vitality_max` | `bar_vitality_reserve` | 健康、伤病、濒死、肉身完整度 |
| 元气 | `bar_qi_current` | `bar_qi_max` | `bar_qi_reserve` | 气力 / 法力 / 可支配能量 |
| 神念 | `bar_mind_current` | `bar_mind_max` | `bar_mind_reserve` | 灵魂、神识、心神稳定 |

规则：

1. 保留值字段统一使用 `reserve`，用于预留不可支配容量。
2. 保留值不得超过对应上限，当前值不得超过扣除保留值后的可支配上限；具体数值约束由数值文档维护。
3. 生机不是寿元。重伤、道伤、燃寿或突破失败可以同时影响生机与寿元，但必须分别写入对应状态。
4. 生机和元气可以读取已经承接寿元年龄影响的体魄 / 精力最终值；神念不读取体魄、精力、寿元年龄影响或悟性资质。
5. 神念可以在新手阶段 UI 隐藏或弱化展示，但数据层保留。
6. 伤势、药性、符箓术式或法宝触发态若影响生机、元气、神念当前值、上限或保留值，应由角色持续状态系统输出状态结算或后天修正导出，本文不维护独立状态列表。

### 5.7 寿元设定与年龄影响

寿元是当前世角色的最大时间预算，不只是死亡倒计时。它服务于当前年龄和寿元上限展示、修炼与突破取舍、延寿与折寿、燃寿、转世决策、年龄影响入口和死亡 / 转世事件链。

推荐寿元状态字段：

```text
LifespanState {
  age: int
  lifespan_limit: int
  lifespan_extension_sources: Array<LifespanExtensionSource>
}

LifespanExtensionSource {
  source_type: string
  source_ref: string
  raw_value: int
  effective_value: int
}
```

字段规则：

1. `age` 是当前年龄，随世界时间推进。
2. `lifespan_limit` 是当前寿元上限。若外层 `CharacterState` 使用 `lifespan` 字段，语义等同于 `lifespan_limit`。
3. `lifespan_extension_sources` 记录延寿来源及数值，至少保留来源类型、来源引用、原始数值和实际生效数值。
4. 寿元基准由寿元基础值和境界突破增加寿元构成；其它所有延寿来源只作为非基准延寿。
5. 资源延寿、宗门供养、秘境机缘、消耗型物品延寿等非基准延寿的有效总和，必须由寿元数值规则按寿元基准的比例阈值统一限制，不由单个来源类型独立决定。
6. 非基准延寿超过有效上限时，超出部分不计入有效寿元上限，但仍应记录来源、原始延寿值、实际生效值和被上限钳制值。
7. 伤势折寿、道伤、燃寿和失败突破等寿元消耗或扣减必须作为消耗记录解释；它们不降低寿元基准，也不得参与非基准延寿上限阈值计算。
8. `remaining_lifespan`、`age_ratio`、体魄 / 精力年龄影响乘区和非基准延寿总上限都是数值层派生或配置，不作为寿元状态的事实字段。
9. 寿元耗尽直接死亡，并进入转世流程；宗门遗产、宗门外洞府 / 普通藏宝线索和真灵藏宝状态等后手检查属于死亡后的转世流程，不阻断死亡触发。

### 5.8 属性改变与记录

| 字段范围 | 先天 | 后天永久 | 临时 | MVP 处理方式 |
| --- | --- | --- | --- | --- |
| `base_physique` | 支持 | 支持 | 支持 | 后天永久改变通过明确行动、突破奖励、宗门培养、资源使用或事件结果写入修正；持续状态造成的临时改变通过后天修正接口导出 |
| `base_vigor` | 支持 | 支持 | 支持 | 后天永久改变通过明确行动、突破奖励、宗门培养、资源使用或事件结果写入修正；持续状态造成的临时改变通过后天修正接口导出 |
| `aptitude_bone` | 支持 | 支持 | 支持 | 后天永久改变只影响灵气吸收效率和丹药炼化后的转化效率；持续状态造成的临时改变通过后天修正接口导出 |
| `aptitude_comprehension` | 支持 | 支持 | 支持 | 后天永久改变只影响功法研习效率；临时效果或事件状态通过后天修正接口导出 |
| `aptitude_root` | 支持 | 不支持 | 不支持 | MVP 只保留先天生成或特殊开局得到的灵根等级 |
| `root_affinity_tags` | 支持 | 不支持 | 不支持 | MVP 只保留先天灵根标签；外部效果写入持续状态、增益、资源、道功、法宝、阵法或事件记录 |
| `lifespan_limit` | 不适用 | 不适用 | 不适用 | 由寿元基础值、境界突破增加寿元、非基准延寿、折寿、道伤、燃寿或失败突破等结果结算，并记录来源 |
| `age` / 寿元派生输出 | 不适用 | 不适用 | 不适用 | `age` 随世界时间推进；剩余寿元、年龄比例和体魄 / 精力年龄影响按数值规则派生 |

后天永久改变必须满足：

1. 有明确来历。
2. 有永久性标记。
3. 能解释给玩家。
4. 能进入角色履历、日志或状态说明。
5. 不把临时增益伪装成永久资质。

### 5.9 旧字段迁移

| 旧字段 / 旧口径 | 当前处理 |
| --- | --- |
| `physique` | 迁为 `base_physique` |
| `energy` 表示精力 | 迁为 `base_vigor` |
| `energy` 表示元气或行动消耗 | 迁为 `bar_qi_current` / `bar_qi_max` / `bar_qi_reserve` |
| `comprehension` / `base_comprehension` | 迁为 `aptitude_comprehension`；不得放入 `BaseAttributes` |
| `foundation` | 迁为 `aptitude_bone` |
| `spiritual_root_tags` | 拆为 `aptitude_root` + `root_affinity_tags` |
| `derived_life` | 迁为 `bar_vitality_current` / `bar_vitality_max` / `bar_vitality_reserve` |
| `derived_qi` | 迁为 `bar_qi_current` / `bar_qi_max` / `bar_qi_reserve` |
| `derived_spirit` | 迁为 `bar_mind_current` / `bar_mind_max` / `bar_mind_reserve` |
| `lifespan` 表示寿元上限 | 迁为 `LifespanState.lifespan_limit`；若保留在外层 `CharacterState`，语义仍为寿元上限 |
| `age_percent` / 年龄% | 迁为数值层派生输出 `age_ratio`，不进入 `LifespanState` 事实字段 |
| `aging_phase` 旧口径 | 迁为数值层年龄影响折线或 UI 摘要，不作为可直接改写的永久属性 |

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 真灵与执念 | 可以在新一世初始化时影响角色属性定型包、出生位置、初始物资和后手；不继承当前世年龄、寿元上限、普通行囊或派生状态 |
| 修炼系统 | 读取根骨、悟性、灵根等级、灵根标签、体魄、精力、派生状态、寿元年龄影响后的属性有效值和状态修正；根骨影响灵气吸收和丹药炼化后的转化效率，悟性影响功法研习效率；具体公式由修炼数值文档维护 |
| 道功与法门 | 读取灵根标签、功法标签、功法基础增幅率、功法增幅类型、元气 / 神念状态和掌握度；不得把灵根直接替代道功掌握 |
| 战斗系统 | 读取生机、元气、神念、体魄、精力和持续状态导出的修正；战斗结束后不默认重置派生状态 |
| 资源、丹药、符箓、法宝、阵法 | 可以创建持续状态，或在明确结算完成后写入后天永久修正、派生状态调整、寿元来源或灵根相关外部效果；丹药系统若需要经脉承载，读取体魄而不是根骨 |
| 事件系统 | 可以检测和改变属性、揭示资质、创建伤势 / 道伤等持续状态，或写入燃寿、延寿来源和角色履历 |
| 死亡与转世 | 寿元耗尽直接死亡并进入转世流程；死亡后的转世流程读取后手和真灵藏宝状态 |
| 角色页面 | 展示玩家可理解的属性、状态、寿元、揭示进度和重要来源，不展示原始公式追踪 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `base_attributes` | 基础属性结构，包含 `base_physique` 和 `base_vigor` |
| `aptitude_profile` | 修炼资质结构，包含根骨、悟性、灵根等级、灵根标签和揭示状态 |
| `derived_bars` | 派生状态结构，包含生机、元气、神念的当前值、上限、保留值和状态调整 |
| `lifespan_state` | 寿元状态结构，包含当前年龄、寿元上限、延寿来源及数值 |
| `acquired_modifiers` | 后天永久修正和临时修正接口，需保留来源、持续性和失效条件；持续状态导出的属性影响通过此处生效 |

建议结构：

```text
CharacterAttributeProfile {
  base_attributes: BaseAttributes
  aptitude_profile: AptitudeProfile
  derived_bars: DerivedBars
  lifespan_state: LifespanState
  acquired_modifiers: Array
}

BaseAttributes {
  base_physique: SourceTrackedAttribute
  base_vigor: SourceTrackedAttribute
}

AptitudeProfile {
  aptitude_bone: SourceTrackedAttribute
  aptitude_comprehension: SourceTrackedAttribute
  aptitude_root: InnateOnlyRootLevel
  root_affinity_tags: InnateOnlyRootTags
  aptitude_rating_visibility: unknown | revealed
}

SourceTrackedAttribute {
  innate_value: number
  acquired_permanent_delta: number
  temporary_modifiers: Array
  effective_value: number
}

DerivedBars {
  bar_vitality_current: number
  bar_vitality_max: number
  bar_vitality_reserve: number
  bar_qi_current: number
  bar_qi_max: number
  bar_qi_reserve: number
  bar_mind_current: number
  bar_mind_max: number
  bar_mind_reserve: number
  permanent_adjustments: Array
  temporary_modifiers: Array
}
```

说明：

1. `SourceTrackedAttribute` 适用于基础属性和非灵根资质。
2. `effective_value` 是当前可被系统读取的实际值；具体计算由数值文档维护。
3. `InnateOnlyRootLevel` 和 `InnateOnlyRootTags` 体现 MVP 阶段灵根等级与灵根标签仅支持先天。
4. `DerivedBars.permanent_adjustments` 不区分先天 / 后天，只表示永久派生状态调整。
5. 剩余寿元、年龄比例、体魄 / 精力年龄影响乘区和非基准延寿总上限可以作为数值层派生输出或缓存，但事实来源仍是 `age`、`lifespan_limit`、寿元来源记录和数值表。
6. 伤势、药性、符箓持续效果、法宝触发态和事件持续结果不进入 `CharacterAttributeProfile`；持续状态系统通过 `character_id` 关联角色，并通过 `acquired_modifiers` 或派生状态结算输出影响本文字段。

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通角色页面应展示：

1. 当前世身份、年龄、寿元上限、剩余寿元、必要的年龄影响摘要和宗门身份。
2. 基础属性：体魄、精力。
3. 修炼资质：根骨、悟性、灵根等级、灵根标签，以及三项资质各自评分。
4. 派生状态：生机、元气、神念。
5. 当前主修道功、修为阶段、瓶颈 / 突破状态。
6. 重要后天修正、持续状态摘要、伤势 / 药性 / 风险标签和资质揭示程度。

普通 UI 不应展示：

1. 综合资质评价或资质总分作为底层判定字段。
2. 灵根包装名作为唯一底层字段。
3. 真灵强度作为稳定修炼效率加成。
4. 执念容量作为传统属性点。
5. 体魄 / 精力的寿元年龄影响作为先天资质或后天永久提升。
6. 原始系数、公式缓存、内部 ID、调参表或 Debug 追踪。

## 9. MVP 范围

MVP 应实现：

1. 基础属性：体魄、精力。
2. 修炼资质：根骨、悟性、灵根等级和灵根标签。
3. 资质揭示状态：MVP 固定使用 `revealed`；`unknown` 仅作为后续检测或信息遮蔽扩展状态保留。
4. 派生状态：生机、元气、神念的当前值、上限和保留值。
5. 寿元状态：当前年龄、寿元上限、延寿来源及数值；剩余寿元和年龄影响由数值层派生。
6. 来源 / 持续性记录：先天、后天永久、持续状态导出的临时后天修正、永久派生状态调整、寿元来源。
7. 旧字段迁移口径。
8. 非基准延寿作为寿元来源之一，并由寿元数值规则统一限制有效总量。
9. 角色属性模块只读取持续状态系统导出的临时修正和结算输出，不维护独立伤势状态字段。

MVP 不实现：

1. 后天永久灵根改写或临时灵根。
2. 复杂五行循环、相生相克链、多层灵根谱系、相斥标签和冲突标签。
3. 单一资质总分或综合资质评分参与核心判定。
4. 真灵继承当前世寿元、年龄、普通行囊或派生状态。
5. 派生状态战斗后自动回满。
6. 角色属性模块替其它系统规定固定结算顺序或倍率。
7. 伤势、药性、符箓持续效果、法宝触发态和事件持续结果作为角色属性字段保存。

## 10. 验收约束

1. 包内文档引用角色属性系统层时，应以本文为字段语义和规则来源。
2. 任何公式、系数、倍率、年龄影响折线、缓存字段和调参边界不得在本文重复维护，应指向数值文档。
3. `base_comprehension` 不得恢复为基础属性；悟性只作为 `aptitude_comprehension`。
4. 寿元年龄影响不得影响根骨、悟性、灵根等级、灵根标签或神念基础值。
5. 生机不得被当作寿元；寿元也不得作为战斗内临时资源。
6. MVP 阶段不得出现后天灵根、临时灵根、相斥标签、冲突标签或把外部效果写回灵根字段。
7. 后天永久改变必须有来源记录；临时修正必须有持续时间、触发条件或失效条件。
8. 非基准延寿不得由物品、丹药、事件或宗门供养文档单独决定总量上限，必须承接寿元数值规则。
9. 非 MVP 信息遮蔽扩展可以隐藏未揭示资质，但数据层不得因此延迟生成资质；MVP 阶段资质可见性固定为 `revealed`。
10. 伤势、道伤、心魔、药性、符箓持续效果、法宝触发态和事件持续结果不得恢复为角色属性分层或 `CharacterAttributeProfile` 字段。
11. 持续状态影响角色属性有效值时，必须通过 `acquired_modifiers` 后天修正接口生效。
12. `LifespanState` 不得重新扩展为寿元派生缓存集合；系统层只保留当前年龄、寿元上限、延寿来源及数值。
13. 不得恢复独立寿元紧迫字段；寿元临界期影响通过体魄 / 精力年龄影响和寿元耗尽死亡体现。
14. 燃寿、折寿、道伤等消耗项不得降低寿元基准，也不得改变非基准延寿总上限阈值。
