## 1. 子系统定位

S11 定义玩家跨世外在资产如何存在于世界中，以及哪些安排能被系统视为“正式后手”。

一句话定位：

> S11 决定前世留下的东西在哪里、是否还能找到、为什么会失效，以及玩家怎样通过轮回账本和行动把它们找回来。
> 

## 2. 普通前世遗产与正式后手

必须区分两类跨世外在资产：

| 类型 | 规则含义 | 保护强度 |
| --- | --- | --- |
| 普通前世遗产 | 前世死亡或放置后自然留在世界中的资产 | 可被发现、搬空、污染、破坏或转移 |
| 正式后手 | 经过正式行为封存、布置、记录并占用后手容量的安排 | 必须可追踪、有日志、失效有原因链 |

正式后手不是无限保险箱。它可以暴露、受损或被争夺，但不能无日志、无原因地消失。

## 3. 后手容量

正式后手容量由 S2 真灵强度提供。

```
FormalContingencySlot {
  spirit_id
  max_slots
  used_slots
  unlocked_by_spirit_strength
}
```

MVP 只需要支持少量正式后手，不追求复杂组合。

## 4. 后手类型

MVP 建议先支持：

1. 藏物后手：封存物品、灵石、丹药、法宝、功法载体。
2. 地点后手：洞府、隐蔽山洞、阵法点、接引点。
3. 信息后手：遗书、地图、暗号、任务链、线索。
4. 权限后手：宗门密库权限、令牌、身份凭证。
5. 护持后手：护道人、弟子安排、阵法守护的抽象接口。

MVP 可先实现 1–3，4–5 作为接口预留。

## 5. 后手创建流程

```
玩家选择正式布置后手
→ 检查真灵后手容量
→ 检查当前位置、物品、资源、权限与时间投入
→ 选择后手类型与封存目标
→ 生成后手记录
→ 写入 S8 节点隐藏层与 S2 轮回账本
→ 消耗行动格、资源或物品
```

后手创建应是持续行动或事件链结果，不应作为纯即时行动完成。

## 7. 后手感应

后手感应不是常规强度加成，而是轮回账本交互规则。

最小规则：

- 玩家越接近正式后手所在区域，账本描述越清晰。
- 相关地点、传闻、路线或事件可提高感应清晰度。
- 感应只提供线索，不自动传送或直接领取。
- 感应强度可受真灵强度、道韵、失败经历、地点状态影响。

## 8. 回收流程

```
玩家获得线索
→ 前往相关节点
→ 执行后手搜寻 / 破解 / 开启持续行动
→ S11 读取隐藏层与访问条件
→ 可能触发 S10 事件或战斗
→ 成功后转移资产、权限或信息
→ 更新轮回账本与节点状态
```

S3 提供行动格、位置、tick 与中断上下文。

如果后手进入 looted 或 destroyed_with_trace，必须记录原因和追查入口。

## 10. 普通遗产规则

普通前世遗产不占用后手容量，也不享受强追踪。

它可以由死亡位置、洞府、背包遗落、宗门接管、敌方掠夺、秘境封存等自然生成。玩家可以通过记忆、传闻、地图变化或偶然探索找到。

## 11. 失效原因链

正式后手失效必须至少包含：

- 何时发生。
- 哪类原因导致。
- 是否可追查。
- 是否可修复或补救。
- 玩家何时能通过账本或传闻得知。

示例原因：

- 节点被敌对宗门控制。
- 隐藏层因秘境波动暴露。
- 后手阵法年久失修。
- 被同道探查发现。
- 玩家前世死亡造成权限断裂。
- 宗门内乱导致密库转移。

## 12. 与其他系统的接口

- S2：读取真灵、后手容量、轮回账本、转世链。
- S3：读取搜寻、封存、破解、回收行动的时间轴。
- S8：挂载后手隐藏层、节点状态与发现状态。
- S9：封存和转移具体资产。
- S10：触发后手事件、守护、争夺、暴露与传闻。
- S13：决定其他玩家是否通过间接方式影响后手所在节点。
- S14：持久化后手记录、隐藏层和原因链日志。

## 13. MVP 验收标准

1. 玩家可创建至少一种正式后手。
2. 正式后手占用容量并写入轮回账本。
3. 转世后玩家可通过感应或线索找到后手。
4. 后手回收需要 S3 行动投入。
5. 后手被破坏或暴露时有日志和追查路径。
6. 普通遗产与正式后手在数据层可区分。
