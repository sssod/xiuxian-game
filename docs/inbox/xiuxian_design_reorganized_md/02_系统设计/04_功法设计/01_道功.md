# 功法设计｜道功

## 1. 文档边界

本文记录“道功”的核心定义、设计理念、修为关系、掌握度与数据口径。

本文只处理道功作为功法类型本身的规则，不展开：

1. 角色当前选择哪一门道功作为主修，以及主修更换窗口、锁定记录和换修流程。
2. 残页、篇章、完整功法等物品链。
3. 法门提供的战斗、探索、移动、采集、生产和事件能力。
4. 每小时修炼公式、境界段数值表和具体倍率调参。

边界口径：

| 概念 | 本文是否负责 | 说明 |
| --- | --- | --- |
| 功法 | 只定义总分类口径 | 功法是泛称，规则层应拆为道功与法门 |
| 道功 | 负责 | 修为路线、上限、吸收转化、突破路线标签、被动效果 |
| 主修道功 | 只说明“道功可被设为主修” | 主修状态、切换与锁定由角色主修功法文档负责 |
| 法门 | 不负责 | 法门是能力、指令、事件选项与效率体系 |
| 功法载体 | 不负责 | 载体是物品系统，不是道功掌握状态 |

## 2. 功法总口径

功法不是单纯技能树，也不是单纯修为倍率表。它在规则层分为两类：

```text
DaoMethod：道功
TechniqueMethod：法门
```

“功法”只作为上位泛称使用，不建议在规则判断中直接用 `method` 表达精确类型。凡涉及修为推进、当前可修上限、大境界突破路线和主修资格的内容，应落到道功；凡涉及战斗指令、行动能力、事件选项和资源效率的内容，应落到法门。

## 3. 核心定义

道功是可推动修为增长的功法类型，也是唯一可以设为主修的功法类型。

道功决定角色一世内的修行路线根基。玩家选择某门道功，本质是在选择当前大境界的修炼路线，而不只是选择一个收益倍率。

道功路线可以体现为：

1. 快修但修为稳定性或纯度压力较高。
2. 慢修但突破更稳。
3. 依赖特定灵气环境、节点或洞府设施。
4. 擅长转化丹药、灵液、灵材和宗门配给。
5. 偏生存，提供护身、辟谷、解毒、凝神、藏息等被动效果。
6. 偏神魂，强化神念成长、心魔抵抗或神魂攻防。
7. 偏后期，早期效率低但更高阶段上限或路线收益更好。

## 4. 道功负责什么

道功负责：

1. 主动吐纳的基础吸收能力。
2. 主动吐纳的基础转化特质。
3. 自动运转的基础收益和稳定性。
4. 当前可修阶段上限。
5. 与灵根、资源输入、节点环境和设施支持的修炼相性。
6. 大境界突破路线标签、挑战倾向、奖励倾向和失败标签池。
7. 主修路线标签。
8. 与该道功绑定的少量被动效果、提示型收益或可追回知识型收益。

道功不负责：

1. 战斗指令的完整展开。
2. 采集、炼丹、炼器、阵法、医术、卜算、隐匿等技艺体系的完整展开。
3. 替代法门系统。
4. 作为物品存在于背包中。
5. 用残页或篇章直接形成运行时学习进度。

## 5. 学习与研习

常规道功流程：

```text
获得完整道功载体
→ 选择研习功法
→ 达到入门阈值
→ 创建 MethodState，进入 learned level 1
→ 可按规则设为主修道功
```

新手基础道功可以由宗门入门事件、新手奖励或教学流程直接授予 learned level 1。该例外用于降低入门摩擦，不代表残页或篇章可以直接学习。

研习道功属于可选投入执行时间的个人持续行动。它读取：

```text
实际投入小时
悟性 aptitude_comprehension
道功阶级 tier_code
道功品级 quality_code
导师
藏经阁、静室、讲经、事件等设施或加成
当前神念状态
前置知识、基础法门或路线理解
```

研习道功可以产出：

1. `MethodState` 经验增加。
2. `MethodState` 掌握等级提升。
3. 未入门道功进入 learned level 1。
4. 道功当前可修上限提高。
5. 主动吐纳或自动运转的单位时间收益提高。
6. 与该道功相关的被动效果、提示型收益或路线信息解锁。

研习道功不能产出：

1. 直接修为进度。
2. 缺失残页或篇章自动补齐。
3. 道功理论最高上限提高。
4. 大境界突破模板类型变化。
5. 小境界升级奖励质量变化。
6. 修为纯度收益变化。
7. 阶段性不可追回收益被事后追回。

## 6. 主动吐纳与自动运转

主动吐纳是角色主动运转当前主修道功，把环境灵气、设施支持和行动内资源输入转化为修为进度的核心行动。

主动吐纳读取：

1. 当前境界与小阶段。
2. 当前主修道功的吸收速度、转化效率、路线标签和掌握度。
3. 角色资质、灵根相性、根骨承载、状态压力和伤势。
4. 所在节点灵气、洞府、设施、宗门支持和机会窗口。
5. 行动内选择的丹药、灵液、灵材等资源输入。

主动吐纳输出：

1. 修为进度。
2. 当前主修道功经验。
3. 可能的纯度、经脉压力、残余药性和使用资源日志。

自动运转是主修道功最基础的被动表现，用于表达修士日常吐纳不息，但不能替代主动吐纳。

自动运转规则：

1. 按世界小时或兼容 tick 结算低额收益。
2. 主动吐纳期间不额外生效，避免同一 tick 同时获得主动吐纳和自动运转收益。
3. 突破事件链、昏迷、重伤、封印等状态下不生效。
4. 可在合法状态下提供少量修为或稳定性收益。
5. 通常可以触发普通小境界升级。
6. 不能完成大境界突破。
7. 不自动消耗高价值丹药或突破资源。

## 7. 掌握度与上限

道功掌握度表示角色对该道功的理解、运转熟练度与当前承载能力。

道功有两个上限概念：

```text
theoretical_max_cap_stage：道功理论最高上限
mastery_current_cap_stage：掌握度当前上限
```

当前有效上限：

```text
effective_current_cap_stage = min(
  theoretical_max_cap_stage,
  mastery_current_cap_stage
)
```

道功掌握度可以影响：

1. 当前可修上限。
2. 主动吐纳单位时间收益。
3. 自动运转单位时间收益。
4. 资源输入兼容性、承载稳定性或风险提示。
5. 某些可追回的知识型、提示型或路线型收益。

道功掌握度不能影响：

1. 道功理论最高上限。
2. 修为纯度收益。
3. 小境界升级奖励质量。
4. 大境界突破模板类型。
5. 大境界突破模板自身的核心风险结构。
6. 阶段性不可追回收益。

旧文档中的“功法等级”“道功等级”统一理解为 `MethodState.mastery_level`。它是掌握度层级，不是残页或篇章收集进度。

## 8. 上限示例

示例：《青木养真诀》

```text
理论最高上限：B-1 100%

level 1：当前可修至 A-2 100%
level 2：当前可修至 A-3 100%
level 3：当前仍可修至 A-3 100%，单位时间收益提高
level 4：当前可修至 B-1 100%
level 5：当前仍可修至 B-1 100%，单位时间收益进一步提高
```

不会发生：

1. level 5 让《青木养真诀》修到 B-2。
2. level 5 让 A-3 → B-1 的突破模板变成另一个模板。
3. level 不足导致 A-1 → A-2 时永久少拿属性。
4. level 不足导致修为纯度永久变差。

## 9. 与大境界突破的关系

大境界突破模板类型来自道功本身的路线特质，而不是掌握等级临时生成。

可以成立：

```text
《青木养真诀》本身具有 A-3 → B-1 的木系稳健突破转接。
```

不应成立：

```text
《青木养真诀》level 1 匹配低级模板，level 5 匹配另一个高级模板。
```

掌握度影响的是“角色是否承载得住目标阶段、是否满足开启条件、是否获得更稳定的可见度或执行表现”，而不是把一门道功改造成另一种突破模板。

示例：

```text
《青木养真诀》理论最高：B-1
突破转接：A-3 → B-1

level 2 当前只能修到 A-3：
- 可以修到 A-3 100%。
- 不能使用该道功完成 A-3 → B-1。
- 原因是当前掌握度承载不住 B-1。

level 4 当前能修到 B-1：
- 可以使用 A-3 → B-1 的木系稳健突破转接。
- 突破模板类型仍来自道功本身特质，不由 level 4 生成。
```

## 10. 自然上限设计规范

可作为主修根基的道功，其自然最高上限原则上应落在某个大境界第一小阶段，方便玩家在新大境界的改修窗口内自然续接。

推荐：

```text
A 段道功：A-1 / A-2 / A-3 / B-1
B 段道功：B-1 / B-2 / B-3 / C-1
C 段道功：C-1 / C-2 / C-3 / D-1
```

不推荐：

```text
A-1 / A-2 / A-3 / B-1 / B-2
```

原因是这会把玩家自然卡在 B-2，而 B-2 已离开 B 阶常规改修窗口。

同一传承可以连续，但规则层应拆成多个完整道功模板。

示例：

```text
lineage_id = qingmu_lineage

《青木养真诀》：A-1 → B-1
《青木长生经》：B-1 → C-1
《青木洞玄篇》：C-1 → D-1
```

它们共享传承标签、宗门来源、世界观文本和资源相性，但在规则层是不同完整道功。

## 11. 数据口径

道功模板建议字段：

```yaml
DaoMethod:
  method_id: string
  method_type: dao_method
  display_name: string
  lineage_id: string
  tier_code: string
  quality_code: string
  route_tags: list
  stage_support_range: list
  theoretical_max_cap_stage: string
  mastery_curve_id: string
  level_cap_profile: map
  absorption_profile: map
  conversion_profile: map
  root_affinity_tags: list
  resource_affinity_tags: list
  node_affinity_tags: list
  passive_effect_refs: list
  breakthrough_route_tags: list
  breakthrough_support_profile: map
  compatibility_requirements: map
```

角色对某门道功的掌握状态由 `MethodState` 表达。`MethodState` 不保存残页或篇章收集进度。

```yaml
MethodState:
  method_state_id: string
  character_id: string
  method_id: string
  method_type: dao_method
  learned_from_carrier_id: string
  mastery_level: number
  mastery_exp: number
  mastery_current_cap_stage: string
  unlocked_effect_refs: list
  active_tags: list
  last_practiced_world_day: number
  last_practiced_world_hour: number
```
