# 随机事件玩法设计

## 1. 当前结论

事件系统的核心不是“发生很多故事”，而是让玩家在世界压力下持续回答问题。常规事件的主干应是选择事件。

## 2. S10 事件分类

MVP 事件分为：

1. 移动事件。
2. 节点事件。
3. 宗门事件。
4. 世界刷新事件。
5. 秘境 / 窗口事件。
6. 控制权变化事件。
7. 传闻生成事件。
8. 专用事件链入口。

专用事件链包括突破、战斗、死亡 / 转世、前世后手回收。

## 3. 选择事件

选择事件本质：系统抛出一个问题，玩家用一个选项回答，系统根据回答生成后果。

常规事件选项结构：

```text
系统抛出问题
→ 玩家从 1–3 个主选项中选择
→ 必要时通过“...”查看溢出选项
→ 事件生成可解释后果
→ 后果写入角色、节点、宗门、日志、传闻或专用事件链
```

五类内部选项维度：正面应对、出奇制胜、逃避推诿、解构问题、欺诈蒙骗。

## 4. 事件结果包

```yaml
EventOutcome:
  event_id: string
  outcome_level: string
  character_delta: object
  inventory_delta: object
  node_delta: object
  sect_delta: object
  route_delta: object
  triggered_child_events: list
  interrupt_s3_plan: bool
  consumed_ticks: number
  ledger_entries: list
  visible_log_entries: list
  hidden_world_log_entries: list
```

所有结果交给 S1 统一回写，避免事件直接绕过结算总线。

## 5. 已定 UI / 选项规则

- 常规事件默认隐藏不可用选项。
- 例外：教学事件、突破准备面板、关键节点事件可少量灰显。
- 窗口事件 MVP 只实现秘境窗口、节点危机、突破资源 / 名额窗口。
