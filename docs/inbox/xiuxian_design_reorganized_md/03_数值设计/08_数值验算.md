# 数值设计｜数值验算

## 1. 设计定位

本文负责维护数值验算的校验口径、场景矩阵、输入样例、输出指标、异常测试和调参验收边界。它回答核心问题：

```text
当前世代在当前境界段的实际效率，是否高于、等于或低于设计基准？
```

当效率低于基准时，轮回应变得有价值；当效率高于基准时，继续修行必须仍然合理。

本文不维护境界表、修炼公式、战斗公式、投放预算或角色属性公式。上述内容由对应数值设计文档维护；本文只消费它们的输入和输出，用于验证曲线、样例和异常边界是否成立。

## 2. 当前结论

1. 数值验算是校验层，不是新公式来源；验算失败时应回到对应公式、配置表或系统规则文档修订。
2. 验算主链从 `RealmSegmentBalance` 开始，经基准小时收益、行动样例、资源输入、状态压力、突破准备和轮回效率判断，最终确认玩家实际效率与设计基准的关系。
3. 必测场景必须同时覆盖低资源、普通资源、高价值资源、事件打断、小境界升级、大境界突破、低效率转世和高效率继续修行。
4. 验算输出必须区分普通调参摘要和 Debug 明细；普通 UI 不读取完整公式追踪。
5. Excel / 表格模型、模拟器和 Debug 输出格式仍待补，但字段结构和验收口径可以先固定。

## 4. 基准、单位与输入参数

### 4.1 单位口径

| 项目 | 口径 |
| --- | --- |
| 验算周期 | 可按单次行动、单个境界段、一次闭关、一轮突破准备或一个宏观预算周期组织 |
| 时间单位 | 使用世界小时；现实等待只用于体验目标检查，不改变数值结算 |
| 进度单位 | 使用 `normalized_segment_progress` 和 `cultivation_points` 双口径检查 |
| 效率倍率 | 使用实际有效进度 / 基准有效进度衡量，不直接用资源数量代替 |
| 异常阈值 | 由被验算文档提供；本文记录是否越界和越界来源 |

## 5. 公式或模型

### 5.1 推荐验算链

```text
RealmSegmentBalance
→ benchmark hour rate
→ 行动规划样例
→ 资源输入样例
→ 状态压力样例
→ 突破资格样例
→ 突破挑战初始分数
→ 轮回效率判断
```

验算链的职责：

1. 从境界段目标反推出基准小时收益。
2. 把行动规划样例转成实际兼容小时。
3. 把资源输入样例转成实际释放小时、有效倍率、残余效果和副作用。
4. 把状态压力样例转成收益裁剪、压力累积或风险结果。
5. 把境界段完成情况转成突破资格和突破挑战初始分。
6. 比较当前世代效率与基准效率，判断继续修行和轮回选择是否都合理。

### 5.2 效率判定

```text
actual_efficiency_ratio =
  actual_normalized_progress_gain
  / benchmark_normalized_progress_gain
```

判定口径：

1. `actual_efficiency_ratio < 1.0`：低于当前境界段基准，应检查轮回或换路径是否具有价值。
2. `actual_efficiency_ratio = 1.0`：接近基准，应作为普通修士或普通玩家路径的参照。
3. `actual_efficiency_ratio > 1.0`：高于基准，应继续检查资源消耗、压力、风险、预算来源和阶段上限是否合理。

### 5.3 异常检查

异常检查不直接修改公式，只输出问题位置：

```text
verification_case
→ run numeric chain
→ compare expected bounds
→ record failed metric
→ point back to owning document
```

常见异常包括：

1. 修为收益超过境界段效率上限。
2. 资源未进入兼容语境却提前产生收益。
3. 事件打断后残余药性丢失、重复结算或无法复盘。
4. 阶段预算打开后资源机会直接变成玩家资产。
5. B1、F1、N1 或 P0 的现实等待影响了世界小时数值。
6. 派生状态上限、寿元年龄影响或保留值被重复计算。

## 6. 配置表或根表

### 6.1 验算场景表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `verification_case_id` | 验算场景 ID | 用于表格、模拟器和 Debug 输出对齐 |
| `realm_segment_id` | 目标境界段 | 读取境界段配置 |
| `case_type` | 场景类型 | 可为 `baseline`、`resource_boost`、`interrupted`、`breakthrough`、`reincarnation`、`budget`、`combat` |
| `action_profile_id` | 行动样例 | 主动吐纳、闭关、自动运转等 |
| `resource_input_set` | 资源输入组合 | MVP 同效果通道最多一个主资源输入 |
| `state_pressure_profile` | 状态压力样例 | 可为空 |
| `expected_metric_bounds` | 期望指标范围 | 保存效率、耗时、资源消耗和风险边界 |
| `owner_document` | 失败回溯文档 | 指向对应公式或系统文档 |

### 6.2 指标表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `benchmark_normalized_progress_gain` | 基准标准化进度收益 | 由境界段和修炼公式反推 |
| `actual_normalized_progress_gain` | 实际标准化进度收益 | 由本次样例结算得到 |
| `actual_efficiency_ratio` | 实际效率倍率 | 用于继续修行 / 轮回判断 |
| `world_hours_elapsed` | 实际世界小时 | 不受现实加速直接改变 |
| `compatible_hours_used` | 实际兼容小时 | 资源释放和修炼收益只读取该值 |
| `resource_consumed_value` | 资源消耗价值 | 用于反查投放与收益是否匹配 |
| `residual_effect_value` | 残余效果价值 | 用于事件打断和残余药性检查 |
| `pressure_delta` | 状态压力变化 | 用于收益裁剪和风险判断 |
| `breakthrough_initial_score` | 突破挑战初始分 | 用于突破准备验算 |
| `failed_metrics` | 未通过指标列表 | 必须能指回负责文档 |

## 7. 结算输出

### 7.1 调参摘要

每个验算场景至少输出：

1. 场景名称、境界段、行动样例和资源输入摘要。
2. 基准有效进度、实际有效进度和实际效率倍率。
3. 世界小时、兼容小时、资源消耗、残余效果和压力变化。
4. 小境界推进、突破资格或突破初始分结果。
5. 是否低于基准、接近基准、超过基准或触发异常。
6. 失败指标和应回溯的包内文档。

### 7.2 Debug / QA 输出

Debug 输出应能复盘：

1. 每个公式输入项、倍率项、裁剪项和输出项。
2. 资源输入的实际释放小时、残余策略和副作用。
3. 事件打断前后的行动状态、资源状态和时间状态。
4. 阶段预算打开后的资源机会、资产实例化位置和反套利检查。
5. 派生状态上限、寿元年龄影响、保留值和状态钳制记录。
6. 现实速度与世界小时的换算检查。

## 8. 调参验收口径

1. 无资源普通修炼应接近或低于当前境界段基准，不应稳定超过高资源路径。
2. 宗门静室 + 普通丹药修炼应提升效率，但必须受境界适配、资源消耗和压力约束。
3. 高价值资源集中闭关可以显著高于基准，但不得突破境界段效率上限和投放预算边界。
4. 行动被事件打断后，残余药性必须可复盘，不能丢失、重复结算或在非兼容语境继续涨修为。
5. 小境界升级可以由修为进度触发，但必须保留自身 `0%-100%` 进度口径。
6. 大境界突破资格只能开启突破挑战或准备链，不得自动完成大境界升级。
7. 低效率世代转世收益必须有可解释价值，但不能把低效率路径变成无成本刷收益。
8. 高效率世代继续修行仍应合理，不能因为轮回收益过高而强迫玩家每段都转世。
9. 阶段预算打开后的资源机会不得直接变成玩家资产，也不得与设施、事件或市场收益重复套利。
10. B1、F1、N1 和 P0 的现实等待差异不得改变世界小时、兼容小时、资源消耗和压力结算。
11. 角色属性、派生状态和寿元公式不得在修炼、战斗或验算链中重复计算。

## 9. MVP 范围

MVP 应实现：

1. 一张验算场景表。
2. 无资源普通修炼样例。
3. 宗门静室 + 普通丹药修炼样例。
4. 高价值资源集中闭关样例。
5. 事件打断后的残余药性样例。
6. 小境界升级样例。
7. 大境界突破资格和突破初始分样例。
8. 低效率世代转世收益样例。
9. 高效率世代继续修行收益样例。
10. 调参摘要和 Debug 输出字段。

MVP 不实现：

1. 完整 Excel / 表格验算模型定稿。
2. 所有境界段的完整样例数据。
3. 自动化平衡模拟器。
4. 战斗技能、法宝品质和 AI 权重完整曲线。
5. 高阶长期世界经济全量模拟。
