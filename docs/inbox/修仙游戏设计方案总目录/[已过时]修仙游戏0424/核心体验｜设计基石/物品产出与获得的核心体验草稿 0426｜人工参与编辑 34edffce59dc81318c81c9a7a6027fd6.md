## 1. 已读取并继承的上位约束

### 1.1 项目级约束

- 游戏是修仙题材、文字 / 策略、选择导向、个人成长 + 宗门经营 + 沙盒演化。
- MVP 边界：本地单人可测试、可部署私人服务器、支持 3 人共玩。
- 技术路线已确定为 Godot，规则与内容应尽量数据驱动。
- 实现层避免过早绑定修仙包装；境界采用 `A-1 / B-1 / C-1` 等抽象编码。
- 世界采用季度推进，产出、事件、战斗、突破、宗门行动最终都应进入统一结算与日志。

### 1.2 现有系统约束

- S9 已确定：不采用传统装备栏；随身携带的法宝、道具、已掌握术法 / 神通都可以成为可用来源，限制来自行动格、交锋格、资源、耐久、充能、事件条件与标签，而不是固定栏位。
- S9 已确定：MVP 不引入重量、体积、背包格子或负重上限，随身资产主要通过标签和事件限制表达。
- 本草稿新增约束：物品随机性必须服从堆叠规则，不能让高频普通道具因为微小随机差异全部拆成独立实例。
- 本草稿新增约束：玩家角色与所有宗门的资源都应明确可计算；由角色或宗门主动生产物品时，优先使用配方制，消耗明确资源，产出明确目标物品，并只在配方允许范围内随机。
- 本草稿新增约束：自然资源点原则上先产出“资源池 / 资源量”，不是直接产出具体物品；资源通过采集、加工、炼制、修复等行动转化为宗门资源或材料物品。
- 本草稿新增约束：宝藏、事件、NPC 掉落、NPC 交易等世界生成物品属于“凭空生成”范畴，需要同时受局部玩法约束与全局分阶预算帽约束。
- 本草稿新增约束：物品存在显性 / 隐性两种状态。玩家库存、宗门库存、正式后手、常规宝库属于显性流通；其他潜在物品可保持隐性，在需要时再实例化。
- S6 已确定：宗门资源必须真实存在，宗门发放给玩家或 NPC 的资源必须来自真实库存；贡献不是货币。
- S7 已确定：每个宗门每季度始终只有 1 个宗门主行动；已控制资源节点的基础产出走常态结算，不占用宗门主行动。
- S8 已确定：资源与建筑挂载在地理节点的槽位层，资源槽代表节点自然或半自然产出。
- S10 已确定：事件结果包可改变角色、库存、节点、宗门与日志；物品获得应尽量通过事件结果包或结算结果包落地。
- S4 已确定：突破资源、功法匹配、地点灵气、宗门支持等是突破输入维度，但 S4 不定义具体物品系统。

## 2. 一句话定位

> 物品产出与获得系统负责管理“资源如何变成物品、物品如何从隐性状态实例化、显性物品如何流通与回收、以及世界凭空生成物品如何受预算帽约束”。
> 

它不是单纯的掉落系统，也不是把所有来源都塞进同一个随机掉落表，而是贯通以下体验的资源—物品—经济生成层：

- 玩家为什么要探索、战斗、拜入宗门、争夺节点、积累后手。
- 宗门为什么要控制资源点、建设设施、安排开采、培养弟子。
- 物品为什么能支撑修炼、突破、战斗、转世与世界演化。
- 随机性如何提供惊喜和复玩性，同时不破坏计划性。

## 3. 核心体验目标

### 3.1 物品获取是长期目标，不是纯奖励结算

物品不应只是“打完事件给一个奖励”。理想体验是：

```
发现线索 / 资源窗口
→ 判断是否投入行动格、宗门行动、风险或资源
→ 通过探索、开采、交易、制造、战斗、任务或后手回收获得物品
→ 识别 / 解除封印 / 使用 / 上交 / 修复 / 拆解 / 封存
→ 影响修炼、突破、战斗、宗门库存、节点状态或轮回账本
```

玩家获得物品后应自然产生选择：

- 自己使用，提高当世成长效率。
- 上交宗门，换取贡献、声望或宗门支持。
- 储存起来，服务后续突破或高风险事件。
- 修复或炼制，尝试提高价值。
- 拆解回收，转化为材料。
- 作为正式后手封存，跨世追踪。
- 出售或交换，转化为其他资源。

### 3.2 物品生成必须有随机性，但不能让玩家失去掌控感

随机性服务三类体验：

1. **世界活性**：同一资源点、秘境、事件不总是产出完全相同的东西。
2. **发现惊喜**：玩家可能发现额外词条、特殊来源、隐藏缺陷或稀有副产物。
3. **复玩差异**：多世、多房间、多人宗门竞争中，资源结构会自然分化。

但随机性必须受约束：

- 玩家投入方向应大体决定产出方向。
- 高风险随机必须提前标注风险来源。
- 关键资源不应因为一次暗骰完全报废。
- 失败或低 roll 也应有回收路径。
- 随机结果应能被日志解释，便于复盘。

### 3.3 物品价值来自“资源效率”，不是单纯战力

本项目的核心循环中，修为、战斗能力、非战斗能力、宗门职位、天赋与后手最终都指向资源获取效率。因此物品价值也应围绕资源效率建模：

- 提高修炼效率。
- 降低突破风险。
- 提高战斗结算质量。
- 增加行动成功率。
- 提高宗门产出。
- 改善节点控制或探索发现率。
- 支撑跨世后手。

## 4. 全游戏统一等级规则：阶级 + 品级

### 4.1 采用统一等级表达

建议全游戏可评级对象统一采用：

```
阶级 Tier + 品级 Quality
```

适用对象：

- 物品。
- 功法 / 术法载体。
- 法宝。
- 消耗道具。
- 材料 / 灵材 / 矿材。
- 突破资源。
- 根骨、悟性、灵根等资质子项。
- 建筑或节点资源槽的产出等级。

原因：

- 修仙体系中大境界跃迁会带来数值阶梯式变化。
- 与之匹配的物品、功法、资质也需要阶梯式表达。
- “凡品功法”这类描述容易把阶级和品级混在一起，后续扩展困难。
- 统一结构便于定价、生成、掉落、检索、UI 展示和数值平衡。

### 4.2 阶级 Tier

阶级对应大层级，规则层与境界大阶段对齐，但数据层不直接绑定具体修仙包装。

实现建议：

```
TierProfile {
  tier_code        // A / B / C / D...
  tier_order       // 1 / 2 / 3 / 4...
  display_key      // 默认读取对应修炼阶级包装
  default_stage_range
  value_multiplier
  access_requirement
}
```

示例：

```
A阶：适配 A-1 ~ A-3 阶段
B阶：适配 B-1 ~ B-3 阶段
C阶：适配 C-1 ~ C-3 阶段
```

#### 已确定决策：阶级显示原则上与修炼阶级包装对齐

规则层仍使用 `A / B / C` 等抽象阶级，但 UI 显示原则上与当前修炼阶级包装对齐，便于玩家理解物品、功法、突破资源与角色阶段的关系。

示例：

```
数据层：A阶 / B阶 / C阶
显示层：炼气阶 / 筑基阶 / 金丹阶，或当前世界观包装中的同阶名称
```

例外：少数系统可以使用独立评级包装，例如灵根等级、特殊天赋等级、血脉等级等。这类系统仍可映射到统一价值模型，但显示上不强制套用修炼阶级名称。

数据层不建议直接使用：

```
lianqi / zhuji / jindan
```

这些只作为本地化显示或世界观包装，不作为规则 ID。

### 4.3 品级 Quality

品级表达同一阶级内部的优劣、稳定性、纯度、成色、完整度或成长潜力。

已确定采用 5 档：

```
Q1：下品
Q2：中品
Q3：上品
Q4：极品
Q5：绝品
```

显示为：

```
下品 / 中品 / 上品 / 极品 / 绝品
```

实现建议：

```
QualityProfile {
  quality_code       // Q1 ~ Q5
  quality_order      // 1 ~ 5
  display_key
  value_multiplier
  random_affix_budget
  instability_modifier
}
```

### 4.4 根骨、悟性、灵根等资质子项的评级

#### 已确定决策：资质不是独立系统

“资质”是玩家理解角色成长潜力时的汇总概念，不作为一个独立评级系统直接存在。

实际需要评级的是资质子项，例如：

- 根骨：偏向身体承载、修炼基础、部分突破准备。
- 悟性：偏向功法理解、配方学习、术法掌握、非战斗技艺成长。
- 灵根：偏向灵气亲和、路线适配、修炼效率与部分功法门槛。

根骨、悟性、灵根可以各自使用阶级 + 品级，也可以在 UI 上使用更贴合世界观的包装。

示例：

```
根骨：炼气阶上品
悟性：筑基阶中品
灵根：异灵根 / 双灵根 / 五行灵根等特殊包装，并映射到内部评级
```

规则口径：

- 不设计一个单独的“总资质等级”参与核心判定。
- 可以在 UI 上生成“综合评价”，但综合评价只用于提示，不作为底层规则字段。
- 根骨、悟性、灵根等子项分别影响不同系统。
- 灵根等级属于少数可不完全跟随修炼阶级显示的例外系统。

这些子项不应直接等价为“战斗力”，而应主要影响：

- 修炼效率。
- 功法理解。
- 突破准备成本。
- 配方学习与非战斗技艺成长。
- 某些路线标签的适配。
- 转世初始化权重价值。

### 4.5 功法的阶级 + 品级

功法也采用相同结构：

```
MethodRating {
  tier_code
  quality_code
  method_tags
  stage_support_range
  bottleneck_support
  learning_difficulty
  compatibility_requirements
}
```

功法价值不只看阶级，也看：

- 支持哪些阶段。
- 是否支持突破。
- 与角色天赋、道韵、资质、资源路线是否匹配。
- 是否有缺页、残本、污染、誓约、因果或宗门权限限制。

### 4.6 跨阶使用原则

高阶物品不应简单等于低阶阶段的无限碾压。建议规则：

- 低阶角色使用高阶物品，可能受限于驱动成本、识别能力、使用权限、法力不足、反噬风险或事件条件。
- 高阶物品可被储存在正式后手、宗门库存、常规宝库中，或作为突破筹码与长期目标，不必立即可用。
- 低阶高品物品可以在本阶内非常优秀，但通常不应完全替代下一阶物品。
- 高阶低品物品在跨阶跃迁时仍有价值，但可能存在瑕疵、消耗过高或不稳定。

## 5. 物品核心类型

### 5.1 MVP 核心类型

在 S9 已列物品类型基础上，本草稿按“产出与生成”视角重组为以下核心类型。

#### 1. 货币与通用资源

包括：铜钱、银两、灵石、抽象修炼资源等。

已确定口径：

- 经济循环只维护灵石这一核心通货。
- 铜钱、银两等低阶货币在角色进入一阶修行体系后基本退出主循环，只在凡人城镇、新手流程、特殊情境下使用。
- 保留灵石兑换低阶货币的入口，用于处理凡人区域消费、伪装、任务或低阶剧情需求。
- 灵石不分等级；修仙小说概念中的“中品灵石 / 上品灵石”等不作为货币等级处理，而用独立物品代替，例如“聚灵石”。
- 聚灵石等高密度灵气物品通过加工灵石、设施转化或特殊配方产出，不直接作为灵石通货的高阶面额。

特点：

- 可堆叠。
- 主要承担交易、消耗、预算和结算功能。
- 通常不生成复杂随机词条。
- 可以有来源日志和污染 / 绑定 / 宗门库存归属等状态。

#### 2. 修炼资源

用于提高修炼效率、缩短闭关周期、支持功法修行。

示例：灵米、丹药、灵液、修炼配给、宗门培养资源。

核心字段：

```
cultivation_efficiency_bonus
stage_match
purity
side_effect_risk
use_limit_context
```

#### 3. 突破资源

用于突破准备、突破方案锁定或突破事件链阶段判定。

示例：破境丹、筑基灵材、阵材、护心符、稳定心境资源、节点灵气凭证。

核心字段：

```
breakthrough_dimension_tags
risk_reduction_profile
success_quality_bonus
consumption_stage
failure_side_effect
```

#### 4. 材料 / 矿材 / 灵材

用于建设、修复、炼制、宗门库存、交易或任务提交。

来源主要来自：资源槽、自然生成、宗门开采、事件奖励、战斗战利品。

核心字段：

```
material_tags
refinement_potential
crafting_affinity
stockpile_category
```

#### 5. 功法 / 术法载体

载体是物品，内容学习后进入角色能力系统。

示例：玉简、书册、碑刻拓本、传承印记、残篇。

核心字段：

```
method_ref
carrier_integrity
copy_permission
learning_requirements
missing_sections
sect_permission
```

#### 6. 法宝

法宝是可主动投入、可被动触发、可损耗、可修复、可封存和可传承的高价值物品。

核心字段：

```
active_command_refs
passive_effect_refs
durability
charge
spirituality
repair_requirements
bind_state
```

法宝不占装备栏，但使用受资源、状态、耐久、充能、指令格和事件条件限制。

#### 7. 消耗道具

包括符箓、丹药、阵盘、一次性护符、逃遁符、疗伤药等。

核心字段：

```
use_contexts
effect_profile
variance_profile
consumed_on_use
failure_result
```

#### 8. 正式后手 / 遗产封存状态

正式后手不是独立产出物品的来源，也不是一种默认物品类型，而是显性物品的一种特殊储存、追踪与跨世回收状态。

可进入正式后手状态的对象包括：

- 灵石、丹药、材料等可堆叠资源。
- 功法 / 术法载体。
- 法宝。
- 任务线索、遗书、接引阵材料等特殊物品。

核心字段：

```
legacy_owner_spirit_ref
sealed_state
stored_item_refs
access_conditions
concealment_level
trace_log_refs
exposure_risk
```

规则口径：

- 正式后手本身不凭空产出物品。
- 正式后手只保存已经显性存在、被玩家正式封存或布置的物品及相关状态。
- 后续回收时，读取封存时的显性物品记录、世界干扰日志、暴露风险与状态变化。
- 若正式后手失效、被发现、被取走、被污染或被破坏，必须有原因链与可追查记录。

#### 9. 任务 / 权限 / 钥匙类物品

用于开启事件、证明身份、解锁地点、进入宗门权限或触发后续链。

核心字段：

```
quest_ref
access_rule
validity_window
consumption_rule
```

### 5.2 可扩展类型

暂不进入 MVP 核心，但预留生成接口：

- 契约 / 誓约载体。
- 情报 / 地图 / 线索物。
- 阵法组件。
- 宗门令牌。
- 灵兽 / 傀儡 / 伴随实体。
- 建筑核心材料。
- 污染物 / 邪物 / 因果残留。
- 市场挂牌凭证。

## 6. 物品随机性的约束与允许范围

### 6.1 随机性总原则

物品随机性用于提供世界活性、发现惊喜和复玩差异，但不能把背包、宗门库存和数值平衡变成不可控噪声。

本系统采用以下原则：

1. **来源决定大方向**：资源槽、事件、宗门行动、制造配方、战斗对象和后手记录决定产出大类。
2. **投入决定最低保障**：玩家或宗门投入越明确，核心产出越不应偏离目标。
3. **随机只影响可解释差异**：数量、品级、状态、副词条、隐藏信息、使用波动可以随机，但必须能由来源和结果等级解释。
4. **高频物品少随机，低频物品可随机**：普通材料、丹药、补给、符箓以堆叠友好为优先；法宝、秘境物、后手物、命名物可以拥有独立随机状态。
5. **随机结果必须可回收**：低 roll 结果仍应有使用、上交、出售、拆解、修复、封存或任务价值。
6. **随机配置必须数据化**：每个物品模板明确 `allowed_random_fields`、`stack_policy`、`variance_type` 和 `risk_tags`。

### 6.2 随机强度分级

建议对每个物品模板配置随机强度：

```
RandomnessLevel {
  locked      // 不随机
  low         // 只随机数量或小幅状态
  medium      // 可随机品级、状态、有限副词条
  high        // 可随机副词条、隐藏缺陷、来源异变
  unknown     // 玩家视角未知，但系统仍有明确生成规则
}
```

MVP 默认：

- 货币、普通补给、普通宗门配给：`locked / low`。
- 普通材料、普通丹药、普通符箓：`low / medium`。
- 突破资源、特殊丹药、秘境资源：`medium / high`。
- 法宝、任务物、功法载体、已封存为正式后手的物品：按实例处理，允许独立状态，但核心身份不随机。

### 6.3 可随机字段

#### 1. 数量

数量随机适合高频资源和常态产出。

规则：

- 数量随机不应改变物品性质。
- 宗门常态产出、节点采集、探索副产物优先随机数量。
- 任务关键物品不随机“是否存在”。正式后手不作为产出来源，其保存的物品来自既有显性物品记录。

#### 2. 阶级与品级

- 阶级通常由来源上下文决定，只允许小范围浮动。
- 跨阶产出必须由高风险事件、秘境窗口、重大探索、宗门重点行动、稀有配方大成功等机制解释。正式后手只保存既有显性物品，不作为跨阶产出解释。
- 品级可以由行动完成度、资源投入、制造能力、节点状态和随机波动共同决定。
- 品级随机应有最低保障，例如明确投入 A阶上品材料制造时，不应无提示地产出 A阶下品且无补偿。

#### 3. 主效果强度

同一物品模板的主效果可以在有限区间内浮动。

示例：

```
A阶中品疗伤丹：恢复生机 18 ~ 24
```

约束：

- 主效果类型不随机偏离玩家预期。
- 可堆叠物品不按每一点效果差异拆分实例，应映射到效果桶或显示代表范围。
- 关键战斗、突破效果必须在 UI 中显示大致预期。

#### 4. 副词条 / 附加标签

物品可根据预算获得额外标签。

示例：

```
purity_high
fire_affinity
sect_marked
fragile
legacy_resonant
unstable
```

约束：

- MVP 普通物品最多 1 个关键副词条或缺陷。
- 高频堆叠物品不默认生成独立副词条。
- 会影响事件判定、突破失败标签、战斗指令或后手追踪的副词条必须进入堆叠键或独立实例。
- 风味标签不应导致无法堆叠。

#### 5. 状态与成色

包括：耐久、完整度、污染、封印、缺页、磨损、充能、灵性等。

来源约束：

- 宗门库房发放：状态稳定，随机较低。
- 资源槽常态产出：数量和品级可随机，状态通常稳定。
- 秘境废墟发现：可能高价值，但完整度、污染、封印可随机。
- 战斗夺取：可能受损或无法完整回收。
- 前世后手：若正式封存，状态变化必须有日志和原因。

#### 6. 使用效果波动

主动法宝、消耗道具、部分丹药或符箓可有使用波动。

建议结构：

```
稳定效果 + 波动区间 + 特殊触发
```

不建议纯随机从强到弱完全不可控。

#### 7. 隐藏信息与封印状态

部分物品可存在未识别字段或封印字段：

```
unknown_affix
hidden_defect
true_origin
sealed_effect
curse_or_cause
```

#### 已确定决策：识别 = 解除封印 / 揭示状态

识别不作为独立职业或独立数值系统处理。它本质上是解除封印、揭示来源、看破缺陷或确认真实效果的过程。

约束：

- 不设计独立“鉴定职业”。
- 不设计独立“鉴定数值”。
- 识别主要通过事件、功法 / 技艺标签、宗门知识、使用经验、NPC 协助、解除封印或特殊道具完成。
- 隐藏信息必须能通过识别、解除封印、使用经验、宗门知识、事件链或日志逐步揭示。
- 隐藏负面不能无提示地摧毁关键事件链。
- 未识别或封印未解状态会影响堆叠与定价，但不应让普通材料大量分裂成独立物品。

### 6.4 不建议随机或必须强约束的字段

以下内容不应完全随机：

- 任务关键物品是否存在。
- 事件链必需物品的最低可用性。
- 玩家明确制造目标的核心类型。
- 宗门承诺发放的资源类型。
- 正式后手保存物的身份与追踪链。
- 已识别物品的核心描述。
- 货币与普通补给的关键属性。
- 高频普通材料的独立特殊词条。

例如：玩家投入 A阶上品灵材炼制护身符，结果可以是中品 / 上品波动，也可以有瑕疵或副词条，但不应无提示地变成完全不相关的攻击符。

### 6.5 随机结果的负体验检查

每个随机产出结果都应通过以下检查：

```
1. 玩家是否能理解为什么会得到这个结果？
2. 结果是否与投入方向大体一致？
3. 即使低 roll，是否仍有使用、出售、上交、拆解、修复或封存价值？
4. 如果有隐藏负面，是否存在揭示路径？
5. 如果随机导致失败，是否有日志和可复盘原因？
6. 是否会破坏关键事件链或造成无理由卡死？
7. 是否因为微小差异制造了大量不可堆叠物品？
```

若任一问题答案为否，应降低随机强度、改为随机桶、增加兜底或改成独立高价值实例。

## 7. 随机性与堆叠规则

### 7.1 补充目的

物品随机性必须考虑道具堆叠。否则会出现两个负体验：

- 每个轻量道具都因随机字段不同而变成独立实例，背包与宗门库存过度膨胀。
- 为了方便堆叠而完全取消随机差异，导致材料、丹药、符箓等物品失去产出惊喜。

推荐采用：

```
堆叠键 StackKey + 实例组 ItemStack + 少量独立实例 ItemInstance
```

核心原则：**高频、同质、低叙事价值的物品优先堆叠；低频、高价值、带状态、独立功能或叙事身份的物品独立成实例。**

### 7.2 堆叠设计目标

物品堆叠需要同时满足：

1. 降低背包、宗门库存与存档体积压力。
2. 保留物品随机性带来的发现感和价值差异。
3. 避免玩家被大量“几乎一样但不能合并”的道具干扰。
4. 支持宗门库存、节点库存、角色背包、市场列表、后手封存等不同资产位置。
5. 不重新引入重量、格子、负重等 MVP 已排除的背包管理玩法。

### 7.3 物品分层：可堆叠 / 独立实例

不再设置“半可堆叠”物品层。MVP 只保留两类：

```
stackable       // 可堆叠
unique_instance // 独立实例
```

#### 1. 可堆叠物品

适用对象：数量频繁、单个差异不重要、无独立历史意义的物品。

典型类型：

- 灵石、铜钱、银两等货币。
- 干粮、普通补给。
- 普通矿材、灵材、药材。
- 普通丹药。
- 普通符箓。
- 抽象修炼资源。
- 宗门库存中的常规资源。

规则：

```
只要 StackKey 相同，就合并为一个 ItemStack。
```

可堆叠物品的随机差异必须被压缩到有限桶或批次摘要中，不因为微小数值差异拆分独立实例。

#### 2. 独立实例物品

适用对象：具备独立身份、耐久、充能、灵性、绑定、封印、后手追踪、特殊功能或叙事历史的物品。

典型类型：

- 法宝。
- 功法 / 术法载体。
- 任务关键物品。
- 正式后手中需要逐件追踪的封存物。
- 带独立缺陷、污染、诅咒、因果、真名痕迹的物品。
- 已在战斗中受损并需要单独追踪状态的道具。
- 稀有秘境产物或命名物品。

规则：

```
只作为 ItemInstance 存在，不进入普通堆叠。
```

### 7.4 StackKey：堆叠键

堆叠键决定哪些物品可以合并。

建议结构：

```
StackKey {
  prototype_id
  tier_code
  quality_code
  stack_grade_bucket
  condition_bucket
  recognition_or_seal_state
  bind_state
  special_stack_tags
}
```

字段说明：

- `prototype_id`：物品模板必须相同。
- `tier_code`：阶级必须相同。
- `quality_code`：品级必须相同。
- `stack_grade_bucket`：用于合并近似随机值，例如纯度、药性、效果波动等归入有限桶。
- `condition_bucket`：完整、轻微受损、严重受损等状态桶。
- `recognition_or_seal_state`：已识别 / 未识别、封印已解 / 封印未解不直接合并。
- `bind_state`：绑定、宗门标记、个人标记等不同不合并。
- `special_stack_tags`：影响使用、突破、事件的关键标签必须一致。

### 7.5 来源字段简化

“来源 / 产地 / 历史来源”不作为所有物品的通用堆叠字段。

规则口径：

- 普通材料、普通丹药、普通符箓、普通补给不记录可影响堆叠的来源参数。
- 普通物品只通过日志记录获得来源，不把来源写入 StackKey。
- 只有少数需要表达来历、传承、因果、归属或特殊历史的物品，才启用来源字段。
- 典型适用对象：法宝、功法载体、命名秘宝、宗门信物、正式后手封存物、任务关键物。

建议字段：

```
OptionalOriginProfile {
  origin_type          // sect / legacy / secret_realm / npc / crafted / unknown
  origin_ref
  origin_tags
  visible_origin_state // hidden / rumored / known / verified
}
```

该字段只在物品模板声明 `uses_origin_profile = true` 时启用。

### 7.6 随机字段与堆叠的关系

#### 1. 不影响堆叠的随机字段

这些字段可以在堆叠内用平均值、范围、桶或批次摘要表达：

- 普通数量随机。
- 小幅效果波动。
- 普通成色小波动。
- 不影响事件判定的风味标签。

示例：

```
A阶中品疗伤丹 × 12
效果范围：恢复生机 18~24
批次纯度：中等
```

#### 2. 影响堆叠的随机字段

这些字段会改变 StackKey 或直接生成独立实例：

- 阶级。
- 品级。
- 关键副词条。
- 明确缺陷。
- 污染 / 诅咒 / 因果。
- 绑定状态。
- 是否已识别，或封印是否已解除。
- 是否处于正式后手封存 / 追踪状态。
- 是否影响突破失败标签。
- 是否影响战斗指令或被动效果。

#### 3. 推荐做法：随机桶而不是逐点分裂

不建议每一点纯度、每一点数值波动都拆成独立物品。

建议将连续随机值映射为有限桶：

```
purity_bucket_low      // 低纯度
purity_bucket_normal   // 标准纯度
purity_bucket_high     // 高纯度
purity_bucket_flawless // 极高纯度
```

这样既保留差异，又不会生成大量不可堆叠碎片。

### 7.7 ItemStack 数据结构

```
ItemStack {
  stack_id
  stack_key
  quantity
  prototype_id
  tier_code
  quality_code
  stack_summary
  representative_effect_profile
  value_per_unit
  total_value
  location_ref
  owner_ref
  acquisition_summary
  stack_logs
}
```

堆叠物品只追踪必要摘要，不追踪每个单体的完整历史。

如果某个堆叠内物品被特殊使用并产生独立状态，例如战斗中某张符箓未完全消耗但被污染，则可以从堆叠中拆出独立实例：

```
ItemStack.quantity - 1
→ create ItemInstance with special_state
```

### 7.8 UI 表达建议

背包默认展示：

```
名称｜阶级｜品级｜数量｜用途标签｜状态摘要
```

示例：

```
A阶中品疗伤丹 × 12｜恢复生机｜可战斗使用｜可突破前准备
A阶上品赤纹符 × 3｜攻击符箓｜效果波动：稳定
B阶下品玄铁矿 × 26｜材料｜宗门建设 / 法宝修复
```

高价值独立物品单列：

```
裂纹护心玉｜A阶极品｜被动法宝｜耐久 42%｜前世后手关联
```

### 7.9 与定价模型的关系

堆叠物品使用单位价值和总价值：

```
stack_total_value = value_per_unit × quantity
```

独立实例继续使用完整价值模型：

```
V_std = B_category × T_tier × Q_quality × E_effect × S_scarcity × C_condition × U_utility
```

如果堆叠内存在效果范围，`value_per_unit` 使用该桶的代表值，而不是为每个单体保存独立价值。

### 7.10 推荐结论

MVP 推荐采用：

1. 货币、补给、普通材料、普通丹药、普通符箓：默认可堆叠。
2. 法宝、功法载体、任务物、正式后手封存物、带独立状态或叙事身份的物品：独立实例。
3. 不设置半可堆叠层。
4. 随机字段不逐点拆分，优先映射为有限桶。
5. 来源 / 产地 / 历史来源不是通用物品参数，只在法宝等少数物品模板中启用。
6. 背包不引入格子限制，但 UI 必须避免大量相近物品刷屏。
7. 堆叠只解决信息组织和存档结构，不作为背包容量玩法。

## 8. 物品生成来源的三层结构

### 8.1 三类生成 / 转化来源

物品来源不能全部使用同一种“随机生成”逻辑。应区分三类：

```
1. 配方制生产：明确资源 → 明确物品
2. 自然资源转化：资源点资源池 → 采集 / 加工 → 资源或材料物品
3. 世界凭空生成：宝藏 / 事件 / NPC / 市场隐性库存 → 实例化物品
```

三者共享价值模型、堆叠规则、日志规则与显隐状态规则，但不共享完全相同的生成约束。

### 8.2 配方制生产

适用对象：玩家角色、宗门、NPC 工坊等拥有明确资源账户的主体。

规则口径：

- 各个宗门，无论是否有玩家角色加入，其库存、资源、人力、设施和行动结果都应明确可计算。
- 玩家角色的背包、资源、已知存储和可调用后手也应明确可计算。
- 因此，宗门或角色主动生成物品时，优先走配方制。
- 配方制必须消耗明确资源，产出明确目标物品。
- 随机只允许发生在配方定义的范围内，例如品级浮动、数量副产、成色桶、副词条、缺陷、失败返还比例。
- 配方制不应凭空创造远超输入约束的价值；若产出价值明显高于输入价值，必须由配方等级、设施、技能、时间、风险或稀有催化资源解释。

### 8.3 自然资源转化

适用对象：S8 资源槽、灵脉、矿脉、药田、荒野资源、秘境环境资源等。

规则口径：

- 自然资源一般不直接生成具体物品，而是生成资源点自身的资源池、资源量、丰度、再生状态或可采额度。
- 资源点通过再生、创建、枯竭、破坏、污染、迁移等规则维护自己的资源上限。
- 自然资源不消耗世界物品预算帽。
- 宗门已控制资源点时，基础采集、加工、药田收成、矿场出矿等属于宗门经营常态结算或持续项目，原则上不占用每季度 1 个宗门主行动。
- 玩家角色可通过持续行动进行类似的采集、加工或收集。
- 当资源需要进入库存、建设、炼制、修复、交易或任务时，才转化为抽象宗门资源、资源堆叠或材料物品。

### 8.4 世界凭空生成

适用对象：宝藏、随机事件奖励、NPC 掉落、NPC 交易库存、秘境宝物、隐藏房间、世界刷新事件等。

规则口径：

- 这些来源的核心特点是：物品不是由某个已显性库存消耗资源生产，而是在事件、NPC、宝藏或交易场景中实例化。
- 每类玩法仍有局部约束：事件难度、节点危险等级、NPC 身份、秘境阶级、区域资源倾向、宗门控制状态、剧情线与风险选择都会限制物品生成范围。
- 但从整个服务器视角看，这类物品属于世界向显性流通层注入新物品，必须受全局分阶物品预算帽约束。
- 正式后手不属于世界凭空生成来源，只是显性物品的储存、封存与跨世追踪状态。
- 预算帽在物品被宗门或玩家角色实际获得时扣除，而不是在隐性候选物品生成时扣除。

### 8.5 统一点：回写结果，而不是统一生成逻辑

原先的“所有来源共用同一生成请求”需要修正为：

```
不同来源使用不同生成 / 转化请求；
最终统一输出为库存变化、物品堆叠、物品实例、日志与价值记录。
```

建议统一结果结构：

```
ItemAcquisitionResult {
  success
  source_mode              // recipe / natural_resource / world_generation / transfer / implicit_instantiation / recycling
  item_stacks
  item_instances
  abstract_resource_delta
  currency_delta
  consumed_inputs
  budget_cost
  recycled_value
  failed_reason
  revealed_info
  hidden_info_refs
  ledger_entries
  visible_log_entries
  hidden_world_log_entries
}
```

## 9. 配方系统与投入产出规则

### 9.1 配方定位

配方是“明确投入 → 明确产出”的生产规则，不是随机掉落表。

它服务于：

- 丹药、符箓、阵盘、法宝修复、材料加工、功法拓印、灵材精炼、建筑构件等物品生产。
- 宗门常态经营中的资源加工。
- 玩家角色的非战斗成长路线。
- NPC 工坊、坊市服务、宗门传承与特殊事件制造。

### 9.2 配方与非战斗类功法的关系

初步推荐：配方可以作为非战斗类功法 / 技艺体系的衍生物，也可以独立学习。

来源包括：

- 学习丹道、器道、符道、阵道、灵植、识别 / 解封、修复、加工等非战斗类功法后解锁。
- NPC 传授。
- 使用物品学习，例如玉简、手札、残方、传承印记。
- 宗门职位、藏经阁权限、任务奖励、秘境发现、前世后手回收。

配方不等于功法本身：

- 功法 / 技艺提供理解、效率、品质上限、失败控制、改造能力。
- 配方提供具体产出规则。
- 一个技艺体系可解锁多个配方。
- 一个配方也可能被多个技艺标签修正。

### 9.5 配方随机边界

配方制允许随机，但必须服从以下边界：

- 核心产物类型由配方决定，不由随机决定。
- 投入资源满足最低条件时，至少产生可用结果或明确失败返还。
- 随机主要影响品级、数量副产、状态桶、成色桶、副词条、失败副作用、返还比例。
- 高阶配方可以有更大波动，但必须提前展示风险。
- 批量生产优先生成 ItemStack，不为每个单体创建独立实例。

配方可以具备独立养成玩法。

```
  byproduct_chance_bonus
  failure_recovery_bonus
  modification_unlocks
}
```

升级效果可以包括：

- 降低输入损耗。
- 提高最低品级。
- 缩小随机波动。
- 提高批量生产数量。
- 提高副产物概率。
- 降低失败损失。
- 解锁替代材料。
- 解锁配方改造槽。

### 9.7 配方改造

配方改造是高级玩法，不建议 MVP 完整展开，但应保留接口。

改造方向：

- 替换核心材料。
- 改变副词条倾向。
- 降低副作用。
- 提高批量产出。
- 增加特定用途标签，例如突破、战斗、修复、封存。
- 将稳定配方改造成高风险高收益配方。

改造风险：

- 配方不稳定。
- 产出质量波动增大。
- 材料损耗上升。
- 产生污染、因果或隐藏缺陷。
- 宗门传承配方可能受到权限或誓约限制。

## 10. 自然资源、资源点与加工转化

### 10.1 自然资源点不直接等价于物品产出点

自然资源点首先管理的是资源状态，而不是背包物品。

建议结构：

```
NaturalResourcePool {
  resource_pool_id
  node_ref
  resource_type
  tier_code
  abundance_state
  current_amount
  max_amount
  regeneration_rate
  extraction_difficulty
  depletion_risk
  pollution_state
  discovery_state
  controlling_faction_bonus
}
```

### 10.2 资源点自己的上限

自然资源不走世界物品预算帽，而由资源点自己的上限约束：

- `max_amount`：资源池上限。
- `regeneration_rate`：再生速度。
- `depletion_risk`：过度采集或事件导致衰退概率。
- `pollution_state`：污染、枯竭、妖兽盘踞、阵法破坏等状态。
- `creation / destruction`：事件、宗门建设、秘境变化可创建或销毁资源点。

### 10.3 宗门经营转化

宗门已控制资源点后，以下行为通常属于宗门经营常态结算或持续项目，不占用每季度 1 个宗门主行动：

- 采矿。
- 药田收成。
- 灵脉基础抽取。
- 初级材料加工。
- 已建成设施的稳定产出。

但以下行为仍可占用宗门主行动或触发事件链：

- 新资源点开采。
- 深层开采。
- 过度开采。
- 资源异变处理。
- 抢占 / 恢复资源点。
- 修复损坏设施。
- 建设高级加工设施。
- 尝试产出特殊物品或高阶材料。

### 10.4 玩家持续行动转化

玩家角色可通过持续行动进行资源采集、加工或转化。

示例：

```
在荒野节点持续采药
→ 消耗行动格与补给
→ 从资源池中抽取资源量
→ 根据角色技艺、工具、风险与事件结果转化为药材 ItemStack
```

玩家持续行动应与宗门经营使用同一资源点状态，避免同一资源被重复结算。

### 10.5 加工转化规则

资源点产出的资源进入库存前可通过两类方式转化：

1. **简单加工规则**：低成本、低随机，适用于普通材料。
2. **配方生产规则**：高控制、高投入，可产出特定物品、特殊材料或更高品级结果。

## 11. 世界生成物品与分阶预算帽

### 11.1 世界生成物品的定义

世界生成物品指不由显性资源账户或配方投入直接生产，而是在世界内容中被实例化的物品。

典型来源：

- 宝藏。
- 秘境宝物。
- 节点事件奖励。
- 世界事件奖励。
- NPC 掉落。
- NPC 交易库存。
- 隐藏房间或遗迹。
- 非正式前世遗产的随机化部分。

这些物品的局部生成范围由玩法决定，但全服注入量由分阶预算帽约束。

### 11.2 预算帽的设计目标

预算帽用于控制整个服务器的高价值物品注入速度。

它解决的问题：

- 世界时间不断推进，事件与宝藏会持续刷新。
- 如果所有世界生成物品都无限凭空出现，显性物品总量会失控。
- 多人房间中，不同玩家和宗门会同时推动世界生成，需要全局约束。
- 高阶物品不应在玩家尚未进入对应阶段时大量积累。

### 11.3 分阶预算结构

预算帽按阶级独立维护。

```
WorldItemBudgetTier {
  tier_code
  accumulated_value
  max_accumulated_value
  generation_rate_by_reach_state
  last_update_quarter
}
```

`generation_rate_by_reach_state` 按三档配置：

```
none_reached_rate     // 无玩家达到该阶级
some_reached_rate     // 至少一名玩家达到，但不是全部
all_reached_rate      // 全部当前有效玩家都达到
```

这里的“达到”建议按玩家当前世或历史最高境界是否达到该阶级判断，具体口径后续由 S2 / 平衡文档定。

### 11.4 预算累积公式

每次季度推进时，按配置累积：

```
reach_state = get_reach_state(tier_code)
rate = generation_rate_table[tier_code][reach_state]
accumulated_value = min(
  max_accumulated_value[tier_code],
  accumulated_value + elapsed_quarters × rate
)
```

`max_accumulated_value` 同样配表设定，防止长期挂机、长时间不探索或服务器暂停后恢复造成无限累加。

### 11.5 预算消耗时机

预算不在隐性候选物品生成时消耗，而在物品进入玩家角色或宗门显性库存时消耗。

消耗条件：

```
世界生成候选物品
→ 被玩家角色获得，或被宗门获得
→ 计算物品预算价值
→ 扣除对应阶级 accumulated_value
→ 进入显性库存 / 宝库 / 后手 / 宗门库存
```

若预算不足，可按玩法选择：

- 降低品级。
- 降低阶级。
- 替换为资源、线索或低阶副产物。
- 生成“发现但暂不可取得”的事件状态。
- 延迟刷新。
- 触发竞争或守护事件，要求额外投入。

### 11.6 预算价值

预算消耗使用物品完整价值模型计算，但不使用通胀后的通货价格。

```
BudgetCost = V_world_budget
```

其中：

```
V_world_budget = V_std × D_random × D_origin × D_information
```

已确定口径：

- 世界生成预算帽按照物品完整价值扣除。
- 不按稀有度、来源或折扣系数另行折算。
- 不乘通胀系数。
- 不受市场买卖价影响。
- 用于扣除对应阶级世界生成预算。
- 如果一个物品跨阶使用，预算仍按物品自身阶级扣除。

### 11.7 不消耗预算帽的来源

以下来源不消耗世界生成物品预算帽：

- 自然资源点再生出的资源量。
- 资源点通过常态加工转化出的基础资源。
- 玩家或宗门使用配方、显性资源、设施、时间生产出的物品。
- 显性库存之间的转移。
- 正式后手中已显性记录过的物品回收或重新进入角色 / 宗门库存。

但这些来源仍然受各自资源账户、资源点上限、配方、设施、时间与日志约束。

## 12. 显性 / 隐性物品状态与回收

### 12.1 显性物品

显性物品是已经进入可追踪流通层的物品。

包括：

- 玩家角色库存。
- 宗门库存。
- 角色正式后手设置中的已封存显性物品。
- 常规宝库设置。
- 已放入节点存储、市场挂牌、任务提交池或事件锁定状态的物品。

显性物品必须有明确位置、所有权、状态和日志。

### 12.2 隐性物品

隐性物品是不完整实例化或仅作为潜在内容存在的物品。

包括：

- 未进入战斗前的普通 NPC 随身物。
- 未打开宝箱中的随机宝物候选。
- NPC 交易中的潜在库存。
- 事件奖励池中的候选物。
- 世界传闻中尚未被确认的宝物。
- 非正式遗产中的可变部分。

隐性物品在需要时才实例化。

示例：

```
玩家与 NPC 进入战斗
→ 系统根据 NPC 模板、境界、身份、事件难度实例化法宝 / 符箓 / 丹药
→ 这些物品影响战斗
→ 战斗后若被玩家或宗门获得，则进入显性库存并扣世界预算
→ 若未被获得，可回收为隐性或消失
```

### 12.3 显性转隐性：物品回收

当物品从显性状态转为隐性状态、被销毁、被消耗、被拆解、被转化或脱离可追踪流通层时，视为发生物品回收。

典型场景：

- 常规宝库被 NPC 发现并取走。
- 物品被消耗。
- 物品被拆解为材料。
- 物品被宗门熔炼、修复消耗或转化为设施维护资源。
- 物品被市场、坊市、NPC 网络吸收，不再逐件追踪。
- 事件中物品破碎、污染、献祭、封印或转化。

世界生成物品被回收、销毁或流出显性层后，不返还世界生成预算。

规则口径：

- 普通消耗和销毁不返还世界物品预算。
- 拆解、熔炼、回收可返还部分显性资源或材料，但不返还世界预算帽。
- 用于经济调节的货币回收应影响通胀系数。
- 正式后手被破坏或转移必须保留原因链和追查日志。

### 12.4 常规宝库与正式后手的区别

常规宝库是显性物品存储，但不享受正式后手的强保护。

- 常规宝库可以被 NPC、宗门、事件、灾害发现或取走。
- 若被取走，物品从玩家可控显性状态脱离，可进入 NPC 隐性网络、宗门库存、市场流通或世界事件线。
- 玩家可能通过日志、线索或传闻追查。

正式后手则必须进入轮回账本或后手追踪系统，不能无理由失效。

## 13. 通货、内部流通与通胀系数

### 13.1 设计问题

世界资源与物品产出本质上随时间增长。

如果没有足够回收机制，灵石等通货会逐渐溢出，导致：

- 玩家与宗门库存膨胀。
- 交易价格失去意义。
- 宗门发放、任务奖励、坊市购买失去压力。
- 中后期经济系统快速崩溃。

因此需要通胀系数来放大流通与回收系统在中后期的作用。

### 13.2 内部流通与真实回收

内部流通不会减少全世界显性通货总量。

内部流通包括：

- 宗门向玩家发放俸禄。
- 宗门任务奖励。
- 玩家向宗门上交资源换取贡献或权限。
- 玩家从宗门购买或申请资源。
- 玩家与宗门之间的交易。
- 显性 NPC、坊市、宗门库存之间的转移。

真实回收才减少显性通货或显性物品总量。

真实回收包括：

- 灵石以基础灵气形式直接消耗。
- 阵法、突破、修炼、设施维护中的资源消耗。
- 制造失败损耗。
- 修复、拆解、熔炼、献祭、净化、封印、传送、税费、手续费。
- 物品被事件销毁、污染、失效或转化。

### 13.3 通胀系数公式

已确定：只维护灵石通货的通胀系数。

```
InflationCoeff_spirit_stone = clamp(
  explicit_spirit_stone_total / reference_spirit_stone_value,
  min_inflation_coeff,
  max_inflation_coeff
)
```

其中：

- `explicit_spirit_stone_total` 只统计显性流通层中的灵石，包括玩家、宗门、市场、宝库等可追踪库存。
- `reference_spirit_stone_value` 由世界阶段、玩家最高阶级、宗门规模、房间人数、季度数等配置决定。
- 当灵石总量接近参考值时，`InflationCoeff_spirit_stone ≈ 1`，物品通货价格约等于模板价值。
- 当显性灵石总量远超参考值时，价格、费用与回收消耗上升。

低阶货币不维护长期经济循环：

- 铜钱、银两等低阶货币只用于凡人区域、新手阶段和特殊情境。
- 不为低阶货币单独维护通胀系数。
- 保留灵石兑换低阶货币入口。

### 13.4 价格与回收受通胀影响

模板价值不受通胀影响；通货价格受通胀影响。

```
CurrencyPrice = V_trade × InflationCoeff × market_spread × relation_modifier × liquidity_modifier
```

通胀系数影响以灵石计价的经济性价格和回收成本，包括交易、手续费、维护、制造、修复、传送、税费等。

但灵石不能直接覆盖所有灵气用途：

- 灵石是基础通货，只支持基础灵气消耗与低中阶通用需求。
- 后续高阶需求不直接用普通灵石无限满足。
- 高阶需求需要通过加工灵石获得独立物品，例如聚灵石、凝灵石、阵基灵核等。
- 这些加工物品不作为灵石的高阶面额，而是独立物品，可有阶级、品级、配方、加工设施要求和用途标签。

设计目的：

- 普通灵石通胀不应无损传导到顶级修炼、突破、阵法和高阶设施需求。
- “灵石 → 聚灵石等高密度灵气物品”的加工链构成经济阀门。
- 加工设施的工作效率、配方、时间、人力与损耗决定通胀向高阶需求传递的效率。
- 这会放大中后期加工设施、宗门财政、资源回收和生产组织的重要性。

### 13.5 通胀系数的设计边界

通胀系数不是完美经济模拟，而是平衡阀。

约束：

- 只维护灵石通货，不维护铜钱、银两等低阶货币的长期经济循环。
- 不直接改变物品的规则强度。
- 不影响世界物品预算帽消耗值。
- 不影响自然资源点再生。
- 不应在新手阶段造成明显经济压力。
- 应平滑变化，避免某季度价格剧烈跳变。
- 调试界面应能查看显性灵石总量、参考值和当前系数。

### 13.6 灵石加工阀门

为了避免普通灵石通胀直接吞没高阶需求，灵石可以被加工为独立物品。

```
SpiritStoneProcessing {
  input_spirit_stone
  facility_ref
  recipe_ref
  time_cost
  manpower_or_actor_cost
  loss_rate
  output_item              // 聚灵石 / 凝灵石 / 阵基灵核等
  output_tier
  output_quality
}
```

规则口径：

- 灵石不分等级。
- 聚灵石等高密度灵气载体是独立物品，不是货币面额。
- 聚灵石可以作为修炼、突破、阵法、设施维护、高阶法宝驱动等需求输入。
- 聚灵石的产出受配方、设施效率、时间、人力、损耗和通胀影响。
- 加工设施效率决定普通灵石向高阶需求传递的速度上限。

## 14. 物品获得来源矩阵

| 来源 | 来源模式 | 主要玩家体验 | 典型产出 | 是否消耗预算帽 | MVP 优先级 |

## 15. 定价、价值与预算模型

### 15.1 定价目标

定价不是只用于商店买卖，而是用于：

- 配方投入产出平衡。
- 世界生成预算帽消耗。
- 宗门库存估值。
- 事件奖励强度控制。
- 掉落与秘境收益控制。
- 制造输入输出平衡。
- 拆解、修复、上交、封存的参考价值。
- 通货价格与通胀调节。

### 15.2 标准价值公式

建议每个物品先计算标准价值：

```
V_std = B_category × T_tier × Q_quality × E_effect × S_scarcity × C_condition × U_utility
```

字段含义：

```
B_category：物品类型基础价值
T_tier：阶级倍率
Q_quality：品级倍率
E_effect：效果预算倍率
S_scarcity：稀缺度倍率
C_condition：状态 / 耐久 / 完整度倍率
U_utility：用途覆盖倍率
```

### 15.3 阶级倍率

阶级倍率必须体现大境界跃迁。

建议形式：

```
T_tier = R_tier ^ (tier_order - 1)
```

其中 `R_tier` 是跨阶倍率。MVP 暂不定最终值，建议测试区间：

```
R_tier = 8 ~ 20
```

含义：B阶物品的基准价值大约是 A阶物品的 8~20 倍，具体取决于资源曲线与突破消耗。

### 15.4 品级倍率

MVP 可先用一组保守倍率：

```
Q1 下品：0.70
Q2 中品：0.90
Q3 上品：1.15
Q4 极品：1.45
Q5 绝品：1.90
```

这组数值只是平衡起点，不是定稿。

设计理由：

- 同阶品级有明显价值差异。
- 品级差异不应超过跨阶差异。
- 极品 / 绝品能带来追求感，但不应让 A阶绝品完全替代 B阶普通物品。

### 15.5 效果预算倍率

不同物品的效果价值不同。建议使用效果预算统一折算：

```
E_effect = 1 + Σ(effect_weight_i × effect_strength_i)
```

效果权重示例：

| 效果方向 | 价值权重倾向 |
| --- | --- |
| 提高修炼效率 | 高 |
| 降低突破失败风险 | 很高 |
| 提供战斗主动指令 | 中~高 |
| 提供被动保命 | 高 |
| 提供一次性恢复 | 中 |
| 提供节点探索加成 | 中 |
| 提供宗门行动加成 | 中~高 |
| 仅风味或日志效果 | 低 |

### 15.6 状态倍率

物品状态影响可用价值：

```
C_condition = durability_factor × integrity_factor × charge_factor × pollution_factor
```

示例：

```
耐久完整：1.00
轻微受损：0.80
严重受损：0.45
破碎但可修复：0.20
污染且未净化：0.30 ~ 0.70
```

对于法宝，状态不只影响售价，还影响：

- 可用指令是否可用。
- 被动触发是否稳定。
- 破碎风险。
- 修复成本。
- 是否适合封存为后手。

### 15.7 用途覆盖倍率

用途越多，价值越高。

```
U_utility = 1 + utility_bonus - restriction_penalty
```

用途包括：

- 可战斗使用。
- 可突破使用。
- 可修炼使用。
- 可宗门上交。
- 可制造 / 修复。
- 可拆解。
- 可封存。
- 可任务提交。

限制包括：

- 绑定角色。
- 宗门权限限制。
- 使用阶段限制。
- 地点限制。
- 一次性消耗。
- 副作用或因果风险。

### 15.8 随机偏差

物品最终价值允许围绕标准价值偏移：

```
V_final = V_std × D_random × D_optional_origin × D_information
```

其中：

```
D_random：随机成色偏差
D_optional_origin：可选来源 / 传承 / 历史修正，默认 1，仅在物品模板启用来源字段时生效
D_information：未识别、封印未解、信息不完整、风险不明导致的折价
```

建议 MVP 偏差范围：

```
普通配方产出：0.85 ~ 1.15
探索 / 秘境：0.65 ~ 1.60
战斗夺取：0.50 ~ 1.30
正式后手封存物：身份来自既有显性物品记录，不重新生成；状态变化按日志修正
```

### 15.9 世界预算价值

世界生成预算帽使用世界预算价值，不使用通货价格。

```
V_world_budget = V_final
```

约束：

- 不乘通胀系数。
- 不受市场买卖价影响。
- 用于扣除对应阶级世界生成预算。
- 如果一个物品跨阶使用，预算仍按物品自身阶级扣除。

### 15.10 交易价格与标准价值分离

标准价值不等于交易价格。

```
BuyPrice  = V_final × InflationCoeff × market_buy_spread × relation_modifier × scarcity_modifier
SellPrice = V_final × InflationCoeff × market_sell_spread × relation_modifier × liquidity_modifier
```

MVP 可不开放完整市场，但保留字段，避免后续重构。

### 15.11 突破资源的特殊估值

突破资源的价值不只看直接数值，而要看它降低失败风险或提高成功质量的能力。

建议估值：

```
V_breakthrough = V_std × (1 + risk_reduction_value + success_quality_value + stage_specificity_value)
```

其中：

- 风险降低越稀有，价值越高。
- 只服务某一突破阶段的资源，泛用性低但关键性高。
- 能覆盖高痛感失败标签的资源应显著提价。

### 15.12 配方价值守恒参考

配方产出不消耗世界预算帽，但必须受投入约束。

建议用以下校验：

```
OutputValueExpected ≤ InputValue × recipe_efficiency × skill_modifier × facility_modifier × risk_modifier
```

如果配方允许长期稳定产出高于投入的价值，必须由以下因素限制：

- 稀有配方。
- 稀有设施。
- 高阶非战斗功法。
- 长时间成本。
- 高失败风险。
- 关键材料稀缺。
- 宗门权限或地域限制。

## 16. 随机使用效果模型

部分物品的使用效果允许随机，尤其是主动法宝、符箓、丹药、秘境所得的不稳定道具。

### 16.1 使用效果结构

```
UseEffectProfile {
  expected_effect
  min_effect
  max_effect
  variance_type
  risk_tags
  failure_modes
  preview_policy
}
```

### 16.2 推荐随机方式

优先使用有限波动：

```
实际效果 = 期望效果 × (1 + 随机偏移)
```

不推荐在 MVP 中大量使用：

```
完全随机效果池
```

除非物品本身明确标记为混沌、邪物、残缺、未识别、封印未解或高风险。

### 16.3 玩家可见预期

使用前 UI 至少应展示：

- 大致效果方向。
- 主要目标条或系统。
- 是否消耗物品。
- 是否有反噬或失败风险。
- 随机范围是稳定、波动、危险还是未知。

示例：

```
护心符｜A阶中品
效果：本场战斗中首次受到神念伤害时自动抵消一部分。
风险：抵消后大概率破裂，小概率完全损毁。
```

### 16.4 使用随机与堆叠

堆叠道具使用时，不为堆叠内每个单体预先保存独立随机结果。

推荐流程：

```
从 ItemStack 消耗 1 个单位
→ 按 stack_key 与 representative_effect_profile 生成本次使用结果
→ 若产生特殊状态且未消耗，则拆出 ItemInstance
```

## 17. 日志、可见性与追踪

每个重要物品都应有来源日志。

```
ItemLogEntry {
  quarter
  source_type
  source_ref
  actor_ref
  location_ref
  item_delta
  state_change
  visibility_state          // explicit / implicit / recycled / destroyed
  budget_cost
  inflation_context
  visible_summary
  hidden_world_log
}
```

日志分层：

- 角色日志：玩家自己获得、使用、损坏、封存的物品。
- 宗门库存日志：宗门资源增减、发放、预留、消耗。
- 世界日志：完整系统记录，用于测试与回放，默认玩家不可见。
- 传闻：世界日志的可见子集，可能提及秘境宝物、资源枯竭、宗门争夺等。
- 轮回账本：正式后手、重大遗产、突破关键资源、死亡 / 转世相关物品。

### 17.1 显性物品的日志要求

显性物品必须记录：

- 来源。
- 位置。
- 所有者或控制者。
- 状态变化。
- 进入显性流通的时间。
- 消耗、拆解、转移、回收或封存原因。

### 17.2 隐性物品的日志要求

隐性物品不要求逐件记录完整状态，但需要记录实例化原因：

- 哪个事件或 NPC 触发实例化。
- 依据哪个物品池、预算帽和局部约束实例化。
- 是否被玩家或宗门获得。
- 若获得，扣除了多少预算值。
- 若未获得，是否回收为隐性或销毁。

### 17.3 正式后手日志要求

正式后手中的物品必须保留强追踪：

- 封存时的显性状态。
- 封存位置与条件。
- 被发现、污染、移动、破坏、取走的原因链。
- 玩家可追查线索。
- 轮回账本摘要。

## 18. 与其他系统接口

### 18.1 与 S2 玩家角色 / 真灵 / 轮回

- 根骨、悟性、灵根等资质子项可采用阶级 + 品级，或使用特殊显示包装并映射到底层评级。
- 资质本身是汇总概念，不作为独立系统字段参与核心判定。
- 物品可进入当世角色背包、已知存储、封存后手或轮回账本。
- 已掌握功法与功法载体分离。
- 正式后手物品必须保留追踪、原因链与日志。
- 角色学习配方可通过非战斗功法、NPC 传授或物品载体完成。
- 识别物品等价于解除封印或揭示状态，不需要鉴定职业和独立鉴定数值。

### 18.2 与 S3 行动经济

- 玩家通过探索、采集、制造、交易、回收、移动事件等获得物品。
- 玩家采集、加工、炼制、修复可作为持续行动或事件化行动。
- 部分物品获得需要消耗行动格或中断原计划。
- 移动事件可消耗补给或产生遭遇奖励。

### 18.3 与 S4 突破

- 突破资源、法宝辅助、地点资源、宗门支持物均由本系统提供具体物品或抽象资源实例。
- S4 只读取物品提供的突破维度支持，不定义物品自身规则。
- 突破失败可损毁、污染或消耗物品，并写入失败原因。
- 突破相关物品的价格、回收、修复和替代方案可受通胀与库存状态影响。

### 18.4 与 S5 宗门组织 / 权限

- 配方传承、宗门工坊、资源申请、宝库调用、配给发放需要读取宗门身份和权限。
- 宗门配方可能受职位、贡献、声望、誓约或藏经阁权限限制。

### 18.5 与 S6 宗门库存

- 宗门库存可保存抽象资源，也可保存具体 ItemStack / ItemInstance。
- 宗门发放物品必须真实扣除库存或生成预留记录。
- 宗门资源不足时，发放、突破支持、配方生产或行动预算应失败、降级或延迟。
- 宗门内部流通不减少全世界显性通货总量；只有真实消耗或回收才减少。

### 18.6 与 S7 宗门行动

- 每季度 1 个宗门主行动不应被普通采集、普通加工、稳定药田产出挤占。
- 稳定资源点的采集 / 加工走常态经营结算或持续项目。
- 重点开采、深层探索、建设高级工坊、资源异变处理、特殊炼制可占用宗门主行动。
- 宗门行动完成度可影响资源转化效率、配方生产质量和特殊副产物概率。

### 18.7 与 S8 地图节点

- 节点资源槽维护自然资源池，不直接等价于物品掉落表。
- 建筑槽可改变采集效率、加工能力、配方可用性、品质上限或储存能力。
- 隐藏层可挂载宝藏、隐性物品候选、前世后手或秘境奖励。
- 自然资源不走世界物品预算帽，而受资源点自己的上限与再生规则约束。

### 18.8 与 S10 事件链

- 世界生成物品主要通过 S10 事件、宝藏、秘境、NPC 互动等入口实例化。
- 事件选择决定物品获得、消耗、损坏、暴露、回收或线索生成。
- 事件难度提供局部约束，世界分阶预算帽提供全局约束。

### 18.9 与战斗系统

- 法宝、符箓、丹药、一次性护符等可提供战斗指令或被动效果。
- NPC 法宝和道具可在进入战斗时从隐性状态实例化。
- 战斗可改变法宝耐久、充能、灵性与损坏状态。
- 战斗战利品必须考虑敌方携带、物品损毁、事件是否允许回收、以及是否消耗世界生成预算帽。

### 18.10 与经济 / 平衡文档

- 分阶世界预算帽、通胀系数、参考通货量、配方效率、资源点再生速度最终进入平衡表。
- 本草稿只定义结构与接口，不定最终数值。

## 19. MVP 最小闭环

MVP 物品产出与获得至少验证以下闭环：

### 19.1 新手物品闭环

```
家庭支持 / 村镇事件
→ 获得铜钱与干粮
→ 前往镇集武馆
→ 获得基础功法载体
→ 学习后转入角色能力
```

验证点：货币、补给、功法载体、学习后内容与载体分离。

### 19.2 资源点到宗门库存闭环

```
宗门控制资源节点
→ 资源点按再生规则增加资源池
→ 宗门常态经营结算采集 / 加工
→ 生成抽象宗门资源或材料 ItemStack
→ 写入宗门库存日志
```

验证点：自然资源不直接掉物品、不消耗预算帽，资源点自身有上限。

### 19.3 玩家持续采集闭环

```
玩家在节点执行持续采集 / 加工行动
→ 读取资源点当前资源池
→ 消耗行动格与补给
→ 根据角色技艺和事件结果转化为材料 ItemStack
→ 写入角色日志与节点资源变化
```

验证点：玩家与宗门共享同一资源点状态，避免重复结算。

### 19.4 配方生产闭环

```
玩家或宗门掌握配方
→ 投入明确资源、材料、设施、时间
→ 产出明确目标物品
→ 品级 / 数量 / 状态在配方范围内随机
→ 获得配方经验或改造进度
```

验证点：显性资源投入、明确产出、有限随机、配方养成。

### 19.5 探索 / 事件世界生成闭环

```
玩家探索荒野 / 节点隐藏层
→ 触发 S10 节点事件
→ 根据事件难度与物品池生成候选物
→ 检查对应阶级世界预算帽
→ 玩家获得后扣预算并进入显性库存
```

验证点：世界凭空生成受局部玩法约束与全局预算帽约束。

### 19.6 战斗隐性实例化闭环

```
玩家与 NPC 进入战斗
→ NPC 法宝 / 符箓 / 丹药按模板实例化
→ 物品影响战斗
→ 战后若被获得，进入显性库存并扣预算
→ 若未获得，回收为隐性或销毁
```

验证点：NPC 不需要长期逐件保存所有物品，但战斗与掉落可解释。

### 19.7 战斗物品使用与损耗闭环

```
玩家携带法宝 / 符箓
→ 战斗中作为指令或被动效果使用
→ 消耗元气、耐久、充能或道具数量
→ 战斗结束回写物品状态
→ 可修复、拆解、回收或继续使用
```

验证点：无装备栏、物品可作为战斗资源、状态回写。

### 19.8 突破资源闭环

```
玩家准备突破
→ 申请宗门资源 / 自行收集突破资源 / 配方生产突破资源
→ S4 读取资源支持维度
→ 突破消耗或损坏资源
→ 成功 / 失败写入角色日志与轮回账本
```

验证点：突破资源不是抽象按钮，而是可追踪资源输入。

### 19.9 前世后手物品闭环

```
玩家将已有显性物品正式封存
→ 写入轮回账本与隐藏层
→ 转世后获得感应或线索
→ 回收时检查封存状态、暴露风险与世界日志
→ 原封存物品重新进入角色背包、宗门库存或节点状态
```

验证点：正式后手不生成新物品，而是让既有显性物品跨世追踪；正式后手不无理由失效。

### 19.10 通货与通胀闭环

```
世界推进产生资源与物品
→ 玩家 / 宗门显性通货总量增加
→ 计算 InflationCoeff
→ 交易价格、手续费、维护、修复、制造损耗上升
→ 回收系统在中后期变得更重要
```

验证点：通胀系数能延迟经济系统崩溃，而不是完全模拟真实经济。

## 21. 当前推荐结论

### 21.1 等级规则推荐

推荐采用：

```
阶级：数据层 A / B / C ...，显示层原则上与修炼阶级包装对齐
品级：Q1 ~ Q5，显示为下品 / 中品 / 上品 / 极品 / 绝品
```

该规则统一适用于物品、功法、根骨 / 悟性 / 灵根等资质子项、资源点产出层级与法宝。少数系统如灵根等级可使用独立显示包装，但仍映射到底层评级与价值模型。

### 21.2 生成系统推荐

不再推荐所有来源使用同一个“物品生成请求”。

推荐改为：

```
配方制生产：RecipeProductionRequest
自然资源转化：NaturalResourceExtraction / ProcessingRequest
世界凭空生成：WorldItemGenerationRequest
显性转移：InventoryTransferRequest
隐性实例化：ImplicitItemInstantiationRequest
回收：ItemRecyclingRequest
```

最终统一输出到 `ItemAcquisitionResult`。

### 21.3 配方系统结论

玩家角色与宗门主动生产物品时，应优先使用配方制。

已确定：

- MVP 支持轻量配方制生产，但不做完整炼丹炼器大系统。
- 配方作为非战斗类功法的衍生物进入正式规则。
- 配方也允许由 NPC 传授，或通过玉简、手札、残方、传承印记等物品学习。
- 配方升级进入 MVP，但只保留配方经验与少量等级效果。
- 配方改造不进入 MVP，只保留数据接口。
- 配方是非战斗成长路线的重要内容。

### 21.4 自然资源推荐

自然资源点不直接产出具体物品。

推荐流程：

```
资源点再生资源池
→ 宗门常态经营或玩家持续行动采集
→ 加工 / 配方 / 简单转化
→ 进入库存资源或材料物品
```

自然资源不消耗世界生成预算帽。

### 21.5 世界生成预算推荐

世界凭空生成物品必须受分阶预算帽约束。

预算按阶级独立维护：

```
accumulated_value = min(max_cap, accumulated_value + time × rate[tier][reach_state])
```

`reach_state` 分为：

```
无人达到 / 有人达到 / 全部达到
```

物品被玩家角色或宗门获得时，按物品完整价值模型扣除对应阶级预算。

### 21.6 显隐状态推荐

显性状态包括：

- 玩家库存。
- 宗门库存。
- 正式后手。
- 常规宝库。
- 市场挂牌。
- 事件锁定物品。

其他物品可处于隐性状态，在战斗、交易、事件或宝藏开启时实例化。

显性转隐性、消耗、拆解、销毁、转化均视为回收。

### 21.7 随机性结论

推荐随机优先影响：

- 数量。
- 品级。
- 状态桶。
- 纯度桶。
- 有限副词条。
- 隐藏信息。
- 使用效果小幅波动。

不推荐随机影响：

- 玩家明确追求的核心物品类型。
- 任务关键物品是否可用。
- 正式后手保存物的身份与追踪链。
- 宗门承诺发放的资源类型。
- 高频普通道具的独立身份。
- 普通材料、丹药、符箓的逐点数值差异。

已确定：

- 绝品是稀有产出，不作为普通自然随机结果。
- 绝品主要来自高风险秘境、重大事件、制造大成功、稀有配方结果或其他明确高价值机制。
- 正式后手本身不产出物品，只保存既有显性物品。
- 不设置半可堆叠物品层，只保留可堆叠与独立实例。
- 来源 / 产地 / 历史来源不是通用物品参数，只在法宝等少数需要来历、传承、因果、归属或特殊历史的物品模板中启用。

随机性必须先经过堆叠规则约束：能用数量、范围、桶、批次摘要表达的差异，不创建独立物品实例。

### 21.8 定价模型结论

先建立标准价值，不急于做完整市场。

```
V_std = B_category × T_tier × Q_quality × E_effect × S_scarcity × C_condition × U_utility
```

后续所有价格、上交价值、拆解价值、修复成本、事件奖励预算、世界生成预算都基于标准价值派生。

通货价格另乘通胀系数。

已确定：

```
R_tier 初始测试值 = 10
```

后续通过 M0→M3 资源曲线校正。

### 21.9 通胀系数结论

通胀系数用于延迟经济系统崩溃，而不是模拟真实经济。

已确定：

- 只维护灵石这一核心通货的通胀系数。
- 铜钱、银两等低阶货币在角色进入一阶修行体系后基本退出主经济循环，只保留特殊情境使用。
- 保留灵石兑换低阶货币入口。
- 灵石不分等级；“上品灵石”等概念由独立物品替代，例如聚灵石。

```
InflationCoeff_spirit_stone = 显性灵石总量 / 灵石参考值
```

当显性灵石总量接近参考值时，物品通货价格约等于模板价值。

普通灵石不能支持所有高阶灵气用途。后续高阶需求需要通过加工灵石获得聚灵石等独立物品来支持消耗。

该加工链是经济阀门：

```
普通灵石通胀
→ 加工设施 / 配方 / 时间 / 损耗限制
→ 聚灵石等高密度灵气物品
→ 高阶修炼、突破、阵法、设施需求
```

加工设施效率限制普通灵石通胀向顶级需求传递的效率。
