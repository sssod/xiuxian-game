# 新旧设定冲突修订总表（v0.1）

> 适用范围：Library 中 v2.2 文档包与两份新规则文档之间的冲突同步。  
> 修订原则：新规则优先；保留 v2.2 中仍兼容的权威服务器、S1 结果回写、小时级底层结算、资产容器、日志可信、宗门 AI 唯一持续行动等原则。

---

## 1. 总体结论

v2.2 的基础结构是：

```text
回合制房间
+ 默认 5 游戏日回合
+ 玩家规划时间预算条
+ 全员锁定 / 超时后统一结算
+ 结算阶段被插入事件链挂起
```

新规则将项目时间骨架修正为：

```text
共享世界日历
+ 服务器以 1 游戏小时为最小 tick
+ 世界按 F1 / N1 / B1 / P0 自适应速度推进
+ 普通指令预输入不暂停自身或世界
+ 个人非交锋事件只冻结本人，其他世界 N1
+ 正式交锋 / 突破挑战统一 B1 交锋轮
+ 自动兜底强制 N1，不参与 F1
```

因此，v2.2 中“固定 5 日回合”不再作为玩家侧最小推进单位；`world_day / world_hour` 成为主时间事实，`turn_id` 若保留，只能作为调试、归档或阶段批处理编号，不再表示玩家必须填满的 5 日预算回合。

## 3. 本次保留的 v2.2 原则

以下 v2.2 设计不与新规则冲突，继续保留：

```text
1. S1 / 权威服务器仍是全系统结算总线。
2. 客户端只提交意图，不直接改写状态。
3. 服务器校验行动、资源、位置、权限、事件触发和结果包。
4. 底层仍建议以 world_hour / hour_tick 进行结算。
5. 宗门 AI 仍自行维护唯一宗门持续行动。
6. 资产容器、资源预留、日志可信和结果包回写原则继续保留。
7. 丹药、灵材、符箓仍作为行动资源输入，不恢复“即时服丹涨修为”。
8. 功法完整载体、掌握度、残余资源效果等 v2.2 新设定继续有效。
```

## 4. 需从 v2.2 全文删除或降级的表达

以下表达在后续全量文档中应删除、替换或改为历史说明：

```text
默认每回合 5 个游戏天
玩家最小推进单位为回合
天级回合时间预算条作为主行动入口
全员锁定后统一结算是普通推进唯一方式
决策阶段倒计时默认 120 秒
结算阶段才推进游戏时间
行动规划后进入锁定等待
突破为固定执行时间持续行动
关键突破物在固定行动开始时统一消耗
个人突破结果属于 P0 结果
无后续队列统一进入休整待机
休整待机默认可作为 F1 低交互依据
低价值事件默认自动处理
```

替换为：

```text
共享世界日历连续推进
服务器最小结算单位 1 游戏小时
世界速度为 F1 / N1 / B1 / P0
普通队列编辑不暂停角色当前行动
当前指令 + 最多 3 条预输入指令
队列为空或校验失败后风险兜底，并强制 N1
个人非交锋事件本人局部时停，gap≤1日，结束后 C1追赶
正式交锋 / 突破挑战 B1交锋轮
个人突破不 P0，资源消耗集中在突破挑战轮内
```
