# 新功法与修炼资源设定｜旧文档冲突同步清单 v0.1

> 文档定位：本文基于《功法系统_收敛设定汇总_v0.4.md》和《修为修炼公式_资源输入与丹药药性处理补充_v0.2.md》的新设定，对当前 sources 中 v2.1 文档进行冲突识别与同步修正整理。  
> 处理原则：**以新方案为准**。本文不直接改写原 sources，而是列出需要同步、替换、删改和新增的内容，供后续整包修订使用。

---

## 0. 新方案权威口径摘要

### 0.1 功法系统

```text
残页 → 篇章 → 完整功法载体 → 学会功法 → 研习功法提升掌握度
```

当前定版：

1. 功法分为道功与法门。
2. 道功推动修为增长，可设为主修。
3. 法门不直接推动修为增长，只提供战斗、探索、采集、生产、事件、移动等能力。
4. 残页和篇章都是**可合成道具**，不可直接学习，不创建 `MethodState`。
5. 只有完整功法载体可以作为学习来源。
6. 常规功法获得完整载体后，需要研习入门。
7. 新手基础功法可由入门事件直接授予 `learned level 1`。
8. 道功掌握度影响当前可修上限和单位时间收益。
9. 道功掌握度不提高功法理论最高上限。
10. 道功掌握度不影响修为纯度收益、小境界升级奖励质量、大境界突破模板类型，也不制造阶段性不可追回收益。
11. 主修道功只在大境界第一小阶段常规开放无时间成本更换。
12. 离开第一小阶段后，本大境界主修道功锁定。
13. MVP 不做废功重修、不做改修折算、不做免费续接换功。
14. 主修锁定提醒在 UI 常驻提示，不在 B-1 → B-2 等结算升级关口插入确认。

---

### 0.2 修炼资源输入

当前定版：

1. 丹药、灵材、符箓、临时增益资源统一作为**行动资源输入项**。
2. MVP 不设计独立持续行动：`丹药炼化`。
3. MVP 不允许即时服用修为丹药后直接增加修为。
4. 修为丹药只能作为主动吐纳的额外输入。
5. 临时悟性丹作为研习功法的额外输入。
6. 解毒丹 / 避瘴丹作为毒瘴移动、探索、采集、战斗等语境的额外输入。
7. 定心丹可作为研习、巩固、突破准备、突破事件链的额外输入。
8. 资源效果总量 = `unit_effect_rate × max_effective_hours`。
9. 实际结算按行动实际兼容小时消耗。
10. 行动未实际开始，则资源不消耗。
11. 行动已开始但未完全消耗资源，则剩余效果进入 `ActiveResourceEffect`。
12. `ActiveResourceEffect` 可跨行动、跨回合保存。
13. 决策阶段时间暂停，不推进药性衰减。
14. 非兼容行动不转化资源效果。
15. 巩固根基可选择性收束残余修为药性，但不转化修为。
16. 同一行动中，同一效果通道 MVP 最多使用 1 个主资源输入。
17. 事件选项可以临时追加资源输入，但必须由事件模板声明 `resource_input_slot`，不得回溯生效。
18. 资源输入 UI 采用行动内折叠项，残余效果在角色面板 / 行动规划器中常驻提示。

## 2.1.2 需要修改：第 7 节“道功与法门”

### 当前问题

当前 `DaoMethod` 示例字段为：

```text
stage_support_range
level_cap_profile
breakthrough_support_profile
```

这些字段不足以表达新方案：

```text
理论最高上限
掌握度当前上限
突破转接模板
```

同时容易继续保留“篇章缺失 / 支持范围缺失导致卡修为”的旧逻辑。

### 建议替换为

```text
DaoMethodTemplate {
  template_id: String,
  method_lineage_id: String,
  tier_code: String,
  quality_code: String,
  method_tags: Array,

  theoretical_max_cap_stage: String,
  mastery_cap_profile: Dictionary,

  absorption_profile: Dictionary,
  conversion_profile: Dictionary,
  purity_profile: Dictionary,

  breakthrough_transition_support: Array,
  compatibility_requirements: Dictionary,
  source_rules: Dictionary
}
```

字段解释：

| 字段 | 新含义 |
|---|---|
| `theoretical_max_cap_stage` | 该完整道功理论最高可修至哪里，例如 `B-1 100%` |
| `mastery_cap_profile` | 不同掌握度 level 当前可承载到哪里 |
| `breakthrough_transition_support` | 该道功本身支持哪些大境界转接，例如 `A-3 → B-1` |
| `absorption_profile` | 环境灵气流中的道功吸收能力 |
| `conversion_profile` | 道功基础转化特质 |
| `purity_profile` | 道功路线本身的纯度倾向，不由掌握度修改 |

## 2.1.3 需要修改：第 7.3 节“主修道功”

### 当前问题

当前写法包含：

```text
主修道功决定被动吸收、主动吐纳、丹药炼化、修为上限和突破模板匹配。
每个大境界记录最终主修道功，用于突破模板、奖励结构和失败标签池。
```

其中有两处需要调整：

1. “丹药炼化”已取消为独立行动，不应继续作为主修道功读取项。
2. “用于突破模板、奖励结构和失败标签池”容易被理解为掌握度或最终记录会改变奖励质量与突破模板。

### 建议替换为

```text
主修道功规则：

1. 同一时间只能有一个主修道功。
2. 只有道功能设为主修。
3. 主修道功决定主动吐纳、自动运转、修为有效上限与突破路线读取。
4. 主修道功只允许在大境界第一小阶段内无时间预算成本替换，例如 A-1 / B-1 / C-1。
5. 离开第一小阶段后，本大境界主修道功锁定。
6. 不因功法理论上限达到、掌握度上限达到、玩家后悔、临时想换更优突破模板而开放免费换主修。
7. MVP 不做废功重修、不做改修折算、不做免费续接换功。
8. 大境界突破模板类型来自当前有效主修道功的路线特质与突破转接配置，不由道功掌握度等级改变。
```

新增 UI 口径：

```text
不在 B-1 → B-2 等结算升级关口插入确认。
主修锁定提醒应在主修道功更换界面、主修道功详情界面、角色修为摘要区常驻展示。
```

## 2.1.4 需要修改：第 8.2 节“主动吐纳”

### 当前问题

当前只说读取：

```text
当前节点灵气
主修道功吸收速度
主修道功转化效率
角色资质
当前状态和伤势
修为阶段与瓶颈
```

新方案需要明确两条输入流：

```text
环境灵气流
修为资源输入流
```

### 建议补充

```text
主动吐纳存在两条输入流：

环境灵气流：
节点灵气 / 聚灵阵 / 灵液池 / 洞府灵气
→ 受道功吸收速度限制
→ 进入转化与承载

修为资源输入流：
修为丹药 / 修为灵材自身提供定额灵气包
→ 跳过道功吸收速度
→ 直接进入转化与承载
```

环境灵气输入公式：

```text
environment_aura_input =
actual_hours
× min(
    node_aura_density + facility_aura_density_bonus + temporary_aura_bonus,
    dao_base_absorption_rate × mastery_absorption_factor × state_factor
  )
```

修为资源输入公式：

```text
cultivation_resource_aura_input =
Σ(unit_aura_rate_i × applied_effective_hours_i × resource_quality_factor_i)
```

合流：

```text
raw_aura_input = environment_aura_input + cultivation_resource_aura_input
```

之后统一进入：

```text
根骨安全承载
根骨转化效率
灵根与道功相性
道功基础转化率
状态修正
修为进度
修炼压力
```

## 2.1.5 需要删除 / 替换：第 8.3 节“丹药炼化”

### 当前问题

当前文档写：

```text
丹药炼化可以作为：
- 独立固定执行时间行动。
- 主动吐纳期间的资源投入修正。
- 突破准备或事件链内的选择资源。
```

这与新方案冲突。

### 建议替换为

```text
### 行动资源输入项

丹药、灵材、符箓和临时增益资源不优先设计为独立持续行动，而是作为行动资源输入项挂载到对应行动或事件选项上。

MVP 明确不做：
1. 独立持续行动：丹药炼化。
2. 即时服用修为丹药后直接增加修为。
3. 修为丹药在主动吐纳之外转化修为。

典型对应关系：
- 修为丹药 → 主动吐纳的额外资源输入。
- 临时悟性丹 → 研习功法的额外资源输入。
- 解毒丹 / 避瘴丹 → 毒瘴移动、探索、采集、战斗语境的额外资源输入。
- 疗伤丹 → 休整 / 治疗 / 医疗事件选项的额外资源输入。
- 定心丹 → 巩固根基 / 突破准备 / 突破事件链选项 / 研习功法的额外资源输入。
```

## 2.1.6 需要修改：第 8.4 节“研习功法”

### 当前可保留内容

研习功法属于：

```text
duration_mode = variable_investment
```

读取：

```text
实际投入小时数
悟性 aptitude_comprehension
功法阶级与品级
导师、宗门设施、相关法门基础
当前状态与神念稳定度
```

这些与新方案一致。

### 需要补充

```text
研习功法只能针对完整功法载体或已学功法 MethodState。
残页和篇章不可作为研习目标。
```

研习可以产出：

```text
1. 未入门完整功法进入 learned level 1。
2. MethodState.exp 增加。
3. MethodState.level 提升。
4. 道功当前可修上限提高。
5. 道功单位时间收益提高。
6. 法门指令、事件选项或行动修正解锁。
7. 可追回的知识型、提示型、法门型收益。
```

研习不能产出：

```text
1. 残页 / 篇章直接学习。
2. 缺失篇章自动补齐。
3. 功法理论最高上限提高。
4. 大境界突破模板类型变化。
5. 小境界升级奖励质量变化。
6. 修为纯度收益变化。
7. 阶段性不可追回收益。
```

```text
AptitudeProfile {
  aptitude_bone: int,
  aptitude_comprehension: int,
```

```text
AptitudeProfile {
  aptitude_bone: int,
  aptitude_comprehension: int,
  aptitude_root: int,

  root_affinity_profile: Dictionary,
```

```text
aptitude_root：灵根强度或基础亲和水平。
root_affinity_tags：例如 wood / fire / water / thunder。
root_affinity_profile：不同路线标签的相性修正，例如 { wood: 1.15, fire: 0.90 }。
```
