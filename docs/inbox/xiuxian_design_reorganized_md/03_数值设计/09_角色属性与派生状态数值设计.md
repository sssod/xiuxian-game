# 数值设计｜角色属性与派生状态

## 1. 设计定位

本文负责角色属性相关的数值层设计，包括单位、输入参数、公式、乘区、配置表、保留值约束、派生状态上限、寿元派生、寿元年龄影响折线、非基准延寿总上限、缓存字段和调参验收口径。

本文不负责角色属性字段语义、来源 / 持续性口径、灵根系统边界、寿元系统职责、UI 展示原则或旧字段迁移。这些系统层规则由《角色属性》（`../02_系统设计/02_角色与真灵设计/02_角色属性.md`）维护。伤势、药性、符箓持续效果、法宝触发态和事件持续状态的生命周期由《角色持续状态系统》（`../02_系统设计/02_角色与真灵设计/07_角色持续状态系统.md`）维护，本文只读取其导出的后天修正合计和派生状态结算结果。

## 2. 当前结论

1. 角色属性系统文档是字段语义和模块边界主文档；本文是数值层唯一配套文档。
2. 常规数值公式优先采用“绝对值先合并、百分比同乘区加减汇总”的单乘区结构。
3. 寿元对体魄 / 精力最终值的影响使用连续分段函数折线，并作为独立年龄影响乘区，不并入生机、元气或神念的普通增幅系数。
4. 生机最大值读取体魄最终值，元气最大值读取精力最终值，神念最大值不读取体魄、精力、寿元年龄影响或悟性资质。
5. 非灵根资质有效值不读取寿元年龄影响；灵根在 MVP 只读取先天结果。
6. 生机、元气、神念的保留值会减少可支配上限；当前值不得超过扣除保留值后的可用容量。
7. 非基准延寿进入 MVP，但有效总量由寿元模块按寿元基准的比例阈值限制；燃寿、折寿、道伤等消耗项不参与阈值计算。
8. 缓存字段不是事实来源；事实来源仍是角色属性、持续状态记录、资源效果、功法效果、事件结果和数值表。

## 4. 基准、单位与输入参数

### 4.1 单位口径

| 项目 | 口径 |
| --- | --- |
| 属性值 | 使用数值点数，具体范围由配置表决定 |
| 派生状态 | 使用当前值、最大值、保留值三类数值 |
| 百分比字段 | 统一使用 `*_percent` 命名；文档中的 `100%` 可由实现层保存为百分数或等价倍率 |
| 绝对值加成 | 先按来源合并为 `*_flat_bonus` 或同类字段，再进入公式 |
| 年龄 | 使用世界时间推进后的当前世年龄，单位与寿元上限一致 |
| 寿元 | 使用当前世最大时间预算；寿元上限变化后，剩余寿元、年龄比例和年龄影响重新派生 |

### 4.2 输入参数

| 参数 | 来源 | 说明 |
| --- | --- | --- |
| `age` | `LifespanState` | 当前年龄 |
| `lifespan_limit` | `LifespanState` | 当前寿元上限 |
| `base_physique.innate_value` | `BaseAttributes` | 体魄先天值 |
| `base_physique.acquired_permanent_delta` | `BaseAttributes` | 体魄后天永久修正合计 |
| `base_physique.temporary_modifiers_total` | 持续状态系统与后天修正接口 | 当前有效体魄临时修正合计 |
| `base_vigor.innate_value` | `BaseAttributes` | 精力先天值 |
| `base_vigor.acquired_permanent_delta` | `BaseAttributes` | 精力后天永久修正合计 |
| `base_vigor.temporary_modifiers_total` | 持续状态系统与后天修正接口 | 当前有效精力临时修正合计 |
| `aptitude_bone` / `aptitude_comprehension` | `AptitudeProfile` | 根骨 / 悟性先天、后天永久和临时修正 |
| `aptitude_root` / `root_affinity_profile` | `AptitudeProfile` | MVP 只读取先天灵根结果 |
| `*_age_effect_multiplier` | 寿元年龄影响折线表 | 体魄 / 精力年龄影响乘区 |

| `non_baseline_lifespan_extension_cap_ratio` | 寿元配置 | 非基准延寿总和不超过寿元基准的比例阈值，即用户口径中的 `x%` |
| `lifespan_consumption_total` | 寿元消耗来源汇总 | 燃寿、折寿、道伤、失败突破等扣减合计 |

## 5. 公式或模型

### 5.1 通用公式口径

常规数值公式优先采用单乘区结构：

```text
result =
  (base_value +/- flat_delta_total)
  * (100% +/- percent_delta_total)
```

规则：

1. 同一公式里的多个绝对值来源先加减合并，再进入乘区。
2. 同一百分比乘区内的多个增减幅来源用加减法汇总，不互相独立连乘。
3. 默认无增减幅时，百分比乘区为 `100%`。
4. 不默认设置多个独立乘区，除非有明确设计理由。
5. 寿元年龄影响是体魄 / 精力最终值计算中的例外独立乘区。

### 5.2 寿元派生与年龄影响折线

```text
remaining_lifespan =
  max(lifespan_limit - age, 0)

age_ratio =
  age / max(lifespan_limit, 1)

physique_age_effect_multiplier =
  piecewise_linear(age_ratio, physique_age_effect_curve)

vigor_age_effect_multiplier =
  piecewise_linear(age_ratio, vigor_age_effect_curve)
```

规则：

1. `lifespan_limit` 应大于 0；公式中的 `max(lifespan_limit, 1)` 只用于避免异常数据造成除零。
2. `piecewise_linear` 使用按 `age_ratio` 升序排列的控制点，在相邻控制点之间做线性插值；低于首点时使用首点倍率，高于末点时使用末点倍率。
3. 体魄和精力可以使用不同折线，但折线必须连续，不得在控制点处产生跳变。
4. 寿元上限变化后，应重新计算 `remaining_lifespan`、`age_ratio` 和体魄 / 精力年龄影响乘区。
5. `age >= lifespan_limit` 时寿元耗尽，系统层直接触发死亡并进入转世流程。

### 5.3 体魄与精力最终值

体魄 / 精力最终值拆分为先天最终值和后天最终值，供生机、元气等公式读取。

```text
base_physique_innate_final =
  base_physique.innate_value
  * physique_age_effect_multiplier

base_physique_acquired_final =
  (
    base_physique.acquired_permanent_delta
    + base_physique.temporary_modifiers_total
  )
  * physique_age_effect_multiplier

base_physique.effective_value =
  base_physique_innate_final
  + base_physique_acquired_final
```

```text
base_vigor_innate_final =
  base_vigor.innate_value
  * vigor_age_effect_multiplier

base_vigor_acquired_final =
  (
    base_vigor.acquired_permanent_delta
    + base_vigor.temporary_modifiers_total
  )
  * vigor_age_effect_multiplier

base_vigor.effective_value =
  base_vigor_innate_final
  + base_vigor_acquired_final
```

规则：

1. `temporary_modifiers_total` 是当前有效临时修正合计；它属于后天来源，但不回写为永久后天属性。
2. `physique_age_effect_multiplier` 和 `vigor_age_effect_multiplier` 默认无影响时为 `100%`。
3. 其他公式读取 `base_physique_*_final` 或 `base_vigor_*_final` 时，不再额外乘一次寿元年龄影响。

### 5.4 非灵根资质有效值

根骨和悟性不读取寿元年龄影响。

```text
aptitude_bone.effective_value =
  aptitude_bone.innate_value
  + aptitude_bone.acquired_permanent_delta
  + aptitude_bone.temporary_modifiers_total

aptitude_comprehension.effective_value =
  aptitude_comprehension.innate_value
  + aptitude_comprehension.acquired_permanent_delta
  + aptitude_comprehension.temporary_modifiers_total
```

灵根在 MVP 只读取先天结果：

```text
aptitude_root.effective_value =
  aptitude_root.innate_value
```

`root_affinity_tags` 和 `root_affinity_profile` 只读取先天相性结构。外部效果影响灵根相关判定时，应在对应系统中作为状态、资源、道功、法宝、阵法或事件效果参与结算，不写回灵根字段。

### 5.5 生机最大值

生机最大值读取体魄最终值：

```text
bar_vitality_max =
  (
    base_physique_innate_final * vitality_innate_physique_coeff_percent
    + base_physique_acquired_final * vitality_acquired_physique_coeff_percent
    + vitality_flat_bonus
  )
  * vitality_amplifier_percent
```

规则：

1. 常规情况下，`vitality_innate_physique_coeff_percent` 与 `vitality_acquired_physique_coeff_percent` 相同。
2. 分成先天 / 后天系数只是为了后续调参和特殊效果预留。
3. `vitality_flat_bonus` 是生机绝对值加成合计，可以来自后天永久、临时状态、资源效果、伤势修复或事件结果。
4. `vitality_amplifier_percent` 是生机增幅系数合计；多个来源在同一乘区内用加减法汇总。
5. 寿元年龄影响已经体现在体魄最终值中，不在生机公式中再次计算。

### 5.6 元气最大值

元气最大值读取精力最终值：

```text
bar_qi_max =
  (
    base_vigor_innate_final * qi_innate_vigor_coeff_percent
    + base_vigor_acquired_final * qi_acquired_vigor_coeff_percent
    + qi_flat_bonus
  )
  * qi_amplifier_percent
```

规则：

1. 常规情况下，`qi_innate_vigor_coeff_percent` 与 `qi_acquired_vigor_coeff_percent` 相同。
2. 分成先天 / 后天系数只是为了后续调参和特殊效果预留。
3. `qi_flat_bonus` 是元气绝对值加成合计，可以来自后天永久、临时状态、资源效果、功法效果或事件结果。
4. `qi_amplifier_percent` 是元气增幅系数合计；多个来源在同一乘区内用加减法汇总。
5. 寿元年龄影响已经体现在精力最终值中，不在元气公式中再次计算。

### 5.7 神念最大值

神念最大值不读取体魄、精力、寿元年龄影响或悟性资质，使用独立基础常量：

```text
bar_mind_max =
  (mind_base_value + mind_flat_bonus)
  * mind_fixed_multiplier_percent
```

规则：

1. `mind_base_value` 默认为所有角色相同的常量。
2. `mind_base_value` 用于避免无加成时神念为 0 造成计算异常。神念为 0 在语义上接近角色死亡，因此常态角色不应以 0 作为神念上限基准。
3. `mind_flat_bonus` 是神念绝对值加成合计，可以来自后天永久、临时状态、功法、资源效果或事件结果。
4. `mind_fixed_multiplier_percent` 是神念固定系数乘区；多个来源在同一乘区内用加减法汇总。
5. 神念公式不承接寿元年龄影响乘区。

### 5.8 保留值与当前值约束

```text
bar_vitality_available_max =
  bar_vitality_max - bar_vitality_reserve

bar_qi_available_max =
  bar_qi_max - bar_qi_reserve

bar_mind_available_max =
  bar_mind_max - bar_mind_reserve
```

约束：

```text
0 <= bar_vitality_reserve <= bar_vitality_max
0 <= bar_qi_reserve <= bar_qi_max
0 <= bar_mind_reserve <= bar_mind_max

0 <= bar_vitality_current <= bar_vitality_available_max
0 <= bar_qi_current <= bar_qi_available_max
0 <= bar_mind_current <= bar_mind_available_max
```

当上限或保留值变化导致当前值超过可支配上限时，当前值应钳制到新的可支配上限，并写入结算日志或状态变更记录。

### 5.9 非基准延寿总上限

寿元基准只由寿元基础值和境界突破增加寿元构成。除这两类以外的所有延寿来源都属于非基准延寿；其有效总和不得超过寿元基准的配置比例阈值 `x%`。

```text
lifespan_baseline =
  lifespan_base_value
  + realm_breakthrough_lifespan_bonus_total

non_baseline_lifespan_extension_cap =
  floor(lifespan_baseline * non_baseline_lifespan_extension_cap_ratio)

effective_non_baseline_lifespan_extension_total =
  min(
    non_baseline_lifespan_extension_total_raw,
    non_baseline_lifespan_extension_cap
  )

lifespan_limit =
  max(
    lifespan_baseline
    + effective_non_baseline_lifespan_extension_total
    - lifespan_consumption_total,
    0
  )

non_baseline_lifespan_extension_ratio =
  effective_non_baseline_lifespan_extension_total
  / max(lifespan_baseline, 1)
```

规则：

1. `lifespan_base_value` 是当前世寿元基础值。
2. `realm_breakthrough_lifespan_bonus_total` 只统计境界突破增加寿元。
3. `lifespan_baseline` 是非基准延寿上限的唯一基准，不受燃寿、折寿、道伤、失败突破等消耗项影响。
4. `non_baseline_lifespan_extension_total_raw` 统计资源延寿、宗门供养、秘境机缘、消耗型物品延寿和其它非基准延寿来源的原始总量。
5. `non_baseline_lifespan_extension_cap_ratio` 表示非基准延寿总和不超过 `lifespan_baseline` 的比例阈值，MVP 默认值待裁决。
6. 超出上限的部分不计入有效 `lifespan_limit`，但必须记录来源、原始延寿值、实际生效值和被上限钳制值。
7. `lifespan_consumption_total` 在延寿上限钳制后扣减寿元上限，但不改变 `lifespan_baseline`，也不改变非基准延寿可生效上限。
8. 若境界突破增加寿元变化，应重新计算 `lifespan_baseline`、非基准延寿上限和最终寿元上限。

### 5.10 推荐重算顺序

```text
寿元来源汇总
→ 寿元基准
→ 非基准延寿总上限钳制
→ 燃寿 / 折寿 / 道伤等寿元消耗扣减
→ remaining_lifespan / age_ratio
→ 体魄 / 精力年龄影响乘区
→ 体魄 / 精力最终值
→ 根骨 / 悟性有效值
→ 生机 / 元气 / 神念最大值
→ 保留值与当前值钳制
→ 可见摘要、日志和 Debug 缓存
```

该顺序是数值重算建议，不强制实现层使用同名函数或同一缓存结构。

## 6. 配置表或根表

### 6.1 寿元年龄影响折线表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `curve_id` | 折线 ID | 如 `default_physique_age_effect`、`default_vigor_age_effect` |
| `target_attribute` | 作用目标 | `base_physique` 或 `base_vigor` |
| `point_order` | 控制点顺序 | 同一折线内按升序排列 |
| `age_ratio_point` | 年龄比例控制点 | 建议覆盖 `0` 到 `1.0`，可按需要配置超过 `1.0` 的耗尽后保护点 |
| `multiplier_percent` | 控制点倍率 | 默认无影响为 `100%` |
| `interpolation` | 插值方式 | MVP 固定为 `linear` |

规则：

1. 同一 `curve_id` 下的 `age_ratio_point` 必须严格递增。
2. 任一相邻控制点之间使用线性插值，保证体魄 / 精力年龄影响是连续折线。
3. 若需要儿童期成长、壮年稳定、衰老下滑，应通过控制点形状表达，不使用离散阶段倍率跳变。
4. 折线控制点的具体数值仍待调参确认；本文先固定表结构和插值口径。

### 6.2 派生状态系数表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `vitality_innate_physique_coeff_percent` | 体魄先天最终值到生机上限的系数 | 常规可与后天系数相同 |
| `vitality_acquired_physique_coeff_percent` | 体魄后天最终值到生机上限的系数 | 为特殊调参预留 |
| `qi_innate_vigor_coeff_percent` | 精力先天最终值到元气上限的系数 | 常规可与后天系数相同 |
| `qi_acquired_vigor_coeff_percent` | 精力后天最终值到元气上限的系数 | 为特殊调参预留 |
| `mind_base_value` | 神念基础常量 | 应大于 0 |
| `default_percent` | 默认百分比乘区 | 通常为 `100%` |

### 6.3 派生状态加成汇总表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `vitality_flat_bonus` | 生机绝对值加成合计 | 来源包括状态、资源、事件等 |
| `vitality_amplifier_percent` | 生机增幅乘区 | 同乘区加减汇总 |
| `qi_flat_bonus` | 元气绝对值加成合计 | 来源包括状态、资源、功法、事件等 |
| `qi_amplifier_percent` | 元气增幅乘区 | 同乘区加减汇总 |
| `mind_flat_bonus` | 神念绝对值加成合计 | 来源包括状态、资源、功法、事件等 |
| `mind_fixed_multiplier_percent` | 神念固定乘区 | 同乘区加减汇总 |

### 6.4 寿元配置表

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `non_baseline_lifespan_extension_cap_ratio` | 非基准延寿总上限比例 | 例如 0.2 表示所有非基准延寿总和不得超过 `lifespan_baseline` 的 20%；MVP 默认值待裁决 |
| `lifespan_base_value` | 当前世寿元基础值 | 可由出生、种族、世界观模板或初始角色配置给出 |
| `realm_breakthrough_lifespan_bonus` | 单次境界突破增加寿元 | 具体按境界表配置 |

## 7. 结算输出

### 7.1 推荐缓存字段

## 8. 调参验收口径

1. 体魄 / 精力寿元年龄影响乘区只能影响体魄 / 精力最终值，不得在生机、元气或其他公式中重复计算。
2. 根骨、悟性、灵根、灵根相性和神念基础值不得读取寿元年龄影响。
3. 常规百分比增减幅在同一乘区内加减汇总，不应因多个来源独立连乘导致异常膨胀。
4. 生机、元气、神念的保留值不能超过对应上限，当前值不能超过可支配上限。
5. 神念基础上限应大于 0，避免常态角色神念上限为 0。
6. 体魄 / 精力寿元年龄影响必须按连续分段函数折线插值，不得退回离散阶段倍率跳变。
7. 非基准延寿有效总量不能超过寿元基准按配置比例计算出的上限。
8. 燃寿、折寿、道伤和失败突破等消耗项不得降低寿元基准，也不得降低非基准延寿可生效上限。
9. `age >= lifespan_limit` 时必须直接触发死亡并进入转世流程，不保留独立寿元紧迫状态。
10. 寿元上限变化后，剩余寿元、年龄比例和体魄 / 精力年龄影响乘区必须同步刷新。
11. 缓存字段必须能追溯到角色属性、持续状态记录、资源效果、功法效果、事件结果和数值表，不得成为新的事实来源。

## 9. MVP 范围

MVP 应实现：

1. 通用单乘区公式口径。
2. 寿元派生：剩余寿元、年龄比例和体魄 / 精力年龄影响乘区。
3. 体魄 / 精力最终值公式及寿元年龄影响折线插值。
4. 根骨 / 悟性有效值公式。
5. MVP 灵根先天有效值读取。
6. 生机 / 元气 / 神念最大值公式。
7. 派生状态保留值和当前值约束。
8. 非基准延寿总上限公式。
9. 推荐缓存字段和结算日志口径。

MVP 不实现：

1. 多层独立乘区叠乘体系。
2. 后天灵根或临时灵根数值公式。
3. 复杂五行循环、相生相克链或多层灵根谱系数值表。
4. 高阶长期曲线验算和完整平衡样例。
5. 由角色属性数值文档替修炼、战斗、事件系统定义完整收益公式。
