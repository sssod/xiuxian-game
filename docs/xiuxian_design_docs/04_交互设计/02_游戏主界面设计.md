# 交互设计｜游戏主界面设计

## 1. 当前状态

本页面仍处于交互约束草案阶段，当前只固定游戏主界面必须承接的状态、入口和反馈边界，不维护完整视觉布局稿、Figma 节点、像素坐标或旧来源清单。

游戏主界面服务于玩家进入共享世界后的日常观察、行动规划、事件处理和结果回读。它不替代指令管理页、角色页、宗门页、储物页、战斗页或突破页的专项操作，但必须把这些专项状态以可理解的摘要和入口汇总到同一主界面。

## 3. 用户目标与入口

玩家进入主界面时，需要完成以下目标：

1. 快速判断当前世界时间、房间速度和是否需要自己立即处理。
2. 查看当前角色位置、行动状态、队列状态和自动兜底状态。
3. 进入行动规划、地图、事件、宗门、角色、修为、功法和储物等专项页面。
4. 阅读事件、传闻、日志、结果包和待处理事项。
5. 在 B1、P0、局部时停或 C1 等特殊状态下理解当前能做什么、不能做什么。

主界面入口来自房间大厅进入共享世界、读取存档恢复、事件结束返回、B1 / P0 结束返回和专项页面返回。

## 4. 必须表达

1. 当前世界时间、共享世界日历和当前流速状态 N1 / F1 / B1 / P0。
2. 当前角色位置、节点摘要、可见路线和地图入口。
3. 当前行动、队列状态、自动兜底、显式托管和行动规划入口。
4. 事件、传闻、日志、待处理事项和结果包摘要。
5. 宗门持续行动反馈、宗门资源申请状态和宗门页面入口。
6. 队列为空或自动兜底时，必须表达世界已降至 N1，并提示玩家接管。
7. B1 状态必须表达“当前速度：交锋慢速”和本轮剩余现实提交时间。
8. B1 状态不得暗示参战交锋自身固定消耗 1 游戏小时；交锋结果摘要应区分 B1 世界推进、非参战行动推进、参战交锋结算耗时和参战 gap。
9. 常规战斗摘要应显示：3 轮以内、每轮 5 个交锋格、交锋叙事 30 分钟、不足 1 小时按 1 小时结算。
10. 突破挑战摘要应显示：每阶段 1 个交锋格、阶段耗时由模板声明、总耗时暂定 1-6 游戏小时。

## 5. 页面区块与信息优先级

主界面应优先表达“现在发生了什么”和“玩家是否需要处理”，其次才是长期信息和专项入口。

推荐信息优先级：

1. 顶层时间与速度区：世界日 / 小时、N1 / F1 / B1 / P0、暂停或降速原因。
2. 当前角色状态区：位置、当前行动、队列摘要、兜底 / 托管状态、关键派生状态摘要。
3. 待处理区：个人即时处理事件、B1 / P0 提交窗口、突破阶段、重要结果包和未读日志。
4. 地图与节点区：当前节点、可见路线、机会窗口、资源槽摘要和移动入口。
5. 结果与日志区：公开摘要、私人日志、传闻、宗门反馈和回放入口。
6. 专项入口区：角色、修为、功法、指令管理、储物空间、宗门。

页面只记录稳定区块和信息层级，不固定具体布局、背景、组件坐标或节点 ID。

## 6. 操作流程与状态

常规 N1 / F1 状态：

```text
进入主界面
→ 查看时间、速度、位置和当前行动
→ 读取事件 / 日志 / 结果包摘要
→ 进入指令管理页编辑普通队列
→ 返回主界面继续观察世界推进
```

自动兜底状态：

```text
队列为空或执行前校验失败
→ 主界面提示自动兜底原因
→ 世界速度显示为 N1
→ 玩家进入指令管理页补充主动指令
```

局部时停状态：

```text
个人即时处理事件触发
→ 本人看到待处理事件入口
→ 外部世界继续 N1
→ 事件完成后显示 C1 追赶摘要
```

B1 交锋状态：

```text
正式战斗或突破挑战触发
→ 主界面显示交锋慢速、提交倒计时和专项入口
→ 玩家进入战斗或突破专项面板提交选择
→ 交锋结束后主界面展示结果包摘要
```

P0 全局暂停状态：

```text
同步处理事件进入 P0 或同步保护触发
→ 主界面显示全局暂停原因、参与要求和默认处理策略
→ 玩家完成必要选择或等待同步解除
→ 恢复 N1 / B1 / F1 判定
```

## 7. 不表达或 Debug 边界

普通主界面不展示：

1. 其他玩家私人事件归因、完整队列、隐藏后手、私人日志或他人真灵信息。
2. Debug 随机种子、完整结果包内部字段、事件权重、节点隐藏层完整清单。
3. 原始公式、倍率追踪、逐 tick C1 明细或内部校验树。
4. 未揭示剧情、未公开宗门 AI 内部判断或未发现资源窗口。

Debug / QA 模式可以显示速度判定来源、结果包 ID、回放片段、C1 诊断和隐藏状态检查，但必须与普通玩家界面分离。
