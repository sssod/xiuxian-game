# 游戏框架与核心裁决

适用范围：修仙题材多人棋盘模拟游戏的局级骨架、当前核心结论、专题权威归属和待裁决总表。本文是新设计包的当前权威入口，不承载已经拆入专题文档的完整细则。

## 1. 权威与维护方式

1. 用户对新方案的明确裁决拥有最高优先级。
2. 本文维护高层摘要、模块边界和待裁决事项；详细规则以第 `7` 章映射的专题文档为唯一维护位置。
3. 摘要与专题细则如有冲突，视为包内冲突，必须停止推断并请求裁决，不得静默择一。
4. 旧正式设计包和两份阶段稿只用于理解背景与识别冲突；未在本包重新表述的内容不属于本方案。
5. 当前仍为设计裁决阶段，不进行游戏开发、测试、工具或运行时代码修改。

## 2. 产品与体验定位

| 项目 | 当前裁决 |
| --- | --- |
| 玩家人数 | `2—4` 人 |
| 单局时长 | `45—60` 分钟 |
| 互动基调 | 竞争为主、合作为辅 |
| 受众与复杂度 | 合家欢，核心规则可理解，构筑保留成长深度 |
| 局内核心目标 | 个人修仙竞速，并通过棋盘事件、战斗、竞价和轻量经营产生互动 |
| 回合特征 | 同时规划、同步移动、统一行动结算 |
| 主题结构 | 通用棋盘框架承载多个主题；首个主题为飞升胜利 |

## 3. 核心单局循环

```text
回合开始即时行动
→ 隐藏规划目的地、路线、移动方式和主要行动类型
→ 同步移动与相遇记录
→ 抵达后补充行动参数
→ 独立结算或玩家竞争
→ 回合末自动修炼、恢复、炼化、寿元与世界结算
→ 检查飞升共同胜利
```

每个正常回合，每名玩家拥有一次移动和一个主要行动。即时行动只在回合开始开放；在资源、对象和状态合法时可以执行多次，但切换主修每回合最多一次。

移动和主要行动采用两段式承诺：移动前锁定行动类型，抵达后才选择对象、数量或投入。未抵达则行动失效；抵达后无合法参数则行动失败，并从当前地点途中事件池抽取一次独立代偿事件。

## 4. 通用框架与主题边界

通用框架负责：玩家与房间结构、同步回合、移动与行动预算、竞争解算、角色成长、自动战斗、资产流转、主题配置契约及通用信息边界。

主题棋盘负责：胜利目标、初始状态、地图拓扑、地点与事件池、敌人与奖励、境界和属性表、内容投放、主题专有覆盖规则。

主题配置可以在明确声明后覆盖通用参数，但不能默默改变通用规则。每个主题必须自带完整初始状态和内容配置，不能依赖旧包补足。

## 5. 当前核心规则摘要

### 5.1 地图、行动与玩家竞争

- 地图采用六边格与多路线结构；距离、移动骰池、速度和元气成本是不同职责。
- 所有玩家在共享移动时间轴上演算；规划内容在揭示实际结果前对其他玩家隐藏。
- 仇恨是方向性宣战开关；任一方成立即可在相遇时触发相关事件。
- 即时行动当前包括交易、调整装备、服丹、切换主修、查看已知信息和无直接收益的资产整理。
- 当前明确的主要行动包括大境界突破、地区影响力经营、地点专有疗伤、研习功法与飞升；完整行动表仍待 `S-02`。
- 玩家争夺同一目标时可以用战斗或竞价解决；多人竞争形成连续战斗，具体先后由实际到达时间与冲突类型决定。

### 5.2 成长、突破、小洞天与转世

- 普通修炼在回合末自动结算，不占主要行动；大境界突破是主要行动。
- 当前人物属性复用并在本包重述当前世属性语义，排除真灵与执念。
- 系统区分标准 CP 与有效修为；常规规则读取有效修为，换功负责标准 CP 折算。
- 生机归零死亡；神念归零重伤；元气归零不直接战败，但不能执行需要元气的移动。
- 重伤当前禁止切换主修、回合末修炼、大境界突破和飞升；未列入黑名单的行为不得被隐式禁止。
- 大境界突破先判成功率，成功后才进入渡劫战斗；渡劫战斗禁止逃遁。
- 小洞天是事件奖励。一个外界回合推进十个角色内部时间单位，外部世界仍只推进一回合。
- 转世是严重失败惩罚，不是主动循环；知识与掌握进度保留，修为和默认随身资产清空。重返对局与追赶仍待 `S-04`。

### 5.3 道功、法门、招式与法宝

- 角色同时只主修一本道功；法门不占主修位。道功与法门均可一对多提供招式。
- 招式不独立积累经验，而按知识来源的 `0—100` 掌握度解锁、升级并获得阶段倍率。
- 战前构筑为一本道功、最多 `5` 个法门招式位，以及攻击、防御、飞遁三个固定法宝位。
- 所有有效招式进入玩家手动排序的统一列表；换主修后旧道功招式退出，新道功招式追加至末尾。
- 飞遁法宝不提供循环战斗招式，只提供被动、移动或逃遁加成。
- 炼化程度为 `0—100` 整数：`50` 及以下不生效，高于 `50` 时按炼化比例发挥。三个已装配法宝各自随回合增长，小洞天受十倍内部时间影响。
- 法宝易主时按取得途径重新初始化炼化度；本方案不采用绑定机制。

### 5.4 自动战斗与数值边界

- 战斗采用冷却驱动、战前构筑、战中自动执行；没有基础攻击。
- 开战时全部冷却招式先等待一次完整冷却；同一角色同刻就绪时从列表左到右尝试，不可用招式跳过且不阻塞右侧。
- 双方同刻触发由本场战斗随机种子决定先后。
- 普通战斗生机归零死亡、神念归零重伤，`60` 秒超时平局。
- MVP 战斗只包含确定命中的直接伤害、护盾，以及直接伤害增减伤 Buff。
- 护盾只保护生机，每场从 `0` 开始，战后及连续战斗的场间清空。
- 普通逃遁为通用能力，每 `5` 秒可尝试；失败使所有招式当前剩余冷却增加 `1` 秒。飞遁法宝加成受炼化影响，最终成功率允许达到 `100%`。
- 直接伤害、固定元气损伤、吸收、掌握倍率、TTK 与逃遁概率的完整公式只在自动战斗数值文档维护。

### 5.5 资产、死亡掉落与宗门

- 死亡角色的全部随身可转移资产被清空；每件独立物品或每个堆叠单位以 `10%` 独立成为战利品，其余由系统回收。
- 胜利者不能选择具体战利品；无合法玩家胜者时全部回收且不生成地图拾取物。
- 连续战斗只在整段结束后统一结算死亡掉落，战利品归最终胜利者。
- 宗门不承担复杂组织模拟，定位为类似地产经营的地区影响力系统，为个人修仙提供资源或地图控制能力。其是否进入首轮 MVP 及最小闭环仍待 `S-05`。

## 6. 首个主题：飞升胜利

首个主题要求玩家达到大乘，并前往主题指定地点执行无参数“飞升”主要行动。达到大乘时只公告一次当前位置与基础身份，之后恢复普通信息边界。

其他玩家可以在飞升开始前通过合法移动、相遇、战斗、竞价或主题事件阻止玩家抵达；一旦合法飞升行动开始，过程本身不会失败。

同一回合中，彼此不存在阻止关系且均满足条件的玩家可以共同飞升、共同获胜。飞升判定完成后结束对局。

## 8. 当前 MVP 框架判断

现有裁决已经足以确定玩法身份和拆分系统，但还不足以形成可配置 MVP。缺口集中在以下大模块：

1. 目标回合数、境界节奏与初始状态；
2. 完整主要行动表及经济 / 资产闭环；
3. 首张主题地图、地点、事件和奖励；
4. NPC / 敌人、构筑、难度与产出；
5. 死亡转世后的重返对局与追赶；
6. 宗门最小闭环或首轮延期；
7. 房间、时限、未提交、掉线、重连、托管和退出；
8. 正式数值表、内容表和交互信息架构验证。

下一阶段先处理大模块，不继续优先消耗轮次于取整等局部细节。完整阶段门与未来开发准备验收见《[MVP 框架缺口与阶段门](02_MVP框架缺口与阶段门.md)》。
