# 经济系统设计｜物品流转

## 1. 当前结论

经济系统的核心不是完整市场模拟，而是资源流转与资产可信系统：

```text
行动格 / 风险 / 权限 / 宗门行动
→ 获得资源、物品、灵石、情报或控制权
→ 投入修炼、突破、战斗、建设、探索、后手
→ 提高个人与宗门资源获取效率
→ 接触更高阶资源窗口
→ 死亡、转世、遗产、后手与世界演化继续改变资源分布
```

## 2. 资产容器

| 容器 | 含义 |
| --- | --- |
| CharacterInventory | 角色 / 高层 NPC 随身资产 |
| CharacterStorage | 角色个人储藏、洞府、临时藏物点 |
| SectStorage | 宗门库存 |
| NodeStorage | 节点储藏 |
| ShopStock | 店铺库存 |
| MarketListing | 市场挂牌 |
| EventLocked | 事件锁定资产 |
| SealedLegacy | 正式后手封存 |
| ResourcePool | 聚合资源池 |

## 3. 个人资产与机构资产分离

错误口径：掌柜 = 商店库存持有人；宗主 = 全宗库房持有人。

正确口径：掌柜是 ShopStock 服务入口；宗主是 SectStorage 权限影响者；村长是 NodeStorage / PopulationPool 的代表。

## 4. 可堆叠与实例物品

不设计“半可堆叠”物品。规则层明确为：

```text
可堆叠物品
或
独立实例物品
```

堆叠键：

```text
item_template + tier + quality + key_state_tags + bind_state + owner_restriction
```

如果字段影响战斗、突破、交易、后手或消耗结果，则进入堆叠键；如果只是风味来源，不拆分堆叠。

## 5. 流转请求

```yaml
AssetTransferRequest:
  actor_ref: string
  source_container_ref: string
  target_container_ref: string
  asset_refs_or_query: object
  amount: number
  transfer_reason: string
  permission_context: object
  allow_partial: bool
```

## 6. 缺口

- 市场挂牌、寄售、税费、交易价格公式未定。
- 拆解、修复、封存、销毁和继承的具体模板未定。
- 玩家交易不进入 MVP 核心，仅作为未来低成本附加能力。
