## 1. 本交付包用途

本交付包是后续开发排期、原型实现、数据契约、验收与 QA 的当前本地依据。核心口径：

```
共享日历房间
+ 自适应流速推进
+ 当前执行指令 + 最多 3 条预输入指令
+ 自动兜底与显式托管分离
+ 个人局部时停 + C1 追赶补结算
+ 正式交锋 / 突破挑战 B1 交锋轮
+ 宗门 AI 自行演化
+ 完整功法载体学习与掌握度成长
+ 丹药 / 灵材 / 符箓作为行动资源输入
+ 权威服务器小时 tick 与结果包回写
```

底层时间事实：

```
1 游戏日 = 24 游戏小时
服务器最小结算单位 = 1 游戏小时
主时间字段 = world_day / world_hour
公开速度档位 = F1 / N1 / B1 / P0
内部追赶机制 = C1
```

当前包不引入现有 Figma 主界面稿作为版面依据。Figma 相关内容将在本包交付后另行迭代；本包中的 UI/UX 文档只描述稳定交互规则、信息结构、速度展示和队列控件要求。

## 5. 当前滚动落地与维护事项

本项目已进入数值设计与系统设计相互验证阶段。以下事项不再作为统一后置项或暂不处理项；涉及行动、修炼、根骨、事件、功法、物品、节点、突破和战斗的模型、公式、模板与样例数值，应随验证逐步写回对应 v2.3 原文档，并同步记录到 `CHANGELOG.md`。

### 5.1 数值与系统设计滚动落地

1. 行动模板的实际耗时、收益、风险曲线，以及 `long_low_interaction`、`f1_eligible_when_explicit`、兜底适配等标签。
2. 修为数值曲线、根骨承载公式、境界阈值、突破消耗和资源输入模板样例数值。
3. 宗门 AI 选择持续行动的具体权重表、触发条件和收益 / 风险反馈。
4. 事件模板脚本格式、内容管线、低价值事件白名单、24 小时 gap 默认选项与 P0 同步保护事件清单。
5. 节点风险等级、资源槽刷新、机会窗口、C1 确定性字段白名单与 B1 交锋模板表。
6. 功法载体、物品、丹药 / 灵材 / 符箓输入、`ActiveResourceEffect` 残余策略的样例数据。

### 5.2 工程与原型后续确认

1. SQLite / Godot Resource / JSON / 混合存档方案最终选择。
2. Figma 视觉稿、交互原型与 Godot 组件拆分。

工程与原型项不改变当前数值模型、公式、事件、功法和物品设计需要逐步落地的口径。
