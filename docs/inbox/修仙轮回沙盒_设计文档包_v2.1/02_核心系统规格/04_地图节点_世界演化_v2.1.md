# 地图节点与沙盒世界演化（v2.1）

## 0. 文档定位

本文整理地图节点、资源槽、建筑槽、控制权、区域、秘境入口、世界初始生成和世界演化规则。

实现重点：地图不是静态菜单，而是用于承载个人行动、宗门 AI 持续行动、资源流转、事件压力、秘境窗口和后手隐藏层的状态机。

---

## 1. 核心定位

沙盒世界演化不是完整生态模拟，而是一个由地图节点模板、资源池、灵气环境、宗门 AI、事件压力、秘境窗口和后手隐藏层共同驱动的状态机。

玩家应感受到：

1. 地图节点会因宗门、资源、事件、灵气和玩家行动改变。
2. 宗门通过 AI 持续行动、节点控制、资源争夺和事件响应改变世界格局。
3. 资源来自节点产能、秘境窗口、事件预算、后手封存或库存转移。
4. 灵气、危险、秘境、妖兽、突破、资源、宗门争夺之间存在可解释关联。
5. 正式后手嵌入世界演化，但不会无日志、无原因地失效。

---

## 2. 地图基础结构

地图采用有向带权节点图。

```text
MapGraph {
  nodes: Dictionary,
  directed_edges: Array,
  route_states: Dictionary,
  hidden_routes: Array,
  global_region_tags: Array
}
```

边可以支持：

- 双向但成本不同。
- 单向门。
- 权限门。
- 状态门。
- 风险门。
- 隐藏路线。
- 临时通道。

S3 读取可达性、通行耗时和路线状态；S8 不直接决定玩家行动计划。

### 2.1 路线字段

```text
RouteEdge {
  edge_id: String,
  from_node: String,
  to_node: String,
  base_travel_hours: int,
  travel_mode_modifiers: Dictionary,
  risk_tags: Array,
  permission_rules: Dictionary,
  state_tags: Array,
  hidden_state: String
}
```

旧 `base_cost_slots` 废弃。

## 3. 世界状态结构

```text
WorldState {
  world_seed: int,
  current_turn_id: int,
  current_world_day: int,
  current_world_hour: int,
  current_macro_period_id: String,
  regions: Dictionary,
  map_graph: MapGraph,
  factions: Dictionary,
  resource_budgets: Dictionary,
  event_pressure_state: Dictionary,
  active_major_events: Array,
  temporary_nodes: Dictionary,
  rumor_pool: Array,
  world_logs: Array
}
```

说明：

- `current_turn_id` 是玩家同步回合。
- `current_macro_period_id` 是资源再生、世界大刷新、N4 宏观行动等较大周期。
- 不把所有世界宏观变化都绑定到每 5 天一次。

## 4. 节点结构

```text
WorldNode {
  node_id: String,
  display_name_key: String,
  node_type: String,
  region_id: String,
  zone_tier: String,
  recommended_stage_range: Array,

  visible_state: Dictionary,
  danger_profile: Dictionary,
  aura_profile: Dictionary,

  control_owner_faction_id: String,
  node_influence_by_faction: Dictionary,
  garrison_state: Dictionary,

  resource_slots: Array,
  building_slots: Array,
  event_slots: Array,
  entrance_slots: Array,
  hidden_layers: Array,
  legacy_layers: Array,

  route_connections: Array,
  node_state_tags: Array,
  cooldown_tags: Array,
  world_log_refs: Array
}
```

关键字段：

| 字段 | 含义 |
|---|---|
| `zone_tier` | 节点所在区域内容阶层，使用 A / B / C 等抽象编码 |
| `recommended_stage_range` | 推荐接触阶段，只用于内容筛选和提示，不作为硬锁 |
| `danger_profile` | 危险结构，例如妖兽、匪修、宗门冲突、灾害、秘境波动 |
| `aura_profile` | 背景灵气与灵气质量 |
| `entrance_slots` | 临时秘境入口、洞府入口、异常空间入口 |
| `node_state_tags` | 当前态势，如 contested、resource_stressed、aura_surge |
| `cooldown_tags` | 防止同类事件短期重复爆发 |

## 5. MVP 节点类型

MVP 建议支持：

1. 宗门山门节点。
2. 城镇 / 坊市节点。
3. 村庄 / 凡人聚落节点。
4. 资源型地理节点。
5. 荒野探索节点。
6. 秘境入口节点。
7. 前世后手节点 / 隐藏层。
8. 禁地 / 高危节点。
9. 道路 / 山道 / 渡口 / 交通设施节点。

第一阶段中的青禾村、镇集、镇集武馆、云麓山道、云麓宗山门均可映射为这些类型。

## 6. 区域层结构

区域不是行政区，而是地图生成与事件演化的中层容器。

```text
RegionState {
  region_id: String,
  display_name_key: String,
  region_type: String,
  zone_tier: String,
  base_aura_band: String,
  base_danger_band: String,
  climate_or_terrain_tags: Array,
  dominant_factions: Array,
  region_pressure_tags: Array,
  major_event_slots: Array,
  resource_budget_refs: Array
}
```

MVP 区域至少包含：

1. 新手 / 凡俗边缘区。
2. 宗门腹地区。
3. 边界 / 荒野 / 禁地区。

## 7. 资源槽

资源槽代表节点自然或半自然产出。

```text
ResourceSlot {
  slot_id: String,
  resource_type: String,
  abundance_state: String,
  extraction_difficulty: String,
  regeneration_rule: Dictionary,
  controlling_faction_bonus: Dictionary,
  depletion_risk: Dictionary,
  discovery_state: String
}
```

规则：

- 自然资源点原则上先产出资源池 / 资源量，不直接产出具体物品。
- 通过采集、开采、加工、炼制、修复等行动转化为宗门资源或材料物品。
- 枯竭、再生、污染、异变按节点模板配置，不做统一生态公式。
- 已控制资源节点的基础产出走常态结算，不占宗门唯一持续行动槽。
- 资源再生可以按 `macro_period_id` 推进，不必每回合都刷新。

## 8. 建筑槽

建筑槽代表人工建设、宗门设施或特殊功能。

```text
BuildingSlot {
  building_id: String,
  building_type: String,
  owner_faction: String,
  construction_state: String,
  level_or_quality: String,
  function_tags: Array,
  damage_state: String,
  access_permissions: Array
}
```

建筑可被：

- 建设。
- 修复。
- 占领。
- 损坏。
- 废弃。
- 用作聚灵阵、防御阵、炼丹炉、炼器炉等设施。

MVP 启用建筑 / 设施维护成本：设施工作时需要消耗维护成本。MVP 不引入复杂折旧曲线和自然磨损压力。

## 9. 控制权与影响力

节点归属采用：

```text
控制权 + 影响力
```

控制权决定：

- 主资源收益权。
- 建设权。
- 驻守权。
- 通行管理权。
- 节点事件优先响应权。

影响力决定：

- 行动耗时与便利。
- 情报发现率。
- 任务成功率。
- 探索与交易便利。
- 控制权争夺基础。
- 对控制者收益的轻微竞争。

控制权变更采用阈值 + 事件模型。玩家不需要逐个节点点击接管。

推动因素：

- 玩家探索、驻守、建设、开采。
- 玩家处理节点事件。
- 玩家亲自参与宗门相关个人行动。
- 宗门 AI 持续行动。
- 外部 AI 宗门压力。
- 节点危机或重大事件链。

达到条件后，S10 触发控制权变更事件。

## 10. 隐藏层与后手层

### 10.1 隐藏层

隐藏层用于承载：

- 隐藏资源。
- 旧洞府。
- 线索。
- 秘境入口。
- 伏笔事件。
- 前世痕迹。

### 10.2 后手层

正式后手挂入节点后手层。

规则：

- 后手必须有位置。
- 后手必须写入世界日志和轮回账本。
- 后手风险只在相关节点发生明确变化时检定。
- 不做每回合随机磨损。
- 不引入年久失修型低频随机风险。

---

## 11. 秘境入口与临时节点

普通临时秘境入口通过 `EntranceSlot` 表达；少数著名秘境可作为常驻高危节点。

规则：

- 普通秘境：常驻节点上的入口槽，开启后生成临时节点或子图。
- 著名秘境：可作为长期显示的世界地标。
- 内部空间、进入窗口、探索阶段和关闭状态仍由 EntranceSlot、TemporaryNode 和事件链管理。

```text
TemporaryNode {
  temp_node_id: String,
  parent_node_id: String,
  created_turn_id: int,
  created_world_day: int,
  expiry_rule: Dictionary,
  access_rules: Dictionary,
  event_chain_refs: Array,
  cleanup_rules: Dictionary
}
```

## 12. 世界演化节奏

玩家回合不等于世界宏观刷新。

推荐节奏：

```text
小时：移动、行动、事件、状态变化。
天：UI 预算条、短期行动摘要、部分状态检查。
回合：玩家同步输入与结算单位。
宏观周期：资源再生、市场常规变化、宗门战略变化、N4 宏观行动。
特殊窗口：秘境、突破资源名额、节点危机等按事件规则开启。
```

这样可以避免把 5 天回合误用为所有世界系统的刷新周期。
