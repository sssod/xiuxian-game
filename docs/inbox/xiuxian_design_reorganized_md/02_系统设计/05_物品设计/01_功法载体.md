# 系统设计｜功法载体

## 1. 设计定位

功法载体是功法内容在物品层的存在形式。本文负责回答功法内容如何以物品形式被获得、保存、合成、转移、学习引用和封存为后手，不负责功法模板、角色已学状态或掌握度成长本身。

本文只处理“功法内容如何以物品形式存在、转移、合成和成为学习来源”。道功的修为路线、上限、主动吐纳和突破路线由《道功》（`../04_功法设计/01_道功.md`）维护；法门的能力、指令、事件选项和效率修正由《法门》（`../04_功法设计/02_法门.md`）维护；角色主修道功的设置、切换、锁定和更换窗口由《角色主修功法》（`../02_角色与真灵设计/04_角色主修功法.md`）维护；功法数值模板、掌握曲线和公式接口由《功法设计基准建模》（`../../03_数值设计/05_功法设计基准建模.md`）维护。

功法载体需要服务：

1. 功法内容投放、收集和合成。
2. 完整功法学习入口。
3. 背包、库存、宗门库存、交易、借阅和封存等资产流转。
4. 宗门外个人洞府、普通藏宝和真灵藏宝等后手规则。
5. 功法页面与储物空间页面对残页、篇章、完整功法和已学功法的区分展示。

## 2. 当前结论

1. 功法模板、功法载体和角色已学功法状态必须分离；拥有完整功法载体不等于角色已经学会功法。
2. 功法投放采用“残页 -> 篇章 -> 完整功法”的三层载体链，整理包内不再保留其它不完整内容称谓作为 active 概念。
3. 残页和篇章都是不可学习的内容资产，只能用于合成、线索、权限、任务推进或投放展示，不创建 `MethodState`。
4. 完整功法是唯一常规可学习来源；学习后创建 `MethodState`，默认不消耗载体。
5. 残页合成篇章、篇章合成完整功法属于物品合成，不属于研习功法；MVP 默认作为个人即时整理操作，不占用行动执行时间预算。
6. 学会功法后，载体仍可以作为物品保留、转移、封存、借阅、交易或成为后手资产；高价值载体应保留可追溯资产日志。

## 4. 核心循环或触发入口

功法载体围绕“获得、归属、合成、学习引用、资产留存、转移封存”循环维护。

```text
获得残页 / 篇章 / 完整功法
-> 进入背包、库存、宗门库存、藏宝或事件锁定容器
-> 残页合成篇章，篇章合成完整功法
-> 完整功法作为学习来源
-> 学会功法后创建 MethodState
-> 载体继续作为物品保留、转移、封存、借阅、交易或损坏
```

常见触发入口：

1. 新手家庭、村镇支持、教学事件、宗门发放、藏经阁权限、讲经、师承或任务奖励。
2. 节点探索、遗迹、秘境窗口、隐藏层、世界事件和战斗 / 危机事件产出。
3. NPC 交易、拍卖、交换、夺取、宗门库存、宗门配给或组织资源转化。
4. 前世真灵藏宝、宗门外藏物开启、宗门遗产清点、普通宝藏或线索兑现。
5. 玩家在储物空间中执行残页合成、篇章合成、借阅、封存、转移、上交或交易操作。

中断点包括载体不完整、缺少目标篇章、权限不足、容器不可访问、载体已封印 / 损毁 / 借出 / 绑定、学习目标不是道功或法门、角色状态禁止研习、后手容量限制不足和资产转移规则不允许。

## 5. 规则与状态

### 5.1 三层载体链

功法投放采用三层载体链：

```text
残页
-> 篇章
-> 完整功法
-> 学会功法
-> 研习功法提升掌握度
```

整理包内只保留三层功法投放概念：

| 概念 | 当前口径 |
| --- | --- |
| 残页 | 最小碎片，按目标篇章归类 |
| 篇章 | 中间完整内容，用于合成完整功法 |
| 完整功法 | 唯一常规可学习来源，在物品层以可学习载体存在 |

旧文档中其它不完整内容称谓不再保留为整理包概念：

| 旧称 / 泛称 | 当前处理 |
| --- | --- |
| 不完整功法碎片 | 迁为残页 |
| 中间完整内容 | 迁为篇章 |
| 可学习的完整内容 | 迁为完整功法 |
| 学会一部分功法 | 废弃表达，不能用于残页或篇章 |

### 5.2 模板、载体与掌握状态分离

功法模板、功法载体和角色掌握状态必须分离：

```text
DaoMethod / TechniqueMethod：规则层功法模板
MethodCarrier：物品层功法载体
MethodState：角色学会后的掌握状态
```

规则：

1. 功法模板不是背包物品，不保存拥有者、损毁、封印、借阅或交易状态。
2. 功法载体是物品资产，不保存角色掌握经验、掌握等级、主修状态或研习进度。
3. `MethodState` 表示角色学会后的掌握状态，不保存残页或篇章收集进度。
4. 玩家拥有完整功法载体，不等于角色已经学会功法。
5. 角色学会功法后，掌握状态与载体分离；载体仍可以保留、转移、封存、借阅、交易或成为后手资产。

### 5.3 残页

残页是可合成道具，不可学习。

规则：

1. 不创建 `MethodState`。
2. 不可设为研习目标。
3. 不直接解锁功法效果。
4. 不直接提高道功或法门掌握度。
5. 只参与合成篇章、线索追踪、任务推进或内容投放。
6. 残页按目标篇章归类，不做精确页码编号。

示例：

```text
《青木养真诀·引木气残页》× 4
-> 《青木养真诀·引木气篇章》
```

不做：

```text
必须集齐第 1 页、第 2 页、第 3 页、第 4 页。
```

### 5.4 篇章

篇章是比残页更完整的中间内容资产，仍然不可学习。

规则：

1. 不创建 `MethodState`。
2. 不可设为研习目标。
3. 不直接作为主修道功内容。
4. 不直接解锁法门能力。
5. 不表达“已学会一部分功法”。
6. 只参与合成完整功法、线索追踪、任务推进或权限展示。
7. 篇章合成完整功法时需要精确篇章。

示例：

```text
引木气篇
养生机篇
藏真元篇
木脉生息篇
-> 《青木养真诀完整玉简》
```

### 5.5 完整功法

完整功法是唯一常规可学习来源，在物品层以完整的功法载体存在。

规则：

1. 可作为学习来源。
2. 可用于研习入门。
3. 入门后创建 `MethodState`。
4. 默认学习时不消耗载体。
5. 高价值道功对应的可学习载体默认使用 `ItemInstance`。
6. 普通低阶法门对应的可学习载体可使用 `ItemStack`。
7. 高价值、唯一、有来源历史、可封存为后手或带独立状态的法门载体也应使用 `ItemInstance`。

特殊例外预留：

```text
一次性传功玉简：consume_on_learn = true
```

MVP 默认不做一次性消耗。

### 5.6 合成归属与耗时

功法合成属于物品系统，不属于研习功法。

```text
残页合成篇章：Item Synthesis / Recipe
篇章合成完整功法：Item Synthesis / Recipe
研习功法：学习完整功法或提升已学功法掌握度
```

研习功法不负责：

1. 修复残页。
2. 校勘错漏。
3. 推演缺失内容。
4. 创造功法。
5. 融合功法。
6. 把残页或篇章直接变成可用内容。

MVP 中，残页合成篇章、篇章合成完整功法默认归类为个人即时物品整理操作，不占用行动执行时间预算。残页和篇章的获得已经通过探索、任务、交易、宗门权限、秘境或后手支付了时间与资源成本，合成本身不再追加低价值摩擦。

未来可扩展为需要设施、导师、权限、固定处理时间或风险校验的高阶操作：

1. 高阶功法校订。
2. 功法誊抄。
3. 装订封印。
4. 传承洗练。
5. 禁制修复。

这些扩展仍属于物品合成或传承处理，不属于研习功法。

### 5.7 获取与投放来源

功法载体可以来自：

1. 新手家庭、村镇支持或教学事件发放基础功法载体。
2. 宗门发放、藏经阁权限、讲经、师承或任务奖励。
3. 节点探索、遗迹、秘境窗口和隐藏层。
4. NPC 交易、拍卖、交换或夺取。
5. 宗门库存、宗门配给或组织资源转化。
6. 前世真灵藏宝、宗门外藏物开启、宗门遗产清点或线索兑现。
7. 普通宝藏、世界事件、战斗 / 危机事件产出。

残页和篇章适合作为探索、任务、权限、线索和内容收集资产。完整功法适合作为正式学习入口、宗门资源、交易物、高价值后手或世界稀有物。

### 5.8 资产、转移与后手

功法载体属于资产容器中的物品，必须与已学功法状态分离。

规则：

1. 普通低阶完整法门载体可以堆叠。
2. 高价值道功对应的可学习载体应为实例物品。
3. 带独立来源、历史、绑定、封印、损毁、拓印、借阅、唯一性或后手价值的载体应为实例物品。
4. 高价值功法载体转移、上交、借阅、封存、交易、损坏或消耗应写入资产日志。
5. 学会功法后，载体默认仍保留为物品；角色掌握状态由 `MethodState` 保存。
6. 功法掌握状态可以作为宗门外个人洞府或普通藏宝的开启条件，但不等于自动取得其中资产。
7. 功法载体若封存为真灵藏宝，必须占用正式后手的数量或单个容量限制。
8. 宗门个人洞府中的功法载体可随遗产清点回收宗门；宗门外藏物中的功法载体作为无主遗留设施资产，需要满足开启条件或破阵结果后才能取出。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 道功 / 法门模板 | 读取 `method_id`、`method_type`、阶级、品级、学习条件和可学习目标；不写入功法模板 |
| `MethodState` | 完整功法学习后创建或引用角色已学状态；残页和篇章不得创建 `MethodState` |
| 背包、库存和资产容器 | 保存功法载体堆叠、实例、归属、封存、借阅、损毁和转移状态 |
| 物品合成 | 读取残页、篇章、合成配方、权限和处理策略，输出篇章或完整功法载体 |
| 地图、事件和投放 | 输出残页、篇章、完整功法或线索；不直接写入角色掌握度 |
| 新手与宗门 | 可以发放基础功法载体，或通过教学、师承、宗门例外直接授予 learned level 1；该例外不代表残页或篇章可学习 |
| 交易、NPC 和宗门库存 | 读取功法载体价值、稀有度、实例化和来源日志，用于交易、借阅、上交、夺取和库存清点 |
| 真灵藏宝、个人洞府和普通藏宝 | 可保存功法载体，或以已学功法、功法阶段、掌握度作为开启条件；资产取出仍需校验地点、线索、钥匙、事件状态和阵法状态 |
| 功法页面和储物空间页面 | 展示载体类型、学习可用性、合成入口、资产状态和不可用原因 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `MethodCarrierTemplate` | 功法载体模板，定义载体类型、目标功法、是否可学习、合成关系和堆叠策略 |
| `MethodCarrierInstance` | 独立实例载体，记录归属、状态、来源、封印、绑定、借阅或后手信息 |
| `MethodCarrierRecipe` | 功法载体合成配方，记录输入、输出、权限、设施、导师、耗时和风险策略 |
| `carrier_type` | 载体类型：残页、篇章或完整功法 |
| `method_id` / `method_type` | 指向目标道功或法门模板 |
| `is_learnable` | 是否可作为学习来源；残页和篇章为 false，完整功法通常为 true |
| `creates_method_state` | 学习后是否创建 `MethodState` |
| `consume_on_learn` | 学习时是否消耗载体；MVP 默认 false |

## 8. UI 展示边界

普通 UI 应展示：

1. 功法载体是残页、篇章还是完整功法。
2. 残页和篇章的目标功法、目标篇章、合成进度和缺失内容。
3. 完整功法是否可研习入门，以及不可学习原因。
4. 学习后是否消耗载体；MVP 默认不消耗。
5. 载体归属、封印、损毁、绑定、借阅、后手封存、交易限制和高价值确认。
6. 学会功法后的 `MethodState` 与背包内载体是两个不同对象。

推荐表达：

| 物品 | UI 状态 |
| --- | --- |
| 残页 | 不可学习；用于合成篇章 |
| 篇章 | 不可学习；用于合成完整功法 |
| 完整功法 | 可研习入门；入门后生成 `MethodState` |
| 已学功法 | 已生成 `MethodState`；不再依赖背包内载体作为学习进度 |

普通 UI 不应展示：

1. 把残页或篇章表达为“已学会一部分功法”。
2. 把残页、篇章或完整功法载体表达为角色掌握等级。
3. 把合成操作伪装成研习功法或主修更换。
4. 内部模板 ID、配方 ID、来源追踪 ID、资产流水 ID 或 Debug 预算字段。
5. 未揭示藏物、宗门权限或隐藏事件的完整真相。

## 9. MVP 范围

MVP 应实现：

1. 三层载体类型：残页、篇章、完整功法。
2. 残页合成篇章、篇章合成完整功法。
3. 残页和篇章不可学习，不创建 `MethodState`。
4. 完整功法可作为学习来源，入门后创建 `MethodState`。
5. 学习完整功法默认不消耗载体。
6. 残页和篇章合成默认为个人即时整理操作，不占用行动执行时间预算。
7. 普通低阶载体可堆叠，高价值、唯一、封存、借阅或带来源历史的载体实例化。
8. 高价值功法载体的转移、交易、封存、借阅、损坏和消耗写入可追溯日志。
9. 功法页面和储物空间页面区分残页、篇章、完整功法和已学功法。

MVP 不实现：

1. 精确页码收集。
2. 一次性传功玉简消耗。
3. 需要设施、导师、固定处理时间或风险校验的高阶校订 / 誊抄 / 禁制修复。
4. 功法推演、创造、融合或用研习补全残页 / 篇章。
5. 残页或篇章直接学习道功或法门。
6. 残页或篇章直接补足主修道功进度。
7. 复杂拓印、版权、借阅期限和宗门法契细则。

## 10. 验收约束

1. 包内文档引用功法载体系统层时，应以本文为残页、篇章、完整功法和载体资产规则来源。
2. 残页和篇章不得创建 `MethodState`，不得作为研习目标，不得直接提升道功或法门掌握度。
3. 完整功法是唯一常规可学习来源；教学、师承、宗门或事件直接授予 learned level 1 必须显式标记为例外。
4. 学会功法后，载体和 `MethodState` 必须继续分离。
5. 合成残页 / 篇章属于物品合成，不得占用研习功法逻辑或主修更换逻辑。
6. UI 不得把残页或篇章表达为“已学会一部分功法”。
7. 高价值、唯一、有来源历史、可封存为后手或带独立状态的功法载体必须作为实例物品处理。
8. 功法载体若封存为真灵藏宝，必须占用正式后手的数量或单个容量限制。
9. 功法掌握状态可以作为藏宝或洞府开启条件，但不等于自动取得其中资产。
10. 功法载体的数值、品级、预算、投放概率和学习掌握曲线不得在本文重复维护，应指向数值文档。
