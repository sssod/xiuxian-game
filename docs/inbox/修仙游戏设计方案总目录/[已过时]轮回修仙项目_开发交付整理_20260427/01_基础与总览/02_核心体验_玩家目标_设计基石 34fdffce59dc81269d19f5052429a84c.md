# 02_核心体验_玩家目标_设计基石

# 核心体验、玩家目标与设计基石

## 0. 文档定位

本文整理核心体验层内容，用于约束后续系统、数值、UI 和内容生产。

系统实现时不要把本文当成数值表；本文只定义“为什么玩家会觉得这个游戏成立”。

## 1. 核心体验总命题

玩家长期追求的不是单一战斗力，而是跨世叠加后的资源获取效率。

```
修为提升
→ 接触更高阶资源
→ 提高单位行动格收益
→ 增强生存和事件处理能力
→ 获得更高宗门权限
→ 调动组织资源
→ 布置更高质量后手
→ 失败或死亡后转化为下一世更优起点
```

因此，战斗、非战斗能力、功法、宗门职位、资质、法宝、后手、地图控制，本质上都应回到同一问题：

> 它是否让玩家在本世或下一世更高效地获取、保存、转化或保护资源？
> 

## 2. 主循环：个人成长

```
修炼
→ 到达瓶颈
→ 准备突破
→ 尝试突破
→ 成功进入更高阶段
→ 获得更高资源获取效率
→ 接触更高风险与更高价值窗口
→ 继续修炼
```

修炼不是简单填经验条。它是玩家将地点灵气、丹药药力、宗门资源、功法效率、角色资质、时间行动格共同转化为修为和功法成长的过程。

突破不是简单升级按钮。它是对玩家前一阶段路线选择、资源积累、风险控制、宗门支持、地点选择、功法匹配的集中审判。

## 3. 负反馈循环：失败与转世

核心负反馈链路：

```
尝试突破
→ 突破失败
→ 本世受损、停滞或死亡
→ 转世重修
→ 使用前世资源、失败标签、后手、账本信息塑造更好基础
→ 更高效率地回到同等修为
→ 再次冲击瓶颈
```

突破失败不应只是惩罚。它必须同时产生：

- 明确失败原因标签。
- 下一世可执行的修正方向。
- 轮回账本记录。
- 可能的后手回收目标。
- 对路线、功法、资源、突破地点、宗门关系的新理解。

理想玩家感受：

> 这一世没过关，但我知道为什么没过关。下一世我能更快回来，并用更好的基础重试。
> 

## 4. 三条并行成长线

### 4.1 当世角色成长

当世角色负责承担本世行动后果，包括：

- 修为阶段。
- 功法等级。
- 生机、元气、神念。
- 宗门身份与关系。
- 当世库存。
- 伤势、状态、寿元压力。
- 本世探索信息。

当世角色死亡后，大部分内容不默认跨世继承。

### 4.2 真灵长期成长

真灵负责长期身份感和跨世容量，包括：

- 真名。
- 真灵强度。
- 执念容量。
- 正式后手容量。
- 轮回履历。
- 道韵。
- 后手感应。

真灵强度不直接稳定提高每世修炼速度。它主要提高执念容量与正式后手容量，避免与资质和功法形成重复收益。

### 4.3 世界与宗门成长

世界不是背景菜单，而是状态机会变化：

- 节点控制权变化。
- 资源槽丰度、枯竭、污染、异变。
- 建筑建设、损坏、维护。
- 秘境窗口开启或关闭。
- 宗门库存与声望变化。
- 传闻传播。
- 正式后手暴露或被干扰。

玩家和 AI 宗门共同推动世界演化。

## 5. 宗门的体验定位

宗门不是玩家本体，而是组织性资源平台。

玩家应感受到：

- 初期宗门提供庇护、基础功法、任务和最低资源入口。
- 中期玩家通过贡献、声望、职位和关键关系获得更多资源与权限。
- 后期玩家可以影响宗门主行动、节点控制、资源分配和突破支持。
- 玩家死亡或转世后，宗门仍然作为世界组织存在。

宗门系统不能变成纯经营游戏。宗门应服务个人成长、资源争夺、突破准备和沙盒演化。

## 6. 地图和世界的体验定位

地图节点应是有决策意义的地点，而不是纯地理填充。

节点有价值的原因包括：

- 影响移动成本、危险和路线。
- 挂载资源槽、建筑槽、事件槽、隐藏层、后手层。
- 是宗门控制、影响力争夺或行动目标。
- 是玩家修炼、交易、探索、突破、回收后手的地点。
- 是传闻、秘境、重大事件或地图认知的锚点。

世界演化不追求完整生态模拟，而是通过节点状态、宗门行动、事件压力、资源变化和传闻构成低成本活世界。

## 7. 物品和经济的体验定位

物品不是单纯奖励图标。获得物品后，玩家应自然产生选择：

- 自己使用。
- 上交宗门。
- 出售或交换。
- 修复、炼制、拆解。
- 储存为突破准备。
- 作为正式后手封存。
- 用于事件选择或战斗指令。

物品价值也应围绕资源效率建模：

- 提高修炼效率。
- 降低突破风险。
- 提高战斗结算质量。
- 增加行动成功率。
- 提高宗门产出。
- 支撑跨世后手。

## 8. 事件的体验定位

常规事件的本质是：

> 系统抛出一个局面问题，玩家通过选项表达解题姿态，并承担后果。
> 

事件不能只是阅读文本，也不能只做暗骰。选项应代表不同解题姿态：

- 正面应对。
- 出奇制胜。
- 逃避推诿。
- 解构问题。
- 欺诈蒙骗。

常规事件主选项区控制在 1–3 个。高级、稀有、解释成本高的选项可以放入溢出区。

## 9. 战斗的体验定位

战斗 / 斗法不是独立战棋，也不是实时操作，而是高风险事件链中的轻量结算框架。

玩家体验重点：

```
观察局面
→ 判断敌方风格和事件目标
→ 预输入指令序列
→ 通过克制、消耗和资源管理影响结果
→ 将结果回写事件链和季度行动
```

战斗应提供“预判、克制、消耗管理、后果承担”，不应变成高频刷怪系统。

## 10. 多人的体验定位

MVP 多人默认：

```
分宗并行 + 间接竞争 + PvE 沙盒演化
```

多人不以直接社交、直接合作或直接 PvP 为核心验证目标。

允许的压力来自：

- 宗门节点控制竞争。
- 秘境 / 突破支持 / 高级修炼场地等资源名额竞争。
- 其他玩家所属宗门改变世界格局。
- 传闻和可见性带来的认知差异。

禁止 MVP 核心化的内容：

- 玩家直接斗法。
- 直接交易和赠予。
- 互相护法。
- 破坏他人突破。
- 离线袭击玩家主体。
- 抢夺玩家洞府。

## 11. 设计判断基准

后续新增功能应通过以下判断：

1. 是否强化跨世主体感？
2. 是否制造有意义的行动格取舍？
3. 是否服务突破准备、失败复盘或转世优化？
4. 是否增强宗门作为组织资源平台的存在感？
5. 是否让世界节点产生可追踪变化？
6. 是否能在 MVP 中低成本验证？
7. 是否有日志、结果包和服务器权威结算路径？

不满足这些标准的功能，即使题材上很合适，也应推迟。
