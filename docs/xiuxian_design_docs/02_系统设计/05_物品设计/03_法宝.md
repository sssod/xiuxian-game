# 系统设计｜法宝

## 1. 设计定位

本文维护法宝作为高价值实例物品的系统规则。法宝可以参与战斗、事件、防护、突破支持、移动、后手封存、遗产分配、修复拆解和资源循环，但它不是装备栏插槽、固定战力挂件或通用背包容量系统。

旧资料中出现的“法器”如未专指另一个低阶物品品类，当前先并入“法宝”口径；后续若需要区分法器、灵器、法宝等阶层，应在法宝模板表中作为品类或阶层字段拆分，不另开并行系统。

法宝进入后手、遗产、宗门回收或无主藏宝时不改变资产规则：宗门个人洞府中的法宝可随遗产清点回收宗门；宗门外洞府或普通藏宝中的法宝属于无主遗留设施资产，需要开启条件或破阵结果才能取出；真灵藏宝中的法宝作为正式后手时，必须占用真灵藏宝数量或容量限制。

## 2. 当前结论

1. 法宝是 `ItemInstance` 的高价值特殊用法，必须追踪来源、容器、状态、归属、可见性和日志。
2. 法宝可用性不由装备位或物品栏格子决定，而由随身状态、上下文、标签、权限、绑定、状态、耐久、充能和资源消耗共同决定。
3. 法宝至少分为主动型、被动型、辅助型和储物空间法宝概念；主动 / 被动法宝可作为 MVP 最小闭环，储物空间法宝在 MVP 只保留概念。
4. 法宝不是完整装备耐久系统；MVP 只维护法宝自身状态变化、结果回写和必要修复 / 回收接口。
5. 角色绑定不是独立法宝类型，也不进入 `artifact_kind`；它只是法宝实例上的绑定状态标记。
6. 法宝对角色施加的持续影响，应交给《角色持续状态系统》（`../02_角色与真灵设计/07_角色持续状态系统.md`）统一管理。
7. 正式后手不等于死亡后自动继承全部法宝；只有已封存进真灵藏宝并满足开启条件的法宝，才按正式后手取出。

## 4. 核心循环或触发入口

法宝围绕“获得、存放、调用、校验、触发、状态回写、资源循环、后手 / 遗产处理”循环维护。

```text
获得或生成法宝实例
-> 进入角色随身、储藏、宗门库存、NPC 持有、节点资源、事件奖励、藏宝或后手容器
-> 行动、战斗、事件、突破、移动或 UI 请求调用法宝
-> 执行前校验容器、权限、上下文、绑定、状态、资源和标签
-> 主动使用、被动触发、辅助生效或作为资产被转移 / 封存
-> 写入耐久、充能、灵性、损毁、持续状态或资源消耗结果
-> 进入修复、拆解、战利品、遗产、宗门回收、普通藏宝或真灵藏宝结算
```

常见触发入口：

1. 战斗开始时读取可调用法宝，生成主动或被动指令。
2. 事件选项声明允许使用某类法宝。
3. 突破准备或突破事件链允许投入护持、镇压、稳定或攻伐法宝。
4. 移动、探索、封印、侦测、破阵或防护行动调用辅助型法宝。
5. 库存、交易、宗门清点、战利品拾取、偷取、后手封存或遗产结算检查法宝资产状态。
6. 修复、拆解、回收或污染清理行动处理法宝残值。

中断点包括资源不足、法宝不在可调用范围、绑定对象不符、当前场景不允许、法宝破损或失灵、耐久 / 充能 / 灵性不足、事件锁定、现场控制权未确定、正式后手开启条件未满足。

## 5. 规则与状态

### 5.1 法宝类型口径

| 角色 | 规则含义 | MVP 口径 |
| --- | --- | --- |
| 主动型法宝 | 提供可主动投入的行动、事件或战斗指令 | 可作为最小法宝闭环 |
| 被动型法宝 | 满足条件时提供持续、触发、抵消、防护、预警或抗性效果 | 可作为最小法宝闭环 |
| 辅助型法宝 | 支持突破、修炼、移动、探索、封印、侦测、修复等非战斗场景 | 可按事件或行动入口处理 |
| 储物空间法宝 | 基础行囊的升级概念，表现为特殊资产容器或容器入口 | MVP 不开发玩法，只保留概念 |

主动型法宝数量过多不会线性提高战斗收益。限制来自交锋格、行动入口、元气、神念、生机、耐久、充能、道具消耗、触发条件、事件限制和克制关系，而不是装备栏位。

被动型法宝不是免费常驻护盾。只要它在战斗或事件中承担防护、抵消、转移、镇压、预警、抗性或替角色承受后果，就可以进入法宝状态变化判定。

角色绑定不属于 `artifact_kind`，也不进入法宝类型表。它只表示某件法宝实例当前是否与角色建立绑定关系，并通过 `bind_state`、`bound_target_ref`、`theft_protection`、`destroy_policy` 等字段表达。

### 5.2 可用性规则

法宝可用性由以下条件共同决定：

1. 资产是否位于可调用范围，例如随身携带、事件允许调用或已被当前行动预留。
2. 法宝是否具备当前场景所需标签，例如 `combat_ready`、`event_ready`、`breakthrough_support`、`storage_artifact`。
3. 当前角色状态是否允许驱动法宝，例如未被封印、昏迷、压制或禁用相关能力。
4. 当前行动、事件、战斗或突破阶段是否允许该类法宝参与。
5. 绑定、权限、宗门身份、位置、可见性和封存状态是否满足。
6. 耐久、充能、灵性、损坏状态是否满足最低使用条件。
7. 法宝使用需要的元气、神念、生机、材料、聚灵石或其他资源是否足够。

系统可显示暂时不可用的法宝，但必须给出明确原因，例如资源不足、状态破损、当前场景不允许、绑定对象不符或资产不在可调用范围内。

### 5.3 战斗规则

战斗开始时，系统读取角色可调用范围内的法宝、消耗道具和已掌握术法神通，并根据当前战斗规则生成可用指令列表。

主动型法宝：

1. 可生成攻击、防御、控制、恢复、逃遁、护体、照魂、封禁等指令。
2. 通常需要占用战斗交锋格、事件选择或行动入口。
3. 可以消耗元气、神念、生机、法宝耐久、法宝充能、使用次数或特定材料。
4. 使用后可能产生受损、失灵、充能下降、灵性下降或破碎。

被动型法宝：

1. 不占用主动交锋格，但必须满足触发条件。
2. 可以抵消伤害、抵抗状态、预警危险、转移后果、护持神魂或降低环境影响。
3. 触发后可能消耗耐久、灵性或充能。
4. 若替角色承受后果或遭到针对性破坏，也可能受损、失灵或破碎。

MVP 只保留法宝自身状态变化与结果回写，不扩展为所有装备的耐久玩法。

### 5.4 状态与生命周期

法宝状态变化包括：

1. 主动使用后受损。
2. 被动触发后受损。
3. 被敌方、环境、阵法、秘境规则或突破前后独立外扰事件针对后受损。
4. 失去充能、使用次数或临时可用性。
5. 灵性消耗、压制或衰弱。
6. 暂时失灵。
7. 破碎或销毁。
8. 战后修复。
9. 拆解回收材料、核心组件、灵性残片或污染物。
10. 作为后手、遗产、宗门资源或战利品重新进入资源循环。

MVP 不引入法宝自然灵性衰退、非事件型自然损耗或复杂保养系统。法宝损耗主要来自主动使用、被动触发、战斗破坏、事件代价、突破前后独立外扰事件、雷劫阶段资源辅助或明确结果包。

法宝自身的耐久、充能、灵性、绑定和损毁状态由本文维护；法宝对角色施加的护体、镇压、预警、短时强化、压制、虚弱或暂时失灵影响，若挂到角色身上持续存在，应创建角色持续状态实例，并通过该系统导出属性修正或行动限制。

死亡、战利品、遗产和后手分配必须等待战斗或事件链完成后结算，避免法宝损坏、现场控制权、合法战利品归属尚未确定时提前分配资产。

### 5.5 储物空间法宝

储物空间法宝是基础行囊的升级版本概念。它可以被理解为一个特殊法宝实例，附带储物能力或资产容器入口。

MVP 边界：

1. 不开发独立储物空间法宝玩法。
2. 不设置玩法层物品栏数量上限。
3. 不做负重、重量、体积、背包格子、容量成长或空间扩容玩法。
4. 物品栏数量只保留程序层上限，用于性能、存档和异常防护。
5. 储物空间法宝不得绕过资产位置、权限、可见性、交易、事件、战斗或后手日志。
6. 若作为叙事或奖励出现，先按普通法宝实例记录，不开放独立取放、扩容、偷取、掉落或容量结算规则。
7. 储物空间法宝不得绕过宗门遗产清点、无主遗留设施开启条件或真灵藏宝数量容量限制。

未来若开发储物空间法宝，应仍然遵守资产容器原则：内部物品需要有容器、权限、可见性和日志；法宝本体被转移、损毁、封存或绑定时，内部资产去向必须有明确规则。

### 5.6 角色绑定状态

角色绑定不是独立法宝类型，而是法宝实例的绑定与否状态标记。当前明确会使用角色绑定状态的对象是储物空间法宝。其他法宝是否允许角色绑定、是否存在真灵绑定、宗门授权、后手封存绑定等规则，暂不进入 MVP。

基础概念：

1. `bind_state = character_bound` 表示该法宝实例绑定当前世角色。
2. 绑定后的法宝不会被普通窃取、扒取、战利品拾取或库存转移直接拿走。
3. 绑定对象死亡后，绑定法宝自主损毁，不作为遗产进入战利品或后手分配。
4. 自主损毁必须写入结果和资产日志，说明损毁发生于绑定对象死亡结算。
5. 绑定不等于跨世继承，不默认进入真灵资产，也不默认绕过后手容量。

MVP 不开发完整认主、解绑、改绑、解除窃取保护、绑定继承、绑定冲突、绑定修复或绑定追踪玩法。若后续需要，只能在本文状态字段基础上扩展。

### 5.7 资源、修复与回收

法宝使用、修复、拆解和回收必须进入资产流水或结果包。

法宝可能消耗：

1. 元气、神念、生机。
2. 法宝耐久。
3. 法宝充能或使用次数。
4. 材料、灵材、聚灵石或专用修复资源。
5. 事件代价、后手容量或封存资源。

法宝修复、拆解和回收暂不写具体公式。MVP 可保留接口，但不需要完整炼器、保养、拆解收益和灵性恢复系统。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 物品流转与库存 | 读取容器、来源、预留、权限、事件锁定和资产流水；写入转移、封存、消耗、损毁、修复和回收结果 |
| 角色属性与持续状态 | 读取元气、神念、生机、角色限制和持续状态；写入法宝触发产生的角色持续状态、属性修正来源或当前值变化日志 |
| 行动系统 | 读取行动标签、可调用范围、执行阶段和中断原因；写入法宝预留、使用消耗、失败原因和结果包 |
| 战斗系统 | 读取交锋格、战斗阶段、敌我目标、现场控制权和战利品边界；写入主动 / 被动法宝触发、受损、破碎和战后分配 |
| 突破系统 | 读取突破阶段资源槽、雷劫辅助资源、突破前后独立外扰事件和关键事件；写入护体、稳定、攻伐、镇压、受损或消耗结果。法宝不得把护法 / 外扰重新塞入突破内部阶段 |
| 移动与地图节点 | 读取路线、设施、危险环境、节点权限和移动方式；写入移动法宝消耗、限制或事件结果 |
| 随机事件与 NPC | 读取事件选项、NPC 权限、偷取 / 交易 / 奖励条件和法宝可见性；写入事件使用、夺取、遗失、奖励或惩罚 |
| 后手、藏宝与遗产 | 读取封存记录、真灵藏宝容量、遗产清点、无主设施开启条件和宗门回收规则；写入正式后手、战利品、藏宝和宗门资产流转 |
| UI 与回放 | 读取可用性、不可用原因、状态、绑定、损毁、消耗和日志摘要；不读取 Debug 原始公式作为普通展示 |

## 7. 数据字段建议

法宝是 `ItemInstance` 的特殊用法，不另建脱离物品系统的资产形态。

```yaml
ArtifactInstance:
  item_instance_id: string
  item_template_id: string
  container_id: string
  quality: string
  tags: list
  artifact_kind: active | passive | support | storage | hybrid
  artifact_role_tags: list
  availability_tags: list
  active_command_refs: list
  passive_effect_refs: list
  durability_state: intact | worn | damaged | broken
  charge_state: integer | null
  spirituality_state: stable | strained | depleted | null
  bind_state: unbound | character_bound
  bound_target_ref: string | null
  theft_protection: none | bound_unstealable
  destroy_policy: none | destroy_on_bound_target_death
  storage_container_ref: string | null
  visibility_policy: string
  source_ref: string
  ledger_refs: list
```

字段统一说明：

| 字段 | 含义 |
| --- | --- |
| `item_instance_id` | 法宝实例 ID，继承物品实例身份 |
| `item_template_id` | 法宝模板 ID，承载品类、阶层、基础效果 |
| `container_id` | 当前资产容器，不使用 `owner_container_ref` |
| `artifact_kind` | 法宝主要功能类型，不包含绑定状态 |
| `artifact_role_tags` | 攻击、防护、储物、突破支持、侦测等角色标签 |
| `availability_tags` | 当前是否可用于战斗、事件、突破、储物等上下文 |
| `durability_state` | 耐久状态使用枚举，不在概念文档中写具体数值公式 |
| `charge_state` | 当前充能或可用次数；无充能机制时为 `null` |
| `spirituality_state` | 法宝灵性状态，避免与真灵字段混淆 |
| `bind_state` | MVP 只保留 `unbound` 与 `character_bound` |
| `bound_target_ref` | 绑定对象引用；MVP 概念上指当前世角色 |
| `theft_protection` | 绑定后的不可被窃取规则 |
| `destroy_policy` | 绑定对象死亡后的自主损毁规则 |
| `storage_container_ref` | 储物空间法宝未来可能关联的内部容器；MVP 不启用玩法 |
| `ledger_refs` | 高价值资产变化、损毁、修复、封存、转移和回收日志 |

旧字段口径收敛：

| 旧口径 | 统一为 |
| --- | --- |
| `ArtifactState.artifact_id` | `ArtifactInstance.item_instance_id` |
| `owner_ref`、`owner_container_ref` | `container_id`；绑定对象另用 `bound_target_ref` |
| `carried_state` | 资产位置由容器表达，可用性由 `availability_tags` 表达 |
| `spirit_state` | `spirituality_state` |
| `combat_ready` | `availability_tags` 中的 `combat_ready` |
| 旧跨世绑定字段 | 不作为 MVP 法宝字段；后手封存由资产容器、后手记录和日志表达 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 可以展示：

1. 法宝名称、品质、类型标签、当前容器和来源摘要。
2. 当前可用或不可用状态，以及明确不可用原因。
3. 可用于战斗、事件、突破、移动或辅助行动的入口。
4. 法宝耐久、充能、灵性、绑定、损毁、失灵和封存状态的玩家可理解摘要。
5. 主动使用或被动触发可能消耗的元气、神念、生机、耐久、充能、材料或聚灵石。
6. 高价值转移、修复、拆解、封存、遗产或后手操作的确认提示。

普通 UI 不展示：

1. 内部模板 ID、日志 ID、流水 ID、随机种子或 Debug 原始倍率。
2. 未揭示法宝的隐藏缺陷、剧情真相、未触发诅咒或隐蔽归属。
3. 暗示装备栏、战力栏位或固定装备插槽的入口。
4. 尚未裁决的真灵绑定、跨世绑定、宗门授权绑定或绑定破解入口。
5. 储物空间法宝的独立取放、扩容、偷取、掉落或内部资产继承界面。

## 9. MVP 范围

MVP 应实现或保留：

1. 法宝作为 `ItemInstance` 的高价值实例资产。
2. 主动型法宝和被动型法宝的最小可用性闭环。
3. 法宝使用前的容器、权限、场景、绑定、状态、资源和标签校验。
4. 战斗、事件、突破、移动或辅助行动中的法宝消耗和结果回写接口。
5. 法宝自身耐久、充能、灵性、损毁、失灵和破碎状态。
6. 法宝触发后进入角色持续状态系统的接口。
7. 修复、拆解和回收的接口占位，以及资产流水记录。
8. 储物空间法宝作为基础行囊升级概念，但不开放独立玩法。
9. 角色绑定作为法宝实例状态标记，绑定后不可被普通窃取，绑定对象死亡后自主损毁。
10. 法宝正式后手必须进入真灵藏宝并占用数量或容量限制。
11. 宗门个人洞府、宗门外洞府、普通藏宝、战利品和遗产中的法宝按对应资产规则结算。

MVP 不实现：

1. 传统装备栏、换装备、换法宝系统。
2. 玩法层携带容量、重量、体积、背包格子或通用负重玩法。
3. 完整法宝类型表、品质表、品阶表和词条表。
4. 完整主动 / 被动法宝效果表。
5. 法宝伤害公式、耐久公式、充能公式、灵性恢复公式。
6. 储物空间法宝容量成长、扩容、取放、偷取、掉落和内部资产继承玩法。
7. 法宝角色绑定状态的认主、解绑、改绑、跨世继承、真灵绑定和绑定冲突玩法。
8. 法宝自然灵性衰退、非事件型自然损耗和复杂维护系统。
9. 完整炼器系统和装备化战力栏位。

## 10. 验收约束

1. 任何文档或实现不得用装备位、物品栏格子或战力栏位决定法宝是否可用。
2. 高价值法宝必须作为实例资产保留来源、容器、状态、归属、可见性和日志。
3. 法宝使用或触发前必须校验可调用范围、场景标签、角色状态、绑定、权限、耐久、充能、灵性和资源消耗。
4. 主动型法宝和被动型法宝触发后产生的损耗、失灵、破碎或资源消耗必须进入结果包和资产流水。
5. 法宝挂到角色身上的持续影响不得私自维护角色状态结构，必须进入角色持续状态系统。
6. 角色绑定不得被解释为法宝类型，也不得自动转化为真灵绑定或跨世继承。
7. 绑定对象死亡后，绑定法宝必须按自主损毁处理，除非未来另有裁决。
8. 储物空间法宝不得绕过资产位置、权限、可见性、交易、事件、战斗、遗产、宗门清点或后手日志。
9. 死亡、战利品、遗产和后手分配必须等待战斗或事件链完成后结算。
10. 法宝封存为正式后手必须进入真灵藏宝，并占用真灵藏宝数量或容量限制。
