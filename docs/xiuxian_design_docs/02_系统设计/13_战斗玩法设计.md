# 系统设计｜战斗玩法

## 1. 设计定位

战斗 / 斗法是高风险事件链中的轻量结算框架，负责回答“何时进入交锋、交锋如何分级、如何消耗时间、如何输出结果包，以及后果交给谁解释”。它不承担复杂战棋、实时操作、高频刷怪、完整伤害公式或战斗专用页面布局。

战斗玩法服务于移动遭遇、节点危机、秘境遭遇、宗门任务、突破外扰、护法失败后的直接冲突、资源争夺、剧情切磋或死战。玩家体验目标是预判、克制、消耗管理和后果承担，而不是长时间操作。

正式战斗采用 B1 交锋慢速和 5 格战术预输入；B1 的现实提交窗口、非参战世界推进和参战交锋自身耗时必须分开记账。普通斗法应是短促、高强度事件；追击、围困、阵法拉锯、秘境转场、疗伤、战后搜索、突破准备或突破巩固才承担长耗时。

## 2. 当前结论

1. 战斗系统只负责内部交锋、时间记账和结果输出；后续行动、死亡、转世、宗门评价、节点变化和传闻由父事件链解释。
2. 轻遭遇使用个人局部时停和少量选项；正式交锋进入 B1，并使用战斗专用交锋状态、默认策略和结果包。
3. 常规正式战斗默认 3 个战斗回合；每回合 5 个交锋格，每回合 10 分钟叙事耗时，常规 3 回合共 30 分钟，不足 1 游戏小时按 1 小时结算。
4. 每个 B1 提交窗口默认 60 秒现实时间；B1 期间非参战玩家和世界按每 60 秒推进 1 游戏小时处理。
5. 生机、元气、神念是角色持久状态；战斗开始读取当前值，战斗结束回写变化，不自动恢复满值。
6. 每场战斗必须携带 `battle_rule` 和结束条件，并在结束后输出 `BattleResult`，供父事件链承接。
7. 突破挑战复用 B1 提交窗口、默认策略、结果包和回放机制，但不是普通战斗；每个突破阶段只输入 1 个交锋格，耗时由突破模板声明。
8. MVP 丹药没有即时生效类型，不允许在战斗 / 突破交锋中作为即时指令使用。

## 4. 核心循环或触发入口

战斗发生在共享世界日历推进过程中，由事件、移动、秘境、宗门行动、突破外扰或资源争夺触发。

标准流程：

```text
世界日历按小时 tick 推进
→ 某 tick / 节点 / 路途段触发战斗事件
→ 当前行动结算暂停进入事件链
→ 判断是轻遭遇还是正式交锋
→ 轻遭遇走个人局部时停
→ 正式交锋进入 B1 专用交锋
→ 生成战斗结果包
→ 回写角色、位置、资源、节点、宗门、日志与回放
→ 父事件链决定继续原计划、消耗时间、中断、撤退、重伤、死亡或转世
```

正式战斗内部循环：

```text
战斗回合开始
→ 查看状态、可用指令、事件目标、敌方倾向
→ 玩家 / AI 各自填入 5 个交锋格
→ 倒计时结束或全员提前提交后锁定
→ 第 1 格交锋结算
→ 检查结束条件
→ 第 2 格交锋结算
→ 检查结束条件
→ ...
→ 第 5 格交锋结算
→ 回合结束处理
→ 若未结束，进入下一 B1 提交窗口或模板结局
```

每个交锋格后都检查结束条件，允许提前结束。战斗不需要为了填满 5 格或达到预设轮数而继续结算。

## 5. 规则与状态

### 5.1 战斗分级

轻遭遇是短文本、少选项、低风险或低复杂度的个人事件，例如采药时遇到低阶妖兽、路上被外门弟子挑衅、小型陷阱、低风险野兽惊扰或普通低阶劫道。

轻遭遇规则：

```text
事件玩家本人局部时停
其他世界 N1
gap 最多 1 游戏日
选择后 C1 追赶
通常不进入完整 5 格战斗
```

轻遭遇可以直接提供“迎战 / 闪避 / 交涉 / 使用符箓或护符 / 撤退”等少量选项。只有当后果足够重、敌方足够强、涉及多人或资源争夺时，才升级为正式交锋。

正式交锋包括秘境关键战斗、强敌斗法、玩家直接冲突、多人组队战斗、宗门任务战斗、可能导致重伤 / 死亡 / 重大资源损失的战斗、突破挑战或突破外扰。

正式交锋规则：

```text
世界进入 B1
使用 B1 专用界面和默认策略
每轮现实提交窗口默认 60 秒
未提交者执行当前默认策略
不因单个玩家未选择而 P0
非参战玩家也处在同一世界慢速中
```

正式交锋不使用个人局部时停。它需要让参战者和非参战者共享同一世界时间秩序，避免私人战斗在世界背后无限冻结。

### 5.2 B1 时间拆分

当前战斗口径采用四层时间：

| 层级 | 含义 | 设计用途 |
| --- | --- | --- |
| 现实提交窗口 | 玩家现实中本轮可提交和修改选择的时间，默认 60 秒 | 保护思考时间，防止多人卡死 |
| B1 世界推进 | 每个 60 秒窗口对应房间和非参战玩家推进 1 游戏小时 | 维持多人共享日历和常态行动推进 |
| 交锋叙事耗时 | 交锋本身在故事中消耗的分钟或小时 | 表达斗法、突破、追击、护法的真实耗时 |
| 交锋结算耗时 | 参战交锋最终计入的游戏时间 | 扣减持续效果、处理 gap、回写结果包 |

核心规则：

```text
B1 = 交锋慢速、提交窗口和非参战世界推进，不等同交锋自身固定 1 游戏小时。
每个 60 秒现实决策窗口仍让其他玩家按 B1 完成 1 游戏小时行动推进。
战斗交锋自身按 5 个交锋格 = 10 分钟叙事耗时计算。
常规战斗 3 轮交锋共 30 分钟，结算不足 1 小时按 1 小时计。
突破交锋按突破模板声明阶段耗时，总耗时暂定 1～6 小时。
```

### 5.3 时间模板

| 场景 | 交互方式 | 建议轮数 / 阶段 | 交锋叙事耗时 | 交锋结算耗时 | 说明 |
| --- | --- | ---: | ---: | ---: | --- |
| 轻遭遇 | 局部时停选项 | 1 次选择 | 0～1 小时 | 按事件选项 | 不进入完整 B1，按事件选项回填 |
| 常规战斗交锋 | B1 + 5 格战术序列 | 3 个战斗回合 | 30 分钟 | 1 小时 | 每回合 5 格共 10 分钟；每回合 60 秒现实窗口 |
| 非常规战斗交锋 | B1 + 5 格战术序列 | 模板指定 | 每回合 10 分钟，额外追击 / 转场另算 | 不足 1 小时按 1 小时，额外耗时按模板 | 强敌、秘境关键战、资源争夺 |
| 突破挑战 | B1 + 单格阶段选择 | 模板指定，常见 2～6 阶段 | 每阶段由模板声明 | 模板累计，暂定总耗时 1～6 小时 | 每阶段只输入 1 个交锋格 |
| 长期围困 / 拉锯 | 事件链或长期行动 | 不按普通战斗处理 | 多小时到多日 | 多小时到多日 | 应转为节点来源事件、宗门行动或长期对峙状态 |

战斗交锋与突破交锋均沿用 gap 最大不超过 1 游戏日的限制，不在实现层面额外增加其他时间预算限制。实际设计层面，普通战斗交锋一般不超过 1 游戏小时，突破交锋一般不超过 6 游戏小时。

常规战斗示例：

```text
3 轮战斗交锋；
每轮 5 个交锋格；
每轮叙事耗时 10 分钟；
交锋自身共 30 分钟；
每轮现实决策窗口 60 秒；
现实时间最多 3 分钟；
B1 世界推进 3 游戏小时；
非参战玩家完成 3 游戏小时行动推进；
参战交锋结算不足 1 小时，按 1 小时计。
```

战斗交锋中每个轮次的 10 分钟耗时主要有叙事作用，几乎不进入逐格计算。突破交锋不同：由于 2～3 个突破阶段就可能累计超过 1 游戏小时，突破阶段耗时除了叙事作用，也参与效果、资源和时间结算。

### 5.4 5 格战斗结构

正式战斗内部采用 5 格战术预输入。一个 B1 提交窗口内，玩家为本战斗回合填入 5 个交锋格。锁定后，系统连续结算这些交锋格并逐格检查结束条件。

突破挑战不使用 5 格战术序列。每个突破阶段只需要 1 个交锋格的选择与输入，决策窗口同样为 60 秒现实时间。

### 5.5 战斗资源

三条战斗相关属性条：

| 显示名 | 含义 | 承载 |
| --- | --- | --- |
| 生机 | 生命、健康、肉身完整度 | 受伤、濒死、肉身崩溃 |
| 元气 | 法力、气力、可支配能量 | 术法消耗、法宝驱动、疲惫 |
| 神念 | 灵魂、神识、心神稳定 | 神魂攻击、幻术、心魔、操控 |

三者都是角色持久状态，不是战斗内临时资源。战斗开始读取当前值，战斗结束回写变化，不自动恢复满值。

建议区分三类变化：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 消耗 | 主动指令支付的成本 | 施法消耗元气、禁术消耗神念 |
| 伤害 | 被对方指令或事件造成的削减 | 剑伤削减生机、魂刺削减神念 |
| 状态封锁 / 扰动 | 不一定立刻削减当前值，但影响效率 | 元气紊乱、神念震荡、经脉阻滞 |

战斗结束条件默认只统计对方造成的伤害，不统计角色主动消耗。特殊模板可以例外。

### 5.6 结束条件

每场战斗进入时必须携带 `battle_rule`，用于定义战斗类型、回合上限、叙事耗时、记账耗时、结束条件、平局处理、可用指令来源和胜负后果。

示例结束条件：

| 类型 | 结束条件 | 说明 |
| --- | --- | --- |
| 切磋 | 任一方被对方造成累计生机或神念伤害达到阈值 | 不以杀死对方为目标 |
| 死战 | 任一方生机或神念归零 | 是否死亡由父事件链解释 |
| 逃亡 / 追击 | 脱离进度达到阈值，或撑过指定交锋格 | 目标是脱离，不是击杀 |
| 护法 / 突破外扰 | 护持进度完成，外扰被压制，或突破者受关键伤害 | 结果返回突破事件链 |
| 资源争夺 | 抢夺物、节点控制或时间窗口达成 | 胜负可能不等于击杀 |
| 强制结局 | 达到最大回合、模板结束条件或 gap 上限 | 模板解释为撤退、僵持、窗口错过等 |

平手不等于无后果。父事件链可解释为双方撤退、敌人逃走、资源窗口错过、移动计划中断、秘境收益下降或突破外扰未完全压制。

### 5.7 战斗结果包

战斗结束后必须输出 `BattleResult`，并至少回写：

```text
角色个人日志
战斗摘要日志
必要的世界日志或宗门传闻
结果包引用
回放记录
```

公开与隐秘信息按事件可见性处理。隐秘战斗不能通过 UI 速度文案暴露具体参战者或原因。

### 5.8 后果边界

战斗作用于本世身躯与灵魂，通常不直接改变真灵强度、执念容量、转世初始化选择或已定正式后手。

战斗可以改变：

```text
当前生机、元气、神念
伤势、道伤、疲惫、心神动摇
随身物品和法宝状态
术法 / 指令使用经验
事件结果
位置和行动计划
宗门评价、传闻、节点状态
```

严重失败可通过死亡、神魂重创、因果加重、宗门外个人洞府或普通藏宝线索暴露等父事件结果间接影响轮回系统。

真灵藏宝是同一真灵跨世感应和开启的正式后手，不应被战斗当作普通战利品、遗产或可被他人直接搬空的资产。宗门外个人洞府和普通藏宝是无主遗留设施，可因战斗后果暴露线索、阵法受损或控制权变化而被其他角色提前开启。

MVP 不以玩家间直接斗法为核心验证项。若出现直接玩家冲突，应进入正式交锋，但系统第一版优先支持玩家 vs NPC、玩家 vs 抽象敌方小队、玩家 + 护法修正 vs 外扰、宗门行动 / 节点来源事件中的抽象战斗结果。

### 5.9 与突破的关系

突破挑战复用 B1 提交窗口、默认策略、结果包和回放机制，但不等同普通战斗。

| 项目 | 普通战斗 | 突破挑战 |
| --- | --- | --- |
| 核心目标 | 击退、逃脱、争夺、护法或生存 | 稳定破境、提高成功率和品质、控制代价 |
| 主要资源 | 生机、元气、神念、法宝、道具 | 突破资源、护法、地点、心境、根基、后手 |
| 输入结构 | 每轮 5 个交锋格 | 每阶段 1 个交锋格 |
| 常用耗时 | 常规 3 轮共 30 分钟，结算按 1 小时 | 模板累计，暂定总耗时 1～6 小时 |
| 长期消耗归属 | 战后休整、追击、事件后果 | 准备期和巩固期 |

突破挑战不应被做成反复 P0，也不应把突破阶段直接解释为固定 1 小时。每个阶段应由突破模板声明耗时、资源消耗、风险标签和默认策略。

一般同境界各个突破阶段耗时相同；不同突破模板的主要差异在突破指令应对、资源取舍和风险标签，而不是默认拉长每阶段耗时。由于突破阶段累计耗时会参与计算，提前炼化中的丹药、符箓、法宝或其他持续效果可能在达到时间节点时生效或扣减剩余持续时间。

MVP 丹药没有即时生效类型，都需要依赖炼化与时间流逝生效，因此丹药不允许在战斗交锋和突破交锋中作为即时指令使用。正式版若引入即时生效丹药，届时可以加入交锋指令列表。

| 接口对象 | 读取 | 写入或影响 |
| --- | --- | --- |

| 地图与环境 | 节点风险、路线状态、秘境规则、阵法、地形、宗门控制和资源窗口 | 节点状态、路线中断、秘境收益、控制权变化和世界日志 |
| 随机事件 | 事件触发类型、事件目标、可见性、选项和父事件链 | 战斗入口、结果包引用、事件后果、余波事件和公开 / 私密信息 |
| NPC 与 AI | NPC 模板、战斗风格、资产、死亡清点边界和难度配置 | AI 序列、死亡资产处理、宗门评价、传闻和事件后续 |
| 日志与回放 | 可见性、参战者、回合摘要、结果字段和父事件链引用 | 角色日志、战斗摘要、世界日志、宗门传闻和回放记录 |

本文只维护职责边界，不重复伤害公式、指令倍率、完整 NPC AI 权重或 UI 布局。

## 7. 数据字段建议

### 7.1 BattleRule

| 字段 | 含义 |
| --- | --- |
| `battle_type` | 战斗类型，例如 `spar`、`deathmatch`、`escape`、`pursuit`、`breakthrough_disturbance`、`resource_contest`、`special` |
| `max_combat_rounds` | 最大战斗回合数 |
| `combat_round_scene_minutes` | 每个战斗回合的交锋叙事耗时，常规为 10 分钟 |
| `minimum_accounting_hours` | 本场交锋最小记账小时数，常规不足 1 小时按 1 小时 |
| `end_conditions` | 结束条件列表 |
| `draw_resolution` | 平局、超时或强制结束时的解释方式 |
| `allowed_command_sources` | 本场允许的指令来源 |
| `defeat_consequence` | 失败后果配置，由父事件链解释 |
| `victory_consequence` | 胜利后果配置，由父事件链解释 |

### 7.2 BattleResult

| 字段 | 含义 |
| --- | --- |
| `result_type` | 结果类型，例如 `victory`、`defeat`、`draw`、`escape_success`、`escape_failed`、`interrupted`、`death`、`special` |
| `winner_side` | 胜利方引用，可为空 |
| `loser_side` | 失败方引用，可为空 |
| `end_reason` | 结束原因 |
| `combat_rounds_used` | 已结算战斗回合数 |
| `breakthrough_stages_resolved` | 已结算突破阶段数 |
| `slots_resolved` | 已结算交锋格数量 |
| `b1_world_elapsed_hours` | B1 期间世界推进小时 |
| `nonparticipant_progress_hours` | 非参战玩家完成的行动推进量 |
| `encounter_scene_elapsed_minutes` | 交锋自身叙事耗时 |
| `encounter_accounting_hours` | 参战交锋最终按游戏规则计入的消耗时间 |
| `participant_gap_hours` | B1 世界推进与参战交锋记账之间的差值 |
| `vitality_delta` | 生机变化 |
| `energy_delta` | 元气变化 |
| `mind_delta` | 神念变化 |
| `consumed_items` | 消耗物品列表 |
| `artifact_state_delta` | 法宝状态变化 |
| `learned_skill_exp_delta` | 术法 / 指令使用经验变化 |
| `status_tags_added` | 新增状态标签 |
| `status_tags_removed` | 移除状态标签 |
| `event_flags` | 事件标记 |
| `suggested_return` | 建议父事件链如何承接，例如继续计划、中断、撤退、休整、重伤、死亡或特殊处理 |
| `log_summary` | 战斗摘要 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

战斗 / 斗法采用沉浸式覆盖界面，但不改变普通队列与 B1 选择的边界。

界面应显示：

1. 触发原因。
2. 当前速度：交锋慢速。
3. B1 本轮剩余提交时间。
4. 本场目标和结束条件。
5. 己方生机、元气、神念。
6. 敌方已知状态与信息层级。
7. 5 格战术指令面板。
8. 当前默认策略。
9. 指令克制提示。
10. 本轮预计己方主动消耗。
11. 上一轮交锋记录。
12. 战斗结果如何回写角色、路线、节点和日志。

界面不应暗示：

1. 普通队列可以替代交锋轮选择。
2. 预计变化等于最终战斗结果。
3. B1 提交窗口必然等于交锋自身 1 游戏小时。
4. 隐秘交锋可以向非参战玩家暴露具体来源。
5. Debug 字段、完整伤害公式、AI 权重、随机种子或未公开敌方完整未来指令属于普通玩家信息。

## 9. MVP 范围

MVP 应实现：

1. 1v1 玩家 vs NPC。
2. 玩家 vs 抽象敌方小队。
3. 5 格战术预输入。
4. 生机 / 元气 / 神念读取与回写。
5. 攻击 / 防御 / Buff 三角克制。
6. 基础指令、术法指令、道具指令、法宝指令。
7. 不同战斗结束条件。
8. 战斗结果包回写父事件链。
9. 可回放的战斗摘要日志。
10. B1 提交窗口、B1 世界推进、交锋结算耗时分离。
11. 符箓、法宝等持续效果按已消耗游戏时间扣减剩余持续时间。

MVP 不实现：

1. 棋盘、站位、距离。
2. 实时操作。
3. 复杂多人同场战斗。
4. 完整 PvP 规则。
5. 装备栏、换装或战斗中换法宝。
6. 完整技能树。
7. 复杂 combo。
8. 高级反制、连锁和多段打断。
9. 战斗中即时生效丹药。

战斗可以提供少量术法 / 指令使用经验，但不能形成刷低风险战斗的最优成长路径。主要成长仍来自修炼、资源、功法和事件。

## 10. 验收约束

1. 轻遭遇不得默认进入完整 5 格战斗；只有高风险、强敌、多人或重大资源争夺才升级正式交锋。
2. 正式交锋必须进入 B1，不得使用个人局部时停绕过共享世界时间。
3. B1 现实提交窗口、B1 世界推进、交锋叙事耗时和参战交锋记账耗时必须分别记录。
4. 常规战斗默认 3 个战斗回合、每回合 5 个交锋格、每回合 10 分钟叙事耗时；不足 1 小时按 1 小时结算。
5. 战斗每个交锋格后都必须检查结束条件，不得为了填满格子或轮数强行继续。
6. 生机、元气、神念必须读取角色当前持久状态并回写变化，不能战后自动回满。
7. 每场战斗必须携带 `battle_rule`，并输出可追踪的 `BattleResult`。
8. 战斗后果不得直接改写真灵强度、执念容量、转世初始化选择或已定正式后手。
9. 真灵藏宝不得被战斗当作普通战利品、遗产或可直接搬空资产。
10. MVP 丹药不得在战斗交锋或突破交锋中作为即时指令使用。
11. 隐秘战斗的 UI、日志和速度提示不得暴露未公开参战者、触发原因或其他玩家私人事件归因。
