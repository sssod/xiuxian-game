# 系统设计｜储物空间法宝

## 1. 设计定位

储物空间法宝负责定义“未来可能出现的特殊随身储物法宝”在当前设计包中的边界。它是基础行囊的升级表现概念，不是 MVP 阶段的独立玩法系统。

本文只维护储物空间法宝的概念边界、与基础行囊和库存系统的关系、MVP 排除项，以及未来扩展时必须裁决的接口问题。当前阶段不把储物空间法宝设计成背包容量成长、负重管理、格子扩展或空间经营功能。

## 2. 当前结论

1. 储物空间法宝在 MVP 阶段不开发独立玩法系统，只保留基础概念设定。
2. 储物空间法宝是基础行囊的未来升级表现，但不会改变 MVP 中“基础行囊无玩法层容量上限”的口径。
3. 若储物空间法宝在文本、奖励或设定中出现，先按普通法宝概念记录，不开放额外取放、容量结算或特殊 UI 页面。
4. 即使后续开发内部资产容器，也必须复用库存系统的资产位置、权限、可见性、预留锁定和流水规则。
5. 储物空间法宝不能绕过遗产、后手、藏宝、交易、事件、战斗和死亡结算边界。

## 4. 核心循环或触发入口

MVP 阶段没有独立储物空间法宝循环。储物空间法宝只可能通过以下入口被提及：

1. 作为法宝文本、奖励预告、世界设定或 NPC 描述出现。
2. 作为未来特殊法宝类型的占位，不提供额外资产容器操作。
3. 作为基础行囊与库存系统之间的未来扩展接口被记录。

未来若开发独立玩法，概念循环应先经过裁决：

```text
当前世角色
→ 持有或绑定储物空间法宝
→ 储物空间法宝作为特殊资产容器入口
→ 内部资产遵守库存系统的位置、权限、可见性和日志规则
→ 取放、封存、损毁、继承或争夺结果写入资产流水
```

在该裁决完成前，任何系统都不应把储物空间法宝当作可操作的额外背包、跨世保险箱或无来源资产入口。

## 5. 规则与状态

### 5.1 MVP 排除规则

MVP 中储物空间法宝遵守以下边界：

1. 不制作独立储物空间法宝系统。
2. 不设置玩法层物品栏数量上限。
3. 物品栏数量只保留程序层上限，用于性能、存档和异常防护。
4. 不做重量、体积、背包格子、负重、容量成长或扩容玩法。
5. 不做储物法宝的战斗中取物、被偷取、掉落、空间破碎、内部资产继承等规则。
6. 不提供额外可操作容量或特殊 UI 页面。

### 5.2 与基础行囊的关系

基础行囊是 MVP 的默认随身资产概念；储物空间法宝是未来对基础行囊的特殊升级表现。

MVP 中：

1. 基础行囊不做玩法层容量上限。
2. 法宝、道具、材料和资源是否可用，由随身状态、上下文、标签、权限、绑定和事件条件决定。
3. 储物空间法宝不会改变上述规则。
4. 储物空间法宝不会让随身资产绕过库存系统的预留、锁定、交易暂存或事件锁定。

### 5.3 与库存系统的关系

储物空间法宝可以理解为一个特殊法宝实例，未来可能关联一个内部资产容器。

若后续开发内部资产容器：

1. 容器字段、权限、预留、锁定和流水应复用《库存系统》（`03_库存系统.md`）。
2. 内部资产仍必须遵守资产位置、权限、可见性和日志规则。
3. 不得另建一套背包容量、无来源资产或不记流水的资产规则。
4. 内部资产不能同时处于行囊、市场挂牌、事件锁定、交易暂存、后手封存或其他库存位置。

### 5.4 遗产、后手与藏宝边界

储物空间法宝不是万能背包，也不是跨世资产豁免规则。

1. 宗门个人洞府库存仍可按宗门遗产清点回收。
2. 宗门外洞府和普通藏宝仍需开启条件或破阵结果。
3. 真灵藏宝仍需同一真灵感应和开启，并受设置数量与单个容量限制。
4. 储物空间法宝不能绕过死亡、转世、遗产、后手封存、宗门审计、战利品分配或资产回收规则。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 本文读取 | 本文写入或要求 |
| --- | --- | --- |
| 角色系统 | 当前角色、绑定关系、随身状态、战斗或事件上下文 | MVP 不新增可操作储物状态；未来扩展需记录持有、绑定和取放权限 |
| 法宝系统 | 法宝实例、绑定、损毁、封存、污染、封印和识别状态 | 储物空间法宝先按普通法宝记录；未来扩展需补充内部容器引用 |
| 基础行囊 | 随身资产位置、可用性校验和无玩法层容量上限口径 | 不改变基础行囊的 MVP 容量、负重和可用性规则 |
| 库存系统 | 容器字段、权限、预留、锁定、可见性和资产流水 | 未来内部资产容器必须复用库存模型 |
| 洞府、藏宝与后手 | 遗产清点、无主遗留设施、真灵藏宝、开启条件和容量限制 | 不提供绕过后手、遗产、藏宝和宗门审计的例外 |
| 事件与战斗系统 | 奖励、战利品、战斗中取物、掉落、偷取和空间破碎上下文 | MVP 不开放储物空间法宝的战斗取物、掉落、偷取或破碎结算 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `item_instance_id` | 储物空间法宝作为法宝实例的引用 |
| `storage_artifact_tag` | 标识该法宝具有储物空间概念，不代表 MVP 已开放内部容器 |
| `bound_character_id` | 法宝绑定或持有的当前角色实例 |
| `internal_container_ref` | 未来扩展字段；指向库存系统中的内部资产容器，MVP 为空 |
| `storage_artifact_status` | 未来扩展字段；可表达封存、损毁、污染、封印、被追踪等状态 |
| `access_policy_ref` | 未来扩展字段；储物空间取放权限应引用库存系统权限策略 |
| `transfer_log_refs` | 未来扩展字段；记录取放、封存、损毁、继承、争夺和异常处理流水 |

字段建议是实现提示，不等同于最终数据库或代码结构。MVP 不要求创建储物空间法宝专属数据表。

## 8. UI 展示边界

MVP 普通 UI 应遵守：

1. 储物空间法宝若出现，只按普通法宝或设定文本展示。
2. 不展示额外容量、格子、负重、空间等级、内部资产列表或取放入口。
3. 不把程序层数量上限展示为玩法层背包容量。
4. 不暗示储物空间法宝能绕过行囊、库存、藏宝、后手或遗产规则。

普通 UI 不展示：

1. 未来预留的 `internal_container_ref`、权限策略、隐藏日志或 Debug 容器字段。
2. 玩家尚未获知的内部资产、藏宝、后手或隐藏空间信息。
3. 未经裁决的空间破碎、掉落、偷取、追踪、污染或继承机制。

## 9. MVP 范围

MVP 应实现：

1. 储物空间法宝作为基础行囊未来升级概念的文档边界。
2. 若文本或奖励中出现储物空间法宝，按普通法宝概念记录。
3. 明确储物空间法宝不改变基础行囊、库存、后手、藏宝和遗产规则。

MVP 不实现：

1. 独立储物空间法宝系统。
2. 玩法层容量、重量、体积、格子、负重、容量成长或扩容玩法。
3. 内部资产容器的取放、权限、预留、锁定和资产流水。
4. 战斗中取物、被偷取、掉落、空间破碎、内部资产继承或跨世复制。
5. 储物空间法宝专属 UI 页面。

## 10. 验收约束

1. MVP 中不得把储物空间法宝实现为额外背包、容量成长系统或空间经营系统。
2. 任何文本、奖励或设定中出现的储物空间法宝，都不能赋予额外资产取放或容量结算效果。
3. 程序层数量上限只能用于性能、存档和异常防护，不得包装成玩法层容量限制。
4. 未来若加入内部资产容器，必须复用库存系统的容器、权限、预留、锁定、可见性和流水规则。
5. 储物空间法宝不得绕过遗产清点、无主遗留设施开启条件、真灵藏宝限制、交易暂存、事件锁定或战斗结算。
