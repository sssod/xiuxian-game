# 系统设计｜法门

## 1. 设计定位

法门是功法体系中负责能力、指令、事件选项和效率修正的功法类型。它回答玩家当前世“角色会做什么、能选择什么、做得是否更稳更省”的系统问题，而不是回答“角色能修到哪里”。

本文只维护法门作为系统对象的定义、分类、学习与研习、掌握度、解锁、使用相性和字段建议。道功的修为路线、可修上限和主修资格由《道功》（`01_道功.md`）维护；残页、篇章和完整功法载体由《功法载体》（`../05_物品设计/01_功法载体.md`）维护；功法数值模板、掌握曲线和公式接口由《功法设计基准建模》（`../../03_数值设计/05_功法设计基准建模.md`）维护。

## 2. 当前结论

1. 功法是上位泛称，规则层应拆为 `DaoMethod` 道功与 `TechniqueMethod` 法门。
2. 法门不能设为主修，不直接推动修为进度，不决定当前可修上限，也不决定大境界突破模板类型。
3. 法门的主要价值来自战斗、移动、探索、采集、生产、事件处理、资源效率和风险规避能力。
4. 角色通过完整法门载体或明确教学 / 宗门 / 事件例外入门后创建 `MethodState`；残页和篇章不能直接创建法门掌握状态。
5. 法门掌握度影响解锁强度、稳定性、消耗、成功率、效果质量和风险。
6. 法门可以与灵根、资源、装备、地点和事件标签产生使用相性，但这种相性不直接改变修为进度。
7. 若一个设计同时包含修为推进和能力展开，应拆分为道功部分与法门部分分别维护。

## 4. 核心循环或触发入口

法门围绕“获得、研习、入门、解锁、使用、提升”循环维护：

```text
获得完整法门载体或教学授予
→ 选择研习功法
→ 达到入门阈值
→ 创建 MethodState，进入 learned level 1
→ 解锁对应能力、指令、事件选项或效率修正
→ 在战斗 / 移动 / 探索 / 生产 / 事件中被读取
→ 继续研习或使用相关内容提升掌握度
→ 更新解锁强度、稳定性、消耗、成功率、效果质量和风险
```

常见中断点包括载体不完整、目标不是法门、前置法门或知识不足、角色状态禁止研习、神念状态不足、资源或装备条件不满足、地点或事件标签不匹配、掌握度未达到解锁阈值、目标系统不接受该法门效果和风险超出当前角色承受范围。

## 5. 规则与状态

### 5.1 功法分类口径

功法不是单一精确规则类型。规则层使用以下分类：

```text
DaoMethod：道功
TechniqueMethod：法门
```

“功法”只作为上位泛称使用，不建议在规则判断中直接用 `method` 表达精确类型。凡涉及修为推进、当前可修上限、大境界突破路线和主修资格的内容，应落到道功；凡涉及战斗指令、行动能力、事件选项、生产配方和资源效率的内容，应落到法门。

旧文档中的“术法”“神通”“技艺”“轻身功法”“战斗功法”“养身功法”等，不作为当前活跃分类名。若这些旧称主要提供能力、指令、事件选项或效率，而不直接推动修为和上限，应统一归入法门。

### 5.2 核心定义

法门是不直接推动修为进度的功法类型。它主要提供战斗、探索、采集、移动、生产、事件处理和资源效率能力。

法门的价值应回到时间与资源效率：

```text
同样投入 5 天，掌握某法门后，角色能否更快移动、更安全探索、更高效采集、更好处理事件或更少损耗资源。
```

法门不是主修道功的弱化版本，也不是直接修为倍率。它回答的是“角色会做什么、能选择什么、做得是否更稳更省”，而不是“角色当前境界能推进到哪里”。

### 5.3 法门职责

法门负责：

1. 战斗指令和战斗策略。
2. 移动、逃遁、追踪、隐匿和路径开销修正。
3. 探索、采集、寻宝、秘境入口识别和隐藏层发现。
4. 炼丹、炼器、制符、阵法、医术、卜算等技艺成长。
5. 事件选项、事件判定修正和风险规避。
6. 资源获取效率、资源损耗降低、品质提升或副产物产生。
7. 某些生产配方、行动模板或行动修正的解锁。

法门不负责：

1. 主动吐纳的基础修为推进。
2. 自动运转的基础修为收益。
3. 当前可修上限。
4. 主修道功记录。
5. 大境界突破模板类型。
6. 残页或篇章的合成。

边界口径：

| 概念 | 本文是否负责 | 说明 |
| --- | --- | --- |
| 功法 | 只定义总分类口径 | 功法是泛称，规则层应拆为道功与法门 |
| 道功 | 不负责 | 道功推动修为并可设为主修 |
| 法门 | 负责 | 法门提供能力、指令、事件选项和效率 |
| 主修功法 | 不负责 | 法门不能设为主修 |
| 功法载体 | 不负责 | 法门也可由完整功法学习，但载体规则归物品系统 |

### 5.4 分类示例

| 法门类型 | 主要作用 | 示例表现 |
| --- | --- | --- |
| 战斗法门 | 解锁迎战选项、战斗指令、克制关系 | 雷法、剑诀、护身术、封禁术 |
| 轻身 / 移动法门 | 影响路径开销、逃遁、追击和移动事件反馈 | 轻身术、遁法、御风诀 |
| 探索法门 | 提高发现隐藏层、秘境入口、前世线索和陷阱的能力 | 望气术、寻脉术、破障术 |
| 采集法门 | 提高资源识别、采集效率、损耗控制或品质 | 采药诀、寻矿术、控火采炼 |
| 生产法门 | 影响配方成功率、品质、损耗或副产物 | 炼丹、炼器、制符、阵法 |
| 生存法门 | 提供解毒、避瘴、疗伤、藏息、护身等能力 | 避瘴诀、敛息术、护体术 |
| 信息法门 | 改善情报、卜算、推演、识别和预警 | 卜算术、鉴宝术、观星术 |

### 5.5 学习与研习

常规法门流程：

```text
获得完整法门载体
→ 选择研习功法
→ 达到入门阈值
→ 创建 MethodState，进入 learned level 1
→ 解锁对应能力、指令、事件选项或效率修正
```

新手流程、师承传授、事件奖励或剧情节点可以直接授予基础法门 learned level 1。该例外用于教学和节奏，不代表残页或篇章可以直接学习。

研习法门属于可选投入执行时间的个人持续行动。它读取：

```text
实际投入小时
悟性 aptitude_comprehension
法门阶级 tier_code
法门品级 quality_code
导师
藏经阁、练功场、工坊、演武场等设施或事件加成
当前神念状态
前置知识、基础法门、装备或资源条件
```

研习法门可以产出：

1. `MethodState` 经验增加。
2. `MethodState` 掌握等级提升。
3. 未入门法门进入 learned level 1。
4. 战斗指令解锁或强化。
5. 行动标签、生产配方或事件选项解锁。
6. 资源效率、成功率、稳定性、消耗、品质或风险修正。

研习法门不能产出：

1. 直接修为进度。
2. 当前可修上限提高。
3. 大境界突破模板类型变化。
4. 缺失残页或篇章自动补齐。
5. 残页或篇章直接变成可用内容。

悟性丹、定心丹等资源可以作为研习法门的行动资源输入，但它们只在研习行动实际执行时提供悟性、稳定性或风险修正，不在非研习行动中产生法门经验。

### 5.6 掌握度与解锁

法门掌握度用于表达角色对某门法门的可用程度、稳定程度和效果边界。掌握度可以影响：

1. 指令、行动标签、事件选项或生产配方是否解锁。
2. 同一效果的强度、持续、品质或覆盖范围。
3. 元气、神念、材料或时间消耗。
4. 成功率、稳定性、失败波动和反噬风险。
5. 事件信息揭示、隐藏层识别和风险预警质量。

掌握度不应绕开法门的系统边界。即使掌握度很高，法门也不能直接增加修为、提高当前可修上限、替代主修道功或把不完整功法载体变成已学内容。

### 5.7 与灵根、资源和地点的相性

法门与灵根的关系主要是使用相性，不直接改变修为进度。

高相性可以表现为：

1. 指令更稳定。
2. 元气或神念消耗更低。
3. 效果质量更好。
4. 失败波动更小。
5. 解锁门槛更低。

低相性可以表现为：

1. 消耗更高。
2. 效果波动更大。
3. 失败或反噬风险更高。
4. 需要更高掌握度、境界、资源或装备才能稳定使用。

示例：

```text
雷系灵根相性高：
使用《雷芒指》时指令稳定性、消耗效率或效果质量更好。

木系灵根相性低：
使用火爆类法门时可能消耗更高、效果不稳定或解锁门槛更高。
```

法门还可以读取资源、装备、地点、事件标签和节点状态。采集法门可以提高隐藏灵植发现率或采集品质，但不能无来源生成超出节点资源池和世界预算的高阶资产；移动法门可以降低路径开销或提高逃遁质量，但不能跳过地图权限、路线封锁或事件强制结算。

### 5.8 与道功的区别

| 判断问题 | 道功 | 法门 |
| --- | --- | --- |
| 是否直接推动修为 | 是 | 否 |
| 是否可设为主修 | 是 | 否 |
| 是否决定当前可修上限 | 是 | 否 |
| 是否决定大境界突破路线标签 | 是 | 否 |
| 是否解锁战斗 / 事件 / 行动能力 | 可有少量附带 | 是主要职责 |
| 是否可被研习提升掌握度 | 是 | 是 |
| 是否可由完整功法学习 | 是 | 是 |

若一个设计同时具备修为推进和能力展开，应按主职责拆分：

1. 推动修为、上限、突破路线的部分写入道功。
2. 战斗、探索、采集、生产、移动、事件选项和效率部分写入法门。

## 6. 资源、角色、地图、事件或 NPC 接口

法门读取：

1. 角色境界、灵根、悟性、神念状态、资源状态、装备和已有 `MethodState`。
2. 法门模板的阶级、品级、分类、路线标签、灵根相性、前置法门和解锁配置。
3. 完整功法载体、教学授予、师承传授、事件奖励或宗门权限等学习来源。
4. 当前行动、战斗、移动、探索、采集、生产或事件的标签、地点、难度、风险和资源输入。
5. 地图节点资源池、路线开销、设施加成、事件状态和世界预算边界。

法门写入：

1. `MethodState` 的入门状态、掌握经验、掌握等级和已解锁内容。
2. 战斗指令、行动标签、事件选项、生产配方或效率修正的可用状态。
3. 对应系统结果包中的法门触发记录、效果质量、消耗、风险、失败原因和日志摘要。
4. 角色可见提示、风险预警、资源损耗变化和隐藏信息揭示结果。

法门不写入：

1. 修为进度、当前可修上限或大境界突破模板。
2. 主修道功状态或主修锁定记录。
3. 残页、篇章或完整功法载体的合成进度。
4. 超出地图、事件或世界预算的资源凭空产出。

## 8. UI 展示边界

普通 UI 应展示：

1. 法门名称、分类、阶级、品级和是否已入门。
2. 当前掌握等级、掌握进度、下一级主要解锁或强化方向。
3. 已解锁的战斗指令、行动标签、事件选项、生产配方或效率能力摘要。
4. 研习条件、时间投入、资源输入、前置要求和不可研习原因。
5. 与当前角色灵根、境界、装备、地点或行动目标相关的相性提示。
6. 使用风险、消耗变化和失败后果的玩家可理解摘要。

普通 UI 不展示：

1. 原始倍率表、完整公式追踪、内部适配矩阵和 Debug 字段。
2. 未发现的隐藏事件选项、隐藏层入口、剧透型秘境信息或未来投放内容。
3. 内部 ID、原始标签集合、未裁决分类、后台预算和节点资源池完整明细。
4. 把法门表达为主修功法、修为进度来源或当前可修上限来源的界面入口。

## 9. MVP 范围

MVP 应实现：

1. `DaoMethod` 与 `TechniqueMethod` 的规则分类。
2. 法门不能设为主修、不能直接推动修为、不能决定当前可修上限的硬边界。
3. 完整功法载体学习后创建 `MethodState`。
4. 法门研习行动，支持基础时间投入、悟性影响和掌握度提升。
5. 至少一组基础法门分类：战斗、移动、探索、采集或生产。
6. 法门解锁行动标签、战斗指令、事件选项、生产配方或效率 / 风险修正的最小闭环。
7. 法门页面能显示分类、入门状态、掌握度、解锁项和不可用原因。

MVP 不实现：

1. 废功重修、功法推演、功法创造、功法融合和复杂功法改造。
2. 残页或篇章直接学习法门。
3. 多法门复杂连携、技能树式深层组合和全部生产技艺曲线。
4. 高阶法门跨阶稳定碾压低阶内容。
5. 所有法门分类、事件选项、战斗指令和生产配方的完整内容表。

## 10. 验收约束

1. 任一功法模板都必须能明确归类为道功或法门。
2. 法门不能被设为主修，不能直接增加修为进度，不能提高当前可修上限。
3. 完整功法载体学习后才创建 `MethodState`；残页和篇章不会创建运行时学习进度。
4. 研习法门不直接给修为，悟性丹在非研习行动中不产生法门经验收益。
5. 法门解锁、效率、消耗、风险和品质修正都必须有作用域和贡献上限。
6. 法门效果不能无来源绕开地图资源池、事件状态、战斗规则、路线权限或世界预算。
7. UI 不能把法门表达为主修道功、修为进度来源或当前可修上限来源。
8. 法门收益、解锁、资源消耗、失败原因、风险变化和状态变化必须能写入对应系统结果包或日志。
