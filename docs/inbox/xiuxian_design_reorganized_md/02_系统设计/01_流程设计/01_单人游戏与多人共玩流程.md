# 流程设计｜单人游戏与多人共玩流程

## 1. 当前结论

本项目的基础流程不是传统实时 MMO，也不是纯单机暂停制 RPG，而是“共享世界 + 可保存房间 + 权威结算 + 可加速低交互阶段”的沙盒流程。

MVP 边界：

```text
本地可单人测试
可部署私人服务器
至少支持 3 人共玩
```

单人房是一等公民；多人是在单人 PvE 宗门沙盒基础上加入真实玩家变量。核心乐趣不依赖高频玩家直接互动。

## 2. 宏观循环

```text
房间创建 / 读取存档
→ 世界种子与节点初始化
→ 玩家创建真灵 / 角色
→ 进入季度或日历推进
→ 宗门行动阶段
→ 角色行动阶段
→ 服务端权威结算
→ 事件链 / 战斗 / 突破 / 后手等插入链
→ 回写角色、宗门、节点、资产、日志、传闻
→ 玩家阅读报告并规划下一阶段
```

## 3. 多人流程边界

MVP 多人默认采用：

```text
分宗并行 + 间接竞争 + PvE 沙盒演化
```

保留两类轻量间接竞争：

1. 宗门节点控制竞争。
2. 世界资源名额竞争。

不作为 MVP 核心验证：玩家直接交易、赠予、互相护法、共同秘境、直接斗法、破坏他人突破、抢夺洞府或后手、复杂同宗议事投票。

## 4. 离线与超时流程

离线和超时玩家采用稳健托管。托管优先级：

```text
保命 / 避险
> 不暴露核心后手
> 延续安全连续状态
> 巩固修炼或基础修炼
> 维持低风险宗门职责
> 休整 / 警戒 / 停留
```

托管不得主动执行高风险突破、主动转世、叛宗、宗门战争、暴露核心后手、高危秘境、强 PvP、消耗稀有不可逆资源或重大路线选择。

## 5. 时间与流速修正案

后期修正案引入 F1 / N1 / B1 / P0：

| 状态 | 用途 |
| --- | --- |
| N1 | 常规推进、主动决策、短行动、事件处理、队列编辑 |
| F1 | 长期低交互行动的高速压缩，例如闭关、养伤、炼制、赶路 |
| B1 | 正式战斗、突破挑战、秘境关键交锋；1 交锋轮 = 1 游戏小时 |
| P0 | 公共阶段事件与同步保护 |

修正案明确移除“跳转到未来时间点 / 推进至下一事件 / 推进至月末”等功能。F1 不是跳转，而是按固定 tick 连续推进。

## 6. 设计历史

早期 S1/S3 使用季度与 6 个朔望行动格描述玩家规划；后期时间规则引入小时级世界日历与流速状态。整理口径：季度仍是玩家宏观规划和多人同步的阶段结构；服务端可在季度内部使用小时 tick 细化结算。

## 7. 缺口

- 季度行动格与小时 tick 的精确换算仍需 S1/S3/S14 后续修订。
- 多人房间锁定、超时时长、房主权限与服务器配置细节未定。
- 宗门 AI 策略独立文档缺失，暂由 S7/S13/S14 约束。
