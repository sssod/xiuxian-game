# 角色与真灵设计｜角色主修功法

## 1. 文档边界

本文记录角色“主修功法”的运行时含义、与修为状态的桥接关系、主修道功更换窗口、锁定规则和相关数据口径。

本文中的“主修功法”是玩家界面和旧文档中常见的泛称；规则层精确名称为“主修道功”。只有道功能成为主修，法门不能设为主修。

本文不重新定义：

1. 道功作为功法类型的完整设计理念、掌握度和上限曲线。
2. 法门作为能力、指令、事件选项和效率体系的规则。
3. 残页、篇章、完整功法等物品链。
4. 每小时修炼公式、境界段数值表和资源输入公式。

边界口径：

| 概念 | 本文是否负责 | 说明 |
| --- | --- | --- |
| 道功定义 | 简述 | 道功是可推动修为并可设为主修的功法 |
| 法门定义 | 只做排除 | 法门不能设为主修 |
| 主修道功 | 负责 | 当前角色修为与道功之间的桥梁 |
| 更换主修 | 负责 | 只记录窗口、锁定、流程和 MVP 边界 |
| 功法载体 | 不负责 | 学习来源和残页 / 篇章属于物品系统 |

## 2. 核心定义

主修道功是当世角色当前正在运转、并以内化灵气为修为为目标的核心道功。

它是角色修为状态与道功模板之间的桥梁：

```text
CharacterState / CultivationState
→ 当前主修道功记录
→ MethodState
→ DaoMethod
→ 修为上限、吐纳收益、自动运转、资源适配和突破路线读取
```

角色同一时间只能有一个主修道功。主修道功不等于装备栏，不占用装备位，也不阻止角色使用法门、法宝或道具。

未设主修道功时，角色不能获得正常修为增长。

## 3. 主修道功决定什么

主修道功决定：

1. 主动吐纳与自动运转读取的修炼路线。
2. 当前境界段的修为吸收、转化和资源适配口径。
3. 当前可修上限。
4. 小境界升级是否受当前道功支持范围覆盖。
5. 大境界突破路线标签、挑战倾向、奖励结构和失败标签池。
6. 一部分被动加成、资源适配和角色状态反馈。
7. 角色摘要、修为页和主修功法界面的核心显示信息。

主修道功不决定：

1. 法门能否使用。
2. 法宝和道具是否占用装备或物品栏。
3. 残页或篇章是否可直接学习。
4. 角色真灵是否跨世继承当前功法掌握。
5. 大境界突破是否可绕过准备、资源、地点、状态和事件挑战。

## 4. 设置主修的前置条件

设置主修道功时至少需要校验：

1. 目标功法类型为道功。
2. 角色已经学会该道功并拥有对应 `MethodState`。
3. 该道功支持角色当前境界或当前目标修炼阶段。
4. 角色状态没有被封印、重伤、昏迷、特殊事件等规则禁止换修。
5. 当前处于允许更换主修道功的窗口，或存在明确事件 / 剧情 / 特殊规则授权。

法门即使已经学会，也只能作为能力、指令、事件选项或效率修正来源，不能被设为主修。

## 5. 改修窗口

主修道功常规只在大境界第一小阶段开放无时间成本更换。

抽象示例：

```text
A-1
B-1
C-1
D-1
……
```

包装示例：

```text
炼气 1 层
筑基初期
金丹初期
元婴初期
……
```

离开第一小阶段后，本大境界主修路线锁定，直到进入下一大境界第一小阶段。

主修道功切换不消耗行动格，不占用固定回合时间预算。它是角色修炼路线选择，不是研习功法、合成载体或装备切换。

## 6. 锁定记录

每个大境界需要记录该大境界最终锁定的主修道功，用于后续读取突破模板、奖励结构、失败标签池和已固化根基。

推荐口径：

1. 在大境界第一小阶段内，当前大境界的主修记录可以被常规更换覆盖。
2. 离开第一小阶段后，当前大境界主修记录锁定。
3. 已固化根基不会因为之后进入更高大境界并更换主修道功而改变。
4. 大境界圆满、临近下一次大境界突破时，不能临时更换主修道功以规避突破难度。

示例：

```text
角色在 B-1 期间从《青木养真诀》改为《青木长生经》。
进入 B-2 后，B 阶主修记录锁定为《青木长生经》。
之后即使进入 C-1 并改修另一门道功，B 阶已固化根基仍读取《青木长生经》。
```

## 7. 与小境界升级的关系

小境界升级必须受当前主修道功支持范围限制。

规则：

1. 当前小阶段进度达到 100% 后，系统先校验主修道功支持范围。
2. 若主修道功支持下一小阶段，且状态合法，则可进入下一小阶段。
3. 若主修道功只支持到当前小阶段上限，该道功不能把角色推进到下一小境界 0%。
4. 自动运转通常可以触发普通小境界升级，但仍受主修道功支持范围限制。
5. 自动运转不能完成大境界突破。

示例：

```text
某道功只支持到金丹初期 100%。
角色达到金丹初期 100% 后，不能依靠该道功自动进入金丹中期 0%。
```

设计目的：

1. 避免旧主修道功的小境界升级奖励污染当前大境界后续阶段。
2. 避免功法支持范围被阶段自动升级绕过。
3. 让“当前可修上限”成为有效路线约束。

## 8. 与大境界突破的关系

大境界突破读取当前大境界最终锁定的主修道功记录。

读取内容包括：

1. 突破路线标签。
2. 挑战倾向。
3. 奖励结构。
4. 失败标签池。
5. 功法阶级与品级配置。
6. 资源转化方向和短板检查。

大境界突破开启前至少需要校验：

```text
当前境界段进度达标
MethodState 掌握度满足目标阶段要求
根基、经脉压力、伤势、心魔等状态满足下限
当前地点允许突破
主修道功突破模板可用
开启阶段所需资源可用
```

掌握度影响的是“是否满足目标阶段承载和开启条件、执行表现是否稳定、相关风险是否更清晰”，而不是把一门道功的突破模板类型改造成另一门道功。

## 9. 主修更换不做什么

MVP 不做：

1. 废功重修。
2. 改修折算。
3. 功法上限后的免费续接换主修。
4. 临近大境界突破时临时换功降低挑战。
5. 中途换主修惩罚。
6. 主修道功经验按比例转移到新道功。
7. 残页或篇章直接补足主修道功进度。

不因为以下原因开放免费换主修：

1. 当前道功理论上限达到。
2. 当前掌握度上限达到。
3. 玩家后悔选择主修。
4. 玩家想临时换更优突破模板。
5. 玩家本世想继续但当前路线不够理想。

## 10. 提醒与 UI 口径

MVP 不在 B-1 → B-2 等小境界升级结算关口插入“是否继续突破小阶段”的强制确认事件。

原因：

1. 小境界升级发生在结算阶段。
2. 插入确认会打断主动吐纳或自动运转结算。
3. 玩家选择不升级可能造成行动规划未成功的损失感。
4. MVP 应保持小境界升级轻量顺滑。

提醒应常驻在：

1. 主修功法更换界面。
2. 主修道功详情界面。
3. 角色修为摘要区。
4. 接近第一小阶段结束时的提示或日志。

示例文案：

```text
当前处于筑基初期，仍可无时间成本更换本大境界主修道功。
当修为推进至筑基中期后，本大境界主修道功将锁定，直至进入金丹初期。
```

## 11. 数据口径

推荐状态字段：

```yaml
MainMethodState:
  character_id: string
  current_main_method_state_id: string
  current_main_method_id: string
  current_main_method_type: dao_method
  current_major_realm_id: string
  locked_major_realm_main_records: list
  last_changed_world_day: number
  last_changed_world_hour: number
  last_changed_at_stage: string
  change_window_available: bool
```

大境界主修锁定记录：

```yaml
MajorRealmMainMethodRecord:
  character_id: string
  major_realm_id: string
  locked_method_state_id: string
  locked_method_id: string
  locked_at_stage: string
  locked_world_day: number
  locked_world_hour: number
  breakthrough_route_tags: list
  reward_profile_ref: string
  failure_tag_pool_ref: string
  foundation_record_ref: string
```

主修道功相关运行时上限：

```yaml
MainMethodEffectiveCap:
  character_id: string
  method_state_id: string
  theoretical_max_cap_stage: string
  mastery_current_cap_stage: string
  effective_current_cap_stage: string
```
