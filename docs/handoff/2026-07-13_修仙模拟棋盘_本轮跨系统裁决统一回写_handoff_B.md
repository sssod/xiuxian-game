## 4. 当前有效裁决与历史段落边界

### 4.1 `CULT-01`

正式规则以 `CULT-R08—R21` 为主。`CULT-R01—R07` 和独立 `φ` 插值方案已经被概念重置或后续掌握方案替代，只能留在裁决汇总中作过程审计，不能进入专题正文。

必须保真：

- 标准 CP 是境界进度唯一来源；
- 普通改修不扣标准 CP，也不改变小境界；
- “实际修为”“有效修为”不再作为跨系统正式术语，统一改为“修为强度”；
- 道功配置 `α_template / β_template / C_template`；
- `α` 决定以后吸收灵气写入标准 CP 的速度；
- `β × M_dao` 决定相同标准进度下当前道功能发挥的修为强度；
- 当前主修重算本世完整累计标准修为量，不保存历史道功快照；
- 掌握与门槛统一，单条效果链同一知识来源只读取一次掌握；
- 自动修炼逐内部时间单位先于自动研习；
- 节点灵气、丹药等效灵气和直接标准 CP 奖励分流；
- `S0` 提供炼气 `0%` 的非零强度，不参与境界进度；
- 普通 UI 只显示最终境界进度、灵气吸收速度、修为强度和最终效果。

### 4.2 `SHIELD-01`

- 所有普通与护劫护盾写入一个总护盾值；

- 每次普通护盾生成先受开战最大生命 `50%` 单次上限；
- 护劫护盾可超过普通单次上限，但仍计入总上限；
- 渡劫开战先生成护劫护盾，再按稳定事件顺序生成其它开战护盾；
- 溢出作废，不替换、不压缩已有总护盾；
- 战中最大生命变化不追溯修改本场上限；
- 伤害先经通用增减伤，再扣总护盾，剩余部分进入体魄减伤；
- 战斗结束清空，连续战斗下一场重新从 `0` 开始。

## 5. `CULT-01` 回写要求

### 5.1 唯一术语与职责

专题正文统一使用：

| 术语 | 唯一职责 |
| --- | --- |
| 境界进度 / 标准 CP | 小境界、瓶颈、突破入口、境界能力解锁 |
| 修为强度 | 同境道功路线产生的基础强弱，是战斗公式输入但不等于总战力 |
| 道功掌握 | 门槛内容与模板字段发挥倍率 |

普通 UI 不显示标准 CP 原始数、`α / β / M / √M` 或中间乘区。规则说明、内容表、Debug 和验算可以保留内部字段。

删除或改写以下陈旧口径：

- 改修会因有效修为变化而改变小境界；
- 改修重算或折算标准 CP；
- 历史境界保存旧道功强度快照；
- 研习等同获得修为或境界进度；
- 一个“有效修为”同时承担进度、战力和熟练度；
- 旧 `S06-K80` 的小境界变化语义。

### 5.2 核心公式

正文需要给出唯一公式链：

```text
节点灵气输入 L_node
= 节点基础灵气 + 当前回合全图固定增量

实际灵气吸收效率 A_dao
= α_template × M_dao × 其它明确吸收修正

本单位写入标准 CP
= L_node × A_dao
+ L_pill × A_dao
+ 明确绕过吸收的直接标准 CP 奖励
```

节点与丹药分别计算后精确相加，再按统一 `0.01` 标准 CP 精度写入；不得逐来源取整。普通修为丹药默认只提供 `L_pill`，不放大节点，也不直接赠送标准 CP。

本世累计标准修为量：

```text
S_total
= 当前身体已经重新达到并完成的各大境界固定总 CP 之和
+ 当前大境界内标准 CP

修为强度
= (S0 + S_total) × β_template × M_dao
+ 其它不重复读取本道功掌握的合法修正
```

`S0`、`1A`、各境总 CP、道功模板值和其它战斗常数继续标记为正式配表缺口。

### 5.3 时序、瓶颈与转世

每内部时间单位：

```text
快照节点 / 全图增量 / 主修 / 掌握 / 丹药 / 状态
→ 写入标准 CP
→ 处理小境界阈值与瓶颈截断
→ 自动研习
→ 新掌握从下一单位提高灵气吸收
```

- 到瓶颈只写入抵达所需 CP，溢出不预存、不返还；
- 改修保持标准 CP 和境界，立即重算当前完整 `S0 + S_total` 的修为强度；
- 同一世取得高品级道功后不要求重修历史境界；
- 转世恢复 `S0`，不恢复上一世 `S_total`；
- 历史突破只免除重复突破，新身体重新修满对应境界后才把该境固定总 CP 纳入本世累计量。

### 5.4 掌握与内容制作

- 道功和法门共用 `25 / 50 / 75` 门槛与 `0.70 / 0.85 / 0.95 / 1.00 / 1.10` 五阶段倍率；
- 道功 `α` 与修为强度系数读取 `M_dao`；
- 战斗法门允许字段读取 `M_fa`；
- 移动法门以离散门槛为主；
- 当前主修道功自身、以修为强度为基础的效果不再在效果系数上第二次读取同一 `M_dao`；
- 特殊模板确需拆分时，内部使用 `√M_dao × √M_dao = M_dao`，不向玩家展示；
- 内容制作优先避免这种特殊结构。

### 5.5 必须保留的验算

专题或数值验收至少保留汇总中的八类用例：标准开局、同品级切换、高品级低掌握、研习跨阶段、节点与丹药分流、瓶颈、小洞天逐单位、转世与高品级历史重算。示例数字必须标记为夹具，不得混入正式表。

## 7. `F-04 / END-01` 回写要求

- 大厅本身没有强制结束倒计时；

- 条件失效立即取消，条件保持则自动开局；

- 房主离开时移交给最早加入的连接玩家；房主无强制开局或对局特权。

### 7.2 阶段计时与安全默认

标准房间：

| 阶段 | 基础时限 |
| --- | ---: |
| 回合开始即时阶段 | `60` 秒 |
| 隐藏规划 | `90` 秒 |
| 行动细节输入 | `45` 秒 |
| 事件 / 竞争短响应 | `30` 秒 |

每名玩家另有 `180` 秒整局跨阶段个人思考储备。所有相关玩家完成后可以提前结束。

- 即时完成与隐藏提交在锁定前可撤回；
- 全员完成触发 `3` 秒收束，撤回会取消；
- 单独确认并结算的即时行动不回滚；
- 单人参数确认开始结算后不能撤回；
- 多人隐藏输入共同锁定前不公开。

安全默认：

- 即时超时：保留已确认结果，丢弃未确认编辑并结束；
- 规划超时：留驻，不移动、不用移动资源、不执行主要行动，正常回合末成长；
- 参数超时：主动放弃行动，不支付未确认费用，不取得“客观无合法参数”代偿；
- 竞争超时：不出价、不追加或放弃可选资格；
- 每个强制选择事件模板必须有无额外消费、低风险、不改变他人资产的安全默认。

### 7.3 掉线、重连与托管

- 每次断线最多保护 `60` 秒，每人整局累计最多 `180` 秒；
- 断线期间冻结本人的输入计时和思考储备；
- 不依赖掉线者的独立流程继续；
- 保护耗尽后立即使用安全默认并进入 MVP 无策略托管；
- MVP 托管只继续锁定构筑自动战斗、回合末成长、恢复、炼化、寿元、地产与世界结算；
- 不主动移动、消费、竞价、换功、调构筑、发起冲突或逃遁；
- 玩家可主动开启安全托管；房主不能操作他人托管；
- 重连不回滚结果，只接管尚未锁定输入，并显示不泄露隐藏信息的追赶摘要；
- 未来单人模式策略 AI 成熟后升级为只读取合法信息的保守策略托管，该方向只记为未来，不进入 MVP 阶段门。

### 7.4 连续掉线 `10` 分钟与退隐

必须区分：

```text
60 / 180 秒：停止等待并进入临时托管
连续 10 分钟：永久失去重连资格，进入待退隐
```

- 主动托管不累计连续掉线；
- 恢复连接立即暂停累计，稳定 `30` 秒后清零；稳定期内再次掉线续算旧值；
- 达到 `10` 分钟的一刻即永久不可重连；
- 角色实际退隐统一在下一次外界回合开始更新完成后、即时阶段向玩家开放前执行；
- 若阈值在即时阶段中途达到，不中途移除，延至再下一回合即时阶段第一步；
- 在线主动永久退出也必须使用相同即时阶段退隐边界；
- 结束表决的全局暂停冻结连续掉线累计；
- 全员离线时世界冻结，但连续连接资格计时继续；最后一个席位也达到阈值后直接全员退隐、无胜者中止，不推进无人回合。

### 7.5 退出资产与地产

退隐时：

- 角色、当前修为、状态、知识、掌握和全部个人数值停止维护；
- 随身灵石、物品、法宝和未学功法载体由系统回收；
- 退隐本身不产生死亡掉落；
- 已锁定战斗与因果链先结算，不能用退出逃避支付、战败或掉落；
- 个人订单 / 收入到退隐回合时直接回收，不建立幽灵账户；
- 地产保留为退隐宗门地产，不因退出直接转无主或赠予其他玩家；
- 原应支付给退出玩家的费用由系统回收，稳定供养作废；
- 已锁定公共建设状态照常完成；
- 事件等正式游戏内规则以后仍可合法取得退隐地产，易主后按新玩家正常结算；
- 只剩一名未退隐玩家时不自动胜利，仍需正常飞升。

### 7.6 主动结束

- 任一连接正常且未退隐玩家可以发起；同一回合最多一次；
- 发起后进入真正的全局暂停；
- 阶段计时、思考储备、断线保护、连续掉线累计、自动战斗、动画推进和游戏结算全部冻结；
- 只有 `30` 秒表决、连接检测、重连和表决 UI 继续；
- 全部未退隐玩家必须亲自同意，掉线、托管、AI、房主均不能代投；
- 全员同意后有 `3` 秒撤回缓冲；
- 失败后从暂停前同一确定状态恢复；
- 规划未全局锁定时，完成当前不可拆分即时结算后结束；
- 规划已经锁定时，恢复并完整结算本轮；
- 同轮合法飞升优先形成正常胜利；否则记录“共同中止、无胜者”；
- 复盘可显示最终状态，但不得生成按修为、地产或资产排序的替代名次。
