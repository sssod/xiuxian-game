## 1. 继承约束

### 1.1 项目与 MVP 约束

- 游戏定位：文字 / 策略、选择导向、个人成长 + 宗门经营 + 沙盒演化的修仙轮回沙盒。
- MVP 边界：本地可单人测试、可部署私人服务器、支持 3 人共玩。
- 技术路线：Godot 客户端 + Godot Headless / Dedicated Server，权威服务器统一结算。
- 世界不会在无人在线时自动推进，只在季度推进中演化。
- 内容与规则应数据驱动，避免硬编码修仙包装名。

### 1.2 时间与行动约束

- 世界采用季度回合制。
- 每季度包含世界刷新、宗门行动阶段、角色行动阶段、权威服务器结算、日志 / 传闻更新。
- 玩家角色每季度有 6 个朔望行动格。
- 移动、持续行动、事件链中断均通过 S3 时间轴表达。
- 宗门行动一般不受玩家当前位置限制；玩家亲自介入宗门行动时必须走 S3 的节点、tick、路线与行动格校验。

### 1.3 地图节点约束

- 地图采用有向带权节点图。
- 地图主单位是地理节点。
- 资源和建筑不是独立漂浮物，而是挂载在地理节点上的槽位层。
- 节点可包含：地理属性、资源槽、建筑槽、控制权、宗门影响力、驻守状态、事件槽、隐藏层、前世后手层、路线连接。
- 节点归属采用“控制权 + 影响力”混合模型。
- 控制权变更采用阈值 + 事件模型，不要求玩家逐个节点手动接管。

### 1.4 宗门与经济约束

- 每个宗门每季度始终只有 1 个宗门主行动。
- 已控制资源节点的稳定产出走常态结算，不占用宗门主行动。
- 宗门资源必须来自真实库存；贡献不是货币，不能绕过库存检查。
- MVP 宗门库存追踪五类资源：灵石、修炼资源、材料 / 矿材、人力 / 弟子规模、声望 / 影响力。
- 灵石是通货，但不是万能高阶灵气资源；高阶需求通过聚灵石、阵法、设施、特殊资源等机制限制。
- 事件生成奖励、秘境奖励、后手奖励等需要受分阶生成预算控制。

### 1.5 事件与后手约束

- S10 负责节点事件、世界事件、秘境窗口、控制权变化、传闻与事件结果包。
- 事件结果不能绕过 S1，必须通过 EventOutcome / Result Package 统一回写角色、宗门、节点、库存、日志。
- 世界日志默认玩家不可见；玩家看到的是角色日志与传闻。
- 正式后手必须可追踪、有日志、失效有原因链；不能无理由永久抹除。
- MVP 不做玩家直接抢洞府、破坏他人突破、直接强 PvP 毁长期体验。

## 2. 一句话定位

> 沙盒世界演化不是完整生态模拟，而是一个由地图节点模板、资源池、灵气环境、宗门行动、事件压力、秘境窗口和后手隐藏层共同驱动的“季度状态机”。
> 

设计重点不是让世界每个角落都自动生活，而是让玩家能感受到：

1. 地图节点不是静态菜单，而会因宗门、资源、事件、灵气和玩家行动改变。
2. 宗门不是背景势力，而会通过节点控制、资源争夺和事件响应改变世界格局。
3. 资源不是凭空奖励，而来自节点产能、秘境窗口、事件预算、后手封存或库存转移。
4. 灵气、危险、秘境、妖兽、突破、资源、宗门争夺之间存在可解释关联。
5. 玩家正式布置的后手会嵌入世界演化，但不会被无日志、无原因地抹掉。

## 3. 设计原则

### 3.1 先确定玩法承载，再反推地图排布

世界地图不是先生成一张地理图，再硬塞玩法内容。

推荐流程：

```
确定 MVP 需要验证的玩法闭环
→ 确定必须存在的节点功能
→ 确定节点之间的行动格距离、风险距离和宗门距离
→ 生成半固定节点图
→ 按节点模板挂载资源、建筑、事件、隐藏层和后手入口
```

MVP 首张地图至少要承载：

- M0 新手入门路线。
- 3 个主要宗门原型，支持 3 人分宗并行的 MVP 验证。
- 至少一条宗门资源常态产出链。
- 至少一次资源节点控制 / 影响力变化。
- 至少一个秘境 / 窗口事件。
- 至少一个正式后手创建与回收链路。
- 至少一个可引发宗门间间接竞争的资源或秘境名额。

### 3.2 节点只表达“有决策意义的地点”

不需要把所有地形都拆成节点。

节点应满足至少一项条件：

- 会影响移动成本、风险或路线选择。
- 有资源槽、建筑槽、事件槽、隐藏层、后手层。
- 是宗门控制、影响力争夺或行动目标。
- 是玩家能执行持续行动、交通设施使用、交易、突破、回收后手等行为的地点。
- 是传闻、秘境、重大事件或地图认知的锚点。

纯地理距离可以由边权表达，不必拆成节点。

### 3.3 用“状态层”表达活世界，而不是高成本 NPC 生态

MVP 不做深度 NPC 生活模拟。

世界活性优先来自：

- 节点状态变化。
- 宗门影响力变化。
- 资源槽丰度、枯竭、异变、污染、再生。
- 建筑维护、损坏、修复、占领。
- 秘境窗口开启 / 关闭。
- 事件压力累积与爆发。
- 传闻传播。
- 后手风险状态变化。

### 3.4 所有高价值变化必须可追踪

高价值变化包括：

- 节点控制权变化。
- 资源槽枯竭、升级、污染、隐藏发现。
- 秘境开启、关闭、坍缩。
- 宗门库存大额变化。
- 正式后手暴露、受损、被争夺、被搬空。
- 高价值 NPC、N4 或宗门战略行为造成的地图变化。

这些变化必须写入世界日志；玩家能否看到，另由传闻、角色日志、宗门权限和情报能力决定。

## 4. 世界地图的分层模型

### 4.1 推荐世界状态结构

```
WorldState {
  world_seed
  current_quarter
  regions
  map_graph
  factions
  resource_budgets
  event_pressure_state
  active_major_events
  temporary_nodes
  rumor_pool
  world_logs
}
```

### 4.2 地图节点扩展结构

在既有 S8 WorldNode 基础上，建议扩展为：

```
WorldNode {
  node_id
  display_name_key
  node_type
  region_id
  zone_tier
  recommended_stage_range

  visible_state
  danger_profile
  aura_profile

  owner_control
  faction_influence_map
  garrison_state

  resource_slots
  building_slots
  event_slots
  entrance_slots
  hidden_layers
  legacy_layers

  route_connections
  node_state_tags
  cooldown_tags
  world_log_refs
}
```

其中新增字段口径：

- `zone_tier`：节点所在区域的内容阶层，建议使用 A / B / C 等抽象编码，不绑定炼气、筑基、金丹包装。
- `recommended_stage_range`：玩家建议接触阶段，例如 A-1 到 B-3；只用于内容筛选与提示，不作为硬锁。
- `danger_profile`：节点危险结构，不只是一个等级，可包含妖兽、匪修、宗门冲突、环境灾害、秘境波动等标签。
- `aura_profile`：节点背景灵气与可用灵气结构。
- `entrance_slots`：用于挂载临时秘境入口、洞府入口、临时通道、异常空间入口等。
- `node_state_tags`：节点当前态势标签，如 `contested`、`resource_stressed`、`aura_surge`、`route_blocked`。
- `cooldown_tags`：避免同类事件在短期内重复爆发。

### 4.3 区域层结构

区域不是行政区，而是地图生成与事件演化的中层容器。

```
RegionState {
  region_id
  display_name_key
  region_type
  zone_tier
  base_aura_band
  base_danger_band
  climate_or_terrain_tags
  dominant_factions
  region_pressure_tags
  major_event_slots
  resource_budget_refs
}
```

MVP 区域建议至少有三类：

1. 新手 / 凡俗边缘区：村庄、镇集、低阶山道、低风险移动事件。
2. 宗门腹地区：宗门山门、坊市、药田、矿场、训练设施、弟子行动范围。
3. 边界 / 荒野 / 禁地区：争夺资源、秘境入口、高危事件、后手隐藏层、宗门间接竞争。

## 5. 世界初始生成：从玩法需求反推节点排布

### 5.1 半固定种子地图原则

MVP 不建议使用完全自由的程序生成地图。

推荐方案：

```
固定核心骨架 + 随机槽位填充 + 稳定种子扰动
```

固定内容：

- 主要宗门数量与核心位置。
- 新手村 / 镇集 / 初始宗门入门路线。
- 主交通路线。
- 基础资源节点数量下限。
- 第一批可验证秘境 / 后手 / 控制权争夺节点。

随机内容：

- 资源槽具体类型、丰度、隐藏状态。
- 部分荒野节点危险类型。
- 秘境窗口出现节点。
- 传闻起始线索。
- 部分隐藏路线。
- 少量前世后手适配点。

### 5.2 推荐地图骨架

MVP 首张地图建议包含：

- 3 个主要宗门。
- 每个主要宗门 1 个山门核心节点。
- 每个主要宗门 2–4 个稳定控制节点。
- 每个主要宗门 1–2 个边界争夺节点。
- 1–2 个中立坊市 / 交通枢纽。
- 2–4 个凡人村镇 / 入门过渡节点。
- 4–8 个资源型地理节点。
- 3–6 个荒野探索节点。
- 1–3 个高危禁地或秘境锚点。
- 若干临时节点槽位，用于秘境、灾害、战场、后手入口等季度生成。

已定规则：首张 MVP 常驻节点规模控制在 **35±10 个**，临时节点同时存在 **0–6 个**。低于 20 个容易缺少宗门和资源空间；高于 60 个会显著增加事件、UI、调试和内容生产成本。

### 5.3 宗门空间结构

每个主要宗门推荐使用四层空间结构：

```
宗门核心
→ 宗门腹地
→ 边界争夺带
→ 外围荒野 / 禁地
```

#### 宗门核心

包含：山门、主殿、内门区域、主要修炼设施。

规则定位：

- 控制权稳定。
- 背景灵气较高。
- 建筑槽多。
- 节点事件以宗门内部、培养、突破支持、职位、资源申请为主。
- 外敌直接夺取不进入 MVP 常态规则。

#### 宗门腹地

包含：宗门坊市、药田、矿场、灵脉支脉、低危试炼地。

规则定位：

- 常态产出主要来源。
- 宗门影响力高。
- 可出现小型危机、资源异变、维护成本、弟子任务。
- 适合验证“已控制资源节点不占宗门主行动，稳定产出走常态结算”。

#### 边界争夺带

包含：争议矿脉、秘境入口、灵脉交汇点、荒废洞府、边境坊市。

规则定位：

- 控制权可能变化。
- 宗门间影响力接近。
- 节点事件、资源窗口、宗门行动更容易触发竞争。
- 多人间接竞争优先发生在这里。

#### 外围荒野 / 禁地

包含：妖兽巢穴、旧战场、秘境群、断裂灵脉、高危山脉。

规则定位：

- 资源价值高，但危险大。
- 常规控制难度高。
- 更适合临时节点、秘境窗口、后手隐藏层和重大事件。
- MVP 不做常态大规模战争，只做远征事件链和阶段性影响力变化。

## 6. 主要宗门的初始分布与演化边界

### 6.1 宗门初始类型

MVP 固定使用 3 个主要宗门原型：

1. 稳健型宗门：腹地资源稳定，扩张欲较低，培养 / 防守倾向高。
2. 扩张型宗门：边界行动频繁，远征 / 争夺倾向高，资源波动大。
3. 秘境 / 技艺型宗门：探索、阵法、炼丹、秘境窗口倾向高，控制节点少但高价值事件多。

不建议 MVP 引入过多宗门层级。小家族、小帮派、散修势力、坊市联盟可以先作为节点影响力或事件标签，不必都成为完整宗门行动主体。

### 6.2 宗门初始资产结构

每个主要宗门至少需要：

```
SectSeed {
  sect_id
  sect_archetype
  home_node
  core_control_nodes
  stable_resource_nodes
  contested_interest_nodes
  initial_inventory
  strategic_tendency
  diplomacy_tags
  visibility_to_players
}
```

推荐初始结构：

- 1 个山门核心节点。
- 1 个坊市 / 外门服务节点。
- 1–2 个稳定资源节点。
- 1 个修炼或突破支持设施节点。
- 1–2 个边界兴趣节点，初始未必控制。
- 1 组宗门战略倾向权重。

### 6.3 影响力梯度

宗门初始影响力不应只按节点归属二分，而应按距离、路线、控制节点和事件状态形成梯度。

```
核心节点：高控制 + 高影响力
腹地节点：控制或高影响力
边界节点：多宗门影响力接近，易触发竞争事件
荒野节点：低控制，影响力来自驻守、探索、传闻、路线开放
```

影响力来源：

- 节点控制权。
- 路线距离与通行成本。
- 驻守与建筑。
- 宗门声望。
- 历史行动。
- 节点事件结果。
- 玩家或 N4 关键行为。

### 6.4 宗门季度演化边界

MVP 中宗门可以演化：

- 改变节点影响力。
- 争夺或失去边界节点控制权。
- 开采、修复、建设、驻守、探索、远征、培养。
- 发现或错过资源 / 秘境窗口。
- 消耗或增加宗门库存。
- 生成传闻与世界日志。

MVP 中宗门暂不常态演化：

- 不完全灭门。
- 不迁移山门。
- 不大规模吞并宗门。
- 山门核心节点不允许被 AI 宗门普通行动夺取；只允许重大事件链造成临时影响。
- 不生成复杂附庸体系。
- 不因为 N4 多而获得额外宗门主行动。
- 不直接围杀玩家、破坏玩家突破或抢夺正式后手。

宗门大变局可作为重大事件链，但不作为普通季度模拟。

## 7. 资源槽初始化、再生、变化与投放控制

### 7.1 资源槽不是库存

资源槽代表节点潜在产能，不等同于已经存在的库存。

```
ResourceSlot {
  slot_id
  node_id
  resource_type
  tier_code
  abundance_state
  extraction_difficulty
  regeneration_rule
  depletion_pressure
  contamination_state
  discovery_state
  controlling_faction_bonus
  budget_class
  state_tags
}
```

资源槽通过开采、采集、宗门常态结算、宗门主行动、事件链或配方加工，转化为：

- 宗门抽象库存。
- NodeStorage。
- 个人 ItemStack / ItemInstance。
- EventLocked 奖励包。

### 7.2 资源初始化规则

资源槽初始化应由以下输入共同决定：

```
区域阶层
+ 节点类型
+ 基础灵气浓度
+ 地形 / 地貌标签
+ 宗门控制状态
+ 世界种子随机扰动
+ 内容投放预算
```

示例：

- 高背景灵气 + 山脉节点：更容易生成灵脉、矿脉、妖兽、洞府、秘境波动。
- 中等灵气 + 宗门腹地：更适合药田、低阶矿场、修炼设施、稳定产出资源。
- 低灵气 + 凡人聚落：主要生成低阶物资、情报、入门任务、低阶货币消费点。
- 灵气异常 + 荒野：更适合秘境入口、污染资源、妖兽潮、失控阵法。

### 7.3 资源类型分层

MVP 资源槽建议分三类：

#### 稳定基础资源

用于宗门常态产出。

特点：

- 低波动。
- 可季度结算。
- 主要进入宗门抽象库存。
- 事件只在过度开采、建筑损坏、敌对干扰或资源异变时触发。

示例：普通矿场、低阶药田、灵脉支流。

#### 机会型资源

用于事件、探索和窗口。

特点：

- 不一定每季度产出。
- 需要探索、宗门主行动或事件链触发。
- 可以进入 EventLocked。
- 适合制造玩家阶段目标。

示例：灵草成熟窗口、矿脉深层、流动灵泉、小型秘境残片。

#### 稀有高价值资源

用于突破、后手、秘境、重大事件。

特点：

- 不直接常态产出。
- 需要隐藏层、秘境、重大事件或高难行动。
- 必须消耗生成预算或已有库存。
- 必须写日志。

示例：高阶突破主材、命名法宝材料、真灵相关遗物、稀有聚灵材料。

### 7.4 资源再生规则

资源再生不使用一个全局公式，而按模板配置。

推荐再生类型：

```
none                // 不自然再生，只能事件刷新或一次性资源
slow                // 缓慢恢复
seasonal            // 按季度或季节性恢复
controlled_stable   // 控制权稳定且设施正常时稳定产出
facility_assisted   // 需要建筑或维护资源辅助恢复
event_only          // 只通过事件或重大变动改变
```

资源槽每季度状态变化建议读取：

- 当前丰度。
- 本季度开采压力。
- 控制宗门投入。
- 设施维护状态。
- 节点灵气变化。
- 污染 / 灾害 / 妖兽 / 争夺事件。
- 是否处于重大事件影响范围。

### 7.5 过度开采与资源压力

资源槽应有 `depletion_pressure`，用于表达过度开采风险。

典型流程：

```
常态开采 → depletion_pressure 小幅上升或稳定
加大开采 → 短期产出上升，depletion_pressure 上升
压力过高 → 触发资源异变 / 丰度下降 / 建筑损坏 / 妖兽袭扰 / 污染事件
休养或维护 → pressure 下降，丰度慢恢复
```

这样可以让宗门经营产生取舍：短期加大开采可补库存，但会提高后续节点危机概率。

### 7.6 投放控制

资源投放不应完全依赖随机概率。

推荐建立分阶预算：

```
WorldResourceBudget {
  world_id
  tier_code
  budget_type       // stable / opportunity / rare / legacy
  max_value
  spent_value
  reserved_value
  refresh_rule
}
```

使用口径：

- 稳定基础资源：按地图骨架保证下限。
- 机会型资源：按区域 / 阶段预算生成。
- 稀有资源：必须由事件、秘境、隐藏层或后手链路承载。
- 正式后手资源：不和普通随机奖励池混用，走后手记录与 SealedLegacy 容器。

重要原则：

- 高价值物品一旦实例化，按完整价值扣除预算。
- 出售、拆解、销毁、上交、损坏不返还生成预算。
- 预算用于控制世界投放，不是玩家可见资源池。

## 8. 临时地图节点与秘境入口

### 8.1 临时节点定位

临时节点用于表达“不应长期存在于常驻地图、但在一段时间内可被进入、探索或影响”的空间。

典型类型：

- 临时秘境空间。
- 洞府显露入口。
- 战场 / 驻扎营地。
- 灾害区域。
- 封锁路线。
- 临时坊市 / 拍卖会。
- 后手暴露点。
- 传送异常空间。

### 8.2 临时节点结构

```
TemporaryNode {
  temp_node_id
  anchor_node_id
  temp_node_type
  created_by_event
  lifecycle_state
  open_quarter
  close_quarter
  entry_conditions
  exit_rules
  inherited_region_tags
  aura_override
  danger_override
  resource_slots
  event_slots
  legacy_layers
  route_edges
  resolution_policy
}
```

生命周期建议：

```
rumored
→ located
→ open
→ active
→ collapsing
→ closed
→ resolved / archived
```

### 8.3 临时节点连接规则

临时节点不应随意插入全图，而应绑定一个或多个锚点。

连接规则：

1. 每个临时节点必须有 `anchor_node_id`。
2. 默认只从锚点节点生成入口边。
3. 入口边可以有行动格成本、权限、危险、开启窗口、队伍限制、宗门名额限制。
4. 临时节点继承锚点所在区域的基本标签，但可以覆盖灵气、危险、资源、事件。
5. 临时节点关闭后，主动入口边失效；节点记录保留到日志与回放中。
6. 未结算资产按 `resolution_policy` 处理：封存、崩毁、转移、留作隐藏层、生成后续传闻。

### 8.4 秘境入口的关联与展现

秘境入口默认不作为地图上的独立节点，而通过常驻节点上的 `EntranceSlot` 表达。例外：少数著名秘境可以作为常驻高危节点存在，用于承载高识别度、长期存在、可反复围绕其产生争夺和传闻的世界地标。

推荐两层表达：

```
EntranceSlot：挂在常驻节点上的入口槽
TemporaryNode：入口开启后生成的临时空间节点
```

```
EntranceSlot {
  entrance_id
  anchor_node_id
  entrance_type
  discovery_state
  window_state
  linked_temp_node_id optional
  access_conditions
  faction_claims
  rumor_refs
  event_refs
}
```

玩家侧展示：

- `unknown`：完全不可见。
- `rumored`：节点传闻显示“此地近期灵气有异”。
- `located`：节点面板显示“疑似秘境入口”，但可能未开启。
- `open`：节点面板显示可进入入口，并提供进入、驻守、封锁、上报宗门等操作。
- `closing`：提示窗口将关闭，行动有撤离风险。
- `closed`：入口消失，但日志 / 传闻 / 后续线索可能保留。

地图 UI 上，普通秘境入口优先作为节点叠加标记，不默认铺成新的全图节点；玩家点击入口后再进入临时空间子图或事件链。著名秘境作为常驻高危节点时，可以在地图上长期显示，但其内部空间、具体窗口和可进入阶段仍可通过 `EntranceSlot` 与 `TemporaryNode` 管理。

## 9. 灵气浓度规则

### 9.1 区分背景灵气与可用灵气

灵气至少分两层：

1. 背景灵气：节点自然环境灵气，影响修炼效率、妖兽、资源、秘境、突破地点基础条件和事件概率。
2. 可用灵气：某个建筑、阵法、洞府、秘境或行动中实际可调用的灵气，影响具体行动结果。

不建议把“节点背景浓度”和“建筑内浓度”混成一个数值。

### 9.2 灵气结构

```
AuraProfile {
  background_aura_band       // low / normal / rich / dense / unstable 等，玩家可见
  background_aura_value      // 精确数值，仅调试与服务端规则可见，玩家不可见
  aura_quality_tags          // pure / mixed / polluted / volatile 等
  natural_modifiers
  facility_modifiers
  event_modifiers
  occupancy_pressure
  usable_context_caps
}
```

### 9.3 背景灵气计算口径

背景灵气由以下因素决定：

```
区域基础灵气
+ 节点模板修正
+ 自然资源槽修正
+ 当前节点状态修正
+ 重大事件修正
- 污染 / 枯竭 / 破坏修正
```

建议不要让普通建筑永久改变整个节点背景灵气。否则建筑系统会变成地图生态改造模拟，MVP 成本过高。

普通设施更适合改变“局部可用灵气”。

### 9.4 建筑 / 设施灵气计算口径

设施灵气用于表达聚灵阵、洞府、练功房、炼丹房、突破场地等局部效果。

```
FacilityAuraEffect {
  building_id
  base_effect
  quality_modifier
  maintenance_state
  fuel_or_input_items      // 如聚灵石
  permission_modifier
  capacity_limit
  context_tags             // cultivate / breakthrough / alchemy / formation 等
}
```

设施可用灵气建议读取：

```
设施基础效果
+ 建筑等级 / 品质
+ 维护状态
+ 输入资源，如聚灵石
+ 节点背景灵气适配修正
- 使用压力 / 损坏 / 污染
```

规则口径：

- 聚灵阵提高局部可用灵气，不直接永久提高全节点背景灵气。
- 聚灵石作为高阶灵气物品，可被设施消耗或作为突破 / 修炼资源投入。
- 设施若长期无人维护，会降低可用灵气或触发建筑损坏事件。
- 高强度使用可提高 `occupancy_pressure`，引发维护、损坏、灵气紊乱等事件。

### 9.5 灵气显示粒度

已定规则：玩家常规只看到灵气标签与趋势，例如“灵气稀薄 / 尚可 / 浓郁 / 紊乱”，不允许看到精确数值。即使玩家拥有高阶身份、阵法能力或特定探查道具，也只提高标签精度、揭示质量标签或显示趋势判断，不开放底层数值。精确数值仅用于服务端规则、调试模式和开发工具。

### 9.6 灵气与事件的关系

灵气越高不等于永远更安全。

高灵气可以提高：

- 修炼收益。
- 突破地点价值。
- 稀有资源生成权重。
- 秘境窗口概率。
- 妖兽、异象、争夺事件概率。

灵气质量标签也很重要：

- `pure`：适合突破、闭关、炼丹。
- `mixed`：收益正常，但高阶用途可能有杂质风险。
- `polluted`：可能导致道伤、妖兽异变、资源污染。
- `volatile`：适合秘境和异象，但事件风险高。

## 10. 事件类型、级别与沙盒状态的关联

### 10.1 事件不是纯随机表

事件候选应从世界状态中生成。

```
事件模板
+ 节点类型
+ 区域阶层
+ 灵气状态
+ 危险状态
+ 资源压力
+ 建筑状态
+ 宗门控制 / 影响力冲突
+ 隐藏层 / 后手层
+ 玩家行动上下文
+ 冷却与去重
= 事件候选
```

MVP 不需要复杂公式，但需要统一输入口径。

### 10.2 事件模板结构建议

```
WorldEventTemplate {
  template_id
  event_scope          // route / node / region / sect / world / legacy
  event_domain         // resource / aura / faction / beast / market / legacy / breakthrough 等
  event_level          // minor / normal / critical / major
  required_node_tags
  required_aura_bands
  required_danger_tags
  required_resource_states
  required_faction_states
  visibility_rules
  outcome_profiles
  cooldown_rule
}
```

### 10.3 事件级别

MVP 建议先用四级：

#### minor：轻量事件

- 常见移动遭遇、低风险传闻、轻微延误、低价值发现。
- 可以中断 tick，但不应造成长期大改动。

#### normal：常规节点事件

- 资源异变、妖兽袭扰、弟子求援、路途山贼、普通探索发现。
- 可以改变角色、节点、库存、传闻。

#### critical：关键事件

- 控制权变化、秘境入口开启、突破外扰、高价值后手线索、宗门边界冲突。
- 应有明确后续链路或阶段性结果。

#### major：重大事件

- 多季度、多节点、多宗门影响。
- 例如秘境群爆发、灵脉迁移、兽潮、宗门内乱、边境大战、坊市封锁。
- MVP 同一区域同时不宜有多个 active major 事件。

### 10.4 合理关联示例

| 沙盒状态 | 更容易生成的事件 |
| --- | --- |
| 高灵气 + 荒野 | 秘境波动、妖兽盘踞、稀有灵草、修士争夺 |
| 高灵气 + 宗门腹地 | 突破支持、闭关机会、弟子争资源、设施维护 |
| 资源压力高 | 矿脉塌方、药田减产、污染、妖兽袭扰、宗门加采争议 |
| 影响力接近 | 驻守冲突、边界摩擦、控制权事件、传闻战 |
| 建筑维护不足 | 聚灵阵失稳、炼丹炉损坏、防御阵漏洞 |
| 秘境入口 rumored | 异象传闻、散修聚集、宗门封锁、竞争名额 |
| 正式后手所在节点动荡 | 后手风险状态变化、账本感应增强、追查 / 修复事件 |
| 低灵气凡俗区 | 凡人求助、低阶交易、入门线索、轻量战斗 |

## 11. 重大事件推动世界演化

### 11.1 重大事件是多季度状态机

重大事件不应只是一次弹窗，而是一个会改变节点、宗门、资源、路线、传闻和窗口的阶段性状态机。

```
MajorEvent {
  major_event_id
  event_type
  region_id
  anchor_nodes
  current_stage
  stage_timer
  involved_factions
  public_visibility
  event_pressure
  possible_resolutions
  aftermath_rules
}
```

推荐阶段：

```
seeded       // 世界内部已有征兆，玩家未必知道
rumored      // 传闻出现
escalating   // 宗门和节点开始受影响
active       // 玩家和宗门可正式介入
resolving    // 根据行动结果结算走向
aftermath    // 留下资源、路线、控制权、后手或传闻变化
closed       // 归档
```

### 11.2 重大事件的作用

重大事件可以：

- 创建临时节点。
- 开启或关闭秘境入口。
- 改变路线状态。
- 改变节点灵气、资源丰度或污染。
- 改变宗门行动倾向。
- 提供宗门间资源名额竞争。
- 暴露隐藏层或正式后手风险。
- 推动控制权变化事件。
- 生成多季度传闻。

### 11.3 MVP 重大事件边界

MVP 建议：

- 同一区域最多 1 个 active major 事件。
- 世界全局同时不超过 2 个 active major 事件。
- 每个重大事件必须有至少一个玩家可理解的介入窗口。
- 玩家忽略事件也会自动演化，但不应无预警造成毁档式损失。
- 重大事件的默认结算应偏“世界变化”而不是“直接惩罚玩家本体”。

## 12. 玩家强相关地图要素的演化与负体验控制

### 12.1 分类

玩家强相关地图要素分三类：

1. 普通遗留物：玩家前世死亡、掉落、临时藏物、未正式记录的资产。
2. 玩家布置的普通藏宝 / 临时藏点：玩家有意隐藏，但未占用正式后手容量。
3. 正式后手：经过正式行为封存、记录、占用容量并写入轮回账本的安排。

三者保护强度不同，不能混为一谈。

### 12.2 正式后手保护原则

正式后手可以受世界演化影响，但必须遵守：

- 不无理由消失。
- 不无日志失效。
- 不在离线期间被系统随机清空。
- 不被其他玩家直接抢夺作为 MVP 常态玩法。
- 风险变化必须有原因链。
- 玩家必须有追查、修复、补救或至少理解原因的路径。

### 12.3 后手风险状态流转

推荐状态：

```
safe
→ unstable
→ exposed / contested
→ damaged / polluted / moved
→ looted / destroyed_with_trace
```

状态上升触发条件：

- 锚点节点控制权变化。
- 秘境 / 灵气重大波动。
- 节点进入 major event 范围。
- 后手保护设施长期失修。
- 玩家主动使用欺诈、伪装或高风险回收方式。
- 相关 NPC / 宗门权限链断裂。

已定规则：正式后手风险只在相关节点发生明确变化时检定，不做每季度随机磨损，也不引入“年久失修”型低频随机风险。后手维护玩法后续若需要，只通过玩家主动选择、节点事件或明确状态变化触发。

### 12.4 玩家体验保护阀

为了避免严重负体验，建议：

1. 正式后手从 safe 直接跳到 looted / destroyed_with_trace 只允许在重大事件或玩家高风险选择中发生。
2. 普通世界刷新不能直接删除正式后手。
3. 后手受损前优先进入 `unstable` 或 `exposed`，通过账本感应、传闻、宗门报告或梦兆给出提示。
4. 玩家若长期忽略，才允许进入更严重状态。
5. 若后手已损失，必须给出原因线索，例如“节点被敌宗接管”“阵法年久失修”“秘境波动冲毁外层封印”。
6. 若资产被转移而非销毁，应生成追查链，而不是直接判定消失。

### 12.5 多人间接影响边界

其他玩家可以间接影响正式后手所在节点，例如推动宗门争夺、改变控制权、触发秘境窗口。

但 MVP 不建议支持：

- 直接定位并抢夺其他玩家正式后手。
- 离线搜刮其他玩家洞府。
- 主动破坏其他玩家突破场地。
- 把玩家后手作为 PvP 战利品。

多人影响应表现为“节点态势改变导致后手风险变化”，而不是“玩家 A 直接洗劫玩家 B 的保险箱”。

## 13. 季度世界演化流程

### 13.1 区分“季度前刷新”和“季度后结算”

季度开始的世界刷新不应直接完成所有变化，否则玩家还没决策就被结果砸中。

推荐拆分：

```
季度前刷新：生成可见窗口、传闻、压力、机会、风险提示
季度中结算：根据宗门行动、角色行动和事件链改变世界
季度后归档：写入日志、传闻、账本、库存和节点状态
```

### 13.2 推荐流程

```
1. 季度开始
2. 更新全局计时器、重大事件阶段、临时节点生命周期
3. 更新资源槽自然再生、建筑维护需求、灵气状态候选
4. 生成事件候选池、秘境窗口候选、传闻候选
5. 输出玩家可见传闻、宗门情报、节点预警
6. 宗门行动阶段：玩家建议 / 决策，AI 宗门生成本季度主行动
7. 角色行动阶段：玩家规划 6 个朔望行动格
8. 权威服务器按 tick 结算移动、持续行动、宗门行动、事件链
9. 事件结果包统一回写角色、库存、节点、宗门、路线、后手、日志
10. 结算常态资源产出、维护消耗、宗门库存变化
11. 更新节点控制权、影响力、资源压力、建筑状态、临时节点状态
12. 生成世界日志、角色日志、传闻池、轮回账本更新
13. 进入下一季度
```

### 13.3 结算顺序建议

同一季度中，建议大体顺序：

1. 强制事件 / 临时节点关闭等硬时限。
2. 玩家与宗门已锁定行动的合法性校验。
3. 移动过程事件判定。
4. 节点持续行动推进。
5. 宗门主行动执行完成度结算。
6. 事件链插入与返回。
7. 常态产出与维护。
8. 控制权 / 影响力变化判定。
9. 传闻、日志、后手账本更新。

具体顺序可由 S1 最终定案，但本稿建议避免“资源产出先于危机处理”或“节点已经失控但仍按稳定控制产出”等语义矛盾。

## 14. 地图节点设计收敛建议

### 14.1 节点类型收敛

MVP 节点类型建议保留：

1. 宗门山门节点。
2. 宗门腹地节点。
3. 城镇 / 坊市节点。
4. 村庄 / 凡人聚落节点。
5. 资源型地理节点。
6. 荒野探索节点。
7. 禁地 / 高危节点。
8. 交通设施 / 路线枢纽节点。
9. 秘境入口锚点。
10. 后手 / 隐藏层锚点。

其中 9 和 10 不一定是独立 node_type，可以作为任何节点上的 `entrance_slots` 或 `legacy_layers`。

### 14.2 节点模板优先于节点实例

地图内容应由模板生成实例。

```

  node_type
  zone_tier_range
  allowed_region_tags
  default_aura_band
  default_danger_band
  resource_slot_profiles
  building_slot_profiles
  event_slot_profiles
  entrance_slot_profiles
  hidden_layer_profiles
  route_profile
}
```

实例只保存差异状态，例如当前控制权、资源丰度、建筑损坏、事件冷却、发现状态。

### 14.3 边权不只表示距离

路线边建议结构：

```

  from_node
  to_node
  base_tick_cost
  allowed_movement_modes
  risk_tags
  permission_rules
  state
  event_tags
  visibility_state
}
```

边权至少影响：

- 行动格成本。
- 移动方式可用性。
- 路途事件。
- 行踪暴露。
- 宗门远征 / 驻守成本。
- 传闻传播速度。

### 14.4 节点发现状态沿用 S8，但补充“情报可信度”

既有发现状态：

```
unknown
rumored
located
partially_revealed
revealed
resolved
```

建议补充一个不一定展示给玩家的 `intel_reliability`：

```
unknown / hearsay / sect_report / witnessed / confirmed
```

原因：传闻与真实状态可以错位，尤其适合修仙世界的秘境、后手、欺诈、伪装、假消息。

### 15.9 正式后手与隐藏层适配点

首张地图应预留若干后手锚点，但不代表每局都生成后手。

推荐适配点：

| node_id | hidden / legacy 适配 | 风险口径 |
| --- | --- | --- |
| `N407_ABANDONED_CAVE` | 藏物后手、洞府后手、遗书后手 | 边界争夺带，可能因控制权变化进入 `unstable` |
| `N408_BROKEN_SHRINE` | 信息后手、暗号、真灵感应 | 低显性、适合前期线索 |
| `N306_ARTIFICE_RUIN` | 阵法封存、权限后手接口 | 受秘境 / 阵法事件影响 |
| `N503_DEMON_BEAST_NEST` | 高风险藏物、遗骸、战斗回收 | 高危，不适合新手直接回收 |
| `N504_OLD_TRANSMISSION_RUIN` | 接引点、传送类后手接口 | 后期路线开放与异常空间 |

后手风险只在相关节点发生明确变化时更新。例如：

```
N407_ABANDONED_CAVE 从无主变为 SECT_EXPAND 临时控制
→ 检查该节点 legacy_layers
→ 正式后手 safe 可转为 unstable 或 exposed
→ 写入原因链："边界洞府所在节点被扩张型宗门驻守搜索"
→ 玩家账本感应增强或收到传闻
```

玩家侧初期可见传闻建议：

### 15.12 生成顺序建议

```
1. 创建 RegionSeed
2. 创建 3 个 SectSeed
3. 创建 35 个常驻 WorldNode 实例
4. 按宗门 Seed 写入核心控制节点和初始影响力
5. 按 NodeTemplate 挂载资源槽、建筑槽、事件槽、入口槽、隐藏层适配点
6. 创建关键 MapEdge
7. 写入中央边界带 InitialInfluenceMap
8. 写入 InitialWorldPressure
9. 按 world_seed 对可随机槽位做稳定扰动
10. 生成玩家可见初始地图、传闻和新手路线入口
```

随机扰动允许改变：

- 非核心资源槽的具体丰度。
- 普通秘境入口的 `discovery_state`。
- 荒野节点危险标签。
- 中央边界带少量影响力数值。
- 部分隐藏路线是否 rumored。

随机扰动不允许改变：

- 3 个主要宗门数量。
- 山门核心节点。
- 新手默认路线。
- 至少一条稳定资源链。
- 著名秘境常驻节点。
- 正式后手保护规则。

## 17. 验收标准

本方案落地后，至少应能验证以下闭环：

1. 玩家从村镇进入宗门，能通过节点、路线、事件理解世界空间结构。
2. 宗门控制资源节点后，资源能稳定进入宗门库存。
3. 宗门加大开采或忽略维护，会引发资源压力、异变或建筑损坏事件。
4. 边界节点因为宗门行动、玩家介入或事件结果发生影响力变化。
5. 高灵气 / 高危险 / 资源异常节点更容易产生符合直觉的事件。
6. 秘境入口先以传闻或异常出现，再开启临时节点，并在关闭后留下日志和后续影响。
7. 正式后手能挂载到节点隐藏层，转世后通过账本感应或线索回收。
8. 正式后手受世界变化影响时，能输出原因链，而不是无声失效。
9. 多人房中，不同玩家所属宗门可以在同一资源或秘境节点上形成间接竞争。
10. 调试视图能解释“为什么这个季度发生了这些世界变化”。

## 18. 已确定决策记录

### 18.1 首张 MVP 地图规模

已定：首张 MVP 常驻节点规模控制在 **35±10 个**，临时节点同时存在 **0–6 个**。

设计理由：该规模足以承载 3 个主要宗门、基础资源链、边界争夺、秘境窗口和后手锚点，同时避免首张地图在事件、UI、调试和内容生产上失控。

### 18.2 主要宗门数量

已定：MVP 首张地图固定为 **3 个主要宗门**。

设计理由：3 个主要宗门更适配 MVP 至少支持 3 人共玩的目标，也便于形成分宗并行、三方影响力梯度和资源 / 秘境名额竞争。相比 2 个宗门，3 个宗门能减少世界格局过于二元对抗的问题。

### 18.3 宗门核心节点是否允许失守

已定：MVP 常态不允许山门核心节点被 AI 宗门普通行动夺取；只允许重大事件链造成临时影响。

设计理由：山门核心节点承载宗门身份、玩家成长路径、设施、权限和宗门库存入口。若常态失守，会显著增加宗门系统、任务链、玩家身份和库存归属的异常处理成本。MVP 阶段应把争夺重点放在边界节点、资源节点、秘境节点和影响力变化上。

### 18.4 灵气显示粒度

已定：玩家常规只看到灵气标签与趋势，如“灵气稀薄 / 尚可 / 浓郁 / 紊乱”，不允许玩家看到精确数值。

补充规则：高阶身份、阵法能力或探查道具可以提高可读信息质量，例如揭示“纯净 / 混杂 / 污染 / 紊乱”等质量标签，或提示趋势变化，但不展示底层数值。精确数值仅用于服务端规则、调试模式和开发工具。

### 18.5 资源再生是否按模板完全配置

已定：MVP 不做统一生态公式，所有资源槽按模板配置再生类型与压力规则。

设计理由：资源再生与枯竭的玩法价值在于形成宗门经营取舍，而不是追求自然生态拟真。模板配置更利于内容控制、调试和首张地图平衡。

### 18.6 秘境入口是否全部通过 EntranceSlot 表达

已定：普通临时秘境入口通过 `EntranceSlot` 表达；但允许少数著名秘境作为常驻高危节点存在。

规则口径：

- 普通秘境：以常驻节点上的入口槽表达，开启后生成临时节点或子图。
- 著名秘境：可以作为常驻高危节点长期显示，用于承载世界地标、长期传闻、宗门争夺和阶段性进入窗口。
- 即使是著名秘境，其内部空间、具体可进入窗口、探索阶段和关闭状态，仍可通过 `EntranceSlot`、`TemporaryNode` 和事件链管理。

### 18.7 正式后手风险是否只在相关节点变化时检定

已定：正式后手风险只在相关节点发生明确变化时检定，不需要“年久失修”型低频风险。

设计理由：正式后手是跨世可信感的重要承诺。每季度随机磨损会制造负体验和调试噪音，也容易让玩家觉得系统在无理由消耗其长期规划。后手风险应来自可解释的节点变化、重大事件、玩家高风险选择或明确的维护失败事件，而不是后台随机损耗。
