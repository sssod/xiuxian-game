# 数据驱动、存档、服务端与调试（v2.2）

## 0. 文档定位

本文整理 Godot 技术路线、客户端 / 权威服务器边界、数据驱动对象、运行时状态、存档、日志、调试回放和版本迁移。

实现目标：让所有玩法系统可配置、可保存、可回放、可调试。

新版重点：存档和回放统一使用 `turn_id / world_day / world_hour / macro_period_id`，废弃旧 `quarter / action_slot / tick` 语义。

---

## 1. 技术路线

已定路线：

```text
Godot 客户端 + Godot Headless / Dedicated Server
```

原则：

- 客户端负责 UI、地图展示、行动规划、事件阅读、账本展示和玩家输入。
- 服务器负责房间状态、回合推进、行动结算、宗门 AI、地图节点、事件触发和存档写入。
- 本地单人测试也走同一套规则模型。
- 回合统一结算，避免复杂实时同步。

---

## 2. 权威服务器边界

客户端只提交意图：

- 个人行动指令队列。
- 个人即时行动请求。
- 事件链选择。
- 战斗指令序列。
- 资源使用请求。
- 托管偏好。

服务器校验并写入：

- 资源消耗。
- 位置变化。
- 行动合法性。
- 事件触发。
- 战斗结果。
- 突破结果。
- 死亡与转世。
- 角色状态。
- 宗门库存。
- 宗门 AI 当前持续行动。
- 节点状态。
- 后手状态。
- 日志与存档。

客户端不再提交：

- 宗门即时指令。
- 宗门主行动建议。
- 宗门提议。
- 宗门决策意图。

## 5. 存档最小要求

存档必须支持：

1. 房间元数据。
2. 世界种子。
3. 当前回合、世界日、世界小时与宏观周期。
4. 玩家与真灵。
5. 当世角色。
6. 宗门状态与库存。
7. 宗门 AI 当前持续行动。
8. 地图节点、边、槽位、控制权、影响力。
9. 事件状态、秘境窗口、隐藏层。
10. 后手与轮回账本。
11. 可见性与传闻。
12. 随机状态或可复盘随机日志。
13. 版本号与迁移信息。
14. 已学功法 `MethodState`、完整功法载体来源与功法组件资产。
15. 角色身上的 `ActiveResourceEffect` 残余资源效果。

## 6. 存档格式原则

SQLite、Godot Resource、JSON 或混合方案暂不在本整理稿中定死。

选择标准：

- 支持私人服务器长期保存。
- 支持调试查询。
- 支持版本迁移。
- 支持本地单人测试。
- 支持多人房间状态一致性。
- 支持大状态对象和事件日志查询。
- 支持开发期快速查看和修复。

建议：MVP 原型可先使用最容易调试的结构，但一旦进入多人长期房间，应尽快评估 SQLite 或混合方案。

## 7. 日志体系

最小日志分三类。

### 7.1 玩家可见日志

包括：

- 角色日志。
- 宗门摘要。
- 传闻。
- 轮回账本。
- 原计划 vs 实际结果。

### 7.2 世界日志

系统完整事件记录，默认玩家不可见。用于：

- 传闻生成。
- 后手失效原因链。
- 节点变化追踪。
- 宗门 AI 行动追踪。
- Debug 查询。

### 7.3 Debug 日志

包括：

- 结算输入。
- 校验过程。
- 随机命名空间。
- 关键 roll。
- 结果包。
- 状态差异。
- 错误。

---

## 8. 日志记录要求

以下必须能追踪：

- 个人行动指令提交与服务端校验。
- 个人即时行动请求与校验。
- 托管生成原因。
- 资源预留、消耗、释放。
- 行动资源输入绑定、实际兼容小时、残余资源效果生成 / 衰减 / 收束。
- 库存转移。
- 宗门 AI 当前持续行动计划、推进和执行结果。
- 节点控制权变化。
- 资源槽枯竭、污染、再生、异变。
- 秘境开启、关闭、坍缩。
- 突破关键资源消耗。
- 事件选项临时追加资源输入。
- 突破失败标签。
- 战斗指令与结果。
- 死亡、转世、遗产分配。
- 正式后手创建、暴露、受损、回收、失效。
- 多人可见性和传闻生成。

## 9. 结算回放

开发期需要支持“回合回放”。

```text
TurnReplay {
  room_id: String,
  turn_id: int,
  initial_state_hash: String,
  submitted_instruction_queues: Array,
  instant_action_requests: Array,
  autopilot_plans: Array,
  sect_ai_steps: Array,
  rng_trace: Array,
  settlement_steps: Array,
  event_outcomes: Array,
  result_packages: Array,
  original_vs_actual_summary: Dictionary,
  final_state_hash: String,
  debug_notes: Array
}
```

回放目标：

- 复现 bug。
- 验证权威结算一致性。
- 调试事件触发。
- 追查资产来源。
- 检查后手失效原因。
- 评估多人可见性。
- 检查宗门 AI 选择过程。

## 10. 版本迁移

存档需要版本号。

```text
SaveMetadata {
  save_version: String,
  ruleset_version: String,
  content_version: String,
  created_at: String,
  last_loaded_at: String,
  migration_history: Array
}
```

迁移应记录：

- 从哪个版本迁移到哪个版本。
- 哪些字段新增、删除、重命名。
- 哪些数据被默认补齐。
- 哪些旧存档无法兼容。
