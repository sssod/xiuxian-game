# 物品设计｜丹药

## 1. 设计定位

丹药是可追踪资产，也是行动、事件选项或炼化吸收过程中的资源输入。它不作为装备栏式被动挂件，也不作为绕过世界时间的即时收益按钮。

当前定版口径：

1. 丹药、灵材、符箓、临时增益资源统一通过资源使用接口和日志进入结算；行动型丹药通过 `ActionResourceInputBinding` 绑定到具体行动或事件选项。
2. 丹药效果只在兼容行动、兼容事件、兼容危险语境、显式炼化过程或自动吸收过程中按实际小时结算。
3. 行动开始、事件选项生效、炼化指令开始或自动吸收确认前再次校验资源；未开始或未确认则不消耗。
4. 行动、炼化或自动吸收已开始但资源未完全用完时，生成 `ActiveResourceEffect`。
5. 所有消耗、残余、衰减、退款、失败原因和结果都进入资产日志、结果包和回放。

明确不做：

1. MVP 不设计可让修为丹药增加修为的独立持续行动“丹药炼化”。
2. MVP 不允许即时服用修为丹药后直接增加修为。
3. MVP 不允许任何丹药在确认使用后立即结算完整效果。
4. MVP 不允许丹药绕过行动时间、炼化时间或吸收时间产生收益。
5. MVP 不引入可长期累计的丹毒值或杂质值。
6. MVP 不做多枚修为丹药复杂叠加、主药 + 辅药 + 药引组合。
7. MVP 完全不投放 `forced_release` 危险丹药；字段和分支仅作未来兼容占位。

“炼丹”是生产丹药的固定执行时间行动；“丹药炼化”是使用丹药后的吸收处理方式。增加修为的丹药不支持通过丹药炼化增加修为，只能作为主动吐纳资源输入。非修为丹药可以按配置支持显式丹药炼化，例如增加属性、洗髓、延寿、强稳定类丹药需要在安全环境下炼化。常规恢复类丹药可以不占用额外炼化行动，使用后自动炼化吸收，但仍按单位时间释放效果。

## 2. 物品身份

普通丹药可以作为可堆叠物品；高价值、命名、突破关键、延寿、剧情危险、后手封存或带独立状态的丹药应作为 `ItemInstance` 追踪。

最小字段建议：

```text
PillItem {
  item_instance_id: String
  item_template_id: String
  container_id: String
  quantity: int
  tier: String
  quality: String
  tags: Array
  resource_effect_template_id: String
  source_ref: String
  visibility_policy: String
  bound_effect_refs: Array
}
```

堆叠条件至少要求：

1. 模板相同。
2. 阶级相同。
3. 品级相同。
4. 关键状态相同。
5. 未绑定独立事件、后手、来源审计或特殊缺陷。

阶级表达丹药适配的境界大层级；品级表达同阶内部的纯度、稳定性、药力成色和副作用风险。品级不应直接写成 raw 修为收益，而应影响 `quality_scaling_profile`、`resource_quality_factor`、稳定性、残余策略、浪费和压力风险。

丹药必须位于某个资产容器，例如角色随身、角色储藏、宗门库存、商店库存、NPC 持有物、节点资源库、事件锁定奖励或后手封存。宗门库存中的丹药可以成为行动资源输入来源，但必须经过权限、申请、预留、消耗和审计日志。

## 3. 丹药分类与对应语境

| 类型 | 对应行动 / 语境 | 效果通道 | 使用方式 / 计时模式 |
| --- | --- | --- | --- |
| 修为丹药 | 主动吐纳 | `cultivation_aura` | `action_resource_input` / `compatible_action_hours` |
| 悟性丹 | 研习功法；少数高价值悟性丹可安全炼化 | `method_insight` | `action_resource_input` 或 `explicit_refinement` |
| 属性丹 / 洗髓丹 | 安全环境炼化 | `attribute_modifier` / `aptitude_modifier` | `explicit_refinement` |
| 解毒丹 / 避瘴丹 | 毒瘴移动、探索、采集、战斗；普通解毒可自动吸收 | `hazard_resist` | `hazard_exposure_hours` 或 `auto_refinement` |
| 疗伤丹 / 恢复丹 | 休整、治疗、医疗事件、战后救治；普通恢复可自动吸收 | `injury_recovery` / `recovery_over_time` | `compatible_action_hours`、事件模板指定或 `auto_refinement` |
| 定心丹 / 清神丹 | 巩固根基、突破准备、突破事件链、研习功法 | `pressure_control` / `breakthrough_modifier` | `compatible_action_hours` 或事件模板指定 |
| 战斗丹药 | 战斗准备、战斗事件链指令、轮内选项 | 战斗模板指定 | 事件模板指定 |
| 突破关键丹药 | 突破准备、开启突破、突破挑战轮内资源 | `breakthrough_modifier` | 突破模板指定 |
| 延寿丹 / 寿元丹药 | 完成炼化后直接增加寿元上限 | `lifespan_extension` | `explicit_refinement` / 完成炼化结算 |
| 危险剧情丹药 | 剧情传功、强行破关、邪道速成、濒死续命 | `forced_release` 分支 | MVP 完全不投放，仅未来预留 |

突破丹药和普通丹药必须区分。普通丹药可按资源模板进入 `ActiveResourceEffect`；所有突破丹药都由突破事件链专门结算，不进入普通残余药性状态。突破事件结束后，突破丹药停止影响，只写入突破结果包、资源消耗日志和角色状态变化日志。

## 4. 资源效果模板

丹药效果应由 `ResourceEffectBalance` 或等价模板定价，不写成固定 raw 修为奖励。

```text
ResourceEffectBalance {
  resource_effect_template_id: String
  effect_type: cultivation_aura | method_insight | pressure_control | injury_recovery | recovery_over_time | hazard_resist | breakthrough_modifier | attribute_modifier | aptitude_modifier | lifespan_extension
  use_mode: action_resource_input | explicit_refinement | auto_refinement | event_only
  valid_segment_tags: Array
  compatible_action_tags: Array
  compatible_context_tags: Array
  effect_tick_mode: compatible_action_hours | hazard_exposure_hours | world_elapsed_hours | refinement_completion
  unit_effect_rate: number
  effect_rate_min: number
  effect_rate_max: number
  effect_random_distribution: fixed | normal_clamped
  max_effective_hours: number
  refinement_duration_hours: number | null
  safe_environment_required: bool
  auto_absorb_without_extra_command: bool
  benchmark_hours_saved: number
  normalized_progress_bonus: number
  contribution_cap_ratio: number
  quality_scaling_profile: Dictionary
  stimulation_level: low | medium | high
  stability_level: stable | volatile
  residual_policy: stable_suspend | slow_decay | stimulating_decay | forced_release
  can_be_settled_by_consolidation: bool
  settlement_policy: none | suppress_side_effect | release_without_progress
  stacking_group: String
  max_same_group_active: int
}
```

资源价值需要通过当前境界段、丹药阶级、角色承载、功法相性、灵根 / 药性标签、状态压力和贡献上限校验。低阶丹药可以安全但贡献降低；高阶丹药可以潜在更强，但 MVP 中主要表现为浪费、承载不足、短期反噬或经脉压力；不适配标签丹药主要表现为转化率低、药力浪费、短期疲劳、短期经脉压力或短期心神扰动。

丹药使用消耗时间由配置决定。原则上，单位时间效果越高、总效果越强、长期改变越明显、失败代价越高，丹药价值越高，所需安全条件、炼化时长、风险提示和日志等级也应越高。常规恢复类丹药可通过 `auto_refinement` 让玩家使用后自动吸收；它不占用额外炼化行动，但效果仍按 `unit_effect_rate` 逐小时释放，单位时间回复量越高，价值越高。

丹药允许主效果波动，但波动必须直接写在资源效果模板中。若 `effect_rate_min` 与 `effect_rate_max` 相同，该丹药按确定性效果结算；若二者不同，则在该范围内按截断正态分布抽取实际效果。是否随机由丹药效果配置决定，不由丹药类型决定。同类丹药可以有确定性模板，也可以有随机波动模板。

实际抽取值应在资源绑定、效果实例、结果包和回放日志中固化。C1 追赶和回放只使用已经固化的抽取值，不重新随机。

## 5. 行动绑定与结算生命周期

行动规划、炼化指令或事件选择创建资源绑定：

```text
ActionResourceInputBinding {
  binding_id: String
  command_id: String | null
  event_option_id: String | null
  character_id: String
  source_container_id: String
  resource_item_ref: String
  resource_item_template_id: String
  resource_effect_template_id: String
  effect_type: String
  use_mode: action_resource_input | explicit_refinement | auto_refinement | event_only
  compatible_action_tags: Array
  compatible_context_tags: Array
  effect_tick_mode: String
  unit_effect_rate: number
  max_effective_hours: number
  activation_policy: consume_on_action_start | consume_on_event_option | consume_on_refinement_start | consume_on_use_confirm
  refinement_duration_hours: number | null
  safe_environment_required: bool
  residual_policy: String
  residual_stability_hours: number
  stacking_group: String
  max_same_group_active: int
  created_world_day: int
  created_world_hour: int
  consumed_at_world_day: int | null
  consumed_at_world_hour: int | null
  active_effect_ref: String | null
}
```

入队时只校验当前拥有和当前可用；队列不锁定未来资源，也不因为前序炼丹、采购或宗门申请可能成功而允许后续直接使用丹药。

执行前再次校验：

1. 角色是否持有或获准调用该丹药。
2. 资源是否位于合法资产容器。
3. 当前行动或事件选项是否允许该丹药。
4. 行动标签是否匹配 `compatible_action_tags`。
5. 地点、危险或事件上下文是否匹配 `compatible_context_tags`。
6. 若为显式炼化，当前位置是否满足安全环境要求。
7. 若为自动吸收，当前状态是否允许开始吸收。
8. 是否违反同类资源叠加限制。
9. 是否存在未处理的同组 `ActiveResourceEffect`。

执行过程中按小时结算：

```text
compatible_hours = 本片段中资源可生效的小时数
applied_hours = min(compatible_hours, effect.remaining_effective_hours)
applied_amount = effect.unit_effect_rate * applied_hours
```

不同效果通道进入不同管线：

```text
修为丹药：applied_amount -> resource_aura_input
悟性丹药：applied_amount / bonus -> method_exp_gain 修正
解毒丹药：applied_amount -> toxic_risk_delta / poison_pressure_delta
疗伤丹药：applied_amount -> vitality_recovery / injury_delta
定心丹药：applied_amount -> mind_stability_delta / risk_tag_delta
突破丹药：applied_amount -> breakthrough_success_delta / breakthrough_quality_delta / risk_delta
延寿丹药：完成炼化后 -> LifespanState.lifespan_limit / lifespan_extension_sources
```

行动未开始、事件选项未生效、炼化指令未开始或使用确认未完成时，不消耗关键丹药。行动、炼化或自动吸收被事件打断时，已生效部分正常结算，未生效部分根据模板进入残余效果、散逸、退款、暂停或事件专用处理。

## 6. 修为丹药结算

修为丹药只能作为主动吐纳资源输入。

合法：

```text
主动吐纳 24 小时，附加清灵丹 x 1。
```

非法：

```text
即时服用清灵丹，立即获得修为。
单独执行丹药炼化 12 小时，并获得修为。
移动途中服用清灵丹，持续获得修为。
```

主动吐纳中存在两条输入流：

| 输入流 | 规则 |
| --- | --- |
| 环境灵气流 | 节点灵气、资源槽灵气、聚灵阵、洞府、灵液池等，受道功吸收速度限制 |
| 修为丹药资源流 | 丹药释放定额灵气包，跳过道功吸收速度，但仍进入转化、承载、压力和相性结算 |

修为丹药不是提高节点灵气浓度、不是提高聚灵阵效果，也不是简单提高最终倍率。

合流公式：

```text
cultivation_resource_aura_input =
  sum(unit_aura_rate_i * applied_effective_hours_i * resource_quality_factor_i)

raw_aura_input =
  environment_aura_input + cultivation_resource_aura_input
```

之后统一进入：

```text
根骨安全承载
根骨转化效率
灵根与道功相性
道功基础转化率
状态修正
修为进度
修炼压力
```

主动吐纳实际执行时长短于丹药 `max_effective_hours` 时，只消耗实际兼容小时，剩余药性进入 `ActiveResourceEffect`。

示例：

```text
行动：主动吐纳 6 小时
资源：清灵丹 x 1
清灵丹：20 灵气 / 小时，最多 12 小时

本次释放灵气：20 * 6 = 120
剩余有效时长：6 小时
剩余可释放灵气：120
```

## 7. 非修为丹药炼化与自动吸收

非修为丹药可以支持“丹药炼化”，但必须通过配置限制使用方式、环境、安全性和消耗时间。

使用方式分三类：

| 使用方式 | 适用对象 | 规则 |
| --- | --- | --- |
| `action_resource_input` | 悟性丹、定心丹、避瘴丹、疗伤丹等行动内资源 | 绑定具体行动或事件选项，在兼容小时内生效 |
| `explicit_refinement` | 属性丹、洗髓丹、高价值悟性丹、延寿丹、强稳定类丹药 | 创建炼化指令，要求安全环境，按配置消耗 `refinement_duration_hours` |
| `auto_refinement` | 常规疗伤、回气、解毒、止血、恢复类药物 | 使用后创建自动吸收效果，不占额外炼化行动，但按世界小时或兼容恢复小时逐步生效 |

显式炼化规则：

1. 增加属性、洗髓、延寿、长期稳定或其他长期改变角色状态的丹药，默认需要安全环境炼化。
2. 安全环境由配置判定，可包括宗门静室、洞府、医馆、闭关室、受保护节点、非战斗状态、非移动状态、无高危环境暴露等条件。
3. 炼化时长由丹药价值、总效果、单位时间释放量、风险等级和效果不可逆程度决定。
4. 炼化期间按小时释放效果；中断后的暂停、散逸、副作用或材料损失由丹药模板声明。
5. 显式炼化不能用于让修为丹药直接增加修为。

自动吸收规则：

1. 常规恢复类丹药可以在使用后自动炼化吸收，不需要额外创建长期炼化行动。
2. 自动吸收仍然不是即时生效；它创建持续效果或残余效果，按配置的单位时间回复量结算。
3. 单位时间回复量越高、总回复量越高、越能覆盖高风险状态，该丹药价值越高。
4. 自动吸收期间若角色进入战斗、移动、危险环境或状态冲突，是否继续生效、暂停、加速消耗或转为风险，由模板配置。
5. 自动吸收必须写入资源使用日志、状态变化日志和结果包。

延寿丹 / 寿元丹药规则：

1. MVP 实现延寿丹，效果为完成显式炼化后直接增加 `LifespanState.lifespan_limit`。
2. 延寿丹不在使用确认时即时完整结算；未完成炼化前不提前增加寿元。
3. 丹药延寿不在丹药层面设置独立总量上限。寿元模块统一限制丹药来源寿元总量，始终按当前非丹药总寿元的百分比钳制，例如不超过当前非丹药总寿元的 20%。
4. 超过寿元模块上限的丹药延寿部分不生效，但消耗、失败原因、实际生效寿元和被上限钳制的寿元都必须写入结果包与角色日志。
5. 延寿丹的具体数值、炼化时长、安全环境、效果是否波动和品级倍率仍由丹药模板配置。

## 8. 残余效果

`ActiveResourceEffect` 表示丹药已被消耗，但效果未在本次行动中完全用完。

生成场景：

1. 行动实际时长少于丹药最大有效时长。
2. 行动开始后被事件打断。
3. 行动中部分小时不满足丹药兼容语境。
4. 显式炼化未完成。
5. 自动吸收尚未释放完整效果。

不生成场景：

1. 带资源输入的行动没有实际开始。
2. 服务端校验未通过，丹药没有消耗。
3. 事件模板声明该资源为一次性无残余。
4. 所有突破丹药由突破事件链专门结算，突破事件结束后停止影响。
5. 丹药模板声明使用失败时全额退款且不产生状态。

最小结构：

```text
ActiveResourceEffect {
  effect_id: String
  character_id: String
  source_binding_id: String
  resource_effect_template_id: String
  effect_type: String
  unit_effect_rate: number
  remaining_effective_hours: number
  remaining_effect_amount: number
  compatible_action_tags: Array
  compatible_context_tags: Array
  effect_tick_mode: compatible_action_hours | hazard_exposure_hours | world_elapsed_hours
  residual_policy: stable_suspend | slow_decay | stimulating_decay | forced_release
  residual_stability_hours_remaining: number
  idle_world_hours: number
  can_be_settled_by_consolidation: bool
  settlement_policy: none | suppress_side_effect | release_without_progress
  stacking_group: String
  source_command_id: String | null
  source_event_option_id: String | null
  created_world_day: int
  created_world_hour: int
  last_applied_world_hour: int
  state: active | suspended | decaying | exhausted
  log_refs: Array
}
```

残余策略：

| 策略 | 用途 | 规则 |
| --- | --- | --- |
| `stable_suspend` | 普通清灵丹、普通启悟丹、低刺激养元资源 | 非兼容行动期间不生效，在稳定窗口内不明显损失，之后缓慢散逸 |
| `slow_decay` | 品质较差丹药、保存状态一般资源 | 非兼容行动期间缓慢减少，通常只造成轻微浪费或疲劳 |
| `stimulating_decay` | 速成修为丹、烈性火系丹药、高刺激破关资源 | 非兼容行动期间较快衰减，衰减可能转为经脉压力、疲劳或神念扰动 |
| `forced_release` | 高阶危险丹药、剧情丹药、强行破关资源 | 按世界小时持续释放，未被吸收部分转为浪费、压力或反噬；MVP 完全不投放，只预留字段 |

残余效果允许跨行动、跨世界小时保存，并随角色存档。决策阶段、局部时停和玩家阅读报告期间不推进药性衰减。C1 追赶只补结算确定性的兼容小时、资源消耗和药性衰减；若丹药模板有随机效果，追赶只读取已固化的实际效果值，不触发新的随机事件。

## 9. 巩固根基与残余药性

巩固根基可以选择性收束残余修为药性，但不转化为修为进度。

它的作用是：

1. 止损。
2. 减压。
3. 稳定根基。
4. 降低散逸或短期副作用风险。

稳定残余药性默认不自动收束，必须由玩家明确选择。刺激型或强制释放型药性应强提示风险，并建议继续主动吐纳或巩固根基收束。

收束结算：

```text
settled_hours = min(action_actual_hours, effect.remaining_effective_hours)
settled_amount = effect.unit_effect_rate * settled_hours
```

`settled_amount` 不进入：

```text
resource_aura_input
cultivation_progress_gain
```

而进入：

```text
pressure_prevention
side_effect_reduction
residual_effect_clearance
```

如果巩固根基本身有纯度收益或根基收益，该收益来自巩固行动本身，不来自修为丹药残余。

## 10. 事件选项中的丹药

事件选项允许临时追加丹药输入，但必须由事件模板声明 `resource_input_slot`。

示例：

```text
毒瘴战斗事件中临时服用避瘴丹。
突破交锋中临时服用定心丹。
战斗中临时服用回气丹。
医疗事件中临时使用疗伤丹。
```

事件丹药规则：

1. 不允许回溯生效。
2. 必须走统一资源校验。
3. 必须写入 `ResourceUseRequest`、`ResourceUseResult`、事件结果包、资产日志和角色日志。
4. 是否产生残余效果由事件模板和丹药模板共同决定。
5. 突破事件链中的丹药优先服从突破事件链资源规则，不产生普通残余药性，突破事件结束后停止影响。

禁止：

```text
事件发生后，回溯让避瘴丹覆盖之前已经暴露的 5 小时。
战斗结束后，回溯使用回气丹改变已结算的交锋。
突破失败后，回溯服用定心丹重算风险。
```

## 11. 叠加与托管

MVP 同一行动中，同一效果通道最多使用 1 个主资源输入。

示例：

```text
主动吐纳：最多 1 种主修为丹药。
研习功法：最多 1 种主悟性增益资源。
毒瘴探索：最多 1 种主避瘴 / 解毒资源。
休整治疗：最多 1 种主疗伤资源。
```

如果角色已有同一 `stacking_group` 的 `ActiveResourceEffect`，默认不允许再使用同组新丹药。玩家应先通过兼容行动承接、等待散逸，或通过巩固根基收束。

显式托管不得主动消耗新的稀有修为丹药、高刺激速成丹药或不可逆高价值资源。托管可以在安全条件下处理已有残余效果，例如继续主动吐纳承接稳定药性，或巩固根基收束刺激型药性。保命、避险、避免重大不可逆选择优先于节省药性。

## 12. 炼丹生产边界

丹药生产可以使用轻量配方制，但不做完整炼丹炼器工业链。

轻量配方制要求：

1. 消耗明确材料、灵石、宗门资源、设施时段或特殊药引。
2. 产出明确丹药模板。
3. 随机性只允许发生在配方声明的范围内，例如品级、数量副产、成色、缺陷、失败副作用或返还比例。
4. 产出价值不得长期稳定高于投入价值，除非由稀有配方、稀有设施、高阶技艺、长时间成本、高失败风险、关键材料稀缺、宗门权限或地域限制解释。
5. 丹药生产消耗和产出必须进入资产流水、结果包和回放。

炼丹生产是固定执行时间行动，可以是长期低交互行动并参与 F1；但队列不会因为前序炼丹可能成功而允许后序使用尚未产出的丹药。

MVP 中，炼丹生产行动一旦开始后被中断，直接判定本炉炼制失败。未开始前仍不消耗材料；已开始后，已投入材料、费用和设施时段不返还，不暂停、不按进度折算，也不产出完成丹药。失败结果包只记录失败原因、消耗和日志。

## 13. UI 口径

资源输入 UI 采用行动内折叠项。玩家选择具体行动后，只显示与该行动兼容的丹药和资源输入。

主动吐纳界面应显示：

```text
可投入丹药
来源容器
单位效果
最大有效小时
预计本次释放小时
预计残余小时
相性提示
经脉压力或副作用风险
```

已有残余效果必须在角色面板或行动规划器中常驻提示。

稳定残余提示：

```text
体内仍有未尽药性：清灵丹，约 6 小时。
执行主动吐纳可继续承接。
若长时间不处理，药性可能散逸。
```

刺激型残余提示：

```text
体内仍有烈性药性：赤焰速元丹，约 4 小时。
非修炼行动期间可能快速散逸并造成经脉压力。
建议：继续主动吐纳或巩固根基收束。
```

事件选项中的丹药作为附加条件或子选项显示，必须明确：

1. 消耗什么丹药。
2. 是否立即消耗。
3. 是否产生残余效果。
4. 是否会中断、改变或接续当前行动。
5. 可能降低什么风险，以及仍然保留什么风险。
6. 若为炼化或自动吸收，需要多少世界小时释放完整效果。

## 14. MVP 范围

MVP 应实现：

1. 丹药通过统一资源使用接口进入结算；行动型丹药作为 `ActionResourceInputBinding`。
2. 修为丹药挂载主动吐纳。
3. 悟性丹挂载研习功法。
4. 避瘴 / 解毒丹挂载危险语境行动或事件。
5. 疗伤丹挂载休整、治疗或医疗事件。
6. 定心丹挂载巩固根基、突破准备、研习功法或突破事件链。
7. 延寿丹完成显式炼化后直接增加寿元上限，并由寿元模块统一限制丹药延寿总量。
8. 行动未开始不消耗资源。
9. 行动开始后按实际兼容小时消耗资源。
10. `ActiveResourceEffect` 残余药性。
11. `stable_suspend`、`slow_decay`、`stimulating_decay` 三类常规残余策略。
12. `forced_release` 字段预留，但不投放危险丹药内容。
13. 巩固根基可选择性收束残余修为药性。
14. 事件选项可临时追加丹药输入。
15. 同效果通道最多 1 个主丹药输入。
16. 资源使用日志、资产流水、结果包和回放。
17. 行动内折叠式资源输入 UI。
18. 非修为丹药的 `use_mode`、炼化时长、安全环境和自动吸收字段。
19. 丹药效果模板按 `effect_rate_min` / `effect_rate_max` 配置是否波动，并固化实际抽取值。

MVP 不实现：

1. 通过独立“丹药炼化”让修为丹药增加修为。
2. 即时服丹涨修为。
3. 多枚修为丹药复杂叠加。
4. 主药 + 辅药 + 药引组合。
5. 危险丹药和 `forced_release` 实际投放内容。
6. 可长期累计的复杂丹毒 / 杂质系统。
7. 丹药作为装备栏式被动挂件。
8. 玩家在结算阶段主动暂停重新安排药性。
9. 完整炼丹炼器工业链。

## 16. 已裁决冲突

| 冲突 | 当前裁决 |
| --- | --- |
| 丹药是独立“丹药炼化”行动，还是行动资源输入 | 修为丹药只能作为主动吐纳资源输入；非修为丹药可按配置显式炼化或自动吸收 |
| 修为丹药是否即时增加修为 | 不允许；必须依附主动吐纳实际兼容小时 |
| 非修为丹药是否可以炼化 | 可以；属性丹等长期改变类丹药需要安全环境和配置时长，常规恢复类丹药可使用后自动吸收 |
| 修为丹药是否提高节点灵气或聚灵阵倍率 | 不提高；它提供独立定额灵气包，并进入后续转化、承载和压力 |
| 决策阶段是否推进药性衰减 | 不推进；只有世界小时实际结算时推进 |
| 巩固根基是否能把残余药性转为修为 | 不能；只能止损、减压、稳定和清理残余 |
| 突破丹药是否产生普通残余药性 | 不产生；所有突破丹药由突破事件链结算，突破事件结束后停止影响 |
| 延寿丹 / 寿元丹药是否进入 MVP | 进入；完成显式炼化后直接增加寿元上限，丹药延寿总量由寿元模块按当前非丹药总寿元百分比限制 |
| 常规 MVP 是否投放强制释放丹药 | 不投放；MVP 完全不投放危险丹药，`forced_release` 只预留字段和未来分支 |
| MVP 是否引入长期丹毒 / 杂质累计值 | 不引入；只保留短期压力、疲劳、心神扰动和未来扩展接口 |
| 炼丹生产中断后的损耗规则 | MVP 中炼丹行动开始后被中断，直接判定炼制失败；未开始则不消耗 |
| 丹药使用效果是否允许随机波动 | 允许；随机波动写在模板效果上下限中，按截断正态分布抽取，非随机丹药把上下限配置为同一数值 |
