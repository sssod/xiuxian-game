# 事件、突破与战斗时间规则

状态：第二批正式定稿
更新日期：2026-05-08
来源主版本：v2.3 calendar_preinput

## 1. 系统定位

S8 负责事件时间模式、个人局部时停、轻遭遇、正式交锋、突破挑战、P0 同步保护、事件结果字段和与 S1 权威结算总线的集成。

核心原则：

```text
普通个人选择保留玩家处理权；
个人非交锋事件使用本人局部时停 + 外部 N1；
正式战斗与突破挑战使用 B1 交锋轮；
全局公共事件或同步保护使用 P0；
所有事件结果必须通过 S1 结果包回写并进入 TimelineReplay。
```

## 2. 事件时间分类

MVP 事件按时间处理分为：

| 类型 | `event_time_mode` | 时间处理 | 示例 |
| --- | --- | --- | --- |
| 信息事件 | `info` | 不打断，进入日志 / 传闻 | 坊市价格、宗门传闻、节点局势 |
| 普通个人选择事件 | `local_time_stop` | 本人局部时停，外部 N1，gap≤1 日，结束后 C1 | 同门邀约、个人机缘、资源反馈、小境界选择 |
| 轻遭遇 | `light_encounter` | 按普通个人选择事件 | 低阶妖兽、小型陷阱、外门挑衅 |
| 正式交锋 | `formal_encounter_b1` | 世界 B1，按交锋轮结算 | 强敌斗法、玩家直接冲突、秘境关键战斗 |
| 突破挑战 | `breakthrough_b1` | 世界 B1，按交锋轮结算 | 筑基挑战、结丹挑战 |
| 全局公共事件 | `global_pause_p0` | 世界 P0 | 宗门大会、全员决策、世界级灾变 |

事件模板必须提供：

```text
event_time_mode
safe_default_option_ref
p0_required_if_timeout
visibility_policy
result_package_template
```

## 3. 普通个人选择事件

普通个人选择事件用于非交锋类个人选择。

规则：

```text
事件玩家本人局部时停；
事件玩家当前行动、资源变化、风险变化暂停；
其他玩家、宗门和世界继续 N1；
gap 最多 1 游戏日；
事件结束后 C1 追赶补结算；
其他玩家不看到事件归因。
```

事件选项可有游戏内时间成本，该时间从事件触发 `world_hour` 开始回填，而不是从玩家现实提交选择后开始计算。

示例：

```text
事件触发：第 12 日午时
世界当前：第 12 日酉时
gap = 6 小时
玩家选择：调息稳定，耗时 6 小时
结果：调息时间覆盖 gap，C1 后同步到世界当前时间。
```

## 4. gap 上限与安全默认

定义：

```text
gap = 世界当前时间 - 玩家局部冻结时间
gap 最大 1 游戏日
```

gap 阶段：

| gap | 系统行为 |
| --- | --- |
| 0～12 游戏小时 | 正常局部时停 |
| 12～18 游戏小时 | 仅事件玩家本人轻提示 |
| 18～24 游戏小时 | 事件玩家本人强提示 |
| 24 游戏小时 | 自动安全默认或 P0 同步保护 |

到达 1 日：

```text
有安全默认选项 → 自动执行默认选项；
无安全默认选项 → P0 同步保护。
```

安全默认例子：

```text
同门邀约：默认婉拒
坊市机会：默认错过
普通资源反馈：默认接受保守方案
轻度机缘：默认不冒险
突破前道具确认：默认取消突破，进入休整
```

P0 同步保护例子：

```text
死亡边缘
不可逆功法路线选择
重大夺舍 / 心魔交易
无法默认处理的多人冲突
严重资源损毁选择
```

## 5. C1 追赶补结算

局部时停事件结束后，事件玩家通过 C1 补齐到世界当前时间。

C1 只结算确定性内容：

```text
行动进度；
修炼收益；
资源消耗；
药性衰减；
伤势恢复；
队列切换；
已知状态变化；
事件选择带来的明确后果。
```

C1 不触发：

```text
随机个人事件；
普通机缘；
普通战斗；
软机会事件；
普通心魔；
普通资源反馈。
```

`CatchupSettlementState` 必须满足：

```text
deterministic_only = true
random_events_blocked = true
```

## 6. 自动处理范围

信息事件不打断，进入日志 / 传闻。

普通个人选择事件保留玩家处理权。

闭关预案和显式托管行动可以覆盖低价值事件。自动兜底只用于防止角色行动空档，不承担事件处理预案。

重大事件不得被普通队列、自动兜底或低价值托管策略吞掉。

## 7. 战斗分级

### 7.1 轻遭遇

轻遭遇是一次性个人事件，例如：

```text
采药时遇到低阶妖兽
路上被外门弟子挑衅
小型陷阱
低风险野兽惊扰
```

处理：

```text
事件玩家局部时停；
其他世界 N1；
gap 最多 1 游戏日；
选择后 C1 追赶。
```

轻遭遇应控制为短文本、少选项、快处理。

### 7.2 正式交锋

正式交锋包括：

```text
秘境关键战斗
强敌斗法
玩家直接交锋
多人组队战斗
宗门任务战斗
可能导致重伤 / 死亡 / 重大资源损失的战斗
突破挑战
```

处理：

```text
世界进入 B1；
按交锋轮结算；
非参战玩家也按 B1 世界时间推进。
```

正式交锋不使用局部时停，不因为单个玩家未选择而进入 P0。

## 8. B1 交锋轮

```text
B1 = 60 秒现实时间 = 1 游戏小时
1 交锋轮 = 1 游戏小时
```

每轮流程：

```text
1. 展示当前交锋态势；
2. 参战者选择本轮策略；
3. 60 秒倒计时；
4. 未提交者执行预设策略；
5. 系统结算本轮；
6. 交锋时间推进 1 游戏小时；
7. 世界时间同步推进 1 游戏小时。
```

玩家可以提前提交，并可在倒计时结束前修改。倒计时结束后统一结算。

每名参战者必须有默认交锋预设：

```text
保命优先
稳健防守
节省灵力
优先击杀
保护队友
尝试撤退
维持突破
优先稳定道基
强冲成功率
```

若 60 秒内未提交，执行当前预设策略。

## 9. 交锋上限

建议：

```text
普通正式交锋：3～8 轮
复杂正式交锋：最多 12 轮
硬上限：24 轮
```

达到硬上限仍未结束，强制进入模板结局：

```text
撤退
僵持
重伤脱离
资源耗尽
突破失败
突破成功但有代价
进入长期对峙状态
```

模板结局由交锋模板决定，并必须写入结果包与回放。

## 10. 大境界突破结构

大境界突破分为：

```text
准备期
→ 开启突破短指令
→ 突破挑战 B1 正式交锋
→ 结果结算个人报告
→ 后续选择按普通个人事件处理
```

### 10.1 准备期

准备期是普通长期低交互行动，可进入 F1：

```text
闭关积蓄灵力；
温养经脉；
炼化基础药性；
布置基础环境；
等待状态满足；
准备关键突破物；
选择突破地点；
寻求护法；
争取宗门支持。
```

准备期不触发 P0。

### 10.2 开启突破短指令

开启突破是短指令：

```text
选择少量突破专用道具；
确认是否开启突破；
确认当前主修功法对应突破模板；
可选择突破挑战默认策略。
```

规则：

```text
若作为普通队列预输入，必须当前已满足条件；
若临时弹出确认，按个人局部时停处理；
默认选项：取消突破，进入休整；
未提交前不消耗突破专用道具。
```

开启条件由当前 `RealmSegmentBalance` 与角色状态共同校验：

```text
normalized_segment_progress >= 1.0；
MethodState 掌握度满足要求；
foundation_quality 达到最低要求；
meridian_pressure / injury / mental_risk 不超过允许上限；
当前地点允许突破；
主修功法突破模板可用；
开启阶段所需资源当前可用。
```

开启突破入队只表示当前条件已经合法后的队列安排；突破挑战轮内策略由 B1 默认策略和本轮选择处理。

### 10.3 突破挑战

突破挑战是正式交锋：

```text
世界进入 B1；
1 轮 = 1 游戏小时；
每轮 60 秒现实窗口；
突破者每轮选择策略；
未选择则执行突破预设；
真实资源消耗发生在交锋轮中；
突破挑战游戏时间消耗 = 交锋轮数 × 1 游戏小时。
```

突破进入 B1 时可读取 `BreakthroughScoreBalance` 生成初始 `success_score` 与 `quality_score`。初始分只承接准备质量，不直接决定最终结果；最终结果必须由 B1 轮内策略、轮内资源消耗、状态变化和模板结局共同结算。

示例轮：

```text
第 1 轮：稳住灵台，是否消耗护心符
第 2 轮：灵力冲关，是否服用破境丹
第 3 轮：道基震荡，是否消耗轮回后手
第 4 轮：心魔诱导，是否舍弃部分根基换成功率
第 5 轮：境界成形，是否追求高品质突破
```

### 10.4 突破默认策略

必须支持：

```text
保命优先
稳健突破
节省珍贵道具
优先成功率
追求高品质
接受根基损伤换突破
失败即中止
```

若玩家某轮没有提交，执行当前突破预设。

### 10.5 突破结果结算

突破挑战结束后，以个人报告、宗门传闻、世界日志呈现。

个人报告包括：

```text
突破成功 / 失败；
境界品质；
根基变化；
伤势；
寿元变化；
道具消耗；
主修功法影响；
失败原因标签；
下一次修正方向；
轮回账本记录。
```

后续选择示例：

```text
巩固境界；
疗伤；
隐瞒突破；
公开报备；
请求宗门护法。
```

这些选择按普通个人事件处理。

## 11. 事件结果字段

`consumed_hours` 含义：

| 场景 | 含义 |
| --- | --- |
| 普通个人事件 | 选项的游戏内时间成本，从事件触发 `world_hour` 回填 |
| C1 追赶 | 补结算覆盖的确定性小时数 |
| B1 交锋 | 交锋轮数 × 1 游戏小时 |
| 突破挑战 | 突破交锋轮数 × 1 游戏小时 |
| 信息事件 | 通常为 0 |

`EventOutcome`：

```text
EventOutcome {
  event_id: String
  event_time_mode: info | local_time_stop | light_encounter | formal_encounter_b1 | breakthrough_b1 | global_pause_p0
  trigger_world_day: int
  trigger_world_hour: int
  frozen_character_world_hour: int | null
  consumed_hours: int
  catchup_required: bool
  default_resolution_used: bool
  speed_transition_refs: Array
  result_package_refs: Array
}
```

## 12. 与 S1 的集成

S8 不直接绕过 S1 改写世界状态。

必须通过 S1 记录：

```text
事件触发 → settlement_steps / event_outcomes；
局部时停创建、gap、默认处理 → local_time_stop_records；
C1 追赶 → catchup_records；
B1 每一轮 → formal_encounter_rounds；
P0 创建与解除 → global_pause_records；
事件选项、战斗轮、突破轮结果 → result_packages；
速度变化 → speed_segments；
个人报告、公开日志、宗门传闻 → visible / hidden / personal log refs。
```

所有状态变更必须带 `world_day / world_hour`。突破挑战使用 `FormalEncounterState.encounter_type = breakthrough`。

## 13. UI 与验收约束

玩家 UI 必须遵守速度隐私：

```text
其他玩家不看到私人事件归因；
F1 降 N1 只显示中性常态推进；
B1 可显示交锋慢速，但隐秘交锋不暴露具体来源；
Debug 面板可显示 private_reason_refs。
```

验收检查：

1. 信息事件不打断，进入日志 / 传闻。
2. 普通个人事件冻结本人 `frozen_world_hour`，其他玩家继续 N1。
3. gap 在 12 / 18 / 24 游戏小时正确提示、默认处理或 P0。
4. C1 只补确定性内容，不触发随机个人事件。
5. 轻遭遇按个人局部时停处理。
6. 正式交锋进入 B1，1 轮 = 1 游戏小时。
7. 未提交 B1 轮选择时执行默认策略。
8. 交锋硬上限不超过 24 轮。
9. 大境界突破不使用多次 P0，真实资源消耗发生在 B1 轮内。
10. 突破结果生成个人报告、公开影响和 `TimelineReplay` 记录。

## 14. Deprecated aliases 与迁移说明

| 旧口径 | 当前处理 | 说明 |
| --- | --- | --- |
| 个人大境界突破开启 P0 | 废弃 | 开启突破为短指令或局部时停确认 |
| 突破临界选择 P0 / 关键抉择 P0 / 结果结算 P0 | 废弃 | 关键选择与真实消耗集中到 B1 突破挑战轮 |
| 正式战斗 P0 | 废弃 | 正式战斗使用 B1 交锋轮 |
| 事件按回合报告消耗 | 废弃 | 事件结果使用 `consumed_hours` 与 `world_day / world_hour` |
| 突破事件链消耗一次性抽象成本 | 收敛 | 开启阶段不消耗；轮内真实资源消耗写入 B1 结果包 |
| 轻遭遇作为正式战斗 | 收敛 | 轻遭遇按个人局部时停，正式交锋才进入 B1 |

参考来源：

```text

```

裁决：

| 采用方案 | 废弃方案 | 原因与实现影响 |
| --- | --- | --- |
| `event_time_mode` 六类时间处理 | 所有事件都走回合中断或公共暂停 | 事件需要按世界小时和速度状态接入 S1 |
| 普通个人事件本人局部时停 + 外部 N1 + C1 | 普通个人事件全局暂停 | 保留个人选择权，同时减少多人阻塞 |
| 正式交锋与突破挑战进入 B1 | 正式战斗 P0、个人突破多次 P0 | B1 将思考时间、游戏时间和资源消耗统一到交锋轮 |
| 突破初始分承接准备质量，最终结果由 B1 轮内结算 | 仅用 CP 达标或单次概率按钮决定突破成败 | 境界准备、资源取舍和轮内策略都需要可复盘 |
| 突破真实资源消耗发生在轮内 | 开启突破立即消耗所有关键资源 | 轮内结果包能复盘每次资源取舍 |
| `EventOutcome.consumed_hours` 以场景解释 | 回合报告中的抽象行动偏差 | 连续日历需要所有成本落到 `world_day / world_hour` |
