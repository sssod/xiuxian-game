# 08_事件突破战斗

# 事件、突破与战斗事件链

## 0. 文档定位

本文整理常规事件框架、选择事件、窗口事件、突破事件链和战斗 / 斗法事件链。

事件系统负责把玩家、NPC、宗门、节点和世界状态在特定上下文中转化为事件链、选择、判定和结果包。所有结果必须交给 S1 统一回写。

## 1. 事件系统定位

S10 是世界演化的事件层。

一句话定位：

> S10 决定玩家、宗门和世界在某个时间、地点、状态下会触发什么事件，以及事件结果如何改变角色、节点、宗门和日志。
> 

S10 是事件框架，不替代突破、战斗、死亡、后手回收等专用事件链。

## 2. 事件分类

MVP 事件分为：

1. 移动事件。
2. 节点事件。
3. 宗门事件。
4. 世界刷新事件。
5. 秘境 / 窗口事件。
6. 控制权变化事件。
7. 传闻生成事件。
8. 专用事件链入口。

专用事件链包括：

- 突破。
- 战斗。
- 死亡 / 转世。
- 前世后手回收。

## 6. 选择事件

选择事件是最核心的常规事件类型。

本质：

> 系统抛出一个可结算的局面问题，玩家用选项回答这个问题，系统根据回答生成后果。
> 

事件选项不是同义按钮集合，而是不同解题姿态。

## 7. 五类选择维度

### 7.1 正面应对

直面事件抛出的核心问题。

示例：

- 威胁来袭 → 正面处理威胁。
- 合理请求 → 满足或如实说明无力满足。
- 不合理侵犯 → 拒绝或反击。

规则：

- 一般事件至少尝试生成正面应对选项。
- 当候选选项超过 3 个时，正面应对默认留在主选项区。
- 正面应对承担事件基本解法和问题理解锚点。

### 7.2 出奇制胜

使用超出默认预设的合法手段解决问题，并确实解决问题本体。

依赖：

- 高阶符箓。
- 特殊法宝。
- 宗门权限。
- 前世线索。
- 隐藏身份。
- 地点布置。

通常收益更好或损耗更低，但需要消耗资源或暴露能力。

### 7.3 逃避推诿

不直接解决问题本体，而是通过离开、拖延、绕行、转移责任、降低接触强度等方式避免承担主要风险。

逃避不是失败按钮。对低价值、高风险、非必要事件，逃避可能是合理策略。

### 7.4 解构问题

改变问题成立的前提、身份关系、规则解释或目标定义，使原问题不再以原强度存在。

例如：

- 将资源争夺重新解释为宗门共同辖区。
- 揭示身份使敌对事件变为关系清算。
- 证明任务目标本身已失效。

### 7.5 欺诈蒙骗

通过虚假信息、伪装、隐瞒、嫁祸等方式解决当下问题。

规则：

- UI 应提示“可能留下后患 / 暴露风险”。
- 不显示具体隐藏标签、追查对象或触发条件。
- 后续追查必须有日志来源。

## 8. 选项显示规则

常规事件默认隐藏不可用选项。

允许灰显的例外：

1. 教学事件。
2. 突破准备面板。
3. 关键节点事件。

常规选择事件主选项区合理数量为 1–3 个。超过 3 个开放选项时：

- 显示“…”按钮。
- 点击后切换到溢出选项区。
- “…”变为“返回”。
- 不使用翻页按钮，不显示页码。

出奇制胜和解构问题优先放入溢出区。

## 9. 多阶段与投入事件

### 9.1 阶段数上限

```
常规选择事件：最多 2 阶段
重要事件：最多 3 阶段
超过 3 阶段：转为专用事件链
```

### 9.2 投入事件

MVP 不允许滑杆式连续追加投入，只允许离散档位：

```
不投入
标准投入
高额投入
```

每个投入档位必须显示明确方向性后果。

### 9.3 窗口事件

MVP 只为以下内容实现窗口事件：

- 秘境窗口。
- 节点危机。
- 突破资源 / 名额窗口。

## 10. 突破事件链定位

S4 负责将突破从概率按钮改造为高价值插入事件链。

突破核心价值：

- 让玩家围绕突破进行多季度准备。
- 让玩家在突破前理解短板和风险。
- 让突破过程中有有意义的交互。
- 让失败输出可解释标签。
- 让失败为下一世提供优化方向。

## 11. 大小境界边界

### 11.1 小境界升级

小境界升级是阶段内成长节点，不进入高风险突破链。

不做：

- 不消耗关键突破物。
- 不进入突破事件链。
- 不触发死亡 / 转世。
- 不生成复杂外部干扰。
- 不需要挑战交锋格。

可以做：

- 弹出轻量提示。
- 更新阶段编码。
- 增加少量派生属性或解锁功法效果。
- 写入角色日志。

### 11.2 大境界突破

大境界突破必须满足：

1. 玩家主动发起。
2. 至少消耗一个关键突破物。
3. 进入事件链后不可回头补准备。
4. 结果可能改变本世路线、宗门地位、轮回账本和下一世规划。

## 12. 突破三层体验

```
长期准备层
→ 破境确认层
→ 事件链交锋层
```

### 12.1 长期准备层

玩家通过以下方式降低风险：

- 修炼。
- 提纯 / 巩固。
- 提升主修道功等级。
- 准备关键突破物。
- 选择突破地点。
- 寻求护法。
- 争取宗门支持。
- 处理心境 / 因果。
- 回收前世后手。

### 12.2 破境确认层

玩家在明确不可逆消耗与风险提示后，选择突破持续行动。

MVP 准备面板不显示完整精确成功率，只显示：

- 风险档位。
- 主要短板。
- 可能失败标签方向。
- 关键消耗。
- 外部干扰预警。

### 12.3 事件链交锋层

玩家无法再回头准备，但可通过指令、资源和判断影响结果质量。

## 13. 关键突破物

关键突破物是玩家从准备阶段跨入不可回头突破事件链的承诺成本。

规则：

- 开始大境界突破至少需要 1 个关键突破物。
- 关键突破物是具体物品实例，不是抽象货币。
- 事件链正式创建时立即消耗。
- 无论成功、失败、中断、残缺突破或身死转世都不返还。
- 必须写入资源使用日志和突破结果包。

## 14. 主修道功与突破模板

大境界突破的难度、挑战结构和奖励，由当前大境界主修道功记录决定。

```
当前大境界主修道功记录
→ 读取突破模板
→ 读取功法阶级 + 品级配置
→ 生成挑战序列、难度参数、奖励结构、失败标签池
```

由于主修道功只能在 A-1 / B-1 / C-1 等大境界突破后的首个小阶段窗口修改，临近突破时无法临时换功法规避难度。

## 15. 突破结果类型

MVP 可支持或预留：

- 完美突破。
- 正常突破。
- 残缺突破。
- 失败但存活。
- 身死转世。
- 严重失败并附带真灵 / 因果 / 遗产后果。

若实现成本紧张，第一版可先做：

```
正常成功
失败存活
身死转世
```

残缺突破保留数据字段。

## 16. 失败标签

突破失败必须输出一个或多个标签。

方向包括：

- 修为积累不足。
- 修为纯度不足。
- 肉身承载不足。
- 心境不稳。
- 功法不合。
- 突破资源不足或不匹配。
- 护法不足。
- 地点灵气不足或不稳定。
- 宗门支持不足。
- 因果负担过重。
- 前世失败阴影未化解。
- 外部干扰过强。

失败标签进入轮回账本。

## 17. MVP 突破链范围

MVP 只需完整验证两段关键突破链：

1. M1 → M2：第一次大境界突破。
2. M2 → M3：第二次大境界突破，加入更明显宗门与世界压力。

已收敛特殊挑战结构：

```
M1 → M2：固定 1 轮 5 格
M2 → M3：可配置为 1 轮 5 格 + 外扰变体
```

低预警外扰不应直接中断突破；高风险预警或明确敌对事件下外部干扰可直接导致突破中断。

## 18. 战斗 / 斗法定位

战斗不是独立战棋、实时操作或高频刷怪系统，而是高风险事件链中的轻量结算框架。

适用：

- 移动遭遇。
- 节点危机。
- 秘境遭遇。
- 宗门任务。
- 突破外扰。
- 资源争夺。
- 剧情切磋或死战。

## 19. 战斗资源

战斗读取角色持久状态：

```
生机 bar_vitality
元气 bar_qi
神念 bar_mind
```

战斗结束后不自动恢复满值。

损失类型：

| 类型 | 含义 |
| --- | --- |
| 消耗 | 主动使用指令支付的成本 |
| 伤害 | 被对方指令或事件造成的削减 |
| 状态封锁 / 扰动 | 影响使用效率，不一定立刻削减当前值 |

## 20. 战斗指令

战斗中一切主动行为统一称为指令。

来源：

1. 随身携带的法宝技能。
2. 消耗道具。
3. 已学习术法 / 神通。
4. 功法解锁基础招式或被动转化行为。
5. 通用基础指令。
6. 事件特殊指令。

```
CombatCommand {
  id: String,
  display_name_key: String,
  source_type: String,
  command_type: String,    # attack / defense / buff / recovery / control / escape / special
  tags: Array,
  target_bar: String,      # vitality / qi / mind / mixed / none
  resource_cost: Dictionary,
  base_power_profile: Dictionary,
  counter_profile: Dictionary,
  duration: int,
  max_uses_per_battle: int,
  slot_restriction: Dictionary,
  event_flags: Array,
  ai_usage_hint: Dictionary
}
```

## 21. 战斗结构

已定：

- 5 格指令预输入。
- 5 格全部结算完成视为 1 个战斗回合。
- 一场战斗最多 3 个战斗回合，常量可配置。
- 每个交锋格后都检查结束条件，允许提前结束。
- 不同战斗可携带不同结束条件。
- 最大回合后未结束，平手 / 僵持后果由父事件链解释。

## 22. 核心克制关系

```
攻击克制 Buff
防御克制攻击
Buff 克制防御
```

规则：

- 攻击 vs 攻击：威力抵消后造成差值伤害。
- 防御通常比攻击消耗低，同层级防御有效值更高。
- Buff 遭遇攻击时仍可生效，但伤害达到阈值才打断。
- 余波、穿透、两败俱伤、反震等作为后续特殊标签扩展。

## 24. 事件 / 突破 / 战斗 MVP 验收清单

- 移动或节点能触发常规选择事件。
- 常规事件可显示 1–3 个主选项。
- 不可用选项默认隐藏。
- 事件结果包交给 S1 回写。
- 大境界突破前显示风险档位和短板。
- 突破需要关键突破物。
- 关键突破物在事件链创建时消耗。
- M1 → M2 可跑通 1 轮 5 格突破挑战。
- 突破失败写入失败标签和轮回账本。
- 战斗可生成 5 格指令预输入。
- 战斗使用生机、元气、神念持久状态。
- 战斗最多 3 回合并可提前结束。
- 战斗结果包返回父事件链。
