# 系统设计｜移动玩法

## 1. 设计定位

移动玩法负责回答玩家角色在共享世界日历中“人在哪里、能去哪里、如何前往、花多少世界小时、消耗什么状态资源、承担什么路线风险、最终停在哪里”。移动不是地图瞬移，也不是独立于行动系统之外的特殊结算，而是普通行动队列中的 `travel` 指令。

本文维护移动行动的指令输入、路线校验、时间成本、资源消耗、移动事件、能力 / 设施 / 法宝影响、落点与中断规则。普通行动队列、自动兜底、F1 / N1 / B1 / P0 和 C1 的房间级边界由《行动指令》（`09_行动指令设计.md`）与流程文档维护；路线节点本体、数值公式和页面布局由对应文档维护。

## 2. 当前结论

1. 移动行动统一建模为 `Command.command_type: travel`，按 `world_day / world_hour` 进入服务端校验、小时 tick、日志和回放。
2. 任何会改变角色所在地图节点的移动行动，最终 `duration_hours` 或 `current_cost_hours` 都不得小于 1 游戏小时。
3. 移动默认消耗玩家角色元气 `bar_qi_current`；交通设施、传送阵、飞舟、移动法宝或特殊路线可以追加灵石、聚灵石、设施费用、法宝耐久、法宝充能、神念、权限或维护资源。
4. 常规移动一般不自动消耗背包物品；干粮、符箓、避瘴丹、通行令等只在路线条件、玩家显式资源输入或事件选项要求时消耗。
5. 长途赶路可以作为长期低交互行动参与 F1 候选，但必须满足全员低交互、无事件、无交锋、无全局节点、无自动兜底和无临近截止事项。

## 4. 核心循环或触发入口

玩家从指令管理入口提交移动行动。服务端根据当前位置、目标节点、移动方式、显式停靠点、资源输入、可见路线、路线状态、角色状态、设施 / 法宝 / 功法条件和当前事件状态生成移动计划。

基础流程：

```text
玩家提交移动指令
→ 服务端做入队校验
→ 生成移动计划与可见预览
→ 指令进入普通行动队列
→ 执行前再次校验路线、资源、状态与事件冲突
→ 按世界小时结算移动段
→ 扣除元气和已生效资源
→ 触发或检查移动事件
→ 抵达、延误、中断或进入交锋 / 公共事件
→ 写入位置、落点、结果包、个人日志和回放
```

底层时间口径：

```text
移动指令 = Command.command_type: travel
结算时间 = world_day / world_hour
服务器最小结算单位 = 1 游戏小时
移动行动最小时间消耗 = 1 游戏小时
```

若同节点服务入口、建筑面板或商店面板不消耗时间，它应被建模为当前节点内的 UI / 服务入口，不应被建模为移动行动。若被建模为移动行动，则仍按最小 1 小时处理。

## 5. 规则与状态

### 5.1 指令输入粒度

MVP 的移动输入粒度为：

```yaml
TravelCommandInput:
  target_node_id: string
  travel_mode: walk | lightness_method | mount_or_vehicle | artifact | facility | teleport | special
  stopover_nodes: list[string]
  resource_inputs: list
```

规则：

1. `target_node_id` 是移动的主要目标。
2. `travel_mode` 表示移动方式，决定时间、元气、风险、可用路线和额外资源消耗。
3. `stopover_nodes` 只记录玩家显式要求停靠或安全中转的节点；MVP 不做完整逐边手动排路，也不做复杂复合交通路线编辑。
4. `resource_inputs` 只记录玩家主动绑定的资源输入或路线要求的资源输入，不自动消耗背包物品。
5. 服务端根据当前位置、可见路线、路线权重、通行条件、风险门、交通设施、隐藏路线和角色状态生成实际移动计划。

### 5.2 路线状态与校验

移动读取有向带权路线。双向路线应拆成两条路线，因为双向成本、风险和通行条件可能不同。

路线校验读取：

```text
当前位置
目标节点
路线是否可见
passability
requirements
risk_tags
current_cost_hours
角色状态
宗门、NPC 或事件授予的通行许可
是否存在路线封锁、节点事件或公开危险
移动方式对应的设施、法宝或功法是否可用
```

入队时校验：

```text
当前地点允许移动
目标节点可见或有合法线索
至少存在一条当前可用路线或条件路线
移动方式当前可用
当前元气、状态和额外资源满足要求
路线风险没有阻止移动
当前事件状态不冲突
```

执行前必须再次校验，防止路线在等待期间被封锁、节点风险变化、权限失效、角色状态恶化、设施停运或法宝不可用。

执行前校验失败时：

```text
1. 跳过该移动指令；
2. 不消耗未生效资源；
3. 记录个人日志；
4. 进入自动兜底；
5. 世界进入 N1，等待玩家补充主动指令。
```

### 5.3 时间成本

移动时间以路线 `current_cost_hours` 为基础，按小时结算。

结算流程：

```text
1. 读取目标路线或路线段。
2. 读取 base_cost_hours。
3. 应用路线状态、风险、天气 / 节点事件、交通设施、功法、法宝和角色状态修正。
4. 得到 current_cost_hours。
5. 对移动行动执行最小时间约束：max(1, current_cost_hours)。
6. 多段移动按各段结果累加；总移动时间不得小于 1 小时。
```

时间成本可被以下因素改变：

| 因素 | 影响方向 |
| --- | --- |
| 轻身功法、飞遁法门、路线熟悉度 | 降低耗时，但不能低于 1 小时 |
| 伤势、疲惫、低元气、负面状态 | 增加耗时或阻止移动 |
| 山路、水路、秘境边界、敌对边境 | 增加耗时、风险或通行条件 |
| 交通设施、飞舟、传送阵、路线枢纽 | 降低耗时或改变可达路线，但通常带来额外资源成本 |
| 路线阻断、封锁、追击、公共节点事件 | 阻止移动、延误或强制中转 |

长途赶路可以作为长期低交互行动参与 F1 的候选，但只有在所有玩家都满足长期低交互条件，且没有事件、交锋、全局节点、自动兜底或临近截止事项时才可进入 F1。

### 5.4 资源消耗

普通移动默认消耗玩家角色的元气。

```yaml
TravelResourceCost:
  primary_bar: bar_qi_current
  cost_basis:
    - travel_hours
    - route_type
    - risk_tags
    - travel_mode
    - character_state
    - method_or_artifact_modifiers
```

设计口径：

1. 元气是气力、法力和可支配能量的统一派生状态条。
2. 移动不是免费改变位置；即使没有物品消耗，也应有元气或状态负担。
3. 元气不足时，移动入队或执行前校验可以失败，也可以由模板提供低速、休整后再行、改走设施路线等替代入口。
4. 元气消耗不得侵占 `bar_qi_reserve` 预留值；预留值代表不可支配容量。
5. 移动消耗的元气、状态变化和失败原因必须写入个人日志、结果包或回放。

使用特殊移动手段时，可以追加资源成本：

| 移动方式 | 可能额外消耗 |
| --- | --- |
| 交通设施、渡口、驿站、坊市路线服务 | 灵石、低阶货币、通行许可、宗门权限或服务费用 |
| 传送阵、阵台、空间设施 | 灵石、聚灵石、设施供能、阵法维护资源、权限 |
| 飞舟、坐骑、载具 | 灵石、维护费用、燃料资源、节点服务费用 |
| 主动型或辅助型移动法宝 | 元气、神念、法宝耐久、法宝充能、聚灵石或特定材料 |
| 特殊危险区域 | 避瘴丹、护身符、通行令、事件选项资源或路线要求资源 |

常规步行、轻身赶路和普通山道移动一般不消耗物品。干粮、丹药、符箓、通行令等只在以下情况下消耗：

1. 玩家在移动指令中显式选择作为 `resource_inputs`。
2. 路线 `requirements` 明确要求。
3. 移动事件选项明确消耗。
4. 设施或法宝模板明确要求。

行动未开始、路线执行前校验失败、事件选项未生效时，不提前消耗关键资源或物品。

### 5.5 移动预览

移动预览应同时表达：

1. 预计时间成本，且明确最小为 1 小时。
2. 默认元气消耗。
3. 设施、法宝、灵石、聚灵石或其他额外资源成本。
4. 当前路线风险、风险标签和公开阻断信息。
5. 通行条件、权限门、状态门和隐藏路线条件。
6. 可选停靠点、中转点和可能的临时停靠。
7. 事件触发可能性，但不展示未发现事件的完整真相。
8. 移动失败或中断后的默认停留位置。

预览只展示玩家可见信息。其他玩家的私人事件、隐秘追击、局部时停原因和未公开路线变化不得通过移动预览泄露。

### 5.6 移动事件

移动事件覆盖：

```text
离开节点
进入节点
途经节点
目标节点
每个移动结算段结束时所在路线段
临时停靠点、中转点或被事件打断后的落点
```

移动事件可产生：

```text
遭遇战
路线阻断
资源消耗
信息发现
行踪暴露
延误
追击
临时停靠
安全抵达
路线风险变化
节点公开传闻
```

事件时间口径：

1. 轻量个人遭遇进入本人局部时停，外部世界继续 N1。
2. 正式追击、玩家直接冲突、重大资源损失风险或正式战斗进入 B1。
3. 全局公共路线封锁、秘境入口公共变化等少数公共节点可进入 P0。
4. 事件选项有游戏内时间成本时，按 `consumed_hours` 回填到世界小时。
5. 事件造成延误时，后续队列开始时间相应推迟。

### 5.7 能力、设施与法宝影响

轻身功法、飞遁法门和身法类能力可以：

1. 降低部分路线移动耗时，但不能突破 1 小时最小消耗。
2. 降低移动元气消耗。
3. 降低延误损失。
4. 解锁逃遁、绕路、攀越、潜行或避险选项。
5. 改善山路、荒野、追击或低阶遭遇中的事件选项。

战斗功法可以改善移动遭遇战、护送、正面迎战和遭遇后结算反馈。

交通设施可以：

1. 改变可达节点或路线。
2. 降低时间成本。
3. 降低路线风险。
4. 提供安全停靠、中转、补给或传送入口。
5. 收取灵石、聚灵石、权限、贡献或维护资源。

移动法宝可以：

1. 作为移动方式参与行动入口。
2. 降低时间或风险。
3. 提供飞遁、渡河、隐蔽、护体、传送或逃遁能力。
4. 消耗元气、神念、耐久、充能、聚灵石或专用材料。
5. 在使用、被拦截、过载或事件代价中产生损坏、失灵或充能下降。

法门、法宝和道具也可作为事件选项依据，但不得默认吞掉玩家选择权。

### 5.8 落点与中断

移动完成时更新 `location_node_id`。若移动被事件或路线变化中断，落点按以下优先级确定：

```text
1. 已抵达的目标节点；
2. 玩家显式停靠点；
3. 当前路线段的安全中转节点；
4. 事件指定临时停靠点；
5. 原出发节点；
6. 失败状态模板指定的危险临时落点。
```

落点必须写入结果包、个人日志和回放。若落点为危险临时点，系统应提示风险，并由节点 `risk_level` 影响自动兜底和显式托管默认。

## 7. 数据字段建议

### 7.1 移动指令输入

| 字段 | 含义 |
| --- | --- |
| `command_type` | 固定为 `travel` |
| `target_node_id` | 移动目标节点 |
| `travel_mode` | 移动方式：`walk`、`lightness_method`、`mount_or_vehicle`、`artifact`、`facility`、`teleport`、`special` |
| `stopover_nodes` | 玩家显式要求停靠或安全中转的节点列表 |
| `resource_inputs` | 玩家主动绑定或路线要求的资源输入项 |

### 7.2 路线状态

| 字段 | 含义 |
| --- | --- |
| `route_id` | 路线唯一标识 |
| `from_node_id` | 起点节点 |
| `to_node_id` | 终点节点 |
| `base_cost_hours` | 路线基础小时成本 |
| `current_cost_hours` | 当前状态下的小时成本 |
| `route_type` | 路线类型：`road`、`mountain_path`、`river`、`teleport`、`hidden`、`rumor` |
| `passability` | 通行状态：`open`、`blocked`、`conditional`、`unknown` |
| `requirements` | 通行条件、权限、资源或状态要求 |
| `risk_tags` | 路线风险标签 |
| `discovered_by` | 已发现该路线的角色、阵营或玩家范围 |
| `last_updated_world_day` | 路线状态最后更新的世界日 |
| `last_updated_world_hour` | 路线状态最后更新的世界小时 |

### 7.3 移动上下文

| 字段 | 含义 |
| --- | --- |
| `command_id` | 关联行动指令 |
| `character_id` | 移动角色 |
| `world_day` | 移动开始或结算所在世界日 |
| `world_hour` | 移动开始或结算所在世界小时 |
| `from_node_id` | 出发节点 |
| `to_node_id` | 目标节点 |
| `route_segment_refs` | 实际移动计划中的路线段引用 |
| `travel_mode` | 本次使用的移动方式 |
| `stopover_nodes` | 显式停靠或安全中转节点 |
| `planned_travel_hours` | 计划移动小时，必须为整数且不得小于 1 |
| `min_consumed_hours` | 移动最小消耗小时，固定为 1 |
| `expected_qi_cost` | 预计元气消耗 |
| `extra_resource_costs` | 额外资源成本列表 |
| `exposure_tags` | 行踪暴露、追踪或公开可见标签 |
| `risk_tags` | 本次移动承接的风险标签 |
| `event_candidate_refs` | 可参与移动事件候选的事件引用 |

### 7.4 移动资源成本

| 字段 | 含义 |
| --- | --- |
| `primary_bar` | 默认状态资源，当前为 `bar_qi_current` |
| `travel_hours` | 移动小时成本 |
| `route_type` | 路线类型成本因子 |
| `risk_tags` | 风险成本因子 |
| `travel_mode` | 移动方式成本因子 |
| `character_state` | 伤势、疲惫、负面状态或增益状态 |
| `method_or_artifact_modifiers` | 功法、法门、设施、法宝或载具修正 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示玩家本人当前位置、目标节点、移动方式、预计时间、最小 1 小时规则、预计元气消耗、额外资源成本、公开路线风险、通行条件、可见中转点、停靠点、移动事件可能性、失败原因、自动兜底结果、抵达 / 延误 / 中断摘要和个人日志入口。

普通 UI 不展示其他玩家私人事件、隐秘追击来源、局部时停原因、未公开路线变化、未发现事件真相、隐藏路线完整条件、内部路线权重、原始事件概率、Debug 字段或服务端逐 tick 明细。

移动预览必须只展示玩家当前可见信息；若某条路线不可见或条件未知，界面应表达“未知 / 需要线索 / 条件不足”，而不是泄露完整门槛。B1、P0 或个人局部时停触发后，移动页面只承接状态和返回入口，不替代正式交锋、公共事件或个人事件选择。

## 9. MVP 范围

MVP 应实现：

1. `travel` 普通指令。
2. 移动行动最小 1 小时消耗。
3. 入队时与执行前双重校验。
4. 有向带权路线与 `current_cost_hours`。
5. 默认元气消耗。
6. 设施、法宝或特殊路线的额外资源消耗入口。
7. 移动预览。
8. 路线风险与事件触发。
9. 移动完成、延误、中断和落点记录。
10. 移动结果写入结果包、日志和回放。

MVP 不实现：

1. 完整逐边手动排路。
2. 复杂复合交通路线编辑器。
3. 0 小时移动行动。
4. 默认消耗干粮、丹药、符箓或其他背包物品。
5. 负重、背包格子、重量和容量玩法。
6. 完整坐骑、飞舟、传送阵产业链。
7. 复杂天气、生态和道路自然磨损模拟。
8. 用托管或自动兜底主动进入高危路线。

## 10. 验收约束

1. 任何改变角色所在地图节点的移动行动，结算耗时不得低于 1 游戏小时。
2. 移动必须作为 `travel` 普通指令经过行动系统的入队校验和执行前校验；不能绕过服务端直接改写位置。
3. 移动执行前校验失败时，不得消耗未生效资源，必须记录失败原因并进入行动系统的自动兜底流程。
4. 常规移动不得默认消耗背包物品；只有显式资源输入、路线要求、事件选项或设施 / 法宝模板要求时才消耗。
5. 元气消耗不得侵占 `bar_qi_reserve` 预留值。
6. 移动预览不得泄露未发现事件、隐秘追击、其他玩家私人事件、隐藏路线完整条件或未公开路线变化。
7. 移动事件进入 B1、P0 或个人局部时停时，移动系统只移交状态和上下文，不替代正式交锋、公共事件或个人事件选择。
8. 抵达、延误、中断、临时落点、危险落点和位置变化必须写入结果包、个人日志和回放。
