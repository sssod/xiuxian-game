# 角色与真灵设计｜角色属性

## 1. 系统定位

角色属性属于当前世“身躯与灵魂”层，不默认跨世继承。它用于描述这一世角色的身体底子、修炼潜质、当前状态、承受风险的能力和对功法的倾向性。

角色属性需要同时服务：

- 角色初始化
- 角色当前状态描述
- 各类机制与事件的检测与判定
- 修炼效果计算
- 战斗结果计算
- 角色页面展示
- BUFF/DEBUFF, HOT/DOT, 健康/伤势/死亡等状态的反馈目标

当前裁决：

- 不设置单一“资质总分”参与核心判定。
- 体魄 / 精力是通用基础属性。
- 根骨 / 悟性 / 灵根是修炼资质子项。
- 悟性不再同时作为基础属性。
- 生机 / 元气 / 神念是持久派生状态条。
- 寿元状态纳入角色属性维度，用于记录当前年龄、寿元上限、寿元压力和体魄 / 精力年龄阶段修正入口；寿元不是生机条，也不是战斗内临时资源。
- 年龄阶段由当前年龄与寿元上限派生，只参与体魄 / 精力的最终值计算；读取体魄 / 精力最终值的公式会承接该影响。年龄阶段不影响修炼资质、灵根或神念基础值，也不回写先天属性或后天永久修正。
- 基础属性和修炼资质区分先天、后天、临时三类来源 / 持续性口径；临时修正均属于后天来源，但不回写为永久后天属性。
- MVP 阶段灵根仅支持先天结果，不支持后天永久改写或临时灵根改写。
- 派生状态只区分永久 / 临时；永久派生状态不再细分先天 / 后天。

## 2. 属性分层

| 层级 | 数据结构 | 作用 |
| --- | --- | --- |
| 基础属性 | `BaseAttributes` | 当前世身躯与状态底子，主要支撑派生状态上限和行动承受 |
| 修炼资质 | `AptitudeProfile` | 当前世修炼潜质、路线适配、学习理解和资源转化差异 |
| 派生状态 | `DerivedBars` | 当前可用生机、元气、神念及其保留容量 |
| 寿元状态 | `LifespanState` | 当前年龄、寿元上限、剩余寿元、寿元压力和体魄 / 精力年龄阶段修正入口 |
| 后天修正 | `acquired_modifiers` | 记录后天永久改变、临时修正、损伤和来历说明 |
| 伤势状态 | `injuries_and_conditions` | 记录伤病、道伤、心魔、药性、负面状态等持续影响 |

## 3. 来源与持续性口径

基础属性和修炼资质使用同一套来源 / 持续性口径：

| 口径 | 含义 | 是否永久 | 记录要求 |
| --- | --- | --- | --- |
| 先天 | 出生、身躯生成、特殊开局或角色初始生成时确定的属性底子 | 是 | 写入对应属性的先天值或先天结构 |
| 后天 | 修炼、突破、宗门培养、资源、事件、伤损修复等形成的永久改变 | 是 | 写入对应属性的后天永久修正，并保留来源 |
| 临时 | 丹药、阵法、法宝、状态、伤势、事件阶段效果等形成的非永久修正 | 否 | 作为后天来源的临时修正记录，必须有持续时间、触发条件或失效条件 |

规则：

- “先天”和“后天”在属性字段中都表示永久结果；若效果不是永久，不应标记为先天或后天永久属性。
- “临时”均为后天来源，但它是持续性口径上的临时修正，不应回写到先天值或后天永久值。
- 基础属性和非灵根资质可以同时拥有先天值、后天永久修正和临时修正。
- MVP 阶段灵根只支持先天：`aptitude_root`、`root_affinity_tags`、`root_affinity_profile` 只记录先天生成或特殊开局结果。
- 影响灵根相关结算的丹药、阵法、法宝、道功补偿、污染、遮蔽等效果，在 MVP 中不得写成“临时灵根”或“后天灵根”，只能作为外部状态、资源效果、道功效果或结算修正存在。
- 派生状态不使用先天 / 后天口径。生机、元气、神念的当前值、上限、保留容量和状态修正只区分永久 / 临时；永久调整不再追溯为先天或后天。
- 寿元状态不使用先天 / 后天 / 临时属性口径。`age` 随世界时间推进；`lifespan_limit` 可由突破延寿、资源延寿、宗门供养、伤势折寿、道伤、燃寿或失败突破等结果改变，并必须记录来源。
- `age_ratio`、`remaining_lifespan`、`aging_phase` 和 `lifespan_pressure_state` 是由年龄、寿元上限、风险标签和数值表派生的当前状态，不应手动写成永久属性。

## 4. 基础属性

基础属性只保留当前世身躯 / 状态底子的基础字段，不包含可评级资质子项。

| 显示名 | 内部字段 | 主要作用 |
| --- | --- | --- |
| 体魄 | `base_physique` | 生机上限、负伤承受、肉身完整度、体力型行动承受、肉身类突破准备 |
| 精力 | `base_vigor` | 元气底子、持续行动承受、疲劳恢复、主动运转功法稳定性 |

来源规则：

- 体魄与精力可以有先天值、后天永久修正和临时修正。
- 临时体魄 / 精力修正均视为后天来源，但不得回写为永久后天属性。
- 年龄阶段修正可以参与体魄与精力的 `effective_value` 计算，用于表达幼年未长成、壮年稳定、衰老下滑等生命周期差异；它不是先天值、后天永久修正或临时增益。
- 年龄阶段修正是体魄 / 精力最终值计算中的独立乘区，不并入普通增减幅系数。
- 普通修为进度不直接增加体魄或精力。
- 突破、宗门培养、资源使用、特殊事件或长期修炼路径可以少量改善体魄或精力，但必须写入来历记录。
- `base_comprehension` 废弃；悟性只进入 `AptitudeProfile`。

具体体魄 / 精力最终值公式、先天最终值 / 后天最终值拆分、年龄阶段乘区和缓存字段，由 `docs/inbox/xiuxian_design_reorganized_md/03_数值设计/09_角色属性与派生状态数值设计.md` 维护。本文只规定字段语义、来源口径和年龄阶段影响边界。

## 5. 修炼资质

修炼资质不是独立总等级。底层规则读取具体资质子项，UI 可以显示综合评价，但综合评价只用于提示和叙事，不直接参与核心判定。

### 5.1 子项总览

| 显示名 | 内部字段 | 主要作用 |
| --- | --- | --- |
| 根骨 | `aptitude_bone` | 身体承载、经脉基础、修炼容器质量、部分突破准备 |
| 悟性 | `aptitude_comprehension` | 理解、参悟、功法学习、复杂路线掌握、非战斗技艺成长 |
| 灵根 | `aptitude_root` | 灵气亲和、路线适配、功法门槛、吸收方向 |
| 灵根相性标签 | `root_affinity_tags` | 灵根与路线、资源、节点环境、道功标签的匹配入口 |
| 灵根相性结构 | `root_affinity_profile` | 灵根相性的数值、权重、主次标签和冲突标签结构 |

### 5.2 生成与揭示

资质在出生 / 身躯生成时已经生成。入门事件、机缘、宗门检测或特定场景只负责检测、揭示、评级和写入角色自知信息，不在检测现场临时生成资质。

推荐可见性字段：

```text
aptitude_rating_visibility = unknown | partial | revealed
```

含义：

- `unknown`：角色尚未检测，不向玩家显示完整资质。
- `partial`：只显示粗略评价、部分标签或疑似方向。
- `revealed`：显示当前已确认的字段和评级。

MVP 中，资质检测后常态显示已揭示资质；未检测前按可见性字段隐藏或弱化展示。

### 5.3 年龄阶段与资质边界

旧设计中的“年龄%分段函数”只适用于一般属性模板，不适用于特殊属性随机池。迁入当前属性结构后，年龄阶段只影响基础属性中的：

- `base_physique`。
- `base_vigor`。

年龄阶段不得影响：

- `aptitude_bone`。
- `aptitude_comprehension`。
- `aptitude_root`。
- `root_affinity_tags`。
- `root_affinity_profile`。

根骨、悟性和灵根仍按资质规则处理。年龄、延寿、折寿、伤势或燃寿状态可以影响修炼、突破或灵根相关结算的外部条件、风险或压力，但不能改写资质有效值、灵根评级和相性结构。

## 6. 灵根专项规则

### 6.1 字段职责

灵根由“基础评级”和“相性结构”共同表达。

| 字段 | 说明 |
| --- | --- |
| `aptitude_root` | 灵根基础评级，表示角色对灵气、功法门槛和修炼路线的总体适配潜力 |
| `root_affinity_tags` | 相性标签，例如木、火、水、风、雷、阴、阳等路线、资源或环境标签 |
| `root_affinity_profile` | 标签权重、主次关系、冲突标签、适配阈值等更细结构 |

`root_affinity_tags` 不能单独代表全部灵根。`aptitude_root` 也不能替代相性标签。两者共同决定“灵根好不好”和“适合走什么路线”。

### 6.2 包装与底层映射

灵根可以在 UI 或世界观文本中包装成单灵根、双灵根、异灵根、杂灵根等说法，但底层仍映射到：

```text
aptitude_root
root_affinity_tags
root_affinity_profile
```

MVP 优先使用标签匹配，不做复杂五行循环、相生相克链或多层灵根谱系。

### 6.3 与道功路线的关系

道功具有路线标签、资源相性、节点环境相性和突破路线标签。灵根相性用于判断角色与当前主修道功、资源输入、修炼环境是否匹配。

读取场景：

- 主动吐纳的路线适配。
- 自动运转的稳定性和收益修正。
- 主修道功的功法门槛与路线匹配。
- 定向资源、丹药、灵材、节点灵气的吸收适配。
- 大境界突破前的路线一致性和风险提示。

灵根不直接替代道功掌握度，也不直接替代根骨承载。一个角色灵根相性好，仍需要合适道功、有效修炼时间、资源输入和状态稳定才能转化为收益。

### 6.4 与法门和战斗指令的关系

法门与灵根的关系主要是使用相性，不直接改变修为进度。

高相性可以表现为：

- 指令更稳定。
- 消耗更低。
- 效果质量更好。
- 解锁门槛更低。

低相性可以表现为：

- 元气消耗更高。
- 效果波动更大。
- 失败或反噬风险更高。
- 需要更高掌握度、资源或境界才能稳定使用。

### 6.5 与资源和环境的关系

修为资源输入先形成可参与结算的灵气输入，再进入承载、相性、转化和状态压力判断。本文只说明灵根在这些环节中的语义位置，不规定修炼系统必须采用固定字段清单或固定结算顺序。

可供修炼系统参考的语义顺序：

```text
环境灵气 + 资源灵气输入
→ 根骨安全承载
→ 根骨转化效率
→ 灵根与道功 / 资源 / 节点相性
→ 道功基础转化率
→ 状态修正
→ 修为进度、压力与副作用
```

灵根相性适合用于判定“这份输入是否适合这个人和这条路线”，不适合直接做成无条件经验倍率。

### 6.6 MVP 灵根边界

MVP 阶段灵根仅支持先天结果。`aptitude_root`、`root_affinity_tags` 和 `root_affinity_profile` 不支持后天永久改写，也不支持临时灵根改写。

允许存在影响灵根相关结算的外部效果：

- 阵法、法宝、丹药、灵材、洞府设施提供定向吸收修正。
- 道功或法门提供路线补偿。
- 特殊事件提供阶段性亲和、遮蔽、污染或过载状态。

这些效果应写入 `acquired_modifiers`、状态 / 增益记录、资源效果记录或道功效果记录；它们可以影响对应系统的判定，但不得回写 `aptitude_root`、`root_affinity_tags` 或 `root_affinity_profile`，也不得在 UI 或规则文本中表述为“临时灵根”或“后天灵根”。

## 7. 派生状态

派生状态是角色状态条，不是战斗内临时资源。战斗结束后不默认回满。

| 状态 | 当前值字段 | 上限字段 | 保留值字段 | 用途 |
| --- | --- | --- | --- | --- |
| 生机 | `bar_vitality_current` | `bar_vitality_max` | `bar_vitality_reserve` | 健康、伤病、濒死、肉身完整度 |
| 元气 | `bar_qi_current` | `bar_qi_max` | `bar_qi_reserve` | 气力 / 法力 / 可支配能量 |
| 神念 | `bar_mind_current` | `bar_mind_max` | `bar_mind_reserve` | 灵魂、神识、心神稳定 |

保留值字段统一使用 `reserve`，用于后续规则预留不可支配容量。默认值为 0。

约束：

```text
0 <= bar_vitality_reserve <= bar_vitality_max
0 <= bar_qi_reserve <= bar_qi_max
0 <= bar_mind_reserve <= bar_mind_max

bar_vitality_current <= bar_vitality_max - bar_vitality_reserve
bar_qi_current <= bar_qi_max - bar_qi_reserve
bar_mind_current <= bar_mind_max - bar_mind_reserve
```

### 7.1 上限计算边界

派生状态上限公式不在本文维护：

- 生机最大值的数值公式由 `docs/inbox/xiuxian_design_reorganized_md/03_数值设计/09_角色属性与派生状态数值设计.md` 维护；本文只规定生机语义上代表健康、伤病、濒死和肉身完整度。
- 元气最大值的数值公式由同一数值文档维护；本文只规定元气语义上代表气力 / 法力 / 可支配能量。
- 神念最大值的数值公式由同一数值文档维护；本文只规定神念语义上代表灵魂、神识和心神稳定。

系统边界：

- 生机不是寿元。
- 生机和元气可以在数值公式中读取体魄 / 精力最终值，因此会承接体魄 / 精力年龄阶段乘区的结果。
- 神念不读取体魄、精力、年龄阶段或悟性资质。

来源规则：

- 派生状态只区分永久 / 临时，不区分先天 / 后天。
- 永久派生状态用于表示稳定的当前值、上限、保留容量或永久性状态影响，不再细分它来自先天底子还是后天培养。
- 临时派生状态用于表示伤势、增益、负面状态、资源残效、场景影响等非永久变化，必须有持续时间、触发条件或失效条件。
- 生机不是寿元。生机描述当前健康、肉身完整度和濒死风险；寿元描述当前世最大时间预算和年龄阶段压力。重伤、道伤、燃寿或突破失败可以同时影响生机与寿元，但必须分别写入对应状态。
- 神念可以在新手阶段 UI 隐藏或弱化展示，但数据层保留。

## 8. 寿元与年龄阶段

### 8.1 系统定位

寿元是当前世角色的最大时间预算，不只是死亡倒计时。它需要服务：

- 当前年龄和剩余寿元展示。
- 修炼、突破、延寿、疗伤、燃寿、折寿和转世决策。
- 年龄阶段对体魄 / 精力最终值的独立乘区修正。
- 死亡 / 转世事件链入口。

寿元属于当前世角色层，死亡后随本世结算；真灵不继承当前年龄、当前寿元上限或当前寿元压力。

### 8.2 推荐字段

```text
LifespanState {
  age: int
  lifespan_limit: int
  remaining_lifespan: int
  age_ratio: number
  aging_phase: childhood | growth | prime | aging | exhausted
  lifespan_pressure_state: safe | pressured | urgent | exhausted
  lifespan_extension_sources: Array
  lifespan_risk_tags: Array
}
```

字段说明：

- `age`：当前年龄，随世界时间推进。
- `lifespan_limit`：当前寿元上限。若外层 `CharacterState` 使用 `lifespan` 字段，语义等同于本文的 `lifespan_limit`。
- `remaining_lifespan`：剩余寿元，通常由 `lifespan_limit - age` 派生；不得作为独立事实覆盖年龄或寿元上限。
- `age_ratio`：年龄比例，按 `age / lifespan_limit` 派生。寿元上限变化后，后续结算使用新的比例。
- `aging_phase`：年龄阶段，由 `age_ratio` 和数值表派生；本文只规定字段语义，不固定分段阈值。
- `lifespan_pressure_state`：寿元压力提示状态，用于避免玩家在无感知状态下突然死亡。
- `lifespan_extension_sources`：突破延寿、资源延寿、宗门供养、秘境机缘等已生效来源记录。
- `lifespan_risk_tags`：寿元折损、道伤、衰败、燃寿、失败突破等风险标签。

### 8.3 年龄比例对属性的影响

年龄比例由当前年龄与寿元上限派生。体魄 / 精力最终值公式、年龄阶段乘区和年龄曲线由 `docs/inbox/xiuxian_design_reorganized_md/03_数值设计/09_角色属性与派生状态数值设计.md` 维护。本文只规定年龄阶段的影响范围和来源口径。

约束：

- 年龄阶段乘区只表示当前年龄阶段对体魄 / 精力的影响，不写入 `innate_value`、`acquired_permanent_delta` 或 `temporary_modifiers`。
- 数值表只为 `base_physique` 和 `base_vigor` 配置年龄曲线，用于表达幼年未长成、壮年稳定、衰老下滑等生命周期差异。
- `aptitude_bone`、`aptitude_comprehension`、`aptitude_root`、`root_affinity_tags` 和 `root_affinity_profile` 不读取年龄阶段修正。
- 生机 / 元气公式不直接读取 `age_ratio` 或 `aging_phase`，但会读取已经承接年龄阶段乘区的体魄 / 精力最终值。神念公式不读取年龄阶段修正。
- `age_ratio >= 1.0` 应至少进入 `exhausted` 风险语境，并触发死亡 / 转世事件链或对应的延寿、续命、后手检查；具体事件流程由死亡与转世规则承接。

### 8.4 寿元变化来源

MVP 至少支持三类寿元变化：

1. 突破延寿：重大突破成功后提高 `lifespan_limit`，是最基础、最稳定的延寿来源。
2. 资源延寿：丹药、灵物、宗门供养、秘境机缘等提高寿元上限或延缓寿元压力。
3. 损耗折寿：重伤、道伤、失败突破、燃烧寿元类事件降低寿元上限或增加寿元风险标签。

寿元压力应显式提示。寿元不足可以推动玩家选择稳健修炼、冒险突破、寻求延寿资源、请求宗门支持、布置后手、主动计划转世或继续硬冲，但不应被设计成无选择空间的强制重开按钮。

## 9. 属性改变与记录

| 字段范围 | 先天 | 后天永久 | 临时 | MVP 处理方式 |
| --- | --- | --- | --- | --- |
| `base_physique` | 支持 | 支持 | 支持 | 后天永久改变通过明确行动、突破奖励、宗门培养、资源使用或事件结果写入修正；临时改变写入临时修正 |
| `base_vigor` | 支持 | 支持 | 支持 | 后天永久改变通过明确行动、突破奖励、宗门培养、资源使用或事件结果写入修正；临时改变写入临时修正 |
| `aptitude_bone` | 支持 | 支持 | 支持 | 后天永久改变可通过洗髓、淬体、重塑经脉、炼体闭关、突破反馈等高成本路径改善；临时改变写入临时修正 |
| `aptitude_comprehension` | 支持 | 支持 | 支持 | 后天永久改变可通过参悟、讲法、读经、秘境悟道、事件反馈等路径改善；临时明悟或丹药效果写入临时修正 |
| `aptitude_root` | 支持 | 不支持 | 不支持 | MVP 只保留先天生成或特殊开局结果 |
| `root_affinity_tags` / `root_affinity_profile` | 支持 | 不支持 | 不支持 | MVP 只保留先天相性结构；外部效果写入状态 / 增益 / 资源 / 道功效果记录 |
| `lifespan_limit` | 不适用 | 不适用 | 不适用 | 由突破延寿、资源延寿、宗门供养、伤势折寿、道伤、燃寿或失败突破等结果改变；作为寿元调整记录来源，不写入属性先天 / 后天 / 临时口径 |
| `age` / `age_ratio` / `aging_phase` | 不适用 | 不适用 | 不适用 | `age` 随世界时间推进；`age_ratio` 与 `aging_phase` 派生，不作为可直接改写的属性 |

后天永久改变必须满足：

- 有明确来历。
- 有永久性标记。
- 能解释给玩家。
- 能进入角色履历、日志或状态说明。
- 不把临时增益伪装成永久资质。

悟性若永久改变，写入 `aptitude_comprehension` 或后天修正记录；若只是短期明悟、丹药或事件增益，写入状态 / 增益记录，不回写永久资质字段。

## 10. 模块边界与展示

### 10.1 模块边界

角色属性是通用角色数据。本文只定义属性字段、来源口径、持续性口径和展示原则，不规定修炼、战斗、事件、AI、UI 等系统必须读取哪些字段，也不反向限制其他模块使用角色属性数据。

各系统可以按自身结算规则读取所需属性。涉及修炼、战斗、事件或资源输入的字段组合、结算顺序、倍率、阈值和风险算法，应由对应系统文档定义；角色属性模块只保证数据语义清晰、来源可追溯、临时与永久不混淆。

本文不维护具体数值公式、系数表或百分比乘区。角色属性相关的体魄 / 精力最终值、生机 / 元气 / 神念上限和年龄阶段数值曲线，由 `docs/inbox/xiuxian_design_reorganized_md/03_数值设计/09_角色属性与派生状态数值设计.md` 维护。

### 10.2 UI 展示

角色页面应展示：

- 当前世身份、年龄、寿元、剩余寿元、寿元压力、年龄阶段、宗门身份。
- 基础属性：体魄、精力。
- 修炼资质：根骨、悟性、灵根。
- 派生状态：生机、元气、神念。
- 当前主修道功、修为阶段、瓶颈 / 突破状态。
- 残余资源效果和重要后天修正。

角色页面不应把：

- 综合资质评价显示成底层判定字段。
- 灵根包装名显示成唯一底层字段。
- 真灵强度显示成稳定修炼效率加成。
- 执念容量显示成传统属性点。
- 体魄 / 精力的年龄阶段修正显示成先天资质或后天永久提升。

## 11. 数据字段建议

```text
CharacterAttributeProfile {
  base_attributes: BaseAttributes
  aptitude_profile: AptitudeProfile
  derived_bars: DerivedBars
  lifespan_state: LifespanState
  acquired_modifiers: Array
  injuries_and_conditions: Array
}

BaseAttributes {
  base_physique: SourceTrackedAttribute
  base_vigor: SourceTrackedAttribute
}

AptitudeProfile {
  aptitude_bone: SourceTrackedAttribute
  aptitude_comprehension: SourceTrackedAttribute
  aptitude_root: InnateOnlyRootRating
  root_affinity_tags: InnateOnlyRootTags
  root_affinity_profile: InnateOnlyRootAffinityProfile
  aptitude_rating_visibility: unknown | partial | revealed
}

SourceTrackedAttribute {
  innate_value: number
  acquired_permanent_delta: number
  temporary_modifiers: Array
  effective_value: number
}

InnateOnlyRootRating {
  innate_value: number
  effective_value: number
}

InnateOnlyRootTags {
  innate_tags: Array
}

InnateOnlyRootAffinityProfile {
  innate_profile: RootAffinityProfile
}

RootAffinityProfile {
  primary_tags: Array
  secondary_tags: Array
  affinity_weights: Dictionary
  conflict_tags: Array
  note: String | null
}

DerivedBars {
  bar_vitality_current: number
  bar_vitality_max: number
  bar_vitality_reserve: number
  bar_qi_current: number
  bar_qi_max: number
  bar_qi_reserve: number
  bar_mind_current: number
  bar_mind_max: number
  bar_mind_reserve: number
  permanent_adjustments: Array
  temporary_modifiers: Array
}

LifespanState {
  age: int
  lifespan_limit: int
  remaining_lifespan: int
  age_ratio: number
  aging_phase: childhood | growth | prime | aging | exhausted
  lifespan_pressure_state: safe | pressured | urgent | exhausted
  lifespan_extension_sources: Array
  lifespan_risk_tags: Array
}
```

说明：

- `SourceTrackedAttribute` 适用于基础属性和非灵根资质；体魄 / 精力的最终值拆分和年龄阶段乘区由数值文档定义。
- `innate_value` 和 `acquired_permanent_delta` 共同构成永久属性结果。
- `temporary_modifiers` 属于后天来源，但不计入永久结果。
- `effective_value` 是当前可被系统读取的实际值。基础属性中的体魄 / 精力可由永久结果、临时修正和年龄阶段修正计算得到；具体公式由数值文档定义。修炼资质不读取年龄阶段修正。
- `InnateOnlyRootRating`、`InnateOnlyRootTags` 和 `InnateOnlyRootAffinityProfile` 体现 MVP 阶段灵根仅支持先天；若有外部效果影响灵根相关判定，应记录在状态、资源、道功或其他效果记录中。
- `DerivedBars.permanent_adjustments` 不区分先天 / 后天，只表示永久派生状态调整。
- `DerivedBars` 只保存派生状态当前值、上限、保留值和状态调整；系数字段、绝对值加成字段和公式缓存由数值文档定义。
- `LifespanState.remaining_lifespan`、`age_ratio`、`aging_phase` 和 `lifespan_pressure_state` 可以作为派生缓存，但事实来源仍是 `age`、`lifespan_limit`、风险标签和数值表。

## 12. 旧字段迁移

| 旧字段 / 旧口径 | 当前处理 |
| --- | --- |
| `physique` | 迁为 `base_physique` |
| `energy` 表示精力 | 迁为 `base_vigor` |
| `energy` 表示元气或行动消耗 | 迁为 `bar_qi_current` / `bar_qi_max` / `bar_qi_reserve` |
| `comprehension` / `base_comprehension` | 迁为 `aptitude_comprehension`；不得放入 `BaseAttributes` |
| `foundation` | 迁为 `aptitude_bone` |
| `spiritual_root_tags` | 拆为 `aptitude_root` + `root_affinity_tags` / `root_affinity_profile` |
| `derived_life` | 迁为 `bar_vitality_current` / `bar_vitality_max` / `bar_vitality_reserve` |
| `derived_qi` | 迁为 `bar_qi_current` / `bar_qi_max` / `bar_qi_reserve` |

## 13. 待补规则

- 灵根标签全集与标签命名规范。
- `aptitude_root` 的评级范围和 UI 包装规则。
- `root_affinity_profile.affinity_weights` 的数值区间。
- 灵根相性表与道功路线标签表。
- 灵根相性对资源输入、节点灵气和法门使用的具体倍率 / 阈值。
- 入门检测的显示文本、误差范围和分阶段揭示方式。
- 与角色属性数值文档保持字段命名、缓存字段和 UI 展示口径同步。

## 14. 设计历史

旧口径曾把体魄、精力、悟性都列为最小基础属性，并使用 `physique`、`energy`、`comprehension`、`foundation`、`derived_*` 等字段。当前校准口径裁决为：

- 体魄 / 精力是通用基础属性。
- 根骨 / 悟性 / 灵根是修炼资质子项。
- 悟性只保留为资质子项，不再同时作为基础属性。
- 基础属性和非灵根资质明确区分先天、后天永久和临时修正；临时修正均属于后天来源，但不回写永久属性。
- MVP 阶段灵根仅支持先天结果，不支持后天永久改写或临时灵根改写。
- 灵根拆成基础评级与相性结构，不再用单一标签列表表达全部灵根。
- 生机 / 元气 / 神念统一为派生状态条，并各自预留 `reserve` 保留值；派生状态只区分永久 / 临时，不在永久项中继续区分先天 / 后天。
- 寿元从旧“角色时间预算 / 死亡倒计时”扩展为 `LifespanState`：记录年龄、寿元上限、剩余寿元、压力状态、延寿来源和风险标签。
- 旧“年龄%分段函数”迁为 `age_ratio` 与 `aging_phase_multiplier`：它只影响体魄 / 精力最终值，不影响修炼资质、灵根或神念基础值，也不回写先天、后天永久或临时修正。
- 体魄 / 精力最终值、生机 / 元气 / 神念最大值和常规公式乘区口径已下沉到 `docs/inbox/xiuxian_design_reorganized_md/03_数值设计/09_角色属性与派生状态数值设计.md`，本文不再维护具体公式。
- 角色属性作为通用数据供各系统按需读取，本文不规定修炼结算必须读取的字段清单。
- 本文为自包含校准口径，不依赖目录外文档作为解释前提。
