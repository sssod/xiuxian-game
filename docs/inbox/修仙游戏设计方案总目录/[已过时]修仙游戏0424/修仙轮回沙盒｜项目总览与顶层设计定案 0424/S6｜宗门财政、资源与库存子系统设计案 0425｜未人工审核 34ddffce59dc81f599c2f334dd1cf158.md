## 1. 子系统定位

S6 定义宗门作为组织平台时，资源是否真实存在、能否被调拨、被谁消耗、如何记录。

一句话定位：

> S6 决定宗门“有什么资源、从哪里来、被谁预留、消耗到哪里去”。
> 

## 2. MVP 五类宗门资源

MVP 宗门追踪五类抽象资源：

1. 灵石。
2. 修炼资源。
3. 材料 / 矿材。
4. 人力 / 弟子规模。
5. 声望 / 影响力。

宗门发放给玩家或 NPC 的资源必须来自真实库存。贡献不是货币，不能绕过库存检查。

## 3. 宗门库存最小结构

```
SectInventory {
  sect_id
  spirit_stone
  cultivation_resource
  material_stock
  manpower
  reputation
  reserved_resources
  income_sources
  expense_records
  stock_logs
}
```

库存可以先使用抽象数量，不要求 MVP 细分所有物品堆叠与品质。

## 4. 资源来源

MVP 资源来源：

- 控制节点的基础产出。
- 宗门行动：开采、探索、远征、建设、培养等结果。
- 玩家上交资源。
- 节点事件奖励。
- 宗门声望带来的外部供给。
- 特殊秘境或后手回收。

## 5. 资源支出

MVP 支出方向：

- 发放弟子培养资源。
- 支持玩家或 NPC 突破。
- 宗门行动消耗。
- 节点建设与修复。
- 驻守、远征、探索的人力占用。
- 应对节点危机。
- 维护宗门核心建筑。

## 6. 预留与占用

为了避免同一资源被多系统重复使用，S6 需要预留机制。

```
ResourceReservation {
  reservation_id
  sect_id
  resource_type
  amount
  reserved_for_system
  reserved_for_event
  start_quarter
  expiry_quarter
  status              // active / consumed / released / failed
}
```

示例：玩家申请突破支持后，宗门同意预留一批修炼资源；若突破开始则消耗，若事件取消则释放或部分损耗。

## 7. 声望 / 影响力的资源口径

声望 / 影响力既是资源，也是外部评价。

MVP 中可以作为抽象数值用于：

- 提高宗门行动采纳与外部响应。
- 影响节点控制竞争。
- 影响招收弟子与资源供给。
- 承担失败事件后的损失。

声望不应像货币一样任意兑换物品。它更接近行动修正和世界态势参数。

## 8. 人力资源口径

人力 / 弟子规模在 MVP 先抽象处理，不做单个 NPC 深度模拟。

人力用途：

- 开采。
- 驻守。
- 探索。
- 远征。
- 建设。
- 培养。
- 护法支持。

人力可以被占用、受损、疲惫或恢复。具体数值进入 S7 与平衡文档。

## 9. 宗门库存可见性

玩家可见范围由 S5 权限决定。

建议分级：

- 弟子：只看到与自己申请、俸禄、任务相关的局部库存。
- 真传 / 执事：看到部分资源余量和紧缺提示。
- 长老：看到更完整的库存、预留、收入和支出趋势。

调试模式可查看完整库存日志。

## 10. 日志规则

每次库存变化必须写入来源和去向：

```
SectStockLog {
  quarter
  resource_type
  delta
  reason
  source_system
  actor
  related_node
  related_event
  visibility
}
```

玩家可见日志只展示其权限范围内的信息；完整世界日志用于测试与回放。

## 11. 与其他系统的接口

- S5：校验玩家是否有资格申请或调拨资源。
- S7：为宗门行动提供资源消耗与执行预算。
- S4：提供突破资源、场地维护、人力护法支持。
- S8：读取节点产出与控制权。
- S9：当资源需要细化为具体物品时交给物品系统。
- S10：节点事件可造成库存变化。
- S13：资源名额竞争读取库存和预留状态。
- S14：持久化库存、预留与日志。

## 12. MVP 验收标准

1. 宗门有五类资源库存。
2. 宗门行动消耗与产出真实改写库存。
3. 玩家申请突破支持会检查库存并生成预留。
4. 资源不足时，宗门行动或突破支持会失败、降级或延迟。
5. 库存变化可被日志追踪。
