# 08_事件突破战斗时间规则_v2.3

# 事件、突破与战斗时间规则（v2.3）

## 1. 事件时间分类

MVP 事件按时间处理分为：

| 类型 | 时间处理 | 示例 |
| --- | --- | --- |
| 信息事件 | 不打断，进入日志 / 传闻 | 坊市价格、宗门传闻、节点局势 |
| 普通个人选择事件 | 本人局部时停，外部 N1，gap≤1日，结束后 C1 | 同门邀约、个人机缘、资源反馈、小境界选择 |
| 轻遭遇 | 按普通个人选择事件 | 低阶妖兽、小型陷阱、外门挑衅 |
| 正式交锋 | 世界 B1，按交锋轮结算 | 强敌斗法、玩家直接冲突、秘境关键战斗 |
| 突破挑战 | 世界 B1，按交锋轮结算 | 筑基挑战、结丹挑战 |
| 全局公共事件 | 世界 P0 | 宗门大会、全员决策、世界级灾变 |

事件模板必须提供：

```
event_time_mode
safe_default_option_ref
p0_required_if_timeout
visibility_policy
result_package_template
```

---

## 2. 普通个人选择事件

规则：

```
事件玩家本人局部时停；
其他玩家、宗门、世界继续 N1；
gap 最多 1 游戏日；
事件结束后 C1 追赶补结算；
其他玩家不看到事件归因。
```

事件选项可有游戏内时间成本，该时间从事件触发 `world_hour` 开始回填。

示例：

```
事件触发：第 12 日午时
世界当前：第 12 日酉时
gap = 6 小时
玩家选择：调息稳定，耗时 6 小时
结果：调息时间覆盖 gap，C1 后同步到世界当前时间。
```

---

## 3. gap 上限与安全默认

```
gap = 世界当前时间 - 玩家局部冻结时间
gap 最大 1 游戏日
```

到达 1 日：

```
有安全默认选项 → 自动执行默认选项；
无安全默认选项 → P0 同步保护。
```

安全默认例子：

```
同门邀约：默认婉拒
坊市机会：默认错过
普通资源反馈：默认接受保守方案
轻度机缘：默认不冒险
突破前道具确认：默认取消突破，进入休整
```

P0 同步保护例子：

```
死亡边缘
不可逆功法路线选择
重大夺舍 / 心魔交易
无法默认处理的多人冲突
严重资源损毁选择
```

---

## 4. C1 追赶补结算

C1 只结算确定性内容：

```
行动进度；
修炼收益；
资源消耗；
药性衰减；
伤势恢复；
队列切换；
已知状态变化；
事件选择带来的明确后果。
```

C1 不触发：

```
随机个人事件；
普通机缘；
普通战斗；
软机会事件；
普通心魔；
普通资源反馈。
```

---

## 5. 自动处理范围

信息事件不打断，进入日志 / 传闻。

普通个人选择事件保留玩家处理权。

闭关预案和显式托管行动可以覆盖低价值事件。自动兜底只用于防止角色行动空档，不承担事件处理预案。

## 6. 战斗分级

### 6.1 轻遭遇

轻遭遇是一次性个人事件，例如：

```
采药时遇到低阶妖兽
路上被外门弟子挑衅
小型陷阱
低风险野兽惊扰
```

处理：

```
事件玩家局部时停；
其他世界 N1；
gap 最多 1 游戏日；
选择后 C1 追赶。
```

### 6.2 正式交锋

正式交锋包括：

```
秘境关键战斗
强敌斗法
玩家直接交锋
多人组队战斗
宗门任务战斗
可能导致重伤 / 死亡 / 重大资源损失的战斗
突破挑战
```

处理：

```
世界进入 B1；
按交锋轮结算；
非参战玩家也按 B1 世界时间推进。
```

---

## 7. B1 交锋轮

```
B1 = 60 秒现实时间 = 1 游戏小时
1 交锋轮 = 1 游戏小时
```

每轮流程：

```
1. 展示当前交锋态势；
2. 参战者选择本轮策略；
3. 60 秒倒计时；
4. 未提交者执行预设策略；
5. 系统结算本轮；
6. 交锋时间推进 1 游戏小时；
7. 世界时间同步推进 1 游戏小时。
```

玩家可以提前提交，并可在倒计时结束前修改。

---

## 8. 交锋默认策略

每名参战者必须有默认交锋预设：

```
保命优先
稳健防守
节省灵力
优先击杀
保护队友
尝试撤退
维持突破
优先稳定道基
强冲成功率
```

若 60 秒内未提交，执行当前预设策略。

---

## 9. 交锋上限

建议：

```
普通正式交锋：3～8 轮
复杂正式交锋：最多 12 轮
硬上限：24 轮
```

达到硬上限仍未结束，强制进入模板结局：

```
撤退
僵持
重伤脱离
资源耗尽
突破失败
突破成功但有代价
进入长期对峙状态
```

---

## 10. 大境界突破结构

大境界突破分为：

```
准备期
→ 开启突破短指令
→ 突破挑战 B1 正式交锋
→ 结果结算个人报告
→ 后续选择按普通个人事件处理
```

---

## 11. 准备期

准备期是普通长期低交互行动，可进入 F1：

```
闭关积蓄灵力；
温养经脉；
炼化基础药性；
布置基础环境；
等待状态满足；
准备关键突破物；
选择突破地点；
寻求护法；
争取宗门支持。
```

---

## 12. 开启突破指令

开启突破是短指令：

```
选择少量突破专用道具；
确认是否开启突破；
确认当前主修功法对应突破模板；
可选择突破挑战默认策略。
```

规则：

```
若作为普通队列预输入，必须当前已满足条件；
若临时弹出确认，按个人局部时停处理；
默认选项：取消突破，进入休整；
未提交前不消耗突破专用道具。
```

开启突破入队只表示当前条件已经合法后的队列安排；突破挑战轮内策略由 B1 默认策略和本轮选择处理。

---

## 13. 突破挑战

突破挑战是正式交锋：

```
世界进入 B1；
1 轮 = 1 游戏小时；
每轮 60 秒现实窗口；
突破者每轮选择策略；
未选择则执行突破预设；
真实资源消耗发生在交锋轮中；
突破挑战游戏时间消耗 = 交锋轮数 × 1 游戏小时。
```

示例轮：

```
第 1 轮：稳住灵台，是否消耗护心符
第 2 轮：灵力冲关，是否服用破境丹
第 3 轮：道基震荡，是否消耗轮回后手
第 4 轮：心魔诱导，是否舍弃部分根基换成功率
第 5 轮：境界成形，是否追求高品质突破
```

---

## 14. 突破挑战默认策略

必须支持：

```
保命优先
稳健突破
节省珍贵道具
优先成功率
追求高品质
接受根基损伤换突破
失败即中止
```

若玩家某轮没有提交，执行当前突破预设。

---

## 15. 突破结果结算

突破挑战结束后，以个人报告、宗门传闻、世界日志呈现。

个人报告包括：

```
突破成功 / 失败；
境界品质；
根基变化；
伤势；
寿元变化；
道具消耗；
主修功法影响；
失败原因标签；
下一次修正方向；
轮回账本记录。
```

后续选择示例：

```
巩固境界；
疗伤；
隐瞒突破；
公开报备；
请求宗门护法。
```

这些选择按普通个人事件处理。

## 16. 事件结果字段

`consumed_hours` 含义：

| 场景 | 含义 |
| --- | --- |
| 普通个人事件 | 选项的游戏内时间成本，从事件触发 world_hour 回填 |
| C1 追赶 | 补结算覆盖的确定性小时数 |
| B1 交锋 | 交锋轮数 × 1 游戏小时 |
| 突破挑战 | 突破交锋轮数 × 1 游戏小时 |
| 信息事件 | 通常为 0 |

```
EventOutcome {
  event_id: String
  event_time_mode: info | local_time_stop | light_encounter | formal_encounter_b1 | breakthrough_b1 | global_pause_p0
  trigger_world_day: int
  trigger_world_hour: int
  frozen_character_world_hour: int | null
  consumed_hours: int
  catchup_required: bool
  default_resolution_used: bool
  speed_transition_refs: Array
  result_package_refs: Array
}
```
