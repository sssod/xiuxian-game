# 个人行动队列与指令预输入（替换稿 v0.1）

> 替换范围：v2.2 `02_核心系统规格/03_个人行动经济_移动通行_托管_v2.2.md` 中的行动规划、指令队列、跨回合、托管、无后续队列兜底、突破作为固定行动等口径。  
> 保留范围：移动行动、固定 / 可选投入行动、行动资源输入、残余效果、资产容器校验等不冲突规则。

---

## 1. 一句话定义

个人行动不再是“填满一个 5 日回合预算条”，而是：

> 玩家给当前角色提交普通行动指令；系统保持一个短队列：当前执行指令 + 最多 3 条预输入指令。队列只保存当前已经合法的普通指令，不是条件脚本或自动化计划器。

---

## 2. 队列结构

MVP 阶段采用：

```text
当前执行指令 + 最多 3 条预输入指令
```

示例：

```text
当前：闭关修炼《青木引气诀》10 日
后续 1：调息 2 日
后续 2：开启筑基突破
后续 3：吐纳 3 日
```

队列中的每条指令均需：

```text
入队时合法性校验
+ 执行前再次合法性校验
```

---

## 3. 与 v2.2 行动经济的关系

保留 v2.2：

```text
行动可以消耗小时或天；
移动读取节点图、有向边权、权限门和风险门；
炼丹、炼器、仪式、治疗等可为固定执行时间行动；
修炼、吐纳、研习、探索、休整等可为可选投入执行时间行动；
丹药、灵材、符箓仍作为行动资源输入绑定具体行动；
行动资源输入必须通过资产容器、位置、权限、行动标签和叠加限制校验。
```

修订 v2.2：

```text
不再把行动映射到固定 5 日回合预算条；
不再要求下一回合继续原路线作为回合边界语义；
不再用 auto_continue 推导未来脚本；
不再让队列预测前序产出满足后序消耗；
不再将大境界突破作为普通固定工期行动。
```

## 4. 可预输入的指令类型

可入队：

```text
闭关修炼
吐纳
休整
养伤
炼丹
炼器
赶路
拜访指定 NPC
申请指定宗门资源
进入指定地图节点
开启当前已满足条件的大境界突破
执行当前已满足条件的小境界突破
显式托管行动
```

不可入队或不建议入队：

```text
未知事件的选项选择
未满足条件的突破
未拥有道具的消耗行为
需要新情报判断的宗门站队
多人直接冲突选择
正式交锋中的轮内策略选择
突破挑战中的轮内选择
临时触发的机缘事件
临时触发的心魔 / 风险抉择
```

---

## 5. 入队合法性

玩家只能预输入当前已经满足条件的普通指令。

合法性包括：

```text
当前状态允许；
当前地点允许；
当前资源足够；
当前风险没有阻止；
当前事件状态不冲突；
当前境界 / 功法 / 关系条件满足；
主修功法对应模板可用；
资源输入项可从资产容器合法取得。
```

禁止：

```text
先闭关到灵力 90%，再自动突破；
先炼出筑基丹，再自动突破；
先完成任务拿到护心符，再自动突破；
等满足条件后自动执行某指令；
如果前序失败则自动改用替代方案；
跨指令资源锁定和未来产出承诺。
```

---

## 6. 队列不做未来推导

队列不做：

```text
资源锁定；
未来产出承诺；
队列内资源占用推导；
条件 if-else 链；
跨指令依赖图；
甘特图计划；
通用事件预案策略表。
```

示例：

```text
指令 1：炼制筑基丹
指令 2：开启筑基突破并使用筑基丹
```

如果玩家当前没有筑基丹，指令 2 不能因为指令 1 可能产出筑基丹而提前合法。

---

## 7. 执行前再次校验

每条预输入指令从队列头进入执行前，必须重新校验。

通过：

```text
开始执行该指令。
```

失败：

```text
1. 跳过该指令；
2. 记录个人日志；
3. 进入自动兜底；
4. 世界降至 N1；
5. 等待玩家输入新指令。
```

失败不全局广播。

## 8. 行动完成后的处理

```pseudo
on_action_complete(player):
    next_command = pop_next_command(player)

    if next_command.exists:
        result = validate(next_command)
        if result.passed:
            start(next_command)
            return
        else:
            log_personal_failure(result)
            start_auto_fallback(player)
            force_speed(N1)
            return

    log_queue_empty(player)
    start_auto_fallback(player)
    force_speed(N1)
```

行动完成后如果下一条指令合法，且全员仍处于长期低交互行动，F1 可以继续。

行动完成后如果进入自动兜底，必须降至 N1。

## 9. 自动兜底规则

触发条件：

```text
当前指令完成后队列为空；
下一条指令执行前校验失败；
下一条指令地点不合法；
下一条指令资源不足；
下一条指令被当前风险状态阻止；
玩家未输入任何后续指令。
```

风险选择：

| 当前节点风险 | 自动兜底 |
|---|---|
| 低风险 / 宗门 / 城镇 / 安全洞府 / 已控制灵地 | 吐纳 |
| 中风险 / 高风险 / 秘境 / 敌对边境 / 未控制节点 / 战斗后区域 | 休整 |
| 风险等级不明 | 按中高风险处理，休整 |

自动兜底特点：

```text
低收益或极低收益；
不消耗关键资源；
不主动探索；
不主动触发高价值事件；
可随时被玩家新指令替换；
强制世界降至 N1；
不具备 F1 资格。
```

---

## 10. 自动兜底、显式托管、超时安全默认的区别

| 类型 | 来源 | 是否等待玩家补指令 | 是否可参与 F1 | 主要用途 |
|---|---|---:|---:|---|
| 自动吐纳 / 自动休整 | 队列空或校验失败 | 是 | 否 | 防止角色冻结 |
| 显式托管行动 | 玩家主动输入 | 否 | 满足条件时可 | 低关注、低收益、安全运行 |
| 超时安全默认 | 局部事件 / B1 / P0 超时或房间规则 | 视事件而定 | 否，除非转成合法显式托管 | 防止多人时间卡死 |

显式托管必须记录：

```text
managed_mode: explicit
managed_duration_hours
low_risk_action: meditate
mid_high_risk_action: rest
safe_event_policy
major_event_interrupt_policy
```

超时安全默认必须记录：

```text
default_reason: local_gap_limit | b1_round_timeout | global_pause_timeout | room_timeout
selected_safe_option
why_safe
whether_player_can_later_review
```

## 11. 显式托管行动

显式托管是玩家主动声明短期低关注，不是普通兜底。

用途：

```text
玩家暂时不想频繁处理小事件；
玩家希望角色维持安全低收益状态；
多人中某玩家短时间低关注；
长期服务器中玩家离线前安排角色状态。
```

默认行为：

```text
低风险节点 → 托管吐纳
中高风险节点 → 托管休整
```

可自动处理低价值事件：

```text
普通邀约：婉拒；
普通传闻：记录；
低价值机会：忽略；
轻微状态波动：保守处理；
普通资源波动：不冒险。
```

不可吞掉重大事件：

```text
死亡风险；
正式交锋；
重大心魔；
重大机缘；
不可逆选择；
大境界突破挑战；
多人直接冲突；
宗门重大事件。
```

## 12. 闭关预案

闭关支持有限预案，只处理闭关内部小波动：

```text
药性轻微波动；
经脉轻微负荷；
灵力流速轻微异常；
短暂杂念；
轻度疲劳。
```

三档：

| 档位 | 行为 |
|---|---|
| 稳妥闭关 | 小波动自动调息；风险升高即中断闭关转休整 |
| 标准闭关 | 小波动自动压制；中等风险提示玩家 |
| 冒险闭关 | 小波动继续闭关；接近严重风险才提示玩家 |

默认：

```text
标准闭关
```

闭关预案不处理：

```text
心魔正式出现；
突破条件达成；
严重走火入魔风险；
同门重要求援；
宗门重大召集；
特殊机缘；
敌袭；
不可逆功法分歧；
重大资源损失；
正式交锋；
突破挑战。
```

## 13. 大境界突破与预输入

大境界突破可以作为普通指令入队，但必须当前已经满足条件。

入队前必须满足：

```text
达到突破条件；
拥有开启阶段需要选择的突破专用道具；
当前地点允许突破；
当前状态允许突破；
主修功法突破模板可用。
```

预输入只保存：

```text
开启突破；
选择少量突破专用道具；
确认当前主修功法对应突破模板；
必要时选择突破挑战默认预设。
```

不保存：

```text
未来何时满足条件；
未来用哪个前序行动产出的道具；
突破挑战每轮如何选择；
复杂失败分支；
成功后多层自动行动树。
```

执行前再次校验：

```text
仍合法 → 进入突破挑战，世界 B1；
不合法 → 跳过突破指令，不消耗突破道具，记录个人日志，进入自动兜底，世界 N1。
```

## 14. 指令字段修订

替换 v2.2 `PersonalActionInstruction` 的回合字段：

```yaml
Command {
  command_id: string
  command_type: cultivate | meditate | rest | heal | craft | travel | visit | apply_resource | breakthrough_open | minor_breakthrough | managed
  subject: player_id
  character_id: string
  target: string | null
  duration_hours: number | null
  selected_items: list
  resource_inputs: list
  location_requirement: string | null
  created_world_day: int
  created_world_hour: int
  created_speed_context: string
  status: queued | running | completed | skipped | failed
  source: explicit_player | timeout_managed | system_fallback
}
```

执行前校验结果：

```yaml
validation:
  passed: boolean
  failed_reason: string | null
  checked_world_day: int
  checked_world_hour: int
```

失败后：

```yaml
fallback:
  action: meditate | rest
  reason: queue_empty | validation_failed | invalid_location | insufficient_resource | blocked_by_state
  node_risk: low | medium | high | unknown
  force_speed: N1
  f1_eligible: false
```

闭关字段：

```yaml
seclusion_policy: safe | standard | risky
```

显式托管字段：

```yaml
managed_mode:
  source: explicit_player
  duration_hours: number | null
  low_risk_action: meditate
  mid_high_risk_action: rest
  low_value_event_policy: conservative
  major_event_policy: notify_or_speed_shift
```

## 15. 与行动资源输入的兼容

行动资源输入仍按 v2.2 规则执行，但同步修正：

```text
1. 入队时只校验当前是否拥有和可使用资源；
2. 队列不锁定未来资源；
3. 行动真正开始前再次校验资源；
4. 行动开始后才消耗资源输入；
5. 未用完资源效果生成 ActiveResourceEffect；
6. 局部时停期间该玩家资源变化暂停；
7. C1 追赶时只补结算确定性资源效果，不触发新的随机资源事件。
```

## 16. UI 提示文本

入队校验：

```text
可入队：当前已满足筑基突破条件。
不可入队：当前未拥有筑基丹。
不可入队：当前地点不允许突破。
不可入队：当前灵力储备不足。
```

执行失败：

```text
预输入指令未执行：开启筑基突破。
原因：缺少筑基丹。
已自动转入：吐纳。
世界进入常态推进，等待你输入新指令。
```

队列为空：

```text
队列已空。
当前处于低风险节点，已自动转入吐纳。
世界进入常态推进，等待你输入新指令。
```
