## 1. 子系统定位

S2 定义玩家到底在控制什么，以及每一世如何生成、成长、死亡和转世。

一句话定位：

> S2 负责把“跨世真灵”与“当世角色”拆成可运行的数据结构，并决定哪些东西本世存在、哪些东西跨世保留、哪些东西进入轮回账本。
> 

## 2. 三层角色结构

玩家主体分为三层：

```
真灵：跨世延续的玩家主体
执念：转世初始化时可携带的少量遗留包
身躯与灵魂：当前世实际行动、成长、承受后果的角色实例
```

核心边界：

- 真灵提供长期身份感和跨世容量。
- 执念只服务下一世初始化，不等于完整记忆或人格继承。
- 身躯与灵魂承载本世修为、属性、关系、宗门身份、战斗损耗和死亡风险。

## 3. 真灵最小数据

```
TrueSpirit {
  spirit_id
  true_name
  spirit_strength
  true_name_visibility     // hidden / declared / exposed
  incarnation_count
  highest_stage_reached
  dao_rhyme_tags
  obsession_capacity
  formal_contingency_slots
  reincarnation_ledger_refs
}
```

规则口径：

1. 真名对玩家自己始终可见，对世界默认隐藏。
2. 真灵强度主要提高执念容量和正式后手容量，不直接叠加修炼效率。
3. 道韵是顶级长期追求，只对匹配技能标签产生加成，不作为每世稳定刷取项。
4. 轮回履历记录重大突破、失败、死亡、后手和最高境界，不等于完整前世记忆回放。

当世角色保存本世实际发生的一切，但默认不跨世继承。死亡或转世后，本世角色进入履历与遗产结算。

## 5. 基础属性与派生状态最小口径

MVP 数据层保留完整属性接口，但新手阶段 UI 只显式暴露少量字段。

最小基础属性：

- 体魄：影响生机、负伤承受、肉身类突破准备。
- 精力：影响元气、持续行动承受、疲劳与恢复。
- 悟性：影响功法学习、理解、修炼效率。

最小派生状态：

- 生机：健康、伤病、濒死与肉身完整度。
- 元气：气力 / 法力 / 可支配能量。
- 神念：灵魂、神识、心神稳定。M0 可在 UI 中隐藏或弱化，数据层保留。

战斗系统读取生机 / 元气 / 神念；S4 读取修为、纯度、肉身承载、心境、因果、寿元压力等突破输入。

## 6. 修为阶段与里程碑

系统实现使用抽象阶段编码，不绑定修仙包装。

```
A-1, A-2, A-3
B-1, B-2, B-3
C-1, C-2, C-3
```

规则判断读取解析字段：

```
major_code
minor_index
major_order
absolute_order
```

MVP 里程碑：

- M0：开局与入门。
- M1：第一阶段修行闭环完成，进入关键突破准备。
- M2：第二大境界。
- M3：第三大境界起点，允许进入长老序列或等价高层决策体验。

## 7. 出生与初始生成

初次入世最小流程：

```
创建真灵
→ 生成第一世身躯与灵魂
→ 生成出生地点、年龄、家庭背景、初始社会身份
→ 生成天赋标签与资质
→ 写入角色自知信息与初始日志
→ 进入 S1 房间季度流程
```

约束：

- 资质在出生 / 身躯生成时已经生成，入门事件只负责检测、揭示和评级。
- 初次入世应保持低认知、低资源、低控制力。
- 出生背景可影响初始资源、身份、家族关系、宗门关系和区域声望，但不应直接替代后续修炼成长。

## 8. 执念与转世初始化

执念是转世时用于选择初始化遗留的容量系统。

### 8.1 已确定决策：采用权重制

**人工决策：执念容量采用权重制。**

规则口径：

- 真灵强度提供 `obsession_capacity`，表示本次转世可承载的执念容量上限。
- 每个可携带遗留配置 `obsession_weight`，不同天赋标签和出生背景的权重可以不同。
- 玩家选择的遗留总权重不得超过当前执念容量。
- 权重不是可自由分配的属性点，不允许玩家把容量拆成根骨 +1、悟性 +1 这类细碎购买。
- 遗留仍然以离散选项存在，例如某个天赋标签、某类出生背景或某个已解锁初始化遗留。
- 权重由解锁难度、效果强度、稀有度、路线适配度和对开局效率的影响共同决定。
- UI 表达应倾向于“已承载 / 可承载”，避免表现成传统 RPG 点数配点。

示例表达：

```
当前执念容量：8
已选择遗留：5 / 8

早慧：2
根骨稍佳：3
宗门杂役亲族：4
没落修行家族：6
```

MVP 优先支持两类执念遗留：

1. 天赋标签：影响下一世一般属性、特殊属性随机池或路线适配。
2. 出生背景：影响初始资源、初始身份、家族关系、宗门关系、区域声望。

无成本基础选项：

- 转世年龄。
- 已知转世地域。
- 已知附近宗门。

这些无成本选项限制在玩家已知信息范围内，但不要求前世亲身抵达过。

## 9. 死亡与转世触发

MVP 支持以下触发：

1. 寿元耗尽。
2. 突破失败导致身死。
3. 战斗或重大事件导致死亡。
4. 玩家主动计划转世。

死亡 / 转世流程：

```
本世结束条件成立
→ 结算身躯与灵魂
→ 写入死亡原因、最高境界、关键关系、失败标签
→ 结算普通前世遗产与正式后手状态
→ 更新真灵强度、执念容量与轮回履历
→ 选择下一世执念遗留与基础选项
→ 生成新身躯与新灵魂
```

## 10. 内在继承与外在继承

内在继承绑定真灵：

- 真灵强度。
- 轮回履历。
- 前世数量。
- 重大突破经验。
- 失败原因标签。
- 道韵。
- 后手感应。

外在继承存在于世界：

- 洞府。
- 藏宝地点。
- 功法玉简。
- 丹药与灵石。
- 法器。
- 接引阵。
- 遗书与任务链。
- 宗门密库权限。
- 护道人或弟子安排。

外在继承不会无条件安全保留；只有正式后手享受更强追踪、日志和原因链保障。

## 11. 轮回账本

轮回账本是玩家跨世信息的可信入口。

最小条目类型：

- 本世摘要。
- 最高阶段。
- 重大突破结果。
- 失败原因标签。
- 死亡原因。
- 正式后手记录。
- 普通遗产线索。
- 前世经验提示。
- 真名暴露记录。

账本只展示玩家可知或可感应的信息，不直接暴露完整世界日志。

## 12. 与其他系统的接口

- S1：读取玩家当前可操作角色、死亡 / 转世状态。
- S3：读取角色位置、状态、行动能力和持续状态。
- S4：读取突破准备维度，写入突破结果、失败标签与轮回账本。
- 战斗系统：读取并回写生机 / 元气 / 神念、伤势、死亡状态。
- S5：读取宗门身份、职位、权限和关系。
- S8：读取出生地点、当前位置、已知区域。
- S9：读取背包、随身物品、资源和法宝状态。
- S11：读取正式后手容量、感应和前世遗产状态。
- S14：持久化真灵、当世角色、账本和转世链。

## 13. MVP 验收标准

S2 最小可验收闭环：

1. 创建真灵并生成第一世角色。
2. 第一世角色拥有可显示的基础属性、派生状态、年龄、位置、身份和日志。
3. 角色可从 M0 推进到至少 M1，并进入突破准备。
4. 一次死亡或主动转世能生成轮回账本条目。
5. 下一世能基于执念容量选择至少一种天赋标签或出生背景遗留。
6. 正式后手容量和普通遗产边界在数据层可区分。
