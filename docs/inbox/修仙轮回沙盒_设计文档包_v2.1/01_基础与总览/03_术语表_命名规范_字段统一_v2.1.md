# 术语表、命名规范与字段统一（v2.1）

## 0. 文档定位

本文是新版开发实现的命名标准。若旧文档中的字段、术语或包装名与本文冲突，开发阶段以本文为准。

原则：

1. 规则层使用抽象、可扩展、可本地化的命名。
2. UI 层可以使用修仙包装名。
3. 数据层不直接写死世界观名。
4. 同一概念只保留一个规则字段名。
5. 旧版 `quarter / action_slot / tick` 的混用必须拆语义。

## 1. 时间与回合术语

### 1.1 新版基础时间层级

| 中文术语 | 规则含义 | 推荐字段 |
|---|---|---|
| 回合 | 玩家最小同步推进单位；由决策阶段与结算阶段组成 | `turn_id` |
| 回合配置 | 控制每回合游戏天数、倒计时、内部 tick 单位 | `TurnConfig` |
| 游戏天 | UI 时间预算条显示单位 | `world_day` / `turn_day_index` |
| 游戏小时 | 服务端内部结算单位 | `world_hour` / `hour_tick` |
| 当前回合开始日 | 回合起点对应的世界绝对日 | `turn_start_world_day` |
| 当前回合结束小时 | 回合终点对应的世界绝对小时 | `turn_end_world_hour` |
| 宏观周期 | 世界刷新、资源再生、宗门战略等非玩家最小回合的周期 | `macro_period_id` |

推荐配置：

```text
TurnConfig {
  turn_duration_days: int,              # 默认 5，但可配置
  decision_countdown_seconds: int,      # 默认 120
  internal_tick_unit: String,           # hour
  visible_time_unit: String             # day
}
```

### 1.2 旧术语处理

| 旧术语 / 字段 | 新处理 |
|---|---|
| `quarter` | 若表示玩家最小回合，改为 `turn_id`；若表示世界季节级刷新，改为 `macro_period_id` 或 `season_id` |
| `current_quarter` | 改为 `current_turn_id`，另保留 `current_macro_period_id` 表达世界周期 |
| `action_slot` | 废弃；改为 `planned_duration_hours`、`planned_duration_days` 或 UI 的 `time_budget_day_segment` |
| `remaining_action_slots` | 改为 `remaining_hours` 或 `remaining_time_budget_hours` |
| `tick` | 改为 `hour_tick` / `world_hour`；不再隐含 15 天或行动格 |
| `created_quarter` | 改为 `created_turn_id`，必要时补 `created_world_day` |
| `start_quarter` / `expiry_quarter` | 改为 `start_turn_id` / `expiry_turn_id`，或使用 `start_world_day` / `expiry_world_day` |
| `base_cost_slots` | 改为 `base_travel_hours` 或 `base_travel_duration` |
| `QuarterReplay` | 改为 `TurnReplay` |

### 1.3 UI 时间条术语

| 中文术语 | 含义 | 推荐字段 / 组件 |
|---|---|---|
| 回合时间预算条 | 底部以天为刻度的时间预算 UI | `TurnTimeBudgetBar` |
| 行动指令规划器 | 将线性指令映射到天级预算条的 UI | `ActionInstructionPlanner` |
| 原计划 vs 实际结果 | 回合结束报告核心组件 | `OriginalVsActualSummary` |

不再使用：

```text
6 个朔望行动格规划器
季度时间条
季度行动规划工作台
```

新版使用：

```text
回合时间预算条
大世界地图驱动的回合行动工作台
```

## 2. 行动术语

### 2.1 个人行动三类

| 中文术语 | 规则含义 | 推荐字段 |
|---|---|---|
| 个人即时行动 | 决策阶段时间暂停时执行，不占用回合时间预算 | `action_type = instant` |
| 移动行动 | 时间消耗型指令，改变位置或路线状态 | `action_type = movement` |
| 个人持续行动 | 占用时间预算，推动进度、收益、状态或事件 | `action_type = continuous` |

### 2.2 持续行动执行时间类型

| 中文术语 | 规则含义 | 推荐字段 |
|---|---|---|
| 固定执行时间 | 必须投入完整时长才有完整结果 | `duration_mode = fixed` |
| 可选投入执行时间 | 投入多少时间就按实际投入结算 | `duration_mode = variable_investment` |
| 移动耗时 | 由路线、距离、移动方式和事件共同决定 | `duration_mode = movement` |
| 即时 | 不推进游戏时间 | `duration_mode = instant` |

推荐字段：

```text
PersonalActionInstruction {
  instruction_id: String,
  actor_ref: String,
  action_type: String,
  action_template_id: String,
  target_node_id: String,
  target_ref: String,

  duration_mode: String,
  planned_duration_days: float,
  planned_duration_hours: int,
  use_remaining_time: bool,

  fixed_required_hours: int,
  min_effective_hours: int,

  route_params: Dictionary,
  resource_budget: Dictionary,
  start_condition: Dictionary,
  stop_condition: Dictionary,

  failure_policy: String,
  interrupt_policy: String,
  overflow_policy: String,
  auto_continue: bool,

  created_turn_id: int,
  submitted_by_player_id: String
}
```

### 2.3 策略字段枚举建议

```text
failure_policy:
- skip_and_continue
- cancel_following_plan
- fallback_to_rest
- fallback_to_guard
- wait_for_player_next_turn

interrupt_policy:
- pause
- fail
- partial_settle
- delay
- convert_to_event_chain

overflow_policy:
- carry_to_next_turn
- settle_partial_at_turn_end
- cancel_if_not_started
- fallback_to_rest_at_current_location
- wait_for_player_next_turn
```

## 3. 境界、阶级、里程碑

### 3.1 境界阶段 Stage

规则层统一使用：

```text
A-1, A-2, A-3
B-1, B-2, B-3
C-1, C-2, C-3
```

推荐字段：

```text
CultivationStage {
  code: String,          # "B-2"
  major_code: String,    # "B"
  minor_index: int,      # 2
  major_order: int,      # 2
  absolute_order: int,   # 202
  display_name_key: String
}
```

禁止：

```text
用 lianqi / zhuji / jindan 做规则判断
用中文境界名做数据库主键
用字符串排序判断阶段高低
```

### 3.2 MVP 里程碑 Milestone

M0–M3 是体验里程碑，不等于境界编码。

| 里程碑 | 含义 | 常见阶段映射 |
|---|---|---|
| M0 | 开局与入门 | 凡人 / A-0 前后 |
| M1 | 第一阶段修行闭环，准备第一次大突破 | A 阶圆满 |
| M2 | 第二大境界起点 | B-1 |
| M3 | 第三大境界起点 | C-1 |

### 3.3 Tier 与 Quality

物品、功法、资质子项、建筑、资源槽等可评级对象统一采用：

```text
tier_code: A / B / C / ...
tier_order: 1 / 2 / 3 / ...
```

品级统一 5 档：

```text
Q1：下品
Q2：中品
Q3：上品
Q4：极品
Q5：绝品
```

## 4. 角色属性命名

| 中文显示 | 规则含义 | 推荐内部字段 |
|---|---|---|
| 体魄 | 基础属性，影响肉身承载与生机 | `base_physique` |
| 精力 | 基础属性，影响气力底子与恢复承受 | `base_vigor` |
| 根骨 | 资质子项，影响承载、修炼基础、突破准备 | `aptitude_bone` |
| 悟性 | 资质子项，影响理解、学习、参悟和技艺成长 | `aptitude_comprehension` |
| 灵根 | 资质子项，影响灵气亲和与功法适配 | `aptitude_root` |
| 生机 | 持久状态条，生命 / 健康 | `bar_vitality` |
| 元气 | 持久状态条，法力 / 气力 / 可支配能量 | `bar_qi` |
| 神念 | 持久状态条，心神 / 神识 / 灵魂稳定 | `bar_mind` |

冲突决议：

- 不再用 `energy` 同时表示“精力”和“元气”。
- 不再使用 `base_comprehension`；“悟性”统一归入资质子项并使用 `aptitude_comprehension`。
- 战斗指令消耗应读取 `bar_qi`，不是 `base_vigor`。

## 5. 功法、道功、法门

| 中文术语 | 含义 | 推荐字段 / 类型 |
|---|---|---|
| 功法 | 泛称，不建议作为精确规则类型 | `MethodBase` |
| 道功 | 可推动修为增长，可设为主修 | `DaoMethod` |
| 法门 | 不直接推动修为，提供技能 / 技艺 / 事件能力 | `TechniqueMethod` |
| 主修道功 | 当前大境界修炼路线核心 | `main_dao_method_ref` |
| 术法 / 神通 | 可生成战斗或事件指令的能力 | `SkillCommandSource` |

## 6. 宗门术语

### 6.1 新版宗门行动术语

| 旧术语 | 新术语 / 处理 |
|---|---|
| 宗门主行动 | 废弃旧语义；改为 `宗门持续行动` |
| 每季度一个宗门主行动 | 改为每宗门同一时间最多 1 个 `SectContinuousActionState` |
| 宗门行动建议 / 提议 / 决策意图 | 暂时移除，不进入 MVP 输入流程 |
| 宗门经营命令 | 暂时移除，不作为即时行动 |
| 宗门反馈等待阶段 | 移除 |
| 玩家亲自介入宗门行动 | 仍保留，但作为个人持续行动或事件选择，不是宗门输入阶段 |

### 6.2 宗门状态字段

推荐：

```text
SectState {
  sect_id: String,
  display_name_key: String,
  sect_archetype: String,
  home_node_id: String,
  identity_rules_ref: String,
  permission_profiles: Dictionary,
  member_records: Dictionary,
  resource_stock: SectResourceStock,
  active_continuous_action: SectContinuousActionState,
  strategic_tendency: Dictionary,
  ai_memory_tags: Array,
  diplomacy_tags: Array,
  world_log_refs: Array
}
```

不再使用：

```text
current_main_action
SectDecisionIntent
SectActionPlan  # 若表示玩家提交的主行动计划则废弃
```

若仍需表达宗门 AI 的当前项目，统一使用：

```text
SectContinuousActionState
```

## 7. 声望、影响力、贡献

| 中文显示 | 规则含义 | 推荐字段 |
|---|---|---|
| 宗门声望 | 宗门整体外部评价 / 组织资源 | `sect_reputation` |
| 门内声望 | 玩家在宗门内部的可靠性 / 影响评价 | `member_reputation` |
| 节点影响力 | 某势力在节点上的影响度 | `node_influence_by_faction` |
| 节点控制权 | 当前主控制势力 | `control_owner_faction_id` |
| 玩家贡献记录 | 历史凭证，不是货币 | `contribution_records` |

规则：

- 贡献不是货币，不能绕过宗门真实库存。
- 宗门声望不是通用兑换资源。
- 节点影响力不等同于宗门库存中的声望资源。

## 8. 库存、资产、位置

推荐统一使用“资产容器”模型，而不是直接问物品属于谁。

```text
AssetContainerRef {
  container_type: String,
  container_id: String
}
```

常用容器类型：

| 容器 | 含义 |
|---|---|
| `CharacterInventory` | 当前角色随身 / 个人储藏 |
| `SectStorage` | 宗门库存 |
| `NodeStorage` | 节点储藏 |
| `ShopStock` | 店铺库存 |
| `MarketListing` | 市场挂牌 |
| `ResourcePool` | 节点资源池 |
| `SealedLegacy` | 正式后手 / 遗产封存 |
| `EventLockedReward` | 事件锁定奖励包 |

## 9. 结果包与日志术语

事件、行动、战斗、突破、宗门 AI、资产变化均应输出结果包，由 S1 统一回写。

推荐结果包字段：

```text
ResultPackage {
  package_id: String,
  source_system: String,
  turn_id: int,
  world_hour: int,
  character_delta: Dictionary,
  inventory_delta: Dictionary,
  node_delta: Dictionary,
  sect_delta: Dictionary,
  route_delta: Dictionary,
  consumed_hours: int,
  interrupt_plan: bool,
  triggered_child_events: Array,
  ledger_entries: Array,
  visible_log_entries: Array,
  hidden_world_log_entries: Array
}
```

旧 `consumed_ticks` 改为：

```text
consumed_hours
```
