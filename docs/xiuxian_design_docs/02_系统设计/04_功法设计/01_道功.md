# 系统设计｜道功

## 1. 设计定位

道功是功法体系中负责推动修为增长、承载修炼路线和提供主修资格的功法类型。它回答玩家当前世“以什么路线修炼、能修到哪里、如何吸收与转化灵气、突破读取什么路线标签”的系统问题。

本文只维护道功作为系统对象的定义、学习与研习、主动吐纳、自动运转、掌握度、当前可修上限、自然上限设计和突破路线边界。角色当前选择哪一门道功作为主修、主修更换窗口、锁定记录和突破读取运行时桥接，由《角色主修功法》（`../02_角色与真灵设计/04_角色主修功法.md`）维护；法门能力体系由《法门》（`02_法门.md`）维护；残页、篇章和完整功法载体由《功法载体》（`../05_物品设计/01_功法载体.md`）维护；功法数值模板、掌握曲线和公式接口由《功法设计基准建模》（`../../03_数值设计/05_功法设计基准建模.md`）维护。

## 2. 当前结论

1. 功法是上位泛称，规则层应拆为 `DaoMethod` 道功与 `TechniqueMethod` 法门。
2. 道功是唯一可以推动修为增长并设为主修的功法类型；法门不能设为主修。
3. 道功决定修炼路线、当前可修上限、环境灵气吸收上限、CP 转化率、法力放大系数、纯度区间、资源和环境相性、突破模板、突破难度、成功收益和失败标签池。
4. 角色通过完整道功载体或明确教学 / 宗门例外入门后创建 `MethodState`；残页和篇章不能直接创建道功掌握状态。
5. 道功掌握度影响当前可修上限、单位时间收益、资源输入兼容、风险提示和可追回知识型收益。
6. 道功掌握度只通过学习、研习或明确的功法系统来源增长；主动吐纳、闭关修炼和自动运转只读取掌握度，不增加掌握度。
7. 道功掌握度不提高理论最高上限，不改变大境界突破模板类型，也不事后改写纯度、法力、小境界奖励或阶段性不可追回收益。
8. 可作为主修根基的道功，其自然最高上限原则上落在某个大境界第一小阶段，方便玩家在新大境界改修窗口自然续接。

## 4. 核心循环或触发入口

道功围绕“获得、研习、入门、主修读取、运转、提升、突破承接”循环维护：

```text
获得完整道功载体或教学授予
→ 选择研习道功
→ 达到入门阈值
→ 创建 MethodState，进入 learned level 1
→ 可按主修规则设为主修道功
→ 主动吐纳 / 自动运转读取道功模板和 MethodState
→ 研习继续提升掌握度
→ 更新当前可修上限、收益、相性和可见路线信息
→ 大境界突破读取道功突破路线标签
```

常见中断点包括载体不完整、目标不是道功、前置知识不足、角色状态禁止研习或运转、神念状态不足、主修道功未设置、当前掌握度不支持目标阶段、当前道功理论上限不足、突破模板缺失和状态压力过高。

## 5. 规则与状态

### 5.1 功法总口径

功法不是单纯技能树，也不是单纯修为倍率表。它在规则层分为两类：

```text
DaoMethod：道功
TechniqueMethod：法门
```

“功法”只作为上位泛称使用，不建议在规则判断中直接用 `method` 表达精确类型。凡涉及修为推进、当前可修上限、大境界突破路线和主修资格的内容，应落到道功；凡涉及战斗指令、行动能力、事件选项和资源效率的内容，应落到法门。

### 5.2 核心定义

道功是可推动修为增长的功法类型，也是唯一可以设为主修的功法类型。

道功决定角色一世内的修行路线根基。玩家选择某门道功，本质是在选择当前大境界的修炼路线，而不只是选择一个收益倍率。

道功路线可以体现为：

1. 快修但默认纯度较低、法力密度较虚。
2. 慢修但单位 CP 法力更高、修为更凝实。
3. 依赖特定灵气环境、节点或洞府设施。
4. 擅长转化丹药、灵液、灵材和宗门配给。
5. 偏生存，提供护身、辟谷、解毒、凝神、藏息等被动效果。
6. 偏神魂，强化神念成长、心魔抵抗或神魂攻防。
7. 偏后期，早期效率低但更高阶段上限或路线收益更好。

当前数值表达必须拆开“速度”和“强度”：

| 体验类型 | CP 转化率 | 法力放大系数 | 默认纯度 | 最高纯度 | 体验定位 |
| --- | ---: | ---: | ---: | ---: | --- |
| 速成道功 | 高 | 低或中 | 低 | 中 | 境界推进快，但修为虚浮 |
| 均衡道功 | 中 | 中 | 中 | 中高 | 速度、法力、巩固成本均衡 |
| 凝实道功 | 低 | 高 | 高 | 最高 | 修得慢，但单位 CP 法力强 |

解释：

```text
转化率 = 修炼速度。
放大系数 = 单位 CP 强度。
纯度 = 虚浮惩罚。
```

### 5.3 道功职责

道功负责：

1. 主动吐纳的环境灵气吸收上限。
2. 主动吐纳和资源消化的 CP 转化率。
3. 单位 CP 对应法力的道功放大系数。
4. 当前大境界默认纯度和可巩固纯度上限。
5. 自动运转的基础收益和稳定性。
6. 当前可修阶段上限。
7. 与灵根、资源输入、节点环境和设施支持的修炼相性。
8. 大境界突破模板、挑战倾向、难度 profile、成功收益 profile 和失败标签池。
9. 主修路线标签。
10. 与该道功绑定的少量被动效果、提示型收益或可追回知识型收益。

道功不负责：

1. 战斗指令的完整展开。
2. 采集、炼丹、炼器、阵法、医术、卜算、隐匿等技艺体系的完整展开。
3. 替代法门系统。
4. 作为物品存在于背包中。
5. 用残页或篇章直接形成运行时学习进度。

边界口径：

| 概念 | 本文是否负责 | 说明 |
| --- | --- | --- |
| 功法 | 只定义总分类口径 | 功法是泛称，规则层应拆为道功与法门 |
| 道功 | 负责 | 修为路线、上限、吸收上限、CP 转化率、法力放大系数、纯度区间、突破路线标签、被动效果 |
| 主修道功 | 只说明“道功可被设为主修” | 主修状态、切换与锁定由角色主修功法文档负责 |
| 法门 | 不负责 | 法门是能力、指令、事件选项与效率体系 |
| 功法载体 | 不负责 | 载体是物品系统，不是道功掌握状态 |

### 5.4 学习与研习

常规道功流程：

```text
获得完整道功载体
→ 选择研习功法
→ 达到入门阈值
→ 创建 MethodState，进入 learned level 1
→ 可按规则设为主修道功
```

新手基础道功可以由宗门入门事件、新手奖励或教学流程直接授予 learned level 1。该例外用于降低入门摩擦，不代表残页或篇章可以直接学习。

研习道功属于可选投入执行时间的个人持续行动。它读取：

```text
实际投入小时
悟性 aptitude_comprehension
道功阶级 tier_code
道功品级 quality_code
导师
藏经阁、静室、讲经、事件等设施或加成
当前神念状态
前置知识、基础法门或路线理解
```

研习道功可以产出：

1. `MethodState` 经验增加。
2. `MethodState` 掌握等级提升。
3. 未入门道功进入 learned level 1。
4. 道功当前可修上限提高。
5. 主动吐纳或自动运转的单位时间收益提高。
6. 与该道功相关的被动效果、提示型收益或路线信息解锁。

研习道功不能产出：

1. 直接修为进度。
2. 缺失残页或篇章自动补齐。
3. 道功理论最高上限提高。
4. 大境界突破模板类型变化。
5. 小境界升级奖励质量变化。
6. 纯度系数、法力放大系数或历史大境界法力记录变化。
7. 阶段性不可追回收益被事后追回。

### 5.5 主动吐纳与自动运转

主动吐纳是角色主动运转当前主修道功，把环境灵气、设施支持和体内药性 / 行动内资源输入转化为 CP 的核心行动。

主动吐纳读取：

1. 当前境界与小阶段。
2. 当前主修道功的环境灵气吸收上限、CP 转化率、法力放大系数、纯度区间、路线标签和掌握度。
3. 根骨 / 悟性效率、灵根标签匹配、体魄承载、状态压力和伤势。
4. 所在节点灵气、洞府、设施、宗门支持和机会窗口。
5. 已服用体内药性和行动内选择的灵液、灵材等资源输入。

主动吐纳输出：

1. 主 CP 和小阶段进度。
2. 当前大境界法力派生变化。
3. 体内药性消化、残余药性和使用资源日志。
4. 外源输入造成的经脉压力或药性容量风险。

主动吐纳默认不直接提高纯度；纯度主要由本大境界道功默认区间和巩固修为行动维护。

主动吐纳、闭关修炼和自动运转只读取当前主修道功的 `MethodState`、掌握度、吸收、转化和相性，不写入 `MethodState.mastery_exp`、掌握等级或掌握度变化。

自动运转是主修道功最基础的被动表现，用于表达修士日常吐纳不息，但不能替代主动吐纳。

自动运转规则：

1. 按世界小时或兼容 tick 结算低额收益。
2. 主动吐纳期间不额外生效，避免同一 tick 同时获得主动吐纳和自动运转收益。
3. 突破事件链、昏迷、重伤、封印等状态下不生效。
4. 可在合法状态下提供少量修为或稳定性收益。
5. 通常可以触发普通小境界升级。
6. 不能完成大境界突破。
7. 不自动消耗高价值丹药或突破资源。

### 5.6 掌握度与上限

道功掌握度表示角色对该道功的理解、运转熟练度与当前承载能力。

道功有两个上限概念：

```text
theoretical_max_cap_stage：道功理论最高上限
mastery_current_cap_stage：掌握度当前上限
```

当前有效上限：

```text
effective_current_cap_stage = min(
  theoretical_max_cap_stage,
  mastery_current_cap_stage
)
```

道功掌握度可以影响：

1. 当前可修上限。
2. 主动吐纳单位时间收益。
3. 自动运转单位时间收益。
4. 资源输入兼容性、体魄承载稳定性或风险提示。
5. 某些可追回的知识型、提示型或路线型收益。

道功掌握度不能影响：

1. 道功理论最高上限。
2. CP 到法力的纯度系数。
3. 道功法力放大系数。
4. 已获得 CP 的法力密度。
5. 小境界升级奖励质量。
6. 大境界突破模板类型。
7. 大境界突破模板自身的核心风险结构。
8. 阶段性不可追回收益。

旧文档中的“功法等级”“道功等级”统一理解为 `MethodState.mastery_level`。它是掌握度层级，不是残页或篇章收集进度。

### 5.7 上限示例

示例：《青木养真诀》

```text
理论最高上限：B-1 100%

level 1：当前可修至 A-2 100%
level 2：当前可修至 A-3 100%
level 3：当前仍可修至 A-3 100%，单位时间收益提高
level 4：当前可修至 B-1 100%
level 5：当前仍可修至 B-1 100%，单位时间收益进一步提高
```

不会发生：

1. level 5 让《青木养真诀》修到 B-2。
2. level 5 让 A-3 → B-1 的突破模板变成另一个模板。
3. level 不足导致 A-1 → A-2 时永久少拿属性。
4. level 不足导致当前大境界纯度或历史法力记录永久变差。

### 5.8 与大境界突破的关系

大境界突破模板来自道功本身的路线特质，而不是掌握等级临时生成。道功突破模板同时定义本次突破的难度与成功收益；突破系统不再额外生成独立突破品质。

可以成立：

```text
《青木养真诀》本身具有 A-3 → B-1 的木系稳健突破转接。
```

不应成立：

```text
《青木养真诀》level 1 匹配低级模板，level 5 匹配另一个高级模板。
```

掌握度影响的是“角色是否获得更稳定的可见度、执行表现或模板声明的事件内修正”，而不是把一门道功改造成另一种突破模板，也不是默认突破入口门槛。

道功强弱在突破中的表达方式包括：

1. 更高或更特殊的阶段阈值。
2. 更明确的属性考验倾向。
3. 金丹到元婴及之后更高的雷劫压力或伤损风险。
4. 更高或更稳定的成功收益 profile。
5. 更稀缺的资源需求、学习门槛、宗门权限或相性要求。

这些内容已经承担突破品质职责，不再叠加“完美 / 正常 / 残缺”或 S / A / B / C 品质层。

示例：

```text
《青木养真诀》理论最高：B-1
突破转接：A-3 → B-1

level 2 当前只能修到 A-3：
- 可以修到 A-3 100%。
- 不能使用该道功完成 A-3 → B-1。
- 原因是当前掌握度承载不住 B-1。

level 4 当前能修到 B-1：
- 可以使用 A-3 → B-1 的木系稳健突破转接。
- 突破模板类型仍来自道功本身特质，不由 level 4 生成。
- 成功后的永久收益读取《青木养真诀》对应的突破模板收益 profile，不再按独立突破品质二次结算。
```

### 5.9 自然上限设计规范

可作为主修根基的道功，其自然最高上限原则上应落在某个大境界第一小阶段，方便玩家在新大境界的改修窗口内自然续接。

推荐：

```text
A 段道功：A-1 / A-2 / A-3 / B-1
B 段道功：B-1 / B-2 / B-3 / C-1
C 段道功：C-1 / C-2 / C-3 / D-1
```

不推荐：

```text
A-1 / A-2 / A-3 / B-1 / B-2
```

原因是这会把玩家自然卡在 B-2，而 B-2 已离开 B 阶常规改修窗口。

同一传承可以连续，但规则层应拆成多个完整道功模板。

示例：

```text
lineage_id = qingmu_lineage

《青木养真诀》：A-1 → B-1
《青木长生经》：B-1 → C-1
《青木洞玄篇》：C-1 → D-1
```

它们共享传承标签、宗门来源、世界观文本和资源相性，但在规则层是不同完整道功。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 角色修为状态 | 读取当前境界、小阶段、修为进度和瓶颈状态；道功本身不直接写入境界，只通过修炼或突破结算承接 |
| 主修道功状态 | 读取当前主修道功、`MethodState`、掌握度、当前可修上限、突破路线标签和锁定记录 |
| 角色属性 | 读取根骨、悟性、灵根标签、体魄承载、元气 / 神念和持续状态导出的修正 |
| 持续状态 | 昏迷、重伤、封印、心魔、药性残余、法宝触发态等可以影响吐纳、自动运转、研习或突破前置 |
| 功法载体 | 完整道功载体提供常规学习来源；残页和篇章只提供合成、线索或权限，不创建 `MethodState` |
| 修炼玩法 | 主动吐纳、闭关和自动运转读取道功模板与掌握状态；研习功法写入掌握变化 |
| 突破玩法 | 大境界突破读取道功突破模板、挑战倾向、难度 profile、成功收益 profile、失败标签池和模板声明的掌握度修正 |
| 地图节点与设施 | 所在节点灵气、洞府、静室、讲经、藏经阁、宗门支持和设施加成影响道功研习与吐纳 |
| 资源与物品 | 丹药、灵液、灵材、宗门配给等作为修炼资源输入，按道功资源相性和体魄承载结算 |
| 事件与 NPC | 导师、宗门入门、传功、特殊事件或剧情可授予道功、提供研习加成、推荐路线或授权例外 |
| UI 页面 | 展示道功类型、掌握度、当前可修上限、理论最高上限、相性、主修资格、研习入口和不可用原因 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `DaoMethod.method_id` | 道功模板 ID |
| `method_type` | 功法类型；道功固定为 `dao_method` |
| `lineage_id` | 传承标签，用于同一传承多段道功的世界观与来源归组 |
| `tier_code` / `quality_code` | 道功阶级与品级，用于研习难度、内容层级和数值适配 |
| `route_tags` | 修炼路线标签，用于路线定位、奖励倾向和风险识别 |
| `stage_support_range` | 道功支持的阶段范围 |
| `theoretical_max_cap_stage` | 道功理论最高上限，掌握度不得提高该值 |
| `mastery_curve_id` / `level_cap_profile` | 掌握等级曲线和掌握度当前上限映射 |
| `aura_absorption_cap_per_hour` | 道功每小时可承接的环境灵气上限 |
| `cp_conversion_rate` | 已承接灵气转化为 CP 或巩固填充的速度 |
| `mana_amplifier` | 单位 CP 对应法力的道功放大系数 |
| `purity_floor` / `purity_ceiling` | 本道功在一个大境界中的默认纯度和最高纯度 |
| `consolidation_cost_factor` / `consolidation_action_efficiency` | 巩固修为需求和行动效率 |
| `cultivation_speed_tag` / `mana_density_tag` | 速成、均衡、凝实等 UI 与调参标签 |
| `root_affinity_tags` / `resource_affinity_tags` / `node_affinity_tags` | 灵根、资源、节点和设施相性入口 |
| `passive_effect_refs` | 道功绑定的少量被动效果、提示型收益或可追回知识型收益 |
| `breakthrough_template_ref` / `breakthrough_route_tags` | 大境界突破模板入口、路线标签、难度 profile、成功收益 profile 和失败标签池入口 |
| `MethodState.method_state_id` | 角色掌握某门道功的运行时状态 ID |
| `MethodState.mastery_level` / `mastery_exp` | 掌握等级与掌握经验 |
| `MethodState.mastery_current_cap_stage` | 由掌握度决定的当前可修上限 |

## 8. UI 展示边界

普通 UI 应展示：

1. 道功名称、类型、传承、阶级、品级和当前是否已学会。
2. 当前掌握等级、掌握进度、当前可修上限和理论最高上限。
3. 是否可设为主修，以及不可设为主修的原因。
4. 道功路线标签、资源 / 灵根 / 节点相性摘要和适合的修炼场景。
5. 环境灵气吸收、修炼速度、法力凝实度、默认纯度和最高纯度的体验摘要。
6. 主动吐纳、自动运转、巩固修为或研习道功时对玩家可理解的收益、风险和短板提示。
7. 与突破相关的可见摘要，例如路线倾向、法力偏虚、承载不足、状态压力和准备短板。

普通 UI 不应展示：

1. 完整失败标签池、奖励配置引用、原始倍率、公式缓存或 Debug 追踪。
2. 残页 / 篇章收集进度作为道功掌握等级。
3. 掌握度直接改变突破模板类型的暗示。
4. 道功理论最高上限之外的越界续修承诺。
5. 转化率高低被直接包装为“道功强弱”的暗示。
6. 法门能力被误展示为主修道功效果。

## 9. MVP 范围

MVP 应实现：

1. `DaoMethod` 与 `TechniqueMethod` 的类型区分。
2. 道功可推动修为增长、可设为主修；法门不能设为主修。
3. 完整道功载体或明确新手 / 宗门例外创建 `MethodState`。
4. 道功研习提升 `MethodState.mastery_level`、`mastery_exp` 和当前可修上限。
5. 主动吐纳读取当前主修道功的环境吸收上限、CP 转化率、法力放大系数、纯度区间、相性、掌握度和状态压力，但不提升掌握度。
6. 自动运转提供低额收益并受状态和主修规则限制。
7. `theoretical_max_cap_stage`、`mastery_current_cap_stage` 和 `effective_current_cap_stage` 的上限约束。
8. 大境界突破读取道功本身的突破路线标签，而不是由掌握等级临时生成模板。
9. 道功模板与 `MethodState` 字段的最小数据口径。
10. 功法页面展示道功掌握、上限、相性、主修资格、修炼速度、法力凝实度、纯度区间和不可用原因。

MVP 不实现：

1. 残页或篇章直接学习道功。
2. 掌握度提高道功理论最高上限。
3. 掌握度改变大境界突破模板类型。
4. 掌握度事后追回当前大境界纯度、历史法力记录、小境界升级奖励或阶段性不可追回收益。
5. 功法推演、功法创造、功法融合、废功重修或改修折算。
6. 道功替代法门的战斗、采集、炼丹、炼器、阵法、医术、卜算和隐匿体系。
7. 自动运转完成大境界突破或自动消耗高价值丹药 / 突破资源。

## 10. 验收约束

1. 任何可以推动正常修为增长并设为主修的功法必须是道功。
2. 法门不得写入主修道功字段，不得决定当前可修上限或大境界突破模板类型。
3. 残页和篇章不得创建 `MethodState`，不得直接提高道功掌握度。
4. 道功模板不得保存角色个人掌握进度；角色进度必须落在 `MethodState`。
5. `effective_current_cap_stage` 必须同时受理论最高上限和掌握度当前上限约束。
6. 掌握度不得提高 `theoretical_max_cap_stage`。
7. 掌握度不得把一门道功的大境界突破模板改造成另一种模板。
8. 道功理论最高上限之外不得通过自动运转、小境界升级或资源输入继续推进。
9. 主动吐纳期间不得额外叠加自动运转收益。
10. 自动运转不得完成大境界突破，也不得自动消耗高价值丹药或突破资源。
11. 主动吐纳、闭关修炼和自动运转不得写入道功掌握经验、掌握等级或掌握度变化。
12. 可作为主修根基的道功若自然卡点不在大境界第一小阶段，需要进入待裁决或特殊设计说明。
13. UI 不得把残页 / 篇章进度、法门能力或 Debug 字段表达成道功掌握状态。
14. UI 不得把 `cp_conversion_rate` 直接表达为道功绝对强弱；强弱需要同时看 `mana_amplifier`、纯度区间和路线。
