# 地图节点设计

更新日期：2026-05-11

## 1. 当前结论

地图采用有向带权节点图。地图主单位是地理节点，路线是节点之间的有向边；资源槽、资源槽附属设施、事件窗口、隐藏层、后手、宗门清点和遗留设施只挂载在节点或路线之上，不替代节点本身。

地图不是静态菜单，而是共享世界中的空间状态机。玩家移动、修炼、探索、资源采集、宗门行动、NPC 行动、事件、秘境窗口、传闻、正式后手、宗门清点和宗门外遗留设施都可以改变节点状态。

地图变化按连续世界时间推进：

```text
world_day / world_hour 是地图主时间；
hour_tick 是服务器推进地图状态的最小结算步；
macro_period_id 只用于季节、旬月、资源批次、灾变期等宏观内容标签，不作为玩家回合；
所有节点、路线、资源、可见性和事件窗口变化都必须能写入结果包和回放。
```

## 2. 地图总状态

`WorldMapState` 是地图运行时主状态。

```yaml
WorldMapState:
  map_id: string
  current_world_day: int
  current_world_hour: int
  current_macro_period_id: string
  node_states: dict[node_id, NodeState]
  route_states: dict[route_id, RouteState]
  active_region_effects: list[RegionEffect]
  resource_budget_refs: list[string]
  rumor_pool_refs: list[string]
  visibility_overrides: dict
```

规则：

1. `current_world_day` 与 `current_world_hour` 必须和房间权威时间同步。
2. 地图系统只输出变化结果，不绕过权威结算直接改写角色、宗门、库存或经济状态。
3. 地图可生成的结果包括 `node_delta`、`route_delta`、`resource_slot_delta`、`visibility_delta`、`event_window_delta`、`risk_level_delta`、`rumor_entries`、`ledger_entries` 和日志条目。

本文件中的“结果包”指权威结算可合并的状态变化集合；“回放”指按世界时间记录的可审计事件序列。地图只负责生成这些变化和记录，不负责直接提交最终状态。

## 3. 节点运行字段

`NodeState` 记录节点当前运行状态。旧版 `WorldNode` 可作为内容模板名保留，但运行时主字段使用 `NodeState`。

```yaml
NodeState:
  node_id: string
  node_type: sect | town | village | wilderness | resource_site | secret_realm_entry | cave | market | battlefield | forbidden_area | transit_facility | special
  node_level: int
  display_name: string
  region_id: string
  owner_faction_id: string | null
  controlling_influence: dict[faction_id, number]
  risk_level: low | medium | high | unknown
  aura_profile: object
  resource_slots: list[NodeResourceSlot]
  facility_refs: list[string]
  active_events: list[string]
  active_windows: list[OpportunityWindow]
  visibility_state: object
  hidden_layer_refs: list[string]
  contingency_refs: list[string]
  sect_clearance_refs: list[string]
  remnant_site_refs: list[string]
  route_edge_refs: list[string]
  node_state_tags: list[string]
  cooldown_tags: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `node_level` | 节点等级，影响自然生成资源槽数量、资源品级范围、灵气浓度、风险强度和可建设规模上限 |
| `owner_faction_id` | 当前主控制势力；无人稳定控制时为空 |
| `controlling_influence` | 各势力在节点上的影响力分布，是控制权变化的基础 |
| `risk_level` | 节点风险等级，驱动移动提示、自动兜底和托管默认 |
| `aura_profile` | 节点整体灵气密度、品阶、相性、污染、稳定度和修炼修正；受节点等级、资源槽和附属设施共同影响 |
| `resource_slots` | 节点自然、半自然、空间、灵气、生态或组织控制的广义资源承载位 |
| `facility_refs` | 节点上已存在或可使用的设施索引；设施必须可追溯到某个广义资源槽 |
| `active_windows` | 秘境入口、资源名额、节点危机、短期交易、突破护法机会等限时窗口 |
| `hidden_layer_refs` | 未完全公开的隐藏空间、路线、资源、线索、旧洞府、伏笔事件引用 |
| `contingency_refs` | 正式后手记录引用；MVP 主要对应真灵藏宝 |
| `sect_clearance_refs` | 宗门管辖洞府、宗门托管资产或职务资产的清点、锁定和回收记录引用 |
| `remnant_site_refs` | 宗门外个人洞府、普通藏宝、旧洞府线索、失落库存或可开启遗留设施引用 |

`danger_level` 不再作为地图节点字段使用。若旧事件模板中仍出现 `danger_level`，应迁移为节点 `risk_level` 或事件自身的风险描述标签，不能同时作为地图节点的第二套风险字段。

## 4. MVP 节点类型

MVP 至少支持以下节点类型：

| 类型 | `node_type` | 作用 |
| --- | --- | --- |
| 宗门山门 | `sect` | 宗门驻地、洞府、宗门设施、宗门库存与宗门行动中心 |
| 城镇 / 坊市 | `town` / `market` | 交易、情报、人流、任务、低到中风险事件 |
| 村庄 / 凡人聚落 | `village` | 早期剧情、凡俗资源、低阶事件和人口线索 |
| 资源型地理节点 | `resource_site` | 灵田、矿脉、药谷、灵泉、妖兽巢穴等资源槽承载点 |
| 荒野探索节点 | `wilderness` | 探索、线索、野外事件、隐藏路线和普通资源 |
| 秘境入口 | `secret_realm_entry` | 机会窗口、准入条件、争夺策略和临时内部节点入口 |
| 洞府 / 藏宝所在节点 | `cave` 或节点隐藏层 | 个人洞府、普通藏宝、真灵藏宝、旧洞府线索的空间承载 |
| 禁地 / 高危节点 | `forbidden_area` | 高风险资源、强敌、灾变、禁制、重大事件 |
| 战场 / 争夺地 | `battlefield` | 宗门冲突、控制权争夺、正式交锋后果 |
| 交通设施节点 | `transit_facility` | 渡口、关隘、传送阵、山道节点等有状态的通行设施 |
| 特殊节点 | `special` | 剧情节点、世界异象、不可归入上列的定制内容 |

普通道路、山路、水路和隐藏通道默认是 `RouteState`，不是独立节点。只有渡口、关隘、传送阵、山道要冲等自身有控制权、风险、设施或事件状态的交通对象，才作为 `transit_facility` 节点建模。

## 5. 路线与移动

路线使用有向带权边。双向通行应建成两条路线，因为两侧成本、风险和通行条件可能不同。

```yaml
RouteState:
  route_id: string
  from_node_id: string
  to_node_id: string
  base_cost_hours: int
  current_cost_hours: int
  route_type: road | mountain_path | river | teleport | hidden | rumor
  passability: open | blocked | conditional | unknown
  requirements: list[object]
  risk_tags: list[string]
  discovered_by: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

移动校验读取：

```text
当前位置；
目标节点；
路线是否可见；
passability；
requirements；
risk_tags；
current_cost_hours；
角色状态；
宗门、NPC 或事件授予的通行许可；
是否存在路线封锁、节点事件或公开危险。
```

移动是普通个人行动，按 `world_hour` 消耗时间。队列中的移动在入队时校验一次，执行前必须再次校验，避免路线被封锁、节点风险改变或权限失效后仍强行通过。

## 6. 风险、节点等级、灵气与设施

`risk_level` 枚举：

```text
low
medium
high
unknown
```

基础兜底口径：

| `risk_level` | 自动兜底 | 显式托管默认 |
| --- | --- | --- |
| `low` | 吐纳 | 托管吐纳 |
| `medium` | 休整 | 托管休整 |
| `high` | 休整 | 托管休整 |
| `unknown` | 休整 | 托管休整 |

风险等级变化必须写入结果包、个人可见日志或公开地图日志。地图 UI 可以显示中性风险提示，但不得泄露其他玩家私人事件来源。

`node_level` 或等价节点等级由节点模板、区域、控制权、历史演化和特殊事件决定。MVP 阶段节点等级至少影响：

1. 自然生成的资源槽数量。
2. 资源槽内资源的基础品级、可波动范围和稀有变体概率。
3. 节点整体 `aura_profile` 的灵气浓度、品质、稳定度、污染和相性权重。
4. 可见风险、机会窗口、资源争夺强度和可建设规模上限的默认区间。

`aura_profile` 最少表达：

```yaml
aura_profile:
  aura_density: number
  aura_quality: string
  element_affinity_tags: list[string]
  pollution_tags: list[string]
  stability_tags: list[string]
  cultivation_modifiers: dict
```

灵气只提供修炼环境、资源输入相性、经脉压力、心魔风险、突破准备和事件选择的修正，不直接发放无来源修为。

设施通过 `facility_refs` 建索引，但设施和建筑不是与资源并列的第二套槽位。MVP 阶段，能建造、升级、运行或维护的生产、修炼、加工、防护、交通、市场、宗门行政等设施，必须附属于一个合法资源槽。设施可以提供修炼环境、功法研习、炼丹炼器、治疗护法、传送、储物、阵法、防护、市场、宗门行政和资源加工等能力。设施效果必须通过行动、权限、资源消耗、资产流水和结果包进入结算，不能作为无来源全局倍率。

设施附属规则：

1. 同一个资源槽同时只能承载一类设施。设施的规模、等级、维护状态和产能可以变化，但设施类别不能在同一槽内并存。
2. 资源槽模板声明可建设施类别、初始规模上限、最终规模上限和升级条件；节点等级可提高或压低这些上限。
3. 更换设施类别必须走拆除、迁移、废弃、污染修复或事件改造流程，不能直接把灵田槽瞬间改成矿场槽。
4. 不易改造资源槽可以禁止常规建设，只允许封禁、维护、参悟、争夺、探索或机会窗口类操作。
5. 交通设施、坊市入口、宗门行政建筑等不依赖自然产出的公共设施，也必须绑定到交通锚点、市场锚点、行政地块或 `special` 等广义资源槽，不能绕过资源槽规模限制。

## 7. 资源槽

`NodeResourceSlot` 代表节点上的广义资源承载位。资源不只指可采集物，也包括灵气节点、灵田、矿脉、药谷、灵泉、妖兽巢穴、稳定空间、洞天福地、秘境入口条件和其他可被争夺、利用或建设依附的世界条件。

```yaml
NodeResourceSlot:
  slot_id: string
  node_id: string
  resource_type: aura_node | spirit_field | mine_vein | herb_valley | spirit_spring | beast_lair | cave_space | blessed_land | secret_realm_window | market_anchor | transit_anchor | administrative_site | special
  resource_template_id: string
  generated_by_node_level: int
  resource_grade: string
  resource_grade_range: string
  current_amount: number
  max_amount: number
  regen_per_world_hour: number
  buildable_facility_classes: list[string]
  attached_facility_class: string | null
  attached_facility_ref: string | null
  facility_scale: int
  facility_level: int
  facility_scale_cap: int
  transformability: free_build | limited_build | preserve_only | no_build
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  depletion_event_refs: list[string]
  contest_state: object
```

规则：

1. 资源采集、争夺、消耗、枯竭和刷新都按 `world_hour` 记录。
2. 自然资源点先产出资源池或资源量，再通过采集、加工、炼制、修复等行动转为物品、材料或宗门资源。
3. 已控制资源节点的基础产出属于常态结算，不占用宗门唯一持续行动槽。
4. 稀有资源、秘境资源、藏宝资源和后手封存资产必须有来源、预算或资产容器记录，不能作为无约束随机奖励。
5. 枯竭、再生、污染、异变按节点模板配置，不使用统一生态公式。
6. 资源槽的自然生成数量、资源品级和 `resource_grade_range` 受节点等级影响；同类节点也可以因区域、污染、秘境窗口或历史事件产生差异。
7. 设施必须读取资源槽的 `buildable_facility_classes`。同一资源槽只能选择一个 `attached_facility_class`，后续只允许在该类别内调整规模、等级、维护和产能。
8. `facility_scale_cap` 是该槽的硬上限。节点等级、资源品级、地形、控制权和特殊事件可以修正上限，但不能在没有记录的情况下无限扩建。
9. 洞天福地在 MVP 阶段按 `blessed_land` 或等价不易改造资源槽处理，通常是 `limited_build`、`preserve_only` 或 `no_build`，不是可随意改造的一般建筑地块。
10. 普通灵气节点按 `aura_node` 资源槽处理，可以建造修炼房、静室、聚灵阵或同类修炼设施；修炼房可内含聚灵阵，但仍占用该资源槽唯一设施类别。

MVP 资源槽与可建设施对应关系：

| `resource_type` | 可建设施类别 | 约束 |
| --- | --- | --- |
| `aura_node` | 修炼房 / 静室 / 聚灵阵类修炼设施 | 修炼房可内含聚灵阵；同槽只允许这一类修炼设施 |
| `spirit_field` / `herb_valley` | 灵植园 / 药园 / 培育棚 | 主要产出灵植、药材或种植资源 |
| `mine_vein` | 采矿场 / 炼矿前置设施 | 主要产出矿石、灵石原矿或炼器材料 |
| `spirit_spring` | 灵泉维护 / 灵液收集设施 | 提供灵液、炼丹辅助或修炼环境输入 |
| `beast_lair` | 狩猎营地 / 驯养栏 / 看守点 | 提供妖兽材料、风险事件或驯养机会 |
| `cave_space` | 洞府 / 藏宝 / 仓储类设施 | 以储物、防护、隐蔽、休整为主 |
| `blessed_land` | 保全 / 封禁 / 参悟 / 突破场地类操作 | 不易改造，通常不允许常规生产建筑替换 |
| `market_anchor` | 坊市 / 店铺 / 摊位 / 拍卖场 | 提供交易服务、摊位规模和市场窗口 |
| `transit_anchor` | 渡口 / 关隘 / 传送阵 / 山道要冲 | 提供通行、封锁、传送和路线控制 |
| `administrative_site` | 宗门行政 / 库房 / 执事堂 / 任务堂 | 提供权限、任务、审计和宗门服务入口 |
| `secret_realm_window` / `special` | 入口维护 / 探索准备 / 临时封锁 | 多数是机会窗口或事件入口，不作为常态建筑地块 |

资源再生可按 `world_hour` 连续累计，也可按 `macro_period_id` 批量刷新；无论哪种方式，都必须保留可追溯的世界时间、来源和可见性记录。

## 8. 控制权与影响力

节点归属采用“控制权 + 影响力”混合模型。

控制权影响：

```text
主资源收益权；
建设权；
驻守权；
通行管理权；
节点事件优先响应权；
宗门 AI 行动目标选择。
```

影响力影响：

```text
行动耗时与便利；
情报发现率；
任务成功率；
探索与交易便利；
控制权争夺基础；
对控制者收益的轻微竞争；
传闻可信度与可见性。
```

控制权变更采用阈值 + 事件模型。玩家不需要逐个节点手动点击接管。可推动节点易主的因素包括：

```text
玩家探索、驻守、建设、开采；
玩家处理节点事件；
玩家亲自参与宗门相关个人行动；
宗门持续行动；
外部宗门或 NPC 压力；
后手触发；
资源枯竭、路线封锁、灾变或重大事件链。
```

达到条件后，控制权变化应生成控制权事件或受控 `node_delta`，再由权威结算合并。

## 9. 机会窗口、秘境与临时节点

秘境、资源名额、节点危机、短期交易、突破护法机会等限时内容使用 `OpportunityWindow`。

```yaml
OpportunityWindow:
  window_id: string
  node_id: string
  starts_world_day: int
  starts_world_hour: int
  ends_world_day: int
  ends_world_hour: int
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  entry_requirements: list[object]
  event_template_refs: list[string]
  contest_policy: string
```

规则：

1. 普通秘境入口作为节点上的机会窗口或入口设施表达。
2. 少数长期存在、可以被反复观察和争夺的著名秘境，可作为 `secret_realm_entry` 或 `forbidden_area` 节点。
3. 窗口开启、关闭、进入、错过、被争夺或被后手影响，都必须写入结果包和回放。
4. 玩家进入机会窗口必须通过个人行动、事件选择或正式交锋入口完成，地图不能直接修改角色状态。

秘境内部或短期空间可使用临时节点：

```yaml
TemporaryNode:
  temp_node_id: string
  parent_node_id: string
  created_world_day: int
  created_world_hour: int
  expiry_rule: object
  access_rules: object
  event_chain_refs: list[string]
  cleanup_rules: object
```

## 10. 隐藏层、后手、清点与遗留设施

隐藏层是地图上的信息与空间承载层，不是后手、宗门清点、遗留设施或库存本身。

隐藏层状态：

```text
unknown → rumored → located → partially_revealed → revealed → resolved
```

隐藏层可承载：

```text
隐藏资源；
旧洞府；
普通藏宝；
真灵藏宝位置；
线索；
秘境入口；
伏笔事件；
前世痕迹；
隐藏路线。
```

当前不再保留旧版把无主遗留物并入遗产的 active 设定。死亡、转世、失踪、洞府失守、组织接管或事件后的资产去向，拆成三类处理：

| 类型 | 地图承载方式 | 资产规则 |
| --- | --- | --- |
| 宗门个人洞府清点层 | 节点设施、宗门管辖状态、宗门清点事件或宗门清点记录 | 玩家转世前留在宗门管辖个人洞府中的普通库存，可由宗门锁定、清点并回收；它不是正式后手，也不是新世角色自动继承物资 |
| 宗门外个人洞府 / 普通藏宝层 | 节点隐藏层、洞府设施、普通藏宝记录、开启条件和争夺事件 | 不进入宗门清点回收，不随转世自动进入宗门库存或新世行囊；必须满足钥匙、功法、线索、位置、事件条件或破阵结果后才能进入或取出，且可能被其他角色提前打开 |
| 真灵藏宝层 | 正式后手记录、真灵藏宝记录、目标节点和隐藏层位置 | MVP 阶段的正式后手藏物形态；绑定同一真灵，可跨世感应和开启；受设置数量和单个容量限制；取出一次性；MVP 阶段不展示被他人搬空、损坏或移动 |

宗门个人洞府清点流程在地图层的最小要求：

```text
角色死亡、转世、长期失踪、被逐、叛宗、资格丧失或洞府权限被撤销
→ 宗门管辖状态校验
→ 洞府入口锁定或权限撤销
→ 普通库存转入宗门库存或临时清点容器
→ 写入资产流水、节点日志、宗门可见摘要和必要的隐藏日志
→ 节点设施状态更新为 locked、cleared、abandoned 或 contested
```

正式后手最少记录：

```yaml
ContingencyRecord:
  contingency_id: string
  true_spirit_id: string
  creator_character_id: string
  created_world_day: int
  created_world_hour: int
  contingency_type: resource_cache | message | formation | relationship_debt | hidden_route | sect_influence | reincarnation_clue
  target_node_id: string | null
  target_ref: string | null

  risk_tags: list[string]
  status: dormant | active | triggered | failed | discovered | contested
  result_package_refs: list[string]
```

宗门清点记录最少表达：

```yaml

  clearance_id: string

  source_facility_ref: string
```

```yaml

  origin_hint_ref: string | null

  access_condition: object
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  discovered_by: list[string]
  status: hidden | known | opened | depleted | lost | contested
```

后手、清点和遗留设施的地图规则：

1. 后手必须有位置或明确目标引用，不能只有抽象描述。
2. 后手创建、触发、失败、争夺和发现必须写入日志、轮回账本、结果包和回放。
3. 正式后手失效必须有原因链，例如节点被占、资源被采尽、宗门清查、NPC 死亡、竞争者发现、世界事件破坏、触发条件被改变、目标资产被转移、隐藏路线被封锁或机会窗口关闭。
4. 宗门清点只处理宗门管辖洞府、宗门托管资产、职务资产或宗门发放但未私有化的资产，不处理宗门外个人洞府、普通藏宝或真灵藏宝。
5. `RemnantSiteRecord` 是无主遗留设施记录。它可以保留来源线索或传闻，但没有当前资产主人，因此不进入遗产分配、继承或回收流程。
6. 宗门外遗留设施只通过钥匙、功法、线索、位置、事件条件、破阵或争夺事件处理，不生成遗产实体。
7. 不做每回合、每季度、年久失修或无世界变化的随机磨损。
8. 高风险后手回收必须由玩家明确行动或事件选择推动，自动兜底和显式托管不得主动回收、暴露、移动或销毁核心后手。

## 11. 可见性与传闻

地图可见性使用统一层级：

```text
private_player：单个玩家、真灵或当前角色可见；
known_to_party：当前事件、队伍、临时协作对象或授权对象可见；
sect_visible：宗门权限范围内可见；
rumor_visible：作为传闻、模糊信息、延迟信息或不完整情报可见；
public_world：公共世界信息，可进入公开地图或世界摘要；
hidden_world：世界真实状态记录，玩家不可直接看到；
debug_only：调试、审计和开发工具可见。
```

玩家 UI 只显示其可见层级内的节点、路线、风险、资源槽摘要、机会窗口、宗门影响与传闻。

不得显示：

```text
其他玩家私人事件归因；
隐秘局部时停来源；
未公开突破选择；
隐藏后手真实归属；
debug_only 信息。
```

公开地图变化应使用中性描述，例如：

```text
黑石岭驻守加强。
云麓山道近日妖兽踪迹增多。
青木谷灵气波动，疑有秘境窗口。
坊市筑基资源短缺。
```

传闻可以模糊、延迟、不完整，不等同于全知世界日志，也不能泄露隐藏真相引用。

## 12. 世界小时演化

每个 `hour_tick`，地图系统根据当前世界状态输出变化结果。

```text
advance_nodes(world):
  for node in node_states:
    regenerate_resource_slots(node)
    update_resource_slot_facilities(node)
    update_risk_level(node)
    update_influence(node)
    check_event_windows(node)
    check_hidden_layers(node)
    write_node_result_packages(node)
```

演化来源：

```text
玩家行动；
宗门行动；
NPC 行动；
资源采集和枯竭；
事件结果；
后手触发；
宏观周期；
世界随机状态。
```

追赶补结算期间只补确定性节点影响，不触发新的随机个人事件、普通机缘或软机会事件。若地图变化属于强制公开节点事件、正式交锋或全局公共决策，应交给房间速度状态处理。

## 13. UI 与验收约束

主界面地图应稳定展示：

```text
当前位置；
可见节点；
可见路线；
节点风险；
资源槽摘要；
宗门影响；
秘境 / 机会窗口；
公开传闻；
队列目标路线；
当前节点可用行动入口。
```

验收检查：

1. 地图状态使用 `current_world_day / current_world_hour`。
2. 移动读取 `RouteState.current_cost_hours` 并按 `world_hour` 结算。
3. `risk_level` 正确影响自动兜底和显式托管默认。
4. 节点 `aura_profile` 能被修炼和突破准备读取。
5. 节点资源槽能按节点等级生成数量、品级范围、灵气影响、刷新、消耗、枯竭、争夺和传闻。
6. 资源槽附属设施遵守一槽一设施类别、规模上限、等级调整和维护状态。
7. 宗门行动能改变节点影响、风险、资源槽、附属设施、路线或机会窗口。
8. 机会窗口有开始、结束、可见性、准入条件和争夺策略。
9. 后手只在有明确世界变化或触发条件时检定，不做无原因随机失效。
10. 地图 UI 不显示其他玩家私人事件归因。
11. 地图变化进入结果包和回放。

## 14. 冲突裁决与废弃口径

| 旧口径或冲突点 | 当前采用口径 | 裁决原因 |
| --- | --- | --- |
| `WorldNode` 作为唯一节点运行结构 | 运行态使用 `NodeState`，`WorldNode` 仅可作为旧模板名 | 节点需要记录时间、可见性、事件窗口、路线、后手和资源状态 |
| `building_slots` | 不采用独立建筑槽；使用广义 `resource_slots` + 附属 `facility_refs` | 资源槽决定可利用世界条件和规模上限，设施是资源槽上的建设或运营形态 |
| 资源槽只代表可采集产出点 | 资源槽泛化为灵气、空间、生态、矿脉、灵泉、洞天福地等世界条件 | 设施建设、修炼环境和资源产出需要同一套来源与规模约束 |
| 同一资源槽堆叠多类建筑 | 同一资源槽只能建造一类设施，规模和等级可变 | 避免一个灵气节点同时无限承载修炼房、炼丹房、矿场和市场，破坏地图资源稀缺性 |
| `danger_level` | 使用 `risk_level` | 风险字段需要直接驱动兜底、托管、移动提示和 UI 摘要 |
| 普通道路作为节点 | 普通道路作为 `RouteState`；只有有状态交通设施才建节点 | 避免路线边和地理节点重复建模 |
| “前世后手节点”作为独立节点类型 | 使用隐藏层、正式后手记录、宗门清点记录、遗留设施记录或洞府 / 藏宝设施承载 | 后手、清点、藏宝和洞府是挂载内容，不应混成节点类型 |
| 旧版无主遗留物作为遗产 active schema | 不采用；拆成宗门清点记录、宗门外遗留设施记录、正式后手记录 | 当前重整口径不再保留无主遗留物作为遗产实体，避免把宗门清点、宗门外洞府和真灵藏宝混成一种跨世继承规则 |
| 宗门个人洞府、宗门外洞府、普通藏宝、真灵藏宝混作同一种遗产 | 按宗门清点、可开启遗留设施、正式后手三类分开 | 解决资产去向、跨世继承、宗门回收和多人竞争规则冲突 |
| 正式后手被随机磨损、年久失修或无日志失效 | 正式后手失效必须有原因链；MVP 真灵藏宝不展示被他人搬空、损坏或移动 | 轮回体验需要可信、可复盘，且不能把正式后手降级为普通随机宝箱 |
| 推荐阶段作为硬锁 | 推荐阶段只做内容筛选、提示和风险预期 | 玩家可以冒险，但系统必须展示风险和后果 |
| 地图公开所有节点真相和私人归因 | 地图按可见性层级展示，中性化公开后果 | 多人间接竞争依赖信息边界，私人事件不能被地图泄露 |
