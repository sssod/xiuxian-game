# 运行时状态、数据模型与结果包（v2.2）

## 0. 文档定位

本文是给开发人员的运行时结构整理，用于把各系统的设计案落到统一的数据对象和结果包。

它不是最终数据库 schema，但可作为 Godot 资源、JSON、SQLite 表结构或 GDScript class 的起点。

---

## 1. 总体原则

1. 客户端提交意图。
2. 服务端校验意图。
3. 服务端生成小时级时间线。
4. 系统只输出结果包。
5. S1 合并结果包并回写状态。
6. 所有高价值变化写日志。
7. 存档保存状态，不保存临时 UI。
8. 文案与规则分离。
9. 玩家最小同步单位使用 `turn_id`。
10. 世界绝对时间使用 `world_day / world_hour`。

```text

  component_type: String,       # fragment / chapter
  method_lineage_tag: String,
  component_group: String,
  completion_weight: int
}

MethodCarrierItem {
  carrier_type: String,         # complete_dao_method / complete_technique_method
  method_template_id: String,
  learn_requirements: Dictionary,
  copy_or_bind_state: String
}
```

高价值完整道功载体默认使用 `ItemInstance`；普通低阶法门完整载体可按内容需要使用 `ItemStack`。
