# 系统设计｜修炼加成设施

## 1. 设计定位

修炼加成设施是资源槽附属设施中的修炼与突破支持类设施，负责把节点灵气、资源槽规模、设施状态、维护投入、权限和资源消耗转化为修炼、闭关、突破或修炼资源加工的系统输入。

本文只维护修炼房、静室、聚灵阵、洞府维护设施、灵泉维护、灵液收集、修炼资源加工、突破场地和护法阵等修炼相关设施的规则边界。资源槽通用字段由《资源槽详细设定》（`../07_地图节点设计/02_资源槽详细设定.md`）维护；一槽一设施类别、设施生命周期和改造规则由《资源槽附属设施通用规则》（`03_资源槽附属设施通用规则.md`）维护。

## 2. 当前结论

1. 修炼加成设施必须附属于合法资源槽或专题文档允许的隐藏层承载记录，不提供无来源全局倍率。
2. 修炼加成设施效果进入 `RealmInputFitMatrix`、`ResourceEffectBalance`、`NodeRealmSupport` 和 `SectSupportBalance` 等修炼数值输入，但不能绕过行动时间、资源输入、主修道功和角色状态压力。
3. 同一个资源槽只能承载一类设施；修炼房、聚灵阵、灵田、传送阵、市场、宗门行政设施等不能在同一资源槽内无成本叠加。
4. 灵石到聚灵石的加工，以及聚灵石作为高密度灵气物品的消耗和资源输入口径，统一由《灵石及聚灵石》（`../05_物品设计/05_灵石及聚灵石.md`）维护。

## 4. 核心循环或触发入口

修炼加成设施由角色建设、宗门建设、洞府分配、资源槽维护、旧设施接管、事件结果或机会窗口生成。

运行循环：

```text
选择资源槽或合法承载点
→ 校验资源槽类型、占用状态、可建设施类别、权限和维护来源
→ 建设、接管、升级、维护或停用修炼相关设施
→ 修炼、闭关、突破或加工行动读取设施状态
→ 输出修炼环境修正、席位、护法条件、资源加工结果、设施变化和资产流水
```

执行修炼、闭关或突破前必须读取设施当前状态。若设施停摆、维护不足、污染、被封锁、权限失效或资源槽被改造，行动应重新校验，而不是继续沿用入队时的旧加成。

## 5. 规则与状态

MVP 可先保留以下修炼相关设施类别：

| 设施类别 | 规则口径 |
| --- | --- |
| 修炼房 / 静室 | 常规修炼席位和闭关场地，主要读取 `aura_node` 或模板允许的 `space_site` |
| 聚灵阵 | 可作为修炼房内部能力或同类设施能力，不另占第二类设施类别 |
| 洞府维护设施 | 个人洞府本身是 `personal_cave`；只有模板声明闭关、聚灵或修炼席位能力时才计入修炼加成设施 |
| 灵泉维护 / 灵液收集 | 只在 `material_deposit`、`blessed_land`、`special` 或模板允许资源槽上提供修炼资源辅助 |
| 修炼资源加工设施 | 承担灵石到聚灵石等修炼资源前置加工，不决定灵石 / 聚灵石的物品规则 |
| 突破场地 / 护法阵 | 提供突破准备、场地稳定、护法和风险缓冲条件 |

附属规则：

1. 一个 `aura_node` 若已用于灵田、传送阵、市场、宗门行政设施或其他设施类别，不能同时承载修炼房、静室或聚灵阵。
2. 自然资源槽若已被个人洞府、宗门洞府区或普通藏宝占用，不能继续建设修炼房、静室或聚灵阵；必须先完成清理、迁移、拆除或事件处理。
3. 修炼房可以内含聚灵阵能力，但仍属于同一修炼设施类别，不额外绕过一槽一设施类别约束。
4. 修炼加成必须来自节点灵气、资源槽规模、设施规模、设施等级、维护状态、资源消耗、权限、角色状态和事件结果。
5. 洞天福地本体只允许受限修炼、参悟、保全、封禁、突破场地或入口维护类操作；若洞天内部存在常规建设空间，应另记子资源槽。
6. 修炼资源加工设施只提供加工入口和设施状态，灵石、聚灵石、消耗和物品流向仍读取物品与经济文档。

## 6. 资源槽、角色、修炼与事件接口

修炼加成设施优先读取以下资源槽：

| 资源槽类型 | 修炼设施口径 |
| --- | --- |
| `aura_node` | 常规修炼设施的主要承载位，可提供环境灵气输入、闭关席位和聚灵阵基础 |
| `material_deposit` | 只有灵泉、灵液池等模板允许时，才提供修炼资源辅助或炼丹辅助 |
| `space_site` | 可承载洞府、仓储、防护、隐蔽和休整设施；修炼加成弱于专门灵气节点，除非附属设施明确投入资源 |
| `blessed_land` | 可作为参悟、突破或特殊修炼地点，但只能使用保全、封禁、参悟、突破场地等受限操作 |
| `opportunity_site` / `special` | 只在机会窗口或定制模板允许时提供临时修炼、突破或护法机会 |

人工常规扩展出的 `aura_node` 可以用于建设修炼房、静室或聚灵阵类设施。MVP 规则为：

1. 该资源槽无特殊属性，不提供特殊相性、特殊突破机会或稀有变体。
2. 该资源槽灵气浓度低于当前地图节点平均灵气浓度。
3. 该资源槽规模可设定，影响席位、维护成本、设施规模上限和常规修炼环境输入。
4. 节点资源槽总数量在 MVP 暂不限制，但每个修炼设施仍按自身规模、维护、人力和资源消耗结算。

接口边界：

| 接口 | 读取或输出 |
| --- | --- |
| 修炼玩法 | 读取设施可用状态、席位、环境灵气输入、维护状态和权限 |
| 突破玩法 | 读取突破场地、护法阵、稳定度、风险缓冲和资源准备 |
| 角色状态 | 读取角色境界、主修道功、身体状态、负面状态、权限和队列行动 |
| 宗门系统 | 读取建设权、维护投入、洞府分配、护法安排和资源调拨 |
| 经济与库存 | 记录建设材料、维护成本、聚灵石加工输入输出和资产流水 |
| 事件系统 | 可改变设施状态、污染、损坏、争夺、封锁、机会窗口或传闻 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `facility_class = cultivation` | 修炼加成设施类别 |
| `facility_template_id` | 修炼房、静室、聚灵阵、灵液池、护法阵等模板 |
| `resource_slot_id` | 承载该设施的资源槽 |
| `supported_actions` | 支持修炼、闭关、突破、护法或加工等行动类型 |
| `seat_capacity` | 可同时提供的修炼或闭关席位 |
| `facility_scale` / `facility_level` | 设施规模与等级 |
| `maintenance_state` | 正常、维护不足、污染、超载、封禁、离线等状态 |
| `aura_input_policy` | 节点灵气、资源槽灵气、聚灵阵和资源输入的读取方式 |
| `resource_input_refs` | 聚灵石、丹药、灵液、维护材料或宗门库存输入 |
| `permission_policy` | 使用、维护、升级、拆除、收益和进入权限 |
| `fit_tags` | 境界、功法、属性、相性或特殊修炼适配标签 |
| `result_package_refs` | 建设、维护、使用、损坏、停摆和收益结果包引用 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 可展示设施名称、所在节点或洞府、可用状态、席位、维护摘要、权限、适配境界、资源消耗、风险提示、预计修炼环境摘要和不可用原因。

普通 UI 不展示原始倍率堆叠、完整 `RealmInputFitMatrix`、隐藏层真实归属、其他玩家未公开设施、未发现资源槽、`hidden_world` 或 `debug_only` 信息。公式追踪、调参倍率和详细日志只进入 Debug、QA 或回放分析。

## 9. MVP 范围

MVP 应实现：

1. 修炼房 / 静室、聚灵阵、修炼资源加工设施、突破场地 / 护法阵的最小设施类别。
2. 修炼加成设施绑定合法资源槽，并遵守一槽一设施类别。
3. 设施状态、维护状态、权限、席位、资源输入和结果包记录。
4. `aura_node`、模板允许的 `space_site`、受限 `blessed_land` 与特殊机会资源槽的读取口径。
5. 修炼、闭关、突破和聚灵石加工行动读取设施状态。

MVP 不实现：

1. 同一资源槽叠加多类修炼或生产设施。
2. 无来源全局修炼倍率。
3. 人工常规扩展制造洞天福地、特殊相性、特殊突破机会或稀有变体。
4. 未记录维护成本和资产流水的长期设施收益。

## 10. 验收约束

1. 修炼加成设施必须能追溯到资源槽、设施实例、维护投入、资源消耗或事件结果。
2. 已被其他设施、个人洞府、宗门洞府区或普通藏宝占用的资源槽，不能直接建设修炼加成设施。
3. 聚灵阵不能作为绕过一槽一设施类别的第二设施叠加在修炼房之外。
4. 修炼、闭关和突破执行前必须重新校验设施状态、权限、资源输入和角色状态。
5. 设施效果进入修炼数值输入，但不能替代行动时间、主修道功、资源输入或角色状态压力。
6. 设施变化、维护成本、加工输入输出和异常停摆必须写入结果包、日志或资产流水。
