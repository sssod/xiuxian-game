# 行动指令设计

## 1. 当前结论

行动指令是玩家提交给服务端的意图，不是客户端直接改状态。服务端校验并写入资源消耗、位置变化、行动合法性、事件触发、角色状态、宗门库存、节点状态、日志与存档。

## 2. 指令预输入修正案

指令预输入不是自动化脚本系统，而是允许玩家把“当前已经合法的普通指令”提前放入短队列。队列为空或校验失败时，系统使用低收益兜底行动维持角色存在，并降至 N1 等待玩家补充新指令。

核心边界：

```text
预输入 = 提前排队已经合法的普通指令
不是 = 条件脚本、自动推导、未来资源规划、通用事件预案、追求全程高速推进
```

## 3. MVP 指令字段

```yaml
command_id: string
command_type: cultivate | meditate | rest | heal | craft | travel | visit | apply_resource | breakthrough | managed
subject: player_id
target: string | null
duration_hours: number | null
selected_items: list
location_requirement: string | null
created_at_game_time: datetime
status: queued | running | completed | skipped | failed
```

执行前校验：

```yaml
validation:
  passed: boolean
  failed_reason: string | null
```

失败兜底：

```yaml
fallback:
  action: meditate | rest
  reason: queue_empty | validation_failed | invalid_location | insufficient_resource | blocked_by_state
  force_speed: N1
```

## 4. MVP 保留

- 当前指令 + 最多 3 条预输入指令。
- 入队时当前合法性校验。
- 执行前再次校验。
- 队列为空 / 校验失败后自动兜底。
- 低风险吐纳，中高风险休整。
- 自动兜底强制降至 N1。
- 闭关三档预案。
- 显式托管行动。
- 大境界突破在当前满足条件时可预输入开启指令。
- 常态事件保留玩家处理权。

## 5. MVP 不做

- if-else 条件脚本。
- “未来满足条件后自动执行”。
- 前置产出和后置消耗的未来推导。
- 通用事件默认策略表。
- 用预输入替代正式战斗、突破挑战和重大事件选择。
