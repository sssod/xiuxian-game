# 核心体验、玩家目标与设计基石

状态：第二批正式定稿
更新日期：2026-05-08
来源主版本：v2.3 calendar_preinput

## 1. 文档定位

本文定义项目的核心体验、玩家身份、MVP 目标和设计基石，用于约束后续系统、数值、UI、事件和内容生产。

本文不承载详细 schema、公式或内容表；实现字段以 `docs/references/glossary-and-field-naming.md`、时间结算以 `docs/systems-design/shared-calendar-room-settlement.md` 为准。

核心体验句：

```text
在共享世界中，用有限注意力和有限行动窗口经营当世修炼、资源、突破与风险，推动个人修为持续攀升；当本世效率不足、路线受限或竞争失位时，以轮回、执念、后手和账本把失败转化为下一次冲击更高境界的资本。
```

显性终极目标：

```text
让玩家个人修为与境界成长到当前设计定义的最高层级。
```

轮回不是玩家目的本身，而是服务修为攀升的跨世手段。它用于修正低效率世代、重构路线、复用信息、布置后手、调整开局，并让死亡或失败不会把长期追求清空。

## 2. 玩家身份

玩家控制的是跨世真灵，不是宗门、国家或固定角色。

```text
真灵 = 跨世身份锚点、真名、轮回账本、执念容量、后手容量与因果痕迹。
当世角色 = 一次生命中的肉身、资质、境界、寿元、身份、关系和资产容器。
```

当世角色承载玩家显性的修为成长。修为、境界、功法掌握、资源、关系和宗门身份首先属于本世角色；它们死亡后大多不默认进入真灵。

真灵承载跨世连续性。它保留轮回账本、失败原因、已知后手、执念容量、因果痕迹和一部分可追踪线索，但不直接等同于“修为目标”，也不默认保存当前修为、当前功法等级、当前背包或当前社会关系。

实现含义：

1. 真灵层记录长期身份锚点、轮回账本、因果痕迹、执念容量和后手索引。
2. 当世角色层记录本世修炼、位置、身份、资产、伤势、寿元、关系和可见性。
3. 玩家界面应让玩家明确自己是在用当世角色冲击更高境界，同时用真灵机制保存复盘、后手和下一世开局资本。
4. 真灵不是稳定数值外挂，不默认直接提高每世修炼效率。
5. 轮回收益应主要表现为更好的下一世初始化、信息复用、后手机会和路线修正，而不是把“下一世”本身写成终局目标。

## 3. MVP 玩家目标

MVP 阶段玩家目标：

1. 让当世角色围绕修为、功法、根基、资源和突破条件持续成长。
2. 通过修炼、资源输入、功法掌握、小境界推进和大境界突破提高个人境界。
3. 在宗门、地图节点、NPC 与事件中争取能提升修炼效率、突破质量和生存余地的机会。
4. 在多人共享世界中围绕节点、资源、窗口、传闻和宗门支持进行间接竞争。
5. 在本世效率低于基准、寿元压力过大、路线受限或主动重构路线时，评估继续修行、冒险冲关、布置后手或轮回。
6. 用轮回账本、执念容量、后手、遗产线索和下一世初始化优势继续服务更高境界追求。

## 4. 玩家主循环

MVP 核心循环：

```text
查看世界日历、速度和地图机会
→ 判断当世角色状态、位置、资源与风险
→ 编辑当前指令与后续短队列
→ 服务器按 hour_tick 推进行动、宗门 AI、节点和事件
→ 处理个人事件、正式交锋、突破挑战或公共暂停
→ 查看个人日志、公开日志、结果包摘要和阶段回放
→ 调整行动、承担失败，必要时评估继续修行、布置后手或轮回重入世界
```

该循环的压力来自共享连续世界日历，而不是固定计划表或玩家回合。

玩家需要持续判断：

```text
当前世界速度；
当前执行指令；
后续 1～3 条预输入；
事件选择 gap；
突破挑战轮；
节点机会窗口；
宗门 AI 行动；
寿元与伤势；
竞争者的间接影响。
```

## 5. 设计基石

| 基石 | 当前口径 | 实现影响 |
| --- | --- | --- |
| 修为主线 | 玩家显性终极目标是个人修为与境界攀升到最高层级 | 修炼、资源、突破、宗门支持、地图机会和轮回判断都应服务境界推进 |
| 跨世主体 | 真灵是跨世主体，当世角色是一次生命的载体 | `TrueSpiritState` 与 `CharacterState` 必须分层 |
| 轮回手段 | 轮回是低效率修正、路线重构、信息复用和后手兑现机制，不是终局目标 | 转世收益应进入初始化、账本、后手和可解释路线修正 |
| 连续时间 | 世界时间连续推进，`hour_tick` 是结算基础 | 所有状态变化应落到 `world_day / world_hour` |
| 服务端权威 | 玩家提交 intent，服务端权威校验与结算 | 客户端不直接确认状态变更 |
| 短队列 | 玩家使用 `Command / CommandQueue`，当前指令 + 最多 3 条预输入 | 队列减少机械操作，不承担脚本计划 |
| 关键选择 | 事件、正式交锋和突破挑战保留玩家处理权 | 普通队列不替代事件选项或 B1 轮内策略 |
| 兜底与托管分离 | 自动兜底防冻结；显式托管表达主动低关注 | 两者来源、F1 资格和日志必须分离 |
| 突破高潮 | 正式战斗与突破挑战使用 `FormalEncounterState` | B1 每轮等于 1 游戏小时 |
| 宗门定位 | 宗门是组织资源平台，由宗门 AI 演化 | 玩家通过身份、贡献、申请和事件间接影响 |
| 资源输入 | 丹药、灵材、符箓绑定行动或事件选项 | 使用 `ActionResourceInputBinding` 与 `ActiveResourceEffect` |
| 复盘可信 | 日志、存档、结果包和回放能复盘关键状态变化 | 使用 `TimelineReplay` 而不是回合报告 |

## 6. 行动决策深度

行动决策的深度来自短期取舍，而不是复杂未来脚本。

玩家每次安排行动时应面对：

```text
当前位置是否安全；
当前资源是否值得投入；
功法是否匹配当前目标；
后续队列是否稳健；
是否主动显式托管；
是否继续推进高风险机会；
是否在突破中消耗关键资源；
是否暴露身份、后手或关系；
是否为了短期收益牺牲后续境界上限、后手安全或下一世开局资本。
```

队列只承担短期安排。玩家不能把复杂未来条件写成自动化计划，关键选择仍由事件、交锋或玩家即时处理。

## 7. 修炼与突破体验

修炼不是简单填经验条。它是玩家将地点灵气、资源输入、宗门支持、功法效率、角色资质、世界小时与风险状态共同转化为修为、功法掌握、根基质量和境界机会的过程。它是显性成长主线，而不是轮回系统的附属产物。

修炼结果受以下因素影响：

```text
角色资质；
主修功法；
MethodState 掌握度；
节点 aura_profile；
设施与宗门支持；
ActionResourceInputBinding；
ActiveResourceEffect；
伤势、心魔、经脉压力；
world_hour 兼容结算。
```

突破不是概率按钮。大境界突破由准备期、开启突破短指令、B1 突破挑战、轮内资源消耗、结果报告和后续影响构成。

突破体验目标：

1. 准备期体现长期经营。
2. 开启突破体现当前条件与地点判断。
3. B1 挑战体现轮内策略、资源取舍和风险承受。
4. 结果报告体现境界品质、根基变化、消耗、失败标签和轮回账本。

## 8. 失败与转世体验

失败、死亡和转世不是单纯重开，也不是玩家追求的主要目标。它们应把本世冲击更高境界过程中的低效率、路线错误、准备缺口、竞争失位或风险代价，转化为下一世可理解、可利用、可修正的信息和开局资本。

轮回判断应围绕“继续修行是否仍然合理”展开：

```text
当前世代效率是否低于境界段基准；
剩余寿元是否足够支撑下一里程碑；
当前路线是否还能获得适配资源、功法、节点和宗门支持；
继续硬冲、降低品质目标、冒险抢窗口、布置后手或轮回，哪一种更服务更高境界追求。
```

失败与转世链路：

```text
突破失败 / 战斗失败 / 寿元耗尽 / 重大事件失败
→ 本世受损、停滞或死亡
→ 写入 LifeLedger、ReincarnationRecord 和可见传闻
→ 结算后手、遗产、因果痕迹和真灵暴露
→ 生成下一世入口与初始化选择
→ 玩家用更清晰的信息、更合适的开局和更可靠的后手继续冲击更高境界
```

理想玩家感受：

```text
这一世修不上去了，但我知道卡在哪里。下一世我能用更好的资质、路线、位置或后手，更快、更稳地冲到更高境界。
```

## 9. 宗门、世界与多人体验

宗门是组织资源平台，不是玩家直接操控对象。

玩家影响宗门的方式：

```text
身份与职位；
贡献与声望；
资源申请；
支持关键 NPC；
亲自参与任务；
事件结果；
突破、传闻和后手影响。
```

世界不是背景菜单。地图节点、宗门 AI、资源槽、秘境窗口、传闻、可见性和后手层共同构成可演化的沙盒。

多人竞争主要是间接的：

```text
节点资源被先占；
秘境窗口被改变；
宗门库存被申请；
传闻和可见性发生偏移；
NPC 关系和机会窗口变化；
正式交锋进入 B1；
公共事件进入 P0。
```

私人事件不向其他玩家暴露归因。其他玩家只看到中性速度状态、公开日志、可见传闻和地图变化。

## 10. 实现约束

必须保持：

```text
共享连续世界日历；
world_day / world_hour；
hour_tick；
F1 / N1 / B1 / P0；
C1；
Command / CommandQueue；
TimelineReplay；
FormalEncounterState；
SectContinuousActionState；
ActionResourceInputBinding；
ActiveResourceEffect。
```

不得作为 active concept 重新引入：

```text
turn_id；
quarter；
action_slot；
current_quarter；
TurnReplay；
QuarterReplay；
宗门主行动输入；
SectDecisionIntent；
每季度 6 个朔望行动格。
```

裁决：

| 采用方案 | 废弃方案 | 原因与实现影响 |
| --- | --- | --- |
| 核心体验定义为“共享世界中用有限注意力经营当世修炼、资源、突破与风险，推动个人修为持续攀升；轮回把失败转化为下一次冲击更高境界的资本” | 把核心体验定义为“为跨世真灵争取更好的下一世命运” | 后者会在设定层面拔高轮回目标；当前口径要求修为与境界攀升是显性主线，轮回服务主线 |
| 轮回作为效率修正、路线重构、信息复用和后手兑现机制 | 轮回作为终局目标、强制重开门槛或单纯收藏履历 | 轮回价值由当前世代效率、寿元预算、竞争压力和路线规划决定；高效率世代继续修行必须合理 |
| 真灵 / 当世角色分层 | 固定角色或宗门本体 | 支持死亡、转世、后手与长期账本；宗门仍是组织平台 |
| 真灵保存身份锚点、账本、执念容量、后手容量和因果痕迹 | 真灵保存当前修为、当前功法、当前背包和当前社会关系 | 避免转世退化为换皮复活，也避免跨世永久叠加锁死数值平衡 |
| 行动深度来自当前合法短队列与关键事件处理 | 条件脚本、未来资源推导、复杂自动化计划 | UI 和数据结构应强调 `CommandQueue`，避免做脚本编辑器 |
| 突破体验为准备期 + 开启短指令 + B1 挑战 + 报告 | 概率按钮或个人突破多次 P0 | 资源消耗与选择集中在 `FormalEncounterState` 轮内 |
| 复盘使用 `TimelineReplay` | 回合结束报告、`TurnReplay`、`QuarterReplay` | 连续日历下需要记录速度片段、事件、队列变化、B1 轮和结果包 |
