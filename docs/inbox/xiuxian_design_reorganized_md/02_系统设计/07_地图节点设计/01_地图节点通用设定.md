# 系统设计｜地图节点通用设定

## 1. 设计定位

地图节点系统负责维护共享世界中的大尺度空间状态：节点是什么、节点如何随世界时间变化、节点对移动、资源、事件、宗门、NPC、隐藏层和传闻提供什么接口。

地图主单位是地理节点或空间区块。宗门山门、坊市、村镇、传送阵、渡口、关隘、洞府入口、秘境入口等不是节点类型；它们应作为设施、资源槽附属内容、机会窗口、隐藏层、路线条件或状态标签挂载在节点与路线之上。

地图只生成可合并的结果包、日志和回放记录，不直接绕过权威结算改写角色、宗门、库存、经济或战斗状态。

## 2. 当前结论

1. 地图采用有向带权节点图：节点是空间承载单位，路线是节点之间的有向边。
2. 节点类型只描述大尺度地理或空间尺度，不描述建筑、组织、市场、交通点或功能入口。
3. 地图按连续世界时间推进，`world_day / world_hour` 是主时间，`hour_tick` 是地图状态最小结算步。
4. 资源槽、设施、机会窗口、隐藏层、后手、宗门清点和遗留设施都挂载在节点或路线之上，不替代节点本身。
5. 玩家 UI 只能显示其可见层级内的节点、路线、资源槽摘要、风险、机会窗口、宗门影响和传闻。

## 4. 核心循环或触发入口

地图不是静态菜单，而是共享世界中的空间状态机。玩家移动、修炼、探索、资源采集、宗门行动、NPC 行动、事件、秘境窗口、传闻、正式后手、宗门清点和宗门外遗留设施都可以改变节点状态。

地图时间口径：

```text
world_day / world_hour 是地图主时间；
hour_tick 是服务器推进地图状态的最小结算步；
macro_period_id 只用于季节、旬月、资源批次、灾变期等宏观内容标签，不作为玩家回合；
所有节点、路线、资源、可见性和事件窗口变化都必须能写入结果包和回放。
```

每个 `hour_tick`，地图系统根据当前世界状态输出变化结果：

```text
advance_nodes(world):
  for node in node_states:
    regenerate_resource_slots(node)
    update_resource_slot_facilities(node)
    update_risk_level(node)
    update_influence(node)
    check_event_windows(node)
    check_hidden_layers(node)
    write_node_result_packages(node)
```

演化来源包括玩家行动、宗门行动、NPC 行动、资源采集和枯竭、事件结果、后手触发、宏观周期与世界随机状态。

追赶补结算期间只补确定性节点影响，不触发新的随机个人事件、普通机缘或软机会事件。若地图变化属于强制公开节点事件、正式交锋或全局公共决策，应交给房间速度状态处理。

## 5. 地图总状态

`WorldMapState` 是地图运行时主状态。

```yaml
WorldMapState:
  map_id: string
  current_world_day: int
  current_world_hour: int
  current_macro_period_id: string
  node_states: dict[node_id, NodeState]
  route_states: dict[route_id, RouteState]
  active_region_effects: list[RegionEffect]
  resource_budget_refs: list[string]
  rumor_pool_refs: list[string]
  visibility_overrides: dict
```

规则：

1. `current_world_day` 与 `current_world_hour` 必须和房间权威时间同步。
2. 地图系统只输出变化结果，不直接提交最终状态。
3. 地图可生成的结果包括 `node_delta`、`route_delta`、`resource_slot_delta`、`visibility_delta`、`event_window_delta`、`risk_level_delta`、`rumor_entries`、`ledger_entries` 和日志条目。
4. “结果包”指权威结算可合并的状态变化集合；“回放”指按世界时间记录的可审计事件序列。

## 6. 节点运行字段

`NodeState` 记录节点当前运行状态。旧版 `WorldNode` 可作为内容模板名保留，但运行时主字段使用 `NodeState`。

```yaml
NodeState:
  node_id: string
  node_type: mountain_region | valley_region | forest_region | river_lake_region | plain_region | underground_region | ruin_region | secret_realm_region | special_region
  node_scale: area | large_region | pocket_realm
  node_level: int
  display_name: string
  region_id: string
  owner_faction_id: string | null
  controlling_influence: dict[faction_id, number]
  risk_level: low | medium | high | unknown
  aura_profile: object
  resource_slots: list[NodeResourceSlot]
  facility_refs: list[string]
  active_events: list[string]
  active_windows: list[OpportunityWindow]
  visibility_state: object
  hidden_layer_refs: list[string]
  contingency_refs: list[string]
  sect_clearance_refs: list[string]
  remnant_site_refs: list[string]
  route_edge_refs: list[string]
  node_state_tags: list[string]
  cooldown_tags: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `node_type` | 大尺度地理或空间类型，不表达宗门、坊市、传送阵、秘境入口等设施或功能身份 |
| `node_scale` | 节点空间尺度；MVP 默认是可容纳大量资源槽和多类设施的大区域，少数秘境内部节点可使用 `pocket_realm` |
| `node_level` | 节点等级，影响自然资源槽基线数量、资源品级范围、灵气浓度、风险强度和可建设规模上限 |
| `owner_faction_id` | 当前主控制势力；无人稳定控制时为空 |
| `controlling_influence` | 各势力在节点上的影响力分布，是控制权变化的基础 |
| `risk_level` | 节点风险等级，驱动移动提示、自动兜底和托管默认 |
| `aura_profile` | 节点整体灵气密度、品阶、相性、污染、稳定度和修炼修正 |
| `resource_slots` | 节点自然、半自然、空间、灵气、生态或组织控制的广义资源承载位 |
| `facility_refs` | 节点上已存在或可使用的设施索引；设施必须可追溯到合法资源槽或隐藏层承载规则 |
| `active_windows` | 秘境入口、资源名额、节点危机、短期交易、突破护法机会等限时窗口 |
| `hidden_layer_refs` | 未完全公开的隐藏空间、路线、资源、线索、旧洞府、伏笔事件引用 |
| `contingency_refs` | 正式后手记录引用；MVP 主要对应真灵藏宝 |
| `sect_clearance_refs` | 宗门管辖洞府、宗门托管资产或职务资产的清点、锁定和回收记录引用 |
| `remnant_site_refs` | 宗门外个人洞府、普通藏宝、旧洞府线索、失落库存或可开启遗留设施引用 |

`danger_level` 不再作为地图节点字段使用。若旧事件模板中仍出现 `danger_level`，应迁移为节点 `risk_level` 或事件自身的风险描述标签，不能同时作为地图节点的第二套风险字段。

## 7. MVP 地理节点类型

MVP 节点类型只保留地理区块大类。节点功能由 `facility_refs`、`resource_slots`、`active_windows`、`node_state_tags`、控制权和可见性共同表达，不通过 `node_type` 表达。

| 地理类型 | `node_type` | 作用 |
| --- | --- | --- |
| 山脉 / 山域 | `mountain_region` | 宗门山门、洞府、矿脉、灵脉、山道、关隘、传送阵、禁地和隐藏层的常见承载区 |
| 谷地 / 盆地 | `valley_region` | 药谷、灵田、聚落、宗门外据点、妖兽巢穴和资源争夺的承载区 |
| 林野 / 荒原 | `forest_region` | 探索、妖兽生态、灵植群落、野外事件、隐藏路线和普通资源的承载区 |
| 河湖 / 水域 | `river_lake_region` | 渡口、水路、灵泉、湖泽秘境、水产资源和路线封锁的承载区 |
| 平原 / 聚落周边 | `plain_region` | 村镇、坊市、农田、驿道、低到中风险事件和人流交易的承载区 |
| 地下 / 洞窟区 | `underground_region` | 洞府、地窟、矿洞、地下遗迹、藏宝和隐蔽空间的承载区 |
| 遗迹 / 古战场区 | `ruin_region` | 古遗迹、旧战场、破败宗门、历史事件、遗留设施和高风险资源的承载区 |
| 秘境 / 独立空间 | `secret_realm_region` | 少数长期存在、可反复观察、探索和争夺的秘境内部空间；入口本身仍是机会窗口、设施或路线条件 |
| 特殊地理区块 | `special_region` | 剧情异象、世界裂隙、不可归入上列的定制空间 |

宗门山门、宗门大殿、坊市、村镇、传送阵、渡口、关隘、洞府入口等应作为设施或资源槽附属内容挂在上述地理节点中。例如“青云宗山门”应是某个 `mountain_region` 节点中的宗门设施群，而不是 `sect` 节点；“青木坊市”应是 `plain_region`、`valley_region` 或 `mountain_region` 中的市场设施，而不是 `market` 节点。

## 8. 风险、节点等级与灵气

`risk_level` 枚举：

```text
low
medium
high
unknown
```

基础兜底口径：

| `risk_level` | 自动兜底 | 显式托管默认 |
| --- | --- | --- |
| `low` | 吐纳 | 托管吐纳 |
| `medium` | 休整 | 托管休整 |
| `high` | 休整 | 托管休整 |
| `unknown` | 休整 | 托管休整 |

风险等级变化必须写入结果包、个人可见日志或公开地图日志。地图 UI 可以显示中性风险提示，但不得泄露其他玩家私人事件来源。

`node_level` 或等价节点等级由节点模板、区域、控制权、历史演化和特殊事件决定。MVP 阶段节点等级至少影响：

1. 自然生成的资源槽基线数量。
2. 资源槽内资源的基础品级、可波动范围和稀有变体概率。
3. 节点整体 `aura_profile` 的灵气浓度、品质、稳定度、污染和相性权重。
4. 可见风险、机会窗口、资源争夺强度和可建设规模上限的默认区间。

节点等级只决定自然生成资源槽的基线和单槽规模、品级、风险的默认区间。MVP 阶段暂时不设置“节点资源槽总数量上限”；人工扩展后的资源槽数量不因节点等级触发总量硬封顶，但每个资源槽自身的规模、设施类别、维护成本和结算产能仍必须被记录。

`aura_profile` 最少表达：

```yaml
aura_profile:
  aura_density: number
  aura_quality: string
  element_affinity_tags: list[string]
  pollution_tags: list[string]
  stability_tags: list[string]
  cultivation_modifiers: dict
```

灵气只提供修炼环境、资源输入相性、经脉压力、心魔风险、突破准备和事件选择的修正，不直接发放无来源修为。

## 9. 控制权与影响力

节点归属采用“控制权 + 影响力”混合模型。

控制权影响主资源收益权、建设权、驻守权、通行管理权、节点事件优先响应权和宗门 AI 行动目标选择。

影响力影响行动耗时与便利、情报发现率、任务成功率、探索与交易便利、控制权争夺基础、对控制者收益的轻微竞争、传闻可信度与可见性。

控制权变更采用阈值 + 事件模型。玩家不需要逐个节点手动点击接管。可推动节点易主的因素包括玩家探索、驻守、建设、开采、处理节点事件、亲自参与宗门相关个人行动、宗门持续行动、外部宗门或 NPC 压力、后手触发、资源枯竭、路线封锁、灾变或重大事件链。

达到条件后，控制权变化应生成控制权事件或受控 `node_delta`，再由权威结算合并。

## 10. 机会窗口、秘境与临时节点

秘境、资源名额、节点危机、短期交易、突破护法机会等限时内容使用 `OpportunityWindow`。

```yaml
OpportunityWindow:
  window_id: string
  node_id: string
  starts_world_day: int
  starts_world_hour: int
  ends_world_day: int
  ends_world_hour: int
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  entry_requirements: list[object]
  event_template_refs: list[string]
  contest_policy: string
```

规则：

1. 普通秘境入口作为节点上的机会窗口或入口设施表达。
2. 少数长期存在、可以被反复观察和争夺的著名秘境，其内部空间可作为 `secret_realm_region` 节点；秘境入口本身仍是机会窗口、入口设施、隐藏层或路线条件。
3. 窗口开启、关闭、进入、错过、被争夺或被后手影响，都必须写入结果包和回放。
4. 玩家进入机会窗口必须通过个人行动、事件选择或正式交锋入口完成，地图不能直接修改角色状态。

秘境内部或短期空间可使用临时节点：

```yaml
TemporaryNode:
  temp_node_id: string
  parent_node_id: string
  created_world_day: int
  created_world_hour: int
  expiry_rule: object
  access_rules: object
  event_chain_refs: list[string]
  cleanup_rules: object
```

## 11. 隐藏层、后手、清点与遗留设施

隐藏层是地图上的信息与空间承载层，不是后手、宗门清点、遗留设施或库存本身。

隐藏层状态：

```text
unknown → rumored → located → partially_revealed → revealed → resolved
```

隐藏层可承载隐藏资源、旧洞府、普通藏宝、真灵藏宝位置、线索、秘境入口、伏笔事件、前世痕迹和隐藏路线。

承载规则：

1. 个人洞府和普通藏宝可以挂在节点隐藏层，不占用资源槽，也不读取资源槽灵气收益；其隐蔽、防御、维持和开启条件由隐藏层、阵法、线索和事件记录决定。
2. 真灵藏宝只能挂在节点隐藏层，不能挂在自然资源槽、人工扩展资源槽、洞天福地 / `blessed_land`、洞天内部子资源槽、洞府设施或普通藏宝设施上。
3. 真灵藏宝所在隐藏层可以与普通洞府线索、旧洞府线索或其他隐藏内容同处一个节点，但必须有独立 `ContingencyRecord` 或真灵藏宝记录，避免被宗门清点、普通藏宝取出或资源槽改造流程误处理。

当前不再保留旧版把无主遗留物并入遗产的 active 设定。死亡、转世、失踪、洞府失守、组织接管或事件后的资产去向，在地图承载上拆成三类：

| 类型 | 地图承载方式 | 资产规则 |
| --- | --- | --- |
| 宗门个人洞府清点层 | 节点设施、宗门管辖状态、宗门清点事件或宗门清点记录 | 玩家转世前留在宗门管辖个人洞府中的普通库存，可由宗门锁定、清点并回收；它不是正式后手，也不是新世角色自动继承物资 |
| 宗门外个人洞府 / 普通藏宝层 | 自然资源槽、节点隐藏层、洞府设施、普通藏宝记录、开启条件和争夺事件 | 不进入宗门清点回收，不随转世自动进入宗门库存或新世行囊；满足钥匙、功法、线索、位置、事件条件或破阵结果后才能进入或取出，且可能被其他角色提前打开 |
| 真灵藏宝层 | 正式后手记录、真灵藏宝记录、目标节点和隐藏层位置 | MVP 阶段的正式后手藏物形态；绑定同一真灵，可跨世感应和开启；受设置数量和单个容量限制；MVP 阶段不展示被他人搬空、损坏或移动 |

后手、清点和遗留设施的地图规则：

1. 后手必须有位置或明确目标引用，不能只有抽象描述。
2. 后手创建、触发、失败、争夺和发现必须写入日志、轮回账本、结果包和回放。
3. 正式后手失效必须有原因链，例如节点被占、资源被采尽、宗门清查、NPC 死亡、竞争者发现、世界事件破坏、触发条件被改变、目标资产被转移、隐藏路线被封锁或机会窗口关闭。
4. 宗门清点只处理宗门管辖洞府、宗门托管资产、职务资产或宗门发放但未私有化的资产，不处理宗门外个人洞府、普通藏宝或真灵藏宝。
5. 宗门外遗留设施只通过钥匙、功法、线索、位置、事件条件、破阵或争夺事件处理，不生成遗产实体。
6. 高风险后手回收必须由玩家明确行动或事件选择推动，自动兜底和显式托管不得主动回收、暴露、移动或销毁核心后手。

## 12. 可见性与传闻

地图可见性使用统一层级：

```text
private_player：单个玩家、真灵或当前角色可见；
known_to_party：当前事件、队伍、临时协作对象或授权对象可见；
sect_visible：宗门权限范围内可见；
rumor_visible：作为传闻、模糊信息、延迟信息或不完整情报可见；
public_world：公共世界信息，可进入公开地图或世界摘要；
hidden_world：世界真实状态记录，玩家不可直接看到；
debug_only：调试、审计和开发工具可见。
```

玩家 UI 只显示其可见层级内的信息。不得显示其他玩家私人事件归因、隐秘局部时停来源、未公开突破选择、隐藏后手真实归属或 `debug_only` 信息。

公开地图变化应使用中性描述，例如：

```text
黑石岭驻守加强。
云麓山道近日妖兽踪迹增多。
青木谷灵气波动，疑有秘境窗口。
坊市筑基资源短缺。
```

传闻可以模糊、延迟、不完整，不等同于全知世界日志，也不能泄露隐藏真相引用。

## 13. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `WorldMapState.current_world_day` / `current_world_hour` | 地图主时间，必须与房间权威时间同步 |
| `NodeState.node_type` | 地理或空间类型，不表达设施、组织或功能入口 |
| `NodeState.node_level` | 节点等级，提供自然资源槽、灵气、风险和规模上限的基础区间 |
| `NodeState.risk_level` | 节点风险等级，驱动移动提示、兜底和托管 |
| `NodeState.aura_profile` | 节点整体灵气环境，供修炼、突破、事件和资源槽读取 |
| `NodeState.hidden_layer_refs` | 节点隐藏层引用，承载隐藏空间、后手、线索和隐藏路线 |
| `NodeState.active_windows` | 节点当前机会窗口引用 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 14. UI 展示边界

主界面地图应稳定展示：

```text
当前位置；
可见节点；
可见路线；
节点风险；
资源槽摘要；
宗门影响；
秘境 / 机会窗口；
公开传闻；
队列目标路线；
当前节点可用行动入口。
```

普通 UI 不显示其他玩家私人事件归因、隐藏后手真实归属、隐藏层内部真实结构、未公开事件来源和 `debug_only` 字段。

## 15. MVP 范围

MVP 应实现：

1. `WorldMapState`、`NodeState`、节点等级、风险等级、灵气概况和可见性层级。
2. 大尺度地理节点类型，不使用宗门、坊市、村镇、传送阵、关隘或秘境入口作为节点类型。
3. 节点控制权与影响力的最小变化记录。
4. 机会窗口、隐藏层、传闻和地图变化结果包。
5. 世界小时演化、确定性追赶补结算和回放记录。

MVP 不实现：

1. 节点级资源槽总数量硬封顶。
2. 无来源全局灵气倍率或无来源修为发放。
3. 无位置的后手、藏宝或遗留设施。
4. 公开泄露其他玩家私人事件归因的全知地图。

## 16. 验收约束

1. 地图状态使用 `current_world_day / current_world_hour`。
2. `node_type` 只使用大尺度地理或空间类型。
3. `risk_level` 正确影响自动兜底和显式托管默认。
4. 节点 `aura_profile` 能被修炼和突破准备读取。
5. 宗门行动能改变节点影响、风险、资源槽、附属设施、路线或机会窗口。
6. 机会窗口有开始、结束、可见性、准入条件和争夺策略。
7. 后手只在有明确世界变化或触发条件时检定，不做无原因随机失效。
8. 地图 UI 不显示其他玩家私人事件归因。
9. 地图变化进入结果包和回放。

## 18. 冲突裁决与废弃口径

| 旧口径或冲突点 | 当前采用口径 | 裁决原因 |
| --- | --- | --- |
| `WorldNode` 作为唯一节点运行结构 | 运行态使用 `NodeState`，`WorldNode` 仅可作为旧模板名 | 节点需要记录时间、可见性、事件窗口、路线、后手和资源状态 |
| 宗门山门、城镇、村庄、坊市、传送阵、关隘、秘境入口作为节点类型 | 节点类型只保留山脉、谷地、林野、水域、平原、地下、遗迹、秘境空间等地理或空间区块；功能对象改由设施、资源槽、机会窗口、隐藏层、路线条件或状态标签表达 | 节点应是可容纳大量资源槽和设施的大尺度空间，建筑、组织、市场和入口不应与地理节点混为一层 |
| `danger_level` | 使用 `risk_level` | 风险字段需要直接驱动兜底、托管、移动提示和 UI 摘要 |
| “前世后手节点”作为独立节点类型 | 使用隐藏层、正式后手记录、宗门清点记录、遗留设施记录或洞府 / 藏宝设施承载 | 后手、清点、藏宝和洞府是挂载内容，不应混成节点类型 |
| 旧版无主遗留物作为遗产 active schema | 不采用；拆成宗门清点记录、宗门外遗留设施记录、正式后手记录 | 避免把宗门清点、宗门外洞府和真灵藏宝混成一种跨世继承规则 |
| 宗门个人洞府、宗门外洞府、普通藏宝、真灵藏宝混作同一种遗产 | 按宗门清点、可开启遗留设施、正式后手三类分开 | 解决资产去向、跨世继承、宗门回收和多人竞争规则冲突 |
| 正式后手被随机磨损、年久失修或无日志失效 | 正式后手失效必须有原因链；MVP 真灵藏宝不展示被他人搬空、损坏或移动 | 轮回体验需要可信、可复盘，且不能把正式后手降级为普通随机宝箱 |
| 推荐阶段作为硬锁 | 推荐阶段只做内容筛选、提示和风险预期 | 玩家可以冒险，但系统必须展示风险和后果 |
| 地图公开所有节点真相和私人归因 | 地图按可见性层级展示，中性化公开后果 | 多人间接竞争依赖信息边界，私人事件不能被地图泄露 |
