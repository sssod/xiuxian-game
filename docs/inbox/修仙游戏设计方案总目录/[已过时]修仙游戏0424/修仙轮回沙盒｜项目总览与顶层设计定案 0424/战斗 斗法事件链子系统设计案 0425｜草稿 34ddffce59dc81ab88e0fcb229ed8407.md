## 1. 背景与上位约束

### 1.1 战斗定位

战斗 / 斗法不是独立复杂战棋、实时操作或高频刷怪系统，而是高风险事件链中的一种轻量结算框架。

它服务于：

- 移动途中遭遇。
- 节点危机。
- 秘境遭遇。
- 宗门任务。
- 突破外扰。
- 护法失败后的直接冲突。
- 资源争夺事件。
- 少量剧情性切磋或死战。

### 1.2 与 S3 的关系

战斗发生在季度结算阶段。

标准关系为：

```
S3 结算时间轴推进
→ 某 tick / 某节点 / 某路途段触发战斗事件
→ 当前结算暂停
→ 进入战斗 / 斗法事件链
→ 生成战斗结果包
→ 回写 S3 / 父事件链
→ 根据结果继续原计划、消耗剩余行动格、强制中断、改变位置、进入重伤 / 死亡 / 转世等状态
```

S3 只负责提供：触发位置、触发 tick、剩余行动格、当前行动状态、暴露上下文、托管状态、季度计划上下文。

战斗系统负责内部指令对抗和结果输出。

### 1.3 与角色模型的关系

战斗作用于本世的“身躯与灵魂”层，而不是直接作用于真灵层。

战斗可以改变：

- 当前生机。
- 当前元气。
- 当前神念。
- 伤势。
- 道伤。
- 疲惫。
- 心神动摇。
- 随身物品。
- 法宝状态。
- 已学术法熟练度。
- 事件结果。
- 位置与行动计划。

通常不直接改变：

- 真灵强度。
- 执念容量。
- 转世初始化选择。
- 已定正式后手。

严重战斗失败可以通过死亡、神魂重创、后手暴露、因果加重等事件结果间接影响轮回系统，但必须由父事件链或死亡 / 转世系统处理。

### 1.4 MVP 多人边界

MVP 不以玩家间直接斗法为核心验证项。

战斗系统第一版优先支持：

- 玩家 vs NPC。
- 玩家 vs 抽象敌方小队。
- 玩家 + 护法修正 vs 外扰。
- 宗门行动 / 节点事件中的抽象战斗结果。

玩家之间直接斗法、强 PvP、离线袭击、围杀转世角色、破坏他人突破，不进入 MVP 核心范围。

## 2. 设计目标

### 2.1 玩家体验目标

战斗应提供的是“预判、克制、消耗管理和后果承担”，而不是长时间操作。

理想体验：

```
我根据敌人的战斗风格、自己的资源状态和当前事件目标，预先排出一组指令。
如果判断正确，我用较低消耗化解威胁，或者抓住对方空档建立优势。
如果判断错误，我会在错误的交锋格里承受明显损失。
```

### 2.2 系统目标

战斗系统需要满足：

1. 能嵌入 S3 统一结算，不拖成独立玩法。
2. 能承载生机 / 元气 / 神念三条持久属性。
3. 能复用功法、术法、法宝、符箓、道具等来源。
4. 能产生可解释结果，而不是纯随机胜负。
5. 能通过配置支持不同战斗目标和结束条件。
6. 能为突破、节点事件、宗门任务、移动遭遇提供统一接口。
7. 能在 MVP 中低成本实现，并保留后续扩展空间。

## 3. 战斗资源：生机 / 元气 / 神念

### 3.1 三条属性条

角色有 3 条战斗相关属性条：

| 显示名 | 暂定含义 | 主要承载 |
| --- | --- | --- |
| 生机 | 生命、健康、肉身完整度 | 受伤、濒死、肉身崩溃、普通攻击后果 |
| 元气 | 法力、气力、可支配能量 | 术法消耗、法宝驱动、持续战斗能力、疲惫 |
| 神念 | 灵魂、神识、心神稳定 | 神魂攻击、幻术、心魔、操控、精神崩溃 |

三者都是角色持久状态，不是战斗内临时资源。

### 3.2 持久性规则

战斗开始时，读取角色当前状态：

```
当前生机 / 生机上限
当前元气 / 元气上限
当前神念 / 神念上限
```

战斗结束后，不自动恢复到满值。

战斗造成的消耗和伤害回写角色状态，并由后续系统决定恢复方式：

- 休整。
- 疗伤。
- 丹药。
- 宗门医治。
- 闭关恢复。
- 特殊功法调息。
- 转世结算。

### 3.3 属性损失类型

建议区分三类变化，便于解释和结算：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 消耗 | 主动使用指令支付的成本 | 施法消耗元气，催动禁术消耗神念 |
| 伤害 | 被对方指令或事件造成的削减 | 剑伤削减生机，魂刺削减神念 |
| 状态封锁 / 扰动 | 不一定立刻削减当前值，但影响使用效率 | 元气紊乱、神念震荡、经脉阻滞 |

战斗结束条件默认只统计“伤害”造成的削减，不统计主动消耗。特殊战斗规则可以例外。

### 3.4 生机归零

生机归零不必在所有战斗中都等于死亡。

根据战斗规则可解释为：

- 切磋：重伤倒地，战斗立即结束。
- 任务战：失去行动能力，事件失败或被救回。
- 死战：肉身死亡，进入死亡 / 转世流程。
- 突破外扰：护法失败或本体受创，回到突破事件链处理。

### 3.5 元气归零

元气归零通常不直接结束战斗，但会严重限制指令可用性。

可能结果：

- 无法使用大多数术法。
- 法宝驱动失败。
- 防御质量下降。
- 只能使用低阶基础指令。
- 后续行动格中进入疲惫或元气枯竭状态。

特殊战斗可以将“元气耗尽并无法继续行动”设为失败条件，但默认不这么做。

### 3.6 神念归零

神念归零代表心神崩溃、神识受创或魂魄失守。

根据战斗规则可解释为：

- 切磋：神念被震散，判负。
- 幻境 / 心魔：意志失守，事件失败。
- 神魂死战：魂魄重创或身死转世。
- 突破外扰：心魔压制突破，返回 S4 生成失败标签。

神念系统可以先在数据层存在，M0 新手阶段 UI 可隐藏或弱化展示，等玩家接触修行、神识、术法后逐步显性化。

## 4. 战斗单位：指令

### 4.1 指令定义

战斗中可用的一切主动战斗行为统一称为“指令”。

指令来源包括：

1. 随身携带的法宝技能。
2. 消耗道具，例如符箓、丹药、阵盘、一次性护符。
3. 已学习的术法 / 神通。
4. 功法修炼后解锁的基础招式或被动转化行为。
5. 通用基础指令，例如防守、闪避、观察、调息、逃遁。

### 4.2 指令基础字段

建议数据层采用抽象字段，不绑定具体修仙包装。

```
CombatCommand {
  id
  display_name_key
  source_type            // learned_skill / artifact_skill / consumable / basic / event_special
  command_type           // attack / defense / buff / recovery / control / escape / special
  tags                   // sword, water, body, soul, defense, movement, healing 等
  target_bar             // vitality / energy / mind / mixed / none
  resource_cost          // 生机 / 元气 / 神念 / 道具 / 法宝耐久等
  base_power_profile
  counter_profile
  duration
  max_uses_per_battle
  slot_restriction
  event_flags
  ai_usage_hint
}
```

### 4.3 指令来源与显示

战斗开始时，系统根据角色当前状态生成“本场可用指令列表”。

可见来源：

- 随身携带且当前可用的法宝。
- 背包中可即时使用的战斗道具。
- 当前已掌握并符合条件的术法 / 神通。
- 当前事件授予的特殊指令。
- 通用基础指令。

资源不足的指令建议仍可显示，但标记为“当前资源不足”，便于玩家理解自己为什么不能使用。

### 4.4 指令消耗

默认规则：

- 大多数指令消耗元气。
- 消耗道具指令额外消耗对应道具。
- 法宝指令可以消耗元气、法宝耐久或法宝内置充能。
- 神魂类术法可以消耗神念。
- 禁术、血祭、燃命类指令可以消耗生机。

高风险指令如果消耗生机或神念，UI 必须给出强提示。

### 4.5 法宝可用性与被动生效

战斗系统不采用“装备栏 / 换装备 / 换法宝”的概念。

只要法宝处于角色随身携带范围内，并且满足当前战斗规则、状态、权限、距离或驱动条件，就可以进入本场可用指令来源。

法宝分为两类效果：

| 类型 | 规则含义 | 示例 |
| --- | --- | --- |
| 主动型法宝 | 提供可填入交锋格的主动指令 | 飞剑斩击、宝镜照魂、护体钟罩 |
| 被动型法宝 | 不占用交锋格，满足条件时提供持续或触发式修正，但可能因此受损 | 护心玉抵消一次神念伤害并产生裂纹，避尘珠降低毒雾影响并损耗灵性 |

被动型法宝不是免费常驻护盾。它可以自动或条件式生效，但只要它在战斗中承担了防护、抵消、转移、镇压、预警、抗性或替角色承受后果，就可以进入法宝状态变化判定。

被动法宝可能受损的来源包括：

- 被动效果触发时消耗耐久、灵性或充能。
- 替角色抵消生机 / 元气 / 神念伤害。
- 抵抗控制、毒雾、幻术、心魔、封禁等状态。
- 承受敌方针对法宝、护体灵光、随身宝物的破坏类指令。
- 在高风险事件中被环境、阵法、秘境规则或突破外扰波及。

设计理念是：修仙成长强调资源积累与资源消耗，而不是受限于有限装备栏位。

玩家可以积累多件法宝、符箓、道具与术法，但战斗中每个战斗回合只有 5 个交锋格，因此主动型法宝数量过多不会线性转化为战斗输出。真正的限制来自：

- 指令格数量有限。
- 元气 / 神念 / 生机消耗有限。
- 法宝耐久、充能或使用次数有限。
- 道具会被消耗。
- 指令之间存在克制和时机风险。
- 部分战斗规则可能限制特定来源或高阶资源使用。

法宝可以有状态变化与回收机制，包括：

- 主动使用后受损。
- 被动触发后受损。
- 被针对性破坏后受损。
- 破碎。
- 失去充能。
- 灵性衰减。
- 暂时失灵。
- 战后修复。
- 拆解回收材料。
- 作为后手、遗产或宗门资源重新进入资源循环。

因此，法宝不是装备栏上的固定战力插槽，而是可被投入、消耗、损坏、修复和传承的战斗资源。

## 5. 战斗流程：5 格预输入 + 最多 3 战斗回合

### 5.1 术语约定

为避免与季度行动格混淆，战斗内部建议使用以下术语：

| 术语 | 含义 |
| --- | --- |
| 战斗 | 一次完整斗法事件链 |
| 战斗回合 | 一次 5 格指令预输入与连续结算 |
| 交锋格 | 战斗回合内的 1 个指令格 |
| 交锋 | 双方同一交锋格的指令对抗 |

一场战斗最多进行 3 个战斗回合。该值为常量配置，不写死在规则中。

### 5.2 单个战斗回合结构

```
战斗回合开始
→ 双方查看当前状态、可用指令、事件目标、已知敌方倾向
→ 玩家 / AI 各自向 5 个交锋格填入指令
→ 锁定本战斗回合指令序列
→ 第 1 格交锋结算
→ 检查是否满足战斗结束条件
→ 第 2 格交锋结算
→ 检查是否满足战斗结束条件
→ ...
→ 第 5 格交锋结算
→ 回合结束处理
→ 若未结束且未达到最大战斗回合，进入下一战斗回合
```

每个新战斗回合开始时，玩家可以根据上一轮结果重新排布 5 格指令。

### 5.3 指令填入规则

MVP 建议：每个交锋格必须有指令。

如果玩家不主动选择，系统填入默认基础指令：

```
默认指令：守势 / 观察 / 调息
```

具体默认指令由战斗规则决定：

- 普通战斗：默认守势。
- 逃亡战：默认闪避 / 脱离。
- 教学战：默认观察。
- 突破外扰：默认护持 / 稳定。

玩家填入指令时，UI 应显示己方生机 / 元气 / 神念的预计变化。

该预计变化只基于玩家当前已填入的己方指令序列计算，用于帮助玩家理解本轮主动消耗与自我状态规划。

该预计变化不考虑对方未来指令、敌方伤害、敌方削减元气 / 神念、打断、控制、状态封锁或战斗提前结束等影响，因此不是战斗结果预测。

### 5.4 指令失败兜底

如果某个交锋格结算时，角色已经没有足够资源执行预输入指令，则该指令失败，并替换为兜底指令。

兜底规则：

```
资源不足
→ 指令失手
→ 执行低效守势 / 喘息 / 空过
→ 记录失败原因
```

资源不足可能来自两类原因：

1. 玩家自身预输入序列主动消耗过高，导致后续格资源不足。
2. 对方指令在前序交锋中造成元气 / 神念削减、状态封锁、打断或额外消耗，使原本在 UI 预估中可执行的后续指令变得不可执行。

因此，填入阶段的状态条预计变化只能帮助玩家规划己方主动消耗，不能保证所有后续指令一定成功执行。

这可以让“前面几格过度消耗”与“误判对方压制能力”都成为战斗策略的一部分。

### 5.5 提前结束

每个交锋格结算后都检查结束条件。

如果条件满足，战斗立即结束，不再结算后续交锋格。

## 6. 核心克制关系

### 6.1 三角关系

战斗核心策略是指令克制。

基础三角关系：

```
攻击克制 Buff
防御克制攻击
Buff 克制防御
```

### 6.2 攻击 vs 攻击

同一交锋格中双方都使用攻击指令时，攻击之间互相抵消威力。

默认结算：

```
双方攻击有效威力相减
→ 威力较高方造成差值伤害
→ 威力较低方攻击被压制
```

该规则用于制造“硬碰硬”的简洁判断。后续可允许特殊指令带有穿透、溅射、两败俱伤等例外标签，但 MVP 默认不展开。

### 6.3 防御 vs 攻击

防御克制攻击。

默认规则：

- 防御消耗通常低于攻击。
- 同等修为 / 同等资源层级下，防御有效值通常高于攻击有效值。
- 防御成功时，攻击被吸收、偏转或削弱。
- 攻击超过防御时，只造成溢出伤害。

### 6.4 攻击 vs Buff

攻击克制 Buff。

Buff 指令通常不提供即时防护，因此在该交锋格承受接近完整攻击伤害。

可能结果：

- Buff 成功但角色受伤。
- Buff 被打断。
- Buff 效果降低。
- Buff 成功并附带风险状态。

MVP 规则：普通 Buff 在承受攻击时仍可生效，但如果伤害超过一定阈值，则被打断。具体阈值后续配置。

### 6.5 Buff vs 防御

Buff 克制防御。

防御在没有遭受攻击时，通常无法产生主要价值；Buff 方获得强化、蓄势、恢复、状态调整或后续优势。

### 6.6 防御 vs 防御

双方都防御时，本格通常低收益。

可能结果：

- 双方消耗少量元气。
- 双方维持姿态。
- 允许少量调息。
- 进入僵持标签。

### 6.7 Buff vs Buff

双方都 Buff 时，双方各自获得效果。

这会制造后续交锋格的高风险爆发窗口。

### 6.8 扩展指令的归类

MVP 可先将扩展指令映射到三角关系中。

| 扩展类型 | 默认归类 | 说明 |
| --- | --- | --- |
| 治疗 / 恢复 | Buff | 被攻击克制，克制纯防御 |
| 调息 / 聚气 | Buff | 为后续格恢复元气或提升效率 |
| 闪避 / 逃遁 | 防御或 Escape | 对攻击有效，但不一定能推进胜利 |
| 控制 / 封禁 | 攻击或 Special | 根据目标条决定是攻击神念、元气还是特殊判定 |
| 观察 / 识破 | Buff 或 Special | 增强后续信息，不直接造成伤害 |
| 护法 / 稳定 | 防御或 Special | 突破外扰场景使用 |

## 7. 有效威力计算框架

### 7.1 不在本页定公式

本草稿不定具体数值公式，只定义影响因子和结算顺序。

### 7.2 有效威力来源

指令有效威力可由以下因素共同决定：

- 指令基础威力。
- 角色修为阶段。
- 术法 / 神通熟练度。
- 功法匹配度。
- 法宝品质或状态。
- 消耗资源量。
- 当前生机 / 元气 / 神念状态。
- 道韵与技能标签匹配。
- 地点环境。
- 节点灵气。
- 宗门支持或护法影响。
- Buff / Debuff 状态。
- 敌方抗性或弱点。

### 7.3 目标条

攻击指令需要指定主要目标条。

| 目标条 | 常见来源 | 后果 |
| --- | --- | --- |
| 生机 | 剑诀、拳脚、法宝轰击、妖兽撕咬 | 受伤、流血、重伤、死亡 |
| 元气 | 破气术、封脉、消耗战、阵法压制 | 施法受阻、疲惫、指令失败 |
| 神念 | 神魂术、幻术、心魔、威压 | 心神动摇、失控、精神失败 |
| 混合 | 高阶神通、特殊法宝、事件攻击 | 多条属性同时受影响 |

### 7.4 状态标签

除数值变化外，战斗应输出状态标签，便于事件链解释。

示例：

```
light_wound
heavy_wound
energy_disrupted
mind_shaken
artifact_damaged
poisoned
burning_life
escape_ready
guard_broken
buff_interrupted
```

这些标签可被 S3、S4、S10、S11、死亡 / 转世系统读取。

## 8. 战斗结束条件

### 8.1 结束条件由战斗规则定义

不同战斗有不同结束条件。

每场战斗进入时，需要携带 battle_rule。

```
BattleRule {
  battle_type
  max_combat_rounds
  end_conditions
  draw_resolution
  allowed_command_sources
  defeat_consequence
  victory_consequence
}
```

### 8.2 切磋

切磋不以杀死对方为目标。

建议结束条件：

```
任一方被对方造成的累计生机伤害 >= 最大生机 10%
或
任一方被对方造成的累计神念伤害 >= 最大神念 10%
```

说明：

- 这里统计“被对方造成的伤害”，不统计自己使用指令主动消耗。
- 如果同一交锋格中双方同时达到阈值，可判为平手，或按伤害比例高低判胜负。
- 切磋结果一般不造成死亡，但可以造成轻伤、声望变化、关系变化或术法经验。

### 8.3 死战

死战以彻底击败对方为目标。

建议结束条件：

```
任一方生机 <= 0
或
任一方神念 <= 0
```

生机归零偏肉身死亡，神念归零偏魂魄崩溃或心神失守。

最终是否进入死亡 / 转世流程，由父事件链根据场景决定。

### 8.4 逃亡 / 追击

逃亡战目标不是击败对方，而是成功脱离。

可能结束条件：

- 逃遁进度达到阈值。
- 生机或神念被击破，逃亡失败。
- 撑过指定交锋格数，抵达安全位置。
- 使用特定移动 / 轻身指令成功累计脱离优势。

### 8.5 护法 / 突破外扰

突破外扰中，战斗的目标可能是保护突破过程，而不是击杀敌人。

可能结束条件：

- 护持进度完成，外扰被压制。
- 突破者生机 / 神念受到超过阈值的伤害。
- 护法力量耗尽。
- 外扰在限定交锋格内未能造成关键打断。

结果应返回 S4，由突破事件链决定是否产生失败标签。

### 8.6 强制平手

如果达到最大战斗回合后仍未满足结束条件，则强制结束。

默认称为“平手 / 僵持 / 双方脱离”。

平手不等于无后果。

父事件链可以解释为：

- 双方撤退。
- 消耗了时间窗口。
- 移动计划被迫中断。
- 资源争夺失败。
- 敌人逃走。
- 秘境窗口错过。
- 突破外扰未完全压制，生成不利修正。

## 9. 战斗结果包

### 9.1 战斗结果类型

```
BattleResultType:
- victory
- defeat
- draw
- escape_success
- escape_failed
- interrupted
- death
- special
```

### 9.2 必须输出内容

战斗结束后输出结果包：

```
BattleResult {
  result_type
  winner_side
  loser_side
  end_reason
  combat_rounds_used
  exchanges_resolved
  vitality_delta
  energy_delta
  mind_delta
  consumed_items
  artifact_state_delta       // 包括主动法宝与被动法宝的受损、破碎、充能变化、失灵等
  learned_skill_exp_delta
  status_tags_added
  status_tags_removed
  event_flags
  suggested_s3_return
  log_summary
}
```

### 9.3 回写 S3 / 父事件链

战斗系统不直接决定所有后果，只返回建议。

父事件链或 S3 根据结果决定：

- 继续原计划。
- 消耗剩余行动格。
- 强制中断本季度计划。
- 改变角色位置。
- 进入休整、重伤、昏迷、被俘、逃脱等状态。
- 进入死亡 / 转世流程。
- 写入角色日志、世界日志、传闻。

## 10. 战斗信息与 UI 原则

### 10.1 玩家需要足够信息做预判

指令预输入玩法成立的前提是玩家有信息可判断。

玩家至少应看到：

- 自己当前三条属性。
- 可用指令、消耗、类型、目标条。
- 己方指令序列造成的状态条预计变化。
- 指令克制关系提示。
- 本场战斗结束条件。
- 敌方已知战斗风格。
- 敌方大致状态。
- 上一战斗回合的交锋记录。
- 当前环境或事件特殊规则。

### 10.2 状态条预计变化

玩家填入或调整 5 个交锋格指令时，界面应即时展示己方生机 / 元气 / 神念的预计变化。

该预计变化只计算己方指令的主动消耗、己方恢复、己方 Buff 或己方自损效果。

它不计算：

- 敌方攻击造成的伤害。
- 敌方破气、封脉、震魂等削减。
- 敌方打断、控制或状态封锁。
- 双方指令克制后的实际威力差。
- 战斗提前结束导致的后续指令跳过。
- 指令因受击、资源被削减或状态变化而失败。

因此，该预览的设计定位是“自我资源规划预览”，不是“战斗结果预览”。

界面文案应避免让玩家误以为预估结果必然发生。建议在预计变化旁提示：

```
仅预估己方指令消耗与恢复；实际结算会受敌方指令影响。
```

### 10.3 敌方指令可见性

MVP 不必默认显示敌方未来 5 格指令。

建议分层：

| 信息层级 | 用途 |
| --- | --- |
| 完全未知 | 高风险、不可预测遭遇 |
| 倾向提示 | 普通战斗默认，显示敌人偏攻、偏守、偏蓄势、偏逃 |
| 局部预兆 | 某些强力指令有前摇，显示可能在后续格爆发 |
| 完全预告 | 教学战、低难度事件、拥有侦查优势时使用 |

### 10.4 交锋记录

每个交锋格结算后都应记录简短摘要。

示例：

```
第 2 格：你以“护身罡气”抵住山魈扑击，消耗 8 元气，未受伤。
第 3 格：你试图运转轻身诀脱离，但山魈抢攻命中，轻身诀被打断，生机 -12。
第 4 格：护心玉替你挡下一道神念冲击，玉身出现裂纹，法宝状态变为受损。
```

这些记录进入本场战斗日志，必要时写入角色日志或系统回放。

## 11. AI 指令策略

### 11.1 AI 同样预输入

AI 与玩家使用同一套 5 格预输入规则。

AI 不应在知道玩家已锁定指令后作弊式逐格改指令。它可以基于以下信息生成本回合指令序列：

- NPC 模板。
- 战斗目标。
- 当前资源状态。
- 上一回合玩家行为。
- 性格或战斗风格。
- 事件脚本倾向。
- 难度配置。

### 11.2 AI 风格模板

示例风格：

| 风格 | 行为倾向 |
| --- | --- |
| 鲁莽 | 高频攻击，低防御，元气消耗快 |
| 稳健 | 攻防均衡，低血量转防御 |
| 狡诈 | 先 Buff / 控制，再爆发 |
| 怯懦 | 受伤后逃遁，偏防御 |
| 护法型 | 优先防御和保护目标 |
| 法修型 | 消耗元气释放高威力术法 |
| 神魂型 | 优先攻击神念，制造心神状态 |

### 11.3 AI 难度控制

MVP 中 AI 难度不靠复杂搜索，而靠：

- 指令池强度。
- 资源量。
- 克制倾向准确率。
- 是否能识别玩家重复模式。
- 是否能根据上一回合调整策略。
- 敌方指令是否给玩家更多预兆。

## 12. MVP 实现边界

### 12.1 MVP 必须支持

- 1v1 玩家 vs NPC 战斗。
- 玩家 vs 抽象敌方小队。
- 5 交锋格指令预输入。
- 最多 3 战斗回合。
- 生机 / 元气 / 神念三条状态读取与回写。
- 攻击 / 防御 / Buff 三角克制。
- 基础指令、术法指令、道具指令、法宝指令。
- 不同战斗结束条件。
- 战斗结果包回写 S3 / 父事件链。
- 可回放的战斗摘要日志。

### 12.2 MVP 可以简化

- 不做棋盘、站位、距离。
- 不做实时操作。
- 不做复杂多人同场战斗。
- 不做玩家间直接 PvP。
- 不做装备栏、换装、换法宝或完整装备耐久系统，只保留法宝状态变化与回收接口。
- 不做完整技能树，只读取已学术法 / 功法解锁指令。
- 不做复杂 combo，只保留 Buff 对后续格的简单影响。
- 不做高级反制、打断、连锁，先用标签预留。

### 12.3 第一版建议内容量

第一版只需要少量指令即可验证闭环。

通用基础指令：

- 普通攻击。
- 防御。
- 闪避。
- 调息。
- 观察。
- 逃遁。

早期功法 / 术法指令：

- 轻身功法：闪避 / 逃遁加成。
- 基础战斗功法：普通攻击增强。
- 护身法门：防御增强。

道具指令：

- 符箓攻击。
- 护身符。
- 小恢复丹 / 止血药。

法宝指令：

- 法宝攻击。
- 法宝护体。

## 13. 第一阶段移动遭遇示例

### 13.1 触发场景

第三回合前往宗门山门时，移动结算触发路途遭遇。

父事件链提供：

```
事件类型：移动遭遇
地点：云麓山道
目标：抵达宗门山门
选择：迎战 / 轻身功法逃遁 / 其他事件选项
```

### 13.2 选择迎战

进入战斗。

战斗规则：

```
battle_type: travel_skirmish
max_combat_rounds: 3
end_condition:
  - 敌方生机受到一定比例伤害，敌方退走
  - 玩家生机或神念受到一定比例伤害，事件失败或受伤撤退
  - 达到最大回合后强制脱离，视状态决定是否继续赶路
```

### 13.3 选择轻身功法逃遁

可以不进入完整战斗，直接进入逃遁判定。

若需要更具操作感，也可以进入“逃亡型战斗”：

- 玩家可用轻身 / 闪避 / 防御 / 调息指令。
- 敌方以攻击 / 追击为主。
- 目标是在若干交锋格内积累脱离进度。

### 13.4 结果回写

可能结果：

- 成功脱离，继续移动并抵达山门。
- 受轻伤但仍抵达山门。
- 元气消耗过多，拜入宗门后的 follow-up 修炼奖励降低。
- 失败撤回上一节点，本季度行动中断。
- 触发额外见闻或传闻。

## 14. 与突破外扰的接口示例

突破事件链阶段 5 “外扰 / 护法 / 地点事件”可以调用战斗系统。

但此时战斗目标不是普通胜负，而是保护突破稳定。

示例规则：

```
battle_type: breakthrough_disturbance
protected_target: self / breakthrough_state
end_condition:
  - 撑过 5 个交锋格且突破稳定值未跌破阈值
  - 外扰被击退
  - 突破者生机 / 神念受到关键伤害
  - 护法资源耗尽
```

结果返回 S4：

```
外扰压制成功 → 突破继续，可能获得护法成功标签
外扰未完全压制 → 突破进入不稳定状态
外扰打断关键阶段 → 生成失败标签：外部干扰过强 / 护法不足 / 地点不安全
```

## 15. 设计理由

### 15.1 为什么采用预输入

预输入能让战斗从“数值互殴”变成“预判对抗”。

玩家的乐趣来自：

- 判断敌方意图。
- 安排何时攻击、何时防御、何时蓄势。
- 控制资源消耗节奏。
- 承担排错指令的后果。

同时，预输入降低了实时操作和同步复杂度，适合回合制、服务端权威结算和多人房间。

### 15.2 为什么一回合 5 格

5 格足够表达短期战术节奏：

```
试探 → 防守 → 蓄势 → 爆发 → 收束
```

又不会像逐回合操作一样拖长事件链。

### 15.3 为什么最多 3 战斗回合

最多 3 战斗回合意味着一场战斗最多 15 个交锋格。

这能控制：

- 单次事件时长。
- 玩家等待成本。
- 结算复杂度。
- 日志长度。
- AI 计算成本。

也符合顶层“战斗是事件链结算框架，不是独立复杂战斗系统”的边界。

### 15.4 为什么三条属性持久存在

如果生机 / 元气 / 神念只在战斗内存在，战斗后果会变轻。

持久属性能让玩家在战斗前后做策略选择：

- 是否带伤继续赶路。
- 是否消耗元气换取逃脱。
- 是否冒神念受损风险使用神魂术。
- 是否先休整再进入秘境。
- 是否为了突破保留神念与元气。

### 15.5 为什么不把战斗作为主要负反馈

项目核心负反馈应来自突破、寿元、转世、后手、资源窗口和路线优化。

战斗可以造成伤势、资源损耗、事件失败和短期修炼受阻，但不应高频制造修为倒退或长期毁灭性惩罚。

## 16. 已确定决策

本轮暂定以下内容：

1. 战斗是事件链内部结算框架，不是独立战棋 / 实时系统。
2. 战斗发生在季度结算阶段，触发后暂停当前结算。
3. 战斗使用生机 / 元气 / 神念三条持久属性。
4. 指令来源包括法宝技能、消耗道具、已学术法神通、基础指令、事件特殊指令。
5. 战斗采用 5 格指令预输入。
6. 5 格全部结算完成视为 1 个战斗回合。
7. 一场战斗最多 3 个战斗回合，常量配置。
8. 每个交锋格后都检查结束条件，允许提前结束。
9. 不同战斗携带不同结束条件。
10. 核心克制关系为：攻击克制 Buff，防御克制攻击，Buff 克制防御。
11. 攻击 vs 攻击采用威力抵消后造成差值伤害。
12. 防御通常比攻击消耗低，且同等层级下防御有效值更高。
13. Buff 在遭遇攻击时承受接近完整攻击风险。
14. 战斗输出结果包，由父事件链决定后续行动、位置、状态与日志。
15. 指令填入阶段显示的状态条预计变化只计算己方指令序列，不考虑敌方指令影响，因此不保证后续指令一定能成功执行。
16. 战斗系统不采用装备栏 / 换装备 / 换法宝概念；随身携带的法宝、道具和已掌握术法神通都可以按条件生成可用指令。
17. 法宝可以有主动指令，也可以有被动生效效果；法宝可受损、破碎、修复、拆解或回收，作为资源循环的一部分。
18. 被动法宝在战斗中触发效果、替角色承受后果、抵抗状态或遭到针对性破坏时，也可能受损、失灵或破碎。
19. 数据层使用抽象字段，显示名暂用“神念”；后续可替换包装名，不影响规则层。
20. 元气共用同一持久状态；战斗消耗应控制在可恢复区间，避免一次小战斗直接毁掉整季度计划。
21. Buff 遭遇攻击时不默认必定失败；MVP 采用“Buff 仍可生效，但伤害达到阈值才打断”的规则。
22. 攻击 vs 攻击在 MVP 中保持纯差值伤害；余波、穿透、两败俱伤、反震等作为后续特殊标签扩展。
23. 最大战斗回合后仍未结束时，平手 / 僵持的具体后果由父事件链解释，不由战斗系统固定解释。
24. 战斗可以提供少量术法 / 指令使用经验，但不能形成刷低风险战斗的最优成长路径。

## 17. 已处理问题与补充决策

### 17.1 命名决策：神念暂用显示名

已决策：数据层使用抽象字段，显示名暂用“神念”。

理由：

- “神念”修仙味较强。
- 可同时覆盖神识、心神、魂魄稳定、精神对抗等方向。
- 比“神识”更宽，比“魂魄”更轻，比“心神”更适合承载神魂类术法。

实现建议：

```
数据层：mind / spirit_mind / soul_mind 等抽象字段
显示层：神念
```

后续如果世界观包装调整，只替换显示名，不改变战斗系统对第三属性条的规则定位。

### 17.2 元气定位决策

已决策：元气共用同一持久状态，但战斗消耗量需要控制在可恢复区间。

当前口径：

- 元气同时承载法力、气力、疲劳与行动消耗。
- 大多数术法、法宝驱动、身法、护体、调息类指令默认消耗元气。
- 肉身类招式也可以消耗元气，但特殊燃血、炼体、禁术类指令可按配置消耗生机或神念。
- 战斗后元气枯竭可以影响本季度剩余行动，但应由父事件链 / S3 根据严重程度解释。
- 小规模路途遭遇不应因为一次战斗消耗过高而直接毁掉整季度计划。

设计原则：

```
元气是跨行动与战斗共用的持久资源，
但战斗消耗需要可控，避免战斗系统抢走行动经济主导权。
```

### 17.3 Buff 被攻击时的处理决策

已决策：MVP 采用“Buff 仍可生效，但伤害达到阈值才打断”。

规则口径：

- Buff 指令被攻击克制，因此会承受接近完整攻击风险。
- 普通 Buff 在遭遇攻击时不必然失败。
- 如果本格受到的伤害、冲击或控制超过对应阈值，Buff 被打断或效果降低。
- 不同 Buff 的抗打断能力后续可以通过标签扩展。

MVP 不采用“被攻击必定失败”，避免 Buff 策略惩罚过重。

### 17.4 攻击 vs 攻击决策

已决策：MVP 保持纯差值伤害。

规则口径：

```
双方攻击有效威力相减
→ 威力较高方造成差值伤害
→ 威力较低方攻击被压制
```

MVP 暂不加入默认余波伤害，避免攻击对攻变得难以理解。

后续可以通过特殊指令标签扩展例外：

- 穿透。
- 余波。
- 两败俱伤。
- 反震。
- 溅射。
- 以伤换伤。

### 17.5 平手 / 僵持后果决策

已决策：达到最大战斗回合后仍未结束时，默认强制结束；具体后果由父事件链解释。

战斗系统只输出：

```
result_type: draw
end_reason: max_combat_rounds_reached
combat_rounds_used: 3
```

父事件链按场景解释：

- 切磋：平手或按伤害比例判定微弱胜负。
- 路途遭遇：双方脱离，角色可能继续赶路或被迫中断。
- 资源争夺：因未能击退对方而失去窗口或降低收益。
- 敌人逃走：战斗未分胜负，但事件目标失败。
- 突破外扰：外扰未完全压制，返回 S4 生成不利修正。

### 17.6 法宝、道具与术法的可用性边界

已决策：不设计战斗中换装备 / 换法宝问题，因为系统不采用装备栏概念。

战斗开始时，系统读取角色随身携带的法宝、消耗道具，以及已经掌握的术法神通，并根据当前战斗规则生成可用指令列表。

原则：

- 随身携带的法宝都可以参与判定，不需要预先装备到有限栏位。
- 随身携带的符箓、丹药、阵盘等道具可在满足条件时生成消耗型指令。
- 已经掌握的术法神通可在满足资源、状态、场景条件时生成指令。
- 法宝可以提供主动指令，也可以被动生效。
- 被动法宝在战斗中触发效果、替角色承受后果、抵抗状态或遭到针对性破坏时，也可能受损、失灵或破碎。
- 法宝可以受损、破碎、失去充能、灵性衰减、战后修复、拆解回收或进入传承 / 后手资源循环。

设计理由：

```
修仙成长强调资源积累与资源消耗，
而不是把战力限制在少数装备栏位上。
```

限制主动型法宝滥用的不是装备栏，而是战斗回合中的指令次数、资源消耗、法宝状态、道具消耗和克制关系。

限制被动型法宝堆叠的也不是装备栏，而是触发条件、状态损耗、受损风险、修复成本、携带风险、事件针对性和资源回收链。

因此，主动型法宝带太多并不会无限提高战斗收益：每个战斗回合只有 5 个交锋格，玩家仍然必须在攻击、防御、Buff、逃遁、恢复、控制等指令之间取舍。

### 17.7 战斗经验决策

已决策：战斗可以提供少量术法 / 指令使用经验，但不能形成刷战斗最优。

原则：

- 实战使用可以增加熟练度。
- 高风险战斗收益可以高于低风险战斗。
- 重复低风险战斗收益递减。
- 主要成长仍来自修炼、资源、功法与事件。
- 战斗经验应服务于“实战验证”和“使用熟练度”，而不是替代修炼行动。

推荐口径：

```
战斗提供使用反馈，修炼提供主要成长。
```

## 18. 后续落地建议

### 18.1 最小原型闭环

```
角色当前属性：生机 / 元气 / 神念
→ 生成一场路途遭遇
→ 玩家获得 6–8 个可用指令
→ 玩家填入 5 个交锋格
→ AI 填入 5 个交锋格
→ 逐格结算克制
→ 输出伤害、消耗、日志
→ 检查结束条件
→ 返回移动事件结果
→ 继续或中断 S3 行动结算
```

### 18.2 最小测试目标

验证以下问题：

1. 玩家是否能理解 5 格预输入。
2. 攻击 / 防御 / Buff 克制是否直观。
3. 生机 / 元气 / 神念是否足以表达战斗后果。
4. 3 个战斗回合是否足够结束大多数事件。
5. 指令消耗是否能制造有效取舍。
6. 状态条预计变化是否能帮助玩家规划主动消耗，同时不会被误解为完整战斗结果预测。
7. 战斗日志是否能解释结果，尤其是解释“为什么某个原本预估可执行的指令最终因资源不足失败”。
8. 战斗结果能否顺利回写 S3 时间轴。
