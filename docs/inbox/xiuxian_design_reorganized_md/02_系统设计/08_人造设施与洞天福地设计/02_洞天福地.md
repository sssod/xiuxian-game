# 系统设计｜洞天福地

## 1. 设计定位

洞天福地是地图节点或节点隐藏层中的高价值 `blessed_land` 资源槽，负责承载特殊灵气、空间稳定、突破机会、隐藏层入口、争夺价值和受限维护操作。它不是常规建筑、普通设施、可自由改造地块，也不是正式后手封存点。

资源槽的通用字段、类型和人工扩展规则由《资源槽详细设定》（`../07_地图节点设计/02_资源槽详细设定.md`）维护；一槽一设施类别、设施建设和设施改造约束由《资源槽附属设施通用规则》（`03_资源槽附属设施通用规则.md`）维护。本文只维护洞天福地作为 `blessed_land` 时的特殊限制、可用操作和系统接口。

## 2. 当前结论

1. 洞天福地必须挂载于地图节点或节点隐藏层中的资源槽，不应成为无位置资产。
2. MVP 阶段，洞天福地按 `blessed_land` 或等价不易改造资源槽处理，通常具有较高灵气、特殊相性、空间稳定性、突破机会、隐藏层或稀有产出条件。
3. 洞天福地可以被发现、争夺、封禁、保全、维护、参悟、污染、破坏或作为突破场地使用，但不默认开放常规生产建筑替换。
4. 洞天福地本体不能直接改建为矿场、药园、坊市、传送阵或普通修炼房；若内部存在可建设空间，应另记子资源槽。
5. 洞天福地本体、洞天内部子资源槽和以洞天资源槽为绑定点的设施，都不能作为真灵藏宝封存点。

## 4. 核心循环或触发入口

洞天福地由节点模板、隐藏层、世界事件、秘境窗口、历史遗留、宗门争夺、特殊发现或人工不可控事件生成。MVP 常规人工扩展不能制造洞天福地，也不能把普通 `aura_node` 升格为 `blessed_land`。

运行循环：

```text
发现或揭示洞天福地
→ 校验位置、可见性、控制权、争夺状态和资源槽改造口径
→ 执行保全、封禁、维护、参悟、突破场地使用、受限修炼或入口维护
→ 写入资源槽状态、设施状态、库存流向、风险变化、传闻和结果包
→ 按 world_hour 或事件结果更新污染、暴露、争夺、破坏、产出和可见性
```

若洞天福地状态在行动排队后发生变化，修炼、突破、探索、维护和争夺行动执行前必须重新校验。

## 5. 规则与状态

洞天福地建议在 `NodeResourceSlot` 上表达为 `resource_type = blessed_land`，并至少记录以下状态：

```yaml
BlessedLandState:
  slot_id: string
  node_id: string
  hidden_layer_id: string | null
  resource_type: blessed_land
  blessed_land_template_id: string
  slot_scale: int
  resource_grade_range: string
  aura_density: number
  special_property_tags: list[string]
  transformability: limited_build | preserve_only | no_build
  allowed_operations: list[string]
  attached_facility_class: string | null
  attached_facility_ref: string | null
  child_resource_slot_refs: list[string]
  contest_state: object
  seal_state: none | preserved | sealed | polluted | damaged | contested
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world
  result_package_refs: list[string]
```

洞天福地本体规则：

1. 必须记录资源品级、品级范围、灵气影响、可见性、控制权、争夺状态、改造限制和允许操作。
2. `transformability` 通常是 `limited_build`、`preserve_only` 或 `no_build`。
3. 宗门或角色只能在其上附加保全、封禁、参悟、突破场地、入口维护等受限设施或操作。
4. 若作为修炼加成来源，应进入数值模型的节点灵气、资源槽修正或受限设施修正；其中设施修正只能来自洞天福地允许的受限附属设施。
5. 若提供资源产出，应先进入资源槽或资源池；实例化后再进入 `sect_storage`、`node_storage`、事件锁定库存或其他合法资产容器。
6. 若一个洞天福地内部确实存在可建设空间，应额外记录为该节点或隐藏层内的 `aura_node`、`space_site` 或 `special` 子资源槽，由子槽承担常规设施建设；`blessed_land` 本体仍保持受限改造口径。
7. 洞天福地不能作为正式后手的真灵藏宝封存点。若同一地图节点内同时存在真灵藏宝，真灵藏宝必须挂在独立的节点隐藏层目标上。
8. 个人洞府或普通藏宝若附着洞天福地相关自然资源槽，应占用该槽设施承载位并降低隐蔽，允许因条件泄露或防御被攻破而被其他角色提前打开；但真灵藏宝仍只能使用独立隐藏层目标。

| 接口 | 洞天福地读取或输出 |
| --- | --- |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `resource_type = blessed_land` | 洞天福地资源槽大类 |
| `blessed_land_template_id` | 洞天福地类型模板 |
| `slot_scale` | 洞天规模，影响承载、争夺、维护成本和产出上限 |
| `resource_grade_range` | 洞天品级和可波动范围 |
| `aura_density` | 灵气浓度或特殊灵气输入 |
| `special_property_tags` | 特殊相性、空间稳定、突破机会、隐藏层或稀有产出标签 |
| `transformability` | 受限建设、保全或禁止建设口径 |
| `allowed_operations` | 保全、封禁、参悟、突破场地、入口维护等允许操作 |
| `child_resource_slot_refs` | 洞天内部可建设子资源槽引用 |
| `contest_state` | 发现、争夺、控制、封锁和归属状态 |
| `seal_state` | 保全、封禁、污染、损坏或争议状态 |
| `visibility_policy` | 可见性、传闻或隐藏层口径 |
| `result_package_refs` | 发现、争夺、污染、封禁、维护、产出和破坏结果包引用 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 可展示洞天福地名称、所在节点或已揭示隐藏层、可见品级摘要、灵气或突破价值摘要、当前控制权、争夺状态、可执行操作、维护或封禁状态、风险提示和不可用原因。

普通 UI 不展示隐藏层真实结构、未公开真灵藏宝线索、未发现子资源槽、其他玩家私人控制来源、完整公式倍率、`hidden_world` 或 `debug_only` 信息。洞天内部子资源槽和真灵藏宝目标必须在 UI 上保持落点边界，不应把真灵藏宝显示为洞天资源槽本体的附属物。

## 9. MVP 范围

MVP 应实现：

1. `blessed_land` 作为资源槽大类。
2. 洞天福地的品级、灵气、特殊标签、可见性、控制权、争夺状态和改造限制。
3. 保全、封禁、维护、参悟、突破场地、受限修炼或入口维护等最小操作。
4. 洞天资源产出进入资源槽、资源池或合法资产容器。
5. 洞天本体与子资源槽、个人洞府、普通藏宝、真灵藏宝的承载边界。

MVP 不实现：

1. 常规人工扩展制造洞天福地。
2. 把普通 `aura_node` 升格为 `blessed_land`。
3. 把洞天福地本体直接改建为矿场、药园、坊市、传送阵或普通修炼房。
4. 把洞天福地、洞天内部子资源槽或洞天相关附属设施作为真灵藏宝封存点。
5. 未记录来源、库存流向和结果包的洞天稀有产出。

## 10. 验收约束

1. 洞天福地必须能追溯到地图节点或节点隐藏层中的 `blessed_land` 资源槽。
2. 洞天福地本体只能执行模板允许的受限操作，不能绕过资源槽附属设施规则进行常规建筑替换。
3. 洞天内部若开放常规建设，必须通过独立子资源槽表达，并保留本体受限口径。
4. 修炼、突破、参悟、维护和争夺行动执行前必须重新校验洞天状态、权限、污染、封禁和控制权。
5. 洞天产出、维护消耗、污染、破坏、封禁和争夺必须写入结果包、日志或资产流水。
6. 真灵藏宝不能附着在洞天福地、洞天内部子资源槽或洞天相关附属设施上；同节点共存时必须使用独立节点隐藏层目标。
