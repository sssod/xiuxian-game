# 储物空间系统设计｜基础行囊

## 1. 当前结论

MVP 不引入背包重量、体积、格子或通用负重上限。随身资产由标签、事件条件、位置、调用权限、combat_ready 等上下文限制。

## 2. 资产位置

```yaml
AssetLocation:
  carried_by_character
  home_storage
  sect_storage
  node_storage
  sealed_legacy
  market_listing
  event_locked
```

基础行囊对应 carried_by_character。

## 3. 可用性限制

物品是否可用不由“装备栏”决定，而由以下条件共同决定：

- 是否随身携带。
- 是否 combat_ready。
- 行动 / 事件 / 战斗上下文是否兼容。
- 角色状态是否允许调用。
- 权限、绑定、宗门身份、位置是否满足。
- 资源是否被预留或事件锁定。

## 4. 缺口

- 行囊 UI 布局。
- 基础行囊与洞府储藏、宗门库存之间的操作流程。
- 后续是否引入负重、体积、容量上限，当前不进 MVP。
