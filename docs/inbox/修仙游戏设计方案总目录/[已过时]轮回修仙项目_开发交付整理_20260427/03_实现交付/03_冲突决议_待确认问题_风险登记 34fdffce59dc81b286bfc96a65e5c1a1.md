# 03_冲突决议_待确认问题_风险登记

# 冲突决议、待确认问题与风险登记

## 0. 文档定位

本文记录本次整理中发现并处理的设定冲突、变量命名冲突、范围冲突和仍需人工确认的问题。

开发阶段建议把本文作为“临时定版口径”。若后续写回 Notion，应将这些决议逐条确认或修订。

## 1. 已消解的关键冲突

### 1.1 MVP 边界冲突

旧文档中存在商业化、Steam EA、正式发售内容量等表述。开发口径统一为：

```
本地可单人测试
+ 可部署私人服务器
+ 支持 3 人共玩
```

Steam 买断制可作为长期商业方向，不作为当前 MVP 验收条件。

### 1.2 M0–M3 与 A/B/C 阶段冲突

决议：

- M0–M3 是体验里程碑。
- A-1 / B-1 / C-1 是规则阶段编码。
- M3 是第三大境界起点，通常对应 C-1，不是 C-3。

### 1.3 修仙包装名与规则 ID 冲突

决议：

- 规则层只使用 `A/B/C`、`A-1/B-1/C-1`、`tier_code`、`quality_code`。
- `炼气 / 筑基 / 金丹` 只作为本地化显示。
- 不允许用 `lianqi / zhuji / jindan` 作为规则判断字段。

### 1.4 行动格术语冲突

决议：

- 统一使用“6 个朔望行动格”。
- 不使用“朔望月行动格”。
- tick 是内部结算时间单位，不是收益公式。

### 1.5 精力与元气字段冲突

旧文档中“精力”和“元气”容易同时被翻译为 `energy`。

决议：

| 中文 | 字段 |
| --- | --- |
| 精力 | `base_vigor` |
| 元气 | `bar_qi` |
| 生机 | `bar_vitality` |
| 神念 | `bar_mind` |

战斗消耗读取 `bar_qi`，不是 `base_vigor`。

### 1.6 宗门声望、门内声望、节点影响力冲突

决议：

| 概念 | 字段 |
| --- | --- |
| 宗门整体声望 | `sect_reputation` |
| 玩家门内声望 | `member_reputation` |
| 节点影响力 | `node_influence_by_faction` |
| 节点控制权 | `control_owner_faction_id` |

贡献记录不是货币。

### 1.7 资质系统冲突

决议：

- 不设置独立“总资质等级”参与核心判定。
- 资质拆为根骨、悟性、灵根等子项。
- 悟性是资质子项，不是基础属性；内部字段统一为 `aptitude_comprehension`。
- `base_comprehension` 弃用，开发实现不得继续使用该字段或用 `base_` 前缀表达悟性。
- 根骨、悟性可后天改善。
- 灵根 MVP 不支持后天修改。
- UI 可显示综合评价，但底层规则不读取总资质。

### 1.8 主修道功切换冲突

决议：

- 同一时间只能有一个主修道功。
- 主修道功只在 A-1 / B-1 / C-1 等大境界第一小阶段窗口内可无行动格替换。
- 离开第一小阶段后，本大境界主修路线锁定。
- 大境界突破模板读取当前大境界最终锁定的主修道功记录。
- 临近突破不能临时换功法规避难度。

### 1.9 自动运转与主动吐纳收益叠加冲突

决议：

- 自动运转按 tick 结算。
- 主动吐纳期间自动运转不额外生效。
- 自动运转可以触发小境界升级。
- 自动运转不能跨越大境界瓶颈。
- 托管可使用自动运转作为保底，但不能主动高风险突破。

### 1.10 小境界与大境界突破冲突

决议：

- 小境界升级是常规成长节点，不进入突破事件链。
- 大境界突破是核心事件链，必须玩家主动发起。
- 大境界突破至少消耗一个关键突破物。
- 突破事件链创建时消耗关键突破物。

### 1.11 丹药副作用冲突

决议：

- MVP 不引入丹毒 / 杂质累计值。
- 不适配丹药表现为转化率低、药力浪费、短期疲劳、短期经脉压力或短期心神扰动。
- 正式版保留丹毒 / 杂质 / 长期残留扩展接口。

### 1.12 灵石等级冲突

决议：

- 灵石是核心通货，不分等级。
- 中品 / 上品灵石等概念不作为货币面额。
- 高密度灵气需求由聚灵石等独立物品表达。
- MVP 只实现“灵石 → 聚灵石”加工路径。

### 1.13 物品堆叠冲突

决议：

- 不设计半可堆叠物品。
- 只保留可堆叠 ItemStack 与独立实例 ItemInstance。
- 来源 / 产地 / 历史不作为通用参数，只在高价值模板启用。

### 1.14 背包容量与装备栏冲突

决议：

- MVP 不引入重量、体积、格子、负重上限。
- 本项目不采用传统装备栏。
- 法宝、道具、术法、神通按条件生成可用指令。
- 限制来自标签、行动格、交锋格、资源、耐久、充能、事件条件。

### 1.15 NPC 库存冲突

决议：

- 不在战斗开始时临时初始化 NPC 完整库存。
- 战利品来自持久化随身 / 可调用资产、事件锁定奖励包或预算生成奖励。
- 商店库存属于 ShopStock / MarketListing / SectStorage / NodeStorage，不属于掌柜个人。
- 不设置 N2.5。
- N3 以上默认持久化个人库存。
- N4 每季度必须有个人宏观行动，但不增加宗门主行动数量。

### 1.16 宗门行动数量冲突

决议：

- 每个宗门每季度始终只有 1 个宗门主行动。
- 宗门规模通过执行完成度、常态收益、持续项目、建筑效果、事件结果体现。
- 已控制资源节点稳定产出走常态结算，不占宗门主行动。

### 1.17 宗门内部派系冲突

决议：

- MVP 不引入宗门内部派系 / 山头作为系统变量。
- 内部影响力通过身份、职位、贡献、门内声望、关键 NPC 支持、特殊授权表达。

### 1.18 山门核心节点失守冲突

决议：

- MVP 常态不允许山门核心节点被 AI 宗门普通行动夺取。
- 只允许重大事件链造成临时影响。
- 争夺重点放在边界节点、资源节点、秘境节点和影响力变化上。

### 1.19 正式后手随机磨损冲突

决议：

- 正式后手风险只在相关节点发生明确变化时检定。
- 不做每季度随机磨损。
- 不引入年久失修型低频随机风险。
- 正式后手失效必须有原因链。

### 1.20 多人边界冲突

决议：

- MVP 多人是分宗并行 + 间接竞争 + PvE 沙盒演化。
- 不做强 PvP。
- 不做玩家直接交易、互相护法、共同秘境、破坏他人突破、离线袭击玩家主体。
- 同宗玩家不做强制投票。

## 2. 仍需人工确认的问题

### 2.1 存档格式

待定：

- SQLite。
- Godot Resource / JSON。
- 混合方案。

建议尽快决策，因为这会影响服务器保存、调试查询、版本迁移和数据驱动工作流。

### 2.2 功法等级结构

待定：

- 固定等级。
- 阶段式熟练度。
- 篇章 / 层数解锁。
- 混合结构。

此项会影响主修道功上限、突破模板、功法学习和 UI 表现。

### 2.3 寿元 MVP 最小实现

待定：

- 只实现突破延寿。
- 同时实现延寿丹 / 延寿灵物。
- 寿元压力显式状态是否使用 safe / pressured / urgent / exhausted。

### 2.4 根骨 / 悟性后天改善

待定：

- 根骨后天改善采用“洗髓资源 + 持续行动”。
- 还是独立洗髓事件链。
- 悟性后天改善采用“参悟机会 + 持续行动”。
- 还是限时明悟状态替代永久改善。

字段约束：悟性后天改善若永久生效，应修改 `aptitude_comprehension`；若只是短期状态，应写入 condition / buff，不得回写 `aptitude_comprehension`。

### 2.5 聚灵阵与定向吸收

待定：

- 聚灵阵固定浓度加成消耗灵石、聚灵石还是设施维护资源。
- 定向吸收加成是否消耗、污染或改变节点灵气状态。

### 2.6 残缺突破是否进入 MVP

当前口径：

- 若实现成本可控，进入 MVP。
- 若成本紧张，保留字段，第一版只做正常成功 / 失败存活 / 身死转世。

需要开发评估后确认。

### 2.7 M2 → M3 外扰复杂度

当前口径：

- M2 → M3 可配置为 1 轮 5 格 + 外扰变体。
- 高风险预警或明确敌对事件可直接中断。
- 低预警外扰不直接中断。

需要确认外扰事件最小内容量。

### 2.8 首张地图具体内容表

已定规模和结构，但未定：

- 35±10 个节点的具体列表。
- 3 个主要宗门名称、风格、起始库存。
- 资源槽模板。
- 秘境入口节点。
- 初始传闻。

### 2.9 事件库内容量

待定：

- 新手移动事件数量。
- 常规选择事件数量。
- 突破事件文本数量。
- 节点危机模板数量。
- 传闻模板数量。

### 2.10 战斗数值

待定：

- 生机 / 元气 / 神念初始量级。
- 指令威力。
- 防御有效值。
- Buff 打断阈值。
- 消耗恢复节奏。
- 最多 3 回合下的战斗强度。

### 2.11 宗门行动执行公式

待定：

- 执行完成度的输入权重。
- 资源 / 人力投入曲线。
- 玩家亲自介入修正。
- 竞争宗门干扰权重。
- 节点危险和控制权影响。

### 2.12 世界生成预算

待定：

- 各阶预算上限。
- R_tier = 10 的初始测试是否过陡。
- 3 人房间预算修正。
- 探索密度与投放节奏。

## 3. 开发风险登记

### 3.1 系统范围膨胀风险

风险：修仙题材天然容易膨胀到炼丹、炼器、阵法、宗门战争、NPC 生态、强 PvP。

控制：

- 严守 MVP 非目标。
- 每个新增功能必须对应 M0→M3 闭环。
- 用接口预留替代完整实现。

### 3.2 数据结构过早复杂化风险

风险：为了未来扩展提前实现过多字段和模拟，会拖慢原型。

控制：

- 抽象资源先用数值。
- 只有进入战斗、交易、突破、封存、遗产时实例化。
- N0–N2 不持久化完整库存。
- 地图首张 35±10 节点。

### 3.3 事件脚本不可控风险

风险：普通事件若无限多阶段，会变成难以测试的剧情脚本系统。

控制：

- 常规事件最多 2 阶段。
- 重要事件最多 3 阶段。
- 超过后转专用事件链。
- 结果包统一回写。

### 3.4 存档迁移风险

风险：多人长期房间一旦存档格式不稳，后续迁移成本高。

控制：

- 尽早决定存档方案。
- 所有存档写版本号。
- Debug 工具支持状态查询。
- 数据对象命名统一。

### 3.5 玩家理解成本风险

风险：角色、宗门、世界、后手、突破、事件太多，玩家入门困难。

控制：

- M0 新手阶段只暴露必要字段。
- 神念、纯度、后手等逐步显性。
- 突破准备面板只显示风险档位和短板，不显示完整概率表。
- 常规事件隐藏不可用选项。

### 3.6 失败体验过重风险

风险：突破失败、死亡、后手失效若无解释，会被视为系统恶意。

控制：

- 失败必须有标签。
- 后手失效必须有原因链。
- 死亡进入轮回账本。
- 下一世有可执行优化方向。
- 托管不执行高风险不可逆选择。

### 3.7 多人破坏长期体验风险

风险：直接 PvP 或离线袭击会破坏跨世经营体验。

控制：

- MVP 只做间接竞争。
- 不做破坏他人突破。
- 不做离线袭击主体。
- 行动可见性不全图公开。
- 资源名额竞争替代直接毁灭。

## 4. 建议下一轮人工审核顺序

推荐：

```
1. 本文冲突决议
2. 术语表与命名规范
3. 存档格式与运行时状态
4. MVP 开发切片
5. 角色养成 + 突破
6. 宗门 + 经济
7. 地图 + 事件
8. 多人 + 后手
```

先确认命名和存档，会显著减少后续重构成本。
