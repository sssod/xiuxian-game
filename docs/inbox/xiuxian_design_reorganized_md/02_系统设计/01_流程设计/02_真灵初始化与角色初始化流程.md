# 系统设计｜真灵初始化与角色初始化流程

## 1. 设计定位

本文固定玩家主体从第一次进入房间到转世重修时的初始化流程，负责说明真灵、执念、当前世身躯与灵魂之间的职责边界，以及初次角色和转世角色应如何生成。

本文只维护初始化流程、可选项、禁用项、字段语义和验收约束。房间创建、玩家槽位和共享世界推进由《单人游戏与多人共玩流程》（`01_单人游戏与多人共玩流程.md`）维护；角色属性、外观、人设、后手资产和页面表达由对应包内文档承接。

## 2. 当前结论

1. 玩家主体采用“真灵 / 执念 / 身躯与灵魂”三层模型：真灵负责跨世延续，执念负责转世初始化遗留容量，身躯与灵魂负责当前世角色实例。
2. 玩家控制的当前角色不再拥有世俗背景身份，不以家族、门第、官籍、凡俗履历或职业作为主线身份锚点。
3. 世界主线剧情直接绑定真灵、真灵名与真灵线索；当前角色只是该真灵在本世的承载者。
4. 初次进入房间时先初始化真灵，再创建初始化角色；转世重修时只重新生成当前世身躯与灵魂，不重建真灵主体。
5. 当前角色仍然拥有姓名、性别、年龄、出生位置、外观、属性、物资和宗门身份等可玩字段，但这些字段不得回退成世俗背景身份。
6. 执念采用权重制，是本次转世初始化中的一次性容量约束，不是可长期累计的属性点货币。

## 4. 核心循环或触发入口

初始化分为两类：

```text
真灵初始化：玩家第一次进入游戏房间时执行一次
角色初始化：生成当前世身躯与灵魂；初次进入与转世重修都会执行
```

初次进入房间流程：

```text
玩家进入游戏房间
→ 创建真灵
→ 选择真灵名
→ 绑定真灵剧情线
→ 介绍真灵背景故事
→ 创建初始化角色
→ 写入角色自知信息与初始日志
→ 进入新手流程 / 第一阶段房间推进
```

转世重修后的角色初始化流程：

```text
本世结束 / 主动计划转世
→ 结算本世身躯与灵魂
→ 提取真灵成长
→ 记录履历、失败原因、后手状态
→ 检查宗门遗产清点、宗门外洞府 / 藏宝等无主遗留设施线索和真灵藏宝状态
→ 按转世前修为境界结算执念
→ 创建新角色初始化草案
→ 选择无成本基础参数
→ 选择是否消耗执念设定强化参数
→ 生成新身躯与灵魂
→ 写入新世初始日志
```

转世触发来源暂定支持三类：

1. 寿元耗尽转世。
2. 突破失败转世。
3. 主动计划转世。

## 5. 规则与状态

### 5.1 三层主体模型

```text
真灵：跨世延续主体
执念：转世初始化遗留容量系统
身躯与灵魂：当前世角色实例
```

真灵负责“我仍然是我”；执念负责“我能把哪些内生遗留带到下一世”；身躯与灵魂负责“这一世具体能做什么、付出什么代价”。

真灵初始化确立跨世主体、真灵名与主线剧情线。角色初始化只确立当前世角色实例，不生成玩家角色的世俗背景身份。

### 5.2 初次进入房间

玩家第一次进入游戏房间时，先初始化真灵，再创建初始化角色。

选择预设真灵名时：

1. 真灵名绑定对应的专属剧情线。
2. 真灵背景故事按该真灵名播放或写入初始日志。
3. 初始化角色直接使用该真灵名对应的预设角色属性、出生位置、性别、年龄与外观。
4. 玩家可以自定义当前角色姓名。
5. 不生成家庭背景、门第身份、凡俗职业、官籍、家族关系等世俗背景身份。
6. 世界主线从真灵线索展开，当前角色只是该真灵第一次显化的当世承载者。

选择自定义真灵名时：

1. 真灵名不绑定专属剧情线，进入通用弱剧情线。
2. 真灵背景故事使用通用版本，只保留与真灵存在、入世异常和世界主线入口相关的信息。
3. 初始化角色使用通用预设角色属性与预设年龄。
4. 玩家可以自定义当前角色姓名与性别。
5. 出生位置与外观随机生成。
6. 不生成世俗背景身份。

初次角色生成约束：

1. 资质、根骨、悟性等角色属性在身躯与灵魂生成时已经确定；MVP 阶段入门事件只负责检测、评级并一次性展示已确认资质，不引入分段揭示状态。
2. 初次入世仍保持低认知、低资源、低控制力，但“低认知”来自新显化角色对世界理解有限，不来自世俗出身身份。
3. 出生位置只表示初始空间落点。它可以影响玩家接触到的地点、NPC、宗门与事件入口，但不得生成玩家角色的家族、门第或社会身份。
4. 初始日志应区分“真灵背景故事”和“当前角色自知信息”。前者服务主线，后者服务本世操作。

### 5.3 转世重修初始化

无成本基础参数：

1. 当前角色姓名。
2. 性别。
3. 年龄。
4. 出生位置的大致区域。
5. 外观预选择。

执念可影响的强化参数：

1. 角色属性设定。
2. 出生具体位置设定。
3. 初始物资设定。

转世重修规则：

1. 执念是基于转世前修为境界获得的一次性初始化代币，只在本次角色初始化中消费。
2. 未消耗执念设定的角色属性、出生具体位置与初始物资按普通生成规则处理。
3. 出生位置的大致区域是无成本选择；确定具体地点、特殊落点或高价值起点需要消耗执念。
4. 外观预选择不等于世俗身份选择。它只影响当前身躯的视觉呈现，不绑定家族、门第、职业或主线身份。
5. 转世重修仍不生成玩家角色的世俗背景身份。前世履历由真灵轮回账本承载，本世身份由游玩过程获得。
6. 玩家转世前留下的宗门个人洞府库存，进入宗门遗产清点流程，按有主遗产规则回收宗门，不作为新世初始化物资自动继承。
7. 宗门外个人洞府和普通藏宝是无主遗留设施；新世角色必须满足钥匙、功法、线索、位置、事件条件或破阵结果后才能进入 / 取出，并可能发现已被其他角色提前打开。
8. 真灵藏宝作为正式后手可由同一真灵跨世感应和开启，但受设置数量与单个容量限制；它不等同于复制前世背包或洞府库存。

### 5.4 执念权重制

执念容量采用权重制：

```text
TrueSpirit.obsession_capacity = 本次转世可承载的执念容量上限
ObsessionOption.obsession_weight = 某遗留或强化配置的占用权重
```

执念权重规则：

1. 玩家选择的总权重不得超过当前执念容量。
2. 权重不是属性点，不允许拆成根骨 +1 / 悟性 +1 等细碎购买。
3. 遗留与强化仍是离散选项，例如属性定型包、具体出生点、初始物资包、已解锁初始化遗留。
4. “出生背景”不再作为玩家角色的主动遗留分类。若旧资料出现出生背景，应改写为出生位置、初始物资、区域接触面或已解锁线索，不得写成世俗身份。
5. 执念可选范围与权重表另行细化；本文件只固定流程入口、允许影响的参数类别和禁用的世俗身份边界。

### 5.5 禁用世俗背景身份

玩家角色初始化不得生成或恢复以下内容：

```yaml
birth_background_id: forbidden
family_background_id: forbidden
initial_social_identity: forbidden
initial_secular_profession: forbidden
main_story_identity_binding: forbidden
```

宗门身份、声望、关系、称号、职位和社会评价可以由游玩过程获得，但不得作为玩家初始化时的世俗背景身份写入。

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `TrueSpiritInit.spirit_id` | 真灵唯一标识 |
| `TrueSpiritInit.true_name` | 真灵名，绑定跨世主体和主线入口 |
| `TrueSpiritInit.true_name_mode` | `preset` 或 `custom`，决定专属剧情线或通用弱剧情线 |
| `TrueSpiritInit.story_line_id` | 真灵主线剧情线标识 |
| `TrueSpiritInit.story_line_type` | `dedicated` 或 `generic_weak` |
| `TrueSpiritInit.incarnation_count` | 真灵已显化次数 |
| `CharacterInit.character_id` | 当前世角色唯一标识 |
| `CharacterInit.true_spirit_id` | 当前世角色绑定的真灵 |
| `CharacterInit.init_context` | `first_entry` 或 `reincarnation` |
| `CharacterInit.attribute_profile_id` | 当前世角色属性模板或生成结果 |
| `CharacterInit.birth_region_id` | 出生大致区域 |
| `CharacterInit.birth_location_id` | 出生具体位置或随机生成结果 |
| `CharacterInit.initial_material_package_ids` | 初始物资包结果 |
| `CharacterInit.obsession_spent` | 本次初始化已消耗执念权重 |
| `CharacterInit.has_secular_background_identity` | 固定为 `false`，表示不生成世俗背景身份 |

建议结构：

```yaml
TrueSpiritInit:
  spirit_id: string
  true_name: string
  true_name_mode: preset | custom
  story_line_id: string
  story_line_type: dedicated | generic_weak
  incarnation_count: int

CharacterInit:
  character_id: string
  true_spirit_id: string
  init_context: first_entry | reincarnation
  character_name: string
  gender: string
  age: int
  attribute_profile_id: string
  birth_region_id: string | null
  birth_location_id: string | random
  appearance_profile_id: string | random
  initial_material_package_ids: list
  obsession_spent: number
  has_secular_background_identity: false
```

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示：

1. 真灵名选择结果、预设 / 自定义模式和玩家本人可见的真灵背景故事。
2. 当前角色姓名、性别、年龄、出生位置、外观、初始属性摘要和初始物资摘要。
3. 初次进入时的“真灵背景故事”和“当前角色自知信息”区分。
4. 转世重修时的无成本基础参数、可消耗执念的强化参数、已用权重和剩余容量。
5. 真灵藏宝、宗门遗产清点、宗门外洞府 / 普通藏宝线索等后手状态的本人可理解摘要。

普通 UI 不应展示：

1. 家庭背景、门第身份、凡俗职业、官籍、族属关系或主线身份绑定作为玩家初始化选项。
2. 他人真灵偏好、专属剧情线细节、Debug 随机顺序或完整内部结果包。
3. 执念细碎属性点购买界面。
4. 前世背包、宗门个人洞府库存或宗门资源的自动继承承诺。

## 9. MVP 范围

MVP 应实现：

1. 初次进入房间的真灵初始化和当前世角色初始化。
2. 预设真灵名与自定义真灵名两种入口。
3. 预设真灵名绑定专属剧情线和预设角色模板；自定义真灵名进入通用弱剧情线和通用角色生成。
4. 当前角色姓名、性别、年龄、出生位置、外观、属性、初始物资和初始日志写入。
5. 禁用世俗背景身份的字段和验收约束。
6. 寿元耗尽、突破失败和主动计划转世三类转世入口的初始化承接。
7. 转世重修的无成本基础参数、执念强化参数和权重上限校验。
8. 宗门个人洞府库存、宗门外无主遗留设施和真灵藏宝的跨世资产边界提示。

MVP 不实现：

1. 完整预设真灵名列表和全部专属剧情线文本。
2. 复杂分段资质揭示。
3. 细碎属性点式执念购买。
4. 自动继承前世背包、宗门洞府库存、宗门职位、普通关系或完整前世记忆。
5. 把出生背景、家族、门第、官籍或凡俗职业恢复为玩家初始化选项。

## 10. 验收约束

1. 真灵初始化只在玩家第一次进入游戏房间时执行；转世重修不得重建真灵主体。
2. 初次进入和转世重修都必须创建当前世角色实例，并写明 `init_context`。
3. 预设真灵名必须绑定专属剧情线；自定义真灵名必须进入通用弱剧情线。
4. 当前角色初始化不得生成家庭背景、门第身份、凡俗职业、官籍、家族关系或主线身份绑定。
5. 出生位置只能作为空间起点和接触面，不得推导为世俗身份。
6. 入门检测在 MVP 阶段只展示已经生成的资质结果，不在检测现场临时生成资质。
7. 执念权重总和不得超过本次转世可用容量，且不得拆成细碎属性点购买。
8. 转世重修不得复制前世背包、洞府库存、当前修为、功法等级、宗门职位、普通关系或完整前世记忆。
9. 宗门个人洞府库存、宗门外无主遗留设施和真灵藏宝必须按后手与资产文档的边界处理，不能被初始化流程绕过。
10. UI 和日志必须区分真灵背景故事与当前角色自知信息。
