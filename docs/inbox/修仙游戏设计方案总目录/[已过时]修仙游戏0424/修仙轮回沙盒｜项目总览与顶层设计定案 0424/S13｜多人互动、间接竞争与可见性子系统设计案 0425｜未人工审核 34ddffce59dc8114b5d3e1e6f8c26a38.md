## 1. 子系统定位

S13 定义多人房间中玩家之间如何共享同一个世界，但不把核心体验变成强 PvP。

一句话定位：

> S13 决定其他玩家的行动何时对我产生间接影响、我能知道多少，以及多人竞争如何不破坏长期轮回体验。
> 

## 2. MVP 多人原则

MVP 多人默认：

```
分宗并行 + 间接竞争 + PvE 沙盒演化
```

不以玩家直接合作、直接对抗或频繁社交互动作为核心验证目标。

## 3. 允许的 MVP 竞争

MVP 保留两类轻量间接竞争：

1. 宗门节点控制竞争。
2. 世界资源名额竞争。

示例：

- 玩家 A 影响宗门占住灵脉节点，玩家 B 所属宗门取得资源成本上升。
- 某季度秘境名额有限，玩家所在宗门竞争进入资格。
- 一个节点控制权变化导致地图通行、事件优先响应或资源收益变化。

## 4. 不作为 MVP 核心的内容

以下不进入 MVP 核心验证：

- 玩家直接斗法。
- 玩家直接交易和赠予。
- 玩家互相护法。
- 共同秘境。
- 抢夺玩家洞府。
- 破坏他人突破。
- 离线袭击玩家主体。
- 围杀转世角色。
- 复杂同宗议事投票。

若后续实现，也只能作为低成本附加能力，不能影响核心闭环开发。

## 5. 分宗与同宗

MVP 默认鼓励玩家加入不同宗门，但不硬性禁止同宗。

如果同宗：

- 多个玩家可提出宗门建议。
- 采纳由 S5 权限、职位、声望、贡献和宗门 AI 倾向决定。
- 不做玩家之间强制投票。
- 不允许通过宗门行动直接毁掉同宗玩家的长期体验。

## 6. 行动可见性

玩家行动不是全图公开。

可见性来源：

- 角色是否同节点。
- 是否同宗门或有权限查看。
- 行动是否公开。
- 行踪是否暴露。
- 是否进入传闻。
- 是否由宗门日志或世界事件公开。

最小可见性层级：

```
private
local_visible
sect_visible
rumor_visible
world_visible
debug_only
```

## 7. 传闻传播

S10 生成世界日志后，S13 决定哪些内容变成传闻。

传闻受以下因素影响：

- 事件公开性。
- 地点人流。
- 宗门关系。
- 玩家声望。
- 行踪暴露标签。
- 事件严重度。
- 情报能力。

传闻可以模糊、延迟、不完整，不能等同于全知日志。

## 8. 资源名额竞争

资源名额竞争适合 MVP，因为它能制造多人压力但不直接毁掉玩家角色。

名额对象：

- 秘境进入名额。
- 宗门突破支持名额。
- 高级修炼场地。
- 关键资源采集窗口。
- 节点事件优先响应权。

竞争结果由 S7、S8、S10 结算，S13 负责玩家可见提示与多人语义。

## 9. 节点控制竞争

节点控制由宗门行动、影响力、驻守、建设、事件处理共同改变。

玩家通过影响各自宗门行动参与竞争，而不是直接点击“攻击某玩家”。

S13 负责：

- 提示哪些节点处于竞争态势。
- 展示可见宗门动向。
- 把对手宗门行动转换成传闻、情报或结果反馈。
- 防止直接玩家伤害成为核心路径。

## 10. 多人结果反馈

季度结算后，玩家应看到：

- 自己行动结果。
- 所属宗门行动结果。
- 已知竞争节点变化。
- 可见资源名额结果。
- 与自身相关的传闻。
- 不展示 debug_only 世界全日志。

## 11. 与其他系统的接口

- S1：读取房间玩家、结算顺序和结果汇总。
- S3：读取行踪暴露上下文。
- S5：读取同宗权限和建议冲突。
- S7：读取宗门行动竞争结果。
- S8：读取节点控制权和影响力变化。
- S10：读取事件公开性和传闻候选。
- S11：保护正式后手，不允许被多人系统无原因暴露。
- S14：持久化可见性、传闻和多人日志。

## 12. MVP 验收标准

1. 3 名玩家可在同一房间提交季度行动。
2. 玩家可加入不同宗门并影响各自宗门行动。
3. 至少一个节点能因不同宗门行动发生控制 / 影响力竞争。
4. 至少一个资源名额能被多个宗门竞争。
5. 玩家只能看到符合可见性规则的信息。
6. 多人竞争不会直接杀死、抢夺或毁掉其他玩家主体。
