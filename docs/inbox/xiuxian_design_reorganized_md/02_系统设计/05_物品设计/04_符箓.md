# 物品设计｜符箓

## 1. 设计定位

符箓是物品，也是消耗品。符箓以“一张 / 一枚”为最小使用单位，一次性使用；使用成功进入结算后消耗对应数量，不作为装备栏式长期挂件，也不作为绕过行动、事件或战斗结算的即时万能按钮。

当前定版口径：

1. 符箓必须位于资产容器中，例如角色随身、角色储藏、宗门库存、商店库存、NPC 持有物、节点奖励、事件锁定奖励或后手封存。
2. 普通符箓可以作为可堆叠物品；高价值、命名、残缺、封印、剧情、后手封存或带独立状态的符箓应作为 `ItemInstance` 追踪。
3. 符箓可以作为行动资源输入、事件选项资源、战斗指令来源、危险语境防护资源或一次性功能道具。
4. 符箓效果由模板配置决定，可以是一次性生效，也可以创建持续效果。
5. 符箓是否随机不由“符箓”这一类型决定，而由效果配置数值决定；同类符箓可以有确定性模板，也可以有随机波动模板。
6. 所有消耗、效果、生效时长、随机抽取值、失败原因、残余状态和结果都必须写入资源使用日志、事件结果包、战斗结果包或行动回放。

明确不做：

1. 不允许符箓在未消耗物品的情况下反复触发。
2. 不允许符箓绕过服务端资源使用接口、事件结果包、战斗结果包和日志。
3. 不允许普通符箓在堆叠内预先保存每个单体的独立随机值。
4. 不允许符箓以“被动装备”方式长期提供无消耗增益；如需长期佩戴类效果，应进入法宝、护符或装备类设计。
5. 不允许修炼辅助符箓即时增加修为；若符箓提供修炼辅助，只能作为兼容修炼行动的资源输入或临时状态修正。

## 2. 物品身份与堆叠

最小字段建议：

```text
TalismanItem {
  item_instance_id: String | null
  item_template_id: String
  container_id: String
  quantity: int
  item_type: talisman
  item_category: consumable
  tier: String
  quality: String
  tags: Array
  stack_key: String
  talisman_effect_template_id: String
  source_ref: String
  visibility_policy: String
  bound_effect_refs: Array
}
```

堆叠条件至少要求：

1. 模板相同。
2. 阶级相同。
3. 品级相同。
4. 关键状态相同。
5. 效果模板相同。
6. 未绑定独立事件、后手、来源审计、特殊残缺、封印或缺陷。

一次性使用的含义：

1. 从 `ItemStack` 使用符箓时，消耗 `quantity = 1`。
2. 从 `ItemInstance` 使用符箓时，该实例进入已消耗、破裂、焚毁、失效或事件专用终态。
3. 若符箓创建持续效果，消耗发生在效果实例创建或战斗 / 事件指令实际生效时；之后的剩余时长属于 `ActiveResourceEffect`，不再属于原符箓物品。
4. 若行动未开始、事件选项未生效、战斗指令未执行或使用确认失败，则不消耗符箓。

## 3. 分类与对应语境

| 类型 | 对应行动 / 语境 | 效果通道 | 生效方式 |
| --- | --- | --- | --- |
| 攻击符 | 战斗指令、事件战斗选项、破障交锋 | `combat_damage` / `combat_command` | 一次性生效，或持续若干战斗轮 |
| 防护符 | 战斗、防守、护体、渡险、护心 | `shield` / `damage_reduction` / `risk_delta` | 一次性抵消，或持续时长 / 战斗轮 |
| 遁行符 / 移动符 | 移动、逃离、追击、跨越危险路线 | `movement_modifier` / `escape_modifier` | 一次性移动修正，或路线片段持续 |
| 探索符 / 感知符 | 探索、侦查、寻物、识别隐藏线索 | `exploration_modifier` / `detection_modifier` | 一次性检定修正，或探索时长持续 |
| 避瘴符 / 解毒符 | 毒瘴、毒雾、腐蚀、寒热等危险语境 | `hazard_resist` | 危险暴露小时内持续 |
| 破禁符 / 破阵符 | 阵法、禁制、秘境门、封印、机关 | `array_modifier` / `barrier_break` | 一次性事件选项或短时破禁窗口 |
| 定心符 / 清神符 | 巩固根基、突破准备、研习、心魔压制 | `pressure_control` / `mind_stability_delta` | 兼容行动小时，或事件模板指定 |
| 聚灵符 / 辅修符 | 主动吐纳、阵法辅助、短期修炼准备 | `cultivation_aura` / `action_modifier` | 兼容行动小时；不得即时涨修为 |
| 传讯符 / 标记符 | 传讯、求援、标记坐标、触发剧情联系 | `event_unlock` / `communication` | 一次性事件生效 |

分类只表达常见用途，不限制后续内容表扩展。每张符箓最终以效果模板的 `effect_type`、`use_mode`、`compatible_action_tags` 和 `compatible_context_tags` 决定是否可用。

## 4. 效果模板

符箓效果与丹药类似，必须由可配置的资源效果模板定价，不直接写死为不可追踪的脚本效果。

```text
TalismanEffectBalance {
  talisman_effect_template_id: String
  effect_type: combat_damage | combat_command | shield | damage_reduction | hazard_resist | movement_modifier | escape_modifier | exploration_modifier | detection_modifier | array_modifier | barrier_break | pressure_control | cultivation_aura | action_modifier | event_unlock | communication
  use_mode: action_resource_input | event_only | combat_command | use_confirm | auto_trigger
  valid_segment_tags: Array
  compatible_action_tags: Array
  compatible_context_tags: Array
  activation_policy: consume_on_action_start | consume_on_event_option | consume_on_combat_command | consume_on_use_confirm | consume_on_trigger
  resolution_mode: instant | duration
  effect_tick_mode: none | compatible_action_hours | hazard_exposure_hours | combat_rounds | world_elapsed_hours
  base_effect_amount: number
  unit_effect_rate: number | null
  effect_amount_min: number
  effect_amount_max: number
  effect_rate_min: number | null
  effect_rate_max: number | null
  effect_random_distribution: fixed | normal_clamped
  max_effective_hours: number | null
  max_effective_rounds: int | null
  target_scope: self | ally | enemy | area | route | node | event_target
  stacking_group: String
  max_same_group_active: int
  residual_policy: none | stable_suspend | slow_decay | event_locked | dissipate_on_interrupt
  failure_modes: Array
  preview_policy: exact | range | qualitative | hidden
  log_level: normal | important | critical
}
```

`resolution_mode = instant` 表示符箓只在一次事件、一次战斗指令、一次检定或一次资源结算点生效。结算完成后，符箓已经消耗，不产生残余效果。

`resolution_mode = duration` 表示符箓消耗后创建 `ActiveResourceEffect` 或战斗 / 事件专用持续状态。持续效果可以按行动小时、危险暴露小时、战斗轮或世界流逝小时结算。

默认不使用无条件 `world_elapsed_hours`。只有隐身、强制燃烧、短时封印、传讯窗口、危险剧情符箓等明确需要“启用后不论玩家做什么都会倒计时”的模板，才使用 `world_elapsed_hours`。

## 5. 使用与结算生命周期

行动规划、事件选择、战斗指令或直接使用创建资源绑定：

```text
TalismanUseBinding {
  binding_id: String
  command_id: String | null
  event_option_id: String | null
  combat_round_id: String | null
  character_id: String
  source_container_id: String
  talisman_item_ref: String
  talisman_item_template_id: String
  talisman_effect_template_id: String
  effect_type: String
  use_mode: String
  activation_policy: String
  resolution_mode: instant | duration
  effect_tick_mode: String
  compatible_action_tags: Array
  compatible_context_tags: Array
  consumed_at_world_day: int | null
  consumed_at_world_hour: int | null
  rolled_effect_amount: number | null
  rolled_effect_rate: number | null
  active_effect_ref: String | null
}
```

执行前再次校验：

1. 角色是否持有或获准调用该符箓。
2. 符箓是否位于合法资产容器。
3. 当前行动、事件选项、战斗指令或使用语境是否允许该符箓。
4. 行动标签是否匹配 `compatible_action_tags`。
5. 地点、危险、战斗或事件上下文是否匹配 `compatible_context_tags`。
6. 是否违反同类持续效果叠加限制。
7. 若为自动触发，触发条件是否已被结果包确认。

一次性效果结算：

```text
消耗符箓 1 个单位
抽取或确认本次效果数值
将效果写入对应事件 / 战斗 / 行动结算段
写入资源消耗日志与结果包
```

持续效果结算：

```text
消耗符箓 1 个单位
创建 ActiveResourceEffect 或事件 / 战斗持续状态
按 effect_tick_mode 逐段结算
剩余时长、剩余效果量、衰减或中断处理写入日志
```

持续符箓被行动、战斗或事件打断时，已生效部分正常结算。未生效部分按照 `residual_policy` 处理：可以暂停为残余状态、缓慢散逸、锁定在事件内、直接消散，或由事件模板专门裁定。

## 6. 随机效果规则

符箓效果是否随机由配置决定。

确定性符箓：

```text
effect_random_distribution = fixed
effect_amount_min = effect_amount_max
或
effect_rate_min = effect_rate_max
```

随机波动符箓：

```text
effect_random_distribution = normal_clamped
effect_amount_min < effect_amount_max
或
effect_rate_min < effect_rate_max
```

结算要求：

1. 随机抽取发生在符箓实际激活、效果实例创建或战斗 / 事件指令实际生效时。
2. 抽取后的 `rolled_effect_amount` 或 `rolled_effect_rate` 必须固化到绑定、效果实例、结果包和回放日志。
3. C1 追赶、回放和补结算只使用已经固化的抽取值，不重新随机。
4. 可堆叠符箓不为堆叠内每个单体预先保存独立随机结果；从堆叠中消耗 1 个单位后，按模板和当前语境生成本次使用结果。
5. 若随机结果产生“未消耗但残缺”“封印未解”“特殊反噬”等独立状态，必须拆出 `ItemInstance` 或创建事件专用状态，不能继续留在普通堆叠中。

使用前 UI 至少应展示：

1. 大致效果方向。
2. 主要影响对象或系统。
3. 是否消耗符箓。
4. 是一次性生效还是持续生效。
5. 若有随机性，展示确定数值、范围、稳定 / 波动 / 危险 / 未知等预期。
6. 若有失败、反噬、破裂或副作用风险，必须明确提示。

## 7. 与丹药、法宝、材料的边界

符箓与丹药的共同点：

1. 都是可作为行动、事件或战斗输入的消耗型资源。
2. 都通过配置模板决定效果值、持续时长、随机性和残余策略。
3. 都必须进入资源使用日志、结果包和回放。

符箓与丹药的区别：

1. 丹药通常表达体内吸收、炼化、恢复、承载、药性残余和长期状态改变。
2. 符箓通常表达外部触发、术式封存、战斗指令、护盾、防护、移动、探索、破禁和事件交互。
3. 符箓默认一次性燃烧、破裂或失效；若出现持续效果，持续的是术式效果，不是原物品继续存在。

符箓与法宝的区别：

1. 法宝可以长期持有、反复使用、养成、维护和产生来历关系。
2. 符箓是一次性消耗物，不承载长期装备成长。
3. 若某设计需要可反复使用的符箓类物件，应改入法宝、护符或装备体系。

符箓与材料的区别：

1. 材料主要用于生产、兑换、任务提交或配方输入。
2. 符箓主要用于使用结算。
3. 制符材料进入材料体系；制成后的符箓进入消耗品体系。
