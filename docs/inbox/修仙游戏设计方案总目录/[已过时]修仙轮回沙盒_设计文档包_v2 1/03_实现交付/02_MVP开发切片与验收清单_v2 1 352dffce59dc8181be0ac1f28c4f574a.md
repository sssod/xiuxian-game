# MVP 开发切片与验收清单（v2.1）

## 0. 文档定位

本文将新版设计拆成可实现、可测试、可验收的开发切片。目标是避免一次性实现完整大系统，而是通过纵向闭环逐步验证核心体验。

MVP 总目标：

```
本地可单人测试
+ 可部署私人服务器
+ 支持 3 人共玩
+ M0 → M3 纵向闭环
```

---

## 1. 开发切片总览

| 切片 | 名称 | 核心目标 |
| --- | --- | --- |
| VS0 | 技术底座 | 回合、权威结算、存档、配置、日志 |
| VS1 | 角色与新手入门 | 真灵、当世角色、初始地图、拜入宗门 |
| VS2 | 个人行动经济与事件 | 回合时间预算条、指令队列、移动、选择事件 |

## 2. VS0：技术底座

### 目标

建立可运行的房间循环和服务端权威结算框架。

### 必做

- 本地单人房间创建。
- 简化私人服务器运行。
- 房间状态。
- 回合阶段机。
- 回合配置 `TurnConfig`。
- 玩家锁定。
- 服务端统一结算。
- 结果包接口。
- 基础日志。
- 存档保存 / 读取。
- 配置加载。
- Debug 状态查看。
- TurnReplay。

### 验收

- 能创建房间并进入回合开始。
- 能从个人行动阶段锁定。
- 能执行一次空结算进入下一回合。
- 能配置每回合游戏天数，默认 5 天。
- 能配置决策倒计时，默认 120 秒。
- 退出后可读取存档继续。
- Debug 面板能看到 phase、turn_id、world_day、world_hour、玩家、状态版本。

## 3. VS1：角色与新手入门

### 目标

跑通“创建真灵 → 初次投生 → 获取基础信息 → 拜入宗门”的新手流程。

### 必做

- 真灵创建。
- 当世角色生成。
- 基础属性：体魄、精力。
- 资质子项：根骨、悟性、灵根。
- 状态条：生机、元气、神念。
- 初始村庄节点。
- 已知 / 半知 / 初步解锁节点。
- 角色日志。
- 新手任务：找村长打听宗门。
- 家庭支持事件。
- 镇集武馆学习轻身功法。
- 前往山门。
- 入门事件链。
- 获得外门身份与基础功法。

### 验收

- 玩家能从青禾村出发，按流程抵达宗门山门。
- 途中至少触发一次移动事件。
- 入门事件能揭示资质子项并给予外门身份。
- 入门 follow-up 修炼作为事件链奖励结算，不计为第二个普通持续行动。

## 4. VS2：个人行动经济与事件

### 目标

让玩家每回合用线性行动指令规划移动和持续行动，并触发常规事件。

### 必做

- 回合时间预算条 UI / 数据。
- 天级预算条显示。
- 指令式行动输入。
- 个人即时行动、移动行动、持续行动。
- 固定执行时间 / 可选投入执行时间。
- 待锁定预案。
- 服务端生成小时级时间线。
- 移动事件。
- 选择事件。
- 事件结果包。
- 角色结束位置权威写入。
- 休整 / 警戒 / 停留。
- 原计划 vs 实际结果报告。

### 验收

- 玩家可输入 1–3 条行动指令占满默认 5 天预算。
- 玩家可选择“投入剩余时间”。
- 玩家可移动到目标节点并消耗实际小时数。
- 服务端可因事件改变实际结束位置。
- 常规事件显示 1–3 个主选项。
- 事件结果包能改变角色状态、库存或日志。
- 事件消耗小时后，后续行动开始时间自动推迟。
- 回合结束报告能解释计划与实际差异。

## 5. VS3：修炼与小境界

### 目标

跑通基础修炼成长，不进入大突破。

### 必做

- 主修道功。
- 自动运转。
- 主动吐纳。
- 研习功法。
- 修为进度。
- 功法经验。
- 主修道功支持范围。
- 小境界升级。
- 修为纯度数据层保留。
- 寿元基础显示。

### 验收

- 主动吐纳占用实际时间并增加修为。
- 自动运转可在合法小时提供少量收益。
- 主动吐纳期间不叠加自动运转。
- 修为达到条件后可从 A-1 升到 A-2。
- 小境界升级不进入突破事件链。
- 主修道功不支持下一阶段时，修为推进被限制。

## 6. VS4：宗门资源平台与 AI

### 目标

让宗门成为真实资源平台和 AI 演化组织，而不是背景文本或玩家直接控制队列。

### 必做

- 宗门身份层级。
- 权限标签。
- 贡献记录。
- 门内声望。
- 宗门库存五类资源。
- 资源申请。
- 资源预留。
- 每宗门同一时间 1 个宗门持续行动。
- 宗门 AI 选择 / 推进 / 中止持续行动。
- 常态资源节点产出。
- 宗门当前持续行动摘要 UI。
- 玩家亲自介入宗门相关个人行动。

### 验收

- 玩家可因身份获得设施使用或资源申请权限。
- 宗门支持资源来自真实库存。
- 贡献不能直接兑换资源。
- 宗门不再要求玩家提交主行动建议。
- 宗门同一时间只有 1 个 active_continuous_action。
- 宗门当前持续行动可跨多个回合推进。
- 已控制资源节点可常态产出，不占持续行动槽。
- 玩家介入宗门相关行动需要通过个人行动抵达节点或事件窗口。

## 7. VS5：物品与经济可信

### 目标

建立资产容器、物品、灵石、关键突破物和 NPC 库存可信边界。

### 必做

- 资产容器。
- 灵石。
- 低阶货币接口。
- 聚灵石接口。
- ItemStack / ItemInstance。
- 物品 Tier + Quality。
- 随身资产标签。
- 无装备栏战斗资源来源。
- 资源使用日志。
- 关键突破物。
- ShopStock。
- N3 / N4 库存持久化。
- 禁止战斗开始临时初始化 NPC 完整库存。

### 验收

- 玩家获得物品后有明确资产容器。
- 玩家使用资源会写日志，并记录 turn_id / world_hour。
- 关键突破物是具体实例。
- 商店库存不属于掌柜个人。
- 战斗战利品只来自持久化资产、事件锁定奖励或预算生成奖励。
- 背包不使用重量、体积、格子限制。

## 8. VS6：大境界突破

### 目标

跑通第一次关键突破链 M1 → M2。

### 必做

- 大境界瓶颈。
- 突破准备面板。
- 固定执行时间突破行动。
- 风险档位。
- 主要短板。
- 失败标签方向。
- 关键突破物消耗。
- 主修道功读取突破模板。
- 专用突破事件链。
- 成功 / 失败存活 / 身死转世。
- 失败标签写入轮回账本。
- 突破结果包。

### 验收

- 玩家不能通过自动运转跨越大境界。
- 玩家必须主动选择突破。
- 突破显示固定执行时间和不可逆资源消耗。
- 事件链创建时消耗关键突破物。
- 突破失败不是只显示“失败”，而有原因标签。
- 身死转世能进入转世流程。
- 轮回账本能显示本次突破信息。

---

## 9. VS7：世界演化

### 目标

让世界节点和宗门 AI 产生可见变化。

### 必做

- 35±10 节点首图。
- 3 个主要宗门。
- 宗门核心 / 腹地 / 边界 / 荒野区域。
- 节点控制权与影响力。
- 资源槽。
- 建筑槽。
- 秘境入口。
- 传闻。
- 宗门 AI 持续行动影响节点。
- 节点事件触发控制权变化。

### 验收

- 节点能显示控制权、危险、灵气和资源摘要。
- 宗门 AI 能推进一个节点相关持续行动。
- 玩家行动可改变节点状态或影响力。
- 资源槽可被采集、枯竭、再生或异变。
- 传闻可由世界日志生成并延迟传播。

---

## 10. VS8：转世与后手

### 目标

跑通死亡、转世、正式后手创建与回收。

### 必做

- 死亡事件链。
- 转世初始化。
- 执念权重。
- 正式后手容量。
- 后手创建持续行动。
- 后手记录写入节点层和轮回账本。
- 后手感应。
- 后手回收事件链。
- 后手失效原因链。

### 验收

- 正式后手有位置、日志和容量占用。
- 后手创建占用时间预算，不是即时完成。
- 下一世可通过账本和线索定位后手。
- 后手可以暴露、受损、被转移或失效，但必须有原因链。
- 托管不得主动执行高风险后手回收。

---

## 11. VS9：3 人共玩

### 目标

验证多人锁定、托管、共享世界和间接竞争。

### 必做

- 3 人房间。
- 玩家独立真灵与当世角色。
- 全员锁定或超时。
- 托管生成。
- 共享地图状态。
- 分宗或同宗状态。
- 不显示其他玩家详细输入。
- 传闻与可见性。
- 宗门 AI 独立演化。

### 验收

- 任一玩家超时后可由托管生成低风险计划。
- 全员锁定 / 超时后自动结算。
- 玩家不能看到其他玩家详细行动指令。
- 世界节点变化能被不同玩家以不同可见性看到。
- 多人竞争主要通过宗门、节点、资源、传闻和秘境窗口间接发生。
