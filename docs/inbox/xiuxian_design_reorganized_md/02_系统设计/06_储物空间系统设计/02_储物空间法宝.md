# 储物空间系统设计｜储物空间法宝

## 1. 当前结论

储物空间法宝在 MVP 阶段不开发独立玩法系统，只保留基础概念设定。

储物空间法宝是基础行囊的升级版本概念。它代表角色未来可能获得的特殊储物法宝，但当前不是核心玩法，也不承担背包容量成长、负重管理、格子扩展或空间经营功能。

## 2. MVP 边界

MVP 中储物空间法宝遵守以下边界：

1. 不制作独立储物空间法宝系统。
2. 不设置玩法层物品栏数量上限。
3. 物品栏数量只保留程序层上限，用于性能、存档和异常防护。
4. 不做重量、体积、背包格子、负重、容量成长或扩容玩法。
5. 不做储物法宝的战斗中取物、被偷取、掉落、空间破碎、内部资产继承等规则。
6. 若储物空间法宝在文本、奖励或设定中出现，先按普通法宝概念记录，不开放额外取放和容量结算。

## 3. 基础概念

储物空间法宝可以理解为一个特殊法宝实例，未来可能关联一个内部资产容器。

概念关系：

```text
当前世角色
→ 持有或绑定储物空间法宝
→ 储物空间法宝可作为特殊资产容器入口
→ 内部资产仍必须遵守资产位置、权限、可见性和日志规则
```

储物空间法宝不是万能背包。即使未来开发，也不能绕过物品来源、资产位置、权限、交易、事件、战斗、后手封存或死亡结算。

储物空间法宝也不能绕过遗产与后手边界。宗门个人洞府库存仍可按宗门遗产清点回收；宗门外洞府和普通藏宝仍需开启条件或破阵结果；真灵藏宝仍需同一真灵感应和开启，并受设置数量与单个容量限制。

若未来开发内部资产容器，容器字段、权限、预留、锁定和流水应复用《03_库存系统》，不得另建一套背包容量或无来源资产规则。

## 4. 与基础行囊的关系

基础行囊是 MVP 的默认随身资产概念；储物空间法宝是未来对基础行囊的特殊升级表现。

MVP 中：

1. 基础行囊不做玩法层容量上限。
2. 法宝、道具、材料和资源是否可用，由随身状态、上下文、标签、权限、绑定和事件条件决定。
3. 储物空间法宝不会改变上述规则。
4. 储物空间法宝不会在 MVP 中提供额外可操作容量或特殊 UI 页面。

## 5. 后续扩展占位

若后续开发储物空间法宝，需要另行裁决：

1. 内部资产容器字段与权限规则。
2. 法宝被损毁、封存、绑定或角色死亡时，内部资产如何处理。
3. 是否允许战斗、突破、移动或事件中从储物空间取物。
4. 储物空间法宝是否可以升级、扩容、污染、封印或被追踪。
5. 储物空间法宝与后手、遗产、宗门审计、战利品分配之间的结算规则。

2026-05-11：同步后手与遗产边界。储物空间法宝不提供绕过宗门遗产清点、宗门外洞府 / 普通藏宝开启条件或真灵藏宝数量容量限制的例外。
