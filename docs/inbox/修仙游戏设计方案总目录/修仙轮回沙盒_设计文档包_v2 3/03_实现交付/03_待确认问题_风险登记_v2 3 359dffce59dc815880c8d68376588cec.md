# 待确认问题与风险登记（v2.3）

## 1. 当前决议

当前开发口径已经统一为：

```
共享世界日历；
服务器 1 游戏小时 tick；
F1 / N1 / B1 / P0 速度状态机；
当前执行指令 + 最多 3 条预输入指令；
自动兜底强制 N1；
显式托管由玩家主动输入；
个人非交锋事件局部时停；
局部时停 gap 上限 1 游戏日；
C1 追赶只补确定性内容；
正式交锋与突破挑战进入 B1；
个人突破主要消耗发生在突破挑战轮内；
回放使用 TimelineReplay。
```

本版没有阻塞开发启动的设定待决项。当前阶段需要把数值模型、公式、事件、功法、物品和模板样例作为设计验证对象持续落地。

---

## 2. 数值 / 内容 / 模板滚动落地事项

以下事项不再只作为后置补表。它们是当前数值设计与系统设计互校的持续工作面；每次确定公式、曲线、模板或样例数值后，需要更新对应系统文档，并在包根 `CHANGELOG.md` 记录变更。

1. 行动模板基础字段：实际耗时、收益、风险曲线、`long_low_interaction`、`f1_eligible_when_explicit`、`can_be_auto_fallback` 与 `risk_sensitive_fallback`。
2. 修炼成长模型：修为数值曲线、根骨承载公式、境界阈值、寿元影响和突破条件。
3. 资源输入模板：丹药、灵材、符箓等 `ActionResourceInputBinding` 样例数值、兼容小时、残余策略和 `ActiveResourceEffect` 效果。
4. 节点风险等级 `low / medium / high / unknown` 判定表、节点默认兜底行动表和资源槽刷新规则。
5. 闭关三档预案的风险阈值、收益修正、事件触发条件和局部时停 / B1 升级边界。
6. 显式托管低价值事件白名单、重大事件通知规则和默认选项策略。
7. B1 交锋轮普通 / 复杂 / 硬上限模板表、默认策略和模板结局。
8. 突破挑战各轮资源消耗模板、轮内选项、失败代价和结果报告样例。
9. 24 小时 gap 默认选项与 P0 同步保护事件清单。
10. C1 追赶补结算确定性字段白名单。
11. UI 速度提示与私人归因屏蔽文案表。

## 3. 风险登记

| 风险 | 描述 | 缓解 |
| --- | --- | --- |
| R01 F1 被误解为跳时 | 高速推进仍需连续 tick 与中断检查 | F1 仅走 `SpeedState`，每小时仍结算并检查事件 / 交锋 / 队列完成 |
| R02 自动兜底被滥用 | 玩家可能依赖低收益兜底长期挂机 | `FallbackState.force_speed=N1` 且 `f1_eligible=false` |
| R03 显式托管吞掉关键事件 | 托管可能被误做成复杂 AI | 托管只覆盖低价值事件，重大事件走局部时停 / B1 / P0 |
| R04 突破预输入边界不清 | 开启突破与挑战轮内策略可能被混用 | `breakthrough_open` 只保存开启指令，挑战轮使用 `FormalEncounterState` |
| R05 局部时停信息泄露 | 其他玩家可能从速度变化推测私人事件 | UI 只显示中性 `public_reason_key` |
| R06 C1 追赶触发循环事件 | 追赶期间再次触发随机事件会导致循环 | `CatchupSettlementState.deterministic_only=true` |
| R07 B1 拖慢非参战玩家 | 正式交锋会使全世界进入慢速 | 控制轮数、默认策略、硬上限与模板结局 |
| R08 字段口径漂移 | 开发中容易出现多套时间字段 | 以 v2.3 术语表和字段检查清单为 schema 入口 |
| R09 UI 过度暴露调试信息 | Debug 字段进入玩家界面会影响多人体验 | 玩家 UI 与 Debug 面板数据源分层 |

## 4. 验收关注点

开发验收时优先检查：

```
world_day / world_hour 是否是唯一运行时间事实；
CommandQueue 是否限制为当前 + 3 后续；
入队与执行前校验是否都有日志；
FallbackState 是否总是 force_speed=N1；
ManagedActionState 是否只能来自玩家主动输入或房间规则；
LocalTimeStopState gap 是否按 12/18/24h 提示；
C1 是否只结算确定性内容；
FormalEncounterState 是否复用给突破挑战；
TimelineReplay 是否记录速度片段和关键状态；
UI 是否屏蔽私人归因。
```
