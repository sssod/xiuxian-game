# 文档架构与迁移计划

状态：首批正式迁移计划
更新日期：2026-05-08
适用阶段：design finalization / development handoff preparation

## 1. 目的

本文定义 `docs/inbox` 原始资料如何收敛到正式 `docs` 目录。后续实现、验收、UI、数据契约和制作管理应优先从正式 docs 读取；`docs/inbox` 保持为来源档案，不作为长期承载区。

当前主源是：

```text
docs/inbox/修仙游戏设计方案总目录/修仙轮回沙盒_设计文档包_v2 3/
```

旧版本与 `[已过时]` 文件只用于比对、补充来源背景和识别冲突，不作为主动权威。

## 2. 正式目录职责

| 目录 | 承载内容 | 迁移原则 |
| --- | --- | --- |
| `docs/concept` | 项目定位、玩家承诺、设计基石、MVP 边界 | 面向制作人与新成员快速理解项目，不承载详细数据结构 |
| `docs/game-design` | 玩家循环、房间流程、行动规则、失败、死亡、轮回 | 写玩家可感知规则和玩法流，不写底层 schema 细节 |
| `docs/systems-design` | 时间系统、房间状态、结算总线、宗门、地图、经济、数据契约 | 写服务端权威规则、结果包、状态模型和跨系统接口 |
| `docs/ui-design` | 屏幕清单、交互状态、速度展示、队列控件、Figma 参考 | 写稳定 UI 行为；节点级布局以当前 UI artifact / Figma 为准 |
| `docs/worldbuilding` | 世界观、宗门、地点、势力、 lore 术语 | 只承载 lore-facing 内容，不混入运行时字段 |
| `docs/production` | MVP 切片、验收清单、风险登记、技术决策门 | 面向排期、QA、开发交付和未决项管理 |
| `docs/references` | 术语表、字段索引、来源映射、冲突裁决、外部资源 | 作为命名和 provenance 的统一入口 |
| `docs/research` | 调研、竞品、未定分析 | 不作为最终设计承诺 |
| `docs/playtest` | 测试计划、反馈、观察、调参记录 | 记录验证结果和后续调整依据 |

## 4. 迁移工作流

1. 先读正式 docs 中是否已有该主题文档；已有则更新，不另建重复文档。
2. 再读 v2.3 README 与该主题 v2.3 主源。
3. 旧版和 `[已过时]` 文件只用于确认冲突历史、迁移别名和遗漏背景。
4. 每份正式文档保留“来源与裁决”段，记录：
   - 吸收了哪些 inbox 主源。
   - 是否参考了阶段性规则或旧版冲突记录。
   - 采用了什么最终口径。
   - 废弃了什么旧口径。
   - 对实现、UI、验收或数据契约的影响。
5. 旧术语仅作为 deprecated aliases / migration notes / conflict history 保留，不作为 active concept。

## 5. 当前核心裁决

| 冲突主题 | 采用口径 | 废弃口径 | 实现影响 |
| --- | --- | --- | --- |
| 玩家面对的时间结构 | 共享连续世界日历，字段为 `world_day / world_hour` | `turn_id` 作为玩家最小推进单位、`quarter` 玩家回合 | 状态、事件、日志、回放和结果包都必须落到绝对世界小时 |
| 服务器结算单位 | `hour_tick`，1 游戏日 = 24 游戏小时 | 行动格、季度格、混用 tick | 服务端按小时统一结算，UI 不做逐小时排班 |
| 玩家行动输入 | `Command` + `CommandQueue`，当前指令 + 最多 3 条预输入 | 每季度 6 个朔望行动格、`action_slot`、条件脚本 | 入队只校验当前已合法；执行前再次校验 |
| 回放结构 | `TimelineReplay` | `TurnReplay`、`QuarterReplay` | 回放记录速度片段、队列变化、事件、交锋轮、结果包和结算步骤 |
| 宗门输入 | 宗门为组织资源平台，宗门 AI 维护 `SectContinuousActionState` | 玩家宗门即时指令、宗门主行动建议、`SectDecisionIntent` | 玩家通过身份、贡献、申请、亲自参与和事件结果间接影响宗门 |
| 玩家侧跳时 | 不做玩家侧未来跳转；F1 是连续 tick 压缩推进 | 推进至下一事件 / 下一关键节点 / 月末 | F1 运行中仍逐小时检查事件、队列完成、交锋和 P0 条件 |
| 突破与正式战斗 | `FormalEncounterState`，B1 每轮 = 1 游戏小时 | 个人突破多次 P0、正式战斗 P0 | 突破真实资源消耗发生在 B1 轮内 |
