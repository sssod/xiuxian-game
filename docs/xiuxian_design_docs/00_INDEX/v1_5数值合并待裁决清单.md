# v1.5 数值合并待裁决清单

适用范围：`docs/xiuxian_design_docs` 中本次吸收 `docs/inbox/design_changed_input/01_标准数值方案_v1_5.md` 与 `03_跨系统数值修改裁定_v1_5.md` 后仍不能机械定稿的数值、系统和交互问题。

## 1. 当前定位

本文只记录本次合并后需要用户裁决或后续补表的项目。已能稳定采用的口径已经写入对应正式文档，尤其是《时间速度与局部时间域数值设计》（`../03_数值设计/10_时间速度与局部时间域数值设计.md`）。

本文不保留包外来源全文，不作为新数值公式来源，也不记录实现模块、调参器代码或本地工具细节。

## 2. 使用方式

1. 实现或继续修订相关系统前，先检查本文是否存在阻塞该主题的待裁决项。
2. 用户裁决后，应把稳定结论写回对应主题文档，再从本文删除或改写该项。
3. 若后续发现正式包内部仍有旧口径残留，应在本文补充“冲突残留”项，并指向需要修订的包内文档。

## 3. 待裁决与冲突项

| 项目 | 当前已合并口径 | 需要裁决或补充 |
| --- | --- | --- |
| 分阶段现实目标重排 | 默认 32 小时作为“大乘圆满并突破进入渡劫期”的理论直线参考；F1 默认 1.5 秒 / 外界日并保留 1 / 1.5 / 2 秒调参档；当前约 47.55 外界年基线已接受；现实时间基线和外界年极限可 Debug 到 50 小时 / 100 年 | 需要重排各境界段现实目标、F1 闭关时间和有效倍率，使默认基线与调试基线都可复算 |
| F1 批量结算 | 采用“最近安全断点 + 最大批次上限”，不逐小时全量展开 | 早期 / 中期 / 后期批次上限是否固定为 1-3 日、7-15 日、30-90 日，或按人数和事件密度动态调整 |
| 事件流采样 | F1 中接受预定事件、阈值 crossing time、危险率采样和条件区间采样 | 是否正式采用非逐小时掷骰模型，以及 Debug / 回放展示精度 |
| 自动处理事件范围 | `silent / summary / auto / soft_interrupt / hard_interrupt` 五级已合并 | 需要列出可自动事件白名单、禁止托管标签和硬中断标签 |
| 洞天 T0-T5 | 已合并分级结构，不锁具体倍率 | 需要补每档时间倍率、进入上限、维护成本、燃料成本、心魔 / 经脉风险和开放窗口表 |
| 洞天资源不足收益 | 资源不足年份保留 0%-20% 基础收益，并提高风险 | 是否按境界、资源类型、功法适配或洞天品级调整该范围 |
| 局部时间域分配 | 默认 70% 修行成长、30% 支持行为；修行成长中 20% 功法研习、80% 道功修炼 | 是否按境界、功法复杂度、路线标签或洞天类型动态变化 |
| 洞天外 F1 普通修炼占比 | 默认 F1 外界流年的 10%-20% 属于普通修炼 / 低阶修炼 | 是否按低阶更高、后期更低的曲线设置 |
| 多人离线托管 | 有显式托管可参与 F1；自动兜底不能参与 F1 | 离线保护窗口、长期无人在线推进和兜底策略需要单独裁决 |
| 轮回总时长 | 合理轮回不保证总通关时间短于单世通关 | 世界资源等待、大型投放窗口等待和结局质量收益如何估算 |
| HTML 调参器去向 | 不写入正式设计包正文；只作为包外建模输入来源 | 是否后续迁移到 `docs/development` 或工具目录，还是保留在 `docs/inbox/design_changed_input` |
| 化神以后宏观推进旧问题 | 不新增玩家可见宏观流年速度；复杂长期流年由 F1 批量结算承接 | 化神以后是否仍需要单独的高阶推进机制、资源周期或事件密度表 |
