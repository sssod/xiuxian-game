# 数值设计｜物品设计基准建模

## 1. 设计定位

本文负责物品的数值基准、阶级 / 品级口径、价值拆分、生成预算、堆叠与实例边界，以及资源输入模板如何进入修炼、突破、战斗、交易和后手系统。

本文回答：

1. 一个物品属于什么阶级，阶级如何影响价值和预算。
2. 一个物品是什么品级，品级如何影响价值、稳定性、浪费和风险。
3. 一个物品应作为可堆叠物品还是独立实例物品。
4. 一个资源输入物如何用 `ResourceEffectBalance` 定价。
5. 一个奖励、掉落、藏宝、商店补货或事件资产如何扣生成预算。
6. `BudgetValue`、`TradeValue`、`SalvageValue` 和 `ContributionValue` 的边界。

本文不负责：

1. 各个丹药、符箓、法宝、功法载体的完整内容表。
2. 商店买卖流程、寄售、税费和成交机制。
3. 宗门库存申请、审批和职位权限。
4. 节点资源池的完整再生、枯竭、污染和采集事件表。
5. 真灵藏宝的设置数量、单个容量和开启事件模板。
6. 每个宏观周期的最终预算点数。

## 2. 当前结论

物品基准不是简单奖励倍率，而是以下链路的组合：

```text
物品阶级
→ 物品品级
→ 物品类型基础价值
→ 效果预算
→ 稀缺度、状态、用途和限制
→ 预算价值 / 交易价值 / 回收价值 / 贡献价值
→ 资产容器、来源日志和结果包
```

当前定版口径：

1. `BudgetValue` 不等于 `TradeValue`。预算价值用于扣世界生成预算，交易价值用于买卖、估价和挂牌。
2. 世界生成预算在资产进入显性库存、事件锁定奖励、商店库存、节点库存、宗门库存或角色行囊时扣除；隐性候选生成不扣预算。
3. 出售、拆解、销毁、上交、回收、损坏或消耗不返还世界生成预算。
4. 自然资源池本身不是可取物品，也不直接消耗物品预算；经采集、加工、事件结算或设施产出转为显性资产后，再按物品或资源预算口径处理。
5. 普通材料、普通丹药、普通符箓可作为可堆叠物品；法宝、高价值完整功法载体、正式后手物、高价值突破资源、带独立状态或高价值来源的物品应作为 `ItemInstance`。
6. 修为丹药、灵材、符箓、聚灵石等资源输入物不应写死 raw 修为收益，应通过 `ResourceEffectBalance` 或等价模板表达单位效果、兼容小时、贡献上限、残余策略、压力和日志。
7. 正式后手物必须先是已存在的显性资产，再封存进真灵藏宝并占用真灵藏宝设置数量或单个容量；不能用数值建模绕过后手容量限制。

## 3. 统一字段

物品模板的数值层建议至少提供：

```yaml
ItemNumericProfile:
  item_template_id: string
  item_type: material | pill | talisman | artifact | method_carrier | currency_stack | condensed_spirit_stone | breakthrough_resource | quest_item | contingency_item
  tier_code: string
  tier_order: number
  quality_code: string
  quality_order: number
  stack_policy: stackable | instance
  value_category: common_resource | consumable_resource | durable_asset | method_asset | breakthrough_key | contingency_asset | currency
  base_category_value: number
  effect_profile_ref: string | null
  scarcity_profile_ref: string | null
  condition_profile_ref: string | null
  utility_tags: list
  trade_policy_ref: string | null
  budget_policy_ref: string | null
  salvage_policy_ref: string | null
  contribution_policy_ref: string | null
  provenance_policy: none | light | full
  log_level: normal | important | critical
```

运行时物品或物品栈建议至少保留：

```yaml
ItemNumericState:
  item_instance_id: string
  item_template_id: string
  container_id: string
  quantity: number
  tier_code: string
  quality_code: string
  stack_key: string
```

`budget_value_locked` 表示该资产生成时已扣除的预算价值快照。它不因后续买卖价格、通胀、关系折扣或节点行情变化而重算。

## 4. 阶级基准

物品阶级表达“适配哪个大境界或内容层级”，不是纯价格等级。它至少影响：

1. 生成预算所属阶级。
2. 资源输入与当前境界段的适配。
3. 交易和贡献估值基准。
4. 突破、战斗、后手、藏宝和事件模板的可用性。
5. 高阶资源对低阶角色的浪费、承载压力和反噬风险。

阶级默认与大境界大层级对齐：

| `tier_order` | `tier_code` | 表现层级 | 默认用途 |
| ---: | --- | --- | --- |
| 0 | `mundane` | 凡俗 / 入门 | 凡人货币、普通物资、新手教学物 |
| 1 | `qi_refining` | 炼气 | 基础丹药、符箓、低阶材料、入门功法载体 |
| 2 | `foundation` | 筑基 | 第一次大境界突破资源、宗门正式资源 |
| 3 | `golden_core` | 金丹 | 宗门骨干、高价值法宝、稀有配方资源 |
| 4 | `nascent_soul` | 元婴 | 区域强者、高级秘境与宗门核心资产 |
| 5 | `spirit_transformation` | 化神 | 第一阶段大后期资源和高风险机会 |
| 6 | `void_refining` | 炼虚 | 后期大宗资源与特殊事件资产 |
| 7 | `integration` | 合体 | 顶级宗门、区域格局级资产 |
| 8 | `mahayana` | 大乘 | 飞升前顶点资源、终局后手和稀有遗产 |

阶级倍率作为建模起点：

```text
T_tier = R_tier ^ (tier_order - 1)
R_tier = 8 ~ 20
```

使用规则：

1. `R_tier` 是调参区间，不是内容表定值。
2. 炼气阶物品可取 `T_tier = 1` 作为低阶物品价值锚。
3. 凡俗物资通常不进入修行世界主预算；若需要进入估价，可作为 `T_tier < 1` 的特殊层级处理。
4. 同阶品级差异应明显，但不应超过跨阶差异。
5. 高于当前阶段预算的物品不得通过普通刷新无来源出现，只能来自先锋泄漏、剧情、强敌真实资产、正式后手、专属资源池、事件锁定奖励或明确的高风险机会。

## 5. 品级基准

品级表达同阶内部的成色、纯度、稳定性、完整度、药力、符箓成符度、材料精炼度、法宝状态或功法载体保存质量。品级不应直接写成 raw 修为收益，而应进入效果模板、稳定性、残余策略、压力、浪费、识别难度和价格。

MVP 建模起点采用五档品级：

| `quality_code` | 表现名称 | `Q_quality` | 默认口径 |
| --- | --- | ---: | --- |
| `q1_low` | 下品 | 0.70 | 可用但浪费高，状态或副作用更明显 |
| `q2_mid` | 中品 | 0.90 | 普通可用，稳定性略低于标准 |
| `q3_high` | 上品 | 1.15 | 标准优质口径，适合作为常用奖励锚 |
| `q4_excellent` | 极品 | 1.45 | 稀有，效果、稳定性或用途显著更好 |
| `q5_perfect` | 绝品 | 1.90 | 极稀有，不应作为常规量产目标 |

品级进入资源效果时，默认通过 `quality_scaling_profile` 转换为 `resource_quality_factor`。不同物品类型可以覆盖默认倍率：

1. 丹药品级优先影响单位药力、稳定性、残余策略、浪费和经脉压力。
2. 符箓品级优先影响效果量、持续时长、失败率、破裂风险和预览精度。
3. 法宝品级优先影响耐久、充能、灵性、可用标签、修复成本和损坏后回收价值。
4. 功法载体品级优先影响完整度、保存状态、抄录 / 借阅 / 封印限制和交易价值，不直接提高角色学会后的掌握度收益。
5. 材料品级优先影响配方产物品级范围、失败波动、可替代性和回收价值。

## 6. 价值公式

物品标准价值从以下公式起步：

```text
V_std =
  B_category
  * T_tier
  * Q_quality
  * E_effect
  * S_scarcity
  * C_condition
  * U_utility
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `B_category` | 物品类型基础价值 |
| `T_tier` | 阶级倍率 |
| `Q_quality` | 品级倍率 |
| `E_effect` | 效果预算倍率 |
| `S_scarcity` | 稀缺度倍率 |
| `C_condition` | 状态、耐久、完整度、充能、污染等倍率 |
| `U_utility` | 用途覆盖倍率 |

状态倍率起点：

| 状态 | `C_condition` |
| --- | ---: |
| 完整 / 稳定 | 1.00 |
| 轻微受损 | 0.80 |
| 严重受损 | 0.45 |
| 破碎但可修复 | 0.20 |
| 污染且未净化 | 0.30 ~ 0.70 |

用途倍率起点：

```text
U_utility = 1 + utility_bonus - restriction_penalty
```

用途包括战斗、突破、修炼、宗门上交、制造、修复、拆解、封存、任务提交和事件解锁。限制包括绑定角色、宗门权限、使用阶段、地点、一次性消耗、副作用、封印、识别难度、因果风险和后手容量占用。

最终预算价值：

```text
V_final = V_std * D_random * D_optional_origin * D_information
BudgetValue = V_world_budget = V_final
```

预算价值规则：

1. `BudgetValue` 不乘通胀系数。
2. `BudgetValue` 不受商店买卖价、关系折扣或市场行情影响。
3. 跨阶使用时，生成预算仍按物品自身阶级扣除。
4. 交易价格可读取通胀、供需、节点状态、宗门关系、权限、声望和事件压力修正。

交易价格接口：

```text
BuyPrice =
  V_final
  * InflationCoeff
  * market_buy_spread
  * relation_modifier
  * scarcity_modifier
  * permission_modifier
  * event_pressure_modifier

SellPrice =
  V_final
  * InflationCoeff
  * market_sell_spread
  * relation_modifier
  * liquidity_modifier
  * condition_modifier
```

回收与贡献：

```text
SalvageValue =
  V_final
  * salvage_ratio_by_type
  * condition_modifier
  * facility_modifier
  * skill_modifier

ContributionValue =
  V_final
  * sect_demand_modifier
  * contribution_policy_modifier
```

贡献不是货币。贡献、门内声望和职位只能影响权限、价格修正、申请资格或可见范围，不能绕过真实库存兑换物品。

## 7. 资源效果模板

资源输入物包括丹药、灵材、符箓、聚灵石、临时增益资源和部分事件专用物。它们通过 `ResourceEffectBalance` 或等价模板进入行动、事件、突破和战斗结算。

模板基准：

```yaml
ResourceEffectBalance:
  resource_effect_template_id: string
  effect_type: cultivation_aura | method_insight | pressure_control | injury_recovery | recovery_over_time | hazard_resist | breakthrough_modifier | attribute_modifier | aptitude_modifier | lifespan_extension | combat_modifier | movement_modifier | exploration_modifier
  use_mode: action_resource_input | explicit_refinement | auto_refinement | event_only | combat_command | use_confirm
  valid_segment_tags: list
  compatible_action_tags: list
  compatible_context_tags: list
  effect_tick_mode: compatible_action_hours | hazard_exposure_hours | combat_rounds | world_elapsed_hours | refinement_completion | none
  unit_effect_rate: number
  effect_rate_min: number
  effect_rate_max: number
  effect_random_distribution: fixed | normal_clamped
  max_effective_hours: number | null
  max_effective_rounds: number | null
  refinement_duration_hours: number | null
  safe_environment_required: bool
  auto_absorb_without_extra_command: bool
  benchmark_hours_saved: number | null
  normalized_progress_bonus: number | null
  contribution_cap_ratio: number
  quality_scaling_profile: object
  stimulation_level: low | medium | high
  stability_level: stable | volatile
  residual_policy: none | stable_suspend | slow_decay | stimulating_decay | forced_release | event_locked | dissipate_on_interrupt
  can_be_settled_by_consolidation: bool
  settlement_policy: none | suppress_side_effect | release_without_progress
  stacking_group: string
  max_same_group_active: number
  log_level: normal | important | critical
```

`benchmark_hours_saved` 的含义是：该资源在适配境界段和标准状态下，相当于节省多少基准兼容小时。它用于估值和预算，不代表资源可以绕过行动时间直接给收益。

修为资源输入换算：

```text
resource_effect_total =
  unit_effect_rate
  * max_effective_hours
  * resource_quality_factor

applied_resource_effect =
  unit_effect_rate
  * applied_effective_hours
  * resource_quality_factor
  * state_factor
  * fit_factor
```

对修为丹药：

```text
cultivation_resource_aura_input =
  Σ(unit_aura_rate_i * applied_effective_hours_i * resource_quality_factor_i)
```

之后进入根骨承载、灵根与道功相性、转化效率、状态压力和段级效率上限，不直接写成最终修为。

## 8. 境界适配与贡献上限

资源价值必须经过当前境界段、物品阶级、角色承载、功法相性、资源标签、状态压力和贡献上限校验。

建议使用 `RealmInputFitMatrix` 或等价配置：

```yaml
RealmInputFitMatrix:
  fit_id: string
  segment_id: string
  item_tier_code: string
  effect_type: string
  method_tag_fit: object
  root_affinity_fit: object
  min_character_state: object
  contribution_cap_ratio: number
  waste_ratio_rule: string
  pressure_risk_rule: string
  hard_block_tags: list
  warning_tags: list
```

定性规则：

| 物品阶级相对角色境界 | 默认处理 |
| --- | --- |
| 低两阶或更多 | 安全但贡献上限很低，适合作为补充或低价材料 |
| 低一阶 | 贡献降低，作为稳定补充资源 |
| 同阶 | 主要设计目标，完整读取效果模板 |
| 高一阶 | 潜在收益更强，但浪费、承载压力、状态风险上升 |
| 高两阶或更多 | 默认阻止常规使用，除非事件、后手、强敌真实资产或专用模板允许 |

贡献上限用于防止低阶资源无限堆叠或高阶资源强行喂给低阶角色造成倍率爆炸：

```text
effective_resource_contribution =
  min(
    raw_resource_effect * fit_factor,
    segment_resource_contribution_cap
  )
```

如果物品效果直接影响突破成功率或突破品质，还应单独读取突破模板的阶段特异性：

```text
V_breakthrough =
  V_std
  * (1 + risk_reduction_value + success_quality_value + stage_specificity_value)
```

突破关键资源不是单纯“节省修炼小时”的物品。它还可能降低失败后果、打开特定策略、提高突破品质或改变失败标签池。

## 9. 堆叠键与实例边界

不设计“半可堆叠”物品。规则层只有：

```text
可堆叠物品
或
独立实例物品
```

推荐堆叠键：

```yaml
StackKey:
  item_template_id: string
  tier: string
  quality: string
  key_state_tags: list
  condition_bucket: string | null
  recognition_state: string | null
  seal_state: string | null
  bind_state: string | null
  owner_restriction: string | null
  special_tags: list
```

进入堆叠键的标准：字段会影响战斗、突破、交易、后手、消耗、绑定、可见性、事件结果或资源效果。仅作为风味来源、普通产地描述或无规则影响的历史，不应拆分堆叠。

默认可堆叠：

1. 普通材料。
2. 普通丹药。
3. 普通符箓。
4. 标准聚灵石。
5. 低价值普通功法残页或篇章。
6. 标准低阶货币或灵石栈。

默认独立实例：

1. 法宝、命名宝物和高价值法器。
2. 高价值完整功法载体、唯一功法载体、封印载体或借阅载体。
3. 正式后手物、真灵藏宝物和遗产待分配核心物。
4. 高价值突破资源、唯一材料、绑定物、不可回收物。
5. 具有损伤、灵性、污染、封印、阵法、残余效果、识别状态或特殊来源历史的物品。
6. 任务钥匙、宗门令牌、藏宝线索、后手凭据。

随机效果物品的原则：

1. 可堆叠物品不为堆叠内每个单体预先保存独立随机结果。
2. 随机抽取发生在实际使用、效果实例创建、配方产出或事件结算时。
3. 抽取后的结果若影响后续规则，必须固化到绑定、效果实例、物品实例、结果包或日志。
4. 若随机结果造成封印、残缺、污染、缺陷、命名、绑定或特殊反噬，应拆出独立实例。

## 10. 生成预算

世界生成预算用于控制“世界还能投放多少有价值资产或机会”。它不是玩家库存，也不是商店价格。

推荐结构：

```yaml
WorldItemBudgetConfig:
  budget_id: string
  tier_code: string
  budget_category: resource | consumable | artifact | method_carrier | breakthrough | treasure | shop_stock | event_reward
  none_reached_rate: number
  some_reached_rate: number
  all_reached_rate: number
  max_accumulated_value: number
  reserve_ratio: number
  overflow_policy: downgrade | delay | substitute | hidden_locked | event_guarded
```

```yaml
WorldItemBudgetState:
  budget_id: string
  tier_code: string
  macro_period_id: string
  accumulated_value: number
  reserved_value: number
  spent_value: number
  last_updated_world_day: number
  last_updated_world_hour: number
  ledger_refs: list
```

增长率口径：

1. `none_reached_rate` 表达房间中尚无人到达该阶时的背景泄漏或隐性沉淀。
2. `some_reached_rate` 表达已有玩家或关键角色到达该阶后的主增长率。
3. `all_reached_rate` 表达多人语境中大多数或全部活跃玩家已到达该阶后的开放增长率。
4. 单人 MVP 可先使用 `some_reached_rate` 作为玩家首次突破后的主预算增长率。

预算投放链路：

```text
WorldItemBudgetState / WorldResourceBudget
→ ResourcePool / OpportunityWindow / AssetGenerationRequest
→ 事件、采集、秘境、任务、商店补货、NPC 真实资产或宗门行动
→ 预算检查
→ 进入 AssetContainer 或 event_locked
→ 扣 BudgetValue
→ 写 ledger / result package / TimelineReplay
```

预算不足时的处理顺序：

1. 降品级。
2. 降阶级。
3. 替换为材料、线索、副产物、残缺物或事件机会。
4. 延迟刷新。
5. 生成“已发现但暂不可取”的隐藏锁定状态。
6. 触发守护、争夺、破阵或风险事件。

不得处理为：

```text
预算不足但仍直接发放高价值物品；
出售或销毁后返还预算；
以商店价格反推预算扣除；
用阶段预算直接改写角色修为。
```

## 11. 资源池、配方与预算的边界

自然资源点先管理潜在产能，不直接等于物品库存。

```text
自然资源池 / 资源槽
→ 采集、加工、炼制、宗门持续行动、事件结算或设施产出
→ 抽象宗门资源、材料 ItemStack、物品 ItemInstance 或事件锁定资产
```

配方生产不直接消耗世界物品预算帽，但必须受投入约束：

```text
OutputValueExpected <=
  InputValue
  * recipe_efficiency
  * skill_modifier
  * facility_modifier
  * risk_modifier
```

配方规则：

1. 核心产物类型由配方决定，不由随机掉落决定。
2. 随机主要影响品级、数量副产、状态桶、成色桶、副词条、失败副作用和返还比例。
3. 产出价值不得长期稳定高于投入价值，除非由稀有配方、稀有设施、高阶技艺、长时间成本、高失败风险、关键材料稀缺、宗门权限或地域限制解释。
4. 批量生产优先生成 `ItemStack`，不为每个普通单体创建独立实例。
5. 配方生产消耗和产出必须写入资产流水、结果包和回放。

## 12. MVP 最小验证闭环

MVP 至少验证以下闭环：

1. 资源点到宗门库存：资源池增长，经宗门常态经营转为抽象宗门资源或材料栈，并写宗门库存日志。
2. 玩家采集：玩家在节点执行采集或加工，读取资源池状态，消耗行动时间和风险，产出材料栈并写角色与节点日志。
3. 配方生产：投入材料、灵石、设施和时间，产出明确物品，随机只影响配方允许字段。
4. 探索 / 事件奖励：事件生成候选物，获得时检查预算并进入行囊、节点库存或事件锁定库存。
5. 战斗隐性实例化：NPC 或事件模板可在战斗中显示可调用法宝、符箓、丹药；战后若获得，进入显性资产并按来源扣预算。
6. 突破资源：突破系统读取关键资源、宗门支持、地点和状态，消耗、损坏、释放或保留资源并写突破结果包。
7. 正式后手：已有显性物品封存为真灵藏宝，转世后同一真灵感应开启，取出时原物品进入合法容器。
8. 通货与高密度资源：普通灵石通过加工转为聚灵石；高阶消耗不直接无限使用普通灵石。

MVP 最小预算池：

```text
pool_newbie_support
pool_basic_sect_supply
pool_qi_refining_exploration_reward
pool_qi_refining_combat_reward
pool_qi_refining_breakthrough_resource
pool_qi_refining_hidden_treasure
pool_qi_refining_npc_trade_implicit_stock
```

MVP 最小随机字段：

1. 品级随机。
2. 数量随机。
3. 状态随机：完整、轻微受损、严重受损。
4. 一个关键副词条或缺陷。
5. 识别 / 封印状态：已识别、未识别、封印未解。
6. 堆叠策略：可堆叠或独立实例。
7. 随机桶：纯度桶、状态桶、效果波动桶。
8. 可选来源字段：只在法宝、功法载体、命名秘宝、宗门信物、正式后手封存物、任务关键物等模板中启用。

## 13. 验收约束

物品数值基准验收时至少检查：

1. 同一物品能同时给出 `BudgetValue`、`TradeValue`、`SalvageValue` 和 `ContributionValue` 的来源或计算路径。
2. 预算扣除发生在资产进入显性容器或事件锁定奖励时。
3. 出售、拆解、销毁、上交、回收、损坏或消耗不会返还世界生成预算。
4. 普通材料、丹药、符箓能正常堆叠；影响战斗、突破、交易、后手、消耗、绑定、可见性或事件结果的字段会进入堆叠键。
5. 高价值法宝、完整功法载体、正式后手物和高价值突破资源使用独立实例。
6. 资源输入物能按 `unit_effect_rate × effective_hours` 或等价模板结算，并保留残余效果、压力风险和日志。
7. 高倍率资源受到阶级适配、贡献上限、状态压力和段级效率上限约束。
8. 商店、宗门、节点、NPC、事件奖励和藏宝中的资产都有来源容器、目标容器、预算来源和流水记录。
9. 真灵藏宝封存物消耗后手数量或容量，不通过物品价值公式绕过限制。
10. Debug / QA 面板可查看预算累积、预留、消耗、降级或替换原因，以及资产流水引用。

## 15. 已裁决口径

| 问题 | 当前裁决 |
| --- | --- |
| 物品价值是否用一个价格字段表达 | 不使用单一价格；至少拆为 `BudgetValue`、`TradeValue`、`SalvageValue`、`ContributionValue` |
| 世界生成预算是否等于市场价格 | 不等于；预算价值不受通胀、折扣或行情影响 |
| 物品生成预算何时扣除 | 进入显性资产容器或事件锁定奖励时扣除，隐性候选不扣 |
| 出售、拆解、销毁或消耗是否返还预算 | 不返还 |
| 可堆叠与独立实例是否允许中间态 | 不允许半可堆叠；只分可堆叠物品和独立实例物品 |
| 丹药、符箓和聚灵石是否直接写 raw 修为收益 | 不写死；通过资源效果模板、兼容小时、贡献上限、压力和残余策略结算 |
| 品级是否直接等于最终收益倍率 | 不等于；品级进入效果模板、稳定性、浪费、风险和价值 |
| 高阶资源是否可无来源刷新 | 不可；必须有预算、强敌真实资产、事件锁定、正式后手、专属资源池或高风险机会来源 |
| 正式后手是否能用物品价值绕过真灵藏宝容量 | 不能；必须消耗真灵藏宝设置数量或单个容量 |
