# 项目总览、MVP 边界与系统依赖

状态：首批正式定稿
更新日期：2026-05-08
来源主版本：v2.3 calendar_preinput

## 1. 项目定位

`xiuxian-game` 是一款设计阶段的多人修仙轮回沙盒。MVP 面向本地单人测试、私人服务器部署与 3 人共享房间，核心体验是玩家控制跨世延续的真灵，而不是控制宗门、国家或固定角色。

玩家在共享连续世界日历中经历当世修炼、移动、资源竞争、事件选择、突破、战斗、死亡、转世和后手遗产回响。世界由服务器维护，以小时为权威结算单位，并根据玩家与世界状态切换公开速度。

开发定位：

```text
共享日历房间
+ 自适应流速推进
+ 跨世角色成长
+ 当前执行指令 + 最多 3 条预输入指令
+ 宗门 AI 资源平台
+ 节点地图沙盒
+ 功法掌握与行动资源输入
+ 事件 / 交锋 / 突破权威结算
```

## 2. MVP 目标

MVP 需要验证：

```text
本地单人测试
+ 私人服务器部署
+ 3 人共享房间
+ 保存、暂停、恢复、续开
+ M0 → M3 纵向闭环
+ 共享日历时间推进
+ 指令队列、兜底、托管与局部时停
```

最小可玩目标：

1. 创建房间并进入共享世界日历。
2. 角色拥有当世身份、基础境界、位置、资产容器和功法状态。
3. 玩家可提交当前行动与后续短队列。
4. 服务器按小时 tick 结算行动、资源输入、事件、宗门 AI 与节点变化。
5. 普通个人事件走局部时停，结束后 C1 追赶。
6. 正式交锋与突破挑战走 B1 交锋轮。
7. 角色可突破、受伤、死亡、转世并保留真灵层记录。
8. 存档、日志、结果包与回放可用于调试。

## 3. 核心设计合同

| 主题 | 当前口径 |
| --- | --- |
| 玩家面对时间 | 共享连续世界日历，不是 `turn_id`、`quarter` 或固定行动槽 |
| 主时间字段 | `world_day / world_hour`；1 游戏日 = 24 游戏小时 |
| 服务端结算 | `hour_tick`，1 小时权威结算 |
| 公开速度 | `F1 / N1 / B1 / P0` |
| 内部追赶 | `C1`，只用于局部时停后的确定性补结算 |
| 玩家行动 | `Command` 与 `CommandQueue`；当前指令 + 最多 3 条预输入 |
| 权威路径 | 客户端提交 intent；校验、结算、状态变更、日志和 replay 属于服务端 |
| 集成总线 | S1 / room authoritative settlement 统一合并结果包 |
| 回放 | `TimelineReplay` |
| 宗门 | 组织资源平台，由宗门 AI 维护持续行动 |
| 多人竞争 | 主要通过宗门、节点、资源、传闻、可见性和机会窗口间接竞争 |
| 功法学习 | 来自完整功法载体；残篇 / 章节不作为运行时学习进度 |
| 资源输入 | 丹药、灵材、符箓、临时 boost 通过 `ActionResourceInputBinding` 绑定行动 |
| 残余效果 | 未消耗完的资源效果进入 `ActiveResourceEffect` |
| 战斗与突破 | `FormalEncounterState`；B1 每轮 = 1 游戏小时 |

## 4. 时间与同步结构

底层时间事实：

```text
1 游戏日 = 24 游戏小时
服务器最小结算单位 = 1 游戏小时
主时间字段 = world_day / world_hour
宏观周期字段 = macro_period_id
```

公开速度档位：

| 档位 | 名称 | 现实时间 : 游戏时间 | 使用场景 |
| --- | --- | --- | --- |
| F1 | 高速推进 | 2 秒 = 1 游戏日 | 全员处于明确长期低交互行动 |
| N1 | 常态推进 | 15 秒 = 1 游戏小时 | 默认多人运行；局部时停外部世界速度 |
| B1 | 交锋慢速 | 60 秒 = 1 游戏小时 | 正式战斗、突破挑战、秘境关键交锋 |
| P0 | 全局暂停 | 游戏时间不流动 | 公共决策、同步保护、主机暂停规则 |

内部机制：

| 机制 | 名称 | 用途 |
| --- | --- | --- |
| C1 | 追赶补结算 | 局部时停结束后，将滞后玩家补结算至当前世界时间 |

## 5. 玩家主循环

```text
查看世界日历、速度与地图状态
→ 查看角色当前行动与后续队列
→ 编辑当前已经合法的普通指令
→ 服务器持续按速度推进 hour_tick
→ 行动完成、事件触发、交锋开始或公共暂停
→ 处理个人事件 / B1 交锋轮 / P0 公共决策
→ 查看个人日志、公开日志和阶段摘要
→ 继续行动或转世后重入世界
```

普通指令编辑不冻结角色当前行动，也不冻结其他玩家或世界。若世界处于 F1，玩家打开普通队列编辑会使世界进入 N1。

## 6. 核心系统依赖

| 系统 | 定位 |
| --- | --- |
| S1 共享日历与权威结算总线 | 维护 `world_day / world_hour`、`SpeedState`、小时 tick、结果包合并、日志与回放 |
| S2 真灵、角色与修炼成长 | 处理当世载体、跨世真灵、修炼、功法、资质、寿元、伤势、境界、轮回账本 |
| S3 个人行动队列与资源输入 | `CommandQueue`、自动兜底、显式托管、`ActionResourceInputBinding` |
| S4 地图节点与世界演化 | 节点、路线、资源槽、势力影响、风险等级、可见性、事件窗口 |
| S5 宗门组织与宗门 AI | 宗门作为组织资源平台；每宗门同一时间最多一个 `SectContinuousActionState` |
| S6 经济、物品与 NPC 持久化 | 资产容器、物品、功法载体、临时资源效果、NPC 状态、交易来源 |
| S7 后手遗产与可见性 | 后手、遗产、传闻、地图可见性、资源竞争、机会窗口 |
| S8 事件、突破与战斗 | `event_time_mode`、局部时停、B1 交锋、突破挑战与结果报告 |

## 7. MVP 硬门槛

1. `WorldClock` 与 `TimeConfig` 可运行。
2. F1 / N1 / B1 / P0 切换和日志可复盘。
3. 当前指令 + 最多 3 条预输入可编辑、校验、执行和失败兜底。
4. 自动兜底强制 N1 且 `f1_eligible=false`。
5. 显式托管可作为玩家主动低关注行动进入队列。
6. 个人局部时停 gap 上限、提示和 C1 追赶可验证。
7. B1 交锋轮有默认策略、提交窗口和硬上限。
8. 突破挑战走 B1，资源消耗发生在挑战轮内。
9. 存档和回放记录 `TimelineReplay`、速度片段、队列变更、局部时停、追赶、交锋轮和结果包。


裁决：

| 采用方案 | 废弃方案 | 原因与影响 |
| --- | --- | --- |
| 共享连续日历 + `world_day / world_hour` | `turn_id` / `quarter` 作为玩家最小推进单位 | v2.3 已将连续日历定为主事实；实现必须以绝对世界小时对齐状态、日志和回放 |
| `CommandQueue` 短队列 | 每季度 6 个朔望行动格 / `action_slot` | 玩家不做逐小时或格子排班；入队只允许当前合法指令 |
| 宗门 AI 维护 `SectContinuousActionState` | 玩家宗门主行动输入、宗门提案、`SectDecisionIntent` | 宗门是组织资源平台，不是玩家直接控制对象 |
| `TimelineReplay` | `TurnReplay` / `QuarterReplay` | 回放需覆盖连续时间片段、速度变化、交锋轮和结果包 |
| 突破挑战走 B1 | 个人突破多次 P0 | 减少多人阻塞，突破真实消耗集中在 `FormalEncounterState` 轮内 |
