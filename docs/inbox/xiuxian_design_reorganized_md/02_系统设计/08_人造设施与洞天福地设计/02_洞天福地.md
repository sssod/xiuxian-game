# 人造设施与洞天福地设计｜洞天福地

## 1. 当前结论

洞天福地是地图节点或隐藏层中的高价值资源槽，不是常规建筑、普通设施或可自由改造地块。资源槽的通用字段、简化类型、人工扩展规则和一槽一设施类别约束，以《../07_地图节点设计.md》为准；本文只说明洞天福地作为 `blessed_land` 时的特殊限制。

MVP 阶段，洞天福地按 `blessed_land` 或等价不易改造资源槽处理，通常具有较高灵气、特殊相性、空间稳定性、突破机会、隐藏层或稀有产出条件。它可以被发现、争夺、封禁、保全、维护、参悟、污染、破坏或作为突破场地使用，但不默认开放常规生产建筑替换。

## 2. 可承载功能

洞天福地可作为：

- 高价值地图节点或隐藏层中的资源槽。
- 修炼加成地点。
- 突破地点。
- 前世后手封存点。
- 宗门控制与资源争夺对象。
- 世界窗口事件或秘境入口。

洞天福地本体不应被直接改建为矿场、药园、坊市、传送阵或普通修炼房。若一个洞天福地内部确实存在可建设空间，应额外记录为该节点或隐藏层内的 `aura_node`、`space_site` 或 `special` 子资源槽，由子槽承担常规设施建设；`blessed_land` 本体仍保持受限改造口径。

## 3. 约束

- 必须挂载于地图节点或隐藏层中的资源槽，不应成为无位置资产。
- 作为资源槽时，应记录资源品级、品级范围、灵气影响、可见性、控制权、争夺状态、改造限制和允许操作。
- 资源槽改造口径通常是 `limited_build`、`preserve_only` 或 `no_build`。
- 宗门或角色只能在其上附加保全、封禁、参悟、突破场地、入口维护等受限设施或操作。
- MVP 常规人工扩展不能制造洞天福地，也不能把普通 `aura_node` 升格为 `blessed_land`。若后续事件产生洞天福地，必须记录事件来源、结果包、可见性和争夺状态。
- 若作为真灵藏宝，只能记录在节点隐藏层中的正式后手目标上，不应直接附着在洞天福地资源槽本体或其子资源槽上；MVP 阶段不进入遗产分配、继承或回收，不展示被他人搬空、损坏或移动。
- 若作为宗门外个人洞府或普通藏宝，可附着在模板允许的自然资源槽或节点隐藏层上，并作为无主遗留设施记录钥匙、功法、线索、位置、事件条件或破阵开启规则；若附着洞天福地相关自然资源槽，应占用该槽设施承载位并降低隐蔽，允许因条件泄露或防御被攻破而被其他角色提前打开。
- 若提供资源产出，应先进入资源槽或资源池；实例化后再进入 `sect_storage`、`node_storage`、事件锁定库存或其他合法资产容器。
- 若提供修炼加成，应进入数值模型的节点灵气、资源槽修正或受限设施修正；其中设施修正只能来自洞天福地允许的受限附属设施。

## 4. 缺口

- 洞天福地类型表。
- 洞天维护成本。
- 洞天暴露、争夺、封存、污染、转移规则。
- 洞天内部可建设子资源槽的生成条件和规模公式。
