# 宗门组织、库存与宗门 AI 持续行动（v2.2）

## 0. 文档定位

本文整理宗门身份、权限、贡献、门内声望、宗门库存、资源预留、宗门 AI、宗门唯一持续行动和玩家间接影响宗门的规则。

新版关键修订：

```text
移除玩家宗门即时指令系统。
移除玩家宗门主行动建议 / 提议 / 决策输入流程。
每个宗门同一时间最多 1 个宗门持续行动。
宗门持续行动由 AI 自行选择、推进、完成、中止或切换。
```

宗门是组织性资源平台，不是玩家本体。玩家通过身份、职位、贡献、声望、权限、关键 NPC 支持、个人行动和事件结果影响宗门，而不是直接操控宗门全部资源。

---

## 1. 宗门系统定位

宗门系统负责回答：

```text
玩家在宗门中是什么身份？
能申请什么资源？
能使用什么设施？
能获得什么情报？
宗门有什么库存？
宗门当前 AI 正在推进什么组织重点？
玩家如何通过个人行动间接影响宗门？
```

宗门死亡、玩家转世、玩家离宗或失势后仍继续存在，并由 AI 托管演化。

---

## 2. MVP 身份层级

MVP 固定五级身份：

```text
外门弟子
→ 内门弟子
→ 真传弟子
→ 执事
→ 长老
```

MVP 不开放宗主职位。

M3 或等价第三大境界起点后，应允许玩家进入长老序列或等价高层影响体验。

| 身份 | 含义 |
|---|---|
| 外门弟子 | 基础功法、基础任务、最低宗门保护 |
| 内门弟子 | 更好的修炼设施、任务层级、宗门关系入口 |
| 真传弟子 | 重点培养，高价值资源、护法、突破名额、核心任务 |
| 执事 | 组织执行层，影响低到中级节点事务，管理部分资源或设施权限 |
| 长老 | 高层身份，获得更高宗门情报、资源批准权、议事事件和 AI 倾向影响 |

---

## 3. 权限系统

MVP 不做复杂树状官僚体系，使用可检查标签。

```text
SectPermission {
  request_resources: bool,
  use_training_site: bool,
  request_breakthrough_support: bool,
  lead_task: bool,
  access_inner_archive: bool,
  manage_node_affairs: bool,
  assign_guard_or_support: bool,
  view_sect_ai_summary: bool,
  influence_sect_ai_weight: float
}
```

移除旧权限：

```text
propose_sect_action
decide_sect_action
```

如果未来恢复玩家主动宗门决策，应另行重开设计，不在 MVP 默认权限中保留。

权限来源：

1. 宗门身份层级。
2. 具体职位。
3. 门内声望。
4. 贡献记录。
5. 关键 NPC 支持。
6. 特殊事件授权。

---

## 4. 不引入宗门内部派系

MVP 不引入宗门内部派系 / 山头作为系统变量。

规则：

- 宗门内部影响力先通过身份、职位、贡献、门内声望、关键 NPC 支持和特殊事件授权表达。
- 不建立派系归属、山头资源、派系声望、派系斗争、派系投票或派系任务线。
- 文案可以出现师承、旧识、执事堂等组织氛围，但不进入 MVP 规则层。

---

## 5. 贡献与门内声望

### 5.1 贡献记录

贡献是玩家为宗门完成任务、上交资源、参与驻守、解决危机的历史凭证。

贡献不是货币，不可直接兑换资源。

### 5.2 门内声望

门内声望是宗门内部对玩家可靠性、潜力和影响力的综合评价。

### 5.3 资源申请

资源申请应读取贡献与声望作为条件，但最终仍由宗门库存检查真实库存。

```text
贡献 / 门内声望 / 权限
→ 是否允许申请
→ 检查宗门库存与预留
→ 生成资源预留或拒绝
→ 写入日志
```

---

## 6. 宗门库存

MVP 宗门追踪五类抽象资源：

1. 灵石。
2. 修炼资源。
3. 材料 / 矿材。
4. 人力 / 弟子规模。
5. 声望 / 影响力。

```text
SectResourceStock {
  sect_id: String,
  spirit_stone: int,
  cultivation_resource: int,
  material_stock: int,
  manpower: int,
  sect_reputation: int,
  reserved_resources: Array,
  income_sources: Array,
  expense_records: Array,
  stock_logs: Array
}
```

注意：

- `sect_reputation` 是宗门整体资源口径，不等同于节点影响力。
- `manpower` 是组织人力规模，不是物品。
- 抽象资源在需要成为具体道具、奖励、突破资源或后手封存时，再由物品系统实例化。

## 7. 宗门资源来源与支出

### 7.1 来源

- 控制节点的基础产出。
- 宗门 AI 持续行动结果。
- 玩家上交资源。
- 节点事件奖励。
- 宗门声望带来的外部供给。
- 特殊秘境。
- 后手回收。
- 宗门商店或设施产出。

### 7.2 支出

- 发放弟子培养资源。
- 支持玩家或 NPC 突破。
- 宗门 AI 持续行动消耗。
- 节点建设与修复。
- 驻守、远征、探索的人力占用。
- 应对节点危机。
- 维护宗门核心建筑或设施。
- 发放俸禄。

宗门俸禄口径：

```text
境界基数 + 职位绝对值
→ 宗门财政状态修正
→ 最终发放额
```

### 7.3 藏经阁与功法奖励

宗门提供功法时应区分：

- 功法组件：残页 / 篇章，用于合成、线索、权限或任务推进。
- 完整功法载体：可学习并生成 `MethodState`。
- 研习设施 / 导师：提高研习效率、降低门槛或解锁可追回收益。

外门可提供基础完整道功或基础法门；内门以上可以通过权限、贡献、任务或事件获得更高价值完整载体。残页 / 篇章奖励不能被 UI 或规则层表达为“已学会一部分功法”。

## 8. 资源预留

为了避免同一资源被多系统重复使用，宗门资源需要预留机制。

```text
ResourceReservation {
  reservation_id: String,
  sect_id: String,
  resource_type: String,
  amount: int,
  reserved_for_system: String,
  reserved_for_event: String,
  start_turn_id: int,
  expiry_turn_id: int,
  status: String  # active / consumed / released / failed
}
```

示例：玩家申请突破支持后，宗门同意预留一批修炼资源。突破开始则消耗；事件取消则释放或部分损耗。

修炼资源申请口径：

- 宗门可批准丹药、灵材、设施时段、导师指点或突破护持。
- 丹药 / 灵材进入个人行动时，必须作为行动资源输入项并通过资产容器消耗。
- 设施时段和导师指点进入行动模板修正，不直接发放无来源倍率。
- 高价值资源申请应生成预留记录，行动开始或事件链创建时再消耗。

## 9. 宗门唯一持续行动

新版核心口径：

> 每个宗门同一时间最多 1 个宗门持续行动。

宗门持续行动不是每回合重新选择一次，而是可以跨多个回合推进。

示例：

- 修复边境据点：预计 6 回合。
- 调查秘境入口：预计 4 回合。
- 强化黑石岭驻守：预计 3 回合。
- 培养内门弟子：预计 8 回合。
- 建设炼丹房：预计 10 回合。

### 9.1 状态结构

```text
SectContinuousActionState {
  action_id: String,
  sect_id: String,
  action_type: String,
  target_node_id: String,
  status: String,                 # active / blocked / completed / interrupted / none
  started_turn_id: int,
  started_world_day: int,
  expected_duration_turns: int,
  expected_duration_hours: int,
  accumulated_hours: int,
  progress: float,
  resource_budget: Dictionary,
  manpower_budget: int,
  ai_reason_tags: Array,
  interruption_rules: Dictionary,
  related_event_refs: Array,
  visible_summary_key: String,
  world_log_refs: Array
}
```

### 9.2 宗门常态运营不占槽

以下属于常态结算，不占用唯一宗门持续行动槽：

- 已控制矿场的基础采矿产出。
- 已控制药田的基础产出。
- 已建成基础设施的持续修正。
- 已建立驻守状态的持续安全或控制稳定。
- 已完成培养体系的基础弟子成长。
- 建筑 / 设施正常工作时的稳定效果。
- 宗门俸禄发放。
- 宗门库存维护。

## 10. 宗门 AI 行为循环

每回合结算时，宗门 AI 执行：

```text
1. 推进当前宗门持续行动。
2. 判断当前行动是否完成、受阻、中止或需要延期。
3. 如果没有持续行动，则选择新的唯一持续行动。
4. 将推进结果写入宗门日志、节点变化、传闻候选和玩家可见摘要。
```

AI 选择依据：

- 宗门资源状态。
- 当前控制节点。
- 边境压力。
- 秘境窗口。
- 宗门战略倾向。
- 关键 NPC 意图。
- 玩家身份、贡献和近期行动。
- 玩家上交资源、解决危机、亲自介入等历史。
- 外部宗门威胁。
- 当前世界事件。

玩家不需要看到宗门 AI 完整推理。

---

## 11. 玩家如何影响宗门

玩家不直接发宗门指令，但仍可影响宗门：

- 身份层级带来的被动权重。
- 门内声望。
- 贡献记录。
- 关键 NPC 关系。
- 亲自参与宗门相关个人行动。
- 在事件中做出选择。
- 上交关键资源。
- 解决宗门危机。
- 突破成功带来的地位变化。
- 申请资源与使用设施产生的组织记录。

高地位价值表现为：

- 看到更多宗门情报。
- 获得更多资源申请权限。
- 更容易触发宗门议事或委派事件。
- 更容易影响宗门 AI 对持续行动方向的判断。
- 对宗门高价值资源、突破支持、节点事务拥有更高访问权。

## 12. 宗门面板 UI 口径

宗门面板不再提供“宗门经营命令 / 宗门主行动输入”。

推荐页签：

```text
宗门概览
宗门当前持续行动
库存与权限
资源申请
身份 / 贡献 / 门内声望
宗门日志与传闻
```

当前持续行动展示：

```text
宗门当前重点：强化黑石岭驻守
进度：40%
预计仍需：约 3 回合
投入：人力中、材料低、灵石低
风险：边境冲突升温
可亲自介入：前往黑石岭驻守 / 协助调查
```

## 13. 已移除设计

本版移除：

- 宗门即时行动域。
- 宗门经营命令。
- 玩家提交宗门建议。
- 玩家提交宗门提议。
- 玩家确认宗门决策意图。
- 宗门主行动反馈等待阶段。
- 同宗多人宗门输入冲突解析。

如未来要恢复宗门主动管理，应作为后续大型模块重新设计，不在 MVP 中预留半成品交互。
