# 数值设计｜修炼公式与数值设计

状态：包内校准稿  
更新日期：2026-05-11

## 1. 设计定位

本文负责修炼数值公式、境界段表结构、资源输入结算、状态压力、修为绝对值映射和修炼 tick 输出。它回答的是：

```text
每个兼容小时如何结算；
资源、地点、功法、宗门和状态如何进入倍率；
丹药、灵材、符箓和临时增益如何按小时释放；
结果包应输出哪些可复盘明细；
哪些调参边界必须防止收益爆炸或绕过时间预算。
```

本文不记录包外来源列表；已采纳的规则在正文中完整重述，保证本目录包内文档可独立阅读。

修为绝对值表示角色当前累计修为规模，字段名为 `cultivation_points`。表格字段和公式字段可使用 `cp_` 前缀表示 cultivation points，但正文优先写“修为绝对值”。小境界修为绝对值上下界由《01_修为境界与期望游玩时间建模.md》维护；本文只消费 `cp_lower_bound / cp_upper_bound`，不另行维护小境界比例表或具体上下界表。

文档边界：

| 文档 | 负责内容 |
| --- | --- |
| `01_修为境界与期望游玩时间建模.md` | 境界体系、标准年限、玩家现实体验目标、小境界修为绝对值上下界、阶段预算和 NPC 成长分层 |
| `../02_系统设计/02_角色与真灵设计/03_角色修为与境界.md` | 境界结构、大小境界分工、角色修炼状态和字段迁移 |
| `../02_系统设计/11_修炼玩法设计.md` | 修炼行动类型、资源输入交互、残余效果提示、F1 消化和玩家反馈 |
| `../02_系统设计/05_物品设计/02_丹药.md` | 丹药身份、使用方式、炼化 / 自动吸收边界、丹药 UI 和物品日志 |
| 本文 | 境界段数值、每小时公式、资源输入公式、效率裁剪、状态压力、tick 明细和调参边界 |

## 2. 当前结论

当前定版口径：

1. 修炼数值以 `RealmSegmentBalance + normalized_segment_progress` 为调参核心。
2. `cultivation_points` 是阈值、表现和日志映射值，不直接线性换算成战斗力。
3. 每小时收益从境界段目标时间反推，不从全局固定经验值开始。
4. 主动吐纳是主要修为来源；闭关修炼是长时段低交互版本，仍按兼容小时结算。
5. F1 只压缩现实等待，不改变世界小时、兼容小时、资源消耗和压力结算。
6. 修为丹药不是即时经验药，也不提供 MVP 独立“丹药炼化涨修为”行动。
7. 丹药、灵材、符箓、临时增益资源统一作为行动或事件选项的资源输入项。
8. 资源只在兼容行动、兼容事件、兼容危险语境、显式炼化或自动吸收过程中按实际小时结算。
9. 行动、事件、炼化或吸收未实际开始时，不消耗关键资源。
10. 已开始但未完整消耗的资源生成 `ActiveResourceEffect`，由残余策略决定暂存、散逸或副作用。
11. MVP 同一行动中同一效果通道最多使用 1 个主资源输入。
12. `forced_release` 字段保留，但常规 MVP 不投放强制释放型危险丹药。
13. 大境界突破只由本文提供准备质量和初始分输入，最终仍由 B1 突破挑战和轮内决策决定。

## 3. 数值主路径

修炼数值不从“1 小时给多少修为”开始，而是从境界段目标、玩家体验时长和资源路径反推。

```text
RealmSegmentBalance
→ RealmBenchmarkRate
→ ActionCultivationProfile
→ RealmInputFitMatrix
→ ResourceEffectBalance / NodeRealmSupport / SectSupportBalance
→ StatePressureModel
→ BreakthroughScoreBalance
→ ReincarnationEfficiencyPolicy
→ 模拟验证
```

含义：

| 模块 | 作用 |
| --- | --- |
| `RealmSegmentBalance` | 定义当前境界段目标时间、进度需求、修为绝对值映射和效率上下限 |
| `RealmBenchmarkRate` | 由境界段目标反推日历基准收益与兼容小时基准收益 |
| `ActionCultivationProfile` | 定义主动吐纳、闭关、自动运转、巩固根基和显式托管的相对效率 |
| `RealmInputFitMatrix` | 定义功法、资源、设施、节点和宗门支持对当前境界段是否适配 |
| `ResourceEffectBalance` | 定价丹药、灵材、符箓、临时增益、炼化效果和残余效果 |
| `NodeRealmSupport` | 定义节点灵气、容量、再生、风险和机会窗口 |
| `SectSupportBalance` | 定义宗门资源、护法、设施、权限和库存支持 |
| `StatePressureModel` | 处理经脉压力、伤势、心魔、寿元压力和强行冲修副作用 |
| `BreakthroughScoreBalance` | 把准备质量转成突破挑战初始分和质量修正 |
| `ReincarnationEfficiencyPolicy` | 判断当前世代效率是否低于境界段基准 |

## 4. 境界段根表

`RealmSegmentBalance` 是修炼数值模型根表。境界段可以表示小境界推进、瓶颈、突破准备或巩固阶段。

```text
RealmSegmentBalance {
  segment_id: String
  realm_from: String
  minor_stage_from: String
  realm_to: String
  minor_stage_to: String
  segment_type: minor_progress | bottleneck | major_breakthrough | consolidation
  target_elapsed_hours_standard: number
  target_elapsed_hours_safe: number
  target_elapsed_hours_risk: number
  target_elapsed_hours_resource: number
  target_elapsed_hours_sect: number
  expected_cultivation_hour_ratio: number
  required_normalized_progress: number
  cp_lower_bound: number
  cp_upper_bound: number
  raw_cultivation_required: number
  required_method_mastery_norm: number
  required_foundation_min: number
  allowed_meridian_pressure_max: number
  allowed_injury_max: number
  allowed_mental_risk_max: number
  expected_breakthrough_rounds: int | null
  breakthrough_template_id: String | null
  min_efficiency_ratio: number
  max_efficiency_ratio: number
  low_efficiency_threshold: number
  high_efficiency_threshold: number
  reincarnation_hint_policy: String
}
```

字段口径：

1. `target_elapsed_hours_standard` 是境界段基准，不是 `hour_tick` 本身。
2. `expected_cultivation_hour_ratio` 表示日历小时中有多少小时是真正有效修炼兼容小时。
3. `cp_lower_bound / cp_upper_bound` 由《01_修为境界与期望游玩时间建模.md》维护。
4. `raw_cultivation_required` 默认可由 `cp_upper_bound - cp_lower_bound` 派生，用于修为绝对值表现和日志映射。
5. `min_efficiency_ratio / max_efficiency_ratio` 是段级裁剪边界，防止倍率爆炸。
6. 轮回效率阈值跟随段配置，不做全局固定值。
7. `target_elapsed_hours_safe / risk / resource / sect` 用于模拟不同路径的目标完成时间，不直接写成玩家无来源倍率。

## 5. 标准化进度与修为绝对值

`normalized_segment_progress` 是当前境界段的调参进度。

建议范围：

```text
0.0 = 当前境界段刚开始
1.0 = 达到该境界段推进目标，具备进入下一阶段或开启突破资格
>1.0 = 超额准备，可转化为突破初始优势、品质修正或稳定性修正
```

`cultivation_points` 是表现值、阈值和日志映射。它可以用于境界膨胀感、调试面板、NPC 成长速度校准和玩家高级详情展示，但不能直接线性换算成战斗力。

玩家界面显示当前小阶段自身进度 `0%-100%`，不显示跨阶段总进度比例：

```text
minor_stage_display_progress =
  clamp(
    (cultivation_points - cp_lower_bound)
    / (cp_upper_bound - cp_lower_bound),
    0,
    1
  )
```

修为绝对值映射：

```text
cultivation_points_gain = normalized_gain * raw_cultivation_required_s
```

因此炼气、筑基、金丹可以拥有不同量级修为绝对值；同一大境界内，不同小阶段也可以拥有不同修为绝对值跨度。调参时同时查看小阶段显示进度、修为绝对值上下界、`normalized_segment_progress`、境界段目标小时和资源路径。

## 6. 基准收益反推

设：

```text
s = 当前 RealmSegment
T_s = target_elapsed_hours_standard_s
U_s = expected_cultivation_hour_ratio_s
P_s = required_normalized_progress_s
```

日历基准推进率：

```text
calendar_benchmark_rate_s = P_s / T_s
```

有效修炼兼容小时基准收益：

```text
compatible_hour_benchmark_rate_s = P_s / (T_s * U_s)
```

如果某段设计为：

```text
target_elapsed_hours_standard = 720
expected_cultivation_hour_ratio = 0.60
required_normalized_progress = 1.0
```

则：

```text
calendar_benchmark_rate = 1 / 720
compatible_hour_benchmark_rate = 1 / 432
```

含义：

```text
标准路径 720 个日历小时完成该段；
其中约 432 小时是真正有效修炼兼容小时；
每个有效修炼小时获得约 0.00231 标准化进度。
```

`RealmBenchmarkRate` 可以作为派生缓存：

```text
RealmBenchmarkRate {
  segment_id: String
  calendar_benchmark_rate: number
  compatible_hour_benchmark_rate: number
  generated_from_balance_version: String
}
```

## 7. 每小时修炼结算

每个兼容小时的核心公式：

```text
normalized_gain_per_compatible_hour =
  B_s
  * A_action
  * Q_aptitude
  * M_method
  * K_mastery
  * N_node_aura
  * F_facility
  * R_resource
  * S_sect_support
  * P_state_penalty
  * C_competition_or_window
```

其中：

```text
B_s = compatible_hour_benchmark_rate_s
```

修正项：

| 项 | 含义 |
| --- | --- |
| `A_action` | 当前行动类型效率，例如主动吐纳、闭关、自动运转、显式托管 |
| `Q_aptitude` | 资质、根骨、灵根等角色底层修正 |
| `M_method` | 主修道功对当前境界段的适配度 |
| `K_mastery` | 功法掌握度修正 |
| `N_node_aura` | 地图节点灵气对当前境界段的适配度 |
| `F_facility` | 洞府、静室、阵法、灵液池维护设施等设施支持 |
| `R_resource` | 丹药、灵材、符箓、`ActiveResourceEffect` 等资源效果 |
| `S_sect_support` | 宗门资源、护法、权限、库存支持 |
| `P_state_penalty` | 伤势、心魔、经脉压力、寿元压力等惩罚 |
| `C_competition_or_window` | 秘境窗口、节点争夺、资源枯竭等动态影响 |

所有修正项先计算原始效率倍率，再按当前境界段边界裁剪：

```text
efficiency_ratio_raw =
  A_action
  * Q_aptitude
  * M_method
  * K_mastery
  * N_node_aura
  * F_facility
  * R_resource
  * S_sect_support
  * P_state_penalty
  * C_competition_or_window

efficiency_ratio = clamp(
  efficiency_ratio_raw,
  min_efficiency_ratio_s,
  max_efficiency_ratio_s
)

normalized_gain = B_s * efficiency_ratio * compatible_hours
cultivation_points_gain = normalized_gain * raw_cultivation_required_s
```

防重复计入口径：

1. 如果某资源以定额灵气进入 `cultivation_resource_aura_input`，同一个资源不得再次作为最终 `R_resource` 倍率重复计入。
2. 如果某资源模板明确是 `rate_multiplier`，则它可以进入 `R_resource`，但必须受境界适配、贡献上限和段级效率上限约束。
3. 同一来源不得同时写成环境灵气提升、资源定额输入和最终倍率，除非模板显式拆分多个独立效果通道并分别记入结果包。

## 8. 行动相对效率

行动类型不直接写死 raw 修为收益，只提供相对当前境界段基准的效率倍率。

```text
ActionCultivationProfile {
  action_type: active_breathing | seclusion_cultivation | auto_circulation | consolidation | managed_action | rest
  source: explicit_player | timeout_managed | system_fallback
  valid_segment_tags: Array
  compatible_hour_policy: full | partial | none
  base_efficiency_ratio: number
  f1_eligible: bool
  event_interrupt_policy: pause | split_segment | force_report | block_f1
  can_trigger_minor_stage_advance: bool
  can_trigger_major_breakthrough: bool
  pressure_profile_id: String
  risk_exposure_ratio: number
  resource_slot_count: int
  resource_input_policy_id: String
  min_duration_hours: number
  max_duration_hours: number | null
}
```

建议口径：

| 行动 | 相对效率口径 | 边界 |
| --- | --- | --- |
| 主动吐纳 | 主要修为推进基准 | 可挂载修为丹药和灵气类资源 |
| 闭关修炼 | 主动吐纳的长时段低交互版本 | 可进入 F1；仍按兼容小时结算；内部执行主动吐纳片段时可挂载修为丹药 |
| 自动运转 | 极低额保底收益 | 可触发小境界，不能触发大境界突破，不消耗关键资源 |
| 巩固根基 | 以压力、纯度、根基稳定为主 | 不把残余修为药性转化为修为 |
| 显式托管 | 低收益低风险 | 不主动执行高风险突破，不主动消耗新高价值资源 |
| 休整 / 疗伤 | 以状态恢复为主 | 不作为成长主路径 |

初始方向：

| 路径 / 行动 | 相对基准效率方向 |
| --- | --- |
| 标准主动路径 | 约 1.00 |
| 安全低风险路径 | 0.65-0.90 |
| 资源投入路径 | 1.20-1.70 |
| 高风险节点路径 | 1.30-2.20 |
| 宗门支持路径 | 1.10-1.60 |
| 显式托管 | 0.20-0.50 |
| 自动兜底 / 自动运转 | 0.05-0.20 |

这些区间只是首版调参方向，不是硬编码表。实际值必须通过数值验算确认各境界段完成时间、压力曲线和资源消耗是否落入目标。

## 9. 境界适配矩阵

功法、资源、设施、节点灵气和宗门支持共用境界适配矩阵，避免跨阶资源直接碾压。

```text
RealmInputFitMatrix {
  input_type: method | resource | facility | node_aura | sect_support
  input_grade: int
  segment_realm_grade: int
  tag_match_policy: String
  efficiency_multiplier: number
  contribution_cap_ratio: number
  waste_ratio: number
  pressure_modifier: number
  side_effect_risk: number
  breakthrough_relevance: number
}
```

初始方向：

| 输入品阶 vs 境界段 | 效率 | 贡献上限 | 浪费 | 压力 / 反噬 |
| --- | --- | --- | --- | --- |
| 低 2 阶 | 极低 | 极低 | 高 | 低 |
| 低 1 阶 | 低 | 低 | 中 | 低 |
| 同阶 | 标准 | 高 | 低 | 低 |
| 高 1 阶 | 高 | 高 | 中 | 中 |
| 高 2 阶以上 | 较高但不稳定 | 中 | 高 | 高 |

高阶资源可以提高效率，但应通过浪费、经脉压力、相性风险、贡献上限和段级效率上限限制。低阶资源可安全但贡献衰减。标签不适配时，应表现为转化率低、药力浪费、短期疲劳、短期经脉压力或心神扰动，而不是完全无声失败。

## 10. 资源输入生命周期

行动资源输入项是挂载在行动、事件选项、显式炼化或自动吸收上的额外资源。它不改变行动本身类型，只在兼容语境中按有效小时释放。

生命周期：

```text
规划或事件选择
→ 创建 ActionResourceInputBinding
→ 执行前重新校验资产、权限、位置、标签和叠加限制
→ 行动 / 事件 / 炼化 / 吸收实际开始后消耗或预留资源
→ 按小时释放效果
→ 完整消耗、生成残余效果、暂停、散逸、失败退款或事件专用处理
→ 写入结果包、资产日志、角色日志和回放
```

基础模型：

```text
resource_effect_total = unit_effect_rate * max_effective_hours

applied_resource_effect =
  unit_effect_rate
  * applied_effective_hours
  * resource_quality_factor
  * state_factor
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `unit_effect_rate` | 每小时释放多少灵气、提供多少悟性修正、抵消多少毒瘴压力、恢复多少伤势等 |
| `max_effective_hours` | 该资源最多能在兼容语境中生效多少小时 |
| `applied_effective_hours` | 本次行动、事件、炼化或吸收中实际消耗的有效小时 |
| `resource_quality_factor` | 品级、成色、稳定性、模板波动等品质修正 |
| `state_factor` | 角色状态、相性、承载、地点、安全环境等修正 |

三类常规计时模式：

| 计时模式 | 适用 | 规则 |
| --- | --- | --- |
| `compatible_action_hours` | 修为丹药、悟性丹、定心丹、疗伤丹等 | 只在兼容行动或兼容事件选项实际执行时消耗有效小时 |
| `hazard_exposure_hours` | 避瘴丹、解毒丹、危险环境防护 | 只在危险暴露小时或事件模板声明的危险语境中消耗 |
| `world_elapsed_hours` | 未来危险丹药、强制释放效果、部分自动吸收 | 按世界小时推进，即使没有兼容行动也会消耗，并可能转为浪费、压力或反噬 |

补充计时模式：

| 计时模式 | 适用 | 规则 |
| --- | --- | --- |
| `refinement_completion` | 延寿丹、属性丹、洗髓丹等完成炼化后结算的长期效果 | 炼化未完成前不提前发放完整效果；完成后按模板写入角色状态 |

MVP 的常规修炼资源默认使用 `compatible_action_hours` 或 `hazard_exposure_hours`。`world_elapsed_hours` 和 `forced_release` 只作为字段和未来分支保留，不作为常规修为资源投放。

## 11. 修为丹药与主动吐纳

修为类丹药只能作为主动吐纳的额外资源输入。闭关修炼若内部执行主动吐纳片段，可在该片段中挂载修为丹药；这不等于独立“丹药炼化”行动。

合法：

```text
主动吐纳 24 小时，附加清灵丹 x 1。
闭关修炼 30 日，其中主动吐纳片段挂载清灵丹。
```

非法：

```text
即时服用清灵丹，立即获得修为。
单独执行丹药炼化 12 小时，并获得修为。
移动途中服用清灵丹，持续获得修为。
突破失败后回溯服丹，重算已经结算的修为。
```

主动吐纳中存在两条输入流：

| 输入流 | 规则 |
| --- | --- |
| 环境灵气流 | 节点灵气、资源槽灵气、聚灵阵、洞府、灵液池等，受道功吸收速度、节点容量和角色状态限制 |
| 修为丹药资源流 | 丹药释放定额灵气包，跳过道功吸收速度上限，但仍进入转化、承载、相性、压力和贡献上限结算 |

修为丹药不是提高节点灵气浓度，不是提高聚灵阵效果，也不是简单提高最终倍率。

环境灵气输入：

```text
environment_aura_input =
  node_aura_density
  * node_aura_fit
  * facility_aura_modifier
  * method_absorption_speed
  * compatible_hours
```

修为资源输入：

```text
cultivation_resource_aura_input =
  Σ(unit_aura_rate_i * applied_effective_hours_i * resource_quality_factor_i)
```

主动吐纳合流：

```text
raw_aura_input =
  environment_aura_input
  + cultivation_resource_aura_input
```

之后统一进入：

```text
根骨安全承载
根骨转化效率
灵根与道功相性
道功基础转化率
状态修正
境界段贡献上限
修为进度
修炼压力
```

如果主动吐纳实际执行时长少于丹药 `max_effective_hours`，只结算实际执行部分。剩余药性进入 `ActiveResourceEffect`，后续只能在兼容行动中继续使用，或由巩固根基选择性收束但不转化为修为。

资源定价原则：

1. 不写成固定 raw 修为奖励，而是折算为节省多少基准兼容小时、最多贡献当前境界段多少比例、增加或降低多少压力，以及是否影响突破初始分。
2. 若资源定义为 `benchmark_hours_saved = H`，则 `normalized_progress_bonus = H * compatible_hour_benchmark_rate_s`。
3. 若资源定义为 `rate_multiplier`，必须经过境界适配矩阵、贡献上限和段级效率上限。
4. 非修为资源进入各自管线，例如悟性修正、解毒、防护、治疗、稳定、突破分或寿元炼化，不得无故转为修为输入。

MVP 同一行动中，同一效果通道最多使用 1 个主资源输入，避免资源倍率堆叠成为主要玩法。

## 13. 残余效果

当资源已被消耗或确认使用，但未在本次行动、事件、炼化或自动吸收中完全释放，生成 `ActiveResourceEffect`。

生成场景：

1. 行动实际时长少于资源最大有效时长。
2. 行动开始后被事件打断。
3. 行动中部分小时不满足资源兼容语境。
4. 显式炼化未完成。
5. 自动吸收尚未释放完整效果。

不生成场景：

1. 带资源输入的行动没有实际开始。
2. 服务端校验未通过，资源没有消耗。
3. 事件模板声明该资源为一次性无残余。
4. 所有突破丹药由突破事件链专门结算，突破事件结束后停止影响。
5. 资源模板声明使用失败时全额退款且不产生状态。

```text
ActiveResourceEffect {
  effect_id: String
  character_id: String
  source_binding_id: String
  resource_effect_template_id: String
  effect_type: String
  unit_effect_rate: number
  actual_unit_effect_rate: number
  remaining_effective_hours: number
  remaining_effect_amount: number
  compatible_action_tags: Array
  compatible_context_tags: Array
  effect_tick_mode: compatible_action_hours | hazard_exposure_hours | world_elapsed_hours | refinement_completion
  residual_policy: stable_suspend | slow_decay | stimulating_decay | forced_release
  residual_stability_hours_remaining: number
  idle_world_hours: number
  can_be_settled_by_consolidation: bool
  settlement_policy: none | suppress_side_effect | release_without_progress
  stacking_group: String
  source_command_id: String | null
  source_event_option_id: String | null
  created_world_day: int
  created_world_hour: int
  last_applied_world_hour: int
  state: active | suspended | decaying | exhausted
  log_refs: Array
}
```

残余策略：

| 策略 | 用途 | 规则 |
| --- | --- | --- |
| `stable_suspend` | 普通清灵丹、普通启悟丹、低刺激养元资源 | 非兼容行动期间不生效，在稳定窗口内不明显损失，之后缓慢散逸 |
| `slow_decay` | 品质较差丹药、保存状态一般资源 | 非兼容行动期间缓慢减少，通常只造成轻微浪费或疲劳 |
| `stimulating_decay` | 速成修为丹、烈性火系丹药、高刺激破关资源 | 非兼容行动期间较快衰减，衰减可能转为经脉压力、疲劳或神念扰动 |
| `forced_release` | 高阶危险丹药、剧情丹药、强行破关资源 | 按世界小时持续释放，未被吸收部分转为浪费、压力或反噬；MVP 不投放，只预留字段 |

跨回合规则：

1. 行动未开始，不消耗资源。
2. 行动已开始，只消耗实际兼容小时。
3. 决策阶段、局部时停和玩家阅读报告期间不推进药性衰减。
4. 服务器结算阶段、世界小时实际推进时，才增加 `idle_world_hours` 或 decay 相关计数。
5. `stable_suspend` 可保留给后续兼容行动继续承接。
6. `stimulating_decay` 和 `forced_release` 应更容易造成散逸、压力或副作用。
7. C1 追赶只补结算确定性的兼容小时、资源消耗和药性衰减；已有随机效果只读取固化值。

## 14. 巩固根基收束

巩固根基可以选择性收束残余修为药性，但收束不产生修为进度，也不替代主动吐纳。

默认规则：

1. 稳定残余药性默认不自动收束，必须由玩家明确选择。
2. 刺激型或强制释放型药性应强提示风险，建议继续主动吐纳或巩固根基收束。
3. 显式托管在安全条件下可以处理已有残余效果，但不得主动消耗新的稀有修为丹药或不可逆高价值资源。

收束结算：

```text
settled_hours = min(action_actual_hours, effect.remaining_effective_hours)
settled_amount = effect.actual_unit_effect_rate * settled_hours
```

`settled_amount` 不进入：

```text
resource_aura_input
cultivation_progress_gain
```

而进入：

```text
pressure_prevention
side_effect_reduction
residual_effect_clearance
```

如果巩固根基本身有纯度收益或根基收益，该收益来自巩固行动本身，不来自修为丹药残余。

## 15. 事件资源输入、叠加与托管

事件选项允许临时追加资源输入，但必须由事件模板声明 `resource_input_slot`。

事件资源输入规则：

1. 不允许回溯生效。
2. 必须走统一资源校验。
3. 必须写入资源使用结果、事件结果包、资产日志、角色日志和回放。
4. 是否产生残余效果由事件模板和资源模板共同决定。
5. 突破事件链中的资源优先服从突破事件链规则，不产生普通残余药性，突破事件结束后停止影响。

禁止：

```text
事件发生后，回溯让避瘴丹覆盖之前已经暴露的 5 小时。
战斗结束后，回溯使用回气丹改变已结算的交锋。
突破失败后，回溯服用定心丹重算风险。
```

叠加规则：

1. MVP 同一行动中，同一效果通道最多使用 1 个主资源输入。
2. 主动吐纳最多 1 种主修为丹药。
3. 研习功法最多 1 种主悟性增益资源。
4. 毒瘴探索最多 1 种主避瘴 / 解毒资源。
5. 休整治疗最多 1 种主疗伤资源。
6. 如果角色已有同一 `stacking_group` 的 `ActiveResourceEffect`，默认不允许再使用同组新资源。

显式托管规则：

1. 托管不得主动消耗新的稀有修为丹药、高刺激速成丹药或不可逆高价值资源。
2. 托管可以在安全条件下通过兼容行动承接已有残余效果。
3. 对刺激型残余效果，托管可以选择巩固根基收束。
4. 保命、避险、避免重大不可逆选择优先于节省药性。

## 16. 状态压力模型

高效率修炼、跨阶资源、污染环境、带伤冲修和长时间强行闭关都可能带来状态压力。

```text
StatePressureModel {
  pressure_model_id: String
  valid_segment_tags: Array
  pressure_from_overbenchmark_rate: number
  pressure_from_resource_grade_gap: number
  pressure_from_risky_node: number
  pressure_from_method_mismatch: number
  pressure_decay_rest_per_hour: number
  pressure_decay_facility_per_hour: number
  meridian_pressure_gain_curve: String
  injury_risk_curve: String
  mental_risk_curve: String
  purity_delta_curve: String
  foundation_quality_delta_curve: String
  pressure_penalty_curve_id: String
  breakthrough_risk_curve_id: String
  pressure_recovery_actions: Array
  hard_limit_policy: warn | block | allow_with_penalty
}
```

压力生成：

```text
over_rate = max(0, efficiency_ratio - 1.0)

meridian_pressure_gain =
  over_rate * pressure_from_overbenchmark_rate
  + resource_pressure
  + node_pressure
  + method_mismatch_pressure
```

状态惩罚：

```text
P_state_penalty =
  1 / (1 + lambda1 * meridian_pressure + lambda2 * injury + lambda3 * mental_risk)
```

状态压力至少影响：

1. `meridian_pressure`。
2. `injury_state`。
3. `mental_state` 或心魔风险。
4. `foundation_quality`。
5. 修为纯度。
6. 大境界突破开启条件和突破质量。

压力模型不应只作为失败惩罚存在；它也需要给巩固根基、疗伤、提纯、换地点、宗门护法和保守修炼留下明确修正入口。

## 19. 调参验收口径

修炼数值调参至少验证：

1. 玩家看到的每个小阶段都能从自身 `0%-100%` 推进。
2. 小阶段之间的修为绝对值跨度、有效修炼小时和资源需求可以不同。
3. 主动吐纳是主要修为来源，自动运转不会替代玩家规划。
4. 闭关和 F1 只压缩现实等待，不改变世界小时、兼容小时和资源消耗。
5. 修为丹药不会成为即时经验药，也不会通过独立丹药炼化增加修为。
6. 修为丹药只在主动吐纳或闭关内部主动吐纳片段中释放修为灵气输入。
7. 非兼容行动不转化修为资源效果。
8. 行动未开始、事件选项未生效、炼化未确认时，不提前消耗关键资源。
9. 已开始但未完整消耗的资源能生成可复盘残余效果。
10. 决策阶段、局部时停和报告阅读不推进药性衰减。
11. 巩固根基可以收束残余修为药性，但不产生修为进度。
12. 同一效果通道的主资源输入叠加不会成为主要收益漏洞。
13. 托管不会主动消耗新高价值资源或主动发起高风险突破。
14. 高倍率资源必须受到境界适配、状态压力、贡献上限和段级效率上限约束。
15. 小境界升级可以轻量触发，大境界突破不能只靠修为绝对值达标自动完成。
16. 结果包能复盘收益、资源消耗、压力变化、残余效果、日志引用和可见摘要。

## 20. MVP 范围

MVP 应实现：

1. `RealmSegmentBalance` 与自动生成 / 派生 `RealmBenchmarkRate`。
2. `normalized_segment_progress` 与 `cultivation_points` 映射。
3. 主动吐纳、闭关修炼、自动运转、巩固根基、显式托管的基础效率表。
4. 行动资源输入项 `ActionResourceInputBinding`。
5. 修为丹药挂载主动吐纳。
6. 悟性丹挂载研习功法。
7. 避瘴 / 解毒资源挂载危险语境行动或事件。
8. 疗伤资源挂载休整、治疗或医疗事件。
9. 定心资源挂载巩固根基、突破准备、研习功法或突破事件链。
10. 行动开始后按实际兼容小时消耗资源。
11. `ActiveResourceEffect` 残余效果。
12. `stable_suspend / slow_decay / stimulating_decay` 三类常规残余策略。
13. `forced_release` 字段预留，但不常规投放。
14. 巩固根基可选择性收束残余修为药性。
15. 事件选项可临时追加资源输入。
16. 同效果通道最多 1 个主资源输入。
17. `CultivationTickResult`、资源使用日志、资产流水、角色日志和回放。
18. `effect_rate_min / effect_rate_max / actual_unit_effect_rate` 支持资源效果波动并固化结果。

MVP 不实现：

1. 通过独立“丹药炼化”让修为丹药增加修为。
2. 即时服丹涨修为。
3. 多枚修为丹药复杂叠加。
4. 主药 + 辅药 + 药引组合。
5. 危险丹药和 `forced_release` 实际投放内容。
6. 可长期累计的复杂丹毒 / 杂质系统。
7. 玩家在结算阶段主动暂停来重新安排药性。
