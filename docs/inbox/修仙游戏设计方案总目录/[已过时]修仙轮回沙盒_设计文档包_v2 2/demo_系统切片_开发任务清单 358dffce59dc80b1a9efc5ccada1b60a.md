## 1. Demo 开发总边界

### 1.1 必须交付的可玩闭环

```
创建本地房间
→ 创建真灵 / 第一世角色
→ 从青禾村出生
→ 打听路线与宗门信息
→ 在地图上规划移动、打听、探索、修炼等行动
→ 锁定回合
→ 服务器结算总线按小时推进
→ 事件改变计划
→ 入门云麓宗并获得外门身份
→ 学习基础道功
→ 使用清灵丹 / 稳定符等行动资源输入
→ 看到宗门 AI 推进一个持续行动
→ 节点资源槽或危险状态变化
→ 达到 demo 瓶颈
→ 准备并执行一次压缩突破链
→ 生成回合报告、日志、TurnReplay 与存档
```

### 1.2 demo 不做但必须留接口的位置

```
3 人真实联网
完整 M0 → M3
完整死亡转世
完整后手回收
多宗门外交
宗门经营命令
玩家直接指挥宗门行动
完整斗法链
完整经济市场
完整炼丹 / 炼器工业链
完整传闻网络
N4 高价值 NPC 宏观意图
```

### 1.3 最高优先级护栏

开发中只要遇到临时实现冲突，优先遵守以下规则：

1. **UI 不直接改世界状态。** UI 只提交意图、展示校验、展示结果。
2. **所有变化经 S1 结算总线回写。** 事件、资源、宗门 AI、突破都输出 `ResultPackage`。
3. **玩家只排天级预算，不手排小时。** 内部可以小时级结算，但 UI 不暴露小时编排器。
4. **资源输入挂在行动 / 事件语境中。** 丹药、符箓、稳定资源不是即时收益按钮。
5. **宗门是 AI 自行演化组织。** 玩家只能申请资源、贡献、触发事件或间接影响，不能提交宗门主行动。
6. **日志与存档从第一天实现。** demo 不是一次性脚本原型，必须可复盘、可保存、可迁移。

# 3. Phase A：可运行骨架

## 3.1 Phase A 目标

先做最小可运行地基，不急着堆内容。Phase A 完成后，项目应能证明：

```
本地房间存在
回合状态存在
玩家可以提交空行动或休整行动
结算总线可以推进世界时间
结果包可以被合并
日志、存档、回放、Debug 可以追溯一次回合
```

## 3.2 Phase A 任务表

| ID | 任务 | 优先级 | 依赖 | 交付物 | 验收 |
| --- | --- | --- | --- | --- | --- |

| A-02 | 定义 `RoomState` 最小结构 | P0 | A-01 | 房间状态数据结构 | 包含房间元数据、玩家列表、世界种子、当前 phase、当前回合、世界时间、版本号 |
| A-03 | 定义 `TurnConfig` | P0 | A-01 | 回合配置对象 | 可配置每回合天数、锁定模式、倒计时开关、demo 默认关闭倒计时 |
| A-04 | 实现回合阶段机 | P0 | A-02, A-03 | 阶段切换逻辑 | 支持 `turn_start → report_review → instant_personal → personal_action_planning → waiting_lock → settlement → inserted_event → writeback → turn_end` |
| A-05 | 实现玩家锁定流程 | P0 | A-04 | lock / unlock / validation | 玩家可提交行动草案并锁定；锁定后进入结算；demo 单人下无需等待其他玩家 |

## 3.3 Phase A 端到端验收脚本

```
1. 启动 demo。
2. 创建本地房间。
3. 创建默认玩家占位。
4. 进入 turn_start。
5. 进入 personal_action_planning。
6. 提交一个 rest_or_guard 行动或空行动。
7. 锁定。
8. S1 执行结算。
9. 生成 ResultPackage。
10. 合并写回 RoomState。
11. 生成 OriginalVsActualSummary。
12. 生成玩家日志、Debug 日志、TurnReplay。
13. 保存。
14. 退出并读取。
15. 继续进入下一回合。
```

### Phase A 不允许延后项

以下内容不能推迟到后续 Phase，否则后续系统容易变成假流程：

```
S1 结算入口
ResultPackage
存档 / 读取
Debug 面板
TurnReplay 最小记录
行动锁定前硬校验
```

# 4. Phase B：地图 + 行动 + 事件

## 4.1 Phase B 目标

让玩家从地图而不是菜单理解游戏。Phase B 完成后，应能玩到：

```
我在青禾村查看周边
我选择前往镇集或云麓山道
我把移动、打听、探索、休整排进 5 天预算
我锁定回合
移动消耗时间并可能触发事件
事件消耗额外小时，后续行动被推迟或中断
回合报告解释原计划与实际发生的差异
```

# 7. Phase E：压缩突破链 + Demo 收束

## 7.1 Phase E 目标

修为达到瓶颈

关键物在事件链创建时消耗
突破事件链中出现 1–3 个关键选择
结果可能成功、失败存活或重伤中断
失败有具体原因标签
结果写入角色日志、宗门摘要、轮回账本占位、回合报告
第一次突破后出现 demo 总结，但允许继续游玩

# 12. 当前仍需后续回收的 Phase Gate 决策

这些问题不阻塞 Phase A 开工，但需要在指定阶段前确认，否则会影响返工成本。

| 决策 | 最晚确认点 | 当前建议 | 影响 |

| 内容数据格式最终采用 JSON、Godot Resource 还是混合 | Phase A 结束前 | demo 先 JSON / Godot Resource；MVP 前评估混合 | 影响内容编辑、校验、迁移 |
