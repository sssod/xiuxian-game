# 移动玩法设计

更新日期：2026-05-11

## 1. 当前结论

移动决定玩家角色在共享世界日历中“人在哪里、能去哪里、做什么、花多少世界小时、消耗多少状态资源、冒多少风险、最后停在哪里”。移动是普通行动队列中的 `travel` 指令，不是独立于行动系统之外的地图瞬移。

底层口径：

```text
移动指令 = Command.command_type: travel
结算时间 = world_day / world_hour
服务器最小结算单位 = 1 游戏小时
移动行动最小时间消耗 = 1 游戏小时
```

任何会改变角色所在地图节点的移动行动，最终 `duration_hours` 或 `current_cost_hours` 都不得小于 1。若某个同节点服务入口、建筑面板或商店面板不消耗时间，它应被建模为当前节点内的 UI / 服务入口，不应被建模为移动行动；若被建模为移动行动，则仍按最小 1 小时处理。

移动的默认资源消耗为玩家角色的元气属性消耗，即读取 `bar_qi_current`。使用交通设施、传送阵、飞舟、特殊法宝或其他外部移动手段时，可以在元气之外额外消耗灵石、聚灵石、设施费用、法宝耐久、法宝充能、神念或特定维护资源。常规移动一般不消耗物品；只有路线条件、玩家显式选择的资源输入或事件选项要求时，才消耗干粮、符箓、避瘴丹、通行令等物品。

## 2. 指令输入粒度

玩家提交移动时，MVP 输入粒度为：

```yaml
TravelCommandInput:
  target_node_id: string
  travel_mode: walk | lightness_method | mount_or_vehicle | artifact | facility | teleport | special
  stopover_nodes: list[string]
  resource_inputs: list
```

规则：

1. `target_node_id` 是移动的主要目标。
2. `travel_mode` 表示移动方式，决定时间、元气、风险、可用路线和额外资源消耗。
3. `stopover_nodes` 只记录玩家显式要求停靠或安全中转的节点；MVP 不做完整逐边手动排路，也不做复杂复合交通路线编辑。
4. `resource_inputs` 只记录玩家主动绑定的资源输入或路线要求的资源输入，不自动消耗背包物品。
5. 服务端根据当前位置、可见路线、路线权重、通行条件、风险门、交通设施、隐藏路线和角色状态生成实际移动计划。

## 3. 路线状态

移动读取有向带权路线。双向路线应拆成两条路线，因为双向成本、风险和通行条件可能不同。

```yaml
RouteState:
  route_id: string
  from_node_id: string
  to_node_id: string
  base_cost_hours: int
  current_cost_hours: int
  route_type: road | mountain_path | river | teleport | hidden | rumor
  passability: open | blocked | conditional | unknown
  requirements: list
  risk_tags: list[string]
  discovered_by: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

路线校验读取：

```text
当前位置；
目标节点；
路线是否可见；
passability；
requirements；
risk_tags；
current_cost_hours；
角色状态；
宗门、NPC 或事件授予的通行许可；
是否存在路线封锁、节点事件或公开危险；
移动方式对应的设施、法宝或功法是否可用。
```

## 4. 移动上下文

移动执行时生成 `MovementContext` 或等价上下文，用于事件、日志、回放、资源消耗和结果包。

```yaml
MovementContext:
  command_id: string
  character_id: string
  world_day: int
  world_hour: int
  from_node_id: string
  to_node_id: string
  route_segment_refs: list[string]
  travel_mode: string
  stopover_nodes: list[string]
  planned_travel_hours: int
  min_consumed_hours: 1
  expected_qi_cost: number
  extra_resource_costs: list
  exposure_tags: list[string]
  risk_tags: list[string]
  event_candidate_refs: list[string]
```

`planned_travel_hours` 必须是整数小时，且移动行动开始后至少消耗 1 小时。若路线被事件提前打断，结果仍记录本次已经消耗的世界小时、元气和已生效资源。

## 5. 时间成本

移动时间以路线 `current_cost_hours` 为基础，按小时结算。

结算流程：

```text
1. 读取目标路线或路线段。
2. 读取 base_cost_hours。
3. 应用路线状态、风险、天气 / 节点事件、交通设施、功法、法宝和角色状态修正。
4. 得到 current_cost_hours。
5. 对移动行动执行最小时间约束：max(1, current_cost_hours)。
6. 多段移动按各段结果累加；总移动时间不得小于 1 小时。
```

时间成本可被以下因素改变：

| 因素 | 影响方向 |
| --- | --- |
| 轻身功法、飞遁法门、路线熟悉度 | 降低耗时，但不能低于 1 小时 |
| 伤势、疲惫、低元气、负面状态 | 增加耗时或阻止移动 |
| 山路、水路、秘境边界、敌对边境 | 增加耗时、风险或通行条件 |
| 交通设施、飞舟、传送阵、路线枢纽 | 降低耗时或改变可达路线，但通常带来额外资源成本 |
| 路线阻断、封锁、追击、公共节点事件 | 阻止移动、延误或强制中转 |

长途赶路可以作为长期低交互行动参与 F1 的候选，但只有在所有玩家都满足长期低交互条件，且没有事件、交锋、全局节点、自动兜底或临近截止事项时才可进入 F1。

## 6. 资源消耗

### 6.1 默认消耗：元气

普通移动默认消耗玩家角色的元气：

```yaml
TravelResourceCost:
  primary_bar: bar_qi_current
  cost_basis:
    - travel_hours
    - route_type
    - risk_tags
    - travel_mode
    - character_state
    - method_or_artifact_modifiers
```

设计口径：

1. 元气是气力、法力和可支配能量的统一派生状态条。
2. 移动不是免费改变位置；即使没有物品消耗，也应有元气或状态负担。
3. 元气不足时，移动入队或执行前校验可以失败，也可以由模板提供低速、休整后再行、改走设施路线等替代入口。
4. 元气消耗不得侵占 `bar_qi_reserve` 预留值；预留值代表不可支配容量。
5. 移动消耗的元气、状态变化和失败原因必须写入个人日志、结果包或回放。

### 6.2 额外消耗

使用特殊移动手段时，可以追加资源成本：

| 移动方式 | 可能额外消耗 |
| --- | --- |
| 交通设施、渡口、驿站、坊市路线服务 | 灵石、低阶货币、通行许可、宗门权限或服务费用 |
| 传送阵、阵台、空间设施 | 灵石、聚灵石、设施供能、阵法维护资源、权限 |
| 飞舟、坐骑、载具 | 灵石、维护费用、燃料资源、节点服务费用 |
| 主动型或辅助型移动法宝 | 元气、神念、法宝耐久、法宝充能、聚灵石或特定材料 |
| 特殊危险区域 | 避瘴丹、护身符、通行令、事件选项资源或路线要求资源 |

常规步行、轻身赶路和普通山道移动一般不消耗物品。干粮、丹药、符箓、通行令等只在以下情况下消耗：

1. 玩家在移动指令中显式选择作为 `resource_inputs`。
2. 路线 `requirements` 明确要求。
3. 移动事件选项明确消耗。
4. 设施或法宝模板明确要求。

行动未开始、路线执行前校验失败、事件选项未生效时，不提前消耗关键资源或物品。

## 7. 移动预览

移动预览应同时表达：

- 预计时间成本，且明确最小为 1 小时。
- 默认元气消耗。
- 设施、法宝、灵石、聚灵石或其他额外资源成本。
- 当前路线风险、风险标签和公开阻断信息。
- 通行条件、权限门、状态门和隐藏路线条件。
- 可选停靠点、中转点和可能的临时停靠。
- 事件触发可能性，不展示未发现事件的完整真相。
- 移动失败或中断后的默认停留位置。

预览只展示玩家可见信息。其他玩家的私人事件、隐秘追击、局部时停原因和未公开路线变化不得通过移动预览泄露。

## 8. 队列与校验

移动可以作为普通指令入队。

入队时校验：

```text
当前地点允许移动；
目标节点可见或有合法线索；
至少存在一条当前可用路线或条件路线；
移动方式当前可用；
当前元气、状态和额外资源满足要求；
路线风险没有阻止移动；
当前事件状态不冲突。
```

执行前必须再次校验，防止路线在等待期间被封锁、节点风险变化、权限失效、角色状态恶化、设施停运或法宝不可用。

执行前校验失败时：

```text
1. 跳过该移动指令；
2. 不消耗未生效资源；
3. 记录个人日志；
4. 进入自动兜底；
5. 世界进入 N1，等待玩家补充主动指令。
```

## 9. 移动事件

移动事件覆盖：

- 离开节点。
- 进入节点。
- 途经节点。
- 目标节点。
- 每个移动结算段结束时所在路线段。
- 临时停靠点、中转点或被事件打断后的落点。

移动事件可产生：

```text
遭遇战；
路线阻断；
资源消耗；
信息发现；
行踪暴露；
延误；
追击；
临时停靠；
安全抵达；
路线风险变化；
节点公开传闻。
```

事件时间口径：

1. 轻量个人遭遇进入本人局部时停，外部世界继续 N1。
2. 正式追击、玩家直接冲突、重大资源损失风险或正式战斗进入 B1。
3. 全局公共路线封锁、秘境入口公共变化等少数公共节点可进入 P0。
4. 事件选项有游戏内时间成本时，按 `consumed_hours` 回填到世界小时。
5. 事件造成延误时，后续队列开始时间相应推迟。

## 10. 能力、设施与法宝影响

轻身功法、飞遁法门和身法类能力可以：

1. 降低部分路线移动耗时，但不能突破 1 小时最小消耗。
2. 降低移动元气消耗。
3. 降低延误损失。
4. 解锁逃遁、绕路、攀越、潜行或避险选项。
5. 改善山路、荒野、追击或低阶遭遇中的事件选项。

战斗功法可以改善移动遭遇战、护送、正面迎战和遭遇后结算反馈。

交通设施可以：

1. 改变可达节点或路线。
2. 降低时间成本。
3. 降低路线风险。
4. 提供安全停靠、中转、补给或传送入口。
5. 收取灵石、聚灵石、权限、贡献或维护资源。

移动法宝可以：

1. 作为移动方式参与行动入口。
2. 降低时间或风险。
3. 提供飞遁、渡河、隐蔽、护体、传送或逃遁能力。
4. 消耗元气、神念、耐久、充能、聚灵石或专用材料。
5. 在使用、被拦截、过载或事件代价中产生损坏、失灵或充能下降。

法门、法宝和道具也可作为事件选项依据，但不得默认吞掉玩家选择权。

## 11. 落点与中断

移动完成时更新 `location_node_id`。若移动被事件或路线变化中断，落点按以下优先级确定：

```text
1. 已抵达的目标节点；
2. 玩家显式停靠点；
3. 当前路线段的安全中转节点；
4. 事件指定临时停靠点；
5. 原出发节点；
6. 失败状态模板指定的危险临时落点。
```

落点必须写入结果包、个人日志和回放。若落点为危险临时点，系统应提示风险，并由节点 `risk_level` 影响自动兜底和显式托管默认。

## 12. MVP 保留

MVP 需要保留：

1. `travel` 普通指令。
2. 移动行动最小 1 小时消耗。
3. 入队时与执行前双重校验。
4. 有向带权路线与 `current_cost_hours`。
5. 默认元气消耗。
6. 设施、法宝或特殊路线的额外资源消耗入口。
7. 移动预览。
8. 路线风险与事件触发。
9. 移动完成、延误、中断和落点记录。
10. 移动结果写入结果包、日志和回放。

## 13. MVP 不做

MVP 不做：

1. 完整逐边手动排路。
2. 复杂复合交通路线编辑器。
3. 0 小时移动行动。
4. 默认消耗干粮、丹药、符箓或其他背包物品。
5. 负重、背包格子、重量和容量玩法。
6. 完整坐骑、飞舟、传送阵产业链。
7. 复杂天气、生态和道路自然磨损模拟。
8. 用托管或自动兜底主动进入高危路线。

## 14. 缺口

- 路线权重公式。
- 元气消耗公式与境界 / 路线 / 状态系数。
- 交通设施模板。
- 传送阵、飞舟、移动法宝的最小资源成本表。
- 移动风险概率与事件候选池。
- 新手路线小时成本和教学事件模板。
