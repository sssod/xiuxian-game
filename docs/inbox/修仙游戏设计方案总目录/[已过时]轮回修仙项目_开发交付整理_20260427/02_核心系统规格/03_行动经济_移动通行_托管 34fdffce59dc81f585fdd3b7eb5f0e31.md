# 03_行动经济_移动通行_托管

# 行动经济、移动通行与稳健托管

## 0. 文档定位

本文整理角色每季度如何规划行动、移动、持续操作、事件中断、宗门协同与离线托管。

S3 是角色层时间、位置和行动格底座。突破、事件、战斗、后手、宗门介入都应从 S3 获取触发位置、tick、剩余行动格和上下文。

## 1. 核心口径

S3 当前采用：

> 节点驱动的季度行动规划。
> 

玩家不是先从抽象行动列表选择，而是面对当前所在节点、当前节点可执行操作、可达范围和移动成本，通过节点选择自然形成本季度计划。

## 2. 6 个朔望行动格

一个季度显性拆分为 6 个行动格：

```
一月·朔
一月·望
二月·朔
二月·望
三月·朔
三月·望
```

行动格不是 6 次完整独立行动，而是本季度时间预算。移动、执行、撤离、休整、持续行动、宗门介入都从这 6 格中分配。

## 3. 双层季度结构

```
宗门行动决策阶段
→ 玩家提出宗门建议 / 决策提议
→ 系统即时反馈采纳、预计消耗、路线、风险
→ 角色行动决策阶段
→ 玩家规划 6 个朔望行动格
→ 锁定提交
→ 服务端统一结算
```

宗门行动一般不受玩家角色当前位置限制；角色亲自介入宗门行动时必须走 S3 的行动格、路线、节点和 tick 校验。

## 4. 三类角色行动

### 4.1 即时行动

即时行动可以改变：

- 信息状态。
- 界面状态。
- 轻量库存状态。
- 轻量行政状态。

即时行动不能推进：

- 时间型进度。
- 风险型事件链。
- 地图控制。
- 突破。
- 后手回收。
- 秘境探索。

资源转移类即时行动必须受位置、权限、库存、交易对象和日志约束。

### 4.2 移动行动

移动行动负责：

- 从当前节点到目标节点。
- 读取边权、路线状态、交通设施、权限门、风险门。
- 消耗行动格。
- 触发移动事件。
- 更新季度结束位置。

MVP 路线粒度：

```
目标节点 + 移动方式 + 可选显式停靠点
```

不做完整逐边手动排路，也不做自动复合交通路线。

### 4.3 持续行动

持续行动包括：

- 修炼 / 吐纳。
- 研习功法。
- 探索。
- 驻守。
- 开采。
- 建设。
- 后手布置。
- 后手回收。
- 宗门行动亲自介入。
- 闭关。
- 休整。

tick 是统一时间单位，不是统一收益公式。不同持续行动拥有不同 tick 效果。

## 5. 角色行动标准交互流程

```
进入角色决策阶段
→ 自动弹出当前角色所在节点面板
→ 展示当前节点可执行操作
→ 展开当前移动方式下可达区域
→ 玩家可在初始节点执行 0–1 次一般持续操作
→ 玩家可执行当前节点允许的即时行动
→ 玩家点击“离开”关闭当前节点操作面板
→ 玩家可切换移动方式
→ 玩家点击新目标节点
→ 系统按当前移动方式预扣行动格
→ 自动弹出目标节点可执行操作
→ 玩家可在目标节点执行 0–1 次一般持续操作
→ 行动格归零后进入待锁定预案
→ 若仍有剩余行动格，可继续移动，但后续节点只能休整、警戒或停留
→ 玩家锁定提交
```

## 6. 持续操作限制

MVP 中，所有玩家主动发起的一般持续行动都受：

```
初始节点 + 第一个目标节点
```

的持续操作限制。

如果玩家本季度不移动，同一节点也只能选择一个主要持续行动。该行动可以消耗多个行动格或形成连续状态，但不能在同一节点组合多个收益、调查、社交、采集等一般持续行动。

例外：

- 移动行动。
- 交通设施。
- 休整 / 警戒 / 停留。
- 插入事件链内部选择。
- 服务端强制触发的危机 / 中断 / 撤离流程。

## 7. 跨季度连续状态

连续状态的存在与本季度是否继续投入行动格分离。

规则：

- 下季度开始时，玩家需要继续投入兼容行动格才延续收益或进度。
- 选择不兼容行动视为中断或退出。
- 离线托管只在安全、低风险、无重大分支的情况下自动延续。

```
ContinuousActionState {
  state_id: String,
  character_id: String,
  action_type: String,
  node_id: String,
  started_quarter: int,
  progress: float,
  compatible_followup_actions: Array,
  interruption_rules: Dictionary,
  risk_tags: Array
}
```

## 8. 插入事件中断权

插入事件链可以中断 S3 时间轴。

S3 提供：

- 触发 tick。
- 触发位置。
- 剩余行动格。
- 当前行动状态。
- 路线段。
- 当前连续行动。
- 托管状态。
- 暴露上下文。

事件链返回：

- 继续原计划。
- 消耗剩余行动格。
- 强制中断本季度计划。
- 改变位置。
- 改变状态。
- 改变连续行动。
- 进入死亡、转世或特殊结算。

## 9. 路线、移动与风险

### 9.1 地图接口

S3 从 S8 读取：

- 节点连接。
- 有向边权。
- 交通设施。
- 隐藏路线。
- 权限门。
- 状态门。
- 风险门。
- 路线封锁。

### 9.2 移动事件接口

S3 为 S10 提供移动上下文：

```
MovementContext {
  character_id: String,
  quarter: int,
  tick: int,
  from_node: String,
  to_node: String,
  route_segment: String,
  travel_mode: String,
  stopover_nodes: Array,
  exposure_tags: Array,
  risk_tags: Array
}
```

S10 决定是否触发：

- 遭遇战。
- 路线阻断。
- 延误。
- 信息发现。
- 行踪暴露。
- 消耗补给。
- 安全抵达。

## 10. 季度结束位置

季度结束位置必须是 S3 一级输出，并由服务端权威写入。

客户端只显示预计位置。以下情况可以改变实际结束位置：

- 事件中断。
- 危险撤离。
- 秘境关闭。
- 交通失败。
- 战斗失败。
- 托管避险。
- 节点封锁。

## 11. 休整、警戒、停留

三者是节奏、风险和位置管理工具，不是主要成长收益来源。

| 行动 | 作用 |
| --- | --- |
| 休整 | 恢复状态、降低疲劳、处理轻伤 |
| 警戒 | 降低突发风险、提高事件反应 |
| 停留 | 保持位置、等待窗口、降低额外风险 |

## 12. 托管系统

### 12.1 托管触发

S12 由 S1 调用。触发条件：

1. 玩家在决策阶段超时未提交。
2. 玩家明确设置本季度托管。
3. 房间恢复后存在缺失决策。
4. 插入事件链需要离线玩家做低风险响应。

### 12.2 托管计划结构

```
AutopilotPlan {
  player_id: String,
  character_id: String,
  quarter: int,
  reason: String,
  priority_mode: String,
  generated_actions: Array,
  protected_assets: Array,
  forbidden_actions: Array,
  expected_outcome_summary: String
}
```

### 12.3 禁止托管行为

托管不得主动执行：

- 高风险突破。
- 主动计划转世。
- 主动叛宗。
- 主动发动宗门战争。
- 主动暴露核心后手。
- 主动回收高风险后手。
- 主动进入高危秘境。
- 主动进行强 PvP。
- 消耗稀有不可逆资源。
- 做重大不可逆路线选择。

### 12.4 允许托管行为

托管可以执行：

- 安全闭关延续。
- 巩固境界。
- 基础修炼。
- 休整 / 疗伤。
- 警戒 / 停留。
- 领取基础俸禄。
- 维持低风险宗门职责。
- 洞府和后手维护。
- 自动防御。
- 保命撤退。

## 13. 新手流程接口

第一阶段“初次创建到拜入宗门”用于验证 S3 基础闭环：

```
创建真灵
→ 初次投生
→ 查询角色、地图、日志
→ 找村长打听宗门
→ 发现移动能力不足
→ 打听轻身之法
→ 获得家庭支持
→ 前往镇集武馆
→ 学习轻身功法
→ 规划山门路线
→ 前往云麓山道
→ 触发移动事件
→ 抵达山门
→ 拜入宗门
→ 入门事件链奖励结算
```

实现要点：

- 初始地图有已知、半知、初步解锁但不可查看详情三类节点。
- 家庭支持是一次性事件，需写日志。
- 入门后 follow-up 修炼属于入门事件链内部教学 / 奖励结算，不计为第二个普通持续行动。
- M0 不引入完整饥饿系统，只保留远行干粮消耗接口。

## 14. S3 输出给其他系统

| 目标系统 | S3 输出 |
| --- | --- |
| S4 突破 | 突破触发位置、剩余行动格、突破地点上下文 |
| S7 宗门行动 | 角色是否亲自抵达宗门行动节点、介入 tick |
| S10 事件 | 移动 / 节点 / 路线 / 暴露上下文 |
| 战斗 | 触发 tick、位置、当前状态、剩余行动格 |
| S11 后手 | 创建 / 回收后手的位置与行动投入 |
| S12 托管 | 合法行动生成与安全判断 |
| S13 可见性 | 移动暴露标签与局部可见性 |
| S14 日志 | 可回放行动时间轴摘要 |

## 15. MVP 验收清单

- 每季度显示 6 个朔望行动格。
- 玩家可从当前节点查看可执行操作。
- 玩家可切换移动方式并看到行动格预估。
- 玩家可规划目标节点和持续行动。
- 行动格归零后进入待锁定预案。
- 服务端能生成权威 tick 时间轴。
- 移动可触发事件。
- 插入事件能中断并返回时间轴。
- 季度结束位置由服务端写入。
- 超时玩家可生成稳健托管行动。
