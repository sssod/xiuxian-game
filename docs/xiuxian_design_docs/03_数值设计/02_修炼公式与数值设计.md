# 数值设计｜修炼公式与数值设计

## 1. 设计定位

本文负责修炼数值公式、境界段表结构、外部灵气输入、CP 增长、法力派生、巩固修为、资源输入结算、状态压力和修炼 tick 输出。它回答每个兼容小时如何结算、环境灵气和丹药药性如何进入 CP、CP 如何派生法力、巩固修为如何提高当前大境界纯度、结果包应输出哪些可复盘明细，以及哪些调参边界必须防止收益爆炸或绕过时间预算。

本文不维护境界体系、玩家行动规则、丹药身份、页面布局或完整投放表。境界上下界、系统流程、物品规则、突破挑战、行动指令和 UI 表达分别由对应包内文档维护。

## 2. 当前结论

1. `cultivation_points / CP` 是标准修为点，用于境界进度、阈值、瓶颈、突破开启和日志；CP 不直接等同战斗力或玩家感知强弱。
2. 法力是玩家直观感知的修为强弱，当前公式为 `major_realm_mana = major_realm_cp × major_realm_purity × dao_method_mana_amplifier`，总法力为各大境界法力求和。
3. 纯度是 `(0, 1]` 的惩罚系数；纯度越低修为越虚浮，纯度不超过 1。道功真正的单位 CP 强度由 `mana_amplifier` 表达。
4. 环境灵气输入先受道功 `aura_absorption_cap_per_hour` 限制，再按 `cp_conversion_rate` 转成 CP；丹药等消耗品输入主要受药性容量、体魄承载、服用规则和释放时长限制，最终同样按 `cp_conversion_rate` 转成 CP 或巩固填充。
5. 巩固修为不增加主 CP、不推进境界、不增加功法研习度；它只填充当前大境界巩固 CP 条，并通过提高当前大境界纯度来提高法力。
6. 每个大境界保存一条修炼记录，记录本大境界主修道功、CP、纯度、道功转化率快照、法力放大系数快照、巩固条和锁定状态。
7. 修为丹药不是即时经验药，也不提供 MVP 独立“丹药炼化涨修为”行动；它可直接服用生成体内药性，再由兼容修为增长流逐步消化。
8. 修炼公式只读取当前主修道功掌握度作为效率、上限、相性和风险输入，不在主动吐纳、闭关修炼或自动运转中产出功法掌握增长。
9. 大境界突破开启门槛仍看 CP；突破质量 / 风险 MVP 可读取当前法力相对推荐法力，不在本文引入复杂根基、心境和心魔质量链。

## 4. 基准、单位与输入参数

修炼数值不从“1 小时给多少修为”开始，而是从境界段目标、玩家体验时长和资源路径反推：

```text
RealmSegmentBalance
→ RealmBenchmarkRate
→ ActionCultivationProfile
→ RealmInputFitMatrix
→ ResourceEffectBalance / NodeRealmSupport / SectSupportBalance
→ StatePressureModel
→ BreakthroughScoreBalance
→ ReincarnationEfficiencyPolicy
→ 模拟验证
```

模块含义：

| 模块 | 作用 |
| --- | --- |
| `RealmSegmentBalance` | 定义当前境界段目标时间、进度需求、修为绝对值映射和效率上下限 |
| `RealmBenchmarkRate` | 由境界段目标反推日历基准收益与兼容小时基准收益 |
| `ActionCultivationProfile` | 定义主动吐纳、闭关、自动 / 被动运转、巩固修为和显式托管的相对效率 |
| `RealmInputFitMatrix` | 定义功法、资源、设施、节点和宗门支持对当前境界段是否适配 |
| `ResourceEffectBalance` | 定价丹药、灵材、符箓、临时增益、炼化效果和残余效果 |
| `NodeRealmSupport` | 定义节点灵气、容量、再生、风险和机会窗口 |
| `SectSupportBalance` | 定义宗门资源、护法、设施、权限和库存支持 |
| `StatePressureModel` | 处理外源药性负载、经脉压力、伤势、心魔、寿元压力和强行冲修副作用 |
| `BreakthroughScoreBalance` | 把准备质量转成突破挑战初始分和质量修正 |
| `ReincarnationEfficiencyPolicy` | 判断当前世代效率是否低于境界段基准 |

基础单位：

| 单位或参数 | 含义 |
| --- | --- |
| `world_hour` | 世界小时，是资源消耗、压力和 C1 追赶的基础时间单位 |
| `outer_world_time` | 外界世界日历时间，用于 F1 外界流年、阶段预算、市场、宗门库存和 NPC 宏观成长 |
| `inner_time_years` | 局部时间域主观年，用于洞天 / 时间阵法内的寿元、修行成长、功法研习、道功修炼和压力结算 |
| `compatible_hours` | 当前行动、事件、炼化或自动吸收中实际满足资源与修炼语境的有效小时 |
| `active_medicine_effect_hours` | 体内药性在本次修为增长流中被消化的有效小时 |
| `resource_supported_inner_years` | 当前资源包、宗门护持、聚灵石、阵法燃料等可支撑的局部时间域修炼年数 |
| `target_elapsed_hours_standard` | 境界段标准目标日历小时，不等于单次 `hour_tick` |
| `expected_cultivation_hour_ratio` | 日历小时中预计有多少比例是真正有效修炼兼容小时 |
| `normalized_segment_progress` | 当前境界段调参进度，`0.0` 为刚开始，`1.0` 为达到推进或突破资格 |
| `cultivation_points` / `CP` | 标准修为点 / 修为绝对值进度，用于阈值、境界推进和日志 |
| `cp_lower_bound / cp_upper_bound` | 小境界修为绝对值上下界，由 `01_修为境界与期望游玩时间建模.md` 维护 |
| `major_realm_cp` | 当前大境界内累计 CP，用于当前大境界法力派生和巩固需求 |
| `major_realm_purity` | 当前大境界纯度，范围 `(0, 1]`，是 CP 转法力的惩罚系数 |
| `mana_amplifier` | 主修道功法力放大系数，表达单位 CP 对应法力强度 |
| `major_realm_mana` | 当前大境界法力，由 CP、纯度和道功放大系数派生 |
| `total_mana` | 角色总法力，当前为各大境界法力求和 |
| `aura_absorption_cap_per_hour` | 道功每小时可承接的环境灵气上限 |
| `cp_conversion_rate` | 已承接灵气转化为 CP 或巩固填充的速度 |
| `consolidation_required` | 当前大境界巩固 CP 条总需求 |
| `consolidation_filled` | 当前大境界巩固 CP 条已填充量 |

`cultivation_points` 是角色当前累计标准修为点。表格字段和公式字段可使用 `cp_` 前缀表示 cultivation points，但正文优先写“CP”或“标准修为点”。小境界修为绝对值上下界由《修为境界与期望游玩时间建模》（`01_修为境界与期望游玩时间建模.md`）维护；本文只消费 `cp_lower_bound / cp_upper_bound`，不另行维护小境界比例表或具体上下界表。

CP 管境界进度，法力管玩家感知强弱：

```text
major_realm_mana =
  major_realm_cp
  * major_realm_purity
  * dao_method_mana_amplifier

total_mana =
  Σ major_realm_mana
```

当前暂不引入 `realm_weight_i`。如果未来 CP 不再是跨境界绝对值，而变成每个大境界内部局部值，需要单独裁决总法力公式中的境界权重。

`normalized_segment_progress` 的建议范围：

```text
0.0 = 当前境界段刚开始
1.0 = 达到该境界段推进目标，具备进入下一阶段或开启突破资格
>1.0 = 超额准备，可转化为突破初始优势、品质修正或稳定性修正
```

玩家界面显示当前小阶段自身进度 `0%-100%`，不显示跨阶段总进度比例：

```text
minor_stage_display_progress =
  clamp(
    (cultivation_points - cp_lower_bound)
    / (cp_upper_bound - cp_lower_bound),
    0,
    1
  )
```

修为绝对值映射：

```text
cultivation_points_gain = normalized_gain * raw_cultivation_required_s
```

因此炼气、筑基、金丹可以拥有不同量级修为绝对值；同一大境界内，不同小阶段也可以拥有不同修为绝对值跨度。调参时同时查看小阶段显示进度、修为绝对值上下界、`normalized_segment_progress`、境界段目标小时和资源路径。

## 5. 公式或模型

### 5.1 基准收益反推

设：

```text
s = 当前 RealmSegment
T_s = target_elapsed_hours_standard_s
U_s = expected_cultivation_hour_ratio_s
P_s = required_normalized_progress_s
```

日历基准推进率：

```text
calendar_benchmark_rate_s = P_s / T_s
```

有效修炼兼容小时基准收益：

```text
compatible_hour_benchmark_rate_s = P_s / (T_s * U_s)
```

如果某段设计为：

```text
target_elapsed_hours_standard = 720
expected_cultivation_hour_ratio = 0.60
required_normalized_progress = 1.0
```

则：

```text
calendar_benchmark_rate = 1 / 720
compatible_hour_benchmark_rate = 1 / 432
```

含义是标准路径 720 个日历小时完成该段，其中约 432 小时是真正有效修炼兼容小时，每个有效修炼小时获得约 `0.00231` 标准化进度。

### 5.2 外部灵气输入与 CP 增长

修炼 tick 先拆分外部输入，再生成 CP。当前有两条主输入流：

| 输入流 | 来源 | 主要限制 |
| --- | --- | --- |
| 环境灵气流 | 节点灵气、灵脉、洞府、聚灵阵、宗门设施等 | 道功环境灵气吸收上限、地点供给、设施支持和兼容小时 |
| 丹药 / 消耗品灵气流 | 丹药、灵材、灵液、符箓、宗门配给等 | 药性容量、体魄承载、服用规则、释放时长、叠加组和资源模板 |

环境灵气流：

```text
environment_aura_intake =
  min(
    node_aura_available,
    dao_method_aura_absorption_cap_per_hour * compatible_hours
  )
```

`node_aura_available` 可以由节点灵气、设施、洞府、聚灵阵、宗门支持和机会窗口合成，但不能绕过道功环境灵气吸收上限。

丹药 / 消耗品灵气流：

```text
medicine_aura_intake =
  min(
    active_medicine_aura_release,
    medicine_capacity_remaining
  )
```

`medicine_capacity_remaining` 由药性容量、体魄承载、经脉负载、同组上限、服用规则和资源释放时长共同限制。丹药流不再受道功环境灵气吸收上限限制，但仍要进入道功转化率、相性、贡献上限和状态安全检查。

合流后生成 CP：

```text
raw_aura_input =
  environment_aura_intake
  + medicine_aura_intake

cp_gain =
  raw_aura_input
  * dao_method_cp_conversion_rate
  * action_efficiency_factor
```

其中 `action_efficiency_factor` 汇总行动类型、资质 / 根骨、主修道功适配、掌握度、设施、宗门支持、状态惩罚和动态窗口：

```text
action_efficiency_factor =
  clamp(
    A_action
    * Q_aptitude
    * M_method
    * K_mastery
    * F_facility
    * S_sect_support
    * P_state_penalty
    * C_competition_or_window,
    min_efficiency_ratio_s,
    max_efficiency_ratio_s
  )
```

CP 更新：

```text
major_realm_cp_after =
  major_realm_cp_before + cp_gain

cultivation_points_after =
  cultivation_points_before + cp_gain
```

小阶段显示进度由 `cp_lower_bound / cp_upper_bound` 派生，不反向决定 CP：

```text
minor_stage_display_progress =
  clamp(
    (cultivation_points_after - cp_lower_bound)
    / (cp_upper_bound - cp_lower_bound),
    0,
    1
  )
```

法力更新：

```text
major_realm_mana_after =
  major_realm_cp_after
  * major_realm_purity
  * dao_method_mana_amplifier
```

防重复计入口径：

1. 环境灵气、丹药定额灵气和最终效率倍率必须分清来源，不得同一资源三次计入。
2. 如果某资源以定额灵气进入 `medicine_aura_intake`，同一个资源不得再次作为最终倍率重复计入。
3. 如果某资源模板明确是 `rate_multiplier`，则它可以进入 `action_efficiency_factor`，但必须受境界适配、贡献上限和段级效率上限约束。
4. 节点灵气浓度带来的输入仍要看道功 `cp_conversion_rate`，不能直接写成 CP 或法力。

### 5.3 行动相对效率

行动类型不直接写死 raw 修为收益，只提供相对当前境界段基准的效率倍率。

| 行动 | 相对效率口径 | 边界 |
| --- | --- | --- |
| 主动吐纳 | 主要主 CP 推进基准 | 高效消化体内修为药性，生成主 CP 并更新当前大境界法力 |
| 闭关修炼 | 主动吐纳的长时段低交互版本 | 可进入 F1；仍按兼容小时结算；内部修行片段可批量消化体内药性并生成主 CP |
| 自动 / 被动运转 | 极低额主 CP 保底收益 | 可低效消化已服用且允许被动消化的药性；可触发小境界，不能触发大境界突破，不主动消耗未服用关键资源 |
| 巩固修为 | 填充当前大境界巩固 CP 条 | 不增加主 CP，不推进境界，不增加功法研习度；只提高当前大境界纯度和法力 |
| 显式托管 | 低收益低风险 | 不主动执行高风险突破，不主动消耗新高价值资源 |
| 休整 / 疗伤 | 以状态恢复为主 | 不作为成长主路径 |

初始方向：

| 路径 / 行动 | 相对基准效率方向 |
| --- | --- |
| 标准主动路径 | 约 1.00 |
| 安全低风险路径 | 0.65-0.90 |
| 资源投入路径 | 1.20-1.70 |
| 高风险节点路径 | 1.30-2.20 |
| 宗门支持路径 | 1.10-1.60 |
| 显式托管 | 0.20-0.50 |
| 自动兜底 / 自动运转 | 0.05-0.20 |

这些区间只是首版调参方向，不是硬编码表。实际值必须通过数值验算确认各境界段完成时间、压力曲线和资源消耗是否落入目标。

### 5.4 境界适配矩阵

功法、资源、设施、节点灵气和宗门支持共用境界适配矩阵，避免跨阶资源直接碾压。

| 输入品阶 vs 境界段 | 效率 | 贡献上限 | 浪费 | 压力 / 反噬 |
| --- | --- | --- | --- | --- |
| 低 2 阶 | 极低 | 极低 | 高 | 低 |
| 低 1 阶 | 低 | 低 | 中 | 低 |
| 同阶 | 标准 | 高 | 低 | 低 |
| 高 1 阶 | 高 | 高 | 中 | 中 |
| 高 2 阶以上 | 较高但不稳定 | 中 | 高 | 高 |

高阶资源可以提高效率，但应通过浪费、经脉压力、相性风险、贡献上限和段级效率上限限制。低阶资源可安全但贡献衰减。标签不适配时，应表现为转化率低、药力浪费、短期疲劳、短期经脉压力或心神扰动，而不是完全无声失败。

### 5.5 资源输入生命周期

资源输入可以来自直接服用、行动、事件选项、显式炼化或自动吸收。它不改变行动本身类型，只在使用确认或兼容语境中按有效小时释放。

生命周期：

```text
直接服用、规划或事件选择
→ 创建 ResourceUseRequest、ActiveResourceEffect 或 ActionResourceInputBinding
→ 执行前重新校验资产、权限、位置、标签、经脉承载和叠加限制
→ 使用确认或行动 / 事件 / 炼化 / 吸收实际开始后消耗或预留资源
→ 按小时释放效果
→ 完整消耗、生成残余效果、暂停、散逸、失败退款或事件专用处理
→ 写入结果包、资产日志、角色日志和回放
```

基础模型：

```text
resource_effect_total = unit_effect_rate * max_effective_hours

applied_resource_effect =
  unit_effect_rate
  * applied_effective_hours
  * resource_quality_factor
  * state_factor
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `unit_effect_rate` | 每小时释放多少灵气、提供多少悟性修正、抵消多少毒瘴压力、恢复多少伤势等 |
| `max_effective_hours` | 该资源最多能在兼容语境中生效多少小时 |
| `applied_effective_hours` | 本次行动、事件、炼化或吸收中实际消耗的有效小时 |
| `resource_quality_factor` | 品级、成色、稳定性、模板波动等品质修正 |
| `state_factor` | 角色状态、相性、承载、地点、安全环境等修正 |

三类常规计时模式：

| 计时模式 | 适用 | 规则 |
| --- | --- | --- |
| `compatible_action_hours` | 修为丹药体内药性、悟性丹、定心丹、疗伤丹等 | 只在兼容修为增长流、兼容行动或兼容事件选项实际执行时消耗有效小时 |
| `hazard_exposure_hours` | 避瘴丹、解毒丹、危险环境防护 | 只在危险暴露小时或事件模板声明的危险语境中消耗 |
| `world_elapsed_hours` | 未来危险丹药、强制释放效果、部分自动吸收 | 按世界小时推进，即使没有兼容行动也会消耗，并可能转为浪费、压力或反噬 |
| `refinement_completion` | 延寿丹、属性丹、洗髓丹等完成炼化后结算的长期效果 | 炼化未完成前不提前发放完整效果；完成后按模板写入角色状态 |

MVP 的常规修炼资源默认使用 `compatible_action_hours` 或 `hazard_exposure_hours`。`world_elapsed_hours` 和 `forced_release` 只作为字段和未来分支保留，不作为常规修为资源投放。

### 5.6 修为丹药与体内药性

修为类丹药可以直接服用并创建体内药性。体内药性不是即时经验药，也不是独立“丹药炼化涨修为”行动；它只能由兼容修为增长流逐步消化。主动吐纳和闭关修行片段是高效消化流，自动 / 被动运转是低效消化流，修为类事件必须由事件模板显式声明是否消化。

合法：

```text
直接服用清灵丹，形成 12 小时体内药性。
主动吐纳 6 小时，消化清灵丹药性 6 小时。
闭关修炼 30 日，其中修行片段批量消化已服用药性。
灵泉事件声明可消化事件结算前已激活药性。
```

非法：

```text
即时服用清灵丹，立即获得完整修为。
单独执行丹药炼化 12 小时，并获得修为。
移动途中服用清灵丹，持续获得修为。
突破失败后回溯服丹，重算已经结算的修为。
```

修为增长结算中存在两条输入流：

| 输入流 | 规则 |
| --- | --- |
| 环境灵气流 | 节点灵气、资源槽灵气、聚灵阵、洞府、灵液池等，受道功环境灵气吸收上限、节点容量和角色状态限制 |
| 体内药性流 | 已服用丹药释放定额灵气包，主要受药性容量、体魄承载、经脉负载、服用规则和资源释放时长限制；不受道功环境灵气吸收上限限制，但仍按道功转化率生成 CP |

修为丹药不是提高节点灵气浓度，不是提高聚灵阵效果，也不是简单提高最终倍率。

环境灵气输入：

```text
environment_aura_input =
  min(
    node_aura_available,
    dao_method_aura_absorption_cap_per_hour * compatible_hours
  )
```

修为资源输入：

```text
medicine_aura_intake =
  Σ(unit_aura_rate_i * consumed_medicine_effect_hours_i * resource_quality_factor_i)
```

主动吐纳合流：

```text
raw_aura_input =
  environment_aura_input
  + medicine_aura_intake

cp_gain =
  raw_aura_input
  * dao_method_cp_conversion_rate
  * action_efficiency_factor
```

之后写入主 CP；法力由 `CP × 纯度 × mana_amplifier` 派生。丹药不直接即时增加法力，也不绕过修炼或巩固流程。

如果本次修为增长流消化量少于丹药 `max_effective_hours`，只结算实际消化部分。剩余药性保留在 `ActiveResourceEffect` 中，后续只能在兼容修为增长流中继续使用，或由巩固修为选择性收束但不转化为主 CP。

### 5.7 残余效果

当资源已被消耗或确认使用，但未在本次修为增长流、行动、事件、炼化或自动吸收中完全释放，生成或保留 `ActiveResourceEffect`。

生成场景：

1. 体内药性在持续时间内未被完全消化。
2. 行动实际时长少于资源最大有效时长。
3. 行动开始后被事件打断。
4. 行动中部分小时不满足资源兼容语境。
5. 显式炼化未完成。
6. 自动吸收尚未释放完整效果。

不生成场景：

1. 带资源输入的行动没有实际开始，或直接服用确认未完成。
2. 服务端校验未通过，资源没有消耗。
3. 事件模板声明该资源为一次性无残余。
4. 所有突破丹药由突破事件链专门结算，突破事件结束后停止影响。
5. 资源模板声明使用失败时全额退款且不产生状态。

残余策略：

| 策略 | 用途 | 规则 |
| --- | --- | --- |
| `stable_suspend` | 普通清灵丹、普通启悟丹、低刺激养元资源 | 非兼容行动期间不生效，在稳定窗口内不明显损失，之后缓慢散逸 |
| `slow_decay` | 品质较差丹药、保存状态一般资源 | 非兼容行动期间缓慢减少，通常只造成轻微浪费或疲劳 |
| `stimulating_decay` | 速成修为丹、烈性火系丹药、高刺激破关资源 | 非兼容行动期间较快衰减，衰减可能转为经脉压力、疲劳或神念扰动 |
| `forced_release` | 高阶危险丹药、剧情丹药、强行破关资源 | 按世界小时持续释放，未被吸收部分转为浪费、压力或反噬；MVP 不投放，只预留字段 |

跨回合规则：

1. 行动未开始或直接服用未确认，不消耗资源。
2. 行动已开始或体内药性正在被消化时，只消耗实际兼容小时。
3. 决策阶段、局部时停和玩家阅读报告期间不推进药性衰减。
4. 服务器结算阶段、世界小时实际推进时，才增加 `idle_world_hours` 或 decay 相关计数。
5. `stable_suspend` 可保留给后续兼容行动继续承接。
6. `stimulating_decay` 和 `forced_release` 应更容易造成散逸、压力或副作用。
7. C1 追赶只补结算确定性的兼容小时、资源消耗和药性衰减；已有随机效果只读取固化值。

### 5.8 巩固修为

巩固修为是当前大境界内的独立修炼选择，用于提高当前大境界纯度和法力密度。它不是主 CP 推进流程，也不是功法研习流程。

巩固修为的稳定边界：

1. 不增加主 CP。
2. 不推进境界进度。
3. 不增加功法研习度。
4. 只填充当前大境界巩固 CP 条。
5. 只修改当前大境界纯度，并由此提高当前大境界法力。
6. 进入下一大境界后，上一大境界记录锁定，普通巩固修为不能再修改其纯度。

巩固需求：

```text
purity_gap =
  purity_ceiling - purity_floor

consolidation_required =
  cp_total_in_current_major_realm
  * purity_gap
  * consolidation_cost_factor
```

若希望最小化字段，MVP 可先令：

```text
consolidation_cost_factor = 1
```

巩固填充仍基于外部输入和道功转化率结算，但写入巩固 CP 条，而不是主 CP 条：

```text
consolidation_gain =
  raw_aura_input
  * dao_method_cp_conversion_rate
  * consolidation_action_efficiency

consolidation_filled_after =
  min(
    consolidation_filled_before + consolidation_gain,
    consolidation_required
  )
```

纯度更新：

```text
current_purity =
  purity_floor
  + (purity_ceiling - purity_floor)
    * (consolidation_filled_after / consolidation_required)
```

当 `consolidation_filled_after == consolidation_required` 时：

```text
current_purity = purity_ceiling
```

法力更新：

```text
major_realm_mana_after =
  cp_total_in_current_major_realm
  * current_purity
  * mana_amplifier_snapshot
```

巩固修为可以选择性收束残余修为药性以降低散逸或副作用，但残余药性收束本身不转化为主 CP。若残余药性被允许参与巩固填充，必须由资源模板明确声明，并按巩固公式写入 `consolidation_gain`，不得同时写入主 CP。

### 5.9 事件资源输入、叠加与托管

事件选项允许临时追加资源输入，但必须由事件模板声明 `resource_input_slot`。

事件资源输入规则：

1. 不允许回溯生效。
2. 必须走统一资源校验。
3. 必须写入资源使用结果、事件结果包、资产日志、角色日志和回放。
4. 修为事件若消化体内药性，必须声明消化上限、转化倍率和过载检查，且只能消化事件结算前已经激活的药性。
5. 是否产生残余效果由事件模板和资源模板共同决定。
6. 突破事件链中的资源优先服从突破事件链规则，不产生普通残余药性，突破事件结束后停止影响。

禁止：

```text
事件发生后，回溯让避瘴丹覆盖之前已经暴露的 5 小时。
战斗结束后，回溯使用回气丹改变已结算的交锋。
突破失败后，回溯服用定心丹重算风险。
修为事件结算后，服用清灵丹回溯放大刚才的修为收益。
```

叠加规则：

1. MVP 同一行动中，同一效果通道最多使用 1 个主资源输入。
2. 体内修为药性受经脉负载、`stacking_group`、`max_same_group_active` 和强刺激互斥限制。
3. 研习功法最多 1 种主悟性增益资源。
4. 毒瘴探索最多 1 种主避瘴 / 解毒资源。
5. 休整治疗最多 1 种主疗伤资源。
6. 如果角色已有同一 `stacking_group` 的 `ActiveResourceEffect`，默认不允许再使用同组新资源。

显式托管规则：

1. 托管不得主动服用新的稀有修为丹药、高刺激速成丹药或不可逆高价值资源。
2. 托管可以在安全条件下通过兼容行动承接已有残余效果。
3. 对刺激型残余效果，托管可以选择巩固修为收束。
4. 保命、避险、避免重大不可逆选择优先于节省药性。

### 5.10 状态压力模型

正常吐纳、正常功法运转和常规闭关中的自然修行不默认增加经脉压力。状态压力主要来自体内药性负载、跨阶或不适配资源、灵材、符箓、阵法灌注、强行吸收外源灵气、污染环境、带伤冲修和长时间高风险闭关。

经脉压力当前职责收窄为体魄考验、药性容量和外源资源过载风险。它不参与法力公式，不默认参与纯度计算，也不承担根基、心境、普通战斗出力或复杂突破质量链。

压力生成：

```text
over_rate = max(0, efficiency_ratio - 1.0)

meridian_pressure_gain =
  external_load_pressure
  + over_rate * pressure_from_forced_overbenchmark_rate
  + resource_pressure
  + node_pressure
  + method_mismatch_pressure
```

`over_rate` 只在强行冲修、高风险闭关、污染环境或外源灌注等模板声明会产生压力时计入。普通主动吐纳或自动 / 被动运转即使产生修为，也不因为“正在修炼”这个事实默认增加经脉压力。

状态惩罚：

```text
P_state_penalty =
  1 / (1 + lambda1 * meridian_pressure + lambda2 * injury + lambda3 * mental_risk)
```

状态压力至少影响：

1. `meridian_pressure`。
2. `injury_state`。
3. `mental_state` 或心魔风险。
4. 药性容量、同服限制、外源资源过载和行动风险。
5. 由突破模板明确读取的开启安全条件。

压力模型不应只作为失败惩罚存在；它也需要给疗伤、换地点、宗门护法、保守修炼、停止服丹和处理残余药性留下明确修正入口。普通巩固修为的主要数值目标是当前大境界纯度，不再默认承担经脉压力、根基和心境的复合修复职责。

### 5.11 分域时间与资源年结算

修炼收益不能再默认按完整生涯时间或外界流年单一切分。结算应读取《时间速度与局部时间域数值设计》（`10_时间速度与局部时间域数值设计.md`）中的分域时间：

```text
local_domain_inner_years
outer_f1_years
live_interaction_outer_hours
```

局部时间域内，首版默认：

```text
local_domain_growth_ratio = 0.70
local_domain_support_ratio = 0.30
method_study_ratio = 0.20
dao_cultivation_ratio = 0.80
```

有效修炼年必须同时受计划主观年、资源年、功法支持、寿元安全和状态承载限制：

```text
planned_growth_inner_years =
  planned_inner_years * local_domain_growth_ratio

effective_cultivation_inner_years =
  min(
    planned_growth_inner_years,
    resource_supported_inner_years,
    method_supported_inner_years,
    lifespan_safe_inner_years,
    state_capacity_inner_years
  )

unsupported_inner_years =
  max(0, planned_growth_inner_years - effective_cultivation_inner_years)
```

资源不足年份仍消耗寿元，但修为收益大幅降低：

```text
unsupported_gain =
  base_breathing_gain
  * unsupported_inner_years
  * unsupported_efficiency_ratio
```

`unsupported_efficiency_ratio` 首版建议为 `0.0-0.2`，并额外提高心魔、经脉压力、枯坐、状态恶化和事件风险。

洞天外 F1 外界流年不应全量算作修行成长。首版只有 10%-20% 建议作为普通修炼 / 低阶修炼，其余主要用于世界资源等待、长耗时生产、长期游历和宗门职责。

### 5.12 突破承接

修炼数值负责提供大境界突破的 CP 开启门槛和法力短板提示。大境界突破最终成败仍由 B1 轮内策略、轮内资源消耗、状态变化和模板结局共同决定。

开启条件可读取：

```text
current_realm_cp >= required_cp
main_dao_method_supports_next_realm == true
required_breakthrough_resource_available == true
location_allows_breakthrough == true
```

MVP 可用法力相对推荐值表达“修为进度够但法力偏虚”的突破短板：

```text
breakthrough_quality_score =
  current_mana / recommended_mana_for_breakthrough
```

或在只检查当前大境界时使用：

```text
breakthrough_quality_score =
  current_purity_adjusted_mana / recommended_mana_for_breakthrough
```

玩家表达：

```text
修为进度够了，可以尝试突破。
但法力偏虚，突破质量较差；建议巩固修为。
```

根基、心境、心魔、复杂纯度惩罚链和多维突破评分不进入 MVP 默认公式。若突破模板需要读取经脉压力、伤势、心境或特殊根基字段，必须在突破文档中单独声明，不由修炼公式默认扩大职责。

## 6. 配置表或根表

`RealmSegmentBalance` 是修炼数值模型根表。境界段可以表示小境界推进、瓶颈、突破准备或巩固阶段。

```text
RealmSegmentBalance {
  segment_id: String
  realm_from: String
  minor_stage_from: String
  realm_to: String
  minor_stage_to: String
  segment_type: minor_progress | bottleneck | major_breakthrough | consolidation
  target_elapsed_hours_standard: number
  target_elapsed_hours_safe: number
  target_elapsed_hours_risk: number
  target_elapsed_hours_resource: number
  target_elapsed_hours_sect: number
  expected_cultivation_hour_ratio: number
  required_normalized_progress: number
  cp_lower_bound: number
  cp_upper_bound: number
  raw_cultivation_required: number
  required_method_mastery_norm: number
  required_foundation_min: number
  allowed_meridian_pressure_max: number
  allowed_injury_max: number
  allowed_mental_risk_max: number
  expected_breakthrough_rounds: int | null
  breakthrough_template_id: String | null
  min_efficiency_ratio: number
  max_efficiency_ratio: number
  low_efficiency_threshold: number
  high_efficiency_threshold: number
  reincarnation_hint_policy: String
}
```

字段口径：

1. `target_elapsed_hours_standard` 是境界段基准，不是 `hour_tick` 本身。
2. `expected_cultivation_hour_ratio` 表示日历小时中有多少小时是真正有效修炼兼容小时。
3. `cp_lower_bound / cp_upper_bound` 由《修为境界与期望游玩时间建模》（`01_修为境界与期望游玩时间建模.md`）维护。
4. `raw_cultivation_required` 默认可由 `cp_upper_bound - cp_lower_bound` 派生，用于修为绝对值表现和日志映射。
5. `min_efficiency_ratio / max_efficiency_ratio` 是段级裁剪边界，防止倍率爆炸。
6. 轮回效率阈值跟随段配置，不做全局固定值。
7. `target_elapsed_hours_safe / risk / resource / sect` 用于模拟不同路径的目标完成时间，不直接写成玩家无来源倍率。

`RealmBenchmarkRate` 可以作为派生缓存：

```text
RealmBenchmarkRate {
  segment_id: String
  calendar_benchmark_rate: number
  compatible_hour_benchmark_rate: number
  generated_from_balance_version: String
}
```

道功修炼数值配置：

```text
DaoMethodCultivationProfile {
  method_id: String
  aura_absorption_cap_per_hour: number
  cp_conversion_rate: number
  mana_amplifier: number
  purity_floor: number
  purity_ceiling: number
  consolidation_cost_factor: number
  consolidation_action_efficiency: number
  cultivation_speed_tag: fast | balanced | slow
  mana_density_tag: loose | balanced | condensed
}
```

字段口径：

1. `aura_absorption_cap_per_hour` 只限制环境灵气流，不限制已服用丹药的定额药性释放。
2. `cp_conversion_rate` 表示已承接灵气转化为 CP 或巩固填充的速度；转化率高低代表修炼速度，不直接代表道功强弱。
3. `mana_amplifier` 表示单位 CP 对应的法力强度；同品级低转化率道功可以有更高 `mana_amplifier`。
4. `purity_floor / purity_ceiling` 共同决定当前大境界默认纯度和可巩固上限，且纯度范围必须在 `(0, 1]` 内。

大境界修炼记录：

```text
MajorRealmCultivationRecord {
  character_id: String
  major_realm_id: String
  main_dao_method_id: String
  main_dao_method_state_id: String
  cp_total_in_realm: number
  cp_conversion_rate_snapshot: number
  mana_amplifier_snapshot: number
  purity_floor_snapshot: number
  purity_ceiling_snapshot: number
  consolidation_required: number
  consolidation_filled: number
  current_purity: number
  mana_value: number
  locked: bool
  locked_at_stage: String | null
  locked_world_day: int | null
  locked_world_hour: int | null
}
```

记录规则：

1. 道功相关数值在大境界记录中保存快照，避免后续道功模板调参或换功回溯改写历史法力。
2. `mana_value` 可以实时派生，也可以保存缓存；若保存缓存，必须与 `cp_total_in_realm * current_purity * mana_amplifier_snapshot` 一致。
3. `locked = true` 后，普通巩固修为不再修改该记录。

## 8. 调参验收口径

1. 玩家看到的每个小阶段都能从自身 `0%-100%` 推进。
2. 小阶段之间的修为绝对值跨度、有效修炼小时和资源需求可以不同。
3. 主动吐纳是主要主 CP 来源，自动运转不会替代玩家规划。
4. 闭关和 F1 只压缩现实等待；内部可批量结算，但结果必须可复盘外界时间、局部主观时间、兼容小时、资源消耗和压力变化。
5. 修为丹药不会成为即时经验药，也不会通过独立丹药炼化增加修为。
6. 修为丹药直接服用后只创建体内药性，体内药性只在兼容修为增长流或明确允许的修为事件中释放修为灵气输入。
7. 非兼容行动不转化修为药性或修为资源效果。
8. 行动未开始、事件选项未生效、炼化未确认或直接服用未确认时，不提前消耗关键资源。
9. 已服用但未完整消化、或已开始但未完整消耗的资源能生成可复盘残余效果。
10. 决策阶段、局部时停和报告阅读不推进药性衰减。
11. 巩固修为只填充当前大境界巩固 CP 条，提高当前大境界纯度和法力；不得增加主 CP、推进境界或增加功法研习度。
12. 经脉负载、叠加组和同组上限可以限制同时服用丹药，不让主资源输入叠加成为主要收益漏洞。
13. 托管不会主动消耗新高价值资源或主动发起高风险突破。
14. 高倍率资源必须受到境界适配、状态压力、贡献上限和段级效率上限约束。
15. 小境界升级可以轻量触发，大境界突破不能只靠修为绝对值达标自动完成。
16. 结果包能复盘收益、资源消耗、压力变化、残余效果、日志引用和可见摘要。
17. 资源不足的局部时间域年份不得继续高效修炼；应耗寿低效并提高心魔、经脉和枯坐风险。
18. 洞天内主观年不得驱动阶段预算、市场、宗门库存或 NPC 宏观成长刷新。
19. 战斗和突破提示读取法力时，必须由 CP、纯度和道功放大系数派生，不能把 CP 直接当作战斗力。

## 9. MVP 范围

MVP 应实现：

1. `RealmSegmentBalance` 与自动生成 / 派生 `RealmBenchmarkRate`。
2. `normalized_segment_progress` 与 `cultivation_points` 映射。
3. 主动吐纳、闭关修炼、自动运转、巩固修为、显式托管的基础效率表。
4. 资源使用请求与行动资源输入项 `ResourceUseRequest` / `ActionResourceInputBinding`。
5. 修为丹药直接服用生成体内药性。
6. 悟性丹挂载研习功法。
7. 避瘴 / 解毒资源挂载危险语境行动或事件。
8. 疗伤资源挂载休整、治疗或医疗事件。
9. 定心资源挂载巩固修为、突破准备、研习功法或突破事件链。
10. 直接服用确认或行动开始后按实际兼容小时消耗资源。
11. `ActiveResourceEffect` 体内药性与残余效果。
12. `stable_suspend / slow_decay / stimulating_decay` 三类常规残余策略。
13. `forced_release` 字段预留，但不常规投放。
14. 经脉负载限制同服丹药。
15. 当前大境界巩固 CP 条、纯度更新和法力更新。
16. 事件选项可临时追加资源输入，修为事件可按模板消化结算前已激活药性。
17. 同效果通道最多 1 个主资源输入，体内药性另受叠加组和经脉承载约束。
18. `CultivationTickResult`、资源使用日志、资产流水、角色日志和回放。
19. `effect_rate_min / effect_rate_max / actual_unit_effect_rate` 支持资源效果波动并固化结果。
20. 局部时间域主观年、资源年、资源不足年和寿元扣除时间域的结算字段。

MVP 不实现：

1. 通过独立“丹药炼化”让修为丹药增加修为。
2. 即时服丹涨修为。
3. 多枚修为丹药复杂叠加。
4. 主药 + 辅药 + 药引组合。
5. 危险丹药和 `forced_release` 实际投放内容。
6. 可长期累计的复杂丹毒 / 杂质系统。
7. 玩家在结算阶段主动暂停来重新安排药性。
8. 所有境界完整资源模板与状态压力曲线。
9. 普通巩固修为修补历史大境界纯度。
10. 突破质量复杂根基、心境和心魔评分链。
