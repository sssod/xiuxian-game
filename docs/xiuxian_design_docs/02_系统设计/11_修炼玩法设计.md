# 系统设计｜修炼玩法

## 1. 设计定位

修炼玩法负责玩家如何通过行动、资源、环境、功法和状态管理推进修为。它回答“玩家做什么、看到什么、如何规划和止损”，不负责定义每小时收益公式、境界段数值表或页面具体布局。

修炼不是挂机等待。本文维护主动吐纳、闭关修炼、自动运转、研习功法、巩固根基、行动资源输入、残余效果、F1 低交互消化和玩家反馈边界。境界结构、修炼公式、功法成长、丹药物品、持续状态和页面表达由对应文档维护。

## 2. 当前结论

1. 玩家主动修炼以行动规划为入口，不以单独经验药按钮或即时服药按钮为入口。
2. 主动吐纳是获得修为和主修道功经验的主要行动；研习功法获得目标功法经验，不直接获得修为。
3. 自动运转提供少量被动收益，通常可触发小境界升级，但不能完成大境界突破。
4. 巩固根基用于处理状态、压力、残余药性和突破准备，不替代主动吐纳获得修为。
5. 修为类丹药只能作为主动吐纳的行动资源输入，按实际兼容小时释放，不提供独立“丹药炼化”行动。
6. 资源输入采用行动内折叠项；已有残余效果在角色面板或行动规划器中常驻提示。
7. 修为绝对值表示角色当前累计修为规模，字段名为 `cultivation_points`；修炼公式、效率倍率、境界段修为绝对值和 `CultivationTickResult` 由修炼数值文档维护。
8. 洞天 / 时间阵法闭关不是免费收益；玩家必须绑定资源年、功法、寿元承载、风险阈值和中断策略，资源不足时仍耗寿但低效。

## 4. 核心循环或触发入口

玩家通过指令管理入口或修为相关页面规划修炼行动。修炼的基础循环是：

```text
在 N1、事件、宗门、地图、市场和 NPC 互动中创造高价值修炼条件
→ 规划主动吐纳、闭关、资源输入或巩固根基
→ 服务端校验行动、地点、状态、功法和资源输入
→ 按世界小时与实际兼容小时结算
→ 在 F1 中快速消化低交互等待
→ 通过小境界反馈、瓶颈提示和突破准备调整下一轮经营
```

常见入口包括：

1. 行动指令队列中提交主动吐纳、闭关修炼、研习功法、巩固根基、疗伤或显式托管。
2. 修为页面查看进度、瓶颈、风险、残余效果和突破准备，并跳转到可执行行动。
3. 角色页面查看经脉压力、根基、伤势、心魔、残余药性和寿元等影响修炼的状态。
4. 宗门、洞府、地图节点、设施、事件或 NPC 互动为修炼提供地点、资源、护法、机会窗口或限制。

中断点包括行动被事件打断、角色状态恶化、资源释放结束、残余药性散逸、进入瓶颈、触发小境界升级、达到突破准备语境、F1 被公共同步事件或交锋中断，以及 C1 追赶后需要重新提示行动结果。

## 5. 规则与状态

### 5.1 行动类型

| 行动 | 玩家意图 | 主要收益 | 玩法边界 |
| --- | --- | --- | --- |
| 主动吐纳 | 投入时间推进当前境界段 | 修为进度、主修道功经验、资源输入转化 | 可挂载修为丹药和灵气类资源 |
| 闭关修炼 | 长时间低交互修炼 | 批量推进修为、消化资源和环境收益 | 可进入 F1；仍按小时结算 |
| 自动运转 | 非吐纳状态下的低额自然推进 | 少量修为或稳定性收益 | 不能完成大境界突破 |
| 研习功法 | 学习或提高道功 / 法门掌握 | 功法经验、可修上限、提示型或知识型收益 | 不直接给修为 |
| 巩固根基 | 降低压力、稳定根基、处理残余药性 | 经脉压力下降、根基稳定、纯度修正或药性收束 | 不把残余修为药性转化为修为 |
| 突破准备 | 为大境界突破集中处理短板 | 资源、地点、护法、状态、纯度和根基准备 | 不等同于开启突破 |
| 显式托管 | 玩家主动设置低交互保守行动 | 低收益、低风险、减少离线损失 | 不主动发起高风险突破 |

### 5.2 主动吐纳

主动吐纳是修为推进的核心行动。玩家选择持续时间、地点、主修道功和兼容资源输入后，系统按实际兼容小时结算。

主动吐纳读取：

1. 当前境界与小阶段。
2. 当前主修道功和掌握度。
3. 所在节点灵气、设施、机会窗口和宗门支持。
4. 角色资质、伤势、心魔、经脉压力、根基质量和修为纯度语境。
5. 行动内选择的资源输入。

主动吐纳不应被设计成“立刻获得修为”的按钮。即使玩家使用丹药，资源也必须随主动吐纳实际执行小时释放。

### 5.3 自动运转

自动运转表示角色在多数非吐纳、非突破、非重伤状态下维持的低额修行。

规则：

1. 自动运转可以产生少量修为或稳定性收益。
2. 自动运转可以触发普通小境界升级。
3. 自动运转不能完成大境界突破。
4. 自动运转不应消耗玩家未显式选择的关键资源。
5. 自动运转结果应进入日志，但普通 UI 不需要展示完整数值公式。

自动运转的目的不是替代主动吐纳，而是让连续世界中角色不会因为没有显式闭关就完全停摆。

### 5.4 巩固根基

巩固根基用于处理日常修炼带来的副作用和突破前状态短板。

它可以用于：

1. 降低经脉压力。
2. 稳定根基质量。
3. 在突破准备语境中改善修为纯度或状态短板。
4. 选择性收束残余修为药性，减少散逸或压力风险。
5. 为后续主动吐纳或大境界突破创造更稳定条件。

巩固根基不能用于：

1. 把残余修为药性直接转化成修为进度。
2. 替代主动吐纳消化修为丹药。
3. 免费修复所有压力和伤势。
4. 绕过大境界突破准备条件。

当角色体内存在稳定残余药性时，巩固根基默认不自动消耗；界面必须让玩家明确选择“保留药性”或“收束药性”。刺激型或强制释放型药性应强提示风险，建议继续主动吐纳或巩固根基收束。

### 5.5 行动资源输入

行动资源输入是玩家在规划某个行动时选择额外投入一类资源。资源只在行动实际执行期间按兼容小时生效，并进入该行动的结算管线。

示例：

```text
行动：主动吐纳 2 天
额外输入：清灵丹 × 1

行动：研习《青木养真诀》1 天
额外输入：启悟丹 × 1

行动：探索毒瘴谷
额外输入：避瘴丹 × 1
```

行动资源输入不改变行动本身类型：

1. 主动吐纳仍然是主动吐纳。
2. 研习功法仍然是研习功法。
3. 探索、移动、治疗、突破事件选项仍然保留原语境。
4. 资源只是挂载输入，不成为默认独立行动入口。

### 5.6 修为丹药规则

修为类丹药只作为主动吐纳的额外资源输入。

合法：

```text
主动吐纳 24 小时，附加清灵丹 × 1。
```

非法：

```text
即时服用清灵丹，立即获得修为。
单独执行丹药炼化 12 小时。
移动途中服用清灵丹，持续获得修为。
```

主动吐纳中存在两条输入流：

| 输入流 | 玩法含义 |
| --- | --- |
| 环境灵气流 | 节点灵气、资源槽灵气、资源槽附属设施如修炼房 / 聚灵阵 / 灵液池维护设施等，受道功吸收速度和状态限制 |
| 修为丹药资源流 | 丹药释放定额灵气包，跳过道功吸收速度，但仍进入根骨转化与体魄承载压力 |

修为丹药不是提高节点灵气浓度、提高聚灵阵效果或简单提高最终倍率，而是在主动吐纳期间释放额外修为灵气输入。

### 5.7 残余效果

当行动时间短于资源完整有效时长、行动被事件打断，或资源只消耗了部分兼容小时，系统生成残余效果。

残余效果应表达：

1. 资源名称。
2. 剩余可生效小时。
3. 当前稳定性。
4. 后续可承接行动。
5. 散逸、反噬或经脉压力风险。

稳定残余示例：

```text
体内仍有未尽药性：清灵丹，约 6 小时。
执行主动吐纳可继续承接。
若长时间不处理，药性可能散逸。
```

刺激型残余示例：

```text
体内仍有烈性药性：赤焰速元丹，约 4 小时。
非修炼行动期间可能快速散逸并造成经脉压力。
建议：继续主动吐纳或巩固根基收束。
```

### 5.8 F1 与低交互消化

闭关修炼、主动吐纳、研习功法、巩固根基、疗伤和显式托管等长期低交互行动可以按规则进入 F1。

F1 的玩法意义：

1. 压缩现实等待。
2. 快速消化玩家已创造的高价值修炼条件。
3. 让低交互行动不阻塞多人房间体验。

F1 不改变数值单位。修炼、资源输入、残余效果、压力变化和小境界判定仍按世界小时与实际兼容小时结算。

洞天、时间阵法和宗门时间阵中的闭关必须额外声明：

```text
局部时间域配置；
预计主观年数；
资源可支撑年数；
资源不足年份处理；
预计寿元消耗；
功法研习与道功修炼时间拆分；
心魔 / 经脉 / 药性 / 阵法风险阈值；
出关、中断和无安全默认时的处理策略。
```

闭关承诺不消除事件。F1 中的闭关事件、低风险预设和摘要事件可自动写入结果摘要；重大心魔、突破契机、资源耗尽且无预设、洞天受袭、控制权变化、公共决策和高风险不可逆选择必须中断到 N1 / B1 / P0。

资源不足时，角色仍按所在时间域消耗寿元，但修为收益大幅降低，并提高心魔、经脉、枯坐和状态恶化风险。普通 UI 必须提示“资源不足，继续闭关会耗寿低效”。

## 6. 资源、角色、地图、事件或 NPC 接口

修炼玩法读取和写入以下系统口径：

| 接口 | 读取 | 写入或影响 |
| --- | --- | --- |
| 角色与境界 | 当前境界、小阶段、`cultivation_points`、瓶颈、突破准备语境 | 小境界进度、修为变化、瓶颈提示、突破准备提示 |
| 角色属性与持续状态 | 根骨、悟性、灵根、体魄、生机、元气、神念、伤势、心魔、经脉压力、根基质量、残余药性 | 经脉压力变化、残余效果、稳定性变化、日志和状态提示 |
| 功法 | 主修道功、掌握度、功法兼容、研习目标 | 主修道功经验、功法经验、可修上限提示 |
| 地图与设施 | 节点灵气、资源槽灵气、修炼房、聚灵阵、灵液池、洞府、宗门支持和机会窗口 | 资源消耗、设施占用、地点收益摘要 |
| 物品与资源 | 修为丹药、灵气类资源、启悟类资源、避险类资源、库存数量和资源有效时长 | 行动内资源消耗、残余效果、散逸或副作用结果 |
| 行动与房间流程 | 普通行动队列、N1 / F1 / B1 / P0 / C1、事件打断和托管策略 | 修炼行动结果包、个人日志、回放摘要、队列继续或中断 |
| 事件与 NPC | 护法、干扰、机缘、宗门任务、NPC 支持或阻碍 | 事件触发、机会窗口关闭、额外风险或奖励提示 |

本文只维护接口职责边界，不重复数值公式、倍率、物品配置表或 UI 组件布局。

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `cultivation_points` | 角色当前累计修为规模；数值映射和境界段表由数值文档维护 |
| `active_cultivation_action_id` | 当前正在执行的修炼相关行动引用 |
| `cultivation_action_type` | 修炼相关行动类型：主动吐纳、闭关、自动运转、研习功法、巩固根基、突破准备或托管 |
| `main_method_id` | 本次修炼读取的主修道功 |
| `training_location_id` | 本次修炼所在地图节点、设施或洞府引用 |
| `planned_duration_hours` | 玩家计划投入的世界小时数 |
| `planned_inner_years` | 局部时间域内预计经历的主观年数，可为空 |
| `resource_supported_inner_years` | 当前资源包、宗门护持、聚灵石、阵法燃料等可支撑的主观修炼年数 |
| `unsupported_inner_years` | 资源不足但仍会消耗寿元的主观年数 |
| `lifespan_time_domain_used` | 寿元扣除读取外界时间还是局部主观时间 |
| `compatible_elapsed_hours` | 当前行动已经满足资源兼容并完成结算的小时数 |
| `resource_inputs` | 玩家为行动显式绑定的资源输入列表 |
| `residual_effects` | 行动未完全消化时生成的残余药性、灵气或其他持续效果引用 |
| `meridian_pressure_delta` | 本次行动对经脉压力的变化摘要 |
| `foundation_quality_delta` | 本次行动对根基质量或稳定性的变化摘要 |
| `cultivation_tick_result` | 小时结算结果包引用；具体字段由修炼数值文档维护 |
| `can_enter_f1` | 当前修炼行动是否满足低交互加速候选条件 |
| `interruption_reason` | 行动中断原因：事件、战斗、资源结束、状态异常、房间节奏或手动取消 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通玩家 UI 应优先展示可决策信息：

1. 当前小阶段自身进度。
2. 本次行动预计收益区间。
3. 是否会消耗资源输入。
4. 是否产生残余药性。
5. 经脉压力、根基、伤势或心魔是否接近风险阈值。
6. 是否接近瓶颈或突破准备语境。
7. 巩固、疗伤、提纯或换地点等可执行修正路径。
8. 若涉及洞天 / 时间阵法，展示现实预计耗时、外界预计经过时间、洞天内预计修炼年数、预计寿元消耗、资源可支撑年数、资源不足年份、预计有效修炼年数和本次 F1 中断策略。

资源输入主入口放在具体行动界面内，采用行动内折叠项。玩家选择具体行动后，只显示与该行动兼容的资源输入。

主动吐纳界面示例：

```text
行动：主动吐纳
计划投入：12 小时
可用资源输入：
- 清灵丹：20 灵气 / 小时，最多 12 小时
- 木髓液：适配木系道功，释放稳定

当前选择：清灵丹 × 1
预计本次释放：12 / 12 小时
```

如果行动时间不足：

```text
行动：主动吐纳
计划投入：6 小时
当前选择：清灵丹 × 1
完整药性：12 小时
预计本次释放：6 / 12 小时
剩余：约 6 小时药性，将暂留体内
```

不采用默认全局资源栏作为主入口，避免资源栏变成背包搜索和倍率堆叠界面。已有残余效果仍应在角色面板或行动规划器中常驻提示。

Debug / QA 信息不进入普通 UI，例如完整公式追踪、原始效率倍率、裁剪前后倍率、境界段内部 ID、完整随机权重和后台状态枚举。

## 9. MVP 范围

MVP 应实现：

1. 主动吐纳、闭关修炼、自动运转、研习功法、巩固根基和显式托管的基础行动语义。
2. 主动吐纳读取地点、主修道功、角色状态和玩家显式资源输入，并按实际兼容小时结算。
3. 修为类丹药作为主动吐纳资源输入，不提供即时服用或独立丹药炼化行动。
4. 行动中断或资源未完全释放时生成残余效果，并提示后续可承接行动和风险。
5. 闭关、吐纳、研习、巩固、疗伤和托管按房间规则进入 F1 候选。
6. 普通 UI 展示进度、预计收益区间、资源消耗、残余效果、风险阈值和可修正路径。
7. 洞天 / 时间阵法闭关的资源年、寿元、风险和中断策略摘要。

MVP 不实现：

1. 复杂多资源自动配比、背包全局资源搜索或自动最优修炼方案。
2. 玩家未显式选择时自动消耗关键丹药、符箓、灵石或稀有材料。
3. 残余药性被巩固根基直接转化为修为进度。
4. 自动运转完成大境界突破。
5. 完整高阶修炼事件链、长期宗门护法协作和复杂 C1 重算 UI。

## 10. 验收约束

1. 任意修为类丹药都不能绕过主动吐纳直接提供修为进度。
2. 修炼资源只在行动实际执行期间按兼容小时释放；行动中断时必须保留已消耗、未消耗和残余效果边界。
3. 主动吐纳、研习功法和巩固根基的收益类型必须区分，不能互相替代。
4. 自动运转可以推进普通小境界，但不得完成大境界突破。
5. 巩固根基不能免费清除所有压力、伤势或风险，也不能把残余修为药性直接转为修为。
6. F1 只压缩低交互等待；内部可批量结算，但不得跳过资源、寿元、压力、事件和结果包。
7. 洞天内主观时间不足资源支撑时，必须耗寿低效并提高风险，不能继续高效修炼。
8. 普通 UI 必须展示玩家做决策所需的收益、消耗、残余和风险信息，不展示 Debug / QA 公式追踪。
9. 所有字段和接口建议必须保持系统设计、数值设计和交互设计分工，不把公式表或 UI 节点坐标写回本文。
