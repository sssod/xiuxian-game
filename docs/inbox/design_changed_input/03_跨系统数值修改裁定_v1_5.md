# 数值设计｜跨系统修改裁定与同步清单 v1.5

适用范围：本文件是从 `数值建模核心修订稿_f_1_术语修正版_canvas草稿_建模版本.md` 拆分出的跨系统修改裁定稿，用于列出基于当前 `docs/xiuxian_design_docs` 正式设计文档包的数值设计修改、系统承接范围和待裁决项。

本文不直接修改正式包。若用户确认采用，应按正式包主题边界把裁定拆入对应文档。

## 1. 当前定位

本文负责把 v1.5 数值建模对其它系统的影响整理成可执行的设计裁定清单，避免把标准数值方案、数学公式和系统同步要求混在同一正文中。

标准数值方案见《修为时间、F1 与洞天局部时间标准数值方案 v1.5》（`01_标准数值方案_v1_5.md`）；公式、变量和 HTML 调参器关联见《数学模型与 HTML 调参器关联 v1.5》（`02_数学模型与HTML调参器关联_v1_5.md`）。

## 2. 总裁定

| 编号 | 裁定 | 影响范围 |
| --- | --- | --- |
| `D01` | 保留玩家可见 F1，不新增独立宏观流年阶段 | 流程、行动指令、修炼、事件、UI |
| `D02` | F1 内部改为批量结算、事件流采样和安全断点，不逐小时全量 tick | 行动、事件、NPC、世界资源、性能验算 |
| `D03` | 理论直线现实参考为 32 小时；N1 / F1 / B1 占比为 66% / 22% / 12% | 数值设计、UI 预估、验算 |
| `D04` | F1 基准速度为 1.5 秒 = 1 外界日；理论直线外界日历约 45-48 年，当前基线约 47.55 年 | 期望时间、洞天开放、阶段预算、世界演化 |
| `D05` | 四层时间模型必须区分现实时间、N1/B1 现场外界时间、F1 外界流年时间和角色主观时间 | 修炼、寿元、事件、UI、结果包 |
| `D06` | 寿元按角色所在时间域扣除；洞天内按主观时间，洞天外按共享外界日历 | 角色状态、修炼、洞天、事件 |
| `D07` | 阶段预算、市场、宗门库存、节点资源和 NPC 宏观成长按外界时间刷新，不按洞天内主观时间刷新 | 投放、宗门、地图、NPC、经济 |
| `D08` | 洞天 / 时间阵法必须消耗资源年，不提供免费完整收益 | 洞天、资源、修炼公式、UI |
| `D09` | 修行成长时间按时间域分配，不再用单一生涯总时间比例切分 | 修炼公式、功法研习、资源投放、UI |
| `D10` | 闭关承诺不吞掉事件；预设只决定事件触发后的处理方式 | 随机事件、托管、F1、UI |
| `D11` | 高风险突破、主动转世、叛宗、强 PvP、稀有不可逆资源消耗等不得被普通预设自动处理 | 事件、突破、战斗、宗门、后手 |
| `D12` | 轮回重修不保证缩短完整通关总时长 | 轮回、投放、结局、UI |

## 3. 正式包文档同步清单

### 3.1 `03_数值设计/01_修为境界与期望游玩时间建模.md`

需要同步的裁定：

1. 将 F1 基准速度从旧口径 `2 秒 = 1 游戏日` 更新为 v1.5 基线 `1.5 秒 = 1 外界日`，并保留是否采用 1 / 1.5 / 2 秒的待裁决记录。
2. 明确理论直线现实参考时长为 32 小时，不等于实际单局总时长。
3. 明确理论直线终点为“大乘圆满 -> 突破进入渡劫期”，渡劫后劫数和飞升不纳入本文时间段。
4. 把外界世界日历目标调整为约 45-48 年，验收范围 20-50 年，当前基线约 47.55 年。
5. 补充四层时间模型，避免把外界年、洞天主观年和角色生涯年混用。
6. 补充阶段预算按外界时间刷新，不按洞天内主观时间刷新的约束。
7. 补充轮回不保证总通关时间缩短的口径。

不应写入该文档的内容：

```text
BatchSettlementKernel 具体字段；
EventStream 完整结构；
HTML 调参器按钮和本地存储；
运行时模块名的实现细节。
```

### 3.2 `03_数值设计/02_修炼公式与数值设计.md`

需要同步的裁定：

1. F1 仍压缩现实等待，但 v1.5 进一步要求 F1 内部不逐小时全量 tick。修炼公式需要支持聚合结算、阈值断点和局部展开。
2. 修炼收益不再默认按完整生涯时间切分，应读取分域时间：局部时间域主观年、洞天外 F1 普通修炼年、N1/B1 现场交互时间。
3. 局部时间域主观时间默认 70% 用于修行成长、30% 用于支持行为；修行成长中功法研习 : 道功修炼默认 20% : 80%。
4. 洞天外 F1 外界流年中只有 10%-20% 建议作为普通修炼 / 低阶修炼，其余主要是世界资源等待、生产、长期游历和宗门职责。
5. 有效修炼年应受 `planned_inner_years`、资源年、功法支持、寿元安全、心神稳定共同限制。
6. 资源不足年份只能获得低效收益，建议 0%-20% 基础收益上限，并提高心魔、经脉和枯坐风险。
7. 结果包需要输出局部时间域拆分、洞天外 F1 拆分、有效修炼年、资源不足年和寿元时间域来源。

需要避免的误写：

```text
不要把 base_cultivation_yield 写成正式修炼收益公式；
不要把 HTML 的单一 inner_years_per_outer_day 调试值写成全局正式倍率；
不要让洞天主观年驱动世界阶段预算刷新。
```

### 3.3 `03_数值设计/06_事件设计基准建模.md`

需要同步的裁定：

1. 新增 EventStream / 危险率采样作为 F1 批量结算中的事件触发模型。
2. 事件可以按外界日历、局部主观年、预定日历、阈值 crossing time 或条件区间触发。
3. 事件等级需要覆盖 `silent`、`summary`、`auto`、`soft_interrupt`、`hard_interrupt`。
4. `max_triggers_per_batch`、冷却、可见性和默认处理策略需要作为事件调参项。
5. 非逐小时掷骰模型应保留采样随机种子、事件流引用、断点和结果摘要，保证可复盘。

### 3.4 `03_数值设计/07_投放数值设计.md`

需要同步的裁定：

1. 阶段预算、资源成熟、市场、宗门库存和大型投放窗口按外界世界日历推进。
2. 洞天内主观数百年不生成数百年外界投放。
3. 轮回后若世界资源不足，允许增加世界资源积累等待和大型投放事件等待。
4. 洞天外 F1 的非修行流年主要承载资源积累、大型窗口等待、长耗时生产、长期游历和宗门职责。

### 3.5 `03_数值设计/08_数值验算.md`

需要新增验算用例：

```text
Case K：F1 可见速度调整为 1.5 秒 = 1 外界日，但内部不执行 24 个全量 hour_tick。
Case L：所有玩家都进入洞天修炼时，房间能稳定进入 F1，并推进到最近出关 / 事件 / 资源耗尽断点。
Case M：闭关期间心魔、资源耗尽、洞天异动等事件能通过 EventStream 触发，而不是被玩家承诺吞掉。
Case N：可自动处理事件写入摘要并继续 F1；无预设重大事件退出 F1。
Case O：资源不足年份导致耗寿低效，而不是继续高效修炼。
Case P：洞天修炼仍强需求修为丹药、聚灵阵、聚灵石、洞天灵气池、宗门护持和功法适配。
Case Q：非相关 NPC 和远端节点不逐小时全量刷新，改为惰性结算或宏观周期结算。
Case R：F1 批量结算结果可复盘，包括采样随机种子、事件流、断点和聚合收益。
Case S：596 年局部时间域主观经历按 70% 修行成长、其中 20% 研习 / 80% 道功修炼拆分后，是否能支撑功法系统与修为推进的目标节奏。
Case T：轮回重修在资源不足与大型投放事件等待存在时，是否允许总通关时间长于单世通关，同时提高成功率与结局质量。
```

### 3.6 `02_系统设计/01_流程设计/01_单人游戏与多人共玩流程.md`

需要同步的裁定：

1. 公开速度状态只保留 N1 / F1 / B1 / P0。
2. F1 的房间语义改为“所有玩家处于长期低交互可批量结算状态”。
3. 不新增独立宏观流年阶段或复杂宏观承诺协议。
4. 多人全员洞天修炼时自然进入 F1；不同玩家可处于不同局部时间域，房间推进到最近断点。
5. F1 批次到达中断事件、公共决策、交锋、资源耗尽或行动完成时，按优先级切回 N1 / B1 / P0。

### 3.7 `02_系统设计/09_行动指令设计.md`

需要同步的裁定：

1. `f1_eligible_states` 应明确包括洞天 / 时间阵法闭关、普通长期闭关、长期修炼、安全长距离移动、显式托管、低风险宗门职责、休整 / 疗伤、资源采集 / 加工等低交互长行动。
2. 自动兜底仍不得作为进入 F1 的依据；显式托管可在安全条件下参与 F1。
3. 长期行动必须提供结束条件、中断策略、资源绑定和安全默认，否则不能进入 F1。
4. 普通队列编辑、关键队列编辑、无安全默认事件和玩家间冲突应降速或阻止 F1。
5. 行动完成点不必强制降速；若下一条行动合法且全员仍低交互，F1 可继续。
6. 结果包和日志需要记录 F1 批量断点、被自动处理事件和中断原因。

### 3.8 `02_系统设计/11_修炼玩法设计.md`

需要同步的裁定：

1. 闭关、主动吐纳、研习功法、巩固根基、疗伤和显式托管等长期低交互行动可由 F1 消化，但必须声明资源、状态、风险和中断策略。
2. 洞天闭关不是免费收益。玩家必须绑定资源包、丹药、聚灵石、洞天灵气池、宗门护持、阵法燃料或其它可追踪支撑。
3. 资源不足时仍消耗寿元，但修为收益大幅降低，并提高心魔 / 经脉 / 枯坐风险。
4. 功法研习与道功修炼时间拆分应写入修炼结果和功法系统接口。
5. F1 中的闭关事件和低风险预设可自动摘要；重大心魔、突破契机、资源耗尽无预设、洞天受袭等必须中断。

### 3.9 `02_系统设计/08_人造设施与洞天福地设计/02_洞天福地.md`

需要同步的裁定：

1. 洞天福地除了作为 `blessed_land` 资源槽，还需要在数值层承接 `LocalTimeDomainProfile` 或等价时间域配置。
2. 洞天分级可采用 T0-T5 口径，但正式文档仍需补类型、品级、倍率、进入上限、维护成本和风险表。
3. 洞天需要维护 `resource_year_capacity_multiplier`、`lifespan_pressure_modifier`、心魔风险、经脉压力、燃料成本和外界维护成本。
4. 洞天内主观时间不驱动外界资源预算刷新。
5. 洞天控制权、入口、席位、污染、受袭和争夺属于 F1 硬中断或软中断来源。

### 3.10 `02_系统设计/15_随机事件玩法设计.md`

需要同步的裁定：

1. 当前事件时间模式仍保留，但需要补 F1 批量结算中的 EventStream 触发方式。
2. `info` / 普通个人事件 / B1 / P0 的现有边界应与 `summary` / `auto` / `soft_interrupt` / `hard_interrupt` 对齐。
3. 显式托管只可保守处理低价值事件；F1 预设同样不得处理高风险不可逆事件。
4. 事件模板应声明适用时间域：外界日历、局部主观年、阈值、预定时间或条件区间。
5. F1 中可自动处理事件仍需要结果包、摘要和回放；不能由事件文本直接改写世界状态。

### 3.11 `02_系统设计/14_突破玩法设计.md`

需要同步的裁定：

1. 大境界突破和高风险突破契机不能被普通预设自动处理。
2. 突破契机在 F1 中触发时，默认应软中断或硬中断，按玩家预设“提醒 / 不自动突破 / 出关处理”执行。
3. 若玩家已明确设置“不自动突破”，F1 可只记录突破契机摘要或提示；若设置“满足条件提醒”，应中断到 N1 / B1 / P0。
4. 突破挑战仍进入 B1，突破轮内选择不进入普通队列或 F1 自动处理。

### 3.12 `02_系统设计/16_NPC设计.md`

需要同步的裁定：

1. F1 中非相关 NPC 不逐小时全量刷新，应改为惰性结算、宏观周期结算或被观察时补结算。
2. NPC 宏观成长、宗门职务变化、市场和世界资源事件读取外界日历，不读取玩家洞天主观年。
3. 与玩家当前 F1 批次相关的 NPC、护法、敌对者、宗门事件和洞天争夺应进入活跃相关对象集合。

### 3.13 `02_系统设计/17_宗门系统设计.md`

需要同步的裁定：

1. 宗门库存、宗门职责、洞天席位、宗门时间阵、宗门会议和资源审批读取外界日历。
2. 低风险宗门职责可作为 F1 eligible state；宗门重大事件、公共决策、席位争夺和资源归属冲突应中断 F1。
3. 宗门护持可以作为洞天资源年与风险缓冲来源，但应有库存、权限、职位或贡献成本。

### 3.14 `04_交互设计/04_修为页面设计.md`

需要同步的裁定：

普通 UI 必须展示：

```text
现实预计耗时；
外界预计经过时间；
洞天内预计修炼年数；
预计寿元消耗；
资源可支撑年数；
资源不足年份；
预计有效修炼年数；
心魔 / 经脉 / 药性 / 阵法风险；
出洞后可能触发的外界事件；
下次洞天开放时间；
本次 F1 中断策略。
```

UI 不应承诺“轮回后一定更快”。建议表达为：

```text
轮回将提高路线确定性、先天适配和成功率；
但若关键资源尚未成熟，下一世可能需要等待世界资源积累或大型机缘窗口。
```

### 3.15 `04_交互设计/06_指令管理页面设计.md`

需要同步的裁定：

1. 行动规划界面需要展示长期行动是否具备 F1 条件。
2. 洞天闭关行动必须提示资源绑定、结束条件、中断策略和无安全默认时不能进入 F1。
3. F1 摘要需要区分自动处理事件、摘要事件、软中断事件、硬中断事件和批量断点。
4. 队列为空、自动兜底、关键编辑和无安全默认事件应明确导致 N1 或阻止 F1。

## 5. 合并优先级建议
