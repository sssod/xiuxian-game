# 系统设计｜资源槽详细设定

## 1. 设计定位

资源槽是地图节点上的广义世界条件承载位。它不只代表可采集资源，也代表灵气节点、可建设地脉、矿脉、药谷、灵泉、妖兽巢穴、稳定空间、洞天福地、秘境入口条件和其他可被争夺、利用或建设依附的世界条件。

本文负责维护资源槽字段、资源槽类型、自然生成、人工扩展、再生、可见性、资源槽与设施 / 洞府 / 藏宝的接口。设施自身的建设、维护、升级和改造细则由《资源槽附属设施通用规则》（`../08_人造设施与洞天福地设计/03_资源槽附属设施通用规则.md`）维护。

## 2. 当前结论

1. 资源槽挂载在地图节点或节点隐藏层中，不是独立漂浮物。
2. MVP 资源槽类型只保留少量大类；具体用途由 `slot_usage_tags`、`buildable_facility_classes`、附属设施类别和模板表达。
3. 节点等级影响自然资源槽基线数量、资源品级范围、单槽规模、灵气浓度和默认风险区间。
4. MVP 不设置节点级资源槽总数量硬上限；只限制单槽规模、设施类别、维护成本和结算产能。
5. 常规人工扩展只能新增普通 `aura_node`，不能制造矿脉、灵泉、洞天福地、秘境窗口、隐藏层特殊入口或带剧情来源的特殊资源。

## 4. 核心循环或触发入口

资源槽由节点模板、区域、节点等级、控制权、历史演化、特殊事件、隐藏层、宗门建设或人工扩展生成。资源槽变化必须按 `world_hour` 或明确的 `macro_period_id` 记录来源、可见性、结果包和回放。

资源槽常态循环：

```text
节点小时推进
→ 资源槽再生、枯竭、污染、异变或机会窗口检查
→ 附属设施维护与产能检查
→ 控制权、争夺状态和可见性更新
→ 输出 resource_slot_delta / facility_delta / rumor_entries / ledger_entries
```

## 5. 规则与状态

`NodeResourceSlot` 代表节点上的广义资源承载位。

```yaml
NodeResourceSlot:
  slot_id: string
  node_id: string
  resource_type: aura_node | material_deposit | ecology_site | space_site | blessed_land | opportunity_site | special
  resource_template_id: string
  slot_origin: natural | artificial_regular | event_created | hidden_layer | legacy
  slot_scale: int
  generated_by_node_level: int
  resource_grade: string
  resource_grade_range: string
  aura_density: number
  aura_density_policy: above_node_average | near_node_average | below_node_average | none
  slot_usage_tags: list[string]
  current_amount: number
  max_amount: number
  regen_per_world_hour: number
  buildable_facility_classes: list[string]
  attached_facility_class: string | null
  attached_facility_ref: string | null
  blocking_site_refs: list[string]
  facility_scale: int
  facility_level: int
  facility_scale_cap: int
  transformability: free_build | limited_build | preserve_only | no_build
  special_property_tags: list[string]
  visibility_policy: private_player | known_to_party | sect_visible | rumor_visible | public_world | hidden_world | debug_only
  depletion_event_refs: list[string]
  contest_state: object
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `resource_type` | 资源槽大类，只表达世界条件类别，不把灵田、市场、传送阵、行政地块拆成独立槽类型 |
| `slot_origin` | 资源槽来源；人工常规扩展使用 `artificial_regular`，事件生成和隐藏层来源必须另记 |
| `slot_scale` | 资源槽自身规模，影响资源量、建设承载、设施规模和维护成本 |
| `resource_grade_range` | 资源品级可波动范围，受节点等级、模板和事件影响 |
| `aura_density_policy` | 资源槽灵气相对节点平均浓度的策略 |
| `buildable_facility_classes` | 该资源槽模板允许建设或挂载的设施类别 |
| `attached_facility_class` / `attached_facility_ref` | 当前附属设施类别和实例引用；详细规则见设施文档 |
| `blocking_site_refs` | 洞府、藏宝、遗留设施等阻塞该槽继续建设或改造的引用 |
| `facility_scale_cap` | 该槽可承载设施的规模硬上限 |
| `transformability` | 常规建设、受限建设、保全或禁止建设的改造口径 |
| `visibility_policy` | 资源槽摘要、传闻或真实状态的可见性 |
| `contest_state` | 资源槽被争夺、封锁、占用或争议时的状态记录 |

资源槽通用规则：

1. 资源采集、争夺、消耗、枯竭和刷新都按 `world_hour` 记录。
2. 自然资源点先产出资源池或资源量，再通过采集、加工、炼制、修复等行动转为物品、材料或宗门资源。
3. 已控制资源节点的基础产出属于常态结算，不占用宗门唯一持续行动槽。
4. 稀有资源、秘境资源、藏宝资源和后手封存资产必须有来源、预算或资产容器记录，不能作为无约束随机奖励。
5. 枯竭、再生、污染、异变按节点模板配置，不使用统一生态公式。
6. 资源槽的自然生成基线数量、资源品级和 `resource_grade_range` 受节点等级影响；同类节点也可以因区域、污染、秘境窗口或历史事件产生差异。
7. 资源再生可按 `world_hour` 连续累计，也可按 `macro_period_id` 批量刷新；无论哪种方式，都必须保留可追溯的世界时间、来源和可见性记录。
8. `slot_scale` 表示资源槽自身规模；`facility_scale_cap` 表示该槽可承载设施的规模硬上限。节点等级、资源品级、地形、控制权和特殊事件可以修正单槽规模与设施上限，但 MVP 不设置节点级资源槽总数量上限。

## 6. 简化资源槽类型

MVP 简化资源槽类型：

| `resource_type` | 覆盖内容 | 常见设施或操作 |
| --- | --- | --- |
| `aura_node` | 灵气节点、灵脉支点、可常规开发地脉、人工扩展的常规资源槽 | 修炼房、静室、聚灵阵、灵田、药园、传送阵、渡口、坊市、店铺、行政建筑、阵法、防护、普通加工 |
| `material_deposit` | 矿脉、药谷、灵泉、灵液池、可采集灵材点等明确物质产出 | 采矿场、灵泉维护、灵液收集、采集前置、炼矿前置 |
| `ecology_site` | 妖兽巢穴、灵植群落、特殊生态位 | 狩猎营地、驯养栏、看守点、生态保全、风险事件入口 |
| `space_site` | 洞府空间、稳定空间、仓储空间、隐藏空间入口、可建空间 | 洞府、仓储、防护、隐蔽、休整、入口维护 |
| `blessed_land` | 洞天福地、特殊高价值空间或特殊灵气场 | 保全、封禁、参悟、突破场地、受限入口维护 |
| `opportunity_site` | 秘境窗口、资源名额、短期入口、临时争夺条件 | 入口维护、探索准备、临时封锁、争夺事件 |
| `special` | 无法归入上列的定制资源槽 | 按模板声明用途、建设限制和结算来源 |

`aura_node` 是通用可建设灵气承载位，不只服务修炼房，也可以按模板支持灵田 / 药园、传送阵、渡口、坊市 / 店铺 / 摊位、宗门行政、阵法、防护和普通加工等设施类别。

洞天福地在 MVP 阶段按 `blessed_land` 或等价不易改造资源槽处理，通常是 `limited_build`、`preserve_only` 或 `no_build`，不是可随意改造的一般建筑地块，也不是常规人工扩展可制造的资源槽。

## 7. 人工扩展资源槽

人工扩展资源槽规则：

1. MVP 只支持常规人工扩展，新增资源槽的 `resource_type` 固定为 `aura_node`，`slot_origin` 记为 `artificial_regular`。
2. 常规人工扩展不能凭空制造矿脉、灵泉、妖兽生态、洞天福地、秘境窗口、隐藏层特殊入口或带剧情来源的特殊资源。
3. 常规人工扩展后的资源槽没有特殊属性，`special_property_tags` 必须为空；如后续事件赋予特殊属性，必须改记为事件来源并写入结果包。
4. 常规人工扩展后的 `aura_density_policy` 必须为 `below_node_average`，其灵气浓度低于当前地图节点平均灵气浓度，不能用人工扩展绕过节点灵气稀缺性。
5. 人工扩展时可以设定 `slot_scale`；规模由建设行动、资源投入、地形、权限和模板约束决定。规模影响可承载设施规模和产能，但不附带特殊相性、特殊产出或稀有变体。
6. 常规人工扩展后的 `aura_node` 可以按模板承载灵田、修炼设施、传送阵、市场、行政等常规设施类别；仍遵守同槽只承载一类设施。

## 8. 资源槽与洞府、藏宝、后手

个人洞府和普通藏宝允许附着在模板允许的自然资源槽上，也允许附着在节点隐藏层上。真灵藏宝只能附着在节点隐藏层上，不能附着在资源槽上，包括洞天福地 / `blessed_land` 及其子资源槽。

资源槽落点规则：

1. 个人洞府或普通藏宝附着在自然资源槽时，会读取该槽的灵气浓度、相性、稳定度、污染和空间条件作为收益或风险来源；同时因为占用明确世界条件，隐蔽程度应低于同等投入的隐藏层藏宝或隐藏层洞府。
2. 个人洞府或普通藏宝不能设置在已有附属设施的自然资源槽上。
3. 设置后该资源槽视为被 `personal_cave` 或 `treasure_cache` 类设施化占用，后续建造、扩建或改造其他设施必须失败，直到清理、迁移、拆除或事件处理该个人洞府 / 藏宝。
4. 真灵藏宝没有资源槽灵气需求，也不承担因资源槽占用带来的普通暴露风险；其可见性、感应和开启只由正式后手、真灵解锁条件和隐藏层记录决定。

## 9. 资源、角色、地图、事件或 NPC 接口

| 接口 | 资源槽输出或读取 |
| --- | --- |
| 地图节点 | 读取节点等级、灵气、风险、控制权和隐藏层；输出资源槽变化 |
| 经济系统 | 读取资源池、资源量、附属设施状态、产出和库存流向 |
| 设施系统 | 读取 `buildable_facility_classes`、`facility_scale_cap`、`transformability` 和当前占用 |
| 修炼 / 突破 | 读取灵气浓度、相性、稳定度、污染、洞天福地和受限设施修正 |
| 事件系统 | 读取枯竭、污染、异变、争夺、隐藏层和机会窗口条件 |
| 宗门系统 | 读取控制权、影响力、建设权、产出权、清点权和资源槽争夺状态 |
| 洞府 / 藏宝 | 读取自然资源槽或隐藏层落点，写入设施占用或隐藏层记录 |

## 11. UI 展示边界

普通地图 UI 可展示资源槽摘要、可见资源类型、风险提示、控制权、是否可建设、是否被占用、资源槽状态和传闻。普通 UI 不显示 `hidden_world` 与 `debug_only` 内容，不显示未公开后手归属、隐藏层真实结构、其他玩家私人事件来源或未公开资源预算。

## 12. MVP 范围

MVP 应实现：

1. `NodeResourceSlot` 的主要字段。
2. 七类简化资源槽。
3. 节点等级影响自然资源槽基线、品级范围、灵气和风险区间。
4. 常规人工扩展新增普通 `aura_node`。
5. 资源槽再生、消耗、枯竭、争夺、可见性和结果包记录。
6. 个人洞府、普通藏宝和真灵藏宝的资源槽 / 隐藏层落点边界。

MVP 不实现：

1. 节点级资源槽总数量硬上限。
2. 人工扩展制造特殊资源槽。
3. 无来源稀有资源奖励。
4. 把真灵藏宝记录为资源槽占用。

## 13. 验收约束

1. 节点资源槽能按节点等级生成自然槽基线、品级范围、灵气影响、刷新、消耗、枯竭、争夺和传闻。
2. 人工常规扩展能新增 `aura_node` 资源槽，记录规模、低于节点平均的灵气浓度和空特殊属性，且 MVP 不校验节点资源槽总数量上限。
3. 资源槽附属设施必须读取资源槽的可建设类别、单槽规模上限和占用状态。
4. 个人洞府和普通藏宝附着自然资源槽时能阻止该槽建设其他设施；附着隐藏层时不读取资源槽灵气收益。
5. 真灵藏宝只能落在节点隐藏层，不能记录为资源槽占用；洞天福地 / `blessed_land` 是资源槽，不能作为正式后手封存点。
6. 资源槽变化进入结果包和回放。

## 15. 冲突裁决与废弃口径

| 旧口径或冲突点 | 当前采用口径 | 裁决原因 |
| --- | --- | --- |
| `building_slots` | 不采用独立建筑槽；使用广义 `resource_slots` + 附属 `facility_refs` | 资源槽决定可利用世界条件和规模上限，设施是资源槽上的建设或运营形态 |
| 资源槽只代表可采集产出点 | 资源槽泛化为灵气、空间、生态、矿脉、灵泉、洞天福地等世界条件 | 设施建设、修炼环境和资源产出需要同一套来源与规模约束 |
| 为灵田、市场、传送阵、行政地块分别设置资源槽类型 | 简化为 `aura_node` 等少量资源槽大类，具体用途由用途标签和可建设施类别表达 | 避免类型爆炸；灵气节点作为通用可建设承载位，可支持灵田、传送阵、市场和行政设施 |
| 地图节点存在资源槽总数量硬上限 | MVP 不设置节点级资源槽总数量上限；只限制单槽规模、设施类别、维护成本和结算产能 | 当前阶段先跑通常规扩展和设施挂载，不把总量上限作为阻断条件 |
| 人工扩展可制造特殊资源槽 | MVP 人工扩展只生成常规 `aura_node`，无特殊属性，灵气浓度低于节点平均浓度，规模可设定 | 防止人工扩展绕过自然资源、洞天福地、秘境窗口和特殊事件来源 |
| 个人洞府、普通藏宝、真灵藏宝都可以任意附着资源槽 | 个人洞府和普通藏宝可附着模板允许的自然资源槽或节点隐藏层；真灵藏宝只能附着节点隐藏层，不能把洞天福地 / `blessed_land` 或洞天内部子资源槽作为封存点 | 普通洞府 / 藏宝需要从资源槽获得灵气等收益并承担暴露代价；真灵藏宝没有灵气需求和普通暴露风险 |
| 个人洞府或普通藏宝不影响资源槽建设 | 附着自然资源槽后视为 `personal_cave` / `treasure_cache` 类设施化占用，其他设施建设必须失败，直到清理、迁移、拆除或事件处理 | 洞府 / 藏宝占用了可建设世界条件，不能与灵田、市场、传送阵、修炼房等设施无成本叠加 |
