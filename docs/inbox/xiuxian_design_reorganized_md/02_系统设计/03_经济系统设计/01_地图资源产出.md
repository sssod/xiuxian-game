# 系统设计｜地图资源产出

## 1. 设计定位

地图资源产出负责回答地图节点、广义资源槽、资源槽附属设施、控制权、宗门持续行动和世界小时结算如何形成可入库资源。

本文只维护地图资源如何进入经济结算、库存流转和资源池管理，不维护资源槽自身定义、资源槽附属设施通用规则、物品对象定义、币制规则、完整产能公式或页面布局。资源槽通用字段、简化类型和人工扩展规则，以《资源槽详细设定》（`../07_地图节点设计/02_资源槽详细设定.md`）为准；一槽一设施类别约束，以《资源槽附属设施通用规则》（`../08_人造设施与洞天福地设计/03_资源槽附属设施通用规则.md`）为准；灵石、低阶货币与聚灵石的对象定义、加工和消耗接口，以《灵石及聚灵石》（`../05_物品设计/05_灵石及聚灵石.md`）为准。

## 2. 当前结论

1. 节点是地图资源产出的主单位；资源不是独立漂浮物，而是挂载在地理节点上的资源槽。
2. 已控制资源节点的基础产出不占宗门持续行动；开采、建设、探索、远征等持续行动只处理额外介入或一次性结果。
3. 产出优先进入宗门抽象库存或节点库存；需要具体物品形态时，再由物品系统转换为 `ItemStack` 或 `ItemInstance`。
4. 常规人工扩展资源槽只新增普通 `aura_node` 承载位，不自带特殊资源、高于节点平均的灵气收益或稀有资源预算。
5. 阶段预算打开资源机会和世界投放渠道，不自动赠送修为或无来源资产。

## 4. 核心循环或触发入口

地图资源产出的常态循环：

```text
节点拥有资源槽
→ 节点等级决定自然资源槽基线、资源品级范围和节点灵气基础
→ 宗门或势力控制节点 / 资源槽附属设施正常运转
→ 按世界小时推进并在宏观周期摘要中汇总产出
→ 写入 sect_storage / node_storage
→ 写入库存日志
```

主要触发入口：

1. 世界小时推进：已控制资源节点和正常运转的附属设施按周期形成常态产出。
2. 宗门持续行动：开采、资源介入、探索、建设、远征等行动产生额外资源结果或改变资源槽状态。
3. 节点建设结果：建设或扩展资源槽后，新增可承载设施的普通 `aura_node`。
4. 事件或灾害结算：资源丰度、再生、污染、敌对干扰或机会窗口被事件改变。
5. 阶段预算激活：玩家首次突破到某大境界后，世界激活对应阶段预算，预算进入节点资源槽、宗门库存、市场交易、机会窗口、NPC 个人资产或事件投放。

## 5. 规则与状态

### 5.1 常态产出

1. 已控制资源节点的基础产出不占宗门持续行动。
2. 资源槽的自然生成基线、资源品级、可波动范围和稀有变体概率受节点等级影响；节点等级也影响灵气浓度、灵气品质、污染、稳定度和相性权重。
3. 产出受控制权、影响力、资源丰度、资源槽规模、资源槽附属设施状态、设施规模、设施等级、灾害、敌对干扰和人力占用影响。
4. 每个资源槽和附属设施都应记录自身规模或规模上限；MVP 暂时不限制单个地图节点的资源槽总数量。
5. 产出优先进入宗门抽象库存或节点库存；若产出需要具体物品形态，再交由物品系统转换为 `ItemStack` 或 `ItemInstance`。

### 5.2 资源槽类型的产出口径

MVP 使用《资源槽详细设定》（`../07_地图节点设计/02_资源槽详细设定.md`）中的简化资源槽类型。经济系统按下表理解产出来源，不在本文维护第二套资源槽类型表。

| 资源槽类型 | 经济产出口径 |
| --- | --- |
| `aura_node` | 自然灵气节点可提供修炼环境、常规设施承载和低到中强度资源生产条件；人工常规扩展的 `aura_node` 只提供普通设施承载，不自带稀有产出 |
| `material_deposit` | 先形成资源池或资源量，再通过采集、开采、维护、炼制或加工转为库存资产 |
| `ecology_site` | 通过狩猎、采集、保全、驯养或事件结算形成材料、风险事件或驯养机会 |
| `space_site` | 通常不自动产出资源，主要提供洞府、仓储、防护、隐蔽、休整或隐藏入口能力；若有产出，必须来自附属设施或事件 |
| `blessed_land` | 可提供修炼、突破、参悟或稀有资源机会，但必须有明确来源、窗口、争夺状态或预算记录，不作为常规可复制产能 |
| `opportunity_site` | 多数是限时入口、资源名额或争夺条件；产出来自机会窗口结果，不进入常态小时产出 |
| `special` | 按模板声明产出来源、预算、可见性和入库规则 |

`aura_node` 可以承载灵田、修炼设施、传送阵、市场、行政建筑等常规设施。经济系统只关心该槽当前附属设施类别、规模、维护、人力和库存流向，不把灵田、市场、传送阵再拆成新的资源槽类型。

### 5.3 人工扩展与占用

1. 建设或扩展资源槽属于持续行动或节点建设结果之一。
2. MVP 只允许常规人工扩展；扩展完成后新增的是普通 `aura_node` 资源槽。
3. 常规人工扩展资源槽本身不产生特殊资源。它只能作为普通 `aura_node` 承载常规设施，且灵气浓度低于当前地图节点平均浓度。
4. 经济收益必须来自附属设施、投入资源、人力维护或后续事件，而不是来自扩展槽自带特殊属性。
5. 个人洞府或普通藏宝附着自然资源槽时，该槽被设施化占用，不能同时作为灵田、矿场、市场、传送阵或其他生产 / 公共设施产出来源。
6. 恢复常态产出或改建前，必须先清理、迁移、拆除或事件处理洞府 / 藏宝。

### 5.4 宗门持续行动产出

每个宗门同一时间最多拥有一个 active `SectContinuousActionState`。开采 / 资源介入、探索、建设、远征等持续行动都可能产生资源结果，但不应替代已控资源节点的常态产出。

持续行动产出需要明确：

1. 行动目标节点、资源槽或机会窗口。
2. 行动占用的人力、时间、消耗和风险。
3. 结果写入的是节点库存、宗门库存、市场供给、机会窗口还是事件后续状态。
4. 是否改变资源槽规模、丰度、污染、设施占用或控制状态。

### 5.5 阶段预算

玩家首次突破到某大境界后，世界激活对应阶段预算。预算可以进入节点资源槽、宗门库存、市场交易、机会窗口、NPC 个人资产或事件投放。

预算打开提供机会，不自动赠送修为；预算产出的资源必须能追溯到节点、市场、事件、NPC、宗门或其他明确来源。

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 地图节点 | 读取节点等级、灵气基础、污染、稳定度、相性权重和控制状态 |
| 资源槽 | 读取资源槽类型、规模、丰度、再生、可见性、设施占用和扩展来源 |
| 资源槽附属设施 | 读取设施类别、规模、等级、运转状态、人力维护和产出方向 |
| 宗门系统 | 读取宗门控制权、影响力、人力占用和持续行动状态；写入宗门资源结果 |
| 库存系统 | 写入 `sect_storage`、`node_storage`、库存日志和必要的物品堆叠 / 实例 |
| 物品系统 | 在需要具体物品形态时，将资源池或抽象资产转换为 `ItemStack` / `ItemInstance` |
| 交易系统 | 承接市场供给、采购、出售和资源兑换口径 |
| 随机事件 | 创建灾害、敌对干扰、机会窗口、稀有变体或资源槽状态变化 |
| NPC / AI | 读取节点资源、市场供给和机会窗口，用于交易、掠夺、建设、争夺或托管决策 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `node_id` | 地图节点身份，产出结算的主归属 |
| `resource_slot_id` | 资源槽实例身份，指向资源槽定义与状态 |
| `slot_type` | 资源槽简化类型，取值以资源槽详细设定为准 |
| `slot_scale` | 资源槽规模或规模上限，用于产能、承载和占用判断 |
| `abundance_state` | 丰度、再生、枯竭或波动状态；具体公式待数值文档补齐 |
| `attached_facility_id` | 当前占用资源槽的附属设施、洞府、藏宝或其他设施化对象 |
| `control_owner_id` | 当前控制宗门、势力或无控制状态 |
| `production_clock` | 常态产出的世界小时、宏观周期或事件周期 |
| `output_destination` | 产出写入宗门库存、节点库存、市场、事件窗口或 NPC 资产 |
| `output_resource_ref` | 产出资源、资源池、物品堆叠或物品实例引用 |
| `budget_phase` | 资源是否来自某境界阶段预算或机会窗口 |
| `last_settled_world_hour` | 最近一次产出结算时间，用于追赶和重复结算防护 |
| `production_log_refs` | 产出、入库、灾害、干扰、扩展或迁移的日志引用 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 应展示：

1. 节点可见资源槽、控制状态、附属设施占用和可理解的产出方向。
2. 资源进入宗门库存、节点库存、市场或机会窗口的摘要。
3. 影响产出的主要可决策因素，例如设施停摆、人力不足、灾害、敌对干扰或槽位被洞府 / 藏宝占用。
4. 宗门持续行动与常态产出的区别，避免玩家误以为开采行动是所有资源产出的唯一来源。

普通 UI 不展示：

1. 原始随机种子、稀有变体内部概率和完整调参表。
2. Debug 用资源槽 ID、预算池 ID、结算批次 ID 和内部公式追踪。
3. 尚未揭示的隐藏资源、藏宝入口、敌对干扰来源或机会窗口剧透。

## 9. MVP 范围

MVP 应实现：

1. 节点挂载资源槽，资源槽按简化类型参与经济产出口径。
2. 已控制资源节点的常态产出进入宗门库存或节点库存。
3. 常规人工扩展只新增普通 `aura_node`，并通过附属设施、投入资源或事件形成收益。
4. 宗门持续行动可以产生额外资源结果，但不替代常态产出。
5. 产出结算写入库存日志，并能区分节点来源、资源槽来源和行动来源。

MVP 不实现：

1. 完整 ResourceSlot 产能公式、丰度曲线、再生周期和灾害系统。
2. 各境界阶段预算的完整数值表。
3. 复杂市场价格、跨区域物流和 NPC 资产长期模拟。
4. 单个地图节点资源槽总数量上限。
5. 高级洞天福地、特殊资源槽和隐藏机会的完整投放链。

## 10. 验收约束

1. 资源产出必须能追溯到节点、资源槽、附属设施、持续行动、事件或阶段预算来源。
2. 已控制资源节点的常态产出不得被宗门持续行动数量限制吞掉。
3. 常规人工扩展资源槽不得直接生成特殊资源、稀有资源预算或高于节点平均灵气的收益。
4. 一个资源槽被洞府、藏宝或其他设施化对象占用时，不得同时作为其他生产 / 公共设施来源结算。
5. 产出进入物品形态前，必须先确认库存归属、抽象资源池或物品转换边界。
6. 阶段预算只能打开机会和投放渠道，不得绕过来源记录直接增加角色修为。
