# 系统设计｜突破玩法

## 1. 设计定位

突破是角色从当前大境界跨入下一大境界的高价值个人验证事件，负责回答“何时允许尝试破境、当前大境界锁定主修道功如何定义突破模板、突破事件内部验证哪些明确角色数值、资源和伤损如何结算，以及结果如何写入本世状态和轮回账本”。

大境界突破不是自动升级、单次概率按钮、普通战斗，也不是外敌入侵事件。它由 CP 触发尝试资格，由当前大境界锁定主修道功的突破模板定义难度和收益，由法力、生机、元气、神念、体魄、精力、根骨、悟性完成事件内验证，最后由结果包写入成功、失败存活或失败死亡及伤损后果。

小境界升级是阶段内成长节点，不默认进入完整突破事件链。大境界突破必须由玩家主动发起，并进入准备确认、突破事件、结果报告和后续处理结构。

## 2. 当前结论

1. 大境界突破的角色数值入口门槛只检查当前大境界 CP 是否达到要求；法力、生机、元气、神念、体魄、精力、根骨、悟性不在开启阶段阻止突破。
2. 当前大境界锁定主修道功决定突破模板、阶段序列、难度、成功收益和失败标签池；临近突破时不能临时换功规避模板。
3. 突破不再设置独立突破品质，也不再区分完美突破、正常突破和残缺突破。
4. 突破结果主类型只保留 `success`、`failed_survived`、`failed_death`；伤势、元气亏损、神念受创、经脉过载等进入结果包。
5. 突破成功后的永久收益由境界基础收益和道功突破模板收益组成；成功但带伤不是残缺突破。
6. 突破事件内可直接考验的数值只包括法力、生机、元气、神念、体魄、精力、根骨和悟性。
7. 伤势、道伤、经脉过载、心魔包装等不作为直接考验项；它们通过持续状态或 debuff 修正明确属性后，间接影响突破阶段验证。
8. 雷劫只从金丹到元婴及之后的大境界突破开始允许进入突破事件内挑战；炼气到筑基、筑基到金丹等前期突破不投放雷劫。
9. 外扰与护法永远不作为突破事件内挑战。外敌干扰只能作为突破前或突破后的独立事件链；护法只能用于突破前后安全、接应、传闻、宗门支持或叙事表达。
10. 经脉压力本身不直接影响属性。体魄决定经脉压力上限；丹药、灵液、灵材和筑基丹等突破道具提供灵气并占用持续经脉压力，超限后生成经脉过载 debuff，再由 debuff 修正属性。
11. 大境界突破和高风险突破契机不能由普通托管、自动兜底或未来条件脚本主动发起；F1 中触发突破契机时应提醒、摘要或中断，等待玩家确认。

## 4. 核心循环或触发入口

大境界突破从长期准备开始，由玩家主动确认：

```text
长期修炼与准备
→ 当前大境界 CP 达到突破要求
→ 玩家打开突破准备 / 修为页面
→ 系统读取当前大境界锁定主修道功的突破模板
→ 玩家确认突破道具、可选资源、默认策略和后续安排
→ 创建突破事件实例
→ 按模板生成体内灵气压力状态、资源锁定和初始阶段
→ 进入 B1 突破事件
→ 逐阶段验证明确角色数值
→ 输出突破结果包
→ 写入境界、伤损、资源、日志、传闻和轮回账本
→ 进入巩固、疗伤、隐瞒、公开报备、接应或转世等后续处理
```

B1 只负责现实提交窗口、房间慢速和非参战世界推进。突破事件自身耗时由突破模板声明，不固定等同于 B1 世界推进 1 小时。

每个突破阶段流程：

```text
1. 展示当前阶段语义、主考 / 辅考数值、可用资源和风险提示；
2. 玩家选择 1 个阶段应对；
3. 每阶段现实决策窗口默认 60 秒；
4. 玩家可提前提交，并可在倒计时结束前修改；
5. 未提交时执行当前突破默认策略；
6. 系统按模板阈值和修正后的明确属性结算本阶段；
7. 写入阶段结果、资源消耗、伤损、失败标签和日志；
8. 进入下一阶段或生成最终结果包。
```

突破阶段选择不进入普通行动队列。B1 或 P0 期间玩家可以编辑普通行动队列，但普通队列只影响突破结束后的后续行动。

## 5. 规则与状态

### 5.1 大小境界分工

小境界升级是阶段内成长节点：

1. 可由修为进度、主修道功掌握度、主修道功支持范围和角色状态共同校验。
2. 可按个人即时处理事件或轻量提示处理。
3. 不消耗关键突破物。
4. 不进入完整突破事件链。
5. 不改变大境界突破模板或成功收益结构。

大境界突破是核心玩法节点：

1. 必须由玩家主动开启。
2. 角色数值入口门槛只看当前大境界 CP。
3. 进入后由当前大境界锁定主修道功的突破模板定义难度和收益。
4. 资源、地点、模板和突破道具属于模板 / 资源 / 场景合法性，不包装成角色当前属性不足。
5. 结果可能改变本世境界、宗门地位、轮回账本、后手安全和下一世规划。

### 5.2 开启突破短指令

开启突破是普通短指令或局部确认，不是 P0，也不是完整阶段选择。

入口角色数值门槛：

```text
can_attempt_breakthrough_by_growth =
  current_realm_cp >= required_breakthrough_cp
```

开启阶段不检查：

1. 法力、生机、元气、神念、体魄、精力、根骨、悟性。
2. 伤势、心境、心魔、因果、执念或前世阴影。
3. 经脉压力作为直接角色数值门槛。
4. 主修道功掌握度作为默认入口门槛。

仍需完成的合法性检查：

```text
locked_main_dao_method_record exists
breakthrough_template_ref exists
breakthrough_template.supported_transition == target_transition
required_template_resource_slots are satisfied
scene_allows_breakthrough_instance_creation == true
```

这些检查用于确认路线、模板、资源和场景是否能创建突破实例，不得写成“角色属性不够格”。若模板缺失或路线不支持，应归类为内容配置缺失、路线不支持或资源条件不满足。

突破契机在 F1 中触发时：

1. 普通预设不得自动发起高风险突破。
2. 玩家已设置“不自动突破”时，F1 可只记录突破契机摘要或提示。
3. 玩家设置“满足条件提醒”时，应中断到 N1 / B1 / P0，由玩家确认。
4. 突破挑战进入 B1 后，轮内选择不进入普通队列或 F1 自动处理。

### 5.3 主修道功与突破模板

大境界突破读取当前大境界最终锁定的主修道功记录：

```text
locked_main_dao_method_record
→ breakthrough_template_ref
→ supported_transition
→ difficulty_profile_ref
→ reward_profile_ref
→ stage_sequence
→ failure_tag_pool_ref
```

道功突破模板至少负责：

```yaml
BreakthroughTemplate:
  template_id: string
  source_dao_method_id: string
  supported_transition: string
  difficulty_profile_ref: string
  reward_profile_ref: string
  stage_sequence: list[BreakthroughStageTemplate]
  required_or_optional_resource_slots: list[ResourceSlot]
  thunder_tribulation_policy: none | enabled_from_this_transition | enabled
  failure_tag_pool_ref: string
  result_report_template_ref: string
```

字段职责：

| 字段 | 职责 |
| --- | --- |
| `difficulty_profile_ref` | 定义阶段阈值、损伤风险、死亡风险和失败标签池 |
| `reward_profile_ref` | 定义成功突破后的境界收益、道功路线收益、属性倾向、寿元 / 权限 / 行动入口等 |
| `stage_sequence` | 定义突破事件内部需要经历的个人数值验证阶段 |
| `required_or_optional_resource_slots` | 定义必须或可选投入的突破道具、丹药、法宝、符箓、灵材等资源槽 |
| `thunder_tribulation_policy` | 定义是否包含雷劫挑战；仅金丹到元婴及以后可启用 |

道功越强，可以表现为突破模板更难、阶段阈值更高、雷劫压力更强、伤损风险更高或成功收益更好。道功强弱已经承担“突破品质”职责，不再额外叠加独立突破品质。

### 5.4 突破道具、丹药与经脉压力

突破道具是事件输入，不是额外属性门槛。筑基丹等道具可以由突破模板声明为必需或可选资源槽。

突破道具的系统职责：

```text
提供大量辅助突破灵气
+ 占用经脉压力
+ 在突破事件中逐步被吸收、消耗或消散
+ 超出经脉压力上限时生成经脉过载 debuff
```

经脉压力链路：

```text
体魄
→ 经脉压力上限
→ 丹药 / 灵材 / 突破道具占用经脉压力
→ 超限时生成经脉过载 debuff
→ debuff 修正明确属性
→ 修正后的属性参与突破事件内验证
```

禁止链路：

```text
经脉压力 → 直接降低属性
经脉压力 → 直接作为突破阶段考验项
```

突破事件创建或阶段开始时，突破道具可生成体内灵气压力状态：

```yaml
InternalAuraPressureState:
  state_id: string
  character_id: string
  source_instance_id: string
  source_type: medicine | breakthrough_item | spirit_liquid | spirit_material | formation_infusion | other
  aura_payload_total: number
  aura_payload_remaining: number
  meridian_pressure_value: number
  release_mode: absorbed_over_time | breakthrough_stage_consumed | dissipating
  started_world_day: int
  started_world_hour: int
  expected_end_world_day: int | null
  expected_end_world_hour: int | null
```

经脉压力超限时生成持续状态：

```yaml
MeridianOverloadDebuff:
  debuff_id: string
  character_id: string
  source_pressure_state_refs: list[string]
  overload_amount: number
  severity: light | medium | severe | critical
  attribute_modifiers:
    mana: number | null
    vitality: number | null
    qi: number | null
    spirit_sense: number | null
    physique: number | null
    stamina: number | null
  duration_rule: object
  recovery_rule: object
  created_by_breakthrough_instance_id: string | null
```

经脉过载默认不常规临时修改根骨和悟性，除非严重长期损伤或特殊事件明确声明。

突破中不得回溯用药改变已结算阶段。丹药、符箓、法宝或后手资源能否在阶段内投入，必须由阶段模板声明资源槽，并从当前或后续阶段开始生效。

### 5.5 事件内验证数值白名单

突破事件内可以直接考验的角色数值只包括：

```text
法力
生机
元气
神念
体魄
精力
根骨
悟性
```

| 数值 | 可承载的突破语义 | 常见阶段包装 |
| --- | --- | --- |
| 法力 | 破境冲击、灵力调度、道功输出 | 灵力冲关、破境推演、关隘攻伐 |
| 生机 | 承受反噬、维持生命、濒死边界 | 生机护持、反噬承受、濒死拉回 |
| 元气 | 气机循环、内耗续航、稳定突破态势 | 气机维稳、元气续航、强行调息 |
| 神念 | 识海稳定、心神抗压、心魔叙事包装 | 神念守关、识海定境、心魔幻象 |
| 体魄 | 肉身承载、经脉承压、雷劫承受 | 肉身承载、经脉震荡、雷劫硬抗 |
| 精力 | 长时间维持、连续阶段消耗、疲劳抗性 | 精力续航、久战维持、持续入定 |
| 根骨 | 承道资质、身体底盘、境界容纳 | 根骨承道、道基成形、灵根承载 |
| 悟性 | 理解新境界、道意成形、路线领悟 | 悟道成形、道意归一、破关理解 |

不直接作为考验项的因素：

| 因素 | 处理口径 |
| --- | --- |
| 伤势 | 持续状态或 debuff，折算为明确属性修正 |
| 经脉压力 | 资源 / 药性 / 突破道具占用系统；超限后生成 debuff |
| 心境 | MVP 不独立设计，用神念、悟性、精力等明确数值包装表达 |
| 心魔 | MVP 不独立设计，用神念 / 悟性阶段叙事包装 |
| 因果 | 暂不作为突破事件内直接数值 |
| 执念 | 暂不作为突破事件内直接数值 |
| 前世阴影 | 可作为文本、日志或未来扩展标签，不直接进入 MVP 结算 |
| 外敌干扰 | 永远不作为突破事件内挑战 |
| 护法 | 永远不作为突破事件内挑战 |
| 雷劫 | 金丹到元婴及以后可作为突破事件内挑战；前期不投放 |

### 5.6 阶段类型

通用个人数值验证阶段：

| 阶段类型 | 主考数值 | 辅考数值 | 语义 |
| --- | --- | --- | --- |
| 灵力冲关 | 法力 | 元气、精力 | 将 CP 积累与道功运转转化为破境冲击 |
| 气机维稳 | 元气 | 法力、精力 | 稳定突破中的气机循环，避免内耗失控 |
| 肉身承载 | 体魄 | 生机、根骨 | 承受破境反噬、肉身压力与经脉震荡 |
| 生机护持 | 生机 | 体魄、元气 | 防止重伤、濒死或生命崩溃 |
| 神念守关 | 神念 | 悟性、精力 | 处理识海、心神、心魔叙事包装 |
| 悟道成形 | 悟性 | 神念、根骨 | 理解新境界结构，使境界成形 |
| 根骨承道 | 根骨 | 体魄、生机 | 检验底层资质与承道能力 |
| 精力续航 | 精力 | 元气、神念 | 长阶段突破中的持续稳定性 |

后期雷劫阶段只能在金丹到元婴及之后的突破模板中出现：

| 阶段类型 | 主考数值 | 辅考数值 | 语义 |
| --- | --- | --- | --- |
| 天雷临身 | 体魄 | 生机、元气 | 肉身承受雷劫冲击 |
| 雷火炼神 | 神念 | 精力、悟性 | 识海与心神承受雷劫淬炼 |
| 劫力贯体 | 法力 | 体魄、元气 | 以法力和气机化解劫力 |
| 劫后道成 | 悟性 | 根骨、神念 | 将劫数压力转化为新境界成形 |

示例模板方向：

| 模板方向 | 阶段示例 | 特点 |
| --- | --- | --- |
| 速成道功 | 灵力冲关 → 气机维稳 → 生机护持 | CP 推进快，但元气 / 生机压力更明显 |
| 凝实道功 | 肉身承载 → 根骨承道 → 悟道成形 | 修炼较慢，成功收益更高或更稳 |
| 神魂道功 | 神念守关 → 悟道成形 → 精力续航 | 神念、悟性、精力是核心考验 |
| 元婴及以后雷劫模板 | 灵力冲关 → 雷火炼神 → 天雷临身 → 劫后道成 | 雷劫进入突破事件内部，但仍是个人数值验证 |

### 5.7 雷劫边界

雷劫是后期大境界突破挑战的一部分，不是外敌，也不是世界随机怪物攻击。

投放规则：

```text
炼气 → 筑基：不投放雷劫
筑基 → 金丹：不投放雷劫
金丹 → 元婴：开始允许投放雷劫
元婴 → 化神：允许投放雷劫
化神 → 炼虚及之后：允许投放雷劫或更高阶劫数变体
```

雷劫进入突破事件内部时，仍然必须遵守个人数值验证原则。雷劫阶段只能读取白名单内明确属性、资源槽和状态修正，不引入护法抵挡雷劫或外敌入侵阶段。

### 5.8 外扰与护法边界

外扰包括外敌袭击、敌对宗门干扰、妖兽闯入、秘境暴动中的敌对实体、行踪暴露追杀、NPC 破坏阵法或玩家直接冲突。

外扰永远不加入突破事件内挑战：

1. 不生成“突破中途被外敌打断”的内部阶段。
2. 不作为阶段检定来源。
3. 不与护法形成阶段内抵消关系。
4. 不写入突破模板 `stage_sequence`。

如果需要表达外扰，只能在突破事件前或突破事件后独立触发：

| 时机 | 独立事件表达 |
| --- | --- |
| 突破前 | 地点暴露、敌人追踪、是否安全闭关、是否延后突破、是否换地点 |
| 突破后 | 刚突破后虚弱被发现、宗门传闻扩散、敌对势力行动、资源点争夺 |

护法可以存在于世界与叙事层，但不能进入突破事件内挑战：

允许：

1. 突破前安排护法，降低突破前地点暴露或被袭击概率。
2. 突破后护法协助封锁消息、接应、疗伤或处理余波。
3. 宗门层面记录某次突破有长老护持，作为传闻或身份表达。

禁止：

1. 突破阶段中出现“护法抵御外敌”。
2. 护法作为阶段内资源格直接修改突破数值检定。
3. 外敌入侵作为突破阶段挑战，然后用护法抵消。

### 5.9 默认策略与超时

突破挑战必须支持默认策略，避免多人时间卡死。

默认策略建议：

1. 保命优先。
2. 稳健突破。
3. 节省珍贵道具。
4. 优先成功率。
5. 保守消耗。
6. 失败即中止。

若玩家某阶段 60 秒内未提交，执行当前突破预设。默认策略不得凭空使用未授权的稀有不可逆资源；只有玩家在开启阶段或上一阶段明确授权的资源，才可被默认策略消耗。

默认策略不得包含“追求高品质”“接受残缺突破”一类已废弃结果目标。

### 5.10 结果类型与结果包

突破结果主类型只保留：

```text
success
failed_survived
failed_death
```

不再保留：

```text
perfect_success
normal_success
incomplete_success
breakthrough_quality_tier
残缺突破
完美突破
普通突破
```

成功时：

1. 写入新大境界。
2. 应用境界基础收益。
3. 应用道功突破模板收益。
4. 结算突破过程中的伤势、debuff、资源消耗和持续状态。
5. 写入日志、传闻、轮回账本必要摘要。

成功后可能出现神完气足成功或带伤成功。带伤成功表示新境界事实和道功模板收益已经成立，但当前战力受伤势、元气亏损、神念受创、经脉过载等状态暂时压制。它不是残缺突破，不降低永久突破品质。

失败存活时：

1. 不写入新大境界。
2. 消耗已承诺资源或机会。
3. 结算伤势、元气亏损、神念受创、经脉过载等 debuff。
4. 写入失败标签。
5. 角色进入疗伤、休整、重新准备或后续选择。

失败死亡时：

1. 不写入新大境界。
2. 进入死亡 / 转世链。
3. 写入轮回账本。
4. 记录失败标签、突破模板、主要损伤来源和资源消耗。
5. 触发宗门清点、遗产、后手或传闻等后续系统。

推荐结果包结构：

```yaml
BreakthroughResultPackage:
  breakthrough_instance_id: string
  character_id: string
  transition_id: string
  source_dao_method_id: string
  source_template_id: string

  result_type: success | failed_survived | failed_death
  realm_changed: bool
  old_realm_id: string
  new_realm_id: string | null

  realm_base_reward_applied: bool
  dao_method_reward_profile_applied: bool

  stage_results:
    - stage_id: string
      stage_type: string
      checked_attributes: list[string]
      check_result: pass | partial | fail
      damage_delta_refs: list[string]
      resource_consumed_refs: list[string]
      failure_tags: list[string]

  damage_results:
    injuries: list[object]
    debuffs: list[object]
    attribute_damage_or_modifiers: object
    recovery_requirements: list[object]

  meridian_pressure_results:
    pressure_sources: list[string]
    overload_created: bool
    overload_debuff_refs: list[string]

  consumed_resources: list[object]
  logs: list[object]
  rumor_or_public_effects: list[object]
  reincarnation_record_delta: object | null
```

### 5.11 失败标签与轮回账本

突破失败必须输出一个或多个失败标签。失败标签用于解释本世代价和下一世准备方向，不用于恢复旧突破品质。

标签方向：

1. 法力不足或灵力冲关失败。
2. 元气续航不足。
3. 生机护持不足。
4. 体魄承载不足。
5. 神念动摇。
6. 精力耗竭。
7. 根骨承道不足。
8. 悟道成形失败。
9. 突破资源不足或不匹配。
10. 突破道具导致经脉过载。
11. 雷劫承受失败，限金丹到元婴及之后。
12. 模板特殊失败标签。

轮回账本写入：

```text
成功：突破阶段、主修道功、突破模板、关键资源、成功收益、伤损摘要、后续路线提示。
失败：失败阶段、失败标签、消耗资源、是否死亡、主要损伤来源、突破模板、下一世准备建议。
```

前世经验不直接保证成功。它可以提前暴露风险、提高挑战序列可见度、提示同类失败标签、解锁特殊准备路径或提供额外破境指令。

## 8. UI 展示边界

突破 UI 应展示玩家可决策信息，而不是完整公式或隐藏权重。

普通界面应展示：

1. 当前目标境界和 CP 入口门槛是否满足。
2. 当前大境界锁定主修道功、突破模板名称、主要考验项和成功收益倾向。
3. 模板所需或允许投入的突破道具和资源。
4. 经脉压力空间、突破道具占用和可能生成的经脉过载状态。
5. 当前伤势、体内药性、经脉过载等状态对突破属性表现的方向性影响。
6. 主要损伤类型、失败标签方向和是否存在死亡风险。
7. 雷劫是否包含在本次模板中；前期突破不应显示雷劫预期。
8. B1 阶段剩余提交时间、当前阶段语义、可用应对、可授权资源和默认策略。
9. 突破结果报告、境界变化、资源消耗、失败原因、伤损状态和下一次准备方向。

普通界面不应展示：

1. 突破品质预测。
2. 完美 / 正常 / 残缺突破结果。
3. 完整阈值权重、隐藏随机种子或 Debug trace。
4. 护法抵御外扰的突破阶段。
5. 外敌入侵作为突破内部阶段。
6. 普通行动队列可以替代阶段选择的暗示。
7. 交锋中回溯服丹或即时涨修为入口。

成功结果页必须区分“已突破”和“当前伤损状态”。带伤成功应表达为已突破但需要疗伤或调息，不得显示为残缺突破。

## 9. MVP 范围

MVP 应实现：

1. 大境界突破必须手动开启。
2. CP 作为唯一角色数值入口门槛。
3. 当前大境界锁定主修道功读取突破模板。
4. 至少 1 个突破道具或等价模板资源条件。
5. B1 突破事件，每阶段 1 个交锋格。
6. 默认策略与 60 秒现实提交窗口。
7. 法力、生机、元气、神念、体魄、精力、根骨、悟性白名单验证。
8. 经脉压力状态和经脉过载 debuff 的最小链路。
9. `success / failed_survived / failed_death` 三类结果。
10. 失败标签和轮回账本写入。
11. 个人结果报告、公开影响和回放记录。
12. 炼气到筑基、筑基到金丹两段前期突破不投放雷劫。

MVP 不实现：

1. 独立突破品质。
2. 完美突破、正常突破、残缺突破。
3. 外扰或护法作为突破内部阶段。
4. 多角色复杂护法操作。
5. 高复杂外扰战斗链。
6. 完整宗门审批、排队和名额争夺流程。
7. 即时生效丹药。
8. 自动条件脚本主动发起突破。

## 10. 验收约束

1. 小境界升级不进入完整突破链。
2. 大境界突破不能由托管、自动运转或未来条件脚本主动发起。
3. CP 未达标时，不能创建大境界突破实例。
4. CP 达标后，法力、生机、元气、神念、体魄、精力、根骨、悟性不得在开启阶段阻止突破。
5. 道功模板缺失、资源不足或场景不合法必须归类为模板 / 资源 / 场景合法性失败。
6. 大境界突破必须读取当前大境界最终锁定主修道功记录。
7. 突破模板必须声明难度 profile 和成功收益 profile。
8. 不得生成独立突破品质字段或品质预测 UI。
9. 结果类型不得恢复完美、正常、残缺突破。
10. 成功但带伤不得降低永久成功收益，不得包装为残缺突破。
11. 伤势、经脉过载和心魔包装不得作为直接考验项，只能通过状态修正明确属性。
12. 经脉压力不得直接修改属性，不得直接作为阶段检定项。
13. 突破道具导致经脉压力超限时，应生成经脉过载 debuff。
14. 雷劫不得出现在炼气到筑基、筑基到金丹突破模板中。
15. 雷劫阶段不得引入外敌或护法抵挡逻辑。
16. 外扰和护法不得进入突破模板阶段序列。
17. 每阶段只有 1 个突破交锋格，现实提交窗口默认 60 秒。
18. 未提交阶段选择时执行当前突破预设。
19. 默认策略不得擅自消耗未授权的稀有不可逆资源。
20. 突破交锋自身耗时由模板声明，并进入持续效果、资源、时间和日志结算。
21. 突破失败必须输出失败标签并写入轮回账本。
22. 结果报告必须显示发生了什么、为什么成功 / 失败、当前伤损和下一次该补什么。
