# 交互设计｜角色成长与资产管理

适用范围：角色状态、修为与境界、道功 / 法门掌握、换功、装备、法宝炼化、随身资产、重伤与转世后果的信息表达。本文不规定具体页面布局。

## 1. 信息分层

角色信息至少分为四组，避免把知识、当前世状态和物品混成一条成长线：

| 信息组 | 核心内容 | 关键边界 |
| --- | --- | --- |
| 当前世状态 | 境界、标准 CP、有效修为、体魄、精力、根骨、悟性、灵根、生机、元气、神念、寿元 | 转世时多数清空或重建 |
| 知识与掌握 | 已知晓道功、法门、招式解锁、`0—100` 掌握度 | 转世保留，但受新境界限制 |
| 构筑与装备 | 当前主修、法门招式、攻击 / 防御 / 飞遁法宝 | 战前决定自动战斗能力 |
| 资产与关系 | 丹药、材料、货币、其它可转移资产及未来地区关系 | 死亡和转世后果不同，未裁决项必须显式标识 |

真灵与执念不属于本方案角色面板。

## 2. 修为、境界与状态反馈

玩家需要同时看到：

- 当前大境界和小境界；
- 当前标准 CP；
- 当前有效修为及限制来源；
- 当前主修道功的境界上限；
- 下一次大境界突破条件；
- 重伤、境界虚浮等会阻止或削弱进度的状态。

标准 CP 是内部折算与保留值，战斗和常规系统读取有效修为。交互不得只展示 CP 而隐藏当前实际生效值。

回合末自动修炼应说明本轮是否获得修为。重伤、未配置主修或其它明确原因导致零收益时，需要展示原因，而不是只显示“+0”。

## 3. 突破与小洞天

选择大境界突破前，应展示合法地点、修为门槛、重伤限制、成功率来源、丹药影响和成功后可能进入渡劫战斗。失败结果按现有规则结算，界面不得把成功率判定和渡劫战斗合并成一次不可解释的随机结果。

小洞天需明确：

- 剩余外界回合；
- 本回合继续停留或主动退出的后果；
- 十倍内部时间对修炼、恢复、资源、炼化和寿元的影响；
- 关闭后的返回位置。

## 4. 道功、法门与掌握

知识条目至少展示整数掌握度、当前阶段、下一阶段阈值、已解锁招式和受境界限制的招式。

| 阶段 | 范围 | 知识招式 `K1/K2` 倍率 |
| --- | ---: | ---: |
| 初识 | `0—24` | `0.70` |
| 熟练 | `25—49` | `0.85` |
| 精通 | `50—74` | `1.00` |
| 圆满 | `75—100` | `1.15` |

研习功法是主要行动；完整地点、单次进度、成本与竞争规则仍待 `S-06`，当前交互文档不得补造默认值。

## 5. 换功确认

切换主修只在回合开始即时阶段开放，每回合最多一次，死亡或重伤时禁止。确认前至少预览：

- 新旧道功阶级与 CP 转化率；
- 折算后的标准 CP；
- 不变的大境界与可能变化的小境界；
- 新的有效修为和境界虚浮风险；
- 三条属性上限变化后的百分比继承结果；
- 旧道功招式退出、新道功招式追加到自动战斗列表末尾。

尚未裁决的 G-23 取整不得以界面示例固化成规则。

## 6. 法宝与炼化

三个固定法宝位必须按攻击、防御、飞遁区分。法宝详情应同时展示当前归属、整数炼化度、是否跨过生效门槛、当前实际效果和下次回合末增量。

```text
r <= 50：加成和招式不生效
r > 50：实际效果 = 基础效果 × r / 100
```

交易、死亡掉落、炼器和来源未明确的取得方式分别以 `50 / 0 / 100 / 30` 初始化。转移确认必须提示取得方的初始化结果；售出后购回也按交易重新初始化。新方案不显示绑定状态，因为不存在绑定机制。

## 7. 死亡与转世后果

死亡前后应清楚区分：

- 保留的知识来源、掌握度与已解锁招式；
- 清空的修为、生机、元气、神念和默认随身资产；
- 每件或每个堆叠单位独立 `10%` 成为战利品、`90%` 系统回收；
- 连续战斗只在整段结束后统一产生最终战利品。

转世出生地点、最低物资和追赶机制仍待 `S-04`，因此当前只表达已确认损失，不应暗示具体重返对局方案。

## 8. MVP 缺口

经济与资产循环、首批物品表、研习闭环、转世重返方案和宗门资产归属未定。关闭这些 P0 门后，才能确定库存分类、批量操作、价格信息、转世预览和经营资产入口。
