# 05_宗门组织_库存_宗门行动

# 宗门组织、库存与宗门行动

## 0. 文档定位

本文整理宗门身份、权限、贡献、门内声望、宗门库存、资源预留、宗门主行动和执行完成度。

宗门是组织性资源平台，不是玩家本体。玩家通过身份、职位、贡献、声望和权限影响宗门，而不是直接操控宗门全部资源。

## 1. 宗门系统定位

宗门系统负责回答：

```
玩家在宗门中是什么身份？
能申请什么资源？
能使用什么设施？
能提出或决定什么组织行动？
宗门有什么库存？
宗门每季度把组织资源投向哪里？
```

宗门死亡、玩家转世、玩家离宗或失势后仍继续存在，并由 AI 托管演化。

## 2. MVP 身份层级

MVP 固定五级身份：

```
外门弟子
→ 内门弟子
→ 真传弟子
→ 执事
→ 长老
```

MVP 不开放宗主职位。

M3 或等价第三大境界起点后，应允许玩家进入长老序列或等价高层决策体验。

## 3. 身份层级含义

| 身份 | 含义 |
| --- | --- |
| 外门弟子 | 基础功法、基础任务、最低宗门保护 |
| 内门弟子 | 更好的修炼设施、任务层级、宗门关系入口 |
| 真传弟子 | 重点培养，高价值资源、护法、突破名额、核心任务 |
| 执事 | 组织执行层，影响低到中级宗门行动，管理部分资源或节点事务 |
| 长老 | 高层决策体验，影响重大宗门行动、节点控制、培养方向和突破支持 |

## 4. 权限系统

MVP 不做复杂树状官僚体系，使用可检查标签。

```
SectPermission {
  request_resources: bool,
  use_training_site: bool,
  request_breakthrough_support: bool,
  propose_sect_action: bool,
  decide_sect_action: bool,
  lead_task: bool,
  access_inner_archive: bool,
  manage_node_affairs: bool,
  assign_guard_or_support: bool
}
```

权限来源：

1. 宗门身份层级。
2. 具体职位。
3. 门内声望。
4. 贡献记录。
5. 关键 NPC 支持。
6. 特殊事件授权。

## 5. 不引入宗门内部派系

已定口径：MVP 不引入宗门内部派系 / 山头作为系统变量。

规则：

- 宗门内部影响力先通过身份、职位、贡献、门内声望、关键 NPC 支持和特殊事件授权表达。
- 不建立派系归属、山头资源、派系声望、派系斗争、派系投票或派系任务线。
- 文案可以出现师承、旧识、执事堂等组织氛围，但不进入 MVP 规则层。

## 6. 贡献与门内声望

### 6.1 贡献记录

贡献是玩家为宗门完成任务、上交资源、参与驻守、解决危机的历史凭证。

贡献不是货币，不可直接兑换资源。

### 6.2 门内声望

门内声望是宗门内部对玩家可靠性、潜力和影响力的综合评价。

### 6.3 资源申请

资源申请应读取贡献与声望作为条件，但最终仍由 S6 检查宗门真实库存。

```
贡献 / 门内声望 / 权限
→ 是否允许申请
→ 检查宗门库存与预留
→ 生成资源预留或拒绝
→ 写入日志
```

## 7. 宗门库存

MVP 宗门追踪五类抽象资源：

1. 灵石。
2. 修炼资源。
3. 材料 / 矿材。
4. 人力 / 弟子规模。
5. 声望 / 影响力。

```
SectResourceStock {
  sect_id: String,
  spirit_stone: int,
  cultivation_resource: int,
  material_stock: int,
  manpower: int,
  sect_reputation: int,
  reserved_resources: Array,
  income_sources: Array,
  expense_records: Array,
  stock_logs: Array
}
```

注意：

- `sect_reputation` 是宗门整体资源口径，不等同于节点影响力。
- `manpower` 是组织人力规模，不是物品。
- 抽象资源在需要成为具体道具、奖励、突破资源或后手封存时，再由物品系统实例化。

## 8. 宗门资源来源

MVP 来源：

- 控制节点的基础产出。
- 宗门行动结果。
- 玩家上交资源。
- 节点事件奖励。
- 宗门声望带来的外部供给。
- 特殊秘境。
- 后手回收。
- 宗门商店或设施产出。

## 9. 宗门资源支出

MVP 支出：

- 发放弟子培养资源。
- 支持玩家或 NPC 突破。
- 宗门行动消耗。
- 节点建设与修复。
- 驻守、远征、探索的人力占用。
- 应对节点危机。
- 维护宗门核心建筑或设施。
- 发放俸禄。

宗门俸禄口径：

```
境界基数 + 职位绝对值
→ 宗门财政状态修正
→ 最终发放额
```

所有宗门采用同一套基础标准，宗门财政状态只作为发放修正。

## 10. 资源预留

为了避免同一资源被多系统重复使用，宗门资源需要预留机制。

```
ResourceReservation {
  reservation_id: String,
  sect_id: String,
  resource_type: String,
  amount: int,
  reserved_for_system: String,
  reserved_for_event: String,
  start_quarter: int,
  expiry_quarter: int,
  status: String  # active / consumed / released / failed
}
```

示例：玩家申请突破支持后，宗门同意预留一批修炼资源。突破开始则消耗；事件取消则释放或部分损耗。

## 11. 宗门行动：核心口径

已定口径：

> 每个宗门每季度始终只有 1 个宗门主行动。
> 

规则：

- 宗门主行动是本季度需要组织资源或高层取舍的重点动作。
- 不随宗门规模、长老数量或建筑数量增加主行动数量。
- 宗门规模通过行动质量、执行完成度、常态收益、持续项目、建筑效果和事件结果表达。
- 该规则用于控制复杂度，避免每季度处理过多组织行动。

## 12. 常态结算

以下不占用宗门主行动：

- 已控制矿场的基础采矿产出。
- 已控制药田的基础产出。
- 已建成基础设施的持续修正。
- 已建立驻守状态的持续安全或控制稳定。
- 已完成培养体系的基础弟子成长。
- 建筑 / 设施正常工作时的稳定效果。

常态结算可受节点状态、建筑损坏、资源枯竭、敌对干扰、灾害事件、库存维护和人力占用影响。

## 13. MVP 六类宗门主行动

1. 开采 / 资源介入。
2. 驻守 / 控制强化。
3. 探索。
4. 远征。
5. 建设。
6. 培养。

这些行动改变宗门库存、节点资源、建筑状态、宗门影响力、控制权事件、玩家贡献与声望、秘境或后手窗口。

## 15. 建议、提议与决策

玩家对宗门行动影响分三档：

1. 建议：低身份玩家提出倾向，系统根据贡献、声望、宗门需求决定是否采纳。
2. 提议：中高身份玩家提出具体行动方案，仍可被宗门 AI 调整。
3. 决策：具备权限时可直接发起部分行动，但仍受库存、节点和风险校验。

采纳因素：

- 玩家身份与职位。
- 门内声望。
- 贡献记录。
- 宗门当前需求。
- 目标节点状态。
- 宗门库存。
- 宗门战略倾向。
- 关键 NPC 支持或反对。
- 多玩家同宗冲突。

## 16. 执行完成度

MVP 不直接使用二元成功 / 失败，而使用执行完成度区间。

```
ExecutionResult {
  level: String  # failed / partial / normal / strong / exceptional
}
```

影响因素：

- 投入资源。
- 投入人力。
- 行动类型与目标节点匹配度。
- 宗门影响力 / 控制权。
- 节点危险与事件状态。
- 角色亲自介入。
- 竞争宗门干扰。
- 随机波动。

## 17. 角色亲自介入

玩家可选择亲自介入宗门行动。此时：

- 必须在 S3 中规划移动和行动格。
- 必须抵达正确节点或事件窗口。
- S3 判断协同资格。
- S7 决定介入带来的完成度、贡献、声望、收益和风险。
- 介入可能触发战斗、选择事件、节点事件或突破 / 后手相关事件。

## 19. 与地图节点的关系

宗门行动以 S8 节点为目标：

- 开采读取资源槽。
- 建设读取建筑槽。
- 驻守读取控制权和危险结构。
- 探索读取隐藏层、事件槽、入口槽。
- 远征读取路线、边界节点和敌对影响力。
- 培养读取宗门设施、库存、弟子规模和玩家 / NPC 状态。

## 20. 与多人系统的关系

MVP 鼓励玩家分宗，但不禁止同宗。

同宗时：

- 多玩家可提出宗门建议。
- 采纳由权限、职位、声望、贡献和宗门 AI 倾向决定。
- 不做玩家强制投票。
- 不允许通过宗门行动直接毁掉同宗玩家长期体验。

## 21. MVP 验收清单

- 玩家可加入宗门并获得身份。
- 宗门身份决定基础权限。
- 玩家贡献不是货币。
- 宗门有五类抽象库存。
- 宗门发放资源必须检查真实库存。
- 宗门每季度只有 1 个主行动。
- 已控制资源节点可常态产出。
- 玩家可提交建议 / 提议 / 决策意图。
- 宗门行动可返回执行完成度。
- 玩家可通过 S3 亲自介入宗门行动。
- 宗门行动结果通过 S1 回写节点、库存、贡献、声望和日志。
