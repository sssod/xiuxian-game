# MVP 框架缺口与阶段门

适用范围：判断飞升胜利主题在设计配置与未来开发计划前，各大模块的规则裁决、正式配表、内容生产和多人韧性状态。这里的“关闭”只表示设计门满足，不解除开发冻结。

## 1. 当前判断

本轮集中裁决已经把原先缺失的大模块推进到“框架规则已形成、正式内容与若干跨系统规则仍待关闭”的阶段。当前方案能够解释从炼气开局、跑图占地、获取资源、自动修炼 / 研习、五次突破、渡劫、转世到大乘飞升的主要状态流。

仍不能直接进入开发：首张地图、正式价格和属性、功法 / 物品 / 敌人内容表尚未完成；多人时限与掉线退出完全开放；有效修为和护盾叠加仍会改变核心结算。

## 3. 会改变规则的剩余 P0 门

### P0-A 多人韧性与主动结束

必须决定：

- 房间创建、加入、准备和宗门选择倒计时；
- 即时 / 规划阶段时限、提交撤回与未提交安全默认；
- 掉线、重连、托管和永久退出；
- 房主离开、对局中止和数据结果；
- 无强制终局前提下，玩家主动提前结束的发起、同意门槛与无胜者表达。

### P0-B 有效修为与改修

必须给出在标准 CP 不变前提下，当前主修模板、掌握度与其它修正如何得到有效修为，并验证：

1. 改修可以改变大境界内表现和小境界状态；
2. 不能让大境界升降或改写历史最高境界；
3. 自动修炼、战斗、UI 预览读取同一结果；
4. 不恢复标准 CP 折算、换功损失系数或境界阶段窗口。

### P0-C 护劫护盾叠加

必须统一护劫护盾与其它通用护盾的进入顺序、来源上限、总上限及伤害消耗顺序，再完成五档比例和四场渡劫敌人验收。不能由 UI 列表或代码顺序先行决定。

### P0-D 外交、退出与专属追赶

需要关闭普通关系、仇敌关系的完整表，明确首轮盟友功能是否继续延期；同时决定永久退出后的宗门与地产归属，以及落后者判定、专属追赶与节点易主事件是否进入首轮。

## 4. 正式配置与内容门

这些项目多数不再需要重开框架裁决，但缺表时仍不能形成可配置 MVP。

### 4.1 地图与地产内容

- 固定地图坐标、连接和人数座位组合；
- 三类经营节点、不可购地点、关隘、洞府和飞升地点；
- 节点标价、建筑类型、等级上限、逐级成本、收益、收费与容量；
- 四出生区域的首枚筑基丹路径与基础经济等价验算。

### 4.2 经济与物品内容

- 资源、商品、配方、丹药、法宝和功法道具清单；
- 停留 / 功能 / 过路费、生产力投入、商品价格与回收期；
- 逐物品成熟开关、默认 `1.5` 例外、完整 `Q1—Q5` 权重和三次取高模板；
- 主动生产链与被动经营的跨阶期望价值验算；
- 宗门贡献白名单、固定贡献值、兑换目录与最终成本。

### 4.3 成长、功法与移动内容

- `1A` 绝对 CP、五境总 CP、属性、状态、恢复、寿元与 `G-23`；
- 六境移动骰池、法门分布、法宝加成及元气 / 灵石 / 耐久成本；
- 五宗门初始功法、三套高阶路线、研习标签和 `72` 项阈值内容；
- 通用高阶功法第 `9—10` 回合投放与标准改修验算。

### 4.4 战斗与敌人内容

- `C1`、`C2`、`C3(g)`、各档 `K1_ref`；
- 招式冷却、成本、`K1/K2/D/K3`、护盾和 Buff；
- 普通、重点、洞府入口和飞升前置敌人；
- 四场固定渡劫的标准构筑与 `Q3` 单次 `70%—80%` 样本胜率验收。

## 5. P1 表达与验证门

P0 规则与正式内容表完成后，再集中处理：

1. 从开局到飞升的逐回合资源、状态与行动验算；
2. 早胜、期望胜利、延长对局、死亡转世和洞天高收益用例；
3. 主棋盘、角色资产、功法研习、地产与战斗的信息架构；
4. 错误、费用变化、未提交、掉线和恢复提示；
5. 简体中文与英语术语表、玩家文本占位；
6. G-23 等取整规则和完整数值回归。

节点级布局、视觉样式和动效仍由未来当前 UI artifact / Figma 承接，不写入稳定玩法规则。

## 6. 推荐后续裁决 / 配置顺序

1. `P0-B` 有效修为公式与 `P0-C` 护盾叠加，关闭跨系统结算缺口；
2. `P0-A` 多人韧性与主动结束；
3. 首张地图节点 / 价格 / 建筑骨架，并同步确定五宗门特色开局资源；
4. 资源、商品、配方、贡献和地产逐级表；
5. `1A`、境界 / 属性、移动与功法内容表；
6. 敌人、四场渡劫和完整战斗配置；
7. `P0-D` 专属追赶、外交与退出边界；
8. P1 逐回合验算、UI 信息架构与双语内容。

这是设计工作顺序，不是开发计划。

## 7. 未来进入开发计划的最小验收

只有同时满足下列条件，且用户明确解除开发冻结，才可制定 MVP 开发计划：

1. 所有会改变规则的 P0 门关闭，或用户明确写出首轮延期范围；
2. 首张地图、初始状态、主要行动、经济、敌人和内容清单可以直接配置；
3. 一局从开局到飞升的状态、资源、地产和异常路径可逐回合解释；
4. 死亡、重伤、逃遁、平局、渡劫失败、未提交、掉线与退出都有闭环；
5. 所有必填常数与内容字段有唯一归属，不存在实现层默认；
6. 本包不依赖旧正式包、草案或 handoff 才能解释规则；
7. 交互文档可以说明稳定信息与操作流，节点布局留给 Figma。
