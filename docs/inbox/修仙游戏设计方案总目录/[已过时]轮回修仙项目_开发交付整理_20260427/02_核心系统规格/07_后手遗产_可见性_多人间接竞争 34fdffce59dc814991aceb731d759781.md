# 07_后手遗产_可见性_多人间接竞争

# 后手、遗产、可见性与多人间接竞争

## 0. 文档定位

本文整理前世遗产、正式后手、隐藏层、后手风险、回收流程、可见性、传闻和 MVP 多人边界。

核心原则：

> 后手可信，多人间接，信息不全知。
> 

## 1. 普通前世遗产与正式后手

必须区分两类跨世外在资产。

| 类型 | 规则含义 | 保护强度 |
| --- | --- | --- |
| 普通前世遗产 | 前世死亡或放置后自然留在世界中的资产 | 可被发现、搬空、污染、破坏或转移 |
| 正式后手 | 经过正式行为封存、布置、记录并占用后手容量的安排 | 必须可追踪、有日志、失效有原因链 |

正式后手不是无限保险箱。它可以暴露、受损或被争夺，但不能无日志、无原因地消失。

## 2. 后手容量

正式后手容量由真灵强度提供。

```
FormalContingencySlot {
  spirit_id: String,
  max_slots: int,
  used_slots: int,
  unlocked_by_spirit_strength: int
}
```

MVP 只需要支持少量正式后手，不追求复杂组合。

## 3. 后手类型

MVP 推荐：

1. 藏物后手：封存物品、灵石、丹药、法宝、功法载体。
2. 地点后手：洞府、隐蔽山洞、阵法点、接引点。
3. 信息后手：遗书、地图、暗号、任务链、线索。

接口预留：

1. 权限后手：宗门密库权限、令牌、身份凭证。
2. 护持后手：护道人、弟子安排、阵法守护。

## 4. 后手创建流程

```
玩家选择正式布置后手
→ 检查真灵后手容量
→ 检查当前位置、物品、资源、权限与时间投入
→ 选择后手类型与封存目标
→ 生成后手记录
→ 写入 S8 节点隐藏层 / 后手层
→ 写入 S2 轮回账本
→ 消耗行动格、资源或物品
```

后手创建应是持续行动或事件链结果，不应作为纯即时行动完成。

## 5. 后手记录结构

```

```

## 6. 后手感应

后手感应不是常规强度加成，而是轮回账本交互规则。

最小规则：

- 玩家越接近正式后手所在区域，账本描述越清晰。
- 相关地点、传闻、路线或事件可提高感应清晰度。
- 感应只提供线索，不自动传送或直接领取。
- 感应强度可受真灵强度、道韵、失败经历、地点状态影响。

## 7. 后手回收流程

```
玩家获得后手线索
→ 通过地图、传闻、账本感应定位区域
→ 规划 S3 行动前往节点
→ 触发隐藏层 / 后手层事件
→ 检查访问条件、封存状态、风险状态
→ 处理守卫、污染、被发现、被搬空等结果
→ 生成回收或失败结果包
→ S1 回写资产、账本、节点状态和日志
```

回收高风险后手不得由托管主动执行。

## 8. 后手风险状态

建议状态：

```
stable：稳定。
exposed：已暴露。
contested：被争夺。
damaged：受损。
polluted：污染。
moved：被转移。
looted：被搬空。
lost_with_reason：失效但有原因链。
```

正式后手风险只在相关节点发生明确变化时检定，例如：

- 节点控制权变化。
- 节点被洗劫。
- 隐藏层被发现。
- 重大灾害。
- 宗门远征。
- 玩家高风险回收失败。
- 后手相关敌对事件触发。

不做每季度随机磨损，不做年久失修型低频随机风险。

## 9. 普通前世遗产

普通遗产不是正式后手。

规则：

- 可自然留在死亡现场、住所、洞府、宗门库房或节点储藏中。
- 可被 NPC、宗门、事件、玩家、世界状态转移或破坏。
- 重要变化应有世界日志。
- 玩家下一世未必能感应或定位。
- 若普通遗产被正式封存，则转为正式后手并占用容量。

## 10. 失效原因链

正式后手失效必须有原因链。

```
ContingencyFailureReason {
  contingency_id: String,
  failure_quarter: int,
  cause_type: String,
  cause_ref: String,
  involved_factions: Array,
  visible_to_player: String,
  recoverable_clue_refs: Array,
  world_log_ref: String
}
```

失效后应尽量提供：

- 可追查线索。
- 传闻或账本模糊记录。
- 可能的补救事件。
- 资产去向或损毁解释。

## 11. 可见性系统

玩家行动不是全图公开。

可见性来源：

- 是否同节点。
- 是否同宗门或有权限查看。
- 行动是否公开。
- 行踪是否暴露。
- 是否进入传闻。
- 是否由宗门日志或世界事件公开。
- 情报能力。

统一层级：

```
private
local_visible
sect_visible
rumor_visible
world_visible
debug_only
```

## 12. 世界日志与传闻

世界日志默认玩家不可见。玩家看到的是：

- 角色日志。
- 宗门摘要。
- 轮回账本。
- 传闻。

传闻由 S10 生成世界日志后，经 S13 决定是否传播。

传闻受以下因素影响：

- 事件公开性。
- 地点人流。
- 宗门关系。
- 玩家声望。
- 行踪暴露标签。
- 事件严重度。
- 情报能力。

传闻可以模糊、延迟、不完整，不能等同于全知日志。

## 13. 多人原则

MVP 多人默认：

```
分宗并行 + 间接竞争 + PvE 沙盒演化
```

不以玩家直接合作、直接对抗或高频社交互动作为核心验证目标。

## 14. 允许的 MVP 竞争

保留两类轻量间接竞争：

1. 宗门节点控制竞争。
2. 世界资源名额竞争。

示例：

- 玩家 A 影响宗门占住灵脉节点，玩家 B 所属宗门取得资源成本上升。
- 某季度秘境名额有限，多个宗门竞争进入资格。
- 节点控制权变化导致地图通行、事件优先响应或资源收益变化。
- 宗门突破支持名额被其他角色或宗门行动占用。

## 15. 不作为 MVP 核心的多人内容

MVP 不做：

- 玩家直接斗法。
- 玩家直接交易和赠予。
- 玩家互相护法。
- 共同秘境。
- 抢夺玩家洞府。
- 破坏他人突破。
- 离线袭击玩家主体。
- 围杀转世角色。
- 复杂同宗议事投票。

如果后续实现，只能作为低成本附加能力，不能影响核心闭环。

## 16. 分宗与同宗

MVP 默认鼓励玩家加入不同宗门，但不硬性禁止同宗。

同宗时：

- 多个玩家可提出宗门建议。
- 采纳由 S5 权限、职位、声望、贡献和宗门 AI 倾向决定。
- 不做玩家之间强制投票。
- 不允许通过宗门行动直接毁掉同宗玩家长期体验。

## 17. 资源名额竞争

适合 MVP 的名额对象：

- 秘境进入名额。
- 宗门突破支持名额。
- 高级修炼场地。
- 关键资源采集窗口。
- 节点事件响应机会。
- 特定宗门任务名额。

名额竞争应制造压力，但不直接毁掉玩家角色。

## 18. 多人结果反馈

多人结果反馈应遵守可见性：

- 玩家只能看到自己可知信息。
- 同宗可见宗门摘要或权限范围内信息。
- 公开世界事件可成为传闻。
- 其他玩家私密行动不全图公开。
- Debug 模式可查看完整世界日志。

## 19. MVP 验收清单

- 玩家可布置至少一种正式后手。
- 后手占用真灵容量。
- 后手挂载在节点隐藏层或后手层。
- 后手创建和变化写入日志。
- 后手回收通过 S3 行动和 S10 事件链。
- 后手失效有原因链。
- 多人房间中玩家行动默认不全图公开。
- 节点控制或资源名额可产生间接竞争。
- 传闻显示不等于世界全知日志。
- 托管不会主动暴露核心正式后手。
