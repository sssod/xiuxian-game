# 房间与时间推进（替换稿 v0.1）

> 替换范围：v2.2 `02_核心系统规格/01_房间回合推进_权威结算_v2.2.md` 中的回合阶段机、锁定、结算主循环、插入事件挂起、回放相关时间口径。  
> 保留范围：权威服务器、S1 结果回写、宗门 AI 调用、结果包合并、日志与存档原则。

---

## 1. 系统定位

S1 不再是“固定 5 日回合统一结算器”，而是：

> **共享世界日历与权威结算总线。**

它负责：

1. 维护世界绝对时间：`world_day / world_hour`。
2. 根据全体玩家和世界状态决定公开世界速度：F1 / N1 / B1 / P0。
3. 在服务器小时 tick 上推进角色行动、宗门 AI、节点状态、事件触发、资源效果和日志。
4. 处理个人局部时停、gap 上限与 C1 追赶补结算。
5. 处理 B1 正式交锋轮与 P0 全局暂停。
6. 合并所有行动、事件、交锋、突破、资产、宗门、节点结果包。

---

## 2. 房间运行目标

MVP 房间必须支持：

1. 本地单人测试。
2. 私人服务器部署。
3. 至少 3 名玩家共玩。
4. 保存、暂停、恢复、续开。
5. 无人在线时世界不自动推进，除非房间规则显式允许离线托管时间推进。
6. 普通行动不要求全员锁定后才结算。
7. P0 全局事件、B1 交锋轮和局部时停均可被日志、回放和调试复盘。
8. 速度切换不泄露私人事件归因。
9. 行动完成、队列为空、预输入校验失败时不会冻结角色，而是触发风险兜底。

---

## 3. 世界时间与速度档位

### 3.1 基础时间单位

```text
1 游戏日 = 24 游戏小时
服务器最小结算单位 = 1 游戏小时
```

### 3.2 公开速度档位

| 档位 | 名称 | 现实时间 : 游戏时间 | 使用场景 |
|---|---|---:|---|
| F1 | 高速推进 | 2 秒 = 1 游戏日 | 全员明确处于长期低交互行动 |
| N1 | 常态推进 | 15 秒 = 1 游戏小时 | 默认多人运行；个人局部时停期间外部世界速度 |
| B1 | 交锋慢速 | 60 秒 = 1 游戏小时 | 正式战斗、突破挑战、秘境关键交锋、玩家直接交锋 |
| P0 | 全局暂停 | 游戏时间不流动 | 全局阶段事件、公共决策、同步保护、主机暂停规则 |

### 3.3 内部机制

| 机制 | 名称 | 作用 |
|---|---|---|
| C1 | 追赶补结算 | 局部时停结束后，将滞后玩家补结算到世界当前时间 |

C1 不是玩家可选速度，也不是跳转功能；它只补齐已产生的本地滞后。

## 4. 速度状态机

速度优先级固定为：

```text
P0 > B1 > N1 > F1
```

伪代码：

```pseudo
update_world_speed(world):
    if world.global_pause_event.exists:
        return P0

    if world.formal_encounter.exists:
        return B1

    if any(player.local_time_stop.active for player in world.players):
        return N1

    if can_enter_F1(world):
        return F1

    return N1
```

F1 判定：

```pseudo
can_enter_F1(world):
    return all_players_have_current_action(world)
       and all_players_in_explicit_long_low_interaction_action(world)
       and no_player_in_auto_fallback(world)
       and no_player_in_local_time_stop(world)
       and no_player_in_catchup(world)
       and no_formal_encounter(world)
       and no_global_pause_event(world)
       and no_near_deadline_within_1_game_day(world)
       and no_global_stage_gate(world)
       and no_forced_public_node(world)
```

关键边界：

```text
自动兜底行动不能参与 F1。
显式托管、明确闭关、明确养伤、明确炼制、明确赶路等可参与 F1。
行动完成后若下一条队列指令合法，不强制打断 F1。
行动完成后若队列为空或后续指令失败，必须降至 N1。
```

## 5. 替换旧回合阶段机

删除普通流程中的：

```text
回合开始
上一回合报告生成 / 展示
信息处理与个人即时行动
个人行动指令预输入
锁定 / 超时等待
服务端统一结算
结果回写与日志生成
下一回合
```

替换为：

```text
房间加载 / 恢复
→ 世界日历运行
→ 玩家随时在允许状态下编辑普通短队列
→ 服务器按当前速度推进小时 tick
→ 行动完成点 / 小时 tick 执行校验、结算、事件判定
→ 个人事件进入局部时停 + 外部 N1
→ 正式交锋 / 突破挑战进入 B1
→ 全局公共事件进入 P0
→ 事件结束后 C1 追赶或恢复速度判定
→ 持续写入日志、摘要、存档与回放片段
```

保留 `current_phase` 时，应改为运行状态枚举：

```text
room_loading
world_running
local_time_stop_active
catchup_settlement
formal_encounter_b1
global_pause_p0
save_writeback
```

旧枚举迁移：

| 旧枚举 | 新处理 |
|---|---|
| `turn_start` | `world_running` 中的摘要查看状态，非时间规则阶段 |
| `report_review` | UI 日志 / 摘要抽屉，非时间暂停阶段，除非处于 P0 |
| `instant_personal` | 普通即时请求入口，服务器即时校验 |
| `personal_action_planning` | 普通队列编辑 UI，默认不暂停角色行动 |
| `waiting_lock` | 删除；仅 P0 / B1 / 局部事件可有等待状态 |
| `settlement` | 删除为阶段；服务器每小时 tick 持续结算 |
| `inserted_event` | 拆为 `local_time_stop_active` / `formal_encounter_b1` / `global_pause_p0` |
| `writeback` | `save_writeback` 或日志写入动作 |
| `turn_end` | 删除；可保留周期摘要生成点 |

## 6. 普通队列编辑规则

玩家主动编辑普通指令队列时：

```text
1. 不触发局部时停。
2. 不冻结自身角色当前行动。
3. 不冻结其他玩家或世界。
4. 若世界当前处于 F1，打开指令输入界面时世界降至 N1。
5. 若世界处于 B1 或 P0，玩家可编辑普通队列，但普通队列不能替代交锋轮选择或全局事件选择。
```

外部 UI 不显示私人归因，只显示：

```text
当前速度：常态推进
```

## 7. 个人局部时停

### 7.1 适用范围

只用于非交锋类个人选择，例如：

```text
同门邀约
师门私事
个人机缘
闭关异常的小型选择
资源申请反馈
功法修炼分歧
轻度探索遭遇
丹药副作用
普通心魔扰动
小境界突破选择
突破前简短道具确认
```

### 7.2 时间规则

当玩家 A 触发个人事件：

```text
A 的角色时间冻结在触发 world_hour；
A 的当前行动、资源变化、风险变化暂停；
B、C、宗门与世界继续 N1；
gap = 世界当前时间 - A 冻结时间；
gap 最大 1 游戏日。
```

### 7.3 gap 阶段

| gap | 系统行为 |
|---:|---|
| 0～12 游戏小时 | 正常局部时停 |
| 12～18 游戏小时 | 仅事件玩家本人轻提示 |
| 18～24 游戏小时 | 事件玩家本人强提示 |
| 24 游戏小时 | 安全默认或 P0 同步保护 |

若事件有安全默认：自动执行默认选项。  
若事件无安全默认：进入 P0 同步保护。

## 8. C1 追赶补结算

局部时停结束后，事件玩家进行 C1 追赶补结算：

```text
1. 从冻结 world_hour 回填事件选择后果。
2. 补结算确定性行动进度、修炼收益、资源消耗、药性衰减、伤势恢复、队列切换。
3. 不触发随机个人事件、普通机缘、普通战斗、软机会事件、普通心魔或普通资源反馈。
4. 最多 2 秒补完 1 游戏日。
5. 补结算完成后重新检查 F1 条件。
```

## 9. B1 正式交锋

正式交锋包括：

```text
正式战斗
秘境关键交锋
玩家直接交锋
多人组队战斗
宗门任务战斗
可能导致重伤 / 死亡 / 重大资源损失的战斗
突破挑战
```

规则：

```text
世界进入 B1；
不局部时停；
不 P0；
1 交锋轮 = 1 游戏小时；
1 交锋轮现实窗口 = 60 秒；
未提交者执行预设策略；
世界时间同步推进。
```

## 10. P0 全局暂停

P0 只用于：

```text
全局阶段闸门
宗门大会 / 全员议事 / 世界级灾变选择
所有玩家共同参与的公共决策
局部时停达到 1 日 gap 且事件不可默认
服务器同步保护
房间规则允许的主机暂停
```

不再使用 P0 的场景：

```text
个人大境界突破开启
个人突破临界选择
个人突破关键抉择
个人突破结果结算
正式战斗
突破挑战
普通心魔
普通闭关异常
小境界突破
个人资源申请反馈
个人机缘选择
```

## 11. 权威服务器原则（保留并修订）

保留 v2.2 原则：

```text
客户端只提交意图。
服务器校验行动、资源、位置、权限、事件触发。
所有结果包交给 S1 统一回写。
宗门 AI、节点变化、事件结果不得绕过 S1。
本地单人测试也走同一规则模型。
```

新增必须校验：

```text
当前世界速度状态；
玩家是否处于局部时停；
玩家 gap 是否接近上限；
玩家是否处于 C1 追赶；
行动是否来自显式队列、显式托管、超时默认或自动兜底；
自动兜底是否错误参与 F1；
B1 回合窗口是否到期；
P0 是否具有合法全局原因。
```

## 12. 连续时间结算主循环

替换旧 `turn_total_hours` 主循环：

```pseudo
server_tick_loop(world):
    speed = update_world_speed(world)

    if speed == P0:
        hold_world_time()
        process_global_pause_inputs_or_defaults()
        return

    if speed == B1:
        process_formal_encounter_rounds()
        advance_world_hour_by_rounds()
        write_result_packages()
        return

    elapsed_game_hours = convert_real_elapsed_to_game_hours(speed)

    for hour in elapsed_game_hours:
        world.current_world_hour += 1
        settle_world_hour(world)
        update_speed_if_needed(world)
        if speed_changed_to_B1_or_P0_or_N1_due_to_event:
            break
```

每个世界小时：

```pseudo
settle_world_hour(world):
    for player in active_players:
        if player.local_time_stop.active:
            update_gap_warning(player)
            continue

        if player.catchup.active:
            process_catchup(player)
            continue

        ensure_current_action_or_fallback(player)
        validate_running_action_segment(player)
        settle_action_progress(player)
        settle_resource_inputs_and_residual_effects(player)
        check_action_completion_and_next_command(player)
        check_personal_events(player)

    advance_sect_ai_continuous_actions(world)
    advance_nodes_resources_rumors(world)
    collect_and_write_result_packages(world)
```

## 13. 行动完成点处理

```pseudo
on_action_complete(player):
    next_command = player.command_queue.pop_next()

    if next_command.exists:
        validation = validate_command_before_execution(next_command, player.current_state)
        if validation.passed:
            start_command(player, next_command)
            return
        else:
            mark_command_skipped(next_command, validation.failed_reason)
            log_to_player(player, validation.failed_reason)
            start_auto_fallback(player, reason='validation_failed')
            force_world_speed(N1)
            return

    log_to_player(player, '队列已空')
    start_auto_fallback(player, reason='queue_empty')
    force_world_speed(N1)
```

## 15. 原计划 vs 实际结果修订

旧 `OriginalVsActualSummary` 可保留，但生成时机改为：

```text
1. 玩家队列发生跳过 / 中断 / 失败；
2. 玩家完成一串显式行动；
3. 局部时停事件结束并完成 C1；
4. B1 交锋或突破挑战结束；
5. P0 全局事件结束；
6. 存档 / 离线前周期摘要。
```
