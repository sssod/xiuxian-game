# 系统设计｜角色属性

## 1. 设计定位

角色属性是当前世“身躯与灵魂”层的系统主文档。它描述这一世角色的身体底子、修炼潜质、当前状态、承受风险的能力、路线倾向和寿元压力，不默认跨世继承。

本文是包内所有文档引用角色属性系统层规则的来源。本文负责字段语义、来源 / 持续性口径、状态边界、玩家可决策内容、MVP 范围和验收约束；不维护公式、系数表、倍率、年龄曲线、缓存字段或调参边界。角色属性数值层设计统一由《角色属性与派生状态数值设计》（`../../03_数值设计/09_角色属性与派生状态数值设计.md`）维护。

角色属性需要服务：

1. 角色初始化与身躯生成。
2. 角色当前状态描述。
3. 修炼、战斗、事件、资源、AI 与 UI 的字段读取。
4. 修炼效果、承载风险、战斗结果和状态反馈。
5. BUFF / DEBUFF、HOT / DOT、健康、伤势、寿元、死亡与转世入口。

## 2. 当前结论

1. 不设置单一“资质总分”参与核心判定；底层系统读取具体属性或资质子项，综合评价只用于 UI 提示和叙事。
2. 体魄 / 精力是通用基础属性；根骨 / 悟性 / 灵根是修炼资质子项；悟性不再同时作为基础属性。
3. 生机 / 元气 / 神念是持久派生状态条，不是战斗结束后默认回满的临时资源。
4. 寿元状态纳入角色属性维度，用于记录当前年龄、寿元上限、剩余寿元、寿元压力、延寿来源和年龄阶段入口；寿元不是生机条。
5. 年龄阶段只影响体魄 / 精力最终值，不影响修炼资质、灵根、灵根相性或神念基础值，也不回写先天属性或后天永久修正。
6. 基础属性和非灵根修炼资质区分先天、后天永久和临时修正。临时修正属于后天来源，但不回写为永久后天属性。
7. MVP 阶段灵根仅支持先天结果，不支持后天永久灵根或临时灵根。影响灵根相关结算的外部效果应记录为状态、资源、道功、法宝、阵法或事件效果。
8. 派生状态只区分永久 / 临时，不再把永久派生状态拆成先天 / 后天。
9. 资质在出生、身躯生成或特殊开局时已经确定；入门检测、宗门检测和机缘只负责检测、揭示、评级或写入自知信息。
10. 后天永久改变必须有明确来历、永久性标记和玩家可解释的记录；不得把短期增益伪装成永久资质。

## 4. 核心循环或触发入口

角色属性围绕“生成、揭示、改变、结算、展示”循环维护。

1. 生成：角色出生、身躯生成、真灵预设或特殊开局写入基础属性、修炼资质、寿元状态和初始派生状态。
2. 揭示：入门事件、宗门检测、机缘、场景鉴定或自我认知更新 `aptitude_rating_visibility`，不在检测现场临时生成资质。
3. 改变：突破、宗门培养、资源使用、伤势、道伤、燃寿、事件、功法、阵法、法宝和状态效果写入后天永久修正、临时修正、寿元来源或派生状态调整。
4. 结算：修炼、战斗、事件、资源输入、死亡与转世等系统按自身规则读取角色属性，不由本文规定固定结算顺序。
5. 展示：角色页面展示玩家可理解的当前世状态、资质揭示程度、重要后天修正、派生状态、寿元压力和不可用原因。

中断点包括死亡 / 转世、寿元耗尽、状态失效、伤势结算、资源炼化完成、突破成功或失败、检测结果更新和角色资料刷新。

## 5. 规则与状态

### 5.1 属性分层

| 层级 | 数据结构 | 作用 |
| --- | --- | --- |
| 基础属性 | `BaseAttributes` | 当前世身躯与状态底子，主要支撑派生状态上限和行动承受 |
| 修炼资质 | `AptitudeProfile` | 当前世修炼潜质、路线适配、学习理解和资源转化差异 |
| 派生状态 | `DerivedBars` | 当前可用生机、元气、神念及其保留容量 |
| 寿元状态 | `LifespanState` | 当前年龄、寿元上限、剩余寿元、寿元压力、延寿来源和年龄阶段入口 |
| 后天修正 | `acquired_modifiers` | 后天永久改变、临时修正、损伤、补偿和来历说明 |
| 伤势状态 | `injuries_and_conditions` | 伤病、道伤、心魔、药性、负面状态和持续影响 |

### 5.2 来源与持续性口径

基础属性和非灵根修炼资质使用同一套来源 / 持续性口径。

| 口径 | 含义 | 是否永久 | 记录要求 |
| --- | --- | --- | --- |
| 先天 | 出生、身躯生成、特殊开局或角色初始生成时确定的属性底子 | 是 | 写入对应属性的先天值或先天结构 |
| 后天永久 | 修炼、突破、宗门培养、资源、事件、伤损修复等形成的永久改变 | 是 | 写入对应属性的后天永久修正，并保留来源 |
| 临时 | 丹药、阵法、法宝、状态、伤势、事件阶段效果等形成的非永久修正 | 否 | 作为后天来源的临时修正记录，必须有持续时间、触发条件或失效条件 |

规则：

1. “先天”和“后天永久”都表示永久事实；非永久效果不得标记为先天或后天永久属性。
2. “临时”是持续性口径，不应回写到先天值或后天永久值。
3. 灵根在 MVP 仅支持先天口径；不得写入后天永久灵根或临时灵根。
4. 派生状态不使用先天 / 后天口径，只区分永久调整和临时修正。
5. 寿元状态不使用先天 / 后天 / 临时属性口径；寿元变化按来源事件记录。

### 5.3 基础属性

基础属性只保留当前世身躯 / 状态底子的基础字段，不包含可评级资质子项。

| 显示名 | 内部字段 | 主要作用 |
| --- | --- | --- |
| 体魄 | `base_physique` | 生机上限、负伤承受、肉身完整度、体力型行动承受、肉身类突破准备 |
| 精力 | `base_vigor` | 元气底子、持续行动承受、疲劳恢复、主动运转功法稳定性 |

规则：

1. 体魄与精力可以有先天值、后天永久修正和临时修正。
2. 年龄阶段可以影响体魄 / 精力的当前有效值，但它不是先天值、后天永久修正或临时增益。
3. 普通修为进度不直接增加体魄或精力。
4. 突破、宗门培养、资源使用、特殊事件或长期修炼路径可以少量改善体魄或精力，但必须写入来历记录。
5. `base_comprehension` 废弃；悟性只进入 `AptitudeProfile`。

### 5.4 修炼资质

修炼资质不是独立总等级。底层规则读取具体资质子项，UI 可以显示综合评价，但综合评价只用于提示和叙事。

| 显示名 | 内部字段 | 主要作用 |
| --- | --- | --- |
| 根骨 | `aptitude_bone` | 身体承载、经脉基础、修炼容器质量、部分突破准备 |
| 悟性 | `aptitude_comprehension` | 理解、参悟、功法学习、复杂路线掌握、非战斗技艺成长 |
| 灵根 | `aptitude_root` | 灵气亲和、路线适配、功法门槛、吸收方向 |
| 灵根相性标签 | `root_affinity_tags` | 灵根与路线、资源、节点环境、道功标签的匹配入口 |
| 灵根相性结构 | `root_affinity_profile` | 灵根相性的权重、主次标签和冲突标签结构 |

推荐可见性字段：

```text
aptitude_rating_visibility = unknown | partial | revealed
```

可见性含义：

1. `unknown`：角色尚未检测，不向玩家显示完整资质。
2. `partial`：只显示粗略评价、部分标签或疑似方向。
3. `revealed`：显示当前已确认字段和评级。

年龄阶段不得影响 `aptitude_bone`、`aptitude_comprehension`、`aptitude_root`、`root_affinity_tags` 或 `root_affinity_profile`。年龄、延寿、折寿、伤势或燃寿可以影响修炼、突破或灵根相关结算的外部条件、风险或压力，但不能改写资质有效值、灵根评级和相性结构。

### 5.5 灵根专项规则

灵根由“基础评级”和“相性结构”共同表达。

| 字段 | 说明 |
| --- | --- |
| `aptitude_root` | 灵根基础评级，表示角色对灵气、功法门槛和修炼路线的总体适配潜力 |
| `root_affinity_tags` | 相性标签，例如木、火、水、风、雷、阴、阳等路线、资源或环境标签 |
| `root_affinity_profile` | 标签权重、主次关系、冲突标签、适配阈值等更细结构 |

规则：

1. `root_affinity_tags` 不能单独代表全部灵根；`aptitude_root` 也不能替代相性标签。
2. UI 或世界观文本可以把灵根包装成单灵根、双灵根、异灵根、杂灵根等说法，但底层仍映射到 `aptitude_root`、`root_affinity_tags` 和 `root_affinity_profile`。
3. MVP 优先使用标签匹配，不做复杂五行循环、相生相克链或多层灵根谱系。
4. 灵根相性用于判断角色与主修道功、资源输入、修炼环境和节点灵气是否匹配。
5. 灵根不直接替代道功掌握度，也不直接替代根骨承载。
6. 法门与灵根的关系主要是使用相性：高相性可降低消耗、提升稳定性或降低门槛；低相性可增加消耗、波动、失败或反噬风险。
7. 影响灵根相关结算的外部效果可以存在，但不得回写为“临时灵根”或“后天灵根”。

### 5.6 派生状态

派生状态是当前世角色状态条，不是战斗内一次性资源。战斗结束后不默认回满。

| 状态 | 当前值字段 | 上限字段 | 保留值字段 | 用途 |
| --- | --- | --- | --- | --- |
| 生机 | `bar_vitality_current` | `bar_vitality_max` | `bar_vitality_reserve` | 健康、伤病、濒死、肉身完整度 |
| 元气 | `bar_qi_current` | `bar_qi_max` | `bar_qi_reserve` | 气力 / 法力 / 可支配能量 |
| 神念 | `bar_mind_current` | `bar_mind_max` | `bar_mind_reserve` | 灵魂、神识、心神稳定 |

规则：

1. 保留值字段统一使用 `reserve`，用于预留不可支配容量。
2. 保留值不得超过对应上限，当前值不得超过扣除保留值后的可支配上限；具体数值约束由数值文档维护。
3. 生机不是寿元。重伤、道伤、燃寿或突破失败可以同时影响生机与寿元，但必须分别写入对应状态。
4. 生机和元气可以读取已经承接年龄阶段影响的体魄 / 精力最终值；神念不读取体魄、精力、年龄阶段或悟性资质。
5. 神念可以在新手阶段 UI 隐藏或弱化展示，但数据层保留。

### 5.7 寿元与年龄阶段

寿元是当前世角色的最大时间预算，不只是死亡倒计时。它服务于当前年龄和剩余寿元展示、修炼与突破压力、延寿与折寿、燃寿、转世决策、年龄阶段入口和死亡 / 转世事件链。

推荐寿元状态字段：

```text
LifespanState {
  age: int
  lifespan_limit: int
  remaining_lifespan: int
  age_ratio: number
  aging_phase: childhood | growth | prime | aging | exhausted
  lifespan_pressure_state: safe | pressured | urgent | exhausted
  lifespan_extension_sources: Array
  pill_lifespan_extension_total: int
  pill_lifespan_extension_cap_ratio: number
  lifespan_risk_tags: Array
}
```

字段规则：

1. `age` 随世界时间推进。
2. `lifespan_limit` 是当前寿元上限。若外层 `CharacterState` 使用 `lifespan` 字段，语义等同于 `lifespan_limit`。
3. `remaining_lifespan`、`age_ratio`、`aging_phase` 和 `lifespan_pressure_state` 由年龄、寿元上限、风险标签和数值表派生，不应手动写成永久属性。
4. `lifespan_extension_sources` 记录突破延寿、资源延寿、宗门供养、秘境机缘、伤势折寿、道伤、燃寿、失败突破等来源。
5. 丹药延寿进入 MVP，但总量限制由寿元数值规则统一处理，不由丹药模板、丹药类型或单个丹药独立决定。
6. 丹药延寿超过有效上限时，超出部分不计入有效寿元上限，但仍应记录来源、原始延寿值、实际生效值和被上限钳制值。
7. 寿元压力必须可被玩家感知，并能引导稳健修炼、冒险突破、寻求延寿资源、请求宗门支持、布置后手、主动计划转世或继续硬冲等选择。
8. 寿元耗尽应触发死亡 / 转世事件链或延寿、续命、后手检查；后手检查只记录宗门遗产清点、宗门外洞府 / 普通藏宝线索和真灵藏宝状态，不把行囊或普通资源自动跨世继承。

### 5.8 属性改变与记录

| 字段范围 | 先天 | 后天永久 | 临时 | MVP 处理方式 |
| --- | --- | --- | --- | --- |
| `base_physique` | 支持 | 支持 | 支持 | 后天永久改变通过明确行动、突破奖励、宗门培养、资源使用或事件结果写入修正；临时改变写入临时修正 |
| `base_vigor` | 支持 | 支持 | 支持 | 后天永久改变通过明确行动、突破奖励、宗门培养、资源使用或事件结果写入修正；临时改变写入临时修正 |
| `aptitude_bone` | 支持 | 支持 | 支持 | 后天永久改变可通过洗髓、淬体、重塑经脉、炼体闭关、突破反馈等高成本路径改善；临时改变写入临时修正 |
| `aptitude_comprehension` | 支持 | 支持 | 支持 | 后天永久改变可通过参悟、讲法、读经、秘境悟道、事件反馈等路径改善；临时明悟或丹药效果写入临时修正 |
| `aptitude_root` | 支持 | 不支持 | 不支持 | MVP 只保留先天生成或特殊开局结果 |
| `root_affinity_tags` / `root_affinity_profile` | 支持 | 不支持 | 不支持 | MVP 只保留先天相性结构；外部效果写入状态、增益、资源、道功、法宝、阵法或事件记录 |
| `lifespan_limit` | 不适用 | 不适用 | 不适用 | 由突破延寿、资源延寿、宗门供养、伤势折寿、道伤、燃寿或失败突破等结果改变，并记录来源 |
| `age` / `age_ratio` / `aging_phase` | 不适用 | 不适用 | 不适用 | `age` 随世界时间推进；其他字段按数值规则派生 |

后天永久改变必须满足：

1. 有明确来历。
2. 有永久性标记。
3. 能解释给玩家。
4. 能进入角色履历、日志或状态说明。
5. 不把临时增益伪装成永久资质。

### 5.9 旧字段迁移

| 旧字段 / 旧口径 | 当前处理 |
| --- | --- |
| `physique` | 迁为 `base_physique` |
| `energy` 表示精力 | 迁为 `base_vigor` |
| `energy` 表示元气或行动消耗 | 迁为 `bar_qi_current` / `bar_qi_max` / `bar_qi_reserve` |
| `comprehension` / `base_comprehension` | 迁为 `aptitude_comprehension`；不得放入 `BaseAttributes` |
| `foundation` | 迁为 `aptitude_bone` |
| `spiritual_root_tags` | 拆为 `aptitude_root` + `root_affinity_tags` / `root_affinity_profile` |
| `derived_life` | 迁为 `bar_vitality_current` / `bar_vitality_max` / `bar_vitality_reserve` |
| `derived_qi` | 迁为 `bar_qi_current` / `bar_qi_max` / `bar_qi_reserve` |
| `derived_spirit` | 迁为 `bar_mind_current` / `bar_mind_max` / `bar_mind_reserve` |
| `lifespan` 表示寿元上限 | 迁为 `LifespanState.lifespan_limit`；若保留在外层 `CharacterState`，语义仍为寿元上限 |
| `age_percent` / 年龄% | 迁为 `LifespanState.age_ratio` |
| `aging_phase` 旧口径 | 保留为由年龄比例派生的年龄阶段，不作为可直接改写的永久属性 |
| `lifespan_pressure` / 寿元压力 | 迁为 `lifespan_pressure_state = safe | pressured | urgent | exhausted` |

## 6. 资源、角色、地图、事件或 NPC 接口

| 接口对象 | 读取 / 写入关系 |
| --- | --- |
| 真灵与执念 | 可以在新一世初始化时影响角色属性定型包、出生位置、初始物资和后手；不继承当前世年龄、寿元上限、普通行囊或派生状态 |
| 修炼系统 | 读取根骨、悟性、灵根、体魄、精力、派生状态、寿元压力和状态修正；具体公式由修炼数值文档维护 |
| 道功与法门 | 读取灵根相性、路线标签、元气 / 神念状态和掌握度；不得把灵根直接替代道功掌握 |
| 战斗系统 | 读取生机、元气、神念、体魄、精力、伤势和状态；战斗结束后不默认重置派生状态 |
| 资源、丹药、法宝、阵法 | 可以写入后天永久修正、临时修正、派生状态调整、寿元来源或灵根相关外部效果 |
| 事件系统 | 可以检测和改变属性、揭示资质、写入伤势、道伤、燃寿、延寿、压力标签和角色履历 |
| 死亡与转世 | 读取寿元耗尽、生机濒死、后手和真灵藏宝状态；承接当前世结算 |
| 角色页面 | 展示玩家可理解的属性、状态、寿元、揭示进度和重要来源，不展示原始公式追踪 |

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `base_attributes` | 基础属性结构，包含 `base_physique` 和 `base_vigor` |
| `aptitude_profile` | 修炼资质结构，包含根骨、悟性、灵根基础评级、灵根相性和揭示状态 |
| `derived_bars` | 派生状态结构，包含生机、元气、神念的当前值、上限、保留值和状态调整 |
| `lifespan_state` | 寿元状态结构，包含年龄、寿元上限、派生压力、延寿来源和风险标签 |
| `acquired_modifiers` | 后天永久修正和临时修正记录，需保留来源、持续性和失效条件 |
| `injuries_and_conditions` | 伤病、道伤、心魔、药性、负面状态和持续影响 |

建议结构：

```text
CharacterAttributeProfile {
  base_attributes: BaseAttributes
  aptitude_profile: AptitudeProfile
  derived_bars: DerivedBars
  lifespan_state: LifespanState
  acquired_modifiers: Array
  injuries_and_conditions: Array
}

BaseAttributes {
  base_physique: SourceTrackedAttribute
  base_vigor: SourceTrackedAttribute
}

AptitudeProfile {
  aptitude_bone: SourceTrackedAttribute
  aptitude_comprehension: SourceTrackedAttribute
  aptitude_root: InnateOnlyRootRating
  root_affinity_tags: InnateOnlyRootTags
  root_affinity_profile: InnateOnlyRootAffinityProfile
  aptitude_rating_visibility: unknown | partial | revealed
}

SourceTrackedAttribute {
  innate_value: number
  acquired_permanent_delta: number
  temporary_modifiers: Array
  effective_value: number
}

DerivedBars {
  bar_vitality_current: number
  bar_vitality_max: number
  bar_vitality_reserve: number
  bar_qi_current: number
  bar_qi_max: number
  bar_qi_reserve: number
  bar_mind_current: number
  bar_mind_max: number
  bar_mind_reserve: number
  permanent_adjustments: Array
  temporary_modifiers: Array
}
```

说明：

1. `SourceTrackedAttribute` 适用于基础属性和非灵根资质。
2. `effective_value` 是当前可被系统读取的实际值；具体计算由数值文档维护。
3. `InnateOnlyRootRating`、`InnateOnlyRootTags` 和 `InnateOnlyRootAffinityProfile` 体现 MVP 阶段灵根仅支持先天。
4. `DerivedBars.permanent_adjustments` 不区分先天 / 后天，只表示永久派生状态调整。
5. `LifespanState.remaining_lifespan`、`age_ratio`、`aging_phase` 和 `lifespan_pressure_state` 可以作为派生缓存，但事实来源仍是 `age`、`lifespan_limit`、风险标签和数值表。

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通角色页面应展示：

1. 当前世身份、年龄、寿元、剩余寿元、寿元压力、年龄阶段和宗门身份。
2. 基础属性：体魄、精力。
3. 修炼资质：根骨、悟性、灵根。
4. 派生状态：生机、元气、神念。
5. 当前主修道功、修为阶段、瓶颈 / 突破状态。
6. 残余资源效果、重要后天修正、伤势、风险标签和资质揭示程度。

普通 UI 不应展示：

1. 综合资质评价作为底层判定字段。
2. 灵根包装名作为唯一底层字段。
3. 真灵强度作为稳定修炼效率加成。
4. 执念容量作为传统属性点。
5. 体魄 / 精力的年龄阶段修正作为先天资质或后天永久提升。
6. 原始系数、公式缓存、内部 ID、调参表或 Debug 追踪。

## 9. MVP 范围

MVP 应实现：

1. 基础属性：体魄、精力。
2. 修炼资质：根骨、悟性、灵根基础评级、灵根相性标签和相性结构。
3. 资质揭示状态：`unknown`、`partial`、`revealed`。
4. 派生状态：生机、元气、神念的当前值、上限和保留值。
5. 寿元状态：年龄、寿元上限、剩余寿元、寿元压力、年龄阶段、延寿来源和风险标签。
6. 来源 / 持续性记录：先天、后天永久、临时、永久派生状态调整、寿元来源。
7. 旧字段迁移口径。
8. 丹药延寿作为寿元来源之一，并由寿元数值规则统一限制有效总量。

MVP 不实现：

1. 后天永久灵根改写或临时灵根。
2. 复杂五行循环、相生相克链和多层灵根谱系。
3. 单一资质总分参与核心判定。
4. 真灵继承当前世寿元、年龄、普通行囊或派生状态。
5. 派生状态战斗后自动回满。
6. 角色属性模块替其它系统规定固定结算顺序或倍率。

## 10. 验收约束

1. 包内文档引用角色属性系统层时，应以本文为字段语义和规则来源。
2. 任何公式、系数、倍率、年龄曲线、缓存字段和调参边界不得在本文重复维护，应指向数值文档。
3. `base_comprehension` 不得恢复为基础属性；悟性只作为 `aptitude_comprehension`。
4. 年龄阶段不得影响根骨、悟性、灵根、灵根相性或神念基础值。
5. 生机不得被当作寿元；寿元也不得作为战斗内临时资源。
6. MVP 阶段不得出现后天灵根、临时灵根或把外部效果写回灵根字段。
7. 后天永久改变必须有来源记录；临时修正必须有持续时间、触发条件或失效条件。
8. 丹药延寿不得由丹药文档单独决定总量上限，必须承接寿元数值规则。
9. UI 可以隐藏未揭示资质，但数据层不得因此延迟生成资质。
