# 物品设计｜法宝

## 1. 文档定位

本文统一收敛法宝相关设定。旧资料中出现的“法器”如未专指另一个低阶物品品类，当前先并入“法宝”口径；后续若需要区分法器、灵器、法宝等阶层，应在法宝模板表中作为品类或阶层字段拆分，不另开并行系统。

法宝是高价值可用资产，可以参与战斗、事件、防护、突破支持、后手封存、遗产分配、修复拆解和资源循环。它不是装备栏插槽，也不是固定战力挂件，而是可被投入、消耗、损坏、追踪和回收的实例物品。

法宝进入后手或遗产时不改变资产规则：宗门个人洞府中的法宝可随遗产清点回收宗门；宗门外洞府或普通藏宝中的法宝属于无主遗留设施资产，需要开启条件或破阵结果才能取出；真灵藏宝中的法宝作为正式后手，必须占用真灵藏宝数量或容量限制。

## 2. MVP 总结论

MVP 中法宝采用以下边界：

1. 不做传统装备栏、换装备、换法宝系统。
2. 不以装备位或物品栏格子决定法宝是否可用。
3. 不引入携带容量数值、重量、体积、背包格子或通用负重玩法。
4. 物品栏数量只保留程序层上限，作为性能、存档和异常防护限制，不作为玩法层上限。
5. 法宝是否可用于行动、事件或战斗，由随身状态、上下文、标签、权限、绑定、状态、耐久、充能和资源消耗共同决定。
6. 高价值法宝必须作为 `ItemInstance` 追踪来源、状态、归属、可见性和日志。
7. 储物空间法宝在 MVP 不开发独立玩法系统，只保留基础概念；角色绑定不是独立法宝类型，而是法宝实例上的绑定状态标记。

## 3. 基础定位

法宝至少承担以下一种角色：

| 角色 | 规则含义 | MVP 口径 |
| --- | --- | --- |
| 主动型法宝 | 提供可主动投入的行动、事件或战斗指令 | 可作为最小法宝闭环 |
| 被动型法宝 | 满足条件时提供持续、触发、抵消、防护、预警或抗性效果 | 可作为最小法宝闭环 |
| 辅助型法宝 | 支持突破、修炼、移动、探索、封印、侦测、修复等非战斗场景 | 可按事件或行动入口处理 |
| 储物空间法宝 | 基础行囊的升级概念，表现为特殊资产容器或容器入口 | MVP 不开发玩法，只保留概念 |

主动型法宝数量过多不会线性提高战斗收益。限制来自交锋格、行动入口、元气、神念、生机、耐久、充能、道具消耗、触发条件、事件限制和克制关系，而不是装备栏位。

被动型法宝不是免费常驻护盾。只要它在战斗或事件中承担防护、抵消、转移、镇压、预警、抗性或替角色承受后果，就可以进入法宝状态变化判定。

角色绑定不属于 `artifact_kind`，也不进入法宝类型表。它只表示某件法宝实例当前是否与角色建立绑定关系，并通过 `bind_state`、`bound_target_ref`、`theft_protection`、`destroy_policy` 等字段表达。

## 4. 可用性规则

法宝可用性由以下条件共同决定：

1. 资产是否位于可调用范围，例如随身携带、事件允许调用或已被当前行动预留。
2. 法宝是否具备当前场景所需标签，例如 `combat_ready`、`event_ready`、`breakthrough_support`、`storage_artifact`。
3. 当前角色状态是否允许驱动法宝，例如未被封印、昏迷、压制或禁用相关能力。
4. 当前行动、事件、战斗或突破阶段是否允许该类法宝参与。
5. 绑定、权限、宗门身份、位置、可见性和封存状态是否满足。
6. 耐久、充能、灵性、损坏状态是否满足最低使用条件。
7. 法宝使用需要的元气、神念、生机、材料、聚灵石或其他资源是否足够。

系统可显示暂时不可用的法宝，但必须给出明确原因，例如资源不足、状态破损、当前场景不允许、绑定对象不符或资产不在可调用范围内。

## 5. 战斗规则

战斗开始时，系统读取角色可调用范围内的法宝、消耗道具和已掌握术法神通，并根据当前战斗规则生成可用指令列表。

主动型法宝：

1. 可生成攻击、防御、控制、恢复、逃遁、护体、照魂、封禁等指令。
2. 通常需要占用战斗交锋格、事件选择或行动入口。
3. 可以消耗元气、神念、生机、法宝耐久、法宝充能、使用次数或特定材料。
4. 使用后可能产生受损、失灵、充能下降、灵性下降或破碎。

被动型法宝：

1. 不占用主动交锋格，但必须满足触发条件。
2. 可以抵消伤害、抵抗状态、预警危险、转移后果、护持神魂或降低环境影响。
3. 触发后可能消耗耐久、灵性或充能。
4. 若替角色承受后果或遭到针对性破坏，也可能受损、失灵或破碎。

法宝不是完整装备耐久系统。MVP 只保留法宝自身状态变化与结果回写，不扩展为所有装备的耐久玩法。

## 6. 状态与生命周期

法宝状态变化包括：

1. 主动使用后受损。
2. 被动触发后受损。
3. 被敌方、环境、阵法、秘境规则或突破外扰针对后受损。
4. 失去充能、使用次数或临时可用性。
5. 灵性消耗、压制或衰弱。
6. 暂时失灵。
7. 破碎或销毁。
8. 战后修复。
9. 拆解回收材料、核心组件、灵性残片或污染物。
10. 作为后手、遗产、宗门资源或战利品重新进入资源循环。

MVP 不引入法宝自然灵性衰退、非事件型自然损耗或复杂保养系统。法宝损耗主要来自主动使用、被动触发、战斗破坏、事件代价、突破外扰或明确结果包。

死亡、战利品、遗产和后手分配必须等待战斗或事件链完成后结算，避免法宝损坏、现场控制权、合法战利品归属尚未确定时提前分配资产。正式后手不等于死亡后自动继承全部法宝；只有已封存进真灵藏宝并满足同一真灵开启条件的法宝，才按正式后手取出。

## 7. 储物空间法宝

储物空间法宝是基础行囊的升级版本概念。它可以被理解为一个特殊法宝实例，附带储物能力或资产容器入口。

MVP 边界：

1. 不开发独立储物空间法宝玩法。
2. 不设置玩法层物品栏数量上限。
3. 不做负重、重量、体积、背包格子、容量成长或空间扩容玩法。
4. 物品栏数量只保留程序层上限，用于性能、存档和异常防护。
5. 储物空间法宝不得绕过资产位置、权限、可见性、交易、事件、战斗或后手日志。
6. 若作为叙事或奖励出现，先按普通法宝实例记录，不开放独立取放、扩容、偷取、掉落或容量结算规则。
7. 储物空间法宝不得绕过宗门遗产清点、无主遗留设施开启条件或真灵藏宝数量容量限制。

未来若开发储物空间法宝，应仍然遵守资产容器原则：内部物品需要有容器、权限、可见性和日志；法宝本体被转移、损毁、封存或绑定时，内部资产去向必须有明确规则。

## 8. 角色绑定状态

角色绑定不是独立法宝类型，而是法宝实例的绑定与否状态标记。当前明确会使用角色绑定状态的对象是储物空间法宝。其他法宝是否允许角色绑定、是否存在真灵绑定、宗门授权、后手封存绑定等规则，暂不进入 MVP。

基础概念：

1. `bind_state = character_bound` 表示该法宝实例绑定当前世角色。
2. 绑定后的法宝不会被普通窃取、扒取、战利品拾取或库存转移直接拿走。
3. 绑定对象死亡后，绑定法宝自主损毁，不作为遗产进入战利品或后手分配。
4. 自主损毁必须写入结果和资产日志，说明损毁发生于绑定对象死亡结算。
5. 绑定不等于跨世继承，不默认进入真灵资产，也不默认绕过后手容量。

MVP 不开发完整认主、解绑、改绑、解除窃取保护、绑定继承、绑定冲突、绑定修复或绑定追踪玩法。若后续需要，只能在本文状态字段基础上扩展。

## 9. 数据字段口径

法宝是 `ItemInstance` 的特殊用法，不另建脱离物品系统的资产形态。字段命名统一如下：

```yaml
ArtifactInstance:
  item_instance_id: string
  item_template_id: string
  container_id: string
  quality: string
  tags: list
  artifact_kind: active | passive | support | storage | hybrid
  artifact_role_tags: list
  availability_tags: list
  active_command_refs: list
  passive_effect_refs: list
  durability_state: intact | worn | damaged | broken
  charge_state: integer | null
  spirituality_state: stable | strained | depleted | null
  bind_state: unbound | character_bound
  bound_target_ref: string | null
  theft_protection: none | bound_unstealable
  destroy_policy: none | destroy_on_bound_target_death
  storage_container_ref: string | null
  visibility_policy: string
  source_ref: string
  ledger_refs: list
```

字段统一说明：

| 字段 | 统一口径 |
| --- | --- |
| `item_instance_id` | 法宝实例 ID，继承物品实例身份 |
| `item_template_id` | 法宝模板 ID，承载品类、阶层、基础效果 |
| `container_id` | 当前资产容器，不使用 `owner_container_ref` |
| `artifact_kind` | 法宝主要功能类型，不包含绑定状态 |
| `artifact_role_tags` | 攻击、防护、储物、突破支持、侦测等角色标签 |
| `availability_tags` | 当前是否可用于战斗、事件、突破、储物等上下文 |
| `durability_state` | 耐久状态使用枚举，不在概念文档中写具体数值公式 |
| `charge_state` | 当前充能或可用次数；无充能机制时为 `null` |
| `spirituality_state` | 法宝灵性状态，避免与真灵字段混淆 |
| `bind_state` | MVP 只保留 `unbound` 与 `character_bound` |
| `bound_target_ref` | 绑定对象引用；MVP 概念上指当前世角色 |
| `theft_protection` | 绑定后的不可被窃取规则 |
| `destroy_policy` | 绑定对象死亡后的自主损毁规则 |
| `storage_container_ref` | 储物空间法宝未来可能关联的内部容器；MVP 不启用玩法 |
| `ledger_refs` | 高价值资产变化、损毁、修复、封存、转移和回收日志 |

旧字段口径收敛：

| 旧口径 | 统一为 |
| --- | --- |
| `ArtifactState.artifact_id` | `ArtifactInstance.item_instance_id` |
| `owner_ref`、`owner_container_ref` | `container_id`；绑定对象另用 `bound_target_ref` |
| `carried_state` | 资产位置由容器表达，可用性由 `availability_tags` 表达 |
| `spirit_state` | `spirituality_state` |
| `combat_ready` | `availability_tags` 中的 `combat_ready` |
| 旧跨世绑定字段 | 不作为 MVP 法宝字段；后手封存由资产容器、后手记录和日志表达 |

## 10. 资源、修复与回收

法宝使用、修复、拆解和回收必须进入资产流水或结果包。

法宝可能消耗：

1. 元气、神念、生机。
2. 法宝耐久。
3. 法宝充能或使用次数。
4. 材料、灵材、聚灵石或专用修复资源。
5. 事件代价、后手容量或封存资源。

法宝修复、拆解和回收暂不写具体公式。MVP 可保留接口，但不需要完整炼器、保养、拆解收益和灵性恢复系统。

## 11. 待补与不进入 MVP

以下内容不在当前 MVP 开发范围内：

1. 完整法宝类型表、品质表、品阶表和词条表。
2. 完整主动 / 被动法宝效果表。
3. 法宝伤害公式、耐久公式、充能公式、灵性恢复公式。
4. 储物空间法宝容量成长、扩容、取放、偷取、掉落和内部资产继承玩法。
5. 法宝角色绑定状态的认主、解绑、改绑、跨世继承、真灵绑定和绑定冲突玩法。
6. 法宝自然灵性衰退和复杂维护系统。
7. 完整炼器系统和装备化战力栏位。
