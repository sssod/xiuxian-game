# 项目总览、MVP 边界与系统依赖（v2.2）

## 0. 文档定位

本文是新版开发交付口径下的项目总览，用于替代旧版“季度推进 + 6 朔望行动格 + 宗门主行动输入”的顶层描述。

本文回答：

1. 这款游戏是什么。
2. MVP 到底要做到什么程度。
3. 回合、个人行动、宗门 AI 与世界演化之间如何协作。
4. 哪些内容明确不是 MVP。
5. 开发实现时应按什么顺序拆分。

---

## 1. 一句话定位

本项目是一款支持本地单人测试、私人服务器部署、3 人共玩的房间制多人修仙轮回沙盒。

玩家控制的不是宗门、国家或固定角色，而是一点跨世延续的真灵。每一世的当世角色会修炼、加入宗门、移动探索、争夺资源、突破失败或成功、死亡转世、布置后手，并在共享地图中影响宗门与世界节点演化。

新版推荐开发定位：

```text
回合制房间
+ 跨世角色成长
+ 指令式个人行动
+ 宗门 AI 资源平台
+ 节点地图沙盒
+ 功法掌握与行动资源输入
+ 事件链权威结算
```

---

## 2. MVP 边界

当前 MVP 不按商业化版本、Steam EA 或正式发售内容量定义。

MVP 边界固定为：

```text
本地可单人测试
+ 可部署私人服务器
+ 支持 3 人共玩
+ 可保存、暂停、恢复、续开
+ M0 → M3 纵向闭环可跑通
```

最低验证目标不是“玩家抵达 M3 就算成功”，而是在 M0 到 M3 的过程中自然验证：

- 至少一段关键突破链。
- 至少一次宗门中高层身份或等价世界影响。
- 至少一次轮回、前世信息、正式后手或跨世反馈。
- 至少一次节点资源竞争、节点局势变化或控制权相关变化。
- 至少一次多人间接竞争或 AI 宗门造成的等价竞争压力。

## 3. 顶层设计承诺

### 3.1 跨世主体感

玩家长期身份来自真灵，而不是某一世的姓名、宗门职位或库存。死亡和转世不是简单重开，而是把前世信息、失败标签、后手、真灵强度和部分初始化选择转化为下一世策略基础。

### 3.2 有压力的时间选择

游戏以“回合”推进。每回合对应的游戏天数由配置决定，当前默认 5 个游戏天。

玩家不能在同一回合同时完成所有目标。修炼、移动、探索、宗门职责、后手回收、突破准备、事件响应都必须竞争同一个回合时间预算。

本版不再使用“每季度 6 个朔望行动格”作为底层约束。玩家看到的是以天为刻度的回合时间预算条，服务端以小时为内部结算单位。

### 3.3 指令式个人行动

玩家每回合输入少量线性个人行动指令，而不是排小时表。

典型指令：

```text
前往镇集
坊市采购避瘴符
前往黑石岭
探索黑石岭，投入 3 天
```

系统将指令映射到天级预算条，并在结算时以小时推进。

### 3.4 突破风险感

突破不是概率按钮。大境界突破由准备度门槛、关键突破物、风险提示、固定执行时间、专用事件链、失败标签和轮回账本构成。

### 3.5 功法与资源转化感

功法不是散装篇章等级，而是完整载体学习后的掌握度成长。道功决定主修路线、当前有效上限、单位时间收益和突破模板读取；法门提供战斗、探索、采集、生产和事件能力。

丹药、灵材、符箓和临时增益资源不绕过时间预算。它们作为行动资源输入绑定到主动吐纳、研习、探索、治疗、突破事件选项等具体语境，并按实际兼容小时结算。

### 3.6 后手可信感

玩家正式布置的后手必须可追踪、有日志、有位置、有封存资产、有暴露或失效原因链。正式后手可以受损或被争夺，但不能无理由消失。

### 3.7 宗门平台感

宗门不是玩家本体，而是组织性资源平台。宗门拥有库存、权限、节点控制、常态运营和唯一宗门持续行动。

本版移除玩家在决策阶段直接发布宗门即时命令或提交宗门主行动建议的流程。宗门由 AI 自行演化。玩家通过身份、职位、贡献、门内声望、资源申请、关键 NPC 支持、亲自参与和事件结果间接影响宗门。

### 3.8 共享世界演化感

地图节点、资源槽、建筑槽、秘境窗口、宗门 AI 持续行动、世界事件、传闻、玩家行动共同改变世界。多人不是强 PvP，而是共享世界中的间接竞争。

## 4. 标准回合流程

新版标准回合流程统一为：

```text
回合开始，时间暂停
→ 上一回合结算汇总报告
→ 玩家查看角色、地图、宗门、账本、传闻和风险提示
→ 个人即时行动
→ 个人行动指令预输入
→ 在线玩家锁定行动
→ 离线 / 超时玩家生成稳健托管
→ 权威服务器统一结算
→ 必要时插入事件链
→ 回写角色、库存、节点、宗门、账本、日志、传闻
→ 生成“原计划 vs 实际结果”报告
→ 进入下一回合
```

开发重点：

- 客户端只提交意图。
- 服务端负责权威校验和最终回写。
- 本地单人也走同一套服务端结算流程。
- 无人在线时世界不自动推进。
- 宗门 AI 不需要玩家输入阶段即可推进。

## 5. 修炼里程碑与阶段编码

MVP 验证使用 M0 / M1 / M2 / M3 表达玩家流程里程碑。

```text
M0：开局与入门阶段。
M1：完成第一阶段修行闭环，具备第一次关键突破准备。
M2：突破到第二大境界，进入宗门中层影响区。
M3：突破到第三大境界起点，进入宗门高层身份 / 世界影响体验。
```

规则层境界编码统一使用：

```text
A-1, A-2, A-3
B-1, B-2, B-3
C-1, C-2, C-3
```

M3 不是 `C-3`，而是第三大境界起点，通常对应 `C-1`。

规则代码不得直接判断 `lianqi`、`zhuji`、`jindan` 等世界观包装字符串。包装名只作为本地化显示。

## 6. 顶层非目标

MVP 不做以下内容：

- 实时 MMO。
- 现实时间挂机私服。
- 纯宗门经营游戏。
- 强 PvP 沙盒。
- 玩家直接交易、直接赠予、共同秘境、互相护法。
- 玩家暗杀玩家、直接抢洞府、围杀转世角色、破坏他人突破、离线袭击玩家主体。
- 深度 NPC 生态和所有 NPC 全量经济模拟。
- 完整高境界体系。
- 大规模宗门战争。
- 完整炼丹炼器工业链。
- 玩家直接控制宗门行动队列。
- 宗门内部派系 / 山头作为 MVP 系统变量。

## 7. 子系统依赖图

建议以 S1 作为结算总线，其他系统不得绕过 S1 直接改写世界状态。

```text
S14 数据驱动 / 存档 / 调试
        ↑
S1 房间回合阶段机 / 权威结算总线
        ↑
S3 个人行动经济 / 移动 / 小时结算时间轴
        ↑
S10 事件链框架 ── 战斗事件链
        ↑              ↑
S4 突破事件链 ────────┘
        ↑
S2 角色 / 真灵 / 轮回 / 养成
S2A 功法 / 行动资源输入 / 残余效果

S5 宗门组织 / 权限 / 宗门 AI 持续行动
S6 经济 / 物品 / 资产容器
S8 地图节点 / 世界演化
S11 后手 / 遗产 / 隐藏层
S13 可见性 / 多人间接竞争
```

核心原则：

```text
客户端提交意图
→ 服务端校验
→ 服务端生成小时级时间线
→ 子系统输出结果包
→ S1 合并结果包并回写状态
→ 写入日志、存档与回放
```
