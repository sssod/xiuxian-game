# 修仙轮回沙盒｜项目总览与顶层设计定案 0424

## 0. 页面用途

本文是新的 Notion 项目页，用于汇总《修仙轮回沙盒：顶层设计方案完善版_0424-1653》与本轮新增决策收敛项。

本页作为后续 S1–S14 子系统文档的上位约束。后续讨论应优先以本页为准，不再从零重议项目定位、核心循环、MVP 边界和主要系统职责。

## 1. 当前项目状态

顶层设计已经基本收束。已定内容包括：项目定位、玩家主体、房间形态、时间推进、修炼里程碑、行动经济顶层结构、轮回与后手原则、突破系统、宗门系统、节点地图、多人与托管边界、MVP 验收口径、世界生成方式、战斗/斗法定位、内容生产策略和 Godot 技术路线。

后续不应继续在顶层展开公式、阈值、事件表、UI 字段、AI 权重或具体数值平衡。这些内容应进入子系统文档。

## 2. 项目一句话定位

本项目是一款面向 Steam 买断制长期方向、支持局域网 / 私人服务器部署、可存档续开的房间制多人修仙轮回沙盒。

玩家控制的核心不是宗门、国家或势力，而是一个跨世延续的修行主体。玩家在多世轮回中修炼、突破、死亡、转世、布置后手、回收遗产、加入宗门、影响宗门、争夺资源并改变世界格局。

> 玩家扮演一个跨世延续的真灵 / 修士主体，在一个可保存、可续开、可多人共享的修仙沙盒世界中，通过个人修炼、突破风险、转世继承、后手布局、宗门影响、节点探索和资源竞争，逐步推进到更高修炼层级。
> 

## 3. 当前 MVP 边界

本轮最新决策对 MVP 边界进行了修正。

当前 MVP 不按商业化、Steam EA、正式发售或首发内容量定义。

当前 MVP 边界为：

> 本地可单人测试、可部署私人服务器、支持 3 人共玩。
> 

具体含义：

- 本地环境下可以单人完整跑通 M0→M3 纵向闭环。
- 可以部署私人服务器并保存房间状态。
- 至少支持 3 名玩家在同一房间中共玩。
- 服务器支持多人季度推进、离线 / 超时托管、宗门与地图统一结算。
- 暂不考虑 Steam 上架、EA 包装、正式商业版本内容量、DLC、创意工坊或商业运营策略。

长期商业定位仍可保留 Steam 买断制方向，但不作为当前 MVP 验收条件。

## 4. 顶层设计承诺

项目需要交付六个核心承诺：

1. 跨世主体感：玩家不是只玩一条生命，而是在多世之间持续经营一个真灵主体。
2. 有压力的修炼选择：季度回合必须带来取舍，玩家不能在同一季度同时完成所有事情。
3. 突破风险感：突破不是概率按钮，而是准备度门槛 + 多阶段事件链。
4. 后手可信感：玩家正式布置的重要后手必须可追踪、可调查、有日志。
5. 宗门平台感：宗门是组织性资源平台，不是玩家本体。
6. 共享世界演化感：地图节点、宗门资源、秘境窗口、区域控制、节点事件、AI 宗门策略和玩家行动共同改变世界。

## 5. 顶层非目标

MVP 不追求以下内容：

- 不是实时 MMO。
- 不是现实时间挂机私服。
- 不是纯宗门经营游戏。
- 不是强 PvP 沙盒。
- 不做玩家暗杀玩家、直接抢洞府、围杀转世角色、主动破坏他人突破、离线袭击玩家主体。
- 不做深度 NPC 生态。
- 不做完整高境界体系。
- 不做大规模宗门战争。
- 不做创意工坊或商业化包装。

## 6. 房间、时间与推进结构

### 6.1 房间形态

采用中局制、可存档续开的多人房间。

特征：

- 支持本地单人测试。
- 支持私人服务器部署。
- MVP 至少支持 3 人共玩。
- 支持保存、暂停、恢复和多次续开。
- 不要求一局一次打完。
- 不在无人在线时自动推进世界。

### 6.2 时间单位

采用：

> 季度回合 + 关键事件插入链。
> 

普通季度负责稳定推进；关键事件链负责承载突破、死亡、转世、秘境、遗产争夺、重大节点危机等高价值事件。

### 6.3 标准季度流程

1. 季度开始。
2. 世界刷新：节点事件、秘境窗口、宗门动态、市场波动、机缘线索。
3. 玩家查看角色、地图、宗门、轮回账本、风险提示。
4. 进入宗门行动决策阶段。
5. 系统即时反馈宗门行动决策结论。
6. 进入角色行动决策阶段。
7. 玩家以 6 个朔望行动格规划本季度角色行动。
8. 在线玩家锁定行动。
9. 离线 / 超时玩家执行稳健托管。
10. 权威服务器统一结算。
11. 触发必要插入事件链。
12. 更新日志、地图、宗门、账本、角色状态。
13. 进入下一季度。

## 7. 修炼里程碑与境界编码

### 7.1 修炼里程碑

MVP 验证目标使用 M0 / M1 / M2 / M3 表达。

```
M0：开局与入门阶段
M1：完成第一阶段修行闭环，具备第一次关键突破准备
M2：突破到第二大境界，进入宗门中层影响区
M3：突破到第三大境界起点，进入宗门高层决策体验
```

默认世界观包装可以是：

```
M0：炼气初入 / 入道初始
M1：炼气圆满 / 第一次大突破前
M2：筑基 / 道基成型
M3：金丹初成 / 凝核 / 第三大境界起点
```

M3 不是 `C-3`，而是第三大境界起点，通常对应 `C-1` 或同等包装。

### 7.2 境界内部编码

系统实现不应直接使用 `lianqi`、`zhuji`、`jindan` 作为规则判断 ID。

推荐使用：

```
A-1, A-2, A-3
B-1, B-2, B-3
C-1, C-2, C-3
```

规则判断使用解析后的数值字段，而不是字符串比较。

```
CultivationStage {
  code: "C-1"
  major_code: "C"
  minor_index: 1
  major_order: 3
  absolute_order: 301
  display_name_key: "stage.core_3_minor_1"
}
```

MVP 和中期版本只支持单字母大境界 A-Z，不提前启用 AA / AB / BA 等多字母编码，但保留未来迁移能力。

## 8. MVP 验收口径

MVP 验收不只看玩家是否抵达 M3。

MVP 应验证：

> 玩家从 M0 到 M3 的过程中，是否自然经历并验证关键突破、宗门高层影响、后手或跨世反馈、节点资源竞争或控制变化。
> 

最低验收应包括：

- 至少一段关键突破链。
- 至少一次宗门高层影响或等价世界影响能力。
- 至少一次后手、轮回、前世信息或跨世反馈。
- 至少一次节点资源竞争、节点局势变化或控制权相关变化。

M3 是 MVP 纵向闭环验证点，不是强制终局。M3 后仍可继续游玩。

## 9. 单局节奏目标

MVP 采用标准中局节奏。

顶层目标为：

- M0→M3 需要多次续开完成。
- 单次游玩应能完成一个清晰阶段性目标。
- 阶段性目标可以是突破准备、关键突破、秘境事件、后手追踪或回收、节点争夺、宗门职位推进等。
- 具体季度数、收益速度和失败后的复起时间下沉到子系统和平衡文档。

MVP 应有足够长度和风险，使死亡、突破失败、计划转世、真灵延续、遗产暴露或前世后手回收等跨世机制自然出现，但不强制每名玩家都必须死亡一次。

## 10. 单人体验地位

单人房必须是一等公民。

设计原则为：

- 单人 + AI 宗门必须能完整体验核心闭环。
- 多人是在单人 PvE 宗门沙盒基础上加入真实玩家变量。
- 核心乐趣不依赖高频玩家直接互动。
- AI 宗门、节点事件、资源窗口和宗门竞争必须能为单人玩家提供足够外部压力。

## 11. 世界生成方式

MVP 采用半固定种子地图。

原则为：

- 核心宗门、主路线、关键节点固定，保证内容质量和调试稳定性。
- 资源槽、节点事件、秘境窗口、部分隐藏层和后手挂载允许半随机。
- 可复玩性主要来自半随机世界状态、玩家路线选择、突破结果、后手布局和宗门节点演化。

## 12. 行动经济顶层方案

行动经济采用：

> 宗门行动 + 角色行动的双层季度结构。
> 

每个季度先进行宗门行动决策，再进行角色行动决策。

术语约束：后续规则文档、UI 文案和接口命名统一使用“宗门行动阶段、角色行动阶段、6 个朔望行动格、即时行动、移动行动、持续行动”。行动经济规则描述不得再使用已废弃的历史表达。

### 12.1 宗门行动阶段

宗门行动代表组织层面的资源调度和世界介入，一般不受玩家角色当前位置限制。

玩家通过身份、职位、贡献、门派内声望、关键 NPC 好感度和权限影响宗门行动。

宗门行动使用底层行动格、路线、交通方式和节点规则，但上层由系统自动寻路、自动选择交通方式，并生成可读的决策预览。

玩家不需要逐格配置宗门队伍行程。

### 12.2 角色行动阶段

角色行动在宗门行动决策反馈之后进行。

玩家以 6 个朔望行动格规划当前角色本季度的行动。

行动格用于表达：移动、执行、介入、撤出、休整、等待 / 留驻。

这里的 6 个行动格不是 6 次完整独立行动，而是本季度时间预算。

### 12.3 移动与交通

移动不作为默认独立行动税，但会占用角色行动格。

移动的作用是改变本季度的时间分配、风险暴露、行动投入和结束位置。

交通方式决定速度、消耗、暴露、风险、可用路线、所需节点设施或权限。

传送阵、公共大型飞舟、渡口、驿站等特殊交通方式需要在抵达对应节点后手动使用，不进入玩家角色的自动寻路。

## 13. 玩家角色、真灵与轮回

玩家核心身份是角色 / 真灵 / 个人修行主体，不是宗门。

转世继承采用规划型转世继承，分为内在继承与外在继承。

### 13.1 内在继承

内在继承绑定真灵，包括：真灵强度、前世数量、大道感悟、重大突破经验、命格痕迹、因果债务、失败原因记录、对关键地点或事件的感应。

### 13.2 外在继承

外在继承存在于世界，包括：洞府、藏宝地点、功法玉简、丹药、灵石、法器、接引阵、遗书和任务链、宗门密库权限、护道人、弟子、道侣安排、秘境入口线索。

### 13.3 正式后手

只有经过正式行为封存、布置、记录或标记的后手，才进入轮回账本。

轮回账本不是全世界物品历史表，而是玩家正式后手的可信追踪系统。

核心传承不能无理由永久抹除。外部资产可以被争夺、破坏、搬空、污染或转移，但必须有原因、日志或追查路径。

## 14. 突破系统顶层方案

突破采用：

> 准备度门槛 + 多阶段事件链。
> 

突破输入包括：修为积累、修为纯度、肉身强度、心境稳定、功法匹配、突破资源、护法力量、突破地点、节点灵气、宗门培养支持、因果负担、前世失败经验。

突破结果至少包括：

- 完美突破。
- 正常突破。
- 残缺突破。
- 失败但存活。
- 身死转世。
- 严重失败并附带真灵受损、因果加重或遗产暴露。

失败必须输出原因标签，例如修为虚浮、肉身不足、心境不稳、因果过重、功法不合、护法不足、地点灵气不足、资源品质不足。

失败原因进入轮回账本，成为下一世优化路线的依据。

## 15. 宗门系统顶层方案

宗门是组织性资源平台，不是玩家本体。

宗门在世界中独立存在，玩家可以加入、影响、利用、离开或转世后重新接触。玩家死亡、叛出、转世或失势后，宗门继续由 AI 托管演化。

MVP 宗门采用抽象实现，正式版向半模拟扩展。

### 15.1 宗门资源

MVP 宗门追踪五类资源：灵石、修炼资源、材料 / 矿材、人力 / 弟子规模、声望 / 影响力。

宗门发放给玩家或 NPC 的资源必须来自真实库存。

贡献不是货币，不可直接兑换资源。

### 15.2 宗门身份层级

MVP 宗门身份层级为：外门弟子、内门弟子、真传弟子、执事、长老。

MVP 不开放宗主职位。

进入 M3 里程碑后，玩家应能够体验长老序列或等价高层决策，而不是只停留在弟子成长阶段。

### 15.3 宗门行动

MVP 宗门行动包括六类：开采、驻守、探索、远征、建设、培养。

这些行动改变宗门库存、节点资源、建筑状态、宗门影响力、控制权事件、玩家贡献和声望、秘境、后手和世界事件窗口。

## 16. 地图与节点顶层方案

地图采用有向带权节点图。

节点间连接支持双向但成本不同、单向门、权限门、状态门、风险门、隐藏路线、临时通道。

地图主单位是地理节点。

资源和建筑不是独立漂浮物，而是挂载在地理节点上的槽位层。

一个节点可包含：地理属性、基础资源槽、人工建筑槽、控制权、宗门影响力、驻守状态、事件槽、隐藏层、前世后手层。

MVP 节点建议包括：宗门山门节点、城镇 / 坊市节点、资源型地理节点、荒野探索节点、秘境入口节点、前世后手节点 / 隐藏层、禁地 / 高危节点。

节点归属采用控制权 + 影响力混合模型。

控制权决定主资源收益权、建设权、驻守权、通行管理权、节点事件优先响应权。

影响力决定行动成本、情报发现率、任务成功率、探索与交易便利、控制权争夺基础、对控制者收益的轻微竞争。

控制权变更采用阈值 + 事件模型。玩家不需要逐个节点点击“接管”，而是通过探索、驻守、建设、开采、处理事件和削弱对手影响力推动节点易主。

## 17. 多人互动 MVP 定案

MVP 多人默认倾向采用：

> 分宗并行 + 间接竞争 + PvE 沙盒演化。
> 

MVP 不以玩家之间的直接合作、直接对抗或频繁社交互动作为核心验证目标。

每名玩家主要经营自己的修行路线和宗门影响，而世界中其他宗门的竞争、扩张、资源占用和节点控制变化构成外部压力。其中某个竞争宗门背后可能也有真实玩家在出谋划策。

MVP 默认鼓励玩家加入不同宗门，但不硬性禁止同宗。

MVP 只保留两类轻量、间接的多人竞争：

1. 宗门节点控制竞争。
2. 世界资源名额竞争。

玩家直接交易、赠予、互相护法、共同秘境、复杂同宗建议冲突、直接斗法、破坏他人突破、抢夺他人洞府或后手，均不作为 MVP 核心验证项。若实现，只能作为低成本附加能力，不得影响核心闭环开发。

## 18. 离线与托管顶层方案

离线和超时玩家采用稳健托管。

托管目标：不阻塞回合、不让玩家严重掉队、不替玩家做重大冒险选择、不主动突破、不主动发动战争、不主动叛宗、不主动暴露核心后手、不做高风险不可逆选择。

托管可以执行：闭关修炼、巩固境界、维持职位日常、领取基础俸禄、低风险宗门事务、洞府和后手维护、自动防御、保命撤退。

离线玩家可以受到世界影响，但不能被系统自动玩坏。

## 19. 失败体验边界

MVP 失败体验强度采用标准体验。

失败、突破受阻、寿元压力、转世重修和前世遗憾弥补是核心体验的一部分，不是边缘惩罚机制。

主要稳定负反馈应放在：突破难度门槛、寿元压力、转世重修、失败经验继承、后手布置与回收。

不建议把战斗重伤、修为倒退作为稳定高频负反馈来源。

标准失败允许玩家遭遇突破失败、身死转世、寿元耗尽、道伤、修为阶段性停滞、外部资产损失、后手暴露或污染、宗门职位下降、错过秘境窗口、节点局势恶化。

坏失败应避免：无理由毁档、核心传承永久消失、玩家正式布置的后手无日志失效、离线期间被系统自动杀死、多人强对抗直接毁掉长期体验、失败后没有任何可执行的修正方向。

## 20. 战斗 / 斗法顶层定位

MVP 中，战斗 / 斗法不作为独立复杂战棋或实时操作系统实现。

顶层定位为：

- 战斗 / 斗法是高风险事件链的一类结算框架。
- 重点是准备、选择、资源投入、风险承受和后果反馈。
- 战斗失败可以造成伤势、资源损耗、声望损失、事件失败、窗口错过或短期修炼受阻。
- 不把高频战斗重伤或修为倒退作为主要长期负反馈来源。
- MVP 不支持玩家之间直接斗法或强 PvP。

## 21. 内容生产策略

MVP 内容策略采用：

> 少量主链 + 中量模板 + 高复用标签化结果。
> 

原则为：

- M0→M3 主路径、突破链、后手链使用较高质量事件链。
- 节点事件、宗门行动、资源变化和世界日志主要依赖模板化事件。
- 事件通过节点类型、资源槽、控制宗门、危险等级、隐藏层、宗门关系和玩家状态进行参数化复用。
- 文案包装与规则数据分离。

MVP 内容骨架包括：2–3 个宗门原型、若干节点类型模板、资源槽和建筑槽模板、两段关键突破链、一套后手创建 / 追踪 / 回收模板、一套节点事件模板、一套宗门财政与行动结果模板、一套弱竞争事件模板。

## 22. 技术路线定案

技术路线已确定采用 Godot。

顶层技术方向为：

> Godot 客户端 + Godot Headless / Dedicated Server。
> 

当前技术约束：

- 使用 Godot 作为主要客户端开发引擎。
- 服务端优先采用 Godot Headless / Dedicated Server 思路。
- 客户端与服务端尽可能共享规则模型和数据结构。
- 游戏采用客户端 + 权威服务器架构。
- 服务器负责房间状态、季度推进、行动结算、宗门 AI、地图节点、事件触发和存档写入。
- 客户端负责 UI 表现、节点地图展示、行动规划、事件阅读、账本展示和玩家输入。
- 继续采用回合统一结算，避免复杂实时同步。
- 内容和规则尽量数据驱动，包括境界、功法、宗门、节点、资源槽、建筑槽、事件、突破链和后手类型。
- 必须支持本地单人测试。
- 必须支持私人服务器部署。
- MVP 至少支持 3 人共玩。

仍留待后续技术子系统细化的问题：GDScript / C# / 混合方案、服务端规则是否完全由 Godot 运行、存档采用 SQLite 还是其他方案、数据表格式、联机协议、房间发现方式、私人服务器启动与版本迁移、Debug 工具、日志、回放和结算追踪工具。

## 24. 子系统展开顺序

确认后续优先展开：

1. S3 个人行动经济与通行子系统。
2. S4 突破事件链子系统。
3. S11 前世后手、遗产与隐藏层子系统。

理由：行动经济决定玩家每季度如何做选择；突破事件链决定修炼压力和核心成长反馈；后手系统决定轮回是否真正成立。

宗门、地图、AI、财政和节点事件后续围绕这三者继续展开。

## 25. 当前 Handoff

后续继续设计时，应默认以下结论成立：

- 项目核心是跨世修行主体，不是宗门。
- 当前 MVP 边界是本地单人测试、私人服务器部署、3 人共玩。
- 商业化、Steam EA 和正式首发包装暂不纳入当前 MVP。
- 时间采用季度回合 + 关键事件插入链。
- 行动经济采用宗门行动 + 角色 6 个朔望行动格。
- MVP 验证闭环是 M0→M3。
- M3 对应第三大境界起点，通常为 C-1 或同等包装。
- 单人体验是一等公民。
- 多人默认是分宗并行 + 间接竞争 + PvE 沙盒演化。
- 世界生成采用半固定种子地图。
- 战斗 / 斗法是事件链结算框架，不是独立复杂战斗系统。
- 失败体验采用标准体验，主要负反馈落在突破、寿元、转世和后手上。
- 宗门是组织性资源平台，有真实库存、财政、职位、权限和六类行动。
- 地图是有向带权节点图，地理节点挂载资源槽、建筑槽、控制权、影响力和隐藏层。
- 后手系统必须保证正式后手可信、可追踪，有损失也必须有原因和追查路径。
- 技术路线已定为 Godot 客户端 + Godot Headless / Dedicated Server。
- 下一步进入 S3：个人行动经济与通行子系统。
