## 3. `CULT-01` 不可改写边界

1. 标准 CP 是跨道功统一的境界进度参数，是小境界、瓶颈、突破入口和境界能力解锁的唯一修为进度尺度。
2. 普通改修不增加、减少、折算或替换标准 CP，因此不改变小境界、大境界、已完成突破、历史最高境界或境界能力解锁。特殊事件若明确扣减标准 CP，产生的境界进度变化按事件自身规则处理，不能伪装成普通改修税。
3. 同一标准 CP 与同一境界下的角色仍可具有不同修为强度；修为强度与总战力不参与反向改写境界进度。
4. 改修可以改变以后取得标准 CP 的速度、当前修为强度和功法效果，但不能用这些变化伪装成境界进度变化。
5. 改修目标只需已学习且阶级不低于当前主修，不要求最低掌握度，不受本大境界阶段窗口限制。
6. 改修只在回合开始即时阶段执行，每回合最多一次，死亡或重伤时禁止。
7. 两部道功之间不转移研习经验或掌握度。
8. 每个内部时间单位先自动修炼、后自动研习；本单位研习新达到的掌握阶段只能从下一内部时间单位影响修炼。
9. 节点实际灵气为“节点基础灵气＋当前回合全图固定增量”。
10. 各境总 CP 与 `15 / 35 / 60 / 100` 累计阈值开局固定；现有早到减速、晚到与转世重修加速的灵气结构必须保留。

## 4. `CULT-01-Q1`｜标准 CP 的唯一语义

状态：已被第 6 章概念重置替代；本章只作过程审计

### 4.1 需要关闭的冲突

现行正文一方面把每单位自动修炼写成“节点实际灵气 × 当前主修道功修为转化率”，另一方面要求改修保持标准 CP 不变、再由新主修重新确定有效修为。若标准 CP 已完整保存当时乘过道功效率的成果，而有效修为读取时再乘同一类道功效率，就会重复计算；若读取时不再读取道功效率，改修又无法仅凭新主修改变有效修为。

因此必须先固定标准 CP 记录哪一层量，再进入自动修炼写入公式。

### 4.2 选项 A｜道功无关的修炼底蕴

标准 CP 记录角色在当前大境界内累积的、尚未经过当前主修道功效率转换的修炼底蕴。它是单一、可累加、与取得时所用道功无关的当前世记录；历史上通过不同道功和不同合法修炼来源取得的底蕴直接共存，不保留逐段道功来源账本。

此口径下：

- 自动修炼只把环境灵气和明确的标准 CP 加算来源写入标准 CP；
- 当前主修模板转化率、掌握倍率与主修限定修正只在“标准 CP → 当前有效修为”层读取一次；
- 改修只替换读取方式，不改写已经累积的标准 CP；
- 同一份标准 CP 可以因改修或主修掌握阶段变化而表现出不同有效修为；
- 当前大境界突破完成后，按既有规则进入新境界并从该境 `0` 标准 CP 开始。

主要代价是：当前主修改变时，会重新解释本境内全部标准 CP，而不只是改修后的新增部分；这是“改修能改变当前小境界表现”的直接来源，需要在后续 Q3—Q5 明确钳制、时序与玩家反馈。

### 4.3 选项 B｜取得时已转换的标准化成果

标准 CP 保存每次修炼在取得当时已经读取主修模板与掌握度后的成果。不同道功取得的成果可以直接相加，历史取得效率保留在累计结果中。

若采用此口径，为使改修仍能改变当前有效修为，必须另增一个与“修炼转化率”性质不同的当前发挥字段，例如“修为发挥率”，只在读取层生效。取得率与发挥率必须分别配表、分别说明掌握倍率作用范围，不能复用同一效率。

主要代价是引入第二套道功修为效率字段、第二层内容预算和额外 UI 解释；否则无法同时满足“改修改变有效修为”与“同一效率不重复计算”。

### 4.4 用户补充的道功差异轴

用户指出，道功至少需要表达三类差异：

1. 灵气吸收效率高，因此同一单位环境灵气与丹药灵气可以写入更多标准 CP；但单位标准 CP 对应的实际修为较低。
2. 灵气吸收效率低，因此写入标准 CP 较少；但单位标准 CP 对应的实际修为较高。
3. 灵气吸收效率与单位标准 CP 对应的实际修为都较高，即修炼快且战力强，通常属于更高品级道功。

前两类道功可以通过相反的吸收与修为密度配置，使“单位灵气最终形成的实际修为”处于相近预算；第三类则允许两项同时较高，形成高品级道功的综合优势。

该补充成立。选项 A 只让道功在“标准 CP → 当前有效修为”层产生差异，所有道功写入标准 CP 的灵气吸收效率相同，因此不能独立表达上述三类模板。原先对选项 A 的推荐撤回。

### 4.5 选项 C｜吸收效率与修为密度双轴

为承接上述差异，可以把道功修炼相关字段拆为两个语义不同、各自只进入一层的参数：

```text
道功灵气吸收效率 α
= 单位环境灵气或丹药灵气写入多少标准 CP

道功修为密度 β
= 当前主修下，每单位标准 CP 对应多少实际修为
```

概念公式为：

```text
本单位写入标准 CP
= 节点灵气输入 × α
+ 丹药灵气输入 × α
+ 明确绕过灵气吸收的直接标准 CP 加算

当前有效修为
= 当前大境界起点
+ 当前大境界标准 CP × β
+ 其它合法的有效修为修正
```

节点灵气与丹药灵气分别记录来源，丹药不会反向放大节点灵气；若某种丹药不是提供可吸收灵气，而是直接授予标准 CP，其模板必须明确声明为第三项输入。

`α` 与 `β` 不是同一效率的重复乘算。角色持续使用同一道功时，单位灵气形成实际修为的综合效率近似由 `α × β` 决定：同品级的吸灵型与凝练型可以保持相近综合预算，高品级道功则可以拥有更高的乘积。

掌握倍率应只在整条链中生效一次，不能把同一个 `0.70 / 0.85 / 0.95 / 1.00 / 1.10` 同时完整乘入 `α` 与 `β`。它最终进入吸收层、修为密度层，或在两层间拆分，留待 Q2—Q3 确认。

### 4.6 双轴模型新增的组合风险

若标准 CP 不保留取得来源，而改修后全部按新主修的 `β` 重新读取，则玩家可以：

```text
先用高 α、低 β 的道功积累较多标准 CP
→ 再切换低 α、高 β 或高 α、高 β 的道功
→ 用新 β 重新解释此前全部标准 CP
```

这会把两部道功的优势串联起来。它可以被设计成需要学习并分别研习多部道功的合法路线，但也可能使“平时用最高 α、需要战斗或突破时改用最高 β”成为缺少实质取舍的固定操作。

在继续确认标准 CP 语义前，需要先决定：

- **允许跨道功组合**：把先吸灵、后凝练视为合法构筑收益；通过知识取得、独立研习投入、每回合一次改修和内容预算控制强度。
- **不允许无损组合**：则必须调整至少一条现有边界，例如保存历史修为密度、限制新 `β` 对既有标准 CP 的作用范围、让小境界不随当前 `β` 重算，或重新引入改修成本 / 限制。上述做法分别会增加持久记录，或改写当前已确认的改修边界，不能静默采用。

## 5. 已暂停的 `CULT-01-Q2`｜掌握倍率在双轴中的作用位置

状态：因标准 CP / 境界 / 修为强度概念重置而暂停；本章只作过程审计

### 5.1 新的约束

现有五阶段标准倍率为：

| 掌握阶段 | 掌握度 | 标准倍率 `M` |
| --- | ---: | ---: |
| 初识 | `0—24` | `0.70` |
| 熟悉 | `25—49` | `0.85` |
| 熟练 | `50—74` | `0.95` |
| 精通 | `75—99` | `1.00` |
| 圆满 | `100` | `1.10` |

用户进一步确认：掌握倍率主要约束灵气吸收侧，不应进入 `β` 并直接重算当前有效修为。否则角色只进行功法研习、没有取得任何新标准 CP，也可能因为掌握阶段提高而增加有效修为或改变小境界，不符合“修为来自灵气积累”的直觉。

掌握对另一部分道功成长的表达，应进入该道功自身的主修限定被动、恢复 / 辅助字段、已解锁招式倍率和正式内容数值投放。研习可以提高道功运用效果，但不能自行生成修为。

### 5.2 已确认方向｜修炼链与内容链分开

```text
实际 α = 模板 α × M
实际 β = 模板 β

本单位写入标准 CP
= 节点灵气输入 × 实际 α
+ 丹药灵气输入 × 实际 α
+ 直接标准 CP 加算

当前有效修为
= 当前大境界起点
+ 当前大境界标准 CP × 实际 β
+ 其它不来自功法掌握的合法修正
```

同一 `M` 仍可按现行规则作用于该道功明确标记的被动、恢复、辅助、直接伤害、护盾等内容字段。这里不是把 `M` 在同一条修为公式中重复计算：

- `α × M` 决定以后能够写入多少标准 CP；
- 内容字段 `× M` 决定角色如何运用该道功；
- `β` 只由道功模板、品级与不依赖掌握的明确修正决定；
- 研习达到新阶段不会重算既有标准 CP、当前有效修为或小境界。

为防止内容表绕过该边界：`25 / 50 / 75` 阈值内容、掌握阶段倍率、主修限定被动、恢复 / 辅助效果和道功招式均不得直接或间接提高 `β`、改写既有标准 CP 或授予当前有效修为。允许它们提高后续灵气吸收、标准 CP 写入、属性、恢复、招式、护盾或其它明确效果，但来源必须进入各自系统，不能改名为被动后重新回流修为读取层。

自动研习在本单位末提高 `M` 后，只从下一内部时间单位改变 `α` 与标准 CP 写入；小洞天仍逐单位重复该顺序。道功内容效果按其既有生效时序更新，但这类变化必须显示为功法效果提高，不能包装成修为增加。

### 5.3 漏洞审计

| 风险 | 审计结论 | 当前处理 |
| --- | --- | --- |
| 研习凭空增加修为 | 已关闭 | `M` 不进入 `β`，研习只影响未来标准 CP 写入和道功内容效果 |
| 同一掌握倍率在修为链平方放大 | 已关闭 | 标准 CP 写入只读取一次 `M`；有效修为读取不再读取 `M` |
| 研习后同单位追溯放大修炼 | 已关闭 | 新 `M` 只从下一内部时间单位改变 `α`；本单位已写入标准 CP 不重算 |
| 掌握阈值被动绕道提高 `β` 或有效修为 | 已关闭 | 所有依赖掌握的阈值、被动与招式禁止修改 `β`、既有标准 CP 或当前有效修为 |
| 掌握同时提高修炼速度和招式输出，长期总战力出现复合成长 | 不是公式重复，但属于数值风险 | `α` 与招式 / 被动是不同系统收益；正式功法与战斗表必须按实际掌握路径联合验算，不能分别配满预算后直接叠加 |
| 低掌握高 `β` 道功立即借用修为密度 | **仍存在** | 见第 5.4 节，需用户确认采用内容约束还是改写现有改修边界 |

### 5.4 仍存在的低掌握高 `β` 借用

现行规则允许掌握度 `0` 的已学道功立即设为主修。若 `β` 完全不读取掌握，则一部刚学会的高 `β` 道功可以立刻重读本境全部标准 CP，并把提高后的有效修为输入所有已装配战斗法门：

```text
既有标准 CP × 新道功完整 β
→ 提高当前有效修为
→ 放大其它已高掌握战斗法门的“有效修为 × K1”基础威力
```

因此，“新主修自己的被动和招式仍处于低掌握”不能完全抵消该收益。尤其当玩家已经有高掌握战斗法门时，新道功即使掌握度 `0`，完整 `β` 仍可能成为近乎无研习成本的全局战力放大器。这与“复合路线通常需要两部道功都投入较高掌握”的定位存在张力。

在坚持“研习不提高有效修为”和“不设置主修最低掌握度”的双重前提下，无法从公式层彻底消除这一风险；只能把它作为内容与验收约束：

- 同品级道功的 `β` 差距保持为有限侧重，不做跨档跳升；
- 高 `β` 必须用较低 `α`、较弱的主修限定被动 / 招式预算或其它同模板代价交换；
- 掌握度 `0—24` 切入高 `β` 道功时，代表性完整构筑的总战斗表现不得稳定优于当前已精通同品级道功；明确以“低掌握过渡也强”为特色的稀有模板除外，但必须占用更高品级或稀有度预算；
- 标准验算必须覆盖“高标准 CP＋已精通战斗法门＋掌握度 `0` 的高 `β` 新主修”，不能只比较两部道功自身招式；
- 若正式内容表无法满足该验收，唯一干净的结构性修正是重新裁决“主修不要求最低掌握度”，而不是让研习倍率静默进入 `β`。

当前建议先保留“无最低掌握度”和固定 `β`，采用上述内容预算与极端用例验收。这样不会让研习凭空增加修为，也保留低掌握提前改修的风险决策；若首批功法表证明无法平衡，再显式重开最低掌握度边界。

请用户确认是否接受这项残余风险及内容验收方案。此前 Q2-B 与对称开方的 Q2-C 均不采用。

### 6.2 推荐的三层道功数值结构

为避免一个“有效修为”同时承担进度、战力和功法熟练度，推荐把道功拆成三个玩家可以直接理解的层：

| 层 | 推荐名称 | 负责内容 | 是否决定境界 |
| --- | --- | --- | --- |
| 进度层 | **标准修为进度（标准 CP）** | 小境界进度、瓶颈、突破入口、境界解锁 | 是，唯一决定 |
| 强度层 | **修为强度** | 同境角色由道功路线造成的基础强弱；作为战斗公式的一个输入，但不等于总战力 | 否 |
| 内容层 | **道功掌握与功法效果** | 主修被动、恢复 / 辅助、道功招式、阈值内容与实际数值 | 否 |

玩家界面优先使用“境界进度”“修为强度”“道功掌握”三个名称。`标准 CP` 可以作为规则说明、详情数字和 Debug 字段保留；“实际修为”“有效修为”不再作为跨系统正式名词，因为它们容易被同时理解为境界进度、战力或当前道功换算结果。

### 6.3 道功的两个基础轴与一个内容轴

每部道功至少配置：

```text
标准修炼效率 α
= 单位节点灵气与丹药灵气能够写入多少标准 CP

修为强度系数 β
= 在相同标准 CP 与境界下，该道功提供多少基础修为强度

功法效果包 C
= 该道功的主修限定被动、恢复 / 辅助、属性补位与可用招式
```

结构规则：

1. `α` 影响以后取得标准 CP 的速度，不改写已经取得的标准 CP。掌握倍率可以作用于 `α`；本单位研习提高掌握后，只从下一内部时间单位改变修炼速度。
2. `β` 不进入境界判定，也不改变标准 CP。改修可以立即改变当前修为强度，但小境界与境界解锁保持原样。
3. 掌握度不改写 `β_template`、标准 CP 或境界。按第 6.8 节当前推荐，掌握成长通过通用发挥倍率 `M_dao` 提高实际 `β`，属于功法发挥改善，必须与“获得修为”分开表达；掌握同时进入 `α` 与内容包 `C` 的合法字段。
4. 内容包 `C` 按现有 `25 / 50 / 75` 阈值、五阶段倍率和主修限定规则生效，不得绕道改写标准 CP、境界或 `β`。
5. 同品级吸灵型可采用高 `α`、较低 `β`；凝练型可采用较低 `α`、高 `β`；高品级道功可以在更高总预算内兼具较高 `α`、`β` 与更好的内容包，但仍允许不同分支侧重。

“折算成标准 CP”应理解为每次修炼取得进度时的标准化写入，而不是换功时再处理已有进度：

```text
灵气输入
→ 按当时主修的 α 与合法修正换算为新增标准 CP
→ 新增标准 CP 写入统一境界进度并失去道功来源差异
```

改修只决定此后新增标准 CP 的换算速度，以及当前修为强度和内容包；已有标准 CP 不需要再次折算。旧资料中的换功 CP 折算公式只能作为历史方案，不进入当前结构。

### 6.4 玩家可理解的换功结果

换功确认只需要表达四件事：

```text
境界进度：不变
当前境界与已解锁能力：不变
以后修炼速度：按新道功 α 与当前掌握重新计算
当前修为强度及功法效果：按新道功 β、被动与招式重新计算
```

这样，“主角与龙套同为金丹中期，但主角修为更强”可以直接解释为：两者标准 CP 均处于金丹中期阈值内，但主角当前道功的 `β`、属性、被动、招式和其它构筑更强。玩家不需要理解换功后为何境界条倒退或前进。

### 6.5 仅用于结构说明的示例

以下数值只说明结构，不进入正式配表：

| 道功 | `α` 标准修炼效率 | `β` 修为强度系数 | 玩家理解 |
| --- | ---: | ---: | --- |
| 同品级吸灵型 | `1.15` | `0.90` | 境界进度积累快，但同 CP 的基础强度较低 |
| 同品级凝练型 | `0.90` | `1.15` | 境界进度积累慢，但同 CP 的基础强度较高 |
| 更高品级均衡型 | `1.10` | `1.10` | 修炼较快、同境也较强，综合预算更高 |

角色已有 `400` 标准 CP 时，从吸灵型改修凝练型：标准 CP 仍为 `400`，境界条与小境界不变；以后每单位灵气取得标准 CP 的速度下降，当前修为强度提高，主修内容切换。这里不存在“折算后的标准 CP”。

### 6.7 基于新设计意图的改修推荐方案

审计状态：本节的“普通改修不扣标准 CP”已由 `CULT-R12` 确认；独立 `φ` 插值公式发现吸灵型 `β<1` 时可能出现“掌握越高、强度反而越低”的反向成长，已由第 6.8 节替代，不再推荐。

用户进一步声明：

1. 允许玩家在两部相近高掌握道功间切换，以应对不同情景。
2. 低掌握道功可以合法切入，但不能仅凭临时切换立即取得高收益；不使用强制禁止切换解决。
3. 品级决定综合预算高低；高品级总体优于低品级，但不要求每个局部字段都严格更高。
4. 同品级道功通过路线分配形成局部优劣，不存在同品级唯一最优模板。

推荐把道功固有模板与角色发挥程度分开：

```text
模板标准修炼效率 α_template
模板修为强度系数 β_template
模板内容预算 C_template

实际标准修炼效率
= α_template × 掌握修炼倍率 Mα

实际修为强度系数
= 1 + (β_template - 1) × 主修发挥度 φ

实际内容效果
= C_template 按掌握门槛、来源字段和内容倍率结算
```

`φ` 不代表修为量，只表示角色能否发挥新道功相对标准路线的强弱特征。首轮推荐使用离散阶段表：

| 掌握阶段 | 掌握度 | 主修发挥度 `φ` |
| --- | ---: | ---: |
| 初识 | `0—24` | `0.00` |
| 熟悉 | `25—49` | `0.50` |
| 熟练 | `50—74` | `0.80` |
| 精通 | `75—99` | `1.00` |
| 圆满 | `100` | `1.00` |

该表使掌握度 `0—24` 的新道功可以切入，但暂时不能取得其高 `β` 路线优势；同时也不会完整承受低 `β` 路线劣势。低掌握角色仍读取较低 `α`、未解锁内容和较弱被动 / 招式，因此临时切换通常不是高收益操作。达到精通后完整发挥模板 `β`；圆满额外收益继续放在 `α`、被动、招式或其它内容字段，不把 `φ` 提高到 `1` 以上，避免凝练型因圆满放大优势、吸灵型却因圆满进一步放大自身低 `β` 代价。

研习提高 `φ` 时，改变的是“当前主修发挥出来的修为强度”，不是标准 CP、境界或修为量。UI 必须把它归入道功发挥变化，不显示为获得修为。若这种表现仍容易误解，可把最终字段命名为“道功发挥强度”，而角色境界区域只展示标准 CP 进度。

#### 普通改修的标准 CP 处理

当前推荐：**普通改修不扣标准 CP。**

理由：

- 扣标准 CP 会直接造成小境界倒退，与“允许相近高掌握道功按情景切换”的目标相冲突；
- 它会让玩家为了战斗临时切换时永久损失境界进度，使路线选择退化为尽量不切换；
- 低掌握临时获利已经由 `φ`、较低 `Mα`、内容门槛与整回合主修选择共同抑制，不需要再叠加永久进度损失；
- 标准 CP 保持不变时，换功预览可以稳定表达“境界不变、发挥变化、以后修炼速度变化”。

若未来需要表达极端功法冲突、走火入魔或特殊剧情代价，应由事件明确扣除标准 CP 或施加临时状态；不能把它做成所有普通改修的隐藏通用税。

#### 品级与路线的内容预算

每个品级先给出一档综合预算包，再由同品级路线在 `α_template / β_template / C_template` 之间分配：

- 吸灵路线偏高 `α`、偏低 `β`；
- 凝练路线偏低 `α`、偏高 `β`；
- 战斗、恢复、辅助或资源路线可以继续调整 `C` 的内部构成；
- 高品级取得更高综合预算，允许局部字段与低品级路线重叠，但同掌握、代表性完整路线的长期总价值必须更高。

综合预算不能只用 `α × β` 判定。`α` 会提前境界阈值、能力解锁、破境准备和终局节奏，其战略价值通常高于同幅度的静态强度变化；正式配表必须把成长回合、固定 PVE 通过率、主要行动机会成本和内容包一起模拟。

#### 必须通过的最小验收

1. 同品级、同为精通的两部道功可以无损切换，并在不同场景各有优势。
2. 掌握度 `0—24` 的高 `β` 新道功切入后，不得仅凭修为强度就让已有精通战斗法门的完整构筑稳定变强。
3. 略高品级道功在初识阶段通常不应立即全面优于已精通低一品级道功；达到熟练或精通后应逐步体现综合升级价值。
4. 长期研习两部同品级道功并择机切换可以成为过渡或情境方案，但取得、研习和机会成本合计后，不得稳定优于研习一部理想高品级道功。
5. 吸灵路线的高 `α` 必须连同提前境界解锁收益验算，不能只用较低 `β` 做表面等价交换。

本节的普通改修无标准 CP 损失已经确认；`φ` 表与插值公式已被第 6.8 节替代，不作为当前推荐或正式规则。

### 6.8 道功与法门掌握效果的统一方案

#### `φ` 与 `β` 的关系

两者不是同一个参数：

- `β_template` 是道功模板在精通基准下的修为强度系数；
- `φ` 是尝试描述角色能发挥多少模板差异的掌握函数；
- 两者合成后的结果才相当于此前讨论的“受掌握影响的实际 `β`”。

因此，较早的“`α` 与 `β` 都受掌握度影响”方案和独立 `φ` 方案在设计目的上相近，都是为了让低掌握道功无法立即取得完整修炼或强度收益。区别只是数学表达。

独立 `φ` 不值得保留。此前公式 `1 + (β_template - 1) × φ` 在 `β_template < 1` 时，会让吸灵型道功随掌握提高而逐步接近更低的强度系数，形成玩家可见的反向成长。当前推荐直接复用现有五阶段掌握倍率 `M`：

| 掌握阶段 | 掌握度 | 通用发挥倍率 `M` |
| --- | ---: | ---: |
| 初识 | `0—24` | `0.70` |
| 熟悉 | `25—49` | `0.85` |
| 熟练 | `50—74` | `0.95` |
| 精通 | `75—99` | `1.00` |
| 圆满 | `100` | `1.10` |

所有功法共用两种掌握收益：

1. **门槛内容**：`25 / 50 / 75` 解锁新能力、离散强化、被动或其它明确内容。
2. **发挥倍率**：模板明确标记为可随掌握缩放的字段读取 `M`；未标记字段只读门槛内容或自身专属规则。

#### 道功

```text
实际标准修炼效率
= α_template × M_dao

实际修为强度系数
= β_template × M_dao
```

掌握提高时：

- 以后每单位灵气写入更多标准 CP；
- 当前标准 CP 与境界不变；
- 角色对既有修为的道功发挥增强，因此“修为强度”提高；
- 主修被动、恢复 / 辅助、道功招式和阈值内容按自身规则更新。

这里的修为强度提高不能表述为“获得修为”或“境界进步”，而应表述为“道功发挥提高”。低掌握高品级道功虽然可以合法切入，但 `α`、`β` 和大部分内容均处于低发挥状态，不会立即取得完整模板收益。

#### 战斗法门

- `25 / 50 / 75` 继续负责新增招式或离散强化；
- 直接伤害、护盾等已标记的 `K1 / K2` 字段读取该战斗法门自身的 `M_fa`；
- 冷却、固定元气损伤、固定吸收、固定消耗等现行排除字段不读取通用倍率；
- 法门不改变标准 CP、道功 `α`、道功 `β` 或角色境界。

#### 移动法门

- `25 / 50 / 75` 继续负责新增移动能力或离散强化；
- 骰池、理论上限和速度等现行离散字段默认不连续读取 `M_fa`，避免玩家面对难以解释的分数骰池；
- 若某个移动法门存在可连续缩放的明确数值字段，可以显式读取 `M_fa`，否则只使用门槛内容；
- 法门不改变标准 CP 或修为强度。

#### 同一来源只读取一次

为防止掌握倍率在一条效果链重复计算：

1. 当前主修道功的 `M_dao` 已进入修为强度后，由该道功自身提供、且以修为强度为基础的招式，不再在 `K1` 上第二次读取同一个 `M_dao`。
2. 战斗法门招式可以读取自己的 `M_fa`；它与主修道功的 `M_dao` 来自两部不同知识，代表两份独立研习投入，可以共同生效。
3. 不读取修为强度的固定值道功效果，可以按模板显式读取一次 `M_dao`。
4. 离散强化先形成当前模板，再应用该效果链唯一一次合法的来源掌握倍率。

因此：

```text
主修道功自身修为伤害招式
= 修为强度（已含 M_dao）× 道功 K1（不再乘 M_dao）

战斗法门修为伤害招式
= 修为强度（已含 M_dao）× 法门 K1 × M_fa
```

#### 品级与低掌握验收

- 每个品级仍以 `α_template / β_template / C_template` 综合预算为上位边界；路线只在品级预算内分配局部侧重。
- 普通模板应满足：略高品级道功在初识 `0.70` 发挥时，通常不能仅凭 `β` 稳定全面优于已精通低一品级道功；熟练或精通后再体现综合升级。
- 同品级同掌握切换时，共用相同 `M`，因此比较结果只来自路线 `α / β / C` 差异，适合情景决策。
- 圆满的 `1.10` 会同时提高道功修炼效率与修为强度；道功自身以修为强度为基础的招式不再额外读取同一倍率，避免同源平方放大。

玩家侧不展示 `α / β / M` 字母，只展示：

```text
境界进度
当前修炼效率
当前修为强度
功法掌握阶段与发挥倍率
已解锁内容
```

本节概念已经确认；具体内容字段与数值表在统一回写和正式配表阶段落实。

### 6.9 同源掌握去重的简化裁决

“同一知识来源在单条效果链只读取一次掌握倍率”不作为玩家规则，也不扩张为所有系统都要维护的复杂通用机制。当前实际需要处理的范围只有：

```text
当前主修道功提供某项解锁效果
+ 该效果以修为强度为基础
+ 该效果又试图读取同一主修道功的掌握倍率
```

内容制作优先避免这种结构。普通主修道功修为伤害效果直接使用已经包含 `M_dao` 的最终修为强度，再乘不读取 `M_dao` 的模板效果系数：

```text
最终效果
= 当前修为强度 × 道功模板效果系数
```

只有少数确实需要把掌握收益分布在两段的特殊效果，内部使用：

```text
效果链内部修为强度侧
= 未应用本道功掌握的修为强度基值 × √M_dao

效果链内部效果系数侧
= 模板效果系数 × √M_dao

最终效果
= 修为强度基值 × 模板效果系数 × M_dao
```

此处使用的是效果链内部基值，不要求普通 UI 展示一个与角色面板不同的“中间修为强度”。玩家只看到角色当前最终修为强度，以及该招式或效果已经计算完成的最终倍率 / 数值。

玩家信息收束为：

| 玩家可见 | 表达目的 |
| --- | --- |
| 当前境界进度百分比 | 唯一境界进度；不显示换功折算或来源 CP |
| 当前灵气吸收速度 | 当前主修、掌握、节点与丹药输入共同形成的最终修炼速度 |
| 当前修为强度 | 当前标准进度在主修道功下能够发挥的最终强度，不影响境界 |
| 招式或效果最终倍率 / 数值 | 已完成门槛、掌握、离散强化和同源去重后的玩家决策结果 |

普通界面不展示 `α / β / M / √M`、掌握乘区、效果链中间值或同源去重规则。Debug、内容表和验算记录仍需保留来源明细，保证结果可追溯。

### 6.10 累计标准修为量与历史重算

角色内部继续按每个大境界分别维护固定总 CP 和当前大境界局部进度；修为强度读取时派生本世累计标准修为量：

```text
本世累计标准修为量 S_total
= 当前身体已经重新达到并完成的各大境界固定总 CP 之和
+ 当前大境界内标准 CP

当前修为强度
= S_total × β_template × M_dao
+ 其它不重复读取本道功掌握的合法修正
```

“已完成大境界固定总 CP”只表示角色当前身体已经重新修过的境界段，不保存当时所用道功、`β`、掌握度或修为强度快照。改修后，当前主修统一重算整个 `S_total`：

- 标准 CP、境界与能力解锁不变；
- 当前修为强度可以按新主修整体变化；
- 不需要废功、重修已完成境界或支付历史根基重塑成本；
- 高品级道功的综合升级价值可以立即覆盖当前完整修为基础，但仍受目标道功当前掌握倍率约束。

转世使用不同边界。上一世已经完成的突破记录仍用于自动跨越，但不把上一世标准 CP 或修为强度带入新身体：

```text
转世开始：本世累计标准修为量按新身体当前境界与 CP 重建
自动跨越历史突破：只在新身体重新修满对应境界时补入下一境界基准
历史最高境界记录：不直接计入 S_total
```

因此转世仍是清空当前修为并重新修炼的惩罚，不会因累计历史记录而获得虚构战力；但角色也不重复消耗丹药或重打已经完成的突破。

### 6.11 已确认｜自动修炼写入标准 CP

普通自动修炼推荐只使用两类常规输入和一类显式例外：

```text
节点灵气输入 L_node
= 节点基础灵气 + 当前回合全图固定增量

丹药灵气输入 L_pill
= 本内部时间单位正在释放并可被吸收的丹药等效灵气

实际灵气吸收效率 A_dao
= α_template × M_dao × 其它明确的吸收修正

本单位节点标准 CP
= L_node × A_dao

本单位丹药标准 CP
= L_pill × A_dao

本单位写入标准 CP
= 本单位节点标准 CP
+ 本单位丹药标准 CP
+ 明确绕过灵气吸收的直接标准 CP 奖励
```

节点灵气与丹药灵气必须分项记录后再相加，保证丹药只增加自身灵气输入，不乘算或放大 `L_node`。普通修为丹药默认提供 `L_pill`，同样读取当前主修吸收效率；只有事件、主题奖励或模板明确写成“直接境界进度”时，才允许绕过 `A_dao` 进入最后一项。首轮普通丹药不使用直接标准 CP 奖励，避免同类物品出现两种难以比较的修炼语义。

每个内部时间单位开始时一次性快照：

- 所在节点与当回合全图灵气增量；
- 当前主修道功；
- 当前主修掌握阶段与 `M_dao`；
- 本单位有效丹药灵气及其它吸收修正；
- 角色是否死亡、重伤或已在当前瓶颈。

随后按以下顺序结算：

```text
锁定本单位输入
→ 计算并写入标准 CP
→ 处理小境界阈值与瓶颈截断
→ 结算自动研习
→ 新掌握只从下一内部时间单位改变 A_dao
```

达到当前未完成大境界瓶颈时，本单位最多写入抵达瓶颈所需的标准 CP；超出部分不预存、不进入下一境界，也不返还为灵气或丹药时长。突破成功后，本回合后续内部时间单位从新境界 `0` 局部标准 CP 继续结算；普通小洞天不能主动突破，仍停在首个未完成瓶颈。

计算中不对节点、丹药或其它来源分别取整；先汇总本单位精确结果，再按统一标准 CP 存储精度写入。当前推荐存储至 `0.01` 标准 CP，境界进度百分比最后单独格式化，避免来源拆分造成系统性损失。若后续 `1A` 绝对尺度证明 `0.01` 过细或过粗，可以整体调整存储精度，但不得改为逐来源取整。

玩家不查看上述拆分，只查看：

```text
当前境界进度百分比
当前灵气吸收速度（折算后的最终标准 CP / 内部时间单位，或对应进度百分比）
```

结果日志可用自然语言说明节点、丹药或状态为何使最终吸收速度变化，但普通 UI 不展示公式乘区。

本节已经确认，由 `CULT-R18—R20` 记录。

### 6.12 已确认｜非零修为基值与最终验算

标准开局为炼气初期境界进度 `0%`，但角色已经是能够移动、战斗和运转道功的修士。若直接使用：

```text
修为强度 = S_total × β_template × M_dao
```

则开局 `S_total = 0` 会令修为强度与所有“修为强度 × K1”效果变成 `0`。境界进度零点不能等同于不存在修为，因此推荐加入一个不参与境界阈值的主题固定基值：

```text
修为强度计算当量 S_power
= 炼气初始修为基值 S0
+ 本世累计标准修为量 S_total

当前修为强度
= S_power × β_template × M_dao
+ 其它合法修正
```

`S0` 只负责给炼气初期 `0%` 提供非零修为强度：

- 不计入标准 CP；
- 不推进小境界、瓶颈或突破；
- 所有角色使用相同主题基值，不制造宗门差异；
- 转世新身体恢复同一 `S0`，但不恢复上一世 `S_total`；
- `S0` 绝对值与 `1A`、炼气总 CP 和开局战斗常数一起配表，当前不填临时数字。

采用 `S0` 后，最小验算应同时覆盖：

1. **标准开局**：炼气初期 `0%` 仍有非零修为强度，初始招式能够正常造成效果。
2. **同品级同掌握改修**：境界进度与标准 CP 不变；灵气吸收速度、修为强度和内容包按路线变化。
3. **高品级低掌握改修**：允许切换但 `M_dao` 较低，不能稳定全面优于已精通低一品级道功。
4. **研习跨阶段**：本单位标准 CP 不重算；修为强度与功法内容在掌握更新后表现为“发挥提高”，下一单位才提高灵气吸收速度。
5. **瓶颈研习与改修**：标准 CP 保持瓶颈；掌握或改修可以改变修为强度和构筑，为渡劫准备，但不越过境界。
6. **小洞天十单位**：逐单位先修炼后研习，较早单位的新掌握从下一单位提高吸收速度；到未完成瓶颈后修炼溢出作废。
7. **转世追赶**：新身体从 `S0 + 当前重新取得的 S_total` 计算强度；历史突破只免除重复突破，不直接恢复上一世强度。
8. **高品级历史重算**：取得并改修高品级道功后，当前主修重算本世全部 `S_total`，无需主动重修历史境界。

本节已经确认，由 `CULT-R21` 记录。`S0` 绝对值仍属于正式数值表，不在本轮补造。

### 6.13 `CULT-01` 交叉复核与最小验算夹具

以下数值只用于证明公式能得到唯一答案，不是正式道功、境界或 `1A` 配表：

```text
炼气初始修为基值 S0 = 100
示例当前大境界总 CP = 1000
示例节点灵气输入 = 100
无其它修正
```

#### 用例 A｜标准开局

初始道功 `α=1.00`、`β=1.00`，熟悉阶段 `M=0.85`：

```text
开局标准 CP = 0
开局境界进度 = 0%
开局修为强度 = (100 + 0) × 1.00 × 0.85 = 85
本单位节点写入 = 100 × 1.00 × 0.85 = 85 标准 CP
```

结论：境界进度 `0%` 不等于零战力；第一次修炼后境界进度由标准 CP 单独推进。

#### 用例 B｜同品级、同掌握路线切换

角色已有本世累计标准修为量 `400`，两部道功均为精通 `M=1.00`：

| 当前主修 | `α` | `β` | 下单位节点写入 | 当前修为强度 |
| --- | ---: | ---: | ---: | ---: |
| 吸灵型 | `1.15` | `0.90` | `115` | `(100+400)×0.90=450` |
| 凝练型 | `0.90` | `1.15` | `90` | `(100+400)×1.15=575` |

改修前后标准 CP 均为 `400`，境界进度不变；未来修炼速度和当前修为强度按路线交换。

#### 用例 C｜高品级、低掌握提前改修

旧道功精通 `β=1.00 / M=1.00`；新高品级道功初识 `β=1.20 / M=0.70`：

```text
旧修为强度 = (100+400) × 1.00 × 1.00 = 500
新修为强度 = (100+400) × 1.20 × 0.70 = 420
```

新道功可以合法主修，但低掌握时不因高品级模板立即全面获利；其 `α` 与内容同样读取低掌握状态。

#### 用例 D｜研习跨阶段

初始本世累计标准修为量 `100`，道功 `α=β=1.00`；本单位开始时为熟悉 `M=0.85`，单位末研习进入熟练 `M=0.95`：

```text
本单位标准 CP 写入 = 100 × 1.00 × 0.85 = 85
写入后累计标准修为量 = 185
研习前修为强度 = (100+185) × 1.00 × 0.85 = 242.25
研习后修为强度 = (100+185) × 1.00 × 0.95 = 270.75
下一单位标准 CP 写入 = 100 × 1.00 × 0.95 = 95
```

本单位已写入的 `85` 不追溯重算；研习后增加的是道功发挥与修为强度，下一单位才提高吸收速度。

#### 用例 E｜节点与丹药分流

节点灵气 `100`、丹药等效灵气 `20`、实际吸收效率 `0.85`：

```text
节点写入 = 100 × 0.85 = 85
丹药写入 = 20 × 0.85 = 17
本单位合计写入 = 102 标准 CP
```

丹药只贡献自身 `17`，没有把节点 `100` 放大为其它数值。

#### 用例 F｜瓶颈与改修

角色已达到当前大境界 `1000 / 1000`：

- 自动修炼新增标准 CP 为 `0`，所有溢出作废；
- 自动研习仍可提高道功发挥、招式或效果；
- 合法改修保持 `1000 / 1000`，只重算修为强度、吸收速度和内容包；
- 未执行或未完成突破前，不进入下一境界。

#### 用例 G｜小洞天逐单位

若洞天单位 `1` 开始时 `M=0.85`，单位末研习进入 `0.95`：

```text
单位 1 修炼读取 0.85
单位 1 研习更新掌握
单位 2 修炼读取 0.95
```

十单位逐次重复；到首个未完成瓶颈后，剩余修炼输入作废，但研习与其它合法逐单位效果继续。

#### 用例 H｜转世与高品级历史重算

- 转世开始时：`S_total=0`，修为强度从 `S0` 与当前主修重新计算；历史最高境界不直接加入强度。
- 新身体重新修满历史已完成境界时：自动跨越并把该境固定总 CP 纳入本世 `S_total`。
- 同一世取得高品级道功并改修时：新 `β × M_dao` 作用于当前完整 `S0 + S_total`，标准 CP 与境界不变，不要求重修已经完成的境界。

#### 复核结论

`CULT-01` 已同时满足：

1. 标准 CP、境界进度与修为强度各有唯一职责；
2. 改修不修改标准 CP 或境界，但可以重算本世全部修为强度；
3. 低掌握道功不会自动取得完整高品级收益；
4. 自动修炼与自动研习没有同单位追溯；

### 9.2 `SHIELD-01-Q1`｜来源账本与容量上限

审计状态：`100%` 总上限、普通单次 `50%` 上限与护劫计入总量继续有效；以下按来源保存余额的候选描述已被第 9.5 节统一总护盾条替代。

#### 选项 A｜统一总上限，护劫计入（推荐）

每个护盾来源分别保存当前值、来源上限与持续时间，角色面板只把各来源当前值求和为总护盾。所有来源共同占用：

```text
战斗总护盾硬上限 = 开战时最大生命的 100%
普通单一来源硬上限 = 开战时最大生命的 50%
护劫护盾来源上限 = 本枚破境丹实际生成值，允许 Q4 / Q5 超过普通 50%
```

每个普通护盾模板仍需配置自己的来源上限，实际值不得超过通用 `50%` 硬上限。护劫护盾也计入 `100%` 总上限；因此 `Q5` 的 `80%` 仍给其它构筑保留最多 `20%` 开战容量，不会与完整普通护盾无上限相加。

优点：玩家只需理解“单来源最多半条生命、所有护盾最多一条生命”；高品破境丹显著提高容错，但不会使完整构筑在开战时取得远超第二条生命的护盾。可重复触发的普通护盾仍可在战斗中补充已消耗容量，因此总上限限制的是同时持有量，不是整场累计吸收量。

#### 选项 B｜护劫独立于普通总上限

普通护盾使用独立总上限，护劫护盾额外相加。若普通总上限同样为最大生命 `100%`，则 `Q5` 开战可达到 `180%` 最大生命护盾；即使把普通总上限降到 `50%`，也可达到 `130%`。

优点是破境丹价值完全不挤占构筑护盾；问题是渡劫构筑比普通战斗多出一套独立容量规则，Q4 / Q5 与防御构筑容易形成过高容错，并显著抬高固定渡劫敌人伤害预算。

#### 选项 C｜只有来源上限，不设总上限

所有护盾只受各自来源上限约束，可以完整叠加。规则最宽松，但多部法门、法宝、被动和护劫来源组合后会随内容数量持续膨胀，无法稳定维护固定敌人与 `60` 秒 TTK，不推荐。

当前推荐选项 A。确认 Q1 后，再依次处理同刻生成 / 总上限溢出、护劫与普通来源的消耗优先级、同源刷新及最小验算。

### 9.3 `SHIELD-01-Q2`｜生成顺序与总上限溢出

审计状态：稳定事件顺序、护劫先生成、溢出作废与开战最大生命快照继续有效；以下来源余额、同源补充与持续时间刷新描述已被第 9.5 节替代。

#### 选项 A｜按事件顺序占用容量，不替换已有来源（推荐）

每次护盾生成或补充按以下步骤处理：

```text
1. 计算本次模板生成量
2. 受该来源自身上限与普通来源 50% 硬上限裁剪
3. 计算当前总护盾剩余容量
4. 只把 min(本次可补充量, 总剩余容量) 写入该来源
5. 超出来源上限或总上限的部分直接作废
```

新来源不会自动挤掉、缩减或覆盖已有来源；也不把溢出转成治疗、减伤、持续时间或以后可用的储备。这样玩家可以从当前来源列表直接推导结果，不需要理解后台“自动优化护盾组合”。

渡劫开战固定顺序：

```text
清空上一场护盾
→ 锁定开战最大生命与两级上限
→ 先生成护劫护盾
→ 再结算普通开战被动、法宝或其它护盾来源
```

因此破境丹承诺的 `10%—80%` 不会被普通开战被动先占容量后裁剪；普通来源只使用护劫生成后的剩余容量。同一时刻的其它普通来源按既有稳定战斗事件顺序处理，不按数值大小、持续时间或 UI 排列重新排序。

同一来源再次成功触发时，按“本次生成量加到当前值、最多到来源上限”的方式补充，并刷新持续时间；不是无条件瞬间回满。若总护盾已满，本次数值补充可以为 `0`，但已经存在的该来源仍刷新持续时间。尚不存在的新来源若实际写入为 `0`，不创建空护盾条目。

最大生命在战斗中变化时，本场护盾来源上限与总上限仍使用开战快照，不扩大、不缩小，也不追溯裁剪已有护盾；下一场重新读取新的开战最大生命。

#### 选项 B｜新来源自动替换即将到期的已有护盾

达到总上限时，新护盾优先挤掉剩余时间最短的已有来源，为自身腾出容量。它能减少即将过期的浪费，但会让“生成护盾”同时成为删除其它来源的操作；周期性小盾可能不断改写大盾组成，玩家难以从最终数值判断哪些来源仍在。

#### 选项 C｜达到总上限时按比例压缩全部来源

所有来源按比例缩小以容纳新护盾。表面公平，但每次生成都会改写全部来源当前值，破坏同源补充、持续时间优先消耗和战斗日志可解释性，不推荐。

当前推荐选项 A。确认后再处理伤害消耗优先级。

### 9.4 `SHIELD-01-Q3`｜受击消耗优先级

审计状态：本节全部候选已失效，只保留为模型演进记录。统一总护盾条直接扣总量，不再区分来源优先级。

#### 选项 A｜先到期先消耗，同到期时后生成先消耗（推荐）

一次生机伤害在进入体魄属性减伤前，按以下顺序逐来源扣除：

```text
1. 剩余持续时间更短的来源先消耗
2. 到期时间相同或都持续整场时，后生成 / 后刷新的来源先消耗
3. 仍完全并列时，使用稳定来源 ID 决定，不读取 UI 排列
4. 当前来源耗尽后，剩余伤害继续扣下一个来源
5. 全部护盾耗尽后，剩余伤害进入体魄属性减伤与最低伤害规则
```

同源刷新持续时间时，同时更新该来源的“最近刷新顺序”，因此它在相同到期时间组内视为较新的外层护盾。来源耗尽后移除；以后再次触发时按新来源重新生成。

护劫护盾开战时最先生成且持续整场，因此：

- 有限时长普通护盾通常先于护劫护盾消耗，避免临时盾未使用便到期；
- 后生成的整场普通护盾与护劫同在战斗结束时到期时，普通来源作为较新外层先消耗；
- 护劫护盾通常成为最后的基础保障，但这来自统一的到期 / 生成顺序，不需要额外记忆“护劫永远最后”。

该顺序只影响多来源护盾的内部扣除，不改变总吸收值。若护盾完全吸收本次伤害，最终生机伤害为 `0`；若有剩余，才对剩余伤害应用体魄减伤，并在正伤害情况下执行最低 `1` 点规则。

#### 选项 B｜护劫护盾固定优先消耗

所有渡劫伤害先扣护劫护盾，再扣普通来源。它最容易解释破境丹消耗，但会使即将到期的普通盾经常浪费，也降低防御构筑在渡劫中的协同价值。

#### 选项 C｜护劫护盾固定最后消耗

普通来源无条件先扣，护劫永远保底。结果接近选项 A 的常见情况，但需要额外处理普通整场盾、同刻刷新和特殊无限时长来源；统一性较差。

当前推荐选项 A。确认后只剩同源持续时间细节与最小验算，可一并关闭 `SHIELD-01`。

Q3 的三个选项因用户重构护盾模型而不再采用。持续时间优先、护劫固定优先和护劫固定最后都只在护盾按来源保存时有意义；当前统一总护盾条不存在来源消耗顺序。

### 9.5 用户重构｜整场统一总护盾条

| 编号 | 当前裁决 |
| --- | --- |
| `SHIELD-R04` | 所有普通护盾与护劫护盾生成后立即合并为一个总护盾数值，不保留来源余额、独立持续时间或刷新状态。所有护盾持续整场战斗，直到被伤害消耗或战斗结束。来源只在生成日志中保留，用于解释本次增加值，不参与后续扣除。 |

| `SHIELD-R06` | 受击时直接从统一总护盾一比一扣除，不再排序来源。总护盾完全吸收则生机伤害为 `0`；剩余伤害继续进入体魄减伤和正伤害最低 `1` 点规则。 |

当前生成与受击流程为：

```text

→ 锁定开战最大生命、普通单次 50% 上限和总量 100% 上限

战中生成普通护盾
→ 计算本次最终生成量
→ 裁剪到普通单次 50%
→ 加入总护盾并裁剪到总量 100%
```

## 10. `F-04 / END-01`｜多人流程韧性与主动结束

状态：Q1—Q6 已确认并统一回写；审计用

### 10.1 已有边界

1. 标准支持 `2—4` 名玩家；五个宗门同局不可重复。
2. 回合采用同时准备、隐藏规划、同步移动和统一行动结算；其他玩家只能看到是否提交，不能看到计划内容。
3. 单人事件、单人 PVE、独立渡劫和参数输入只等待相关玩家；涉及多名玩家的竞争才暂停全局统一行动队列。
4. 标准局没有强制最终回合、现实时间上限或替代胜者。
5. 飞升前主动提前结束只能产生无胜者结果，不能按修为、地产或资产选出领先者。

### 10.2 `F-04-Q1`｜房间、宗门选择与开局倒计时

#### 选项 A｜目标席位＋全员准备后自动开局（推荐）

房主创建房间时选择目标席位数 `2—4`。房间等待阶段本身不设强制倒计时；只有同时满足以下条件才进入 `10` 秒开局倒计时：

```text
目标席位全部有人
+ 每名玩家已确认一个未重复宗门
+ 每名玩家已标记准备
```

规则：

- 玩家准备前可自由更换未被锁定的宗门；准备后宗门锁定。
- 玩家取消准备时同时解除自己的开局锁定，但不自动放弃当前宗门选择；其他玩家仍不能选择已被其占用的宗门。
- 两名玩家近同时确认同一宗门时，以服务器 / 会话收到确认的稳定顺序为准；落后者保持未选择并立即收到冲突提示。
- 倒计时期间任一玩家取消准备、掉线、离开，或宗门选择失效，倒计时立即取消并回到等待阶段。
- 房主要以更少人数开局时，必须先在未倒计时状态修改目标席位数；不能在倒计时中踢除未准备席位或强行开始。
- 全部条件持续满足至倒计时结束后自动开局，不再要求房主二次点击开始。
- 房主在大厅离开时，把房主权限移交给当前最早加入且仍连接的玩家；无人可接替时关闭房间。
- 房主身份只管理大厅设置，不在对局中获得结算、暂停、踢出或终局特权。

#### 选项 B｜房主在达到两人后随时强制开局

房主可以忽略未准备状态手动开始。优点是组织熟人局更快；问题是未完成宗门选择、设置或理解规则的玩家可能被强制带入对局，房主权力也会延伸为多人争议来源，不推荐。

#### 选项 C｜大厅创建后固定倒计时开局

房间创建即开始固定时限，到时按当前人数开局或关闭。优点是公开匹配节奏固定；问题是本方案当前没有独立匹配队列与机器人补位规则，且宗门选择、加入速度和新手阅读时间差异较大，容易造成无准备开局，不推荐。

#### 已确认裁决

采用选项 A。`10` 秒只承担“全员已经准备后的反悔缓冲”，不是强迫大厅结束的等待时限。

| 编号 | 当前裁决 |
| --- | --- |
| `F04-R01` | 房主设置 `2—4` 个目标席位；目标席位满员、宗门均唯一且全员准备后进入 `10` 秒倒计时，条件失效立即取消，条件保持则自动开局。房主没有强制开局或对局内特权；大厅房主离开时按加入顺序移交。 |
| `F04-R02` | 宗门选择采用大厅内自由选择与占用，不再使用旧集中记录 `S05-R11` 的“房间准备完成后随机生成顺序、玩家依次选宗门”。近同时确认同一宗门时按服务器 / 会话稳定收到顺序处理，落后者保持未选择。该条是对旧顺序制的显式替代。 |

### 10.3 `F-04-Q2`｜阶段计时、提交撤回与未提交默认

#### 选项 A｜基础时限＋全局个人思考储备＋安全默认（推荐）

标准房间采用以下初始计时锚点；所有阶段在相关玩家全部完成后都可提前结束，不强制等满：

| 输入阶段 | 基础时限 | 超时前允许的操作 |
| --- | ---: | --- |
| 回合开始即时阶段 | `60` 秒 | 执行即时行动、整理构筑并标记完成 |
| 隐藏规划 | `90` 秒 | 编辑并提交移动与主要行动计划 |
| 抵达后的行动细节输入 | `45` 秒 | 为已承诺行动补齐对象、数量、投入等参数 |
| 事件强制选择、多人竞争等短响应 | `30` 秒 | 仅由相关玩家输入；无关玩家不等待确认 |

每名玩家另有一份本局共享的个人思考储备，初始建议为 `180` 秒：

- 某玩家在当前输入的基础时限结束时仍未完成，才开始消耗自己的储备；已经完成的玩家不消耗。
- 多名未完成玩家的储备同时计时，不按座位依次扣减。
- 储备可以跨即时、规划、参数与短响应使用，但不会每回合恢复。
- 基础时限与 `180` 秒储备是首轮标准房间的调参锚点；以后若提供快速 / 宽松预设，必须在开局前对所有玩家公开并固定，对局中房主不能临时延长、缩短或暂停他人计时。

提交与撤回统一遵守：

1. 即时阶段的“完成”和隐藏计划的“提交”在阶段真正锁定前可以撤回；其他玩家只看完成 / 提交状态，不看计划内容。
2. 全部相关玩家完成或提交时进入 `3` 秒收束倒计时；任一玩家撤回则取消收束。倒计时结束或所有未完成玩家触发超时默认后，阶段锁定。
3. 已经单独确认并立即结算的即时行动不会因撤回“完成”而回滚；尚在编辑器中的未确认调整不视为已执行。
4. 单人独立参数确认后可以立即进入其个人结算，不提供事后撤回；多人暗标、同时选择等输入在所有相关玩家锁定前保持隐藏，并使用同一 `3` 秒收束。

超时默认以“不替玩家消费资源、不猜测策略、不因超时取得代偿收益”为原则：

- **即时阶段超时**：保留已经确认并结算的即时行动；放弃未确认编辑，自动结束即时阶段。
- **隐藏规划超时**：未提交者自动执行“留驻”——本回合不移动、不使用移动法门或法宝、不执行主要行动；仍正常参加回合末自动修炼与研习。不得自动提交屏幕上最后一份草稿。
- **行动参数超时**：视为主动放弃已经承诺的主要行动；不支付尚未确认的费用，也不触发“成功抵达但客观上无任何合法参数”才有的代偿事件。
- **多人竞争输入超时**：视为不出价、不追加投入或放弃该项可选竞争资格；已经按上位规则不可撤回的前置成本不返还。
- **必须得到结果才能继续的事件选择**：每个此类内容模板必须预先标记一个无额外消费、风险最低且不改变其他玩家资产的安全默认；没有合法安全默认的模板不得进入正式内容表。

计时只在玩家已经取得控制权并能够合法输入时运行；世界更新、同步移动演算、自动战斗播放、服务器结算和不可操作动画不占用玩家输入时间。掉线是否暂停或转入托管留给 Q3，不在本题预先假定。

#### 选项 B｜只有固定阶段时限，不设个人思考储备

仍使用分阶段硬时限并采用相同安全默认。规则最简单、局长最稳定，但复杂后期回合、新手阅读和偶发无障碍需求没有弹性，玩家可能为了避免整轮留驻而被迫仓促提交，不推荐。

#### 选项 C｜无统一硬时限，由提醒或房主催促推进

只显示建议时间，依靠全员自行完成或房主操作结束等待。熟人局最宽松，但无法防止无响应与拖延，房主也会取得对局中干预权，与 `90—120` 分钟局长目标和 Q1 的房主无对局特权冲突，不推荐。

#### 已确认裁决

采用选项 A。其重点不是要求玩家每阶段都用满固定秒数，而是让通常回合提前完成、少数复杂决策使用有限的跨局储备，并让真正未响应时有无收益、可预测的安全结果。

| 编号 | 当前裁决 |
| --- | --- |
| `F04-R03` | 标准房间的即时、隐藏规划、行动参数和短响应基础时限依次以 `60 / 90 / 45 / 30` 秒为首轮锚点；每名玩家另有 `180` 秒整局跨阶段个人思考储备。相关玩家全部完成后可以提前结束；对局中房主不能改变计时。 |
| `F04-R04` | 即时完成与隐藏计划提交在阶段锁定前可以撤回；全员完成时进入 `3` 秒收束倒计时，撤回会取消收束。已经单独确认并结算的即时行动不回滚；单人参数确认并开始结算后不事后撤回，多人隐藏输入在共同锁定前不公开。 |
| `F04-R05` | 未响应使用无消费、无策略猜测、无额外收益的安全默认：即时阶段保留已确认结果后结束；规划使用“留驻”；行动参数超时放弃行动且不给代偿事件；竞争超时视为不参与或不追加；强制事件模板必须预设安全默认。不可操作演算与播放不占输入时间。 |

### 10.4 `F-04-Q3`｜掉线、重连与临时托管

#### 选项 A｜有限断线保护＋无策略安全托管（推荐）

每名玩家拥有独立于个人思考储备的断线保护额度：

```text
单次断线最多保护 60 秒
整局累计最多保护 180 秒
```

断线保护从系统确认连接中断时开始按现实时间计算，不因当时是否正在等待该玩家而延后：

- 其他玩家可以继续完成不依赖掉线者的输入、独立事件、独立 PVE 与界面查看；只有流程真正抵达必须等待掉线者的共同锁点时，才会在剩余保护期内等待。
- 掉线者当前输入计时与个人思考储备冻结，不会把网络中断误算为思考时间。
- 玩家在本次 `60` 秒和整局 `180` 秒额度都未耗尽前重连，恢复到同一席位与当前尚未锁定的输入；服务器已经确认的行动保持有效。
- 单次或累计保护先耗尽且玩家仍未重连时，当前未完成输入立即使用 Q2 的对应安全默认，玩家进入临时托管；不再继续消耗个人思考储备。
- 若玩家断线时当前没有待输入，保护到期后直接标记为托管；其下一次需要输入时不再新增等待，立即使用安全默认。

重连恢复遵守状态不可回滚与隐藏信息不泄漏：

1. 已经锁定、结算或由托管提交的结果不能撤销；重连者从下一个尚未锁定的本人输入点恢复控制。
2. 系统提供断线期间的个人追赶摘要，包括公开事件、本人资产与状态变化、托管采用的默认动作；不显示当时仍应隐藏的其他玩家计划、暗标或未公开选择。
3. 仍在保护期内且输入尚未锁定时，重连者继续使用断线前剩余的基础时限 / 思考储备，不重新取得完整计时。
4. 掉线与托管状态向全体公开，但其他玩家只能看到连接状态、是否已由托管完成和流程等待原因，不能看到其隐藏输入内容。

临时托管不使用会规划路线、估价、消费资源或选择攻击对象的策略 AI，只执行现有自动系统与安全默认：

- 已锁定构筑下的自动战斗、回合末修炼 / 研习、恢复、炼化、寿元、地产收入和世界结算照常进行。
- 托管不会主动逃遁、服丹、换功、调整构筑、移动、执行主要行动、竞价或发动可选冲突。
- 玩家可以在连接正常时主动开启临时托管；若当前有未提交输入，确认开启即对该输入使用安全默认。
- 玩家可以随时请求退出托管，但只能接管尚未锁定的输入，不能回滚托管已经生成的结果。
- 房主无权替其他玩家开启、关闭或操作托管。

普通自动战斗若在断线前已经开始，仍按锁定构筑自动演算；系统不会代替掉线者发起主动逃遁。若该战斗属于必须等待玩家手动短响应的特殊模板，则仍按 `30` 秒短响应和本题断线保护处理。永久离线何时转为退出、退出后席位和资产如何处理留给 Q4。

#### 选项 B｜掉线后由策略 AI 继续操作（MVP 不采用；未来已选方向）

AI继续规划移动、选择主要行动与处理日常资源。MVP 尚无成熟策略 AI，若现在采用就无法稳定定义信息边界、策略强度和责任归属，因此当前阶段不采用。未来单人模式的策略 AI 完善后，托管升级采用该方案，但固定使用保守策略，只读取该席位本来合法可见的信息，不读取其他玩家隐藏计划、暗标或未公开选择。

未来的保守托管既用于断线，也允许玩家主动开启以降低操作或决策负担；它属于合家欢定位下的正式辅助方式，不视为违规或消极游戏。AI 具体如何选择低风险路线、保留稀有资源、避免主动冲突及处理胜利目标，留到单人 / AI 专题建立时配套裁决。

#### 选项 C｜任一掉线即全局无限暂停，等待重连或玩家投票

最能保护掉线者的完整操作机会，但一次网络故障即可无限阻塞整局，并把是否继续游戏转化为其他玩家的临时裁量；与已确认的有限计时和局长目标冲突，不推荐。

#### 已确认裁决

MVP 采用选项 A。它把网络故障与玩家思考分开保护，同时把全局最多受阻时间限制在可预测范围内；保护耗尽后的托管只维持角色与世界规则，不替玩家做策略决策。

未来单人模式的策略 AI 完善后，保留 A 的断线保护、重连、不可回滚和隐藏信息边界，把托管执行层升级为选项 B 的保守策略 AI。玩家可以主动托管以减少操作与决策负担。

| --- | --- |
| `F04-R06` | MVP 每名玩家单次断线最多保护 `60` 秒、整局累计最多 `180` 秒；断线期间冻结其输入计时和思考储备，不依赖其输入的流程继续。保护耗尽后使用 Q2 安全默认并进入无策略临时托管。 |
| `F04-R07` | 重连不回滚已锁定、已结算或托管生成的结果，只接管尚未锁定的本人输入；追赶摘要不得泄露其他玩家隐藏信息。房主不能控制他人托管，玩家可以主动启用 MVP 安全托管。 |
| `F04-R08` | 未来单人模式策略 AI 成熟后，临时托管升级为只读取合法玩家信息的保守策略 AI，并同时作为玩家主动降低操作 / 决策负担的辅助功能。AI 策略细则由未来单人 / AI 专题维护，不提前伪造实现默认。 |

### 10.5 `F-04-Q4`｜永久退出、对局续行与资产边界

#### 选项 A｜席位退隐＋地产保持归属（推荐）

永久退出只由玩家在连接正常时通过二次确认主动触发；关闭客户端、网络中断或进入临时托管都不自动视为永久退出。其他玩家和房主不能投票踢出或替其确认永久退出。

退出请求遵守“已锁定结果不回滚，新决策不再生成”：

1. 尚未锁定的本人输入立即使用对应安全默认，不再开放新的主动选择。
2. 已经锁定的移动、主要行动、竞争、战斗或事件链继续结算到该角色当前不可拆分的因果链结束；不能通过退出逃避已经承诺的支付、战败或掉落。
3. 因果链结束后角色从地图移除，席位标记为“永久退隐”，本局不能由原玩家或新玩家重新接管。
4. 若退出角色在移除前的已锁定战斗中死亡，仍按正常死亡与战利品规则结算；正常退隐本身不是死亡，不生成战利品。

角色与资产按以下边界处理：

| 状态 | 永久退出结果 |
| --- | --- |
| 角色、当前境界 / CP、属性、状态、已学知识与掌握度 | 随退隐席位移出本局，不转移给其他玩家 |
| 灵石、物品、法宝、未学习功法载体与其它随身资产 | 在角色正式移除时由系统回收，不掉落、不拍卖、不赠送 |
| 已下单但尚未领取的个人成品 | 原订单不退款；完成时直接由系统回收 |
| 节点主导权、已有建筑、建设 / 改建中状态 | 保留为“退隐宗门地产”，不因退出直接转为无主或转给其他玩家；以后仍可被事件或其它正式游戏规则合法易主 |
| 退隐地产的稳定供养与收费收入 | 在合法易主前不再积累到退出玩家账户；供养作废，所有本应支付给退出玩家的费用由系统回收 |
| 退隐地产的使用与建设状态 | 其他玩家仍可按原规则停留和使用并支付费用；已经锁定的建设 / 改建照常完成，但退隐后不再发起新建设 |

系统不再维护退出玩家的灵石、贡献点、修为、资产、收入累计或其它继续变化的个人数值。退隐宗门地产只保留地图上仍有规则意义的归属、建筑与建设状态；若以后通过合法事件或规则转给新玩家，从易主完成时起按新归属正常结算收益与费用。

对局续行规则：

- 只要仍有至少一名未永久退出的玩家，对局继续，不因人数降至 `1` 自动授予胜利；剩余玩家仍必须完成正常飞升条件。
- 暂时掉线或临时托管的席位仍属于未永久退出玩家，不触发退隐资产处理。
- 房主或当前会话协调者永久退出时，协调身份移交给当前最早加入且仍连接的未退隐玩家；该身份仍无对局裁决特权。
- 当所有未退隐玩家都暂时没有连接时，世界流程冻结，不让托管席位在无人观看时无限推进；任一玩家重连后恢复。会话技术保存时长以后作为平台配置，不改变规则结果。
- 所有玩家均永久退出时，对局立即以“已中止、无胜者”结束。

该方案不让退出成为给盟友赠送资产、把地产重新投放形成抢购风口，或逃避已锁定战斗的工具；同时尽量保持其他玩家此前围绕地图主导权形成的局势不被场外退出突然重置。

#### 选项 B｜退出后全部地产恢复无主

角色和随身资产回收，所有地产立即重新开放购买。地图会更活跃，但退出会制造规模与位置完全取决于场外行为的抢地红利，甚至可能被用于给特定玩家让地，不推荐。

#### 选项 C｜退出资产自动转给其他玩家或现场拍卖

按房主、最低修为、随机结果或竞价分配退出资产。能减少闲置地产，却会凭退出事件投放大量非正常收益，并引入串通、补偿公平和拍卖时序问题，不推荐。

#### 已确认裁决

采用选项 A。核心口径是“退出者从玩家竞争与数值维护中移除，但已经形成的地图结构不因退出直接重置”。退隐地产以后仍能通过事件等游戏内合法途径被其他玩家取得；合法易主前，本应支付给退出玩家的费用由系统回收。

| --- | --- |
| `F04-R09` | 永久退出只能由连接正常的玩家二次确认；断线、关闭客户端或临时托管不自动转为退出。未锁定输入使用安全默认，已锁定因果链继续结算。早期“结算后角色退隐”的时点已被 `F04-R14` 统一覆盖：这里只标记待退隐，实际移除只在最近一次合法回合开始即时阶段第一步发生。 |
| `F04-R10` | 退出玩家的角色、知识与个人数值停止维护，随身资产由系统回收且退隐本身不生成掉落。已锁定战斗仍正常结算，不能通过退出逃避支付、战败或掉落。 |
| `F04-R11` | 退出时地产不直接转为无主或转让，保留为退隐宗门地产；退出玩家不再积累任何个人数值，本应支付给其的费用由系统回收。地产仍可通过事件等正式游戏内途径合法易主，易主后按新归属正常结算。 |
| `F04-R12` | 对局不因只剩一名未退隐玩家而自动判胜；全部玩家永久退出时才立即以无胜者中止。暂时无人连接时冻结世界，重连后恢复；会话协调身份只迁移连接职责，不产生对局特权。 |

### 10.6 `END-01-Q5`｜全体玩家主动提前结束

#### 选项 A｜所有未退隐玩家一致同意，无胜者结束（推荐）

任一连接正常且未永久退隐的玩家都可以发起结束提议。发起后立即进入全局暂停：

- 同一外界回合最多开启一次结束表决，避免重复弹窗；表决持续 `30` 秒。
- 所有阶段输入计时、个人思考储备、断线保护、自动战斗时钟、动画推进与服务器游戏结算全部冻结；其他玩家不能趁表决修改构筑、计划、报价或其它游戏输入。
- 表决倒计时、连接状态检测、重连和表决界面自身仍然运行；否则掉线玩家无法恢复并亲自表决。
- 所有尚未永久退隐的玩家都必须亲自同意。临时掉线、安全托管及未来策略 AI 托管都不能代替玩家投赞成票；未响应或明确反对均使本次表决失败。
- 其他玩家只能看到谁已响应、谁尚未响应以及最终结果；表决不公开任何隐藏计划、暗标或未公开选择。
- 全员同意后进入 `3` 秒最终确认倒计时；倒计时内任一玩家撤回同意，表决取消。倒计时结束后结束决定不可撤销。
- 表决失败只关闭提议，随后从暂停前的同一确定状态继续计时与结算；任何房主、会话协调者或单个玩家都没有额外票权。

结束生效点按是否已经锁定本轮隐藏计划区分：

1. **隐藏计划尚未全局锁定**：完成当前已经开始的不可拆分即时结算后结束；未锁定计划与未确认草稿全部放弃，不产生支付或效果。
2. **隐藏计划已经全局锁定**：完整结算本外界回合，包括已锁定移动、主要行动、战斗、回合末成长与同轮飞升判定，再结束对局。不能通过结束表决撤销已承诺行动或阻止该轮合法飞升。
3. 若本轮结算中已经出现合法飞升者，按正常飞升胜利记录，不再改写为提前结束；只有整轮结束后仍无飞升者时，才应用“全体一致提前结束、无胜者”。

最终结果页固定表达：

```text
对局已由全体玩家一致同意提前结束
结果：无胜者
已完成外界回合：N
```

结果页可以展示各玩家公开历程与最终状态供复盘，但不能按修为、境界、地产、灵石、战力或综合评分排列替代名次，也不发放飞升胜利记录。该结果在战绩中记为“共同中止”，不记为任何玩家获胜或战败。

#### 选项 B｜只要求当前连接玩家一致同意

临时掉线或托管玩家不参与门槛。能够避免离线席位阻塞结束，但可能在玩家仍有重连权时直接终止其对局，与已确认的断线保护和托管可回归定位冲突，不推荐。

#### 选项 C｜多数票、房主决定或领先者判胜

多数票或房主决定会允许部分玩家强行结束他人的正常对局；按当前领先状态选胜者则会反向制造一套隐藏的计分终局，与“飞升是唯一胜利、没有替代胜者”的既有边界直接冲突，不推荐。

#### 已确认裁决

采用选项 A，并按用户修正为发起表决即全局暂停。它允许所有玩家在一致认为无需继续时体面结束，又不让暂时掉线、托管、房主身份或场上领先转化为剥夺他人继续游玩的权限。

| 编号 | 当前裁决 |
| --- | --- |
| `END-R01` | 任一连接正常且未退隐玩家可以发起结束表决；同一外界回合最多一次。表决触发全局暂停，除 `30` 秒表决、连接检测、重连和表决界面外，所有游戏计时、输入和结算冻结；失败后从同一状态恢复。 |
| `END-R02` | 只有全部未永久退隐玩家亲自同意才能通过；掉线、MVP 安全托管、未来策略 AI、房主和会话协调身份都不能代投或取得额外票权。全员同意后仍有 `3` 秒撤回缓冲。 |
| `END-R03` | 规划未全局锁定时，在当前不可拆分即时结算后无胜者结束；规划已经锁定时，恢复并完整结算本轮后结束。若该轮产生合法飞升者，优先记录正常飞升胜利；否则记为“共同中止、无胜者”，不生成替代排名。 |

### 10.7 已确认｜最小流程验算与关闭

以下用例均有唯一结果：

1. **大厅宗门冲突**：两人近同时确认同一宗门，稳定收到顺序较早者占用；另一人保持未选择，不能进入开局倒计时。
2. **倒计时中掉线**：全员准备后的 `10` 秒倒计时立即取消；玩家重连、宗门仍唯一且全员重新满足准备条件后，重新开始完整倒计时。
3. **全员提前提交后撤回**：进入 `3` 秒收束；任一玩家在结束前撤回，收束取消且隐藏内容不公开。
4. **规划未提交**：基础时限与个人思考储备均耗尽后执行“留驻”，不采用屏幕草稿、不消费移动资源、不执行主要行动，但仍取得正常回合末成长。
5. **行动参数超时**：已经抵达但有合法参数却未提交时，主动行动放弃且不支付未确认费用；不会冒充“客观无合法参数”取得代偿事件。
6. **规划中短暂掉线并重连**：输入与思考储备冻结；在单次 `60` 秒及整局 `180` 秒保护内重连时恢复剩余计时，不获得完整新时限，也不泄露其他玩家计划。
7. **断线保护耗尽**：当前输入立即使用安全默认并进入 MVP 无策略托管；以后重连只能接管尚未锁定输入，不能撤销托管结果。
8. **主动托管**：MVP 玩家可以主动选择无策略安全托管降低操作负担；未来策略 AI 完善后按保守策略继续合法日常操作，但仍不能读取隐藏对手信息。
9. **永久退出发生在未锁定输入**：未锁定输入使用安全默认；角色退隐、随身资产回收，不生成死亡掉落，退出玩家的全部个人数值停止维护。
10. **永久退出发生在已锁定战斗**：战斗与相关因果链照常结算；若在移除前死亡，正常掉落，不能用退出逃避败局。
11. **退隐地产后续易主**：合法易主前保留地图归属，原应支付给退出玩家的费用由系统回收；事件等正式规则完成易主后，从该时点起由新玩家正常取得收益。
12. **只剩一名未退隐玩家**：不自动胜利，对局继续并要求其合法完成飞升；所有玩家永久退出才立即无胜者中止。
13. **全员暂时离线**：世界冻结，不让托管席位自行无限推进；任一未退隐玩家重连后从保存状态恢复。
14. **结束表决中发生重连**：游戏计时与结算保持冻结，连接与重连仍运行；重连玩家可以在剩余表决时间内亲自同意，托管不能代投。
15. **结束表决失败**：明确反对或 `30` 秒内未全员同意，表决结束，所有计时与结算从暂停前的数值继续，不丢失或重复执行事件。
16. **规划锁定前一致结束**：当前不可拆分即时结算完成后直接记为共同中止；未锁定草稿无效。
17. **规划锁定后一致结束且同轮有人飞升**：恢复并完整结算本轮，合法飞升优先成为正常胜利；不能用中止票抹除已经锁定的飞升路线。
18. **规划锁定后一致结束但无人飞升**：本轮完整结算后记录“共同中止、无胜者”，最终状态只供复盘，不生成领先者或替代名次。

`F-04 / END-01` 的房间、阶段计时、未响应、断线、重连、托管、永久退出、资产、无人在线冻结和主动结束边界至此均有唯一答案，基础规则裁决关闭。未来保守策略 AI 的具体决策模型、平台会话保存时长，以及退出地产可调用的具体易主事件仍属于后续专题 / 内容配置，不影响本组关闭。

### 10.8 `F-04-Q6`｜连续掉线后的强制退隐（补充裁决）

用户补充边界：连续掉线达到固定时长后，席位必须失去重连资格，并在最近一次回合开始即时阶段执行角色退隐；角色不能在移动、行动、战斗、回合末或其它任意时点中途退隐。

该时长独立于 Q3 的断线保护：

- `60` 秒单次 / `180` 秒整局断线保护只决定何时停止等待并进入临时托管；
- 本题的连续离线时长决定何时把“临时可回归”变为“永久不可回归”；
- 玩家主动开启托管但连接仍正常时，不累计连续掉线时长；未来主动使用保守策略 AI 托管同样不累计。

#### 选项 A｜连续掉线 `10` 分钟后锁定强制退隐（推荐）

玩家连续掉线达到 `10` 分钟时，立即把席位标记为“待强制退隐”：

1. 从达到阈值的一刻起，即使客户端重新连上，也不再允许恢复该席位；这不是继续延长到下个回合的重连宽限。
2. 当前已经锁定的行动与因果链照常结算；未锁定输入继续由安全托管处理。
3. 在下一次外界回合开始更新完成后、即时阶段向其他玩家开放操作前，先执行强制退隐；这是该回合即时阶段的第一个系统步骤。
4. 强制退隐完全沿用 Q4：角色与个人数值停止维护、随身资产系统回收、退隐本身不生成掉落、地产保持退隐宗门归属并允许以后由合法游戏规则易主。
5. 本应在该回合开始更新中交给待退隐玩家的订单、收入或其它个人结果不再短暂写入其账户，直接按既有退出边界回收；地图建设等仍有公共意义的状态正常更新后保留。

为避免瞬断反复重置阈值：客户端恢复连接时先立即暂停连续掉线计时；只有稳定连接满 `30` 秒后，才把连续掉线累计清零。若在这 `30` 秒内再次掉线，则从先前已经累计的连续离线时长继续，而不是重新从零开始。只要连接已经恢复，连续掉线计时暂停期间不会越过 `10` 分钟阈值。

结束投票造成的全局暂停会同时冻结连续掉线强制退隐计时；表决结束后再继续，避免角色在游戏明确暂停期间跨过不可逆阈值。

若所有尚未退隐玩家都处于离线、世界因此冻结：

- 连续掉线计时仍按现实时间推进，因为它是连接资格边界，不是世界结算；
- 只要仍有至少一个席位未达到 `10` 分钟，世界保持冻结并允许其重连；
- 当最后一个未退隐席位也达到阈值时，已没有可恢复世界的玩家，不再人为推进一个无人回合；会话直接按“全部玩家退隐”记录为无胜者中止。这是无存续玩家时对即时阶段退隐规则的唯一结果等价例外。

`10` 分钟约占标准 `90—120` 分钟对局的 `8%—11%`：既明显长于普通重启客户端、切换网络或短暂家庭中断，又不会让一个无法回归的席位以安全默认持续影响过多回合。断线保护耗尽后的前 `9` 分钟左右由安全托管承接，因此不会让其他玩家继续等待。

#### 选项 B｜连续掉线 `5` 分钟后强制退隐

能更快清理长期离线席位，但游戏重启、家庭网络修复或平台重连稍慢就可能造成不可逆退隐；由于安全托管已经解除其他玩家的等待压力，没有必要把永久失去席位的门槛压得这么短，不推荐。

#### 选项 C｜连续掉线 `15` 分钟后强制退隐

对掉线者最宽容，但已经接近标准局长的八分之一到六分之一；MVP 无策略托管在这段时间只会留驻与放弃行动，容易长期保留一个实际不参与竞争却仍占席位的角色，不推荐。

#### 已确认裁决

采用选项 A：连续掉线 `10` 分钟后锁定强制退隐。

| 编号 | 当前裁决 |
| --- | --- |
| `F04-R13` | 连续掉线达到 `10` 分钟时，席位立即永久失去重连资格并标记为待强制退隐；该阈值独立于 `60 / 180` 秒断线保护，主动托管不累计。恢复连接会立即暂停累计，稳定连接 `30` 秒后才清零；期间再次掉线则续算。 |
| `F04-R14` | 待强制退隐角色只在下一外界回合开始更新完成后、即时阶段向玩家开放前退隐。已锁定因果链和当前轮托管照常结算；回合开始产生的个人订单 / 收入直接回收，公共地图建设状态正常更新。 |
| `F04-R15` | 结束表决的全局暂停冻结连续掉线计时。全员离线时世界冻结但连接资格计时继续；最后一个未退隐席位也达到 `10` 分钟后，因已无可恢复玩家，直接按全员退隐、无胜者中止。 |

补充验算：

1. **保护期内重连**：掉线 `40` 秒重连，仍处于单次 `60` 秒保护内；恢复当前输入剩余时间，不进入托管，更不会退隐。
2. **保护耗尽但未到退隐阈值**：掉线 `2` 分钟时已经进入安全托管，但仍有重连资格；重连后只能接管尚未锁定输入。
3. **临界重连稳定期**：掉线累计 `9` 分 `50` 秒时恢复连接，计时立即停在该值；稳定满 `30` 秒后清零。若稳定期内再次掉线，则从 `9` 分 `50` 秒续算，累计再达 `10` 秒即锁定退隐。
4. **回合中达到 `10` 分钟**：当前回合不把角色从移动、战斗或结算中途删除；席位立即不可重连，剩余输入由托管承接，下一回合即时阶段第一步执行退隐。
5. **即时阶段中途达到 `10` 分钟**：本即时阶段已经开放，不在阶段中途插入退隐；标记待退隐并在下一外界回合即时阶段第一步执行，保持所有退隐都发生在统一边界。
6. **退隐回合的开始收入**：回合开始更新照常完成地图建设；本应写入待退隐玩家账户的订单、供养或收费不创建余额，直接由系统回收，随后在即时阶段第一步退隐。
7. **结束表决覆盖阈值**：玩家掉线累计 `9` 分 `55` 秒时进入结束表决，全局暂停 `30` 秒；掉线累计仍为 `9` 分 `55` 秒，表决失败恢复后再计 `5` 秒才锁定退隐。
8. **全员离线**：世界保持冻结，各席位按现实连接状态分别累计；仍有任何席位未到 `10` 分钟时允许其重连。最后一个席位也达到阈值后直接无胜者中止，不运行无人回合或产生新的世界收益。

补充用例与原十八类流程验算相容，`F-04 / END-01` 再次关闭。未来保守策略 AI、平台会话保存时长和具体地产易主事件仍是后续专题 / 配置项，不影响基础规则关闭。
