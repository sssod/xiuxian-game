# 战斗玩法设计

## 1. 定位

战斗 / 斗法不是独立复杂战棋、实时操作或高频刷怪系统，而是高风险事件链中的轻量结算框架。

它服务于：

```text
移动遭遇
节点危机
秘境遭遇
宗门任务
突破外扰
护法失败后的直接冲突
资源争夺
剧情切磋或死战
```

玩家体验目标是“预判、克制、消耗管理和后果承担”，不是长时间操作。玩家应根据敌方风格、己方资源、事件目标和环境规则排布短序列；判断正确时低损化解威胁或抓住空档，判断错误时在对应交锋格承担明显后果。

## 2. 与共享日历结算的关系

战斗发生在共享世界日历推进过程中，由事件、移动、秘境、宗门行动、突破外扰或资源争夺触发。

标准流程：

```text
世界日历按小时 tick 推进
→ 某 tick / 节点 / 路途段触发战斗事件
→ 当前行动结算暂停进入事件链
→ 判断是轻遭遇还是正式交锋
→ 轻遭遇走个人局部时停
→ 正式交锋进入 B1 专用交锋
→ 生成战斗结果包
→ 回写角色、位置、资源、节点、宗门、日志与回放
→ 父事件链决定继续原计划、消耗时间、中断、撤退、重伤、死亡或转世
```

战斗系统只负责内部指令对抗和结果输出。后续行动、死亡、转世、宗门评价、节点变化和传闻由父事件链解释。

## 3. 战斗分级

### 3.1 轻遭遇

轻遭遇是短文本、少选项、低风险或低复杂度的个人事件，例如：

```text
采药时遇到低阶妖兽
路上被外门弟子挑衅
小型陷阱
低风险野兽惊扰
普通低阶劫道
```

处理规则：

```text
事件玩家本人局部时停
其他世界 N1
gap 最多 1 游戏日
选择后 C1 追赶
通常不进入完整 5 格战斗
```

轻遭遇可以直接提供“迎战 / 闪避 / 交涉 / 使用符箓或护符 / 撤退”等少量选项。只有当后果足够重、敌方足够强、涉及多人或资源争夺时，才升级为正式交锋。

### 3.2 正式交锋

正式交锋包括：

```text
秘境关键战斗
强敌斗法
玩家直接冲突
多人组队战斗
宗门任务战斗
可能导致重伤 / 死亡 / 重大资源损失的战斗
突破挑战或突破外扰
```

处理规则：

```text
世界进入 B1
使用 B1 专用界面和默认策略
每轮现实提交窗口默认 60 秒
未提交者执行当前默认策略
不因单个玩家未选择而 P0
非参战玩家也处在同一世界慢速中
```

正式交锋不使用个人局部时停。它需要让参战者和非参战者共享同一世界时间秩序，避免私人战斗在世界背后无限冻结。

## 4. B1 时间比例复审

### 4.1 问题

旧口径曾把 B1 现实窗口、世界推进和交锋自身耗时合并理解为：

```text
每次 B1 决策都让交锋自身消耗 1 游戏小时
普通正式交锋 = 3～8 轮
复杂正式交锋 = 最多 12 轮
硬上限 = 24 轮
```

则普通斗法会经常消耗 3～8 游戏小时，复杂战斗会消耗半日，硬上限会消耗一整日。这不适合修仙世界观下的大多数战斗。

更合理的世界观口径：

```text
真正的斗法交锋通常短促、猛烈、胜负窗口窄。
修士会在短时间内完成试探、破招、祭宝、护体、撤退或一击定胜负。
长耗时应来自追击、围困、阵法拉锯、秘境路径、疗伤、战后搜索、突破准备或突破巩固。
突破的长期部分应主要落在准备期和事后巩固，挑战本身应是集中爆发。
```

因此，原有比例的问题不是 60 秒提交窗口太长，而是把“玩家现实思考时间”直接等同为“游戏世界过去 1 小时”。

### 4.2 修正方案

本目录包采用四层时间：

| 层级 | 含义 | 设计用途 |
| --- | --- | --- |
| 现实提交窗口 | 玩家现实中本轮可提交和修改选择的时间，默认 60 秒 | 保护思考时间，防止多人卡死 |
| B1 世界推进 | 每个 60 秒窗口对应房间和非参战玩家推进 1 游戏小时 | 维持多人共享日历和常态行动推进 |
| 交锋叙事耗时 | 交锋本身在故事中消耗的分钟或小时 | 表达斗法、突破、追击、护法的真实耗时 |
| 交锋结算耗时 | 参战交锋最终计入的游戏时间 | 扣减持续效果、处理 gap、回写结果包 |

核心规则：

```text
B1 = 交锋慢速、提交窗口和非参战世界推进，不再等同交锋自身固定 1 游戏小时。
每个 60 秒现实决策窗口仍让其他玩家按 B1 完成 1 游戏小时行动推进。
战斗交锋自身按 5 个交锋格 = 10 分钟叙事耗时计算。
常规战斗 3 轮交锋共 30 分钟，结算不足 1 小时按 1 小时计。
突破交锋按突破模板声明阶段耗时，总耗时暂定 1～6 小时。
```

这样既保留 B1 的同步优势，又避免普通战斗在叙事上变成长时间拉锯。

### 4.3 建议时间模板

| 场景 | 交互方式 | 建议轮数 / 阶段 | 交锋叙事耗时 | 交锋结算耗时 | 说明 |
| --- | --- | ---: | ---: | ---: | --- |
| 轻遭遇 | 局部时停选项 | 1 次选择 | 0～1 小时 | 按事件选项 | 不进入完整 B1，按事件选项回填 |
| 常规战斗交锋 | B1 + 5 格战术序列 | 3 个战斗回合 | 30 分钟 | 1 小时 | 每回合 5 格共 10 分钟；每回合 60 秒现实窗口 |
| 非常规战斗交锋 | B1 + 5 格战术序列 | 模板指定 | 每回合 10 分钟，额外追击 / 转场另算 | 不足 1 小时按 1 小时，额外耗时按模板 | 强敌、秘境关键战、资源争夺 |
| 突破挑战 | B1 + 单格阶段选择 | 模板指定，常见 2～6 阶段 | 每阶段由模板声明 | 模板累计，暂定总耗时 1～6 小时 | 每阶段只输入 1 个交锋格 |
| 长期围困 / 拉锯 | 事件链或长期行动 | 不按普通战斗处理 | 多小时到多日 | 多小时到多日 | 应转为节点事件、宗门行动或长期对峙状态 |

战斗交锋与突破交锋均沿用 gap 最大不超过 1 游戏日的限制，不在实现层面额外增加其他时间预算限制。实际设计层面，普通战斗交锋一般不超过 1 游戏小时，突破交锋一般不超过 6 游戏小时。

常规战斗示例：

```text
3 轮战斗交锋；
每轮 5 个交锋格；
每轮叙事耗时 10 分钟；
交锋自身共 30 分钟；
每轮现实决策窗口 60 秒；
现实时间最多 3 分钟；
B1 世界推进 3 游戏小时；
非参战玩家完成 3 游戏小时行动推进；
参战交锋结算不足 1 小时，按 1 小时计。
```

战斗交锋中每个轮次的 10 分钟耗时主要有叙事作用，几乎不进入逐格计算。突破交锋不同：由于 2～3 个突破阶段就可能累计超过 1 游戏小时，突破阶段耗时除了叙事作用，也参与效果、资源和时间结算。

## 5. 5 格战斗结构

正式战斗内部采用 5 格战术预输入。一个 B1 提交窗口内，玩家为本战斗回合填入 5 个交锋格。

```text
战斗回合开始
→ 查看状态、可用指令、事件目标、敌方倾向
→ 玩家 / AI 各自填入 5 个交锋格
→ 倒计时结束或全员提前提交后锁定
→ 第 1 格交锋结算
→ 检查结束条件
→ 第 2 格交锋结算
→ 检查结束条件
→ ...
→ 第 5 格交锋结算
→ 回合结束处理
→ 若未结束，进入下一 B1 提交窗口或模板结局
```

每个交锋格后都检查结束条件，允许提前结束。战斗不需要为了填满 5 格或达到预设轮数而继续结算。

突破挑战不使用 5 格战术序列。每个突破阶段只需要 1 个交锋格的选择与输入，决策窗口同样为 60 秒现实时间。

## 6. 战斗资源

三条战斗相关属性条：

| 显示名 | 含义 | 承载 |
| --- | --- | --- |
| 生机 | 生命、健康、肉身完整度 | 受伤、濒死、肉身崩溃 |
| 元气 | 法力、气力、可支配能量 | 术法消耗、法宝驱动、疲惫 |
| 神念 | 灵魂、神识、心神稳定 | 神魂攻击、幻术、心魔、操控 |

三者都是角色持久状态，不是战斗内临时资源。战斗开始读取当前值，战斗结束回写变化，不自动恢复满值。

建议区分三类变化：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 消耗 | 主动指令支付的成本 | 施法消耗元气、禁术消耗神念 |
| 伤害 | 被对方指令或事件造成的削减 | 剑伤削减生机、魂刺削减神念 |
| 状态封锁 / 扰动 | 不一定立刻削减当前值，但影响效率 | 元气紊乱、神念震荡、经脉阻滞 |

战斗结束条件默认只统计对方造成的伤害，不统计角色主动消耗。特殊模板可以例外。

## 7. 结束条件

每场战斗进入时必须携带 `battle_rule`：

```yaml
BattleRule:
  battle_type: spar | deathmatch | escape | pursuit | breakthrough_disturbance | resource_contest | special
  max_combat_rounds: number
  combat_round_scene_minutes: number
  minimum_accounting_hours: number
  end_conditions: list
  draw_resolution: string
  allowed_command_sources: list
  defeat_consequence: object
  victory_consequence: object
```

示例结束条件：

| 类型 | 结束条件 | 说明 |
| --- | --- | --- |
| 切磋 | 任一方被对方造成累计生机或神念伤害达到阈值 | 不以杀死对方为目标 |
| 死战 | 任一方生机或神念归零 | 是否死亡由父事件链解释 |
| 逃亡 / 追击 | 脱离进度达到阈值，或撑过指定交锋格 | 目标是脱离，不是击杀 |
| 护法 / 突破外扰 | 护持进度完成，外扰被压制，或突破者受关键伤害 | 结果返回突破事件链 |
| 资源争夺 | 抢夺物、节点控制或时间窗口达成 | 胜负可能不等于击杀 |
| 强制结局 | 达到最大回合、模板结束条件或 gap 上限 | 模板解释为撤退、僵持、窗口错过等 |

平手不等于无后果。父事件链可解释为双方撤退、敌人逃走、资源窗口错过、移动计划中断、秘境收益下降或突破外扰未完全压制。

## 8. 战斗结果包

战斗结束后输出结果包：

```yaml
BattleResult:
  result_type: victory | defeat | draw | escape_success | escape_failed | interrupted | death | special
  winner_side: string | null
  loser_side: string | null
  end_reason: string
  combat_rounds_used: number
  breakthrough_stages_resolved: number
  slots_resolved: number
  b1_world_elapsed_hours: number
  nonparticipant_progress_hours: number
  encounter_scene_elapsed_minutes: number
  encounter_accounting_hours: number
  participant_gap_hours: number
  vitality_delta: object
  energy_delta: object
  mind_delta: object
  consumed_items: list
  artifact_state_delta: list
  learned_skill_exp_delta: object
  status_tags_added: list
  status_tags_removed: list
  event_flags: list
  suggested_return: continue_plan | interrupt_plan | retreat | rest | wounded | captured | death_or_reincarnation | special
  log_summary: string
```

必须写入：

```text
角色个人日志
战斗摘要日志
必要的世界日志或宗门传闻
结果包引用
回放记录
```

公开与隐秘信息按事件可见性处理。隐秘战斗不能通过 UI 速度文案暴露具体参战者或原因。

## 9. 后果边界

战斗作用于本世身躯与灵魂，通常不直接改变真灵强度、执念容量、转世初始化选择或已定正式后手。

战斗可以改变：

```text
当前生机、元气、神念
伤势、道伤、疲惫、心神动摇
随身物品和法宝状态
术法 / 指令使用经验
事件结果
位置和行动计划
宗门评价、传闻、节点状态
```

严重失败可通过死亡、神魂重创、因果加重、宗门外个人洞府或普通藏宝线索暴露等父事件结果间接影响轮回系统。

真灵藏宝是同一真灵跨世感应和开启的正式后手，不应被战斗当作普通战利品、遗产或可被他人直接搬空的资产。宗门外个人洞府和普通藏宝是无主遗留设施，可因战斗后果暴露线索、阵法受损或控制权变化而被其他角色提前开启。

MVP 不以玩家间直接斗法为核心验证项。若出现直接玩家冲突，应进入正式交锋，但系统第一版优先支持玩家 vs NPC、玩家 vs 抽象敌方小队、玩家 + 护法修正 vs 外扰、宗门行动 / 节点事件中的抽象战斗结果。

## 10. UI 边界

战斗 / 斗法采用沉浸式覆盖界面，但不改变普通队列与 B1 选择的边界。

界面应显示：

```text
触发原因
当前速度：交锋慢速
B1 本轮剩余提交时间
本场目标和结束条件
己方生机 / 元气 / 神念
敌方已知状态与信息层级
5 格战术指令面板
当前默认策略
指令克制提示
本轮预计己方主动消耗
上一轮交锋记录
战斗结果如何回写角色、路线、节点和日志
```

界面不应暗示：

```text
普通队列可以替代交锋轮选择
预计变化等于最终战斗结果
B1 提交窗口必然等于 1 游戏小时
隐秘交锋可以向非参战玩家暴露具体来源
```

## 11. 与突破的关系

突破挑战复用 B1 提交窗口、默认策略、结果包和回放机制，但不等同普通战斗。

区别：

| 项目 | 普通战斗 | 突破挑战 |
| --- | --- | --- |
| 核心目标 | 击退、逃脱、争夺、护法或生存 | 稳定破境、提高成功率和品质、控制代价 |
| 主要资源 | 生机、元气、神念、法宝、道具 | 突破资源、护法、地点、心境、根基、后手 |
| 输入结构 | 每轮 5 个交锋格 | 每阶段 1 个交锋格 |
| 常用耗时 | 常规 3 轮共 30 分钟，结算按 1 小时 | 模板累计，暂定总耗时 1～6 小时 |
| 长期消耗归属 | 战后休整、追击、事件后果 | 准备期和巩固期 |

突破挑战不应被做成反复 P0，也不应把突破阶段直接解释为固定 1 小时。每个阶段应由突破模板声明耗时、资源消耗、风险标签和默认策略。

一般同境界各个突破阶段耗时相同；不同突破模板的主要差异在突破指令应对、资源取舍和风险标签，而不是默认拉长每阶段耗时。由于突破阶段累计耗时会参与计算，提前炼化中的丹药、符箓、法宝或其他持续效果可能在达到时间节点时生效或扣减剩余持续时间。

MVP 丹药没有即时生效类型，都需要依赖炼化与时间流逝生效，因此丹药不允许在战斗交锋和突破交锋中作为即时指令使用。正式版若引入即时生效丹药，届时可以加入交锋指令列表。

## 12. MVP 保留与简化

MVP 必须支持：

```text
1v1 玩家 vs NPC
玩家 vs 抽象敌方小队
5 格战术预输入
生机 / 元气 / 神念读取与回写
攻击 / 防御 / Buff 三角克制
基础指令、术法指令、道具指令、法宝指令
不同战斗结束条件
战斗结果包回写父事件链
可回放的战斗摘要日志
B1 提交窗口、B1 世界推进、交锋结算耗时分离
符箓、法宝等持续效果按已消耗游戏时间扣减剩余持续时间
```

MVP 可以简化：

```text
不做棋盘、站位、距离
不做实时操作
不做复杂多人同场战斗
不做完整 PvP 规则
不做装备栏、换装或战斗中换法宝
不做完整技能树
不做复杂 combo
不做高级反制、连锁和多段打断
```

战斗可以提供少量术法 / 指令使用经验，但不能形成刷低风险战斗的最优成长路径。主要成长仍来自修炼、资源、功法和事件。

## 13. 本次修订结论

1. 保留 B1 作为正式交锋的同步慢速和提交窗口。
2. 废止“普通战斗每轮必定消耗 1 游戏小时”的绝对口径。
3. 常规战斗每轮 5 个交锋格，叙事耗时 10 分钟；常规 3 轮共 30 分钟，不足 1 小时按 1 小时结算。
4. 每轮战斗决策时间为 60 秒现实时间；常规 3 轮最多 3 分钟现实时间，对应 B1 下非参战玩家推进 3 游戏小时。
5. 突破挑战每阶段只输入 1 个交锋格，每阶段耗时由突破模板声明，总耗时暂定 1～6 小时。
6. 战斗和突破均沿用 gap 最大不超过 1 游戏日的限制，不额外增加实现层时间预算限制；实际设计层面一般战斗不超过 1 游戏小时，突破不超过 6 游戏小时。
7. MVP 丹药没有即时生效类型，不允许在战斗 / 突破交锋中即时使用；符箓、法宝等持续效果可在指令用出后生效，并在交锋结束后按已消耗游戏时间扣减剩余持续时间。
8. 结果包必须同时记录 `b1_world_elapsed_hours`、`nonparticipant_progress_hours`、`encounter_scene_elapsed_minutes`、`encounter_accounting_hours` 和 `participant_gap_hours`。
