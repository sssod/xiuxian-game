# 系统设计｜灵石及聚灵石

## 1. 设计定位

本文维护灵石、低阶货币与聚灵石在物品与经济系统中的对象身份、币制边界、加工接口、资源输入规则和价值口径。经济系统、交易系统、资源流转、设施维护、突破资源和资源输入规则只引用本文口径，不再各自维护币制或“高阶灵石”定义。

灵石是修行世界主经济循环通货；聚灵石是高密度灵气物品，不是灵石的高阶面额；低阶货币只服务凡人阶段和局部剧情语境。贡献、门内声望和职位不属于本文的货币体系。

## 2. 当前结论

1. 灵石不分等级，不设计“中品灵石 / 上品灵石”作为货币面额。
2. 灵石默认是资产容器中的货币余额；在封存、事件锁定、后手储藏、任务打包或来源追踪语境下，可以表现为可堆叠物品栈。
3. 低阶货币只服务凡人阶段、村镇消费、伪装、剧情任务和新手教学，不进入主修行经济循环。
4. 聚灵石是高密度灵气物品，默认按可堆叠物品处理；高价值、命名、事件锁定、正式后手或带独立状态时可提升为 `ItemInstance`。
5. 普通灵石不能无损满足所有高阶灵气需求；高阶需求应通过聚灵石、阵法、设施、特殊资源或专用配方形成供给阀门。
6. 贡献、门内声望和职位不是货币，只能影响权限、价格修正、申请资格或可见范围，不能绕过真实库存兑换物品。

## 4. 核心循环或触发入口

灵石围绕“获得、入账、预留、支付、转移、封存、回收、流水审计”循环维护。

```text
获得灵石
-> 写入资产容器货币余额，或在特殊语境下创建灵石栈
-> 交易、服务、设施、事件、交通、修炼基础消耗或资源申请预留灵石
-> 执行前校验容器、权限、绑定、锁定、预留、地点和交易状态
-> 支付、转移、冻结、退回、封存或回收
-> 写入资产流水、交易结果、事件结果或行动回放
```

聚灵石围绕“加工、入库、申请、资源输入、消耗、残余、日志”循环维护。

```text
灵石 + 加工设施 + 时间 / 人力 / 技艺修正
-> 聚灵石
-> 进入行囊、宗门库存、商店库存、节点库存、事件锁定容器或后手容器
-> 阵法、突破、洞府、法宝、配方或事件选项申请资源输入
-> 校验容器、权限、绑定、预留、位置、标签、阶级和品级
-> 消耗、部分释放、退款或残余处理
-> 写入资源使用日志、资产流水和结果包
```

低阶货币只在凡人节点、村镇消费、身份伪装、低风险任务、新手教学或指定剧情中触发。角色进入修行世界主循环后，低阶货币不应成为稳定资源入口。

## 5. 规则与状态

### 5.1 灵石

灵石默认表达为资产容器中的货币余额，用于交易、基础修行消耗、交通通行、常规设施维护、服务费用、罚没、赔偿和事件支付。

```yaml
SpiritStoneBalance:
  currency_key: spirit_stone
  amount: number
  owner_container_ref: string
  bind_state: string | null
  reservation_refs: list
  ledger_refs: list
```

当灵石被封存、事件锁定、后手储藏、任务打包或需要独立追踪来源时，可以表现为可堆叠物品栈，但它仍然不是分级货币。

```yaml
SpiritStoneStack:
  item_template_id: spirit_stone_stack
  amount: number
  owner_container_ref: string
  bind_state: string | null
  stack_key_tags: list
  source_ref: string | null
  ledger_refs: list
```

规则：

1. 普通买卖、商店支付和玩家交易优先读写 `AssetContainer.currency_balances.spirit_stone`。
2. 灵石可作为基础修行、低阶设施、交通设施、服务入口和常规事件的支付成本。
3. 灵石支付不等于灵气资源输入。若某行动需要“灵气包”“高密度灵气”或“突破资源”，必须走资源输入、物品消耗或设施供能接口。
4. 绑定灵石、事件锁定灵石、市场挂牌所得、交易暂存灵石和后手封存灵石必须保留容器、预留和流水记录。
5. 出售、拆解、销毁、上交、回收或消耗灵石相关资产，不返还世界生成预算。

### 5.2 低阶货币

低阶货币用于凡人世界与新手阶段的局部交易，不承担修行世界通用价值锚。

```yaml
MundaneCurrencyBalance:
  currency_key: coin_copper | silver | custom
  amount: number
  owner_container_ref: string
  context_tags: list
  ledger_refs: list
```

规则：

1. 低阶货币可用于村镇购买、干粮、住宿、凡人工具、伪装、低风险任务和早期教学。
2. 灵石可以兑换低阶货币，用于凡人区域消费、身份伪装或剧情任务。
3. 低阶货币兑换或折算灵石只能作为受限场景入口，不能成为稳定套利、刷修行资源或绕过主经济循环的入口。
4. 角色进入修行世界主循环后，普通 UI 应弱化低阶货币，只在相关节点、任务或身份伪装语境中展示。

### 5.3 聚灵石

聚灵石是高密度灵气物品。它用来表达“普通通货经过加工、设施转化或特殊配方后，变成可供高阶系统调用的灵气资源”。

聚灵石默认可作为可堆叠物品处理；当它被用于正式后手、高价值突破、命名资源、事件锁定奖励或带有独立状态时，可以提升为 `ItemInstance`。

```yaml
CondensedSpiritStone:
  item_template_id: condensed_spirit_stone
  tier_code: string
  quality_code: string
  amount: number
  owner_container_ref: string
  stack_key_tags: list
  bind_state: string | null
  source_ref: string
  resource_effect_profile_ref: string | null
  compatible_hours: number | null
  ledger_refs: list
```

堆叠键至少包含：

```text
item_template_id + tier_code + quality_code + bind_state + key_state_tags
```

若来源、污染、宗门标记、后手共鸣、封印、相性或不稳定状态会影响突破、战斗、交易、后手、设施供能或消耗结果，则必须进入堆叠键，或改为独立实例。

### 5.4 加工与生产接口

灵石加工属于轻量配方制生产，不展开完整工业链。MVP 只打通一条加工路径：

```text
灵石 + 加工设施 + 时间 / 人力 / 技艺修正
-> 聚灵石
```

```yaml
CondenseSpiritStoneRecipe:
  recipe_id: string
  input_currency:
    spirit_stone: number
  required_facility_ref: string
  required_skill_tags: list
  action_cost_hours: number
  manpower_cost: number | null
  loss_rate_rule: string
  output_tier_rule: string
  output_quality_rule: string
  byproduct_profile_ref: string | null
  failure_profile_ref: string | null
```

规则：

1. 加工必须消耗真实容器中的灵石，并写资产流水。
2. 加工设施可以来自宗门设施、市场服务、个人洞府设施、节点资源槽附属设施或事件临时设施。
3. 加工产物进入指定行囊、宗门库存、节点库存、商店库存或事件锁定容器。
4. 加工效率、损耗率、产物阶级、产物品级和失败结果受设施等级、节点灵气、资源槽规模、人力、技艺、权限和事件状态影响。
5. MVP 阶段只要求能验证“通货 -> 高密度灵气物品”的供给阀门，不要求开放多级加工链、金融套利或复杂市场工业。

### 5.5 消耗与资源输入

聚灵石参与消耗时按物品或资源输入处理，不按货币支付处理。

典型用途：

1. 高阶阵法启动、维持、修复或过载。
2. 突破准备、突破事件链阶段消耗或护法阵供能。
3. 洞府维护、闭关设施供能、灵气环境临时强化。
4. 法宝充能、修复或特殊主动效果。
5. 特殊配方、炼器、阵盘、符箓或资源转换。
6. 事件选项中的高密度灵气投入。

资源输入可使用以下接口：

```yaml
ResourceUseRequest:
  request_id: string
  character_id: string
  source_container_id: string
  item_instance_id: string
  target_command_id: string | null
  target_event_option_id: string | null
  submitted_world_day: int
  submitted_world_hour: int
  status: pending | approved | rejected | consumed | refunded
  validation_result_ref: string
```

规则：

1. 消耗前必须检查容器权限、物品存在、数量、绑定、预留、事件锁定、市场挂牌、位置、行动标签兼容和角色状态。
2. 若聚灵石按兼容小时释放灵气，必须记录 `compatible_hours`、已消耗小时、残余策略和日志。
3. 若聚灵石作为一次性设施燃料或突破阶段资源，必须记录消耗阶段、失败损耗、释放或退款规则。
4. MVP 暂不在消耗环节强制复杂的阶级和品级限制；但所有消耗必须保留 Tier / Quality，供数值、日志、UI 和正式版适配矩阵读取。
5. 普通灵石不能自动替代聚灵石消耗。若系统允许临时折算，必须通过明确配方、设施服务或事件选项完成，并写明损耗和失败风险。

### 5.6 价值与预算口径

灵石、低阶货币和聚灵石至少区分以下价值：

| 价值 | 灵石 | 低阶货币 | 聚灵石 |
| --- | --- | --- | --- |
| `TradeValue` | 主交易锚，可作为普通价格单位 | 只在凡人或特殊语境折算 | 按物品估价，受 Tier / Quality / 供给影响 |
| `BudgetValue` | 由生成预算或奖励模板决定，不等于交易价格 | 通常很低或不进入修行预算 | 按高密度资源预算扣除，可能高于加工灵石面值 |
| `SalvageValue` | 通常直接保留为余额或回收价 | 场景内折价处理 | 受损耗、污染、设施、技艺和品级影响 |
| `ContributionValue` | 可作为上交宗门的贡献折算来源 | 通常不作为宗门核心贡献来源 | 可按宗门需求、阶级和品级高权重折算 |

规则：

1. `BudgetValue` 不必等于 `TradeValue`。
2. 加工聚灵石的灵石投入不自动决定聚灵石最终交易价；设施成本、时间、人力、损耗、技术门槛和供给风险都应进入价格修正。
3. 贡献不是货币。上交灵石或聚灵石可以产生贡献、声望、职位评价或权限修正，但宗门发放资源仍必须检查真实库存。
4. 市场交易中的聚灵石是物品挂牌；成交后移动物品与灵石余额，不把聚灵石折算进货币余额。

### 5.7 与经济系统的接口

经济系统引用本文时按以下边界处理：

| 场景 | 灵石口径 | 聚灵石口径 |
| --- | --- | --- |
| 商店买卖 | 主支付通货，读写货币余额 | 商品物品，进入 `shop_stock`、行囊或市场挂牌 |
| 玩家交易 | 可作为交易支付项 | 可作为交易物品项，需校验绑定、锁定和预留 |
| 市场寄售 | 成交款默认以灵石结算 | 挂牌资产本身是物品，不是货币余额 |
| 宗门库存 | 可作为五类宗门库存之一 | 作为修炼资源、材料或具体物品栈入库 |
| 资源申请 | 可申请或预留灵石支付 | 可申请或预留为突破、设施或资源输入 |
| 节点产出 | 通常来自事件、交易、税收或库存流转 | 可来自加工设施、特殊节点、事件或配方 |
| 世界生成预算 | 由奖励模板或预算规则决定 | 作为高密度灵气物品扣预算或由加工转化产生 |
| 后手封存 | 可封存为灵石栈 | 可封存为物品栈或实例，占用后手容量 |

## 6. 资源、角色、地图、事件或 NPC 接口

1. 资源接口：灵石读写货币余额或灵石栈；聚灵石读写物品栈、实例状态、资源效果模板、预留、消耗和退款结果。
2. 角色接口：角色只通过合法容器、权限、位置、绑定状态和资源请求调用灵石或聚灵石；聚灵石产生的持续影响应进入行动、事件、突破、设施或角色持续状态系统。
3. 地图接口：资源槽、节点设施、坊市服务、秘境奖励和地点事件可以生成、加工、出售、锁定或消耗灵石与聚灵石，但不得重定义币制。
4. 事件接口：事件选项可以要求灵石支付、低阶货币伪装成本或聚灵石资源输入；事件结果包必须记录支付、消耗、失败原因、退款和锁定奖励来源。
5. NPC 接口：NPC、商店、宗门、市场和工坊可以持有、出售、加工、回收或奖励灵石 / 聚灵石；隐性资源若战后或事件后变成玩家资产，应进入显性容器和资产流水。
6. 宗门接口：宗门可把灵石作为库存或支付资源，把聚灵石作为修炼资源、材料或具体物品入库；贡献、声望和职位只影响申请、折扣、权限或可见范围。
7. 后手接口：灵石可封存为灵石栈；聚灵石可封存为物品栈或实例，占用后手容量，并必须保留来源、状态和开启条件。

## 7. 数据字段建议

| 字段 | 含义 |
| --- | --- |
| `currency_key` | 货币键；灵石固定为 `spirit_stone`，低阶货币使用 `coin_copper`、`silver` 或剧情自定义键 |
| `amount` | 货币余额、灵石栈数量或聚灵石堆叠数量 |
| `owner_container_ref` / `source_container_id` | 当前归属或消耗来源容器 |
| `bind_state` | 绑定、事件锁定、宗门锁定、后手封存等状态 |
| `reservation_refs` | 交易、行动、事件、市场、资源申请或设施占用的预留引用 |
| `ledger_refs` | 资产流水、交易流水、加工流水或资源使用日志 |
| `item_template_id` | 灵石栈或聚灵石物品模板 |
| `tier_code` | 聚灵石阶级；灵石余额不使用面额等级 |
| `quality_code` | 聚灵石品级、纯度或加工质量 |
| `stack_key_tags` | 堆叠键标签，包含模板、阶级、品级、绑定和关键状态 |
| `source_ref` | 来源、奖励、交易、加工、后手、宗门或审计引用 |
| `resource_effect_profile_ref` | 聚灵石作为资源输入时读取的资源效果模板 |
| `compatible_hours` | 聚灵石按兼容小时释放灵气时的可用小时数 |
| `recipe_id` | 灵石加工为聚灵石的配方 ID |
| `required_facility_ref` | 加工所需设施、服务或事件临时设施 |
| `loss_rate_rule` | 加工损耗率规则 |
| `output_tier_rule` / `output_quality_rule` | 加工产物阶级与品级规则 |
| `validation_result_ref` | 资源使用请求的校验结果 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

普通 UI 至少应展示：

1. 灵石余额、低阶货币余额和聚灵石数量，不把聚灵石合并进货币余额。
2. 聚灵石名称、阶级、品级、数量、来源关键状态、绑定 / 锁定状态和可用语境。
3. 灵石支付、低阶货币支付、聚灵石资源输入的消耗对象、来源容器、预留状态和不可用原因。
4. 加工聚灵石时的灵石投入、设施要求、耗时、预计产物、损耗风险和失败风险。
5. 宗门上交或资源申请时，展示贡献 / 声望 / 权限影响，但不得把贡献表现成可自由消费货币。
6. 消耗、加工、退款、交易完成或失败后，应展示资产变化摘要和日志入口。

普通 UI 不展示：

1. 内部容器 ID、完整堆叠键、服务端锁定字段、随机种子或隐藏事件分支。
2. Debug 预算扣减、完整价格公式、原始供需倍率、隐性 NPC 资源池或未公开剧情奖励。
3. 未被角色识别的聚灵石污染、封印、后手共鸣、相性或未来事件触发信息。

## 9. MVP 范围

MVP 应实现或保留：

1. 灵石作为主交易通货，默认读写资产容器中的 `spirit_stone` 余额。
2. 特殊语境下的灵石栈，用于封存、事件锁定、后手储藏、任务打包或来源追踪。
3. 低阶货币用于凡人阶段、村镇消费、伪装、剧情任务和新手教学，并限制进入修行主经济循环。
4. 聚灵石作为可堆叠高密度灵气物品，保留阶级、品级、来源、绑定、资源效果和兼容小时字段。
5. 一条“灵石 + 加工设施 + 时间 / 人力 / 技艺修正 -> 聚灵石”的加工路径。
6. 聚灵石作为资源输入进入阵法、突破、洞府、法宝、配方或事件选项的校验与消耗流程。
7. 灵石、低阶货币、聚灵石的交易价值、预算价值、回收价值和贡献折算口径区分。
8. 资产流水、资源使用日志、交易结果、事件结果和行动回放能追踪灵石与聚灵石变化。

MVP 不实现：

1. 中品灵石、上品灵石等多面额或分级灵石货币体系。
2. 普通灵石无损替代聚灵石或所有高阶灵气资源输入。
3. 多级灵石金融、复杂市场工业链、稳定套利和跨货币刷资源入口。
4. 聚灵石完整阶级 / 品级适配矩阵、全部消耗表和全部高级配方。
5. 贡献、门内声望或职位作为可自由消费货币。
6. 普通 UI 中展示完整预算公式、隐藏供需倍率或未识别聚灵石状态。

## 10. 验收约束

1. 灵石不得被设计为多等级货币面额。
2. 聚灵石不得进入货币余额；交易聚灵石必须按物品转移处理。
3. 普通灵石不得在未走配方、设施服务或事件选项的情况下自动替代聚灵石消耗。
4. 低阶货币不得成为稳定套利、刷修行资源或绕过主经济循环的入口。
5. 贡献、声望和职位不得绕过真实库存、权限、地点和资源申请校验直接兑换物品。
6. 加工聚灵石必须消耗真实容器中的灵石，并写入资产流水。
7. 聚灵石消耗前必须校验容器权限、数量、绑定、预留、事件锁定、市场挂牌、位置、标签兼容和角色状态。
8. 出售、拆解、销毁、上交、回收或消耗灵石 / 聚灵石，不得返还世界生成预算。
9. 正式后手或高价值聚灵石必须保留来源、状态、容量占用和开启 / 消耗日志。
10. UI 必须区分灵石支付、低阶货币支付和聚灵石资源输入，并在不可用时说明原因。
