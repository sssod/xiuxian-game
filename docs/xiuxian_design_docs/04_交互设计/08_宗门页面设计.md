# 交互设计｜宗门页面设计

## 1. 当前状态

本页面仍处于交互约束草案阶段，当前只固定宗门页面对身份、权限、库存、资源申请、预留、宗门持续行动、建议和日志的展示边界，不维护完整视觉布局稿、Figma 节点或最终美术样式。

宗门页面服务于玩家理解自己与宗门的关系、可申请什么资源、宗门正在做什么、自己的建议是否被采纳。它不替代储物空间页的资产转移，不替代指令管理页的行动提交，也不公开调试级完整宗门库存。

## 3. 用户目标与入口

玩家进入宗门页面时，需要完成以下目标：

1. 查看自己的宗门身份、职位、权限标签和资源申请资格。
2. 查看可见的宗门库存摘要、资源分类、预留状态和申请结果。
3. 申请宗门资源，或查看申请被批准、拒绝、释放、消耗、过期和失败的原因。
4. 查看宗门当前持续行动、玩家建议、宗门 AI 采纳倾向和结果日志。
5. 在突破准备、交易、宗门任务和资源行动中理解宗门支持状态。

入口来自主界面宗门摘要、角色页宗门身份、修为页突破支持、储物空间宗门库存入口、行动指令宗门行动入口和宗门事件结果包。

## 4. 必须表达

1. 玩家身份：外门、内门、真传、执事、长老。
2. 权限标签与资源申请资格。
3. 宗门五类库存：灵石、修炼资源、材料 / 矿材、人力 / 弟子规模、声望 / 影响力。
4. 宗门库存详情、资源申请状态、预留状态、用途、过期时间、消耗 / 释放 / 失败 / 拒绝结果。
5. 当前宗门持续行动。
6. 玩家建议、宗门 AI 采纳倾向、行动预览、执行进度与结果日志。
7. 宗门资源支持突破必须显示库存检查与预留状态。
8. 不同身份、职位和权限看到不同库存摘要，不展示调试级完整库存。
9. 同宗玩家建议冲突不做复杂议会，按权限、职位、声望、贡献、宗门 AI 倾向等生成采纳倾向。
10. 宗门库存被申请会影响其他玩家机会，但资源申请结果默认只对本人、相关宗门权限层和 Debug 可见。

## 5. 页面区块与信息优先级

推荐信息优先级：

1. 身份与权限区：宗门身份、职位、权限标签、贡献或声望摘要。
2. 资源库存区：五类库存摘要、可见详情、可申请资源和限制原因。
3. 申请与预留区：申请状态、预留用途、过期时间、消耗、释放、拒绝和失败结果。
4. 宗门持续行动区：当前持续行动、进度、预览、玩家建议和采纳倾向。
5. 突破支持区：突破资源支持、库存检查、预留状态和结果回传。
6. 日志与审计摘要区：本人相关日志、权限层可见日志、公开宗门摘要。
7. 相关入口区：宗门库存、宗门商店、宗门任务、行动指令和储物空间。

页面只固定信息层级和交互边界，不固定宗门页面布局、表格密度或图标样式。

## 6. 操作流程与状态

查看宗门状态：

```text
打开宗门页面
→ 查看身份、权限和库存摘要
→ 查看宗门持续行动和最近日志
→ 根据权限进入资源申请、宗门行动或宗门库存入口
```

资源申请：

```text
选择可申请资源
→ 查看资格、用途、库存检查和预留规则
→ 提交申请
→ 宗门系统返回批准、拒绝或等待状态
→ 页面显示预留、过期、消耗、释放或失败结果
```

宗门支持突破：

```text
从突破准备进入宗门支持
→ 查看所需资源、可见库存和申请资格
→ 申请或使用已预留资源
→ 突破结果回写消耗、释放或失败状态
```

宗门持续行动建议：

```text
查看当前宗门持续行动
→ 提交玩家建议
→ 页面显示宗门 AI 采纳倾向
→ 行动推进后显示执行进度与结果日志
```

多人边界：

```text
同宗多人提交建议或申请资源
→ 页面只显示本人可见结果和权限层摘要
→ 不公开他人私人申请细节或 Debug 采纳计算
```

## 7. 不表达或 Debug 边界

普通宗门页面不展示：

1. 调试级完整宗门库存。
2. 其他玩家私人资源申请细节。
3. 宗门 AI 完整内部权重、随机种子和采纳公式。
4. 未公开的宗门战略、隐藏库存、暗线 NPC 关系或后手归因。
5. 库存系统审计字段、完整资产可信链或 Debug 日志。

宗门页面不应表达为：

1. 复杂同宗议会投票系统。
2. 玩家可以直接任意调拨宗门库存。
3. 宗门库存等同个人背包。
4. 资源申请批准后永久占用，不受用途、过期、释放和失败处理约束。
5. 多人房中所有宗门行为对所有玩家公开。
