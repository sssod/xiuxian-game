# 物品设计｜功法载体

## 1. 文档边界

本文记录功法与物品之间的关系，重点定义功法载体、残页、篇章、完整功法和合成链路。

本文只处理“功法内容如何以物品形式存在、转移、合成和成为学习来源”，不重新定义：

1. 道功的修为路线、上限、主动吐纳和突破路线。
2. 法门的能力、指令、事件选项和效率修正。
3. 主修道功的设置、切换、锁定和更换窗口。
4. 角色对功法的掌握度成长曲线。

边界口径：

| 概念 | 本文是否负责 | 说明 |
| --- | --- | --- |
| 功法模板 | 不负责 | 道功和法门模板不是物品 |
| MethodState | 不负责 | 角色学会后的掌握状态，不是背包物 |
| 功法载体 | 负责 | 承载功法内容的物品 |
| 残页 / 篇章 | 负责 | 不完整内容资产，只能合成、线索或投放 |
| 完整功法 | 负责 | 唯一常规可学习来源，在物品层以可学习载体存在 |

## 2. 核心定义

功法载体是承载功法内容的物品。它可以是玉简、书册、碑刻拓本、传承令、秘卷、讲义、残页或篇章等。

功法模板与功法载体必须分离：

```text
DaoMethod / TechniqueMethod：规则层功法模板
MethodCarrier：物品层功法载体
MethodState：角色学会后的掌握状态
```

玩家拥有完整功法的载体，不等于角色已经学会功法。角色学会功法后，掌握状态与载体分离；载体仍可以作为物品保留、转移、封存、借阅、交易或成为后手资产。

功法掌握状态可以作为宗门外个人洞府或普通藏宝的开启条件，但不等于自动取得其中资产。功法载体若封存为真灵藏宝，必须占用正式后手的数量或单个容量限制。

## 3. 当前定版链路

功法投放采用三层载体链：

```text
残页
→ 篇章
→ 完整功法
→ 学会功法
→ 研习功法提升掌握度
```

整理包内只保留三层功法投放概念：

```text
残页：最小碎片，按目标篇章归类
篇章：中间完整内容，用于合成完整功法
完整功法：唯一常规可学习来源，在物品层以可学习载体存在
```

旧文档中其他不完整内容称谓不再保留为整理包概念，统一落到三层链路：

| 旧称 / 泛称 | 当前口径 |
| --- | --- |
| 不完整功法碎片 | 残页 |
| 中间完整内容 | 篇章 |
| 可学习的完整内容 | 完整功法 |
| 学会一部分功法 | 废弃表达，不能用于残页或篇章 |

## 4. 残页

残页是可合成道具，不可学习。

规则：

1. 不创建 `MethodState`。
2. 不可设为研习目标。
3. 不直接解锁功法效果。
4. 不直接提高道功或法门掌握度。
5. 只参与合成篇章、线索追踪、任务推进或内容投放。
6. 残页按目标篇章归类，不做精确页码编号。

示例：

```text
《青木养真诀·引木气残页》× 4
→ 《青木养真诀·引木气篇章》
```

不做：

```text
必须集齐第 1 页、第 2 页、第 3 页、第 4 页。
```

## 5. 篇章

篇章是比残页更完整的中间内容资产，仍然不可学习。

规则：

1. 不创建 `MethodState`。
2. 不可设为研习目标。
3. 不直接作为主修道功内容。
4. 不直接解锁法门能力。
5. 不表达“已学会一部分功法”。
6. 只参与合成完整功法、线索追踪、任务推进或权限展示。
7. 篇章合成完整功法时需要精确篇章。

示例：

```text
引木气篇
养生机篇
藏真元篇
木脉生息篇
→ 《青木养真诀完整玉简》
```

## 6. 完整功法

完整功法是唯一常规可学习来源，在物品层以完整的功法载体存在。

规则：

1. 可作为学习来源。
2. 可用于研习入门。
3. 入门后创建 `MethodState`。
4. 默认学习时不消耗载体。
5. 高价值道功对应的可学习载体默认使用 `ItemInstance`。
6. 普通低阶法门对应的可学习载体可使用 `ItemStack`。
7. 高价值、唯一、有来源历史、可封存为后手或带独立状态的法门载体也应使用 `ItemInstance`。

特殊例外预留：

```text
一次性传功玉简：consume_on_learn = true
```

MVP 默认不做一次性消耗。

## 7. 合成归属

功法合成属于物品系统，不属于研习功法。

```text
残页合成篇章：Item Synthesis / Recipe
篇章合成完整功法：Item Synthesis / Recipe
研习功法：学习完整功法或提升已学功法掌握度
```

研习功法不负责：

1. 修复残页。
2. 校勘错漏。
3. 推演缺失内容。
4. 创造功法。
5. 融合功法。
6. 把残页或篇章直接变成可用内容。

## 8. MVP 合成耗时

MVP 中，残页合成篇章、篇章合成完整功法默认归类为个人即时物品整理操作，不占用行动执行时间预算。

理由：

1. 残页和篇章的获得已经通过探索、任务、交易、宗门权限、秘境或后手支付了时间与资源成本。
2. 合成本身再收时间，会增加低价值摩擦。
3. 残页和篇章不是运行时学习进度，合成不应伪装成研习功法。

未来可扩展为需要设施、导师、权限、固定处理时间或风险校验的高阶操作：

1. 高阶功法校订。
2. 功法誊抄。
3. 装订封印。
4. 传承洗练。
5. 禁制修复。

这些扩展仍属于物品合成或传承处理，不属于研习功法。

## 9. 获取与投放来源

功法载体可以来自：

1. 新手家庭、村镇支持或教学事件发放基础功法载体。
2. 宗门发放、藏经阁权限、讲经、师承或任务奖励。
3. 节点探索、遗迹、秘境窗口和隐藏层。
4. NPC 交易、拍卖、交换或夺取。
5. 宗门库存、宗门配给或组织资源转化。
6. 前世真灵藏宝、宗门外藏物开启、宗门遗产清点或线索兑现。
7. 普通宝藏、世界事件、战斗 / 危机事件产出。

残页和篇章适合作为探索、任务、权限、线索和内容收集资产。完整功法适合作为正式学习入口、宗门资源、交易物、高价值后手或世界稀有物。

功法相关的后手与藏宝口径：

1. 已学会的特定功法、功法阶段或掌握度，可以作为宗门外个人洞府、普通藏宝或阵法禁制的开启条件。
2. 满足功法条件只获得进入或取出的资格；仍需校验地点、线索、钥匙、事件状态、阵法状态和资产转移规则。
3. 功法载体本身可以被封存进真灵藏宝，但必须受真灵藏宝设置数量和单个容量限制。
4. 宗门个人洞府中的功法载体可随遗产清点回收宗门；宗门外藏物中的功法载体作为无主遗留设施资产，需要满足开启条件或破阵结果后才能取出。

## 10. 资产与转移

功法载体属于资产容器中的物品，必须与已学功法状态分离。

推荐口径：

1. 普通低阶完整法门载体可以堆叠。
2. 高价值道功对应的可学习载体应为实例物品。
3. 带独立来源、历史、绑定、封印、损毁、拓印、借阅、唯一性或后手价值的载体应为实例物品。
4. 高价值功法载体转移、上交、借阅、封存、交易、损坏或消耗应写入资产日志。
5. 学会功法后，载体默认仍保留为物品；角色掌握状态由 `MethodState` 保存。

## 11. UI 表达口径

UI 不得把残页或篇章表达为“已学会一部分功法”。

推荐表达：

| 物品 | UI 状态 |
| --- | --- |
| 残页 | 不可学习；用于合成篇章 |
| 篇章 | 不可学习；用于合成完整功法 |
| 完整功法 | 可研习入门；入门后生成 MethodState |
| 已学功法 | 已生成 MethodState；不再依赖背包内载体作为学习进度 |

## 12. 数据口径

功法载体模板建议字段：

```yaml
MethodCarrierTemplate:
  item_template_id: string
  carrier_type: fragment_page | chapter | complete_method
  method_id: string
  method_type: dao_method | technique_method
  display_name: string
  tier_code: string
  quality_code: string
  is_learnable: bool
  creates_method_state: bool
  consume_on_learn: bool
  synthesis_recipe_id: string
  required_chapter_ids: list
  target_chapter_id: string
  stack_policy: stack | instance
  provenance_policy: none | light | full
  copy_policy: none | copyable | restricted | unique
```

实例载体建议字段：

```yaml
MethodCarrierInstance:
  item_instance_id: string
  item_template_id: string
  owner_container_id: string
  method_id: string
  carrier_type: fragment_page | chapter | complete_method
  state: intact | damaged | sealed | copied | bound
  provenance_record_ref: string
  created_world_day: number
  created_world_hour: number
  bound_character_id: string
  locked_by_permission_ref: string
```

```yaml
MethodCarrierRecipe:
  recipe_id: string
  input_item_refs: list

  requires_facility: bool
  facility_tag: string
  requires_mentor: bool
  requires_permission_ref: string
  processing_time_policy: instant_mvp | fixed_hours | event_resolution
  risk_profile_ref: string
```
