# 战斗指令设计

## 1. 当前结论

战斗指令是正式战斗、斗法、逃亡、护法、突破外扰等高风险事件链中的轮内主动行为。它不进入普通行动队列，也不替代行动指令系统中的“当前执行指令 + 最多 3 条预输入指令”。

正式交锋仍使用 B1 专用界面和 60 秒现实提交窗口，但本文件将 B1 拆成三个概念：

```text
B1 提交窗口 = 每轮给玩家思考和提交的现实时间，默认 60 秒；
B1 世界推进 = 每 60 秒现实时间对应其他玩家和世界行动推进 1 游戏小时；
交锋结算耗时 = 参战交锋自身在游戏内消耗的时间，由战斗 / 突破规则决定。
```

因此，战斗指令不再默认绑定“交锋自身每轮消耗 1 游戏小时”。普通斗法应是短耗时、高强度事件；常规战斗按 5 个交锋格消耗 10 分钟游戏时间、3 轮交锋共 30 分钟叙事耗时处理，结算不足 1 游戏小时按 1 游戏小时计。长耗时应属于追击、围困、秘境拉锯、战后搜索、疗伤、突破准备或突破巩固，而不是普通交锋本身。

## 2. 与普通指令队列的边界

普通行动队列只保存已经合法的长期或短期行动，例如闭关、赶路、炼丹、申请资源、开启已满足条件的大境界突破。正式交锋开始后，轮内选择由 `FormalEncounterState` 管理。

不能写入普通行动队列的内容：

```text
正式交锋中的轮内策略选择
突破挑战中的轮内策略选择
战斗 5 格战术指令序列
敌方行为预案
未知事件选项
需要新情报判断的追击、撤退、护法或消耗道具选择
```

B1 或 P0 期间，玩家可以编辑普通队列，但普通队列只影响交锋结束后的后续行动，不影响本轮战斗结算。

## 3. 战斗指令来源

战斗开始时，系统根据角色当前状态、随身资产、已掌握能力和事件规则生成本场可用指令列表。

可用来源：

| 来源 | 说明 | 示例 |
| --- | --- | --- |
| 基础指令 | 所有角色可用，强度低但稳定 | 普通攻击、防御、闪避、观察、调息、逃遁 |
| 已学术法 / 神通 / 法门 | 来自主修功法、法门和已掌握术法 | 剑诀、护体法、轻身术、神魂术 |
| 法宝主动效果 | 随身携带且当前可驱动的法宝提供主动指令 | 飞剑斩击、宝镜照魂、护体钟罩 |
| 法宝被动效果 | 不占交锋格，满足条件时触发修正或承受后果 | 护心玉抵消神念伤害、避毒珠降低毒雾影响 |
| 消耗道具 | 符箓、阵盘、一次性护符等；MVP 丹药不允许在交锋中即时使用 | 攻击符、护身符、阵盘压制 |
| 事件特殊指令 | 当前事件临时授予，只在本场有效 | 护住突破者、封锁洞口、抢夺信物、斩断外扰 |

资源不足的指令可以显示，但必须标明不可用原因。这样玩家能理解自己为什么无法使用某个术法、法宝或道具。

## 4. 指令基础字段

建议数据层使用抽象字段，显示层再包装修仙术语。

```yaml
CombatCommand:
  command_id: string
  display_name: string
  source_type: learned_skill | method_unlock | artifact_active | artifact_passive | consumable | basic | event_special
  command_type: attack | defense | buff | recovery | control | escape | special
  tags: list
  target_bar: vitality | energy | mind | mixed | none
  resource_cost:
    vitality: number
    energy: number
    mind: number
    items: list
    artifact_durability: number
    artifact_charge: number
  base_power_profile: object
  counter_profile: object
  duration_slots: number
  max_uses_per_encounter: number | null
  slot_restriction: string | null
  event_flags: list
  ai_usage_hint: object
```

三条状态条沿用：

| 显示名 | 数据含义 | 主要承载 |
| --- | --- | --- |
| 生机 | `vitality` | 生命、肉身完整度、伤势、濒死 |
| 元气 | `energy` | 法力、气力、术法消耗、法宝驱动、疲惫 |
| 神念 | `mind` | 神魂、心神、神识稳定、幻术和心魔对抗 |

战斗读取当前值，战后不自动回满。消耗、伤害和状态封锁都必须回写角色、物品、事件结果包和回放。

## 5. 指令类型

MVP 先把大多数行为映射到攻击、防御、Buff 三角关系，再用恢复、控制、逃遁和特殊类型补充事件目标。

| 类型 | 默认定位 | 常见目标 | 说明 |
| --- | --- | --- | --- |
| 攻击 | 克制 Buff | 生机 / 元气 / 神念 | 造成伤害、打断、压制或破气 |
| 防御 | 克制攻击 | 自身 / 队友 / 目标 | 抵消、偏转、护持、屏障、格挡 |
| Buff | 克制防御 | 自身 / 队友 / 场地 | 蓄势、调息、强化、观察、恢复或改变后续格 |
| 恢复 | 默认归入 Buff | 生机 / 元气 / 神念 | 被攻击克制，适合在对方防御或空档时使用 |
| 控制 | 视模板归入攻击或特殊 | 元气 / 神念 / 行动能力 | 封脉、定身、幻术、打断、缴械 |
| 逃遁 | 视模板归入防御或特殊 | 脱离进度 | 逃亡、追击、撤退战使用 |
| 特殊 | 由事件定义 | 事件目标 | 护法、稳定突破、抢夺物品、破阵、封锁 |

## 6. 核心克制

基础三角关系：

```text
攻击克制 Buff
防御克制攻击
Buff 克制防御
```

攻击 vs 攻击：

```text
双方攻击有效威力相减
威力较高方造成差值伤害
威力较低方攻击被压制
```

防御 vs 攻击：

```text
防御消耗通常低于攻击
同等层级下防御有效值通常高于攻击
攻击超过防御时只造成溢出伤害
```

攻击 vs Buff：

```text
Buff 通常不提供即时防护
Buff 方承受接近完整攻击风险
普通 Buff 不默认必定失败
伤害、冲击或控制超过阈值时，Buff 被打断或效果降低
```

Buff vs 防御：

```text
防御未遭遇攻击时主要价值下降
Buff 方获得蓄势、恢复、观察、强化或后续优势
```

防御 vs 防御通常产生低收益僵持；Buff vs Buff 则制造后续高风险爆发窗口。

## 7. 5 格战术预输入

战斗内部采用 5 格战术指令结构。一个 B1 提交窗口内，玩家为本轮战斗回合填入 5 个交锋格；倒计时结束或所有参战者提前提交后，系统连续结算这些交锋格。

战斗交锋计时：

```text
1 个战斗回合 = 5 个交锋格 = 10 分钟游戏内叙事耗时；
常规战斗 = 3 个战斗回合 = 30 分钟游戏内叙事耗时；
每个战斗回合的现实决策窗口 = 60 秒；
常规战斗最多 3 分钟现实决策时间；
B1 世界推进仍按 60 秒现实时间 = 1 游戏小时计算；
所以常规战斗期间，非参战玩家最多完成 3 游戏小时行动推进；
战斗交锋结算后，不足 1 游戏小时按 1 游戏小时计入参战交锋消耗。
```

战斗回合的 10 分钟耗时主要用于叙事、日志和表现，不作为逐格计算依据。符箓、法宝等持续效果在战斗结束后按本场已结算的游戏时间扣减剩余持续时间；常规 30 分钟战斗按不足 1 小时取 1 小时处理。

术语：

| 术语 | 含义 |
| --- | --- |
| 战斗 | 一次完整斗法事件链 |
| 战斗回合 | 一次 5 格指令预输入与连续结算 |
| 交锋格 | 战斗回合内的 1 个指令格 |
| 交锋 | 双方同一交锋格的指令对抗 |

流程：

```text
展示当前态势、结束条件和敌方信息层级
玩家 / AI 填入 5 个交锋格
允许倒计时结束前修改
锁定本战斗回合指令序列
第 1 格结算并检查结束条件
第 2 格结算并检查结束条件
...
第 5 格结算并检查结束条件
若未结束，进入下一 B1 提交窗口或模板结局
```

每个交锋格都必须有指令。玩家未选择时，系统按战斗规则填入默认基础指令：

| 场景 | 默认指令 |
| --- | --- |
| 普通战斗 | 守势 |
| 逃亡战 | 闪避 / 脱离 |
| 教学战 | 观察 |
| 突破外扰 | 护持 / 稳定 |
| 资源不足 | 低效守势 / 喘息 / 空过 |

## 8. 填入预览与失败兜底

玩家填入 5 格时，UI 可以显示己方生机、元气、神念的预计变化。该预计只计算己方主动消耗、己方恢复、己方 Buff 和己方自损，不计算敌方未来指令、克制、打断、资源削减、状态封锁或提前结束。

如果某个交锋格结算时资源不足或状态不允许，原指令失败并替换为低效兜底：

```text
资源不足或状态被封锁
→ 指令失手
→ 执行低效守势 / 喘息 / 空过
→ 记录失败原因
```

失败原因可能来自己方前序格消耗过高，也可能来自敌方前序格造成的元气削减、神念震荡、打断、封脉或额外消耗。

## 9. 信息层级

5 格预输入成立的前提是玩家有足够信息做判断。敌方未来指令不必默认完全公开，但必须给出可用情报。

| 层级 | 说明 | 使用场景 |
| --- | --- | --- |
| 完全未知 | 只知道敌方存在和大致威胁 | 高风险、陌生敌人、伏击 |
| 倾向提示 | 显示偏攻、偏守、偏蓄势、偏逃等 | 普通战斗默认 |
| 局部预兆 | 显示某些强力指令前摇或后续爆发风险 | 精英敌人、可观察法术 |
| 完全预告 | 显示敌方部分或全部格子 | 教学战、低难度事件、侦查优势 |

玩家至少应看到：

```text
己方三条状态
可用指令、消耗、类型、目标条
己方指令序列的主动消耗预览
指令克制关系
本场结束条件
敌方已知战斗风格
敌方大致状态
上一战斗回合交锋记录
当前环境或事件特殊规则
```

## 10. AI 指令

AI 与玩家使用同一套 5 格战术预输入规则。AI 不应在知道玩家已锁定指令后作弊式逐格改指令。

AI 生成指令序列时可读取：

```text
NPC 模板
战斗目标
当前资源状态
上一战斗回合玩家行为
性格 / 战斗风格
事件脚本倾向
难度配置
敌方指令预兆配置
```

示例 AI 风格：

| 风格 | 行为倾向 |
| --- | --- |
| 鲁莽 | 高频攻击，低防御，元气消耗快 |
| 稳健 | 攻防均衡，低血量转防御 |
| 狡诈 | 先 Buff / 控制，再爆发 |
| 怯懦 | 受伤后逃遁，偏防御 |
| 护法型 | 优先防御、保护目标、维持阵线 |
| 法修型 | 消耗元气释放高威力术法 |
| 神魂型 | 优先攻击神念，制造心神状态 |

MVP 难度不靠复杂搜索，而靠指令池强度、资源量、克制倾向准确率、识别玩家重复模式的能力和敌方预兆透明度控制。

## 11. 法宝与道具边界

战斗系统不采用“装备栏 / 换装备 / 换法宝”作为核心限制。随身携带且满足条件的法宝、符箓、阵盘、护符和已掌握术法，都可以参与生成可用指令或被动效果。

MVP 丹药规则：

```text
MVP 丹药没有即时生效类型；
丹药必须依赖炼化与时间流逝生效；
丹药不允许在战斗交锋或突破交锋中作为即时指令使用；
正式版若引入即时生效丹药，可再将其加入交锋可用指令。
```

主动型法宝的限制来自：

```text
5 格指令数量
元气 / 神念 / 生机消耗
法宝耐久、充能或使用次数
道具消耗
指令克制和时机风险
战斗规则对来源的限制
```

被动型法宝不是免费常驻护盾。只要它在战斗中承担防护、抵消、转移、镇压、预警、抗性或替角色承受后果，就可以进入状态变化判定。

符箓、法宝、阵盘或护符若带有持续增益 / 减益效果，可以在指令用出后立即生效。战斗或突破结束时，持续效果按已消耗游戏时间扣减剩余持续时间。

可回写状态包括：

```text
受损
破碎
失去充能
灵性衰减
暂时失灵
战后修复
拆解回收材料
进入后手、遗产或宗门资源循环
```

## 12. B1 时间模板

为了修正“普通斗法动辄数小时”的问题，B1 的现实提交窗口、B1 世界推进和交锋结算耗时分离。战斗模板必须声明 `scene_time_profile`。

建议模板：

| 模板 | 单次提交窗口 | 交锋输入结构 | 交锋结算耗时 | 适用场景 |
| --- | ---: | --- | ---: | --- |
| `combat_standard` | 60 秒 | 5 个交锋格 | 10 分钟 / 战斗回合；常规 3 回合共 30 分钟，不足 1 小时按 1 小时结算 | 普通斗法、切磋、路途正式战 |
| `combat_extended` | 60 秒 | 5 个交锋格 | 10 分钟 / 战斗回合；额外追击、阵法、转场另由事件模板处理 | 强敌斗法、秘境关键战斗、资源争夺 |
| `breakthrough_stage` | 60 秒 | 1 个交锋格 | 由突破模板声明，总耗时暂定 1～6 小时 | 突破挑战阶段 |
| `long_confrontation` | 60 秒或事件链处理 | 不按普通战斗处理 | 多小时到多日 | 围困、守阵、长期对峙、宗门节点拉锯 |

普通战斗默认使用 `combat_standard`。只有模板明确包含追击、阵法、场地拉锯、多人协同、秘境转场或突破阶段时，才允许显著跨小时。实现层面不额外设置战斗 / 突破时间预算限制，只沿用 gap 最大不超过 1 游戏日；实际设计层面一般战斗交锋不超过 1 游戏小时，突破交锋不超过 6 游戏小时。

突破交锋特殊规则：

```text
突破模板声明每个突破阶段与挑战耗时；
一般同境界各突破阶段耗时相同；
不同模板的主要差异在突破指令应对，而不是默认拉长耗时；
每个突破阶段只需要 1 个交锋格选择与输入；
每次阶段决策窗口为 60 秒现实时间；
突破阶段累计耗时通常 2～3 阶段就超过 1 游戏小时；
因此突破阶段耗时不仅用于叙事，也参与效果、资源和时间结算。
```

例如，提前服用并已经处在炼化过程中的丹药或持续资源效果，可能因为突破阶段累计超过 1 游戏小时而生效 1 次。注意这不表示丹药可以在突破交锋中即时使用；MVP 丹药仍只能通过提前炼化与时间流逝生效。

## 13. 时间记账字段建议

B1 结算结果应同时记录现实窗口、B1 世界推进、交锋输入结构和交锋结算耗时，避免再把三者混成一个字段。

```yaml
FormalEncounterRound:
  round_index: number
  submit_window_seconds: 60
  scene_time_profile: combat_standard | combat_extended | breakthrough_stage | long_confrontation
  encounter_kind: combat | breakthrough
  combat_rounds_used: number
  breakthrough_stages_resolved: number
  slots_resolved: number
  b1_world_elapsed_hours: number
  nonparticipant_progress_hours: number
  encounter_scene_elapsed_minutes: number
  encounter_accounting_hours: number
  participant_gap_hours: number
  default_strategy_used_by: list
  result_package_refs: list
```

建议时间换算：

```text
submit_window_seconds 只表示现实决策时间；
b1_world_elapsed_hours 表示房间 B1 慢速推进量，默认每 60 秒 = 1 游戏小时；
nonparticipant_progress_hours 表示非参战玩家在 B1 期间完成的行动推进量；
encounter_scene_elapsed_minutes 表示交锋自身叙事耗时；
encounter_accounting_hours 表示参战交锋最终按游戏规则计入的消耗时间；
participant_gap_hours 表示 B1 世界推进与参战交锋计入耗时之间的差值，必须受 1 游戏日 gap 上限约束。
```

常规战斗示例：

```text
3 个战斗回合；
现实决策时间最多 3 分钟；
B1 世界推进 3 游戏小时；
非参战玩家完成 3 游戏小时行动推进；
交锋自身叙事耗时 30 分钟；
参战交锋结算耗时按不足 1 小时取 1 小时；
participant_gap_hours = 2 小时。
```

非参战玩家在 B1 期间按同一世界慢速推进；随机个人事件和普通机缘应等 B1 结束并到达合法检查点后再检查。

## 14. MVP 指令集

第一版只需要少量指令验证闭环。

通用基础指令：

```text
普通攻击
防御
闪避
调息
观察
逃遁
```

早期功法 / 术法指令：

```text
轻身功法：闪避 / 逃遁加成
基础战斗功法：普通攻击增强
护身法门：防御增强
神念术法：攻击神念或识破幻术
```

道具指令：

```text
符箓攻击
护身符
阵盘压制
```

法宝指令：

