# 修仙轮回沙盒 UI/UX 需求最终方案

**版本**：v1.1  
**日期**：2026-04-29  
**文档定位**：系统策划优先的 UI/UX 需求稿，可供 UI/UX 设计、Godot 客户端实现、原型制作、ChatGPT / 图像工具生成 UI 效果图使用。  
**生成方式**：基于 `修仙轮回沙盒_UIUX需求最终方案_v1.0.md`、`UI效果图生成Prompt速查_v1.0.md`、当前项目核心系统文档，以及本轮 canvas 修订内容整理。  
**修订重点**：将“大世界地图”提升为整个游戏主界面的核心；将原“当前所在地节点卡”降级为依附大地图的节点上下文面板；将主界面状态明确拆为“决策阶段 / 结算阶段”；结算阶段不允许玩家主动暂停，只允许因插入事件链或多人交叉事件链被动挂起。

## 0. 设计结论摘要

本项目核心界面应被定义为：

> **大世界地图驱动的季度行动工作台。**

玩家不是从角色详情页、宗门后台或当前节点卡开始游戏，而是在一张可自由拖动、可缩放、带战争迷雾与节点可见性层级的大世界地图上，理解自己、宗门、节点、资源、风险、传闻和世界演化之间的关系。

大地图承担四个主职责：

1. **世界认知容器**：展示已探索区域、已知节点、宗门控制区、路线、风险、传闻、秘境窗口和后手线索。
2. **季度决策底图**：宗门主行动目标、个人移动目标、探索目标、后手位置、突破地点都应回到地图上表达。
3. **结算演出舞台**：季度结算时，地图作为世界状态推进的主画面，展示移动、宗门行动、节点变化、事件爆发和传闻生成。
4. **功能面板锚点**：大部分功能界面不脱离主界面，而是作为地图上的侧边栏、下边栏、中心弹窗、节点浮层或抽屉出现。

因此，主界面常规结构修订为：

```text
中心：可拖动 / 可缩放大世界地图
顶部：阶段条 / 结算动态进度条 + 当前角色摘要 + 房间状态
左侧：待处理变动 / 重要传闻，可折叠
右侧：目标模板 / 当前选中对象摘要，可折叠
底部：季度时间条 / 行动规划器，可折叠
地图浮层：当前节点卡、选中节点卡、路线预估、势力图层、战争迷雾说明
侧边入口：宗门面板、全局事务抽屉、日志 / 账本、库存、设置
```

原 v1.0 中的“当前所在地节点卡”仍然重要，但它不再是主界面第一视觉重心。它应作为地图上下文的一种“选中节点面板”出现，并与玩家当前位置、正在查看节点、目标节点、宗门行动目标保持清晰区分。

玩家的核心问题链修订为：

```text
世界现在变成什么样了？
我已探索区域中有哪些节点值得关注？
我当前人在何处，宗门势力在何处，目标节点在何处？
哪些地图变化、传闻、宗门行动或节点风险影响本季度决策？
我是否要提出或决定宗门主行动？
我是否要亲自移动、探索、修炼、介入宗门行动或处理后手？
锁定后，结算推进过程中世界格局如何变化？
```

本需求稿优先服务：

```text
系统策划
```

其次服务：


- 每个界面服务哪个系统决策。
- 玩家在该界面上要回答什么问题。

- 宗门面板。
- 个人事务抽屉。

- 锁定前风险确认。

## 2. 核心 UI/UX 原则

### 2.1 以大地图为主界面核心

界面优先回答：

```text
这个季度的世界格局、节点状态和我的位置关系是什么？
```

而不是只回答：

```text
我当前所在节点能做什么？
```

大地图是常驻容器，不是一个通过按钮打开的次级地图页。玩家进入主界面后应直接看到地图，并能自由拖动、缩放、查看已探索节点。

### 2.2 以季度决策为主轴

界面仍然优先回答：

```text
本季度我该如何决策？
```

但这个问题必须通过地图回答。玩家的行动格、宗门行动、资源窗口、节点风险、后手线索和路线状态都应回到地图上呈现。

### 2.3 地图认知与可达性分离

已探索节点可以查看，即使当前不可达。

必须区分：

```text
我知道这个节点在哪里 / 大致是什么
```

和：

```text
我本季度能否抵达 / 是否有权限进入 / 路线是否安全
```

因此，节点状态至少拆为两组：

```text
可见性状态：未知 / 传闻 / 已探索 / 情报过期 / 当前可见
可达性状态：可达 / 条件可达 / 当前不可达 / 路线封锁 / 权限不足
```

UI 上不得用“不可达”隐藏已探索节点。不可达节点仍应允许点击查看，但行动按钮不可用或显示原因。

### 2.4 战争迷雾是主地图基础机制

地图必须支持战争迷雾。推荐状态：

```text
未知区域：地图被雾遮蔽，不显示节点或只显示模糊轮廓。
传闻区域：显示模糊区域名、传闻标记或疑似节点，不显示完整详情。
已探索区域：显示节点、基本类型、已知路线和上次掌握状态。
情报过期区域：节点仍可查看，但状态标注“情报可能过期”。
当前视野 / 当前情报区域：显示最新可见状态。
Debug 全知：仅开发调试使用。
```

战争迷雾不等于黑屏遮挡。它应服务修仙沙盒的信息不完全体验：传闻、后手感应、宗门情报、移动探索、节点控制变化都会改变地图可见性。

### 2.5 决策阶段与结算阶段共用同一张地图

决策阶段与结算阶段不是两个完全割裂的界面。二者应共用同一张大世界地图，只改变面板密度、交互权限和顶部阶段表现。

决策阶段：

```text
地图可自由操作
侧边栏 / 下边栏可展开
可选择节点、查看详情、规划行动、提交意图
```

结算阶段：

```text
地图仍在中心
默认隐藏大部分规划面板
顶部阶段条变成动态结算进度条
地图上播放或逐步呈现结算结果
仅在插入事件链或多人交叉事件链阻塞时进入被动挂起态
```

### 2.6 节点卡是地图上下文面板，不是主界面本体

节点卡用于解释地图上被选中的节点。

节点卡分三类：

```text
当前位置节点卡：你人在这里。
选中节点卡：你正在查看这里。
目标节点卡：当前计划、宗门行动或目标模板正在指向这里。
```

三者可以重合，也可以不同。UI 必须避免玩家误以为“正在查看的节点”就是“当前所在节点”。

### 2.7 即时行动不是行动格里的小动作

即时行动必须发生在正式决策指令开始前：

- 宗门即时行动必须早于宗门主行动输入。
- 个人即时行动必须早于个人决策指令开始。
- 进入个人行动规划后，若要再处理个人即时事务，必须退回并清除 6 格草稿。

### 2.8 决策阶段不处理事件链交互

事件链、突破链、战斗链只在服务端结算 / 插入事件阶段进行交互。

决策阶段出现的只是：

- 信息提示。
- 即时行动邀请。
- 计划合法性提示。
- 高风险提醒。
- 重要传闻。
- 目标受阻提示。

### 2.9 客户端只提交意图

客户端负责显示、规划、预估和提交。最终位置、资源消耗、行动合法性、事件触发、库存变化、宗门结果、节点状态和日志写入均以服务端权威结算为准。

### 2.10 功能界面默认依附主界面

大部分功能界面不应跳转到完全独立页面，而应依附在主地图上：

```text
中心弹窗：短流程确认、风险提醒、资源申请、锁定前检查。
左侧栏：待处理变动、传闻、日志摘要。
右侧栏：目标模板、节点详情、当前选中对象摘要。
下边栏：季度时间条、6 格行动规划器、路线预估。
全局抽屉：个人事务、轮回账本、库存、设置。
地图浮层：节点卡、势力标记、路线、风险、后手感应。
```

只有少数高价值、强沉浸、强交互的界面可以覆盖主界面。

### 2.11 沉浸式覆盖界面的适用范围

首版保守允许以下界面沉浸式覆盖整个主界面：

1. 战斗 / 斗法交锋。
2. 大境界突破事件链。
3. 死亡 / 转世关键流程。
4. 未来与突破、战斗同性质的高价值专用事件链。

沉浸式覆盖并不意味着脱离地图语义。覆盖界面应保留来源上下文：

```text
触发季度
触发 tick
触发节点
关联路线或宗门行动
返回结算后将回写到哪类状态
```

普通事件、资源申请、宗门面板、节点详情、日志、传闻、目标模板原则上不使用全屏覆盖。

## 3. 顶层阶段机

### 3.1 主界面两大阶段

```text
阶段 A：决策阶段
阶段 B：结算阶段
```

### 3.2 决策阶段子阶段

决策阶段内部固定为：

```text
A0 季度刷新 / 回合开始
A1 信息处理 / 即时行动
A2 宗门主行动建议或决策
A3 个人持续行动决策
A4 锁定提交 / 决策结束
```

顶部阶段条显示为：

```text
季度刷新 → 信息处理 / 即时行动 → 宗门主行动 → 个人行动 → 锁定提交
```

其中“信息处理 / 即时行动”同时包含宗门即时行动与个人即时行动，但二者入口仍然分离。

### 3.3 A0：季度刷新 / 回合开始

主界面状态：

- 大地图居中显示。
- 地图根据上一季度结算结果刷新节点状态、传闻标记、战争迷雾、控制区、路线状态。
- 左侧显示待处理变动摘要。
- 右侧显示目标模板摘要。
- 底部季度时间条折叠。

玩家目标：

```text
先从地图上理解世界变化，而不是先进入节点详情。
```

### 3.4 A1：信息处理 / 即时行动

开放内容：

- 地图拖动、缩放、节点查看。
- 当前节点特殊即时行动。
- 全局个人即时事务。
- 宗门经营命令。
- 日志、传闻、轮回账本查看。
- 目标模板调整。

限制：

- 不可规划 6 格个人行动。
- 不可锁定本季度。
- 宗门主行动尚未提交时，宗门经营命令仍可执行。

### 3.5 A2：宗门主行动建议或决策

玩家从宗门面板进入宗门主行动输入。宗门面板作为大地图之上的右侧或中心面板打开。

地图在此阶段仍可见，并应支持选择宗门行动目标节点。

宗门主行动目标选择推荐流程：

```text
打开宗门面板
→ 选择行动类型
→ 在地图上点击目标节点
→ 面板显示目标节点控制权、影响力、风险、资源、人力预估
→ 提交宗门建议 / 提议 / 决策意图
```

提交后：

- 宗门输入冻结。
- 宗门经营命令冻结。
- 玩家仍可回到地图处理个人即时事务。
- 不显示其他玩家宗门输入或提交状态。

### 3.6 A3：个人持续行动决策

触发条件：

```text
宗门反馈已生成
```

主界面变化：

- 大地图仍为中心。
- 底部展开 6 个朔望行动格规划器。
- 可通过点击地图节点规划移动、目标节点、停靠点和持续行动。
- 当前位置、目标节点、预计路线、预计结束位置在地图上同时显示。

个人行动规划不应变成纯表格编辑器。地图应直接参与：

```text
点选目标节点
→ 显示路线与行动格成本
→ 显示可达性、风险门、权限门
→ 将移动段写入底部行动格
→ 目标节点面板显示抵达后可执行持续行动
```

### 3.7 A4：锁定提交 / 决策结束

锁定前风险确认以中心弹窗或右侧确认面板出现，但地图仍可见。

锁定后：

- 地图可查看但不可修改计划。
- 底部行动规划器只读。
- 显示自己的已锁定预案。
- 不展示其他玩家详细状态或输入内容。

### 3.8 B：结算阶段

结算阶段是主界面的另一种状态，而不是完全跳转。

进入结算后：

- 顶部阶段条切换为动态进度条。
- 大地图居中放大为主要画面。
- 左侧待处理、右侧目标、底部行动规划器默认收起。
- 地图上按结算顺序显示移动、宗门行动、节点变化、事件候选、传闻扩散、资源窗口变化。
- 玩家不能修改任何决策。
- 玩家不能主动暂停结算推进。

动态进度条示例：

```text
>>> 结算开始 >>> 移动推进 >>> 宗门行动 >>> 节点事件 >>> 插入事件 >>> 结果回写 >>> 季度结束
```

结算摘要示例：

```text
二月·望：你沿云麓山道前往黑石岭，路线风险升高。
宗门行动：云麓宗远征队抵达青霜谷边界。
节点变化：黑石岭矿脉控制权争夺加剧。
```

如触发插入事件链：

```text
结算地图被动挂起
→ 弹出事件入口
→ 普通事件用中心事件面板
→ 战斗 / 突破用沉浸式覆盖界面
→ 当前玩家提交响应后，若仍需等待其他玩家交叉事件链，则维持被动等待态
→ 事件结果回写后返回结算地图继续自动推进
```

结算阶段的日志摘要查看规则：

```text
常态自动结算中：不提供主动暂停，不展开完整日志。
当前玩家事件响应中：允许查看与当前事件、原计划、触发节点相关的日志摘要。
等待其他玩家交叉事件链时：允许查看已结算到本玩家可见范围内的日志摘要。
结算完全结束后：进入季度结果摘要，可查看完整可见日志与“原计划 vs 实际结果”。
```

## 4. 主界面信息架构

### 4.1 常规布局

```text
顶部：阶段条 / 动态结算进度条 + 当前角色摘要 + 房间状态
中心：可拖动 / 可缩放大世界地图
左侧：待处理变动 / 重要传闻，可折叠
右侧：目标模板 / 当前选中对象摘要，可折叠
底部：季度时间条 / 6 格行动规划器，可折叠
地图浮层：节点卡、路线预估、战争迷雾说明、图层切换
侧边入口：宗门面板、全局事务抽屉、日志 / 账本、库存、设置
```

### 4.2 大地图画布

大地图画布必须支持：

- 拖动平移。
- 缩放。
- 点击节点。
- 悬停摘要。
- 地图图层切换。
- 战争迷雾。
- 已探索节点查看。
- 路线与可达性预估。
- 当前角色位置标记。
- 宗门势力范围或控制节点标记。
- 传闻 / 风险 / 秘境窗口标记。
- 当前目标、宗门行动目标、个人行动目标的高亮。

### 4.3 地图空间表现形式

定案：采用：

```text
节点图 + 区域底图
```

不做完整无格地形地图，也不做纯六边格 4X 地图。该方案兼容现有“有向带权节点图”的规则结构，同时在视觉上满足传统 4X 大地图的拖动、缩放、迷雾、势力范围体验。

实现含义：

```text
规则层：有向带权节点图
表现层：区域底图 + 节点 + 路线 + 势力范围 + 战争迷雾
```

### 4.4 地图图层

MVP 默认只暴露 4 个玩家图层：

```text
基础 / 势力 / 风险传闻 / 行动规划
```

资源机会与后手感应不作为常驻玩家图层，而作为上下文图层出现：

- 资源机会：在目标、宗门行动、资源传闻、秘境窗口相关时出现。
- 后手感应：在轮回账本、后手目标、相关节点查看时出现。
- Debug 图层：仅开发调试视图可见。

图层默认不要全部叠满。应按阶段自动推荐：

- 信息处理：风险传闻层、目标相关层优先。
- 宗门行动：势力控制层、资源机会层优先。
- 个人行动：行动规划层、路线风险层优先。
- 结算阶段：动态结算层优先。

### 4.5 左侧栏：待处理变动 / 重要传闻

左侧栏默认窄态显示数量、最高风险等级和前三条摘要。展开后显示 P0–P5 信息。

左侧栏不应遮挡地图核心区域。玩家可折叠为地图边缘竖向标签。

### 4.6 右侧栏：目标模板 / 选中对象摘要

右侧栏在不同状态下切换内容：

```text
未选中节点：显示目标模板。
选中节点：显示选中节点摘要。
规划行动时：显示目标节点与行动可行性。
宗门面板打开时：显示宗门行动目标配置。
```

目标模板不是独立页面，而是地图筛选和高亮规则的来源。

### 4.7 底部栏：季度时间条 / 行动规划器

底部栏折叠态：

- 显示 6 个朔望行动格。
- 显示已预占行动。
- 显示预计结束位置。
- 显示锁定状态。

展开态：

- 成为 6 格行动规划器。
- 地图进入行动规划交互模式。
- 点击节点、路线、持续行动会写入底部规划器。

结算阶段：

- 底部规划器默认隐藏。
- 常态自动结算过程中不可主动暂停查看完整规划细节。
- 若进入当前玩家事件响应或等待其他玩家交叉事件链的被动挂起态，可展开只读查看与当前阻塞点相关的“原计划 vs 当前实际推进”摘要。
- 结算完全结束后，可查看完整“原计划 vs 实际结果”。

## 5. 大地图、战争迷雾与节点浏览

### 5.1 地图主视觉

主界面必须采用：

```text
大世界节点图 / 区域图
```

而不是：

```text
纯文字节点列表
```

也不是：

```text
当前节点卡 + 地图按钮
```

地图不是背景装饰，而是玩家进行宗门目标选择、个人移动规划、传闻定位、资源判断、后手回收和结算观看的核心交互区。

### 5.2 节点可见性状态

推荐节点可见性：

| 状态 | UI 表现 | 可查看内容 | 可交互内容 |
|---|---|---|---|
| 未知 | 被迷雾覆盖 | 无 | 无 |
| 传闻 | 模糊节点 / 问号 / 传闻标记 | 传闻摘要、可能区域 | 可设为关注目标，不可直接行动 |
| 已探索 | 正常节点标记 | 已知基础信息、上次记录 | 可查看详情，即使当前不可达 |
| 情报过期 | 节点标记带旧情报纹理 | 历史信息 + 过期提示 | 可查看，可规划但风险提示增强 |
| 当前可见 | 高亮或清晰节点 | 当前最新可见状态 | 可查看，可规划，可执行合法交互 |
| Debug 全知 | 开发视图 | 全量状态 | 调试操作 |

### 5.3 情报过期 MVP 口径

情报过期进入 MVP UI 表现，但规则先简化。

MVP 只做最小表现：

```text
已探索但非当前可见节点显示“情报可能过期”标签。
```

首版不做复杂情报新鲜度公式，不要求每个节点计算精确情报衰减。后续可根据宗门情报、传闻、路线探索、节点控制权变化扩展为更完整的情报系统。

### 5.4 已探索但不可达

已探索节点不可因不可达而隐藏。

UI 规则：

```text
节点可见性决定能不能看。
路线 / 权限 / 状态门决定能不能去。
行动阶段与位置决定能不能做。
```

不可达节点点击后显示：

- 节点基础信息。
- 上次掌握的资源 / 风险 / 控制权摘要。
- 不可达原因。
- 解锁路径或可能条件。
- 相关传闻和目标关联。

行动按钮显示为不可用，并说明原因：

```text
当前路线封锁
缺少通行权限
本季度行动格不足
未知安全路线
目标位于未开放区域
```

### 5.5 路线与可达性

点击目标节点时，地图显示：

- 当前节点。
- 目标节点。
- 推荐路线或概略路线。
- 移动方式。
- 预计行动格成本。
- 风险标签。
- 权限门 / 状态门 / 风险门。
- 是否存在可选停靠点。

MVP 不做完整逐边手动排路，但地图上应显示路线方向和关键中转节点。

### 5.6 结算阶段地图变化展示

结算阶段地图用于展示：

- 玩家移动轨迹。
- 宗门行动目标推进。
- 节点控制权 / 影响力变化。
- 秘境窗口开启或关闭。
- 传闻扩散。
- 战争迷雾被揭开或情报变旧。
- 插入事件链触发点。

表现不需要做成复杂动画，但至少要有阶段化地图反馈：

```text
高亮节点
路线闪烁
状态标签变化
传闻标记生成
控制权颜色变化
结算摘要逐条出现
```

## 6. 节点上下文面板

原 v1.0 的“当前所在地节点卡”改名为：

```text
节点上下文面板
```

节点上下文面板包含三种模式：

1. **当前位置模式**：显示当前角色所在节点，可执行当前位置特殊即时行动和抵达后持续行动。
2. **选中节点模式**：显示地图上被点击节点的信息，不要求当前可达。
3. **计划目标模式**：显示被行动计划、宗门行动或目标模板选中的节点。

### 6.1 面板层级

```text
悬停摘要
→ 点击浮层 / 右侧摘要面板
→ 详情抽屉
```

悬停摘要用于快速扫图，点击面板用于决策比较，详情抽屉用于深层信息。

### 6.2 节点面板顶部标签

节点上下文面板顶部必须显示三类标签：

```text
当前位置
正在查看
计划目标
```

示例：

```text
当前位置：云麓宗山门
正在查看：黑石岭矿脉
计划目标：尚未选定
```

或：

```text
当前位置：云麓宗山门
正在查看：青霜谷
宗门行动目标：青霜谷
```

### 6.3 当前位置模式字段

- 节点名称。
- 节点类型。
- 当前控制权。
- 灵气标签与趋势。
- 危险档位。
- 当前位置特殊即时行动。
- 当前位置可执行持续行动。
- 可达节点入口。
- 与目标模板相关的推荐。

### 6.4 选中节点模式字段

- 节点名称。
- 可见性状态。
- 可达性状态。
- 上次情报时间或情报新鲜度。
- 节点类型。
- 控制权 / 影响力摘要。
- 风险 / 资源 / 入口摘要。
- 与当前目标或传闻的关联。
- 抵达后可能处理事项。

### 6.5 计划目标模式字段

- 目标类型：个人移动目标 / 宗门行动目标 / 目标模板关注点 / 后手感应点。
- 预计行动格成本。
- 路线风险。
- 权限和状态门。
- 预计收益方向。
- 与锁定前风险确认的关联。

### 6.6 非当前位置节点的即时行动

非当前位置节点不显示可直接执行的即时行动按钮。

非当前位置节点相关内容只显示为：

```text
抵达后可能处理事项
```

这样避免玩家误以为可以远程领取、交互、进入设施或处理地点事务。

## 7. 节点行动入口

### 7.1 节点卡只显示当前位置特殊即时行动

节点上下文面板中的即时行动只在当前位置模式显示，且只展示当前节点特殊即时行动，不展示通用即时行动。

显示示例：

- 领取宗门俸禄。
- 领取宗门配给。
- 接收炼器房成品。
- 查看当前节点公告。
- 使用当前节点特殊设施。

不显示示例：

- 传讯联络 NPC。
- 查看日志。
- 查看轮回账本。
- 调整目标模板。
- 查看功法详情。

判断标准：

```text
如果离开当前节点仍然可以执行，则默认不进入节点卡。
如果依赖当前节点、设施、NPC、权限、库存或事件状态，则可以进入节点卡。
```

### 7.2 个人持续行动

个人持续行动包括：

- 吐纳修炼。
- 研习功法。
- 探索。
- 采集 / 开采。
- 建设协助。
- 驻守。
- 后手布置。
- 后手回收。
- 闭关。
- 休整。
- 警戒。
- 停留。
- 亲自介入宗门主行动。

宗门相关持续行动不单独作为“宗门持续行动”大类，而是归入：

```text
个人持续行动 · 宗门关联
```

### 7.3 移动入口

移动不混入普通节点行动列表，而通过：

- 可达节点。
- 地图点选目标。
- 移动方式。
- 路线成本预估。
- 底部季度时间条。

来呈现。

## 8. 宗门面板

### 8.1 宗门主行动不是节点行动

宗门主行动是组织级行动，不是节点卡中的普通持续行动分类。

每个宗门每季度只有 1 个宗门主行动。

完整决策在宗门面板中完成。节点上下文面板只显示上下文提示和亲自介入口。

### 8.2 宗门面板页签

推荐页签：

```text
宗门概览
宗门经营命令
宗门主行动
库存权限
本季度反馈
```

### 8.3 宗门经营命令

宗门经营命令属于通用即时行动，通过远程传讯解释，不要求角色亲自抵达节点。

示例：

- 调整资源点开采强度。
- 调整宗门阵法开关 / 强弱。
- 调整俸禄策略。
- 调整常态资源分配倾向。
- 查看宗门库存与资源预留。

宗门经营命令必须发生在宗门主行动输入前。

一旦点击：

```text
进入宗门主行动决策
```

宗门经营命令冻结，本季度不可回退修改。

### 8.4 宗门主行动输入与地图联动

根据权限，按钮文案变化：

```text
提交宗门建议
提交宗门提议
确认宗门决策意图
```

宗门主行动输入必须支持地图点选目标节点。

推荐流程：

```text
宗门面板 → 宗门主行动页签
→ 选择行动类型
→ 地图高亮合法目标节点
→ 点击目标节点
→ 面板显示资源预算、人力预算、风险预估和执行完成度方向
→ 提交宗门建议 / 提议 / 决策意图
```

提交后立即冻结，玩家不可修改。

### 8.5 同宗多人输入不可见

宗门面板不展示：

- 其他玩家姓名。
- 其他玩家建议数量。
- 其他玩家目标节点。
- 其他玩家预算。
- 其他玩家权限层级。
- 其他玩家提交状态。
- 其他玩家影响宗门反馈的权重。

### 8.6 宗门反馈

宗门反馈在全房间所有玩家完成宗门输入或超时后，由服务器统一生成。

反馈自动确认，玩家只查看结果。

反馈面板只显示最终结果：

- 行动类型。
- 目标节点。
- 预计风险。
- 预计资源投入。
- 预计人力投入。
- 亲自介入机会。
- 相关节点入口。

不显示：

- 你的输入是否被采纳。
- 为什么采纳或未采纳。
- 其他玩家因素。
- 宗门 AI 完整判断过程。

### 8.7 反馈后的宗门面板

宗门反馈生成后，宗门面板仍可查看，但所有控件冻结。

允许：

- 查看最终反馈。
- 查看冻结摘要。
- 跳转相关节点。
- 本地 UI 备注，但必须明确“不影响结算”。

不允许：

- 修改宗门经营命令。
- 修改宗门主行动输入。
- 修改预算。
- 修改目标节点。
- 重新生成宗门反馈。

## 9. 即时行动体系

### 9.1 两类即时域

```text
宗门即时行动域
个人即时行动域
```

二者在回合开始后同时开放，但入口不同。

### 9.2 宗门即时行动

入口：

```text
宗门面板 → 宗门经营命令
```

特点：

- 远程传讯发布。
- 不消耗角色行动格。
- 受权限、职位、宗门身份校验。
- 点击后立即提交服务器。
- 必须早于宗门主行动输入。
- 冻结后本季度不可再改。

### 9.3 个人即时行动

入口：

```text
当前位置节点上下文面板
全局事务抽屉
```

类型：

- 当前位置特殊即时行动。
- 通用个人即时行动。
- 传讯。
- 回信查看。
- 委托结果接收。
- 已完成成品接收。
- 资源领取。

特点：

- 不消耗 6 个朔望行动格。
- 点击后立即提交服务器。
- 必须早于个人决策指令开始。
- 进入行动规划后冻结。

### 9.4 全局事务抽屉

承载：

- 传讯联络 NPC。
- 查看回信。
- 查看随身事务。
- 查看个人委托结果。
- 查看角色日志。
- 查看轮回账本。
- 调整目标模板。
- 其他不依赖当前节点的通用个人事务。

### 9.5 高价值个人即时事务

点击“开始规划本季度行动”前固定提醒：

- 宗门俸禄。
- 宗门配给。
- 已批准资源。
- 炼器成品。
- 配方 / 委托成品。
- 关键 NPC 回信。
- 关键情报。

不按当前目标模板过滤。

### 9.6 即时行动提交

即时行动不是本地 UI 效果。点击后：

```text
客户端提交即时请求
→ 服务器校验权限 / 位置 / 库存 / 资源 / 日志
→ 返回成功 / 失败 / 状态变化
→ 客户端刷新当前季度可见状态
```

## 10. 个人行动规划器

### 10.1 展开条件

只有在以下条件满足后，按钮才启用：

```text
宗门反馈已由服务器统一生成
玩家尚未开始个人决策指令
```

按钮：

```text
开始规划本季度行动
```

点击后：

- 高价值个人即时事务弹窗提醒。
- 玩家确认继续后，个人即时行动冻结。
- 6 个朔望行动格展开。
- 地图进入行动规划模式。

### 10.2 6 格布局

推荐采用底部横向 6 格时间轴：

```text
一月·朔｜一月·望｜二月·朔｜二月·望｜三月·朔｜三月·望
```

每格可放行动段。

### 10.3 跨格持续行动

跨多个行动格的持续行动使用一条跨格行动段覆盖多个格子。

例如：

```text
吐纳修炼：二月·朔 → 三月·朔
```

### 10.4 移动行动显示

移动行动显示：

```text
起点 → 目标节点
移动方式
消耗格数
风险标签
预计结束位置
```

MVP 不显示完整逐边手动排路，只显示目标节点、移动方式和可选显式停靠点。

### 10.5 地图点选规划流程

```text
点击地图目标节点
→ 地图显示路线预估与风险标签
→ 右侧面板显示可达性 / 权限 / 行动格成本
→ 玩家确认移动段
→ 底部行动格写入移动行动
→ 目标节点上下文面板显示抵达后持续行动
```

### 10.6 个人行动可选类型

个人决策指令阶段只允许：

- 移动。
- 个人持续行动。
- 休整。
- 警戒。
- 停留。
- 亲自介入宗门主行动。

不允许：

- 领取俸禄。
- 接收法宝。
- 传讯 NPC。
- 查看 / 处理通用个人即时事务。
- 执行目标节点即时事务。

### 10.7 回退规则

从个人决策指令阶段退回个人即时准备时：

- 清除当前 6 个朔望行动格草稿。
- 保留已完成即时行动结果。
- 保留宗门主行动反馈。
- 保留目标模板。
- 保留已查看节点信息。
- 保留待处理变动状态。

文案建议：

```text
退回个人即时准备？
当前本季度行动格规划将被清除。
已领取资源、已接收物品、已确认宗门反馈不会撤销。
```

## 11. 待处理变动与重要传闻

### 11.1 排序规则

```text
P0：强制可见重大风险
P1：高风险待处理变动
P2：主目标相关变化
P3：行动格相关变化
P4：重要世界传闻
P5：普通日志入口
```

### 11.2 P0 强提示

使用弹窗覆盖主界面。

示例：

- 当前节点被封锁。
- 当前计划因结算变化不再合法。
- 正式后手暴露 / 受损 / 失效。
- 角色死亡、重伤、突破失败、寿元告急。
- 当前节点高危状态影响本季度生存。

P0 不等于事件链响应。决策阶段不处理事件链交互。

### 11.3 P1 警报条

使用顶部警报条，不强制弹窗。

示例：

- 主目标受阻。
- 关键资源窗口即将消失。
- 宗门突破支持名额紧张。
- 当前节点风险上升。
- 路线状态变化影响移动计划。

### 11.4 P4 重要世界传闻

P4 位于普通日志之前，独立于普通日志。

包括：

- N4 级 NPC 宏观行动传闻。
- 已识别为玩家的游戏角色公开行动传闻。
- 宗门边界争夺。
- 秘境窗口。
- 资源名额。
- 节点控制权变化。
- 与玩家所属宗门或目标区域相关的重大公开信息。

传闻不是全知日志，可以模糊、延迟、不完整。

### 11.5 普通日志

普通日志不在主界面全部展开，只显示入口和数量。

## 12. 目标模板系统

### 12.1 目标形态

采用系统模板目标，不采用纯自由文本目标。

目标分为：

```text
主目标
副目标
搁置目标
```

### 12.2 推荐模板数量

首版控制在 8–12 个。

推荐模板：

- 准备突破。
- 提升境界。
- 研习功法。
- 提升宗门身份。
- 申请宗门资源。
- 参与宗门主行动。
- 探索指定节点。
- 回收后手。
- 布置后手。
- 处理伤势 / 寿元压力。
- 获取关键突破物。
- 关注特定 NPC / 玩家角色。

### 12.3 目标作用

目标模板用于：

- 高亮相关变动。
- 推荐节点行动。
- 解释行动风险。
- 帮助玩家比较目标节点。
- 排序待处理变动。
- 提供下一步建议。
- 控制地图上下文图层显示。

目标模板不直接替玩家提交行动，也不绕过服务端校验。

## 13. 锁定、等待与托管

### 13.1 锁定前风险确认

分四类：

```text
硬错误
高风险提醒
未处理高价值事务
重要传闻
```

硬错误示例：

- 行动格超过 6 格。
- 起点不是当前角色位置。
- 目标节点不可达。
- 权限不足。
- 资源预留不存在。
- 计划包含非法行动。

提醒示例：

- 俸禄未领取。
- 炼器成品未接收。
- 关键 NPC 回信未查看。
- N4 传闻未查看。
- 当前节点风险上升但玩家仍计划停留。

### 13.2 锁定后等待界面

显示：

- 已锁定预案。
- 等待结算状态。
- 托管 / 超时说明。
- 当前玩家自己的锁定状态。

不显示其他玩家详细状态或输入内容。

### 13.3 托管偏好入口

入口：

```text
锁定 / 等待区
设置页
```

托管说明应明确：

- 托管不会主动执行高风险突破。
- 不会主动暴露核心后手。
- 不会消耗稀有不可逆资源。
- 优先保命、避险、延续安全连续状态、基础修炼、休整、警戒、停留。

## 14. 结算阶段 UI

### 14.1 结算阶段核心规则

结算阶段自动推进，不允许玩家主动暂停。

允许进入可阅读状态的情况只有：

- 当前玩家触发选择事件、战斗、突破等插入事件链，需要响应。
- 当前玩家已完成自身响应，但服务端正在等待其他玩家的交叉事件链。
- 多人交叉事件链阻塞了本玩家后续结算推进。

### 14.2 结算阶段默认画面

结算阶段默认：

- 大地图占据主画面。
- 左侧、右侧、底部面板收起。
- 顶部显示动态结算进度条。
- 地图显示结算步骤变化。
- 右下角或底部小区域显示简短结算摘要。

### 14.3 结算被动挂起态

当出现需要当前玩家响应或等待其他玩家交叉事件链时，进入：

```text
结算被动挂起态
```

被动挂起态允许：

- 查看当前事件相关日志摘要。
- 查看原计划相关片段。
- 查看当前已可见结果。
- 查看等待说明。

被动挂起态不允许：

- 修改已锁定行动。
- 主动推进他人事件。
- 查看不可见世界日志。
- 打开完整 Debug 回放。

### 14.4 原计划 vs 实际结果

结算完全结束后显示季度结果摘要，其中包含：

```text
原计划
实际推进
差异原因
最终位置
资源变化
角色状态变化
节点 / 宗门 / 传闻变化
```

该面板用于解释服务端权威结算造成的偏差，例如事件中断、路线阻断、宗门行动冲突、战斗失败、秘境关闭、托管避险等。

## 15. 事件、突破与战斗 UI 边界

### 15.1 普通事件 UI

普通事件链在结算阶段触发时，不必全屏覆盖。推荐为：

```text
结算地图因事件链被动挂起
→ 触发节点高亮
→ 中心事件选择面板弹出
→ 玩家可查看与当前事件相关的日志摘要
→ 玩家选择
→ 面板关闭
→ 若无其他交叉事件链阻塞，则地图继续自动结算
```

普通事件面板应显示：

- 触发节点。
- 触发原因。
- 与原计划的关系。
- 选择项。
- 可能消耗或风险方向。

常规事件主选项区：

```text
1–3 个选项
```

超过 3 个开放选项时使用：

```text
…
```

进入溢出选项区。

不可用选项默认隐藏。只有教学事件、突破准备面板、关键节点事件允许灰显。

### 15.2 突破准备面板

突破分两种界面：

1. **突破准备面板**：决策阶段打开，依附地图，显示突破地点、关键资源、风险、短板、改善路径。
2. **突破事件链界面**：结算阶段触发，沉浸式覆盖主界面。

突破准备面板不全屏，因为玩家需要联动地图选择突破地点、护法来源、宗门支持和资源路径。

突破准备面板显示：

- 风险档位。
- 主要短板。
- 可能失败标签方向。
- 关键消耗。
- 外部干扰预警。
- 可改善路径。
- 相关地点和宗门支持入口。

不显示完整精确概率表。

### 15.3 突破事件链界面

突破事件链可以全屏，因为它是专用高价值交互。

进入前：

- 地图高亮突破节点。
- 显示突破地点、关键突破物、外部干扰来源。

覆盖界面内：

- 显示阶段交锋。
- 显示关键资源和状态。
- 显示不可回头提示。
- 显示本轮选择或指令。

结束后：

- 返回结算地图。
- 显示突破结果如何回写角色、宗门、轮回账本和传闻。

### 15.4 战斗 / 斗法 UI

战斗 / 斗法采用沉浸式覆盖界面。

进入前：

- 地图高亮触发节点或路线段。
- 显示触发原因：移动遭遇、节点危机、宗门行动介入、突破外扰等。

战斗界面内：

- 5 格指令预输入。
- 生机 / 元气 / 神念状态。
- 敌我态势。
- 资源与法宝可用入口。

结束后：

- 返回结算地图。
- 显示战斗结果如何影响路线、节点、角色状态和日志。

### 15.5 普通重大事件覆盖边界

普通重大事件暂不使用沉浸式覆盖。

普通重大事件先使用：

```text
结算被动挂起
+ 触发节点高亮
+ 中心事件面板
```

只有以下专用高价值事件链使用沉浸式覆盖：

- 战斗 / 斗法交锋。
- 大境界突破。
- 死亡 / 转世。
- 未来与战斗、突破、死亡转世同等级的专用事件链。

未来若普通重大事件的文本量、交互深度和状态变化复杂度明显提高，可以从中心弹窗扩展为覆盖界面，但不进入 MVP 默认口径。

常态自动结算中不提供主动暂停，不展开完整日志。

## 22. 关键硬规则

1. 主界面核心是大世界地图画布，不是角色详情页、宗门后台或当前节点卡。
2. 当前节点卡是地图上下文面板，不是主界面第一视觉重心。
3. 大地图必须支持拖动、缩放、节点点击、战争迷雾、已探索节点查看。
4. 已探索节点即使当前不可达，也必须允许查看；可见性与可达性必须分离。
5. 主界面顶层分为决策阶段与结算阶段。
6. 决策阶段细分为季度刷新 / 信息处理即时行动 / 宗门主行动 / 个人持续行动 / 锁定提交。
7. 结算阶段沿用同一张大地图，但隐藏非必要侧边栏和下边栏。
8. 决策阶段顶部是阶段条，结算阶段顶部是动态进度条。
9. 结算阶段大地图用于展示移动、宗门行动、节点变化、传闻扩散和插入事件触发。
10. 结算阶段不允许玩家主动暂停；只能因当前玩家插入事件链或等待其他玩家交叉事件链而被动挂起。
11. 日志摘要只在事件响应中、等待其他玩家事件阻塞时、或结算结束后开放，不作为常态结算中的主动暂停功能。
12. 宗门主行动目标选择应支持地图点选目标节点。
13. 个人行动规划应支持地图点选目标节点并生成路线预估。
14. 大部分功能界面必须依附主地图，以侧边栏、下边栏、中心弹窗或抽屉呈现。
15. 只有战斗、突破、死亡转世及同等级专用事件链允许沉浸式覆盖主界面。
16. 普通事件优先使用结算被动挂起 + 中心事件面板，不默认全屏覆盖。
17. 沉浸式覆盖界面必须保留触发节点、季度、tick 和回写摘要。
18. 结算结束后应提供“原计划 vs 实际结果”摘要，解释服务端权威结算造成的偏差。
19. 战争迷雾、传闻和情报过期状态必须与日志、传闻、目标模板和后手感应联动。
20. Debug 全知地图必须与玩家 UI 分离，不能混入普通地图视图。
21. P0 强提示可临时覆盖地图，但不等于事件链交互。
22. 6 个朔望行动格默认折叠，开始规划后展开。
23. 节点上下文面板只在当前位置模式显示当前位置特殊即时行动。
24. 通用个人即时行动进入全局事务抽屉。
25. 宗门经营命令进入宗门面板，不进入节点卡。
26. 宗门主行动是组织级行动，不是角色节点行动。
27. 每个宗门每季度只有 1 个宗门主行动。
28. 宗门经营命令必须早于宗门主行动输入。
29. 宗门经营命令冻结后本季度不可回退修改。
30. 玩家提交宗门输入后不可修改。
31. 同宗其他玩家宗门输入完全不可见。
32. 全房间所有玩家完成宗门输入或超时后，服务器统一生成宗门反馈。
33. 宗门反馈只显示最终结果，不解释采纳过程。
34. 宗门反馈生成前，任何玩家都不能开始个人行动规划。
35. 宗门反馈生成后，宗门面板可查看但所有控件冻结。
36. 个人即时行动必须早于个人决策指令开始。
37. 进入个人行动规划后，个人即时行动冻结。
38. 退回个人即时准备只清除 6 格草稿，不撤销已完成即时行动或宗门反馈。
39. 非当前位置节点的即时行动只在详情抽屉中显示为抵达后事项。
40. 锁定前提醒不阻止锁定，硬错误阻止提交。
41. 事件链交互只在结算 / 插入阶段出现。
42. 客户端只提交意图，服务端权威校验和回写最终状态。
43. 世界日志默认不可见，玩家看到角色日志、宗门摘要、传闻和轮回账本。
44. 传闻不是全知日志，可以模糊、延迟、不完整。
45. 托管不得主动执行重大不可逆选择。
46. Debug / 开发视图必须单独设计，不混入玩家 UI。

## 24. 开发落地优先级

### 24.1 第一优先级

1. 大世界地图画布。
2. 战争迷雾基础状态。
3. 节点点击与节点上下文面板。
4. 决策阶段顶部阶段条。
5. 宗门主行动依附地图选择目标。
6. 个人行动规划依附地图选择路线。
7. 底部 6 格行动规划器。
8. 锁定前风险确认。
9. 结算阶段动态进度条与地图摘要。
10. 结算被动挂起态。

### 24.2 第二优先级

1. 地图图层切换。
2. 情报过期标签。
3. 目标模板联动地图高亮。
4. 传闻与风险标记。
5. 原计划 vs 实际结果摘要。
6. 事件选择面板与地图触发点高亮。
7. 突破准备面板地图联动。
8. 战斗 / 突破沉浸式覆盖返回地图回写。

### 24.3 第三优先级

1. 地图动画优化。
2. 后手感应上下文图层。
3. 资源机会上下文图层。
4. 更细的结算阅读速度设置。
5. Debug 全知地图和季度回放工具。

## 25. 与 v1.0 的主要差异

| v1.0 口径 | v1.1 修订 |
|---|---|
| 主界面为季度行动规划工作台 | 主界面为大世界地图驱动的季度行动工作台 |
| 当前所在地节点卡是常规第一视觉重心 | 大世界地图画布是第一视觉重心 |
| 地图是节点浏览模块 | 地图是主界面核心交互区 |
| 主界面阶段偏向 0–9 细分状态 | 顶层拆为决策阶段 / 结算阶段，决策阶段内细分 |
| 结算阶段并未单独强化地图表现 | 结算阶段以大地图为中心，显示动态推进 |
| 暂未明确主动暂停限制 | 结算阶段不允许玩家主动暂停，只允许被动挂起 |
| 节点可见性为已知 / 半知 / 已解锁不可详情 / 隐藏 | 扩展为未知 / 传闻 / 已探索 / 情报过期 / 当前可见 / Debug 全知 |
| 当前节点卡、地图节点浏览并列 | 节点卡变为节点上下文面板，依附地图 |
| 宗门目标节点主要在面板内表达 | 宗门目标节点必须支持地图点选与地图高亮 |
| 个人移动规划主要在规划器表达 | 个人移动规划必须支持地图点选与路线预估 |
| 普通事件 UI 边界较宽 | 普通重大事件不默认全屏，只使用中心面板；战斗 / 突破 / 死亡转世才沉浸式覆盖 |
