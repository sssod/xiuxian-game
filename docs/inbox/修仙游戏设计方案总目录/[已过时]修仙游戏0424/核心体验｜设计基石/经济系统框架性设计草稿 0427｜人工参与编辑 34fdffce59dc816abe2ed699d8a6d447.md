## 1. 一句话定位

> 经济系统负责让资源、物品、灵石、宗门库存、NPC 资产、市场库存、事件奖励和后手遗产都拥有可信来源、明确位置、可验证消耗、可追踪流转，并最终服务于“个人成长效率 + 宗门经营取舍 + 沙盒世界演化”。
> 

本项目的经济系统不是完整市场模拟，也不是所有 NPC 都有钱包、背包和消费偏好的社会经济模拟。

它更接近一个资源流转与资产可信系统：

```
行动格 / 风险 / 权限 / 宗门行动
→ 获得资源、物品、灵石、情报或控制权
→ 投入修炼、突破、战斗、建设、探索、后手
→ 提高个人与宗门资源获取效率
→ 接触更高阶资源窗口
→ 死亡、转世、遗产、后手与世界演化继续改变资源分布
```

## 2. 设计目标

### 2.1 玩家体验目标

玩家应能形成稳定理解：

1. 资源不是凭空来的：矿场、药田、秘境、事件、宗门行动、NPC 持有、市场挂牌都应有可解释来源。
2. 物品不是单纯奖励图标：获得物品后，玩家可以自用、上交、出售、拆解、修复、封存、炼制、作为突破资源或战斗资源投入。
3. 灵石是通货，但不是万能资源：灵石能支付交易与基础修行消耗，但高阶灵气需求需要通过聚灵石、阵法、设施或特殊资源转换。
4. 宗门经营有真实库存压力：宗门支持突破、培养弟子、建设设施、开采节点、维护驻守都要从库存或人力中支付。
5. 沙盒演化有资产后果：NPC 死亡、宗门控制权变化、节点被掠夺、后手暴露，都应改变资产位置和世界日志。

### 2.2 系统目标

1. 统一个人、宗门、节点、市场、NPC、事件、后手的资产容器模型。
2. 区分资源池 / 抽象资源 / 可堆叠物品 / 独立实例物品。
3. 区分资产生成、资产转移、资产消耗、资产回收、资产封存。
4. 避免 NPC 临时生成完整库存导致刷物品、掉落不可信、交易与战斗不一致。
5. 控制灵石通胀与高阶资源供给，不让普通通货直接满足所有高阶需求。
6. 支持 MVP 低成本实现，并保留正式版扩展空间。

## 3. 已继承的上位约束

### 3.1 项目与实现边界

- 游戏是修仙题材、文字 / 策略、选择导向、个人成长 + 宗门经营 + 沙盒演化。
- MVP 边界：本地单人可测试、可部署私人服务器、支持 3 人共玩。
- 技术路线为 Godot，服务器进行权威结算，规则与内容应数据驱动。
- 世界按季度推进，每季度角色有 6 个朔望行动格。
- 每个宗门每季度始终只有 1 个宗门主行动。
- 已控制资源节点的稳定产出走常态结算，不占用宗门主行动。

### 3.2 资产与库存约束

- 个人库存与宗门库存必须区分。
- 宗门发放给玩家或 NPC 的资源必须来自真实库存。
- 贡献不是货币，不能直接兑换资源。
- MVP 不引入背包重量、体积、格子或通用负重上限。
- 随身资产由标签、事件条件、位置、调用权限、combat_ready 等上下文限制。
- 战斗中没有换装备 / 换法宝的概念；随身携带且满足条件的法宝、道具、术法、神通都可能成为指令来源。
- 被动法宝可能在战斗、事件或防护中受损。

### 3.3 灵石与货币约束

- 灵石是修行世界核心通货。
- 灵石不分等级。
- 低阶货币，如铜钱、银两，只用于凡人阶段、新手流程和特殊情境，不进入主经济循环。
- 保留灵石兑换低阶货币的入口，用于凡人区域消费、伪装、剧情任务等。
- 修仙小说概念中的“中品灵石 / 上品灵石”等不作为货币等级处理，而以独立物品表达，例如聚灵石。
- 高阶灵气需求通过灵石加工、设施转化、聚灵阵维护、聚灵石等机制表达。

### 3.4 NPC 经济边界

- 不做所有 NPC 的全量经济模拟。
- NPC 采用分层持久化。
- N2 服务型 NPC 的商品库存通常不属于 NPC 个人，而属于 ShopStock、MarketListing、SectStorage 或 NodeStorage。
- N3 / N4 关键 NPC 可以拥有真实个人库存、状态和宏观行动。
- 战斗开始时不得临时初始化完整 NPC 库存。
- 战斗战利品只能来自 NPC 已持久化随身 / 可调用资产、事件锁定奖励包，或由事件预算生成并写日志的奖励。

## 4. 核心原则

### 4.1 先问资产容器，再问物品归属

经济系统不应先问：

```
这个 NPC 身上有什么？
```

而应先问：

```
这个资产属于哪个容器？
容器在哪里？
谁有权限调用？
它是否显性存在？
它的变化是否需要写入日志？
```

### 4.2 资产变化分为五类

```
生成：世界、节点、事件、配方或预算创造新资产
转移：资产从一个容器移动到另一个容器
消耗：资产被行动、事件、战斗、突破、建设等用掉
回收：资产被拆解、修复、出售、上交、再加工，转换成其他资产
封存：资产进入正式后手、遗产、密库、事件锁定或隐藏层
```

这五类必须在数据层区分，不能全部用“获得 / 失去物品”表达。

### 4.3 抽象到足够低成本，具体到足够可信

MVP 不需要让所有资源都是具体物品实例。

推荐口径：

- 宗门大宗资源可以先抽象为库存数值。
- 节点自然产能可以先作为 ResourcePool / ResourceSlot。
- 普通材料、丹药、符箓可作为可堆叠物品。
- 法宝、功法载体、正式后手物、高价值突破资源、带独立状态的物品应作为实例物品。
- 当抽象资源需要进入战斗、交易、突破、封存、奖励、遗产等具体语境时，再转换为物品栈或实例。

### 4.4 生成预算与库存流转并存

经济系统需要同时维护两套概念：

1. 库存流转：已经显性存在的资源和物品在容器之间移动。
2. 生成预算：事件、宝藏、NPC 掉落、秘境奖励等“凭空生成”内容受分阶预算帽约束。

规则建议：

- 一旦物品由事件 / 宝藏 / 隐性状态实例化，就按该物品完整预算价值扣除生成预算。
- 后续出售、拆解、损坏、销毁、上交、封存，不返还生成预算。
- 生成预算用于控制世界投放，不是玩家可见资源，也不是资产回收池。

### 4.5 不设计“半可堆叠”物品

物品应在规则层明确为：

```
可堆叠物品
或
独立实例物品
```

不引入“半可堆叠”作为通用第三类，避免库存规则复杂化。

可堆叠性的判断应由堆叠键决定：

```
item_template + tier + quality + key_state_tags + bind_state + owner_restriction
```

如果某个字段会影响战斗、突破、交易、后手、消耗结果，则进入堆叠键；如果只是风味来源，不影响规则，则不应拆分堆叠。

物品来源字段也不要求所有物品强制保存。只有对玩法有意义的物品才保留来源参数，例如法宝、正式后手物、命名物品、高价值突破资源、剧情物品。

## 5. 经济对象分层

### 5.1 货币 Currency

MVP 主货币：

```
SpiritStoneStack {
  amount
  owner_container_ref
  bind_state optional
  ledger_refs
}
```

低阶货币：

```
MundaneCurrencyStack {
  currency_type     // coin / silver 等
  amount
  context_tags      // mortal_trade / disguise / village_flow 等
}
```

规则：

- 灵石是主经济循环通货。
- 低阶货币不进入修行世界主循环。
- 灵石可以兑换低阶货币，但低阶货币不应反向成为主要修行资源入口。
- 聚灵石不是货币面额，而是高密度灵气物品。

### 5.2 宗门抽象资源 AbstractResourceStock

MVP 宗门追踪五类资源：

1. 灵石。
2. 修炼资源。
3. 材料 / 矿材。
4. 人力 / 弟子规模。
5. 声望 / 影响力。

建议结构：

```
SectResourceStock {
  sect_id
  spirit_stone
  cultivation_resource
  material_stock
  manpower
  reputation
  reserved_resources
  income_sources
  expense_records
  stock_logs
}
```

规则：

- 这是 MVP 的低成本组织库存表达。
- 当资源需要成为具体道具、法宝、材料堆叠、突破资源、奖励包时，由 S9 / 物品系统细化。
- 声望 / 影响力不是货币，不直接兑换物品，而是行动修正、外部响应、控制权竞争和事件承担参数。
- 人力不是物品，可被占用、损耗、恢复或转化为执行完成度修正。

### 5.3 资源池 ResourcePool

资源池不是库存，而是节点或世界中尚未被开采 / 转化的潜在产能。

```
ResourcePool {
  pool_id
  node_ref
  resource_type
  tier_code
  abundance_state
  extraction_difficulty
  regeneration_rule
  depletion_risk
  discovery_state
  controlling_faction_bonus
}
```

规则：

- 自然资源点原则上先产出资源池 / 资源量，不直接产出具体物品。
- 开采、采集、炼制、加工、宗门行动、节点事件会把资源池转化为宗门库存、个人物品或事件奖励。
- 已控制且状态稳定的资源池可以季度常态产出。
- 加大开采、深层探索、处理异变、抢夺控制权才占用宗门主行动或触发事件链。
- 节点 ResourcePool 的枯竭、再生、污染、异变等规则按节点模板配置，不做全局统一公式。

### 5.4 可堆叠物品 ItemStack

适用于：

- 灵石以外的普通材料。
- 普通丹药。
- 普通符箓。
- 补给。
- 一般修炼资源。
- 一般突破材料。

```
ItemStack {
  item_template_id
  tier_code
  quality_code
  amount
  stack_key_tags
  owner_container_ref
  state_tags
}
```

规则：

- 高频普通道具不应因为细微随机差异拆成大量实例。
- 如果纯度、污染、绑定、宗门标记、后手关联会影响规则，则纳入堆叠键。
- 如果来源只是叙事风味，不影响消耗和判定，则不拆分。

### 5.5 独立实例物品 ItemInstance

适用于：

- 法宝。
- 功法 / 术法载体。
- 高价值突破资源。
- 正式后手封存物。
- 事件锁定物。
- 命名物品。
- 带耐久、灵性、缺页、封印、来源、隐藏缺陷、独立状态的物品。

```
ItemInstance {
  item_id
  item_template_id
  tier_code
  quality_code
  owner_container_ref
  location_ref
  state_tags
  durability optional
  charge optional
  spirituality optional
  source_record optional
  legacy_state optional
  ledger_refs
}
```

## 6. 资产容器模型

所有显性资产都应属于容器。

```
AssetContainer {
  container_id
  container_type
  owner_ref
  location_ref
  persistence_mode
  currency_stacks
  abstract_resources optional
  item_stacks
  item_instances
  access_rules
  visibility_rules
  ledger_refs
}
```

### 6.1 容器类型

| 容器类型 | 含义 | 示例 |
| --- | --- | --- |
| CharacterInventory | 角色 / 高层 NPC 随身资产 | 玩家背包、长老随身法宝 |
| CharacterStorage | 角色个人储藏 | 洞府、临时藏物点 |
| SectStorage | 宗门库存 | 宗门库房、培养资源、材料仓 |
| NodeStorage | 节点储藏 | 矿场库存、村庄仓储、秘境封存区 |
| ShopStock | 店铺库存 | 丹药铺、法宝铺、坊市摊位 |
| MarketListing | 市场挂牌 | 玩家或 NPC 挂售物品 |
| EventLocked | 事件锁定资产 | 押运货物、秘境奖励、战斗赌注 |
| SealedLegacy | 正式后手封存 | 前世洞府、封印阵、遗产盒 |
| ResourcePool | 聚合资源池 | 灵脉产能、矿脉储量、药田收成 |

### 6.2 个人资产与机构资产必须分离

错误口径：

```
掌柜 = 商店库存持有人
宗主 = 全宗门库房持有人
村长 = 全村资产持有人
```

正确口径：

```
掌柜 = ShopStock 的服务入口
宗主 = SectStorage 的权限影响者
村长 = NodeStorage / PopulationPool 的角色代表
```

设计理由：

- NPC 死亡后机构仍可存在。
- 职位更替后库存不丢失。
- 抢劫、查抄、交易、发放、征收都能定位到正确资产容器。
- NPC 个人失败不等于组织资产全量失守。

## 7. 资产来源框架

### 7.1 节点常态产出

来源：S8 ResourceSlot / ResourcePool。

流程：

```
节点拥有资源槽
→ 宗门或势力控制节点 / 建筑正常运转
→ 每季度常态结算产出
→ 写入 SectStorage / NodeStorage
→ 写入库存日志
```

规则：

- 已控制资源节点的基础产出不占宗门主行动。
- 产出受控制权、影响力、建筑状态、资源丰度、灾害、敌对干扰、人力占用影响。
- 产出优先进入宗门抽象库存或节点库存。
- 若产出需要具体物品形态，再由物品系统转换为 ItemStack / ItemInstance。

### 7.2 宗门主行动产出

来源：S7 六类宗门主行动。

包括：

- 开采 / 资源介入。
- 驻守 / 控制强化。
- 探索。
- 远征。
- 建设。
- 培养。

流程：

```
宗门主行动计划
→ 检查权限、库存、人力、节点、风险
→ 预留 / 消耗资源
→ 结算执行完成度
→ 生成结果包
→ 改写库存、节点、控制权、影响力、事件状态
```

规则：

- 宗门主行动消耗必须来自 SectStorage 或已预留资源。
- 产出进入 SectStorage、NodeStorage、EventLocked 或触发后续事件。
- 不因为宗门有多个长老 / N4 就增加宗门主行动数量。
- N4 个人宏观行动可以影响宗门倾向、事件链或执行修正，但不能默认给宗门额外组织行动。

### 7.3 角色个人行动产出

来源：S3 持续行动、节点特有行动、事件链。

包括：

- 探索。
- 修炼。
- 采集。
- 秘境推进。
- 后手搜寻 / 回收。
- 个人介入宗门行动。
- 战斗 / 斗法事件。
- 任务链结果。

规则：

- 角色个人行动消耗行动格。
- 产出与风险必须接入 S3 时间轴和事件日志。
- 高价值产出通常应通过 EventLocked 或结果包先锁定，再转入角色、宗门、节点或市场容器。
- 角色亲自介入宗门行动时，S3 判断位置 / tick / 路线资格，S7 判断执行完成度修正。

### 7.4 事件生成与隐性实例化

事件、宝藏、NPC 掉落、秘境奖励、隐藏层发现等属于“可能凭空生成”的高风险来源，需要受预算约束。

流程：

```
事件触发
→ 读取事件奖励表 / 隐性资产表 / 生成预算
→ 锁定奖励包 EventLocked
→ 结算事件结果
→ 成功则实例化或转移
→ 失败则保留、转移、损毁或重新隐藏
→ 写入来源日志
```

规则：

- 事件奖励不是 NPC 战斗开始时临时背包。
- 高价值随机物品必须扣除分阶生成预算。
- 生成预算按完整价值扣除。
- 生成后即使物品被拆解、销毁、出售或上交，也不返还生成预算。
- 隐性状态只表示“世界中可能存在但尚未显性进入库存”，不等于玩家可无限刷新。

### 7.5 NPC 经济来源

NPC 分层决定其资产复杂度。

| 层级 | 经济口径 |
| --- | --- |
| N0 抽象人群 | 不持有物品实例，只作为人力、人口、消费、风险池 |
| N1 轻量身份 NPC | 不持久化个人库存，奖励来自节点 / 事件 / 组织预算 |
| N2 服务 NPC | 服务状态持久化，库存归 ShopStock / SectStorage / NodeStorage |
| N3 关键 NPC | 拥有个人库存、随身资产、宏观行动，可参与经济流转 |
| N4 世界轴心 NPC | 必定生成季度个人宏观行动，影响世界事件与势力倾向 |

规则：

- NPC 被击败时，不初始化完整随机背包。
- 可获得资产来自其真实随身 / 可调用资产、事件锁定物、事件预算奖励。
- 商人被击败不等于获得整个店铺库存。
- 若目标是商店、仓库、押运货物或宗门库房，应进入节点 / 宗门 / 事件链，不是普通 NPC 掉落。
- MVP 阶段暂不做 N3 的完整宗门培养资源申请与支持闭环；可先用俸禄领取或季度资源消耗表达宗门支出与 NPC 修为增长的关联。
- N3 / N4 个人资产与宗门资产之间的借用、挪用、赏赐、托管等复杂关系不进入 MVP，后续正式版再展开。

### 7.6 配方生产与加工

由角色或宗门主动生产物品时，优先采用配方制。

```
Recipe {
  recipe_id
  input_resources
  required_facility
  required_skill_tags
  action_cost
  output_profile
  byproduct_profile
  failure_profile
  random_allowed_fields
}
```

规则：

- 配方消耗明确资源，产出明确目标物品。
- 随机只在配方允许范围内发生。
- 生产失败应有回收、次品、损耗或副产物规则。
- 高阶资源生产应绑定设施、节点、权限、技能或宗门行动。

### 7.7 灵石加工与聚灵石

灵石不分等级，但高阶灵气需求需要被限制。

已确定决策：**灵石加工进入 MVP，但 MVP 只打通“灵石 → 聚灵石”这一条加工路径。**

```
灵石 + 加工设施 + 时间 / 人力 / 技艺修正
→ 聚灵石
```

聚灵石规则口径：

- 聚灵石是独立物品，不是灵石的高阶面额。
- 聚灵石拥有阶级 Tier 与品级 Quality。
- MVP 主要目标是引入“上级资源 / 高密度灵气物品”的概念。
- MVP 暂不在聚灵石消耗环节增加复杂的阶级和品级限制。
- 聚灵石可先作为高阶阵法、突破、洞府维护、法宝充能、特殊配方等系统的统一高密度资源接口。
- 后续正式版可再细化为：不同阶级 / 品级聚灵石适配不同阶级设施、突破方案或高阶资源转换。

设计作用：

- 普通灵石继续作为通货。
- 聚灵石承担高阶灵气资源的物品化表达。
- 高阶需求不直接吞普通灵石，避免灵石通胀向顶级需求无损传递。
- 加工设施效率、配方损耗、节点条件成为高阶资源供给阀门。
- MVP 只验证“通货 → 高密度资源”的加工阀门，不展开完整加工工业链。

## 8. 资产去向与消耗框架

### 8.1 角色修炼消耗

消耗对象：

- 行动格。
- 环境灵气。
- 丹药 / 灵液 / 灵米 / 修炼配给。
- 聚灵阵维护资源。
- 主修道功适配条件。

规则：

- 丹药不直接加修为数字，而是提供药力 / 灵气输入包。
- 输入包仍需通过主修道功、资质、地点和状态转化。
- MVP 不引入丹毒 / 杂质累计，但保留修为纯度接口。
- 未转化部分表现为逸散、浪费或短期不适。

### 8.2 突破消耗

消耗对象：

- 突破资源。
- 宗门预留资源。
- 场地灵气。
- 护法支持。
- 阵法 / 法宝 / 消耗道具。
- 行动格或剩余季度时间。

规则：

- 突破支持必须检查库存并生成预留。
- 突破事件链开始后，预留资源按阶段消耗或锁定。
- 突破失败可导致部分资源消耗、道伤、寿元损耗、死亡、转世或遗产事件链。
- 大境界突破不能由自动运转完成。

### 8.3 战斗消耗

消耗对象：

- 生机 / 元气 / 神念。
- 消耗道具。
- 法宝耐久、灵性、充能。
- 战斗事件锁定资产。

规则：

- 战斗消耗回写角色持久状态。
- 法宝主动使用、被动触发、抵伤、被针对破坏均可能受损。
- 战斗中资源不足会导致指令失败并触发兜底指令。
- 战斗战利品只来自真实资产或事件锁定奖励。

### 8.4 移动与交通消耗

消耗对象：

- 行动格。
- 补给。
- 灵石。
- 票据。
- 权限。
- 阵法状态。
- 交通设施维护状态。

规则：

- 飞舟、传送阵、渡口等归入移动行动。
- 交通设施不占节点一般持续操作次数，但可消耗资源并触发风险。
- 补给只作为远行约束和事件消耗，不做完整生存系统。

### 8.5 宗门支出

消耗对象：

- 灵石。
- 修炼资源。
- 材料 / 矿材。
- 人力。
- 声望 / 影响力。
- 具体物品。

支出方向：

- 发放弟子培养资源。
- 发放宗门俸禄。
- 支持玩家或 NPC 突破。
- 宗门主行动。
- 节点建设与修复。
- 驻守、远征、探索的人力占用。
- 应对节点危机。
- 维护宗门核心建筑。
- 设施加工，例如聚灵石生产。

#### 8.5.1 建筑 / 设施维护成本

已确定决策：**MVP 启用建筑 / 设施维护成本，但不引入折旧、自然损耗或法宝自然灵性衰退等复杂损失机制。**

适用对象示例：

- 聚灵阵。
- 防御阵。
- 炼丹炉。
- 炼器炉。
- 其他持续工作的宗门建筑、设施或部门核心设备。

规则口径：

- 设施每季度如果工作，则需要消耗维护成本。
- 不工作的设施默认不产生工作维护成本，但仍可被事件、攻击、灾害或特殊状态影响。
- 维护成本可以消耗灵石、材料 / 矿材、聚灵石、修炼资源、人力或特定物品，具体由设施模板配置。
- 若维护成本不足，设施本季度工作效果降低、暂停、失败或触发轻量故障事件。
- MVP 不引入设施折旧曲线，不做“每季度自然磨损导致耐久下降”的长期维护压力。
- MVP 不引入法宝自然灵性衰退；法宝损耗主要来自主动使用、被动触发、战斗破坏或事件后果。

设计理由：

- 维护成本让宗门设施产出与宗门财政形成闭环。
- 不引入折旧和自然衰退，避免经济系统过早变成设备管理和耐久维护游戏。

#### 8.5.2 宗门俸禄规则

已确定决策：**宗门俸禄由境界基数 + 职位绝对值构成，所有宗门采用同一套基础标准；宗门财政状态只作为发放修正。**

基础结构：

```
俸禄基数 = 境界基础俸禄 + 职位附加俸禄
最终俸禄 = 俸禄基数 + 利润分成修正 - 财政不足削减
```

规则口径：

- 境界决定基础俸禄。
- 职位提供一个绝对值附加，不使用百分比附加。
- 俸禄基数与季度序号无关。
- 所有宗门共享同一套境界 / 职位基础标准，避免每个宗门维护独立俸禄表。
- 宗门当季有净利润时，可按俸禄基数比例将净利润增配到最终俸禄中。
- 利润分成的增配上限为俸禄基数本身，即最终俸禄最高为俸禄基数的 2 倍。
- 宗门当季赤字时，无利润分成。
- 宗门扣除当季非俸禄支出后，剩余库存不足以全额支付俸禄时，所有应发俸禄按比例减少发放。

示例：

```
金丹中期基础俸禄：20000 灵石 / 季度
长老职位附加：5000 灵石 / 季度
俸禄基数：25000 灵石 / 季度
若宗门利润分成充足，最终最高可达：50000 灵石 / 季度
```

NPC 层级适用范围：

- N0 不分配俸禄；N0 是抽象人群 / 劳力池，不作为个人资产主体。
- N1 不分配俸禄；N1 是轻量身份 NPC，不维护完整个人经济循环。
- N2 分配俸禄，俸禄进入其个人库存，但 MVP 暂不用于修炼成长，只用于服务型 NPC 的经济可信表达与后续扩展接口。
- N3 / N4 可分配俸禄，并可作为其个人经济流转、宏观行动或角色成长的输入之一。MVP 可先以季度资源消耗 / 俸禄领取表达其与宗门支出的关联，不展开完整申请和竞争流程。

### 8.6 市场与交易消耗

MVP 不做完整供需市场模拟。

基础交易类型：

1. 一口价购买：从 ShopStock 或 MarketListing 转移到个人库存。
2. 一口价出售：从个人库存转移到 ShopStock。
3. 宗门内部领取：从 SectStorage 转移到个人库存或直接进入事件。
4. 上交宗门：从个人库存转移到 SectStorage，换取贡献、声望或权限变化。
5. 事件交换：由事件链决定双方资产变化。

规则：

- 贡献不是货币，不能无库存兑换物品。
- 出售是资产转移或系统回收，不返还生成预算。
- 店铺库存属于 ShopStock，不属于掌柜个人。
- 价格可以先采用基准价 + 节点 / 宗门 / 供给状态修正，不做动态市场清算。

#### 8.6.1 宗门商店与非宗门商店供给差异

已确定决策：**只有宗门商店需要依赖真实供给状态；非宗门商店按商店常规运营事件处理，属于世界生成的一部分。**

宗门商店：

- 库存供应依赖宗门建筑、设施、部门、资源节点和宗门生产能力。
- 例如丹药铺库存可读取炼丹房、药田、采购渠道、宗门库存、丹师部门状态。
- 宗门商店库存不足时，应反映宗门生产、库存或供给链压力。

非宗门商店：

- 不要求读取完整供给链。
- 按商店常规运营事件、节点繁荣度、商路状态、世界生成预算和刷新规则处理。
- 可被抢劫、断供、灾害、战争、事件状态影响，但不维护完整上游生产链。

设计理由：

- 宗门商店是宗门经营闭环的一部分，必须反馈宗门设施和库存。
- 非宗门商店主要承担世界交易入口和物品投放功能，不应把 MVP 推入完整社会经济模拟。

#### 8.6.2 玩家出售物品后的 ShopStock 保留与回收

已确定决策：**玩家出售给商店的物品真实进入 ShopStock，但不支持原价回购，并在保留期后进入回收规则。**

出售行为规则：

- 出售行为属于即时行动。
- 出售在回合决策阶段之前完成。
- 出售后，物品进入商店 ShopStock。
- 商店按回收价向玩家支付灵石。
- 出售给商店的物品不支持原价回购；玩家若再次购买，按商店售价规则购买。

保留期规则：

- 玩家出售给商店的物品默认保留 1 个季度 / 1 个回合。
- 例如本回合卖出物品，下个回合开始时仍可以买回。
- 下个回合执行抢劫商店库存的行动时，如果该物品是可堆叠物品，则通常已经进入回收环节，不再存在于货架库存中。

保留期结束后的处理：

- 不可堆叠物品：继续保留在货架 / ShopStock 中。
- 可堆叠物品：例如标准符箓、标准丹药，直接按回收价折算成等值灵石补充到商店库存，视为进入系统回收环节。
- 该过程等价于玩家角色直接将物品出售给世界并换回等价回收价灵石。

库存上限与警戒缓冲区：

- 商店设置库存上限与库存警戒缓冲区。
- 不可堆叠物品进入库存警戒缓冲区后，按照回收价从低到高依次进入回收系统。
- 被回收的不可堆叠物品从 ShopStock 移除，并向商店库存返还等价回收价灵石。
- 回收持续执行，直到库存重新低于警戒区。

不可回收标签：

- 带有 `non_recyclable` / 不可回收标签的物品，不会被玩家角色回收，也不会被系统回收。
- 一般适用于剧情物品、关键道具、任务链物品或必须保留追踪状态的特殊资产。
- 不可回收物品进入 ShopStock 后，应通过事件、任务、权限或特殊库存规则处理，不进入自动回收队列。

## 9. 回收、拆解与遗产

### 9.1 回收类型

| 类型 | 规则含义 |
| --- | --- |
| 出售 | 资产转移为灵石，物品进入市场 / 店铺 / 抽象回收池 |
| 上交 | 资产进入宗门库存，角色获得贡献、声望或权限修正 |
| 拆解 | 物品转化为材料、残片、副产物或损耗 |
| 修复 | 消耗材料与资源恢复法宝、建筑或物品状态 |
| 加工 | 低密度资源转化为高密度物品，例如灵石加工为聚灵石 |
| 销毁 | 物品从显性资产中移除，写入原因日志 |
| 封存 | 资产转入正式后手或隐藏层，保留追踪状态 |

### 9.2 拆解规则

建议拆解使用配置化回收表：

```
SalvageProfile {
  source_item_type
  minimum_state_requirement
  output_materials
  output_ratio
  byproduct_chance
  required_action_or_facility
  failure_loss_profile
}
```

规则：

- 拆解返还的是材料或副产物，不返还生成预算。
- 高价值实例物品拆解必须写入日志。
- 法宝拆解可能返还材料、灵性残片、核心组件或污染物。
- 普通可堆叠物品拆解可先低成本处理，不要求逐件实例追踪。

### 9.3 死亡与遗产分配框架

死亡事件必须先结算事件链，再分配遗产。

已确定决策：**MVP 不按复杂世界观关系细分遗产优先级；除当场损失外，其余资产归属权整体移交给一个主体。**

推荐顺序：

```
角色 / NPC 死亡判定
→ 结算死亡原因、战斗结果、随身物品损坏、现场控制权
→ 结算父事件链明确指定的战利品、赔偿、赌注、任务结算和当场损失
→ 锁定剩余可继承资产
→ 按继承主体顺序选择一个接收主体
→ 将剩余资产归属权整体移交给该主体
→ 写入资产日志、世界日志、传闻或轮回账本
```

当场损失包括：

- 父事件链明确转移给胜利者、劫掠者、救援者或任务对象的资产。
- 战斗中损坏、破碎、消耗、遗失、污染的资产。
- 事件明确销毁、封禁、暴露、失效或转入 EventLocked 的资产。
- 正式后手触发暴露、争夺、污染或失效时，由 S11 单独处理。

剩余资产归属权移交顺序：

```
N3 / N4 的道侣
→ 子嗣
→ 弟子
→ 宗门
→ 家族
→ 世界
```

规则口径：

- 每次死亡遗产只选择一个最终接收主体，不做多主体比例分配。
- 若前一顺位不存在、不可用、无继承资格或事件链禁止继承，则顺延到下一顺位。
- “世界”表示资产脱离可追踪个人 / 组织继承关系，可进入无主遗产、传闻、隐藏层、市场回收、节点储藏或世界生成池，由事件模板决定。
- 正式后手默认不进入普通遗产池，仍按 S11 的封存、感应、暴露和失效规则处理。
- 普通遗产可以整体移交为容器归属权变化，不要求逐件弹窗分配。

设计理由：

- 简化死亡后的经济结算成本。
- 避免遗产系统过早扩展成复杂家族、婚姻、师徒、宗门法理模拟。
- 保留 N3 / N4 重要关系对世界演化的影响，但只作为归属权转移顺序。

## 10. 价值、价格与预算口径

经济系统至少需要区分四类价值，不建议混用。

### 10.1 交易价值 TradeValue

用于买卖、估价、商店价格、市场挂牌。

影响因素：

- 阶级 Tier。
- 品级 Quality。
- 物品类型。
- 稀缺度。
- 状态完整度。
- 节点供给。
- 宗门关系 / 权限。
- 市场规则。

### 10.2 生成预算价值 BudgetValue

用于事件、秘境、掉落、宝藏等生成预算扣除。

规则：

- 生成时按完整预算价值扣除。
- 后续出售、拆解、销毁、上交不返还预算。
- BudgetValue 不必等于 TradeValue。
- 高风险事件可以允许超常规预算，但必须写入事件原因。

### 10.3 回收价值 SalvageValue

用于拆解、修复折价、残片产出。

规则：

- 通常低于交易价值。
- 受物品状态、拆解设施、角色技艺、法宝灵性、污染等影响。
- 回收产物进入材料库存或物品栈。

### 10.4 宗门贡献价值 ContributionValue

用于上交宗门后的贡献、声望、职位评价或权限修正。

已确定决策：**贡献价值基于交易价值折算，不维护第二套独立基础价值表。**

基础公式：

```
贡献价值 = 宗门需求程度% × 交易价值
```

规则：

- 贡献不是货币。
- 贡献价值不维护独立基础值，而是读取 TradeValue。
- 宗门需求程度是百分比修正，可由宗门库存短缺、当前建设、培养方向、突破支持需求、节点危机、部门需求等决定。
- 宗门急需资源时，需求程度提高，贡献价值提高。
- 宗门不需要或无法消化的物品，需求程度降低，贡献价值降低。
- 实际资源发放仍必须检查 SectStorage，不能用贡献绕过库存约束。

## 11. 预留、锁定与日志

### 11.1 资源预留

为了避免同一资源被多系统重复使用，需要预留机制。

```
ResourceReservation {
  reservation_id
  container_ref
  resource_type
  amount
  reserved_for_system
  reserved_for_event
  start_quarter
  expiry_quarter
  status              // active / consumed / released / failed
}
```

使用场景：

- 宗门同意支持突破。
- 宗门行动提前锁定材料和人力。
- 市场交易锁定挂牌物。
- 事件赌注、押运、任务奖励锁定资产。
- 后手封存过程中锁定物品。

### 11.2 经济日志

每次生成、转移、消耗、回收、封存都应写入日志。

```
EconomicLedgerEntry {
  ledger_id
  quarter
  operation_type       // generate / transfer / consume / salvage / seal / destroy
  source_container_ref optional
  target_container_ref optional
  asset_refs
  resource_delta
  reason
  source_system
  actor_ref optional
  related_node optional
  related_event optional
  visibility
}
```

显示规则：

- 玩家只看到权限范围内的经济日志。
- 调试模式可查看完整世界日志。
- 世界日志是系统测试与回放语义；玩家端表现为传闻、账本、宗门公告、库存记录或事件描述。

## 12. 季度经济结算建议顺序

本顺序只定义经济层内部推荐顺序，不替代 S1 总结算流程。

```
季度开始快照
→ 处理过期预留与锁定资产
→ 节点常态产出进入 NodeStorage / SectStorage
→ N2 服务刷新、ShopStock 补货、价格状态刷新
→ N4 个人宏观行动生成；N3 活跃集宏观行动生成
→ 宗门主行动消耗预留并结算结果包
→ 玩家 S3 行动推进，触发资源使用、采集、交易、修炼、后手、事件
→ 战斗 / 突破 / 节点事件链结算资产变化
→ 死亡事件链结算，再进行遗产分配
→ 市场挂牌、库存、后手、节点状态最终回写
→ 生成可见日志、传闻、宗门记录与调试日志
```

设计理由：

- 先处理常态产出，保证宗门行动和玩家行动读取的是本季度可用库存。
- 先锁定资源再结算事件，避免重复消耗。
- 死亡遗产必须在死亡事件链完成后分配，避免战斗结果、现场控制权、法宝损坏还未确定就提前分资产。
- 日志最后汇总，但每一步应生成可追踪条目。

## 14. 已发现矛盾与本稿修正

### 14.1 宗门抽象资源 vs 具体物品库存

潜在矛盾：S6 使用五类抽象宗门资源，S9 又要求物品真实存在。

修正：采用双层库存。

- MVP 宗门大宗库存使用抽象资源数值。
- 具体到法宝、功法载体、突破资源、正式后手、交易商品时，转换为 ItemStack / ItemInstance。
- 二者之间通过配方、发放、上交、奖励、消耗接口转换。

### 14.2 资源点直接产出物品 vs 资源点产出资源池

潜在矛盾：部分语义会把矿场、药田理解为直接产出具体物品。

修正：资源点默认先是 ResourcePool。

- 常态结算产出抽象资源或基础材料。
- 采集、加工、炼制、宗门行动或事件结果再转换为具体物品。
- 高价值物品需要事件、深层探索、加工或配方解释。

### 14.3 NPC 掉落 vs NPC 不全量持久库存

潜在矛盾：如果 NPC 平时没有完整库存，战斗掉落从哪里来？

修正：战斗战利品来源限定为三类。

1. NPC 已持久化的随身 / 可调用资产。
2. 事件链在结算前锁定的 EventLocked 奖励。
3. 由事件生成预算创造、并写入来源日志的奖励。

不得在战斗开始时临时初始化 NPC 完整背包。

### 14.4 商店库存 vs 掌柜个人库存

潜在矛盾：商店商品是否属于掌柜？

修正：商店库存属于 ShopStock / MarketListing / NodeStorage。

掌柜是服务入口，不是商店资产所有者。抢劫商店应进入节点或事件链，而不是击败掌柜即可获得全部商品。

### 14.5 灵石不分等级 vs 高阶灵气需求

潜在矛盾：灵石不分等级后，高阶修炼和阵法如何表达高密度资源？

修正：灵石只做通货，高阶需求由聚灵石等独立物品表达。

聚灵石通过加工灵石、设施效率、配方损耗、节点条件和宗门能力产生，是高阶资源阀门。

### 14.6 贡献与货币混淆

潜在矛盾：玩家上交物品后是否可用贡献直接换资源？

修正：贡献不是货币。

贡献用于宗门评价、权限、采纳率、发放资格、职位和支持申请修正。实际资源发放仍必须检查 SectStorage。

### 14.7 物品来源字段过度泛化

潜在矛盾：若所有物品都保存完整来源，会增加实现成本和堆叠复杂度。

修正：来源日志优先保存在 EconomicLedgerEntry；只有玩法需要时，物品本身才保留 source_record。

适合保留来源的物品：法宝、正式后手物、高价值突破资源、剧情物品、命名物品、污染物或因果相关物。

## 17. 待决问题收敛记录

### 17.1 已收敛决策

1. 灵石加工进入 MVP，但只打通“灵石 → 聚灵石”一条路径。聚灵石是有阶级和品级的独立物品；MVP 不在消耗聚灵石的环节增加阶级和品级限制。
2. 只有宗门商店需要依赖供给状态，即由宗门建筑 / 设施 / 部门产出来决定库存供应；非宗门商店按商店常规运营事件处理，属于世界生成的一部分。
3. 玩家出售给商店的物品进入 ShopStock，默认保留 1 个季度。保留期后，可堆叠物品按回收价折算为灵石进入商店库存；不可堆叠物品继续保留，超出库存警戒区时按回收价从低到高进入回收系统。出售给商店的物品不支持原价回购。带不可回收标签的物品不进入玩家回收或系统回收。
4. 宗门贡献价值不维护独立基础值，基于交易价值折算：贡献价值 = 宗门需求程度% × 交易价值。
5. 宗门俸禄基数取决于境界，职位附加一个绝对值，所有宗门一致；宗门财政状态通过利润分成或不足比例削减修正最终发放额。
6. N3 / N4 个人资产与宗门资产之间的借用、挪用、赏赐、托管等复杂关系不进入 MVP，后续正式版再展开。
7. MVP 启用建筑 / 设施维护成本设计。聚灵阵、防御阵、炼丹炉、炼器炉等设施每季度如果工作，都需要消耗维护成本；MVP 不引入折旧和法宝自然灵性衰退等复杂损失机制。
8. 节点 ResourcePool 的枯竭、再生、污染、异变等规则按节点模板配置，不做全局统一公式。
9. 死亡遗产分配不细化复杂世界观规则。除当场损失外，其余资产归属权整体移交给某个主体，顺序为：N3 / N4 的道侣 → 子嗣 → 弟子 → 宗门 → 家族 → 世界。
10. MVP 不做操控市场和倒卖赚差价玩法；这不是本游戏的核心玩法和核心体验。
11. N0 / N1 不分配俸禄；N2 俸禄先暂定进入个人库存，但不用于修炼。

## 18. 推荐定案方向摘要

本稿建议将经济系统定为：

```
资产容器为骨架
资源池为产能
抽象宗门资源为 MVP 组织库存
物品栈 / 物品实例为具体可用资产
生成预算控制凭空投放
预留机制防止重复消耗
日志系统保证追踪与回放
灵石作为通货
聚灵石作为 MVP 高阶加工阀门
建筑 / 设施维护成本连接宗门财政与设施产出
NPC 分层参与经济，不做全量生态模拟
```

这样可以同时满足：

- 玩家资源获得与消耗可信。
- 宗门经营有库存压力。
- NPC 掉落与交易不冲突。
- 后手和遗产可追踪。
- 高阶经济不被普通灵石无限打通。
- MVP 实现成本可控。
