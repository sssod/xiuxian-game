# 系统设计｜符箓

## 1. 设计定位

本文维护符箓作为一次性消耗物品的系统规则。符箓以“一张 / 一枚”为最小使用单位，可以作为行动资源输入、事件选项资源、战斗指令来源、危险语境防护资源或一次性功能道具；使用成功进入结算后消耗对应数量。

符箓不是装备栏式长期挂件，也不是绕过行动、事件或战斗结算的即时万能按钮。若某个设计需要长期佩戴、反复使用、成长维护或稳定被动增益，应进入法宝、护符或装备类设计。

## 2. 当前结论

1. 符箓必须位于资产容器中，例如角色随身、角色储藏、宗门库存、商店库存、NPC 持有物、节点奖励、事件锁定奖励或后手封存。
2. 普通符箓可以作为可堆叠物品；高价值、命名、残缺、封印、剧情、后手封存或带独立状态的符箓应作为 `ItemInstance` 追踪。
3. 符箓效果由模板配置决定，可以是一次性生效，也可以在消耗后创建持续效果。
4. 符箓是否随机不由“符箓”这一类型决定，而由效果配置数值决定；同类符箓可以有确定性模板，也可以有随机波动模板。
5. 修炼辅助符箓不得即时增加修为；若符箓提供修炼辅助，只能作为兼容修炼行动的资源输入或临时状态修正。
6. 所有消耗、效果、生效时长、随机抽取值、失败原因、残余状态和结果都必须写入资源使用日志、事件结果包、战斗结果包或行动回放。

## 4. 核心循环或触发入口

符箓围绕“获得、存放、调用、校验、消耗、结算、状态承接、日志回放”循环维护。

```text
获得或生成符箓
-> 进入角色随身、储藏、宗门库存、NPC 持有、节点奖励、事件锁定奖励或后手容器
-> 行动、事件、战斗、移动、探索、突破准备或背包直接使用请求调用符箓
-> 执行前校验容器、权限、上下文、标签、叠加限制和触发条件
-> 按激活策略消耗符箓 1 个单位或终结符箓实例
-> 执行一次性效果，或创建持续效果实例
-> 将效果、随机抽取值、失败原因、残余状态和消耗写入结果包与日志
```

常见触发入口：

1. 行动规划时，把聚灵符、定心符、探索符、防护符等作为资源输入绑定到兼容行动。
2. 事件选项中，使用破禁符、避瘴符、传讯符、护身符等满足选项条件或改变风险。
3. 战斗或突破交锋中，使用攻击符、防护符、护心符、阵禁相关符箓生成战斗 / 阶段效果。
4. 移动、逃离、追击或跨越危险路线时，使用遁行符、避瘴符、通行类符箓等作为条件资源。
5. 背包直接使用时，只允许进入明确支持 `use_confirm` 或 `auto_trigger` 的模板，不允许绕过行动、事件或战斗结果包。

中断点包括符箓不在合法资产容器、角色未获准调用、当前语境不兼容、行动或事件未生效、战斗指令未执行、同类持续效果叠加超限、自动触发条件未被结果包确认、使用确认失败或资源锁定状态变化。

## 5. 规则与状态

### 5.1 物品身份与堆叠

堆叠条件至少要求：

1. 模板相同。
2. 阶级相同。
3. 品级相同。
4. 关键状态相同。
5. 效果模板相同。
6. 未绑定独立事件、后手、来源审计、特殊残缺、封印或缺陷。

一次性使用的含义：

1. 从 `ItemStack` 使用符箓时，消耗 `quantity = 1`。
2. 从 `ItemInstance` 使用符箓时，该实例进入已消耗、破裂、焚毁、失效或事件专用终态。
3. 若符箓创建持续效果，消耗发生在效果实例创建或战斗 / 事件指令实际生效时；之后的剩余时长属于 `ActiveResourceEffect` 或角色持续状态，不再属于原符箓物品。
4. 若行动未开始、事件选项未生效、战斗指令未执行或使用确认失败，则不消耗符箓。

### 5.2 分类与对应语境

| 类型 | 对应行动 / 语境 | 效果通道 | 生效方式 |
| --- | --- | --- | --- |
| 攻击符 | 战斗指令、事件战斗选项、破障交锋 | `combat_damage` / `combat_command` | 一次性生效，或持续若干战斗轮 |
| 防护符 | 战斗、防守、护体、渡险、护心 | `shield` / `damage_reduction` / `risk_delta` | 一次性抵消，或持续时长 / 战斗轮 |
| 遁行符 / 移动符 | 移动、逃离、追击、跨越危险路线 | `movement_modifier` / `escape_modifier` | 一次性移动修正，或路线片段持续 |
| 探索符 / 感知符 | 探索、侦查、寻物、识别隐藏线索 | `exploration_modifier` / `detection_modifier` | 一次性检定修正，或探索时长持续 |
| 避瘴符 / 解毒符 | 毒瘴、毒雾、腐蚀、寒热等危险语境 | `hazard_resist` | 危险暴露小时内持续 |
| 破禁符 / 破阵符 | 阵法、禁制、秘境门、封印、机关 | `array_modifier` / `barrier_break` | 一次性事件选项或短时破禁窗口 |
| 定心符 / 清神符 | 巩固根基、突破准备、研习、心魔压制 | `pressure_control` / `mind_stability_delta` | 兼容行动小时，或事件模板指定 |
| 聚灵符 / 辅修符 | 主动吐纳、阵法辅助、短期修炼准备 | `cultivation_aura` / `action_modifier` | 兼容行动小时；不得即时涨修为 |
| 传讯符 / 标记符 | 传讯、求援、标记坐标、触发剧情联系 | `event_unlock` / `communication` | 一次性事件生效 |

分类只表达常见用途，不限制后续内容表扩展。每张符箓最终以效果模板的 `effect_type`、`use_mode`、`compatible_action_tags` 和 `compatible_context_tags` 决定是否可用。

### 5.3 效果模板规则

符箓效果与丹药类似，必须由可配置的资源效果模板定价，不直接写死为不可追踪的脚本效果。

`resolution_mode = instant` 表示符箓只在一次事件、一次战斗指令、一次检定或一次资源结算点生效。结算完成后，符箓已经消耗，不产生残余效果。

`resolution_mode = duration` 表示符箓消耗后创建角色持续状态实例；若效果只存在于战斗或事件内部，可由战斗 / 事件专用持续状态承接，但挂到角色身上的持续影响仍归入《角色持续状态系统》（`../02_角色与真灵设计/07_角色持续状态系统.md`）。持续效果可以按行动小时、危险暴露小时、战斗轮或世界流逝小时结算。

默认不使用无条件 `world_elapsed_hours`。只有隐身、强制燃烧、短时封印、传讯窗口、危险剧情符箓等明确需要“启用后不论玩家做什么都会倒计时”的模板，才使用 `world_elapsed_hours`。

### 5.4 使用与结算生命周期

行动规划、事件选择、战斗指令或直接使用会创建符箓资源绑定。执行前再次校验：

1. 角色是否持有或获准调用该符箓。
2. 符箓是否位于合法资产容器。
3. 当前行动、事件选项、战斗指令或使用语境是否允许该符箓。
4. 行动标签是否匹配 `compatible_action_tags`。
5. 地点、危险、战斗或事件上下文是否匹配 `compatible_context_tags`。
6. 是否违反同类持续效果叠加限制。
7. 若为自动触发，触发条件是否已被结果包确认。

一次性效果结算：

```text
消耗符箓 1 个单位
抽取或确认本次效果数值
将效果写入对应事件 / 战斗 / 行动结算段
写入资源消耗日志与结果包
```

持续效果结算：

```text
消耗符箓 1 个单位
创建角色持续状态实例或事件 / 战斗专用持续状态
按 effect_tick_mode 逐段结算
剩余时长、剩余效果量、衰减或中断处理写入日志
```

持续符箓被行动、战斗或事件打断时，已生效部分正常结算。未生效部分按照 `residual_policy` 处理：可以暂停为残余状态、缓慢散逸、锁定在事件内、直接消散，或由事件模板专门裁定。

### 5.5 随机效果规则

符箓效果是否随机由配置决定。

确定性符箓：

```text
effect_random_distribution = fixed
effect_amount_min = effect_amount_max
或
effect_rate_min = effect_rate_max
```

随机波动符箓：

```text
effect_random_distribution = normal_clamped
effect_amount_min < effect_amount_max
或
effect_rate_min < effect_rate_max
```

结算要求：

1. 随机抽取发生在符箓实际激活、效果实例创建或战斗 / 事件指令实际生效时。
2. 抽取后的 `rolled_effect_amount` 或 `rolled_effect_rate` 必须固化到绑定、效果实例、结果包和回放日志。
3. C1 追赶、回放和补结算只使用已经固化的抽取值，不重新随机。
4. 可堆叠符箓不为堆叠内每个单体预先保存独立随机结果；从堆叠中消耗 1 个单位后，按模板和当前语境生成本次使用结果。
5. 若随机结果产生“未消耗但残缺”“封印未解”“特殊反噬”等独立状态，必须拆出 `ItemInstance` 或创建事件专用状态，不能继续留在普通堆叠中。

### 5.6 与丹药、法宝、材料的边界

符箓与丹药的共同点：

1. 都是可作为行动、事件或战斗输入的消耗型资源。
2. 都通过配置模板决定效果值、持续时长、随机性和残余策略。
3. 都必须进入资源使用日志、结果包和回放。

符箓与丹药的区别：

1. 丹药通常表达体内吸收、炼化、恢复、承载、药性残余和长期状态改变。
2. 符箓通常表达外部触发、术式封存、战斗指令、护盾、防护、移动、探索、破禁和事件交互。
3. 符箓默认一次性燃烧、破裂或失效；若出现持续效果，持续的是术式效果，不是原物品继续存在。

符箓与法宝的区别：

1. 法宝可以长期持有、反复使用、养成、维护和产生来历关系。
2. 符箓是一次性消耗物，不承载长期装备成长。
3. 若某设计需要可反复使用的符箓类物件，应改入法宝、护符或装备体系。

符箓与材料的区别：

1. 材料主要用于生产、兑换、任务提交或配方输入。
2. 符箓主要用于使用结算。
3. 制符材料进入材料体系；制成后的符箓进入消耗品体系。

## 6. 资源、角色、地图、事件或 NPC 接口

1. 资源接口：符箓读取资产容器、堆叠键、实例状态、预留锁定和消耗流水；使用失败或取消时必须按行动 / 事件 / 战斗结果决定是否退款或保持未消耗。
2. 角色接口：符箓持续效果挂到角色后，只输出状态实例、持续时间、叠加组、来源引用和属性修正，不在角色属性文档中另建私有状态。
3. 行动接口：行动资源输入只绑定兼容行动标签和语境标签；行动未开始或未生效时不消耗符箓。
4. 地图与危险接口：移动、探索、毒瘴、封印、节点机关和路线危险读取符箓的 `compatible_context_tags` 与 `effect_tick_mode`。
5. 事件接口：事件选项可以要求、允许或奖励符箓；事件结果包必须记录消耗、效果、失败原因、残余状态和锁定奖励的来源。
6. 战斗接口：符箓可以生成战斗指令、护盾、防护或持续效果；战斗结束后按已结算游戏时间扣减持续时长。
7. NPC 与宗门接口：NPC、商店、宗门库存和事件模板可以持有、出售、消耗或奖励符箓；隐性实例化的符箓若战后获得，应进入显性资产并按来源扣预算。

## 8. UI 展示边界

普通 UI 至少应展示：

1. 符箓名称、数量、阶级、品级、可用语境和主要效果方向。
2. 是否消耗符箓，以及从哪个容器或预留来源消耗。
3. 主要影响对象、行动、事件、战斗、路线或节点。
4. 是一次性生效还是持续生效。
5. 若有随机性，展示确定数值、范围、稳定 / 波动 / 危险 / 未知等预期。
6. 若有失败、反噬、破裂、副作用、同类叠加限制或不可用原因，必须明确提示。
7. 使用后应展示消耗结果、效果摘要、剩余持续时间、失败原因和回放可追溯入口。

普通 UI 不展示：

1. 内部模板 ID、堆叠键、完整随机种子、服务端锁定状态或未鉴定的隐藏效果。
2. Debug 公式追踪、原始倍率、预算扣减、隐性 NPC 资源池或事件隐藏分支。
3. 未被当前角色识别的完整符箓效果表、剧情锁定奖励或未来事件触发条件。

## 9. MVP 范围

MVP 应实现或保留：

1. 普通符箓作为可堆叠消耗品，高价值或独立状态符箓作为 `ItemInstance`。
2. 符箓位于合法资产容器并通过资源使用接口进入行动、事件、战斗或直接使用结算。
3. 攻击符、防护符、移动 / 遁行符、探索 / 感知符、避瘴 / 解毒符、破禁 / 破阵符、定心 / 清神符、聚灵 / 辅修符、传讯 / 标记符作为首批分类占位。
4. `instant` 与 `duration` 两类效果结算，以及持续效果进入角色持续状态系统或事件 / 战斗专用状态。
5. 符箓实际生效时消耗 1 个单位或终结对应实例。
6. 确定性与随机波动两类效果模板，随机结果在生效时固化进绑定、结果包和日志。
7. 行动、事件、战斗和背包直接使用前的容器、权限、语境、标签、叠加限制和触发条件校验。
8. 使用前预览、不可用原因、消耗确认、结果摘要和回放日志。

MVP 不实现：

1. 符箓被动装备化、长期佩戴化或无消耗反复触发。
2. 普通堆叠内每张符箓预先保存独立随机值。
3. 修炼辅助符箓即时增加修为。
4. 完整符箓内容表、各境界模板、制符配方、制符熟练度、失败副产物和高级生产循环。
5. 高价值命名符箓、残缺符箓、封印符箓、后手封存符箓的完整特殊剧情规则。
6. 战斗符、移动符、防护符、探索符、破禁符的完整数值基准和调参表。

## 10. 验收约束

1. 任何符箓使用不得在未消耗物品、未写入结果包或未记录日志的情况下反复触发。
2. 符箓不得绕过服务端资源使用接口、事件结果包、战斗结果包、行动回放和资产流水。
3. 行动未开始、事件选项未生效、战斗指令未执行或使用确认失败时，不得错误消耗符箓。
4. 可堆叠符箓不得在堆叠内预先保存每个单体的独立随机结果。
5. 随机符箓的抽取值必须在实际激活时固化，C1 追赶、回放和补结算不得重新随机。
6. 持续符箓消耗后创建的角色持续影响，必须交给角色持续状态系统统一管理。
7. 修炼辅助符箓不得即时增加修为，只能作为兼容修炼行动的资源输入或临时状态修正。
8. 若随机结果产生独立状态、残缺、封印、反噬或特殊剧情后果，必须拆出 `ItemInstance` 或事件专用状态。
9. 若某设计需要长期佩戴、反复使用或养成维护，必须改入法宝、护符或装备体系。
10. UI 必须在使用前提示消耗、可用语境、持续 / 一次性、生效范围、随机风险和失败 / 副作用风险。
