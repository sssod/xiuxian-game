# 系统设计｜节点路线详细设定

## 1. 设计定位

节点路线负责维护地图节点之间的通行关系、耗时、风险、可见性、通行条件和路线状态变化。路线是节点图中的有向边，不是独立地理节点。

普通道路、山路、水路和隐藏通道默认是 `RouteState`。渡口、关隘、传送阵、山道要冲等有状态交通对象优先作为节点内设施、路线条件或路线状态建模；只有当其本身扩展成大尺度地理区块时，才按对应地理节点类型建模。

## 2. 当前结论

1. 路线使用有向带权边。双向通行应建成两条路线，因为两侧成本、风险和通行条件可能不同。
2. 移动是普通个人行动，按 `world_hour` 消耗时间。
3. 队列中的移动在入队时校验一次，执行前必须再次校验。
4. 路线可见性、通行状态、要求、风险和耗时都可能被节点事件、宗门控制、交通设施、隐藏层、传闻和世界状态改变。

## 4. 核心循环或触发入口

路线状态变化来源包括节点事件、路线封锁、宗门驻守、交通设施状态、隐藏层揭示、传闻可信度变化、天气 / 灾变、战斗或事件结果、秘境窗口、权限变化和世界小时演化。

移动校验读取：

```text
当前位置；
目标节点；
路线是否可见；
passability；
requirements；
risk_tags；
current_cost_hours；
角色状态；
宗门、NPC 或事件授予的通行许可；
是否存在路线封锁、节点事件或公开危险。
```

## 5. 规则与状态

路线运行态使用 `RouteState`：

```yaml
RouteState:
  route_id: string
  from_node_id: string
  to_node_id: string
  base_cost_hours: int
  current_cost_hours: int
  route_type: road | mountain_path | river | teleport | hidden | rumor
  passability: open | blocked | conditional | unknown
  requirements: list[object]
  risk_tags: list[string]
  discovered_by: list[string]
  last_updated_world_day: int
  last_updated_world_hour: int
```

字段口径：

| 字段 | 含义 |
| --- | --- |
| `from_node_id` / `to_node_id` | 有向路线的起点与终点 |
| `base_cost_hours` | 模板基础耗时 |
| `current_cost_hours` | 当前实际耗时，受路线状态、设施、事件、角色状态和权限影响 |
| `route_type` | 路线大类，不把普通道路单独建成节点 |
| `passability` | 当前是否可通行 |
| `requirements` | 通行许可、境界、道具、宗门权限、事件状态、设施状态或隐藏层条件 |
| `risk_tags` | 路线风险、埋伏、妖兽、封锁、污染、风暴等标签 |
| `discovered_by` | 已发现该路线的角色、真灵、队伍、宗门或可见性群体 |

路线规则：

1. 双向路线必须分别建模，不能默认同耗时、同风险、同条件。
2. 入队校验只证明当时可移动；执行前必须再次校验，避免路线被封锁、节点风险改变或权限失效后仍强行通过。
3. `blocked` 路线不能由普通移动穿越；如允许强闯，应转入事件、战斗、破阵或特殊移动流程。
4. `conditional` 路线必须展示玩家可见的条件摘要；隐藏条件只保留在可见性允许的层级内。
5. `unknown` 路线不能作为普通队列目标，除非事件或传闻流程允许“循迹探索”。
6. 路线耗时变化必须写入 `route_delta`，并可进入个人日志、宗门日志或公开传闻。
7. 隐藏路线可以由隐藏层、线索、真灵感应、宗门情报、NPC 指引或事件结果揭示。
8. 传闻路线可以作为模糊入口存在，但在成为可移动路线前必须转化为可校验 `RouteState` 或事件入口。

## 6. 路线与交通设施接口

交通设施不是默认节点类型。传送阵、渡口、关隘、山道要冲等有状态交通对象应满足以下口径：

1. 若它们只是通行条件或耗时修正，记录为路线 `requirements`、`passability`、`risk_tags` 或 `current_cost_hours` 的来源。
2. 若它们可建设、维护、升级、占领或破坏，记录为节点中的资源槽附属设施，并由路线读取设施状态。
3. 若它们扩展成可承载资源槽、事件、设施、隐藏层和争夺的大尺度地理区块，才建立为地理节点。
4. 传送路线必须有入口设施、权限、目标、消耗、冷却或风险来源，不能作为无来源瞬移。
5. 水路、山路和隐藏通道可以被资源槽、事件、宗门行动或设施状态阻塞。

| 字段 | 含义 |

| `base_cost_hours` | 基础通行耗时 |

字段建议是实现提示，不等同于最终数据库或代码结构。

## 8. UI 展示边界

地图 UI 应展示玩家可见路线、目标节点、当前耗时、风险摘要、通行状态、可见条件和队列目标路线。普通 UI 不显示其他玩家私人封锁来源、隐藏路线真实目标、未公开条件、`hidden_world` 和 `debug_only` 信息。

## 9. MVP 范围

MVP 应实现：

1. 有向 `RouteState`。
2. 路线可见性、通行状态、要求、风险和当前耗时。
3. 移动入队校验与执行前再校验。
4. 路线封锁、开放、条件变化和传闻的结果包记录。
5. 交通设施对路线条件和耗时的最小读取。

MVP 不实现：

1. 把普通道路作为独立节点。
2. 无来源瞬移。
3. 绕过路线可见性和通行条件的普通移动。

## 10. 验收约束

1. 移动读取 `RouteState.current_cost_hours` 并按 `world_hour` 结算。
2. 双向路线必须能表达不同耗时、风险和通行条件。
3. 入队后路线状态变化会触发执行前再校验。
4. 普通道路、水路、山道和隐藏通道默认是路线，不是节点。
5. 渡口、关隘、传送阵等交通对象优先作为设施、路线条件或路线状态表达。
6. 路线变化进入结果包和回放。
