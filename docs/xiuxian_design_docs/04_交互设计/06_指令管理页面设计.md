# 交互设计｜指令管理页面设计

## 1. 当前状态

本页面仍处于交互约束草案阶段，当前只固定指令管理页面对普通行动短队列、入队校验、执行失败、自动兜底、显式托管和 B1 / P0 边界的展示要求，不维护完整视觉稿、Figma 节点或旧来源清单。

指令管理页面服务于玩家提交和编辑普通行动意图。它不替代战斗轮内选择、突破阶段选择、未知事件选项或 P0 全局公共选择。

## 3. 用户目标与入口

玩家进入指令管理页面时，需要完成以下目标：

1. 查看当前执行指令和最多 3 条预输入指令。
2. 新增、替换或移除当前合法的普通行动。
3. 查看入队失败原因和执行前失败原因。
4. 查看自动兜底、显式托管、资源输入和当前速度影响。
5. 理解 B1 / P0 期间普通队列只影响结束后的后续行动。

入口来自主界面行动状态、修为页修炼入口、移动入口、宗门行动入口、储物资源输入、事件结果和自动兜底提示。

## 4. 必须表达

1. 当前指令、后续 1、后续 2、后续 3。
2. 当前兜底规则、自动兜底原因和显式托管状态。
3. 入队时只提示当前是否合法，不提示复杂未来推演。
4. 执行前失败时，必须说明未执行指令、失败原因和自动转入的兜底行动。
5. 队列为空时，必须说明当前已进入低收益兜底，并显示世界进入 N1。
6. B1 或 P0 期间可以编辑普通行动队列，但普通队列只影响交锋或公共阶段结束后的后续行动。
7. 普通行动队列页面不得保存战斗 5 格序列、突破阶段选择、敌方行为预案或未知事件选项。
8. 长期行动必须展示是否具备 F1 条件；洞天闭关必须提示资源绑定、结束条件、中断策略和无安全默认时不能进入 F1。
9. F1 摘要必须区分自动处理事件、摘要事件、软中断事件、硬中断事件、外界日提交边界、F1 校验断点和 F1 中断断点。

## 5. 页面区块与信息优先级

推荐信息优先级：

1. 队列区：当前指令、后续 1、后续 2、后续 3。
2. 状态区：当前速度、是否可编辑、兜底、托管、局部时停 / B1 / P0 说明。
3. 新增指令区：可入队普通行动、地点 / 资源 / 状态要求和当前校验结果。
4. 资源输入区：本行动绑定的资源、消耗时点和残余效果提示。
5. F1 条件区：长期行动的资源绑定、结束条件、中断策略、安全默认、外界日提交边界、F1 校验断点和 F1 中断断点摘要。
6. 失败反馈区：入队失败、执行前失败、跳过指令和自动兜底记录。
7. B1 / P0 边界提示区：说明普通队列与战斗、突破、事件选择的边界。

页面不固定队列控件样式、拖拽方式或具体按钮位置。

## 6. 操作流程与状态

普通入队：

```text
选择普通行动
→ 展示当前合法性校验
→ 通过则加入当前执行或后续队列
→ 不通过则展示当前失败原因
```

入队失败提示示例：

```text
不可入队：当前未拥有筑基丹。
不可入队：当前地点不允许突破。
不可入队：当前灵力储备不足。
```

页面不提示复杂未来推演，例如“预计 8 日后满足”或“如果前序炼丹成功则执行”。

执行前失败：

```text
预输入指令未执行：开启筑基突破。
原因：缺少筑基丹。
已自动转入：吐纳。
```

队列为空：

```text
队列已空。
当前处于低风险节点，已自动转入吐纳。
世界进入 N1，等待你输入新指令。
```

F1 条件不足提示示例：

```text
不能进入 F1：洞天闭关未绑定资源年。
不能进入 F1：该行动缺少资源耗尽后的中断策略。
不能进入 F1：当前存在无安全默认的待处理事件。
```

F1 摘要示例：

```text
本批次推进：12 外界日。
自动处理：2 件。
摘要事件：3 件。
软中断：资源即将耗尽，已按预设出关。
硬中断：无。
```

B1 专用提示：

```text
当前速度：交锋慢速
本轮剩余现实提交时间：60 秒
战斗：5 个交锋格 / 轮，常规 3 轮共 30 分钟，结算不足 1 小时按 1 小时
突破：1 个交锋格 / 阶段，阶段耗时由突破模板声明，总耗时暂定 1-6 小时
默认策略：未提交时执行当前预设
```

## 7. 不表达或 Debug 边界

普通指令管理页面不展示其他玩家队列、私人事件归因、隐藏资源输入、Debug 校验树、完整事件权重、C1 逐 tick 明细或敌方行为预案。

页面不应表达为：

1. 条件脚本编辑器。
2. 未来资源规划器。
3. 通用事件预案表。
4. 战斗 5 格序列保存页。
5. 突破阶段选择保存页。
6. 未知事件选项预设页。
