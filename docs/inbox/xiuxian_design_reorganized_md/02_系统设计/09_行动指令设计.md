# 行动指令设计

## 1. 当前结论

行动指令是玩家提交给服务端的意图，不是客户端直接改状态。服务端在共享世界日历中按 `world_day / world_hour` 校验并结算行动，统一写入资源消耗、位置变化、行动合法性、事件触发、角色状态、宗门库存、节点状态、日志、回放与存档。

底层时间口径：

```text
1 游戏日 = 24 游戏小时
服务器最小结算单位 = 1 游戏小时
公开速度档位 = F1 / N1 / B1 / P0
C1 = 局部时停结束后的追赶补结算机制
```

行动指令与速度关系：

| 档位 | 行动含义 |
| --- | --- |
| F1 | 仅在全员明确处于长期低交互行动，且无自动兜底、局部时停、C1、正式交锋、全局公共事件或临近截止节点时进入 |
| N1 | 普通多人运行、普通队列编辑、局部时停期间外部世界运行、自动兜底等待玩家接管 |
| B1 | 正式战斗、突破挑战、秘境关键交锋、玩家直接交锋等正式交锋 |
| P0 | 全局公共事件、全员决策、同步保护和房间规则允许的主机暂停 |

## 2. 普通指令队列

玩家角色保留一个短队列：

```text
当前执行指令 + 最多 3 条预输入指令
```

指令预输入不是自动化脚本系统，而是允许玩家把“当前已经合法的普通指令”提前放入短队列。队列为空或校验失败时，系统使用低收益兜底行动维持角色存在，并降至 N1 等待玩家补充新指令。

核心边界：

```text
预输入 = 提前排队已经合法的普通指令
不是 = 条件脚本、自动推导、未来资源规划、通用事件预案、追求全程高速推进
```

玩家主动编辑普通队列时：

1. 角色当前行动继续结算。
2. 其他玩家、宗门与世界继续推进。
3. 若当前为 F1，打开普通队列编辑界面时世界降至 N1。
4. B1 或 P0 中可编辑普通队列，但普通队列不替代交锋轮选择或全局公共选择。
5. 外部 UI 只显示中性速度状态，不暴露私人事件或具体玩家归因。

## 3. 可入队指令类型

可作为普通指令入队：

```text
闭关修炼
吐纳
休整
养伤
炼丹
炼器
长期赶路
拜访指定 NPC
申请指定宗门资源
进入指定地图节点
开启当前已满足条件的大境界突破
执行当前已满足条件的小境界突破
显式托管行动
```

不进入普通队列，改由事件、交锋或即时处理系统处理：

```text
未知事件的选项选择
需要新情报判断的宗门站队
多人直接冲突选择
正式交锋中的轮内策略选择
突破挑战中的轮内选择
临时触发的机缘事件
临时触发的心魔或风险抉择
```

长期低交互行动由行动模板标签决定，典型包括闭关、养伤、炼丹、炼器、长期赶路、长期打坐、资源整理、普通宗门事务、突破准备期和显式托管行动。自动兜底固定 `f1_eligible=false`，不能作为进入 F1 的依据。

## 5. 校验规则

每条指令在入队时和执行前都必须校验。

入队时必须满足：

```text
当前状态允许
当前地点允许
当前资源足够
当前风险没有阻止
当前事件状态不冲突
当前境界 / 功法 / 关系条件满足
主修功法对应模板可用
资源输入项可从合法资产容器取得
```

队列不做：

```text
资源锁定
未来产出承诺
队列内资源占用推导
条件 if-else 链
跨指令依赖图
甘特图计划
通用事件预案策略表
```

校验结果：

```yaml
validation:
  passed: boolean
  failed_reason: string | null
  failed_reason_tags: list
  checked_world_day: int
  checked_world_hour: int
  phase: enqueue | before_execution
  resource_check: dictionary
  location_check: dictionary
  state_check: dictionary
  event_conflict_check: dictionary
```

执行前校验通过时，角色开始该指令。执行前校验失败时，系统跳过该指令，记录个人日志，进入自动兜底并强制世界进入 N1。

## 6. 行动完成点

行动完成后，系统按以下顺序处理：

```text
1. 取出下一条预输入指令。
2. 对下一条指令做执行前校验。
3. 若下一条指令合法，直接开始执行。
4. 若下一条指令不存在或校验失败，进入自动兜底。
5. 自动兜底时世界进入 N1，等待玩家补充主动指令。
```

行动完成后若下一条指令合法，且全员仍处于长期低交互行动，没有事件、交锋、全局节点或自动兜底，F1 可以继续。行动完成本身不强制降速。

## 7. 自动兜底、显式托管与超时默认

自动兜底触发条件：

```text
当前指令完成后队列为空
下一条指令执行前校验失败
下一条指令地点不合法
下一条指令资源不足
下一条指令被当前风险状态阻止
玩家未输入任何后续指令
```

风险兜底：

| 当前节点风险 | 自动兜底 |
| --- | --- |
| 低风险 / 宗门 / 城镇 / 安全洞府 / 已控制灵地 | 吐纳 |
| 中风险 / 高风险 / 秘境 / 敌对边境 / 未控制节点 / 战斗后区域 | 休整 |
| 风险等级不明 | 休整 |

兜底状态：

```yaml
fallback:
  fallback_id: string
  character_id: string
  started_world_day: int
  started_world_hour: int
  action: meditate | rest
  reason: queue_empty | validation_failed | invalid_location | insufficient_resource | blocked_by_state
  node_risk: low | medium | high | unknown
  expected_reward_level: very_low | low
  force_speed: N1
  f1_eligible: false
  replaced_by_command_ref: string | null
```

显式托管是玩家主动声明短期低关注，不等于自动兜底。它可以在满足安全条件时参与 F1，但不得主动消耗新高价值资源、发起重大不可逆选择、进入高危区域或开启高风险突破。

托管可保守处理低价值事件，例如普通邀约、普通传闻、低价值机会、轻微状态波动和普通资源波动。死亡风险、正式交锋、重大心魔、重大机缘、不可逆选择、大境界突破挑战、多人直接冲突和宗门重大事件仍进入通知、局部时停、B1 或 P0。

## 8. 行动资源输入

丹药、灵材、符箓、临时增益资源统一作为行动或事件选项的资源输入项，不设计独立持续行动“丹药炼化”。

资源输入规则：

1. 入队时只校验当前是否拥有和可使用资源。
2. 队列不锁定未来资源。
3. 行动真正开始前再次校验资源。
4. 行动开始后才消耗资源输入。
5. 未用完资源效果生成 `ActiveResourceEffect`。
6. 局部时停期间，该玩家资源变化暂停。
7. C1 追赶只补结算确定性资源效果。

资源输入绑定建议：

```yaml
ActionResourceInputBinding:
  binding_id: string
  command_id: string
  character_id: string
  resource_item_ref: string
  resource_item_template_id: string
  resource_effect_template_id: string
  effect_type: string
  compatible_action_tags: list
  compatible_context_tags: list
  effect_tick_mode: string
  unit_effect_rate: number
  max_effective_hours: number
  activation_policy: consume_on_action_start
  residual_policy: stable_suspend | slow_decay | stimulating_decay | forced_release
  residual_stability_hours: number
  stacking_group: string
  max_same_group_active: int
  created_world_day: int
  created_world_hour: int
```

## 9. 事件、局部时停与 C1

普通个人选择事件保留玩家处理权：

```text
事件玩家本人局部时停
其他玩家、宗门与世界继续 N1
gap 最大 1 游戏日
事件结束后 C1 追赶补结算
其他玩家不看到事件归因
```

事件选项可有游戏内时间成本，该时间从事件触发 `world_hour` 开始回填。C1 只补结算确定性行动进度、修炼收益、资源消耗、药性衰减、伤势恢复、队列切换、已知状态变化和事件选择明确后果，不触发随机个人事件、普通机缘、普通战斗、软机会事件、普通心魔或普通资源反馈。

## 10. 突破与正式交锋边界

大境界突破可以预输入开启指令，但必须在入队当下已经满足条件。预输入保存“开启突破”本身，以及少量突破专用道具、主修功法突破模板确认和必要的突破挑战默认策略。

若开启突破在执行前仍合法，则进入突破挑战，世界切换至 B1。若执行前不合法，则跳过开启指令，不消耗突破道具，记录个人日志，进入自动兜底并降至 N1。

正式交锋和突破挑战不由普通队列替代：

```text
世界进入 B1
每个决策窗口现实时间 = 60 秒
B1 世界推进 = 每 60 秒现实时间对应非参战玩家和世界推进 1 游戏小时
未提交者执行当前默认策略
战斗交锋自身：每轮 5 个交锋格，叙事耗时 10 分钟，常规 3 轮共 30 分钟，不足 1 游戏小时按 1 游戏小时结算
突破交锋自身：每阶段 1 个交锋格，阶段耗时由突破模板声明，总耗时暂定 1～6 游戏小时
战斗 / 突破交锋均沿用 gap 最大 1 游戏日，不额外设置实现层时间预算限制
```

正式交锋结果包应区分 `b1_world_elapsed_hours`、`nonparticipant_progress_hours`、`encounter_scene_elapsed_minutes`、`encounter_accounting_hours` 和 `participant_gap_hours`。普通行动队列只承接交锋结束后的后续行动，不记录战斗 5 格序列或突破阶段选择。

## 11. MVP 保留

1. 当前执行指令 + 最多 3 条预输入指令。
2. 入队时当前合法性校验。
3. 执行前再次校验。
4. 队列为空或校验失败后自动兜底。
5. 低风险吐纳，中高风险休整。
6. 自动兜底强制降至 N1。
7. 自动兜底不参与 F1。
8. 闭关三档预案。
9. 显式托管行动。
10. 大境界突破在当前满足条件时可预输入开启指令。
11. 常态事件保留玩家处理权。
12. 资源输入绑定行动或事件选项，并按世界小时结算残余效果。
13. B1 交锋区分世界推进、现实提交窗口和交锋自身结算耗时。

## 12. MVP 不做

1. if-else 条件脚本。
2. “未来满足条件后自动执行”。
3. 前置产出和后置消耗的未来推导。
4. 通用事件默认策略表。
5. 用预输入替代正式战斗、突破挑战和重大事件选择。
6. 让自动兜底伪装成长期高速计划。
