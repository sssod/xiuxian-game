# 储物空间系统设计｜基础行囊

## 1. 当前结论

行囊和库存是两个概念。

行囊是角色随身携带的物品、道具、法宝、材料和可调用资产所在的储存位置。行囊绑定当前角色实例，是随身资产的默认容器。

库存是非随身储存空间，通常绑定在设施、店铺、宗门、节点、洞府、藏宝点、真灵藏宝、市场、事件或交易暂存容器上。库存规则统一见《03_库存系统》。

MVP 不引入背包重量、体积、格子或通用负重上限。物品栏数量只保留程序层上限，用于性能、存档和异常防护，不作为玩法层上限。物品能否被使用，由资产位置、权限、标签、事件条件、角色状态和上下文共同决定。

行囊不跨世复制。玩家角色转世前留下的宗门个人洞府库存按有主遗产清点回收；宗门外个人洞府和普通藏宝是无主遗留设施，需要开启条件或破阵结果；真灵藏宝可由同一真灵跨世感应和开启，但受设置数量和单个容量限制。

## 2. 行囊定义

基础行囊对应随身资产位置：

```yaml
AssetLocation:
  carried_by_character
```

基础行囊的规则：

1. 行囊绑定当前角色实例，随角色行动移动。
2. 行囊中的资产默认视为随身，但随身不等于任何场景都可用。
3. 行囊不使用玩法容量、重量、体积或格子限制。
4. 行囊中高价值、唯一、绑定、后手相关或带独立状态的物品仍应作为独立实例追踪。
5. 行囊中的可堆叠物品仍需按模板、品阶、品质、关键状态、绑定状态和所有者限制拆分堆叠。
6. 行囊变更必须写入资产流水，至少记录来源、目标、物品、数量、时间、原因和可见日志。

## 3. 行囊与库存的最小区别

| 概念 | 绑定点 | 是否随角色移动 | 典型使用 |
| --- | --- | --- | --- |
| 行囊 | 当前角色实例 | 是 | 随身物品、可调用道具、当前携带资产 |
| 库存 | 设施、地点、组织、事件、市场、洞府、藏宝或后手封存点 | 否 | 商店库存、宗门库存、节点库存、洞府库存、藏宝库存、事件锁定资产 |

当前重整包中的库存类型、容器字段、权限策略、预留锁定、交易暂存和资产位置枚举，以《03_库存系统》为准。

商店特别规则在本页只保留边界：掌柜、摊主、接引 NPC 或商店入口 NPC 不等于商店库存持有人。商店交易和出售物回收规则见《03_经济系统设计/04_交易系统》。

## 4. 可用性限制

物品是否可用不由“装备栏”决定，而由以下条件共同决定：

1. 资产是否在行囊中，或当前行动是否允许从指定库存调用。
2. 物品是否 `combat_ready`。
3. 行动、事件、战斗、突破或交易上下文是否兼容。
4. 角色状态是否允许调用。
5. 权限、绑定、宗门身份、贡献、位置和可见性是否满足。
6. 资源是否被预留、事件锁定、后手封存、市场挂牌或交易暂存。
7. 目标库存是否允许当前角色存入、取出、查看或转移。

随身不等于可用。非随身也不等于永远不可用。部分行动可以在合法条件下从宗门库存、个人洞府库存或事件锁定容器调用资源，但必须经过权限校验和资产流水记录。

## 5. 行囊流转

行囊与库存之间的转移使用库存系统的 `AssetTransferRequest`。

通用规则：

1. 从库存取出到行囊时，校验库存访问权、当前位置、角色状态和物品状态。
2. 从行囊存入库存时，校验目标库存是否接受该物品类型、当前模式是否允许存入、是否需要权限或消耗。
3. 商店买卖、洞府存取、藏宝设置、后手封存、事件奖励领取都使用同一类流转记录。
4. 藏宝类库存只能在设置藏宝时存入；正式取出后按一次性取出规则处理。
5. 任何高价值物品、后手物、法宝、功法载体、突破资源或绑定物的流转必须写入可复盘日志。
6. 从宗门外洞府或普通藏宝取入行囊前，必须先满足钥匙、功法、线索、位置、事件条件或破阵结果；从真灵藏宝取入行囊前，必须校验同一真灵、数量容量限制和一次性取出状态。

## 6. MVP 边界

MVP 保留：

1. 行囊作为角色随身资产容器。
2. 行囊与库存的概念区分。
3. 行囊与库存之间的转移、预留、消耗和日志规则。
4. 高价值物品的实例追踪。
5. 可堆叠物品与独立实例物品的区别。

MVP 不做：

1. 背包格子、重量、体积、通用负重和容量成长玩法。
2. 通过装备栏决定法宝或道具可用性。
3. 储物空间法宝的独立取放、扩容、偷取、掉落和内部空间结算玩法。
4. 把入口 NPC 当成商店库存绑定点。

## 7. 待细化问题

3. NPC 随身资产在普通查看、交易、战斗和死亡事件中的可见性分层。
