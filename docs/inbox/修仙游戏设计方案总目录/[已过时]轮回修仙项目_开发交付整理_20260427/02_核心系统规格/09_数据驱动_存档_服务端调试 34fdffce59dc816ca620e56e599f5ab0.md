# 数据驱动、存档、服务端与调试

## 0. 文档定位

本文整理 Godot 技术路线、客户端 / 权威服务器边界、数据驱动对象、运行时状态、存档、日志、调试回放和版本迁移。

实现目标：让所有玩法系统可配置、可保存、可回放、可调试。

## 1. 技术路线

已定路线：

```
Godot 客户端 + Godot Headless / Dedicated Server
```

原则：

- 客户端负责 UI、地图展示、行动规划、事件阅读、账本展示和玩家输入。
- 服务器负责房间状态、季度推进、行动结算、宗门 AI、地图节点、事件触发和存档写入。
- 本地单人测试也走同一套规则模型。
- 回合统一结算，避免复杂实时同步。

## 2. 权威服务器边界

客户端只提交意图：

- 宗门建议 / 决策意图。
- 角色行动计划。
- 事件链选择。
- 战斗指令序列。
- 资源使用请求。
- 托管偏好。

服务器校验并写入：

- 资源消耗。
- 位置变化。
- 行动合法性。
- 事件触发。
- 战斗结果。
- 突破结果。
- 死亡与转世。
- 角色状态。
- 宗门库存。
- 节点状态。
- 后手状态。
- 日志与存档。

## 5. 存档最小要求

存档必须支持：

1. 房间元数据。
2. 世界种子。
3. 当前季度与阶段。
4. 玩家与真灵。
5. 当世角色。
6. 宗门状态与库存。
7. 地图节点、边、槽位、控制权、影响力。
8. 事件状态、秘境窗口、隐藏层。
9. 后手与轮回账本。
10. 可见性与传闻。
11. 随机状态或可复盘随机日志。
12. 版本号与迁移信息。

## 6. 存档格式原则

SQLite、Godot Resource、JSON 或混合方案暂不在本整理稿中定死。

选择标准：

- 支持私人服务器长期保存。
- 支持调试查询。
- 支持版本迁移。
- 支持本地单人测试。
- 支持多人房间状态一致性。
- 支持大状态对象和事件日志查询。
- 支持开发期快速查看和修复。

推荐实现评估：

| 方案 | 优点 | 风险 |
| --- | --- | --- |
| JSON / Resource | 开发快，Godot 集成容易 | 大存档、查询、迁移不便 |
| SQLite | 查询与调试好，适合服务器长期保存 | Godot 集成和数据映射成本更高 |
| 混合方案 | 配置用 Resource/JSON，运行存档用 SQLite | 架构复杂，需要早期约定 |

建议：MVP 原型可先使用最容易调试的结构，但一旦进入多人长期房间，应尽快评估 SQLite 或混合方案。

## 7. 日志体系

最小日志分三类。

### 7.1 玩家可见日志

包括：

- 角色日志。
- 宗门摘要。
- 传闻。
- 轮回账本。

### 7.2 世界日志

系统完整事件记录，默认玩家不可见。用于：

- 传闻生成。
- 后手失效原因链。
- 节点变化追踪。
- 宗门行动追踪。
- Debug 查询。

### 7.3 Debug 日志

包括：

- 结算输入。
- 校验过程。
- 随机命名空间。
- 关键 roll。
- 结果包。
- 状态差异。
- 错误。

## 8. 日志记录要求

以下必须能追踪：

- 角色行动提交与服务端校验。
- 托管生成原因。
- 资源预留、消耗、释放。
- 库存转移。
- 宗门行动计划和执行结果。
- 节点控制权变化。
- 资源槽枯竭、污染、再生、异变。
- 秘境开启、关闭、坍缩。
- 突破关键资源消耗。
- 突破失败标签。
- 战斗指令与结果。
- 死亡、转世、遗产分配。
- 正式后手创建、暴露、受损、回收、失效。
- 多人可见性和传闻生成。

## 9. 结算回放

开发期需要支持“季度回放”。

最小回放内容：

```
QuarterReplay {
  room_id: String,
  quarter: int,
  initial_state_hash: String,
  submitted_decisions: Array,
  autopilot_plans: Array,
  rng_trace: Array,
  settlement_steps: Array,
  result_packages: Array,
  final_state_hash: String,
  debug_notes: Array
}
```

回放目标：

- 复现 bug。
- 验证权威结算一致性。
- 调试事件触发。
- 追查资产来源。
- 检查后手失效原因。
- 评估多人可见性。

## 10. 版本迁移

存档需要版本号。

```
SaveMetadata {
  save_version: String,
  ruleset_version: String,
  content_version: String,
  created_at: String,
  last_loaded_at: String,
  migration_history: Array
}
```

迁移应记录：

- 从哪个版本迁移到哪个版本。
- 哪些字段新增、删除、重命名。
- 哪些数据被默认补齐。
- 哪些旧存档无法兼容。

## 11. 配置与文案分离

规则配置：

- JSON / Resource / 数据表。
- 不包含长文案。
- 不包含中文包装作为规则判断。

本地化文案：

- 显示名。
- 描述。
- 事件文本。
- 选项文本。
- 日志文本。
- 传闻文本。

建议所有日志也使用模板 + 参数生成，方便本地化与调试。

## 12. 服务端部署边界

MVP 私人服务器需要：

- 创建房间。
- 保存房间。
- 加载房间。
- 玩家加入 / 离开。
- 提交决策。
- 锁定 / 超时。
- 统一结算。
- 返回结果摘要。
- 同步当前可见状态。
- 导出 debug 日志。

不需要：

- 全球匹配。
- 账号系统商业化。
- 反作弊体系完整化。
- 高并发 MMO 同步。
- 无人在线自动推进。
