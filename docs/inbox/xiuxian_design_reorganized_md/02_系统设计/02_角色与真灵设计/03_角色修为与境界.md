# 角色与真灵设计｜角色修为与境界

## 1. 当前结论

系统实现使用抽象阶段编码，不在规则层硬绑定修仙包装：

```text
A-1, A-2, A-3
B-1, B-2, B-3
C-1, C-2, C-3
```

解析字段：

```yaml
major_code
minor_index
major_order
absolute_order
```

MVP 里程碑：

- M0：开局与入门。
- M1：第一阶段修行闭环完成，进入关键突破准备。
- M2：第二大境界。
- M3：第三大境界起点，允许进入长老序列或等价高层决策体验。

## 2. 修为推进原则

修为提升不是孤立数值增长，而是提高本世资源获取效率，并把玩家推向瓶颈、突破、资源准备、宗门支持和后手布局。

小境界升级：

- 应轻量处理。
- 不消耗关键突破物。
- 不进入完整突破事件链。
- 不触发死亡 / 转世。
- 可更新阶段编码、少量派生属性 / 功法效果、日志与瓶颈提示。

大境界突破：

- 由玩家主动发起。
- 至少消耗一个关键突破物或等价高承诺资源。
- 进入事件链后不可临时回头补准备。
- 结果影响本世路线、宗门关系、轮回账本和下一世策略。

## 3. 数值草案映射

当前数值设计不从“1 小时给多少收益”开始，而从 RealmSegmentBalance 开始：

```text
RealmSegmentBalance
→ RealmBenchmarkRate
→ ActionCultivationProfile
→ RealmInputFitMatrix
→ ResourceEffectBalance / NodeRealmSupport / SectSupportBalance
→ StatePressureModel
→ BreakthroughScoreBalance
→ ReincarnationEfficiencyPolicy
→ 模拟验证
```

标准化进度用于内部调参；cultivation_points 可作为表现层字段、日志展示、境界膨胀感和调试面板。

## 4. 设计历史

早期修为层级作为顶层里程碑；后续数值草案把境界拆成 RealmSegment，并将玩家现实体验时间与标准修士背景年限分离。

## 5. 缺口

- A/B/C 与具体炼气/筑基/金丹等包装的映射表未最终定稿。
- 小境界字段、瓶颈状态、巩固状态、突破资格状态需要与数值表合并。
- 修为纯度、根基稳定、经脉压力等长期字段尚未形成最终表。
