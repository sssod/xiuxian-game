# 交互设计｜战斗构筑与自动战斗

适用范围：战前构筑、普通与重点 PVE 预览、自动释放时间轴、护盾与 Buff、逃遁、连续战斗、渡劫和战后结果的信息职责。本文不固定画面节点或视觉表现。

## 1. 构筑入口

战斗构筑区分：当前主修道功招式、最多 `5` 个已装配战斗法门招式、攻击法宝招式、防御法宝招式。飞遁法宝只显示被动和逃遁加成，不进入循环列表；炼化度不高于 `50` 时，法宝内容明确标记为未生效。

所有有效招式合并为手动左右排序列表。顺序表示同一角色多个招式同刻可用时的扫描优先级，不是一次性施放队列。法门阈值强化应展示在原能力详情中，不伪装成新候选招式。

## 2. 招式条目

每个招式至少展示：

- 来源、解锁门槛、装配与主修状态；
- 当前五阶段掌握及该字段是否读取 `0.70 / 0.85 / 0.95 / 1.00 / 1.10` 倍率，或法宝炼化后的有效值；
- 已应用的新增、单招强化或整门强化来源；
- 基础冷却、当前剩余冷却、元气或自损成本；
- 伤害、护盾、Buff、固定元气损伤 `D` 或吸收 `K3`；
- 无法释放时的具体原因。

固定元气字段、冷却、消耗和离散强化不应误显示为随掌握倍率连续缩放。

## 3. 战斗前预览

普通途中战斗只展示事件提供的必要信息。主动重点 PVE 必须在确认挑战前展示当前档位、升档来源、敌方战力摘要、奖励、逃遁规则和失败后果。

固定小洞天入口预览同时展示当前洞府资格、挑战顺位和入口 PVE 档位。洞府开放时间不冻结敌人档位。

渡劫预览必须与普通重点 PVE 区分：

- 显示绑定的目标境界和“不随回合 / 失败次数变化”的固定难度；
- 显示新提交破境丹品级及 `10% / 20% / 35% / 55% / 80%` 最大生命护劫护盾锚点；
- 显示本次敌人、构筑、状态和消耗；
- 明确允许主动逃遁，逃遁会使突破失败并要求以后重新持丹；
- 明确成功无额外普通战利品，失败 / 逃遁也无战利品；
- 其它玩家不能加入或影响该独立战斗；
- 显示护劫护盾先加入统一总护盾后的最终开战值、开战最大生命 `100%` 总上限，以及其它开战护盾可能发生的溢出。

预览不把护劫护盾保存为独立可消耗余额，也不展示来源持续时间或受击优先级。五档比例是当前调参锚点，正式敌人和招式数值仍待配表。

## 4. 自动战斗时间轴

开战后全部冷却招式先等待一次完整基础冷却。战斗中持续显示：

- 双方生机、元气、神念；
- 只保护生机的单一总护盾条；
- 招式剩余冷却和当前扫描结果；
- Buff 层数、最大层数与共享持续时间；
- 已用时间与普通战斗 `60` 秒上限；
- 下一次允许逃遁尝试的时间。

反馈需区分“冷却中”“等待资源”“条件不成立”“无合法目标”和“本次扫描跳过”。同刻先后由稳定战斗随机结果决定，结果应可追溯但无需暴露种子。

## 5. 伤害、护盾与 Buff

单次直接伤害允许展开：

```text
修为强度与自损形成基础威力
→ 通用增伤 / 减伤
→ 生机伤害先扣护盾，或神念伤害绕过护盾
→ 目标属性减伤
→ 最终状态变化
```

所有普通与护劫护盾只显示一个总护盾条。战斗日志可以说明“何来源本次请求增加多少、实际增加多少、多少因上限溢出”，但不显示或暗示来源余额、剩余时间、刷新状态和消耗顺序。

护盾详情固定说明：

- 总护盾以开战最大生命 `100%` 为本场上限；
- 普通护盾每次生成以开战最大生命 `50%` 为单次上限；
- 护劫护盾可超过普通单次上限，但仍计入总上限；
- 渡劫开战先生成护劫护盾，其它开战护盾按稳定事件顺序加入；
- 所有护盾整场持续，伤害直接扣总值；战中最大生命变化不追溯修改上限；
- 战斗结束清空，连续战斗下一场从 `0` 重建。

可变数值 Buff 最大一层，新值无条件替代旧值并刷新时间；普通叠层 Buff 显示当前 / 最大层数和共享剩余时间。

## 6. 逃遁

普通逃遁是无需装配的通用能力；失败后 `5` 秒可重试，并使所有招式当前剩余冷却增加 `1` 秒。入口展示：

- 当前是否允许；普通事件若禁逃需显式说明；
- 按大境界差得到的基础成功率；
- 飞遁法宝经炼化缩放后的百分点加成；
- 最终成功率，最高 `100%`；
- 失败冷却惩罚和成功后的地图落点规则。

四场渡劫明确允许逃遁。渡劫按钮除通用信息外，还需提示“本次突破失败、丹药与战斗消耗不返还、实际伤势保留、下一次重新持丹”。不得继续显示“渡劫禁逃”。

## 7. 结束、连续战斗与结果

生机归零为死亡，神念归零为重伤，普通战斗 `60` 秒到时为平局；元气归零不结束战斗。平局明确显示双方无胜负、行动失败、目标无人获得且不能开始飞升。

多人连续战斗显示当前参战顺序、保留状态和每场重置护盾；中途不显示死亡掉落，整段结束后才展示最终胜者、逐件 / 逐单位 `10%` 战利品与系统回收。

同刻小洞天挑战和同刻渡劫都是彼此独立战斗，不显示为多人连续战斗。小洞天以通过者战斗用时、再以稳定随机结果裁定资格；渡劫各自返回共享流程。
